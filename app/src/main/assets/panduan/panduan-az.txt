Create Aplikasi by Al Kautsar tətbiqinə xoş gəlmisiniz
Create Aplikasi — noutbuka ehtiyac olmadan, birbaşa telefonda işləyən Android tətbiqləri yaradan tətbiqdir. Bu tətbiq hər kəsə, o cümlədən tətbiq yaratmağı yeni öyrənənlərə və ekran oxuyucusu istifadəçilərinə öz Android tətbiqini yaratmağa imkan verir. Bu tətbiqdən istifadə üzrə tam təlimat məhz bu Tentang Alat ekranında mövcuddur.

Bu hansı tətbiqdir və kimlər üçündür
Create Aplikasi — telefonda işləyən Android tətbiqləri yaratmaq üçün vasitədir. Bu tətbiq öz Android tətbiqini yaratmaq istəyən hər kəs, o cümlədən yeni başlayanlar və ekran oxuyucusu istifadəçiləri üçün nəzərdə tutulub. Bu tətbiq kod redaktoru, layihəni sınamaq üçün Jalankan düyməsi, APK yaratmaq üçün Bangun düyməsi, eləcə də APK-nı imzalamaq və quraşdırmaq üçün menyu təqdim edir.

Bu tətbiqin məqsədi
Bu tətbiq hər kəsin öz Android tətbiqini birbaşa telefondan asanlıqla yarada bilməsi üçün yaradılıb. Onun görünüşü yeni istifadəçilərin də dərhal sınaya bilməsi üçün mümkün qədər sadə edilib.

Yeni layihə yaratmaq, addım-addım
1. Əsas menyuda Buat Project düyməsini basın.
2. Layihə növünü seçin: HTML, Situs Web, Java, Kotlin, Compose və ya Python.
3. Tətbiq adını daxil edin, məsələn: Garuda Decode.
4. Paket adını (package name) daxil edin, məsələn: com.android.garudadecode. Paket adı kiçik hərflərdən ibarət olmalı və nöqtə ilə ayrılan ən azı iki hissədən təşkil olunmalıdır.
5. Tətbiq versiyasını, məsələn: 1.0, və rəqəm şəklində versiya kodunu, məsələn: 1 daxil edin. Boş buraxılsa, versiya avtomatik olaraq 1.0, versiya kodu isə 1 ilə doldurulacaq.
6. Lazım gələrsə, minimum SDK və hədəf SDK daxil edin. Boş buraxılsa, standart qiymətlər istifadə olunacaq. Minimum SDK — dəstəklənən ən aşağı Android versiyasıdır, məsələn: 21 demək Android 5.0. Hədəf SDK-nin maksimum qiyməti 36 (Android 16) təşkil edir.
7. Tətbiq icazələrini seçmək üçün Pilih Izin düyməsini basın, məsələn: INTERNET. INTERNET icazəsi standart olaraq işarələnib. Yalnız tətbiqə həqiqətən lazım olan icazələri işarələyin.
8. İstəsəniz, APK ölçüsünün daha kiçik olması üçün "Gunakan arsitektur terpisah 64 bit dan 32 bit" xanasını işarələyin və öz yaratdığınız keystore-dan istifadə etmək istəsəniz, "Gunakan tanda tangan pribadi" xanasını işarələyin.
9. Buat Proyek düyməsini basın. Yeni layihə Download/project qovluğunda saxlanılır və dərhal Kelola Project daxilində görünür.

Mövcud layihə növləri
• HTML: WebView vasitəsilə işləyən index.html, style.css və script.js-dən ibarət görünüş. Birbaşa telefonda yığılır.
• Situs Web: WebView vasitəsilə işləyən index.html, tentang.html, kontak.html, style.css və script.js-dən ibarət, menyusu (Beranda, Tentang, Kontak) olan veb-sayt. Birbaşa telefonda yığılır.
• Java: telefonda yığılır. MainActivity app/src/main/java/<nama-paket>/MainActivity.java daxilində yerləşir. Görünüş app/src/main/res/layout/activity_main.xml-dən, mətn app/src/main/res/values/strings.xml-dən, mövzu isə app/src/main/res/values/styles.xml-dən götürülür.
• Kotlin: tətbiqə daxil edilmiş Kotlin kompilyatoru vasitəsilə cihazın özündə (offline) və ya GitHub Actions vasitəsilə yığıla bilər. MainActivity app/src/main/java/<nama-paket>/MainActivity.kt daxilində yerləşir, res faylları isə Java layihəsindəki kimidir. Kompilyatorun ölçüsü böyük olduğu üçün ilk Kotlin yığılması daha yavaşdır və Kotlin siniflərinə istinad edən .java faylları hələlik yığıla bilmir (.java faylları .kt fayllarından əvvəl kompilyasiya olunur).
• Compose: interfeysi Jetpack Compose ilə yaradılmış müasir Android tətbiqi (XML düzülüşü deyil). MainActivity app/src/main/java/<nama-paket>/MainActivity.kt daxilində yerləşir. Compose layihələri GitHub Actions vasitəsilə (Bangun proyek menyusu, sonra Bangun online) və ya Gradle ilə Termux daxilində yığılır, çünki Compose cihazda mövcud olmayan Jetpack Compose kitabxanalarını tələb edir.
• Python: tətbiq məntiqi Python dilində (Chaquopy) app/src/main/python/main.py daxilində yazılır və app/src/main/java/<nama-paket>/MainActivity.java daxilindəki MainActivity hostu tərəfindən işə salınır. Python layihələrini birbaşa telefonda (Chaquopy iş mühiti tətbiqə daxil edilib) eləcə də GitHub Actions vasitəsilə yığmaq olar. Python layihəsinin minimum SDK-si 24 (Android 7.0) təşkil edir.

Layihə Arxitekturasını Dəyişdir
Yeni layihə yaratmadan mövcud layihənin arxitektura seçimlərini dəyişdirmək üçün: əsas menyuda «Layihə Arxitekturasını Dəyişdir» düyməsini basın, sonra layihəni seçin və «64 bitlik APK yığın (arm64-v8a)» və ya «32 bitlik APK yığın (armeabi-v7a)» onay qutusunu dəyişdirin; və ya «Layihələri idarə et» bölməsində layihə adını uzun basın və həmin layihə üçün eyni ekranı birbaşa açmaq üçün «Arxitekturanı Dəyişdirin» seçin. Qayda belədir: hər iki onay qutusu işarələnibsə, yığma iki ayrı APK faylı yaradır, biri 64 bitlik və biri 32 bitlik; yalnız bir onay qutusu işarələnibsə, yığma 64 bitlik və 32 bitlik cihazlarda işləməyə davam edən tək universal APK faylı yaradır. Yalnız bir variant üçün ayrı APK hələ dəstəklənmir, çünki yığma yolu yalnız bölünmüş və ya universal seçimi tanıyır, lakin hər variantın seçimi ekran yenidən açılanda itməsin deyə layihə daxilində saxlanılır.

Java, HTML, Situs Web, Kotlin, Compose və Python layihələrinin fayl quruluşu
Java, HTML, Situs Web, Kotlin, Compose və Python layihələri adi Android layihələri kimi qurulub. app qovluğunun içində src qovluğu, onun içində isə main qovluğu var. main qovluğunun içində java qovluğunun yanında AndroidManifest.xml, layout/activity_main.xml ilə values/strings.xml və values/styles.xml-i əhatə edən res qovluğu, HTML və Situs Web üçün isə index.html-i əhatə edən assets qovluğu (Situs Web-də tentang.html və kontak.html də var) yerləşir. HTML və Situs Web layihələrində də app/src/main/java/<nama-paket>/MainActivity.java daxilində öz MainActivity-si var, o, index.html-i WebView içərisinə yükləyir və AndroidManifest-də işəsalıcı (launcher) olur. Python layihəsinin Python kodu app/src/main/python/main.py daxilində, host MainActivity.java isə app/src/main/java/<nama-paket>/MainActivity.java daxilində yerləşir. AndroidManifest.xml, layout, strings və styles-i MainActivity kimi redaktorda açıb dəyişmək olar. Manifesti hələ app qovluğunun yanında yerləşən köhnə layihələri də yığmaq olar, çünki yığma zamanı tətbiq əvvəlcə app/src/main/ daxilindəki AndroidManifest.xml-i, sonra app qovluğunun yanındakını, ən sonda isə layihə məlumatları faylını yoxlayır.

İcazə qaydaları (vacib)
Layihə yaradılarkən işarələnən icazələr layihə növünə görə yalnız bir yerdə qeyd olunur. Java, HTML, Situs Web, Kotlin, Compose və Python layihələri üçün işarələnən icazələr YALNIZ layihə qovluğunun içindəki java qovluğunun yanında, app/src/main/ daxilində yerləşən AndroidManifest.xml daxilində qeyd olunur. Java, HTML, Situs Web, Kotlin, Compose və Python layihələrinin layihə məlumatları faylında icazələr siyahısı yoxdur. Java seçib INTERNET və CAMERA işarələsəniz, AndroidManifest.xml daxilində başqa icazələr əlavə olunmadan yalnız INTERNET və CAMERA qeyd olunur. Yığma zamanı tətbiq icazələri həmin yerdən oxuyur: Java, HTML, Situs Web, Kotlin, Compose və Python layihələri üçün app/src/main/ daxilindəki AndroidManifest.xml-dən (olmazsa, köhnə layihələr üçün app qovluğunun yanındakı AndroidManifest.xml-dən), köhnə layihələr üçün isə layihə məlumatları faylından.

Redaktordan istifadə qaydası
Kelola Project-i açın, redaktoru açmaq üçün layihə adına toxunun. Redaktorda faylları açmaq, kod yazmaq və dəyişiklikləri saxlamaq olar. Java, HTML, Situs Web, Kotlin, Compose və Python layihələri üçün fayllar app/src/main qovluğunun içində yerləşir. Layihəni paylaşmaq üçün Ekspor ZIP istifadə edin (aşağıdakı bölməyə baxın).

Layihəni işə salmaq qaydası
Redaktorda layihəni sınamaq üçün Jalankan düyməsini basın. HTML və Situs Web layihələri üçün index.html WebView vasitəsilə işə salınır. Xəta baş verərsə, xəta haqqında mesajı oxuyun, kodu düzəldin, sonra yenidən işə salın.

APK yığmaq qaydası
Redaktorda Bangun düyməsini basın. Yığmağın iki yolu var. Birincisi, cihazda yığmaq: HTML, Situs Web, Java, Kotlin və Python layihələri üçün internetsiz birbaşa telefonda yığır. İkincisi, GitHub Actions vasitəsilə onlayn yığmaq: internet vasitəsilə GitHub-da yığır və bütün layihə növləri üçün istifadə oluna bilər. Compose layihələrini yalnız ikinci yolla (Bangun online) və ya Gradle ilə Termux daxilində yığmaq olar, çünki Compose cihazda mövcud olmayan Jetpack Compose kitabxanalarını tələb edir. İlk yığma nəticəsi hələ imzalanmayıb. Sonra tətbiq onu imzalayır: avtomatik olaraq daxili açarla və ya layihə yaradılarkən "Gunakan tanda tangan pribadi" xanası işarələnibsə, şəxsi imza ilə.

APK quraşdırmaq qaydası
APK hazır olduqdan sonra, onu quraşdırmaq üçün Pasang düyməsini basın. Android 8 və yuxarısında telefon əvvəlcə "Izinkan dari sumber ini" icazəsini istəyəcək, çünki bu tətbiq APK-nı Play Store-dan kənarda quraşdırır. Bu icazəni Pengaturan daxilində bir dəfə aktivləşdirin, sonra tətbiqə qayıdın: quraşdırma Pasang düyməsini yenidən basmadan avtomatik davam edəcək. Pasang düyməsi görünmürsə, yığmanın bitdiyini və APK-nın yaradıldığını yoxlayın.

Tətbiqi imzalamaq qaydası
Quraşdırıla bilməsi üçün hər bir APK imzalanmalıdır. İki seçim var. Birincisi, daxili açar: tətbiq heç nə etmədən özü avtomatik imzalayır. İkincisi, şəxsi imza: əvvəlcə əsas menyudakı Buat Keystore menyusu vasitəsilə keystore yaradın, onun parolunu yaxşı saxlayın, sonra layihə yaradılarkən "Gunakan tanda tangan pribadi" xanasını işarələyin. Keystore Download/project/signing daxilində saxlanılır.

Layihəni ZIP kimi ixrac etmək
Ekspor ZIP layihənin dostlarla paylaşıla bilməsi üçün təqdim edilir. Qaydası: Kelola Project daxilində layihə adını uzun basın, sonra Ekspor ZIP seçin. Nəticə Download/project/<NamaProyek>.zip kimi saxlanılır. bin qovluğu daxil edilmir, ona görə ölçüsü kiçikdir, cəmi onlarla KB. Bu ZIP faylı dostlara göndərmək və ya GitHub-a yükləmək olar.

Ekstensi JAWS
Ekstensi JAWS Jieshuo (CSR)-in genişləndirmə mühərrikindən istifadə edir, onun ekran oxuyucusundan deyil. Beləliklə, istifadəçi TalkBack istifadə etsə də dizayn işləyə bilir. Qaydası: əsas menyuda Ekstensi JAWS-i açın. Avtomatik klik özü işlədiyi üçün xidmət əvvəlcə Pengaturan Aksesibilitas daxilində aktivləşdirilməlidir. Sonra yeni dizayn yaratmaq olar: dizayn adını yazın, OK basın, sonra onun xanasını doldurun.

Daftar Klik səliqəli olması üçün ayrılıb
Dizaynın içində iki xana var: skript xanası və Daftar Klik xanası. Düymələr siyahısı daftar_klik.txt faylında ayrıca saxlanılır, hər sətirdə bir ad. Onun məzmununa misal: tombolSimpan, tombolHapus, tombolBuka. Tətbiqi açmaq üçün siyahıya >WhatsApp yazın. Hələ daftar_klik.txt faylı olmayan köhnə dizaynlar bu standart misalı göstərəcək.

Təqdim olunan sadə funksiyalar
• klikTombol("tombolSimpan") — mətni üzrə bir düyməni klikləmək.
• klikDaftarTombol(daftar) — daftar_klik.txt daxilindəki siyahını klikləmək, hər sətirdə bir düymə, ardıcıl, sonra neçəsinin uğurlu olduğunu və neçəsinin tapılmadığını bildirir.
• bukaAplikasi("WhatsApp") — tətbiqi adı üzrə açmaq və ya siyahıya ">WhatsApp" yazmaq.
• klik(540, 1200) — ekran koordinatlarında klikləmək.
Bütün funksiyalar əvvəlcə sadə edilib. Öyrəşdikdən sonra əlavə funksiyaları sonra əlavə etmək olar.

Ekran oxuyucusu haqqında
Bu tətbiq ekran oxuyucusuna uyğun yaradılıb. Hər bir doldurma sahəsinin etiketi və doldurma misalı var və bütün düymələrə mürəkkəb jestlər olmadan çatmaq olar. Ekstensi JAWS istifadəçi TalkBack istifadə etsə də işləyə bilməsi üçün yaradılıb, çünki istifadə olunan onun genişləndirmə mühərrikidir, ekran oxuyucusu deyil.

Məxfilik və təhlükəsizlik
Layihələr və keystore telefonunuzda saxlanılır. GitHub tokeni yalnız onlayn yığmaq üçün istifadə olunur və bu tətbiqin içində saxlanılır. Tokeninizi və ya keystore parolunuzu heç kəslə paylaşmayın. Şəxsi imzadan istifadə edirsinizsə, keystore-u və onun parolunu təhlükəsiz yerdə saxlayın, çünki onlar itərsə, köhnə APK-nı eyni imza ilə yeniləmək mümkün olmayacaq.

Tələblər
Android 5.0 və ya daha yeni. Yaddaş icazəsi: Android 11 və yuxarısında bütün fayllara giriş icazəsi istifadə olunur, Android 10 və aşağısında adi yaddaş icazəsi (yaddaşı oxumaq/yazmaq) istifadə olunur, çünki Android 10-da bütün fayllara giriş icazəsi yoxdur. Cihazda yığmaq ARM prosessorlu (32 və ya 64 bit) telefon tələb edir. GitHub Actions vasitəsilə onlayn yığmaq internet və GitHub tokeni tələb edir. Kotlin layihələrini cihazda yığmaq olar, lakin Kotlin kompilyatorunun ölçüsü böyük olduğu üçün ilk yığma daha yavaşdır və daha çox yaddaş istifadə edir. Compose layihələri GitHub Actions vasitəsilə və ya Gradle ilə Termux daxilində yığılır. Python layihələri Android 7.0 və ya daha yeni (minimum SDK 24) tələb edir və nəticədəki APK Python iş mühitini (Chaquopy) və onun standart kitabxanasını əhatə etdiyi üçün daha böyük olur.

Terminal
Əsas ekrandakı Terminal menyusu bu tətbiqin içində terminal açır. ls kimi əmrlər layihə qovluğunun məzmununu görmək üçün, cd əmri qovluqlar arasında keçmək üçün, git əmri isə kodu idarə etmək üçün istifadə oluna bilər. Əmr çıxışı ekran oxuyucusunun oxuya bildiyi mətn kimi göstərilir və son nəticəni dinləmək üçün Bacakan hasil düyməsi var. Bu terminal telefonun sistem shell-indən istifadə edir, ona görə nano və vim kimi interaktiv proqramlar hələlik burada istifadə oluna bilmir.

Lisensi (ödənişli versiya)
Tətbiqləri satmaq üçün layihə yaradılarkən "Aktifkan Lisensi" xanasını işarələyin, sonra WhatsApp nömrənizi daxil edin. Yığılmış tətbiq ilk dəfə açılanda lisenziya kodu istəyəcək: istifadəçi öz cihazının ID-sini görür, ID Perangkat-i göndərmək üçün Kirim ID Perangkat düyməsini basıb həmin ID-ni sizin WhatsApp-ınıza göndərir, sonra siz onun lisenziya kodunu cavab olaraq göndərirsiniz. Lisenziya kodu cihaz ID-sindən və layihə parolundan (layihə məlumatları faylındakı lisensi_seed) hesablanır — bu parolu yaxşı saxlayın və onu paylaşmayın. Düzgün kod daxil edildikdən sonra tətbiq açılır və kodu yenidən istəmir.

Pencarian dan Filter Proyek
Layihələr çoxalıbsa, Kelola Project daxilində axtarış xanası və növ filtri var. Axtarış xanasına layihə adını yazın, siyahı dərhal filtrlənir (böyük və kiçik hərflər fərqləndirilmir). Növ filtri siyahını yalnız bir növ ilə məhdudlaşdırır: Semua, HTML, Situs Web, Java, Kotlin, Compose və ya Python. Hər bir layihənin menyusunu filtrlənmiş siyahıdan da adəti üzrə açmaq olar.

Səslə Tətbiq Qur
Yazmaq istəmirsinizsə, səsdən istifadə edin: əsas menyuda Səslə qur düyməsini basın, sonra əmr deyin. Deyə biləcəyiniz əmrlər: "Buat proyek kalkulator", "Bangun proyek Kalkulator", "Buka proyek Kalkulator", "Jalankan proyek Kalkulator", "Daftar proyek", "Buka ikon", "Kembali" və "Bantuan". Tətbiq səs və mətnlə cavab verir, ona görə də ekrana baxmadan da istifadə oluna bilər. Səs tanınması telefonun daxili səs tanıma tətbiqindən istifadə edir (pulsuzdur; İndoneziya dil paketi quraşdırılıbsa, oflayn işləyə bilər). Telefonda səs tanınması yoxdursa, əmrlər eyni ekrandakı mətn qutusuna yazıla bilər.

AI tətbiq yaradıcısı
AI tətbiq yaradıcısı ekranında istədiyiniz tətbiqi yazın və ya dikdə edin, məsələn: «yadda saxla düyməsi olan qeyd tətbiqi». Tətbiq telefonun daxilində açar sözləri təhlil edir (internetsiz, pulsuz) və sonra ən uyğun şablondan həqiqi layihə yaradır: kalkulyator, qeydlər, tapşırıq siyahısı, veb kalkulyator, profil saytı və ya sayğac. Təsvirinizə hələ uyğun şablon yoxdursa, tətbiq boş layihə yaradır və bunu dürüst deyir — başa düşürmüş kimi davranmır. AI tərəfindən yaradılmış layihəni Layihələri idarə et bölməsində birbaşa açmaq olar.

Dostun Telefonuna Canlı Önizləmə
Layihəni qurmazdan əvvəl dosta göstərmək üçün: Layihələri idarə et bölməsində layihənin adını uzun basıb, sonra Dostun Telefonuna Önizləmə seçin. Tətbiq layihənin əsas fayllarını (index.html, MainActivity və ya main.py) və təlimatları olan OXU-MƏNİ.txt faylı və info.txt faylını ehtiva edən kiçik önizləmə paketi yaradır. Paket ZIP kimi WhatsApp və ya Telegram vasitəsilə göndərilir. Onu alan dost önizləməni birbaşa aça bilər: HTML səhifələr brauzerdə açılır, Java/Kotlin/Python kodu mətn kimi oxunur.

Layihə bazarı
Layihə bazarı bir toxunuşla layihə qovluğuna quraşdırıla bilən daxili nümunə layihələri ehtiva edir: Kalkulyator, Qeydlər, Tapşırıq Siyahısı, Veb Kalkulyator, Profil Saytı, Sayğac, Rəqəmsal Saat və Veb Viktorina. Onlayn bazar (internetdən nümunələr yükləmək) hələ yoxdur, ona görə də bu bazarda tətbiqdə artıq olan nümunələr var. Quraşdırılmış layihəni Layihələri idarə et bölməsində özünüz yaratdığınız layihə kimi açıb dəyişdirmək olar.

Birbaşa əməkdaşlıq
Dostla birlikdə layihə üzərində işləmək üçün: əsas menyuda Əməkdaşlıq açın, layihəni seçin, dəyişiklik qeydi yazın (nə dəyişdi) və sonra Əməkdaşlıq üçün Paylaş basın. Layihə içində CATATAN.txt faylı olan ZIP kimi göndərilir. Dostunuz onun üzərində işləyir və ZIP-i geri göndərir; siz Cavabı Qəbul Et basırsınız, əvvəlcə dəyişiklik qeydini oxuyursunuz, sonra köhnə layihəni əvəz etmək üçün Tətbiq et və ya peşman olsanız Ləğv et seçirsiniz. CATATAN.txt olmayan ZIP əməkdaşlıq paketi deyil — adi layihə ZIP-i üçün Layihələri idarə et bölməsində Layihəni idxal et istifadə edin.

Avtomatik Tətbiq Tərcüməçisi
Tətbiqin mətnini başqa dilə tərcümə etmək üçün: əsas menyuda Tətbiq tərcüməçisi açın, layihəni və hədəf dili (ingilis, ərəb və ya yava) seçin, sonra Tərcümə et basın. Lüğət artıq telefonun daxilindədir (internetsiz, pulsuz) və gündəlik adi sözləri ehtiva edir; mətn strings.xml, tərtibat və koddan oxunur, sonra tərcümə edilir. Nəticə values-dil/strings.xml qovluğuna (layihədə strings.xml varsa) və layihə qovluğundakı tərcümə-dil.txt hesabatına yazılır. Lüğətdə hələ olmayan sözlər olduğu kimi buraxılır və bildirilir — beləliklə hansı sözləri özünüz tərcümə etməli olduğunuzu bilirsiniz.

Kodsuz Oyun Yaradıcısı

Oyun Layihələri idarə et bölməsində birbaşa işlədilə bilən və hər hansı digər layihə kimi APK kimi qurula bilən həqiqi layihə kimi yaradılır.

Avtomatik Tətbiq Sınağı
Layihəni qurmazdan əvvəl yoxlamaq üçün: Layihələri idarə et bölməsində layihənin adını uzun basıb, sonra Avtomatik Test seçin. IDE APK qurmadan 10 şeyi yoxlayır — məcburi fayllar var (layihə məlumat faylı, manifest, əsas fayl, tərtibat, sətirlər), paket adı və versiyası, istifadə olunan icazələr, ikon və kod mötərizələrinin balansı. Nəticə hər maddə üzrə göstərilir (KEÇDİ/KEÇMƏDİ mesajla) və Jieshuo tərəfindən səslə oxunur. Əvvəlcə KEÇMƏYƏN hər şeyi düzəldin, sonra Layihəni qur basın.

AI Kod Yoxlayıcısı
Layihə kodunu tez-tez problem yaradan nümunələrə görə yoxlamaq üçün: əsas menyuda Kodu yoxla açın, layihəni seçin, sonra Kodu yoxla basın. Yoxlayıcı telefonun daxilində işləyir (internetsiz) və istifadə olunmayan dəyişənləri, boş funksiyaları, açıq-aydın sonsuz dövrləri, birbaşa kodda yazılmış mətni (strings.xml-də daha yaxşıdır), təhlükəli icazələri və API-ləri, TODO/FIXME işarələrini və dinamik icranı axtarır. Hər tapıntıda fayl adı, sətir nömrəsi və düzəliş təklifi var. Bu yoxlayıcı nümunəyə əsaslanır, həqiqi AI deyil — nümunəyə uyğun gəlməyən problemlər yenə də keçə bilər.

İnteraktiv öyrənmə rejimi
Tətbiqlər yaratmağı addım-addım öyrənmək üçün: əsas menyuda Öyrənmə Rejimi açın. 5 dərs var: İlk Layihənizi Yaradın, Düymə Əlavə Edin, Rəngi Dəyişdirin, Səs Əlavə Edin və APK Qurun. Bulud sinxronizasiyası

GitHub ehtiyat nüsxəsi layihə ZIP-ini şəxsi reponuza yükləyir (GitHub parametrlərindən token ilə) və yenidən yüklənə bilər. Avtomatik Backend yaradıcısı
Server kodu yazmadan Backend yaratmaq üçün: əsas menyuda Backend yaradıcısı açın, Backend növünü seçin (Qeydlər, Tapşırıq Siyahısı və ya Elan Lövhəsi), layihənin adını doldurub, sonra Backend Yarat basın. Bu Backend telefonda işləyir; internet serveri olmadığından iki telefon hələ eyni məlumatları paylaşa bilmir.

Avtomatik Tema Dizayneri
Layihəyə rəng mövzusu vermək üçün: əsas menyuda Mövzu dizayneri açın, layihəni və mövzunu seçin (Açıq, Qaranlıq, Mavi, Yaşıl, Qırmızı və ya Bənövşəyi). Animasiya yaradıcısı

Hərəkət yazıcısı

Əsas menyuda Hərəkət yazıcısı açın qeydə alınmış hərəkətlərin siyahısını onların planı ilə görmək üçün, sonra Təkrar Oxut basın — IDE avtomatlaşdırıla bilən hərəkətləri yenidən yerinə yetirir (ehtiyat nüsxə və layihə yaratmaq yerində yerinə yetirilir; işə salmaq, qurmaq və ixrac etmək əsas ekranını açır; açmaq və saxlamaq redaktoru açır). Avtomatlaşdırıla bilməyən hərəkətlər ötürülür və sonda bildirilir.

Avtomatik təhlükəsizlik

Hər tapıntı düzəliş təklifi ilə TƏHLÜKƏSİZ, XƏBƏRDARLIQ və ya TƏHLÜKƏ səviyyəsini alır və xülasə Jieshuo tərəfindən səslə oxunur.

AI oflayn
İnternetsiz mətn və kod köməkçilərindən istifadə etmək üçün: əsas menyuda AI oflayn açın. 4 alət var: Mətni Düzəlt (böyük hərflər, durğu işarələri və qoşa boşluqlar), Mətni Xülasə Et (ən vacib 3 cümləni götürür), Tətbiq Adı Yarat (yazılmış təsvirdən) və Dəyişən Adları Təklif Et (layihədə 1–2 hərfli dəyişən adlarını axtarır). Widget və Divar Kağızı Yaradıcısı

Sosial Media İnteqrasiyası
Tətbiqə paylaşma düymələri əlavə etmək üçün: əsas menyuda Sosial Media İnteqrasiyası açın, layihəni seçin, sonra WhatsApp, Facebook və ya Telegram-a paylaşma əlavə edin (və ya hər üçünü eyni vaxtda). Paylaşma Testi düyməsi IDE-dən nümunə mətnlə paylaşma seçicisini açır ki, tətbiq qurulmazdan əvvəl axını hiss etmək olar.

Şəkildən tətbiq
Şəkildən qalereya tətbiqi yaratmaq üçün: əsas menyuda Şəkildən tətbiq açın və qalereyadan şəkil seçin. Qalereya tətbiqini işə salmaq və ya qurmaq üçün Layihələri idarə et açın.

İnteraktiv terminal (VT analizatoru)
Terminalda interaktiv proqramlardan istifadə etmək üçün: əsas menyuda Terminal açın, sonra nano, vim, top və ya htop işə salın. Terminal indi VT analizatorundan istifadə edir (24 sətir x 80 sütun şəbəkə ekranı), beləliklə bu proqramlar düzgün göstərilir — kursor hərəkət edir, sətirlər silinir və ekran həqiqi terminaldakı kimi dəyişir. İnteraktiv proqramları idarə etmək üçün Tab, Yuxarı Ox, Aşağı Ox və Esc xüsusi düymələri var. Çıxış hələ də Jieshuo-nun oxuya biləcəyi mətndir; son sətri eşitmək üçün Ekranı oxu basın.

Terminal Exec (Tətbiq Binari)
Tətbiq qovluğundakı ikili faylı (məsələn aapt2, ECJ, D8) Terminaldan işə salmaq üçün: əmri həmişəki kimi yazın. IDE libkautsarexec.so istifadə edir ki, tətbiq qovluğundakı ikili fayllar Android 10 və daha yeni versiyalarda işlədilə bilsin. Bu telefonda ikili exec yolunun işlədiyini yoxlamaq üçün Terminalda Exec Testi basın — nəticə olduğu kimi göstərilir. Əgər exec sistem tərəfindən bloklanıbsa, sistem əmrləri və shell skriptləri hələ də işləyir; ikili faylı əvəzinə Layihəni qur menyusu vasitəsilə işə salın.

Terminalı Aktiv Saxla (KeepAlive)
Ekranı dəyişdirərkən shell-i işlək saxlamaq üçün: Terminal açın, əmr işə salın, sonra Geri basın və ya başqa ekrana keçin — shell ÖLMÜR və Terminal bildirişi göstərilməyə davam edir ki, bir toxunuşla qayıda biləsiniz. İcra olunmuş əmrlər tarixdə saxlanılır (Tarixçə düyməsi və ya əmr sahəsində yuxarı/aşağı oxlar) və tez-tez istifadə olunan əmrlər sevimli kimi saxlanıla bilər (Sevimlilər düyməsi). Bitirdikdə shell həqiqətən bitsin deyə Shell-i bağla basın. Layihə menyusunda və redaktor menyusunda Terminalda Qur düyməsi də var: Terminal layihə qovluğunda qurma əmri artıq doldurulmuş halda açılır.

Terminal Alətlərini Quraşdır (Sınaq)
Hələ sınaqdan keçirilən xüsusiyyət: Terminalda tərtibatçının alat-termux repo-sundakı (github.com/syudat/alat-termux) güzgüdən Termux mühiti quraşdırmaq üçün Terminal Alətlərini Quraşdır (Sınaq) düyməsi var, rəsmi Termux buraxılışından götürən Termux Quraşdır düyməsinə əlavə yol kimi. Güzgünün məzmunu rəsmi buraxılışla tam eynidir və quraşdırma zamanı SHA-256 ilə yoxlanılır. Mühit quraşdırıldıqda pkg update və pkg install əmrlərindən istifadə oluna bilər və repodan əlavə alətlər də terminala quraşdırılır: info-terminal mühit məlumatlarını görmək üçün, bersih-terminal keşii təmizləmək üçün və cadangkan-proyek layihə qovluğunu tək tarixli tar.gz faylına arxivləşdirmək üçün. Sonra tətbiq əsas Linux paketlərini (git, python, curl, wget, nano, openssh, zip, unzip) və imzalı APK qurma alətlərini (openjdk-21, kotlin, gradle, ecj, aapt2, d8, apksigner, clang, cmake, ninja, make) rəsmi Termux repo-sundan avtomatik quraşdırır ki, terminal tətbiqlər qurmağa dərhal hazır olsun. Böyük paketləri (yüzlərlə MB) yükləmək uzun çəkə bilər. Quraşdırma işləyərkən irəliləyiş və əmr çıxışı Terminalın əsas ekranında göstərilir və son nəticə ekran oxuyucusu tərəfindən səslə oxunur. Paket quraşdırılması hələ bitməyibsə, davam etmək üçün Terminal Alətlərini Quraşdır (Sınaq) düyməsini yenidən basın.

Tam Səs Rejimi
IDE-ni tamamilə səslə idarə etmək üçün: əsas menyuda Tam Səs Rejimi açın, sonra Dinləməyə Başla basın. IDE fasiləsiz dinləyir — hər əmr üçün düymə basmağa ehtiyac yoxdur — əmri icra edir və səslə cavab verir. 26 əmr var: yarat, qur, aç, işə sal, siyahıya al, axtar, sil, sına, yoxla, ixrac et, ehtiyat nüsxə çıxar, paylaş, ikon yarat, tərcümə et, terminalda qur, ekranı oxu, bütün ekranları aç (təhlükəsizlik, AI oflayn, vidjet, sosial media, oyun, öyrənmə, bulud, backend, mövzu, animasiya, yazıcı daxil olmaqla), geri, bağla və kömək. Rejim aktiv buraxılarsa, bu ekran yenidən açıldıqda dinləmə avtomatik davam edir. Rejimi söndürmək üçün Dinləməni Dayandır basın. Telefonda səs tanıma xidməti yoxdursa, əmrlər yenə də mətn qutusuna yazıla bilər.

Kod tərcüməçisi
Kodu dillər arasında internetsiz tərcümə etmək üçün: əsas menyuda Kod tərcüməçisi açın, layihəni seçin, mənbə faylı (.java/.kt) seçin, sonra istiqaməti seçin: Java-dan Kotlin-ə. Tərcümə et basın — nəticə tərcümə oluna bilməyən sətirlərin hesabatı ilə birlikdə göstərilir (bu sətirlər olduğu kimi saxlanılır və işarələnir). Eyni qovluğa YENİ fayl (ad-tərcümə.java/.kt) yazmaq üçün Nəticəni saxla basın; orijinal fayl heç vaxt üstünə yazılmır. Bu nümunə qayda tərcüməçisidir, kompilyator deyil — istifadə etməzdən əvvəl nəticəni həmişə yoxlayın.

Tətbiqdə Git
IDE-də Termux-suz Git istifadə etmək üçün: əsas menyuda Tətbiqdə Git açın, layihəni seçin, sonra Git Reposu Yarat basın bu layihədə yerli repo (.git) yaratmaq üçün. Son commit ilə müqayisədə yeni, dəyişdirilmiş və ya silinmiş faylları görmək üçün Statusu Yoxla basın; commit mesajını doldurub, sonra layihənin şəklini saxlamaq üçün Commit basın; commit tarixini görmək üçün Commit Loguna Bax basın. GitHub-a Push və GitHub-dan Pull GitHub tokeni vasitəsilə şəkillərdən istifadə edir (pembuat-aplikasi-build repo) — git protokolu deyil. Clone, Push (system-git) və Pull (system-git) yalnız telefonda git ikili faylı quraşdırıldıqda işləyir (adətən yox). Bu tam git deyil: birləşdirmə, budaq və ya fərq yoxdur — hər commit layihənin tam ZIP şəklini saxlayır.

Reklam yaradıcısı
Qurulmuş tətbiqə reklam əlavə etmək üçün: əsas menyuda Reklam yaradıcısı açın, layihəni, təchizatçını (AdMob, Unity Ads və ya AppLovin) və reklam növünü (Banner, Interstitial və ya Mükafatlı) seçin. Əgər artıq varsa, reklam vahidi ID-sini doldurun — boş o deməkdir ki, sınaq ID istifadə olunur (AdMob Google-un rəsmi sınaq ID-sini istifadə edir; Unity nümunə Game ID istifadə edir; AppLovin boş yer istifadə edir). Java və Kotlin kodunu və bələdçini görmək üçün Reklam Kodu Yarat basın; hər şeyi layihədəki reklam-<təchizatçı>-<növ>.txt faylına yazmaq üçün Layihəyə Saxla basın. Bu kod şablonu + bələdçidir, reklam SDK deyil — SDK IDE-yə daxil deyil; həqiqi reklamlar yalnız təchizatçı hesabı yaratdıqda, reklam vahidi yaratdıqda, öz vahid ID-nizi yapışdırdıqda və SDK asılılığını layihənin build.gradle faylına əlavə etdikdə görünür.

Uşaq rejimi
IDE-ni uşaqla birlikdə istifadə etmək üçün: əsas menyuda Uşaq rejimi açın. Ekran böyük düymələrlə sadələşdirilib və yalnız 4 təhlükəsiz hərəkəti var: Layihə yarat (təhlükəsiz şablonlardan: Kalkulyator, Rəqəmi Tap, Viktorina, Ulduzu Tut), Layihəni Aç, İşə Sal və Öyrənmə Rejimi. Bu ekranda silmək, ixrac etmək, ehtiyat nüsxə çıxarmaq və ya token təyin etmək düyməsi yoxdur. İlk girişdə 4 rəqəmli PIN yaradırsınız — bu PIN-dən valideyn Uşaq rejimindən çıxmaq üçün istifadə edir (Uşaq Rejimindən Çıx düyməsi və ya Geri düyməsi). Bu PIN kiçik uşaqlar üçün yüngül qorunmadır, həqiqi təhlükəsizlik deyil.

Wear OS və TV Tətbiq Yaradıcısı
Saat tətbiqi (Wear OS) və ya TV tətbiqi (Android TV) yaratmaq üçün: əsas menyuda Wear OS və TV Tətbiq Yaradıcısı açın və hədəfi seçin (Wear OS, Android TV və ya hər ikisi). Layihənin adını doldurub, sonra Yeni Wear/TV Layihəsi Yarat basın — IDE Java layihəsi yaradır, sonra onu uyğunlaşdırır — və ya mövcud layihəni seçib, sonra Bu Layihəyə Tətbiq Et basın. Uyğunlaşdırmalar: manifestdə uses-feature, TV üçün LEANBACK_LAUNCHER kateqoriyası + banner və uyğunlaşdırılmış activity_main.xml tərtibatı (Wear: kiçik ekran; TV: D-pad-ə uyğun böyük ekran). Tam izah layihədəki wear-tv.txt faylına yazılır. Bu layihə şablonudur — qurma + sınaq üçün hələ Wear OS və ya Android TV cihazı/emulyatoru lazımdır; TV banneri (banner.png 320x180) avtomatik yaradılmır, onu özünüz əlavə etməlisiniz (məsələn, İkon yaradıcısı vasitəsilə).

Layihə xəritəsi
Layihənin strukturunu görmək üçün: əsas menyuda Layihə xəritəsi açın, layihəni seçin, sonra Xəritəni göstər basın — IDE qovluq və faylların siyahısını onların ölçüləri, ümumi ölçü, fayl növünə görə ölçü və vacib fayllar (əsas fayl, manifest, tərtibat, sətirlər, ikon, veb səhifə) ilə göstərir. Eyni xəritəni layihənin kökünə yazmaq üçün peta-proyek.txt-i saxla basın. bin/ qovluğu (qurma nəticəsi) və .git/ qovluğu (yerli repo) xəritəyə daxil edilmir, çünki onların məzmunu yenidən yaradıla bilər.

APK ölçü kalkulyatoru
Qurulmuş APK-nın ölçüsünü qurmadan əvvəl təxmin etmək üçün: əsas menyuda APK ölçü kalkulyatoru açın, layihəni seçin, sonra Təxmini hesablamaq basın. IDE kateqoriya üzrə təfərrüatları göstərir (kod/DEX, resurslar, aktivlər, daxili kitabxanalar, manifest + resources.arsc, əlavə xərclər), ümumi təxmini, ən böyük 5 faylı və kiçiltmə təkliflərini (məsələn, böyük şəkillər ayırdetmədə kiçildilir, böyük səslər uzunluqda kəsilir). Bu TƏXMİNİDİR, dəqiq ölçü deyil — həqiqi ölçü aapt2 sıxılması, istifadə olunmayan kodun silinməsi (R8) və qurma nəticəsinin resursları səbəbindən fərqlənə bilər.

APK analizatoru
Hazır APK-nın məzmununu oxumaq üçün (Android Studio-dakı APK analizatoru kimi): əsas menyuda APK analizatoru açın, layihəni seçin, sonra Yığım Nəticəsi APK Təhlili basın. IDE həmin layihənin bin qovluğundakı ən son APK-nı oxuyur və paket adını, versiyanı, ən aşağı və hədəf SDK-nı, istifadə olunan icazələrin siyahısını, dex fayllarının sayını, hissə üzrə ölçü təfərrüatlarını (proqram kodu, resurslar, aktivlər, daxili kitabxanalar, imza) və ən böyük 10 girişi bildirir. APK-nı hansı hissənin böyük etdiyini və qurulmuş tətbiqin hansı icazələrdən istifadə etdiyini bilmək üçün faydalıdır.

Ekran ölçüsünə önizləmə
Layihənin görünüşünü eyni vaxtda bir çox ekran ölçüsündə yoxlamaq üçün (Android Studio-dakı kimi): əsas menyuda Ekran ölçüsünə önizləmə açın, layihəni seçin, sonra Ekran Ölçüsünü Yoxla basın. IDE layihənin bütün tərtibatlarını oxuyur və eni sabit yazılmış (məsələn 400dp) və 320, 360, 411 və ya 480 dp ekran enini aşan elementləri bildirir, çünki kiçik ekranlı telefonda belə element örtülə və ya daşa bilər. match_parent və ya wrap_content eni olan elementlər ekrana avtomatik uyğunlaşır və yoxlanılmağa ehtiyac yoxdur.

Resurs meneceri
Layihənin bütün resurslarını bir yerdə görmək və idarə etmək üçün (Android Studio-dakı Resurs meneceri kimi): əsas menyuda Resurs meneceri açın, layihəni seçin, sonra Resurslara Bax basın. IDE fayl sayını və ölçüsünü kateqoriya üzrə (drawable, layout, values, mipmap və digərləri), strings.xml, colors.xml və styles.xml məzmununu bildirir. Eyni ekrandan ad və dəyər doldurmaqla strings.xml-ə yeni sətir və colors.xml-ə yeni rəng əlavə etmək olar — ad yoxlanılır və təkrarlar rədd edilir ki, XML faylı zədələnməsin.

Yüngül performans monitoru
İşləyən tətbiqin RAM və prosessor istifadəsini izləmək üçün (Android Studio-dakı Profiler kimi, yüngül versiya): əsas menyuda Yüngül performans monitoru açın, əvvəlcə yoxlamaq istədiyiniz tətbiqi işə salın (məsələn, sınaqdan keçirilən qurulmuş tətbiq), onun paket adını doldurun — və ya layihə seçib, sonra Layihədən Paket Adını Doldur basın — sonra İzləməyə Başla basın. Hər iki saniyədə IDE həmin tətbiqin RAM (PSS) və CPU-sunu telefonun boş RAM-ı ilə birlikdə qeyd edir; orta və zirvənin xülasəsini görmək üçün Dayandır basın. Əlavə icazə yoxdur. Android-ın yeni versiyalarında başqa tətbiqin prosessoruna oxuma girişi sistem tərəfindən məhdudlaşdırılır, ona görə də CPU oxuna bilmirsə, hesabat bunu olduğu kimi deyir və RAM izləmə davam edir.

Əlçatanlıq Auditi
Layihəni buraxmazdan əvvəl onun düzəninin ekran oxuyucuları (TalkBack/Jieshuo) üçün uyğun olub-olmadığını yoxlamaq üçün: əsas menyuda Əlçatanlıq Auditi bölməsini açın, layihəni seçin, sonra Düzən Siyahısını Yüklə düyməsini basın və düzən faylını seçin. IDE həmin XML faylını oxuyur və etiketsiz düymələri sətir nömrələri ilə birlikdə, təkrar-təkrar istifadə olunan etiketləri və bir-birini üst-üstə düşən elementləri bildirir, sonra Jieshuo-nun ucadan oxuduğu kimi fokus sırasının transkriptini qurur. Düymənin etiketi yoxdursa, etiketini doldurun, sonra Etiketi Avtomatik Əlavə Et düyməsini basın — etiket düzən faylına contentDescription kimi yazılır. Bu yoxlama yalnız düzən XML-ni oxuyur; Compose görünüşləri və hazır APK-lar hələ skan edilmir.

Qəza Autopsiyası
Unikal ID ilə çökmə jurnalından tətbiqin niyə özünü bağladığını öyrənmək üçün: əsas menyuda «Qəza Autopsiyası» açın, jurnal siyahısından çökmə ID-sini seçin, sonra «Yoxlayın» düyməsini basın. IDE jurnalda sinif və sətir nömrəsini layihə mənbəyi ilə uyğunlaşdırır və səbəbi İndoneziya dilində izah edir (məsələn, boş istinad, hələ istənilməmiş icazə və ya JSON xətası), kod yama təklifi ilə. «Yamanı Tətbiq Et» düyməsini yalnız mənbə sətri çökmə baş verdiyi kimi hələ olduqda basın; dəyişibsə, yama rədd edilir və IDE sizdən özünüz yoxlamağı xahiş edir. Qurulmuş tətbiqin çökmələri üçün «Çökmə Tutucusunu Layihəyə Daxil Edin» düyməsini basın, sonra APK-ni həmişəki kimi yığın: qurulmuş tətbiq öz çökmələrini tutur və jurnalını telefonda yazır və həmin jurnal «Yığılmış Tətbiq Çökmə Jurnalını Tap» düyməsi ilə tapıla bilər. Dürüst məhdudiyyət: jurnalı Android 11 və yuxarıda ictimai Download qovluğuna köçürmək bütün fayllara giriş icazəsi olmadan uğursuz ola bilər.

Paradigmalararası Transpiler
Sadə Java kodunu Kotlin-a və ya sadə XML düzənini Compose koduna çevirmək üçün: əsas menyuda Paradigmalararası Transpiler bölməsini açın, layihə və fayl seçin, sonra Önizləmə düyməsini basın. IDE çevirmə nəticəsini mətn kimi göstərir — əvvəlcə onu yoxlayın, çünki tanımadığı sətirlər olduğu kimi qalır, Java-dakı static sözü isə Kotlin-da buraxılır (istifadə etməzdən əvvəl mənasını yoxlayın). XML-dən Compose-a çevirmə yalnız mətni, işarələri və istiqaməti dəyişir — ölçü, rəng və digər atributlar hələ daxil edilməyib. Nəticə düzgündürsə, hədəf faylı yazmaq üçün Fayla Tətbiq Et düyməsini basın; mənbə faylı dəyişmir. Yalnız təhlükəsiz, adi nümunələr çevrilir.

Yerli Mikro Server
İnternetsiz server tələb edən tətbiqi sınaqdan keçirmək üçün: əsas menyuda «Yerli Mikro Server» açın, marşrut tərifləri yazın (məsələn, GET /halo, ardınca onun JSON cavabı) sonra «Serveri Başlat» düyməsini basın. IDE eyni telefonda kiçik HTTP server işlədir (yalnız HTTP, TLS yoxdur, eyni Wi-Fi şəbəkəsi üçün) və hər sorğu və cavabı ekranda qeyd edir. Marşrutlar {nama} kimi parametrlərdən və sadə API açarından istifadə edə bilər. Server qurulmuş APK-də də qablaşdırıla bilər: «Serveri layihəyə sarın» düyməsini basın və server mənbəyi, aktivləri və manifesti layihəyə daxil edilir, beləliklə qurulmuş tətbiq işləyərkən özü server olur. IDE-dəki server ekranı bağlandıqda dayanır.

Təhlükəsizlik Auditoru
Nəşrdən əvvəl layihə kodunu təhlükəsizlik boşluqları üçün yoxlamaq üçün: əsas menyuda «Təhlükəsizlik Auditoru» açın, layihəni seçin, sonra «Skanı Başlat» düyməsini basın. IDE layihə kodunu, manifesti və konfiqurasiyanı skan edir və yüksəkdən aşağı riskə qədər tapıntıları bildirir — kodda açıq qalmış API açarı, icazəsiz ifşa edilmiş komponent, JavaScript interfeysi ilə JavaScript-i aktivləşdirən WebView, zəif kripto (MD5, SHA1, DES), TLS olmadan http ünvanı və kodda birbaşa yazılmış parol — faylları və sətir nömrələri ilə. Düzəlişi təhlükəsiz olan tapıntılar üçün (məsələn, MD5-i SHA-256-ya və ya http-ni https-ə dəyişdirin) «Düzəlişi Tətbiq Et» düyməsini basın; API açarları və parollar üçün IDE yalnız düzəliş təklifini göstərir, çünki əvəzetməni tərtibatçının özü qərar verməlidir. Skan indi qurulmuş APK daxilində real DEX baytkodunu da təhlil edir (yalnız kodda mətn nümunələri deyil), beləliklə çağırılan təhlükəli API-lər və DEX-ə daxil edilmiş sirlər də tutulur; nümunəni izləməyən boşluqlar hələ skandan qaça bilər — tətbiq etməzdən əvvəl yoxlayın.

İnterfeysi Sınayan Robot
Mətn ssenariləri vasitəsilə tətbiq ekranını avtomatik sınaqdan keçirmək üçün: əsas menyuda «İnterfeysi Sınayan Robot» açın, layihəni seçin, sonra «Ssenarini Avtomatik Yarat» düyməsini basın. IDE layihə manifestini və düzülüşünü oxuyur və ssenarini mətn addımları kimi yazır (düyməni basın, sahəni doldurun, gözləyin, geri qayıdın). Ssenarinin icra jurnalını onun vaxt möhürləri ilə görmək üçün «Dry Run İşə Sal» düyməsini basın — bu dry run hələ yalnız ardıcıllığın simulyasiyasıdır. Real sınaq üçün «Test agentini layihəyə daxil edin» düyməsini basın: IDE ssenari aktivləri ilə test agentini layihəyə daxil edir; APK-ni həmişəki kimi yığın, quraşdırın, sonra «Test» nişanını açın — agent qurulmuş tətbiqin içərisində işləyir və həqiqətən düymələri basır, real sahələri doldurur və sürüşdürür, sonra hesabatını ekranda tutulmuş real çökmələrlə göstərir. Agenti yenidən çıxarmaq üçün «Test agentini layihədən çıxarın» düyməsini basın. Agent tətbiqin öz prosesi daxilində işləyir, ona görə əlçatanlıq xidməti və ya sistem avtomatlaşdırması lazım deyil.

Kod Zamanı Səyahəti
Git əmrləri yazmadan layihəni əvvəlki kod vəziyyətinə qaytarmaq üçün: əsas menyuda Kod Zamanı Səyahəti bölməsini açın, layihəni seçin, vaxt nöqtəsi üçün etiket doldurun (boş qala bilər), sonra Vaxt Nöqtəsini Qeyd Et düyməsini basın. IDE layihənin mənbə fayllarının surətini onların hash dəyərləri ilə birlikdə layihənin içindəki .riwayat qovluğuna saxlayır. Vaxt nöqtələrinin siyahısı hamısını göstərir; iki nöqtə seçin, sonra əlavə edilmiş, dəyişdirilmiş və ya silinmiş faylları və funksiyaları görmək üçün Müqayisə Et düyməsini basın. Köhnə vəziyyəti qaytarmaq üçün Bərpa Et düyməsini basın — bərpadan əvvəl IDE həmişə əvvəlcə cari vəziyyətin ehtiyat nüsxəsini yaradır, ona görə də heç nə itmir. Layihəni yeni qovluğa köçürmək və orijinal layihəni narahat etmədən dəyişiklikləri sınamaq üçün Təcrübə Nüsxəsi Yarat düyməsini basın. Yalnız mənbə faylları qeyd edilir.

Modul Fabriki
Layihənin bir hissəsini başqa layihənin istifadə edə biləcəyi modul kimi yığmaq üçün: əsas menyuda Modul Fabriki bölməsini açın, mənbə layihəni seçin, yığılacaq ekran, sinif, sətir və icazə fayllarını işarələyin, sonra Modul kimi Yığ düyməsini basın. IDE JSON metadataları ilə birlikdə ZIP arxivi yazır (modul adı, versiyası, istifadə olunan sətirlər və icazələr). Modulu başqa layihəyə quraşdırmaq üçün Modul Fabriki bölməsini açın, hədəf layihəni seçin, sonra Modulu Quraşdır düyməsini basın və modulun .zip faylını seçin — birləşmə sətirləri və icazələri mövcud kodu üzərinə yazmadan əlavə edir və adı hədəf layihədə artıq istifadə olunan faylı birləşdirmir. Modul nə kitabxanaları, nə də qurma parametrlərini özü ilə aparmır.

Polimorf qalxan və aktivlər anbarı
Nəşrdən əvvəl identifikator adlarını təsadüfi dəyişdirmək və layihə aktivlərini şifrələmək üçün: əsas menyuda «Polimorf qalxan və aktivlər anbarı» açın, layihəni seçin, sonra «Adları təsadüfi dəyişdirin və aktivləri şifrələyin» düyməsini basın. IDE mənbə kodundakı sinif və metod adlarını skan edir, təsadüfi ad xəritəsi yaradır, bu adları tərtib edilmiş DEX fayllarının içərisində yenidən yazır (əvəzedici adlar bütün sürüşmələrin etibarlı qalması üçün orijinallar qədər uzun edilir, sonra DEX başlığının yoxlama cəmi və SHA-1 imzası yenidən hesablanır), layihə aktiv fayllarını layihə daxilindəki brankas-aset qovluğunda AES-GCM ilə şifrələyir və çökmə jurnallarını oxuyarkən orijinal adların bərpa edilə bilməsi üçün şifrələnmiş bərpa xəritəsini (perisai-peta.brankas) saxlayır. Şifrələmə açarı indi layihə adından deyil, tərtibatçının parolundan PBKDF2, 20 000 təkrarlama ilə əldə edilir. Düz mətn, annotasiya adı və sazlama adı kimi də istifadə olunan adlar qəsdən yenidən yazılmır və yığma yolundakı DEX yenidən yazma daxiletmə nöqtələri hələ real telefonda sınağı gözləyir.

Etibar zənciri və mühit qoruyucusu
Nəşrdən əvvəl imza açar zəncirini və telefon mühitini yoxlamaq üçün: əsas menyuda «Etibar zənciri və mühit qoruyucusu» açın, layihəni seçin, sonra «Zəncir və mühiti yoxlayın» düyməsini basın. IDE layihənin paket adından 5 nəsil açar zənciri qurur və onun bütövlüyünü yoxlayır, yaddaşdakı kod seqmentlərinin məzmununu diskdəki fayllarla müqayisə edərək real yaddaş bütövlüyünü yoxlayır və adsız icra edilə bilən (RWX) xəritələri, xarici kitabxanaları və memfd xəritələrini bildirir, sonra öz proses yaddaş xəritəsini və cihaz xüsusiyyətlərini Frida, Xposed və ya emulyator izləri üçün skan edir. Anbar açarı mövcud olduqda avadanlıq təhlükəsizlik çipindən istifadə edən AndroidKeyStore-dakı AES açarı ilə bükülür və açar fırlanması indi v3 sxem imza sertifikatı nəsil xətti ilə realdır: köhnə açar yeni açara fırlanma sübutunu imzalayır və APK həmin nəsillə yenidən imzalanır. Nəticə mətn sübutu ilə «təhlükəsiz», «ehtiyatlı» və ya «təhlükəli» risk səviyyəsidir. Sistem yaddaş oxunuşunu rədd edərsə, yoxlama «yoxlanıla bilməz» kimi bildirilir, təhlükəsiz deyil; və açarın həqiqətən avadanlıq təhlükəsizlik çipindən istifadə edib-etmədiyini yalnız real cihazda təsdiqləmək olar.

Mətn ağacı düzülüş memarı
Ekranı görmədən dizayn etmək üçün: əsas menyuda «Mətn ağacı düzülüş memarı» açın, layihəni və düzülüş faylını seçin, sonra «Düzülüşü yoxlayın» düyməsini basın. IDE XML düzülüşünü mətn ağacı kimi oxuyur və hər elementin mövqe təsvirini ucadan oxuyur (məsələn, aşağı sağda, ekran eninin 45 faizi) sonra elementlər arasında üst-üstə düşmələri və 360 dp enində ekrandan kənara çıxan elementləri riyazi olaraq bildirir. İndi sayılanlar LinearLayout və sadə dp ölçüləri, tam ConstraintLayout (bütün məhdudiyyətlər, meyl, zəncirlər, bələdçilər, maneələr, faiz enləri, 0dp match_constraint və ölçü nisbətləri) və Compose ekranlarıdır (Column, Row və Box ölçü dəyişdiriciləri ilə). Yalnız işləmə zamanı dəyişən MotionLayout və ConstraintSet hələ naməlum mövqe kimi bildirilir, çünki onların dəyərləri yalnız tətbiq işləyərkən mövcuddur.

Dizayn sistemi studiyası
Bütün ekranlarda və layihələrdə məsafələri, şriftləri və küncləri vahid etmək üçün: əsas menyuda «Dizayn sistemi studiyası» açın, layihəni seçin, dizayn tokenlərini yazın (məsələn jarak=8, huruf=16, sudut=12), komponent seçin, sonra «Komponentlər yaradın» düyməsini basın. IDE tokenləri yoxlayır — əsas məsafə 4-dən 16 dp-ə qədər, əsas şrift 12-dən 20 sp-ə qədər, künclər 0-dan 32 dp-ə qədər və minimum toxunma sahəsi 48 dp — sonra istifadəyə hazır XML komponentlərini (komponen-studio.xml) XML mövzusu (tema-studio.xml) və Compose mövzusu (tema-studio.kt) ilə layihə qovluğunda yazır. Tokenlər layihələr arasında paylaşılan token kitabxanasında adlı dəst kimi də saxlanıla bilər və tək sinxronlaşdırma əmri kitabxananın ən son tokenlərini həmin dəstdən istifadə edən bütün layihələrə tətbiq edir. Komponentlər düzülüşə yapışdırılan və sonra «Mətn ağacı düzülüş memarı» ilə yoxlanılan mətn kimi yaradılır; planşetdə iki sütunlu tənzimləmə işləyərkən cihaz identifikasiyası əvəzinə ekran eni keyfiyyətindən istifadə edir.

Semantik refaktorinq və AST naviqasiyası
Tərifləri tapmaq və simvol adlarını təsadüfən eyni adı olan başqa kodu qırmadan dəyişdirmək üçün: əsas menyuda «Semantik refaktorinq və AST naviqasiyası» açın, layihəni seçin, sonra bütün sinifləri və metodları faylları və sətir nömrələri ilə görmək üçün «Layihə simvollarını skan edin» düyməsini basın. Simvol adını yazın, sonra onun tərifini və onu çağıran bütün faylları görmək üçün «Layihə simvollarını skan edin» düyməsini yenidən basın. Adını dəyişdirmək üçün yeni adı yazın, hər faylda baş vermə sayını görmək üçün «Ad dəyişikliyinə baxış» düyməsini basın, sonra «Ad dəyişikliyini tətbiq et» düyməsini basın. İndeks indi əl ilə qurulmuş AST parserindən istifadə edir (Java və Kotlin alt çoxluğu üçün lekser və rekursiv parser), buna görə fayllar arasında metod ad dəyişiklikləri həll edilir və digər fayllardakı çağıranlar da dəyişir; kod blokunu yeni funksiyaya çıxarma düyməsi indi bu ekrandadır. Bu parser hələ minimaldır: çox mürəkkəb generiklər, parametrli annotasiyalar və anonim siniflər olduğu kimi skan edilir, refleksiya və interfeys vasitəsilə çağırışlar isə həll edilmir.

Addım-addım sazlayıcı və yaddaş yoxlayıcısı
Jurnallardan təxmin etmədən proqram axınının ortasında dəyişən məzmununu yoxlamaq üçün: əsas menyuda «Addım-addım sazlayıcı və yaddaş yoxlayıcısı» açın, layihəni seçin, icra izi yazın (hər sətirə bir addım, format sətir nömrəsi, kod, sonra | ilə ayrılmış dəyişənlər və dəyərlər, məsələn 10|int total = harga * jumlah;|harga=5000, jumlah=3, total=15000), kəsmə nöqtəsi sətir nömrəsini yazın, sonra «Sazlama izini yerinə yetirin» düyməsini basın. IDE ilk kəsmə nöqtəsinə qədər işləyir və aktiv sətri Jieshuo vasitəsilə dəyişən dəyərləri ilə ucadan oxuyur. Bir sətir irəli getmək üçün «Bir sətirlik addım» düyməsini basın, çağırılan funksiyaya daxil olmaq üçün «Funksiyaya daxil olun» düyməsini basın (çağırış yığını ilə) və ya növbəti kəsmə nöqtəsinə keçmək üçün «Proqramı davam etdir» düyməsini basın. Bu iz sazlayıcısı hələ qeydə alınmış və ya əl ilə yazılmış izi izləyir; onun yanında JDWP tel protokolu üçün təmiz Java müştərisi var ki, əl sıxışa, kəsmə nöqtələri qoya, içəri, üstündən və bayıra addımlaya və TCP vasitəsilə və ya dinləmə rejimində VM-ni dayandırıb davam etdirə bilər. Adi tətbiqin içindən real prosesi dayandırmaq hələ tam mümkün deyil, çünki prosesin JDWP soketi yalnız adbd vasitəsilə açılır — sübut edilmiş yol simsiz sazlama və hədəfi qabıq vasitəsilə başlatmağı tələb edir ki, bu da tətbiqin özünün edə biləcəyindən kənardır.

Oflayn asılılıq meneceri
İnternetsiz üçüncü tərəf kitabxanalarından istifadə etmək və yığmadan əvvəl versiya ziddiyyətlərindən qaçmaq üçün: əsas menyuda «Oflayn asılılıq meneceri» açın, layihəni seçin, sonra «Asılılıqları yoxlayın» düyməsini basın. IDE layihənin bütün .gradle fayllarını oxuyur, Download/brankas-bersama qovluğunda layihələr arasında paylaşılan anbarı yoxlayır və ziddiyyətləri həll edir — iki kitabxana eyni artefaktın fərqli versiyalarını istəsə, ən yüksək versiya istifadə olunur və ziddiyyət bildirilir. Kitabxana yükləmək üçün onun koordinatlarını yazın (format qrup:artefakt:versiya, məsələn com.google.code.gson:gson:2.10.1) sonra «Asılılıqları yoxlayın» düyməsini basın: onlayn olduqda AAR, JAR və ya WHL faylları həqiqətən Maven, Google və ya PyPI-dən onların keçid asılılıq qrafı ilə (rekursiv, dövrlər qırılır, dərinlik 25 səviyyəyə qədər) yüklənir və yalnız uğurla yüklənmiş fayllar mövcud kimi qeyd olunur. Oflayn olduqda yalnız paylaşılan anbarda artıq mövcud olan kitabxanalardan istifadə etmək olar. Maven versiya diapazonları həll edilmir və yüklənmiş fayllar yalnız SHA-1 ilə yoxlanılır, PGP yoxlaması olmadan.

Verilənlər bazası və saxlama yoxlayıcısı
Cədvəl məzmununu çap edən kod yazmadan layihə verilənlər bazasının məzmununu yoxlamaq və sınaqdan keçirmək üçün: əsas menyuda «Verilənlər bazası və saxlama yoxlayıcısı» açın, layihəni və verilənlər bazası faylını (.db, .sqlite və ya .sqlite3) seçin, sonra «Verilənlər bazasını açın» düyməsini basın. IDE onun bütün cədvəllərinin sxemini tam SQLite səhifə parseri (daşma səhifələri ilə B-ağacı) ilə oxuyur və ilk 20 sətri Jieshuo-nun ucadan oxuduğu mətn cədvəli kimi göstərir. SELECT sorğusu yazın və «Sorğunu yerinə yetirin» düyməsini basın (məsələn SELECT nama FROM pengguna WHERE kota = 'Makassar') — sorğular indi JOIN, GROUP BY, ORDER BY və LIKE dəstəkləyir və telefondakı real Android SQLite mühərriki ilə işlədilir. Dəyəri dəyişdirmək üçün sətir nömrəsini (1 = birinci sətir), sütun adını və yeni dəyəri yazın, sonra «Xana dəyərini dəyiş» düyməsini basın — dəyər .db faylına geri yazılır. Cədvəlin cari vəziyyətini layihədə <verilənlər-bazası-adı>.cadangan.txt faylı kimi saxlamaq üçün «Ehtiyat nüsxəni saxla» düyməsini basın. SharedPreferences və DataStore də oxuna bilər. Hələ oxuna bilməyənlər: şifrələnmiş verilənlər bazaları, təsdiqlənməmiş WAL dəyişiklikləri və ixtisaslaşdırılmış DataStore Proto-dakı tipli dəyərlər (yalnız ümumi sahə görünüşü kimi göstərilir).

Vahid test fabriki və fuzzing
Tətbiqi paylaşmadan əvvəl məntiq boşluqlarını tapmaq üçün: əsas menyuda «Vahid test fabriki və fuzzing» açın, layihəni və kod faylını seçin, sonra «Testlər yaradın və yerinə yetirin» düyməsini basın. IDE fayldakı funksiya imzalarını oxuyur, adi və sərhəd test halları yaradır (boş mətn, null, maksimum rəqəmlər, qəribə simvollar) sonra həqiqətən bu testləri yerinə yetirir: layihə kodu tərtib edilir və hər @Test metodu 5 saniyəlik limitlə icra olunur, buna görə nəticə onların real dəyərləri ilə real keçidlər və uğursuzluqlardır. Fuzzing də layihə funksiyaları üzərində həqiqətən işlədilir (refleksiya vasitəsilə, hər çağırışa 2 saniyə, maksimum 20 metod) və sətir əhatə faizi orijinal sətir nömrələrini qoruyan alətləşdirmə vasitəsilə həqiqətən hesablanır. Nəticə neçə testin keçdiyini və uğursuz olduğunu, neçə kod sətri və funksiyanın tapıldığını və hansı test hallarının yaradıldığını bildirir. Yaradılmış testlər JUnit ilə tam eyni API-dən istifadə edir, lakin annotasiya və iddia tərifləri yaradılmış test faylının içərisində yazılır, çünki real JUnit kitabxanası tətbiqə daxil edilməyib.

Cihazın ekstremal vəziyyət simulyatoru və yaddaş sızması auditoru
Sistem onun prosesini öldürdükdə, şəbəkə kəsildikdə, ekran fırlandıqda və ya batareya qənaəti işə salındıqda tətbiqin dözümlülüyünü sınaqdan keçirmək üçün: əsas menyuda «Cihazın ekstremal vəziyyət simulyatoru və yaddaş sızması auditoru» açın, layihəni seçin, sonra «Simulyasiyanı yerinə yetirin» düyməsini basın. IDE simulyasiya edilmiş ekran fırlanması ilə üç stress ssenarisini işlədir və ekranları bağlandıqdan sonra belə yaddaşda saxlanılan obyektləri izləyir, sonra itirilmiş məlumatları və sızan obyekt zəncirlərini bildirir. Saxlama və bərpa vəziyyəti indi sabit nümunədən deyil, istifadəçinin öz layihə mənbəyindən oxunur; yerli loopback server şəbəkə kəsilməsini ölçmək üçün sınağın ortasında həqiqətən dayandırılır; real heap dump alınır və təhlil edilir, iki dump müqayisə edilir və saxlama zənciri GC köklərindən izlənilir; və tətbiqin öz prosesi vəziyyəti saxlanıldıqdan sonra həqiqətən öldürülür, sonra yenidən açılanda hansı məlumatların qayıtdığı yoxlanılır. Adi tətbiqdən hələ mümkün olmayanlar: telefon radiosunu və ya Wi-Fi-ni söndürmək və digər tətbiqləri məcburi dayandırmaq — hər ikisi sistem icazəsi tələb edir; bunun əvəzinə fon tətbiqləri killBackgroundProcesses vasitəsilə öldürülür, icazəsi artıq manifestdədir, ekranda dürüst etiketlə.

Layihə planı memarı
Böyük tətbiq ideyasını addım-addım iş planına çevirmək üçün: əsas menyuda «Layihə planı memarı» açın, layihəni seçin, tətbiq ideyasını yazın (məsələn, hissə-hissə ödənişli kiçik ərzaq mağazası kassa tətbiqi) sonra «Plan yaradın» düyməsini basın. IDE modullar, fayl siyahısı və kiçik mərhələlər qurur, sonra onları layihə qovluğunda cetak-biru.txt kimi saxlayır. Mərhələ tamamlandıqca «Növbəti mərhələni tamamlandı kimi işarələyin» düyməsini basın və ya saxlanılmış planı yenidən açmaq üçün «Saxlanılmış planı yüklə» düyməsini basın. Aktiv AI provayderi «AI parametrləri» bölməsində seçilibsə və açarı mövcuddursa, plan həmin provayder tərəfindən qurulur; açar yoxdursa və ya provayderə çatmaq mümkün deyilsə, IDE oflayn açar söz nümunələrinə qayıdır və bu məhdudiyyəti dürüst deyir. Provayderin cavabı yalnız format üçün yoxlanılır (modullar və mərhələlər mövcuddur), məzmun həqiqəti üçün deyil — qurmazdan əvvəl həmişə planı nəzərdən keçirin.

Kod məntiqi axını rəvayətçisi
Sintaksisi sətir-sətir dinləmədən uzun kodu başa düşmək üçün: əsas menyuda «Kod məntiqi axını rəvayətçisi» açın, layihəni və kod faylını seçin, sonra «Kod rəvayəti» düyməsini basın. IDE hər sətri İndoneziya cümləsinə çevirir (məsələn, cəmi 100000-dən çoxdursa, növbəti bloku yerinə yetirin), metodlar arasında çağırış xəritəsi və metodlar arasında məlumat axını təhlili (ötürülən, istifadə olunan və ya nəzərə alınmayan dəyərlər) göstərir və incə potensial səhvləri sətir nömrələri ilə işarələyir — == ilə müqayisə edilən String, bağlanmadan açılan axın və iki fərqli metodda yazılan dəyişən. Aktiv AI provayderi «AI parametrləri» bölməsində seçilibsə, həmin provayderdən axın xülasəsi də mövcuddur; yoxdursa, ekran oflayn rəvayətdən istifadə edir və bu məhdudiyyəti deyir. Rəvayət, çağırış xəritəsi və məlumat axını tam AST parseri deyil, oflayn mətn nümunəsi təhlilindən istifadə edir — açılış mötərizəsi öz sətrində olan metodlar, sinif sahələri və refleksiya vasitəsilə çağırışlar izlənilmir — və məlumat yarışı xəbərdarlıqları əslində yalnız növbə ilə istifadə olunan dəyişən üçün görünə bilər.

Tətbiq dəsti fabriki və Play Store hazırlığı
Tətbiqi birbaşa telefondan Google Play Store üçün hazırlamaq üçün: əsas menyuda «Tətbiq dəsti fabriki və Play Store hazırlığı» açın, layihəni seçin, sonra «AAB dəstini yaradın» düyməsini basın. IDE real BundleConfig.pb ilə layihə manifestindən, resurslardan və aktivlərdən .aab faylını qurur, dəst strukturunu yoxlayır, sonra dəsti real variant APK-lərinə bölür (əsas, arxitekturaya görə, dilə görə və universal) həmin bölünmədən ölçülən ölçülərlə, təxminlər deyil. Dəst APK imzası üçün istifadə olunan eyni layihə açarı ilə JAR v1 ilə imzalanır və imza zənciri kriptoqrafik olaraq yoxlanılır. Bu ekran Play hazırlığını da yoxlayır — 35-dən aşağı hədəf SDK «yüksək» kimi işarələnir, çünki Play Store 35 və ya daha çox tələb edir və itkin 64 bitlik kitabxana da «yüksək» kimi işarələnir. Real bundletool cihazda işləyə bilməz, çünki bundletool JVM tələb edir, Android-da isə JVM yoxdur; yuxarıdakı yol cihazda ən yaxın real yoldur.

OTA yeniləmə mühərriki və mərhələli buraxılışlar
İstifadəçiləri bütün APK-ni yenidən yükləməyə məcbur etmədən kiçik düzəliş göndərmək üçün: əsas menyuda «OTA yeniləmə mühərriki və mərhələli buraxılışlar» açın, layihəni seçin, köhnə və yeni versiya məzmununu yazın, sonra «Yama dəsti yaradın» düyməsini basın. IDE fərqi hesablayır və yeni məzmunun SHA-256 barmaq izi ilə yama dəsti (patch-ota.zip) yaradır, sonra bu cihazın ilk 10 faizlik buraxılış addımında olub-olmadığını yoxlayır. Yamalar indi istənilən faylda ikili delta dəstəkləyir (DEX və APK daxil olmaqla), RSA-2048 imzası ilə qablaşdırılır və tətbiq edilməzdən əvvəl etibarlı açıq açarla yoxlanılır və tərtibatçının serverindən onun buraxılış siyahısı ilə yüklənə bilər; tətbiq uğursuz olarsa, köhnə fayl toxunulmaz qalır. İşləyən tətbiqə yama tətbiq etmək layihə açarı ilə yenidən imzalamaq və PackageInstaller vasitəsilə edilir, çünki işləyən prosesin kodunu öz içindən əvəz etmək mümkün deyil — APK kilidlidir və DEX artıq yüklənib.

Komanda kod baxış studiyası
Həmkarın dəyişikliklərini nəzərdən keçirmək və Git oxlarını oxumadan birləşmə ziddiyyətlərini həll etmək üçün: əsas menyuda «Komanda kod baxış studiyası» açın, layihəni seçin, üç mətn versiyası yazın (əsas, yerli, həmkar) sonra «Komanda baxışını açın» düyməsini basın. IDE üçünü Java sintaksis vahidləri əsasında birləşdirir — eyni sətirdə iki dəyişiklik, lakin fərqli ifadələrdə artıq ziddiyyət sayılmır — və hər ziddiyyəti səsvermə seçimi kimi göstərir: yerli versiyadan istifadə edin, həmkar versiyasından istifadə edin və ya hər ikisini birləşdirin — nəticə sətri sətir sırası düzgün qalması üçün orijinal ziddiyyət mövqeyinə daxil edilir — sonra nəticəni layihədə gabung-hasil.txt faylına yazır. Aşağıda layihənin iş lövhəsi var: tapşırıq başlığı yazın, sonra «Tapşırıq əlavə edin» düyməsini basın; tapşırıqlar layihə daxilindəki .tugas qovluğunda mətn kimi saxlanılır və tətbiq daxilindəki Git-də commitlər vasitəsilə sinxronlaşdırılır, beləliklə lövhə istənilən commit tarixindən yenidən oxuna bilər. Bu sintaksis bölünməsi tam AST parseri deyil və tətbiq daxilindəki Git hər commit üçün tam anlıq görüntü saxlayır; ayrı sinxronlaşdırma serveri yoxdur.

Kod Strukturu Diktəsi
Redaktorun içində səslə kod yazmaq üçün: layihəni Redaktorda açın, sonra Kod Strukturu Diktəsi düyməsini basın. Əmrləri indonez dilində deyin, məsələn buat fungsi tambah dengan parameter a angka dan b angka, buat kelas Mobil və ya buat variabel teks nama sama dengan Budi — IDE nitqi sintaktik cəhətdən düzgün Java, Kotlin, Python və ya Compose kod blokuna çevirir və onu kursor mövqeyinə qoyur, sonra Jieshuo vasitəsilə qısa xülasəni ucadan oxuyur. Diktə sistemin daxili səs daxiletmə xidmətindən istifadə edir, əlavə mikrofon icazəsi olmadan və yalnız artıq qeydiyyatdan keçmiş əmr nümunələrini tanıyır; bu nümunələrdən kənar nitq koda çevrilmir. Sözlə deyilən rəqəmlər (məsələn, 'lima') hələ rəqəmlərə çevrilmir.

Yerli Əməkdaşlıq Otağı (internetsiz)
İnternetsiz bir otaqda birlikdə işləmək üçün: əsas menyuda Əməkdaşlıq bölməsini açın, sonra Yerli Əməkdaşlıq Otağı bölməsini açın. Bir telefon sessiya açır (IDE yerli IP ünvanı və 6 rəqəmli PIN göstərir), başqa telefon həmin ünvan və PIN ilə qoşulur. Mətn dəyişiklikləri sətir fərqləri kimi göndərilir, qurulmuş APK sınaqçının telefonuna göndərilə bilər və sınaqçının telefonundan qəza hesabatları geri alınır. Bir sessiya yalnız bir dost üçündür; iki nəfər eyni sətri eyni zamanda dəyişirsə, son dəyişiklik istifadə olunur. PIN yerli şəbəkədə açıq mətn kimi göndərilir. Bu otaq hələ həqiqi telefonda sınaqdan keçirilməyib.

AI parametrləri
Tətbiqlər qurmaq üçün AI provayderi və API açarlarını qurmaq üçün: əsas menyuda, parametrlər qrupunda «AI parametrləri» düyməsini basın («Konnektor» düyməsinin yanında). Mövcud siyahıdan istifadə ediləcək provayderi seçin və model uğursuz olarsa IDE-nin eyni provayderin növbəti modelini avtomatik sınaması üçün «Provayder xəta verəndə modeli dəyiş» işarələyin. Ehtiyat açarlar əlavə etmək üçün «API açarlarını idarə et» düyməsini basın (ad və açar yazın, sonra «Saxla» düyməsini basın; açarlar maskalanmış göstərilir, yalnız son 4 simvol görünür). Açarlar telefonda saxlanılır və tətbiq qurularkən seçilmiş provayderdən başqa heç yerə göndərilmir. Seçilmiş provayder indi həqiqətən «Layihə planı memarı» və «Kod məntiqi axını rəvayətçisi» tərəfindən istifadə olunur; «AI tətbiq yaradıcısı» ekranında tətbiq qurmaq hələ telefonda yerli AI-dən istifadə edir (internetsiz).

Konnektor
APK-ni təhlil etmək və sonra göndərmək üçün: əsas menyuda, Parametrlər qrupunda, Konnektor düyməsini basın (AI parametrləri düyməsinin yanında). Telefondan APK faylı seçin, IDE onun məzmununu oxuyur (paket adı, versiyası, fəaliyyətlər siyahısı), sonra sistemin paylaşma menyusu vasitəsilə göndərmək üçün APK göndər düyməsini basın (məsələn, WhatsApp və ya Drive).

Dil və səs
Tətbiqin dilini dəyişmək üçün: Parametrlər bölməsini açın, sonra Tətbiq dili bölməsini açın və dil və ya Sistemi izlə seçimini seçin. Əsas ekran və əksər ekranlar tətbiqi bağlamadan və ya yenidən başlatmadan dərhal seçilmiş dilə keçir; bəzi ekranlar (məsələn, Terminal, Əməkdaşlıq, AI parametrləri və Açarların idarə edilməsi) yenidən açılana qədər köhnə dildən istifadə etməyə davam edir. Sistemi izlə seçimini seçsəniz, dil telefonun sistem dilini izləyir.

Layihə üzrə Standart İmza və Anti Tamper
5.7 versiyasından bəri şəxsi imzadan istifadə etməyən layihə layihənin öz daxili açarı ilə imzalanır (layihə daxilindəki tanda-tangan-bawaan qovluğunda bir dəfə yaradılıb, sonra istifadə olunmağa davam edir), beləliklə daxili imza layihədən layihəyə fərqlənir — artıq bütün tətbiqlər üçün ortaq açar deyil. tanda-tangan-bawaan qovluğunu silməyin: bu açar olmadan yeni APK eyni layihə üçün köhnə APK-nın üstünə yaza bilməz. Hər layihənin parametrləri (ayrı arxitektura, şəxsi imza, Anti Tamper, seçilmiş keystore, SDK) indi layihə daxilindəki settings.gradle faylına saxlanılır və layihə hər qurulduqda yenidən oxunur. Parametrlər, İmza kateqoriyasında qurulmuş tətbiq üçün Anti Tamper onay qutusu var: aktivdirsə, qurulmuş tətbiq cihazda imzasını və dex məzmununu hər açıldıqda yoxlayır; başqası tərəfindən yenidən imzalanıbsa və ya dəyişdirilibsə, tətbiq işləməkdən imtina edir. Frida/Xposed kimi sazlama və yeritmə alətləri də aşkar edilir və tətbiq pəncərəsi ekran yazılmasından kilidlənib.

Demo video yaradıcısı
Qurulmuş tətbiqin demo videosunu yaratmaq üçün: əsas menyuda Demo video yaradıcısı açın, layihəni seçin, video başlığını doldurub, sonra Demo Video Skripti Yarat basın — IDE 5 standart səhnə (açılış, əsas görünüş, funksiya 1, funksiya 2, bağlanış) olan video-demo.txt faylını rəvayət mətni və hər səhnənin müddəti ilə birlikdə yazır. Layihənin şəkillərindən (ikon + ekran şəkilləri, əgər varsa) video-demo.html yaratmaq üçün HTML Slideshow Yarat basın, onlar hər 5 saniyədə avtomatik dəyişir. Bu .mp4 video DEYİL — həqiqi video üçün video-demo.html faylını telefon brauzerində açın, sonra ekranı yazın və ya işləyən tətbiqi yazarkən video-demo.txt faylındakı rəvayəti oxuyun.

Android Studio üslubunda Yeni Görünüş
IDE-nin görünüşü indi Android Studio kimi səliqəyə salınıb (yalnız görünüş — bütün düymələr, menyular və axınlar tam olaraq əvvəlki kimi qalır): açıq boz fon, qalın qara ekran başlıqları, ağ mətnli mavi düymələr və nazik çərçivəli ağ daxiletmə sahələri. Əsas menyu vizual olaraq qruplaşdırılıb (Yaradıcının funksiyaları, Bulud, Mövzu və digərləri, Səs, Kod və yeni funksiyalar, Alətlər) düymələrin sırasını dəyişmədən. Terminal Android Studio-dakı Terminal pəncərəsi kimi qaranlıq paneldən istifadə etməyə davam edir və kod redaktorunun fonu hələ ağ, mətni qaradır. Bütün mətn Jieshuo tərəfindən hələ də aydın oxunur.

Parametrlər
Tətbiqi qurmaq üçün: əsas ekrandakı seçimlər menyusunu açın, sonra Parametrlər basın. Daxildə 12 kateqoriya var: GitHub parametrləri (təhlükəsizlik, şəxsi imza, qurma tarixi və GitHub tokeni), Cihazda APK Qurma Parametrləri (keystore parolunu və qurma tarixini cihazda saxlamaq), Mövzu (tətbiq rəngi), İmza (şəxsi imza üçün keystore yaratmaq və qurulmuş tətbiq üçün Anti Tamper onay qutusu), Layihə Qovluğu (layihə qovluğunun yeri), Dil və Səs (interfeys dili və səs rejiminin danışma sürəti), Mətn Ölçüsü və Görünüş (redaktorun şrift ölçüsü), Qurma (Layihə Yarat ekranı üçün standart hədəf SDK və standart arxitektura bölgüsü), Bildirişlər (qurma bitdikdə səs), Avtomatik Ehtiyat Nüsxə (layihə ehtiyat nüsxəsinin cədvəli), Tərtibatçı Profili (ad, WhatsApp nömrəsi və ianə ekranında göstərilən hesab) və Məxfilik və Məlumatlar (parametrləri sıfırlamaq və tətbiq məlumatlarını silmək). Hər kateqoriyanın kateqoriya menyusuna qayıtmaq üçün Əvvəlkinə qayıt düyməsi var. Yenicə saxlanılmış parametrlər (hələ tətbiq olunmamış) ekranda dürüst izah edilir.

Tərtibatçıya ianə
Tərtibatçıya ianə etmək və ya salam vermək üçün: əsas ekranda Alət haqqında düyməsinin yanındakı Tərtibatçıya ianə düyməsini basın. İanə ekranında BRI Hesabını Kopyala düyməsi var — tərtibatçının hesab nömrəsini köçürmək üçün onu basın, sonra bank tətbiqinizə yapışdırın. Tərtibatçını WhatsApp-da Salamla bölməsi də var: adınızı və doğma şəhərinizi doldurub, sonra WhatsApp-da Göndər basın — WhatsApp salam mesajı artıq doldurulmuş halda açılır, sadəcə WhatsApp-da Göndər basın, sonra tətbiqə qayıdın. WhatsApp digər tətbiqlərə mesajları avtomatik göndərməyə icazə vermir, ona görə də göndərmə hələ də WhatsApp-da özünüz tərəfindən edilir.

Terminalın sevimli əmrləri
Terminalda tez-tez istifadə olunan əmrləri saxlamaq üçün: Terminal açın, sonra Sevimlilər basın. Yeni sevimli əlavə et basın, adı (məsələn Fayla bax) və onun əmrini (məsələn ls -la) doldurub, sonra Saxla basın — sevimli telefonda daimi saxlanılır. Onu terminalda birbaşa işə salmaq üçün sevimlinin adını basın; Sevimlini sil basın, sonra silmək üçün birini seçin (təsdiqlə). Artıq 3 daxili sevimli var: Fayla bax (ls -la), Məkanı yoxla (df -h) və Ekranı təmizlə (clear) — hamısı silinə bilər. Boş əmr nə saxlanıla, nə də işə salına bilər; Terminal bu baş verərsə, mesaj və səslə xəbər verir.

Analitika və keyfiyyət
Tətbiq istifadəsinin və qəza hesabatlarının xülasəsini görmək üçün: əsas ekranda Tərtibatçıya ianə düyməsinin yanındakı Analitika və keyfiyyət düyməsini basın. Bu ekran tətbiqin neçə dəfə açıldığını, hansı ekranların ən çox açıldığını, qəzaların sayını və qısa düzəliş təklifləri ilə son qəzaların siyahısını göstərir. Bu məlumatlar yalnız telefonunuzda saxlanılır və heç yerə göndərilmir. Bütün bu məlumatları silmək üçün təsdiq dialoqu olan Analitika Məlumatlarını Sil düyməsi var. Son ekran yalnız əsas ekran və bu ekran üçün qeyd olunur.
