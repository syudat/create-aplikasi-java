Create Aplikasi by Al Kautsar-এ স্বাগতম
Create Aplikasi হলো একটি Android অ্যাপ তৈরির অ্যাপ যা সরাসরি ফোনে চলে, ল্যাপটপের প্রয়োজন ছাড়াই। এই অ্যাপটি যে কাউকে নিজের Android অ্যাপ তৈরি করার সুযোগ দেয়, যার মধ্যে এমন ব্যবহারকারীরাও আছেন যারা অ্যাপ তৈরি শিখতে শুরু করেছেন এবং স্ক্রিন রিডার ব্যবহারকারীরাও আছেন। এই অ্যাপটি ব্যবহারের সম্পূর্ণ নির্দেশিকা এই Tentang Alat স্ক্রিনে পাওয়া যায়।

এই অ্যাপটি কী এবং এটি কাদের জন্য
Create Aplikasi হলো একটি Android অ্যাপ তৈরির সরঞ্জাম যা ফোনে চলে। এই অ্যাপটি তাদের জন্য যারা নিজের Android অ্যাপ তৈরি করতে চান, যার মধ্যে নতুন ব্যবহারকারী এবং স্ক্রিন রিডার ব্যবহারকারীরাও আছেন। এই অ্যাপটিতে একটি কোড সম্পাদক, প্রকল্প পরীক্ষা করার জন্য Jalankan বোতাম, APK তৈরি করার জন্য Bangun বোতাম, এবং APK স্বাক্ষর করা ও ইনস্টল করার মেনু রয়েছে।

এই অ্যাপটির উদ্দেশ্য
এই অ্যাপটি তৈরি করা হয়েছে যাতে যে কেউ সহজে, সরাসরি ফোন থেকে নিজের Android অ্যাপ তৈরি করতে পারেন। এর চেহারা যতটা সম্ভব সহজ করে তৈরি করা হয়েছে যাতে নতুন ব্যবহারকারীরাও সরাসরি চেষ্টা করতে পারেন।

ধাপে ধাপে নতুন প্রকল্প তৈরি করার পদ্ধতি
1. প্রধান মেনুতে Buat Project চাপুন।
2. প্রকল্পের ধরন বেছে নিন: HTML, Situs Web, Java, Kotlin, Compose, অথবা Python।
3. অ্যাপের নাম লিখুন, উদাহরণ: Garuda Decode।
4. প্যাকেজের নাম (package name) লিখুন, উদাহরণ: com.android.garudadecode। প্যাকেজের নামে ছোট হাতের অক্ষর ব্যবহার করতে হবে এবং বিন্দু দিয়ে আলাদা করা অন্তত দুটি অংশ থাকতে হবে।
5. অ্যাপের সংস্করণ লিখুন, উদাহরণ: 1.0, এবং সংখ্যা আকারে সংস্করণ কোড লিখুন, উদাহরণ: 1। খালি রাখলে সংস্করণ স্বয়ংক্রিয়ভাবে 1.0 এবং সংস্করণ কোড 1 দিয়ে পূরণ করা হবে।
6. প্রয়োজনে সর্বনিম্ন SDK এবং লক্ষ্য SDK পূরণ করুন। খালি রাখলে ডিফল্ট মান ব্যবহার করা হবে। সর্বনিম্ন SDK হলো সমর্থিত সবচেয়ে পুরোনো Android সংস্করণ, উদাহরণ: 21 মানে Android 5.0। সর্বোচ্চ লক্ষ্য SDK হলো 36 (Android 16)।
7. অ্যাপের অনুমতি বেছে নিতে Pilih Izin বোতাম চাপুন, উদাহরণ: INTERNET। INTERNET অনুমতিটি ডিফল্টভাবে আগেই চিহ্নিত করা থাকে। শুধুমাত্র অ্যাপের সত্যিকারের প্রয়োজনীয় অনুমতিগুলোতেই টিক দিন।
8. ইচ্ছা হলে, APK-এর আকার ছোট করতে "Gunakan arsitektur terpisah 64 bit dan 32 bit" চিহ্নিত করুন, এবং নিজের তৈরি keystore ব্যবহার করতে চাইলে "Gunakan tanda tangan pribadi" চিহ্নিত করুন।
9. Buat Proyek চাপুন। নতুন প্রকল্পটি Download/project ফোল্ডারে সংরক্ষিত হয় এবং সঙ্গে সঙ্গে Kelola Project-এ দেখা যায়।

উপলভ্য প্রকল্পের ধরনসমূহ
• HTML: index.html, style.css, এবং script.js থেকে তৈরি চেহারা, WebView-এর মাধ্যমে চলে। সরাসরি ফোনে তৈরি করা হয়।
• Situs Web: index.html, tentang.html, kontak.html, style.css, এবং script.js থেকে তৈরি মেনুসহ (Beranda, Tentang, Kontak) ওয়েবসাইট, WebView-এর মাধ্যমে চলে। সরাসরি ফোনে তৈরি করা হয়।
• Java: ফোনে তৈরি করা হয়। MainActivity থাকে app/src/main/java/<nama-paket>/MainActivity.java-তে। চেহারা আসে app/src/main/res/layout/activity_main.xml থেকে, লেখা আসে app/src/main/res/values/strings.xml থেকে, এবং থিম আসে app/src/main/res/values/styles.xml থেকে।
• Kotlin: অ্যাপে অন্তর্ভুক্ত Kotlin কম্পাইলার ব্যবহার করে ডিভাইসে (অফলাইনে) তৈরি করা যায়, অথবা GitHub Actions-এর মাধ্যমে। MainActivity থাকে app/src/main/java/<nama-paket>/MainActivity.kt-তে, এবং res ফাইলগুলো Java প্রকল্পের মতোই। প্রথম Kotlin বিল্ড ধীর হয় কারণ কম্পাইলারের আকার বড়, এবং Kotlin ক্লাসের উল্লেখ করা .java ফাইল এখনও তৈরি করা যায় না (.java ফাইল .kt ফাইলের আগে কম্পাইল করা হয়)।
• Compose: আধুনিক Android অ্যাপ যার ইন্টারফেস Jetpack Compose দিয়ে তৈরি (XML লেআউট নয়)। MainActivity থাকে app/src/main/java/<nama-paket>/MainActivity.kt-তে। Compose প্রকল্প GitHub Actions-এর মাধ্যমে (Bangun proyek মেনু, তারপর Bangun online) অথবা Termux-এ Gradle দিয়ে তৈরি করা হয়, কারণ Compose-এর জন্য Jetpack Compose লাইব্রেরি প্রয়োজন যা ডিভাইসে পাওয়া যায় না।
• Python: অ্যাপের যুক্তি Python ভাষায় (Chaquopy) app/src/main/python/main.py-তে লেখা হয়, এবং app/src/main/java/<nama-paket>/MainActivity.java-তে থাকা হোস্ট MainActivity.java দ্বারা চালানো হয়। Python প্রকল্প সরাসরি ফোনে তৈরি করা যায় (Chaquopy রানটাইম অ্যাপে অন্তর্ভুক্ত) অথবা GitHub Actions-এর মাধ্যমে। Python প্রকল্পের সর্বনিম্ন SDK হলো 24 (Android 7.0)।

Java, HTML, Situs Web, Kotlin, Compose, এবং Python প্রকল্পের ফাইল বিন্যাস
Java, HTML, Situs Web, Kotlin, Compose, এবং Python প্রকল্প সাধারণ Android প্রকল্পের মতোই সাজানো থাকে। app ফোল্ডারের ভিতরে src ফোল্ডার থাকে, এবং তার ভিতরে main ফোল্ডার থাকে। main ফোল্ডারের ভিতরে java ফোল্ডারের পাশাপাশি AndroidManifest.xml থাকে, res ফোল্ডার থাকে যাতে layout/activity_main.xml এবং values/strings.xml ও values/styles.xml থাকে, এবং HTML ও Situs Web-এর জন্য assets ফোল্ডার থাকে যাতে index.html থাকে (Situs Web-এ tentang.html এবং kontak.html-ও থাকে)। HTML এবং Situs Web প্রকল্পের নিজস্ব MainActivity-ও থাকে app/src/main/java/<nama-paket>/MainActivity.java-তে, যা WebView-তে index.html লোড করে এবং AndroidManifest-এ লঞ্চার হিসেবে থাকে। Python প্রকল্পের Python কোড থাকে app/src/main/python/main.py-তে এবং হোস্ট MainActivity.java থাকে app/src/main/java/<nama-paket>/MainActivity.java-তে। AndroidManifest.xml, লেআউট, strings, এবং styles সম্পাদকে খোলা ও পরিবর্তন করা যায়, MainActivity-এর মতোই। পুরোনো প্রকল্প যার ম্যানিফেস্ট এখনও app ফোল্ডারের পাশে আছে তাও তৈরি করা যায়, কারণ তৈরির সময় অ্যাপটি প্রথমে app/src/main/-এ AndroidManifest.xml খোঁজে, তারপর app ফোল্ডারের পাশেরটি, এবং সবশেষে প্রকল্পের ডেটা ফাইল।

অনুমতির নিয়ম (গুরুত্বপূর্ণ)
প্রকল্প তৈরির সময় চিহ্নিত অনুমতিগুলো প্রকল্পের ধরন অনুযায়ী শুধুমাত্র একটি জায়গায় লিপিবদ্ধ থাকে। Java, HTML, Situs Web, Kotlin, Compose, এবং Python প্রকল্পের ক্ষেত্রে, চিহ্নিত অনুমতিগুলো শুধুমাত্র প্রকল্প ফোল্ডারের ভিতরে, java ফোল্ডারের পাশাপাশি, app/src/main/-এ থাকা AndroidManifest.xml-এ লিপিবদ্ধ থাকে। Java, HTML, Situs Web, Kotlin, Compose, এবং Python প্রকল্পের প্রকল্প ডেটা ফাইলে অনুমতির তালিকা থাকে না। আপনি যদি Java বেছে নিয়ে INTERNET এবং CAMERA চিহ্নিত করেন, তাহলে AndroidManifest.xml-এ শুধু INTERNET এবং CAMERA-ই লিপিবদ্ধ থাকবে, অন্য কোনো অনুমতি যুক্ত হবে না। তৈরির সময়, অ্যাপটি একই জায়গা থেকে অনুমতি পড়ে: Java, HTML, Situs Web, Kotlin, Compose, এবং Python প্রকল্পের জন্য app/src/main/-এর AndroidManifest.xml থেকে (না থাকলে, পুরোনো প্রকল্পের জন্য app ফোল্ডারের পাশের AndroidManifest.xml থেকে), এবং পুরোনো প্রকল্পের জন্য প্রকল্প ডেটা ফাইল থেকে।

সম্পাদক ব্যবহার করার পদ্ধতি
Kelola Project খুলুন, সম্পাদক খুলতে প্রকল্পের নামে চাপ দিন। সম্পাদকে ফাইল খোলা যায়, কোড লেখা যায়, এবং পরিবর্তন সংরক্ষণ করা যায়। Java, HTML, Situs Web, Kotlin, Compose, এবং Python প্রকল্পের ক্ষেত্রে ফাইলগুলো app/src/main ফোল্ডারের ভিতরে সাজানো থাকে। প্রকল্প ভাগ করতে Ekspor ZIP ব্যবহার করুন (নিচের অংশ দেখুন)।

প্রকল্প চালানোর পদ্ধতি
সম্পাদকে, প্রকল্প পরীক্ষা করতে Jalankan চাপুন। HTML এবং Situs Web প্রকল্পের ক্ষেত্রে, WebView-এর মাধ্যমে index.html চালানো হয়। কোনো ত্রুটি ঘটলে, ত্রুটির বার্তাটি পড়ুন, কোড ঠিক করুন, তারপর আবার চালান।

APK তৈরি করার পদ্ধতি
সম্পাদকে, Bangun চাপুন। তৈরির দুটি উপায় আছে। প্রথম, Bangun di perangkat: ইন্টারনেট ছাড়াই সরাসরি ফোনে তৈরি করা, HTML, Situs Web, Java, Kotlin, এবং Python প্রকল্পের জন্য। দ্বিতীয়, GitHub Actions-এর মাধ্যমে Bangun online: ইন্টারনেটের মাধ্যমে GitHub-এ তৈরি করা, এবং সব ধরনের প্রকল্পের জন্য ব্যবহার করা যায়। Compose প্রকল্প শুধুমাত্র দ্বিতীয় উপায়ে (Bangun online) অথবা Termux-এ Gradle দিয়ে তৈরি করা যায়, কারণ Compose-এর জন্য Jetpack Compose লাইব্রেরি প্রয়োজন যা ডিভাইসে পাওয়া যায় না। প্রথম বিল্ডের ফলাফল এখনও স্বাক্ষরিত থাকে না। এরপর অ্যাপটি তা স্বাক্ষর করে: ডিফল্ট চাবি দিয়ে স্বয়ংক্রিয়ভাবে, অথবা প্রকল্প তৈরির সময় "Gunakan tanda tangan pribadi" বাক্সটি চিহ্নিত করা থাকলে ব্যক্তিগত স্বাক্ষর দিয়ে।

APK ইনস্টল করার পদ্ধতি
APK তৈরি হয়ে গেলে, ইনস্টল করতে Pasang চাপুন। Android 8 বা তার উপরে, ফোনটি প্রথমে "Izinkan dari sumber ini" চাইবে, কারণ এই অ্যাপটি Play Store-এর বাইরে থেকে APK ইনস্টল করে। Pengaturan-এ একবার সেই অনুমতিটি সক্রিয় করুন, তারপর অ্যাপে ফিরে আসুন: আবার Pasang চাপতে না হয়েই ইনস্টল স্বয়ংক্রিয়ভাবে চলতে থাকবে। Pasang বোতামটি না এলে, নিশ্চিত করুন বিল্ড শেষ হয়েছে এবং APK তৈরি হয়েছে।

অ্যাপে স্বাক্ষর করার পদ্ধতি
প্রতিটি APK ইনস্টল করার জন্য স্বাক্ষরিত হতে হবে। দুটি বিকল্প আছে। প্রথম, ডিফল্ট চাবি: অ্যাপটি নিজে নিজেই স্বয়ংক্রিয়ভাবে স্বাক্ষর করে, আপনাকে কিছু করতে হয় না। দ্বিতীয়, ব্যক্তিগত স্বাক্ষর: প্রথমে প্রধান মেনুর Buat Keystore মেনুর মাধ্যমে একটি keystore তৈরি করুন, এর পাসওয়ার্ড ভালো করে সংরক্ষণ করুন, তারপর প্রকল্প তৈরির সময় "Gunakan tanda tangan pribadi" চিহ্নিত করুন। Keystore Download/project/signing-এ সংরক্ষিত থাকে।

প্রকল্প ZIP হিসেবে রপ্তানি করা
Ekspor ZIP দেওয়া হয়েছে যাতে প্রকল্প বন্ধুদের সঙ্গে ভাগ করা যায়। পদ্ধতি: Kelola Project-এ, প্রকল্পের নাম দীর্ঘক্ষণ চেপে ধরুন, তারপর Ekspor ZIP বেছে নিন। ফলাফল Download/project/<NamaProyek>.zip-এ সংরক্ষিত হয়। bin ফোল্ডার অন্তর্ভুক্ত থাকে না, ফলে আকার ছোট থাকে, মাত্র কয়েক দশক KB। সেই ZIP ফাইলটি বন্ধুকে পাঠানো যায় অথবা GitHub-এ আপলোড করা যায়।

JAWS এক্সটেনশন
JAWS এক্সটেনশন Jieshuo (CSR)-এর এক্সটেনশন ইঞ্জিন ব্যবহার করে, এর স্ক্রিন রিডার নয়। ফলে, ব্যবহারকারী TalkBack ব্যবহার করলেও ডিজাইন চলতে পারে। পদ্ধতি: প্রধান মেনুতে Ekstensi JAWS খুলুন। যেহেতু স্বয়ংক্রিয় ক্লিক নিজে নিজে চলে, সেবাটি প্রথমে Pengaturan Aksesibilitas-এ সক্রিয় করতে হবে। এরপর, নতুন ডিজাইন তৈরি করা যায়: ডিজাইনের নাম লিখুন, OK চাপুন, তারপর এর বাক্সগুলো পূরণ করুন।

পরিচ্ছন্নতার জন্য Daftar Klik আলাদা করা হয়েছে
ডিজাইনের ভিতরে দুটি বাক্স আছে: স্ক্রিপ্ট বাক্স এবং Daftar Klik বাক্স। বোতামের তালিকা আলাদাভাবে daftar_klik.txt ফাইলে সংরক্ষিত থাকে, প্রতি লাইনে একটি নাম। এর বিষয়বস্তুর উদাহরণ: tombolSimpan, tombolHapus, tombolBuka। কোনো অ্যাপ খুলতে, সেই তালিকায় শুধু >WhatsApp লিখুন। পুরোনো ডিজাইন যার এখনও daftar_klik.txt ফাইল নেই, তা সেই ডিফল্ট উদাহরণটি দেখাবে।

প্রদত্ত সহজ ফাংশনসমূহ
• klikTombol("tombolSimpan") — লেখা অনুযায়ী একটি বোতামে ক্লিক করে।
• klikDaftarTombol(daftar) — daftar_klik.txt-এর তালিকায় ক্লিক করে, প্রতি লাইনে একটি বোতাম, ক্রমানুসারে, তারপর জানিয়ে দেয় কতটি সফল হয়েছে এবং কতটি পাওয়া যায়নি।
• bukaAplikasi("WhatsApp") — নাম অনুযায়ী একটি অ্যাপ খোলে, অথবা তালিকায় ">WhatsApp" লিখুন।
• klik(540, 1200) — স্ক্রিনের স্থানাঙ্কে ক্লিক করে।
সব ফাংশন প্রথমে সহজ করে তৈরি করা হয়েছে। অভ্যস্ত হয়ে গেলে, পরে অতিরিক্ত ফাংশন যোগ করা যাবে।

স্ক্রিন রিডার সম্পর্কে
এই অ্যাপটি স্ক্রিন রিডার-বান্ধব করে ডিজাইন করা হয়েছে। প্রতিটি ইনপুট ঘরে লেবেল এবং পূরণের উদাহরণ আছে, এবং সব বোতাম জটিল ইশারা ছাড়াই পৌঁছানো যায়। JAWS এক্সটেনশন এমনভাবে তৈরি যাতে ব্যবহারকারী TalkBack ব্যবহার করলেও তা চলতে থাকে, কারণ যা ব্যবহার করা হয় তা হলো এর এক্সটেনশন ইঞ্জিন, এর স্ক্রিন রিডার নয়।

গোপনীয়তা এবং নিরাপত্তা
প্রকল্প এবং keystore আপনার ফোনে সংরক্ষিত থাকে। GitHub টোকেন শুধুমাত্র অনলাইন বিল্ডের জন্য ব্যবহৃত হয় এবং এই অ্যাপের ভিতরে সংরক্ষিত থাকে। আপনার টোকেন বা keystore পাসওয়ার্ড কারও সঙ্গে ভাগ করবেন না। ব্যক্তিগত স্বাক্ষর ব্যবহার করলে, keystore এবং এর পাসওয়ার্ড নিরাপদ জায়গায় রাখুন, কারণ তা হারিয়ে গেলে পুরোনো APK একই স্বাক্ষর দিয়ে আপডেট করা যাবে না।

প্রয়োজনীয়তা
Android 5.0 বা তার চেয়ে নতুন। সংরক্ষণের অনুমতি: Android 11 বা তার উপরে সব ফাইলে প্রবেশের অনুমতি ব্যবহার করে, Android 10 বা তার নিচে সাধারণ সংরক্ষণ অনুমতি (সংরক্ষণ পড়া/লেখা) ব্যবহার করে কারণ Android 10-এ সব ফাইলে প্রবেশের অনুমতি নেই। ডিভাইসে তৈরি করতে ARM প্রসেসরযুক্ত (32 বা 64 বিট) ফোন প্রয়োজন। GitHub Actions-এর মাধ্যমে অনলাইনে তৈরি করতে ইন্টারনেট এবং GitHub টোকেন প্রয়োজন। Kotlin প্রকল্প ডিভাইসে তৈরি করা যায়, কিন্তু এর প্রথম বিল্ড ধীর হয় এবং বেশি মেমরি ব্যবহার করে কারণ Kotlin কম্পাইলারের আকার বড়। Compose প্রকল্প GitHub Actions-এর মাধ্যমে অথবা Termux-এ Gradle দিয়ে তৈরি করা হয়। Python প্রকল্পের জন্য Android 7.0 বা তার চেয়ে নতুন (সর্বনিম্ন SDK 24) প্রয়োজন এবং ফলাফলের APK বড় হয় কারণ এতে Python রানটাইম (Chaquopy) এবং এর স্ট্যান্ডার্ড লাইব্রেরি অন্তর্ভুক্ত থাকে।

Terminal
প্রধান স্ক্রিনের Terminal মেনু এই অ্যাপের ভিতরে একটি টার্মিনাল খোলে। ls-এর মতো কমান্ড প্রকল্প ফোল্ডারের বিষয়বস্তু দেখতে, cd ফোল্ডার বদলাতে, এবং git কোড পরিচালনা করতে ব্যবহার করা যায়। কমান্ডের আউটপুট স্ক্রিন রিডারে পড়া যায় এমন লেখা হিসেবে দেখা যায়, এবং সর্বশেষ ফলাফল শোনার জন্য Bacakan hasil বোতাম আছে। এই টার্মিনালটি ফোনের সিস্টেম শেল ব্যবহার করে, ফলে nano এবং vim-এর মতো ইন্টারঅ্যাক্টিভ প্রোগ্রাম এখানে এখনও ব্যবহার করা যায় না।

লাইসেন্স (পেইড সংস্করণ)
অ্যাপ বিক্রি করতে, প্রকল্প তৈরির সময় "Aktifkan Lisensi" চিহ্নিত করুন, তারপর আপনার WhatsApp নম্বর পূরণ করুন। বিল্ডের ফলাফলের অ্যাপটি প্রথমবার খোলার সময় একটি লাইসেন্স কোড চাইবে: ব্যবহারকারী তার ডিভাইসের ID দেখতে পান, আপনার WhatsApp-এ সেই ID পাঠাতে Kirim ID Perangkat বোতাম চাপেন, তারপর আপনি লাইসেন্স কোড দিয়ে উত্তর দেন। লাইসেন্স কোড ডিভাইসের ID এবং প্রকল্পের পাসওয়ার্ড (প্রকল্প ডেটা ফাইলে lisensi_seed) থেকে হিসাব করা হয় — সেই পাসওয়ার্ড ভালো করে সংরক্ষণ করুন এবং ভাগ করবেন না। সঠিক কোড প্রবেশ করানো হলে, অ্যাপটি খুলে যায় এবং আর কোড চায় না।

Pembuat Ikon Otomatis
নতুন প্রকল্পের আইকন এখনও স্বচ্ছ, তাই প্রধান মেনুতে Pembuat Ikon পাওয়া যায়। পদ্ধতি: Pembuat Ikon চাপুন, এক বা দুটি অক্ষর লিখুন (উদাহরণস্বরূপ অ্যাপের নামের আদ্যাক্ষর), পটভূমির রং এবং লেখার রং বেছে নিন, এর প্রিভিউ দেখুন, তারপর বেছে নেওয়া প্রকল্পে সেই আইকন ব্যবহার করতে Simpan ke Proyek চাপুন, অথবা এর PNG ফাইল অন্য কোথাও ব্যবহার করতে Simpan ke Download চাপুন। প্রকল্প তৈরি হওয়ার পর, অ্যাপটি আইকন তৈরির প্রস্তাবও দেয়। পুরোনো প্রকল্পের আইকন Kelola Project-এর প্রকল্প মেনু থেকে যেকোনো সময় বদলানো যায় (প্রকল্পের নাম দীর্ঘক্ষণ চেপে ধরুন, তারপর Ganti Ikon বেছে নিন)।

প্রস্তুত প্রকল্প টেমপ্লেট
খালি প্রকল্প থেকে শুরু করতে না চাইলে, প্রকল্প তৈরির সময় একটি টেমপ্লেট বেছে নিন: Kalkulator (Java), Catatan (Java), Daftar Tugas (Kotlin), Kalkulator Web (HTML), Situs Profil (Situs Web), অথবা Penghitung (Compose)। টেমপ্লেট বেছে নিলে প্রকল্পের ধরন স্বয়ংক্রিয়ভাবে সেই টেমপ্লেট অনুযায়ী বদলে যায়, এবং প্রকল্পটি তৈরি শুরুর কোডসহ তৈরি হয় — শুধু চালানো বা পরিবর্তন করা বাকি। টেমপ্লেট বেছে নেওয়ার পর প্রকল্পের ধরন আবার হাতে বদলালে, টেমপ্লেট বাতিল হয়ে যায় এবং প্রকল্প আবার খালি হয়ে যায়। HTML এবং Situs Web টেমপ্লেটের ক্ষেত্রে, টেমপ্লেট index.html-এর বিষয়বস্তু প্রতিস্থাপন করে, ফর্মে লেখা HTML স্ক্রিপ্টসহ।

প্রকল্পের ব্যাকআপ এবং পুনরুদ্ধার

কণ্ঠ দিয়ে অ্যাপ তৈরি করুন
টাইপ করতে না চাইলে ভয়েস ব্যবহার করুন: মূল মেনুতে ভয়েস দিয়ে বিল্ড করুন ট্যাপ করুন, তারপর একটি কমান্ড বলুন। বলা যায় এমন কমান্ড: "Buat proyek kalkulator", "Bangun proyek Kalkulator", "Buka proyek Kalkulator", "Jalankan proyek Kalkulator", "Daftar proyek", "Buka ikon", "Kembali" এবং "Bantuan"। অ্যাপটি ভয়েস ও টেক্সটে উত্তর দেয়, তাই স্ক্রিনের দিকে না তাকিয়েও ব্যবহার করা যায়। ভয়েস শনাক্তকরণ ফোনের অন্তর্নির্মিত স্পিচ রিকগনিশন অ্যাপ ব্যবহার করে (ফ্রি; ইন্দোনেশীয় ভাষা প্যাক ইনস্টল থাকলে অফলাইনেও চলতে পারে)। ফোনে ভয়েস শনাক্তকরণ না থাকলে কমান্ড একই স্ক্রিনের টেক্সট বাক্সে লেখা যায়।

অ্যাক্সেসিবিলিটি অডিট
রিলিজের আগে কোনো প্রোজেক্টের লেআউট স্ক্রিন রিডারের (TalkBack/Jieshuo) জন্য সহায়ক কি না তা পরীক্ষা করতে: মূল মেনুতে অ্যাক্সেসিবিলিটি অডিট খুলুন, প্রোজেক্ট বেছে নিন, তারপর লেআউটের তালিকা লোড করুন ট্যাপ করে একটি লেআউট ফাইল বেছে নিন। IDE সেই XML ফাইল পড়ে লেবেলবিহীন বোতামগুলোর সারি সংখ্যাসহ, বারবার ব্যবহৃত লেবেল এবং একে অপরকে ঢাকা উপাদানগুলোর প্রতিবেদন দেয়, তারপর Jieshuo যেভাবে জোরে পড়ে সেভাবে ফোকাসের ক্রমের প্রতিলিপি বানায়। কোনো বোতামের লেবেল না থাকলে তার লেবেল পূরণ করুন তারপর স্বয়ংক্রিয়ভাবে লেবেল যোগ করুন ট্যাপ করুন — লেবেলটি contentDescription হিসেবে লেআউট ফাইলে লেখা হয়। এই পরীক্ষা শুধু লেআউট XML পড়ে; Compose ভিউ ও তৈরি APK এখনো স্ক্যান হয় না।

ক্র্যাশের ময়নাতদন্ত
অনন্য আইডিসহ ক্র্যাশ লগ থেকে অ্যাপ কেন নিজে নিজে বন্ধ হয় তা জানতে: মূল মেনুতে ক্র্যাশের ময়নাতদন্ত খুলুন, লগের তালিকা থেকে ক্র্যাশ আইডি বেছে নিন, তারপর পরীক্ষা করুন ট্যাপ করুন। IDE লগের ক্লাস ও সারি সংখ্যা প্রোজেক্টের সোর্সের সঙ্গে মিলিয়ে কারণটি ইন্দোনেশীয় ভাষায় ব্যাখ্যা করে (যেমন খালি রেফারেন্স, এখনো না চাওয়া অনুমতি, বা JSON ত্রুটি), সঙ্গে কোড প্যাচের পরামর্শ। সোর্সের সারি ক্র্যাশের সময় যেমন ছিল ঠিক তেমন থাকলেই কেবল প্যাচ প্রয়োগ করুন ট্যাপ করুন; বদলে গেলে প্যাচ প্রত্যাখ্যান করা হয় এবং IDE আপনাকে নিজে পরীক্ষা করতে বলে। যা পড়া হয় তা IDE-র নিজের ক্র্যাশ লগ, তৈরি অ্যাপের লগ নয়।

ক্রস-প্যারাডাইম ট্রান্সপাইলার
সহজ Java কোড Kotlin-এ, বা সহজ XML লেআউট Compose কোডে বদলাতে: মূল মেনুতে ক্রস-প্যারাডাইম ট্রান্সপাইলার খুলুন, প্রোজেক্ট ও ফাইল বেছে নিন, তারপর প্রিভিউ ট্যাপ করুন। IDE রূপান্তরের ফল টেক্সট হিসেবে দেখায় — প্রথমে তা পরীক্ষা করুন, কারণ যে সারিগুলো চেনে না সেগুলো যেমন আছে তেমনই থাকে এবং Java-র static শব্দটি Kotlin-এ বাদ যায় (ব্যবহারের আগে এর অর্থ পরীক্ষা করুন)। XML থেকে Compose রূপান্তর শুধু টেক্সট, ইঙ্গিত ও অভিমুখ বদলায় — আকার, রং ও অন্যান্য বৈশিষ্ট্য এখনো অন্তর্ভুক্ত নয়। ফল সঠিক হলে লক্ষ্য ফাইল লিখতে ফাইলে প্রয়োগ করুন ট্যাপ করুন; সোর্স ফাইল বদলায় না। শুধু নিরাপদ, সাধারণ প্যাটার্নই রূপান্তরিত হয়।

স্থানীয় মাইক্রো সার্ভার
ইন্টারনেট ছাড়া সার্ভার দরকার এমন অ্যাপ পরীক্ষা করতে: মূল মেনুতে স্থানীয় মাইক্রো সার্ভার খুলুন, রুটের সংজ্ঞা লিখুন (যেমন GET /halo তারপর তার JSON উত্তর), তারপর সার্ভার শুরু করুন ট্যাপ করুন। IDE একই ফোনে একটি ছোট HTTP সার্ভার চালায় (শুধু HTTP, TLS ছাড়া, একই Wi-Fi নেটওয়ার্কের জন্য) এবং প্রতিটি অনুরোধ ও উত্তর স্ক্রিনে লিপিবদ্ধ করে। রুটগুলো {nama}-র মতো প্যারামিটার ও একটি সাধারণ API কী ব্যবহার করতে পারে। এই সার্ভার শুধু ফোনে পরীক্ষার জন্য; তৈরি APK এখনো সার্ভার হতে পারে না, এবং তার স্ক্রিন বন্ধ হলে সার্ভার থেমে যায়।

নিরাপত্তা অডিটর
রিলিজের আগে প্রোজেক্টের কোডে নিরাপত্তা ফাঁক পরীক্ষা করতে: মূল মেনুতে নিরাপত্তা অডিটর খুলুন, প্রোজেক্ট বেছে নিন, তারপর স্ক্যান শুরু করুন ট্যাপ করুন। IDE কোড, ম্যানিফেস্ট ও প্রোজেক্টের কনফিগারেশন স্ক্যান করে উচ্চ থেকে নিম্ন ঝুঁকিতে ফলাফল জানায় — কোডে খোলা API কী, অনুমতি ছাড়া খোলা কম্পোনেন্ট, JavaScript ইন্টারফেসসহ JavaScript চালু করা WebView, দুর্বল ক্রিপ্টো (MD5, SHA1, DES), TLS ছাড়া http ঠিকানা, এবং কোডে সরাসরি লেখা পাসওয়ার্ড — প্রতিটির সঙ্গে ফাইল ও সারি সংখ্যা। যেসব ফলের নিরাপদ সংশোধন আছে (যেমন MD5 বদলে SHA-256 বা http বদলে https) সেগুলোর জন্য সংশোধন প্রয়োগ করুন ট্যাপ করুন; API কী ও পাসওয়ার্ডের জন্য IDE শুধু প্রস্তাবিত সংশোধন দেখায় কারণ বিকল্প ডেভেলপারকেই ঠিক করতে হয়। এই স্ক্যান কোডের টেক্সট প্যাটার্ন পড়ে, বাইটকোড নয়, তাই কিছু ফল আসলে নিরাপদ হতে পারে, আর প্যাটার্ন ছাড়া ফাঁক স্ক্যান এড়িয়ে যেতে পারে — প্রয়োগের আগে পরীক্ষা করুন।

ইন্টারফেস পরীক্ষক রোবট
টেক্সট পরিস্থিতি দিয়ে অ্যাপের চেহারা স্বয়ংক্রিয়ভাবে পরীক্ষা করতে: মূল মেনুতে ইন্টারফেস পরীক্ষক রোবট খুলুন, প্রোজেক্ট বেছে নিন, তারপর স্বয়ংক্রিয় পরিস্থিতি তৈরি করুন ট্যাপ করুন। IDE প্রোজেক্টের ম্যানিফেস্ট ও লেআউট পড়ে টেক্সট ধাপের পরিস্থিতি লেখে (বোতাম ট্যাপ করুন, ঘর পূরণ করুন, অপেক্ষা করুন, ফিরে যান)। পরিস্থিতি চলার সময়-চিহ্নসহ লগ দেখতে ড্রাই রান চালান ট্যাপ করুন। এই ধাপে রোবট শুধু অনুকরণ চালায় (ড্রাই রান) — ফোনে বোতাম সত্যিই টেপা ও আসল ক্র্যাশ ধরা পরের ধাপ, তাই এখানে ক্র্যাশ প্রতিবেদন এখনো নমুনা ধরনের।

কোডের সময় ভ্রমণ
Git কমান্ড না টাইপ করে প্রোজেক্টকে আগের কোডের অবস্থায় ফেরাতে: মূল মেনুতে কোডের সময় ভ্রমণ খুলুন, প্রোজেক্ট বেছে নিন, সময়বিন্দুর লেবেল পূরণ করুন (খালি থাকতে পারে), তারপর সময়বিন্দু রেকর্ড করুন ট্যাপ করুন। IDE প্রোজেক্টের সোর্স ফাইলগুলোর অনুলিপি তাদের hash-সহ প্রোজেক্টের ভেতরের .riwayat ফোল্ডারে সংরক্ষণ করে। সময়বিন্দুর তালিকা সব দেখায়; দুটি বিন্দু বেছে নিন তারপর যোগ করা, বদলানো বা মোছা ফাইল ও ফাংশন দেখতে তুলনা করুন ট্যাপ করুন। পুরনো অবস্থা ফেরাতে পুনরুদ্ধার করুন ট্যাপ করুন — পুনরুদ্ধারের আগে IDE সবসময় প্রথমে বর্তমান অবস্থার ব্যাকআপ বানায়, তাই কিছুই হারায় না। মূল প্রোজেক্টকে বিরক্ত না করে পরিবর্তন চেষ্টা করতে প্রোজেক্টকে নতুন ফোল্ডারে কপি করতে পরীক্ষার অনুলিপি তৈরি করুন ট্যাপ করুন। শুধু সোর্স ফাইলই রেকর্ড করা হয়।

মডিউল কারখানা
প্রোজেক্টের কোনো অংশকে মডিউল হিসেবে প্যাক করতে যা অন্য প্রোজেক্ট ব্যবহার করতে পারে: মূল মেনুতে মডিউল কারখানা খুলুন, উৎস প্রোজেক্ট বেছে নিন, প্যাক করতে চাওয়া স্ক্রিন, ক্লাস, স্ট্রিং ও অনুমতির ফাইলগুলোতে টিক দিন, তারপর মডিউল হিসেবে প্যাক করুন ট্যাপ করুন। IDE JSON মেটাডেটা (মডিউলের নাম, সংস্করণ, ব্যবহৃত স্ট্রিং ও অনুমতি) সহ একটি ZIP আর্কাইভ লেখে। অন্য প্রোজেক্টে মডিউল ইনস্টল করতে মডিউল কারখানা খুলুন, লক্ষ্য প্রোজেক্ট বেছে নিন, তারপর মডিউল ইনস্টল করুন ট্যাপ করে মডিউলের .zip ফাইলটি বেছে নিন — একত্রীকরণ বিদ্যমান কোড না লিখে স্ট্রিং ও অনুমতি যোগ করে, এবং লক্ষ্য প্রোজেক্টে নামটি ইতিমধ্যে ব্যবহৃত হলে ফাইল একত্রিত করে না। মডিউল লাইব্রেরি বা বিল্ড সেটিং বহন করে না।

বহুরূপী ঢাল ও সম্পদ সিন্দুক
প্রকাশের আগে শনাক্তকারীর নাম এলোমেলো করতে ও প্রকল্পের সম্পদ এনক্রিপ্ট করতে: মূল মেনুতে বহুরূপী ঢাল ও সম্পদ সিন্দুক খুলুন, প্রকল্প বেছে নিন, তারপর নাম এলোমেলো করুন ও সম্পদ এনক্রিপ্ট করুন চাপুন। IDE উৎস কোডে ক্লাস ও মেথডের নাম স্ক্যান করে, এলোমেলো নামের মানচিত্র তৈরি করে, প্রকল্পের সম্পদ ফাইলগুলো AES-GCM দিয়ে প্রকল্পের ভেতরে brankas-aset ফোল্ডারে এনক্রিপ্ট করে, এবং এনক্রিপ্ট করা পুনরুদ্ধার মানচিত্র (perisai-peta.brankas) সংরক্ষণ করে যাতে ক্র্যাশ লগ পড়ার সময় আসল নাম পুনরুদ্ধার করা যায়। এনক্রিপশন কী প্রকল্পের নাম থেকে তৈরি হয়, তাই প্রকল্পের নাম জানলেই যে কেউ সিন্দুক খুলতে পারে — এটি আড়চোখে পড়া থেকে সুরক্ষা, পাসওয়ার্ডে তালা দেওয়া সিন্দুক নয়। এখানে যা তৈরি হয় তা হল নামের মানচিত্র ও সম্পদ সিন্দুক; কম্পাইল করা DEX ফাইলের ভেতরে নাম পুনর্লেখন পরের ধাপ, তাই তৈরি APK-এর ভেতরের নাম এখনো এলোমেলো হয়নি।

আস্থা শৃঙ্খল ও পরিবেশ রক্ষক
প্রকাশের আগে স্বাক্ষর কী শৃঙ্খল ও ফোনের পরিবেশ পরীক্ষা করতে: মূল মেনুতে আস্থা শৃঙ্খল ও পরিবেশ রক্ষক খুলুন, প্রকল্প বেছে নিন, তারপর শৃঙ্খল ও পরিবেশ পরীক্ষা করুন চাপুন। IDE প্রকল্পের প্যাকেজ নাম থেকে ৫ প্রজন্মের কী শৃঙ্খল তৈরি করে ও এর অখণ্ডতা পরীক্ষা করে, তারপর নিজের প্রক্রিয়ার মেমরি মানচিত্র ও ডিভাইসের বৈশিষ্ট্যে Frida, Xposed বা এমুলেটরের চিহ্ন স্ক্যান করে। ফলাফল হলো ঝুঁকির স্তর নিরাপদ, সতর্ক, বা বিপজ্জনক, সঙ্গে লিখিত প্রমাণ। এই পরীক্ষা মেমরি মানচিত্র ও সিস্টেম বৈশিষ্ট্যে লেখার ধরন পড়ে, নেটিভ লাইব্রেরি স্তরে কাঁচা মেমরির অখণ্ডতা নয়, এবং কীগুলোকে হার্ডওয়্যার নিরাপত্তা চিপের সঙ্গে বাঁধে না — যে ইনজেকশন যন্ত্র তার লেখার চিহ্ন লুকায়, তা এই স্ক্যান এড়িয়ে যেতে পারে।

পাঠ্য বৃক্ষ বিন্যাস স্থপতি
পর্দা না দেখে পর্দা সাজাতে: মূল মেনুতে পাঠ্য বৃক্ষ বিন্যাস স্থপতি খুলুন, প্রকল্প ও বিন্যাস ফাইল বেছে নিন, তারপর বিন্যাস পরীক্ষা করুন চাপুন। IDE XML বিন্যাসকে পাঠ্য বৃক্ষ হিসেবে পড়ে ও প্রতিটি উপাদানের অবস্থানের বিবরণ জোরে পড়ে (যেমন ডান নিচে, পর্দার প্রস্থের ৪৫ শতাংশ), তারপর ৩৬০ dp প্রস্থে উপাদানগুলোর মধ্যে সংঘর্ষ ও পর্দার বাইরে যাওয়া উপাদান গাণিতিকভাবে জানায়। যা হিসাব করা হয় তা হল LinearLayout ও সরল dp মাপ; ConstraintLayout ও Compose পর্দার অবস্থান অনিশ্চিত বলে জানানো হয়, অনুমান করা হয় না।

নকশা ব্যবস্থা স্টুডিও
সব পর্দা ও প্রকল্পে দূরত্ব, অক্ষর ও কোণ এক করতে: মূল মেনুতে নকশা ব্যবস্থা স্টুডিও খুলুন, প্রকল্প বেছে নিন, নকশা টোকেন লিখুন (যেমন jarak=8, huruf=16, sudut=12), উপাদান বেছে নিন, তারপর উপাদান তৈরি করুন চাপুন। IDE টোকেন যাচাই করে — মূল দূরত্ব ৪ থেকে ১৬ dp, মূল অক্ষর ১২ থেকে ২০ sp, কোণ ০ থেকে ৩২ dp, ও সর্বনিম্ন স্পর্শ এলাকা ৪৮ dp — তারপর ব্যবহারের জন্য প্রস্তুত XML উপাদান (komponen-studio.xml) সঙ্গে XML থিম (tema-studio.xml) ও Compose থিম (tema-studio.kt) প্রকল্প ফোল্ডারে লেখে। উপাদান লেখা হিসেবে তৈরি হয়, যা বিন্যাসে বসানো হয় ও পরে বিন্যাস স্থপতি দিয়ে পরীক্ষা করা হয়; ট্যাবলেটে দুই কলামের সমন্বয় পর্দার প্রস্থের যোগ্যতা ব্যবহার করে, চলার সময় ডিভাইস শনাক্তকরণ নয়।

অর্থগত পুনর্গঠন ও AST নেভিগেশন
সংজ্ঞা খুঁজতে ও প্রতীকের নাম বদলাতে, যাতে একই নামের অন্য কোড ভেঙে না যায়: মূল মেনুতে অর্থগত পুনর্গঠন ও AST নেভিগেশন খুলুন, প্রকল্প বেছে নিন, তারপর সব ক্লাস ও মেথড তাদের ফাইল ও লাইন নম্বরসহ দেখতে প্রকল্পের প্রতীক স্ক্যান করুন চাপুন। প্রতীকের নাম লিখুন, তারপর তার সংজ্ঞা ও তাকে ডাকা সব ফাইল দেখতে আবার প্রকল্পের প্রতীক স্ক্যান করুন চাপুন। নাম বদলাতে নতুন নাম লিখুন, প্রতিটি ফাইলে কতবার আছে দেখতে নাম পরিবর্তনের পূর্বরূপ চাপুন, তারপর নাম পরিবর্তন প্রয়োগ করুন চাপুন। এই সূচি লেখার ধরন ব্যবহার করে, পূর্ণ AST পার্সার নয়: ক্লাসের নাম বদল সব ফাইলে প্রযোজ্য, আর মেথডের নাম বদল শুধু তার মালিক ফাইলে — অন্য ফাইলে ডাকা জায়গা বদলায় না, তাই প্রয়োগের আগে পূর্বরূপ ও ডাকা জায়গার স্ক্যান ফল পরীক্ষা করুন। কোড ব্লক নতুন ফাংশনে বের করার কাজ যুক্তি ইঞ্জিনে আছে, কিন্তু এই পর্দায় এখনো তার বোতাম নেই।

ধাপে ধাপে ডিবাগার ও মেমরি পরিদর্শক
লগ থেকে অনুমান না করে প্রোগ্রামের প্রবাহের মাঝখানে চলকের ভেতরের বিষয় পরীক্ষা করতে: মূল মেনুতে ধাপে ধাপে ডিবাগার ও মেমরি পরিদর্শক খুলুন, প্রকল্প বেছে নিন, কার্যকরণের চিহ্ন লিখুন (প্রতি লাইনে এক ধাপ, ধরন লাইন নম্বর, কোড, তারপর চলক ও মান | দিয়ে আলাদা, যেমন 10|int total = harga * jumlah;|harga=5000, jumlah=3, total=15000), থামার বিন্দুর লাইন নম্বর লিখুন, তারপর ডিবাগ ট্রেস চালান চাপুন। IDE প্রথম থামার বিন্দু পর্যন্ত চলে ও Jieshuo দিয়ে সক্রিয় লাইন ও তার চলকের মান জোরে পড়ে। এক লাইন এগোতে এক লাইন এগিয়ে যান চাপুন, বা পরের থামার বিন্দু পর্যন্ত চলতে প্রোগ্রাম চালিয়ে যান চাপুন। এটি চিহ্ন ডিবাগার: এটি রেকর্ড করা বা হাতে লেখা কার্যকরণের চিহ্ন অনুসরণ করে, চলমান অ্যান্ড্রয়েড অ্যাপ থামায় না — আসল প্রক্রিয়া থামাতে ডিবাগ সেতু দরকার, যা এই ধাপে নেই।

অফলাইন নির্ভরতা ব্যবস্থাপক
ইন্টারনেট ছাড়া তৃতীয় পক্ষের লাইব্রেরি ব্যবহার করতে ও বিল্ডের আগে সংস্করণ সংঘর্ষ এড়াতে: মূল মেনুতে অফলাইন নির্ভরতা ব্যবস্থাপক খুলুন, প্রকল্প বেছে নিন, তারপর নির্ভরতা পরীক্ষা করুন চাপুন। IDE প্রকল্পের সব .gradle ফাইল পড়ে, অফলাইন সিন্দুক (প্রকল্পের ভেতরে brankas-maven.txt) পরীক্ষা করে, ও সংঘর্ষ মেটায় — দুই লাইব্রেরি একই আর্টিফ্যাক্টের আলাদা সংস্করণ চাইলে সর্বোচ্চ সংস্করণ ব্যবহৃত হয় ও সংঘর্ষ জানানো হয়। লাইব্রেরি সিন্দুকে লিখতে তার স্থানাঙ্ক লিখুন (ধরন গোষ্ঠী:আর্টিফ্যাক্ট:সংস্করণ, যেমন com.google.code.gson:gson:2.10.1) তারপর নির্ভরতা পরীক্ষা করুন চাপুন। Maven, Google বা PyPI থেকে ডাউনলোডে ইন্টারনেট দরকার: অফলাইনে শুধু সিন্দুকে থাকা লাইব্রেরিই ব্যবহার করা যায়, আর স্থানাঙ্ক যোগ করা শুধু সূচিতে লেখে — AAR, JAR বা WHL ফাইল নিজে থেকে ডাউনলোড হয় না। সিন্দুক এখনো প্রতি প্রকল্পে সংরক্ষিত হয়।

ডাটাবেস ও সংরক্ষণ পরিদর্শক
টেবিলের বিষয় ছাপানোর কোড না লিখে প্রকল্পের ডাটাবেসের বিষয় পরীক্ষা ও যাচাই করতে: মূল মেনুতে ডাটাবেস ও সংরক্ষণ পরিদর্শক খুলুন, প্রকল্প ও ডাটাবেস ফাইল (.db, .sqlite বা .sqlite3) বেছে নিন, তারপর ডাটাবেস খুলুন চাপুন। IDE টেবিলের কাঠামো পড়ে ও প্রথম ২০ সারি লেখা টেবিল হিসেবে দেখায়, যা Jieshuo জোরে পড়ে। সরল SELECT ক্যোয়ারি লিখুন তারপর ক্যোয়ারি চালান চাপুন (যেমন SELECT nama FROM pengguna WHERE kota = 'Makassar')। মান বদলাতে সারির নম্বর (১ = প্রথম সারি), কলামের নাম ও নতুন মান লিখুন, তারপর সেলের মান পরিবর্তন করুন চাপুন — মান .db ফাইলে ফিরে লেখা হয়। টেবিলের বর্তমান অবস্থা প্রকল্পে <ডাটাবেস-নাম>.cadangan.txt ফাইল হিসেবে সংরক্ষণ করতে ব্যাকআপ সংরক্ষণ করুন চাপুন। শুধু প্রথম টেবিল পড়া হয়; সমর্থিত ক্যোয়ারি শুধু সরল SELECT, JOIN বা GROUP BY ছাড়া; SharedPreferences ও DataStore এখনো পড়া হয় না।

ইউনিট পরীক্ষা কারখানা ও ফাজিং
অ্যাপ ভাগ করার আগে যুক্তির ফাঁক খুঁজতে: মূল মেনুতে ইউনিট পরীক্ষা কারখানা ও ফাজিং খুলুন, প্রকল্প ও কোড ফাইল বেছে নিন, তারপর পরীক্ষা তৈরি ও চালান চাপুন। IDE ফাইলে ফাংশনের স্বাক্ষর পড়ে, সাধারণ ও সীমা পরীক্ষার ক্ষেত্র তৈরি করে (খালি লেখা, null, সর্বোচ্চ সংখ্যা, অদ্ভুত অক্ষর), নমুনা ফাংশনে ফাজিং চালায়, ও JUnit পরীক্ষার কাঠামো (Uji<ক্লাসের নাম>.java) প্রকল্পে লেখে। ফলাফল জানায় কটি পরীক্ষা পাস ও ফেল করেছে, কত লাইন কোড ও ফাংশন পাওয়া গেছে, ও কটি পরীক্ষার ক্ষেত্র তৈরি হয়েছে। তৈরি পরীক্ষা এখনো কাঠামো — প্রত্যাশিত মান ডেভেলপারকে লিখতে হবে — আর আসল ফাজিং শুধু নমুনা ফাংশনে চলে, প্রকল্পের ফাংশনে নয়; লাইন কভারেজের শতাংশ এখনো হিসাব করা হয় না।

চরম ডিভাইস অবস্থা অনুকরণকারী ও মেমরি লিক নিরীক্ষক
সিস্টেম তার প্রক্রিয়া বন্ধ করলে, নেটওয়ার্ক ছিন্ন হলে, পর্দা ঘুরলে, বা ব্যাটারি সাশ্রয় চালু হলে অ্যাপের সহনশীলতা পরীক্ষা করতে: মূল মেনুতে চরম ডিভাইস অবস্থা অনুকরণকারী ও মেমরি লিক নিরীক্ষক খুলুন, প্রকল্প বেছে নিন, তারপর অনুকরণ চালান চাপুন। IDE পর্দা ঘোরার অনুকরণসহ তিনটি চাপের পরিস্থিতি চালায় ও তাদের পর্দা বন্ধ হওয়ার পর মেমরিতে আটকে থাকা বস্তু অনুসরণ করে, তারপর হারানো তথ্য ও ফাঁস হওয়া বস্তুর শৃঙ্খল জানায়। এটি অবস্থার মডেলের ওপর অনুকরণ, আসলে প্রক্রিয়া বন্ধ করা নয়, আসলে ফোনের নেটওয়ার্ক কাটা নয়, আর আসল হিপ ডাম্প নয়; এই পর্দার অবস্থার মডেল এখনো স্থির উদাহরণ, ব্যবহারকারীর প্রকল্পের পর্দার অবস্থা নয়।

প্রকল্প নীলনকশা স্থপতি
বড় অ্যাপের ধারণা ধাপে ধাপে কাজের পরিকল্পনায় বদলাতে: মূল মেনুতে প্রকল্প নীলনকশা স্থপতি খুলুন, প্রকল্প বেছে নিন, অ্যাপের ধারণা লিখুন (যেমন কিস্তিসহ মুদি দোকানের ক্যাশিয়ার অ্যাপ), তারপর নীলনকশা তৈরি করুন চাপুন। IDE মডিউল, ফাইলের তালিকা ও ছোট কাজের মাইলফলক সাজায়, তারপর সেগুলো প্রকল্প ফোল্ডারে cetak-biru.txt হিসেবে সংরক্ষণ করে। প্রতিটি মাইলফলক শেষ হলে পরবর্তী মাইলফলক সম্পূর্ণ চিহ্নিত করুন চাপুন, বা সংরক্ষিত নীলনকশা আবার খুলতে সংরক্ষিত নীলনকশা লোড করুন চাপুন। নীলনকশা ডিভাইসে মূল শব্দের ধরন থেকে তৈরি হয়, অনলাইন AI মডেল থেকে নয় — অচেনা ধারণা সাধারণ কাঠামো ব্যবহার করে (তথ্য মডেল, সংরক্ষণ, পর্দা, যুক্তি) — আর সক্রিয় AI সরবরাহকারীর মাধ্যমে তৈরি এই ধাপে নেই।

কোড যুক্তি প্রবাহ কথক
লাইন ধরে ধরে সিনট্যাক্স না শুনে দীর্ঘ কোড বুঝতে: মূল মেনুতে কোড যুক্তি প্রবাহ কথক খুলুন, প্রকল্প ও কোড ফাইল বেছে নিন, তারপর কোড বর্ণনা চাপুন। IDE প্রতিটি লাইন ইন্দোনেশীয় বাক্যে বদলায় (যেমন মোট 100000-এর বেশি হলে, পরের ব্লক চালান), মেথডগুলোর মধ্যে ডাকার মানচিত্র দেখায়, ও সূক্ষ্ম ভুলের সম্ভাবনা লাইন নম্বরসহ চিহ্নিত করে — == দিয়ে তুলনা করা String, না বন্ধ করে খোলা স্ট্রিম, ও দুই আলাদা মেথডে লেখা চলক। বর্ণনা ও পরীক্ষা অফলাইন লেখার ধরন ব্যবহার করে, অনলাইন AI মডেল নয় আর পূর্ণ তথ্য প্রবাহ বিশ্লেষণও নয়; অচেনা ধরন যেমন আছে তেমন কোড লাইন হিসেবে বর্ণনা করা হয়, আর তথ্য প্রতিযোগিতার সতর্কতা এমন চলকের ক্ষেত্রেও আসতে পারে যা আসলে শুধু পালা করে ব্যবহৃত হয়।

অ্যাপ বান্ডেল কারখানা ও Play Store প্রস্তুতি
সরাসরি ফোন থেকে Google Play Store-এর জন্য অ্যাপ তৈরি করতে: মূল মেনুতে অ্যাপ বান্ডেল কারখানা ও Play Store প্রস্তুতি খুলুন, প্রকল্প বেছে নিন, তারপর AAB বান্ডেল তৈরি করুন চাপুন। IDE ম্যানিফেস্ট, সম্পদ ও প্রকল্পের অ্যাসেট থেকে .aab ফাইল জোড়া দেয়, স্থাপত্য (arm64-v8a, armeabi-v7a, x86_64) ও ভাষা অনুযায়ী ডাউনলোডের ভাগের আকারের অনুকরণ করে, তারপর Play প্রস্তুতি নিরীক্ষা করে — লক্ষ্য SDK ৩৫-এর নিচে হলে উচ্চ বলে চিহ্নিত হয় কারণ Play Store ৩৫ বা তার বেশি চায়, আর হারিয়ে যাওয়া ৬৪-বিট লাইব্রেরিও উচ্চ বলে চিহ্নিত হয়। তৈরি বান্ডেল মানসম্মত কাঠামোর AAB সংরক্ষণাগার; ভাগের আকার ফাইলের আকার থেকে অনুমান, bundletool বিভাজনের আসল ফল নয়, আর Play Console-এর জন্য বান্ডেলে স্বাক্ষর এখনো APK-এর মতো একই বিল্ড পথ ব্যবহার করে।

OTA আপডেট ইঞ্জিন ও ধাপে ধাপে প্রকাশ
ব্যবহারকারীদের পুরো APK আবার ডাউনলোড করতে বাধ্য না করে ছোট সংশোধন পাঠাতে: মূল মেনুতে OTA আপডেট ইঞ্জিন ও ধাপে ধাপে প্রকাশ খুলুন, প্রকল্প বেছে নিন, পুরনো ও নতুন সংস্করণের বিষয় লিখুন, তারপর প্যাচ প্যাকেজ তৈরি করুন চাপুন। IDE লাইনের পার্থক্য হিসাব করে ও নতুন বিষয়ের SHA-256 আঙুলের ছাপসহ প্যাচ প্যাকেজ (patch-ota.zip) তৈরি করে, তারপর পরীক্ষা করে এই ডিভাইস প্রাথমিক ১০ শতাংশ প্রকাশ ধাপে আছে কি না। এখানে প্যাচ শুধু লেখা ফাইলে কাজ করে (স্ক্রিপ্ট, সম্পদ, কনফিগারেশন) — বাইনারি DEX বা APK প্যাচ এখনো সমর্থিত নয়, আর অ্যাপ আবার খোলার সময় প্যাচ প্রয়োগ হয়। ম্যানিফেস্টের আঙুলের ছাপ শুধু বিষয়ের অখণ্ডতা প্রমাণ করে, পাঠানোর লোকের সত্যতা নয়, কারণ এখনো ব্যক্তিগত কী স্বাক্ষর ব্যবহার করা হয় না।

দল কোড পর্যালোচনা স্টুডিও
Git-এর তীর চিহ্ন না পড়ে সহকর্মীর পরিবর্তন পর্যালোচনা করতে ও একত্রীকরণ সংঘর্ষ মেটাতে: মূল মেনুতে দল কোড পর্যালোচনা স্টুডিও খুলুন, প্রকল্প বেছে নিন, তিনটি লেখা সংস্করণ পূরণ করুন (ভিত্তি, স্থানীয়, সহকর্মী), তারপর দল পর্যালোচনা খুলুন চাপুন। IDE তিনটিই একত্র করে ও প্রতিটি সংঘর্ষ ভয়েস পছন্দ হিসেবে দেখায়: স্থানীয় সংস্করণ ব্যবহার করুন, সহকর্মীর সংস্করণ ব্যবহার করুন, বা দুটোই একত্র করুন — ফলাফলের লাইন সংঘর্ষের আসল জায়গায় বসানো হয় যাতে লাইনের ক্রম ঠিক থাকে — তারপর ফলাফল প্রকল্পে gabung-hasil.txt-এ লেখে। এর নিচে প্রকল্পের কাজের বোর্ড: কাজের শিরোনাম লিখুন তারপর কাজ যোগ করুন চাপুন; কাজ প্রকল্পের ভেতরে .tugas ফোল্ডারে লেখা হিসেবে সংরক্ষিত হয়। একত্রীকরণ লাইনের মিল ব্যবহার করে, সিনট্যাক্স নয়, তাই একই লাইনে দুই পরিবর্তন সবসময় সংঘর্ষ ধরা হয়, যদিও অর্থ না মিললেও; কাজের বোর্ড তার লেখা ফাইল Git ইতিহাসের সঙ্গে অনুলিপি করে সিঙ্ক হয়, কোনো বিশেষ সিঙ্ক সার্ভার ছাড়া।

কোডের কাঠামো বলুন
এডিটরের ভেতরে কণ্ঠে কোড লিখতে: এডিটরে প্রোজেক্ট খুলুন, তারপর কোডের কাঠামো বলুন বোতাম ট্যাপ করুন। ইন্দোনেশীয় ভাষায় কমান্ড বলুন, যেমন buat fungsi tambah dengan parameter a angka dan b angka, buat kelas Mobil, বা buat variabel teks nama sama dengan Budi — IDE কণ্ঠকে ব্যাকরণগতভাবে সঠিক Java, Kotlin, Python বা Compose কোড ব্লকে বদলে কার্সরের জায়গায় বসায়, তারপর Jieshuo দিয়ে সংক্ষিপ্ত সারাংশ জোরে পড়ে। ডিকটেশন সিস্টেমের অন্তর্নির্মিত ভয়েস ইনপুট পরিষেবা ব্যবহার করে, অতিরিক্ত মাইক্রোফোন অনুমতি ছাড়াই, এবং শুধু আগে থেকে নিবন্ধিত কমান্ড প্যাটার্নই চেনে; সেই প্যাটার্নের বাইরের কথা কোডে বদলায় না। শব্দে বলা সংখ্যা (যেমন 'lima') এখনো অঙ্কে বদলায় না।

স্থানীয় সহযোগিতার ঘর (ইন্টারনেট ছাড়া)
ইন্টারনেট ছাড়া একই ঘরে একসঙ্গে কাজ করতে: মূল মেনুতে সহযোগিতা খুলুন, তারপর স্থানীয় সহযোগিতার ঘর অংশটি খুলুন। একটি ফোন সেশন খোলে (IDE স্থানীয় IP ঠিকানা ও ৬ সংখ্যার PIN দেখায়), অন্য ফোন সেই ঠিকানা ও PIN দিয়ে যোগ দেয়। টেক্সট পরিবর্তন সারির পার্থক্য হিসেবে পাঠানো হয়, তৈরি APK পরীক্ষকের ফোনে পাঠানো যায়, এবং পরীক্ষকের ফোন থেকে ক্র্যাশ প্রতিবেদন ফিরে আসে। একটি সেশন শুধু একজন বন্ধুর জন্য; দুজন একই সময়ে ঠিক একই সারি বদলালে শেষ পরিবর্তনটিই ব্যবহৃত হয়। PIN স্থানীয় নেটওয়ার্কে সাধারণ টেক্সট হিসেবে পাঠানো হয়। এই ঘরটি এখনো আসল ফোনে পরীক্ষা হয়নি।

AI সেটিংস
অ্যাপ তৈরির জন্য AI প্রোভাইডার ও API কী সেট করতে: মূল মেনুতে, সেটিংস গ্রুপে, AI সেটিংস ট্যাপ করুন (সংযোগকারী বোতামের পাশে)। উপলভ্য তালিকা থেকে ব্যবহারের প্রোভাইডার বেছে নিন, এবং প্রোভাইডার ত্রুটি হলে মডেল বদলান-এ টিক দিন যাতে একটি মডেল ব্যর্থ হলে IDE একই প্রোভাইডারের পরের মডেলটি স্বয়ংক্রিয়ভাবে চেষ্টা করে। ব্যাকআপ কী যোগ করতে API কী পরিচালনা করুন ট্যাপ করুন (নাম ও কী পূরণ করুন, তারপর সংরক্ষণ করুন ট্যাপ করুন; কীগুলো ঢেকে দেখানো হয়, শুধু শেষ ৪টি অক্ষর দেখা যায়)। কীগুলো ফোনে সংরক্ষিত হয় এবং অ্যাপ তৈরির সময় বেছে নেওয়া প্রোভাইডার ছাড়া আর কোথাও পাঠানো হয় না। নোট: এই মুহূর্তে প্রোভাইডার ও কী-র পছন্দ শুধু লিপিবদ্ধ হয় এবং AI Pembuat Aplikasi স্ক্রিনে দেখানো হয় — অ্যাপ তৈরি এখনো ফোনের স্থানীয় AI (ইন্টারনেট ছাড়া) ব্যবহার করে; অনলাইন প্রোভাইডারের ব্যবহার পরে আসবে।

সংযোগকারী
APK বিশ্লেষণ করে তারপর পাঠাতে: মূল মেনুতে, সেটিংস গ্রুপে, সংযোগকারী ট্যাপ করুন (AI সেটিংস বোতামের পাশে)। ফোন থেকে APK ফাইল বেছে নিন, IDE এর বিষয়বস্তু পড়ে (প্যাকেজের নাম, সংস্করণ, অ্যাক্টিভিটির তালিকা), তারপর সিস্টেম শেয়ার মেনু (যেমন WhatsApp বা Drive) দিয়ে পাঠাতে APK পাঠান ট্যাপ করুন।

ভাষা ও শব্দ
অ্যাপের ভাষা বদলাতে: সেটিংস খুলুন, তারপর অ্যাপের ভাষা, তারপর একটি ভাষা বা সিস্টেম অনুসরণ করুন বেছে নিন। মূল স্ক্রিন ও বেশিরভাগ স্ক্রিন অ্যাপ বন্ধ বা পুনরায় চালু না করেই সঙ্গে সঙ্গে বেছে নেওয়া ভাষায় বদলে যায়; কিছু স্ক্রিন (যেমন Terminal, সহযোগিতা, AI সেটিংস ও কী পরিচালনা) আবার না খোলা পর্যন্ত পুরনো ভাষাই ব্যবহার করে। সিস্টেম অনুসরণ করুন বেছে নিলে ভাষা ফোনের সিস্টেম ভাষা অনুসরণ করে।
