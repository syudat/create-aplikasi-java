Willkommen bei Create Aplikasi by Al Kautsar
Create Aplikasi ist eine Android-App-Ersteller-Anwendung, die direkt auf dem Telefon läuft, ohne dass ein Laptop benötigt wird. Diese Anwendung ermöglicht es jedem, eigene Android-Anwendungen zu erstellen, einschließlich Benutzern, die gerade erst lernen, Anwendungen zu erstellen, und Benutzern von Screenreadern. Die vollständige Anleitung zur Verwendung dieser Anwendung ist auf diesem Bildschirm „Über dieses Tool" verfügbar.

Was diese Anwendung ist und für wen sie ist
Create Aplikasi ist ein Android-App-Ersteller-Tool, das auf dem Telefon läuft. Diese Anwendung richtet sich an alle, die eigene Android-Anwendungen erstellen möchten, einschließlich Anfängern und Benutzern von Screenreadern. Diese Anwendung bietet einen Code-Editor, eine Schaltfläche „Ausführen" zum Testen von Projekten, eine Schaltfläche „Erstellen" zum Erzeugen einer APK sowie Menüs zum Signieren und Installieren der APK.

Zweck dieser Anwendung
Diese Anwendung wurde erstellt, damit jeder ganz einfach direkt vom Telefon aus eigene Android-Anwendungen erstellen kann. Ihre Oberfläche ist so einfach wie möglich gestaltet, damit auch neue Benutzer sie sofort ausprobieren können.

Wie man ein neues Projekt erstellt, Schritt für Schritt
1. Tippen Sie im Hauptmenü auf „Projekt erstellen".
2. Wählen Sie den Projekttyp: HTML, Website, Java, Kotlin, Compose oder Python.
3. Geben Sie den Anwendungsnamen ein, Beispiel: Garuda Decode.
4. Geben Sie den Paketnamen (package name) ein, Beispiel: com.android.garudadecode. Der Paketname muss Kleinbuchstaben verwenden und aus mindestens zwei durch Punkte getrennten Teilen bestehen.
5. Geben Sie die Anwendungsversion ein, Beispiel: 1.0, und einen Versionscode in Form einer Zahl, Beispiel: 1. Wenn leer gelassen, wird die Version automatisch mit 1.0 und der Versionscode mit 1 ausgefüllt.
6. Geben Sie bei Bedarf das Mindest-SDK und das Ziel-SDK ein. Wenn leer gelassen, werden die Standardwerte verwendet. Das Mindest-SDK ist die niedrigste unterstützte Android-Version, Beispiel: 21 bedeutet Android 5.0. Das maximale Ziel-SDK ist 36 (Android 16).
7. Tippen Sie auf die Schaltfläche „Berechtigungen auswählen", um die Anwendungsberechtigungen auszuwählen, Beispiel: INTERNET. Die Berechtigung INTERNET ist standardmäßig bereits angehakt. Haken Sie nur die Berechtigungen an, die die Anwendung wirklich benötigt.
8. Falls gewünscht, haken Sie „Separate 64-Bit- und 32-Bit-Architekturen verwenden" an, damit die APK-Größe kleiner wird, und haken Sie „Persönliche Signatur verwenden" an, wenn Sie einen selbst erstellten Keystore verwenden möchten.
9. Tippen Sie auf „Projekt erstellen". Das neue Projekt wird im Ordner Download/project gespeichert und erscheint sofort unter „Projekte verwalten".

Verfügbare Projekttypen
• HTML: Anzeige aus index.html, style.css und script.js, läuft über WebView. Wird direkt auf dem Telefon erstellt.
• Website: eine Website mit Menüs (Startseite, Über, Kontakt) aus index.html, tentang.html, kontak.html, style.css und script.js, läuft über WebView. Wird direkt auf dem Telefon erstellt.
• Java: wird auf dem Telefon erstellt. MainActivity befindet sich in app/src/main/java/<package-name>/MainActivity.java. Die Anzeige stammt aus app/src/main/res/layout/activity_main.xml, der Text aus app/src/main/res/values/strings.xml und das Theme aus app/src/main/res/values/styles.xml.
• Kotlin: kann auf dem Gerät (offline) mit dem in der Anwendung enthaltenen Kotlin-Compiler erstellt werden oder über GitHub Actions. MainActivity befindet sich in app/src/main/java/<package-name>/MainActivity.kt, und die res-Dateien sind dieselben wie bei einem Java-Projekt. Der erste Kotlin-Build ist wegen der großen Größe des Compilers langsamer, und .java-Dateien, die auf Kotlin-Klassen verweisen, können noch nicht erstellt werden (.java-Dateien werden vor .kt-Dateien kompiliert).
• Compose: eine moderne Android-Anwendung, deren Oberfläche mit Jetpack Compose erstellt wird (nicht mit XML-Layouts). MainActivity befindet sich in app/src/main/java/<package-name>/MainActivity.kt. Compose-Projekte werden über GitHub Actions (Menü „Projekt erstellen", dann „Online erstellen") oder in Termux mit Gradle erstellt, weil Compose die Jetpack-Compose-Bibliotheken erfordert, die auf dem Gerät nicht verfügbar sind.
• Python: Die Anwendungslogik wird in der Sprache Python (Chaquopy) in app/src/main/python/main.py geschrieben und vom Host MainActivity.java in app/src/main/java/<package-name>/MainActivity.java ausgeführt. Python-Projekte können direkt auf dem Telefon erstellt werden (die Chaquopy-Laufzeitumgebung ist in der Anwendung enthalten) oder über GitHub Actions. Das Mindest-SDK für Python-Projekte ist 24 (Android 7.0).

Projektarchitektur ändern
Um die Architektur-Einstellungen eines bestehenden Projekts zu ändern, ohne ein neues Projekt zu erstellen: Tippen Sie im Hauptmenü auf Projektarchitektur ändern, wählen Sie dann ein Projekt und ändern Sie das Kontrollkästchen 64-Bit-APK bauen (arm64-v8a) oder 32-Bit-APK bauen (armeabi-v7a); oder halten Sie in Projekte verwalten einen Projektnamen lange gedrückt und wählen Sie Architektur ändern, um denselben Bildschirm direkt für dieses Projekt zu öffnen. Die Regel lautet: Wenn beide Kästchen aktiviert sind, erzeugt der Build zwei getrennte APKs, eine 64-Bit- und eine 32-Bit-APK; wenn nur ein Kästchen aktiviert ist, erzeugt der Build eine einzige universelle APK, die weiterhin auf 64-Bit- wie auf 32-Bit-Geräten läuft. Eine getrennte APK für nur eine Variante wird noch nicht unterstützt, weil der Build-Pfad nur die geteilte oder die universelle Auswahl kennt, aber die Auswahl jeder Variante bleibt im Projekt gespeichert, damit sie beim erneuten Öffnen des Bildschirms nicht verloren geht.

Dateistruktur von Java-, HTML-, Website-, Kotlin-, Compose- und Python-Projekten
Java-, HTML-, Website-, Kotlin-, Compose- und Python-Projekte sind wie Android-Projekte im Allgemeinen aufgebaut. Innerhalb des Ordners app befindet sich der Ordner src, und darin befindet sich der Ordner main. Innerhalb des Ordners main befindet sich AndroidManifest.xml neben dem Ordner java, der Ordner res mit layout/activity_main.xml und values/strings.xml sowie values/styles.xml, und für HTML und Website gibt es den Ordner assets mit index.html (Website hat auch tentang.html und kontak.html). HTML- und Website-Projekte haben auch ihre eigene MainActivity in app/src/main/java/<package-name>/MainActivity.java, die index.html in einer WebView lädt und zum Launcher im AndroidManifest wird. Python-Projekte haben Python-Code in app/src/main/python/main.py und den Host MainActivity.java in app/src/main/java/<package-name>/MainActivity.java. AndroidManifest.xml, Layouts, Strings und Styles können im Editor geöffnet und geändert werden, genau wie MainActivity. Alte Projekte, deren Manifest sich noch neben dem Ordner app befindet, können weiterhin erstellt werden, weil die Anwendung beim Erstellen zuerst AndroidManifest.xml in app/src/main/ prüft, dann diejenige neben dem Ordner app und zuletzt die Projektdatendatei.

Berechtigungsregeln (wichtig)
Bei der Projekterstellung angehakte Berechtigungen werden je nach Projekttyp nur an einem Ort aufgezeichnet. Für Java-, HTML-, Website-, Kotlin-, Compose- und Python-Projekte werden die angehakten Berechtigungen NUR in AndroidManifest.xml aufgezeichnet, das sich in app/src/main/, neben dem Ordner java, innerhalb des Projektordners befindet. Die Projektdatendatei für Java-, HTML-, Website-, Kotlin-, Compose- und Python-Projekte enthält keine Liste von Berechtigungen. Wenn Sie Java wählen und dann INTERNET und CAMERA anhaken, wird in AndroidManifest.xml nur INTERNET und CAMERA aufgezeichnet, ohne dass andere Berechtigungen enthalten sind. Beim Erstellen liest die Anwendung die Berechtigungen von derselben Stelle: aus AndroidManifest.xml in app/src/main/ für Java-, HTML-, Website-, Kotlin-, Compose- und Python-Projekte (falls keine vorhanden ist, aus AndroidManifest.xml neben dem Ordner app für alte Projekte) und aus der Projektdatendatei für alte Projekte.

Wie man den Editor verwendet
Öffnen Sie „Projekte verwalten", tippen Sie auf einen Projektnamen, um den Editor zu öffnen. Im Editor können Dateien geöffnet, Code geschrieben und Änderungen gespeichert werden. Für Java-, HTML-, Website-, Kotlin-, Compose- und Python-Projekte sind die Dateien innerhalb des Ordners app/src/main angeordnet. Um ein Projekt zu teilen, verwenden Sie „ZIP exportieren" (siehe Abschnitt unten).

Wie man ein Projekt ausführt
Tippen Sie im Editor auf „Ausführen", um das Projekt zu testen. Bei HTML- und Website-Projekten wird index.html über WebView ausgeführt. Wenn ein Fehler auftritt, lesen Sie die Fehlermeldung, korrigieren Sie den Code und führen Sie es dann erneut aus.

Wie man eine APK erstellt
Tippen Sie im Editor auf „Erstellen". Es gibt zwei Möglichkeiten zu erstellen. Erstens: „Auf dem Gerät erstellen": erstellt direkt auf dem Telefon ohne Internet, für HTML-, Website-, Java-, Kotlin- und Python-Projekte. Zweitens: „Online erstellen" über GitHub Actions: erstellt über das Internet auf GitHub und kann für alle Projekttypen verwendet werden. Compose-Projekte können nur auf die zweite Weise („Online erstellen") oder in Termux mit Gradle erstellt werden, weil Compose die Jetpack-Compose-Bibliotheken erfordert, die auf dem Gerät nicht verfügbar sind. Das Ergebnis des ersten Builds ist noch nicht signiert. Danach signiert die Anwendung es: automatisch mit dem integrierten Schlüssel oder mit einer persönlichen Signatur, wenn das Kästchen „Persönliche Signatur verwenden" bei der Projekterstellung angehakt war.

Wie man eine APK installiert
Wenn die APK bereit ist, tippen Sie auf „Installieren", um sie zu installieren. Auf Android 8 und höher wird das Telefon zuerst um „Aus dieser Quelle zulassen" bitten, weil diese Anwendung APKs von außerhalb des Play Store installiert. Aktivieren Sie diese Berechtigung einmal in den Einstellungen und kehren Sie dann zur Anwendung zurück: Die Installation wird automatisch fortgesetzt, ohne dass Sie erneut auf „Installieren" tippen müssen. Wenn die Schaltfläche „Installieren" nicht erscheint, stellen Sie sicher, dass der Build abgeschlossen ist und die APK erstellt wurde.

Wie man eine Anwendung signiert
Jede APK muss signiert werden, damit sie installiert werden kann. Es stehen zwei Möglichkeiten zur Verfügung. Erstens der integrierte Schlüssel: Die Anwendung signiert sie automatisch selbst, ohne dass Sie etwas tun müssen. Zweitens eine persönliche Signatur: Erstellen Sie zuerst einen Keystore über das Menü „Keystore erstellen" im Hauptmenü, speichern Sie sein Passwort sorgfältig und haken Sie dann bei der Projekterstellung „Persönliche Signatur verwenden" an. Der Keystore wird in Download/project/signing gespeichert.

Ein Projekt in ZIP exportieren
„ZIP exportieren" wird bereitgestellt, damit Projekte mit Freunden geteilt werden können. So geht es: Halten Sie unter „Projekte verwalten" den Projektnamen lange gedrückt und wählen Sie dann „ZIP exportieren". Das Ergebnis wird in Download/project/<ProjectName>.zip gespeichert. Der Ordner bin ist nicht enthalten, sodass die Größe klein ist, nur einige zehn KB. Diese ZIP-Datei kann an Freunde gesendet oder auf GitHub hochgeladen werden.

JAWS-Erweiterung
Die JAWS-Erweiterung verwendet die Erweiterungs-Engine von Jieshuo (CSR), nicht dessen Screenreader. Auf diese Weise können Designs weiterhin laufen, selbst wenn der Benutzer TalkBack verwendet. So geht es: Öffnen Sie „JAWS-Erweiterung" im Hauptmenü. Da das automatische Klicken von selbst läuft, muss der Dienst zuerst in den Einstellungen für Bedienungshilfen aktiviert werden. Danach kann ein neues Design erstellt werden: Geben Sie den Designnamen ein, tippen Sie auf OK und füllen Sie dann seine Felder aus.

Klickliste der Übersichtlichkeit halber getrennt
Innerhalb eines Designs gibt es zwei Felder: das Skriptfeld und das Feld „Klickliste". Die Liste der Schaltflächen wird getrennt in der Datei daftar_klik.txt gespeichert, ein Name pro Zeile. Ein Beispiel für ihren Inhalt: tombolSimpan, tombolHapus, tombolBuka. Um eine Anwendung zu öffnen, schreiben Sie einfach >WhatsApp in diese Liste. Alte Designs, die noch keine Datei daftar_klik.txt haben, zeigen dieses Standardbeispiel an.

Bereitgestellte einfache Funktionen
• klikTombol("tombolSimpan") — klickt eine Schaltfläche anhand ihres Textes.
• klikDaftarTombol(daftar) — klickt die Liste in daftar_klik.txt, eine Schaltfläche pro Zeile, der Reihe nach, und meldet dann, wie viele erfolgreich waren und wie viele nicht gefunden wurden.
• bukaAplikasi("WhatsApp") — öffnet eine Anwendung anhand ihres Namens, oder schreiben Sie ">WhatsApp" in die Liste.
• klik(540, 1200) — klickt auf Bildschirmkoordinaten.
Alle Funktionen sind zunächst einfach gehalten. Sobald Sie sich an sie gewöhnt haben, können später zusätzliche Funktionen hinzugefügt werden.

Über Screenreader
Diese Anwendung ist so gestaltet, dass sie screenreaderfreundlich ist. Jedes Eingabefeld hat eine Beschriftung und ein Ausfüllbeispiel, und alle Schaltflächen können ohne komplizierte Gesten erreicht werden. Die JAWS-Erweiterung ist so gemacht, dass sie weiterhin läuft, selbst wenn der Benutzer TalkBack verwendet, weil ihre Erweiterungs-Engine verwendet wird, nicht ihr Screenreader.

Datenschutz und Sicherheit
Projekte und Keystores werden auf Ihrem Telefon gespeichert. Das GitHub-Token wird nur für Online-Builds verwendet und innerhalb dieser Anwendung gespeichert. Teilen Sie Ihr Token oder Ihr Keystore-Passwort mit niemandem. Wenn Sie eine persönliche Signatur verwenden, bewahren Sie den Keystore und sein Passwort an einem sicheren Ort auf, denn wenn sie verloren gehen, können alte APKs nicht mit derselben Signatur aktualisiert werden.

Anforderungen
Android 5.0 oder neuer. Speicherberechtigung: Auf Android 11 und höher wird die Berechtigung für den Zugriff auf alle Dateien verwendet, auf Android 10 und niedriger wird die normale Speicherberechtigung (Speicher lesen/schreiben) verwendet, weil Android 10 keine Berechtigung für den Zugriff auf alle Dateien hat. Das Erstellen auf dem Gerät erfordert ein Telefon mit einem ARM-Prozessor (32 oder 64 Bit). Das Online-Erstellen über GitHub Actions erfordert Internet und ein GitHub-Token. Kotlin-Projekte können auf dem Gerät erstellt werden, aber ihr erster Build ist langsamer und verbraucht mehr Speicher wegen der großen Größe des Kotlin-Compilers. Compose-Projekte werden über GitHub Actions oder in Termux mit Gradle erstellt. Python-Projekte erfordern Android 7.0 oder neuer (Mindest-SDK 24), und die resultierende APK ist größer, weil sie die Python-Laufzeitumgebung (Chaquopy) zusammen mit ihrer Standardbibliothek enthält.

Terminal
Das Menü „Terminal" auf dem Hauptbildschirm öffnet ein Terminal innerhalb dieser Anwendung. Befehle wie ls können verwendet werden, um den Inhalt des Projektordners anzuzeigen, cd, um zwischen Ordnern zu wechseln, und git, um Code zu verwalten. Die Befehlsausgabe erscheint als Text, der von einem Screenreader gelesen werden kann, und es gibt eine Schaltfläche „Ergebnis vorlesen", um sich das letzte Ergebnis anzuhören. Dieses Terminal verwendet die Systemshell des Telefons, sodass interaktive Programme wie nano und vim hier noch nicht verwendet werden können.

Lizenz (kostenpflichtige Version)
Um eine Anwendung zu verkaufen, haken Sie bei der Projekterstellung „Lizenz aktivieren" an und geben Sie dann Ihre WhatsApp-Nummer ein. Die erstellte Anwendung wird beim ersten Öffnen einen Lizenzcode anfordern: Der Benutzer sieht seine Geräte-ID, tippt auf die Schaltfläche „Geräte-ID senden", um diese ID an Ihr WhatsApp zu senden, und dann antworten Sie mit dem Lizenzcode. Der Lizenzcode wird aus der Geräte-ID und dem Projektpasswort (lisensi_seed in der Projektdatendatei) berechnet — bewahren Sie dieses Passwort sorgfältig auf und teilen Sie es nicht. Nachdem der richtige Code eingegeben wurde, öffnet sich die Anwendung und fragt nicht erneut nach einem Code.

Automatischer Symbol-Ersteller
Die Symbole neuer Projekte sind noch transparent, daher ist im Hauptmenü ein Symbol-Ersteller verfügbar. So geht es: Tippen Sie auf „Symbol-Ersteller", schreiben Sie einen oder zwei Buchstaben (zum Beispiel die Initialen des Anwendungsnamens), wählen Sie eine Hintergrundfarbe und eine Textfarbe, sehen Sie sich die Vorschau an und tippen Sie dann auf „In Projekt speichern", um dieses Symbol im ausgewählten Projekt zu verwenden, oder auf „In Downloads speichern", um seine PNG-Datei woanders zu verwenden. Nachdem ein Projekt erstellt wurde, bietet die Anwendung auch an, ein Symbol zu erstellen. Das alte Symbol eines Projekts kann jederzeit über das Projektmenü unter „Projekte verwalten" ersetzt werden (halten Sie den Projektnamen lange gedrückt und wählen Sie dann „Symbol ändern").

Gebrauchsfertige Projektvorlagen
Wenn Sie nicht mit einem leeren Projekt beginnen möchten, wählen Sie bei der Projekterstellung eine Vorlage: Taschenrechner (Java), Notizen (Java), Aufgabenliste (Kotlin), Web-Rechner (HTML), Profil-Website (Website) oder Zähler (Compose). Die Auswahl einer Vorlage ändert den Projekttyp automatisch entsprechend dieser Vorlage, und das Projekt wird mit bereits fertigem Startcode erstellt — führen Sie ihn einfach aus oder ändern Sie ihn. Wenn der Projekttyp nach der Auswahl einer Vorlage wieder manuell geändert wird, wird die Vorlage abgebrochen und das Projekt wird wieder leer. Bei HTML- und Website-Vorlagen ersetzt die Vorlage den Inhalt von index.html, einschließlich des im Formular eingegebenen HTML-Skripts.

Projekte sichern und wiederherstellen
Damit Projekte nicht verloren gehen, ist eine Sicherungsfunktion verfügbar. So geht es: Halten Sie unter „Projekte verwalten" den Projektnamen lange gedrückt und wählen Sie dann „Sichern". Die Sicherung wird als ZIP im Ordner Download/backup mit dem Projektnamen und dem Datum gespeichert, Beispiel: GarudaDecode-2026-11-14-123045.zip. Ihr Inhalt ist derselbe wie bei „ZIP exportieren" (der gesamte Inhalt des Projekts, ohne den Ordner bin). Zum Wiederherstellen: Öffnen Sie das Menü unter „Projekte verwalten", wählen Sie „Sicherung wiederherstellen" und wählen Sie dann die Sicherungsdatei. Wenn der Projektname bereits existiert, fragt die Anwendung: Das alte Projekt überschreiben oder mit einem Neuen Namen speichern.

Projekte teilen und importieren
Um ein Projekt mit Freunden zu teilen: Halten Sie unter „Projekte verwalten" den Projektnamen lange gedrückt und wählen Sie dann „Teilen". Das Projekt wird als ZIP über Sharing-Anwendungen (WhatsApp, Telegram und andere) gesendet. Um ein Projekt von einem Freund zu erhalten: Öffnen Sie das Menü unter „Projekte verwalten", wählen Sie „Projekt importieren" und wählen Sie dann die ZIP-Datei. Diese ZIP-Datei muss eine Projektdatendatei enthalten — wenn keine vorhanden ist, wird die Datei mit einer klaren Meldung abgelehnt, weil diese Datei kein Create-Aplikasi-Projekt ist. Wenn der Projektname bereits existiert, fragt die Anwendung: Das alte Projekt überschreiben oder mit einem Neuen Namen speichern.

Projektsuche und -filter
Wenn es bereits viele Projekte gibt, gibt es unter „Projekte verwalten" ein Suchfeld und einen Typfilter. Geben Sie den Projektnamen in das Suchfeld ein, und die Liste wird sofort gefiltert (Groß- und Kleinbuchstaben werden nicht unterschieden). Der Typfilter beschränkt die Liste auf nur einen Typ: Alle, HTML, Website, Java, Kotlin, Compose oder Python. Das Menü jedes Projekts kann weiterhin wie gewohnt aus der bereits gefilterten Liste geöffnet werden.

Anwendungen per Sprache erstellen
Wenn du nicht tippen möchtest, nutze deine Stimme: Tippe im Hauptmenü auf Mit Stimme erstellen und sprich dann einen Befehl. Befehle, die du sprechen kannst: "Buat proyek kalkulator", "Bangun proyek Kalkulator", "Buka proyek Kalkulator", "Jalankan proyek Kalkulator", "Daftar proyek", "Buka ikon", "Kembali" und "Bantuan". Die App antwortet mit Stimme und Text, sodass sie auch benutzt werden kann, ohne auf den Bildschirm zu schauen. Die Spracherkennung nutzt die eingebaute Spracherkennungs-App des Handys (kostenlos; sie kann offline arbeiten, wenn das indonesische Sprachpaket installiert ist). Wenn das Handy keine Spracherkennung hat, können die Befehle im Textfeld auf demselben Bildschirm eingegeben werden.

KI-App-Ersteller
Tippen oder diktieren Sie die gewünschte App auf dem Bildschirm des KI-App-Erstellers, zum Beispiel: «eine Notizen-App mit einem Speichern-Knopf». Die App analysiert die Schlüsselwörter im Telefon selbst (ohne Internet, ohne Kosten) und erstellt dann ein echtes Projekt aus der am besten passenden Vorlage: Taschenrechner, Notizen, Aufgabenliste, Web-Taschenrechner, Profilseite oder Zähler. Wenn Ihre Beschreibung noch keine passende Vorlage hat, erstellt die App ein leeres Projekt und sagt das ehrlich — sie tut nicht so, als ob sie es versteht. Ein von der KI erstelltes Projekt kann direkt in Projekte verwalten geöffnet werden.

Live-Vorschau auf dem Handy eines Freundes
Um ein Projekt einem Freund vor dem Erstellen zu zeigen: Drücken Sie in Projekte verwalten lange auf den Projektnamen und wählen Sie Vorschau auf das Telefon eines Freundes. Die App erstellt ein kleines Vorschau-Paket mit den Hauptdateien des Projekts (index.html, MainActivity oder main.py) plus BACA-SAYA.txt mit Anweisungen und info.txt. Das Paket wird als ZIP über WhatsApp oder Telegram gesendet. Der Freund, der es erhält, kann die Vorschau sofort öffnen: HTML-Seiten öffnen sich im Browser, Java-/Kotlin-/Python-Code wird als Text gelesen.

Projekt-Marktplatz
Der Projekt-Markt enthält eingebaute Beispielprojekte, die mit einem Tippen in den Projektordner installiert werden können: Taschenrechner, Notizen, Aufgabenliste, Web-Taschenrechner, Profilseite, Zähler, Digitaluhr und Web-Quiz. Der Online-Markt (Beispiele aus dem Internet herunterladen) ist noch nicht verfügbar, daher enthält dieser Markt Beispiele, die bereits in der App sind. Ein installiertes Projekt kann in Projekte verwalten geöffnet und geändert werden wie ein selbst erstelltes Projekt.

Direkte Zusammenarbeit
Um gemeinsam mit einem Freund an einem Projekt zu arbeiten: Öffnen Sie Zusammenarbeit im Hauptmenü, wählen Sie das Projekt, schreiben Sie eine Änderungsnotiz (was geändert wurde) und drücken Sie Teilen zur Zusammenarbeit. Das Projekt wird als ZIP zusammen mit einer Datei CATATAN.txt darin gesendet. Ihr Freund arbeitet daran und schickt die ZIP zurück; Sie drücken Antwort empfangen, lesen zuerst die Änderungsnotiz und wählen dann Anwenden, um das alte Projekt zu überschreiben, oder Abbrechen, wenn Sie es sich anders überlegen. Eine ZIP ohne CATATAN.txt ist kein Kollaborationspaket — für eine gewöhnliche Projekt-ZIP verwenden Sie Projekt importieren in Projekte verwalten.

Automatischer App-Übersetzer
Um den Text in einer App in eine andere Sprache zu übersetzen: Öffnen Sie App-Übersetzer im Hauptmenü, wählen Sie das Projekt und die Zielsprache (Englisch, Arabisch oder Javanisch) und drücken Sie Übersetzen. Das Wörterbuch ist bereits im Telefon (ohne Internet, ohne Kosten) und enthält alltägliche gebräuchliche Wörter; Text aus strings.xml, Layout und Code wird gelesen und dann übersetzt. Das Ergebnis wird in den Ordner values-sprache/strings.xml geschrieben (wenn das Projekt eine strings.xml hat) und ein Bericht übersetzung-sprache.txt im Projektordner. Wörter, die noch nicht im Wörterbuch sind, werden so gelassen wie sie sind und gemeldet — so wissen Sie, welche Wörter Sie noch selbst übersetzen müssen.

Spieleentwickler ohne Code
Um ein Spiel zu erstellen, ohne Code zu schreiben: Öffnen Sie Spiele-Ersteller im Hauptmenü, wählen Sie den Spieltyp (Zahl raten, Quiz oder Stern fangen), füllen Sie den Spielnamen, die Anzahl (Level/Fragen/Sterne) und die Gewinnnachricht aus und drücken Sie Spiel erstellen. Das Spiel wird als echtes Projekt erstellt, das direkt in Projekte verwalten ausgeführt und wie jedes andere Projekt als APK erstellt werden kann.

Automatischer App-Test
Um ein Projekt vor dem Erstellen zu prüfen: Drücken Sie in Projekte verwalten lange auf den Projektnamen und wählen Sie Automatischer Test. Die IDE prüft 10 Dinge, ohne eine APK zu erstellen — Pflichtdateien vorhanden (Projektdatendatei, Manifest, Hauptdatei, Layout, Strings), Paketname und Version, verwendete Berechtigungen, Symbol und Gleichgewicht der Code-Klammern. Das Ergebnis wird pro Element angezeigt (BESTANDEN/NICHT BESTANDEN mit einer Nachricht) und von Jieshuo vorgelesen. Beheben Sie zuerst alles, was NICHT BESTANDEN hat, und drücken Sie dann Projekt erstellen.

AI-Codeprüfer
Um Projektcode auf Muster zu prüfen, die oft Probleme verursachen: Öffnen Sie Code prüfen im Hauptmenü, wählen Sie das Projekt und drücken Sie Code prüfen. Der Prüfer läuft im Telefon (ohne Internet) und sucht nach ungenutzten Variablen, leeren Funktionen, eindeutig endlosen Schleifen, Text, der direkt im Code geschrieben ist (besser in strings.xml), gefährlichen Berechtigungen und APIs, TODO-/FIXME-Markierungen und dynamischer Ausführung. Jeder Fund enthält den Dateinamen, die Zeilennummer und einen Behebungsvorschlag. Dieser Prüfer basiert auf Mustern, ist keine echte KI — Probleme, die keinem Muster folgen, können trotzdem durchkommen.

Interaktiver Lernmodus
Um Schritt für Schritt zu lernen, Apps zu erstellen: Öffnen Sie Lernen im Hauptmenü. Es gibt 5 Lektionen: Ihr erstes Projekt erstellen, Einen Knopf hinzufügen, Die Farbe ändern, Ton hinzufügen und Eine APK erstellen. Tippen Sie auf eine Lektion, um ihre Erklärung und praktische Aufgabe zu lesen, machen Sie die Aufgabe und drücken Sie dann Aufgabe prüfen — die IDE prüft wirklich, ob die Aufgabe erledigt wurde (indem sie das Projekt und die APK auf Ihrem Telefon scannt). Bestandene Lektionen werden als abgeschlossen markiert und gespeichert.

Cloud-Synchronisierung
Um ein Projekt in die Cloud zu sichern: Öffnen Sie Cloud-Synchronisierung im Hauptmenü. Eine lokale Sicherung speichert die Projekt-ZIP mit einem Zeitstempel im Ordner Download/cloud und kann jederzeit aus der Sicherungsliste wiederhergestellt werden. Eine GitHub-Sicherung lädt die Projekt-ZIP in Ihr privates Repo hoch (mit dem Token aus den GitHub-Einstellungen) und kann wieder heruntergeladen werden. Dies ist manuelles Sichern und Wiederherstellen — eine vollständige automatische Zwei-Wege-Synchronisierung braucht einen Server und ist daher noch nicht verfügbar.

Automatischer Backend-Ersteller
Um ein Backend zu erstellen, ohne Server-Code zu schreiben: Öffnen Sie Backend-Ersteller im Hauptmenü, wählen Sie den Backend-Typ (Notizen, Aufgabenliste oder Pinnwand), füllen Sie den Projektnamen aus und drücken Sie Backend erstellen. Die IDE erstellt ein echtes HTML-Projekt mit einer Formularseite und einer Datenliste, die im lokalen Speicher des Telefons (localStorage) gespeichert wird — Daten werden gespeichert und können beim Ausführen der App wieder gelesen werden. Dieses Backend läuft auf einem Telefon; zwei Telefone können die gleichen Daten noch nicht teilen, da es keinen Internet-Server gibt.

Automatischer Theme-Designer
Um einem Projekt ein Farbthema zu geben: Öffnen Sie Theme-Designer im Hauptmenü, wählen Sie das Projekt und das Thema (Hell, Dunkel, Blau, Grün, Rot oder Lila). Die Vorschau zeigt die sechs Farben des Themas (primär, dunkel primär, Akzent, Hintergrund, Text, sekundärer Text) und wird von Jieshuo vorgelesen. Drücken Sie Thema anwenden — die IDE schreibt colors.xml und styles.xml (Stil app_theme) in das Projekt, die direkt verwendet werden, wenn das Projekt ausgeführt oder erstellt wird.

Animations-Ersteller
Um einem Projekt eine Animation zu geben: Öffnen Sie Animations-Ersteller im Hauptmenü, wählen Sie das Projekt, den Animationstyp (Einblenden, Verschieben, Drehen, Springen oder Pulsieren), die Dauer (100 bis 10000 Millisekunden) und das Ziel (Knopf, Text oder Bild) und drücken Sie Animation erstellen. Die IDE schreibt eine echte Animationsdatei (res/anim/anim_<typ>.xml für Java-/Kotlin-/Compose-Projekte oder animasi.css für HTML-/Website-Projekte) zusammen mit einem Beispiel-Verwendungscode, der auf dem Bildschirm angezeigt wird.

Aktionsrekorder
Um Arbeit automatisch zu wiederholen: Die IDE zeichnet ausgeführte Aktionen auf (Projekt öffnen, ausführen, erstellen, exportieren, sichern, Projekt erstellen, Datei speichern). Öffnen Sie Aktionsrekorder im Hauptmenü, um die Liste der aufgezeichneten Aktionen mit ihrem Plan zu sehen, und drücken Sie dann Wiedergeben — die IDE führt die Aktionen erneut aus, die automatisiert werden können (Sichern und Projekt erstellen laufen an Ort und Stelle; Ausführen, Erstellen und Exportieren öffnen ihren Hauptbildschirm; Öffnen und Speichern öffnen den Editor). Aktionen, die nicht automatisiert werden können, werden übersprungen und am Ende gemeldet.

Automatische Sicherheit
Um die Sicherheit eines Projekts zu prüfen: Öffnen Sie Automatische Sicherheit im Hauptmenü, wählen Sie das Projekt und drücken Sie Sicherheit prüfen. Die IDE prüft 8 Dinge lokal (ohne Internet): gefährliche Berechtigungen (Standort, SMS, Anrufe, Kamera, Mikrofon, Kontakte), Datenversand über HTTP, SMS-Versand, ausgehende Anrufe, ein Passwort oder einen Schlüssel, der direkt im Code steht, ein WebView ohne Schutz, eine Komponente, die ohne Berechtigung exportiert wurde, und eine http-Adresse ohne Verschlüsselung. Jeder Fund erhält eine Stufe SICHER, WARNUNG oder GEFAHR mit einem Behebungsvorschlag, und die Zusammenfassung wird von Jieshuo vorgelesen.

Offline-KI
Um Text- und Code-Hilfswerkzeuge ohne Internet zu nutzen: Öffnen Sie Offline-KI im Hauptmenü. Es gibt 4 Werkzeuge: Text korrigieren (Großbuchstaben, Zeichensetzung und doppelte Leerzeichen), Text zusammenfassen (nimmt die 3 wichtigsten Sätze), App-Namen erstellen (aus der geschriebenen Beschreibung) und Variablenname vorschlagen (sucht 1-2 Buchstaben lange Variablennamen im Projekt). Das sind einfache Regeln im Telefon, kein echtes KI-Modell. Das Ergebnis der Textkorrektur kann mit der Schaltfläche Anwenden auf die strings.xml des Projekts angewendet werden.

Widget- & Hintergrundbild-Ersteller
Um ein Widget für den Startbildschirm zu erstellen: Öffnen Sie Widgets & Hintergründe im Hauptmenü, wählen Sie das Projekt, füllen Sie den Widget-Text aus und drücken Sie Widget erstellen. Die IDE schreibt WidgetSaya.java, das Widget-Layout, die Widget-Informationen und fügt einen Empfänger zur AndroidManifest.xml des Projekts hinzu — erstellen Sie das Projekt und installieren Sie dann das Widget vom Startbildschirm des Telefons. Für ein Hintergrundbild: Füllen Sie den Text sowie die Hintergrund- und Textfarben aus, erstellen Sie eine Vorschau und speichern Sie es dann als PNG im Download-Ordner oder legen Sie es direkt als Telefon-Hintergrund fest.

Integration sozialer Medien
Um Teilen-Knöpfe zu einer App hinzuzufügen: Öffnen Sie Soziale Medien im Hauptmenü, wählen Sie das Projekt und fügen Sie Teilen zu WhatsApp, Facebook oder Telegram hinzu (oder alle drei auf einmal). Die IDE schreibt echten Teilen-Code in die Hauptdatei des Projekts (MainActivity oder index.html). Die Schaltfläche Teilen testen öffnet den Teilen-Auswahldialog aus der IDE mit einem Beispieltext, damit der Ablauf vor dem Erstellen der App erlebt werden kann.

App aus Bild
Um eine Galerie-App aus einem Bild zu erstellen: Öffnen Sie App aus Bild im Hauptmenü und wählen Sie ein Bild aus der Galerie. Die IDE analysiert die Bildgröße und die dominierende Farbe und erstellt dann ein echtes Galerie-App-Projekt: Das Bild wird in die Assets des Projekts kopiert, die Themenfarbe wird aus der dominierenden Farbe des Bildes übernommen und der App-Name wird aus dem Bilddateinamen übernommen. Öffnen Sie Projekte verwalten, um diese Galerie-App auszuführen oder zu erstellen.

Interaktives Terminal (VT-Parser)
Um interaktive Programme im Terminal zu nutzen: Öffnen Sie Terminal im Hauptmenü und führen Sie nano, vim, top oder htop aus. Das Terminal verwendet jetzt einen VT-Parser (ein Rasterbildschirm mit 24 Zeilen x 80 Spalten), sodass diese Programme korrekt angezeigt werden — der Cursor bewegt sich, Zeilen werden gelöscht und der Bildschirm wechselt wie in einem echten Terminal. Es gibt spezielle Tasten Tab, Pfeil nach oben, Pfeil nach unten und Esc, um interaktive Programme zu steuern. Die Ausgabe bleibt Text, den Jieshuo lesen kann; drücken Sie Bildschirm vorlesen, um die letzte Zeile zu hören.

Terminal Exec (App-Binärdatei)
Um eine Binärdatei im App-Ordner (zum Beispiel aapt2, ECJ, D8) aus dem Terminal auszuführen: Tippen Sie den Befehl wie gewohnt. Die IDE verwendet libkautsarexec.so, damit Binärdateien im App-Ordner unter Android 10 und höher ausgeführt werden können. Drücken Sie Exec-Test im Terminal, um zu prüfen, ob der Binär-Exec-Pfad auf diesem Telefon funktioniert — das Ergebnis wird so angezeigt, wie es ist. Wenn exec vom System blockiert wird, laufen Systembefehle und Shell-Skripte weiterhin; führen Sie die Binärdatei stattdessen über das Menü Projekt erstellen aus.

Terminal am Leben halten (KeepAlive)
Um die Shell beim Wechseln des Bildschirms weiterlaufen zu lassen: Öffnen Sie das Terminal, führen Sie einen Befehl aus und drücken Sie dann Zurück oder wechseln Sie zu einem anderen Bildschirm — die Shell stirbt NICHT, und die Terminal-Benachrichtigung bleibt sichtbar, sodass Sie mit einem Tippen zurückkehren können. Bereits ausgeführte Befehle werden im Verlauf gespeichert (Schaltfläche Verlauf oder die Pfeile nach oben/unten im Befehlsfeld), und oft verwendete Befehle können als Favorit gespeichert werden (Schaltfläche Favorit). Drücken Sie Shell schließen, wenn Sie fertig sind, damit die Shell wirklich beendet wird. Es gibt auch eine Schaltfläche Erstellen im Terminal im Projektmenü und im Editormenü: Das Terminal öffnet sich im Projektordner mit dem bereits ausgefüllten Erstellungsbefehl.

Terminal-Tools installieren (Test)
Eine Funktion, die sich noch im Test befindet: Im Terminal gibt es eine Schaltfläche Terminal-Tools installieren, um eine Termux-Umgebung aus dem Spiegel im alat-termux-Repository des Entwicklers zu installieren (github.com/syudat/alat-termux), als einen weiteren Weg neben der Schaltfläche Termux installieren, die von der offiziellen Termux-Version nimmt. Der Spiegelinhalt ist genau derselbe wie die offizielle Version und wird während der Installation mit SHA-256 geprüft. Nachdem die Umgebung installiert ist, können die Befehle pkg update und pkg install verwendet werden, und zusätzliche Werkzeuge aus dem Repository werden ebenfalls im Terminal installiert: info-terminal, um Umgebungsinformationen zu sehen, bersih-terminal, um den Cache zu leeren, und cadangkan-proyek, um den Projektordner in eine einzige datierte tar.gz-Datei zu archivieren. Danach installiert die App automatisch die grundlegenden Linux-Pakete (git, python, curl, wget, nano, openssh, zip, unzip) und die APK-Erstellungswerkzeuge mit Signierung (openjdk-21, kotlin, gradle, ecj, aapt2, d8, apksigner, clang, cmake, ninja, make) aus dem offiziellen Termux-Repository, sodass das Terminal sofort bereit ist, Apps zu erstellen. Das Herunterladen großer Pakete (Hunderte MB) kann lange dauern. Während die Installation läuft, erscheinen Fortschritt und Befehlsausgabe auf dem Hauptbildschirm des Terminals, und das Endergebnis wird vom Screenreader vorgelesen. Wenn die Paketinstallation noch nicht abgeschlossen ist, drücken Sie Terminal-Tools installieren erneut, um sie fortzusetzen.

Vollständiger Sprachmodus
Um die IDE vollständig per Stimme zu steuern: Öffnen Sie Sprachmodus im Hauptmenü und drücken Sie Zuhören starten. Die IDE hört kontinuierlich zu — es ist nicht nötig, für jeden Befehl eine Taste zu drücken — führt den Befehl aus und antwortet per Stimme. Es gibt 26 Befehle: erstellen, bauen, öffnen, ausführen, auflisten, suchen, löschen, testen, prüfen, exportieren, sichern, teilen, Symbol erstellen, übersetzen, im Terminal erstellen, Bildschirm lesen, alle Bildschirme öffnen (einschließlich Sicherheit, Offline-KI, Widget, soziale Medien, Spiel, Lernen, Cloud, Backend, Thema, Animation, Rekorder), zurück, schließen und Hilfe. Wenn der Modus aktiv gelassen wird, wird das Zuhören automatisch fortgesetzt, wenn dieser Bildschirm erneut geöffnet wird. Drücken Sie Zuhören stoppen, um diesen Modus auszuschalten. Wenn das Telefon keinen Spracherkennungsdienst hat, können Befehle weiterhin in das Textfeld geschrieben werden.

Code-Übersetzer
Um Code ohne Internet zwischen Sprachen zu übersetzen: Öffnen Sie Code-Übersetzer im Hauptmenü, wählen Sie das Projekt, wählen Sie die Quelldatei (.java/.kt) und wählen Sie dann die Richtung: Java zu Kotlin. Drücken Sie Übersetzen — das Ergebnis wird zusammen mit einem Bericht der Zeilen angezeigt, die nicht übersetzt werden können (diese Zeilen werden so belassen, wie sie sind, und markiert). Drücken Sie Ergebnis speichern, um eine NEUE Datei (name-übersetzung.java/.kt) im selben Ordner zu schreiben; die Originaldatei wird niemals überschrieben. Dies ist ein Musterregel-Übersetzer, kein Compiler — prüfen Sie das Ergebnis immer vor der Verwendung.

Git in der App
Um Git in der IDE ohne Termux zu nutzen: Öffnen Sie Git in der App im Hauptmenü, wählen Sie das Projekt und drücken Sie Git-Repo erstellen, um ein lokales Repo (.git) in diesem Projekt zu erstellen. Drücken Sie Status prüfen, um neue, geänderte oder gelöschte Dateien im Vergleich zum letzten Commit zu sehen; füllen Sie die Commit-Nachricht aus und drücken Sie Commit, um einen Schnappschuss des Projekts zu speichern; drücken Sie Commit-Log anzeigen, um den Commit-Verlauf zu sehen. Push zu GitHub und Pull von GitHub verwenden Schnappschüsse über ein GitHub-Token (das Repo pembuat-aplikasi-build) — nicht das Git-Protokoll. Klonen, Push (System-Git) und Pull (System-Git) laufen nur, wenn die Git-Binärdatei auf dem Telefon installiert ist (normalerweise nicht). Dies ist kein vollständiges Git: kein Merge, kein Branch, kein Diff — jeder Commit speichert einen vollständigen ZIP-Schnappschuss des Projekts.

Anzeigen-Ersteller
Um Werbung zu einer erstellten App hinzuzufügen: Öffnen Sie Anzeigen-Ersteller im Hauptmenü, wählen Sie das Projekt, den Anbieter (AdMob, Unity Ads oder AppLovin) und den Anzeigentyp (Banner, Interstitial oder Belohnt). Füllen Sie die Anzeigenblock-ID aus, wenn Sie bereits eine haben — leer bedeutet, eine Test-ID zu verwenden (AdMob verwendet Googles offizielle Test-ID; Unity verwendet eine Beispiel-Game-ID; AppLovin verwendet eine leere Platzierung). Drücken Sie Werbecode erstellen, um den Java- und Kotlin-Code sowie die Anleitung zu sehen; drücken Sie Im Projekt speichern, um alles in die Datei werbung-<anbieter>-<typ>.txt im Projekt zu schreiben. Dies ist eine Code-Vorlage + Anleitung, kein Werbe-SDK — das SDK ist nicht in der IDE enthalten; echte Werbung erscheint erst, nachdem Sie ein Anbieterkonto erstellt, einen Anzeigenblock erstellt, Ihre eigene Block-ID eingefügt und die SDK-Abhängigkeit in der build.gradle des Projekts hinzugefügt haben.

Kindermodus
Um die IDE gemeinsam mit einem Kind zu nutzen: Öffnen Sie Kindermodus im Hauptmenü. Der Bildschirm ist mit großen Knöpfen vereinfacht und hat nur 4 sichere Aktionen: Projekt erstellen (aus sicheren Vorlagen: Taschenrechner, Zahl raten, Quiz, Stern fangen), Projekt öffnen, Ausführen und Lernen. Es gibt keinen Löschen-, Exportieren-, Sichern- oder Token-Einstellungen-Knopf auf diesem Bildschirm. Beim ersten Betreten erstellen Sie eine 4-stellige PIN — diese PIN wird von den Eltern verwendet, um den Kindermodus zu verlassen (die Schaltfläche Kindermodus verlassen oder die Zurück-Taste). Diese PIN ist ein leichter Schutz für kleine Kinder, keine echte Sicherheit.

Wear OS- & TV-App-Ersteller
Um eine Uhren-App (Wear OS) oder eine TV-App (Android TV) zu erstellen: Öffnen Sie Wear OS & TV im Hauptmenü und wählen Sie das Ziel (Wear OS, Android TV oder beide). Füllen Sie den Projektnamen aus und drücken Sie Neues Wear/TV-Projekt erstellen — die IDE erstellt ein Java-Projekt und passt es dann an — oder wählen Sie ein bereits vorhandenes Projekt und drücken Sie Auf dieses Projekt anwenden. Die Anpassungen: uses-feature im Manifest, die Kategorie LEANBACK_LAUNCHER + Banner für TV und ein angepasstes activity_main.xml-Layout (Wear: kleiner Bildschirm; TV: großer Bildschirm, D-Pad-freundlich). Die vollständige Erklärung wird in wear-tv.txt im Projekt geschrieben. Dies ist eine Projektvorlage — Erstellen + Testen braucht weiterhin ein Wear-OS- oder Android-TV-Gerät/einen Emulator; das TV-Banner (banner.png 320x180) wird nicht automatisch erstellt, es muss selbst hinzugefügt werden (zum Beispiel über den Symbol-Ersteller).

Projektkarte
Um die Struktur eines Projekts zu sehen: Öffnen Sie Projektkarte im Hauptmenü, wählen Sie das Projekt und drücken Sie Karte anzeigen — die IDE zeigt die Liste der Ordner und Dateien mit ihren Größen, die Gesamtgröße, die Größe pro Dateityp und die wichtigen Dateien (Hauptdatei, Manifest, Layout, Strings, Symbol, Webseite). Drücken Sie Karte-projekt.txt speichern, um dieselbe Karte in das Projektstammverzeichnis zu schreiben. Der Ordner bin/ (Erstellungsergebnisse) und der Ordner .git/ (lokales Repo) werden nicht kartiert, da ihr Inhalt neu erstellt werden kann.

APK-Größenrechner
Um die Größe der erstellten APK vor dem Erstellen zu schätzen: Öffnen Sie APK-Größenrechner im Hauptmenü, wählen Sie das Projekt und drücken Sie Schätzung berechnen. Die IDE zeigt die Aufschlüsselung pro Kategorie (Code/DEX, Ressourcen, Assets, native Bibliotheken, Manifest + resources.arsc, Overhead), die Gesamtschätzung, die 5 größten Dateien und Vorschläge zum Verkleinern (zum Beispiel große Bilder werden in der Auflösung verkleinert, große Töne in der Dauer gekürzt). Dies ist eine SCHÄTZUNG, keine genaue Größe — die tatsächliche Größe kann aufgrund der aapt2-Komprimierung, der Entfernung ungenutzten Codes (R8) und der erstellten Ressourcen abweichen.

APK-Analysator
Um den Inhalt einer fertigen APK zu lesen (wie der APK-Analysator in Android Studio): Öffnen Sie APK-Analysator im Hauptmenü, wählen Sie das Projekt und drücken Sie Analyse der APK aus dem Build-Ergebnis. Die IDE liest die neueste APK im bin-Ordner dieses Projekts und meldet den Paketnamen, die Version, das minimale und Ziel-SDK, die Liste der verwendeten Berechtigungen, die Anzahl der Dex-Dateien, die Größenaufschlüsselung pro Teil (Programmcode, Ressourcen, Assets, native Bibliotheken, Signatur) und die 10 größten Einträge. Nützlich, um zu wissen, welcher Teil die APK groß macht und welche Berechtigungen die erstellte App verwendet.

Vorschau der Bildschirmgröße
Um das Aussehen eines Projekts auf vielen Bildschirmgrößen gleichzeitig zu prüfen (wie in Android Studio): Öffnen Sie Vorschau der Bildschirmgröße im Hauptmenü, wählen Sie das Projekt und drücken Sie Bildschirmgröße prüfen. Die IDE liest alle Layouts des Projekts und meldet Elemente, deren Breite fest geschrieben ist (zum Beispiel 400dp) und die Bildschirmbreite von 320, 360, 411 oder 480 dp überschreitet, da auf einem Telefon mit kleinem Bildschirm ein solches Element verdeckt werden oder überlaufen kann. Elemente mit der Breite match_parent oder wrap_content passen sich automatisch an den Bildschirm an und müssen nicht geprüft werden.

Ressourcen-Manager
Um alle Ressourcen eines Projekts an einem Ort zu sehen und zu verwalten (wie der Ressourcen-Manager in Android Studio): Öffnen Sie Ressourcen-Manager im Hauptmenü, wählen Sie das Projekt und drücken Sie Ressourcen anzeigen. Die IDE meldet die Anzahl und Größe der Dateien pro Kategorie (drawable, layout, values, mipmap und andere), den Inhalt von strings.xml, colors.xml und styles.xml. Vom selben Bildschirm aus kann eine neue Zeichenkette zu strings.xml und eine neue Farbe zu colors.xml hinzugefügt werden, indem Name und Wert ausgefüllt werden — der Name wird geprüft und Duplikate werden abgelehnt, sodass die XML-Datei nicht beschädigt wird.

Schlanker Leistungsmonitor
Um die RAM- und Prozessornutzung einer laufenden App zu überwachen (wie der Profiler in Android Studio, leichte Version): Öffnen Sie Schlanker Leistungsmonitor im Hauptmenü, führen Sie zuerst die zu prüfende App aus (zum Beispiel die erstellte App, die gerade getestet wird), füllen Sie ihren Paketnamen aus — oder wählen Sie das Projekt und drücken Sie Paketnamen aus Projekt ausfüllen — und drücken Sie dann Überwachung starten. Alle 2 Sekunden zeichnet die IDE den RAM (PSS) und die CPU dieser App zusammen mit dem freien RAM des Telefons auf; drücken Sie Stopp, um die Zusammenfassung von Durchschnitt und Spitze zu sehen. Ohne zusätzliche Berechtigung. In neueren Android-Versionen ist der Lesezugriff auf den Prozessor einer anderen App vom System begrenzt, sodass, wenn die CPU nicht gelesen werden kann, der Bericht dies so sagt, wie es ist, und der RAM weiterhin überwacht wird.

Barrierefreiheit-Audit
Um vor der Veröffentlichung zu prüfen, ob ein Projektlayout screenreaderfreundlich ist (TalkBack/Jieshuo): Öffne Barrierefreiheit-Audit im Hauptmenü, wähle ein Projekt und tippe dann auf Layoutliste laden und wähle eine Layoutdatei. Die IDE liest diese XML-Datei und meldet Schaltflächen ohne Beschriftung samt ihren Zeilennummern, mehrfach verwendete Beschriftungen und Elemente, die sich gegenseitig überdecken, und erstellt dann ein Transkript der Fokusreihenfolge, wie es Jieshuo vorliest. Wenn eine Schaltfläche keine Beschriftung hat, trage ihre Beschriftung ein und tippe dann auf Beschriftungen automatisch einfügen — die Beschriftung wird als contentDescription in die Layoutdatei geschrieben. Diese Prüfung liest nur Layout-XML; Compose-Ansichten und fertige APKs werden noch nicht geprüft.

Absturz-Autopsie
Um herauszufinden, warum eine App von selbst schließt, anhand eines Absturzprotokolls mit eindeutiger ID: Öffnen Sie Absturz-Autopsie im Hauptmenü, wählen Sie eine Absturz-ID aus der Protokollliste und tippen Sie auf Prüfen. Die IDE gleicht Klasse und Zeilennummer im Protokoll mit der Projektquelle ab und erklärt die Ursache auf Indonesisch (zum Beispiel eine leere Referenz, eine noch nicht angefragte Berechtigung oder ein JSON-Fehler), mit einem vorgeschlagenen Code-Patch. Tippen Sie nur dann auf Patch anwenden, wenn die Quellzeile noch genau dieselbe ist wie zum Zeitpunkt des Absturzes; wenn sie sich geändert hat, wird der Patch abgelehnt und die IDE bittet Sie, selbst zu prüfen. Für Abstürze einer GEBAUTEN App tippen Sie auf Absturzfänger in Projekt injizieren und bauen Sie dann die APK wie gewohnt: Diese gebaute App fängt ihre eigenen Abstürze ab und schreibt ihr Protokoll auf das Telefon, und dieses Protokoll kann mit der Schaltfläche Absturzprotokoll der gebauten App suchen gefunden werden. Die ehrliche Grenze: Das Kopieren des Protokolls in den öffentlichen Download-Ordner kann unter Android 11 und neuer ohne die Alle-Dateien-Zugriffsberechtigung fehlschlagen.

Paradigmenübergreifender Transpiler
Um einfachen Java-Code in Kotlin umzuwandeln oder ein einfaches XML-Layout in Compose-Code: Öffne Paradigmenübergreifender Transpiler im Hauptmenü, wähle ein Projekt und eine Datei und tippe dann auf Vorschau. Die IDE zeigt das Umwandlungsergebnis als Text — prüfe es zuerst, denn Zeilen, die sie nicht erkennt, bleiben unverändert, und das Wort static aus Java entfällt in Kotlin (prüfe seine Bedeutung, bevor du es verwendest). Die Umwandlung von XML nach Compose ändert nur Text, Hinweise und Ausrichtung — Größe, Farbe und andere Attribute sind noch nicht dabei. Wenn das Ergebnis richtig ist, tippe auf Auf Datei anwenden, um die Zieldatei zu schreiben; die Quelldatei wird nicht geändert. Nur sichere, gängige Muster werden umgewandelt.

Lokaler Mikroserver
Um eine App zu testen, die einen Server braucht, ohne Internet: Öffnen Sie Lokaler Mikroserver im Hauptmenü, schreiben Sie die Routendefinitionen (zum Beispiel GET /halo und dann seine JSON-Antwort) und tippen Sie auf Server starten. Die IDE betreibt einen kleinen HTTP-Server auf demselben Telefon (nur HTTP, kein TLS, für dasselbe WLAN) und protokolliert jede Anfrage und Antwort auf dem Bildschirm. Routen können Parameter wie {nama} und einen einfachen API-Schlüssel nutzen. Der Server kann auch in die gebaute APK gebündelt werden: Tippen Sie auf Server in Projekt bündeln, dann werden Serverquelle, Assets und Manifest in das Projekt injiziert, sodass die gebaute App selbst zum Server wird, wenn sie ausgeführt wird. Der Server in der IDE stoppt, wenn sein Bildschirm geschlossen wird.

Sicherheits-Auditor
Um Projektcode vor der Veröffentlichung auf Sicherheitslücken zu prüfen: Öffnen Sie Sicherheits-Auditor im Hauptmenü, wählen Sie ein Projekt und tippen Sie auf Scan starten. Die IDE scannt den Projektcode, das Manifest und die Konfiguration und meldet Funde von hohem zu niedrigem Risiko — einen API-Schlüssel, der offen im Code liegt, eine Komponente ohne Berechtigung, ein WebView, das JavaScript mit seiner JavaScript-Schnittstelle aktiviert, schwache Krypto (MD5, SHA1, DES), eine http-Adresse ohne TLS und ein Passwort, das direkt im Code steht — mit ihren Dateien und Zeilennummern. Für Funde, deren Korrektur sicher ist (zum Beispiel MD5 zu SHA-256 oder http zu https ändern), tippen Sie auf Patch anwenden; für API-Schlüssel und Passwörter zeigt die IDE nur den Korrekturvorschlag, weil der Ersatz vom Entwickler selbst entschieden werden muss. Der Scan parst jetzt auch den echten DEX-Bytecode in der gebauten APK (nicht nur Textmuster im Code), sodass gefährliche APIs, die aufgerufen werden, und Geheimnisse, die im DEX eingebettet sind, ebenfalls erkannt werden; Lücken ohne Muster können dem Scan weiterhin entgehen — prüfen Sie vor dem Anwenden.

Testroboter für die Benutzeroberfläche
Um einen App-Bildschirm automatisch über Text-Szenarien zu testen: Öffnen Sie Testroboter für die Benutzeroberfläche im Hauptmenü, wählen Sie ein Projekt und tippen Sie auf Szenario automatisch erstellen. Die IDE liest das Manifest und Layout des Projekts und schreibt ein Szenario als Textschritte (eine Schaltfläche antippen, ein Feld ausfüllen, warten, zurückgehen). Tippen Sie auf Dry Run ausführen, um das Szenario-Ausführungsprotokoll mit seinen Zeitstempeln zu sehen — dieser Dry Run ist weiterhin nur eine Sequenzsimulation. Für echte Tests tippen Sie auf Testagent in Projekt injizieren: Die IDE injiziert einen Testagenten mit den Szenario-Assets in das Projekt; bauen Sie die APK wie gewohnt, installieren Sie sie und öffnen Sie dann das Test-Symbol — dieser Agent läuft innerhalb der gebauten App und tippt wirklich auf Schaltflächen, füllt echte Felder aus und scrollt und zeigt dann seinen Bericht auf dem Bildschirm mit den echten Abstürzen, die er abgefangen hat. Tippen Sie auf Testagent aus Projekt entfernen, um diesen Agenten wieder zu entfernen. Der Agent läuft innerhalb des App-Prozesses selbst, braucht also keinen Accessibility-Dienst und keine Systemautomatisierung.

Code-Zeitreise
Um ein Projekt in einen früheren Codezustand zurückzubringen, ohne Git-Befehle einzutippen: Öffne Code-Zeitreise im Hauptmenü, wähle ein Projekt, trage eine Bezeichnung für den Zeitpunkt ein (kann leer bleiben) und tippe dann auf Zeitpunkt aufzeichnen. Die IDE speichert eine Kopie der Projektquelldateien zusammen mit ihren Hashes im Ordner .riwayat innerhalb des Projekts. Die Liste der Zeitpunkte zeigt sie alle; wähle zwei Zeitpunkte und tippe dann auf Vergleichen, um hinzugefügte, geänderte oder gelöschte Dateien und Funktionen zu sehen. Tippe auf Wiederherstellen, um einen alten Zustand zurückzuholen — vor dem Wiederherstellen erstellt die IDE immer zuerst eine Sicherung des aktuellen Zustands, sodass nichts verloren geht. Tippe auf Experimentkopie erstellen, um das Projekt in einen neuen Ordner zu kopieren und Änderungen auszuprobieren, ohne das Originalprojekt zu stören. Nur Quelldateien werden aufgezeichnet.

Modulfabrik
Um einen Teil eines Projekts als Modul zu verpacken, das ein anderes Projekt nutzen kann: Öffne Modulfabrik im Hauptmenü, wähle ein Quellprojekt, hake die zu verpackenden Bildschirm-, Klassen-, Text- und Berechtigungsdateien an und tippe dann auf Als Modul verpacken. Die IDE schreibt ein ZIP-Archiv zusammen mit JSON-Metadaten (Modulname, Version, verwendete Texte und Berechtigungen). Um ein Modul in ein anderes Projekt zu installieren, öffne die Modulfabrik, wähle das Zielprojekt und tippe dann auf Modul installieren und wähle die .zip-Datei des Moduls — das Zusammenführen fügt Texte und Berechtigungen hinzu, ohne bestehenden Code zu überschreiben, und führt eine Datei nicht zusammen, wenn ihr Name im Zielprojekt schon verwendet wird. Ein Modul bringt keine Bibliotheken oder Build-Einstellungen mit.

Polymorpher Schild und Asset-Tresor
Um Bezeichnernamen zufällig zu machen und Projekt-Assets vor der Veröffentlichung zu verschlüsseln: Öffnen Sie Polymorpher Schild und Asset-Tresor im Hauptmenü, wählen Sie ein Projekt und tippen Sie auf Namen zufällig machen und Assets verschlüsseln. Die IDE scannt Klassen- und Methodennamen im Quellcode, erstellt eine Zufallsnamen-Tabelle, schreibt diese Namen IN den kompilierten DEX-Dateien neu (die Ersatznamen werden genauso lang wie die Originalnamen gemacht, damit alle Offsets gültig bleiben, danach werden Prüfsumme und SHA-1-Signatur des DEX-Kopfs neu berechnet), verschlüsselt die Projekt-Asset-Dateien mit AES-GCM in den Ordner brankas-aset im Projekt und speichert eine verschlüsselte Wiederherstellungstabelle (perisai-peta.brankas), damit Originalnamen beim Lesen von Absturzprotokollen wiederhergestellt werden können. Der Verschlüsselungsschlüssel wird jetzt aus dem Entwicklerpasswort mit PBKDF2, 20.000 Iterationen, abgeleitet, nicht mehr aus dem Projektnamen. Namen, die auch als einfacher Text, Annotationsnamen und Debug-Namen verwendet werden, werden absichtlich nicht neu geschrieben, und die Einfügepunkte der DEX-Neuschreibung im Build-Pfad warten noch auf einen Test auf einem echten Telefon.

Vertrauenskette und Umgebungswächter
Um die Signaturschlüsselkette und die Telefonumgebung vor der Veröffentlichung zu prüfen: Öffnen Sie Vertrauenskette und Umgebungswächter im Hauptmenü, wählen Sie ein Projekt und tippen Sie auf Kette und Umgebung prüfen. Die IDE baut eine Schlüsselkette aus 5 Generationen aus dem Paketnamen des Projekts und prüft ihre Integrität, prüft die echte Speicherintegrität, indem sie den Inhalt von Code-Segmenten im Speicher mit den Dateien auf dem Datenträger vergleicht, und meldet anonyme ausführbare (RWX) Mappings, fremde Bibliotheken und memfd-Mappings; danach scannt sie die Speicherkarte ihres eigenen Prozesses und die Geräteeigenschaften nach Spuren von Frida, Xposed oder einem Emulator. Der Tresorschlüssel wird mit einem AES-Schlüssel im AndroidKeyStore verpackt, der den Hardware-Sicherheitschip nutzt, wenn einer verfügbar ist, und die Schlüsselrotation ist jetzt echt und nutzt die Signaturzertifikats-Linie des Schemas v3: Der alte Schlüssel signiert den Rotationsnachweis zum neuen Schlüssel und die APK wird mit dieser Linie neu signiert. Das Ergebnis ist eine Risikostufe Sicher, Vorsicht oder Gefährlich, mit Textbelegen. Wenn das System das Lesen des Speichers verweigert, wird die Prüfung als nicht prüfbar gemeldet, nicht als sicher; und ob ein Schlüssel wirklich den Hardware-Sicherheitschip nutzt, kann nur auf einem echten Gerät bestätigt werden.

Textbaum-Layout-Architekt
Um einen Bildschirm zu entwerfen, ohne ihn zu sehen: Öffnen Sie Textbaum-Layout-Architekt im Hauptmenü, wählen Sie ein Projekt und eine Layout-Datei und tippen Sie auf Layout prüfen. Die IDE liest das XML-Layout als Textbaum und liest eine Positionsbeschreibung für jedes Element vor (zum Beispiel unten rechts, 45 Prozent der Bildschirmbreite), meldet dann Überlappungen zwischen Elementen und Elemente, die bei 360 dp Breite aus dem Bildschirm laufen, mathematisch. Was jetzt berechnet wird, umfasst LinearLayout und einfache dp-Größen, das vollständige ConstraintLayout (alle Constraints, Bias, Ketten, Guidelines, Barrieren, Prozentbreiten, 0dp match_constraint und Seitenverhältnisse) sowie Compose-Bildschirme (Column, Row und Box mit ihren Größen-Modifiern). Nur MotionLayout und zur Laufzeit geänderte ConstraintSets werden weiterhin als Position unbekannt gemeldet, weil ihre Werte erst existieren, während die App läuft.

Designsystem-Studio
Um Abstände, Schrift und Ecken auf allen Bildschirmen und Projekten anzugleichen: Öffnen Sie Designsystem-Studio im Hauptmenü, wählen Sie ein Projekt, schreiben Sie die Design-Token (zum Beispiel jarak=8, huruf=16, sudut=12), wählen Sie eine Komponente und tippen Sie auf Komponenten erzeugen. Die IDE prüft die Token — Basisabstand 4 bis 16 dp, Basisschrift 12 bis 20 sp, Ecken 0 bis 32 dp und ein Mindest-Touchbereich von 48 dp — und schreibt dann gebrauchsfertige XML-Komponenten (komponen-studio.xml) mit einem XML-Theme (tema-studio.xml) und einem Compose-Theme (tema-studio.kt) in den Projektordner. Token können auch als benannter Satz in der gemeinsamen projektübergreifenden Token-Bibliothek gespeichert werden, und ein einziger Sync-Befehl wendet die neuesten Bibliotheks-Token auf alle Projekte an, die diesen Satz nutzen. Komponenten werden als Text erzeugt, der in ein Layout eingefügt und dann mit dem Textbaum-Layout-Architekt geprüft wird; die zweispaltige Tablet-Anpassung nutzt einen Bildschirmbreiten-Qualifier, keine Laufzeit-Geräteerkennung.

Semantisches Refactoring und AST-Navigation
Um Definitionen zu finden und Symbole umzubenennen, ohne anderen Code zu beschädigen, der zufällig denselben Namen trägt: Öffnen Sie Semantisches Refactoring und AST-Navigation im Hauptmenü, wählen Sie ein Projekt und tippen Sie auf Projektsymbole scannen, um alle Klassen und Methoden mit ihren Dateien und Zeilennummern zu sehen. Geben Sie einen Symbolnamen ein und tippen Sie erneut auf Projektsymbole scannen, um seine Definition und alle Dateien zu sehen, die ihn aufrufen. Zum Umbenennen geben Sie den neuen Namen ein, tippen Sie auf Umbenennung – Vorschau, um die Anzahl der Vorkommen in jeder Datei zu sehen, und dann auf Umbenennung anwenden. Der Indexer nutzt jetzt einen selbst gebauten AST-Parser (einen Lexer und rekursiven Parser für Java und eine Kotlin-Teilmenge), sodass dateiübergreifende Methodenumbenennungen aufgelöst werden und Aufrufer in anderen Dateien ebenfalls geändert werden; die Schaltfläche zum Extrahieren eines Codeblocks in eine neue Funktion ist jetzt auf diesem Bildschirm. Dieser Parser ist noch minimal: Sehr komplexe Generics, parametrisierte Annotationen und anonyme Klassen werden so gescannt, wie sie sind, während Aufrufe über Reflection und über Interfaces nicht aufgelöst werden.

Schritt-Debugger und Speicherinspektor
Um Variableninhalte mitten im Programmablauf zu prüfen, ohne durch Protokolle zu raten: Öffnen Sie Schritt-Debugger und Speicherinspektor im Hauptmenü, wählen Sie ein Projekt, schreiben Sie den Ausführungs-Trace (ein Schritt pro Zeile, in der Form Zeilennummer, Code, dann Variablen und Werte getrennt durch |, zum Beispiel 10|int total = harga * jumlah;|harga=5000, jumlah=3, total=15000), geben Sie die Haltepunkt-Zeilennummer ein und tippen Sie auf Debug-Ablauf ausführen. Die IDE läuft bis zum ersten Haltepunkt und liest die aktive Zeile mit ihren Variablenwerten über Jieshuo vor. Tippen Sie auf Eine Zeile weiter, um eine Zeile weiterzugehen, auf In Funktion eintreten, um in die aufgerufene Funktion einzutreten (mit einem Aufrufstapel), oder auf Programm fortsetzen, um bis zum nächsten Haltepunkt zu laufen. Dieser Trace-Debugger folgt weiterhin einem aufgezeichneten oder handgeschriebenen Trace; daneben gibt es einen reinen Java-JDWP-Drahtprotokoll-Client, der Handshake, Haltepunkte setzen, Ein-, Über- und Austreten sowie das Anhalten und Fortsetzen der VM über TCP oder im Listen-Modus kann. Das Anhalten eines echten Prozesses ist aus einer gewöhnlichen App heraus weiterhin nicht vollständig möglich, weil ein JDWP-Socket eines Prozesses nur über adbd offengelegt wird — der bewährte Weg braucht drahtloses Debugging und das Starten des Ziels über die Shell, jenseits dessen, was die App selbst kann.

Offline-Abhängigkeitsmanager
Um Bibliotheken von Drittanbietern ohne Internet zu nutzen und Versionskonflikte vor dem Build zu vermeiden: Öffnen Sie Offline-Abhängigkeitsmanager im Hauptmenü, wählen Sie ein Projekt und tippen Sie auf Abhängigkeiten prüfen. Die IDE liest alle .gradle-Dateien des Projekts, prüft den gemeinsamen projektübergreifenden Tresor im Ordner Download/brankas-bersama und löst Konflikte — wenn zwei Bibliotheken unterschiedliche Versionen desselben Artefakts verlangen, wird die höchste Version verwendet und der Konflikt gemeldet. Um eine Bibliothek herunterzuladen, geben Sie ihre Koordinaten ein (in der Form Gruppe:Artefakt:Version, zum Beispiel com.google.code.gson:gson:2.10.1) und tippen Sie auf Abhängigkeiten prüfen: Im Online-Zustand werden AAR-, JAR- oder WHL-Dateien wirklich von Maven, Google oder PyPI heruntergeladen, zusammen mit ihrem transitiven Abhängigkeitsgraphen (rekursiv, Zyklen getrennt, Tiefe bis zu 25 Ebenen), und nur erfolgreich heruntergeladene Dateien werden als verfügbar vermerkt. Im Offline-Zustand können nur Bibliotheken verwendet werden, die bereits im gemeinsamen Tresor sind. Maven-Versionsbereiche werden nicht aufgelöst, und heruntergeladene Dateien werden nur anhand ihres SHA-1 geprüft, ohne PGP-Verifizierung.

Datenbank- und Speicherinspektor
Um den Inhalt einer Projektdatenbank zu prüfen und zu testen, ohne Code zu schreiben, der Tabelleninhalte ausgibt: Öffnen Sie Datenbank- und Speicherinspektor im Hauptmenü, wählen Sie ein Projekt und eine Datenbankdatei (.db, .sqlite oder .sqlite3) und tippen Sie auf Datenbank öffnen. Die IDE liest das Schema aller Tabellen mit einem vollständigen SQLite-Seitenparser (B-Baum mit Überlaufseiten) und zeigt die ersten 20 Zeilen als Texttabelle, die von Jieshuo vorgelesen wird. Schreiben Sie eine SELECT-Abfrage und tippen Sie auf Abfrage ausführen (zum Beispiel SELECT nama FROM pengguna WHERE kota = 'Makassar') — Abfragen unterstützen jetzt JOIN, GROUP BY, ORDER BY und LIKE und laufen auf dem Telefon über die echte Android-SQLite-Engine. Um einen Wert zu ändern, geben Sie die Zeilennummer (1 = erste Zeile), den Spaltennamen und den neuen Wert ein und tippen Sie auf Zellenwert ändern — dieser Wert wird in die .db-Datei zurückgeschrieben. Tippen Sie auf Sicherung speichern, um den aktuellen Tabellenzustand als Datei <db-name>.cadangan.txt im Projekt zu speichern. SharedPreferences und DataStore können ebenfalls gelesen werden. Was weiterhin nicht gelesen werden kann: verschlüsselte Datenbanken, nicht committete WAL-Änderungen und typisierte Werte in speziellem DataStore Proto (nur als generische Feldansicht gezeigt).

Unit-Test-Fabrik und Fuzzing
Um Logiklücken zu finden, bevor eine App geteilt wird: Öffnen Sie Unit-Test-Fabrik und Fuzzing im Hauptmenü, wählen Sie ein Projekt und eine Codedatei und tippen Sie auf Tests erstellen und ausführen. Die IDE liest die Funktionssignaturen in der Datei, erzeugt normale und Grenz-Testfälle (leerer Text, null, maximale Zahlen, seltsame Zeichen) und führt diese Tests dann wirklich aus: Der Projektcode wird kompiliert und jede @Test-Methode wird mit einer 5-Sekunden-Grenze ausgeführt, sodass das Ergebnis echte Bestehens- und Fehlschläge mit ihren tatsächlichen Werten sind. Fuzzing läuft ebenfalls wirklich über Projektfunktionen (über Reflection, 2 Sekunden pro Aufruf, höchstens 20 Methoden), und der Zeilenabdeckungsprozentsatz wird wirklich durch Instrumentierung berechnet, die die ursprünglichen Zeilennummern beibehält. Das Ergebnis meldet, wie viele Tests bestanden und fehlgeschlagen sind, wie viele Codezeilen und Funktionen gefunden wurden und welche Testfälle erstellt wurden. Die erzeugten Tests nutzen genau dieselbe API wie JUnit, aber die Annotations- und Assertions-Definitionen stehen in der erzeugten Testdatei selbst, weil die echte JUnit-Bibliothek nicht in der App gebündelt ist.

Simulator für extreme Gerätebedingungen und Speicherleck-Prüfer
Um zu testen, wie widerstandsfähig eine App ist, wenn das System ihren Prozess beendet, das Netzwerk abbricht, der Bildschirm sich dreht oder der Batteriesparmodus aktiv wird: Öffnen Sie Simulator für extreme Gerätebedingungen und Speicherleck-Prüfer im Hauptmenü, wählen Sie ein Projekt und tippen Sie auf Simulation ausführen. Die IDE führt drei Druckszenarien mit einer Bildschirmdreh-Simulation aus und verfolgt Objekte, die nach dem Schließen ihres Bildschirms noch im Speicher gehalten werden, und meldet dann verlorene Daten und leckende Objektketten. Der Speicher- und Wiederherstellungszustand wird jetzt aus der Quelle des eigenen Projekts des Nutzers gelesen, nicht aus einem festen Beispiel; der lokale Loopback-Server wird mitten im Test wirklich gestoppt, um den Netzabbruch zu messen; ein echter Heap-Dump wird genommen und geparst, um zwei Dumps zu vergleichen und die Haltekette von den GC-Wurzeln aus zu verfolgen; und der eigene Prozess der App wird nach dem Speichern seines Zustands wirklich beendet, dann wird geprüft, welche Daten beim erneuten Öffnen zurückkommen. Was aus einer gewöhnlichen App weiterhin unmöglich ist: das Telefon-Funkmodul oder WLAN abzuschalten und andere Apps per Force-Stop zu beenden — beides braucht Systemberechtigung; stattdessen werden Hintergrund-Apps über killBackgroundProcesses beendet, dessen Berechtigung bereits im Manifest ist, mit einer ehrlichen Beschriftung auf dem Bildschirm.

Projekt-Blaupausen-Architekt
Um eine große App-Idee in einen schrittweisen Arbeitsplan zu verwandeln: Öffnen Sie Projekt-Blaupausen-Architekt im Hauptmenü, wählen Sie ein Projekt, schreiben Sie die App-Idee (zum Beispiel eine Kassen-App für einen kleinen Lebensmittelladen mit Ratenzahlung) und tippen Sie auf Blaupause erstellen. Die IDE baut Module, eine Dateiliste und kleine Meilensteine und speichert sie als cetak-biru.txt im Projektordner. Tippen Sie auf Nächsten Meilenstein als erledigt markieren, sobald ein Meilenstein fertig ist, oder auf Gespeicherten Bauplan laden, um eine gespeicherte Blaupause wieder zu öffnen. Wenn in den KI-Einstellungen ein aktiver KI-Anbieter gewählt ist und sein Schlüssel verfügbar ist, wird die Blaupause von diesem Anbieter erstellt; wenn es keinen Schlüssel gibt oder der Anbieter nicht erreichbar ist, fällt die IDE auf die Offline-Schlüsselwortmuster zurück und sagt diese Grenze ehrlich. Eine Anbieterantwort wird nur auf ihr Format geprüft (Module und Meilensteine vorhanden), nicht auf die Wahrheit ihres Inhalts — prüfen Sie die Blaupause immer vor dem Bauen.

Erzähler des logischen Code-Ablaufs
Um langen Code zu verstehen, ohne Syntax Zeile für Zeile zu hören: Öffnen Sie Erzähler des logischen Code-Ablaufs im Hauptmenü, wählen Sie ein Projekt und eine Codedatei und tippen Sie auf Code-Erzählung. Die IDE verwandelt jede Zeile in einen indonesischen Satz (zum Beispiel wenn die Summe größer als 100000 ist, dann führe den folgenden Block aus), zeigt eine Aufrufkarte zwischen Methoden und eine Datenflussanalyse zwischen Methoden (Werte, die weitergegeben, genutzt oder ignoriert werden) und markiert subtile mögliche Fehler mit ihren Zeilennummern — String mit == verglichen, ein Stream ohne Schließen geöffnet, und eine Variable, die in zwei verschiedenen Methoden geschrieben wird. Wenn in den KI-Einstellungen ein aktiver KI-Anbieter gewählt ist, gibt es auch eine Ablaufzusammenfassung von diesem Anbieter; wenn nicht verfügbar, nutzt der Bildschirm die Offline-Erzählung und sagt diese Grenze. Erzählung, Aufrufkarte und Datenfluss nutzen Offline-Textmusteranalyse, keinen vollständigen AST-Parser — Methoden, deren öffnende Klammer in einer eigenen Zeile steht, Klassenfelder und Aufrufe über Reflection werden nicht verfolgt — und Datenrennen-Warnungen können für eine Variable erscheinen, die in Wirklichkeit nur abwechselnd genutzt wird.

App-Bundle-Fabrik und Play-Store-Bereitschaft
Um eine App direkt vom Telefon aus für den Google Play Store vorzubereiten: Öffnen Sie App-Bundle-Fabrik und Play-Store-Bereitschaft im Hauptmenü, wählen Sie ein Projekt und tippen Sie auf AAB-Bundle erstellen. Die IDE baut die .aab-Datei aus dem Manifest, den Ressourcen und den Assets des Projekts zusammen mit einer echten BundleConfig.pb, validiert die Bundle-Struktur und teilt das Bundle dann in echte Varianten-APKs (Basis, pro Architektur, pro Sprache und universell) mit Größen, die aus dieser Teilung gemessen werden, nicht geschätzt. Das Bundle wird mit JAR v1 signiert, mit demselben Projektschlüssel wie die APK-Signierung, und seine Signaturkette wird kryptografisch verifiziert. Dieser Bildschirm prüft auch die Play-Bereitschaft — ein Ziel-SDK unter 35 wird als Hoch markiert, weil der Play Store 35 oder mehr verlangt, und eine fehlende 64-Bit-Bibliothek wird ebenfalls als Hoch markiert. Ein echtes bundletool kann auf dem Gerät nicht laufen, weil bundletool eine JVM braucht, Android aber keine JVM hat; der obige Weg ist der nächstliegende echte Weg auf dem Gerät.

OTA-Aktualisierungsmodul und gestaffelte Veröffentlichungen
Um eine kleine Korrektur zu senden, ohne dass Nutzer die gesamte APK erneut herunterladen müssen: Öffnen Sie OTA-Aktualisierungsmodul und gestaffelte Veröffentlichungen im Hauptmenü, wählen Sie ein Projekt, schreiben Sie den Inhalt der alten und der neuen Version und tippen Sie auf Patch-Paket erstellen. Die IDE berechnet den Unterschied und erstellt ein Patch-Paket (patch-ota.zip) mit einem SHA-256-Fingerabdruck des neuen Inhalts und prüft dann, ob dieses Gerät in der ersten 10-Prozent-Ausrollstufe ist. Patches unterstützen jetzt binäre Deltas über jede Datei (einschließlich DEX und APK), werden mit einer RSA-2048-Signatur verpackt und vor dem Anwenden mit einem vertrauenswürdigen öffentlichen Schlüssel verifiziert und können vom Entwicklerserver zusammen mit seiner Release-Liste heruntergeladen werden; wenn das Anwenden fehlschlägt, bleibt die alte Datei intakt. Das Anwenden eines Patches auf die gerade laufende App geschieht durch erneutes Signieren mit dem Projektschlüssel und den PackageInstaller, weil das Ersetzen des Codes eines laufenden Prozesses von innen heraus unmöglich ist — die APK ist gesperrt und das DEX ist bereits geladen.

Team-Codeprüfungs-Studio
Um die Änderungen eines Kollegen zu prüfen und Merge-Konflikte zu lösen, ohne Git-Pfeilmarkierungen zu lesen: Öffnen Sie Team-Codeprüfungs-Studio im Hauptmenü, wählen Sie ein Projekt, geben Sie drei Textversionen ein (Basis, lokal, Kollege) und tippen Sie auf Teamprüfung öffnen. Die IDE führt alle drei auf Basis von Java-Syntaxeinheiten zusammen — zwei Änderungen in derselben Zeile, aber in unterschiedlichen Anweisungen, gelten nicht mehr als Konflikt — und zeigt jeden Konflikt als Abstimmungsoption: Lokale Version verwenden, Kollegenversion verwenden oder Beide zusammenführen — die Ergebniszeile wird an der ursprünglichen Konfliktposition eingefügt, damit die Reihenfolge korrekt bleibt — und schreibt dann das Ergebnis in gabung-hasil.txt im Projekt. Darunter ist das Projekt-Aufgabenboard: Geben Sie einen Aufgabentitel ein und tippen Sie auf Aufgabe hinzufügen; Aufgaben werden als Text im Ordner .tugas im Projekt gespeichert und über Commits im In-App-Git synchronisiert, sodass das Board aus jedem Commit-Verlauf wieder gelesen werden kann. Dieser Syntax-Splitter ist kein vollständiger AST-Parser und das In-App-Git speichert einen vollständigen Snapshot pro Commit; es gibt keinen speziellen Sync-Server.

Code-Struktur-Diktat
Um Code per Stimme im Editor zu schreiben: Öffne ein Projekt im Editor und tippe dann auf die Schaltfläche Code-Struktur-Diktat. Sprich Befehle auf Indonesisch, zum Beispiel buat fungsi tambah dengan parameter a angka dan b angka, buat kelas Mobil oder buat variabel teks nama sama dengan Budi — die IDE verwandelt die Sprache in einen syntaktisch gültigen Java-, Kotlin-, Python- oder Compose-Codeblock und fügt ihn an der Cursorposition ein, und liest dann über Jieshuo eine kurze Zusammenfassung vor. Das Diktat nutzt den eingebauten Spracheingabedienst des Systems, ohne zusätzliche Mikrofonberechtigung, und erkennt nur bereits registrierte Befehlsmuster; Sprache außerhalb dieser Muster wird nicht in Code verwandelt. Zahlen, die als Wörter gesprochen werden (zum Beispiel 'lima'), werden noch nicht in Ziffern verwandelt.

Lokaler Kollaborationsraum (ohne Internet)
Um in einem Raum ohne Internet zusammenzuarbeiten: Öffne Zusammenarbeit im Hauptmenü und dann den Abschnitt Lokaler Kollaborationsraum. Ein Handy öffnet eine Sitzung (die IDE zeigt eine lokale IP-Adresse und eine 6-stellige PIN), ein anderes Handy tritt mit dieser Adresse und PIN bei. Textänderungen werden als Zeilenunterschiede gesendet, eine gebaute APK kann an das Handy des Testers gesendet werden, und Absturzberichte vom Handy des Testers kommen zurück. Eine Sitzung ist nur für einen Freund; wenn zwei Personen genau dieselbe Zeile zur selben Zeit ändern, wird die letzte Änderung verwendet. Die PIN wird als Klartext im lokalen Netzwerk gesendet. Dieser Raum wurde noch nicht auf einem echten Handy getestet.

KI-Einstellungen
Um den KI-Anbieter und API-Schlüssel für die App-Erstellung einzurichten: Tippen Sie im Hauptmenü in der Gruppe Einstellungen auf KI-Einstellungen (neben der Schaltfläche Konnektor). Wählen Sie den zu verwendenden Anbieter aus der verfügbaren Liste und aktivieren Sie Modell wechseln, wenn der Anbieter einen Fehler meldet, damit die IDE bei einem Fehlschlag eines Modells automatisch das nächste Modell desselben Anbieters versucht. Tippen Sie auf API-Schlüssel verwalten, um Ersatzschlüssel hinzuzufügen (geben Sie den Namen und den Schlüssel ein und tippen Sie auf Speichern; Schlüssel werden maskiert angezeigt, nur die letzten 4 Zeichen sind sichtbar). Schlüssel werden auf dem Telefon gespeichert und nirgendwohin gesendet, außer an den gewählten Anbieter bei der App-Erstellung. Der gewählte Anbieter wird jetzt wirklich vom Projekt-Blaupausen-Architekt und vom Erzähler des logischen Code-Ablaufs genutzt; die App-Erstellung auf dem Bildschirm KI-App-Ersteller nutzt weiterhin die lokale KI auf dem Telefon (ohne Internet).

Konnektor
Um eine APK zu analysieren und dann zu senden: Tippe im Hauptmenü in der Gruppe Einstellungen auf Konnektor (neben der Schaltfläche KI-Einstellungen). Wähle eine APK-Datei vom Handy, die IDE liest ihren Inhalt (Paketname, Version, Liste der Aktivitäten) und tippe dann auf APK senden, um sie über das Teilen-Menü des Systems zu senden (zum Beispiel WhatsApp oder Drive).

Sprache und Stimme
Um die App-Sprache zu ändern: Öffne Einstellungen, dann App-Sprache und wähle dann eine Sprache oder System folgen. Der Hauptbildschirm und die meisten Bildschirme wechseln sofort zur gewählten Sprache, ohne die App zu schließen oder neu zu starten; einige Bildschirme (zum Beispiel Terminal, Zusammenarbeit, KI-Einstellungen und API-Schlüssel verwalten) nutzen noch die alte Sprache, bis sie erneut geöffnet werden. Wenn du System folgen wählst, folgt die Sprache der Systemsprache des Handys.

Standard-Signatur pro Projekt und Anti Tamper
Seit Version 5.7 wird ein Projekt, das keine persönliche Signatur verwendet, mit dem EIGENEN eingebauten Schlüssel dieses Projekts signiert (einmal im Ordner tanda-tangan-bawaan innerhalb des Projekts erstellt und danach weiter verwendet), sodass sich die eingebaute Signatur von Projekt zu Projekt unterscheidet — kein gemeinsamer Schlüssel mehr für alle Apps. Löschen Sie den Ordner tanda-tangan-bawaan nicht: Ohne diesen Schlüssel kann eine neue APK die alte APK desselben Projekts nicht überschreiben. Die Einstellungen jedes Projekts (separate Architektur, persönliche Signatur, Anti-Tamper, gewählter Keystore, SDK) werden jetzt in der Datei settings.gradle innerhalb des Projekts gespeichert und bei jedem Erstellen des Projekts erneut gelesen. In den Einstellungen, in der Kategorie Signatur, gibt es ein Kontrollkästchen Anti-Tamper der erstellten App: Wenn es aktiv ist, prüft die erstellte App auf dem Gerät bei jedem Öffnen ihre Signatur und ihren Dex-Inhalt; wenn sie neu signiert oder von jemand anderem geändert wurde, verweigert die App die Ausführung. Debugger- und Injektionswerkzeuge wie Frida/Xposed werden ebenfalls erkannt, und das App-Fenster ist gegen Bildschirmaufzeichnung gesperrt.

Demo-Video-Ersteller
Um ein Demo-Video einer erstellten App zu erstellen: Öffnen Sie Demo-Video-Ersteller im Hauptmenü, wählen Sie das Projekt, füllen Sie den Videotitel aus und drücken Sie Demo-Videoskript erstellen — die IDE schreibt video-demo.txt mit 5 Standardszenen (Eröffnung, Hauptansicht, Funktion 1, Funktion 2, Schluss) zusammen mit dem Erzähltext und der Dauer jeder Szene. Drücken Sie HTML-Slideshow erstellen, um video-demo.html aus den Bildern des Projekts (Symbol + Bildschirmfotos, falls vorhanden) zu erstellen, die automatisch alle 5 Sekunden wechseln. Dies ist KEIN .mp4-Video — für ein echtes Video öffnen Sie video-demo.html im Telefonbrowser und nehmen dann den Bildschirm auf, oder lesen Sie die Erzählung in video-demo.txt, während Sie die laufende App aufnehmen.

Neues Aussehen im Stil von Android Studio
Das Aussehen der IDE ist jetzt aufgeräumt und ähnelt Android Studio (nur das Aussehen — alle Knöpfe, Menüs und Abläufe bleiben genau wie zuvor): ein hellgrauer Hintergrund, fette schwarze Bildschirmtitel, blaue Knöpfe mit weißem Text und weiße Eingabefelder mit dünnem Rahmen. Das Hauptmenü ist visuell gruppiert (Ersteller-Funktionen, Cloud, Thema & Sonstiges, Stimme, Code & Neue Funktionen, Werkzeuge), ohne die Knopfreihenfolge zu ändern. Das Terminal verwendet weiterhin ein dunkles Panel wie das Terminal-Fenster in Android Studio, und der Code-Editor hat weiterhin einen weißen Hintergrund mit schwarzem Text. Der gesamte Text wird von Jieshuo weiterhin klar gelesen.

Einstellungen
Um die App einzustellen: Öffnen Sie das Optionsmenü auf dem Hauptbildschirm und drücken Sie Einstellungen. Darin gibt es 12 Kategorien: GitHub-Einstellungen (Sicherheit, persönliche Signatur, Erstellungsverlauf und GitHub-Token), Einstellungen für die APK-Erstellung auf dem Gerät (Keystore-Passwort und Erstellungsverlauf auf dem Gerät speichern), Thema (App-Farben), Signatur (einen Keystore für eine persönliche Signatur erstellen und das Kontrollkästchen Anti-Tamper der erstellten App), Projektordner (Speicherort des Projektordners), Sprache und Stimme (Sprache der Benutzeroberfläche und Sprechgeschwindigkeit des Sprachmodus), Textgröße und Aussehen (Schriftgröße des Editors), Erstellen (Standard-Ziel-SDK und Standard-Architekturaufteilung für den Bildschirm Projekt erstellen), Benachrichtigungen (Ton, wenn ein Erstellen fertig ist), Automatische Sicherung (Sicherungsplan für Projekte), Entwicklerprofil (Name, WhatsApp-Nummer und Konto, die auf dem Spendenbildschirm angezeigt werden) sowie Datenschutz und Daten (Einstellungen zurücksetzen und App-Daten löschen). Jede Kategorie hat eine Schaltfläche Zurück, um zum Kategoriemenü zurückzukehren. Einstellungen, die gerade erst gespeichert wurden (noch nicht angewendet), haben ihre Erklärung ehrlich auf dem Bildschirm geschrieben.

An den Entwickler spenden
Um zu spenden oder den Entwickler zu begrüßen: Drücken Sie die Schaltfläche An den Entwickler spenden auf dem Hauptbildschirm, neben der Schaltfläche Über das Werkzeug. Auf dem Spendenbildschirm gibt es eine Schaltfläche BRI-Konto kopieren — drücken Sie sie, um die Kontonummer des Entwicklers zu kopieren, und fügen Sie sie dann in Ihre Bank-App ein. Es gibt auch einen Abschnitt Entwickler auf WhatsApp begrüßen: Füllen Sie Ihren Namen und Ihre Heimatstadt aus und drücken Sie Per WhatsApp senden — WhatsApp öffnet sich mit der bereits ausgefüllten Begrüßungsnachricht, drücken Sie einfach Senden in WhatsApp und kehren Sie dann zur App zurück. WhatsApp erlaubt es anderen Apps nicht, Nachrichten automatisch zu senden, daher wird das Senden weiterhin von Ihnen selbst in WhatsApp erledigt.

Lieblingsbefehle des Terminals
Um Befehle zu speichern, die oft im Terminal verwendet werden: Öffnen Sie das Terminal und drücken Sie Favorit. Tippen Sie auf Neuen Favoriten hinzufügen, füllen Sie den Namen (zum Beispiel Datei anzeigen) und seinen Befehl (zum Beispiel ls -la) aus und drücken Sie Speichern — der Favorit wird dauerhaft auf dem Telefon gespeichert. Tippen Sie auf einen Favoritennamen, um ihn direkt im Terminal auszuführen; tippen Sie auf Favoriten löschen und wählen Sie einen aus, um ihn zu löschen (mit Bestätigung). Es gibt bereits 3 eingebaute Favoriten: Datei anzeigen (ls -la), Speicher prüfen (df -h) und Bildschirm leeren (clear) — alle können gelöscht werden. Ein leerer Befehl kann weder gespeichert noch ausgeführt werden; das Terminal teilt Ihnen dies per Nachricht und Stimme mit, wenn das passiert.

Analyse & Qualität
Um eine Zusammenfassung der App-Nutzung und Absturzberichte zu sehen: Drücken Sie die Schaltfläche Analyse & Qualität auf dem Hauptbildschirm, neben der Schaltfläche An den Entwickler spenden. Dieser Bildschirm zeigt, wie oft die App geöffnet wurde, welche Bildschirme am häufigsten geöffnet wurden, die Anzahl der Abstürze und die Liste der letzten Abstürze mit einem kurzen Behebungsvorschlag. Diese Daten werden nur auf Ihrem Telefon gespeichert und nirgendwohin gesendet. Es gibt eine Schaltfläche Analysedaten löschen mit einem Bestätigungsdialog, um alle diese Daten zu löschen. Der letzte Bildschirm wird nur für den Hauptbildschirm und diesen Bildschirm aufgezeichnet.
