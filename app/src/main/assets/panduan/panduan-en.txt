Welcome to Create Aplikasi by Al Kautsar
Create Aplikasi is an Android app builder application that runs directly on your phone, without needing a laptop. This application allows anyone to create their own Android applications, including users who are just learning to create applications and screen reader users. The complete guide to using this application is available on this About This Tool screen.

What this application is and who it is for
Create Aplikasi is an Android app builder tool that runs on your phone. This application is intended for anyone who wants to create their own Android applications, including beginners and screen reader users. This application provides a code editor, a Run button to test projects, a Build button to create an APK, and menus for signing and installing the APK.

Purpose of this application
This application was made so that anyone can create their own Android applications easily, directly from a phone. Its interface is made as simple as possible so that even new users can try it right away.

How to create a new project, step by step
1. Press Create Project in the main menu.
2. Choose the project type: HTML, Website, Java, Kotlin, Compose, or Python.
3. Enter the application name, for example: Garuda Decode.
4. Enter the package name, for example: com.android.garudadecode. The package name must use lowercase letters and consist of at least two parts separated by dots.
5. Enter the application version, for example: 1.0, and a version code in the form of a number, for example: 1. If left empty, the version will be filled in automatically with 1.0 and version code 1.
6. Enter the minimum SDK and target SDK if needed. If left empty, the default values will be used. The minimum SDK is the lowest Android version supported, for example: 21 means Android 5.0. The maximum target SDK is 36 (Android 16).
7. Press the Select Permissions button to choose application permissions, for example: INTERNET. The INTERNET permission is already checked by default. Check only the permissions that the application actually needs.
8. If desired, check "Use separate 64-bit and 32-bit architectures" to make the APK size smaller, and check "Use personal signature" if you want to use your own keystore.
9. Press Create Project. The new project is saved in the Download/project folder and immediately appears in Manage Projects.

Available project types
• HTML: display from index.html, style.css, and script.js, running through WebView. Built directly on the phone.
• Website: a website with menus (Home, About, Contact) from index.html, tentang.html, kontak.html, style.css, and script.js, running through WebView. Built directly on the phone.
• Java: built on the phone. MainActivity is located at app/src/main/java/<package-name>/MainActivity.java. The display comes from app/src/main/res/layout/activity_main.xml, the text from app/src/main/res/values/strings.xml, and the theme from app/src/main/res/values/styles.xml.
• Kotlin: can be built on the device (offline) using the Kotlin compiler included in the application, or through GitHub Actions. MainActivity is located at app/src/main/java/<package-name>/MainActivity.kt, and the res files are the same as in a Java project. The first Kotlin build is slower because of the large compiler size, and .java files that reference Kotlin classes cannot yet be built (.java files are compiled before .kt files).
• Compose: a modern Android application whose interface is created with Jetpack Compose (not XML layouts). MainActivity is located at app/src/main/java/<package-name>/MainActivity.kt. Compose projects are built through GitHub Actions (the Build project menu, then Build online) or in Termux with Gradle, because Compose requires the Jetpack Compose libraries, which are not available on the device.
• Python: the application logic is written in the Python language (Chaquopy) in app/src/main/python/main.py, and is run by the host MainActivity.java at app/src/main/java/<package-name>/MainActivity.java. Python projects can be built directly on the phone (the Chaquopy runtime is included in the application) or through GitHub Actions. The minimum SDK for Python projects is 24 (Android 7.0).

File structure of Java, HTML, Website, Kotlin, Compose, and Python projects
Java, HTML, Website, Kotlin, Compose, and Python projects are structured like Android projects in general. Inside the app folder there is the src folder, and inside it there is the main folder. Inside the main folder there is AndroidManifest.xml next to the java folder, the res folder containing layout/activity_main.xml and values/strings.xml as well as values/styles.xml, and for HTML and Website there is the assets folder containing index.html (Website also has tentang.html and kontak.html). HTML and Website projects also have their own MainActivity at app/src/main/java/<package-name>/MainActivity.java, which loads index.html in a WebView and becomes the launcher in the AndroidManifest. Python projects have Python code at app/src/main/python/main.py and the host MainActivity.java at app/src/main/java/<package-name>/MainActivity.java. AndroidManifest.xml, layouts, strings, and styles can be opened and changed in the editor, just like MainActivity. Old projects whose manifest is still next to the app folder can still be built, because when building, the application checks AndroidManifest.xml in app/src/main/ first, then the one next to the app folder, and finally the project data file.

Permission rules (important)
Permissions checked when creating a project are recorded in only one place, according to the project type. For Java, HTML, Website, Kotlin, Compose, and Python projects, the checked permissions are recorded ONLY in AndroidManifest.xml located in app/src/main/, next to the java folder, inside the project folder. The project data file for Java, HTML, Website, Kotlin, Compose, and Python projects does not contain a list of permissions. If you choose Java and then check INTERNET and CAMERA, what is recorded in AndroidManifest.xml is only INTERNET and CAMERA, with no other permissions included. When building, the application reads permissions from the same place: from AndroidManifest.xml in app/src/main/ for Java, HTML, Website, Kotlin, Compose, and Python projects (if there is none, from AndroidManifest.xml next to the app folder for old projects), and from the project data file for old projects.

How to use the editor
Open Manage Projects, tap a project name to open the editor. In the editor, files can be opened, code can be written, and changes can be saved. For Java, HTML, Website, Kotlin, Compose, and Python projects, the files are arranged inside the app/src/main folder. To share a project, use Export ZIP (see the section below).

How to run a project
In the editor, press Run to test the project. For HTML and Website projects, what runs is index.html through WebView. If an error occurs, read the error message, fix the code, then run it again.

How to build an APK
In the editor, press Build. There are two ways to build. First, Build on device: builds directly on the phone without internet, for HTML, Website, Java, Kotlin, and Python projects. Second, Build online through GitHub Actions: builds over the internet on GitHub, and can be used for all project types. Compose projects can only be built the second way (Build online) or in Termux with Gradle, because Compose requires the Jetpack Compose libraries, which are not available on the device. The first build result is not yet signed. After that the application signs it: automatically with the built-in key, or with a personal signature if the "Use personal signature" box was checked when creating the project.

How to install an APK
When the APK is ready, press Install to install it. On Android 8 and above, the phone will first ask for "Allow from this source", because this application installs APKs from outside the Play Store. Enable that permission once in Settings, then return to the application: the installation will continue automatically without needing to press Install again. If the Install button does not appear, make sure the build has finished and the APK has been created.

How to sign an application
Every APK must be signed in order to be installed. There are two choices available. First, the built-in key: the application signs it by itself automatically, without you needing to do anything. Second, a personal signature: first create a keystore through the Create Keystore menu in the main menu, save its password carefully, then check "Use personal signature" when creating the project. The keystore is stored in Download/project/signing.

Exporting a project to ZIP
Export ZIP is provided so that projects can be shared with friends. How to do it: in Manage Projects, long-press the project name, then choose Export ZIP. The result is saved in Download/project/<ProjectName>.zip. The bin folder is not included, so the size is small, only tens of KB. That ZIP file can be sent to friends or uploaded to GitHub.

JAWS Extension
The JAWS Extension uses the extension engine from Jieshuo (CSR), not its screen reader. That way, designs can still run even if the user uses TalkBack. How to do it: open JAWS Extension in the main menu. Because automatic clicking runs by itself, the service must first be enabled in Accessibility Settings. After that, a new design can be created: type the design name, press OK, then fill in its boxes.

Click List kept separate for neatness
Inside a design there are two boxes: the script box and the Click List box. The list of buttons is stored separately in the file daftar_klik.txt, one name per line. An example of its contents: tombolSimpan, tombolHapus, tombolBuka. To open an application, just write >WhatsApp in that list. Old designs that do not yet have a daftar_klik.txt file will display that default example.

Simple functions provided
• klikTombol("tombolSimpan") — clicks one button based on its text.
• klikDaftarTombol(daftar) — clicks the list in daftar_klik.txt, one button per line, in order, then reports how many succeeded and how many were not found.
• bukaAplikasi("WhatsApp") — opens an application by its name, or write ">WhatsApp" in the list.
• klik(540, 1200) — clicks at screen coordinates.
All functions are made simple first. Once you are used to them, additional functions can be added later.

About screen readers
This application is designed to be screen reader friendly. Every input field has a label and a filling example, and all buttons can be reached without complicated gestures. The JAWS Extension is made to keep running even if the user uses TalkBack, because what is used is its extension engine, not its screen reader.

Privacy and security
Projects and keystores are stored on your phone. The GitHub token is only used for online builds and is stored inside this application. Do not share your token or keystore password with anyone. If you use a personal signature, keep the keystore and its password in a safe place, because if they are lost, old APKs cannot be updated with the same signature.

Requirements
Android 5.0 or newer. Storage permission: on Android 11 and above it uses the all-files access permission, on Android 10 and below it uses the regular storage permission (read/write storage) because Android 10 does not have the all-files access permission. Building on device requires a phone with an ARM processor (32 or 64 bit). Building online through GitHub Actions requires internet and a GitHub token. Kotlin projects can be built on device, but the first build is slower and uses more memory because of the large size of the Kotlin compiler. Compose projects are built through GitHub Actions or in Termux with Gradle. Python projects require Android 7.0 or newer (minimum SDK 24) and the resulting APK is larger because it includes the Python runtime (Chaquopy) along with its standard library.

Terminal
The Terminal menu on the main screen opens a terminal inside this application. Commands such as ls can be used to view the contents of the project folder, cd to move between folders, and git to manage code. Command output appears as text that can be read by a screen reader, and there is a Read Result Aloud button to listen to the last result. This terminal uses the phone's system shell, so interactive programs such as nano and vim cannot yet be used here.

License (paid version)
To sell an application, check "Enable License" when creating the project, then enter your WhatsApp number. The built application will ask for a license code when first opened: the user sees their device ID, presses the Send Device ID button to send that ID to your WhatsApp, then you reply with the license code. The license code is calculated from the device ID and the project password (lisensi_seed in the project data file) — keep that password carefully and do not share it. After the correct code is entered, the application opens and does not ask for a code again.

Automatic Icon Maker
New project icons are still transparent, so an Icon Maker is available in the main menu. How to do it: press Icon Maker, write one or two letters (for example the initials of the application name), choose a background color and a text color, view the preview, then press Save to Project to use that icon in the selected project, or Save to Download to use its PNG file elsewhere. After a project is created, the application also offers to create an icon. A project's old icon can be replaced at any time from the project menu in Manage Projects (long-press the project name, then choose Change Icon).

Ready-to-Use Project Templates
If you do not want to start from an empty project, choose a template when creating a project: Calculator (Java), Notes (Java), To-Do List (Kotlin), Web Calculator (HTML), Profile Site (Website), or Counter (Compose). Choosing a template automatically changes the project type to follow that template, and the project is created with ready-made starter code — just run it or change it. If the project type is changed manually again after choosing a template, the template is canceled and the project returns to empty. For HTML and Website templates, the template replaces the contents of index.html, including the HTML script typed in the form.

Back Up and Restore Projects
So that projects are not lost, a backup feature is available. How to do it: in Manage Projects, long-press the project name, then choose Back Up. The backup is saved as a ZIP in the Download/backup folder with the project name and date, for example: GarudaDecode-2026-11-14-123045.zip. Its contents are the same as Export ZIP (the entire contents of the project, without the bin folder). To restore: open the menu in Manage Projects, choose Restore backup, then choose the backup file. If the project name already exists, the application will ask: Overwrite the old project, or save with a New name.

Share and Import Projects
To share a project with friends: in Manage Projects, long-press the project name, then choose Share. The project is sent as a ZIP through sharing applications (WhatsApp, Telegram, and others). To receive a project from a friend: open the menu in Manage Projects, choose Import project, then choose the ZIP file. That ZIP file must contain a project data file — if there is none, the file is rejected with a clear message, because that file is not a Create Aplikasi project. If the project name already exists, the application will ask: Overwrite the old project, or save with a New name.

Project Search and Filter
If there are already many projects, in Manage Projects there is a search box and a type filter. Type the project name in the search box, and the list is filtered immediately (uppercase and lowercase letters are not distinguished). The type filter limits the list to just one type: All, HTML, Website, Java, Kotlin, Compose, or Python. Each project's menu can still be opened as usual from the filtered list.

Building Applications with Voice
If you do not want to type, use your voice: tap Build with Voice in the main menu, then speak a command. Commands you can say: "Buat proyek kalkulator", "Bangun proyek Kalkulator", "Buka proyek Kalkulator", "Jalankan proyek Kalkulator", "Daftar proyek", "Buka ikon", "Kembali", and "Bantuan". The app answers with voice and text, so it can still be used without looking at the screen. Voice recognition uses the phone's built-in speech recognizer app (free; it can work offline if the Indonesian language pack is installed). If the phone has no speech recognizer, commands can be typed in the text box on the same screen.

Accessibility Audit
To check whether a project layout is screen-reader friendly (TalkBack/Jieshuo) before release: open Accessibility Audit in the main menu, choose a project, then tap Load Layout List and choose a layout file. The IDE reads that XML file and reports buttons without labels along with their line numbers, labels used repeatedly, and elements that overlap each other, then builds a focus-order transcript like the one Jieshuo reads aloud. If a button has no label, fill in its label then tap Insert Labels Automatically — the label is written into the layout file as a contentDescription. This check reads layout XML only; Compose views and finished APKs are not scanned yet.

Crash Autopsy
To find out why an app closes by itself from a uniquely-identified crash log: open Crash Autopsy in the main menu, choose a crash ID from the log list, then tap Check. The IDE matches the class and line number in the log against the project source and explains the cause in Indonesian (for example an empty reference, a permission not yet requested, or a JSON error), along with a suggested code patch. Tap Apply Patch only if the source line is still exactly the same as when the crash happened; if it has changed, the patch is refused and the IDE asks you to check it yourself. What is read is the IDE's own crash log, not the log of a built app.

Cross-Paradigm Transpiler
To convert simple Java code into Kotlin, or a simple XML layout into Compose code: open Cross-Paradigm Transpiler in the main menu, choose a project and a file, then tap Preview. The IDE shows the conversion result as text — check it first, because lines it does not recognize are left as they are and the word static in Java is dropped in Kotlin (check its meaning before using it). XML to Compose conversion only changes text, hints, and orientation — size, color, and other attributes are not included yet. If the result is correct, tap Apply to File to write the target file; the source file is not changed. Only safe, common patterns are converted.

Local Micro Server
To test an app that needs a server without internet: open Local Micro Server in the main menu, write a route definition (for example GET /halo followed by its JSON answer), then tap Start Server. The IDE runs a small HTTP server on the same phone (HTTP only, without TLS, for the same Wi-Fi network) and records every request and answer on the screen. Routes can use parameters such as {nama} and a simple API key. This server is only for testing on the phone; a built APK cannot become a server yet, and the server stops when its screen is closed.

Security Auditor
To check for security holes in project code before release: open Security Auditor in the main menu, choose a project, then tap Start Scan. The IDE scans the code, manifest, and project configuration and reports findings from high to low risk — API keys exposed in code, components exposed without permission, a WebView that enables JavaScript together with a JavaScript interface, weak crypto (MD5, SHA1, DES), http addresses without TLS, and passwords written directly in code — along with the file and line number of each. For findings with a safe fix (for example changing MD5 to SHA-256 or http to https), tap Apply Fix; for API keys and passwords, the IDE only shows the suggested fix because the replacement must be decided by the developer. This scan reads text patterns in code, not bytecode, so there may be findings that are actually safe, and a hole without a pattern can slip through the scan — check before applying.

Interface Test Robot
To test an app's appearance automatically using text scenarios: open Interface Test Robot in the main menu, choose a project, then tap Create Automatic Scenario. The IDE reads the project manifest and layouts and writes a scenario of text steps (tap a button, fill a field, wait, go back). Tap Run Dry Run to see the scenario run log with its timestamps. At this stage the robot only runs a simulation (dry run) — real button presses on the phone and catching real crashes are the next stage, so the crash report here is still a sample format.

Code Time Travel
To return a project to an earlier code state without typing Git commands: open Code Time Travel in the main menu, choose a project, fill in a time-point label (it may be empty), then tap Record Time Point. The IDE saves a copy of the project source files together with their hashes in the .riwayat folder inside the project. The time-point list shows all of them; choose two points then tap Compare to see files and functions that were added, changed, or removed. Tap Restore to bring back an old state — before restoring, the IDE always makes a backup of the current state first, so nothing is lost. Tap Create Experiment Copy to copy the project to a new folder and try changes without disturbing the original project. Only source files are recorded.

Module Factory
To package part of a project as a module that another project can use: open Module Factory in the main menu, choose a source project, tick the screen, class, string, and permission files to package, then tap Package as Module. The IDE writes a ZIP archive together with JSON metadata (module name, version, strings, and permissions used). To install a module into another project, open Module Factory, choose the target project, then tap Install Module and choose the module .zip file — the merger adds strings and permissions without overwriting existing code, and does not merge a file if its name is already used in the target project. A module does not carry libraries or build settings.

Polymorphic Shield and Asset Vault
To randomize identifier names and encrypt project assets before release: open Polymorphic Shield and Asset Vault in the main menu, choose a project, then tap Randomize Names and Encrypt Assets. The IDE scans class and method names in the source code, builds a random name map, encrypts the project asset files with AES-GCM into the brankas-aset folder inside the project, and saves an encrypted recovery map (perisai-peta.brankas) so original names can be restored when reading crash logs. The encryption key is derived from the project name, so anyone who knows the project name can open the vault — this is protection from casual reading, not a password-locked vault. What is built here is a name map and an asset vault; rewriting names inside the compiled DEX file is a later stage, so names inside the finished APK are not randomized yet.

Trust Chain and Environment Guard
To check the signing key chain and the phone environment before release: open Trust Chain and Environment Guard in the main menu, choose a project, then tap Check Chain and Environment. The IDE builds a 5-generation key chain from the project package name and checks its integrity, then scans the memory map of its own process and device properties for traces of Frida, Xposed, or an emulator. The result is a risk level of Safe, Caution, or Dangerous, together with the text evidence. This check reads text patterns in the memory map and system properties, not raw memory integrity at native library level, and it does not bind keys to the hardware security chip — an injection tool that hides its text traces can slip past this scan.

Text Tree Layout Architect
To design a screen without seeing it: open Text Tree Layout Architect in the main menu, choose a project and a layout file, then tap Check Layout. The IDE reads the XML layout as a text tree and reads aloud a position narration for each element (for example bottom right, 45 percent of screen width), then reports overlaps between elements and elements that go off-screen at 360 dp width, mathematically. What is calculated is LinearLayout and simple dp sizes; ConstraintLayout and Compose screens are reported as having uncertain positions, not guessed.

Design System Studio
To make spacing, type, and corners consistent across all screens and projects: open Design System Studio in the main menu, choose a project, write the design tokens (for example jarak=8, huruf=16, sudut=12), choose a component, then tap Generate Components. The IDE validates the tokens — base spacing 4 to 16 dp, base type 12 to 20 sp, corners 0 to 32 dp, and a minimum touch area of 48 dp — then writes ready-to-use XML components (komponen-studio.xml) together with an XML theme (tema-studio.xml) and a Compose theme (tema-studio.kt) in the project folder. Components are generated as text that is pasted into a layout and then checked with the Layout Architect; two-column adjustment on tablets uses screen-width qualifiers, not runtime device detection.

Semantic Refactoring and AST Navigation
To find definitions and rename symbols without breaking other code that happens to share a name: open Semantic Refactoring and AST Navigation in the main menu, choose a project, then tap Scan Project Symbols to see all classes and methods with their files and line numbers. Enter a symbol name, then tap Scan Project Symbols again to see its definition and all files that call it. To rename, enter the new name, tap Preview Rename to see the number of occurrences in each file, then tap Apply Rename. This indexer uses text patterns, not a full AST parser: renaming a class applies to all files, while renaming a method applies only to its owning file — callers in other files are not changed, so check the preview and the caller scan results before applying. Extracting a code block into a new function already exists in the logic engine, but it has no button on this screen yet.

Step Debugger and Memory Inspector
To inspect variable contents in the middle of a program flow without guessing through logs: open Step Debugger and Memory Inspector in the main menu, choose a project, write the execution trace (one step per line, in the form line number, code, then variables and values separated by |, for example 10|int total = harga * jumlah;|harga=5000, jumlah=3, total=15000), enter the breakpoint line number, then tap Run Debug Trace. The IDE runs to the first breakpoint and reads aloud the active line together with its variable values through Jieshuo. Tap Step One Line to advance one line, or Continue Program to run to the next breakpoint. This is a trace debugger: it walks through a recorded or hand-written execution trace, it does not pause a running Android app — pausing a real process needs a debug bridge and does not exist at this stage.

Offline Dependency Manager
To use third-party libraries without internet and avoid version conflicts before building: open Offline Dependency Manager in the main menu, choose a project, then tap Check Dependencies. The IDE reads all the project .gradle files, checks the offline vault (brankas-maven.txt inside the project), and resolves conflicts — if two libraries request different versions of the same artifact, the highest version is used and the conflict is reported. To record a library in the vault, enter its coordinates (group:artifact:version form, for example com.google.code.gson:gson:2.10.1) then tap Check Dependencies. Downloading from Maven, Google, or PyPI needs internet: while offline only libraries already in the vault can be used, and adding coordinates only records them in the index — the AAR, JAR, or WHL files themselves are not downloaded automatically. The vault is still stored per project.

Database and Storage Inspector
To inspect and test a project database contents without writing code to print table contents: open Database and Storage Inspector in the main menu, choose a project and a database file (.db, .sqlite, or .sqlite3), then tap Open Database. The IDE reads the table schema and shows the first 20 rows as a text table read aloud by Jieshuo. Write a simple SELECT query then tap Run Query (for example SELECT nama FROM pengguna WHERE kota = 'Makassar'). To change a value, enter the row number (1 = first row), the column name, and the new value, then tap Change Cell Value — the value is written back to the .db file. Tap Save Backup to save the current table state as a <db-name>.cadangan.txt file in the project. Only the first table is read; supported queries are simple SELECT only, without JOIN or GROUP BY; SharedPreferences and DataStore are not read yet.

Unit Test Factory and Fuzzing
To find logic gaps before an app is shared: open Unit Test Factory and Fuzzing in the main menu, choose a project and a code file, then tap Create and Run Tests. The IDE reads function signatures in the file, generates normal and boundary test cases (empty text, null, maximum numbers, strange characters), runs fuzzing on example functions, and writes a JUnit test skeleton (Uji<ClassName>.java) in the project. The result reports how many tests passed and failed, how many lines of code and functions were found, and how many test cases were created. The generated tests are still skeletons — the expected values must be written by the developer — and real fuzzing only runs on the example functions, not on project functions; line coverage percentage is not calculated yet.

Extreme Device Condition Simulator and Memory Leak Auditor
To test app resilience when the system kills its process, the network drops, the screen rotates, or battery saver is on: open Extreme Device Condition Simulator and Memory Leak Auditor in the main menu, choose a project, then tap Run Simulation. The IDE runs three stress scenarios together with a screen-rotation simulation and tracks objects held in memory after their screen is closed, then reports lost data and leaking object chains. This is a simulation over a state model, not really killing a process, not really cutting the phone network, and not a real heap dump; the state model on this screen is still a fixed example, not the state of the user's project screens.

Project Blueprint Architect
To turn a large app idea into a step-by-step work plan: open Project Blueprint Architect in the main menu, choose a project, write the app idea (for example a grocery store cashier app with installments), then tap Create Blueprint. The IDE arranges modules, a file list, and small work milestones, then saves them as cetak-biru.txt in the project folder. Tap Mark Next Milestone Done each time a milestone finishes, or tap Load Saved Blueprint to open a saved blueprint again. Blueprints are built from keyword patterns on the device, not from an online AI model — ideas that are not recognized use a general skeleton (data model, storage, screens, logic) — and building through the active AI provider does not exist at this stage.

Code Logic Flow Narrator
To understand long code without listening to syntax line by line: open Code Logic Flow Narrator in the main menu, choose a project and a code file, then tap Code Narration. The IDE turns each line into an Indonesian sentence (for example if the total is more than 100000, then run the following block), shows a call map between methods, and marks potential subtle bugs with their line numbers — String compared with ==, a stream opened without being closed, and a variable written in two different methods. Narration and checking use offline text patterns, not an online AI model and not full data-flow analysis; patterns that are not recognized are narrated as-is as a line of code, and data-race warnings can appear for variables that are actually only used in turn.

App Bundle Factory and Play Store Readiness
To prepare an app for the Google Play Store straight from the phone: open App Bundle Factory and Play Store Readiness in the main menu, choose a project, then tap Build AAB Bundle. The IDE assembles the .aab file from the project manifest, resources, and assets, simulates download split sizes per architecture (arm64-v8a, armeabi-v7a, x86_64) and language, then audits Play readiness — a target SDK below 35 is marked High because the Play Store requires 35 or more, and a missing 64-bit library is also marked High. The resulting bundle is a standard-structured AAB archive; split sizes are estimates from file sizes, not real bundletool split results, and signing the bundle for the Play Console still uses the same build path as the APK.

OTA Update Engine and Staged Releases
To send small fixes without forcing users to re-download the whole APK: open OTA Update Engine and Staged Releases in the main menu, choose a project, write the old and new version contents, then tap Create Patch Package. The IDE calculates the line differences and creates a patch package (patch-ota.zip) with the SHA-256 fingerprint of the new contents, then checks whether this device is in the early 10 percent rollout stage. Patches here only work on text files (scripts, assets, configuration) — binary DEX or APK patches are not supported yet, and a patch is applied when the app is reopened. The fingerprint in the manifest only proves content integrity, not sender authenticity, because it does not use a private-key signature yet.

Team Code Review Studio
To review a teammate's changes and resolve merge conflicts without reading Git arrow marks: open Team Code Review Studio in the main menu, choose a project, fill in three text versions (base, local, teammate), then tap Open Team Review. The IDE merges all three and shows each conflict as a voice choice: Use local version, Use teammate version, or Merge both — result lines are inserted at the original conflict position so the line order stays correct — then writes the result to gabung-hasil.txt in the project. Below it is the project task board: enter a task title then tap Add Task; tasks are saved as text in the .tugas folder inside the project. Merging uses line matching, not syntax, so two changes to the same line are always treated as a conflict even if their meanings do not collide; the task board syncs by copying its text file together with the Git history, without a dedicated sync server.

Code Structure Dictation
To write code by voice inside the editor: open a project in the Editor, then tap the Code Structure Dictation button. Speak commands in Indonesian, for example buat fungsi tambah dengan parameter a angka dan b angka, buat kelas Mobil, or buat variabel teks nama sama dengan Budi — the IDE turns the speech into a syntactically valid Java, Kotlin, Python, or Compose code block and inserts it at the cursor position, then reads a short summary aloud through Jieshuo. Dictation uses the system's built-in voice input service, without an extra microphone permission, and only recognizes command patterns that are already registered; speech outside those patterns is not turned into code. Numbers spoken as words (for example 'lima') are not yet turned into digits.

Local Collaboration Room (without internet)
To work together in one room without internet: open Collaboration in the main menu, then open the Local Collaboration Room section. One phone opens a session (the IDE shows a local IP address and a 6-digit PIN), another phone joins with that address and PIN. Text changes are sent as line differences, a built APK can be sent to the tester's phone, and crash reports from the tester's phone are received back. One session is for one friend only; if two people change exactly the same line at the same time, the last change is the one used. The PIN is sent as plain text on the local network. This room has not been tested on a real phone yet.

AI Settings
To set the AI provider and API keys for app creation: in the main menu, in the Settings group, tap AI Settings (next to the Connector button). Choose the provider to use from the available list, and tick Switch model when provider errors so that if one model fails, the IDE automatically tries the next model from the same provider. Tap Manage API Keys to add backup keys (fill in the name and the key, then tap Save; keys are shown masked, only the last 4 characters visible). Keys are stored on the phone and are never sent anywhere except to the chosen provider when creating an app. Note: at the moment the provider and key selection is only recorded and shown on the AI Pembuat Aplikasi screen — app creation still uses the local AI on the phone (without internet); use of online providers is coming.

Connector
To analyze an APK and then send it: in the main menu, in the Settings group, tap Connector (next to the AI Settings button). Choose an APK file from the phone, the IDE reads its contents (package name, version, list of activities), then tap Send APK to send it through the system share menu (for example WhatsApp or Drive).

Language and Voice
To change the app language: open Settings, then App Language, then choose a language or Follow System. The main screen and most screens change to the chosen language immediately without closing or restarting the app; some screens (for example Terminal, Collaboration, AI Settings, and Manage Keys) still use the old language until reopened. If you choose Follow System, the language follows the phone system language.
