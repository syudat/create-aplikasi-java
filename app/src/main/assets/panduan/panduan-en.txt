Welcome to Create Aplikasi by Al Kautsar
Create Aplikasi is an Android app builder application that runs directly on your phone, without needing a laptop. This application allows anyone to create their own Android applications, including users who are just learning to create applications and screen reader users. The complete guide to using this application is available on this About This Tool screen.

What this application is and who it is for
Create Aplikasi is an Android app builder tool that runs on your phone. This application is intended for anyone who wants to create their own Android applications, including beginners and screen reader users. This application provides a code editor, a Run button to test projects, a Build button to create an APK, and menus for signing and installing the APK.

Purpose of this application
This application was made so that anyone can create their own Android applications easily, directly from a phone. Its interface is made as simple as possible so that even new users can try it right away.

How to create a new project, step by step
1. Press Create Project in the main menu.
2. Choose the project type: HTML, Website, Java, Kotlin, Compose, or Python.
3. Enter the application name, for example: Garuda Decode.
4. Enter the package name, for example: com.android.garudadecode. The package name must use lowercase letters and consist of at least two parts separated by dots.
5. Enter the application version, for example: 1.0, and a version code in the form of a number, for example: 1. If left empty, the version will be filled in automatically with 1.0 and version code 1.
6. Enter the minimum SDK and target SDK if needed. If left empty, the default values will be used. The minimum SDK is the lowest Android version supported, for example: 21 means Android 5.0. The maximum target SDK is 36 (Android 16).
7. Press the Select Permissions button to choose application permissions, for example: INTERNET. The INTERNET permission is already checked by default. Check only the permissions that the application actually needs.
8. If desired, check "Use separate 64-bit and 32-bit architectures" to make the APK size smaller, and check "Use personal signature" if you want to use your own keystore.
9. Press Create Project. The new project is saved in the Download/project folder and immediately appears in Manage Projects.

Available project types
• HTML: display from index.html, style.css, and script.js, running through WebView. Built directly on the phone.
• Website: a website with menus (Home, About, Contact) from index.html, tentang.html, kontak.html, style.css, and script.js, running through WebView. Built directly on the phone.
• Java: built on the phone. MainActivity is located at app/src/main/java/<package-name>/MainActivity.java. The display comes from app/src/main/res/layout/activity_main.xml, the text from app/src/main/res/values/strings.xml, and the theme from app/src/main/res/values/styles.xml.
• Kotlin: can be built on the device (offline) using the Kotlin compiler included in the application, or through GitHub Actions. MainActivity is located at app/src/main/java/<package-name>/MainActivity.kt, and the res files are the same as in a Java project. The first Kotlin build is slower because of the large compiler size, and .java files that reference Kotlin classes cannot yet be built (.java files are compiled before .kt files).
• Compose: a modern Android application whose interface is created with Jetpack Compose (not XML layouts). MainActivity is located at app/src/main/java/<package-name>/MainActivity.kt. Compose projects are built through GitHub Actions (the Build project menu, then Build online) or in Termux with Gradle, because Compose requires the Jetpack Compose libraries, which are not available on the device.
• Python: the application logic is written in the Python language (Chaquopy) in app/src/main/python/main.py, and is run by the host MainActivity.java at app/src/main/java/<package-name>/MainActivity.java. Python projects can be built directly on the phone (the Chaquopy runtime is included in the application) or through GitHub Actions. The minimum SDK for Python projects is 24 (Android 7.0).

Change Project Architecture
To change the architecture choices of an existing project without creating a new one: in the main menu, tap Change Project Architecture, then choose a project and change the Build 64-bit APK (arm64-v8a) or Build 32-bit APK (armeabi-v7a) checkbox; or in Manage Projects, long-press a project name and choose Change Architecture to open the same screen directly for that project. The rule is: if both checkboxes are on, the build produces two separate APKs, one 64-bit and one 32-bit; if only one checkbox is on, the build produces a single universal APK that still runs on both 64-bit and 32-bit devices. A separate APK for a single variant alone is not supported yet, because the build path only knows the split or universal choice, but each variant choice stays saved inside the project so it is not lost when the screen is opened again.

File structure of Java, HTML, Website, Kotlin, Compose, and Python projects
Java, HTML, Website, Kotlin, Compose, and Python projects are structured like Android projects in general. Inside the app folder there is the src folder, and inside it there is the main folder. Inside the main folder there is AndroidManifest.xml next to the java folder, the res folder containing layout/activity_main.xml and values/strings.xml as well as values/styles.xml, and for HTML and Website there is the assets folder containing index.html (Website also has tentang.html and kontak.html). HTML and Website projects also have their own MainActivity at app/src/main/java/<package-name>/MainActivity.java, which loads index.html in a WebView and becomes the launcher in the AndroidManifest. Python projects have Python code at app/src/main/python/main.py and the host MainActivity.java at app/src/main/java/<package-name>/MainActivity.java. AndroidManifest.xml, layouts, strings, and styles can be opened and changed in the editor, just like MainActivity. Old projects whose manifest is still next to the app folder can still be built, because when building, the application checks AndroidManifest.xml in app/src/main/ first, then the one next to the app folder, and finally the project data file.

Permission rules (important)
Permissions checked when creating a project are recorded in only one place, according to the project type. For Java, HTML, Website, Kotlin, Compose, and Python projects, the checked permissions are recorded ONLY in AndroidManifest.xml located in app/src/main/, next to the java folder, inside the project folder. The project data file for Java, HTML, Website, Kotlin, Compose, and Python projects does not contain a list of permissions. If you choose Java and then check INTERNET and CAMERA, what is recorded in AndroidManifest.xml is only INTERNET and CAMERA, with no other permissions included. When building, the application reads permissions from the same place: from AndroidManifest.xml in app/src/main/ for Java, HTML, Website, Kotlin, Compose, and Python projects (if there is none, from AndroidManifest.xml next to the app folder for old projects), and from the project data file for old projects.

How to use the editor
Open Manage Projects, tap a project name to open the editor. In the editor, files can be opened, code can be written, and changes can be saved. For Java, HTML, Website, Kotlin, Compose, and Python projects, the files are arranged inside the app/src/main folder. To share a project, use Export ZIP (see the section below).

How to run a project
In the editor, press Run to test the project. For HTML and Website projects, what runs is index.html through WebView. If an error occurs, read the error message, fix the code, then run it again.

How to build an APK
In the editor, press Build. There are two ways to build. First, Build on device: builds directly on the phone without internet, for HTML, Website, Java, Kotlin, and Python projects. Second, Build online through GitHub Actions: builds over the internet on GitHub, and can be used for all project types. Compose projects can only be built the second way (Build online) or in Termux with Gradle, because Compose requires the Jetpack Compose libraries, which are not available on the device. The first build result is not yet signed. After that the application signs it: automatically with the built-in key, or with a personal signature if the "Use personal signature" box was checked when creating the project.

How to install an APK
When the APK is ready, press Install to install it. On Android 8 and above, the phone will first ask for "Allow from this source", because this application installs APKs from outside the Play Store. Enable that permission once in Settings, then return to the application: the installation will continue automatically without needing to press Install again. If the Install button does not appear, make sure the build has finished and the APK has been created.

How to sign an application
Every APK must be signed in order to be installed. There are two choices available. First, the built-in key: the application signs it by itself automatically, without you needing to do anything. Second, a personal signature: first create a keystore through the Create Keystore menu in the main menu, save its password carefully, then check "Use personal signature" when creating the project. The keystore is stored in Download/project/signing.

Exporting a project to ZIP
Export ZIP is provided so that projects can be shared with friends. How to do it: in Manage Projects, long-press the project name, then choose Export ZIP. The result is saved in Download/project/<ProjectName>.zip. The bin folder is not included, so the size is small, only tens of KB. That ZIP file can be sent to friends or uploaded to GitHub.

JAWS Extension
The JAWS Extension uses the extension engine from Jieshuo (CSR), not its screen reader. That way, designs can still run even if the user uses TalkBack. How to do it: open JAWS Extension in the main menu. Because automatic clicking runs by itself, the service must first be enabled in Accessibility Settings. After that, a new design can be created: type the design name, press OK, then fill in its boxes.

Click List kept separate for neatness
Inside a design there are two boxes: the script box and the Click List box. The list of buttons is stored separately in the file daftar_klik.txt, one name per line. An example of its contents: tombolSimpan, tombolHapus, tombolBuka. To open an application, just write >WhatsApp in that list. Old designs that do not yet have a daftar_klik.txt file will display that default example.

Simple functions provided
• klikTombol("tombolSimpan") — clicks one button based on its text.
• klikDaftarTombol(daftar) — clicks the list in daftar_klik.txt, one button per line, in order, then reports how many succeeded and how many were not found.
• bukaAplikasi("WhatsApp") — opens an application by its name, or write ">WhatsApp" in the list.
• klik(540, 1200) — clicks at screen coordinates.
All functions are made simple first. Once you are used to them, additional functions can be added later.

About screen readers
This application is designed to be screen reader friendly. Every input field has a label and a filling example, and all buttons can be reached without complicated gestures. The JAWS Extension is made to keep running even if the user uses TalkBack, because what is used is its extension engine, not its screen reader.

Privacy and security
Projects and keystores are stored on your phone. The GitHub token is only used for online builds and is stored inside this application. Do not share your token or keystore password with anyone. If you use a personal signature, keep the keystore and its password in a safe place, because if they are lost, old APKs cannot be updated with the same signature.

Requirements
Android 5.0 or newer. Storage permission: on Android 11 and above it uses the all-files access permission, on Android 10 and below it uses the regular storage permission (read/write storage) because Android 10 does not have the all-files access permission. Building on device requires a phone with an ARM processor (32 or 64 bit). Building online through GitHub Actions requires internet and a GitHub token. Kotlin projects can be built on device, but the first build is slower and uses more memory because of the large size of the Kotlin compiler. Compose projects are built through GitHub Actions or in Termux with Gradle. Python projects require Android 7.0 or newer (minimum SDK 24) and the resulting APK is larger because it includes the Python runtime (Chaquopy) along with its standard library.

Terminal
The Terminal menu on the main screen opens a terminal inside this application. Commands such as ls can be used to view the contents of the project folder, cd to move between folders, and git to manage code. Command output appears as text that can be read by a screen reader, and there is a Read Result Aloud button to listen to the last result. This terminal uses the phone's system shell, so interactive programs such as nano and vim cannot yet be used here.

License (paid version)
To sell an application, check "Enable License" when creating the project, then enter your WhatsApp number. The built application will ask for a license code when first opened: the user sees their device ID, presses the Send Device ID button to send that ID to your WhatsApp, then you reply with the license code. The license code is calculated from the device ID and the project password (lisensi_seed in the project data file) — keep that password carefully and do not share it. After the correct code is entered, the application opens and does not ask for a code again.

Automatic Icon Maker
New project icons are still transparent, so an Icon Maker is available in the main menu. How to do it: press Icon Maker, write one or two letters (for example the initials of the application name), choose a background color and a text color, view the preview, then press Save to Project to use that icon in the selected project, or Save to Download to use its PNG file elsewhere. After a project is created, the application also offers to create an icon. A project's old icon can be replaced at any time from the project menu in Manage Projects (long-press the project name, then choose Change Icon).

Ready-to-Use Project Templates
If you do not want to start from an empty project, choose a template when creating a project: Calculator (Java), Notes (Java), To-Do List (Kotlin), Web Calculator (HTML), Profile Site (Website), or Counter (Compose). Choosing a template automatically changes the project type to follow that template, and the project is created with ready-made starter code — just run it or change it. If the project type is changed manually again after choosing a template, the template is canceled and the project returns to empty. For HTML and Website templates, the template replaces the contents of index.html, including the HTML script typed in the form.

Back Up and Restore Projects
So that projects are not lost, a backup feature is available. How to do it: in Manage Projects, long-press the project name, then choose Back Up. The backup is saved as a ZIP in the Download/backup folder with the project name and date, for example: GarudaDecode-2026-11-14-123045.zip. Its contents are the same as Export ZIP (the entire contents of the project, without the bin folder). To restore: open the menu in Manage Projects, choose Restore backup, then choose the backup file. If the project name already exists, the application will ask: Overwrite the old project, or save with a New name.

Share and Import Projects
To share a project with friends: in Manage Projects, long-press the project name, then choose Share. The project is sent as a ZIP through sharing applications (WhatsApp, Telegram, and others). To receive a project from a friend: open the menu in Manage Projects, choose Import project, then choose the ZIP file. That ZIP file must contain a project data file — if there is none, the file is rejected with a clear message, because that file is not a Create Aplikasi project. If the project name already exists, the application will ask: Overwrite the old project, or save with a New name.

Project Search and Filter
If there are already many projects, in Manage Projects there is a search box and a type filter. Type the project name in the search box, and the list is filtered immediately (uppercase and lowercase letters are not distinguished). The type filter limits the list to just one type: All, HTML, Website, Java, Kotlin, Compose, or Python. Each project's menu can still be opened as usual from the filtered list.

Building Applications with Voice
If you do not want to type, use your voice: tap Build with Voice in the main menu, then speak a command. Commands you can say: "Buat proyek kalkulator", "Bangun proyek Kalkulator", "Buka proyek Kalkulator", "Jalankan proyek Kalkulator", "Daftar proyek", "Buka ikon", "Kembali", and "Bantuan". The app answers with voice and text, so it can still be used without looking at the screen. Voice recognition uses the phone's built-in speech recognizer app (free; it can work offline if the Indonesian language pack is installed). If the phone has no speech recognizer, commands can be typed in the text box on the same screen.

AI App Builder
Type or dictate the app you want on the AI App Builder screen, for example: "a notes app with a save button". The app analyzes the keywords inside the phone itself (no internet, no cost), then creates a real project from the best matching template: calculator, notes, to-do list, web calculator, profile site, or counter. If your description has no matching template yet, the app creates an empty project and says so honestly — it does not pretend to understand. A project made by the AI can be opened directly in Manage Projects.

Live Preview to a Friend's Phone
To show a project to a friend before it is built: in Manage Projects, long-press the project name, then choose Preview to a Friend's Phone. The app creates a small preview package containing the project's main files (index.html, MainActivity, or main.py) plus BACA-SAYA.txt with instructions and info.txt. The package is sent as a ZIP through WhatsApp or Telegram. The friend who receives it can open the preview right away: HTML pages open in the browser, Java/Kotlin/Python code is read as text.

Project Marketplace
The Project Market contains built-in sample projects that can be installed into the project folder with one tap: Calculator, Notes, To-Do List, Web Calculator, Profile Site, Counter, Digital Clock, and Web Quiz. The online market (downloading samples from the internet) is not available yet, so this market contains samples that are already inside the app. An installed project can be opened and changed in Manage Projects like a project you made yourself.

Direct Collaboration
To work on a project together with a friend: open Collaboration in the main menu, choose the project, write a change note (what was changed), then press Share for Collaboration. The project is sent as a ZIP together with a CATATAN.txt file inside it. Your friend works on it and sends the ZIP back; you press Receive Reply, first read the change note, then choose Apply to overwrite the old project, or Cancel if you change your mind. A ZIP without CATATAN.txt is not a collaboration package — for an ordinary project ZIP, use Import project in Manage Projects.

Automatic App Translator
To translate the text in an app to another language: open App Translator in the main menu, choose the project and the target language (English, Arabic, or Javanese), then press Translate. The dictionary is already inside the phone (no internet, no cost) and contains everyday common words; text from strings.xml, layout, and code is read and then translated. The result is written to the values-language/strings.xml folder (if the project has a strings.xml) and a translation-language.txt report in the project folder. Words that are not in the dictionary yet are left as they are and reported — so you know which words still have to be translated by yourself.

No-Code Game Maker
To make a game without writing code: open Game Maker in the main menu, choose the game type (Guess the Number, Quiz, or Catch the Star), fill in the game name, the amount (levels/questions/stars), and the winning message, then press Create Game. The game is made as a real project that can be run directly in Manage Projects and built into an APK like any other project.

Automatic App Testing
To check a project before it is built: in Manage Projects, long-press the project name, then choose Automatic Test. The IDE checks 10 things without building an APK — required files present (project data file, manifest, main file, layout, strings), package name and version, permissions used, icon, and balance of code brackets. The result is shown per item (PASSED/FAILED with a message) and read aloud by Jieshuo. Fix everything that FAILED first, then press Build project.

AI Code Checker
To check project code for patterns that often cause trouble: open Code Checker in the main menu, choose the project, then press Check Code. The checker runs inside the phone (no internet) and looks for unused variables, empty functions, clearly endless loops, text written directly in code (better in strings.xml), dangerous permissions and APIs, TODO/FIXME markers, and dynamic execution. Each finding contains the file name, the line number, and a fix suggestion. This checker is pattern-based, not a real AI — problems that do not follow a pattern can still slip through.

Interactive Learning Mode
To learn to make apps step by step: open Learn in the main menu. There are 5 lessons: Making your first project, Adding a button, Changing the color, Adding sound, and Building an APK. Tap a lesson to read its explanation and practice task, do the task, then press Check task — the IDE really checks whether the task has been done (by scanning the project and the APK on your phone). Lessons that pass are marked done and saved.

Cloud Sync
To back up a project to the cloud: open Cloud Sync in the main menu. A local backup saves the project ZIP to the Download/cloud folder with a timestamp, and can be restored at any time from the backup list. A GitHub backup uploads the project ZIP to your private repo (using the token from GitHub Settings) and can be downloaded again. This is manual backup and restore — full automatic two-way sync needs a server, so it is not available yet.

Automatic Backend Builder
To make a backend without writing server code: open Backend Builder in the main menu, choose the backend type (Notes, To-Do List, or Message Board), fill in the project name, then press Create Backend. The IDE makes a real HTML project with a form page and a data list stored in the phone's local storage (localStorage) — data is stored and can be read back when the app is run. This backend runs on one phone; two phones cannot share the same data yet because there is no internet server.

Automatic Theme Designer
To give a color theme to a project: open Theme Designer in the main menu, choose the project and the theme (Light, Dark, Blue, Green, Red, or Purple). The preview shows the theme's six colors (primary, dark primary, accent, background, text, secondary text) and is read aloud by Jieshuo. Press Apply Theme — the IDE writes colors.xml and styles.xml (app_theme style) to the project, used directly when the project is run or built.

Animation Maker
To give animation to a project: open Animation Maker in the main menu, choose the project, the animation type (Fade, Slide, Rotate, Bounce, or Pulse), the duration (100 to 10000 milliseconds), and the target (button, text, or image), then press Create Animation. The IDE writes a real animation file (res/anim/anim_<type>.xml for Java/Kotlin/Compose projects, or animasi.css for HTML/Web Site projects) together with a sample usage code shown on the screen.

Action Recorder
To repeat work automatically: the IDE records actions that are done (open a project, run, build, export, back up, create a project, save a file). Open Action Recorder in the main menu to see the list of recorded actions with their plan, then press Replay — the IDE runs again the actions that can be automated (back up and create a project run in place; run, build, and export open their main screen; open and save open the editor). Actions that cannot be automated are skipped and reported at the end.

Automatic Security
To check the security of a project: open Automatic Security in the main menu, choose the project, then press Check Security. The IDE checks 8 things locally (no internet): dangerous permissions (location, SMS, calls, camera, microphone, contacts), sending data over HTTP, sending SMS, outgoing calls, a password or key written directly in code, a WebView without protection, a component exported without permission, and an http address without encryption. Each finding is given a level SAFE, WARNING, or DANGER with a fix suggestion, and the summary is read aloud by Jieshuo.

Offline AI
To use text and code helper tools without internet: open Offline AI in the main menu. There are 4 tools: Fix Text (capitals, punctuation, and double spaces), Summarize Text (takes the 3 most important sentences), Make App Name (from the description written), and Suggest Variable Name (looks for 1-2 letter variable names in the project). These are simple rules inside the phone, not a real AI model. The text fix result can be applied to the project's strings.xml with the Apply button.

Widget & Wallpaper Maker
To make a home screen widget: open Widgets & Wallpapers in the main menu, choose the project, fill in the widget text, then press Create Widget. The IDE writes WidgetSaya.java, the widget layout, the widget info, and adds a receiver to the project's AndroidManifest.xml — build the project, then install the widget from the phone's home screen. For a wallpaper: fill in the writing and the background and text colors, make a preview, then save it as a PNG to the Download folder or set it directly as the phone wallpaper.

Social Media Integration
To add share buttons to an app: open Social Media in the main menu, choose the project, then add sharing to WhatsApp, Facebook, or Telegram (or all three at once). The IDE writes real sharing code to the project's main file (MainActivity or index.html). The Test Sharing button opens the sharing chooser from the IDE with a sample text, so the flow can be felt before building the app.

App from Image
To make a gallery app from an image: open App from Image in the main menu, choose an image from the gallery. The IDE analyzes the image size and dominant color, then makes a real gallery app project: the image is copied to the project's assets, the theme color is taken from the image's dominant color, and the app name is taken from the image file name. Open Manage Projects to run or build that gallery app.

Interactive Terminal (VT Parser)
To use interactive programs in the Terminal: open Terminal in the main menu, then run nano, vim, top, or htop. The Terminal now uses a VT parser (a 24 row x 80 column grid screen) so those programs display correctly — the cursor moves, lines are erased, and the screen changes like in a real terminal. There are special Tab, Up Arrow, Down Arrow, and Esc buttons to control interactive programs. The output is still text that Jieshuo can read; press Read the screen aloud to hear the last line.

Exec Terminal (App Binary)
To run a binary in the app folder (for example aapt2, ECJ, D8) from the Terminal: type the command as usual. The IDE uses libkautsarexec.so so binaries in the app folder can be executed on Android 10 and above. Press Exec Test in the Terminal to check whether the binary exec path works on this phone — the result is shown as it is. If exec is blocked by the system, system commands and shell scripts still run; run the binary through the Build project menu instead.

Terminal Keep Alive (KeepAlive)
To keep the shell running while moving to another screen: open the Terminal, run a command, then press Back or move to another screen — the shell does NOT die, and the Terminal notification stays visible so you can return with one tap. Commands that have been run are stored in the history (History button, or the up/down arrows in the command field) and commands that are often used can be saved as favorites (Favorites button). Press Close shell when you are done, so the shell is really killed. There is also a Build button in the Terminal in the project menu and in the editor menu: the Terminal opens in the project folder with the build command already filled in.

Install Terminal Tools (Trial)
A feature still in trial: in the Terminal there is an Install Terminal Tools button to install a Termux environment from the mirror in the developer's alat-termux repository (github.com/syudat/alat-termux), as another path besides the Install Termux button that takes from the official Termux release. The mirror contents are exactly the same as the official release and are checked with SHA-256 during installation. After the environment is installed, the pkg update and pkg install commands can be used, and extra tools from the repository are also installed into the terminal: info-terminal to see environment info, bersih-terminal to clean the cache, and cadangkan-proyek to archive the project folder into one dated tar.gz file. After that the app automatically installs the basic Linux packages (git, python, curl, wget, nano, openssh, zip, unzip) and the APK build tools with signing (openjdk-21, kotlin, gradle, ecj, aapt2, d8, apksigner, clang, cmake, ninja, make) from the official Termux repository, so the terminal is ready at once to build apps. Downloading large packages (hundreds of MB) can take a long time. While installation is running, the progress and command output appear on the Terminal main screen, and the final result is read aloud by the screen reader. If the package installation is not finished yet, press Install Terminal Tools again to continue it.

Full Voice Mode
To control the IDE completely with voice: open Voice Mode in the main menu, then press Start Listening. The IDE listens continuously — there is no need to press a button for each command — runs the command and answers with voice. There are 26 commands: create, build, open, run, list, search, delete, test, check, export, back up, share, make icon, translate, build in terminal, read screen, open all screens (including security, offline AI, widget, social media, game, learn, cloud, backend, theme, animation, recorder), back, close, and help. If the mode is left active, listening continues automatically when this screen is opened again. Press Stop Listening to turn this mode off. If the phone has no voice recognition service, commands can still be written in the text box.

Code Translator
To translate code between languages without internet: open Code Translator in the main menu, choose the project, choose the source file (.java/.kt), then choose the direction: Java to Kotlin. Press Translate — the result is shown together with a report of lines that cannot be translated (those lines are kept as they are and marked). Press Save result to write a NEW file (name-translation.java/.kt) in the same folder; the original file is never overwritten. This is a pattern-rule translator, not a compiler — always check the result before using it.

Git Inside the App
To use Git inside the IDE without Termux: open Git Inside the App in the main menu, choose the project, then press Create Git Repo to make a local repo (.git) in that project. Press Check Status to see files that are new, changed, or deleted compared to the last commit; fill in the commit message, then press Commit to save a snapshot of the project; press View Commit Log to see the commit history. Push to GitHub and Pull from GitHub use snapshots through a GitHub token (the pembuat-aplikasi-build repo) — not the git protocol. Clone, Push (system git), and Pull (system git) only run if the git binary is installed on the phone (usually it is not). This is not full git: there is no merge, branch, or diff — each commit stores a whole ZIP snapshot of the project.

Ad Maker
To add ads to a built app: open Ad Maker in the main menu, choose the project, the provider (AdMob, Unity Ads, or AppLovin), and the ad type (Banner, Interstitial, or Rewarded). Fill in the ad unit ID if you already have one — empty means using a test ID (AdMob uses Google's official test ID; Unity uses a sample Game ID; AppLovin uses an empty placement). Press Create Ad Code to see the Java and Kotlin code and the guide; press Save to Project to write everything to the ads-<provider>-<type>.txt file in the project. This is a code template + guide, not an ad SDK — the SDK is not included in the IDE; real ads only appear after you create a provider account, create an ad unit, paste your own unit ID, and add the SDK dependency in the project's build.gradle.

Kids Mode
To use the IDE together with a child: open Kids Mode in the main menu. The screen is simplified with big buttons and only 4 safe actions: Create Project (from safe templates: Calculator, Guess the Number, Quiz, Catch the Star), Open Project, Run, and Learn. There is no delete, export, backup, or token settings button on this screen. When first entering, make a 4-digit PIN — that PIN is used by the parent to exit Kids Mode (the Exit Kids Mode button or the Back button). This PIN is a light guard for small children, not real security.

Wear OS & TV App Maker
To make a watch app (Wear OS) or a TV app (Android TV): open Wear OS & TV in the main menu, choose the target (Wear OS, Android TV, or both). Fill in the project name, then press Create New Wear/TV Project — the IDE makes a Java project and then adjusts it — or choose a project that already exists, then press Apply to This Project. The adjustments: uses-feature in the manifest, the LEANBACK_LAUNCHER category + banner for TV, and an adjusted activity_main.xml layout (Wear: small screen; TV: large screen friendly to the D-pad). The full explanation is written to wear-tv.txt in the project. This is a project template — building + testing still needs a Wear OS or Android TV device/emulator; the TV banner (banner.png 320x180) is not made automatically, it must be added by yourself (for example through the Icon Maker).

Project Map
To see the structure of a project: open Project Map in the main menu, choose the project, then press Show Map — the IDE shows the list of folders and files with their sizes, the total size, the size per file type, and the important files (main file, manifest, layout, strings, icon, web page). Press Save map-project.txt to write the same map to the project root. The bin/ folder (build results) and the .git/ folder (local repo) are not mapped because their contents can be made again.

APK Size Calculator
To estimate the size of the built APK before building: open APK Size Calculator in the main menu, choose the project, then press Calculate Estimate. The IDE shows the breakdown per category (code/DEX, resources, assets, native libraries, manifest + resources.arsc, overhead), the total estimate, the 5 biggest files, and suggestions to shrink it (for example big images are reduced in resolution, big sounds are cut in duration). This is an ESTIMATE, not the exact size — the real size can differ because of aapt2 compression, removal of unused code (R8), and built resources.

APK Analyzer
To read the contents of a finished APK (like the APK Analyzer in Android Studio): open APK Analyzer in the main menu, choose the project, then press Build Result APK Analysis. The IDE reads the newest APK in that project's bin folder and reports the package name, the version, the minimum and target SDK, the list of permissions used, the number of dex files, the size breakdown per part (program code, resources, assets, native libraries, signature), and the 10 biggest entries. Useful to know which part makes the APK big and which permissions the built app uses.

Screen Size Preview
To check a project's appearance on many screen sizes at once (like in Android Studio): open Screen Size Preview in the main menu, choose the project, then press Check Screen Size. The IDE reads all of the project's layouts and reports elements whose width is written fixed (for example 400dp) and exceeds the screen width of 320, 360, 411, or 480 dp, because on a small-screen phone such an element can be covered or overflow. Elements with match_parent or wrap_content width adjust to the screen automatically and do not need to be checked.

Resource Manager
To see and manage all of a project's resources in one place (like the Resource Manager in Android Studio): open Resource Manager in the main menu, choose the project, then press View Resources. The IDE reports the number and size of files per category (drawable, layout, values, mipmap, and others), the contents of strings.xml, colors.xml, and styles.xml. From the same screen, a new string can be added to strings.xml and a new color to colors.xml by filling in its name and value — the name is checked and duplicates are rejected, so the XML file is not broken.

Lightweight Performance Monitor
To monitor the RAM and processor use of a running app (like the Profiler in Android Studio, light version): open Lightweight Performance Monitor in the main menu, first run the app to be checked (for example the built app being tried), fill in its package name — or choose the project, then press Fill in Package Name from Project — then press Start Monitoring. Every 2 seconds the IDE records the RAM (PSS) and CPU of that app together with the phone's free RAM; press Stop to see the summary of the average and the peak. No extra permission. On newer Android versions, reading another app's processor access is limited by the system, so if the CPU cannot be read, the report says so as it is and the RAM is still monitored.

Accessibility Audit
To check whether a project layout is screen-reader friendly (TalkBack/Jieshuo) before release: open Accessibility Audit in the main menu, choose a project, then tap Load Layout List and choose a layout file. The IDE reads that XML file and reports buttons without labels along with their line numbers, labels used repeatedly, and elements that overlap each other, then builds a focus-order transcript like the one Jieshuo reads aloud. If a button has no label, fill in its label then tap Insert Labels Automatically — the label is written into the layout file as a contentDescription. This check reads layout XML only; Compose views and finished APKs are not scanned yet.

Crash Autopsy
To find out why an app closes by itself from a crash log with a unique ID: open Crash Autopsy in the main menu, choose a crash ID from the log list, then tap Check. The IDE matches the class and line number in the log with the project source and explains the cause in Indonesian (for example an empty reference, a permission not yet requested, or a JSON error), with a suggested code patch. Tap Apply Patch only if the source line is still exactly the same as when the crash happened; if it has changed, the patch is refused and the IDE asks you to check it yourself. For crashes of a BUILT app, tap Inject Crash Catcher into Project, then build the APK as usual: that built app catches its own crashes and writes its log to the phone, and that log can be found with the Find Built App Crash Log button. The honest limit: copying the log to the public Download folder on Android 11 and above can fail without the all-files access permission.

Cross-Paradigm Transpiler
To convert simple Java code into Kotlin, or a simple XML layout into Compose code: open Cross-Paradigm Transpiler in the main menu, choose a project and a file, then tap Preview. The IDE shows the conversion result as text — check it first, because lines it does not recognize are left as they are and the word static in Java is dropped in Kotlin (check its meaning before using it). XML to Compose conversion only changes text, hints, and orientation — size, color, and other attributes are not included yet. If the result is correct, tap Apply to File to write the target file; the source file is not changed. Only safe, common patterns are converted.

Local Micro Server
To test an app that needs a server without internet: open Local Micro Server in the main menu, write the route definitions (for example GET /halo then its JSON answer), then tap Start Server. The IDE runs a small HTTP server on the same phone (HTTP only, no TLS, for the same Wi-Fi network) and records every request and answer on the screen. Routes can use parameters like {nama} and a simple API key. The server can also be bundled into the built APK: tap Bundle Server into Project, and the server source, assets, and manifest are injected into the project, so the built app itself becomes the server when it is run. The server in the IDE stops when its screen is closed.

Security Auditor
To check a project code for security gaps before release: open Security Auditor in the main menu, choose a project, then tap Start Scan. The IDE scans the project code, manifest, and configuration and reports findings from high to low risk — an API key left open in code, a component exposed without permission, a WebView that enables JavaScript with its JavaScript interface, weak crypto (MD5, SHA1, DES), an http address without TLS, and a password written directly in code — with their files and line numbers. For findings whose fix is safe (for example change MD5 to SHA-256 or http to https), tap Apply Fix; for API keys and passwords, the IDE only shows the fix suggestion because the replacement must be decided by the developer. The scan now also parses the real DEX bytecode inside the built APK (not only text patterns in code), so dangerous APIs that are called and secrets embedded in the DEX are detected too; gaps that follow no pattern can still slip through the scan — check before applying.

Interface Test Robot
To test an app screen automatically through text scenarios: open Interface Test Robot in the main menu, choose a project, then tap Create Automatic Scenario. The IDE reads the project manifest and layout and writes a scenario as text steps (tap a button, fill a field, wait, go back). Tap Run Dry Run to see the scenario run log with its timestamps — this dry run is still only a sequence simulation. For real testing, tap Inject Test Agent into Project: the IDE injects a test agent with the scenario assets into the project; build the APK as usual, install it, then open the Test icon — that agent runs inside the built app and really taps buttons, fills real fields, and scrolls, then shows its report on the screen with the real crashes it caught. Tap Remove Test Agent from Project to remove that agent again. The agent runs inside the app process itself, so it needs no accessibility service or system automation.

Code Time Travel
To return a project to an earlier code state without typing Git commands: open Code Time Travel in the main menu, choose a project, fill in a time-point label (it may be empty), then tap Record Time Point. The IDE saves a copy of the project source files together with their hashes in the .riwayat folder inside the project. The time-point list shows all of them; choose two points then tap Compare to see files and functions that were added, changed, or removed. Tap Restore to bring back an old state — before restoring, the IDE always makes a backup of the current state first, so nothing is lost. Tap Create Experiment Copy to copy the project to a new folder and try changes without disturbing the original project. Only source files are recorded.

Module Factory
To package part of a project as a module that another project can use: open Module Factory in the main menu, choose a source project, tick the screen, class, string, and permission files to package, then tap Package as Module. The IDE writes a ZIP archive together with JSON metadata (module name, version, strings, and permissions used). To install a module into another project, open Module Factory, choose the target project, then tap Install Module and choose the module .zip file — the merger adds strings and permissions without overwriting existing code, and does not merge a file if its name is already used in the target project. A module does not carry libraries or build settings.

Polymorphic Shield and Asset Vault
To randomize identifier names and encrypt project assets before release: open Polymorphic Shield and Asset Vault in the main menu, choose a project, then tap Randomize Names and Encrypt Assets. The IDE scans class and method names in the source code, builds a random name map, rewrites those names INSIDE the compiled DEX files (replacement names are made the same length as the original names so all offsets stay valid, then the DEX header checksum and SHA-1 signature are recalculated), encrypts the project asset files with AES-GCM into the brankas-aset folder inside the project, and saves an encrypted recovery map (perisai-peta.brankas) so original names can be restored when reading crash logs. The encryption key is now derived from the developer password with PBKDF2, 20,000 iterations, no longer from the project name. Names also used as plain text, annotation names, and debug names are deliberately not rewritten, and the DEX rewrite insertion points in the build path are still awaiting a test on a real phone.

Trust Chain and Environment Guard
To check the signing key chain and the phone environment before release: open Trust Chain and Environment Guard in the main menu, choose a project, then tap Check Chain and Environment. The IDE builds a 5-generation key chain from the project package name and checks its integrity, checks real memory integrity by comparing the contents of code segments in memory with the files on disk and reports anonymous executable (RWX) mappings, foreign libraries, and memfd mappings, then scans the memory map of its own process and device properties for traces of Frida, Xposed, or an emulator. The vault key is wrapped with an AES key in the AndroidKeyStore, which uses the hardware security chip when one is available, and key rotation is now real, using the v3 signing certificate lineage: the old key signs proof of rotation to the new key and the APK is re-signed with that lineage. The result is a risk level of Safe, Caution, or Dangerous, with text evidence. If the system refuses the memory read, the check is reported as cannot be verified, not as safe; and whether a key really uses the hardware security chip can only be confirmed on a real device.

Text Tree Layout Architect
To design a screen without seeing it: open Text Tree Layout Architect in the main menu, choose a project and a layout file, then tap Check Layout. The IDE reads the XML layout as a text tree and reads aloud a position narration for each element (for example bottom right, 45 percent of screen width), then reports overlaps between elements and elements that go off-screen at 360 dp width, mathematically. What is now computed covers LinearLayout and simple dp sizes, the full ConstraintLayout (all constraints, bias, chains, guidelines, barriers, percent widths, 0dp match_constraint, and aspect ratios), and Compose screens (Column, Row, and Box with their size Modifiers). Only MotionLayout and ConstraintSet changed at runtime are still reported as position unknown, because their values only exist while the app is running.

Design System Studio
To make spacing, type, and corners consistent across all screens and projects: open Design System Studio in the main menu, choose a project, write the design tokens (for example jarak=8, huruf=16, sudut=12), choose a component, then tap Generate Components. The IDE validates the tokens — base spacing 4 to 16 dp, base type 12 to 20 sp, corners 0 to 32 dp, and a minimum touch area of 48 dp — then writes ready-to-use XML components (komponen-studio.xml) with an XML theme (tema-studio.xml) and a Compose theme (tema-studio.kt) in the project folder. Tokens can also be saved as a named set in the shared cross-project token library, and one sync command applies the newest library tokens to every project using that set. Components are generated as text that is pasted into a layout and then checked with the Text Tree Layout Architect; the two-column tablet adjustment uses a screen-width qualifier, not runtime device detection.

Semantic Refactoring and AST Navigation
To find definitions and rename symbols without breaking other code that happens to share a name: open Semantic Refactoring and AST Navigation in the main menu, choose a project, then tap Scan Project Symbols to see all classes and methods with their files and line numbers. Enter a symbol name, then tap Scan Project Symbols again to see its definition and all files that call it. To rename, enter the new name, tap Preview Rename to see the number of occurrences in each file, then tap Apply Rename. The indexer now uses a hand-built AST parser (a lexer and recursive parser for Java and a Kotlin subset), so cross-file method renames are resolved and callers in other files are changed too; the button to extract a code block into a new function is now on this screen. This parser is still minimal: very complex generics, parameterized annotations, and anonymous classes are scanned as-is, while calls through reflection and through interfaces are not resolved.

Step Debugger and Memory Inspector
To inspect variable contents in the middle of a program flow without guessing through logs: open Step Debugger and Memory Inspector in the main menu, choose a project, write the execution trace (one step per line, in the form line number, code, then variables and values separated by |, for example 10|int total = harga * jumlah;|harga=5000, jumlah=3, total=15000), enter the breakpoint line number, then tap Run Debug Trace. The IDE runs to the first breakpoint and reads aloud the active line with its variable values through Jieshuo. Tap Step One Line to advance one line, Step Into Function to enter the called function (with a call stack), or Continue Program to run to the next breakpoint. This trace debugger still follows a recorded or handwritten trace; next to it there is a pure-Java JDWP wire-protocol client that can shake hands, set breakpoints, step in, over, and out, and suspend and resume the VM over TCP or in listen mode. Suspending a real process is still not fully possible from inside an ordinary app, because a process JDWP socket is only exposed through adbd — the proven path needs wireless debugging and launching the target through the shell, beyond what the app itself can do.

Offline Dependency Manager
To use third-party libraries without internet and avoid version conflicts before building: open Offline Dependency Manager in the main menu, choose a project, then tap Check Dependencies. The IDE reads all the project .gradle files, checks the shared cross-project vault in the Download/brankas-bersama folder, and resolves conflicts — if two libraries ask for different versions of the same artifact, the highest version is used and the conflict is reported. To download a library, enter its coordinates (in group:artifact:version form, for example com.google.code.gson:gson:2.10.1) then tap Check Dependencies: while online, AAR, JAR, or WHL files are really downloaded from Maven, Google, or PyPI together with their transitive dependency graph (recursive, cycles broken, depth up to 25 levels), and only files that downloaded successfully are recorded as available. While offline only libraries already in the shared vault can be used. Maven version ranges are not resolved, and downloaded files are only checked by their SHA-1, with no PGP verification.

Database and Storage Inspector
To inspect and test the contents of a project database without writing code that prints table contents: open Database and Storage Inspector in the main menu, choose a project and a database file (.db, .sqlite, or .sqlite3), then tap Open Database. The IDE reads the schema of all its tables with a full SQLite page parser (B-tree with overflow pages) and shows the first 20 rows as a text table read aloud by Jieshuo. Write a SELECT query then tap Run Query (for example SELECT nama FROM pengguna WHERE kota = 'Makassar') — queries now support JOIN, GROUP BY, ORDER BY, and LIKE, and on the phone they run through the real Android SQLite engine. To change a value, enter the row number (1 = first row), column name, and new value, then tap Change Cell Value — that value is written back into the .db file. Tap Save Backup to save the current table state as a <db-name>.cadangan.txt file in the project. SharedPreferences and DataStore can also be read. What still cannot be read: encrypted databases, uncommitted WAL changes, and typed values in special DataStore Proto (only shown as a generic field view).

Unit Test Factory and Fuzzing
To find logic gaps before an app is shared: open Unit Test Factory and Fuzzing in the main menu, choose a project and a code file, then tap Create and Run Tests. The IDE reads the function signatures in the file, generates normal and boundary test cases (empty text, null, maximum numbers, strange characters), then really runs those tests: the project code is compiled and each @Test method is executed with a 5-second limit, so the result is real passes and failures with their actual values. Fuzzing also really runs over project functions (through reflection, 2 seconds per call, at most 20 methods), and the line coverage percentage is really computed through instrumentation that keeps the original line numbers. The result reports how many tests passed and failed, how many lines of code and functions were found, and the test cases that were created. The generated tests use exactly the same API as JUnit, but the annotation and assertion definitions are written inside the generated test file itself, because the real JUnit library is not bundled in the app.

Extreme Device Condition Simulator and Memory Leak Auditor
To test how tough an app is when the system kills its process, the network drops, the screen rotates, or battery saver turns on: open Extreme Device Condition Simulator and Memory Leak Auditor in the main menu, choose a project, then tap Run Simulation. The IDE runs three pressure scenarios with a screen-rotation simulation and tracks objects still held in memory after their screen is closed, then reports lost data and leaking object chains. The save-and-restore state is now read from the user's own project source, not a fixed example; the local loopback server is really stopped in the middle of the test to measure the network cut; a real heap dump is taken and parsed to compare two dumps and trace the retaining chain from the GC roots; and the app's own process is really killed after its state is saved, then it is checked which data comes back when it is opened again. What is still impossible from an ordinary app: turning off the phone radio or Wi-Fi and force-stopping other apps — both need system permission; instead, background apps are killed through killBackgroundProcesses, whose permission is already in the manifest, with an honest label on the screen.

Project Blueprint Architect
To turn a big app idea into a step-by-step work plan: open Project Blueprint Architect in the main menu, choose a project, write the app idea (for example a small grocery store cashier app with installments), then tap Create Blueprint. The IDE builds modules, a file list, and small milestones, then saves them as cetak-biru.txt in the project folder. Tap Mark Next Milestone Done each time a milestone is finished, or tap Load Saved Blueprint to open a saved blueprint again. If an active AI provider is chosen in AI Settings and its key is available, the blueprint is built by that provider; if there is no key or the provider cannot be reached, the IDE falls back to the offline keyword patterns and says that limit honestly. A provider answer is only checked for format (modules and milestones present), not for the truth of its contents — always review the blueprint before building.

Code Logic Flow Narrator
To understand long code without listening to syntax line by line: open Code Logic Flow Narrator in the main menu, choose a project and a code file, then tap Code Narration. The IDE turns each line into an Indonesian sentence (for example if the total is more than 100000, then run the following block), shows a call map between methods and a data-flow analysis between methods (values passed on, used, or ignored), and marks subtle potential bugs with their line numbers — String compared with ==, a stream opened without being closed, and a variable written in two different methods. If an active AI provider is chosen in AI Settings, a flow summary from that provider is also available; if not available, the screen uses the offline narration and says that limit. The narration, call map, and data flow use offline text-pattern analysis, not a full AST parser — methods whose opening brace is on its own line, class fields, and calls through reflection are not tracked — and data-race warnings can appear for a variable that is really only used in turns.

App Bundle Factory and Play Store Readiness
To prepare an app for the Google Play Store straight from the phone: open App Bundle Factory and Play Store Readiness in the main menu, choose a project, then tap Build AAB Bundle. The IDE builds the .aab file from the project manifest, resources, and assets together with a real BundleConfig.pb, validates the bundle structure, then splits the bundle into real variant APKs (base, per architecture, per language, and universal) with sizes measured from that split, not estimated. The bundle is signed with JAR v1 using the same project key as APK signing, and its signature chain is verified cryptographically. This screen also audits Play readiness — a target SDK below 35 is marked High because the Play Store requires 35 or more, and a missing 64-bit library is also marked High. A real bundletool cannot run on the device, because bundletool needs a JVM while Android has no JVM; the path above is the closest real one on the device.

OTA Update Engine and Staged Releases
To send a small fix without forcing users to download the whole APK again: open OTA Update Engine and Staged Releases in the main menu, choose a project, write the old and new version contents, then tap Create Patch Package. The IDE computes the difference and creates a patch package (patch-ota.zip) with a SHA-256 fingerprint of the new contents, then checks whether this device is in the first 10 percent rollout stage. Patches now support binary deltas over any file (including DEX and APK), are packed with an RSA-2048 signature and verified with a trusted public key before being applied, and can be downloaded from the developer server together with its release list; if applying fails, the old file stays intact. Applying a patch to the app that is currently running is done through re-signing with the project key and the PackageInstaller, because replacing the code of a process that is running from inside itself is impossible — the APK is locked and the DEX is already loaded.

Team Code Review Studio
To review a colleague's changes and resolve merge conflicts without reading Git arrow marks: open Team Code Review Studio in the main menu, choose a project, enter three text versions (base, local, colleague), then tap Open Team Review. The IDE merges all three based on Java syntax units — two changes on the same line but in different statements are no longer treated as a conflict — and shows each conflict as a vote choice: Use local version, Use colleague version, or Merge both — the result line is inserted at the original conflict position so the order stays correct — then writes the result to gabung-hasil.txt in the project. Below it is the project task board: enter a task title then tap Add Task; tasks are saved as text in the .tugas folder inside the project and synced through commits in the in-app Git, so the board can be read back from any commit history. This syntax splitter is not a full AST parser and the in-app Git stores a full snapshot per commit; there is no special sync server.

Code Structure Dictation
To write code by voice inside the editor: open a project in the Editor, then tap the Code Structure Dictation button. Speak commands in Indonesian, for example buat fungsi tambah dengan parameter a angka dan b angka, buat kelas Mobil, or buat variabel teks nama sama dengan Budi — the IDE turns the speech into a syntactically valid Java, Kotlin, Python, or Compose code block and inserts it at the cursor position, then reads a short summary aloud through Jieshuo. Dictation uses the system's built-in voice input service, without an extra microphone permission, and only recognizes command patterns that are already registered; speech outside those patterns is not turned into code. Numbers spoken as words (for example 'lima') are not yet turned into digits.

Local Collaboration Room (without internet)
To work together in one room without internet: open Collaboration in the main menu, then open the Local Collaboration Room section. One phone opens a session (the IDE shows a local IP address and a 6-digit PIN), another phone joins with that address and PIN. Text changes are sent as line differences, a built APK can be sent to the tester's phone, and crash reports from the tester's phone are received back. One session is for one friend only; if two people change exactly the same line at the same time, the last change is the one used. The PIN is sent as plain text on the local network. This room has not been tested on a real phone yet.

AI Settings
To set up the AI provider and API keys for app creation: in the main menu, in the Settings group, tap AI Settings (next to the Connector button). Choose the provider to use from the available list, and check Switch model when provider errors so that if one model fails, the IDE automatically tries the next model from the same provider. Tap Manage API Keys to add backup keys (enter the name and the key, then tap Save; keys are shown masked, only the last 4 characters visible). Keys are stored on the phone and never sent anywhere except to the chosen provider when creating an app. The chosen provider is now really used by the Project Blueprint Architect and the Code Logic Flow Narrator; app creation on the AI App Maker screen still uses the local AI on the phone (without internet).

Connector
To analyze an APK and then send it: in the main menu, in the Settings group, tap Connector (next to the AI Settings button). Choose an APK file from the phone, the IDE reads its contents (package name, version, list of activities), then tap Send APK to send it through the system share menu (for example WhatsApp or Drive).

Language and Voice
To change the app language: open Settings, then App Language, then choose a language or Follow System. The main screen and most screens change to the chosen language immediately without closing or restarting the app; some screens (for example Terminal, Collaboration, AI Settings, and Manage Keys) still use the old language until reopened. If you choose Follow System, the language follows the phone system language.

Default Signature per Project and Anti Tamper
Since version 5.7, a project that does not use a personal signature is signed with the project's OWN built-in key (created once in the tanda-tangan-bawaan folder inside the project, then used onwards), so the built-in signature differs from project to project — no longer one shared key for all apps. Do not delete the tanda-tangan-bawaan folder: without that key, a new APK cannot overwrite the old APK of the same project. Each project's settings (separate architecture, personal signature, anti tamper, chosen keystore, SDK) are now stored in the settings.gradle file inside the project and read again every time the project is built. In Settings, in the Signature category, there is an Anti tamper built app checkbox: if active, the built app on the device checks its signature and dex contents every time it is opened; if it was re-signed or changed by someone else, the app refuses to run. Debugger and injection tools such as Frida/Xposed are also detected, and the app window is locked from screen recording.

Demo Video Maker
To make a demo video of a built app: open Demo Video Maker in the main menu, choose the project, fill in the video title, then press Create Demo Video Script — the IDE writes video-demo.txt containing 5 standard scenes (opening, main view, feature 1, feature 2, closing) with the narration text and the duration of each scene. Press Create HTML Slideshow to make video-demo.html from the project's images (icon + screenshots if any) that change automatically every 5 seconds. This is NOT an .mp4 video — for a real video, open video-demo.html in the phone browser and then record the screen, or read the narration in video-demo.txt while recording the running app.

New Look in Android Studio Style
The IDE appearance is now tidied to resemble Android Studio (only the appearance — all buttons, menus, and flows stay exactly as before): a light grey background, bold black screen titles, blue buttons with white text, and white input boxes with a thin border. The main menu is grouped visually (Maker Features, Cloud Theme & Others, Voice Code & New Features, Tools) without changing the button order. The Terminal still uses a dark panel like the Terminal window in Android Studio, and the code editor still has a white background with black text. All text is still read clearly by Jieshuo.

Settings
To set the app: open the Options menu on the main screen, then press Settings. Inside there are 12 categories: GitHub Settings (security, personal signature, build history, and GitHub token), Device APK Build Settings (save the keystore password and build history on the device), Theme (app colors), Signature (make a keystore for a personal signature and the built app anti tamper checkbox), Project Folder (project folder location), Language and Voice (interface language and Voice Mode speech speed), Text Size and Appearance (editor font size), Build (default target SDK and default architecture split for the Create Project screen), Notifications (sound when a build finishes), Automatic Backup (project backup schedule), Developer Profile (name, WhatsApp number, and account shown on the Donation screen), and Privacy and Data (reset settings and delete app data). Each category has a Go Back button to return to the category menu. Settings that were just saved (not yet applied) have their explanation written honestly on the screen.

Donate to the Developer
To donate or greet the developer: press the Donate to the Developer button on the main screen, beside the About Tool button. On the donation screen there is a Copy BRI Account button — press it to copy the developer's account number, then paste it in your bank app. There is also a Greet the Developer on WhatsApp section: fill in your name and home town, then press Send on WhatsApp — WhatsApp opens with the greeting message already filled in, just press Send in WhatsApp and then return to the app. WhatsApp does not allow other apps to send messages automatically, so sending is still done by yourself in WhatsApp.

Terminal Favorite Commands
To save commands that are often used in the Terminal: open the Terminal, then press Favorites. Tap Add a new favorite, fill in the name (for example View file) and its command (for example ls -la), then press Save — the favorite is saved permanently on the phone. Tap a favorite name to run it directly in the terminal; tap Delete favorite, then choose one to delete it (with confirmation). There are already 3 built-in favorites: View file (ls -la), Check space (df -h), and Clear screen (clear) — all of them may be deleted. An empty command cannot be saved or run; the Terminal tells you through a message and voice if that happens.

Analytics & Quality
To see a summary of app use and crash reports: press the Analytics & Quality button on the main screen, beside the Donate to the Developer button. This screen shows how many times the app was opened, the most often opened screens, the number of crashes, and the list of the latest crashes with a short fix suggestion. This data is only stored on your phone and is not sent anywhere. There is a Delete Analytics Data button with a confirmation dialog to delete all of that data. The last screen is only recorded for the main screen and this screen.
