Bienvenido a Create Aplikasi by Al Kautsar
Create Aplikasi es una aplicación creadora de aplicaciones Android que funciona directamente en el teléfono, sin necesidad de una computadora portátil. Esta aplicación permite que cualquiera cree sus propias aplicaciones Android, incluidos los usuarios que recién están aprendiendo a crear aplicaciones y los usuarios de lectores de pantalla. La guía completa de uso de esta aplicación está disponible en esta pantalla Acerca de esta herramienta.

Qué es esta aplicación y para quién es
Create Aplikasi es una herramienta creadora de aplicaciones Android que funciona en el teléfono. Esta aplicación está dirigida a cualquiera que quiera crear sus propias aplicaciones Android, incluidos principiantes y usuarios de lectores de pantalla. Esta aplicación proporciona un editor de código, un botón Ejecutar para probar proyectos, un botón Compilar para crear un APK, y menús para firmar e instalar el APK.

Propósito de esta aplicación
Esta aplicación fue creada para que cualquiera pueda crear sus propias aplicaciones Android fácilmente, directamente desde el teléfono. Su interfaz está hecha lo más sencilla posible para que incluso los usuarios nuevos puedan probarla de inmediato.

Cómo crear un proyecto nuevo, paso a paso
1. Pulsa Crear proyecto en el menú principal.
2. Elige el tipo de proyecto: HTML, Sitio web, Java, Kotlin, Compose o Python.
3. Escribe el nombre de la aplicación, por ejemplo: Garuda Decode.
4. Escribe el nombre del paquete (package name), por ejemplo: com.android.garudadecode. El nombre del paquete debe usar letras minúsculas y constar de al menos dos partes separadas por puntos.
5. Escribe la versión de la aplicación, por ejemplo: 1.0, y un código de versión en forma de número, por ejemplo: 1. Si se deja vacío, la versión se completará automáticamente con 1.0 y el código de versión 1.
6. Escribe el SDK mínimo y el SDK de destino si es necesario. Si se dejan vacíos, se usarán los valores predeterminados. El SDK mínimo es la versión de Android más baja admitida, por ejemplo: 21 significa Android 5.0. El SDK de destino máximo es 36 (Android 16).
7. Pulsa el botón Seleccionar permisos para elegir los permisos de la aplicación, por ejemplo: INTERNET. El permiso INTERNET ya está marcado de forma predeterminada. Marca solo los permisos que la aplicación realmente necesita.
8. Si lo deseas, marca "Usar arquitecturas separadas de 64 bits y 32 bits" para que el tamaño del APK sea menor, y marca "Usar firma personal" si quieres usar tu propio keystore.
9. Pulsa Crear proyecto. El proyecto nuevo se guarda en la carpeta Download/project y aparece de inmediato en Gestionar proyectos.

Tipos de proyecto disponibles
• HTML: visualización desde index.html, style.css y script.js, ejecutándose a través de WebView. Se compila directamente en el teléfono.
• Sitio web: un sitio web con menús (Inicio, Acerca de, Contacto) desde index.html, tentang.html, kontak.html, style.css y script.js, ejecutándose a través de WebView. Se compila directamente en el teléfono.
• Java: se compila en el teléfono. MainActivity se encuentra en app/src/main/java/<nombre-del-paquete>/MainActivity.java. La visualización proviene de app/src/main/res/layout/activity_main.xml, el texto de app/src/main/res/values/strings.xml y el tema de app/src/main/res/values/styles.xml.
• Kotlin: se puede compilar en el dispositivo (sin conexión) usando el compilador de Kotlin incluido en la aplicación, o a través de GitHub Actions. MainActivity se encuentra en app/src/main/java/<nombre-del-paquete>/MainActivity.kt, y los archivos res son los mismos que en un proyecto Java. La primera compilación de Kotlin es más lenta debido al gran tamaño del compilador, y los archivos .java que hacen referencia a clases de Kotlin aún no se pueden compilar (los archivos .java se compilan antes que los archivos .kt).
• Compose: una aplicación Android moderna cuya interfaz se crea con Jetpack Compose (no con diseños XML). MainActivity se encuentra en app/src/main/java/<nombre-del-paquete>/MainActivity.kt. Los proyectos Compose se compilan a través de GitHub Actions (el menú Compilar proyecto, luego Compilar en línea) o en Termux con Gradle, porque Compose requiere las bibliotecas de Jetpack Compose, que no están disponibles en el dispositivo.
• Python: la lógica de la aplicación se escribe en el lenguaje Python (Chaquopy) en app/src/main/python/main.py, y la ejecuta el host MainActivity.java en app/src/main/java/<nombre-del-paquete>/MainActivity.java. Los proyectos Python se pueden compilar directamente en el teléfono (el entorno de ejecución de Chaquopy está incluido en la aplicación) o a través de GitHub Actions. El SDK mínimo para proyectos Python es 24 (Android 7.0).

Cambiar arquitectura del proyecto
Para cambiar las opciones de arquitectura de un proyecto existente sin crear uno nuevo: en el menú principal, toca Cambiar arquitectura del proyecto, luego elige un proyecto y cambia la casilla Compilar APK de 64 bits (arm64-v8a) o Compilar APK de 32 bits (armeabi-v7a); o en Gestionar proyectos, mantén pulsado el nombre de un proyecto y elige Cambiar arquitectura para abrir la misma pantalla directamente para ese proyecto. La regla es: si las dos casillas están activadas, la compilación produce dos APK separados, uno de 64 bits y uno de 32 bits; si solo una casilla está activada, la compilación produce un único APK universal que sigue funcionando en dispositivos de 64 y de 32 bits. Todavía no se admite un APK separado para una sola variante, porque la ruta de compilación solo conoce la opción de dividir o la universal, pero la elección de cada variante queda guardada dentro del proyecto para no perderse al volver a abrir la pantalla.

Estructura de archivos de los proyectos Java, HTML, Sitio web, Kotlin, Compose y Python
Los proyectos Java, HTML, Sitio web, Kotlin, Compose y Python están estructurados como los proyectos Android en general. Dentro de la carpeta app está la carpeta src, y dentro de ella está la carpeta main. Dentro de la carpeta main está AndroidManifest.xml junto a la carpeta java, la carpeta res que contiene layout/activity_main.xml y values/strings.xml así como values/styles.xml, y para HTML y Sitio web está la carpeta assets que contiene index.html (Sitio web también tiene tentang.html y kontak.html). Los proyectos HTML y Sitio web también tienen su propio MainActivity en app/src/main/java/<nombre-del-paquete>/MainActivity.java, que carga index.html en un WebView y se convierte en el lanzador en el AndroidManifest. Los proyectos Python tienen el código Python en app/src/main/python/main.py y el host MainActivity.java en app/src/main/java/<nombre-del-paquete>/MainActivity.java. AndroidManifest.xml, los diseños, las cadenas y los estilos se pueden abrir y cambiar en el editor, igual que MainActivity. Los proyectos antiguos cuyo manifiesto aún está junto a la carpeta app todavía se pueden compilar, porque al compilar, la aplicación comprueba primero AndroidManifest.xml en app/src/main/, luego el que está junto a la carpeta app, y por último el archivo de datos del proyecto.

Reglas de permisos (importante)
Los permisos marcados al crear un proyecto se registran en un solo lugar, según el tipo de proyecto. Para los proyectos Java, HTML, Sitio web, Kotlin, Compose y Python, los permisos marcados se registran SOLO en AndroidManifest.xml ubicado en app/src/main/, junto a la carpeta java, dentro de la carpeta del proyecto. El archivo de datos del proyecto para los proyectos Java, HTML, Sitio web, Kotlin, Compose y Python no contiene una lista de permisos. Si eliges Java y luego marcas INTERNET y CAMERA, lo que se registra en AndroidManifest.xml es solo INTERNET y CAMERA, sin que se incluya ningún otro permiso. Al compilar, la aplicación lee los permisos del mismo lugar: desde AndroidManifest.xml en app/src/main/ para los proyectos Java, HTML, Sitio web, Kotlin, Compose y Python (si no hay ninguno, desde AndroidManifest.xml junto a la carpeta app para proyectos antiguos), y desde el archivo de datos del proyecto para proyectos antiguos.

Cómo usar el editor
Abre Gestionar proyectos, toca el nombre de un proyecto para abrir el editor. En el editor, los archivos se pueden abrir, se puede escribir código y los cambios se pueden guardar. Para los proyectos Java, HTML, Sitio web, Kotlin, Compose y Python, los archivos están organizados dentro de la carpeta app/src/main. Para compartir un proyecto, usa Exportar ZIP (consulta la sección siguiente).

Cómo ejecutar un proyecto
En el editor, pulsa Ejecutar para probar el proyecto. Para los proyectos HTML y Sitio web, lo que se ejecuta es index.html a través de WebView. Si ocurre un error, lee el mensaje de error, corrige el código y luego ejecútalo de nuevo.

Cómo compilar un APK
En el editor, pulsa Compilar. Hay dos formas de compilar. Primera, Compilar en el dispositivo: compila directamente en el teléfono sin internet, para proyectos HTML, Sitio web, Java, Kotlin y Python. Segunda, Compilar en línea a través de GitHub Actions: compila por internet en GitHub, y se puede usar para todos los tipos de proyecto. Los proyectos Compose solo se pueden compilar de la segunda forma (Compilar en línea) o en Termux con Gradle, porque Compose requiere las bibliotecas de Jetpack Compose, que no están disponibles en el dispositivo. El resultado de la primera compilación aún no está firmado. Después, la aplicación lo firma: automáticamente con la clave incorporada, o con una firma personal si la casilla "Usar firma personal" estaba marcada al crear el proyecto.

Cómo instalar un APK
Cuando el APK esté listo, pulsa Instalar para instalarlo. En Android 8 y versiones superiores, el teléfono pedirá primero "Permitir desde esta fuente", porque esta aplicación instala APK desde fuera de Play Store. Activa ese permiso una vez en Ajustes, luego vuelve a la aplicación: la instalación continuará automáticamente sin necesidad de pulsar Instalar de nuevo. Si el botón Instalar no aparece, asegúrate de que la compilación haya terminado y el APK haya sido creado.

Cómo firmar una aplicación
Todo APK debe estar firmado para poder instalarse. Hay dos opciones disponibles. Primera, la clave incorporada: la aplicación lo firma por sí misma automáticamente, sin que tengas que hacer nada. Segunda, una firma personal: crea primero un keystore a través del menú Crear keystore en el menú principal, guarda su contraseña con cuidado, luego marca "Usar firma personal" al crear el proyecto. El keystore se guarda en Download/project/signing.

Exportar un proyecto a ZIP
Exportar ZIP se proporciona para que los proyectos se puedan compartir con amigos. Cómo hacerlo: en Gestionar proyectos, mantén pulsado el nombre del proyecto, luego elige Exportar ZIP. El resultado se guarda en Download/project/<NombreDelProyecto>.zip. La carpeta bin no se incluye, por lo que el tamaño es pequeño, solo decenas de KB. Ese archivo ZIP se puede enviar a amigos o subir a GitHub.

Extensión JAWS
La Extensión JAWS utiliza el motor de extensiones de Jieshuo (CSR), no su lector de pantalla. De ese modo, los diseños pueden seguir funcionando aunque el usuario use TalkBack. Cómo hacerlo: abre Extensión JAWS en el menú principal. Como el clic automático funciona por sí solo, el servicio debe activarse primero en Ajustes de accesibilidad. Después de eso, se puede crear un diseño nuevo: escribe el nombre del diseño, pulsa OK, luego completa sus casillas.

Lista de clics separada para mayor orden
Dentro de un diseño hay dos casillas: la casilla de script y la casilla Lista de clics. La lista de botones se guarda por separado en el archivo daftar_klik.txt, un nombre por línea. Un ejemplo de su contenido: tombolSimpan, tombolHapus, tombolBuka. Para abrir una aplicación, simplemente escribe >WhatsApp en esa lista. Los diseños antiguos que aún no tengan un archivo daftar_klik.txt mostrarán ese ejemplo predeterminado.

Funciones sencillas proporcionadas
• klikTombol("tombolSimpan") — hace clic en un botón según su texto.
• klikDaftarTombol(daftar) — hace clic en la lista en daftar_klik.txt, un botón por línea, en orden, y luego informa cuántos tuvieron éxito y cuántos no se encontraron.
• bukaAplikasi("WhatsApp") — abre una aplicación por su nombre, o escribe ">WhatsApp" en la lista.
• klik(540, 1200) — hace clic en las coordenadas de la pantalla.
Todas las funciones se hacen sencillas primero. Una vez que te acostumbres a ellas, se pueden agregar funciones adicionales más adelante.

Acerca de los lectores de pantalla
Esta aplicación está diseñada para ser compatible con lectores de pantalla. Cada campo de entrada tiene una etiqueta y un ejemplo de cómo completarlo, y se puede llegar a todos los botones sin gestos complicados. La Extensión JAWS está hecha para seguir funcionando aunque el usuario use TalkBack, porque lo que se utiliza es su motor de extensiones, no su lector de pantalla.

Privacidad y seguridad
Los proyectos y los keystores se guardan en tu teléfono. El token de GitHub solo se usa para compilaciones en línea y se guarda dentro de esta aplicación. No compartas tu token ni la contraseña de tu keystore con nadie. Si usas una firma personal, guarda el keystore y su contraseña en un lugar seguro, porque si se pierden, los APK antiguos no se pueden actualizar con la misma firma.

Requisitos
Android 5.0 o más reciente. Permiso de almacenamiento: en Android 11 y versiones superiores usa el permiso de acceso a todos los archivos, en Android 10 y versiones inferiores usa el permiso de almacenamiento normal (lectura/escritura de almacenamiento) porque Android 10 no tiene el permiso de acceso a todos los archivos. Compilar en el dispositivo requiere un teléfono con procesador ARM (32 o 64 bits). Compilar en línea a través de GitHub Actions requiere internet y un token de GitHub. Los proyectos Kotlin se pueden compilar en el dispositivo, pero la primera compilación es más lenta y usa más memoria debido al gran tamaño del compilador de Kotlin. Los proyectos Compose se compilan a través de GitHub Actions o en Termux con Gradle. Los proyectos Python requieren Android 7.0 o más reciente (SDK mínimo 24) y el APK resultante es más grande porque incluye el entorno de ejecución de Python (Chaquopy) junto con su biblioteca estándar.

Terminal
El menú Terminal en la pantalla principal abre una terminal dentro de esta aplicación. Comandos como ls se pueden usar para ver el contenido de la carpeta del proyecto, cd para moverse entre carpetas, y git para gestionar el código. La salida de los comandos aparece como texto que puede leer un lector de pantalla, y hay un botón Leer resultado en voz alta para escuchar el último resultado. Esta terminal usa el shell del sistema del teléfono, por lo que los programas interactivos como nano y vim aún no se pueden usar aquí.

Licencia (versión de pago)
Para vender una aplicación, marca "Activar licencia" al crear el proyecto, luego escribe tu número de WhatsApp. La aplicación compilada pedirá un código de licencia cuando se abra por primera vez: el usuario ve su ID de dispositivo, pulsa el botón Enviar ID de dispositivo para enviar ese ID a tu WhatsApp, y luego tú respondes con el código de licencia. El código de licencia se calcula a partir del ID de dispositivo y la contraseña del proyecto (lisensi_seed en el archivo de datos del proyecto) — guarda esa contraseña con cuidado y no la compartas. Después de introducir el código correcto, la aplicación se abre y no vuelve a pedir un código.

Creador Automático de Iconos
Los iconos de los proyectos nuevos aún son transparentes, por lo que hay un Creador de iconos disponible en el menú principal. Cómo hacerlo: pulsa Creador de iconos, escribe una o dos letras (por ejemplo las iniciales del nombre de la aplicación), elige un color de fondo y un color de texto, mira la vista previa, luego pulsa Guardar en el proyecto para usar ese icono en el proyecto seleccionado, o Guardar en Descargas para usar su archivo PNG en otro lugar. Después de crear un proyecto, la aplicación también ofrece crear un icono. El icono antiguo de un proyecto se puede reemplazar en cualquier momento desde el menú del proyecto en Gestionar proyectos (mantén pulsado el nombre del proyecto, luego elige Cambiar icono).

Plantillas de Proyecto Listas para Usar
Si no quieres empezar desde un proyecto vacío, elige una plantilla al crear un proyecto: Calculadora (Java), Notas (Java), Lista de tareas (Kotlin), Calculadora web (HTML), Sitio de perfil (Sitio web) o Contador (Compose). Elegir una plantilla cambia automáticamente el tipo de proyecto para seguir esa plantilla, y el proyecto se crea con código inicial ya listo — solo tienes que ejecutarlo o cambiarlo. Si el tipo de proyecto se cambia manualmente de nuevo después de elegir una plantilla, la plantilla se cancela y el proyecto vuelve a estar vacío. Para las plantillas HTML y Sitio web, la plantilla reemplaza el contenido de index.html, incluido el script HTML escrito en el formulario.

Copia de Seguridad y Restauración de Proyectos
Para que los proyectos no se pierdan, hay una función de copia de seguridad disponible. Cómo hacerlo: en Gestionar proyectos, mantén pulsado el nombre del proyecto, luego elige Hacer copia de seguridad. La copia de seguridad se guarda como un ZIP en la carpeta Download/backup con el nombre del proyecto y la fecha, por ejemplo: GarudaDecode-2026-11-14-123045.zip. Su contenido es el mismo que Exportar ZIP (todo el contenido del proyecto, sin la carpeta bin). Para restaurar: abre el menú en Gestionar proyectos, elige Restaurar copia de seguridad, luego elige el archivo de copia de seguridad. Si el nombre del proyecto ya existe, la aplicación preguntará: Sobrescribir el proyecto antiguo, o guardar con un Nombre nuevo.

Compartir e Importar Proyectos
Para compartir un proyecto con amigos: en Gestionar proyectos, mantén pulsado el nombre del proyecto, luego elige Compartir. El proyecto se envía como un ZIP a través de aplicaciones para compartir (WhatsApp, Telegram y otras). Para recibir un proyecto de un amigo: abre el menú en Gestionar proyectos, elige Importar proyecto, luego elige el archivo ZIP. Ese archivo ZIP debe contener un archivo de datos del proyecto — si no hay ninguno, el archivo se rechaza con un mensaje claro, porque ese archivo no es un proyecto de Create Aplikasi. Si el nombre del proyecto ya existe, la aplicación preguntará: Sobrescribir el proyecto antiguo, o guardar con un Nombre nuevo.

Búsqueda y Filtro de Proyectos
Si ya hay muchos proyectos, en Gestionar proyectos hay un cuadro de búsqueda y un filtro por tipo. Escribe el nombre del proyecto en el cuadro de búsqueda, y la lista se filtra de inmediato (no se distinguen mayúsculas y minúsculas). El filtro por tipo limita la lista a un solo tipo: Todos, HTML, Sitio web, Java, Kotlin, Compose o Python. El menú de cada proyecto se puede seguir abriendo como siempre desde la lista ya filtrada.

Crear Aplicaciones con la Voz
Si no quieres escribir, usa la voz: toca Crear con la voz en el menú principal y luego di un comando. Comandos que puedes decir: "Buat proyek kalkulator", "Bangun proyek Kalkulator", "Buka proyek Kalkulator", "Jalankan proyek Kalkulator", "Daftar proyek", "Buka ikon", "Kembali" y "Bantuan". La aplicación responde con voz y texto, así que se puede seguir usando sin mirar la pantalla. El reconocimiento de voz usa la aplicación de reconocimiento de voz integrada del teléfono (gratis; puede funcionar sin conexión si el paquete de idioma indonesio está instalado). Si el teléfono no tiene reconocimiento de voz, los comandos se pueden escribir en el cuadro de texto de la misma pantalla.

Creador de aplicaciones con IA
Escriba o dicte la aplicación que desea en la pantalla del Creador de aplicaciones con IA, por ejemplo: "una aplicación de notas con un botón de guardar". La aplicación analiza las palabras clave dentro del propio teléfono (sin internet, sin costo), luego crea un proyecto real a partir de la plantilla que mejor coincide: calculadora, notas, lista de tareas, calculadora web, sitio de perfil o contador. Si su descripción aún no tiene una plantilla adecuada, la aplicación crea un proyecto vacío y lo dice con honestidad — no finge entender. Un proyecto creado por la IA puede abrirse directamente en Gestionar proyectos.

Vista previa en vivo en el teléfono de un amigo
Para mostrar un proyecto a un amigo antes de compilarlo: en Gestionar proyectos, mantenga pulsado el nombre del proyecto y elija Vista previa al teléfono de un amigo. La aplicación crea un pequeño paquete de vista previa con los archivos principales del proyecto (index.html, MainActivity o main.py) más BACA-SAYA.txt con instrucciones e info.txt. El paquete se envía como ZIP por WhatsApp o Telegram. El amigo que lo recibe puede abrir la vista previa de inmediato: las páginas HTML se abren en el navegador, el código Java/Kotlin/Python se lee como texto.

Mercado de proyectos
El Mercado de proyectos contiene proyectos de ejemplo integrados que se pueden instalar en la carpeta del proyecto con un toque: Calculadora, Notas, Lista de tareas, Calculadora web, Sitio de perfil, Contador, Reloj digital y Cuestionario web. El mercado en línea (descargar ejemplos de internet) aún no está disponible, por lo que este mercado contiene ejemplos que ya están dentro de la aplicación. Un proyecto instalado se puede abrir y modificar en Gestionar proyectos como un proyecto hecho por usted mismo.

Colaboración directa
Para trabajar en un proyecto junto con un amigo: abra Colaboración en el menú principal, elija el proyecto, escriba una nota de cambio (qué se cambió) y pulse Compartir para colaborar. El proyecto se envía como ZIP junto con un archivo CATATAN.txt dentro. Su amigo trabaja en él y devuelve el ZIP; usted pulsa Recibir respuesta, primero lee la nota de cambio y luego elige Aplicar para sobrescribir el proyecto anterior, o Cancelar si cambia de opinión. Un ZIP sin CATATAN.txt no es un paquete de colaboración — para un ZIP de proyecto normal, use Importar proyecto en Gestionar proyectos.

Traductor automático de aplicaciones
Para traducir el texto de una aplicación a otro idioma: abra Traductor de aplicaciones en el menú principal, elija el proyecto y el idioma de destino (inglés, árabe o javanés) y pulse Traducir. El diccionario ya está dentro del teléfono (sin internet, sin costo) y contiene palabras comunes de todos los días; el texto de strings.xml, del diseño y del código se lee y luego se traduce. El resultado se escribe en la carpeta values-idioma/strings.xml (si el proyecto tiene un strings.xml) y en un informe traduccion-idioma.txt en la carpeta del proyecto. Las palabras que aún no están en el diccionario se dejan como están y se informan — así usted sabe qué palabras aún debe traducir por sí mismo.

Creador de juegos sin código
Para crear un juego sin escribir código: abra Creador de juegos en el menú principal, elija el tipo de juego (Adivina el número, Cuestionario o Atrapa la estrella), complete el nombre del juego, la cantidad (niveles/preguntas/estrellas) y el mensaje de victoria, luego pulse Crear juego. El juego se crea como un proyecto real que se puede ejecutar directamente en Gestionar proyectos y compilar en APK como cualquier otro proyecto.

Pruebas automáticas de aplicaciones
Para comprobar un proyecto antes de compilarlo: en Gestionar proyectos, mantenga pulsado el nombre del proyecto y elija Prueba automática. El IDE comprueba 10 cosas sin compilar un APK — archivos obligatorios presentes (archivo de datos del proyecto, manifiesto, archivo principal, diseño, cadenas), nombre del paquete y versión, permisos usados, icono y equilibrio de los paréntesis del código. El resultado se muestra por elemento (APROBADO/FALLIDO con un mensaje) y Jieshuo lo lee en voz alta. Corrija primero todo lo que FALLÓ y luego pulse Compilar proyecto.

AI Revisora de Código
Para comprobar el código del proyecto en busca de patrones que suelen causar problemas: abra Revisar código en el menú principal, elija el proyecto y pulse Revisar código. El revisor se ejecuta dentro del teléfono (sin internet) y busca variables sin usar, funciones vacías, bucles sin fin evidentes, texto escrito directamente en el código (mejor en strings.xml), permisos y API peligrosos, marcadores TODO/FIXME y ejecución dinámica. Cada hallazgo contiene el nombre del archivo, el número de línea y una sugerencia de corrección. Este revisor se basa en patrones, no es una IA real — los problemas que no siguen un patrón aún pueden pasar.

Modo de aprendizaje interactivo
Para aprender a crear aplicaciones paso a paso: abra Aprender en el menú principal. Hay 5 lecciones: Crear su primer proyecto, Añadir un botón, Cambiar el color, Añadir sonido y Compilar un APK. Toque una lección para leer su explicación y su tarea práctica, haga la tarea y luego pulse Comprobar tarea — el IDE comprueba de verdad si la tarea ya se hizo (escaneando el proyecto y el APK en su teléfono). Las lecciones aprobadas se marcan como terminadas y se guardan.

Sincronización en la nube
Para hacer una copia de seguridad de un proyecto en la nube: abra Sincronización en la nube en el menú principal. Una copia local guarda el ZIP del proyecto en la carpeta Download/cloud con una marca de tiempo, y se puede restaurar en cualquier momento desde la lista de copias. Una copia en GitHub sube el ZIP del proyecto a su repositorio privado (usando el token de Ajustes de GitHub) y se puede descargar de nuevo. Esto es copia y restauración manual — la sincronización automática completa en ambos sentidos necesita un servidor, por lo que aún no está disponible.

Creador automático de backend
Para crear un backend sin escribir código de servidor: abra Creador de backend en el menú principal, elija el tipo de backend (Notas, Lista de tareas o Tablón de mensajes), complete el nombre del proyecto y pulse Crear backend. El IDE crea un proyecto HTML real con una página de formulario y una lista de datos guardados en el almacenamiento local del teléfono (localStorage) — los datos se guardan y se pueden leer de nuevo cuando se ejecuta la aplicación. Este backend funciona en un solo teléfono; dos teléfonos aún no pueden compartir los mismos datos porque no hay un servidor de internet.

Diseñador automático de temas
Para dar un tema de color a un proyecto: abra Diseñador de temas en el menú principal, elija el proyecto y el tema (Claro, Oscuro, Azul, Verde, Rojo o Morado). La vista previa muestra los seis colores del tema (primario, primario oscuro, acento, fondo, texto, texto secundario) y Jieshuo la lee en voz alta. Pulse Aplicar tema — el IDE escribe colors.xml y styles.xml (estilo app_theme) en el proyecto, que se usan directamente cuando el proyecto se ejecuta o se compila.

Creador de animaciones
Para dar animación a un proyecto: abra Creador de animaciones en el menú principal, elija el proyecto, el tipo de animación (Fundido, Deslizar, Girar, Rebotar o Pulsar), la duración (de 100 a 10000 milisegundos) y el objetivo (botón, texto o imagen), luego pulse Crear animación. El IDE escribe un archivo de animación real (res/anim/anim_<tipo>.xml para proyectos Java/Kotlin/Compose, o animasi.css para proyectos HTML/Sitio web) junto con un ejemplo de código de uso que se muestra en la pantalla.

Grabador de acciones
Para repetir el trabajo automáticamente: el IDE registra las acciones realizadas (abrir un proyecto, ejecutar, compilar, exportar, hacer copia, crear un proyecto, guardar un archivo). Abra Grabador de acciones en el menú principal para ver la lista de acciones grabadas con su plan, luego pulse Repetir — el IDE vuelve a ejecutar las acciones que se pueden automatizar (hacer copia y crear un proyecto se ejecutan en el momento; ejecutar, compilar y exportar abren su pantalla principal; abrir y guardar abren el editor). Las acciones que no se pueden automatizar se omiten y se informan al final.

Seguridad automática
Para comprobar la seguridad de un proyecto: abra Seguridad automática en el menú principal, elija el proyecto y pulse Comprobar seguridad. El IDE comprueba 8 cosas localmente (sin internet): permisos peligrosos (ubicación, SMS, llamadas, cámara, micrófono, contactos), envío de datos por HTTP, envío de SMS, llamadas salientes, una contraseña o clave escrita directamente en el código, un WebView sin protección, un componente exportado sin permiso y una dirección http sin cifrado. Cada hallazgo recibe un nivel SEGURO, ADVERTENCIA o PELIGRO con una sugerencia de corrección, y Jieshuo lee el resumen en voz alta.

IA sin conexión
Para usar herramientas de ayuda de texto y código sin internet: abra IA sin conexión en el menú principal. Hay 4 herramientas: Corregir texto (mayúsculas, puntuación y espacios dobles), Resumir texto (toma las 3 frases más importantes), Crear nombre de aplicación (a partir de la descripción escrita) y Sugerir nombre de variable (busca nombres de variable de 1-2 letras en el proyecto). Estas son reglas simples dentro del teléfono, no un modelo de IA real. El resultado de la corrección de texto se puede aplicar al strings.xml del proyecto con el botón Aplicar.

Creador de widgets y fondos de pantalla
Para crear un widget de la pantalla principal: abra Widgets y fondos de pantalla en el menú principal, elija el proyecto, complete el texto del widget y pulse Crear widget. El IDE escribe WidgetSaya.java, el diseño del widget, la información del widget y añade un receptor al AndroidManifest.xml del proyecto — compile el proyecto y luego instale el widget desde la pantalla principal del teléfono. Para un fondo de pantalla: complete el texto y los colores de fondo y de texto, cree una vista previa y luego guárdelo como PNG en la carpeta Download o configúrelo directamente como fondo de pantalla del teléfono.

Integración de redes sociales
Para añadir botones para compartir a una aplicación: abra Redes sociales en el menú principal, elija el proyecto y añada compartir a WhatsApp, Facebook o Telegram (o los tres a la vez). El IDE escribe código real para compartir en el archivo principal del proyecto (MainActivity o index.html). El botón Probar compartir abre el selector para compartir desde el IDE con un texto de ejemplo, para que el flujo se pueda sentir antes de compilar la aplicación.

Aplicación desde imagen
Para crear una aplicación de galería a partir de una imagen: abra Aplicación desde imagen en el menú principal y elija una imagen de la galería. El IDE analiza el tamaño de la imagen y el color dominante, luego crea un proyecto real de aplicación de galería: la imagen se copia a los assets del proyecto, el color del tema se toma del color dominante de la imagen y el nombre de la aplicación se toma del nombre del archivo de imagen. Abra Gestionar proyectos para ejecutar o compilar esa aplicación de galería.

Terminal interactiva (analizador VT)
Para usar programas interactivos en el Terminal: abra Terminal en el menú principal y ejecute nano, vim, top o htop. El Terminal ahora usa un analizador VT (una pantalla de cuadrícula de 24 filas x 80 columnas) para que esos programas se muestren correctamente — el cursor se mueve, las líneas se borran y la pantalla cambia como en un terminal real. Hay botones especiales Tab, Flecha arriba, Flecha abajo y Esc para controlar los programas interactivos. La salida sigue siendo texto que Jieshuo puede leer; pulse Leer la pantalla en voz alta para escuchar la última línea.

Terminal Exec (binario de la aplicación)
Para ejecutar un binario en la carpeta de la aplicación (por ejemplo aapt2, ECJ, D8) desde el Terminal: escriba el comando como siempre. El IDE usa libkautsarexec.so para que los binarios de la carpeta de la aplicación se puedan ejecutar en Android 10 y versiones posteriores. Pulse Prueba de Exec en el Terminal para comprobar si la ruta exec de binarios funciona en este teléfono — el resultado se muestra tal como es. Si el sistema bloquea exec, los comandos del sistema y los scripts de shell siguen funcionando; ejecute el binario a través del menú Compilar proyecto.

Terminal siempre activo (KeepAlive)
Para mantener el shell en marcha al cambiar de pantalla: abra el Terminal, ejecute un comando y luego pulse Atrás o cambie a otra pantalla — el shell NO muere, y la notificación del Terminal sigue visible para que pueda volver con un toque. Los comandos ya ejecutados se guardan en el historial (botón Historial, o las flechas arriba/abajo en el campo de comando) y los comandos que se usan a menudo se pueden guardar como favoritos (botón Favoritos). Pulse Cerrar shell cuando termine, para que el shell se cierre de verdad. También hay un botón Compilar en el Terminal en el menú del proyecto y en el menú del editor: el Terminal se abre en la carpeta del proyecto con el comando de compilación ya rellenado.

Instalar herramientas del terminal (prueba)
Una función aún en prueba: en el Terminal hay un botón Instalar herramientas del terminal para instalar un entorno Termux desde el espejo en el repositorio alat-termux del desarrollador (github.com/syudat/alat-termux), como otra vía además del botón Instalar Termux que toma de la versión oficial de Termux. El contenido del espejo es exactamente el mismo que la versión oficial y se comprueba con SHA-256 durante la instalación. Una vez instalado el entorno, se pueden usar los comandos pkg update y pkg install, y también se instalan en el terminal herramientas adicionales del repositorio: info-terminal para ver la información del entorno, bersih-terminal para limpiar la caché y cadangkan-proyek para archivar la carpeta del proyecto en un solo archivo tar.gz con fecha. Después de eso, la aplicación instala automáticamente los paquetes básicos de Linux (git, python, curl, wget, nano, openssh, zip, unzip) y las herramientas de compilación de APK con firma (openjdk-21, kotlin, gradle, ecj, aapt2, d8, apksigner, clang, cmake, ninja, make) desde el repositorio oficial de Termux, por lo que el terminal queda listo de inmediato para crear aplicaciones. Descargar paquetes grandes (cientos de MB) puede tardar mucho. Mientras la instalación está en marcha, el progreso y la salida de los comandos aparecen en la pantalla principal del Terminal, y el resultado final lo lee en voz alta el lector de pantalla. Si la instalación de paquetes aún no está completa, pulse Instalar herramientas del terminal de nuevo para continuarla.

Modo de voz completo
Para controlar el IDE completamente con la voz: abra Modo de voz en el menú principal y pulse Iniciar escucha. El IDE escucha continuamente — no hace falta pulsar un botón para cada comando — ejecuta el comando y responde con voz. Hay 26 comandos: crear, compilar, abrir, ejecutar, listar, buscar, eliminar, probar, comprobar, exportar, hacer copia, compartir, crear icono, traducir, compilar en el terminal, leer la pantalla, abrir todas las pantallas (incluidas seguridad, IA sin conexión, widget, redes sociales, juego, aprender, nube, backend, tema, animación, grabador), volver, cerrar y ayuda. Si el modo se deja activo, la escucha continúa automáticamente cuando se vuelve a abrir esta pantalla. Pulse Detener escucha para apagar este modo. Si el teléfono no tiene servicio de reconocimiento de voz, los comandos aún se pueden escribir en el cuadro de texto.

Traductor de código
Para traducir código entre lenguajes sin internet: abra Traductor de código en el menú principal, elija el proyecto, elija el archivo fuente (.java/.kt) y luego elija la dirección: Java a Kotlin. Pulse Traducir — el resultado se muestra junto con un informe de las líneas que no se pueden traducir (esas líneas se conservan como están y se marcan). Pulse Guardar resultado para escribir un archivo NUEVO (nombre-traduccion.java/.kt) en la misma carpeta; el archivo original nunca se sobrescribe. Este es un traductor de reglas de patrones, no un compilador — compruebe siempre el resultado antes de usarlo.

Git dentro de la aplicación
Para usar Git dentro del IDE sin Termux: abra Git dentro de la aplicación en el menú principal, elija el proyecto y pulse Crear repositorio Git para crear un repositorio local (.git) en ese proyecto. Pulse Comprobar estado para ver los archivos nuevos, cambiados o eliminados respecto al último commit; escriba el mensaje del commit y pulse Confirmar para guardar una instantánea del proyecto; pulse Ver registro de commits para ver el historial de commits. Subir a GitHub y Descargar de GitHub usan instantáneas a través de un token de GitHub (el repositorio pembuat-aplikasi-build) — no el protocolo git. Clonar, Subir (git del sistema) y Descargar (git del sistema) solo funcionan si el binario git está instalado en el teléfono (normalmente no lo está). Esto no es git completo: no hay fusión, ramas ni diff — cada commit guarda una instantánea ZIP completa del proyecto.

Creador de anuncios
Para añadir anuncios a una aplicación compilada: abra Creador de anuncios en el menú principal, elija el proyecto, el proveedor (AdMob, Unity Ads o AppLovin) y el tipo de anuncio (Banner, Intersticial o Recompensado). Complete el ID de la unidad de anuncios si ya tiene uno — vacío significa usar un ID de prueba (AdMob usa el ID de prueba oficial de Google; Unity usa un ID de juego de ejemplo; AppLovin usa una ubicación vacía). Pulse Crear código de anuncios para ver el código Java y Kotlin y la guía; pulse Guardar en el proyecto para escribir todo en el archivo anuncios-<proveedor>-<tipo>.txt del proyecto. Esto es una plantilla de código + guía, no un SDK de anuncios — el SDK no está incluido en el IDE; los anuncios reales solo aparecen después de crear una cuenta de proveedor, crear una unidad de anuncios, pegar su propio ID de unidad y añadir la dependencia del SDK en el build.gradle del proyecto.

Modo infantil
Para usar el IDE junto con un niño: abra Modo infantil en el menú principal. La pantalla está simplificada con botones grandes y solo 4 acciones seguras: Crear proyecto (a partir de plantillas seguras: Calculadora, Adivina el número, Cuestionario, Atrapa la estrella), Abrir proyecto, Ejecutar y Aprender. No hay botón de eliminar, exportar, hacer copia ni de ajustes de token en esta pantalla. Al entrar por primera vez, cree un PIN de 4 dígitos — ese PIN lo usan los padres para salir del Modo infantil (el botón Salir del modo infantil o el botón Atrás). Este PIN es una protección ligera para niños pequeños, no una seguridad real.

Creador de aplicaciones para Wear OS y TV
Para crear una aplicación de reloj (Wear OS) o de TV (Android TV): abra Wear OS y TV en el menú principal y elija el objetivo (Wear OS, Android TV o ambos). Complete el nombre del proyecto y pulse Crear proyecto nuevo Wear/TV — el IDE crea un proyecto Java y luego lo ajusta — o elija un proyecto que ya exista y pulse Aplicar a este proyecto. Los ajustes: uses-feature en el manifiesto, la categoría LEANBACK_LAUNCHER + banner para TV, y un diseño activity_main.xml ajustado (Wear: pantalla pequeña; TV: pantalla grande cómoda para el D-pad). La explicación completa se escribe en wear-tv.txt en el proyecto. Esto es una plantilla de proyecto — compilar + probar aún necesita un dispositivo/emulador Wear OS o Android TV; el banner de TV (banner.png 320x180) no se crea automáticamente, debe añadirlo usted mismo (por ejemplo, a través del Creador de iconos).

Mapa del proyecto
Para ver la estructura de un proyecto: abra Mapa del proyecto en el menú principal, elija el proyecto y pulse Mostrar mapa — el IDE muestra la lista de carpetas y archivos con sus tamaños, el tamaño total, el tamaño por tipo de archivo y los archivos importantes (archivo principal, manifiesto, diseño, cadenas, icono, página web). Pulse Guardar mapa-proyecto.txt para escribir el mismo mapa en la raíz del proyecto. La carpeta bin/ (resultados de compilación) y la carpeta .git/ (repositorio local) no se mapean porque su contenido se puede crear de nuevo.

Calculadora de tamaño de APK
Para estimar el tamaño del APK compilado antes de compilar: abra Calculadora de tamaño de APK en el menú principal, elija el proyecto y pulse Calcular estimación. El IDE muestra el desglose por categoría (código/DEX, recursos, assets, bibliotecas nativas, manifiesto + resources.arsc, sobrecarga), la estimación total, los 5 archivos más grandes y sugerencias para reducirlo (por ejemplo, las imágenes grandes se reducen en resolución, los sonidos grandes se recortan en duración). Esto es una ESTIMACIÓN, no el tamaño exacto — el tamaño real puede diferir por la compresión de aapt2, la eliminación de código sin usar (R8) y los recursos compilados.

Analizador de APK
Para leer el contenido de un APK ya terminado (como el Analizador de APK de Android Studio): abra Analizador de APK en el menú principal, elija el proyecto y pulse Análisis del APK resultante de la compilación. El IDE lee el APK más reciente en la carpeta bin de ese proyecto e informa el nombre del paquete, la versión, el SDK mínimo y objetivo, la lista de permisos usados, el número de archivos dex, el desglose de tamaño por parte (código del programa, recursos, assets, bibliotecas nativas, firma) y las 10 entradas más grandes. Es útil para saber qué parte hace grande el APK y qué permisos usa la aplicación compilada.

Vista previa de tamaño de pantalla
Para comprobar el aspecto de un proyecto en muchos tamaños de pantalla a la vez (como en Android Studio): abra Vista previa de tamaño de pantalla en el menú principal, elija el proyecto y pulse Comprobar tamaños de pantalla. El IDE lee todos los diseños del proyecto e informa de los elementos cuyo ancho está escrito fijo (por ejemplo 400dp) y supera el ancho de pantalla de 320, 360, 411 o 480 dp, porque en un teléfono de pantalla pequeña un elemento así puede quedar tapado o desbordarse. Los elementos con ancho match_parent o wrap_content se ajustan a la pantalla automáticamente y no necesitan comprobarse.

Gestor de recursos
Para ver y gestionar todos los recursos de un proyecto en un solo lugar (como el Gestor de recursos de Android Studio): abra Gestor de recursos en el menú principal, elija el proyecto y pulse Ver recursos. El IDE informa el número y el tamaño de los archivos por categoría (drawable, layout, values, mipmap y otros), el contenido de strings.xml, colors.xml y styles.xml. Desde la misma pantalla, se puede añadir una cadena nueva a strings.xml y un color nuevo a colors.xml rellenando su nombre y valor — el nombre se comprueba y los duplicados se rechazan, por lo que el archivo XML no se rompe.

Monitor ligero de rendimiento
Para supervisar el uso de RAM y procesador de una aplicación en ejecución (como el Profiler de Android Studio, versión ligera): abra Monitor ligero de rendimiento en el menú principal, primero ejecute la aplicación que se va a comprobar (por ejemplo, la aplicación compilada que se está probando), complete el nombre de su paquete — o elija el proyecto y pulse Rellenar nombre del paquete desde el proyecto — y luego pulse Iniciar supervisión. Cada 2 segundos el IDE registra la RAM (PSS) y la CPU de esa aplicación junto con la RAM libre del teléfono; pulse Detener para ver el resumen del promedio y del máximo. Sin permiso adicional. En las versiones nuevas de Android, el acceso de lectura al procesador de otra aplicación está limitado por el sistema, por lo que si la CPU no se puede leer, el informe lo dice tal como es y la RAM sigue supervisándose.

Auditoría de Accesibilidad
Para comprobar si el diseño de un proyecto es amable con el lector de pantalla (TalkBack/Jieshuo) antes de publicarlo: abre Auditoría de Accesibilidad en el menú principal, elige un proyecto y luego toca Cargar Lista de Diseños y elige un archivo de diseño. El IDE lee ese archivo XML e informa de los botones sin etiqueta junto con su número de línea, las etiquetas usadas repetidas veces y los elementos que se superponen, y luego elabora una transcripción del orden de foco como la que lee Jieshuo en voz alta. Si un botón no tiene etiqueta, escribe su etiqueta y luego toca Insertar Etiquetas Automáticamente — la etiqueta se escribe en el archivo de diseño como contentDescription. Esta comprobación solo lee XML de diseño; las vistas de Compose y los APK terminados aún no se analizan.

Autopsia de Fallo
Para averiguar por qué una aplicación se cierra sola a partir de un registro de fallo con un ID único: abre Autopsia de Fallo en el menú principal, elige un ID de fallo de la lista de registros y toca Examinar. El IDE compara la clase y el número de línea del registro con la fuente del proyecto y explica la causa en indonesio (por ejemplo una referencia vacía, un permiso aún no solicitado, o un error JSON), con una sugerencia de parche de código. Toca Aplicar Parche solo si la línea de fuente sigue siendo exactamente la misma que cuando ocurrió el fallo; si ha cambiado, el parche se rechaza y el IDE te pide que lo compruebes tú mismo. Para fallos de una aplicación COMPILADA, toca Inyectar capturador de fallos en el proyecto y luego compila el APK como siempre: esa aplicación compilada captura sus propios fallos y escribe su registro en el teléfono, y ese registro se puede encontrar con el botón Buscar registro de fallos de la aplicación compilada. El límite honesto: copiar el registro a la carpeta pública Download en Android 11 o superior puede fallar sin el permiso de acceso a todos los archivos.

Transpilador entre Paradigmas
Para convertir código Java sencillo en Kotlin, o un diseño XML sencillo en código Compose: abre Transpilador entre Paradigmas en el menú principal, elige un proyecto y un archivo, y luego toca Vista Previa. El IDE muestra el resultado de la conversión como texto — revísalo primero, porque las líneas que no reconoce se dejan tal cual y la palabra static de Java se elimina en Kotlin (comprueba su significado antes de usarla). La conversión de XML a Compose solo cambia el texto, las sugerencias y la orientación — el tamaño, el color y otros atributos aún no se incluyen. Si el resultado es correcto, toca Aplicar al Archivo para escribir el archivo de destino; el archivo de origen no se modifica. Solo se convierten los patrones comunes y seguros.

Servidor Micro Local
Para probar una aplicación que necesita un servidor sin internet: abre Servidor Micro Local en el menú principal, escribe las definiciones de ruta (por ejemplo GET /halo y luego su respuesta JSON) y toca Iniciar Servidor. El IDE ejecuta un pequeño servidor HTTP en el mismo teléfono (solo HTTP, sin TLS, para la misma red Wi-Fi) y registra cada petición y respuesta en la pantalla. Las rutas pueden usar parámetros como {nama} y una clave API sencilla. El servidor también puede empaquetarse en el APK compilado: toca Empaquetar servidor en el proyecto, y la fuente del servidor, los recursos y el manifiesto se inyectan en el proyecto, así que la propia aplicación compilada se convierte en el servidor cuando se ejecuta. El servidor del IDE se detiene cuando se cierra su pantalla.

Auditor de Seguridad
Para comprobar el código de un proyecto en busca de fallos de seguridad antes de publicarlo: abre Auditor de Seguridad en el menú principal, elige un proyecto y toca Iniciar Escaneo. El IDE examina el código, el manifiesto y la configuración del proyecto e informa de hallazgos de riesgo alto a bajo — una clave API dejada abierta en el código, un componente expuesto sin permiso, un WebView que activa JavaScript con su interfaz JavaScript, criptografía débil (MD5, SHA1, DES), una dirección http sin TLS, y una contraseña escrita directamente en el código — con sus archivos y números de línea. Para los hallazgos cuya corrección es segura (por ejemplo cambiar MD5 por SHA-256 o http por https), toca Aplicar Corrección; para claves API y contraseñas, el IDE solo muestra la sugerencia de corrección porque el reemplazo debe decidirlo el desarrollador. El análisis ahora también examina el bytecode DEX real dentro del APK compilado (no solo patrones de texto en el código), así que las API peligrosas que se llaman y los secretos incrustados en el DEX también se detectan; los fallos que no siguen ningún patrón aún pueden escapar del análisis — comprueba antes de aplicar.

Robot Probador de Interfaz
Para probar la pantalla de una aplicación automáticamente mediante escenarios de texto: abre Robot Probador de Interfaz en el menú principal, elige un proyecto y toca Crear Escenario Automático. El IDE lee el manifiesto y el diseño del proyecto y escribe un escenario como pasos de texto (tocar un botón, rellenar un campo, esperar, volver). Toca Ejecutar Prueba en Seco para ver el registro de ejecución del escenario con sus marcas de tiempo — esta prueba en seco sigue siendo solo una simulación de secuencia. Para pruebas reales, toca Inyectar agente de pruebas en el proyecto: el IDE inyecta un agente de pruebas con los recursos del escenario en el proyecto; compila el APK como siempre, instálalo y abre el icono de Prueba — ese agente se ejecuta dentro de la aplicación compilada y toca botones de verdad, rellena campos reales y se desplaza, y luego muestra su informe en la pantalla con los fallos reales que capturó. Toca Quitar agente de pruebas del proyecto para quitar ese agente de nuevo. El agente se ejecuta dentro del propio proceso de la aplicación, así que no necesita un servicio de accesibilidad ni automatización del sistema.

Viaje en el Tiempo del Código
Para devolver un proyecto a un estado anterior del código sin escribir comandos de Git: abre Viaje en el Tiempo del Código en el menú principal, elige un proyecto, escribe una etiqueta para el punto en el tiempo (puede quedar vacía) y luego toca Registrar punto en el tiempo. El IDE guarda una copia de los archivos fuente del proyecto junto con sus hashes en la carpeta .riwayat dentro del proyecto. La lista de puntos en el tiempo los muestra todos; elige dos puntos y luego toca Comparar para ver los archivos y funciones añadidos, cambiados o eliminados. Toca Restaurar para recuperar un estado antiguo — antes de restaurar, el IDE siempre hace primero una copia de seguridad del estado actual, así que no se pierde nada. Toca Crear Copia de Experimento para copiar el proyecto a una carpeta nueva y probar cambios sin molestar al proyecto original. Solo se registran los archivos fuente.

Fábrica de Módulos
Para empaquetar parte de un proyecto como un módulo que otro proyecto pueda usar: abre Fábrica de Módulos en el menú principal, elige un proyecto de origen, marca los archivos de pantalla, clase, texto y permisos que se van a empaquetar, y luego toca Empaquetar como Módulo. El IDE escribe un archivo ZIP junto con metadatos JSON (nombre del módulo, versión, textos y permisos usados). Para instalar un módulo en otro proyecto, abre Fábrica de Módulos, elige el proyecto de destino y luego toca Instalar Módulo y elige el archivo .zip del módulo — la fusión añade textos y permisos sin sobrescribir el código existente, y no fusiona un archivo si su nombre ya se usa en el proyecto de destino. Un módulo no lleva bibliotecas ni ajustes de compilación.

Escudo polimórfico y bóveda de recursos
Para aleatorizar los nombres de identificadores y cifrar los recursos del proyecto antes de publicarlo: abre Escudo polimórfico y bóveda de recursos en el menú principal, elige un proyecto y toca Aleatorizar nombres y cifrar recursos. El IDE examina los nombres de clases y métodos en el código fuente, crea un mapa de nombres aleatorios, reescribe esos nombres DENTRO de los archivos DEX compilados (los nombres de reemplazo se hacen de la misma longitud que los originales para que todos los desplazamientos sigan siendo válidos, y luego se recalculan la suma de comprobación y la huella SHA-1 de la cabecera DEX), cifra los archivos de recursos del proyecto con AES-GCM en la carpeta brankas-aset dentro del proyecto, y guarda un mapa de recuperación cifrado (perisai-peta.brankas) para poder restaurar los nombres originales al leer registros de fallos. La clave de cifrado ahora se deriva de la contraseña del desarrollador con PBKDF2, 20.000 iteraciones, ya no del nombre del proyecto. Los nombres que también se usan como texto normal, nombres de anotación y nombres de depuración no se reescriben a propósito, y los puntos de inserción de la reescritura DEX en la ruta de compilación aún esperan una prueba en un teléfono real.

Cadena de confianza y guardián del entorno
Para comprobar la cadena de claves de firma y el entorno del teléfono antes de publicar: abre Cadena de confianza y guardián del entorno en el menú principal, elige un proyecto y toca Comprobar cadena y entorno. El IDE construye una cadena de claves de 5 generaciones a partir del nombre de paquete del proyecto y comprueba su integridad, comprueba la integridad real de la memoria comparando el contenido de los segmentos de código en memoria con los archivos del disco e informa de asignaciones anónimas ejecutables (RWX), bibliotecas ajenas y asignaciones memfd, y luego examina el mapa de memoria de su propio proceso y las propiedades del dispositivo en busca de rastros de Frida, Xposed o un emulador. La clave de la bóveda se envuelve con una clave AES en el AndroidKeyStore, que usa el chip de seguridad de hardware cuando está disponible, y la rotación de claves ahora es real, usando el linaje de certificados de firma del esquema v3: la clave antigua firma la prueba de rotación a la clave nueva y el APK se vuelve a firmar con ese linaje. El resultado es un nivel de riesgo Seguro, Precaución o Peligroso, con pruebas en texto. Si el sistema rechaza la lectura de memoria, la comprobación se informa como no se puede verificar, no como segura; y si una clave usa realmente el chip de seguridad de hardware solo puede confirmarse en un dispositivo real.

Arquitecto de diseño con árbol de texto
Para diseñar una pantalla sin verla: abre Arquitecto de diseño con árbol de texto en el menú principal, elige un proyecto y un archivo de diseño, y toca Comprobar diseño. El IDE lee el diseño XML como un árbol de texto y lee en voz alta una narración de posición para cada elemento (por ejemplo abajo a la derecha, 45 por ciento del ancho de pantalla), y luego informa de solapamientos entre elementos y de elementos que se salen de la pantalla con un ancho de 360 dp, de forma matemática. Lo que ahora se calcula incluye LinearLayout y tamaños dp sencillos, ConstraintLayout completo (todas las restricciones, sesgo, cadenas, guías, barreras, anchos en porcentaje, 0dp match_constraint y relaciones de aspecto) y pantallas Compose (Column, Row y Box con sus modificadores de tamaño). Solo MotionLayout y ConstraintSet que cambian al ejecutarse se siguen informando como posición desconocida, porque sus valores solo existen mientras la aplicación se ejecuta.

Estudio de sistema de diseño
Para igualar espaciados, tipos y esquinas en todas las pantallas y proyectos: abre Estudio de sistema de diseño en el menú principal, elige un proyecto, escribe los tokens de diseño (por ejemplo jarak=8, huruf=16, sudut=12), elige un componente y toca Generar componentes. El IDE valida los tokens — espaciado base de 4 a 16 dp, tipo base de 12 a 20 sp, esquinas de 0 a 32 dp y un área táctil mínima de 48 dp — y luego escribe componentes XML listos para usar (komponen-studio.xml) con un tema XML (tema-studio.xml) y un tema Compose (tema-studio.kt) en la carpeta del proyecto. Los tokens también pueden guardarse como un conjunto con nombre en la biblioteca compartida de tokens entre proyectos, y un solo comando de sincronización aplica los tokens más recientes de la biblioteca a todos los proyectos que usan ese conjunto. Los componentes se generan como texto que se pega en el diseño y luego se comprueba con el Arquitecto de diseño con árbol de texto; el ajuste de dos columnas en tableta usa un calificador de ancho de pantalla, no detección del dispositivo en ejecución.

Refactorización semántica y navegación AST
Para buscar definiciones y cambiar el nombre de símbolos sin romper otro código que casualmente comparte el nombre: abre Refactorización semántica y navegación AST en el menú principal, elige un proyecto y toca Escanear símbolos del proyecto para ver todas las clases y métodos con sus archivos y números de línea. Escribe el nombre de un símbolo y toca Escanear símbolos del proyecto de nuevo para ver su definición y todos los archivos que lo llaman. Para cambiar el nombre, escribe el nuevo nombre, toca Vista previa del cambio de nombre para ver el número de apariciones en cada archivo, y luego toca Aplicar cambio de nombre. El indexador ahora usa un analizador AST hecho a mano (un analizador léxico y un analizador recursivo para Java y un subconjunto de Kotlin), así que los cambios de nombre de métodos entre archivos se resuelven y los llamadores de otros archivos también cambian; el botón para extraer un bloque de código en una función nueva ya está en esta pantalla. Este analizador sigue siendo mínimo: los genéricos muy complejos, las anotaciones con parámetros y las clases anónimas se examinan tal cual, mientras que las llamadas por reflexión y por interfaz no se resuelven.

Depurador paso a paso e inspector de memoria
Para inspeccionar el contenido de variables en medio del flujo de un programa sin adivinar a través de registros: abre Depurador paso a paso e inspector de memoria en el menú principal, elige un proyecto, escribe la traza de ejecución (un paso por línea, con la forma número de línea, código, y luego variables y valores separados por |, por ejemplo 10|int total = harga * jumlah;|harga=5000, jumlah=3, total=15000), escribe el número de línea del punto de interrupción y toca Ejecutar rastro de depuración. El IDE avanza hasta el primer punto de interrupción y lee en voz alta la línea activa con sus valores de variables a través de Jieshuo. Toca Avanzar una línea para avanzar una línea, Entrar en la función para entrar en la función llamada (con una pila de llamadas), o Continuar programa para avanzar hasta el siguiente punto de interrupción. Este depurador de traza sigue recorriendo una traza grabada o escrita a mano; junto a él hay un cliente puro Java del protocolo de cable JDWP que puede saludar, poner puntos de interrupción, avanzar dentro, por encima y fuera, y suspender y reanudar la VM por TCP o en modo escucha. Suspender un proceso real sigue sin ser del todo posible desde dentro de una aplicación normal, porque el socket JDWP de un proceso solo se expone a través de adbd — el camino comprobado necesita depuración inalámbrica y lanzar el objetivo desde la consola, fuera de lo que la propia aplicación puede hacer.

Gestor de dependencias sin conexión
Para usar bibliotecas de terceros sin internet y evitar conflictos de versiones antes de compilar: abre Gestor de dependencias sin conexión en el menú principal, elige un proyecto y toca Comprobar dependencias. El IDE lee todos los archivos .gradle del proyecto, revisa la bóveda compartida entre proyectos en la carpeta Download/brankas-bersama y resuelve conflictos — si dos bibliotecas piden versiones distintas del mismo artefacto, se usa la versión más alta y se informa del conflicto. Para descargar una biblioteca, escribe sus coordenadas (en forma grupo:artefacto:versión, por ejemplo com.google.code.gson:gson:2.10.1) y toca Comprobar dependencias: con conexión, los archivos AAR, JAR o WHL se descargan de verdad desde Maven, Google o PyPI junto con su grafo de dependencias transitivas (recursivo, ciclos cortados, profundidad de hasta 25 niveles), y solo los archivos descargados con éxito se registran como disponibles. Sin conexión solo se pueden usar las bibliotecas que ya están en la bóveda compartida. Los rangos de versiones de Maven no se resuelven, y los archivos descargados solo se comprueban por su SHA-1, sin verificación PGP.

Inspector de base de datos y almacenamiento
Para inspeccionar y probar el contenido de la base de datos de un proyecto sin escribir código que imprima el contenido de las tablas: abre Inspector de base de datos y almacenamiento en el menú principal, elige un proyecto y un archivo de base de datos (.db, .sqlite o .sqlite3), y toca Abrir base de datos. El IDE lee el esquema de todas sus tablas con un analizador completo de páginas SQLite (árbol-B con páginas de desbordamiento) y muestra las primeras 20 filas como una tabla de texto leída en voz alta por Jieshuo. Escribe una consulta SELECT y toca Ejecutar consulta (por ejemplo SELECT nama FROM pengguna WHERE kota = 'Makassar') — las consultas ahora admiten JOIN, GROUP BY, ORDER BY y LIKE, y en el teléfono se ejecutan con el motor SQLite real de Android. Para cambiar un valor, escribe el número de fila (1 = primera fila), el nombre de columna y el valor nuevo, y toca Cambiar valor de celda — ese valor se escribe de nuevo en el archivo .db. Toca Guardar copia de seguridad para guardar el estado actual de la tabla como un archivo <nombre-bd>.cadangan.txt en el proyecto. SharedPreferences y DataStore también se pueden leer. Lo que aún no se puede leer: bases de datos cifradas, cambios WAL sin confirmar y valores con tipo en DataStore Proto especial (solo se muestran como vista genérica de campos).

Fábrica de pruebas unitarias y fuzzing
Para encontrar fallos de lógica antes de compartir una aplicación: abre Fábrica de pruebas unitarias y fuzzing en el menú principal, elige un proyecto y un archivo de código, y toca Crear y ejecutar pruebas. El IDE lee las firmas de función del archivo, genera casos de prueba normales y límite (texto vacío, null, números máximos, caracteres extraños), y luego ejecuta esas pruebas de verdad: el código del proyecto se compila y cada método @Test se ejecuta con un límite de 5 segundos, así que el resultado son aprobados y fallos reales con sus valores reales. El fuzzing también se ejecuta de verdad sobre funciones del proyecto (por reflexión, 2 segundos por llamada, como máximo 20 métodos), y el porcentaje de cobertura de líneas se calcula de verdad mediante instrumentación que conserva los números de línea originales. El resultado informa cuántas pruebas pasaron y fallaron, cuántas líneas de código y funciones se encontraron, y los casos de prueba creados. Las pruebas generadas usan exactamente la misma API que JUnit, pero las definiciones de anotaciones y aserciones se escriben dentro del propio archivo de prueba generado, porque la biblioteca JUnit real no viene incluida en la aplicación.

Simulador de condiciones extremas del dispositivo y auditor de fugas de memoria
Para probar la resistencia de una aplicación cuando el sistema mata su proceso, se corta la red, gira la pantalla o se activa el ahorro de batería: abre Simulador de condiciones extremas del dispositivo y auditor de fugas de memoria en el menú principal, elige un proyecto y toca Ejecutar simulación. El IDE ejecuta tres escenarios de presión con una simulación de giro de pantalla y rastrea los objetos que quedan retenidos en memoria después de cerrar su pantalla, y luego informa de los datos perdidos y de las cadenas de objetos con fugas. El estado de guardar y restaurar ahora se lee de la fuente del propio proyecto del usuario, no de un ejemplo fijo; el servidor local de loopback se detiene de verdad en medio de la prueba para medir el corte de red; se toma y se analiza un volcado de montón real para comparar dos volcados y rastrear la cadena de retención desde las raíces del GC; y el propio proceso de la aplicación se mata de verdad después de guardar su estado, y luego se comprueba qué datos vuelven al abrirla de nuevo. Lo que sigue siendo imposible desde una aplicación normal: apagar la radio o el Wi-Fi del teléfono y forzar la detención de otras aplicaciones — ambas necesitan permiso del sistema; en su lugar, las aplicaciones en segundo plano se cierran con killBackgroundProcesses, cuyo permiso ya está en el manifiesto, con una etiqueta honesta en la pantalla.

Arquitecto de planos de proyecto
Para convertir una idea grande de aplicación en un plan de trabajo paso a paso: abre Arquitecto de planos de proyecto en el menú principal, elige un proyecto, escribe la idea de la aplicación (por ejemplo una aplicación de caja para una pequeña tienda de comestibles con pagos a plazos) y toca Crear plano. El IDE construye módulos, una lista de archivos y pequeños hitos, y los guarda como cetak-biru.txt en la carpeta del proyecto. Toca Marcar siguiente hito como terminado cada vez que se completa un hito, o toca Cargar plano guardado para abrir de nuevo un plano guardado. Si se elige un proveedor de IA activo en Ajustes de IA y su clave está disponible, el plano lo construye ese proveedor; si no hay clave o no se puede contactar con el proveedor, el IDE vuelve a los patrones de palabras clave sin conexión y dice ese límite con honestidad. La respuesta del proveedor solo se comprueba por formato (módulos e hitos presentes), no por la veracidad de su contenido — revisa siempre el plano antes de construir.

Narrador del flujo lógico del código
Para entender código largo sin escuchar la sintaxis línea por línea: abre Narrador del flujo lógico del código en el menú principal, elige un proyecto y un archivo de código, y toca Narración de código. El IDE convierte cada línea en una frase en indonesio (por ejemplo si el total es más de 100000, entonces ejecuta el bloque siguiente), muestra un mapa de llamadas entre métodos y un análisis de flujo de datos entre métodos (valores pasados, usados o ignorados), y marca posibles errores sutiles con sus números de línea — String comparado con ==, un stream abierto sin cerrar, y una variable escrita en dos métodos distintos. Si se elige un proveedor de IA activo en Ajustes de IA, también hay un resumen del flujo de ese proveedor; si no está disponible, la pantalla usa la narración sin conexión y dice ese límite. La narración, el mapa de llamadas y el flujo de datos usan análisis de patrones de texto sin conexión, no un analizador AST completo — los métodos cuya llave de apertura está en su propia línea, los campos de clase y las llamadas por reflexión no se rastrean — y las advertencias de carrera de datos pueden aparecer para una variable que en realidad solo se usa por turnos.

Fábrica de paquetes de aplicación y preparación para Play Store
Para preparar una aplicación para Google Play Store directamente desde el teléfono: abre Fábrica de paquetes de aplicación y preparación para Play Store en el menú principal, elige un proyecto y toca Crear paquete AAB. El IDE construye el archivo .aab a partir del manifiesto, los recursos y los activos del proyecto junto con un BundleConfig.pb real, valida la estructura del paquete, y luego divide el paquete en APK variantes reales (base, por arquitectura, por idioma y universal) con tamaños medidos de esa división, no estimados. El paquete se firma con JAR v1 usando la misma clave de proyecto que la firma de APK, y su cadena de firma se verifica criptográficamente. Esta pantalla también audita la preparación para Play — un SDK objetivo por debajo de 35 se marca Alto porque Play Store exige 35 o más, y una biblioteca de 64 bits faltante también se marca Alto. Un bundletool real no puede ejecutarse en el dispositivo, porque bundletool necesita una JVM mientras que Android no tiene JVM; el camino anterior es el más cercano real en el dispositivo.

Motor de actualización OTA y lanzamientos graduales
Para enviar una pequeña corrección sin obligar a los usuarios a descargar todo el APK de nuevo: abre Motor de actualización OTA y lanzamientos graduales en el menú principal, elige un proyecto, escribe el contenido de la versión antigua y de la nueva, y toca Crear paquete de parche. El IDE calcula la diferencia y crea un paquete de parche (patch-ota.zip) con una huella SHA-256 del contenido nuevo, y luego comprueba si este dispositivo está en la primera etapa de lanzamiento del 10 por ciento. Los parches ahora admiten deltas binarios sobre cualquier archivo (incluidos DEX y APK), se empaquetan con una firma RSA-2048 y se verifican con una clave pública de confianza antes de aplicarse, y se pueden descargar del servidor del desarrollador junto con su lista de lanzamientos; si la aplicación falla, el archivo antiguo queda intacto. Aplicar un parche a la aplicación que se está ejecutando se hace volviendo a firmar con la clave del proyecto y con el PackageInstaller, porque reemplazar el código de un proceso en ejecución desde dentro de sí mismo es imposible — el APK está bloqueado y el DEX ya está cargado.

Estudio de revisión de código en equipo
Para revisar los cambios de un colega y resolver conflictos de fusión sin leer las marcas de flecha de Git: abre Estudio de revisión de código en equipo en el menú principal, elige un proyecto, escribe tres versiones de texto (base, local, colega) y toca Abrir revisión de equipo. El IDE fusiona las tres basándose en unidades sintácticas de Java — dos cambios en la misma línea pero en sentencias distintas ya no se tratan como conflicto — y muestra cada conflicto como una opción de voto: Usar versión local, Usar versión del colega, o Fusionar ambas — la línea resultante se inserta en la posición original del conflicto para que el orden se mantenga correcto — y luego escribe el resultado en gabung-hasil.txt en el proyecto. Debajo está el tablero de tareas del proyecto: escribe el título de una tarea y toca Añadir tarea; las tareas se guardan como texto en la carpeta .tugas dentro del proyecto y se sincronizan mediante commits en el Git de la aplicación, así que el tablero puede leerse de nuevo desde cualquier historial de commits. Este divisor sintáctico no es un analizador AST completo y el Git de la aplicación guarda una instantánea completa por commit; no hay un servidor de sincronización especial.

Dictado de Estructura de Código
Para escribir código por voz dentro del editor: abre un proyecto en el Editor y luego toca el botón Dictado de Estructura de Código. Di comandos en indonesio, por ejemplo buat fungsi tambah dengan parameter a angka dan b angka, buat kelas Mobil, o buat variabel teks nama sama dengan Budi — el IDE convierte la voz en un bloque de código Java, Kotlin, Python o Compose sintácticamente válido y lo inserta en la posición del cursor, y luego lee en voz alta un breve resumen a través de Jieshuo. El dictado usa el servicio de entrada de voz integrado del sistema, sin permiso adicional de micrófono, y solo reconoce patrones de comandos ya registrados; la voz fuera de esos patrones no se convierte en código. Los números dichos con palabras (por ejemplo 'lima') aún no se convierten en dígitos.

Sala de Colaboración Local (sin internet)
Para trabajar juntos en una misma habitación sin internet: abre Colaboración en el menú principal y luego abre la sección Sala de Colaboración Local. Un teléfono abre una sesión (el IDE muestra una dirección IP local y un PIN de 6 dígitos), otro teléfono se une con esa dirección y ese PIN. Los cambios de texto se envían como diferencias de líneas, un APK compilado se puede enviar al teléfono del probador y los informes de fallos del teléfono del probador se reciben de vuelta. Una sesión es solo para un amigo; si dos personas cambian exactamente la misma línea al mismo tiempo, se usa el último cambio. El PIN se envía como texto plano en la red local. Esta sala aún no se ha probado en un teléfono real.

Ajustes de IA
Para configurar el proveedor de IA y las claves API para crear aplicaciones: en el menú principal, en el grupo Ajustes, toca Ajustes de IA (junto al botón Conector). Elige el proveedor a usar de la lista disponible, y marca Cambiar de modelo si el proveedor falla para que si un modelo falla, el IDE pruebe automáticamente el siguiente modelo del mismo proveedor. Toca Gestionar claves API para añadir claves de reserva (escribe el nombre y la clave, y toca Guardar; las claves se muestran ocultas, solo se ven los últimos 4 caracteres). Las claves se guardan en el teléfono y nunca se envían a ningún lugar excepto al proveedor elegido al crear una aplicación. El proveedor elegido ahora lo usan de verdad el Arquitecto de planos de proyecto y el Narrador del flujo lógico del código; la creación de aplicaciones en la pantalla Creador de aplicaciones con IA sigue usando la IA local del teléfono (sin internet).

Conector
Para analizar un APK y luego enviarlo: en el menú principal, en el grupo Ajustes, toca Conector (junto al botón Ajustes de IA). Elige un archivo APK del teléfono, el IDE lee su contenido (nombre de paquete, versión, lista de actividades) y luego toca Enviar APK para enviarlo a través del menú de compartir del sistema (por ejemplo, WhatsApp o Drive).

Idioma y voz
Para cambiar el idioma de la aplicación: abre Ajustes, luego Idioma de la aplicación, y luego elige un idioma o Seguir el sistema. La pantalla principal y la mayoría de las pantallas cambian al idioma elegido de inmediato sin cerrar ni reiniciar la aplicación; algunas pantallas (por ejemplo, Terminal, Colaboración, Ajustes de IA y Gestionar claves) siguen usando el idioma anterior hasta que se vuelven a abrir. Si eliges Seguir el sistema, el idioma sigue al idioma del sistema del teléfono.

Firma predeterminada por proyecto y Anti Tamper
Desde la versión 5.7, un proyecto que no usa una firma personal se firma con la clave integrada PROPIA de ese proyecto (creada una vez en la carpeta tanda-tangan-bawaan dentro del proyecto y luego usada siempre), por lo que la firma integrada es diferente entre proyectos — ya no es una clave compartida para todas las aplicaciones. No elimine la carpeta tanda-tangan-bawaan: sin esa clave, un APK nuevo no puede sobrescribir el APK anterior del mismo proyecto. Los ajustes de cada proyecto (arquitectura separada, firma personal, anti manipulación, keystore elegido, SDK) ahora se guardan en el archivo settings.gradle dentro del proyecto y se leen de nuevo cada vez que se compila el proyecto. En Ajustes, en la categoría Firma, hay una casilla Anti manipulación de la aplicación compilada: si está activa, la aplicación compilada en el dispositivo comprueba su firma y el contenido de su dex cada vez que se abre; si fue firmada de nuevo o modificada por otra persona, la aplicación se niega a ejecutarse. Las herramientas de depuración e inyección como Frida/Xposed también se detectan, y la ventana de la aplicación se bloquea para la grabación de pantalla.

Creador de videos de demostración
Para crear un vídeo de demostración de una aplicación compilada: abra Creador de vídeo de demostración en el menú principal, elija el proyecto, complete el título del vídeo y pulse Crear guion de vídeo de demostración — el IDE escribe video-demo.txt con 5 escenas estándar (apertura, vista principal, función 1, función 2, cierre) junto con el texto de narración y la duración de cada escena. Pulse Crear presentación HTML para crear video-demo.html a partir de las imágenes del proyecto (icono + capturas de pantalla si las hay) que cambian automáticamente cada 5 segundos. Nueva interfaz al estilo Android Studio
La apariencia del IDE ahora está ordenada para parecerse a Android Studio (solo la apariencia — todos los botones, menús y flujos siguen exactamente como antes): un fondo gris claro, títulos de pantalla en negrita y negro, botones azules con texto blanco y cuadros de entrada blancos con un borde fino. El menú principal está agrupado visualmente (Funciones de creación, Nube, tema y otros, Voz, código y funciones nuevas, Herramientas) sin cambiar el orden de los botones. El Terminal sigue usando un panel oscuro como la ventana del Terminal de Android Studio, y el editor de código sigue con fondo blanco y texto negro. Todo el texto sigue leyéndose claramente con Jieshuo.

Ajustes
Para configurar la aplicación: abra el menú Opciones en la pantalla principal y pulse Ajustes. Dentro hay 12 categorías: Ajustes de GitHub (seguridad, firma personal, historial de compilación y token de GitHub), Ajustes de compilación de APK en el dispositivo (guardar la contraseña del keystore y el historial de compilación en el dispositivo), Tema (colores de la aplicación), Firma (crear un keystore para una firma personal y la casilla anti manipulación de la aplicación compilada), Carpeta de proyectos (ubicación de la carpeta de proyectos), Idioma y voz (idioma de la interfaz y velocidad de voz del Modo de voz), Tamaño de texto y apariencia (tamaño de fuente del editor), Compilación (SDK objetivo predeterminado y división de arquitectura predeterminada para la pantalla Crear proyecto), Notificaciones (sonido cuando termina una compilación), Copia de seguridad automática (programación de copias de proyectos), Perfil del desarrollador (nombre, número de WhatsApp y cuenta que se muestran en la pantalla Donar) y Privacidad y datos (restablecer ajustes y eliminar datos de la aplicación). Cada categoría tiene un botón Volver Atrás para regresar al menú de categorías. Los ajustes que acaban de guardarse (aún no aplicados) tienen su explicación escrita con honestidad en la pantalla.

Donar al desarrollador
Para donar o saludar al desarrollador: pulse el botón Donar al desarrollador en la pantalla principal, junto al botón Acerca de la herramienta. En la pantalla de donación hay un botón Copiar cuenta BRI — púlselo para copiar el número de cuenta del desarrollador y luego péguelo en su aplicación bancaria. También hay una sección Saludar al desarrollador por WhatsApp: complete su nombre y ciudad de origen y pulse Enviar por WhatsApp — WhatsApp se abre con el mensaje de saludo ya rellenado, solo pulse Enviar en WhatsApp y luego vuelva a la aplicación. WhatsApp no permite que otras aplicaciones envíen mensajes automáticamente, por lo que el envío aún se hace por usted mismo en WhatsApp.

Comandos favoritos del terminal
Para guardar comandos que se usan a menudo en el Terminal: abra el Terminal y pulse Favoritos. Toque Añadir favorito nuevo, complete el nombre (por ejemplo Ver archivo) y su comando (por ejemplo ls -la) y pulse Guardar — el favorito se guarda permanentemente en el teléfono. Toque el nombre de un favorito para ejecutarlo directamente en el terminal; toque Eliminar favorito y elija uno para eliminarlo (con confirmación). Ya hay 3 favoritos integrados: Ver archivo (ls -la), Comprobar espacio (df -h) y Limpiar pantalla (clear) — todos se pueden eliminar. Un comando vacío no se puede guardar ni ejecutar; el Terminal se lo dice con un mensaje y con voz si eso ocurre.

Analítica y calidad
Para ver un resumen del uso de la aplicación y los informes de fallos: pulse el botón Analítica y calidad en la pantalla principal, junto al botón Donar al desarrollador. Esta pantalla muestra cuántas veces se abrió la aplicación, las pantallas que se abren con más frecuencia, el número de fallos y la lista de los últimos fallos con una breve sugerencia de corrección. Estos datos solo se guardan en su teléfono y no se envían a ningún lugar. Hay un botón Eliminar datos analíticos con un diálogo de confirmación para eliminar todos esos datos. La última pantalla solo se registra para la pantalla principal y esta pantalla.
