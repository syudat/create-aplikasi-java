به Create Aplikasi by Al Kautsar خوش آمدید
Create Aplikasi یک برنامهٔ ساخت برنامهٔ اندروید است که مستقیماً روی تلفن اجرا می‌شود و نیازی به لپ‌تاپ ندارد. این برنامه به هر کسی امکان می‌دهد برنامهٔ اندروید خودش را بسازد، از جمله کاربرانی که تازه ساخت برنامه را یاد می‌گیرند و کاربران صفحه‌خوان. راهنمای کامل استفاده از این برنامه در همین صفحهٔ Tentang Alat (دربارهٔ ابزار) در دسترس است.

این برنامه چیست و برای چه کسانی است
Create Aplikasi ابزاری برای ساخت برنامهٔ اندروید است که روی تلفن اجرا می‌شود. این برنامه برای هر کسی است که می‌خواهد برنامهٔ اندروید خودش را بسازد، از جمله تازه‌کارها و کاربران صفحه‌خوان. این برنامه یک ویرایشگر کد، دکمهٔ Jalankan (اجرا) برای آزمودن پروژه، دکمهٔ Bangun (ساخت) برای ساخت APK و همچنین منوهایی برای امضا و نصب APK ارائه می‌دهد.

هدف این برنامه
این برنامه ساخته شده است تا هر کسی بتواند به‌آسانی و مستقیماً از تلفن، برنامهٔ اندروید خودش را بسازد. ظاهر آن تا حد امکان ساده ساخته شده است تا حتی کاربران تازه‌کار هم بتوانند بلافاصله آن را امتحان کنند.

روش ساخت پروژهٔ جدید، گام به گام
1. در منوی اصلی Buat Project (ساخت پروژه) را فشار دهید.
2. نوع پروژه را انتخاب کنید: HTML، Situs Web (وب‌سایت)، Java، Kotlin، Compose یا Python.
3. نام برنامه را پر کنید، برای مثال: Garuda Decode.
4. نام بسته (package name) را پر کنید، برای مثال: com.android.garudadecode. نام بسته باید از حروف کوچک استفاده کند و از دست‌کم دو بخش تشکیل شود که با نقطه از هم جدا شده‌اند.
5. نسخهٔ برنامه را پر کنید، برای مثال: 1.0، و کد نسخه را به صورت عدد، برای مثال: 1. اگر خالی بماند، نسخه به طور خودکار با 1.0 و کد نسخه با 1 پر می‌شود.
6. در صورت نیاز SDK حداقلی و SDK هدف را پر کنید. اگر خالی بماند، مقدار پیش‌فرض استفاده می‌شود. SDK حداقلی پایین‌ترین نسخهٔ اندروید پشتیبانی‌شده است، برای مثال: 21 یعنی Android 5.0. حداکثر SDK هدف 36 (Android 16) است.
7. دکمهٔ Pilih Izin (انتخاب مجوزها) را فشار دهید تا مجوزهای برنامه را انتخاب کنید، برای مثال: INTERNET. مجوز INTERNET از پیش به طور پیش‌فرض علامت خورده است. فقط مجوزهایی را علامت بزنید که برنامه واقعاً به آن‌ها نیاز دارد.
8. اگر می‌خواهید، گزینهٔ "Gunakan arsitektur terpisah 64 bit dan 32 bit" (استفاده از معماری‌های جدا 64 بیت و 32 بیت) را علامت بزنید تا اندازهٔ APK کوچک‌تر شود، و اگر می‌خواهید از یک keystore ساختهٔ خودتان استفاده کنید، گزینهٔ "Gunakan tanda tangan pribadi" (استفاده از امضای شخصی) را علامت بزنید.
9. Buat Proyek (ساخت پروژه) را فشار دهید. پروژهٔ جدید در پوشهٔ Download/project ذخیره می‌شود و بلافاصله در Kelola Project (مدیریت پروژه‌ها) دیده می‌شود.

انواع پروژهٔ در دسترس
• HTML: نما از index.html، style.css و script.js که از طریق WebView اجرا می‌شود. مستقیماً روی تلفن ساخته می‌شود.
• Situs Web: وب‌سایتی با منو (Beranda (خانه)، Tentang (درباره)، Kontak (تماس)) از index.html، tentang.html، kontak.html، style.css و script.js که از طریق WebView اجرا می‌شود. مستقیماً روی تلفن ساخته می‌شود.
• Java: روی تلفن ساخته می‌شود. MainActivity در app/src/main/java/<nama-paket>/MainActivity.java قرار دارد. نما از app/src/main/res/layout/activity_main.xml، متن از app/src/main/res/values/strings.xml و پوسته از app/src/main/res/values/styles.xml می‌آید.
• Kotlin: می‌تواند روی دستگاه (آفلاین) با استفاده از کامپایلر Kotlin که همراه برنامه است ساخته شود، یا از طریق GitHub Actions. MainActivity در app/src/main/java/<nama-paket>/MainActivity.kt قرار دارد و فایل‌های res همان فایل‌های پروژهٔ Java هستند. نخستین ساخت Kotlin به دلیل اندازهٔ بزرگ کامپایلر کندتر است و فایل‌های .java که به کلاس‌های Kotlin ارجاع می‌دهند هنوز نمی‌توانند ساخته شوند (فایل‌های .java پیش از فایل‌های .kt کامپایل می‌شوند).
• Compose: یک برنامهٔ اندروید مدرن که رابط آن با Jetpack Compose ساخته شده است (نه با چیدمان XML). MainActivity در app/src/main/java/<nama-paket>/MainActivity.kt قرار دارد. پروژه‌های Compose از طریق GitHub Actions (منوی Bangun پروژه، سپس Bangun online (ساخت آنلاین)) یا در Termux با Gradle ساخته می‌شوند، زیرا Compose به کتابخانه‌های Jetpack Compose نیاز دارد که روی دستگاه در دسترس نیستند.
• Python: منطق برنامه به زبان Python (Chaquopy) در app/src/main/python/main.py نوشته می‌شود و توسط میزبان MainActivity.java در app/src/main/java/<nama-paket>/MainActivity.java اجرا می‌شود. پروژه‌های Python می‌توانند مستقیماً روی تلفن ساخته شوند (محیط اجرای Chaquopy همراه برنامه است) و همچنین از طریق GitHub Actions. SDK حداقلی پروژه‌های Python برابر 24 (Android 7.0) است.

چیدمان فایل‌های پروژه‌های Java، HTML، Situs Web، Kotlin، Compose و Python
پروژه‌های Java، HTML، Situs Web، Kotlin، Compose و Python همانند پروژه‌های اندروید به طور کلی چیده شده‌اند. درون پوشهٔ app پوشهٔ src قرار دارد و درون آن پوشهٔ main. درون پوشهٔ main فایل AndroidManifest.xml در کنار پوشهٔ java قرار دارد، پوشهٔ res که layout/activity_main.xml و values/strings.xml و همچنین values/styles.xml را در خود دارد، و برای HTML و Situs Web پوشهٔ assets که index.html را در خود دارد (Situs Web فایل‌های tentang.html و kontak.html را هم دارد). پروژه‌های HTML و Situs Web نیز MainActivity خودشان را در app/src/main/java/<nama-paket>/MainActivity.java دارند که index.html را در WebView بارگذاری می‌کند و در AndroidManifest لانچر می‌شود. پروژه‌های Python کد Python را در app/src/main/python/main.py و میزبان MainActivity.java را در app/src/main/java/<nama-paket>/MainActivity.java دارند. AndroidManifest.xml، layout، strings و styles را می‌توان در ویرایشگر باز کرد و تغییر داد، درست مانند MainActivity. پروژه‌های قدیمی که مانیفست آن‌ها هنوز در کنار پوشهٔ app قرار دارد نیز می‌توانند ساخته شوند، زیرا هنگام ساخت، برنامه ابتدا AndroidManifest.xml را در app/src/main/ بررسی می‌کند، سپس آن را که در کنار پوشهٔ app است و در پایان فایل دادهٔ پروژه را.

قوانین مجوزها (مهم)
مجوزهایی که هنگام ساخت پروژه علامت زده می‌شوند فقط در یک جا ثبت می‌شوند، بسته به نوع پروژه. برای پروژه‌های Java، HTML، Situs Web، Kotlin، Compose و Python، مجوزهای علامت‌خورده فقط در AndroidManifest.xml که در app/src/main/، در کنار پوشهٔ java، درون پوشهٔ پروژه قرار دارد ثبت می‌شوند. فایل دادهٔ پروژه برای پروژه‌های Java، HTML، Situs Web، Kotlin، Compose و Python فهرست مجوزها را در خود ندارد. اگر Java را انتخاب کنید و INTERNET و CAMERA را علامت بزنید، آنچه در AndroidManifest.xml ثبت می‌شود فقط INTERNET و CAMERA است و هیچ مجوز دیگری همراه آن نمی‌آید. هنگام ساخت، برنامه مجوزها را از همان جا می‌خواند: از AndroidManifest.xml در app/src/main/ برای پروژه‌های Java، HTML، Situs Web، Kotlin، Compose و Python (اگر نباشد، از AndroidManifest.xml در کنار پوشهٔ app برای پروژه‌های قدیمی)، و از فایل دادهٔ پروژه برای پروژه‌های قدیمی.

روش استفاده از ویرایشگر
Kelola Project را باز کنید و روی نام پروژه بزنید تا ویرایشگر باز شود. در ویرایشگر می‌توان فایل‌ها را باز کرد، کد نوشت و تغییرات را ذخیره کرد. برای پروژه‌های Java، HTML، Situs Web، Kotlin، Compose و Python، فایل‌ها درون پوشهٔ app/src/main چیده شده‌اند. برای به اشتراک گذاشتن پروژه، از Ekspor ZIP (خروجی ZIP) استفاده کنید (بخش زیر را ببینید).

روش اجرای پروژه
در ویرایشگر، Jalankan را فشار دهید تا پروژه آزموده شود. برای پروژه‌های HTML و Situs Web، آنچه اجرا می‌شود index.html از طریق WebView است. اگر خطایی رخ داد، پیام خطا را بخوانید، کد را اصلاح کنید و سپس دوباره اجرا کنید.

روش ساخت APK
در ویرایشگر، Bangun را فشار دهید. دو راه برای ساخت وجود دارد. نخست، Bangun di perangkat (ساخت روی دستگاه): مستقیماً روی تلفن بدون اینترنت می‌سازد، برای پروژه‌های HTML، Situs Web، Java، Kotlin و Python. دوم، Bangun online از طریق GitHub Actions: از طریق اینترنت روی GitHub می‌سازد و برای همهٔ انواع پروژه می‌توان از آن استفاده کرد. پروژه‌های Compose فقط با راه دوم (Bangun online) یا در Termux با Gradle می‌توانند ساخته شوند، زیرا Compose به کتابخانه‌های Jetpack Compose نیاز دارد که روی دستگاه در دسترس نیستند. نتیجهٔ نخستین ساخت هنوز امضا نشده است. پس از آن برنامه آن را امضا می‌کند: به طور خودکار با کلید پیش‌فرض، یا با امضای شخصی اگر خانهٔ "Gunakan tanda tangan pribadi" هنگام ساخت پروژه علامت خورده باشد.

روش نصب APK
وقتی APK آماده شد، Pasang (نصب) را فشار دهید تا نصب شود. در Android 8 و بالاتر، تلفن ابتدا "Izinkan dari sumber ini" (اجازه از این منبع) را درخواست می‌کند، زیرا این برنامه APKها را از بیرون Play Store نصب می‌کند. آن مجوز را یک بار در Pengaturan (تنظیمات) فعال کنید، سپس به برنامه بازگردید: نصب به طور خودکار ادامه می‌یابد بدون آنکه لازم باشد دوباره Pasang را فشار دهید. اگر دکمهٔ Pasang ظاهر نشد، مطمئن شوید که ساخت به پایان رسیده و APK ساخته شده است.

روش امضای برنامه
هر APK باید امضا شود تا بتوان آن را نصب کرد. دو گزینه در دسترس است. نخست، کلید پیش‌فرض: برنامه خودش به طور خودکار امضا می‌کند و شما نیازی نیست کاری انجام دهید. دوم، امضای شخصی: ابتدا از طریق منوی Buat Keystore (ساخت keystore) در منوی اصلی یک keystore بسازید، گذرواژهٔ آن را به خوبی نگه دارید، سپس هنگام ساخت پروژه "Gunakan tanda tangan pribadi" را علامت بزنید. Keystore در Download/project/signing نگهداری می‌شود.

خروجی گرفتن از پروژه به صورت ZIP
Ekspor ZIP ارائه شده است تا پروژه را بتوان با دوستان به اشتراک گذاشت. روش آن: در Kelola Project، نام پروژه را طولانی فشار دهید، سپس Ekspor ZIP را انتخاب کنید. نتیجه در Download/project/<NamaProyek>.zip ذخیره می‌شود. پوشهٔ bin همراه آن نمی‌آید، بنابراین اندازه‌اش کوچک است، فقط چند ده KB. آن فایل ZIP را می‌توان برای یک دوست فرستاد یا در GitHub بارگذاری کرد.

Ekstensi JAWS
Ekstensi JAWS از موتور افزونهٔ Jieshuo (CSR) استفاده می‌کند، نه از صفحه‌خوان آن. به این ترتیب، طرح می‌تواند همچنان کار کند حتی اگر کاربر از TalkBack استفاده کند. روش آن: Ekstensi JAWS را در منوی اصلی باز کنید. از آنجا که کلیک خودکار خودش کار می‌کند، سرویس باید ابتدا در Pengaturan Aksesibilitas (تنظیمات دسترس‌پذیری) فعال شود. پس از آن می‌توان طرح جدیدی ساخت: نام طرح را بنویسید، OK را فشار دهید، سپس خانه‌های آن را پر کنید.

Daftar Klik برای مرتب بودن جدا نگه داشته شده است
درون یک طرح دو خانه وجود دارد: خانهٔ اسکریپت و خانهٔ Daftar Klik (فهرست کلیک). فهرست دکمه‌ها به طور جدا در فایل daftar_klik.txt نگهداری می‌شود، در هر سطر یک نام. نمونهٔ محتوا: tombolSimpan، tombolHapus، tombolBuka. برای باز کردن یک برنامه، کافی است در آن فهرست >WhatsApp بنویسید. طرح‌های قدیمی که هنوز فایل daftar_klik.txt ندارند، آن نمونهٔ پیش‌فرض را نشان می‌دهند.

توابع ساده‌ای که ارائه شده‌اند
• klikTombol("tombolSimpan") — یک دکمه را بر اساس متنش کلیک می‌کند.
• klikDaftarTombol(daftar) — فهرست درون daftar_klik.txt را کلیک می‌کند، در هر سطر یک دکمه، به ترتیب، سپس اطلاع می‌دهد چند تا موفق بوده و چند تا پیدا نشده است.
• bukaAplikasi("WhatsApp") — یک برنامه را بر اساس نامش باز می‌کند، یا در فهرست ">WhatsApp" بنویسید.
• klik(540, 1200) — در مختصات صفحه کلیک می‌کند.
همهٔ توابع ابتدا ساده ساخته شده‌اند. وقتی به آن‌ها عادت کردید، بعداً می‌توان توابع بیشتری افزود.

دربارهٔ صفحه‌خوان
این برنامه طوری طراحی شده است که با صفحه‌خوان سازگار باشد. هر خانهٔ پرکردنی یک برچسب و یک نمونهٔ پرکردن دارد و همهٔ دکمه‌ها بدون حرکات پیچیده قابل دسترس‌اند. Ekstensi JAWS طوری ساخته شده است که حتی اگر کاربر از TalkBack استفاده کند همچنان کار کند، زیرا آنچه استفاده می‌شود موتور افزونهٔ آن است، نه صفحه‌خوان آن.

حریم خصوصی و امنیت
پروژه‌ها و keystoreها روی تلفن شما نگهداری می‌شوند. توکن GitHub فقط برای ساخت آنلاین استفاده می‌شود و درون همین برنامه نگهداری می‌شود. توکن یا گذرواژهٔ keystore خود را با هیچ‌کس به اشتراک نگذارید. اگر از امضای شخصی استفاده می‌کنید، keystore و گذرواژهٔ آن را در جایی امن نگه دارید، زیرا اگر گم شوند، APK قدیمی را نمی‌توان با همان امضا به‌روز کرد.

نیازمندی‌ها
Android 5.0 یا جدیدتر. مجوز ذخیره‌سازی: در Android 11 و بالاتر از مجوز دسترسی به همهٔ فایل‌ها استفاده می‌شود، در Android 10 و پایین‌تر از مجوز معمول ذخیره‌سازی (خواندن/نوشتن ذخیره‌سازی) استفاده می‌شود زیرا Android 10 مجوز دسترسی به همهٔ فایل‌ها را ندارد. ساخت روی دستگاه به تلفنی با پردازندهٔ ARM (32 یا 64 بیت) نیاز دارد. ساخت آنلاین از طریق GitHub Actions به اینترنت و یک توکن GitHub نیاز دارد. پروژه‌های Kotlin می‌توانند روی دستگاه ساخته شوند، اما نخستین ساخت آن‌ها به دلیل اندازهٔ بزرگ کامپایلر Kotlin کندتر است و حافظهٔ بیشتری مصرف می‌کند. پروژه‌های Compose از طریق GitHub Actions یا در Termux با Gradle ساخته می‌شوند. پروژه‌های Python به Android 7.0 یا جدیدتر (SDK حداقلی 24) نیاز دارند و APK به دست آمده بزرگ‌تر است زیرا محیط اجرای Python (Chaquopy) را همراه با کتابخانهٔ استاندارد آن در خود دارد.

Terminal
منوی Terminal در صفحهٔ اصلی یک ترمینال درون همین برنامه باز می‌کند. دستورهایی مانند ls را می‌توان برای دیدن محتوای پوشهٔ پروژه، cd را برای جابه‌جایی پوشه و git را برای مدیریت کد به کار برد. خروجی دستورها به صورت متنی نمایش داده می‌شود که صفحه‌خوان می‌تواند آن را بخواند، و دکمهٔ Bacakan hasil (خواندن نتیجه) برای شنیدن آخرین نتیجه وجود دارد. این ترمینال از پوستهٔ سیستم تلفن استفاده می‌کند، بنابراین برنامه‌های تعاملی مانند nano و vim هنوز نمی‌توانند اینجا به کار بروند.

Lisensi (نسخهٔ پولی)
برای فروش یک برنامه، هنگام ساخت پروژه "Aktifkan Lisensi" (فعال کردن مجوز) را علامت بزنید، سپس شمارهٔ WhatsApp خود را پر کنید. برنامهٔ ساخته‌شده هنگام نخستین باز شدن یک کد مجوز درخواست می‌کند: کاربر شناسهٔ دستگاهش را می‌بیند، دکمهٔ Kirim ID Perangkat (فرستادن شناسهٔ دستگاه) را فشار می‌دهد تا آن شناسه را به WhatsApp شما بفرستد، سپس شما با کد مجوز پاسخ می‌دهید. کد مجوز از شناسهٔ دستگاه و گذرواژهٔ پروژه (lisensi_seed در فایل دادهٔ پروژه) محاسبه می‌شود — آن گذرواژه را به خوبی نگه دارید و به اشتراک نگذارید. پس از آنکه کد درست وارد شد، برنامه باز می‌شود و دیگر کد درخواست نمی‌کند.

Pembuat Ikon Otomatis
نماد پروژه‌های جدید هنوز شفاف است، بنابراین Pembuat Ikon (نمادساز) در منوی اصلی در دسترس است. روش آن: Pembuat Ikon را فشار دهید، یک یا دو حرف بنویسید (برای مثال حروف اول نام برنامه)، رنگ پس‌زمینه و رنگ نوشته را انتخاب کنید، پیش‌نمایش آن را ببینید، سپس Simpan ke Proyek (ذخیره در پروژه) را فشار دهید تا آن نماد در پروژهٔ انتخاب‌شده به کار رود، یا Simpan ke Download (ذخیره در Download) را فشار دهید تا فایل PNG آن در جای دیگری به کار رود. پس از آنکه پروژه ساخته شد، برنامه همچنین ساخت نماد را پیشنهاد می‌دهد. نماد قدیمی یک پروژه را می‌توان هر وقت از منوی پروژه در Kelola Project تغییر داد (نام پروژه را طولانی فشار دهید، سپس Ganti Ikon (تغییر نماد) را انتخاب کنید).

Template Proyek Siap Pakai
اگر نمی‌خواهید از یک پروژهٔ خالی شروع کنید، هنگام ساخت پروژه یک قالب انتخاب کنید: Kalkulator (Java)، Catatan (Java)، Daftar Tugas (Kotlin)، Kalkulator Web (HTML)، Situs Profil (Situs Web) یا Penghitung (Compose). انتخاب یک قالب نوع پروژه را به طور خودکار مطابق آن قالب تغییر می‌دهد و پروژه با کد آغازینی که از پیش آماده است ساخته می‌شود — فقط آن را اجرا یا تغییر دهید. اگر نوع پروژه پس از انتخاب قالب دوباره به صورت دستی تغییر کند، قالب لغو می‌شود و پروژه دوباره خالی می‌شود. برای قالب‌های HTML و Situs Web، قالب محتوای index.html را جایگزین می‌کند، از جمله اسکریپت HTML که در فرم نوشته شده است.

Cadangan dan Pulihkan Proyek
برای آنکه پروژه‌ها گم نشوند، قابلیت پشتیبان‌گیری در دسترس است. روش آن: در Kelola Project، نام پروژه را طولانی فشار دهید، سپس Cadangkan (پشتیبان‌گیری) را انتخاب کنید. پشتیبان به صورت ZIP در پوشهٔ Download/backup با نام پروژه و تاریخ ذخیره می‌شود، برای مثال: GarudaDecode-2026-11-14-123045.zip. محتوای آن همان محتوای Ekspor ZIP است (همهٔ محتوای پروژه، بدون پوشهٔ bin). برای بازیابی: منو را در Kelola Project باز کنید، Pulihkan cadangan (بازیابی پشتیبان) را انتخاب کنید، سپس فایل پشتیبان آن را انتخاب کنید. اگر نام پروژه از پیش وجود داشته باشد، برنامه می‌پرسد: Timpa proyek lama (بازنویسی پروژهٔ قدیمی)، یا ذخیره با Nama baru (نام جدید).

Bagikan dan Impor Proyek
برای به اشتراک گذاشتن پروژه با یک دوست: در Kelola Project، نام پروژه را طولانی فشار دهید، سپس Bagikan (اشتراک‌گذاری) را انتخاب کنید. پروژه به صورت ZIP از طریق برنامه‌های اشتراک‌گذاری (WhatsApp، Telegram و دیگران) فرستاده می‌شود. برای دریافت پروژه از یک دوست: منو را در Kelola Project باز کنید، Impor proyek (وارد کردن پروژه) را انتخاب کنید، سپس فایل ZIP آن را انتخاب کنید. آن فایل ZIP باید یک فایل دادهٔ پروژه در خود داشته باشد — اگر نداشته باشد، فایل با پیامی روشن رد می‌شود، زیرا آن فایل یک پروژهٔ Create Aplikasi نیست. اگر نام پروژه از پیش وجود داشته باشد، برنامه می‌پرسد: Timpa proyek lama، یا ذخیره با Nama baru.

Pencarian dan Filter Proyek
اگر پروژه‌ها زیاد شده‌اند، در Kelola Project یک خانهٔ جستجو و یک پالایهٔ نوع وجود دارد. نام پروژه را در خانهٔ جستجو بنویسید، فهرست بلافاصله پالایش می‌شود (حروف بزرگ و کوچک از هم تشخیص داده نمی‌شوند). پالایهٔ نوع فهرست را فقط به یک نوع محدود می‌کند: Semua (همه)، HTML، Situs Web، Java، Kotlin، Compose یا Python. منوی هر پروژه همچنان می‌تواند مانند همیشه از فهرست پالایش‌شده باز شود.

ساخت برنامه با صدا
اگر نمی‌خواهید تایپ کنید، از صدا استفاده کنید: در منوی اصلی روی ساخت با صدا بزنید، سپس یک دستور بگویید. دستورهایی که می‌توانید بگویید: "Buat proyek kalkulator"، "Bangun proyek Kalkulator"، "Buka proyek Kalkulator"، "Jalankan proyek Kalkulator"، "Daftar proyek"، "Buka ikon"، "Kembali" و "Bantuan". برنامه با صدا و متن پاسخ می‌دهد، پس بدون نگاه کردن به صفحه هم می‌توان از آن استفاده کرد. تشخیص صدا از برنامه تشخیص گفتار داخلی گوشی استفاده می‌کند (رایگان؛ اگر بسته زبان اندونزیایی نصب باشد می‌تواند آفلاین هم کار کند). اگر گوشی تشخیص صدا ندارد، دستورها را می‌توان در کادر متن همان صفحه نوشت.

ممیزی دسترس‌پذیری
برای بررسی اینکه آیا چیدمان پروژه پیش از انتشار برای صفحه‌خوان (TalkBack/Jieshuo) مناسب است: در منوی اصلی ممیزی دسترس‌پذیری را باز کنید، پروژه‌ای را انتخاب کنید، سپس روی بارگذاری فهرست چیدمان بزنید و یک پرونده چیدمان انتخاب کنید. IDE آن پرونده XML را می‌خواند و دکمه‌های بدون برچسب را با شماره خط‌هایشان، برچسب‌های تکراری، و عناصری که همدیگر را می‌پوشانند گزارش می‌دهد، سپس رونوشت ترتیب تمرکز را می‌سازد، همان‌گونه که Jieshuo با صدای بلند می‌خواند. اگر دکمه‌ای برچسب ندارد، برچسب آن را پر کنید سپس روی درج خودکار برچسب بزنید — برچسب به‌عنوان contentDescription در پرونده چیدمان نوشته می‌شود. این بررسی فقط XML چیدمان را می‌خواند؛ نماهای Compose و APKهای آماده هنوز پویش نمی‌شوند.

کالبدشکافی خرابی
برای اینکه بفهمید چرا برنامه از روی گزارش خرابی با شناسه یکتا خودبه‌خود بسته می‌شود: در منوی اصلی کالبدشکافی خرابی را باز کنید، شناسه خرابی را از فهرست گزارش‌ها انتخاب کنید، سپس روی بررسی بزنید. IDE کلاس و شماره خط گزارش را با منبع پروژه تطبیق می‌دهد و علت را به زبان اندونزیایی توضیح می‌دهد (مثلاً مرجع خالی، مجوزی که هنوز درخواست نشده، یا خطای JSON)، همراه با پیشنهاد وصله کد. روی اعمال وصله فقط زمانی بزنید که خط منبع هنوز دقیقاً همان باشد که هنگام خرابی بود؛ اگر تغییر کرده باشد، وصله رد می‌شود و IDE از شما می‌خواهد خودتان بررسی کنید. آنچه خوانده می‌شود گزارش خرابی خود IDE است، نه گزارش برنامه ساخته‌شده.

مبدل بین‌پارادایمی
برای تبدیل کد ساده Java به Kotlin، یا چیدمان ساده XML به کد Compose: در منوی اصلی مبدل بین‌پارادایمی را باز کنید، پروژه و پرونده‌ای را انتخاب کنید، سپس روی پیش‌نمایش بزنید. IDE نتیجه تبدیل را به‌صورت متن نشان می‌دهد — اول بررسی کنید، چون خط‌هایی که نمی‌شناسد همان‌طور باقی می‌مانند و واژه static در Java در Kotlin حذف می‌شود (پیش از استفاده معنای آن را بررسی کنید). تبدیل XML به Compose فقط متن، راهنما و جهت را تغییر می‌دهد — اندازه، رنگ و ویژگی‌های دیگر هنوز شامل نیستند. اگر نتیجه درست است، روی اعمال به پرونده بزنید تا پرونده مقصد نوشته شود؛ پرونده منبع تغییر نمی‌کند. فقط الگوهای رایج و امن تبدیل می‌شوند.

سرور ریز محلی
برای آزمودن برنامه‌ای که بدون اینترنت به سرور نیاز دارد: در منوی اصلی سرور ریز محلی را باز کنید، تعریف مسیر بنویسید (مثلاً GET /halo و سپس پاسخ JSON آن)، سپس روی آغاز سرور بزنید. IDE یک سرور HTTP کوچک روی همان گوشی اجرا می‌کند (فقط HTTP، بدون TLS، برای همان شبکه Wi-Fi) و هر درخواست و پاسخ را روی صفحه ثبت می‌کند. مسیرها می‌توانند از پارامترهایی مانند {nama} و یک کلید API ساده استفاده کنند. این سرور فقط برای آزمایش روی گوشی است؛ APK ساخته‌شده هنوز نمی‌تواند سرور شود، و سرور با بسته شدن صفحه آن متوقف می‌شود.

ممیزی امنیتی
برای بررسی حفره‌های امنیتی در کد پروژه پیش از انتشار: در منوی اصلی ممیزی امنیتی را باز کنید، پروژه‌ای را انتخاب کنید، سپس روی آغاز پویش بزنید. IDE کد، مانیفست و پیکربندی پروژه را پویش می‌کند و یافته‌ها را از پرخطر به کم‌خطر گزارش می‌دهد — کلیدهای API آشکار در کد، اجزای آشکار بدون مجوز، WebView که JavaScript را همراه با رابط JavaScript فعال می‌کند، رمزنگاری ضعیف (MD5، SHA1، DES)، نشانی‌های http بدون TLS، و گذرواژه‌هایی که مستقیم در کد نوشته شده‌اند — همراه با پرونده و شماره خط هر یک. برای یافته‌هایی که اصلاح امن دارند (مثلاً تغییر MD5 به SHA-256 یا http به https)، روی اعمال اصلاح بزنید؛ برای کلیدهای API و گذرواژه‌ها، IDE فقط اصلاح پیشنهادی را نشان می‌دهد چون جایگزین باید خود توسعه‌دهنده تصمیم بگیرد. این پویش الگوهای متنی در کد را می‌خواند، نه بایت‌کد را، پس ممکن است برخی یافته‌ها در واقع امن باشند، و حفره‌ای بدون الگو ممکن است از پویش بگریزد — پیش از اعمال بررسی کنید.

ربات آزمونگر رابط کاربری
برای آزمودن خودکار ظاهر برنامه با سناریوهای متنی: در منوی اصلی ربات آزمونگر رابط کاربری را باز کنید، پروژه‌ای را انتخاب کنید، سپس روی ساخت خودکار سناریو بزنید. IDE مانیفست و چیدمان‌های پروژه را می‌خواند و سناریویی از گام‌های متنی می‌نویسد (دکمه را بزن، فیلد را پر کن، صبر کن، برگرد). روی اجرای آزمایشی بزنید تا گزارش اجرای سناریو با برچسب‌های زمانی آن را ببینید. در این مرحله ربات فقط شبیه‌سازی اجرا می‌کند (اجرای آزمایشی) — فشردن واقعی دکمه‌ها روی گوشی و گرفتن خرابی‌های واقعی مرحله بعد است، پس گزارش خرابی اینجا هنوز قالب نمونه است.

سفر زمانی کد
برای بازگرداندن پروژه به حالت قبلی کد بدون تایپ دستورهای Git: در منوی اصلی سفر زمانی کد را باز کنید، پروژه‌ای را انتخاب کنید، برچسب نقطه زمانی را پر کنید (می‌تواند خالی بماند)، سپس روی ثبت نقطه زمانی بزنید. IDE رونوشتی از پرونده‌های منبع پروژه را همراه با hashهایشان در پوشه .riwayat درون پروژه ذخیره می‌کند. فهرست نقاط زمانی همه را نشان می‌دهد؛ دو نقطه را انتخاب کنید سپس روی مقایسه بزنید تا پرونده‌ها و تابع‌های افزوده، تغییرکرده یا حذف‌شده را ببینید. روی بازیابی بزنید تا حالت قدیمی برگردد — پیش از بازیابی، IDE همیشه اول از حالت کنونی پشتیبان می‌گیرد، پس چیزی از دست نمی‌رود. روی ساخت رونوشت آزمایشی بزنید تا پروژه را در پوشه‌ای تازه رونوشت کنید و تغییرها را بدون دست‌کاری پروژه اصلی بیازمایید. فقط پرونده‌های منبع ثبت می‌شوند.

کارخانه ماژول
برای بسته‌بندی بخشی از پروژه به‌عنوان ماژولی که پروژه دیگری بتواند استفاده کند: در منوی اصلی کارخانه ماژول را باز کنید، پروژه منبع را انتخاب کنید، پرونده‌های صفحه، کلاس، رشته و مجوز را که می‌خواهید بسته‌بندی شوند علامت بزنید، سپس روی بسته‌بندی به‌عنوان ماژول بزنید. IDE بایگانی ZIP را همراه با فراداده JSON (نام ماژول، نسخه، رشته‌ها و مجوزهای استفاده‌شده) می‌نویسد. برای نصب ماژول در پروژه دیگر، کارخانه ماژول را باز کنید، پروژه مقصد را انتخاب کنید، سپس روی نصب ماژول بزنید و پرونده .zip ماژول را انتخاب کنید — ادغام رشته‌ها و مجوزها را بدون بازنویسی کد موجود اضافه می‌کند، و اگر نام پرونده‌ای در پروژه مقصد استفاده شده باشد آن را ادغام نمی‌کند. ماژول کتابخانه یا تنظیمات ساخت همراه ندارد.

دیکته ساختار کد
برای نوشتن کد با صدا درون ویرایشگر: پروژه‌ای را در ویرایشگر باز کنید، سپس روی دکمه دیکته ساختار کد بزنید. دستورها را به زبان اندونزیایی بگویید، مثلاً buat fungsi tambah dengan parameter a angka dan b angka، buat kelas Mobil، یا buat variabel teks nama sama dengan Budi — IDE گفتار را به بلوک کد Java، Kotlin، Python یا Compose معتبر از نظر نحوی تبدیل می‌کند و در جای نشانگر می‌گذارد، سپس خلاصه‌ای کوتاه را از طریق Jieshuo با صدای بلند می‌خواند. دیکته از خدمت ورودی صدای داخلی سیستم استفاده می‌کند، بدون مجوز اضافی میکروفون، و فقط الگوهای دستور ثبت‌شده را می‌شناسد؛ گفتار خارج از آن الگوها به کد تبدیل نمی‌شود. عددهایی که با واژه گفته می‌شوند (مثلاً 'lima') هنوز به رقم تبدیل نمی‌شوند.

فضای همکاری محلی (بدون اینترنت)
برای کار مشترک در یک اتاق بدون اینترنت: در منوی اصلی همکاری را باز کنید، سپس بخش فضای همکاری محلی را باز کنید. یک گوشی جلسه‌ای باز می‌کند (IDE نشانی IP محلی و PIN شش‌رقمی را نشان می‌دهد)، گوشی دیگر با آن نشانی و PIN می‌پیوندد. تغییرهای متن به‌صورت تفاوت خط‌ها فرستاده می‌شوند، APK ساخته‌شده را می‌توان به گوشی آزمایش‌کننده فرستاد، و گزارش‌های خرابی از گوشی آزمایش‌کننده بازپس گرفته می‌شوند. یک جلسه فقط برای یک دوست است؛ اگر دو نفر دقیقاً همان خط را هم‌زمان تغییر دهند، آخرین تغییر استفاده می‌شود. PIN به‌صورت متن ساده در شبکه محلی فرستاده می‌شود. این اتاق هنوز روی گوشی واقعی آزموده نشده است.

تنظیمات هوش مصنوعی
برای تنظیم ارائه‌دهنده هوش مصنوعی و کلیدهای API برای ساخت برنامه: در منوی اصلی، در گروه تنظیمات، روی تنظیمات هوش مصنوعی بزنید (کنار دکمه اتصال‌دهنده). ارائه‌دهنده مورد استفاده را از فهرست موجود انتخاب کنید، و تعویض مدل هنگام خطای ارائه‌دهنده را علامت بزنید تا اگر مدلی شکست خورد، IDE خودکار مدل بعدی همان ارائه‌دهنده را بیازماید. روی مدیریت کلیدهای API بزنید تا کلیدهای پشتیبان اضافه کنید (نام و کلید را پر کنید، سپس روی ذخیره بزنید؛ کلیدها پوشیده نشان داده می‌شوند، فقط ۴ کاراکتر آخر دیده می‌شود). کلیدها روی گوشی ذخیره می‌شوند و هرگز به جایی جز ارائه‌دهنده انتخاب‌شده هنگام ساخت برنامه فرستاده نمی‌شوند. توجه: در حال حاضر انتخاب ارائه‌دهنده و کلید فقط ثبت و روی صفحه AI Pembuat Aplikasi نمایش داده می‌شود — ساخت برنامه هنوز از هوش مصنوعی محلی روی گوشی استفاده می‌کند (بدون اینترنت)؛ استفاده از ارائه‌دهندگان آنلاین بعداً می‌آید.

اتصال‌دهنده
برای تحلیل APK و سپس فرستادن آن: در منوی اصلی، در گروه تنظیمات، روی اتصال‌دهنده بزنید (کنار دکمه تنظیمات هوش مصنوعی). پرونده APK را از گوشی انتخاب کنید، IDE محتوای آن را می‌خواند (نام بسته، نسخه، فهرست فعالیت‌ها)، سپس روی ارسال APK بزنید تا از طریق منوی اشتراک‌گذاری سیستم (مثلاً WhatsApp یا Drive) فرستاده شود.

زبان و صدا
برای تغییر زبان برنامه: تنظیمات را باز کنید، سپس زبان برنامه را باز کنید، سپس زبان یا پیروی از سیستم را انتخاب کنید. صفحه اصلی و بیشتر صفحه‌ها بی‌درنگ و بدون بستن یا راه‌اندازی دوباره برنامه به زبان انتخاب‌شده تغییر می‌کنند؛ برخی صفحه‌ها (مثلاً ترمینال، همکاری، تنظیمات هوش مصنوعی و مدیریت کلیدها) تا باز شدن دوباره هنوز از زبان قدیمی استفاده می‌کنند. اگر پیروی از سیستم را انتخاب کنید، زبان از زبان سیستم گوشی پیروی می‌کند.
