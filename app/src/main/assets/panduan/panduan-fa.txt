به Create Aplikasi by Al Kautsar خوش آمدید
Create Aplikasi یک برنامهٔ ساخت برنامهٔ اندروید است که مستقیماً روی تلفن اجرا می‌شود و نیازی به لپ‌تاپ ندارد. این برنامه به هر کسی امکان می‌دهد برنامهٔ اندروید خودش را بسازد، از جمله کاربرانی که تازه ساخت برنامه را یاد می‌گیرند و کاربران صفحه‌خوان. راهنمای کامل استفاده از این برنامه در همین صفحهٔ Tentang Alat (دربارهٔ ابزار) در دسترس است.

این برنامه چیست و برای چه کسانی است
Create Aplikasi ابزاری برای ساخت برنامهٔ اندروید است که روی تلفن اجرا می‌شود. این برنامه برای هر کسی است که می‌خواهد برنامهٔ اندروید خودش را بسازد، از جمله تازه‌کارها و کاربران صفحه‌خوان. این برنامه یک ویرایشگر کد، دکمهٔ Jalankan (اجرا) برای آزمودن پروژه، دکمهٔ Bangun (ساخت) برای ساخت APK و همچنین منوهایی برای امضا و نصب APK ارائه می‌دهد.

هدف این برنامه
این برنامه ساخته شده است تا هر کسی بتواند به‌آسانی و مستقیماً از تلفن، برنامهٔ اندروید خودش را بسازد. ظاهر آن تا حد امکان ساده ساخته شده است تا حتی کاربران تازه‌کار هم بتوانند بلافاصله آن را امتحان کنند.

روش ساخت پروژهٔ جدید، گام به گام
1. در منوی اصلی Buat Project (ساخت پروژه) را فشار دهید.
2. نوع پروژه را انتخاب کنید: HTML، Situs Web (وب‌سایت)، Java، Kotlin، Compose یا Python.
3. نام برنامه را پر کنید، برای مثال: Garuda Decode.
4. نام بسته (package name) را پر کنید، برای مثال: com.android.garudadecode. نام بسته باید از حروف کوچک استفاده کند و از دست‌کم دو بخش تشکیل شود که با نقطه از هم جدا شده‌اند.
5. نسخهٔ برنامه را پر کنید، برای مثال: 1.0، و کد نسخه را به صورت عدد، برای مثال: 1. اگر خالی بماند، نسخه به طور خودکار با 1.0 و کد نسخه با 1 پر می‌شود.
6. در صورت نیاز SDK حداقلی و SDK هدف را پر کنید. اگر خالی بماند، مقدار پیش‌فرض استفاده می‌شود. SDK حداقلی پایین‌ترین نسخهٔ اندروید پشتیبانی‌شده است، برای مثال: 21 یعنی Android 5.0. حداکثر SDK هدف 36 (Android 16) است.
7. دکمهٔ Pilih Izin (انتخاب مجوزها) را فشار دهید تا مجوزهای برنامه را انتخاب کنید، برای مثال: INTERNET. مجوز INTERNET از پیش به طور پیش‌فرض علامت خورده است. فقط مجوزهایی را علامت بزنید که برنامه واقعاً به آن‌ها نیاز دارد.
8. اگر می‌خواهید، گزینهٔ "Gunakan arsitektur terpisah 64 bit dan 32 bit" (استفاده از معماری‌های جدا 64 بیت و 32 بیت) را علامت بزنید تا اندازهٔ APK کوچک‌تر شود، و اگر می‌خواهید از یک keystore ساختهٔ خودتان استفاده کنید، گزینهٔ "Gunakan tanda tangan pribadi" (استفاده از امضای شخصی) را علامت بزنید.
9. Buat Proyek (ساخت پروژه) را فشار دهید. پروژهٔ جدید در پوشهٔ Download/project ذخیره می‌شود و بلافاصله در Kelola Project (مدیریت پروژه‌ها) دیده می‌شود.

انواع پروژهٔ در دسترس
• HTML: نما از index.html، style.css و script.js که از طریق WebView اجرا می‌شود. مستقیماً روی تلفن ساخته می‌شود.
• Situs Web: وب‌سایتی با منو (Beranda (خانه)، Tentang (درباره)، Kontak (تماس)) از index.html، tentang.html، kontak.html، style.css و script.js که از طریق WebView اجرا می‌شود. مستقیماً روی تلفن ساخته می‌شود.
• Java: روی تلفن ساخته می‌شود. MainActivity در app/src/main/java/<nama-paket>/MainActivity.java قرار دارد. نما از app/src/main/res/layout/activity_main.xml، متن از app/src/main/res/values/strings.xml و پوسته از app/src/main/res/values/styles.xml می‌آید.
• Kotlin: می‌تواند روی دستگاه (آفلاین) با استفاده از کامپایلر Kotlin که همراه برنامه است ساخته شود، یا از طریق GitHub Actions. MainActivity در app/src/main/java/<nama-paket>/MainActivity.kt قرار دارد و فایل‌های res همان فایل‌های پروژهٔ Java هستند. نخستین ساخت Kotlin به دلیل اندازهٔ بزرگ کامپایلر کندتر است و فایل‌های .java که به کلاس‌های Kotlin ارجاع می‌دهند هنوز نمی‌توانند ساخته شوند (فایل‌های .java پیش از فایل‌های .kt کامپایل می‌شوند).
• Compose: یک برنامهٔ اندروید مدرن که رابط آن با Jetpack Compose ساخته شده است (نه با چیدمان XML). MainActivity در app/src/main/java/<nama-paket>/MainActivity.kt قرار دارد. پروژه‌های Compose از طریق GitHub Actions (منوی Bangun پروژه، سپس Bangun online (ساخت آنلاین)) یا در Termux با Gradle ساخته می‌شوند، زیرا Compose به کتابخانه‌های Jetpack Compose نیاز دارد که روی دستگاه در دسترس نیستند.
• Python: منطق برنامه به زبان Python (Chaquopy) در app/src/main/python/main.py نوشته می‌شود و توسط میزبان MainActivity.java در app/src/main/java/<nama-paket>/MainActivity.java اجرا می‌شود. پروژه‌های Python می‌توانند مستقیماً روی تلفن ساخته شوند (محیط اجرای Chaquopy همراه برنامه است) و همچنین از طریق GitHub Actions. SDK حداقلی پروژه‌های Python برابر 24 (Android 7.0) است.

تغییر معماری پروژه
برای تغییر گزینه‌های معماری یک پروژه موجود بدون ساخت پروژه جدید: در منوی اصلی، روی «تغییر معماری پروژه» بزنید، سپس پروژه را انتخاب کنید و تیک «ساخت APK ۶۴ بیتی (arm64-v8a)» یا «ساخت APK ۳۲ بیتی (armeabi-v7a)» را تغییر دهید؛ یا در «مدیریت پروژه»، نام پروژه را لمس طولانی کنید و «تغییر معماری» را انتخاب کنید تا همان صفحه مستقیماً برای آن پروژه باز شود. قانون این است: اگر هر دو تیک فعال باشند، ساخت دو APK جداگانه تولید می‌کند، یکی ۶۴ بیتی و یکی ۳۲ بیتی؛ اگر فقط یک تیک فعال باشد، ساخت یک APK جهانی تولید می‌کند که همچنان روی دستگاه‌های ۶۴ بیتی و ۳۲ بیتی کار می‌کند. APK جداگانه برای یک گونه به‌تنهایی هنوز پشتیبانی نمی‌شود، چون مسیر ساخت فقط انتخاب جداگانه یا جهانی را می‌شناسد، اما انتخاب هر گونه داخل پروژه ذخیره می‌ماند تا هنگام باز کردن دوباره صفحه از دست نرود.

چیدمان فایل‌های پروژه‌های Java، HTML، Situs Web، Kotlin، Compose و Python
پروژه‌های Java، HTML، Situs Web، Kotlin، Compose و Python همانند پروژه‌های اندروید به طور کلی چیده شده‌اند. درون پوشهٔ app پوشهٔ src قرار دارد و درون آن پوشهٔ main. درون پوشهٔ main فایل AndroidManifest.xml در کنار پوشهٔ java قرار دارد، پوشهٔ res که layout/activity_main.xml و values/strings.xml و همچنین values/styles.xml را در خود دارد، و برای HTML و Situs Web پوشهٔ assets که index.html را در خود دارد (Situs Web فایل‌های tentang.html و kontak.html را هم دارد). پروژه‌های HTML و Situs Web نیز MainActivity خودشان را در app/src/main/java/<nama-paket>/MainActivity.java دارند که index.html را در WebView بارگذاری می‌کند و در AndroidManifest لانچر می‌شود. پروژه‌های Python کد Python را در app/src/main/python/main.py و میزبان MainActivity.java را در app/src/main/java/<nama-paket>/MainActivity.java دارند. AndroidManifest.xml، layout، strings و styles را می‌توان در ویرایشگر باز کرد و تغییر داد، درست مانند MainActivity. پروژه‌های قدیمی که مانیفست آن‌ها هنوز در کنار پوشهٔ app قرار دارد نیز می‌توانند ساخته شوند، زیرا هنگام ساخت، برنامه ابتدا AndroidManifest.xml را در app/src/main/ بررسی می‌کند، سپس آن را که در کنار پوشهٔ app است و در پایان فایل دادهٔ پروژه را.

قوانین مجوزها (مهم)
مجوزهایی که هنگام ساخت پروژه علامت زده می‌شوند فقط در یک جا ثبت می‌شوند، بسته به نوع پروژه. برای پروژه‌های Java، HTML، Situs Web، Kotlin، Compose و Python، مجوزهای علامت‌خورده فقط در AndroidManifest.xml که در app/src/main/، در کنار پوشهٔ java، درون پوشهٔ پروژه قرار دارد ثبت می‌شوند. فایل دادهٔ پروژه برای پروژه‌های Java، HTML، Situs Web، Kotlin، Compose و Python فهرست مجوزها را در خود ندارد. اگر Java را انتخاب کنید و INTERNET و CAMERA را علامت بزنید، آنچه در AndroidManifest.xml ثبت می‌شود فقط INTERNET و CAMERA است و هیچ مجوز دیگری همراه آن نمی‌آید. هنگام ساخت، برنامه مجوزها را از همان جا می‌خواند: از AndroidManifest.xml در app/src/main/ برای پروژه‌های Java، HTML، Situs Web، Kotlin، Compose و Python (اگر نباشد، از AndroidManifest.xml در کنار پوشهٔ app برای پروژه‌های قدیمی)، و از فایل دادهٔ پروژه برای پروژه‌های قدیمی.

روش استفاده از ویرایشگر
Kelola Project را باز کنید و روی نام پروژه بزنید تا ویرایشگر باز شود. در ویرایشگر می‌توان فایل‌ها را باز کرد، کد نوشت و تغییرات را ذخیره کرد. برای پروژه‌های Java، HTML، Situs Web، Kotlin، Compose و Python، فایل‌ها درون پوشهٔ app/src/main چیده شده‌اند. برای به اشتراک گذاشتن پروژه، از Ekspor ZIP (خروجی ZIP) استفاده کنید (بخش زیر را ببینید).

روش اجرای پروژه
در ویرایشگر، Jalankan را فشار دهید تا پروژه آزموده شود. برای پروژه‌های HTML و Situs Web، آنچه اجرا می‌شود index.html از طریق WebView است. اگر خطایی رخ داد، پیام خطا را بخوانید، کد را اصلاح کنید و سپس دوباره اجرا کنید.

روش ساخت APK
در ویرایشگر، Bangun را فشار دهید. دو راه برای ساخت وجود دارد. نخست، Bangun di perangkat (ساخت روی دستگاه): مستقیماً روی تلفن بدون اینترنت می‌سازد، برای پروژه‌های HTML، Situs Web، Java، Kotlin و Python. دوم، Bangun online از طریق GitHub Actions: از طریق اینترنت روی GitHub می‌سازد و برای همهٔ انواع پروژه می‌توان از آن استفاده کرد. پروژه‌های Compose فقط با راه دوم (Bangun online) یا در Termux با Gradle می‌توانند ساخته شوند، زیرا Compose به کتابخانه‌های Jetpack Compose نیاز دارد که روی دستگاه در دسترس نیستند. نتیجهٔ نخستین ساخت هنوز امضا نشده است. پس از آن برنامه آن را امضا می‌کند: به طور خودکار با کلید پیش‌فرض، یا با امضای شخصی اگر خانهٔ "Gunakan tanda tangan pribadi" هنگام ساخت پروژه علامت خورده باشد.

روش نصب APK
وقتی APK آماده شد، Pasang (نصب) را فشار دهید تا نصب شود. در Android 8 و بالاتر، تلفن ابتدا "Izinkan dari sumber ini" (اجازه از این منبع) را درخواست می‌کند، زیرا این برنامه APKها را از بیرون Play Store نصب می‌کند. آن مجوز را یک بار در Pengaturan (تنظیمات) فعال کنید، سپس به برنامه بازگردید: نصب به طور خودکار ادامه می‌یابد بدون آنکه لازم باشد دوباره Pasang را فشار دهید. اگر دکمهٔ Pasang ظاهر نشد، مطمئن شوید که ساخت به پایان رسیده و APK ساخته شده است.

روش امضای برنامه
هر APK باید امضا شود تا بتوان آن را نصب کرد. دو گزینه در دسترس است. نخست، کلید پیش‌فرض: برنامه خودش به طور خودکار امضا می‌کند و شما نیازی نیست کاری انجام دهید. دوم، امضای شخصی: ابتدا از طریق منوی Buat Keystore (ساخت keystore) در منوی اصلی یک keystore بسازید، گذرواژهٔ آن را به خوبی نگه دارید، سپس هنگام ساخت پروژه "Gunakan tanda tangan pribadi" را علامت بزنید. Keystore در Download/project/signing نگهداری می‌شود.

خروجی گرفتن از پروژه به صورت ZIP
Ekspor ZIP ارائه شده است تا پروژه را بتوان با دوستان به اشتراک گذاشت. روش آن: در Kelola Project، نام پروژه را طولانی فشار دهید، سپس Ekspor ZIP را انتخاب کنید. نتیجه در Download/project/<NamaProyek>.zip ذخیره می‌شود. پوشهٔ bin همراه آن نمی‌آید، بنابراین اندازه‌اش کوچک است، فقط چند ده KB. آن فایل ZIP را می‌توان برای یک دوست فرستاد یا در GitHub بارگذاری کرد.

Ekstensi JAWS
Ekstensi JAWS از موتور افزونهٔ Jieshuo (CSR) استفاده می‌کند، نه از صفحه‌خوان آن. به این ترتیب، طرح می‌تواند همچنان کار کند حتی اگر کاربر از TalkBack استفاده کند. روش آن: Ekstensi JAWS را در منوی اصلی باز کنید. از آنجا که کلیک خودکار خودش کار می‌کند، سرویس باید ابتدا در Pengaturan Aksesibilitas (تنظیمات دسترس‌پذیری) فعال شود. پس از آن می‌توان طرح جدیدی ساخت: نام طرح را بنویسید، OK را فشار دهید، سپس خانه‌های آن را پر کنید.

Daftar Klik برای مرتب بودن جدا نگه داشته شده است
درون یک طرح دو خانه وجود دارد: خانهٔ اسکریپت و خانهٔ Daftar Klik (فهرست کلیک). فهرست دکمه‌ها به طور جدا در فایل daftar_klik.txt نگهداری می‌شود، در هر سطر یک نام. نمونهٔ محتوا: tombolSimpan، tombolHapus، tombolBuka. برای باز کردن یک برنامه، کافی است در آن فهرست >WhatsApp بنویسید. طرح‌های قدیمی که هنوز فایل daftar_klik.txt ندارند، آن نمونهٔ پیش‌فرض را نشان می‌دهند.

توابع ساده‌ای که ارائه شده‌اند
• klikTombol("tombolSimpan") — یک دکمه را بر اساس متنش کلیک می‌کند.
• klikDaftarTombol(daftar) — فهرست درون daftar_klik.txt را کلیک می‌کند، در هر سطر یک دکمه، به ترتیب، سپس اطلاع می‌دهد چند تا موفق بوده و چند تا پیدا نشده است.
• bukaAplikasi("WhatsApp") — یک برنامه را بر اساس نامش باز می‌کند، یا در فهرست ">WhatsApp" بنویسید.
• klik(540, 1200) — در مختصات صفحه کلیک می‌کند.
همهٔ توابع ابتدا ساده ساخته شده‌اند. وقتی به آن‌ها عادت کردید، بعداً می‌توان توابع بیشتری افزود.

دربارهٔ صفحه‌خوان
این برنامه طوری طراحی شده است که با صفحه‌خوان سازگار باشد. هر خانهٔ پرکردنی یک برچسب و یک نمونهٔ پرکردن دارد و همهٔ دکمه‌ها بدون حرکات پیچیده قابل دسترس‌اند. Ekstensi JAWS طوری ساخته شده است که حتی اگر کاربر از TalkBack استفاده کند همچنان کار کند، زیرا آنچه استفاده می‌شود موتور افزونهٔ آن است، نه صفحه‌خوان آن.

حریم خصوصی و امنیت
پروژه‌ها و keystoreها روی تلفن شما نگهداری می‌شوند. توکن GitHub فقط برای ساخت آنلاین استفاده می‌شود و درون همین برنامه نگهداری می‌شود. توکن یا گذرواژهٔ keystore خود را با هیچ‌کس به اشتراک نگذارید. اگر از امضای شخصی استفاده می‌کنید، keystore و گذرواژهٔ آن را در جایی امن نگه دارید، زیرا اگر گم شوند، APK قدیمی را نمی‌توان با همان امضا به‌روز کرد.

نیازمندی‌ها
Android 5.0 یا جدیدتر. مجوز ذخیره‌سازی: در Android 11 و بالاتر از مجوز دسترسی به همهٔ فایل‌ها استفاده می‌شود، در Android 10 و پایین‌تر از مجوز معمول ذخیره‌سازی (خواندن/نوشتن ذخیره‌سازی) استفاده می‌شود زیرا Android 10 مجوز دسترسی به همهٔ فایل‌ها را ندارد. ساخت روی دستگاه به تلفنی با پردازندهٔ ARM (32 یا 64 بیت) نیاز دارد. ساخت آنلاین از طریق GitHub Actions به اینترنت و یک توکن GitHub نیاز دارد. پروژه‌های Kotlin می‌توانند روی دستگاه ساخته شوند، اما نخستین ساخت آن‌ها به دلیل اندازهٔ بزرگ کامپایلر Kotlin کندتر است و حافظهٔ بیشتری مصرف می‌کند. پروژه‌های Compose از طریق GitHub Actions یا در Termux با Gradle ساخته می‌شوند. پروژه‌های Python به Android 7.0 یا جدیدتر (SDK حداقلی 24) نیاز دارند و APK به دست آمده بزرگ‌تر است زیرا محیط اجرای Python (Chaquopy) را همراه با کتابخانهٔ استاندارد آن در خود دارد.

Terminal
منوی Terminal در صفحهٔ اصلی یک ترمینال درون همین برنامه باز می‌کند. دستورهایی مانند ls را می‌توان برای دیدن محتوای پوشهٔ پروژه، cd را برای جابه‌جایی پوشه و git را برای مدیریت کد به کار برد. خروجی دستورها به صورت متنی نمایش داده می‌شود که صفحه‌خوان می‌تواند آن را بخواند، و دکمهٔ Bacakan hasil (خواندن نتیجه) برای شنیدن آخرین نتیجه وجود دارد. این ترمینال از پوستهٔ سیستم تلفن استفاده می‌کند، بنابراین برنامه‌های تعاملی مانند nano و vim هنوز نمی‌توانند اینجا به کار بروند.

Lisensi (نسخهٔ پولی)
برای فروش یک برنامه، هنگام ساخت پروژه "Aktifkan Lisensi" (فعال کردن مجوز) را علامت بزنید، سپس شمارهٔ WhatsApp خود را پر کنید. برنامهٔ ساخته‌شده هنگام نخستین باز شدن یک کد مجوز درخواست می‌کند: کاربر شناسهٔ دستگاهش را می‌بیند، دکمهٔ Kirim ID Perangkat (فرستادن شناسهٔ دستگاه) را فشار می‌دهد تا آن شناسه را به WhatsApp شما بفرستد، سپس شما با کد مجوز پاسخ می‌دهید. کد مجوز از شناسهٔ دستگاه و گذرواژهٔ پروژه (lisensi_seed در فایل دادهٔ پروژه) محاسبه می‌شود — آن گذرواژه را به خوبی نگه دارید و به اشتراک نگذارید. پس از آنکه کد درست وارد شد، برنامه باز می‌شود و دیگر کد درخواست نمی‌کند.

Pembuat Ikon Otomatis
نماد پروژه‌های جدید هنوز شفاف است، بنابراین Pembuat Ikon (نمادساز) در منوی اصلی در دسترس است. روش آن: Pembuat Ikon را فشار دهید، یک یا دو حرف بنویسید (برای مثال حروف اول نام برنامه)، رنگ پس‌زمینه و رنگ نوشته را انتخاب کنید، پیش‌نمایش آن را ببینید، سپس Simpan ke Proyek (ذخیره در پروژه) را فشار دهید تا آن نماد در پروژهٔ انتخاب‌شده به کار رود، یا Simpan ke Download (ذخیره در Download) را فشار دهید تا فایل PNG آن در جای دیگری به کار رود. پس از آنکه پروژه ساخته شد، برنامه همچنین ساخت نماد را پیشنهاد می‌دهد. نماد قدیمی یک پروژه را می‌توان هر وقت از منوی پروژه در Kelola Project تغییر داد (نام پروژه را طولانی فشار دهید، سپس Ganti Ikon (تغییر نماد) را انتخاب کنید).

Template Proyek Siap Pakai
اگر نمی‌خواهید از یک پروژهٔ خالی شروع کنید، هنگام ساخت پروژه یک قالب انتخاب کنید: Kalkulator (Java)، Catatan (Java)، Daftar Tugas (Kotlin)، Kalkulator Web (HTML)، Situs Profil (Situs Web) یا Penghitung (Compose). انتخاب یک قالب نوع پروژه را به طور خودکار مطابق آن قالب تغییر می‌دهد و پروژه با کد آغازینی که از پیش آماده است ساخته می‌شود — فقط آن را اجرا یا تغییر دهید. اگر نوع پروژه پس از انتخاب قالب دوباره به صورت دستی تغییر کند، قالب لغو می‌شود و پروژه دوباره خالی می‌شود. برای قالب‌های HTML و Situs Web، قالب محتوای index.html را جایگزین می‌کند، از جمله اسکریپت HTML که در فرم نوشته شده است.

Cadangan dan Pulihkan Proyek
برای آنکه پروژه‌ها گم نشوند، قابلیت پشتیبان‌گیری در دسترس است. روش آن: در Kelola Project، نام پروژه را طولانی فشار دهید، سپس Cadangkan (پشتیبان‌گیری) را انتخاب کنید. پشتیبان به صورت ZIP در پوشهٔ Download/backup با نام پروژه و تاریخ ذخیره می‌شود، برای مثال: GarudaDecode-2026-11-14-123045.zip. محتوای آن همان محتوای Ekspor ZIP است (همهٔ محتوای پروژه، بدون پوشهٔ bin). برای بازیابی: منو را در Kelola Project باز کنید، Pulihkan cadangan (بازیابی پشتیبان) را انتخاب کنید، سپس فایل پشتیبان آن را انتخاب کنید. اگر نام پروژه از پیش وجود داشته باشد، برنامه می‌پرسد: Timpa proyek lama (بازنویسی پروژهٔ قدیمی)، یا ذخیره با Nama baru (نام جدید).

Bagikan dan Impor Proyek
برای به اشتراک گذاشتن پروژه با یک دوست: در Kelola Project، نام پروژه را طولانی فشار دهید، سپس Bagikan (اشتراک‌گذاری) را انتخاب کنید. پروژه به صورت ZIP از طریق برنامه‌های اشتراک‌گذاری (WhatsApp، Telegram و دیگران) فرستاده می‌شود. برای دریافت پروژه از یک دوست: منو را در Kelola Project باز کنید، Impor proyek (وارد کردن پروژه) را انتخاب کنید، سپس فایل ZIP آن را انتخاب کنید. آن فایل ZIP باید یک فایل دادهٔ پروژه در خود داشته باشد — اگر نداشته باشد، فایل با پیامی روشن رد می‌شود، زیرا آن فایل یک پروژهٔ Create Aplikasi نیست. اگر نام پروژه از پیش وجود داشته باشد، برنامه می‌پرسد: Timpa proyek lama، یا ذخیره با Nama baru.

Pencarian dan Filter Proyek
اگر پروژه‌ها زیاد شده‌اند، در Kelola Project یک خانهٔ جستجو و یک پالایهٔ نوع وجود دارد. نام پروژه را در خانهٔ جستجو بنویسید، فهرست بلافاصله پالایش می‌شود (حروف بزرگ و کوچک از هم تشخیص داده نمی‌شوند). پالایهٔ نوع فهرست را فقط به یک نوع محدود می‌کند: Semua (همه)، HTML، Situs Web، Java، Kotlin، Compose یا Python. منوی هر پروژه همچنان می‌تواند مانند همیشه از فهرست پالایش‌شده باز شود.

ساخت برنامه با صدا
اگر نمی‌خواهید تایپ کنید، از صدا استفاده کنید: در منوی اصلی روی ساخت با صدا بزنید، سپس یک دستور بگویید. دستورهایی که می‌توانید بگویید: "Buat proyek kalkulator"، "Bangun proyek Kalkulator"، "Buka proyek Kalkulator"، "Jalankan proyek Kalkulator"، "Daftar proyek"، "Buka ikon"، "Kembali" و "Bantuan". برنامه با صدا و متن پاسخ می‌دهد، پس بدون نگاه کردن به صفحه هم می‌توان از آن استفاده کرد. تشخیص صدا از برنامه تشخیص گفتار داخلی گوشی استفاده می‌کند (رایگان؛ اگر بسته زبان اندونزیایی نصب باشد می‌تواند آفلاین هم کار کند). اگر گوشی تشخیص صدا ندارد، دستورها را می‌توان در کادر متن همان صفحه نوشت.

سازنده برنامه با AI
برنامهٔ مورد نظر را در صفحهٔ سازنده برنامه با هوش مصنوعی بنویسید یا دیکته کنید، برای مثال: «برنامهٔ یادداشت با دکمهٔ ذخیره». برنامه کلیدواژه‌ها را درون خود گوشی تحلیل می‌کند (بدون اینترنت، بدون هزینه)، سپس یک پروژهٔ واقعی از مناسب‌ترین قالب می‌سازد: ماشین‌حساب، یادداشت، فهرست کارها، ماشین‌حساب وب، سایت پروفایل یا شمارنده. اگر توصیف شما هنوز قالب مناسبی ندارد، برنامه یک پروژهٔ خالی می‌سازد و صادقانه می‌گوید — وانمود به فهمیدن نمی‌کند. پروژهٔ ساخته‌شده با هوش مصنوعی را می‌توان مستقیم در مدیریت پروژه‌ها باز کرد.

پیش‌نمایش مستقیم در تلفن دوست
برای نشان دادن پروژه به دوست پیش از ساخت: در مدیریت پروژه‌ها، نام پروژه را طولانی فشار دهید، سپس پیش‌نمایش در تلفن دوست را انتخاب کنید. برنامه یک بستهٔ کوچک پیش‌نمایش می‌سازد که شامل فایل‌های اصلی پروژه است (index.html یا MainActivity یا main.py) به‌علاوه BACA-SAYA.txt با دستورالعمل‌ها و info.txt. بسته به‌صورت ZIP از طریق WhatsApp یا Telegram فرستاده می‌شود. دوستی که آن را دریافت می‌کند می‌تواند پیش‌نمایش را فوراً باز کند: صفحه‌های HTML در مرورگر باز می‌شوند و کد Java/Kotlin/Python به‌صورت متن خوانده می‌شود.

بازار پروژه
بازار پروژه شامل پروژه‌های نمونهٔ داخلی است که با یک ضربه می‌توان آن‌ها را در پوشهٔ پروژه نصب کرد: ماشین‌حساب، یادداشت، فهرست کارها، ماشین‌حساب وب، سایت پروفایل، شمارنده، ساعت دیجیتال و آزمون وب. بازار آنلاین (دانلود نمونه‌ها از اینترنت) هنوز در دسترس نیست، پس این بازار شامل نمونه‌هایی است که از پیش در برنامه هستند. پروژهٔ نصب‌شده را می‌توان در مدیریت پروژه‌ها باز کرد و تغییر داد، مانند پروژه‌ای که خودتان ساخته‌اید.

همکاری مستقیم
برای کار روی پروژه همراه با دوست: همکاری را در منوی اصلی باز کنید، پروژه را انتخاب کنید، یک یادداشت تغییر بنویسید (چه چیزی تغییر کرده است)، سپس اشتراک‌گذاری برای همکاری را فشار دهید. پروژه به‌صورت ZIP همراه با فایل CATATAN.txt درون آن فرستاده می‌شود. دوست شما روی آن کار می‌کند و ZIP را برمی‌گرداند؛ شما دریافت پاسخ را فشار می‌دهید، نخست یادداشت تغییر را می‌خوانید، سپس اعمال را انتخاب می‌کنید تا پروژهٔ قدیمی جایگزین شود، یا لغو اگر نظرتان عوض شد. ZIP بدون CATATAN.txt بستهٔ همکاری نیست — برای ZIP معمولی پروژه، از وارد کردن پروژه در مدیریت پروژه‌ها استفاده کنید.

مترجم خودکار برنامه
برای ترجمهٔ متن برنامه به زبان دیگر: مترجم برنامه را در منوی اصلی باز کنید، پروژه و زبان مقصد (انگلیسی، عربی یا جاوه‌ای) را انتخاب کنید، سپس ترجمه را فشار دهید. فرهنگ لغت از پیش در گوشی است (بدون اینترنت، بدون هزینه) و شامل واژه‌های رایج روزمره است؛ متن strings.xml و چیدمان و کد خوانده و سپس ترجمه می‌شود. نتیجه در پوشهٔ values-زبان/strings.xml نوشته می‌شود (اگر پروژه strings.xml داشته باشد) و گزارش ترجمه-زبان.txt در پوشهٔ پروژه. واژه‌هایی که هنوز در فرهنگ لغت نیستند، همان‌طور که هستند باقی می‌مانند و گزارش می‌شوند — پس می‌دانید کدام واژه‌ها را هنوز باید خودتان ترجمه کنید.

بازی‌ساز بدون کد
برای ساخت بازی بدون نوشتن کد: بازی‌ساز را در منوی اصلی باز کنید، نوع بازی را انتخاب کنید (حدس عدد، آزمون یا گرفتن ستاره)، نام بازی و تعداد (مرحله/سؤال/ستاره) و پیام پیروزی را پر کنید، سپس ساخت بازی را فشار دهید. بازی به‌صورت یک پروژهٔ واقعی ساخته می‌شود که می‌توان آن را مستقیم در مدیریت پروژه‌ها اجرا کرد و مانند هر پروژهٔ دیگری به APK ساخت.

آزمایش خودکار برنامه
برای بررسی پروژه پیش از ساخت: در مدیریت پروژه‌ها، نام پروژه را طولانی فشار دهید، سپس آزمون خودکار را انتخاب کنید. IDE ده چیز را بدون ساخت APK بررسی می‌کند — وجود فایل‌های اجباری (فایل دادهٔ پروژه، مانیفست، فایل اصلی، چیدمان، رشته‌ها)، نام بسته و نسخه، مجوزهای استفاده‌شده، آیکون و تعادل پرانتزهای کد. نتیجه برای هر مورد نمایش داده می‌شود (قبول/رد با پیام) و Jieshuo آن را با صدای بلند می‌خواند. نخست هر چیزی را که رد شده است اصلاح کنید، سپس ساخت پروژه را فشار دهید.

AI بررسی‌کننده کد
برای بررسی کد پروژه از نظر الگوهایی که اغلب مشکل‌ساز می‌شوند: بررسی کد را در منوی اصلی باز کنید، پروژه را انتخاب کنید، سپس بررسی کد را فشار دهید. بررسی‌کننده درون گوشی کار می‌کند (بدون اینترنت) و به دنبال متغیرهای استفاده‌نشده، توابع خالی، حلقه‌های بی‌پایان آشکار، متن نوشته‌شده مستقیم در کد (بهتر است در strings.xml)، مجوزها و APIهای خطرناک، نشانگرهای TODO/FIXME و اجرای پویا می‌گردد. هر یافته شامل نام فایل، شمارهٔ خط و پیشنهاد اصلاح است. این بررسی‌کننده مبتنی بر الگوست، نه هوش مصنوعی واقعی — مشکلاتی که از الگو پیروی نمی‌کنند، هنوز می‌توانند عبور کنند.

حالت یادگیری تعاملی
برای یادگیری ساخت برنامه گام‌به‌گام: یادگیری را در منوی اصلی باز کنید. ۵ درس وجود دارد: ساخت نخستین پروژه، افزودن دکمه، تغییر رنگ، افزودن صدا و ساخت APK. روی یک درس ضربه بزنید تا توضیح و تکلیف عملی آن را بخوانید، تکلیف را انجام دهید، سپس بررسی تکلیف را فشار دهید — IDE واقعاً بررسی می‌کند که آیا تکلیف انجام شده است (با اسکن پروژه و APK در گوشی شما). درس‌های قبول‌شده کامل علامت‌گذاری و ذخیره می‌شوند.

همگام‌سازی ابری
برای پشتیبان‌گیری از پروژه در ابر: همگام‌سازی ابری را در منوی اصلی باز کنید. پشتیبان محلی ZIP پروژه را با مهر زمانی در پوشهٔ Download/cloud ذخیره می‌کند و می‌توان آن را هر وقت از فهرست پشتیبان‌ها بازیابی کرد. پشتیبان GitHub ZIP پروژه را به مخزن خصوصی شما بارگذاری می‌کند (با استفاده از توکن تنظیمات GitHub) و می‌توان دوباره آن را دانلود کرد. این پشتیبان‌گیری و بازیابی دستی است — همگام‌سازی خودکار کامل دوطرفه به سرور نیاز دارد، پس هنوز در دسترس نیست.

سازنده خودکار بک‌اند
برای ساخت بک‌اند بدون نوشتن کد سرور: سازنده بک‌اند را در منوی اصلی باز کنید، نوع بک‌اند را انتخاب کنید (یادداشت، فهرست کارها یا تابلوی پیام)، نام پروژه را پر کنید، سپس ساخت Backend را فشار دهید. IDE یک پروژهٔ HTML واقعی با صفحهٔ فرم و فهرست داده‌های ذخیره‌شده در حافظهٔ محلی گوشی (localStorage) می‌سازد — داده‌ها ذخیره می‌شوند و هنگام اجرای برنامه دوباره خوانده می‌شوند. این بک‌اند روی یک گوشی کار می‌کند؛ دو گوشی هنوز نمی‌توانند داده‌های یکسان را به اشتراک بگذارند چون سرور اینترنتی وجود ندارد.

طراح خودکار تم
برای دادن تم رنگی به پروژه: طراح تم را در منوی اصلی باز کنید، پروژه و تم را انتخاب کنید (روشن، تیره، آبی، سبز، قرمز یا بنفش). پیش‌نمایش شش رنگ تم را نشان می‌دهد (اصلی، اصلی تیره، تأکید، پس‌زمینه، متن، متن ثانویه) و Jieshuo آن را با صدای بلند می‌خواند. اعمال تم را فشار دهید — IDE فایل‌های colors.xml و styles.xml (سبک app_theme) را در پروژه می‌نویسد که مستقیم هنگام اجرا یا ساخت پروژه استفاده می‌شوند.

سازنده انیمیشن
برای دادن انیمیشن به پروژه: سازنده انیمیشن را در منوی اصلی باز کنید، پروژه، نوع انیمیشن (محو، لغزش، چرخش، جهش یا تپش)، مدت (۱۰۰ تا ۱۰۰۰۰ میلی‌ثانیه) و هدف (دکمه، متن یا تصویر) را انتخاب کنید، سپس ساخت انیمیشن را فشار دهید. IDE یک فایل انیمیشن واقعی می‌نویسد (res/anim/anim_<نوع>.xml برای پروژه‌های Java/Kotlin/Compose یا animasi.css برای پروژه‌های HTML/وب‌سایت) همراه با نمونه کد استفاده که روی صفحه نمایش داده می‌شود.

ضبط‌کننده اقدامات
برای تکرار خودکار کار: IDE اقدام‌های انجام‌شده را ضبط می‌کند (باز کردن پروژه، اجرا، ساخت، خروجی، پشتیبان، ساخت پروژه، ذخیرهٔ فایل). ضبط‌کننده اقدامات را در منوی اصلی باز کنید تا فهرست اقدام‌های ضبط‌شده با برنامه‌شان را ببینید، سپس بازپخش را فشار دهید — IDE اقدام‌هایی را که می‌توان خودکار کرد دوباره اجرا می‌کند (پشتیبان و ساخت پروژه در محل اجرا می‌شوند؛ اجرا، ساخت و خروجی صفحهٔ اصلی‌شان را باز می‌کنند؛ باز کردن و ذخیره ویرایشگر را باز می‌کنند). اقدام‌هایی که نمی‌توان خودکار کرد، رد شده و در پایان گزارش می‌شوند.

امنیت خودکار
برای بررسی امنیت پروژه: امنیت خودکار را در منوی اصلی باز کنید، پروژه را انتخاب کنید، سپس بررسی امنیت را فشار دهید. IDE هشت چیز را به‌صورت محلی بررسی می‌کند (بدون اینترنت): مجوزهای خطرناک (مکان، پیامک، تماس، دوربین، میکروفون، مخاطبین)، ارسال داده از طریق HTTP، ارسال پیامک، تماس‌های خروجی، گذرواژه یا کلید نوشته‌شده مستقیم در کد، WebView بدون محافظت، مؤلفهٔ صادرشده بدون مجوز و نشانی http بدون رمزگذاری. هر یافته سطح امن، هشدار یا خطر با پیشنهاد اصلاح می‌گیرد و خلاصه با صدای بلند توسط Jieshuo خوانده می‌شود.

AI آفلاین
برای استفاده از ابزارهای کمکی متن و کد بدون اینترنت: AI آفلاین را در منوی اصلی باز کنید. ۴ ابزار وجود دارد: اصلاح متن (حروف بزرگ، نشانه‌گذاری و فاصله‌های دوتایی)، خلاصهٔ متن (۳ جملهٔ مهم‌تر را می‌گیرد)، ساخت نام برنامه (از توصیف نوشته‌شده) و پیشنهاد نام متغیر (نام‌های متغیر ۱ تا ۲ حرفی را در پروژه جستجو می‌کند). این‌ها قواعد ساده درون گوشی‌اند، نه مدل واقعی هوش مصنوعی. نتیجهٔ اصلاح متن را می‌توان با دکمهٔ اعمال روی strings.xml پروژه اعمال کرد.

سازنده ویجت و تصویر پس زمینه
برای ساخت ویجت صفحهٔ اصلی: ویجت‌ها و تصاویر پس‌زمینه را در منوی اصلی باز کنید، پروژه را انتخاب کنید، متن ویجت را پر کنید، سپس ساخت ویجت را فشار دهید. IDE فایل WidgetSaya.java، چیدمان ویجت، اطلاعات ویجت را می‌نویسد و یک گیرنده به AndroidManifest.xml پروژه اضافه می‌کند — پروژه را بسازید، سپس ویجت را از صفحهٔ اصلی گوشی نصب کنید. برای تصویر پس‌زمینه: نوشته و رنگ‌های پس‌زمینه و متن را پر کنید، پیش‌نمایش بسازید، سپس آن را به‌صورت PNG در پوشهٔ Download ذخیره کنید یا مستقیم به‌عنوان تصویر پس‌زمینهٔ گوشی تنظیم کنید.

ادغام رسانه‌های اجتماعی
برای افزودن دکمه‌های اشتراک‌گذاری به برنامه: رسانه‌های اجتماعی را در منوی اصلی باز کنید، پروژه را انتخاب کنید، سپس اشتراک‌گذاری به WhatsApp یا Facebook یا Telegram (یا هر سه با هم) را اضافه کنید. IDE کد واقعی اشتراک‌گذاری را در فایل اصلی پروژه (MainActivity یا index.html) می‌نویسد. دکمهٔ آزمایش اشتراک‌گذاری انتخاب‌گر اشتراک‌گذاری را از IDE با متن نمونه باز می‌کند تا جریان را پیش از ساخت برنامه حس کنید.

برنامه از روی تصویر
برای ساخت برنامهٔ گالری از روی تصویر: برنامه از روی تصویر را در منوی اصلی باز کنید، تصویری را از گالری انتخاب کنید. IDE اندازهٔ تصویر و رنگ غالب را تحلیل می‌کند، سپس یک پروژهٔ واقعی برنامهٔ گالری می‌سازد: تصویر در assets پروژه کپی می‌شود، رنگ تم از رنگ غالب تصویر گرفته می‌شود و نام برنامه از نام فایل تصویر گرفته می‌شود. مدیریت پروژه‌ها را باز کنید تا آن برنامهٔ گالری را اجرا یا بسازید.

ترمینال تعاملی (تجزیه‌گر VT)
برای استفاده از برنامه‌های تعاملی در ترمینال: ترمینال را در منوی اصلی باز کنید، سپس nano یا vim یا top یا htop را اجرا کنید. ترمینال اکنون از تجزیه‌گر VT استفاده می‌کند (صفحهٔ شبکه‌ای ۲۴ سطر در ۸۰ ستون) تا آن برنامه‌ها درست نمایش داده شوند — مکان‌نما حرکت می‌کند، خط‌ها پاک می‌شوند و صفحه مانند ترمینال واقعی عوض می‌شود. دکمه‌های ویژهٔ Tab و پیکان بالا و پیکان پایین و Esc برای کنترل برنامه‌های تعاملی وجود دارد. خروجی همچنان متنی است که Jieshuo می‌تواند بخواند؛ خواندن صفحه را فشار دهید تا آخرین خط را بشنوید.

Terminal Exec (باینری برنامه)
برای اجرای فایل باینری در پوشهٔ برنامه (مثلاً aapt2 یا ECJ یا D8) از ترمینال: دستور را مثل همیشه تایپ کنید. IDE از libkautsarexec.so استفاده می‌کند تا فایل‌های باینری در پوشهٔ برنامه در Android 10 و بالاتر اجرا شوند. آزمون Exec را در ترمینال فشار دهید تا بررسی کنید آیا مسیر exec باینری در این گوشی کار می‌کند — نتیجه همان‌طور که هست نمایش داده می‌شود. اگر exec توسط سیستم مسدود شود، دستورهای سیستم و اسکریپت‌های shell همچنان کار می‌کنند؛ باینری را از طریق منوی ساخت پروژه اجرا کنید.

ترمینال همیشه فعال (KeepAlive)
برای اینکه shell هنگام رفتن به صفحهٔ دیگر همچنان در حال اجرا بماند: ترمینال را باز کنید، دستوری اجرا کنید، سپس بازگشت را فشار دهید یا به صفحهٔ دیگر بروید — shell نمی‌میرد و اعلان ترمینال همچنان دیده می‌شود تا بتوانید با یک ضربه برگردید. دستورهای اجراشده در سابقه ذخیره می‌شوند (دکمهٔ سابقه یا پیکان‌های بالا/پایین در فیلد دستور) و دستورهای پرکاربرد را می‌توان به‌عنوان دلخواه ذخیره کرد (دکمهٔ موارد دلخواه). بستن shell را وقتی تمام شد فشار دهید تا shell واقعاً کشته شود. دکمهٔ ساخت در ترمینال هم در منوی پروژه و هم در منوی ویرایشگر وجود دارد: ترمینال در پوشهٔ پروژه با دستور ساخت از پیش پرشده باز می‌شود.

نصب ابزارهای ترمینال (آزمایشی)
قابلیتی که هنوز در آزمایش است: در ترمینال دکمهٔ نصب ابزارهای ترمینال برای نصب محیط Termux از آینه در مخزن alat-termux توسعه‌دهنده (github.com/syudat/alat-termux) وجود دارد، به‌عنوان مسیری دیگر علاوه بر دکمهٔ نصب Termux که از نسخهٔ رسمی Termux می‌گیرد. محتوای آینه دقیقاً همان نسخهٔ رسمی است و هنگام نصب با SHA-256 بررسی می‌شود. پس از نصب محیط، دستورهای pkg update و pkg install قابل استفاده‌اند و ابزارهای اضافی از مخزن نیز در ترمینال نصب می‌شوند: info-terminal برای دیدن اطلاعات محیط، bersih-terminal برای پاک کردن کش و cadangkan-proyek برای بایگانی پوشهٔ پروژه در یک فایل tar.gz تاریخ‌دار. پس از آن برنامه به‌صورت خودکار بسته‌های پایهٔ لینوکس (git و python و curl و wget و nano و openssh و zip و unzip) و ابزارهای ساخت APK با امضا (openjdk-21 و kotlin و gradle و ecj و aapt2 و d8 و apksigner و clang و cmake و ninja و make) را از مخزن رسمی Termux نصب می‌کند، پس ترمینال فوراً آمادهٔ ساخت برنامه است. دانلود بسته‌های بزرگ (صدها مگابایت) ممکن است طول بکشد. در حین نصب، پیشرفت و خروجی دستورها در صفحهٔ اصلی ترمینال نمایش داده می‌شود و نتیجهٔ نهایی با صدای بلند توسط صفحه‌خوان خوانده می‌شود. اگر نصب بسته‌ها هنوز کامل نشده است، نصب ابزارهای ترمینال را دوباره فشار دهید تا ادامه یابد.

حالت صوتی کامل
برای کنترل کامل IDE با صدا: حالت صوتی را در منوی اصلی باز کنید، سپس شروع گوش دادن را فشار دهید. IDE پیوسته گوش می‌دهد — نیازی نیست برای هر دستور دکمه‌ای فشار دهید — دستور را اجرا می‌کند و با صدا پاسخ می‌دهد. ۲۶ دستور وجود دارد: ساخت، ساخت، باز کردن، اجرا، فهرست، جستجو، حذف، آزمون، بررسی، خروجی، پشتیبان، اشتراک‌گذاری، ساخت آیکون، ترجمه، ساخت در ترمینال، خواندن صفحه، باز کردن همهٔ صفحه‌ها (شامل امنیت، AI آفلاین، ویجت، رسانه‌های اجتماعی، بازی، یادگیری، ابر، بک‌اند، تم، انیمیشن، ضبط‌کننده)، بازگشت، بستن و کمک. اگر حالت فعال باقی بماند، گوش دادن به‌صورت خودکار هنگام باز شدن دوبارهٔ این صفحه ادامه می‌یابد. توقف گوش دادن را فشار دهید تا این حالت خاموش شود. اگر گوشی سرویس تشخیص صدا ندارد، دستورها همچنان در کادر متن قابل نوشتن‌اند.

مترجم کد
برای ترجمهٔ کد میان زبان‌ها بدون اینترنت: مترجم کد را در منوی اصلی باز کنید، پروژه را انتخاب کنید، فایل منبع (.java/.kt) را انتخاب کنید، سپس جهت را انتخاب کنید: Java به Kotlin. ترجمه را فشار دهید — نتیجه همراه با گزارش خط‌هایی که نمی‌توان ترجمه کرد نمایش داده می‌شود (آن خط‌ها همان‌طور که هستند نگه داشته و علامت‌گذاری می‌شوند). ذخیره نتیجه را فشار دهید تا یک فایل جدید (نام-ترجمه.java/.kt) در همان پوشه نوشته شود؛ فایل اصلی هرگز بازنویسی نمی‌شود. این مترجم قاعدهٔ الگوست، نه کامپایلر — همیشه نتیجه را پیش از استفاده بررسی کنید.

Git درون برنامه
برای استفاده از Git درون IDE بدون Termux: Git درون برنامه را در منوی اصلی باز کنید، پروژه را انتخاب کنید، سپس ساخت Repo Git را فشار دهید تا یک مخزن محلی (.git) در آن پروژه بسازید. بررسی وضعیت را فشار دهید تا فایل‌های جدید، تغییرکرده یا حذف‌شده نسبت به آخرین commit را ببینید؛ پیام commit را پر کنید، سپس Commit را فشار دهید تا یک عکس فوری از پروژه ذخیره شود؛ مشاهده Log Commit را فشار دهید تا سابقهٔ commit را ببینید. Push به GitHub و Pull از GitHub از عکس‌های فوری از طریق توکن GitHub استفاده می‌کنند (مخزن pembuat-aplikasi-build) — نه پروتکل git. Clone و Push (git سیستم) و Pull (git سیستم) فقط زمانی کار می‌کنند که فایل باینری git روی گوشی نصب باشد (معمولاً نیست). این git کامل نیست: merge و branch و diff ندارد — هر commit یک عکس فوری ZIP کامل از پروژه ذخیره می‌کند.

سازنده تبلیغات
برای افزودن تبلیغات به برنامهٔ ساخته‌شده: سازنده تبلیغات را در منوی اصلی باز کنید، پروژه، ارائه‌دهنده (AdMob یا Unity Ads یا AppLovin) و نوع تبلیغ (بنر، بینابینی یا پاداش‌دار) را انتخاب کنید. شناسهٔ واحد تبلیغ را اگر دارید پر کنید — خالی یعنی استفاده از شناسهٔ آزمایشی (AdMob از شناسهٔ آزمایشی رسمی Google استفاده می‌کند؛ Unity از شناسهٔ بازی نمونه استفاده می‌کند؛ AppLovin از جای خالی استفاده می‌کند). ساخت کد تبلیغ را فشار دهید تا کد Java و Kotlin و راهنما را ببینید؛ ذخیره در پروژه را فشار دهید تا همه‌چیز در فایل تبلیغ-<ارائه‌دهنده>-<نوع>.txt در پروژه نوشته شود. این قالب کد + راهنماست، نه SDK تبلیغات — SDK در IDE گنجانده نشده است؛ تبلیغات واقعی فقط پس از ساخت حساب ارائه‌دهنده، ساخت واحد تبلیغ، چسباندن شناسهٔ واحد خودتان و افزودن وابستگی SDK در build.gradle پروژه نمایش داده می‌شوند.

حالت کودک
برای استفاده از IDE همراه با کودک: حالت کودک را در منوی اصلی باز کنید. صفحه ساده‌شده با دکمه‌های بزرگ و فقط ۴ اقدام امن است: ایجاد پروژه (از قالب‌های امن: ماشین‌حساب، حدس عدد، آزمون، گرفتن ستاره)، باز کردن پروژه، اجرا و یادگیری. هیچ دکمهٔ حذف، خروجی، پشتیبان یا تنظیمات توکن در این صفحه نیست. هنگام ورود نخست، یک PIN چهاررقمی بسازید — آن PIN توسط والد برای خروج از حالت کودک استفاده می‌شود (دکمهٔ خروج از حالت کودک یا دکمهٔ بازگشت). این PIN محافظ سبکی برای کودکان کوچک است، نه امنیت واقعی.

برنامه‌ساز Wear OS و TV
برای ساخت برنامهٔ ساعت (Wear OS) یا تلویزیون (Android TV): Wear OS & TV را در منوی اصلی باز کنید، هدف را انتخاب کنید (Wear OS یا Android TV یا هر دو). نام پروژه را پر کنید، سپس ساخت پروژه جدید Wear/TV را فشار دهید — IDE یک پروژهٔ Java می‌سازد و سپس آن را تنظیم می‌کند — یا پروژه‌ای که از پیش وجود دارد را انتخاب کنید، سپس اعمال روی این پروژه را فشار دهید. تنظیم‌ها: uses-feature در مانیفست، دستهٔ LEANBACK_LAUNCHER + بنر برای تلویزیون و چیدمان activity_main.xml تنظیم‌شده (Wear: صفحهٔ کوچک؛ TV: صفحهٔ بزرگ مناسب D-pad). توضیح کامل در wear-tv.txt در پروژه نوشته می‌شود. این قالب پروژه است — ساخت + آزمون هنوز به دستگاه/شبیه‌ساز Wear OS یا Android TV نیاز دارد؛ بنر تلویزیون (banner.png 320x180) به‌صورت خودکار ساخته نمی‌شود، باید خودتان اضافه کنید (مثلاً از طریق سازندهٔ آیکون).

نقشه پروژه
برای دیدن ساختار پروژه: نقشه پروژه را در منوی اصلی باز کنید، پروژه را انتخاب کنید، سپس نمایش نقشه را فشار دهید — IDE فهرست پوشه‌ها و فایل‌ها را با اندازه‌هایشان، اندازهٔ کل، اندازه بر حسب نوع فایل و فایل‌های مهم (فایل اصلی، مانیفست، چیدمان، رشته‌ها، آیکون، صفحهٔ وب) نمایش می‌دهد. ذخیره نقشه-پروژه.txt را فشار دهید تا همان نقشه در ریشهٔ پروژه نوشته شود. پوشهٔ bin/ (نتایج ساخت) و پوشهٔ .git/ (مخزن محلی) نقشه‌برداری نمی‌شوند چون محتوایشان را می‌توان دوباره ساخت.

محاسبه‌گر اندازه APK
برای برآورد اندازهٔ APK ساخته‌شده پیش از ساخت: محاسبه‌گر اندازه APK را در منوی اصلی باز کنید، پروژه را انتخاب کنید، سپس محاسبه برآورد را فشار دهید. IDE جزئیات را بر حسب دسته نشان می‌دهد (کد/DEX، منابع، دارایی‌ها، کتابخانه‌های بومی، مانیفست + resources.arsc، سربار)، برآورد کل، ۵ فایل بزرگ‌تر و پیشنهادهای کوچک‌سازی (مثلاً تصاویر بزرگ در وضوح کوچک می‌شوند، صداهای بزرگ در مدت کوتاه می‌شوند). این برآورد است، نه اندازهٔ دقیق — اندازهٔ واقعی می‌تواند به دلیل فشرده‌سازی aapt2 و حذف کد استفاده‌نشده (R8) و منابع ساخته‌شده متفاوت باشد.

تحلیل‌گر APK
برای خواندن محتوای APK تمام‌شده (مانند تحلیل‌گر APK در Android Studio): تحلیل‌گر APK را در منوی اصلی باز کنید، پروژه را انتخاب کنید، سپس تحلیل APK حاصل ساخت را فشار دهید. IDE جدیدترین APK را در پوشهٔ bin آن پروژه می‌خواند و نام بسته، نسخه، SDK حداقل و هدف، فهرست مجوزهای استفاده‌شده، تعداد فایل‌های dex، جزئیات اندازه بر حسب بخش (کد برنامه، منابع، دارایی‌ها، کتابخانه‌های بومی، امضا) و ۱۰ ورودی بزرگ‌تر را گزارش می‌کند. مفید است تا بدانید کدام بخش APK را بزرگ می‌کند و برنامهٔ ساخته‌شده از چه مجوزهایی استفاده می‌کند.

پیش‌نمایش اندازه صفحه
برای بررسی ظاهر پروژه در اندازه‌های صفحهٔ زیاد به‌صورت هم‌زمان (مانند Android Studio): پیش‌نمایش اندازه صفحه را در منوی اصلی باز کنید، پروژه را انتخاب کنید، سپس بررسی اندازه صفحه را فشار دهید. IDE همهٔ چیدمان‌های پروژه را می‌خواند و عناصری را گزارش می‌کند که عرضشان ثابت نوشته شده است (مثلاً 400dp) و از عرض صفحهٔ ۳۲۰ یا ۳۶۰ یا ۴۱۱ یا ۴۸۰ dp بیشتر است، چون در گوشی با صفحهٔ کوچک چنین عنصری می‌تواند پوشیده یا سرریز شود. عناصر با عرض match_parent یا wrap_content به‌صورت خودکار با صفحه سازگار می‌شوند و نیازی به بررسی ندارند.

مدیر منابع
برای دیدن و مدیریت همهٔ منابع پروژه در یک جا (مانند مدیر منابع در Android Studio): مدیر منابع را در منوی اصلی باز کنید، پروژه را انتخاب کنید، سپس مشاهده منابع را فشار دهید. IDE تعداد و اندازهٔ فایل‌ها را بر حسب دسته گزارش می‌کند (drawable و layout و values و mipmap و غیره)، محتوای strings.xml و colors.xml و styles.xml. از همان صفحه می‌توان رشتهٔ جدیدی به strings.xml و رنگ جدیدی به colors.xml با پر کردن نام و مقدارشان اضافه کرد — نام بررسی می‌شود و موارد تکراری رد می‌شوند، پس فایل XML خراب نمی‌شود.

ناظر عملکرد سبک
برای پایش استفاده از RAM و پردازندهٔ برنامهٔ در حال اجرا (مانند Profiler در Android Studio، نسخهٔ سبک): ناظر عملکرد سبک را در منوی اصلی باز کنید، نخست برنامه‌ای را که می‌خواهید بررسی کنید اجرا کنید (مثلاً برنامهٔ ساخته‌شده‌ای که در حال آزمایش است)، نام بستهٔ آن را پر کنید — یا پروژه را انتخاب کنید، سپس پر کردن نام بسته از پروژه را فشار دهید — سپس شروع نظارت را فشار دهید. هر ۲ ثانیه IDE رم (PSS) و CPU آن برنامه را همراه با رم آزاد گوشی ثبت می‌کند؛ توقف را فشار دهید تا خلاصهٔ میانگین و اوج را ببینید. بدون مجوز اضافی. در نسخه‌های جدیدتر Android، دسترسی خواندن پردازندهٔ برنامهٔ دیگر توسط سیستم محدود شده است، پس اگر CPU خوانده نشود، گزارش همان‌طور که هست می‌گوید و رم همچنان پایش می‌شود.

ممیزی دسترس‌پذیری
برای بررسی اینکه آیا چیدمان پروژه پیش از انتشار برای صفحه‌خوان (TalkBack/Jieshuo) مناسب است: در منوی اصلی ممیزی دسترس‌پذیری را باز کنید، پروژه‌ای را انتخاب کنید، سپس روی بارگذاری فهرست چیدمان بزنید و یک پرونده چیدمان انتخاب کنید. IDE آن پرونده XML را می‌خواند و دکمه‌های بدون برچسب را با شماره خط‌هایشان، برچسب‌های تکراری، و عناصری که همدیگر را می‌پوشانند گزارش می‌دهد، سپس رونوشت ترتیب تمرکز را می‌سازد، همان‌گونه که Jieshuo با صدای بلند می‌خواند. اگر دکمه‌ای برچسب ندارد، برچسب آن را پر کنید سپس روی درج خودکار برچسب بزنید — برچسب به‌عنوان contentDescription در پرونده چیدمان نوشته می‌شود. این بررسی فقط XML چیدمان را می‌خواند؛ نماهای Compose و APKهای آماده هنوز پویش نمی‌شوند.

کالبدشکافی خرابی
برای فهمیدن این‌که چرا برنامه خودش بسته می‌شود، از گزارش خرابی با شناسه یکتا: «کالبدشکافی خرابی» را در منوی اصلی باز کنید، شناسه خرابی را از فهرست گزارش‌ها انتخاب کنید، سپس روی «بررسی» بزنید. IDE کلاس و شماره خط در گزارش را با منبع پروژه تطبیق می‌دهد و علت را به اندونزیایی توضیح می‌دهد (مثلاً مرجع خالی، مجوز هنوز درخواست‌نشده، یا خطای JSON)، همراه با پیشنهاد وصله کد. فقط وقتی روی «اعمال وصله» بزنید که خط منبع هنوز دقیقاً همان باشد که هنگام خرابی بود؛ اگر تغییر کرده باشد، وصله رد می‌شود و IDE از شما می‌خواهد خودتان بررسی کنید. برای خرابی‌های برنامه ساخته‌شده، روی «تزریق گیرنده خرابی به پروژه» بزنید، سپس APK را مثل همیشه بسازید: آن برنامه ساخته‌شده خرابی‌های خودش را می‌گیرد و گزارشش را روی گوشی می‌نویسد، و آن گزارش را می‌توان با دکمه «یافتن گزارش خرابی برنامه ساخته‌شده» پیدا کرد. حد صادقانه: کپی گزارش به پوشه عمومی Download در اندروید ۱۱ و بالاتر می‌تواند بدون مجوز دسترسی به همه فایل‌ها ناموفق باشد.

مبدل بین‌پارادایمی
برای تبدیل کد ساده Java به Kotlin، یا چیدمان ساده XML به کد Compose: در منوی اصلی مبدل بین‌پارادایمی را باز کنید، پروژه و پرونده‌ای را انتخاب کنید، سپس روی پیش‌نمایش بزنید. IDE نتیجه تبدیل را به‌صورت متن نشان می‌دهد — اول بررسی کنید، چون خط‌هایی که نمی‌شناسد همان‌طور باقی می‌مانند و واژه static در Java در Kotlin حذف می‌شود (پیش از استفاده معنای آن را بررسی کنید). تبدیل XML به Compose فقط متن، راهنما و جهت را تغییر می‌دهد — اندازه، رنگ و ویژگی‌های دیگر هنوز شامل نیستند. اگر نتیجه درست است، روی اعمال به پرونده بزنید تا پرونده مقصد نوشته شود؛ پرونده منبع تغییر نمی‌کند. فقط الگوهای رایج و امن تبدیل می‌شوند.

سرور ریز محلی
برای آزمون برنامه‌ای که به سرور نیاز دارد بدون اینترنت: «سرور ریز محلی» را در منوی اصلی باز کنید، تعریف‌های مسیر را بنویسید (مثلاً GET /halo سپس پاسخ JSON آن)، سپس روی «آغاز سرور» بزنید. IDE سرور HTTP کوچکی روی همان گوشی اجرا می‌کند (فقط HTTP، بدون TLS، برای همان شبکه Wi-Fi) و هر درخواست و پاسخ را روی صفحه ثبت می‌کند. مسیرها می‌توانند از پارامترهایی مثل {nama} و کلید API ساده استفاده کنند. سرور را می‌توان در APK ساخته‌شده هم بسته‌بندی کرد: روی «بسته‌بندی سرور در پروژه» بزنید، و منبع سرور، دارایی‌ها و مانیفست به پروژه تزریق می‌شوند، پس خود برنامه ساخته‌شده هنگام اجرا سرور می‌شود. سرور در IDE هنگام بسته شدن صفحه‌اش متوقف می‌شود.

ممیزی امنیتی
برای بررسی کد پروژه از نظر شکاف‌های امنیتی پیش از انتشار: «ممیزی امنیت» را در منوی اصلی باز کنید، پروژه را انتخاب کنید، سپس روی «آغاز پویش» بزنید. IDE کد پروژه، مانیفست و پیکربندی را پویش می‌کند و یافته‌ها را از خطر بالا تا پایین گزارش می‌دهد — کلید API که در کد باز مانده، مؤلفه‌ای که بدون مجوز نمایان شده، WebView که JavaScript را همراه با واسط JavaScript آن فعال می‌کند، رمزنگاری ضعیف (MD5 و SHA1 و DES)، نشانی http بدون TLS، و گذرواژه‌ای که مستقیماً در کد نوشته شده — همراه با فایل‌ها و شماره خط‌هایشان. برای یافته‌هایی که اصلاحشان امن است (مثلاً MD5 را به SHA-256 یا http را به https تغییر دهید)، روی «اعمال اصلاح» بزنید؛ برای کلیدهای API و گذرواژه‌ها، IDE فقط پیشنهاد اصلاح را نشان می‌دهد چون جایگزین باید خود توسعه‌دهنده تصمیم بگیرد. پویش اکنون بایت‌کد واقعی DEX را درون APK ساخته‌شده هم تجزیه می‌کند (نه فقط الگوهای متن در کد)، پس APIهای خطرناک فراخوانده‌شده و رازهای جاسازی‌شده در DEX هم شناسایی می‌شوند؛ شکاف‌هایی که از الگویی پیروی نمی‌کنند هنوز می‌توانند از پویش بگریزند — پیش از اعمال بررسی کنید.

ربات آزمونگر رابط کاربری
برای آزمون خودکار صفحه برنامه از طریق سناریوهای متنی: «ربات آزمونگر رابط کاربری» را در منوی اصلی باز کنید، پروژه را انتخاب کنید، سپس روی «ساخت خودکار سناریو» بزنید. IDE مانیفست و چیدمان پروژه را می‌خواند و سناریو را به‌صورت گام‌های متنی می‌نویسد (روی دکمه بزن، فیلد را پر کن، صبر کن، برگرد). روی «اجرای آزمایشی» بزنید تا گزارش اجرای سناریو را همراه با مهرهای زمانی‌اش ببینید — این اجرای آزمایشی هنوز فقط شبیه‌سازی توالی است. برای آزمون واقعی، روی «تزریق عامل آزمون به پروژه» بزنید: IDE عامل آزمون را همراه با دارایی‌های سناریو به پروژه تزریق می‌کند؛ APK را مثل همیشه بسازید، نصب کنید، سپس نماد «آزمون» را باز کنید — آن عامل درون برنامه ساخته‌شده اجرا می‌شود و واقعاً روی دکمه‌ها می‌زند، فیلدهای واقعی را پر می‌کند، و پیمایش می‌کند، سپس گزارشش را روی صفحه همراه با خرابی‌های واقعی که گرفته نشان می‌دهد. روی «حذف عامل آزمون از پروژه» بزنید تا آن عامل را دوباره حذف کنید. عامل درون فرایند خود برنامه اجرا می‌شود، پس به سرویس دسترس‌پذیری یا خودکارسازی سیستم نیاز ندارد.

سفر زمانی کد
برای بازگرداندن پروژه به حالت قبلی کد بدون تایپ دستورهای Git: در منوی اصلی سفر زمانی کد را باز کنید، پروژه‌ای را انتخاب کنید، برچسب نقطه زمانی را پر کنید (می‌تواند خالی بماند)، سپس روی ثبت نقطه زمانی بزنید. IDE رونوشتی از پرونده‌های منبع پروژه را همراه با hashهایشان در پوشه .riwayat درون پروژه ذخیره می‌کند. فهرست نقاط زمانی همه را نشان می‌دهد؛ دو نقطه را انتخاب کنید سپس روی مقایسه بزنید تا پرونده‌ها و تابع‌های افزوده، تغییرکرده یا حذف‌شده را ببینید. روی بازیابی بزنید تا حالت قدیمی برگردد — پیش از بازیابی، IDE همیشه اول از حالت کنونی پشتیبان می‌گیرد، پس چیزی از دست نمی‌رود. روی ساخت رونوشت آزمایشی بزنید تا پروژه را در پوشه‌ای تازه رونوشت کنید و تغییرها را بدون دست‌کاری پروژه اصلی بیازمایید. فقط پرونده‌های منبع ثبت می‌شوند.

کارخانه ماژول
برای بسته‌بندی بخشی از پروژه به‌عنوان ماژولی که پروژه دیگری بتواند استفاده کند: در منوی اصلی کارخانه ماژول را باز کنید، پروژه منبع را انتخاب کنید، پرونده‌های صفحه، کلاس، رشته و مجوز را که می‌خواهید بسته‌بندی شوند علامت بزنید، سپس روی بسته‌بندی به‌عنوان ماژول بزنید. IDE بایگانی ZIP را همراه با فراداده JSON (نام ماژول، نسخه، رشته‌ها و مجوزهای استفاده‌شده) می‌نویسد. برای نصب ماژول در پروژه دیگر، کارخانه ماژول را باز کنید، پروژه مقصد را انتخاب کنید، سپس روی نصب ماژول بزنید و پرونده .zip ماژول را انتخاب کنید — ادغام رشته‌ها و مجوزها را بدون بازنویسی کد موجود اضافه می‌کند، و اگر نام پرونده‌ای در پروژه مقصد استفاده شده باشد آن را ادغام نمی‌کند. ماژول کتابخانه یا تنظیمات ساخت همراه ندارد.

سپر چندریخت و گاوصندوق دارایی‌ها
برای تصادفی کردن نام شناسه‌ها و رمزگذاری دارایی‌های پروژه پیش از انتشار: «سپر چندریخت و گاوصندوق دارایی‌ها» را در منوی اصلی باز کنید، پروژه را انتخاب کنید، سپس روی «تصادفی کردن نام‌ها و رمزگذاری دارایی‌ها» بزنید. IDE نام کلاس‌ها و متدها را در کد منبع پویش می‌کند، نقشه نام تصادفی می‌سازد، آن نام‌ها را درون فایل‌های DEX کامپایل‌شده بازنویسی می‌کند (نام‌های جایگزین به همان طول نام‌های اصلی ساخته می‌شوند تا همه آفست‌ها معتبر بمانند، سپس جمع کنترل و امضای SHA-1 سربرگ DEX دوباره محاسبه می‌شود)، فایل‌های دارایی پروژه را با AES-GCM در پوشه brankas-aset داخل پروژه رمزگذاری می‌کند، و نقشه بازیابی رمزگذاری‌شده (perisai-peta.brankas) را ذخیره می‌کند تا نام‌های اصلی هنگام خواندن گزارش‌های خرابی قابل بازیابی باشند. کلید رمزگذاری اکنون از گذرواژه توسعه‌دهنده با PBKDF2 و ۲۰٬۰۰۰ تکرار مشتق می‌شود، نه دیگر از نام پروژه. نام‌هایی که به‌عنوان متن ساده، نام حاشیه‌نویسی و نام اشکال‌زدایی هم استفاده می‌شوند عمداً بازنویسی نمی‌شوند، و نقاط درج بازنویسی DEX در مسیر ساخت هنوز در انتظار آزمون روی گوشی واقعی است.

زنجیره اعتماد و نگهبان محیط
برای بررسی زنجیره کلید امضا و محیط گوشی پیش از انتشار: «زنجیره اعتماد و نگهبان محیط» را در منوی اصلی باز کنید، پروژه را انتخاب کنید، سپس روی «بررسی زنجیره و محیط» بزنید. IDE زنجیره کلیدی ۵ نسلی از نام بسته پروژه می‌سازد و یکپارچگی آن را بررسی می‌کند، یکپارچگی واقعی حافظه را با مقایسه محتوای بخش‌های کد در حافظه با فایل‌های روی دیسک بررسی می‌کند و نگاشت‌های ناشناس قابل اجرا (RWX)، کتابخانه‌های بیگانه و نگاشت‌های memfd را گزارش می‌دهد، سپس نقشه حافظه فرایند خودش و ویژگی‌های دستگاه را برای ردپای Frida یا Xposed یا شبیه‌ساز پویش می‌کند. کلید گاوصندوق با کلید AES در AndroidKeyStore پیچیده می‌شود که هنگام در دسترس بودن از تراشه امنیت سخت‌افزاری استفاده می‌کند، و چرخش کلید اکنون واقعی است، با استفاده از دودمان گواهی امضای طرح v3: کلید قدیمی اثبات چرخش به کلید جدید را امضا می‌کند و APK دوباره با آن دودمان امضا می‌شود. نتیجه سطح خطر «امن»، «احتیاط» یا «خطرناک» همراه با شواهد متنی است. اگر سیستم خواندن حافظه را رد کند، بررسی به‌عنوان «قابل بررسی نیست» گزارش می‌شود، نه امن؛ و این‌که آیا کلید واقعاً از تراشه امنیت سخت‌افزاری استفاده می‌کند فقط روی دستگاه واقعی قابل تأیید است.

معمار چیدمان درخت متنی
برای طراحی صفحه بدون دیدن آن: «معمار چیدمان درخت متنی» را در منوی اصلی باز کنید، پروژه و فایل چیدمان را انتخاب کنید، سپس روی «بررسی چیدمان» بزنید. IDE چیدمان XML را به‌عنوان درخت متن می‌خواند و روایت موقعیت هر عنصر را با صدای بلند می‌خواند (مثلاً پایین راست، ۴۵ درصد عرض صفحه)، سپس هم‌پوشانی بین عناصر و عناصری را که در عرض ۳۶۰ dp از صفحه خارج می‌شوند، به‌صورت ریاضی گزارش می‌دهد. آنچه اکنون محاسبه می‌شود شامل LinearLayout و اندازه‌های ساده dp، ConstraintLayout کامل (همه قیدها، سوگیری، زنجیره‌ها، راهنماها، موانع، عرض‌های درصدی، 0dp match_constraint و نسبت‌های ابعاد) و صفحه‌های Compose (Column و Row و Box همراه با تغییر‌دهنده‌های اندازه‌شان) است. فقط MotionLayout و ConstraintSet که هنگام اجرا تغییر می‌کنند همچنان با موقعیت نامشخص گزارش می‌شوند، چون مقدارهایشان فقط هنگام اجرای برنامه وجود دارد.

استودیو سیستم طراحی
برای یکسان کردن فاصله‌ها، حروف و گوشه‌ها در همه صفحه‌ها و پروژه‌ها: «استودیو سیستم طراحی» را در منوی اصلی باز کنید، پروژه را انتخاب کنید، توکن‌های طراحی را بنویسید (مثلاً jarak=8, huruf=16, sudut=12)، جزء را انتخاب کنید، سپس روی «ساخت اجزا» بزنید. IDE توکن‌ها را اعتبارسنجی می‌کند — فاصله پایه ۴ تا ۱۶ dp، حرف پایه ۱۲ تا ۲۰ sp، گوشه ۰ تا ۳۲ dp، و ناحیه لمس حداقل ۴۸ dp — سپس اجزای XML آماده استفاده (komponen-studio.xml) را همراه با تم XML (tema-studio.xml) و تم Compose (tema-studio.kt) در پوشه پروژه می‌نویسد. توکن‌ها را می‌توان به‌عنوان مجموعه نام‌دار در کتابخانه مشترک توکن بین پروژه‌ها هم ذخیره کرد، و یک دستور همگام‌سازی توکن‌های جدید کتابخانه را روی همه پروژه‌هایی که از آن مجموعه استفاده می‌کنند اعمال می‌کند. اجزا به‌صورت متن ساخته می‌شوند که در چیدمان چسبانده و سپس با «معمار چیدمان درخت متنی» بررسی می‌شود؛ تنظیم دو ستونی در تبلت از صلاحیت عرض صفحه استفاده می‌کند، نه تشخیص دستگاه هنگام اجرا.

بازساخت معنایی و ناوبری AST
برای یافتن تعریف‌ها و تغییر نام نمادها بدون خراب کردن کد دیگری که تصادفاً همان نام را دارد: «بازساخت معنایی و ناوبری AST» را در منوی اصلی باز کنید، پروژه را انتخاب کنید، سپس روی «اسکن نمادهای پروژه» بزنید تا همه کلاس‌ها و متدها را همراه با فایل‌ها و شماره خط‌هایشان ببینید. نام نماد را وارد کنید، سپس دوباره روی «اسکن نمادهای پروژه» بزنید تا تعریف آن و همه فایل‌هایی که آن را فرا می‌خوانند ببینید. برای تغییر نام، نام جدید را وارد کنید، روی «پیش‌نمایش تغییر نام» بزنید تا تعداد رخدادها در هر فایل را ببینید، سپس روی «اعمال تغییر نام» بزنید. نمایه‌ساز اکنون از تجزیه‌کننده AST دست‌ساز (واژه‌ساز و تجزیه‌کننده بازگشتی برای Java و زیرمجموعه Kotlin) استفاده می‌کند، پس تغییر نام متد بین فایل‌ها حل می‌شود و فراخواننده‌ها در فایل‌های دیگر هم تغییر می‌کنند؛ دکمه استخراج بلوک کد به تابع جدید اکنون روی این صفحه است. این تجزیه‌کننده هنوز حداقلی است: جنریک‌های بسیار پیچیده، حاشیه‌نویسی‌های پارامتری و کلاس‌های ناشناس همان‌طور که هستند پویش می‌شوند، در حالی که فراخوانی‌ها از طریق بازتاب و از طریق واسط حل نمی‌شوند.

اشکال‌زدای گام‌به‌گام و بازرس حافظه
برای بررسی محتوای متغیرها در میانه جریان برنامه بدون حدس زدن از روی گزارش‌ها: «اشکال‌زدای گام‌به‌گام و بازرس حافظه» را در منوی اصلی باز کنید، پروژه را انتخاب کنید، رد اجرا را بنویسید (یک گام در هر خط، به شکل شماره خط، کد، سپس متغیرها و مقدارها جدا شده با |، مثلاً 10|int total = harga * jumlah;|harga=5000, jumlah=3, total=15000)، شماره خط نقطه توقف را وارد کنید، سپس روی «اجرای رد اشکال‌زدایی» بزنید. IDE تا اولین نقطه توقف پیش می‌رود و خط فعال را همراه با مقدارهای متغیرهایش از طریق Jieshuo با صدای بلند می‌خواند. روی «یک خط جلو برو» بزنید تا یک خط جلو بروید، روی «ورود به تابع» بزنید تا وارد تابع فراخوانده‌شده شوید (با پشته فراخوانی)، یا روی «ادامه برنامه» بزنید تا به نقطه توقف بعدی برسید. این اشکال‌زدای رد همچنان ردی ضبط‌شده یا دست‌نویس را دنبال می‌کند؛ در کنار آن یک مشتری جاوای خالص از پروتکل سیمی JDWP وجود دارد که می‌تواند دست بدهد، نقطه توقف بگذارد، به داخل و روی و بیرون گام بردارد، و VM را از طریق TCP یا در حالت شنیدن متوقف و از سر گیرد. توقف یک فرایند واقعی از داخل یک برنامه معمولی هنوز کاملاً ممکن نیست، چون سوکت JDWP یک فرایند فقط از طریق adbd نمایان می‌شود — مسیر اثبات‌شده به اشکال‌زدایی بی‌سیم و راه‌اندازی هدف از طریق پوسته نیاز دارد، فراتر از آنچه خود برنامه می‌تواند انجام دهد.

مدیر وابستگی آفلاین
برای استفاده از کتابخانه‌های شخص ثالث بدون اینترنت و جلوگیری از تعارض نسخه‌ها پیش از ساخت: «مدیر وابستگی آفلاین» را در منوی اصلی باز کنید، پروژه را انتخاب کنید، سپس روی «بررسی وابستگی‌ها» بزنید. IDE همه فایل‌های .gradle پروژه را می‌خواند، گاوصندوق مشترک بین پروژه‌ها در پوشه Download/brankas-bersama را بررسی می‌کند، و تعارض‌ها را حل می‌کند — اگر دو کتابخانه نسخه‌های متفاوتی از یک مصنوع بخواهند، بالاترین نسخه استفاده و تعارض گزارش می‌شود. برای دانلود کتابخانه، مختصات آن را وارد کنید (به شکل گروه:مصنوع:نسخه، مثلاً com.google.code.gson:gson:2.10.1) سپس روی «بررسی وابستگی‌ها» بزنید: هنگام آنلاین بودن، فایل‌های AAR یا JAR یا WHL واقعاً از Maven یا Google یا PyPI دانلود می‌شوند همراه با گراف وابستگی متعدی‌شان (بازگشتی، چرخه‌ها قطع می‌شوند، عمق تا ۲۵ سطح)، و فقط فایل‌هایی که با موفقیت دانلود شده‌اند به‌عنوان در دسترس ثبت می‌شوند. هنگام آفلاین بودن فقط کتابخانه‌هایی که از پیش در گاوصندوق مشترک هستند قابل استفاده‌اند. بازه‌های نسخه Maven حل نمی‌شوند، و فایل‌های دانلودشده فقط با SHA-1شان بررسی می‌شوند، بدون تأیید PGP.

بازرس پایگاه داده و ذخیره‌سازی
برای بررسی و آزمون محتوای پایگاه داده پروژه بدون نوشتن کدی که محتوای جدول‌ها را چاپ کند: «بازرس پایگاه داده و ذخیره‌سازی» را در منوی اصلی باز کنید، پروژه و فایل پایگاه داده (.db یا .sqlite یا .sqlite3) را انتخاب کنید، سپس روی «باز کردن پایگاه داده» بزنید. IDE طرح همه جدول‌های آن را با تجزیه‌کننده کامل صفحه SQLite (درخت-B همراه با صفحه‌های سرریز) می‌خواند و ۲۰ ردیف اول را به‌صورت جدول متنی نشان می‌دهد که Jieshuo با صدای بلند می‌خواند. پرس‌وجوی SELECT بنویسید سپس روی «اجرای پرس‌وجو» بزنید (مثلاً SELECT nama FROM pengguna WHERE kota = 'Makassar') — پرس‌وجوها اکنون JOIN و GROUP BY و ORDER BY و LIKE را پشتیبانی می‌کنند، و روی گوشی از طریق موتور واقعی SQLite اندروید اجرا می‌شوند. برای تغییر مقدار، شماره ردیف (۱ = ردیف اول) و نام ستون و مقدار جدید را وارد کنید، سپس روی «تغییر مقدار سلول» بزنید — آن مقدار دوباره در فایل .db نوشته می‌شود. روی «ذخیره پشتیبان» بزنید تا وضعیت کنونی جدول به‌عنوان فایل <نام-پایگاه‌داده>.cadangan.txt در پروژه ذخیره شود. SharedPreferences و DataStore هم قابل خواندن‌اند. آنچه هنوز خوانده نمی‌شود: پایگاه‌های داده رمزگذاری‌شده، تغییرات WAL تأییدنشده، و مقدارهای نوع‌دار در DataStore Proto ویژه (فقط به‌عنوان نمای کلی میدان‌ها نشان داده می‌شود).

کارخانه آزمون واحد و فازینگ
برای یافتن شکاف‌های منطقی پیش از به اشتراک گذاشتن برنامه: «کارخانه آزمون واحد و فازینگ» را در منوی اصلی باز کنید، پروژه و فایل کد را انتخاب کنید، سپس روی «ساخت و اجرای آزمون‌ها» بزنید. IDE امضاهای تابع در فایل را می‌خواند، موارد آزمون عادی و حدی می‌سازد (متن خالی، null، اعداد بیشینه، نویسه‌های عجیب)، سپس واقعاً آن آزمون‌ها را اجرا می‌کند: کد پروژه کامپایل می‌شود و هر متد @Test با حد ۵ ثانیه اجرا می‌شود، پس نتیجه قبولی‌ها و مردودی‌های واقعی همراه با مقدارهای واقعی‌شان است. فازینگ هم واقعاً روی تابع‌های پروژه اجرا می‌شود (از طریق بازتاب، ۲ ثانیه در هر فراخوانی، حداکثر ۲۰ متد)، و درصد پوشش خط واقعاً از طریق ابزارگذاری که شماره خط‌های اصلی را حفظ می‌کند محاسبه می‌شود. نتیجه گزارش می‌دهد چند آزمون قبول و چند مردود شد، چند خط کد و تابع پیدا شد، و چه موارد آزمونی ساخته شد. آزمون‌های ساخته‌شده دقیقاً همان API جی‌یونیت را استفاده می‌کنند، اما تعریف‌های حاشیه‌نویسی و گزاره درون خود فایل آزمون ساخته‌شده نوشته شده‌اند، چون کتابخانه واقعی JUnit در برنامه گنجانده نشده است.

شبیه‌ساز شرایط حدی دستگاه و حسابرس نشت حافظه
برای آزمون استقامت برنامه هنگامی که سیستم فرایند آن را می‌کشد، شبکه قطع می‌شود، صفحه می‌چرخد، یا صرفه‌جویی باتری فعال می‌شود: «شبیه‌ساز شرایط حدی دستگاه و حسابرس نشت حافظه» را در منوی اصلی باز کنید، پروژه را انتخاب کنید، سپس روی «اجرای شبیه‌سازی» بزنید. IDE سه سناریوی فشار را همراه با شبیه‌سازی چرخش صفحه اجرا می‌کند و اشیایی را که پس از بسته شدن صفحه‌شان در حافظه نگه داشته شده‌اند دنبال می‌کند، سپس داده‌های از دست رفته و زنجیره‌های نشت‌کننده شیء را گزارش می‌دهد. وضعیت ذخیره و بازیابی اکنون از منبع خود پروژه کاربر خوانده می‌شود، نه مثال ثابت؛ سرور حلقه‌برگردان محلی واقعاً در میانه آزمون متوقف می‌شود تا قطع شبکه اندازه‌گیری شود؛ heap dump واقعی گرفته و تجزیه می‌شود تا دو dump مقایسه و زنجیره نگه‌داری از ریشه‌های GC دنبال شود؛ و فرایند خود برنامه واقعاً پس از ذخیره وضعیتش کشته می‌شود، سپس بررسی می‌شود چه داده‌هایی هنگام باز کردن دوباره برمی‌گردند. آنچه هنوز از یک برنامه معمولی ممکن نیست: خاموش کردن رادیو یا Wi-Fi گوشی و توقف اجباری برنامه‌های دیگر — هر دو به مجوز سیستم نیاز دارند؛ در عوض، برنامه‌های پس‌زمینه از طریق killBackgroundProcesses کشته می‌شوند که مجوزش از پیش در مانیفست است، با برچسبی صادقانه روی صفحه.

معمار نقشه پروژه
برای تبدیل ایده بزرگ برنامه به برنامه کاری گام‌به‌گام: «معمار نقشه پروژه» را در منوی اصلی باز کنید، پروژه را انتخاب کنید، ایده برنامه را بنویسید (مثلاً برنامه صندوق برای خواربارفروشی کوچک با اقساط)، سپس روی «ساخت نقشه» بزنید. IDE ماژول‌ها، فهرست فایل‌ها و نقاط عطف کوچک می‌سازد، سپس آن‌ها را به‌عنوان cetak-biru.txt در پوشه پروژه ذخیره می‌کند. هر بار که نقطه عطفی کامل شد روی «علامت‌گذاری نقطه عطف بعدی به عنوان کامل» بزنید، یا روی «بارگذاری نقشه ذخیره‌شده» بزنید تا نقشه ذخیره‌شده را دوباره باز کنید. اگر در «تنظیمات هوش مصنوعی» ارائه‌دهنده هوش مصنوعی فعالی انتخاب شده و کلیدش در دسترس باشد، نقشه را آن ارائه‌دهنده می‌سازد؛ اگر کلیدی نباشد یا ارائه‌دهنده در دسترس نباشد، IDE به الگوهای کلیدواژه آفلاین برمی‌گردد و آن حد را صادقانه می‌گوید. پاسخ ارائه‌دهنده فقط از نظر قالب بررسی می‌شود (ماژول‌ها و نقاط عطف موجود‌اند)، نه درستی محتوایش — همیشه پیش از ساخت نقشه را بازبینی کنید.

راوی جریان منطقی کد
برای فهمیدن کد طولانی بدون گوش دادن به نحو خط به خط: «راوی جریان منطقی کد» را در منوی اصلی باز کنید، پروژه و فایل کد را انتخاب کنید، سپس روی «روایت کد» بزنید. IDE هر خط را به جمله‌ای اندونزیایی تبدیل می‌کند (مثلاً اگر مجموع بیش از ۱۰۰۰۰۰ باشد، بلوک بعدی را اجرا کن)، نقشه فراخوانی بین متدها و تحلیل جریان داده بین متدها (مقدارهای ردشده، استفاده‌شده یا نادیده‌گرفته‌شده) را نشان می‌دهد، و اشکالات ظریف احتمالی را همراه با شماره خط‌هایشان علامت می‌زند — String که با == مقایسه شده، جریانی که بدون بسته شدن باز شده، و متغیری که در دو متد متفاوت نوشته شده است. اگر در «تنظیمات هوش مصنوعی» ارائه‌دهنده هوش مصنوعی فعالی انتخاب شده باشد، خلاصه جریان از آن ارائه‌دهنده هم در دسترس است؛ اگر در دسترس نباشد، صفحه از روایت آفلاین استفاده می‌کند و آن حد را می‌گوید. روایت، نقشه فراخوانی و جریان داده از تحلیل الگوی متن آفلاین استفاده می‌کنند، نه تجزیه‌کننده کامل AST — متدهایی که آکولاد بازشان در خط جداگانه است، فیلدهای کلاس، و فراخوانی‌ها از طریق بازتاب دنبال نمی‌شوند — و هشدارهای مسابقه داده می‌تواند برای متغیری ظاهر شود که در واقع فقط نوبتی استفاده می‌شود.

کارخانه بسته برنامه و آمادگی Play Store
برای آماده کردن برنامه برای Google Play Store مستقیماً از گوشی: «کارخانه بسته برنامه و آمادگی Play Store» را در منوی اصلی باز کنید، پروژه را انتخاب کنید، سپس روی «ساخت بسته AAB» بزنید. IDE فایل .aab را از مانیفست، منابع و دارایی‌های پروژه همراه با BundleConfig.pb واقعی می‌سازد، ساختار بسته را اعتبارسنجی می‌کند، سپس بسته را به APKهای گونه واقعی (پایه، بر پایه معماری، بر پایه زبان، و جهانی) تقسیم می‌کند با اندازه‌هایی که از آن تقسیم اندازه‌گیری شده‌اند، نه تخمین زده شده‌اند. بسته با JAR v1 با همان کلید پروژه امضای APK امضا می‌شود، و زنجیره امضایش به‌صورت رمزنگاری تأیید می‌شود. این صفحه آمادگی Play را هم حسابرسی می‌کند — SDK هدف زیر ۳۵ به‌عنوان بالا علامت می‌خورد چون Play Store به ۳۵ یا بیشتر نیاز دارد، و کتابخانه ۶۴ بیتی گمشده هم به‌عنوان بالا علامت می‌خورد. bundletool واقعی نمی‌تواند روی دستگاه اجرا شود، چون bundletool به JVM نیاز دارد در حالی که اندروید JVM ندارد؛ مسیر بالا نزدیک‌ترین مسیر واقعی روی دستگاه است.

موتور به‌روزرسانی OTA و عرضه‌های مرحله‌ای
برای فرستادن اصلاحی کوچک بدون وادار کردن کاربران به دانلود دوباره کل APK: «موتور به‌روزرسانی OTA و عرضه‌های مرحله‌ای» را در منوی اصلی باز کنید، پروژه را انتخاب کنید، محتوای نسخه قدیم و جدید را بنویسید، سپس روی «ساخت بسته وصله» بزنید. IDE تفاوت را محاسبه می‌کند و بسته وصله (patch-ota.zip) را همراه با اثر انگشت SHA-256 محتوای جدید می‌سازد، سپس بررسی می‌کند آیا این دستگاه در مرحله اول عرضه ۱۰ درصدی است یا نه. وصله‌ها اکنون دلتای باینری روی هر فایلی (از جمله DEX و APK) را پشتیبانی می‌کنند، با امضای RSA-2048 بسته‌بندی و با کلید عمومی مورد اعتماد پیش از اعمال تأیید می‌شوند، و می‌توانند از سرور توسعه‌دهنده همراه با فهرست عرضه‌هایش دانلود شوند؛ اگر اعمال ناموفق باشد، فایل قدیمی دست‌نخورده می‌ماند. اعمال وصله روی برنامه در حال اجرا از طریق امضای دوباره با کلید پروژه و PackageInstaller انجام می‌شود، چون جایگزین کردن کد فرایندی در حال اجرا از درون خودش ناممکن است — APK قفل شده و DEX از پیش بارگذاری شده است.

استودیو بازبینی کد تیم
برای بازبینی تغییرهای همکار و حل تعارض‌های ادغام بدون خواندن علامت‌های پیکان Git: «استودیو بازبینی کد تیم» را در منوی اصلی باز کنید، پروژه را انتخاب کنید، سه نسخه متنی (پایه، محلی، همکار) را وارد کنید، سپس روی «باز کردن بازبینی تیم» بزنید. IDE هر سه را بر پایه واحدهای نحوی جاوا ادغام می‌کند — دو تغییر در یک خط اما در دستورهای متفاوت دیگر تعارض شمرده نمی‌شوند — و هر تعارض را به‌عنوان گزینه رأی نشان می‌دهد: استفاده از نسخه محلی، استفاده از نسخه همکار، یا ادغام هر دو — خط نتیجه در موقعیت اصلی تعارض درج می‌شود تا ترتیب درست بماند — سپس نتیجه را در gabung-hasil.txt در پروژه می‌نویسد. زیر آن تابلوی وظایف پروژه است: عنوان وظیفه را وارد کنید سپس روی «افزودن وظیفه» بزنید؛ وظیفه‌ها به‌عنوان متن در پوشه .tugas داخل پروژه ذخیره و از طریق کامیت‌ها در Git درون‌برنامه همگام می‌شوند، پس تابلو را می‌توان از هر تاریخچه کامیت دوباره خواند. این تقسیم‌کننده نحوی تجزیه‌کننده کامل AST نیست و Git درون‌برنامه برای هر کامیت یک عکس کامل ذخیره می‌کند؛ سرور همگام‌سازی ویژه‌ای وجود ندارد.

دیکته ساختار کد
برای نوشتن کد با صدا درون ویرایشگر: پروژه‌ای را در ویرایشگر باز کنید، سپس روی دکمه دیکته ساختار کد بزنید. دستورها را به زبان اندونزیایی بگویید، مثلاً buat fungsi tambah dengan parameter a angka dan b angka، buat kelas Mobil، یا buat variabel teks nama sama dengan Budi — IDE گفتار را به بلوک کد Java، Kotlin، Python یا Compose معتبر از نظر نحوی تبدیل می‌کند و در جای نشانگر می‌گذارد، سپس خلاصه‌ای کوتاه را از طریق Jieshuo با صدای بلند می‌خواند. دیکته از خدمت ورودی صدای داخلی سیستم استفاده می‌کند، بدون مجوز اضافی میکروفون، و فقط الگوهای دستور ثبت‌شده را می‌شناسد؛ گفتار خارج از آن الگوها به کد تبدیل نمی‌شود. عددهایی که با واژه گفته می‌شوند (مثلاً 'lima') هنوز به رقم تبدیل نمی‌شوند.

فضای همکاری محلی (بدون اینترنت)
برای کار مشترک در یک اتاق بدون اینترنت: در منوی اصلی همکاری را باز کنید، سپس بخش فضای همکاری محلی را باز کنید. یک گوشی جلسه‌ای باز می‌کند (IDE نشانی IP محلی و PIN شش‌رقمی را نشان می‌دهد)، گوشی دیگر با آن نشانی و PIN می‌پیوندد. تغییرهای متن به‌صورت تفاوت خط‌ها فرستاده می‌شوند، APK ساخته‌شده را می‌توان به گوشی آزمایش‌کننده فرستاد، و گزارش‌های خرابی از گوشی آزمایش‌کننده بازپس گرفته می‌شوند. یک جلسه فقط برای یک دوست است؛ اگر دو نفر دقیقاً همان خط را هم‌زمان تغییر دهند، آخرین تغییر استفاده می‌شود. PIN به‌صورت متن ساده در شبکه محلی فرستاده می‌شود. این اتاق هنوز روی گوشی واقعی آزموده نشده است.

تنظیمات هوش مصنوعی
برای تنظیم ارائه‌دهنده هوش مصنوعی و کلیدهای API برای ساخت برنامه: در منوی اصلی، در گروه تنظیمات، روی «تنظیمات هوش مصنوعی» بزنید (کنار دکمه «اتصال‌دهنده»). ارائه‌دهنده مورد استفاده را از فهرست در دسترس انتخاب کنید، و «تعویض مدل هنگام خطای ارائه‌دهنده» را علامت بزنید تا اگر یک مدل ناموفق شد، IDE خودکار مدل بعدی همان ارائه‌دهنده را امتحان کند. روی «مدیریت کلیدهای API» بزنید تا کلیدهای پشتیبان اضافه کنید (نام و کلید را وارد کنید، سپس روی «ذخیره» بزنید؛ کلیدها پوشیده نشان داده می‌شوند، فقط ۴ نویسه آخر دیده می‌شود). کلیدها روی گوشی ذخیره می‌شوند و هرگز به جایی جز ارائه‌دهنده انتخاب‌شده هنگام ساخت برنامه فرستاده نمی‌شوند. ارائه‌دهنده انتخاب‌شده اکنون واقعاً توسط «معمار نقشه پروژه» و «راوی جریان منطقی کد» استفاده می‌شود؛ ساخت برنامه در صفحه «سازنده برنامه با هوش مصنوعی» هنوز از هوش مصنوعی محلی روی گوشی استفاده می‌کند (بدون اینترنت).

اتصال‌دهنده
برای تحلیل APK و سپس فرستادن آن: در منوی اصلی، در گروه تنظیمات، روی اتصال‌دهنده بزنید (کنار دکمه تنظیمات هوش مصنوعی). پرونده APK را از گوشی انتخاب کنید، IDE محتوای آن را می‌خواند (نام بسته، نسخه، فهرست فعالیت‌ها)، سپس روی ارسال APK بزنید تا از طریق منوی اشتراک‌گذاری سیستم (مثلاً WhatsApp یا Drive) فرستاده شود.

زبان و صدا
برای تغییر زبان برنامه: تنظیمات را باز کنید، سپس زبان برنامه را باز کنید، سپس زبان یا پیروی از سیستم را انتخاب کنید. صفحه اصلی و بیشتر صفحه‌ها بی‌درنگ و بدون بستن یا راه‌اندازی دوباره برنامه به زبان انتخاب‌شده تغییر می‌کنند؛ برخی صفحه‌ها (مثلاً ترمینال، همکاری، تنظیمات هوش مصنوعی و مدیریت کلیدها) تا باز شدن دوباره هنوز از زبان قدیمی استفاده می‌کنند. اگر پیروی از سیستم را انتخاب کنید، زبان از زبان سیستم گوشی پیروی می‌کند.

امضای پیش‌فرض برای هر پروژه و ضد دست‌کاری
از نسخهٔ ۵٫۷، پروژه‌ای که از امضای شخصی استفاده نمی‌کند، با کلید داخلیِ خودِ آن پروژه امضا می‌شود (یک بار در پوشهٔ tanda-tangan-bawaan درون پروژه ساخته شده، سپس همواره استفاده می‌شود)، پس امضای داخلی از پروژه‌ای به پروژهٔ دیگر متفاوت است — دیگر یک کلید مشترک برای همهٔ برنامه‌ها نیست. پوشهٔ tanda-tangan-bawaan را حذف نکنید: بدون آن کلید، APK جدید نمی‌تواند APK قدیمی همان پروژه را جایگزین کند. تنظیمات هر پروژه (معماری جداگانه، امضای شخصی، ضد دستکاری، keystore انتخاب‌شده، SDK) اکنون در فایل settings.gradle درون پروژه ذخیره می‌شود و هر بار که پروژه ساخته می‌شود دوباره خوانده می‌شود. در تنظیمات، در دستهٔ امضا، یک چک‌باکس ضد دستکاری برنامهٔ ساخته‌شده وجود دارد: اگر فعال باشد، برنامهٔ ساخته‌شده روی دستگاه امضا و محتوای dex خود را هر بار که باز می‌شود بررسی می‌کند؛ اگر دوباره امضا شده یا توسط شخص دیگری تغییر کرده باشد، برنامه از اجرا خودداری می‌کند. ابزارهای دیباگ و تزریق مانند Frida/Xposed نیز شناسایی می‌شوند و پنجرهٔ برنامه از ضبط صفحه قفل می‌شود.

سازنده ویدیوی نمایشی
برای ساخت ویدیوی دمو از برنامهٔ ساخته‌شده: سازنده ویدیوی دمو را در منوی اصلی باز کنید، پروژه را انتخاب کنید، عنوان ویدیو را پر کنید، سپس ساخت اسکریپت ویدیوی دمو را فشار دهید — IDE فایل video-demo.txt را با ۵ صحنهٔ استاندارد (آغاز، نمای اصلی، قابلیت ۱، قابلیت ۲، پایان) همراه با متن روایت و مدت هر صحنه می‌نویسد. ساخت Slideshow HTML را فشار دهید تا video-demo.html از تصاویر پروژه (آیکون + اسکرین‌شات‌ها اگر هست) ساخته شود که هر ۵ ثانیه به‌صورت خودکار عوض می‌شوند. این ویدیوی .mp4 نیست — برای ویدیوی واقعی، video-demo.html را در مرورگر گوشی باز کنید، سپس صفحه را ضبط کنید، یا روایت را در video-demo.txt بخوانید در حالی که برنامهٔ در حال اجرا را ضبط می‌کنید.

ظاهر جدید به سبک Android Studio
ظاهر IDE اکنون مرتب شده تا شبیه Android Studio باشد (فقط ظاهر — همهٔ دکمه‌ها، منوها و جریان‌ها دقیقاً مانند قبل باقی می‌مانند): پس‌زمینهٔ خاکستری روشن، عنوان‌های صفحهٔ ضخیم و مشکی، دکمه‌های آبی با متن سفید و کادرهای ورودی سفید با قاب نازک. منوی اصلی به‌صورت بصری گروه‌بندی شده است (قابلیت‌های ساخت، ابر، تم و غیره، صدا، کد و قابلیت‌های جدید، ابزارها) بدون تغییر ترتیب دکمه‌ها. ترمینال همچنان از پنل تیره مانند پنجرهٔ ترمینال در Android Studio استفاده می‌کند و ویرایشگر کد همچنان پس‌زمینهٔ سفید با متن مشکی دارد. همهٔ متن‌ها همچنان به‌وضوح توسط Jieshuo خوانده می‌شوند.

تنظیمات
برای تنظیم برنامه: منوی گزینه‌ها را در صفحهٔ اصلی باز کنید، سپس تنظیمات را فشار دهید. درون آن ۱۲ دسته وجود دارد: تنظیمات GitHub (امنیت، امضای شخصی، سابقهٔ ساخت و توکن GitHub)، تنظیمات ساخت APK روی دستگاه (ذخیرهٔ گذرواژهٔ keystore و سابقهٔ ساخت روی دستگاه)، تم (رنگ‌های برنامه)، امضا (ساخت keystore برای امضای شخصی و چک‌باکس ضد دستکاری برنامهٔ ساخته‌شده)، پوشهٔ پروژه (موقعیت پوشهٔ پروژه)، زبان و صدا (زبان رابط و سرعت صدای حالت صوتی)، اندازهٔ متن و ظاهر (اندازهٔ قلم ویرایشگر)، ساخت (SDK هدف پیش‌فرض و تقسیم معماری پیش‌فرض برای صفحهٔ ایجاد پروژه)، اعلان‌ها (صدا هنگام پایان ساخت)، پشتیبان خودکار (زمان‌بندی پشتیبان پروژه)، پروفایل توسعه‌دهنده (نام، شمارهٔ WhatsApp و حساب نمایش‌داده‌شده در صفحهٔ اهدا) و حریم خصوصی و داده (بازنشانی تنظیمات و حذف داده‌های برنامه). هر دسته دکمهٔ بازگشت به صفحهٔ قبل برای بازگشت به منوی دسته‌ها دارد. تنظیماتی که تازه ذخیره شده‌اند (هنوز اعمال نشده‌اند) توضیحشان صادقانه روی صفحه نوشته شده است.

اهدا به توسعه‌دهنده
برای اهدا یا سلام به توسعه‌دهنده: دکمهٔ اهدا به توسعه‌دهنده را در صفحهٔ اصلی، کنار دکمهٔ دربارهٔ ابزار فشار دهید. در صفحهٔ اهدا دکمهٔ کپی حساب BRI وجود دارد — آن را فشار دهید تا شماره حساب توسعه‌دهنده کپی شود، سپس آن را در برنامهٔ بانکی خود بچسبانید. بخش سلام به توسعه‌دهنده در WhatsApp نیز وجود دارد: نام و شهر زادگاه خود را پر کنید، سپس ارسال در WhatsApp را فشار دهید — WhatsApp با پیام سلام از پیش پرشده باز می‌شود، فقط ارسال را در WhatsApp فشار دهید و سپس به برنامه برگردید. WhatsApp به برنامه‌های دیگر اجازهٔ ارسال خودکار پیام نمی‌دهد، پس ارسال همچنان توسط خودتان در WhatsApp انجام می‌شود.

دستورهای دلخواه ترمینال
برای ذخیرهٔ دستورهایی که اغلب در ترمینال استفاده می‌شوند: ترمینال را باز کنید، سپس موارد دلخواه را فشار دهید. افزودن مورد علاقه جدید را لمس کنید، نام (مثلاً مشاهده فایل) و دستور آن (مثلاً ls -la) را پر کنید، سپس ذخیره را فشار دهید — مورد علاقه برای همیشه روی گوشی ذخیره می‌شود. نام مورد علاقه را لمس کنید تا مستقیم در ترمینال اجرا شود؛ حذف مورد علاقه را لمس کنید، سپس یکی را برای حذف انتخاب کنید (با تأیید). از پیش ۳ مورد علاقهٔ داخلی وجود دارد: مشاهده فایل (ls -la)، بررسی فضا (df -h) و پاک کردن صفحه (clear) — همه را می‌توان حذف کرد. دستور خالی را نمی‌توان ذخیره یا اجرا کرد؛ ترمینال از طریق پیام و صدا به شما می‌گوید اگر چنین شود.

تحلیل و کیفیت
برای دیدن خلاصهٔ استفاده از برنامه و گزارش‌های خرابی: دکمهٔ تحلیل و کیفیت را در صفحهٔ اصلی، کنار دکمهٔ اهدا به توسعه‌دهنده فشار دهید. این صفحه نشان می‌دهد برنامه چند بار باز شده است، کدام صفحه‌ها بیشتر باز شده‌اند، تعداد خرابی‌ها و فهرست آخرین خرابی‌ها با پیشنهاد اصلاح کوتاه. این داده‌ها فقط روی گوشی شما ذخیره می‌شوند و به هیچ جا فرستاده نمی‌شوند. دکمهٔ حذف داده‌های تحلیلی با گفتگوی تأیید برای حذف همهٔ آن داده‌ها وجود دارد. آخرین صفحه فقط برای صفحهٔ اصلی و این صفحه ثبت می‌شود.

پایان
از استفاده از Create Aplikasi سپاسگزاریم. امیدواریم این ابزار به شما و هر کسی که می‌خواهد ساخت برنامه‌های Android را از روی گوشی یاد بگیرد، کمک کند. اگر مشکلی پیش آمد، آن را گام‌به‌گام با این راهنما اصلاح کنید و در تلاش دوباره تردید نکنید.
