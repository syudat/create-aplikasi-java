Maligayang pagdating sa Create Aplikasi by Al Kautsar
Ang Create Aplikasi ay isang app na gumagawa ng mga Android app na direktang tumatakbo sa telepono, nang hindi nangangailangan ng laptop. Pinapayagan ng app na ito ang sinuman na gumawa ng sarili nilang Android app, kabilang ang mga user na nagsisimula pa lang matutong gumawa ng mga app at ang mga user ng screen reader. Ang kumpletong gabay sa paggamit ng app na ito ay available sa screen na Tentang Alat na ito.

Ano ang app na ito at para kanino ito
Ang Create Aplikasi ay isang kasangkapan sa paggawa ng mga Android app na tumatakbo sa telepono. Ang app na ito ay para sa sinumang gustong gumawa ng sarili nilang Android app, kabilang ang mga baguhan at mga user ng screen reader. Nagbibigay ang app na ito ng code editor, ng button na Jalankan para subukan ang proyekto, ng button na Bangun para gumawa ng APK, at ng mga menu para lagdaan at i-install ang APK.

Ang layunin ng app na ito
Ginawa ang app na ito para madaling makagawa ang sinuman ng sarili nilang Android app, direkta mula sa telepono. Ginawang pinakasimple ang hitsura nito para kahit ang mga bagong user ay makasubok agad.

Paano gumawa ng bagong proyekto, hakbang-hakbang
1. Pindutin ang Buat Project sa pangunahing menu.
2. Piliin ang uri ng proyekto: HTML, Situs Web, Java, Kotlin, Compose, o Python.
3. Ilagay ang pangalan ng app, halimbawa: Garuda Decode.
4. Ilagay ang pangalan ng package (package name), halimbawa: com.android.garudadecode. Ang pangalan ng package ay dapat gumamit ng maliliit na titik at binubuo ng hindi bababa sa dalawang bahagi na pinaghihiwalay ng tuldok.
5. Ilagay ang bersyon ng app, halimbawa: 1.0, at ang code ng bersyon sa anyong numero, halimbawa: 1. Kung iiwang blangko, awtomatikong pupunan ang bersyon ng 1.0 at ang code ng bersyon ng 1.
6. Ilagay ang minimum na SDK at target na SDK kung kailangan. Kung iiwang blangko, ang mga default na value ang gagamitin. Ang minimum na SDK ay ang pinakamababang bersyon ng Android na sinusuportahan, halimbawa: ang 21 ay nangangahulugang Android 5.0. Ang maximum na target na SDK ay 36 (Android 16).
7. Pindutin ang button na Pilih Izin para pumili ng mga pahintulot ng app, halimbawa: INTERNET. Ang pahintulot na INTERNET ay nakamarka na bilang default. Markahan lamang ang mga pahintulot na talagang kailangan ng app.
8. Kung nais, markahan ang "Gunakan arsitektur terpisah 64 bit dan 32 bit" para mas maliit ang sukat ng APK, at markahan ang "Gunakan tanda tangan pribadi" kung gustong gumamit ng sariling gawang keystore.
9. Pindutin ang Buat Proyek. Ang bagong proyekto ay mase-save sa folder na Download/project at agad na makikita sa Kelola Project.

Mga uring proyekto na available
• HTML: hitsura mula sa index.html, style.css, at script.js, tumatakbo sa pamamagitan ng WebView. Direktang ginagawa sa telepono.
• Situs Web: website na may menu (Beranda, Tentang, Kontak) mula sa index.html, tentang.html, kontak.html, style.css, at script.js, tumatakbo sa pamamagitan ng WebView. Direktang ginagawa sa telepono.
• Java: ginagawa sa telepono. Ang MainActivity ay nasa app/src/main/java/<nama-paket>/MainActivity.java. Ang hitsura ay mula sa app/src/main/res/layout/activity_main.xml, ang teksto ay mula sa app/src/main/res/values/strings.xml, at ang tema ay mula sa app/src/main/res/values/styles.xml.
• Kotlin: maaaring gawin sa device (offline) gamit ang Kotlin compiler na kasama sa app, o sa pamamagitan ng GitHub Actions. Ang MainActivity ay nasa app/src/main/java/<nama-paket>/MainActivity.kt, at ang mga res file ay katulad ng sa proyektong Java. Ang unang pagbuo sa Kotlin ay mas mabagal dahil sa malaking sukat ng compiler, at ang mga .java file na tumutukoy sa mga Kotlin class ay hindi pa maaaring buuin (ang mga .java file ay kina-compile muna bago ang mga .kt file).
• Compose: modernong Android app na ang interface ay ginawa gamit ang Jetpack Compose (hindi XML layout). Ang MainActivity ay nasa app/src/main/java/<nama-paket>/MainActivity.kt. Ang mga proyektong Compose ay binubuo sa pamamagitan ng GitHub Actions (menu na Bangun proyek, pagkatapos Bangun online) o sa Termux gamit ang Gradle, dahil kailangan ng Compose ang mga Jetpack Compose library na hindi available sa device.
• Python: ang logic ng app ay isinusulat sa wikang Python (Chaquopy) sa app/src/main/python/main.py, at pinatatakbo ng host na MainActivity.java sa app/src/main/java/<nama-paket>/MainActivity.java. Ang mga proyektong Python ay maaaring direktang buuin sa telepono (ang Chaquopy runtime ay kasama sa app) o sa pamamagitan ng GitHub Actions. Ang minimum na SDK ng mga proyektong Python ay 24 (Android 7.0).

Ayos ng mga file ng proyektong Java, HTML, Situs Web, Kotlin, Compose, at Python
Ang mga proyektong Java, HTML, Situs Web, Kotlin, Compose, at Python ay nakaayos tulad ng mga Android project sa pangkalahatan. Sa loob ng folder na app ay may folder na src, at sa loob nito ay may folder na main. Sa loob ng folder na main ay may AndroidManifest.xml sa tabi ng folder na java, folder na res na naglalaman ng layout/activity_main.xml at values/strings.xml at values/styles.xml, at para sa HTML at Situs Web ay may folder na assets na naglalaman ng index.html (ang Situs Web ay mayroon ding tentang.html at kontak.html). Ang mga proyektong HTML at Situs Web ay mayroon ding sariling MainActivity sa app/src/main/java/<nama-paket>/MainActivity.java, na naglo-load ng index.html sa WebView at nagsisilbing launcher sa AndroidManifest. Ang mga proyektong Python ay may Python code sa app/src/main/python/main.py at host na MainActivity.java sa app/src/main/java/<nama-paket>/MainActivity.java. Ang AndroidManifest.xml, layout, strings, at styles ay maaaring buksan at baguhin sa editor, tulad ng MainActivity. Ang mga lumang proyekto na ang manifest ay nasa tabi pa rin ng folder na app ay maaari pa ring buuin, dahil kapag nagbubuo, sinusuri muna ng app ang AndroidManifest.xml sa app/src/main/, pagkatapos ang nasa tabi ng folder na app, at panghuli ang project data file.

Mga patakaran sa pahintulot (mahalaga)
Ang mga pahintulot na minarkahan kapag gumagawa ng proyekto ay naitatala lamang sa isang lugar, ayon sa uri ng proyekto. Para sa mga proyektong Java, HTML, Situs Web, Kotlin, Compose, at Python, ang mga minarkahang pahintulot ay naitatala LAMANG sa AndroidManifest.xml na nasa app/src/main/, sa tabi ng folder na java, sa loob ng folder ng proyekto. Ang project data file para sa mga proyektong Java, HTML, Situs Web, Kotlin, Compose, at Python ay walang listahan ng mga pahintulot. Kung pipiliin mo ang Java at mamarkahan ang INTERNET at CAMERA, ang maitatala sa AndroidManifest.xml ay INTERNET at CAMERA lamang, nang walang ibang pahintulot na kasama. Kapag nagbubuo, binabasa ng app ang mga pahintulot mula sa iisang lugar: mula sa AndroidManifest.xml sa app/src/main/ para sa mga proyektong Java, HTML, Situs Web, Kotlin, Compose, at Python (kung wala, mula sa AndroidManifest.xml sa tabi ng folder na app para sa mga lumang proyekto), at mula sa project data file para sa mga lumang proyekto.

Paano gamitin ang editor
Buksan ang Kelola Project, i-tap ang pangalan ng proyekto para buksan ang editor. Sa editor, maaaring buksan ang mga file, maaaring isulat ang code, at maaaring i-save ang mga pagbabago. Para sa mga proyektong Java, HTML, Situs Web, Kotlin, Compose, at Python, ang mga file ay nakaayos sa loob ng folder na app/src/main. Para magbahagi ng proyekto, gamitin ang Ekspor ZIP (tingnan ang seksyon sa ibaba).

Paano patakbuhin ang proyekto
Sa editor, pindutin ang Jalankan para subukan ang proyekto. Para sa mga proyektong HTML at Situs Web, ang pinatatakbo ay ang index.html sa pamamagitan ng WebView. Kung may maganap na error, basahin ang mensahe ng error, ayusin ang code, pagkatapos ay patakbuhin ulit.

Paano buuin ang APK
Sa editor, pindutin ang Bangun. May dalawang paraan ng pagbuo. Una, Bangun di perangkat: direktang pagbuo sa telepono nang walang internet, para sa mga proyektong HTML, Situs Web, Java, Kotlin, at Python. Pangalawa, Bangun online sa pamamagitan ng GitHub Actions: pagbuo sa pamamagitan ng internet sa GitHub, at maaaring gamitin para sa lahat ng uri ng proyekto. Ang mga proyektong Compose ay maaari lamang buuin sa pangalawang paraan (Bangun online) o sa Termux gamit ang Gradle, dahil kailangan ng Compose ang mga Jetpack Compose library na hindi available sa device. Ang resulta ng unang pagbuo ay hindi pa nalalagdaan. Pagkatapos noon ay lalagdaan ito ng app: awtomatiko gamit ang default na key, o gamit ang personal na lagda kung ang kahon na "Gunakan tanda tangan pribadi" ay minarkahan kapag gumagawa ng proyekto.

Paano i-install ang APK
Kung handa na ang APK, pindutin ang Pasang para i-install ito. Sa Android 8 pataas, hihingin muna ng telepono ang "Izinkan dari sumber ini", dahil nag-i-install ang app na ito ng mga APK mula sa labas ng Play Store. I-activate ang pahintulot na iyon nang isang beses sa Pengaturan, pagkatapos ay bumalik sa app: awtomatikong magpapatuloy ang pag-install nang hindi na kailangang pindutin ulit ang Pasang. Kung hindi lumabas ang button na Pasang, tiyaking tapos na ang pagbuo at nagawa na ang APK.

Paano lagdaan ang app
Bawat APK ay dapat lagdaan para ma-install. May dalawang pagpipilian. Una, ang default na key: awtomatikong lumalagda ang app nang mag-isa, nang hindi mo na kailangang gumawa ng anuman. Pangalawa, ang personal na lagda: gumawa muna ng keystore sa pamamagitan ng menu na Buat Keystore sa pangunahing menu, itago nang maayos ang password nito, pagkatapos ay markahan ang "Gunakan tanda tangan pribadi" kapag gumagawa ng proyekto. Ang keystore ay nase-save sa Download/project/signing.

I-export ang proyekto bilang ZIP
Ang Ekspor ZIP ay ibinibigay para maibahagi ang mga proyekto sa mga kaibigan. Ang paraan: sa Kelola Project, pindutin nang matagal ang pangalan ng proyekto, pagkatapos ay piliin ang Ekspor ZIP. Ang resulta ay mase-save sa Download/project/<NamaProyek>.zip. Ang folder na bin ay hindi kasama, kaya maliit ang sukat, ilang sampung KB lamang. Ang ZIP file na iyon ay maaaring ipadala sa kaibigan o i-upload sa GitHub.

Extension na JAWS
Ang extension na JAWS ay gumagamit ng extension engine ng Jieshuo (CSR), hindi ng screen reader nito. Dahil dito, ang disenyo ay maaari pa ring tumakbo kahit TalkBack ang gamit ng user. Ang paraan: buksan ang Ekstensi JAWS sa pangunahing menu. Dahil ang awtomatikong pag-click ay tumatakbo nang mag-isa, dapat munang i-activate ang serbisyo sa Pengaturan Aksesibilitas. Pagkatapos noon, maaaring gumawa ng bagong disenyo: i-type ang pangalan ng disenyo, pindutin ang OK, pagkatapos ay punan ang mga kahon nito.

Ang Daftar Klik ay pinaghiwalay para maayos
Sa loob ng disenyo ay may dalawang kahon: ang kahon ng script at ang kahon ng Daftar Klik. Ang listahan ng mga button ay hiwalay na nase-save sa file na daftar_klik.txt, isang pangalan bawat linya. Halimbawa ng laman nito: tombolSimpan, tombolHapus, tombolBuka. Para magbukas ng app, isulat lamang ang >WhatsApp sa listahang iyon. Ang mga lumang disenyo na wala pang file na daftar_klik.txt ay magpapakita ng default na halimbawang iyon.

Mga simpleng function na ibinibigay
• klikTombol("tombolSimpan") — nagki-click ng isang button batay sa teksto nito.
• klikDaftarTombol(daftar) — nagki-click ng listahan sa daftar_klik.txt, isang button bawat linya, nang sunod-sunod, pagkatapos ay sinasabi kung ilan ang nagtagumpay at ilan ang hindi natagpuan.
• bukaAplikasi("WhatsApp") — nagbubukas ng app batay sa pangalan nito, o isulat ang ">WhatsApp" sa listahan.
• klik(540, 1200) — nagki-click sa mga coordinate ng screen.
Ang lahat ng function ay ginawang simple muna. Kung nasanay na, maaaring magdagdag ng karagdagang mga function sa bandang huli.

Tungkol sa screen reader
Ang app na ito ay dinisenyo para maging magiliw sa screen reader. Bawat field ng paglalagay ay may label at halimbawa ng pagpuno, at lahat ng button ay maaabot nang walang kumplikadong mga gesture. Ang extension na JAWS ay ginawa para tumakbo pa rin kahit TalkBack ang gamit ng user, dahil ang ginagamit ay ang extension engine nito, hindi ang screen reader nito.

Privacy at seguridad
Ang mga proyekto at keystore ay nase-save sa iyong telepono. Ang GitHub token ay ginagamit lamang para sa mga online na pagbuo at nase-save sa loob ng app na ito. Huwag ibahagi ang iyong token o password ng keystore kaninuman. Kung gagamit ng personal na lagda, itago ang keystore at ang password nito sa ligtas na lugar, dahil kung mawala ang mga ito, ang lumang APK ay hindi na maa-update gamit ang parehong lagda.

Mga pangangailangan
Android 5.0 o mas bago. Pahintulot sa storage: sa Android 11 pataas ay gumagamit ng pahintulot sa pag-access ng lahat ng file, sa Android 10 pababa ay gumagamit ng karaniwang pahintulot sa storage (basahin/isulat ang storage) dahil ang Android 10 ay walang pahintulot sa pag-access ng lahat ng file. Ang pagbuo sa device ay nangangailangan ng teleponong may ARM processor (32 o 64 bit). Ang pagbuo online sa pamamagitan ng GitHub Actions ay nangangailangan ng internet at GitHub token. Ang mga proyektong Kotlin ay maaaring buuin sa device, ngunit ang unang pagbuo nito ay mas mabagal at gumagamit ng mas maraming memory dahil sa malaking sukat ng Kotlin compiler. Ang mga proyektong Compose ay binubuo sa pamamagitan ng GitHub Actions o sa Termux gamit ang Gradle. Ang mga proyektong Python ay nangangailangan ng Android 7.0 o mas bago (minimum na SDK 24) at ang resultang APK ay mas malaki dahil kasama nito ang Python runtime (Chaquopy) at ang standard library nito.

Terminal
Ang menu na Terminal sa pangunahing screen ay nagbubukas ng terminal sa loob ng app na ito. Ang mga command tulad ng ls ay maaaring gamitin para tingnan ang laman ng folder ng proyekto, cd para lumipat ng folder, at git para pamahalaan ang code. Ang output ng command ay lumalabas bilang tekstong mababasa ng screen reader, at may button na Bacakan hasil para pakinggan ang huling resulta. Ang terminal na ito ay gumagamit ng system shell ng telepono, kaya ang mga interactive na programa tulad ng nano at vim ay hindi pa maaaring gamitin dito.

Lisensya (bayad na bersyon)
Para magbenta ng mga app, markahan ang "Aktifkan Lisensi" kapag gumagawa ng proyekto, pagkatapos ay ilagay ang iyong numero ng WhatsApp. Ang app na resulta ng pagbuo ay hihingi ng code ng lisensya kapag unang binuksan: makikita ng user ang ID ng kanyang device, pipindutin ang button na Kirim ID Perangkat para ipadala ang ID na iyon sa iyong WhatsApp, pagkatapos ay sasagot ka gamit ang code ng lisensya. Ang code ng lisensya ay kinukuwenta mula sa ID ng device at sa password ng proyekto (lisensi_seed sa project data file) — itago nang maayos ang password na iyon at huwag ibahagi. Pagkatapos mailagay ang tamang code, bubukas ang app at hindi na hihingi ng code ulit.

Pembuat Ikon Otomatis
Ang mga icon ng bagong proyekto ay transparent pa rin, kaya available ang Pembuat Ikon sa pangunahing menu. Ang paraan: pindutin ang Pembuat Ikon, magsulat ng isa o dalawang titik (halimbawa, ang mga inisyal ng pangalan ng app), piliin ang kulay ng background at kulay ng teksto, tingnan ang preview nito, pagkatapos ay pindutin ang Simpan ke Proyek para gamitin ang icon na iyon sa napiling proyekto, o ang Simpan ke Download para gamitin ang PNG file nito sa ibang lugar. Pagkatapos magawa ang proyekto, nag-aalok din ang app na gumawa ng icon. Ang mga lumang icon ng proyekto ay maaaring palitan anumang oras mula sa menu ng proyekto sa Kelola Project (pindutin nang matagal ang pangalan ng proyekto, pagkatapos ay piliin ang Ganti Ikon).

Mga Template ng Proyekto na Handa Nang Gamitin
Kung ayaw mong magsimula sa blangkong proyekto, pumili ng template kapag gumagawa ng proyekto: Kalkulator (Java), Catatan (Java), Daftar Tugas (Kotlin), Kalkulator Web (HTML), Situs Profil (Situs Web), o Penghitung (Compose). Ang pagpili ng template ay awtomatikong binabago ang uri ng proyekto para sumunod sa template na iyon, at ang proyekto ay ginagawa nang may handa nang panimulang code — patatakbuhin o babaguhin na lamang ito. Kung babaguhin ulit nang mano-mano ang uri ng proyekto pagkatapos pumili ng template, makakansela ang template at babalik sa blangko ang proyekto. Para sa mga template na HTML at Situs Web, pinapalitan ng template ang laman ng index.html, kabilang ang HTML script na itinype sa form.

Backup at Pag-restore ng Proyekto
Para hindi mawala ang mga proyekto, may feature na backup. Ang paraan: sa Kelola Project, pindutin nang matagal ang pangalan ng proyekto, pagkatapos ay piliin ang Cadangkan. Ang backup ay mase-save bilang ZIP sa folder na Download/backup na may pangalan ng proyekto at petsa, halimbawa: GarudaDecode-2026-11-14-123045.zip. Ang laman nito ay katulad ng Ekspor ZIP (ang buong laman ng proyekto, nang walang folder na bin). Para mag-restore: buksan ang menu sa Kelola Project, piliin ang Pulihkan cadangan, pagkatapos ay piliin ang backup file nito. Kung mayroon nang pangalan ng proyekto, magtatanong ang app: Timpa proyek lama, o i-save gamit ang Nama baru.

Pagbahagi at Pag-import ng Proyekto
Para magbahagi ng proyekto sa kaibigan: sa Kelola Project, pindutin nang matagal ang pangalan ng proyekto, pagkatapos ay piliin ang Bagikan. Ang proyekto ay ipinapadala bilang ZIP sa pamamagitan ng mga app sa pagbahagi (WhatsApp, Telegram, at iba pa). Para tumanggap ng proyekto mula sa kaibigan: buksan ang menu sa Kelola Project, piliin ang Impor proyek, pagkatapos ay piliin ang ZIP file nito. Ang ZIP file na iyon ay dapat maglaman ng project data file — kung wala, ang file ay tatanggihan nang may malinaw na mensahe, dahil ang file na iyon ay hindi proyekto ng Create Aplikasi. Kung mayroon nang pangalan ng proyekto, magtatanong ang app: Timpa proyek lama, o i-save gamit ang Nama baru.

Paghahanap at Filter ng Proyekto
Kung marami na ang mga proyekto, sa Kelola Project ay may kahon ng paghahanap at filter ng uri. I-type ang pangalan ng proyekto sa kahon ng paghahanap, agad na mafi-filter ang listahan (ang malalaki at maliliit na titik ay hindi pinag-iiba). Ang filter ng uri ay nililimitahan ang listahan sa iisang uri lamang: Semua, HTML, Situs Web, Java, Kotlin, Compose, o Python. Ang menu ng bawat proyekto ay maaari pa ring buksan tulad ng dati mula sa na-filter nang listahan.

Bumuo ng App gamit ang Boses
Kung ayaw mong mag-type, gamitin ang boses: pindutin ang Mag-build Gamit ang Boses sa main menu, pagkatapos ay magsalita ng utos. Mga utos na maaari mong sabihin: "Buat proyek kalkulator", "Bangun proyek Kalkulator", "Buka proyek Kalkulator", "Jalankan proyek Kalkulator", "Daftar proyek", "Buka ikon", "Kembali", at "Bantuan". Sumasagot ang app gamit ang boses at teksto, kaya magagamit pa rin ito nang hindi tumitingin sa screen. Ang pagkilala sa boses ay gumagamit ng built-in na voice recognition app ng telepono (libre; maaari itong gumana offline kung naka-install ang Indonesian language pack). Kung walang voice recognition ang telepono, maaaring i-type ang mga utos sa text box sa parehong screen.

Accessibility Audit
Para malaman kung ang layout ng proyekto ay friendly sa screen reader (TalkBack/Jieshuo) bago i-release: buksan ang Accessibility Audit sa main menu, pumili ng proyekto, pagkatapos ay pindutin ang I-load ang Listahan ng Layout at pumili ng layout file. Binabasa ng IDE ang XML file na iyon at nag-uulat ng mga button na walang label kasama ang kanilang line number, mga label na paulit-ulit na ginamit, at mga element na magkakapatong, pagkatapos ay gumagawa ng transcript ng focus order tulad ng binabasa ni Jieshuo. Kung may button na walang label, punan ang label nito pagkatapos ay pindutin ang Maglagay ng Label nang Awtomatiko — isinusulat ang label sa layout file bilang contentDescription. Ang pagsusuring ito ay nagbabasa lamang ng layout XML; ang mga Compose view at tapos na APK ay hindi pa ini-scan.

Autopsy ng Crash
Para malaman kung bakit nagsasara nang mag-isa ang isang app mula sa crash log na may natatanging ID: buksan ang Autopsy ng Crash sa main menu, pumili ng crash ID mula sa listahan ng log, pagkatapos ay pindutin ang Suriin. Itinutugma ng IDE ang class at line number sa log sa pinagmulan ng proyekto at ipinapaliwanag ang dahilan sa Indonesian (halimbawa walang laman na reference, pahintulot na hindi pa hinihingi, o JSON error), kasama ang mungkahing patch sa code. Pindutin lamang ang Ilapat ang Patch kung ang linya ng pinagmulan ay pareho pa ring eksakto tulad noong nangyari ang crash; kung nagbago na ito, tinatanggihan ang patch at hinihiling ng IDE na suriin mo ito nang mag-isa. Ang binabasa ay ang sariling crash log ng IDE, hindi ang log ng isang built na app.

Transpiler na Cross-Paradigm
Para i-convert ang simpleng Java code sa Kotlin, o ang simpleng XML layout sa Compose code: buksan ang Transpiler na Cross-Paradigm sa main menu, pumili ng proyekto at file, pagkatapos ay pindutin ang Preview. Ipinapakita ng IDE ang resulta ng conversion bilang teksto — suriin mo muna ito, dahil ang mga linyang hindi nito nakikilala ay iniiwan kung ano sila at ang salitang static sa Java ay tinatanggal sa Kotlin (suriin ang kahulugan nito bago gamitin). Ang conversion ng XML sa Compose ay binabago lamang ang teksto, hint, at oryentasyon — ang laki, kulay, at iba pang attribute ay hindi pa kasama. Kung tama na ang resulta, pindutin ang Ilapat sa File para isulat ang target file; hindi binabago ang source file. Tanging mga ligtas at karaniwang pattern lamang ang kino-convert.

Lokal na Micro Server
Para subukan ang isang app na nangangailangan ng server nang walang internet: buksan ang Lokal na Micro Server sa main menu, sumulat ng depinisyon ng ruta (halimbawa GET /halo na sinusundan ng JSON answer nito), pagkatapos ay pindutin ang Simulan ang Server. Nagpapatakbo ang IDE ng maliit na HTTP server sa parehong telepono (HTTP lamang, walang TLS, para sa parehong Wi-Fi network) at itinatala ang bawat request at sagot sa screen. Maaaring gumamit ang mga ruta ng mga parameter tulad ng {nama} at isang simpleng API key. Ang server na ito ay para lamang sa pagsubok sa telepono; ang isang built na APK ay hindi pa maaaring maging server, at humihinto ang server kapag isinara ang screen nito.

Security Auditor
Para suriin ang mga butas sa seguridad sa code ng proyekto bago i-release: buksan ang Security Auditor sa main menu, pumili ng proyekto, pagkatapos ay pindutin ang Simulan ang Pag-scan. Ini-scan ng IDE ang code, manifest, at configuration ng proyekto at nag-uulat ng mga natuklasan mula sa pinakamataas hanggang sa pinakamababang panganib — mga API key na nakalantad sa code, mga component na nakalantad nang walang pahintulot, isang WebView na nagpapagana ng JavaScript kasama ang isang JavaScript interface, mahinang crypto (MD5, SHA1, DES), mga http address na walang TLS, at mga password na direktang isinulat sa code — kasama ang file at line number ng bawat isa. Para sa mga natuklasan na may ligtas na ayos (halimbawa palitan ang MD5 ng SHA-256 o ang http ng https), pindutin ang Ilapat ang Pag-aayos; para sa mga API key at password, ipinapakita lamang ng IDE ang mungkahing ayos dahil ang kapalit ay kailangang pagpasyahan mismo ng developer. Ang pag-scan na ito ay nagbabasa ng mga pattern ng teksto sa code, hindi bytecode, kaya maaaring may mga natuklasan na sa totoo ay ligtas, at ang isang butas na walang pattern ay maaaring makalusot sa pag-scan — suriin bago ilapat.

Robot na Tagasubok ng Interface
Para awtomatikong subukan ang itsura ng isang app gamit ang mga text scenario: buksan ang Robot na Tagasubok ng Interface sa main menu, pumili ng proyekto, pagkatapos ay pindutin ang Gumawa ng Awtomatikong Scenario. Binabasa ng IDE ang manifest at mga layout ng proyekto at sumusulat ng scenario na binubuo ng mga hakbang na teksto (pindutin ang button, punan ang field, maghintay, bumalik). Pindutin ang Patakbuhin ang Dry Run para makita ang log ng pagtakbo ng scenario kasama ang mga timestamp nito. Sa yugtong ito, ang robot ay nagpapatakbo lamang ng simulation (dry run) — ang tunay na pagpindot sa mga button sa telepono at paghuli ng tunay na crash ay susunod na yugto, kaya ang ulat ng crash dito ay sample format pa rin.

Paglalakbay sa Oras ng Code
Para ibalik ang isang proyekto sa dating kalagayan ng code nang hindi nagta-type ng mga utos ng Git: buksan ang Paglalakbay sa Oras ng Code sa main menu, pumili ng proyekto, punan ang label para sa time point (maaaring walang laman), pagkatapos ay pindutin ang Itala ang Time Point. Nagse-save ang IDE ng kopya ng mga source file ng proyekto kasama ang kanilang mga hash sa .riwayat folder sa loob ng proyekto. Ipinapakita ng listahan ng mga time point ang lahat ng ito; pumili ng dalawang punto pagkatapos ay pindutin ang Ihambing para makita ang mga file at function na idinagdag, binago, o tinanggal. Pindutin ang I-restore para maibalik ang lumang kalagayan — bago mag-restore, palaging gumagawa muna ang IDE ng backup ng kasalukuyang kalagayan, kaya walang nawawala. Pindutin ang Gumawa ng Kopya ng Eksperimento para kopyahin ang proyekto sa isang bagong folder at subukan ang mga pagbabago nang hindi ginugulo ang orihinal na proyekto. Ang mga source file lamang ang nire-record.

Pabrika ng Module
Para i-package ang bahagi ng isang proyekto bilang module na magagamit ng ibang proyekto: buksan ang Pabrika ng Module sa main menu, pumili ng source project, lagyan ng tsek ang mga screen, class, string, at permission file na ipa-package, pagkatapos ay pindutin ang I-package bilang Module. Sumusulat ang IDE ng ZIP archive kasama ang JSON metadata (pangalan ng module, bersyon, mga string na ginamit, at mga pahintulot). Para i-install ang isang module sa ibang proyekto, buksan ang Pabrika ng Module, pumili ng target project, pagkatapos ay pindutin ang I-install ang Module at piliin ang .zip file ng module — idinaragdag ng pagsasama ang mga string at pahintulot nang hindi pino-overwrite ang umiiral na code, at hindi pinagsasama ang isang file kung ang pangalan nito ay ginagamit na sa target project. Ang isang module ay hindi nagdadala ng mga library o build setting.

Polymorphic na Kalasag at Vault ng Asset
Para i-randomize ang mga pangalan ng identifier at i-encrypt ang mga asset ng proyekto bago ilabas: buksan ang Polymorphic na Kalasag at Vault ng Asset sa pangunahing menu, pumili ng proyekto, pagkatapos ay pindutin ang I-randomize ang mga pangalan at i-encrypt ang mga asset. Ini-scan ng IDE ang mga pangalan ng klase at metodo sa source code, gumagawa ng mapa ng mga random na pangalan, ini-encrypt ang mga asset file ng proyekto gamit ang AES-GCM papunta sa folder na brankas-aset sa loob ng proyekto, at nagse-save ng naka-encrypt na mapa ng pagbawi (perisai-peta.brankas) upang maibalik ang mga orihinal na pangalan kapag binabasa ang mga crash log. Ang susi ng pag-encrypt ay galing sa pangalan ng proyekto, kaya sinumang nakakaalam ng pangalan ng proyekto ay makakabukas ng vault — ito ay proteksyon laban sa pasimpleng pagbasa, hindi vault na naka-lock ng password. Ang nabubuo dito ay mapa ng pangalan at vault ng asset; ang muling pagsulat ng mga pangalan sa loob ng naka-compile na DEX file ay susunod na hakbang, kaya ang mga pangalan sa loob ng natapos na APK ay hindi pa na-randomize.

Chain ng Tiwala at Tagapagbantay ng Kapaligiran
Para suriin ang chain ng susi sa pagpirma at ang kapaligiran ng telepono bago ilabas: buksan ang Chain ng Tiwala at Tagapagbantay ng Kapaligiran sa pangunahing menu, pumili ng proyekto, pagkatapos ay pindutin ang Suriin ang Chain at Kapaligiran. Bumubuo ang IDE ng chain ng susi na 5 henerasyon mula sa pangalan ng package ng proyekto at sinusuri ang kabuuan nito, pagkatapos ay ini-scan ang memory map ng sarili nitong proseso at ang mga katangian ng device para sa mga bakas ng Frida, Xposed, o emulator. Ang resulta ay antas ng panganib na Ligtas, Mag-ingat, o Mapanganib, kasama ang tekstong ebidensya. Binabasa ng pagsusuring ito ang mga tekstong padron sa memory map at mga katangian ng sistema, hindi ang kabuuan ng hilaw na memorya sa antas ng katutubong aklatan, at hindi nito itinatali ang mga susi sa chip ng seguridad ng hardware — ang kagamitang pang-inject na nagtatago ng mga tekstong bakas nito ay makakalusot sa pag-scan na ito.

Arkitekto ng Layout na Puno ng Teksto
Para magdisenyo ng screen nang hindi tinitingnan ang screen: buksan ang Arkitekto ng Layout na Puno ng Teksto sa pangunahing menu, pumili ng proyekto at layout file, pagkatapos ay pindutin ang Suriin ang Layout. Binabasa ng IDE ang XML layout bilang puno ng teksto at binabasa nang malakas ang salaysay ng posisyon ng bawat elemento (halimbawa sa kanang ibaba, 45 porsyento ng lapad ng screen), pagkatapos ay inuulat nang matematikal ang mga pagbangga sa pagitan ng mga elemento at ang mga elementong lumalabas sa screen sa lapad na 360 dp. Ang kinakalkula ay LinearLayout at mga simpleng sukat na dp; ang ConstraintLayout at mga Compose screen ay inuulat na hindi tiyak ang posisyon, hindi hinuhulaan.

Studio ng Design System
Para gawing magkapareho ang layo, titik, at sulok sa lahat ng screen at proyekto: buksan ang Studio ng Design System sa pangunahing menu, pumili ng proyekto, isulat ang mga token ng disenyo (halimbawa jarak=8, huruf=16, sudut=12), pumili ng sangkap, pagkatapos ay pindutin ang Gumawa ng mga Sangkap. Bine-verify ng IDE ang mga token — batayang layo 4 hanggang 16 dp, batayang titik 12 hanggang 20 sp, sulok 0 hanggang 32 dp, at pinakamababang lugar ng pagdampi na 48 dp — pagkatapos ay isinusulat ang mga handa nang XML na sangkap (komponen-studio.xml) kasama ang XML na tema (tema-studio.xml) at tema ng Compose (tema-studio.kt) sa folder ng proyekto. Ang mga sangkap ay ginagawa bilang teksto na idinidikit sa layout at pagkatapos ay sinusuri gamit ang Arkitekto ng Layout; ang pagsasaayos ng dalawang hanay sa tablet ay gumagamit ng mga qualifier ng lapad ng screen, hindi pagtuklas ng device habang tumatakbo.

Semantic na Refactoring at Pag-navigate sa AST
Para maghanap ng mga kahulugan at palitan ang pangalan ng mga simbolo nang hindi sinisira ang ibang code na nagkataong kapareho ang pangalan: buksan ang Semantic na Refactoring at Pag-navigate sa AST sa pangunahing menu, pumili ng proyekto, pagkatapos ay pindutin ang I-scan ang mga Simbolo ng Proyekto upang makita ang lahat ng klase at metodo kasama ang kanilang mga file at numero ng linya. Ilagay ang pangalan ng simbolo pagkatapos ay pindutin ulit ang I-scan ang mga Simbolo ng Proyekto upang makita ang kahulugan nito at lahat ng file na tumatawag dito. Para palitan ang pangalan, ilagay ang bagong pangalan, pindutin ang Silip sa Pagpapalit ng Pangalan upang makita ang bilang ng paglitaw sa bawat file, pagkatapos ay pindutin ang Ilapat ang Pagpapalit ng Pangalan. Gumagamit ang indeks na ito ng mga tekstong padron, hindi ng buong AST parser: ang pagpapalit ng pangalan ng klase ay nalalapat sa lahat ng file, samantalang ang pagpapalit ng pangalan ng metodo ay sa file lamang ng may-ari nito — ang mga tumatawag sa ibang file ay hindi binabago, kaya suriin ang silip at ang mga resulta ng pag-scan ng tumatawag bago ilapat. Ang pagkuha ng bloke ng code bilang bagong function ay nasa lohikang makina na, ngunit wala pang pindutan para dito sa screen na ito.

Debugger na Hakbang-hakbang at Inspektor ng Memorya
Para suriin ang laman ng mga variable sa gitna ng daloy ng programa nang hindi nanghuhula sa pamamagitan ng mga log: buksan ang Debugger na Hakbang-hakbang at Inspektor ng Memorya sa pangunahing menu, pumili ng proyekto, isulat ang bakas ng pagpapatupad (isang hakbang bawat linya, ang anyo ay numero ng linya, code, pagkatapos ay mga variable at halaga na pinaghiwalay ng |, halimbawa 10|int total = harga * jumlah;|harga=5000, jumlah=3, total=15000), ilagay ang numero ng linya ng hintuan, pagkatapos ay pindutin ang Patakbuhin ang Debug Trace. Tumatakbo ang IDE hanggang sa unang hintuan at binabasa nang malakas ang aktibong linya kasama ang mga halaga ng variable nito sa pamamagitan ng Jieshuo. Pindutin ang Isang Linyang Hakbang upang umusad ng isang linya, o Ituloy ang Programa upang tumakbo hanggang sa susunod na hintuan. Ito ay debugger ng bakas: sinusundan nito ang naitala o isinulat-kamay na bakas ng pagpapatupad, hindi pinapahinto ang tumatakbong Android app — ang pagpahinto sa tunay na proseso ay nangangailangan ng tulay ng debug na wala pa sa yugtong ito.

Tagapamahala ng Dependency na Offline
Para gumamit ng mga aklatan ng ikatlong partido nang walang internet at iwasan ang mga salungatan ng bersyon bago mag-build: buksan ang Tagapamahala ng Dependency na Offline sa pangunahing menu, pumili ng proyekto, pagkatapos ay pindutin ang Suriin ang mga Dependency. Binabasa ng IDE ang lahat ng .gradle file ng proyekto, sinusuri ang offline na vault (brankas-maven.txt sa loob ng proyekto), at nilulutas ang mga salungatan — kung humihingi ang dalawang aklatan ng magkaibang bersyon ng parehong artifact, ang pinakamataas na bersyon ang gagamitin at iuulat ang salungatan. Para itala ang aklatan sa vault, ilagay ang mga koordinat nito (anyong pangkat:artifact:bersyon, halimbawa com.google.code.gson:gson:2.10.1) pagkatapos ay pindutin ang Suriin ang mga Dependency. Ang pag-download mula sa Maven, Google, o PyPI ay nangangailangan ng internet: kapag offline, ang mga aklatan lamang na nasa vault na ang magagamit, at ang pagdaragdag ng mga koordinat ay nagtatala lamang sa mga ito sa indeks — ang mga AAR, JAR, o WHL file mismo ay hindi awtomatikong dina-download. Ang vault ay naka-save pa rin bawat proyekto.

Inspektor ng Database at Imbakan
Para suriin at subukan ang laman ng database ng proyekto nang hindi sumusulat ng code na nagpi-print ng laman ng talahanayan: buksan ang Inspektor ng Database at Imbakan sa pangunahing menu, pumili ng proyekto at database file (.db, .sqlite, o .sqlite3), pagkatapos ay pindutin ang Buksan ang Database. Binabasa ng IDE ang iskema ng talahanayan at ipinapakita ang unang 20 hanay bilang tekstong talahanayan na binabasa nang malakas ng Jieshuo. Sumulat ng simpleng SELECT na query pagkatapos ay pindutin ang Patakbuhin ang Query (halimbawa SELECT nama FROM pengguna WHERE kota = 'Makassar'). Para baguhin ang halaga, ilagay ang numero ng hanay (1 = unang hanay), pangalan ng haligi, at bagong halaga, pagkatapos ay pindutin ang Baguhin ang Halaga ng Cell — ang halaga ay isinusulat pabalik sa .db file. Pindutin ang I-save ang Backup upang i-save ang kasalukuyang kalagayan ng talahanayan bilang file na <pangalan-ng-db>.cadangan.txt sa proyekto. Ang unang talahanayan lamang ang binabasa; ang mga sinusuportahang query ay simpleng SELECT lamang na walang JOIN o GROUP BY; ang SharedPreferences at DataStore ay hindi pa binabasa.

Pabrika ng Unit Test at Fuzzing
Para makahanap ng mga butas sa lohika bago ibahagi ang app: buksan ang Pabrika ng Unit Test at Fuzzing sa pangunahing menu, pumili ng proyekto at code file, pagkatapos ay pindutin ang Gumawa at Patakbuhin ang mga Pagsubok. Binabasa ng IDE ang mga lagda ng function sa file, gumagawa ng normal at hangganang mga kaso ng pagsubok (walang laman na teksto, null, pinakamataas na numero, kakaibang mga karakter), nagpapatakbo ng fuzzing sa mga halimbawang function, at nagsusulat ng balangkas ng pagsubok na JUnit (Uji<Pangalan ng Klase>.java) sa proyekto. Iniuulat ng resulta kung ilang pagsubok ang pumasa at bumagsak, kung ilang linya ng code at function ang natagpuan, at kung ilang kaso ng pagsubok ang nabuo. Ang mga nabuong pagsubok ay balangkas pa rin — ang inaasahang (expected) halaga ay dapat isulat ng developer — at ang tunay na fuzzing ay tumatakbo lamang sa mga halimbawang function, hindi sa mga function ng proyekto; ang porsyento ng saklaw ng linya ay hindi pa kinakalkula.

Simulator ng Matinding Kondisyon ng Device at Auditor ng Memory Leak
Para subukan ang katatagan ng app kapag pinapatay ng sistema ang proseso nito, napuputol ang network, umiikot ang screen, o aktibo ang pagtitipid ng baterya: buksan ang Simulator ng Matinding Kondisyon ng Device at Auditor ng Memory Leak sa pangunahing menu, pumili ng proyekto, pagkatapos ay pindutin ang Patakbuhin ang Simulasyon. Nagpapatakbo ang IDE ng tatlong senaryo ng stress kasama ang simulasyon ng pag-ikot ng screen at sinusubaybayan ang mga bagay na nananatili sa memorya matapos isara ang kanilang screen, pagkatapos ay inuulat ang nawalang datos at ang mga kadena ng mga bagay na tumatagas. Ito ay simulasyon sa modelo ng kalagayan, hindi tunay na pagpatay ng proseso, hindi tunay na pagputol ng network ng telepono, at hindi tunay na heap dump; ang modelo ng kalagayan sa screen na ito ay nakapirming halimbawa pa rin, hindi kalagayan ng mga screen ng proyekto ng gumagamit.

Arkitekto ng Blueprint ng Proyekto
Para gawing hakbang-hakbang na plano ng trabaho ang malaking ideya ng app: buksan ang Arkitekto ng Blueprint ng Proyekto sa pangunahing menu, pumili ng proyekto, isulat ang ideya ng app (halimbawa app ng kahera ng tindahan ng grocery na may hulugan), pagkatapos ay pindutin ang Gumawa ng Blueprint. Inaayos ng IDE ang mga modyul, listahan ng file, at maliliit na milyahe ng trabaho, pagkatapos ay sine-save ang mga ito bilang cetak-biru.txt sa folder ng proyekto. Pindutin ang Markahan ang Susunod na Milestone bilang Tapos Na tuwing matatapos ang isang milyahe, o pindutin ang I-load ang Naka-save na Blueprint upang buksang muli ang naka-save na blueprint. Ang mga blueprint ay binubuo mula sa mga padron ng keyword sa device, hindi mula sa online na modelong AI — ang mga ideyang hindi nakikilala ay gumagamit ng pangkalahatang balangkas (modelo ng datos, imbakan, mga screen, lohika) — at ang pagbuo sa pamamagitan ng aktibong tagapagbigay ng AI ay wala pa sa yugtong ito.

Tagapagsalaysay ng Lohikal na Daloy ng Code
Para maunawaan ang mahabang code nang hindi pinapakinggan ang sintaks linya sa linya: buksan ang Tagapagsalaysay ng Lohikal na Daloy ng Code sa pangunahing menu, pumili ng proyekto at code file, pagkatapos ay pindutin ang Salaysay ng Code. Ginagawa ng IDE ang bawat linya bilang pangungusap sa wikang Indonesia (halimbawa kung ang kabuuan ay higit sa 100000, pagkatapos ay patakbuhin ang sumusunod na bloke), ipinapakita ang mapa ng pagtawag sa pagitan ng mga metodo, at minamarkahan ang mga posibleng banayad na bug kasama ang kanilang mga numero ng linya — String na ikinukumpara sa ==, stream na binuksan nang hindi isinara, at variable na isinulat sa dalawang magkaibang metodo. Ang salaysay at pagsusuri ay gumagamit ng mga offline na tekstong padron, hindi ng online na modelong AI at hindi ng buong pagsusuri ng daloy ng datos; ang mga hindi nakikilalang padron ay isinasalaysay kung ano sila bilang linya ng code, at ang mga babala sa karera ng datos ay maaaring lumitaw para sa mga variable na sa katunayan ay ginagamit lamang nang salitan.

Pabrika ng App Bundle at Kahandaan sa Play Store
Para ihanda ang app para sa Google Play Store nang direkta mula sa telepono: buksan ang Pabrika ng App Bundle at Kahandaan sa Play Store sa pangunahing menu, pumili ng proyekto, pagkatapos ay pindutin ang Bumuo ng AAB Bundle. Binubuo ng IDE ang .aab file mula sa manifest, mga mapagkukunan, at mga asset ng proyekto, ginagaya ang mga hati ng laki ng pag-download bawat arkitektura (arm64-v8a, armeabi-v7a, x86_64) at wika, pagkatapos ay sinusuri ang kahandaan sa Play — ang target SDK na mas mababa sa 35 ay minamarkahang Mataas dahil hinihingi ng Play Store ang 35 o higit pa, at ang nawawalang 64-bit na aklatan ay minamarkahan ding Mataas. Ang nabuong bundle ay arkibo ng AAB na may karaniwang kayarian; ang mga hati ng laki ay mga pagtatantya mula sa mga laki ng file, hindi tunay na mga resulta ng paghahati ng bundletool, at ang pagpirma sa bundle para sa Play Console ay gumagamit pa rin ng parehong landas ng build tulad ng APK.

Makina ng Pag-update ng OTA at Unti-unting Paglulunsad
Para magpadala ng maliliit na pag-aayos nang hindi pinipilit ang mga gumagamit na i-download muli ang buong APK: buksan ang Makina ng Pag-update ng OTA at Unti-unting Paglulunsad sa pangunahing menu, pumili ng proyekto, isulat ang laman ng luma at bagong bersyon, pagkatapos ay pindutin ang Gumawa ng Patch Package. Kinakalkula ng IDE ang mga pagkakaiba ng linya at gumagawa ng patch package (patch-ota.zip) kasama ang SHA-256 fingerprint ng bagong laman, pagkatapos ay sinusuri kung ang device na ito ay nasa maagang 10 porsyentong yugto ng paglulunsad. Ang mga patch dito ay gumagana lamang sa mga tekstong file (mga script, asset, pagsasaayos) — ang mga binary na DEX o APK patch ay hindi pa sinusuportahan, at ang patch ay inilalapat kapag muling binuksan ang app. Ang fingerprint sa manifest ay nagpapatunay lamang sa kabuuan ng laman, hindi sa pagiging tunay ng nagpadala, dahil hindi pa ito gumagamit ng lagda ng pribadong susi.

Studio ng Pagsusuri ng Code ng Koponan
Para suriin ang mga pagbabago ng kasamahan at lutasin ang mga salungatan sa pagsasama nang hindi binabasa ang mga tanda ng arrow ng Git: buksan ang Studio ng Pagsusuri ng Code ng Koponan sa pangunahing menu, pumili ng proyekto, punan ang tatlong tekstong bersyon (batayan, lokal, kasamahan), pagkatapos ay pindutin ang Buksan ang Pagsusuri ng Koponan. Pinagsasama ng IDE ang tatlo at ipinapakita ang bawat salungatan bilang pagpipiliang tinig: Gamitin ang lokal na bersyon, Gamitin ang bersyon ng kasamahan, o Pagsamahin ang dalawa — ang mga nagresultang linya ay isinisingit sa orihinal na posisyon ng salungatan upang manatiling tama ang ayos ng mga linya — pagkatapos ay isinusulat ang resulta sa gabung-hasil.txt sa proyekto. Sa ibaba nito ay ang lupon ng gawain ng proyekto: ilagay ang pamagat ng gawain pagkatapos ay pindutin ang Magdagdag ng Gawain; ang mga gawain ay naka-save bilang teksto sa .tugas folder sa loob ng proyekto. Gumagamit ang pagsasama ng pagtutugma ng linya, hindi sintaks, kaya ang dalawang pagbabago sa parehong linya ay palaging itinuturing na salungatan kahit na hindi nagbabanggaan ang kanilang mga kahulugan; ang lupon ng gawain ay nagsi-sync sa pamamagitan ng pagkopya ng tekstong file nito kasama ang kasaysayan ng Git, nang walang nakalaang server ng pag-sync.

Diktasyon ng Istraktura ng Code
Para sumulat ng code gamit ang boses sa loob ng editor: buksan ang isang proyekto sa Editor, pagkatapos ay pindutin ang Diktasyon ng Istraktura ng Code na button. Magsalita ng mga utos sa Indonesian, halimbawa buat fungsi tambah dengan parameter a angka dan b angka, buat kelas Mobil, o buat variabel teks nama sama dengan Budi — binabago ng IDE ang pananalita sa isang wastong Java, Kotlin, Python, o Compose code block ayon sa syntax at inilalagay ito sa posisyon ng cursor, pagkatapos ay binabasa nang malakas ang isang maikling buod sa pamamagitan ni Jieshuo. Gumagamit ang pagdidikta ng built-in na voice input service ng system, nang walang karagdagang pahintulot sa microphone, at kinikilala lamang ang mga pattern ng utos na nakarehistro na; ang pananalita sa labas ng mga pattern na iyon ay hindi binabago sa code. Ang mga numerong sinabi bilang mga salita (halimbawa 'lima') ay hindi pa binabago sa mga digit.

Lokal na Silid ng Kolaborasyon (nang walang internet)
Para magtrabaho nang magkasama sa isang silid nang walang internet: buksan ang Kolaborasyon sa main menu, pagkatapos ay buksan ang seksyon ng Lokal na Silid ng Kolaborasyon. Nagbubukas ang isang telepono ng session (ipinapakita ng IDE ang lokal na IP address at isang 6-digit na PIN), sumasali ang isa pang telepono gamit ang address at PIN na iyon. Ang mga pagbabago sa teksto ay ipinapadala bilang mga pagkakaiba sa linya, ang isang built na APK ay maaaring ipadala sa telepono ng tester, at ang mga ulat ng crash mula sa telepono ng tester ay natatanggap pabalik. Ang isang session ay para lamang sa isang kaibigan; kung binago ng dalawang tao ang eksaktong parehong linya sa parehong oras, ang huling pagbabago ang gagamitin. Ipinapadala ang PIN bilang plain text sa lokal na network. Ang silid na ito ay hindi pa nasusubukan sa isang tunay na telepono.

Mga Setting ng AI
Para itakda ang AI provider at mga API key para sa paggawa ng app: sa main menu, sa pangkat ng Mga Setting, pindutin ang Mga Setting ng AI (sa tabi ng button na Konektor). Piliin ang provider na gagamitin mula sa magagamit na listahan, at lagyan ng tsek ang Lumipat ng model kapag nag-error ang provider para kung mabigo ang isang model, awtomatikong susubukan ng IDE ang susunod na model mula sa parehong provider. Pindutin ang Pamahalaan ang mga API Key para magdagdag ng mga backup key (punan ang pangalan at ang key, pagkatapos ay pindutin ang I-save; ang mga key ay ipinapakita na nakatago, tanging ang huling 4 na karakter lamang ang nakikita). Naka-save ang mga key sa telepono at hindi kailanman ipinapadala kahit saan maliban sa napiling provider kapag gumagawa ng app. Tandaan: sa ngayon, ang pagpili ng provider at key ay itinatala lamang at ipinapakita sa AI Pembuat Aplikasi screen — ang paggawa ng app ay gumagamit pa rin ng lokal na AI sa telepono (nang walang internet); ang paggamit ng mga online provider ay susunod pa.

Konektor
Para suriin ang isang APK at pagkatapos ay ipadala ito: sa main menu, sa pangkat ng Mga Setting, pindutin ang Konektor (sa tabi ng button na Mga Setting ng AI). Pumili ng APK file mula sa telepono, binabasa ng IDE ang mga nilalaman nito (pangalan ng package, bersyon, listahan ng mga activity), pagkatapos ay pindutin ang Ipadala ang APK para ipadala ito sa pamamagitan ng system share menu (halimbawa WhatsApp o Drive).

Wika at Boses
Para baguhin ang wika ng app: buksan ang Mga Setting, pagkatapos ay Wika ng App, pagkatapos ay pumili ng wika o Sundin ang System. Ang main screen at karamihan sa mga screen ay agad na lumilipat sa napiling wika nang hindi isinasara o nire-restart ang app; ang ilang screen (halimbawa Terminal, Kolaborasyon, Mga Setting ng AI, at Pamahalaan ang mga Key) ay gumagamit pa rin ng lumang wika hanggang sa buksan muli. Kung pipiliin mo ang Sundin ang System, ang wika ay sumusunod sa wika ng system ng telepono.
