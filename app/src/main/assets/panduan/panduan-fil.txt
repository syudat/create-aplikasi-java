Maligayang pagdating sa Create Aplikasi by Al Kautsar
Ang Create Aplikasi ay isang app na gumagawa ng mga Android app na direktang tumatakbo sa telepono, nang hindi nangangailangan ng laptop. Pinapayagan ng app na ito ang sinuman na gumawa ng sarili nilang Android app, kabilang ang mga user na nagsisimula pa lang matutong gumawa ng mga app at ang mga user ng screen reader. Ang kumpletong gabay sa paggamit ng app na ito ay available sa screen na Tentang Alat na ito.

Ano ang app na ito at para kanino ito
Ang Create Aplikasi ay isang kasangkapan sa paggawa ng mga Android app na tumatakbo sa telepono. Ang app na ito ay para sa sinumang gustong gumawa ng sarili nilang Android app, kabilang ang mga baguhan at mga user ng screen reader. Nagbibigay ang app na ito ng code editor, ng button na Jalankan para subukan ang proyekto, ng button na Bangun para gumawa ng APK, at ng mga menu para lagdaan at i-install ang APK.

Ang layunin ng app na ito
Ginawa ang app na ito para madaling makagawa ang sinuman ng sarili nilang Android app, direkta mula sa telepono. Ginawang pinakasimple ang hitsura nito para kahit ang mga bagong user ay makasubok agad.

Paano gumawa ng bagong proyekto, hakbang-hakbang
1. Pindutin ang Buat Project sa pangunahing menu.
2. Piliin ang uri ng proyekto: HTML, Situs Web, Java, Kotlin, Compose, o Python.
3. Ilagay ang pangalan ng app, halimbawa: Garuda Decode.
4. Ilagay ang pangalan ng package (package name), halimbawa: com.android.garudadecode. Ang pangalan ng package ay dapat gumamit ng maliliit na titik at binubuo ng hindi bababa sa dalawang bahagi na pinaghihiwalay ng tuldok.
5. Ilagay ang bersyon ng app, halimbawa: 1.0, at ang code ng bersyon sa anyong numero, halimbawa: 1. Kung iiwang blangko, awtomatikong pupunan ang bersyon ng 1.0 at ang code ng bersyon ng 1.
6. Ilagay ang minimum na SDK at target na SDK kung kailangan. Kung iiwang blangko, ang mga default na value ang gagamitin. Ang minimum na SDK ay ang pinakamababang bersyon ng Android na sinusuportahan, halimbawa: ang 21 ay nangangahulugang Android 5.0. Ang maximum na target na SDK ay 36 (Android 16).
7. Pindutin ang button na Pilih Izin para pumili ng mga pahintulot ng app, halimbawa: INTERNET. Ang pahintulot na INTERNET ay nakamarka na bilang default. Markahan lamang ang mga pahintulot na talagang kailangan ng app.
8. Kung nais, markahan ang "Gunakan arsitektur terpisah 64 bit dan 32 bit" para mas maliit ang sukat ng APK, at markahan ang "Gunakan tanda tangan pribadi" kung gustong gumamit ng sariling gawang keystore.
9. Pindutin ang Buat Proyek. Ang bagong proyekto ay mase-save sa folder na Download/project at agad na makikita sa Kelola Project.

Mga uring proyekto na available
• HTML: hitsura mula sa index.html, style.css, at script.js, tumatakbo sa pamamagitan ng WebView. Direktang ginagawa sa telepono.
• Situs Web: website na may menu (Beranda, Tentang, Kontak) mula sa index.html, tentang.html, kontak.html, style.css, at script.js, tumatakbo sa pamamagitan ng WebView. Direktang ginagawa sa telepono.
• Java: ginagawa sa telepono. Ang MainActivity ay nasa app/src/main/java/<nama-paket>/MainActivity.java. Ang hitsura ay mula sa app/src/main/res/layout/activity_main.xml, ang teksto ay mula sa app/src/main/res/values/strings.xml, at ang tema ay mula sa app/src/main/res/values/styles.xml.
• Kotlin: maaaring gawin sa device (offline) gamit ang Kotlin compiler na kasama sa app, o sa pamamagitan ng GitHub Actions. Ang MainActivity ay nasa app/src/main/java/<nama-paket>/MainActivity.kt, at ang mga res file ay katulad ng sa proyektong Java. Ang unang pagbuo sa Kotlin ay mas mabagal dahil sa malaking sukat ng compiler, at ang mga .java file na tumutukoy sa mga Kotlin class ay hindi pa maaaring buuin (ang mga .java file ay kina-compile muna bago ang mga .kt file).
• Compose: modernong Android app na ang interface ay ginawa gamit ang Jetpack Compose (hindi XML layout). Ang MainActivity ay nasa app/src/main/java/<nama-paket>/MainActivity.kt. Ang mga proyektong Compose ay binubuo sa pamamagitan ng GitHub Actions (menu na Bangun proyek, pagkatapos Bangun online) o sa Termux gamit ang Gradle, dahil kailangan ng Compose ang mga Jetpack Compose library na hindi available sa device.
• Python: ang logic ng app ay isinusulat sa wikang Python (Chaquopy) sa app/src/main/python/main.py, at pinatatakbo ng host na MainActivity.java sa app/src/main/java/<nama-paket>/MainActivity.java. Ang mga proyektong Python ay maaaring direktang buuin sa telepono (ang Chaquopy runtime ay kasama sa app) o sa pamamagitan ng GitHub Actions. Ang minimum na SDK ng mga proyektong Python ay 24 (Android 7.0).

Baguhin ang Arkitektura ng Proyekto
Para baguhin ang mga pagpipilian sa arkitektura ng isang umiiral na proyekto nang hindi gumagawa ng bagong proyekto: sa pangunahing menu, pindutin ang «Baguhin ang Arkitektura ng Proyekto», pagkatapos ay pumili ng proyekto at baguhin ang checkbox na «I-build ang 64-bit APK (arm64-v8a)» o «I-build ang 32-bit APK (armeabi-v7a)»; o sa «Kelola Project», pindutin nang matagal ang pangalan ng proyekto at piliin ang «Baguhin ang Arkitektura» upang buksan ang parehong screen nang direkta para sa proyektong iyon. Ang panuntunan ay: kung parehong checkbox ay naka-on, ang build ay gumagawa ng dalawang magkahiwalay na APK, isa 64-bit at isa 32-bit; kung isang checkbox lang ang naka-on, ang build ay gumagawa ng isang solong universal na APK na patuloy na gumagana sa 64-bit at 32-bit na mga device. Ang magkahiwalay na APK para sa iisang variant lamang ay hindi pa sinusuportahan, dahil ang landas ng build ay nakakaalam lamang ng hiwalay o universal na pagpipilian, ngunit ang pagpipilian ng bawat variant ay nananatiling naka-save sa loob ng proyekto upang hindi mawala kapag muling binuksan ang screen.

Ayos ng mga file ng proyektong Java, HTML, Situs Web, Kotlin, Compose, at Python
Ang mga proyektong Java, HTML, Situs Web, Kotlin, Compose, at Python ay nakaayos tulad ng mga Android project sa pangkalahatan. Sa loob ng folder na app ay may folder na src, at sa loob nito ay may folder na main. Sa loob ng folder na main ay may AndroidManifest.xml sa tabi ng folder na java, folder na res na naglalaman ng layout/activity_main.xml at values/strings.xml at values/styles.xml, at para sa HTML at Situs Web ay may folder na assets na naglalaman ng index.html (ang Situs Web ay mayroon ding tentang.html at kontak.html). Ang mga proyektong HTML at Situs Web ay mayroon ding sariling MainActivity sa app/src/main/java/<nama-paket>/MainActivity.java, na naglo-load ng index.html sa WebView at nagsisilbing launcher sa AndroidManifest. Ang mga proyektong Python ay may Python code sa app/src/main/python/main.py at host na MainActivity.java sa app/src/main/java/<nama-paket>/MainActivity.java. Ang AndroidManifest.xml, layout, strings, at styles ay maaaring buksan at baguhin sa editor, tulad ng MainActivity. Ang mga lumang proyekto na ang manifest ay nasa tabi pa rin ng folder na app ay maaari pa ring buuin, dahil kapag nagbubuo, sinusuri muna ng app ang AndroidManifest.xml sa app/src/main/, pagkatapos ang nasa tabi ng folder na app, at panghuli ang project data file.

Mga patakaran sa pahintulot (mahalaga)
Ang mga pahintulot na minarkahan kapag gumagawa ng proyekto ay naitatala lamang sa isang lugar, ayon sa uri ng proyekto. Para sa mga proyektong Java, HTML, Situs Web, Kotlin, Compose, at Python, ang mga minarkahang pahintulot ay naitatala LAMANG sa AndroidManifest.xml na nasa app/src/main/, sa tabi ng folder na java, sa loob ng folder ng proyekto. Ang project data file para sa mga proyektong Java, HTML, Situs Web, Kotlin, Compose, at Python ay walang listahan ng mga pahintulot. Kung pipiliin mo ang Java at mamarkahan ang INTERNET at CAMERA, ang maitatala sa AndroidManifest.xml ay INTERNET at CAMERA lamang, nang walang ibang pahintulot na kasama. Kapag nagbubuo, binabasa ng app ang mga pahintulot mula sa iisang lugar: mula sa AndroidManifest.xml sa app/src/main/ para sa mga proyektong Java, HTML, Situs Web, Kotlin, Compose, at Python (kung wala, mula sa AndroidManifest.xml sa tabi ng folder na app para sa mga lumang proyekto), at mula sa project data file para sa mga lumang proyekto.

Paano gamitin ang editor
Buksan ang Kelola Project, i-tap ang pangalan ng proyekto para buksan ang editor. Sa editor, maaaring buksan ang mga file, maaaring isulat ang code, at maaaring i-save ang mga pagbabago. Para sa mga proyektong Java, HTML, Situs Web, Kotlin, Compose, at Python, ang mga file ay nakaayos sa loob ng folder na app/src/main. Para magbahagi ng proyekto, gamitin ang Ekspor ZIP (tingnan ang seksyon sa ibaba).

Paano patakbuhin ang proyekto
Sa editor, pindutin ang Jalankan para subukan ang proyekto. Para sa mga proyektong HTML at Situs Web, ang pinatatakbo ay ang index.html sa pamamagitan ng WebView. Kung may maganap na error, basahin ang mensahe ng error, ayusin ang code, pagkatapos ay patakbuhin ulit.

Paano buuin ang APK
Sa editor, pindutin ang Bangun. May dalawang paraan ng pagbuo. Una, Bangun di perangkat: direktang pagbuo sa telepono nang walang internet, para sa mga proyektong HTML, Situs Web, Java, Kotlin, at Python. Pangalawa, Bangun online sa pamamagitan ng GitHub Actions: pagbuo sa pamamagitan ng internet sa GitHub, at maaaring gamitin para sa lahat ng uri ng proyekto. Ang mga proyektong Compose ay maaari lamang buuin sa pangalawang paraan (Bangun online) o sa Termux gamit ang Gradle, dahil kailangan ng Compose ang mga Jetpack Compose library na hindi available sa device. Ang resulta ng unang pagbuo ay hindi pa nalalagdaan. Pagkatapos noon ay lalagdaan ito ng app: awtomatiko gamit ang default na key, o gamit ang personal na lagda kung ang kahon na "Gunakan tanda tangan pribadi" ay minarkahan kapag gumagawa ng proyekto.

Paano i-install ang APK
Kung handa na ang APK, pindutin ang Pasang para i-install ito. Sa Android 8 pataas, hihingin muna ng telepono ang "Izinkan dari sumber ini", dahil nag-i-install ang app na ito ng mga APK mula sa labas ng Play Store. I-activate ang pahintulot na iyon nang isang beses sa Pengaturan, pagkatapos ay bumalik sa app: awtomatikong magpapatuloy ang pag-install nang hindi na kailangang pindutin ulit ang Pasang. Kung hindi lumabas ang button na Pasang, tiyaking tapos na ang pagbuo at nagawa na ang APK.

Paano lagdaan ang app
Bawat APK ay dapat lagdaan para ma-install. May dalawang pagpipilian. Una, ang default na key: awtomatikong lumalagda ang app nang mag-isa, nang hindi mo na kailangang gumawa ng anuman. Pangalawa, ang personal na lagda: gumawa muna ng keystore sa pamamagitan ng menu na Buat Keystore sa pangunahing menu, itago nang maayos ang password nito, pagkatapos ay markahan ang "Gunakan tanda tangan pribadi" kapag gumagawa ng proyekto. Ang keystore ay nase-save sa Download/project/signing.

I-export ang proyekto bilang ZIP
Ang Ekspor ZIP ay ibinibigay para maibahagi ang mga proyekto sa mga kaibigan. Ang paraan: sa Kelola Project, pindutin nang matagal ang pangalan ng proyekto, pagkatapos ay piliin ang Ekspor ZIP. Ang resulta ay mase-save sa Download/project/<NamaProyek>.zip. Ang folder na bin ay hindi kasama, kaya maliit ang sukat, ilang sampung KB lamang. Ang ZIP file na iyon ay maaaring ipadala sa kaibigan o i-upload sa GitHub.

Extension na JAWS
Ang extension na JAWS ay gumagamit ng extension engine ng Jieshuo (CSR), hindi ng screen reader nito. Dahil dito, ang disenyo ay maaari pa ring tumakbo kahit TalkBack ang gamit ng user. Ang paraan: buksan ang Ekstensi JAWS sa pangunahing menu. Dahil ang awtomatikong pag-click ay tumatakbo nang mag-isa, dapat munang i-activate ang serbisyo sa Pengaturan Aksesibilitas. Pagkatapos noon, maaaring gumawa ng bagong disenyo: i-type ang pangalan ng disenyo, pindutin ang OK, pagkatapos ay punan ang mga kahon nito.

Ang Daftar Klik ay pinaghiwalay para maayos
Sa loob ng disenyo ay may dalawang kahon: ang kahon ng script at ang kahon ng Daftar Klik. Ang listahan ng mga button ay hiwalay na nase-save sa file na daftar_klik.txt, isang pangalan bawat linya. Halimbawa ng laman nito: tombolSimpan, tombolHapus, tombolBuka. Para magbukas ng app, isulat lamang ang >WhatsApp sa listahang iyon. Ang mga lumang disenyo na wala pang file na daftar_klik.txt ay magpapakita ng default na halimbawang iyon.

Mga simpleng function na ibinibigay
• klikTombol("tombolSimpan") — nagki-click ng isang button batay sa teksto nito.
• klikDaftarTombol(daftar) — nagki-click ng listahan sa daftar_klik.txt, isang button bawat linya, nang sunod-sunod, pagkatapos ay sinasabi kung ilan ang nagtagumpay at ilan ang hindi natagpuan.
• bukaAplikasi("WhatsApp") — nagbubukas ng app batay sa pangalan nito, o isulat ang ">WhatsApp" sa listahan.
• klik(540, 1200) — nagki-click sa mga coordinate ng screen.
Ang lahat ng function ay ginawang simple muna. Kung nasanay na, maaaring magdagdag ng karagdagang mga function sa bandang huli.

Tungkol sa screen reader
Ang app na ito ay dinisenyo para maging magiliw sa screen reader. Bawat field ng paglalagay ay may label at halimbawa ng pagpuno, at lahat ng button ay maaabot nang walang kumplikadong mga gesture. Ang extension na JAWS ay ginawa para tumakbo pa rin kahit TalkBack ang gamit ng user, dahil ang ginagamit ay ang extension engine nito, hindi ang screen reader nito.

Privacy at seguridad
Ang mga proyekto at keystore ay nase-save sa iyong telepono. Ang GitHub token ay ginagamit lamang para sa mga online na pagbuo at nase-save sa loob ng app na ito. Huwag ibahagi ang iyong token o password ng keystore kaninuman. Kung gagamit ng personal na lagda, itago ang keystore at ang password nito sa ligtas na lugar, dahil kung mawala ang mga ito, ang lumang APK ay hindi na maa-update gamit ang parehong lagda.

Mga pangangailangan
Android 5.0 o mas bago. Pahintulot sa storage: sa Android 11 pataas ay gumagamit ng pahintulot sa pag-access ng lahat ng file, sa Android 10 pababa ay gumagamit ng karaniwang pahintulot sa storage (basahin/isulat ang storage) dahil ang Android 10 ay walang pahintulot sa pag-access ng lahat ng file. Ang pagbuo sa device ay nangangailangan ng teleponong may ARM processor (32 o 64 bit). Ang pagbuo online sa pamamagitan ng GitHub Actions ay nangangailangan ng internet at GitHub token. Ang mga proyektong Kotlin ay maaaring buuin sa device, ngunit ang unang pagbuo nito ay mas mabagal at gumagamit ng mas maraming memory dahil sa malaking sukat ng Kotlin compiler. Ang mga proyektong Compose ay binubuo sa pamamagitan ng GitHub Actions o sa Termux gamit ang Gradle. Ang mga proyektong Python ay nangangailangan ng Android 7.0 o mas bago (minimum na SDK 24) at ang resultang APK ay mas malaki dahil kasama nito ang Python runtime (Chaquopy) at ang standard library nito.

Terminal
Ang menu na Terminal sa pangunahing screen ay nagbubukas ng terminal sa loob ng app na ito. Ang mga command tulad ng ls ay maaaring gamitin para tingnan ang laman ng folder ng proyekto, cd para lumipat ng folder, at git para pamahalaan ang code. Ang output ng command ay lumalabas bilang tekstong mababasa ng screen reader, at may button na Bacakan hasil para pakinggan ang huling resulta. Ang terminal na ito ay gumagamit ng system shell ng telepono, kaya ang mga interactive na programa tulad ng nano at vim ay hindi pa maaaring gamitin dito.

Lisensya (bayad na bersyon)
Para magbenta ng mga app, markahan ang "Aktifkan Lisensi" kapag gumagawa ng proyekto, pagkatapos ay ilagay ang iyong numero ng WhatsApp. Ang app na resulta ng pagbuo ay hihingi ng code ng lisensya kapag unang binuksan: makikita ng user ang ID ng kanyang device, pipindutin ang button na Kirim ID Perangkat para ipadala ang ID na iyon sa iyong WhatsApp, pagkatapos ay sasagot ka gamit ang code ng lisensya. Ang code ng lisensya ay kinukuwenta mula sa ID ng device at sa password ng proyekto (lisensi_seed sa project data file) — itago nang maayos ang password na iyon at huwag ibahagi. Pagkatapos mailagay ang tamang code, bubukas ang app at hindi na hihingi ng code ulit.

Pembuat Ikon Otomatis
Ang mga icon ng bagong proyekto ay transparent pa rin, kaya available ang Pembuat Ikon sa pangunahing menu. Ang paraan: pindutin ang Pembuat Ikon, magsulat ng isa o dalawang titik (halimbawa, ang mga inisyal ng pangalan ng app), piliin ang kulay ng background at kulay ng teksto, tingnan ang preview nito, pagkatapos ay pindutin ang Simpan ke Proyek para gamitin ang icon na iyon sa napiling proyekto, o ang Simpan ke Download para gamitin ang PNG file nito sa ibang lugar. Pagkatapos magawa ang proyekto, nag-aalok din ang app na gumawa ng icon. Ang mga lumang icon ng proyekto ay maaaring palitan anumang oras mula sa menu ng proyekto sa Kelola Project (pindutin nang matagal ang pangalan ng proyekto, pagkatapos ay piliin ang Ganti Ikon).

Mga Template ng Proyekto na Handa Nang Gamitin
Kung ayaw mong magsimula sa blangkong proyekto, pumili ng template kapag gumagawa ng proyekto: Kalkulator (Java), Catatan (Java), Daftar Tugas (Kotlin), Kalkulator Web (HTML), Situs Profil (Situs Web), o Penghitung (Compose). Ang pagpili ng template ay awtomatikong binabago ang uri ng proyekto para sumunod sa template na iyon, at ang proyekto ay ginagawa nang may handa nang panimulang code — patatakbuhin o babaguhin na lamang ito. Kung babaguhin ulit nang mano-mano ang uri ng proyekto pagkatapos pumili ng template, makakansela ang template at babalik sa blangko ang proyekto. Para sa mga template na HTML at Situs Web, pinapalitan ng template ang laman ng index.html, kabilang ang HTML script na itinype sa form.

Backup at Pag-restore ng Proyekto
Para hindi mawala ang mga proyekto, may feature na backup. Ang paraan: sa Kelola Project, pindutin nang matagal ang pangalan ng proyekto, pagkatapos ay piliin ang Cadangkan. Ang backup ay mase-save bilang ZIP sa folder na Download/backup na may pangalan ng proyekto at petsa, halimbawa: GarudaDecode-2026-11-14-123045.zip. Ang laman nito ay katulad ng Ekspor ZIP (ang buong laman ng proyekto, nang walang folder na bin). Para mag-restore: buksan ang menu sa Kelola Project, piliin ang Pulihkan cadangan, pagkatapos ay piliin ang backup file nito. Kung mayroon nang pangalan ng proyekto, magtatanong ang app: Timpa proyek lama, o i-save gamit ang Nama baru.

Pagbahagi at Pag-import ng Proyekto
Para magbahagi ng proyekto sa kaibigan: sa Kelola Project, pindutin nang matagal ang pangalan ng proyekto, pagkatapos ay piliin ang Bagikan. Ang proyekto ay ipinapadala bilang ZIP sa pamamagitan ng mga app sa pagbahagi (WhatsApp, Telegram, at iba pa). Para tumanggap ng proyekto mula sa kaibigan: buksan ang menu sa Kelola Project, piliin ang Impor proyek, pagkatapos ay piliin ang ZIP file nito. Ang ZIP file na iyon ay dapat maglaman ng project data file — kung wala, ang file ay tatanggihan nang may malinaw na mensahe, dahil ang file na iyon ay hindi proyekto ng Create Aplikasi. Kung mayroon nang pangalan ng proyekto, magtatanong ang app: Timpa proyek lama, o i-save gamit ang Nama baru.

Paghahanap at Filter ng Proyekto
Kung marami na ang mga proyekto, sa Kelola Project ay may kahon ng paghahanap at filter ng uri. I-type ang pangalan ng proyekto sa kahon ng paghahanap, agad na mafi-filter ang listahan (ang malalaki at maliliit na titik ay hindi pinag-iiba). Ang filter ng uri ay nililimitahan ang listahan sa iisang uri lamang: Semua, HTML, Situs Web, Java, Kotlin, Compose, o Python. Ang menu ng bawat proyekto ay maaari pa ring buksan tulad ng dati mula sa na-filter nang listahan.

Bumuo ng App gamit ang Boses
Kung ayaw mong mag-type, gamitin ang boses: pindutin ang Mag-build Gamit ang Boses sa main menu, pagkatapos ay magsalita ng utos. Mga utos na maaari mong sabihin: "Buat proyek kalkulator", "Bangun proyek Kalkulator", "Buka proyek Kalkulator", "Jalankan proyek Kalkulator", "Daftar proyek", "Buka ikon", "Kembali", at "Bantuan". Sumasagot ang app gamit ang boses at teksto, kaya magagamit pa rin ito nang hindi tumitingin sa screen. Ang pagkilala sa boses ay gumagamit ng built-in na voice recognition app ng telepono (libre; maaari itong gumana offline kung naka-install ang Indonesian language pack). Kung walang voice recognition ang telepono, maaaring i-type ang mga utos sa text box sa parehong screen.

AI Tagagawa ng App
I-type o idikta ang app na gusto mo sa screen ng AI Tagagawa ng App, halimbawa: «notes app na may save button». Sinusuri ng app ang mga keyword sa loob mismo ng telepono (walang internet, walang bayad), pagkatapos ay gumagawa ng tunay na proyekto mula sa pinakaangkop na template: calculator, notes, listahan ng gawain, web calculator, profile site, o counter. Kung wala pang angkop na template ang iyong paglalarawan, gumagawa ang app ng blangkong proyekto at sinasabi ito nang tapat — hindi ito nagpapanggap na naintindihan. Ang proyektong gawa ng AI ay maaaring buksan nang direkta sa Pamahalaan ang Project.

Live Preview sa Telepono ng Kaibigan
Upang ipakita ang isang proyekto sa kaibigan bago ito buuin: sa Pamahalaan ang Project, pindutin nang matagal ang pangalan ng proyekto, pagkatapos ay piliin ang Preview sa Telepono ng Kaibigan. Gumagawa ang app ng maliit na preview package na naglalaman ng mga pangunahing file ng proyekto (index.html, MainActivity, o main.py) kasama ang BACA-SAYA.txt na may mga tagubilin at info.txt. Ang package ay ipinapadala bilang ZIP sa pamamagitan ng WhatsApp o Telegram. Ang kaibigang makakatanggap ay maaaring buksan agad ang preview: ang mga HTML page ay nagbubukas sa browser, ang Java/Kotlin/Python code ay binabasa bilang teksto.

Market ng Project
Ang Market ng Project ay naglalaman ng mga built-in na sample project na maaaring i-install sa folder ng proyekto sa isang tap: Calculator, Notes, Listahan ng Gawain, Web Calculator, Profile Site, Counter, Digital na Orasan, at Web Quiz. Ang online market (pag-download ng mga sample mula sa internet) ay hindi pa available, kaya ang market na ito ay naglalaman ng mga sample na nasa loob na ng app. Ang naka-install na proyekto ay maaaring buksan at baguhin sa Pamahalaan ang Project tulad ng proyektong ikaw mismo ang gumawa.

Direktang Kolaborasyon
Upang magtrabaho sa isang proyekto kasama ang isang kaibigan: buksan ang Kolaborasyon sa pangunahing menu, piliin ang proyekto, sumulat ng tala ng pagbabago (ano ang binago), pagkatapos ay pindutin ang Ibahagi para sa Kolaborasyon. Ang proyekto ay ipinapadala bilang ZIP kasama ang CATATAN.txt file sa loob nito. Ang iyong kaibigan ay magtatrabaho rito at ibabalik ang ZIP; pindutin mo ang Tanggapin ang Sagot, basahin muna ang tala ng pagbabago, pagkatapos ay piliin ang Ilapat upang i-overwrite ang lumang proyekto, o Kanselahin kung magbago ang isip mo. Ang ZIP na walang CATATAN.txt ay hindi collaboration package — para sa karaniwang ZIP ng proyekto, gamitin ang I-import ang proyekto sa Pamahalaan ang Project.

Awtomatikong Tagasalin ng App
Upang isalin ang teksto sa isang app sa ibang wika: buksan ang Tagasalin ng App sa pangunahing menu, piliin ang proyekto at ang target na wika (Ingles, Arabe, o Javanese), pagkatapos ay pindutin ang Isalin. Ang diksyunaryo ay nasa loob na ng telepono (walang internet, walang bayad) at naglalaman ng mga karaniwang salita sa araw-araw; ang teksto mula sa strings.xml, layout, at code ay binabasa pagkatapos ay isinasalin. Awtomatikong Pagsubok ng App
Upang suriin ang isang proyekto bago ito buuin: sa Pamahalaan ang Project, pindutin nang matagal ang pangalan ng proyekto pagkatapos ay piliin ang Awtomatikong Pagsubok. Sinusuri ng IDE ang 10 bagay nang hindi nagbu-build ng APK — naroon ang mga kinakailangang file (file ng data ng proyekto, manifest, pangunahing file, layout, strings), pangalan ng package at bersyon, mga pahintulot na ginamit, icon, at balanse ng mga bracket ng code. AI Tagasuri ng Code

Ang checker ay tumatakbo sa loob ng telepono (walang internet) at naghahanap ng mga hindi nagamit na variable, mga walang lamang function, mga malinaw na walang katapusang loop, tekstong direktang isinulat sa code (mas mainam sa strings.xml), mga mapanganib na pahintulot at API, mga marker ng TODO/FIXME, at dynamic na pagpapatupad. Ang bawat natuklasan ay naglalaman ng pangalan ng file, numero ng linya, at mungkahi sa pag-aayos. Ang checker na ito ay batay sa pattern, hindi tunay na AI — ang mga problemang hindi sumusunod sa pattern ay maaari pa ring makalusot.

Pag-sync sa Cloud

Ito ay manu-manong backup at restore — ang buong awtomatikong two-way sync ay nangangailangan ng server, kaya hindi pa ito available.

Awtomatikong Tagadisenyo ng Tema

Pindutin ang Ilapat ang Tema — isinusulat ng IDE ang colors.xml at styles.xml (estilo ng app_theme) sa proyekto, na direktang ginagamit kapag pinatakbo o binuo ang proyekto.

Tagagawa ng Animation

Tagarekord ng Aksyon

Awtomatikong Seguridad
Upang suriin ang seguridad ng isang proyekto: buksan ang Awtomatikong Seguridad sa pangunahing menu, piliin ang proyekto, pagkatapos ay pindutin ang Suriin ang Seguridad. Sinusuri ng IDE ang 8 bagay nang lokal (walang internet): mga mapanganib na pahintulot (lokasyon, SMS, tawag, camera, mikropono, contact), pagpapadala ng data sa pamamagitan ng HTTP, pagpapadala ng SMS, mga papalabas na tawag, password o key na direktang isinulat sa code, WebView na walang proteksyon, component na na-export nang walang pahintulot, at http address na walang encryption. Ang bawat natuklasan ay binibigyan ng antas na LIGTAS, BABALA, o PANGANIB kasama ang mungkahi sa pag-aayos, at ang buod ay binabasa nang malakas ni Jieshuo.

Widget & Wallpaper Maker

Pagsasama ng Social Media

App mula sa Larawan

Interactive na Terminal (VT Parser)
Upang gumamit ng mga interactive na program sa Terminal: buksan ang Terminal sa pangunahing menu, pagkatapos ay patakbuhin ang nano, vim, top, o htop. Terminal Exec (Binary ng App)

Terminal na Nananatiling Buhay (KeepAlive)
Upang panatilihing tumatakbo ang shell habang lumilipat sa ibang screen: buksan ang Terminal, patakbuhin ang isang utos, pagkatapos ay pindutin ang Bumalik o lumipat sa ibang screen — ang shell ay HINDI mamamatay, at ang notification ng Terminal ay nananatiling nakikita upang makabalik ka sa isang tap. Ang mga utos na napatakbo ay naka-save sa kasaysayan (button ng Kasaysayan, o ang pataas/pababang arrow sa field ng utos) at ang mga utos na madalas gamitin ay maaaring i-save bilang paborito (button ng Paborito). Pindutin ang Isara ang shell kapag tapos ka na, upang ang shell ay talagang matapos. Mayroon ding button na Bumuo sa Terminal sa menu ng proyekto at sa menu ng editor: ang Terminal ay nagbubukas sa folder ng proyekto na ang build command ay napunan na.

I-install ang Terminal Tool (Pagsubok)
Isang tampok na nasa pagsubok pa: sa Terminal ay may button na I-install ang Terminal Tool upang mag-install ng Termux environment mula sa mirror sa alat-termux repository ng developer (github.com/syudat/alat-termux), bilang isa pang daan bukod sa button na I-install ang Termux na kumukuha mula sa opisyal na release ng Termux. Ang nilalaman ng mirror ay eksaktong kapareho ng opisyal na release at sinusuri gamit ang SHA-256 habang nag-i-install. Matapos mai-install ang environment, maaaring gamitin ang mga utos na pkg update at pkg install, at ang mga karagdagang tool mula sa repository ay naka-install din sa terminal: info-terminal upang makita ang impormasyon ng environment, bersih-terminal upang linisin ang cache, at cadangkan-proyek upang i-archive ang folder ng proyekto sa isang dated na tar.gz file. Pagkatapos nito ay awtomatikong ini-install ng app ang mga pangunahing Linux package (git, python, curl, wget, nano, openssh, zip, unzip) at ang mga APK build tool na may lagda (openjdk-21, kotlin, gradle, ecj, aapt2, d8, apksigner, clang, cmake, ninja, make) mula sa opisyal na repository ng Termux, upang ang terminal ay handa kaagad na gumawa ng mga app. Ang pag-download ng malalaking package (daan-daang MB) ay maaaring tumagal nang matagal. Habang tumatakbo ang pag-install, ang pag-usad at output ng utos ay lumilitaw sa pangunahing screen ng Terminal, at ang huling resulta ay binabasa nang malakas ng screen reader. Kung hindi pa tapos ang pag-install ng package, pindutin muli ang I-install ang Terminal Tool upang ipagpatuloy ito.

Full Voice Mode

Tagasalin ng Code
Upang isalin ang code sa pagitan ng mga wika nang walang internet: buksan ang Tagasalin ng Code sa pangunahing menu, piliin ang proyekto, piliin ang source file (.java/.kt), pagkatapos ay piliin ang direksyon: Java papuntang Kotlin. Pindutin ang Isalin — ang resulta ay ipinapakita kasama ang ulat ng mga linyang hindi maisasalin (ang mga linyang iyon ay pinananatili kung ano ang mga ito at minarkahan). Pindutin ang I-save ang resulta upang isulat ang isang BAGONG file (pangalan-pagsasalin.java/.kt) sa parehong folder; ang orihinal na file ay hindi kailanman na-o-overwrite. Ito ay isang pattern-rule na tagasalin, hindi compiler — laging suriin ang resulta bago gamitin.

Git sa Loob ng App
Upang gumamit ng Git sa loob ng IDE nang walang Termux: buksan ang Git sa Loob ng App sa pangunahing menu, piliin ang proyekto, pagkatapos ay pindutin ang Gumawa ng Git Repo upang gumawa ng lokal na repo (.git) sa proyektong iyon. Pindutin ang Suriin ang Status upang makita ang mga bago, binago, o tinanggal na file kumpara sa huling commit; punan ang mensahe ng commit pagkatapos ay pindutin ang Commit upang i-save ang snapshot ng proyekto; pindutin ang Tingnan ang Commit Log upang makita ang kasaysayan ng commit. Ang Push sa GitHub at Pull mula sa GitHub ay gumagamit ng mga snapshot sa pamamagitan ng GitHub token (repo na pembuat-aplikasi-build) — hindi git protocol. Ang Clone, Push (system git), at Pull (system git) ay tumatakbo lamang kapag ang git binary ay naka-install sa telepono (karaniwang wala). Hindi ito buong git: walang merge, branch, o diff — ang bawat commit ay nagse-save ng buong ZIP snapshot ng proyekto.

Tagagawa ng Ad
Upang magdagdag ng mga ad sa nabuong app: buksan ang Tagagawa ng Ad sa pangunahing menu, piliin ang proyekto, ang provider (AdMob, Unity Ads, o AppLovin) at ang uri ng ad (Banner, Interstitial, o Rewarded). Magaan na Performance Monitor
Upang subaybayan ang paggamit ng RAM at processor ng isang tumatakbong app (tulad ng Profiler sa Android Studio, magaan na bersyon): buksan ang Magaan na Performance Monitor sa pangunahing menu, patakbuhin muna ang app na nais suriin (halimbawa ang nabuong app na sinusubukan), punan ang pangalan ng package nito — o pumili ng proyekto pagkatapos ay pindutin ang Punan ang Pangalan ng Package mula sa Proyekto — pagkatapos ay pindutin ang Simulan ang Pagsubaybay. Walang karagdagang pahintulot. Sa mga bagong bersyon ng Android, ang access sa pagbasa ng processor ng ibang app ay nililimitahan ng system, kaya kung hindi mabasa ang CPU, sinasabi ito ng ulat kung ano ito at ang pagsubaybay sa RAM ay nagpapatuloy.

Para malaman kung ang layout ng proyekto ay friendly sa screen reader (TalkBack/Jieshuo) bago i-release: buksan ang Accessibility Audit sa main menu, pumili ng proyekto, pagkatapos ay pindutin ang I-load ang Listahan ng Layout at pumili ng layout file. Binabasa ng IDE ang XML file na iyon at nag-uulat ng mga button na walang label kasama ang kanilang line number, mga label na paulit-ulit na ginamit, at mga element na magkakapatong, pagkatapos ay gumagawa ng transcript ng focus order tulad ng binabasa ni Jieshuo. Kung may button na walang label, punan ang label nito pagkatapos ay pindutin ang Maglagay ng Label nang Awtomatiko — isinusulat ang label sa layout file bilang contentDescription. Ang pagsusuring ito ay nagbabasa lamang ng layout XML; ang mga Compose view at tapos na APK ay hindi pa ini-scan.

Autopsy ng Crash
Para malaman kung bakit nagsasara ang app nang mag-isa, mula sa crash log na may natatanging ID: buksan ang «Autopsy ng Crash» sa pangunahing menu, pumili ng crash ID mula sa listahan ng log, pagkatapos ay pindutin ang «Suriin». Itinatapat ng IDE ang class at numero ng linya sa log sa pinagmulan ng proyekto at ipinapaliwanag ang dahilan sa Indonesian (halimbawa walang laman na sanggunian, pahintulot na hindi pa hinihingi, o error sa JSON), kasama ang mungkahi sa patch ng code. Pindutin lamang ang «Ilapat ang Patch» kapag ang linya ng pinagmulan ay eksaktong kapareho pa rin ng noong nangyari ang crash; kung nagbago ito, ang patch ay tinatanggihan at hinihiling ng IDE na suriin mo mismo. Para sa mga crash ng na-build na app, pindutin ang «I-inject ang Crash Catcher sa Proyekto», pagkatapos ay i-build ang APK gaya ng dati: ang na-build na app na iyon ay humuhuli sa sarili nitong mga crash at isinusulat ang log nito sa telepono, at ang log na iyon ay matatagpuan gamit ang button na «Hanapin ang Crash Log ng Na-build na App». Ang tapat na limitasyon: ang pagkopya ng log sa pampublikong Download folder sa Android 11 pataas ay maaaring mabigo nang walang pahintulot sa pag-access sa lahat ng file.

Transpiler na Cross-Paradigm
Para i-convert ang simpleng Java code sa Kotlin, o ang simpleng XML layout sa Compose code: buksan ang Transpiler na Cross-Paradigm sa main menu, pumili ng proyekto at file, pagkatapos ay pindutin ang Preview. Ipinapakita ng IDE ang resulta ng conversion bilang teksto — suriin mo muna ito, dahil ang mga linyang hindi nito nakikilala ay iniiwan kung ano sila at ang salitang static sa Java ay tinatanggal sa Kotlin (suriin ang kahulugan nito bago gamitin). Ang conversion ng XML sa Compose ay binabago lamang ang teksto, hint, at oryentasyon — ang laki, kulay, at iba pang attribute ay hindi pa kasama. Kung tama na ang resulta, pindutin ang Ilapat sa File para isulat ang target file; hindi binabago ang source file. Tanging mga ligtas at karaniwang pattern lamang ang kino-convert.

Lokal na Micro Server
Para subukan ang isang app na nangangailangan ng server nang walang internet: buksan ang «Lokal na Micro Server» sa pangunahing menu, isulat ang mga kahulugan ng ruta (halimbawa GET /halo pagkatapos ay ang JSON na sagot nito), pagkatapos ay pindutin ang «Simulan ang Server». Nagpapatakbo ang IDE ng maliit na HTTP server sa mismong telepono (HTTP lamang, walang TLS, para sa parehong Wi-Fi network) at nagtatala ng bawat kahilingan at sagot sa screen. Ang mga ruta ay maaaring gumamit ng mga parameter tulad ng {nama} at isang simpleng API key. Ang server ay maaari ring i-package sa na-build na APK: pindutin ang «I-package ang Server sa Proyekto», at ang pinagmulan ng server, mga asset, at manifest ay ini-inject sa proyekto, kaya ang na-build na app mismo ay nagiging server kapag tumatakbo. Ang server sa IDE ay humihinto kapag isinara ang screen nito.

Security Auditor
Para suriin ang code ng proyekto para sa mga puwang sa seguridad bago ilabas: buksan ang «Security Auditor» sa pangunahing menu, pumili ng proyekto, pagkatapos ay pindutin ang «Simulan ang Pag-scan». Ini-scan ng IDE ang code ng proyekto, manifest, at configuration at nag-uulat ng mga natuklasan mula sa pinakamataas hanggang sa pinakamababang panganib — API key na naiwang bukas sa code, bahagi na nalantad nang walang pahintulot, WebView na nagpapagana sa JavaScript kasama ang JavaScript interface nito, mahinang crypto (MD5, SHA1, DES), http address na walang TLS, at password na isinulat nang direkta sa code — kasama ang kanilang mga file at numero ng linya. Para sa mga natuklasan na ligtas ayusin (halimbawa baguhin ang MD5 sa SHA-256 o http sa https), pindutin ang «Ilapat ang Pag-aayos»; para sa mga API key at password, ipinapakita lamang ng IDE ang mungkahi sa pag-aayos dahil ang kapalit ay dapat pagpasyahan ng developer mismo. Sinusuri na ngayon ng pag-scan ang tunay na DEX bytecode sa loob ng na-build na APK (hindi lamang mga pattern ng teksto sa code), kaya ang mga mapanganib na tinawag na API at mga lihim na naka-embed sa DEX ay nahuhuli rin; ang mga puwang na hindi sumusunod sa pattern ay maaari pa ring makatakas sa pag-scan — suriin bago ilapat.

Robot na Tagasubok ng Interface
Para awtomatikong subukan ang screen ng app sa pamamagitan ng mga tekstong scenario: buksan ang «Robot na Tagasubok ng Interface» sa pangunahing menu, pumili ng proyekto, pagkatapos ay pindutin ang «Gumawa ng Awtomatikong Scenario». Binabasa ng IDE ang manifest at layout ng proyekto at isinusulat ang scenario bilang mga hakbang ng teksto (pindutin ang button, punan ang field, maghintay, bumalik). Pindutin ang «Patakbuhin ang Dry Run» upang makita ang log ng pagtakbo ng scenario kasama ang mga timestamp nito — ang dry run na ito ay simulation lamang ng pagkakasunud-sunod. Para sa tunay na pagsubok, pindutin ang «I-inject ang Test Agent sa Proyekto»: ini-inject ng IDE ang test agent kasama ang mga asset ng scenario sa proyekto; i-build ang APK gaya ng dati, i-install, pagkatapos ay buksan ang icon na «Pagsubok» — ang agent na iyon ay tumatakbo sa loob ng na-build na app at tunay na pumipindot ng mga button, nagpupuno ng mga tunay na field, at nag-i-scroll, pagkatapos ay ipinapakita ang ulat nito sa screen kasama ang mga tunay na crash na nahuli nito. Pindutin ang «Alisin ang Test Agent sa Proyekto» upang alisin muli ang agent na iyon. Ang agent ay tumatakbo sa loob ng sariling proseso ng app, kaya hindi nito kailangan ang accessibility service o system automation.

Paglalakbay sa Oras ng Code
Para ibalik ang isang proyekto sa dating kalagayan ng code nang hindi nagta-type ng mga utos ng Git: buksan ang Paglalakbay sa Oras ng Code sa main menu, pumili ng proyekto, punan ang label para sa time point (maaaring walang laman), pagkatapos ay pindutin ang Itala ang Time Point. Nagse-save ang IDE ng kopya ng mga source file ng proyekto kasama ang kanilang mga hash sa .riwayat folder sa loob ng proyekto. Ipinapakita ng listahan ng mga time point ang lahat ng ito; pumili ng dalawang punto pagkatapos ay pindutin ang Ihambing para makita ang mga file at function na idinagdag, binago, o tinanggal. Pindutin ang I-restore para maibalik ang lumang kalagayan — bago mag-restore, palaging gumagawa muna ang IDE ng backup ng kasalukuyang kalagayan, kaya walang nawawala. Pindutin ang Gumawa ng Kopya ng Eksperimento para kopyahin ang proyekto sa isang bagong folder at subukan ang mga pagbabago nang hindi ginugulo ang orihinal na proyekto. Ang mga source file lamang ang nire-record.

Pabrika ng Module
Para i-package ang bahagi ng isang proyekto bilang module na magagamit ng ibang proyekto: buksan ang Pabrika ng Module sa main menu, pumili ng source project, lagyan ng tsek ang mga screen, class, string, at permission file na ipa-package, pagkatapos ay pindutin ang I-package bilang Module. Sumusulat ang IDE ng ZIP archive kasama ang JSON metadata (pangalan ng module, bersyon, mga string na ginamit, at mga pahintulot). Para i-install ang isang module sa ibang proyekto, buksan ang Pabrika ng Module, pumili ng target project, pagkatapos ay pindutin ang I-install ang Module at piliin ang .zip file ng module — idinaragdag ng pagsasama ang mga string at pahintulot nang hindi pino-overwrite ang umiiral na code, at hindi pinagsasama ang isang file kung ang pangalan nito ay ginagamit na sa target project. Ang isang module ay hindi nagdadala ng mga library o build setting.

Polymorphic na Kalasag at Vault ng Asset
Para i-randomize ang mga pangalan ng identifier at i-encrypt ang mga asset ng proyekto bago ilabas: buksan ang «Polymorphic na Kalasag at Vault ng Asset» sa pangunahing menu, pumili ng proyekto, pagkatapos ay pindutin ang «I-randomize ang mga pangalan at i-encrypt ang mga asset». Ini-scan ng IDE ang mga pangalan ng class at method sa source code, gumagawa ng random na mapa ng pangalan, isinusulat muli ang mga pangalang iyon sa loob ng mga na-compile na DEX file (ang mga pamalit na pangalan ay ginawang kasinghaba ng mga orihinal na pangalan upang manatiling balido ang lahat ng offset, pagkatapos ay muling kinukuwenta ang checksum at SHA-1 na lagda ng DEX header), ini-encrypt ang mga asset file ng proyekto gamit ang AES-GCM sa folder na brankas-aset sa loob ng proyekto, at nagse-save ng naka-encrypt na mapa ng pagbawi (perisai-peta.brankas) upang maibalik ang mga orihinal na pangalan kapag binabasa ang mga crash log. Ang susi ng encryption ay nagmula na ngayon sa password ng developer gamit ang PBKDF2 na may 20,000 pag-uulit, hindi na mula sa pangalan ng proyekto. Ang mga pangalang ginagamit din bilang plain text, pangalan ng annotation, at pangalan ng debug ay sadyang hindi muling isinusulat, at ang mga insertion point ng muling pagsulat ng DEX sa landas ng build ay naghihintay pa rin ng pagsubok sa totoong telepono.

Chain ng Tiwala at Tagapagbantay ng Kapaligiran
Para suriin ang chain ng signing key at ang kapaligiran ng telepono bago ilabas: buksan ang «Chain ng Tiwala at Tagapagbantay ng Kapaligiran» sa pangunahing menu, pumili ng proyekto, pagkatapos ay pindutin ang «Suriin ang Chain at Kapaligiran». Gumagawa ang IDE ng 5-henerasyong key chain mula sa pangalan ng package ng proyekto at sinusuri ang integridad nito, sinusuri ang tunay na integridad ng memorya sa pamamagitan ng paghahambing ng nilalaman ng mga bahagi ng code sa memorya sa mga file sa disk at nag-uulat ng mga hindi pinangalanang maipapatupad (RWX) na mapping, mga dayuhang library, at mga memfd mapping, pagkatapos ay ini-scan ang memory map ng sarili nitong proseso at mga katangian ng device para sa mga bakas ng Frida, Xposed, o emulator. Ang susi ng vault ay binabalot ng AES key sa AndroidKeyStore na gumagamit ng hardware security chip kapag available, at ang pag-ikot ng susi ay totoo na ngayon, gamit ang schema v3 signing certificate lineage: nilalagdaan ng lumang susi ang patunay ng pag-ikot sa bagong susi at ang APK ay muling nilalagdaan gamit ang lineage na iyon. Ang resulta ay antas ng panganib na «ligtas», «mag-ingat», o «mapanganib» kasama ng tekstong ebidensya. Kung tumanggi ang system na basahin ang memorya, ang pagsusuri ay iniuulat bilang «hindi mabe-verify», hindi ligtas; at kung ang isang susi ay talagang gumagamit ng hardware security chip ay maaari lamang kumpirmahin sa totoong device.

Arkitekto ng Layout na Puno ng Teksto
Para magdisenyo ng screen nang hindi ito nakikita: buksan ang «Arkitekto ng Layout na Puno ng Teksto» sa pangunahing menu, pumili ng proyekto at layout file, pagkatapos ay pindutin ang «Suriin ang Layout». Binabasa ng IDE ang XML layout bilang puno ng teksto at binabasa nang malakas ang salaysay ng posisyon ng bawat elemento (halimbawa ibaba kanan, 45 porsyento ng lapad ng screen), pagkatapos ay nag-uulat ayon sa matematika ng mga overlap sa pagitan ng mga elemento at mga elementong lumalabas sa screen sa lapad na 360 dp. Ang kinakalkula na ngayon ay kinabibilangan ng LinearLayout at simpleng laki ng dp, buong ConstraintLayout (lahat ng constraint, bias, chain, gabay, hadlang, lapad na porsyento, 0dp match_constraint, at aspect ratio), at mga Compose screen (Column, Row, at Box kasama ang kanilang mga size modifier). Ang MotionLayout at ConstraintSet lamang na nagbabago habang tumatakbo ang siyang iniuulat pa rin bilang hindi alam ang posisyon, dahil ang kanilang mga halaga ay umiiral lamang habang tumatakbo ang app.

Studio ng Design System
Para pag-isahin ang mga distansya, font, at sulok sa lahat ng screen at proyekto: buksan ang «Studio ng Design System» sa pangunahing menu, pumili ng proyekto, isulat ang mga token ng disenyo (halimbawa jarak=8, huruf=16, sudut=12), pumili ng sangkap, pagkatapos ay pindutin ang «Gumawa ng mga Sangkap». Bine-verify ng IDE ang mga token — batayang distansya 4 hanggang 16 dp, batayang font 12 hanggang 20 sp, sulok 0 hanggang 32 dp, at pinakamababang lugar ng paghawak na 48 dp — pagkatapos ay isinusulat ang mga handa nang gamiting XML na sangkap (komponen-studio.xml) kasama ang XML theme (tema-studio.xml) at Compose theme (tema-studio.kt) sa folder ng proyekto. Ang mga token ay maaari ring i-save bilang pinangalanang set sa shared na library ng token sa pagitan ng mga proyekto, at ang isang utos ng pag-sync ay naglalapat ng pinakabagong mga token ng library sa lahat ng proyektong gumagamit ng set na iyon. Ang mga sangkap ay ginawa bilang teksto na idinidikit sa layout pagkatapos ay sinusuri gamit ang «Arkitekto ng Layout na Puno ng Teksto»; ang pagsasaayos ng dalawang column sa tablet ay gumagamit ng screen width qualifier, hindi ng pagtuklas ng device habang tumatakbo.

Semantic na Refactoring at Pag-navigate sa AST
Para hanapin ang mga kahulugan at palitan ang pangalan ng mga simbolo nang hindi sinisira ang ibang code na nagkataong may parehong pangalan: buksan ang «Semantic na Refactoring at Pag-navigate sa AST» sa pangunahing menu, pumili ng proyekto, pagkatapos ay pindutin ang «I-scan ang mga Simbolo ng Proyekto» upang makita ang lahat ng class at method kasama ang kanilang mga file at numero ng linya. I-type ang pangalan ng simbolo, pagkatapos ay pindutin muli ang «I-scan ang mga Simbolo ng Proyekto» upang makita ang kahulugan nito at lahat ng file na tumatawag dito. Para palitan ang pangalan, i-type ang bagong pangalan, pindutin ang «Silip sa Pagpapalit ng Pangalan» upang makita ang bilang ng mga paglitaw sa bawat file, pagkatapos ay pindutin ang «Ilapat ang Pagpapalit ng Pangalan». Gumagamit na ngayon ang indexer ng sariling gawang AST parser (lexer at recursive parser para sa Java at subset ng Kotlin), kaya ang mga pagpapalit ng pangalan ng method sa pagitan ng mga file ay nalulutas at ang mga tumatawag sa ibang mga file ay nagbabago rin; ang button para kunin ang isang block ng code sa isang bagong function ay nasa screen na ito ngayon. Ang parser na ito ay minimal pa rin: ang napakakomplikadong generics, mga annotation na may parameter, at mga anonymous na class ay ini-scan kung ano sila, habang ang mga tawag sa pamamagitan ng reflection at sa pamamagitan ng interface ay hindi nalulutas.

Debugger na Hakbang-hakbang at Inspektor ng Memorya
Para suriin ang nilalaman ng mga variable sa gitna ng daloy ng programa nang hindi nanghuhula mula sa mga log: buksan ang «Debugger na Hakbang-hakbang at Inspektor ng Memorya» sa pangunahing menu, pumili ng proyekto, isulat ang trace ng pagpapatupad (isang hakbang bawat linya, anyo numero ng linya, code, pagkatapos ay mga variable at halaga na pinaghihiwalay ng |, halimbawa 10|int total = harga * jumlah;|harga=5000, jumlah=3, total=15000), i-type ang numero ng linya ng breakpoint, pagkatapos ay pindutin ang «Patakbuhin ang Debug Trace». Tumatakbo ang IDE hanggang sa unang breakpoint at binabasa nang malakas ang aktibong linya kasama ang mga halaga ng variable nito sa pamamagitan ng Jieshuo. Pindutin ang «Isang Linyang Hakbang» upang umusad ng isang linya, «Pumasok sa Function» upang pumasok sa tinawag na function (kasama ang call stack), o «Ituloy ang Programa» upang umusad sa susunod na breakpoint. Ang trace debugger na ito ay sumusunod pa rin sa isang naitala o sulat-kamay na trace; sa tabi nito ay may isang purong Java na JDWP wire protocol client na maaaring makipagkamay, maglagay ng mga breakpoint, humakbang papasok, pataas, at palabas, at huminto at magpatuloy sa VM sa pamamagitan ng TCP o sa listening mode. Ang paghinto sa isang tunay na proseso mula sa loob ng isang ordinaryong app ay hindi pa rin ganap na posible, dahil ang JDWP socket ng isang proseso ay nalalantad lamang sa pamamagitan ng adbd — ang napatunayang landas ay nangangailangan ng wireless debugging at paglulunsad ng target sa pamamagitan ng shell, na lampas sa magagawa ng app mismo.

Tagapamahala ng Dependency na Offline
Para gumamit ng mga third-party library nang walang internet at maiwasan ang mga salungatan sa bersyon bago mag-build: buksan ang «Tagapamahala ng Dependency na Offline» sa pangunahing menu, pumili ng proyekto, pagkatapos ay pindutin ang «Suriin ang mga Dependency». Binabasa ng IDE ang lahat ng .gradle file ng proyekto, sinusuri ang shared na vault sa pagitan ng mga proyekto sa folder na Download/brankas-bersama, at nilulutas ang mga salungatan — kung ang dalawang library ay humihingi ng magkaibang bersyon ng parehong artifact, ang pinakamataas na bersyon ang ginagamit at ang salungatan ay iniuulat. Para mag-download ng library, i-type ang mga coordinate nito (anyo grupo:artifact:bersyon, halimbawa com.google.code.gson:gson:2.10.1) pagkatapos ay pindutin ang «Suriin ang mga Dependency»: kapag online, ang mga AAR, JAR, o WHL file ay tunay na dina-download mula sa Maven, Google, o PyPI kasama ang kanilang transitive dependency graph (recursive, ang mga cycle ay pinuputol, lalim hanggang 25 antas), at ang mga file lamang na matagumpay na na-download ang naitala bilang available. Kapag offline, ang mga library lamang na nasa shared na vault na ang magagamit. Ang mga saklaw ng bersyon ng Maven ay hindi nalulutas, at ang mga na-download na file ay sinusuri lamang sa pamamagitan ng kanilang SHA-1, nang walang pagpapatunay ng PGP.

Inspektor ng Database at Imbakan
Para suriin at subukan ang nilalaman ng database ng proyekto nang hindi sumusulat ng code na nagpi-print ng nilalaman ng talahanayan: buksan ang «Inspektor ng Database at Imbakan» sa pangunahing menu, pumili ng proyekto at database file (.db, .sqlite, o .sqlite3), pagkatapos ay pindutin ang «Buksan ang Database». Binabasa ng IDE ang schema ng lahat ng talahanayan nito gamit ang buong SQLite page parser (B-tree na may mga overflow page) at ipinapakita ang unang 20 hilera bilang tekstong talahanayan na binabasa nang malakas ni Jieshuo. Sumulat ng SELECT query pagkatapos ay pindutin ang «Patakbuhin ang Query» (halimbawa SELECT nama FROM pengguna WHERE kota = 'Makassar') — sinusuportahan na ngayon ng mga query ang JOIN, GROUP BY, ORDER BY, at LIKE, at sa telepono ay tumatakbo sa pamamagitan ng tunay na Android SQLite engine. Para baguhin ang isang halaga, i-type ang numero ng hilera (1 = unang hilera), pangalan ng column, at bagong halaga, pagkatapos ay pindutin ang «Baguhin ang Halaga ng Cell» — ang halagang iyon ay isinusulat muli sa .db file. Pindutin ang «I-save ang Backup» upang i-save ang kasalukuyang estado ng talahanayan bilang <pangalan-ng-database>.cadangan.txt file sa proyekto. Ang SharedPreferences at DataStore ay maaari ring basahin. Ang hindi pa mababasa: mga naka-encrypt na database, mga hindi pa na-commit na pagbabago sa WAL, at mga may-uring halaga sa espesyal na DataStore Proto (ipinapakita lamang bilang pangkalahatang pagtingin sa field).

Pabrika ng Unit Test at Fuzzing
Para hanapin ang mga puwang sa lohika bago ibahagi ang app: buksan ang «Pabrika ng Unit Test at Fuzzing» sa pangunahing menu, pumili ng proyekto at code file, pagkatapos ay pindutin ang «Gumawa at Patakbuhin ang mga Pagsubok». Binabasa ng IDE ang mga lagda ng function sa file, gumagawa ng mga ordinaryo at hangganang kaso ng pagsubok (walang laman na teksto, null, pinakamataas na numero, kakaibang karakter), pagkatapos ay tunay na pinapatakbo ang mga pagsubok na iyon: ang code ng proyekto ay kino-compile at ang bawat @Test na method ay isinasagawa na may 5 segundong limitasyon, kaya ang resulta ay mga tunay na pumasa at bumagsak kasama ang kanilang mga aktwal na halaga. Ang fuzzing ay tunay ding tumatakbo sa mga function ng proyekto (sa pamamagitan ng reflection, 2 segundo bawat tawag, maximum na 20 method), at ang porsyento ng saklaw ng linya ay tunay na kinakalkula sa pamamagitan ng instrumentation na nagpapanatili sa mga orihinal na numero ng linya. Iniulat ng resulta kung ilang pagsubok ang pumasa at bumagsak, kung ilang linya ng code at function ang natagpuan, at kung anong mga kaso ng pagsubok ang ginawa. Ang mga ginawang pagsubok ay gumagamit ng eksaktong parehong API tulad ng JUnit, ngunit ang mga kahulugan ng annotation at assertion ay isinulat sa loob mismo ng ginawang test file, dahil ang tunay na JUnit library ay hindi kasama sa app.

Simulator ng Matinding Kondisyon ng Device at Auditor ng Memory Leak
Para subukan ang tibay ng app kapag pinapatay ng system ang proseso nito, napuputol ang network, umiikot ang screen, o naka-on ang pagtitipid ng baterya: buksan ang «Simulator ng Matinding Kondisyon ng Device at Auditor ng Memory Leak» sa pangunahing menu, pumili ng proyekto, pagkatapos ay pindutin ang «Patakbuhin ang Simulasyon». Pinapatakbo ng IDE ang tatlong senaryo ng stress kasama ang simulasyon ng pag-ikot ng screen at sinusubaybayan ang mga bagay na nananatiling hawak sa memorya matapos isara ang kanilang screen, pagkatapos ay nag-uulat ng nawalang data at mga tumatagas na chain ng bagay. Ang estado ng pag-save at pagpapanumbalik ay binabasa na ngayon mula sa mismong pinagmulan ng proyekto ng user, hindi mula sa nakapirming halimbawa; ang lokal na loopback server ay tunay na hinihinto sa gitna ng pagsubok upang sukatin ang pagkaputol ng network; ang tunay na heap dump ay kinukuha at sinusuri upang ihambing ang dalawang dump at subaybayan ang chain ng paghawak mula sa mga ugat ng GC; at ang sariling proseso ng app ay tunay na pinapatay matapos i-save ang estado nito, pagkatapos ay sinusuri kung anong data ang bumabalik kapag muling binuksan. Ang nananatiling imposible mula sa isang ordinaryong app: ang pagpatay sa radio o Wi-Fi ng telepono at ang sapilitang paghinto sa ibang mga app — parehong nangangailangan ng pahintulot ng system; sa halip, ang mga background app ay pinapatay sa pamamagitan ng killBackgroundProcesses na ang pahintulot ay nasa manifest na, na may tapat na label sa screen.

Arkitekto ng Blueprint ng Proyekto
Para gawing hakbang-hakbang na plano sa trabaho ang isang malaking ideya ng app: buksan ang «Arkitekto ng Blueprint ng Proyekto» sa pangunahing menu, pumili ng proyekto, isulat ang ideya ng app (halimbawa cashier app ng maliit na tindahan ng grocery na may hulugan), pagkatapos ay pindutin ang «Gumawa ng Blueprint». Gumagawa ang IDE ng mga module, listahan ng file, at maliliit na milestone, pagkatapos ay sine-save ang mga ito bilang cetak-biru.txt sa folder ng proyekto. Sa bawat oras na makumpleto ang isang milestone, pindutin ang «Markahan ang Susunod na Milestone bilang Tapos Na», o pindutin ang «I-load ang Naka-save na Blueprint» upang muling buksan ang naka-save na blueprint. Kung ang isang aktibong AI provider ay napili sa «Mga Setting ng AI» at ang susi nito ay available, ang blueprint ay ginawa ng provider na iyon; kung walang susi o hindi maabot ang provider, bumabalik ang IDE sa mga offline na pattern ng keyword at sinasabi ang limitasyong iyon nang tapat. Ang sagot ng provider ay sinusuri lamang para sa format (naroon ang mga module at milestone), hindi para sa katotohanan ng nilalaman nito — palaging suriin ang blueprint bago mag-build.

Tagapagsalaysay ng Lohikal na Daloy ng Code
Para maunawaan ang mahabang code nang hindi nakikinig sa syntax linya sa linya: buksan ang «Tagapagsalaysay ng Lohikal na Daloy ng Code» sa pangunahing menu, pumili ng proyekto at code file, pagkatapos ay pindutin ang «Salaysay ng Code». Ginagawa ng IDE ang bawat linya sa pangungusap na Indonesian (halimbawa kung ang kabuuan ay higit sa 100000, patakbuhin ang susunod na block), ipinapakita ang mapa ng tawag sa pagitan ng mga method at pagsusuri ng daloy ng data sa pagitan ng mga method (mga halagang ipinasa, ginamit, o hindi pinansin), at minamarkahan ang mga banayad na posibleng bug kasama ang kanilang mga numero ng linya — String na inihambing gamit ang ==, stream na binuksan nang hindi isinara, at variable na isinulat sa dalawang magkaibang method. Kung ang isang aktibong AI provider ay napili sa «Mga Setting ng AI», magagamit din ang buod ng daloy mula sa provider na iyon; kung hindi available, gumagamit ang screen ng offline na salaysay at sinasabi ang limitasyong iyon. Ang salaysay, mapa ng tawag, at daloy ng data ay gumagamit ng offline na pagsusuri ng pattern ng teksto, hindi ng buong AST parser — ang mga method na ang pambungad na brace ay nasa sarili nitong linya, mga field ng class, at mga tawag sa pamamagitan ng reflection ay hindi sinusubaybayan — at ang mga babala sa karera ng data ay maaaring lumitaw para sa isang variable na sa katunayan ay ginagamit lamang nang salitan.

Pabrika ng App Bundle at Kahandaan sa Play Store
Para ihanda ang app para sa Google Play Store nang direkta mula sa telepono: buksan ang «Pabrika ng App Bundle at Kahandaan sa Play Store» sa pangunahing menu, pumili ng proyekto, pagkatapos ay pindutin ang «Bumuo ng AAB Bundle». Gumagawa ang IDE ng .aab file mula sa manifest, resources, at assets ng proyekto kasama ang tunay na BundleConfig.pb, bine-verify ang istraktura ng bundle, pagkatapos ay hinahati ang bundle sa mga tunay na variant APK (base, ayon sa arkitektura, ayon sa wika, at universal) na may mga sukat na sinusukat mula sa paghahating iyon, hindi tinatantya. Ang bundle ay nilalagdaan gamit ang JAR v1 na may parehong susi ng proyekto na ginamit sa paglagda sa APK, at ang chain ng lagda nito ay kriptograpikong bine-verify. Sinusuri rin ng screen na ito ang kahandaan sa Play — ang target SDK na mas mababa sa 35 ay minamarkahan bilang «mataas» dahil ang Play Store ay nangangailangan ng 35 o higit pa, at ang nawawalang 64-bit library ay minamarkahan din bilang «mataas». Ang tunay na bundletool ay hindi maaaring tumakbo sa device, dahil ang bundletool ay nangangailangan ng JVM habang ang Android ay walang JVM; ang landas sa itaas ay ang pinakamalapit na tunay na landas sa device.

Makina ng Pag-update ng OTA at Unti-unting Paglulunsad
Para magpadala ng maliit na pag-aayos nang hindi pinipilit ang mga user na muling i-download ang buong APK: buksan ang «Makina ng Pag-update ng OTA at Unti-unting Paglulunsad» sa pangunahing menu, pumili ng proyekto, isulat ang nilalaman ng luma at bagong bersyon, pagkatapos ay pindutin ang «Gumawa ng Patch Package». Kinukuwenta ng IDE ang pagkakaiba at gumagawa ng patch package (patch-ota.zip) kasama ang SHA-256 fingerprint ng bagong nilalaman, pagkatapos ay sinusuri kung ang device na ito ay nasa unang 10 porsyentong yugto ng paglulunsad. Sinusuportahan na ngayon ng mga patch ang binary delta sa anumang file (kabilang ang DEX at APK), naka-package na may RSA-2048 na lagda at bine-verify gamit ang pinagkakatiwalaang pampublikong susi bago ilapat, at maaaring ma-download mula sa server ng developer kasama ang listahan ng paglulunsad nito; kung mabigo ang paglalapat, ang lumang file ay nananatiling buo. Ang paglalapat ng patch sa tumatakbong app ay ginagawa sa pamamagitan ng muling paglagda gamit ang susi ng proyekto at PackageInstaller, dahil ang pagpapalit ng code ng isang tumatakbong proseso mula sa loob mismo nito ay imposible — ang APK ay naka-lock at ang DEX ay naka-load na.

Studio ng Pagsusuri ng Code ng Koponan
Para suriin ang mga pagbabago ng kasamahan at lutasin ang mga salungatan sa pagsasama nang hindi binabasa ang mga marka ng arrow ng Git: buksan ang «Studio ng Pagsusuri ng Code ng Koponan» sa pangunahing menu, pumili ng proyekto, mag-type ng tatlong bersyon ng teksto (base, lokal, kasamahan), pagkatapos ay pindutin ang «Buksan ang Pagsusuri ng Koponan». Pinagsasama ng IDE ang tatlo batay sa mga yunit ng syntax ng Java — ang dalawang pagbabago sa parehong linya ngunit sa magkaibang mga pahayag ay hindi na itinuturing na salungatan — at ipinapakita ang bawat salungatan bilang pagpipilian sa pagboto: gamitin ang lokal na bersyon, gamitin ang bersyon ng kasamahan, o pagsamahin ang dalawa — ang resultang linya ay ipinasok sa orihinal na posisyon ng salungatan upang manatiling tama ang pagkakasunud-sunod — pagkatapos ay isinusulat ang resulta sa gabung-hasil.txt sa proyekto. Sa ibaba ay ang board ng gawain ng proyekto: i-type ang pamagat ng gawain pagkatapos ay pindutin ang «Magdagdag ng Gawain»; ang mga gawain ay naka-save bilang teksto sa .tugas folder sa loob ng proyekto at naka-sync sa pamamagitan ng mga commit sa in-app na Git, kaya ang board ay maaaring basahin muli mula sa anumang kasaysayan ng commit. Ang tagahati ng syntax na ito ay hindi isang buong AST parser at ang in-app na Git ay nagse-save ng buong snapshot para sa bawat commit; walang dedikadong sync server.

Diktasyon ng Istraktura ng Code
Para sumulat ng code gamit ang boses sa loob ng editor: buksan ang isang proyekto sa Editor, pagkatapos ay pindutin ang Diktasyon ng Istraktura ng Code na button. Magsalita ng mga utos sa Indonesian, halimbawa buat fungsi tambah dengan parameter a angka dan b angka, buat kelas Mobil, o buat variabel teks nama sama dengan Budi — binabago ng IDE ang pananalita sa isang wastong Java, Kotlin, Python, o Compose code block ayon sa syntax at inilalagay ito sa posisyon ng cursor, pagkatapos ay binabasa nang malakas ang isang maikling buod sa pamamagitan ni Jieshuo. Gumagamit ang pagdidikta ng built-in na voice input service ng system, nang walang karagdagang pahintulot sa microphone, at kinikilala lamang ang mga pattern ng utos na nakarehistro na; ang pananalita sa labas ng mga pattern na iyon ay hindi binabago sa code. Ang mga numerong sinabi bilang mga salita (halimbawa 'lima') ay hindi pa binabago sa mga digit.

Lokal na Silid ng Kolaborasyon (nang walang internet)
Para magtrabaho nang magkasama sa isang silid nang walang internet: buksan ang Kolaborasyon sa main menu, pagkatapos ay buksan ang seksyon ng Lokal na Silid ng Kolaborasyon. Nagbubukas ang isang telepono ng session (ipinapakita ng IDE ang lokal na IP address at isang 6-digit na PIN), sumasali ang isa pang telepono gamit ang address at PIN na iyon. Ang mga pagbabago sa teksto ay ipinapadala bilang mga pagkakaiba sa linya, ang isang built na APK ay maaaring ipadala sa telepono ng tester, at ang mga ulat ng crash mula sa telepono ng tester ay natatanggap pabalik. Ang isang session ay para lamang sa isang kaibigan; kung binago ng dalawang tao ang eksaktong parehong linya sa parehong oras, ang huling pagbabago ang gagamitin. Ipinapadala ang PIN bilang plain text sa lokal na network. Ang silid na ito ay hindi pa nasusubukan sa isang tunay na telepono.

Mga Setting ng AI
Para i-set up ang AI provider at mga API key para sa paggawa ng mga app: sa pangunahing menu, sa grupo ng mga setting, pindutin ang «Mga Setting ng AI» (sa tabi ng button na «Konektor»). Piliin ang provider na gagamitin mula sa available na listahan, at lagyan ng tsek ang «Lumipat ng model kapag nag-error ang provider» upang kung ang isang model ay mabigo, awtomatikong susubukan ng IDE ang susunod na model ng parehong provider. Pindutin ang «Pamahalaan ang mga API Key» upang magdagdag ng mga backup key (i-type ang pangalan at susi, pagkatapos ay pindutin ang «I-save»; ang mga susi ay ipinapakita nang nakatakip, ang huling 4 na karakter lamang ang nakikita). Ang mga susi ay naka-save sa telepono at hindi kailanman ipinapadala kahit saan maliban sa napiling provider kapag gumagawa ng app. Ang napiling provider ay tunay na ginagamit na ngayon ng «Arkitekto ng Blueprint ng Proyekto» at «Tagapagsalaysay ng Lohikal na Daloy ng Code»; ang paggawa ng app sa screen na «Tagagawa ng App gamit ang AI» ay gumagamit pa rin ng lokal na AI sa telepono (walang internet).

Konektor
Para suriin ang isang APK at pagkatapos ay ipadala ito: sa main menu, sa pangkat ng Mga Setting, pindutin ang Konektor (sa tabi ng button na Mga Setting ng AI). Pumili ng APK file mula sa telepono, binabasa ng IDE ang mga nilalaman nito (pangalan ng package, bersyon, listahan ng mga activity), pagkatapos ay pindutin ang Ipadala ang APK para ipadala ito sa pamamagitan ng system share menu (halimbawa WhatsApp o Drive).

Wika at Boses
Para baguhin ang wika ng app: buksan ang Mga Setting, pagkatapos ay Wika ng App, pagkatapos ay pumili ng wika o Sundin ang System. Ang main screen at karamihan sa mga screen ay agad na lumilipat sa napiling wika nang hindi isinasara o nire-restart ang app; ang ilang screen (halimbawa Terminal, Kolaborasyon, Mga Setting ng AI, at Pamahalaan ang mga Key) ay gumagamit pa rin ng lumang wika hanggang sa buksan muli. Kung pipiliin mo ang Sundin ang System, ang wika ay sumusunod sa wika ng system ng telepono.

Default na Lagda bawat Proyekto at Anti Tamper
Mula sa bersyon 5.7, ang isang proyekto na hindi gumagamit ng personal na lagda ay nilalagdaan gamit ang sarili nitong built-in na key na NATATANGI sa proyektong iyon (ginawa nang isang beses sa folder na tanda-tangan-bawaan sa loob ng proyekto, pagkatapos ay patuloy na ginagamit), kaya ang built-in na lagda ay nag-iiba-iba sa bawat proyekto — hindi na isang ibinahaging key para sa lahat ng app. Huwag tanggalin ang folder na tanda-tangan-bawaan: kung wala ang key na iyon, ang bagong APK ay hindi makaka-overwrite sa lumang APK ng parehong proyekto. Ang mga setting ng bawat proyekto (hiwalay na arkitektura, personal na lagda, anti tamper, napiling keystore, SDK) ay naka-save na ngayon sa settings.gradle file sa loob ng proyekto at muling binabasa sa tuwing binubuo ang proyekto. Sa Mga Setting, kategorya ng Lagda, mayroong checkbox na Anti tamper ng app na nabuo: kung aktibo, sinusuri ng nabuong app sa device ang sarili nitong lagda at nilalaman ng dex sa tuwing ito ay bubuksan; kung ito ay nilagdaan muli o binago ng iba, tumatanggi ang app na tumakbo. Ang mga debugger at injection tool tulad ng Frida/Xposed ay natutukoy din, at ang window ng app ay naka-lock mula sa pag-record ng screen.

Tagagawa ng Demo Video
Upang gumawa ng demo video ng isang nabuong app: buksan ang Tagagawa ng Demo Video sa pangunahing menu, piliin ang proyekto, punan ang pamagat ng video, pagkatapos ay pindutin ang Gumawa ng Demo Video Script — isinusulat ng IDE ang video-demo.txt na naglalaman ng 5 karaniwang eksena (panimula, pangunahing tanawin, tampok 1, tampok 2, pagtatapos) kasama ang teksto ng narasyon at tagal ng bawat eksena. Pindutin ang Gumawa ng HTML Slideshow upang gumawa ng video-demo.html mula sa mga larawan ng proyekto (icon + mga screenshot kung mayroon) na awtomatikong nagpapalit bawat 5 segundo. Ito ay HINDI .mp4 na video — para sa tunay na video, buksan ang video-demo.html sa browser ng telepono pagkatapos ay i-record ang screen, o basahin ang narasyon sa video-demo.txt habang nirerekord ang tumatakbong app.

Bagong Hitsura ala Android Studio
Ang hitsura ng IDE ay inayos na ngayon upang maging tulad ng Android Studio (hitsura lamang — ang lahat ng button, menu, at daloy ay nananatiling eksaktong kapareho ng dati): mapusyaw na kulay-abong background, makakapal na itim na pamagat ng screen, mga asul na button na may puting teksto, at mga puting input box na may manipis na hangganan. Ang pangunahing menu ay pinangkat nang biswal (Mga Feature ng Builder, Cloud, Tema at Iba Pa, Boses, Code at Bagong Feature, Mga Tool) nang hindi binabago ang pagkakasunud-sunod ng mga button. Ang Terminal ay gumagamit pa rin ng madilim na panel tulad ng Terminal window sa Android Studio, at ang code editor ay nananatili pa ring puting background na may itim na teksto. Ang lahat ng teksto ay nananatiling malinaw na nababasa ni Jieshuo.

Mga Setting
Upang i-set ang app: buksan ang menu ng Mga Opsyon sa pangunahing screen pagkatapos ay pindutin ang Mga Setting. Sa loob nito ay mayroong 12 kategorya: Mga Setting ng GitHub (seguridad, personal na lagda, kasaysayan ng build, at GitHub token), Mga Setting sa Pagbuo ng APK sa Device (i-save ang keystore password at kasaysayan ng build sa device), Tema (kulay ng app), Lagda (gumawa ng keystore para sa personal na lagda at checkbox ng anti tamper ng app na nabuo), Folder ng Proyekto (lokasyon ng folder ng proyekto), Wika at Boses (wika ng interface at bilis ng pagsasalita ng Mode ng Boses), Laki ng Teksto at Display (laki ng font ng editor), Build (default na target SDK at default na paghihiwalay ng arkitektura para sa screen na Gumawa ng Proyekto), Mga Notification (tunog kapag tapos na ang build), Awtomatikong Backup (iskedyul ng backup ng proyekto), Profile ng Developer (pangalan, numero ng WhatsApp, at account na ipinapakita sa screen ng Mag-donate), at Privacy at Data (i-reset ang mga setting at burahin ang data ng app). Ang bawat kategorya ay may button na Bumalik sa Nakaraan upang bumalik sa menu ng kategorya. Ang mga setting na kakasave lamang (hindi pa nailalapat) ay ipinaliwanag nang tapat sa screen.

Mag-donate sa Developer
Upang mag-donate o batiin ang developer: pindutin ang button na Mag-donate sa Developer sa pangunahing screen, sa tabi ng button na Tungkol sa Tool. Sa screen ng pag-donate ay may button na Kopyahin ang BRI Account — pindutin ito upang kopyahin ang numero ng account ng developer, pagkatapos ay i-paste ito sa iyong banking app. Mayroon ding seksyong Batiin ang Developer sa WhatsApp: punan ang iyong pangalan at bayan, pagkatapos ay pindutin ang Magpadala sa WhatsApp — bubukas ang WhatsApp na ang mensahe ng pagbati ay napunan na, pindutin lamang ang Magpadala sa WhatsApp pagkatapos ay bumalik sa app. Hindi pinapayagan ng WhatsApp ang ibang app na magpadala ng mga mensahe nang awtomatiko, kaya ang pagpapadala ay ikaw pa rin mismo ang gumagawa sa WhatsApp.

Mga Paboritong Utos ng Terminal
Upang i-save ang mga utos na madalas gamitin sa Terminal: buksan ang Terminal pagkatapos ay pindutin ang Paborito. I-tap ang Magdagdag ng bagong paborito, punan ang pangalan (halimbawa Tingnan ang file) at ang utos nito (halimbawa ls -la), pagkatapos ay pindutin ang I-save — ang paborito ay permanenteng naka-save sa telepono. I-tap ang pangalan ng paborito upang patakbuhin ito nang direkta sa terminal; i-tap ang Burahin ang paborito pagkatapos ay pumili ng isa upang tanggalin ito (may kumpirmasyon). Mayroon nang 3 built-in na paborito: Tingnan ang file (ls -la), Suriin ang espasyo (df -h), at Linisin ang screen (clear) — lahat ay maaaring tanggalin. Ang walang lamang utos ay hindi maaaring i-save o patakbuhin; ipinapaalam ito sa iyo ng Terminal sa pamamagitan ng mensahe at boses kung mangyari iyon.

Analytics at Kalidad
Upang makita ang buod ng paggamit ng app at mga ulat ng crash: pindutin ang button na Analytics at Kalidad sa pangunahing screen, sa tabi ng button na Mag-donate sa Developer. Ipinapakita ng screen na ito kung ilang beses binuksan ang app, kung aling mga screen ang pinakamadalas buksan, ang bilang ng mga crash, at ang listahan ng mga pinakahuling crash kasama ang maikling mungkahi sa pag-aayos. Ang data na ito ay naka-save lamang sa iyong telepono at hindi ipinapadala kahit saan. Mayroong button na Burahin ang Analytics Data na may dialog ng kumpirmasyon upang burahin ang lahat ng data na iyon. Ang huling screen ay naitala lamang para sa pangunahing screen at sa screen na ito.

Pagtatapos
Salamat sa paggamit ng Create Aplikasi. Sana ay matulungan ng tool na ito ikaw at ang sinumang nais matutong gumawa ng mga Android app mula sa telepono. Kung may problema, ayusin ito nang hakbang-hakbang mula sa gabay na ito, at huwag mag-atubiling subukang muli.
