Bienvenue dans Create Aplikasi by Al Kautsar
Create Aplikasi est une application de création d'applications Android qui fonctionne directement sur le téléphone, sans avoir besoin d'un ordinateur portable. Cette application permet à quiconque de créer ses propres applications Android, y compris les utilisateurs qui commencent tout juste à apprendre à créer des applications et les utilisateurs de lecteurs d'écran. Le guide complet d'utilisation de cette application est disponible sur cet écran À propos de cet outil.

Ce qu'est cette application et à qui elle s'adresse
Create Aplikasi est un outil de création d'applications Android qui fonctionne sur le téléphone. Cette application est destinée à quiconque souhaite créer ses propres applications Android, y compris les débutants et les utilisateurs de lecteurs d'écran. Cette application fournit un éditeur de code, un bouton Exécuter pour tester les projets, un bouton Compiler pour créer un APK, ainsi que des menus pour signer et installer l'APK.

Objectif de cette application
Cette application a été créée pour que quiconque puisse créer facilement ses propres applications Android, directement depuis le téléphone. Son interface est rendue aussi simple que possible afin que même les nouveaux utilisateurs puissent l'essayer immédiatement.

Comment créer un nouveau projet, étape par étape
1. Appuyez sur Créer un projet dans le menu principal.
2. Choisissez le type de projet : HTML, Site Web, Java, Kotlin, Compose ou Python.
3. Saisissez le nom de l'application, par exemple : Garuda Decode.
4. Saisissez le nom du paquet (package name), par exemple : com.android.garudadecode. Le nom du paquet doit utiliser des lettres minuscules et se composer d'au moins deux parties séparées par des points.
5. Saisissez la version de l'application, par exemple : 1.0, et un code de version sous forme de nombre, par exemple : 1. Si vous le laissez vide, la version sera automatiquement remplie avec 1.0 et le code de version 1.
6. Saisissez le SDK minimum et le SDK cible si nécessaire. Si vous les laissez vides, les valeurs par défaut seront utilisées. Le SDK minimum est la version Android la plus basse prise en charge, par exemple : 21 signifie Android 5.0. Le SDK cible maximum est 36 (Android 16).
7. Appuyez sur le bouton Sélectionner les autorisations pour choisir les autorisations de l'application, par exemple : INTERNET. L'autorisation INTERNET est déjà cochée par défaut. Ne cochez que les autorisations dont l'application a réellement besoin.
8. Si vous le souhaitez, cochez « Utiliser des architectures séparées 64 bits et 32 bits » pour que la taille de l'APK soit plus petite, et cochez « Utiliser une signature personnelle » si vous voulez utiliser un keystore créé par vous-même.
9. Appuyez sur Créer un projet. Le nouveau projet est enregistré dans le dossier Download/project et apparaît immédiatement dans Gérer les projets.

Types de projet disponibles
• HTML : affichage à partir de index.html, style.css et script.js, fonctionnant via WebView. Compilé directement sur le téléphone.
• Site Web : un site web avec des menus (Accueil, À propos, Contact) à partir de index.html, tentang.html, kontak.html, style.css et script.js, fonctionnant via WebView. Compilé directement sur le téléphone.
• Java : compilé sur le téléphone. MainActivity se trouve dans app/src/main/java/<package-name>/MainActivity.java. L'affichage provient de app/src/main/res/layout/activity_main.xml, le texte de app/src/main/res/values/strings.xml et le thème de app/src/main/res/values/styles.xml.
• Kotlin : peut être compilé sur l'appareil (hors ligne) à l'aide du compilateur Kotlin inclus dans l'application, ou via GitHub Actions. MainActivity se trouve dans app/src/main/java/<package-name>/MainActivity.kt, et les fichiers res sont les mêmes que dans un projet Java. La première compilation Kotlin est plus lente en raison de la grande taille du compilateur, et les fichiers .java qui référencent des classes Kotlin ne peuvent pas encore être compilés (les fichiers .java sont compilés avant les fichiers .kt).
• Compose : une application Android moderne dont l'interface est créée avec Jetpack Compose (et non des mises en page XML). MainActivity se trouve dans app/src/main/java/<package-name>/MainActivity.kt. Les projets Compose sont compilés via GitHub Actions (le menu Compiler le projet, puis Compiler en ligne) ou dans Termux avec Gradle, car Compose nécessite les bibliothèques Jetpack Compose, qui ne sont pas disponibles sur l'appareil.
• Python : la logique de l'application est écrite dans le langage Python (Chaquopy) dans app/src/main/python/main.py, et est exécutée par l'hôte MainActivity.java dans app/src/main/java/<package-name>/MainActivity.java. Les projets Python peuvent être compilés directement sur le téléphone (l'environnement d'exécution Chaquopy est inclus dans l'application) ou via GitHub Actions. Le SDK minimum pour les projets Python est 24 (Android 7.0).

Modifier l'architecture du projet
Pour modifier les choix d'architecture d'un projet existant sans en créer un nouveau : dans le menu principal, touchez Modifier l'architecture du projet, puis choisissez un projet et modifiez la case Compiler un APK 64 bits (arm64-v8a) ou Compiler un APK 32 bits (armeabi-v7a) ; ou dans Gérer les projets, appuyez longuement sur le nom d'un projet puis choisissez Modifier l'architecture pour ouvrir le même écran directement pour ce projet. La règle est : si les deux cases sont cochées, la compilation produit deux APK séparés, un 64 bits et un 32 bits ; si une seule case est cochée, la compilation produit un seul APK universel qui fonctionne toujours sur les appareils 64 bits comme 32 bits. Un APK séparé pour une seule variante n'est pas encore pris en charge, car le chemin de compilation ne connaît que le choix séparé ou universel, mais le choix de chaque variante reste enregistré dans le projet pour ne pas être perdu à la réouverture de l'écran.

Structure des fichiers des projets Java, HTML, Site Web, Kotlin, Compose et Python
Les projets Java, HTML, Site Web, Kotlin, Compose et Python sont structurés comme les projets Android en général. À l'intérieur du dossier app se trouve le dossier src, et à l'intérieur de celui-ci se trouve le dossier main. À l'intérieur du dossier main se trouve AndroidManifest.xml à côté du dossier java, le dossier res contenant layout/activity_main.xml et values/strings.xml ainsi que values/styles.xml, et pour HTML et Site Web il y a le dossier assets contenant index.html (Site Web a aussi tentang.html et kontak.html). Les projets HTML et Site Web ont également leur propre MainActivity dans app/src/main/java/<package-name>/MainActivity.java, qui charge index.html dans une WebView et devient le lanceur dans le AndroidManifest. Les projets Python ont le code Python dans app/src/main/python/main.py et l'hôte MainActivity.java dans app/src/main/java/<package-name>/MainActivity.java. AndroidManifest.xml, les mises en page, les chaînes et les styles peuvent être ouverts et modifiés dans l'éditeur, tout comme MainActivity. Les anciens projets dont le manifeste se trouve encore à côté du dossier app peuvent toujours être compilés, car lors de la compilation, l'application vérifie d'abord AndroidManifest.xml dans app/src/main/, puis celui à côté du dossier app, et enfin le fichier de données du projet.

Règles relatives aux autorisations (important)
Les autorisations cochées lors de la création d'un projet sont enregistrées à un seul endroit, selon le type de projet. Pour les projets Java, HTML, Site Web, Kotlin, Compose et Python, les autorisations cochées sont enregistrées UNIQUEMENT dans AndroidManifest.xml situé dans app/src/main/, à côté du dossier java, à l'intérieur du dossier du projet. Le fichier de données du projet pour les projets Java, HTML, Site Web, Kotlin, Compose et Python ne contient pas de liste d'autorisations. Si vous choisissez Java puis cochez INTERNET et CAMERA, ce qui est enregistré dans AndroidManifest.xml n'est que INTERNET et CAMERA, sans qu'aucune autre autorisation ne soit incluse. Lors de la compilation, l'application lit les autorisations au même endroit : depuis AndroidManifest.xml dans app/src/main/ pour les projets Java, HTML, Site Web, Kotlin, Compose et Python (s'il n'y en a pas, depuis AndroidManifest.xml à côté du dossier app pour les anciens projets), et depuis le fichier de données du projet pour les anciens projets.

Comment utiliser l'éditeur
Ouvrez Gérer les projets, appuyez sur le nom d'un projet pour ouvrir l'éditeur. Dans l'éditeur, les fichiers peuvent être ouverts, du code peut être écrit et les modifications peuvent être enregistrées. Pour les projets Java, HTML, Site Web, Kotlin, Compose et Python, les fichiers sont organisés à l'intérieur du dossier app/src/main. Pour partager un projet, utilisez Exporter en ZIP (voir la section ci-dessous).

Comment exécuter un projet
Dans l'éditeur, appuyez sur Exécuter pour tester le projet. Pour les projets HTML et Site Web, ce qui est exécuté est index.html via WebView. Si une erreur se produit, lisez le message d'erreur, corrigez le code, puis exécutez-le à nouveau.

Comment compiler un APK
Dans l'éditeur, appuyez sur Compiler. Il y a deux façons de compiler. Premièrement, Compiler sur l'appareil : compile directement sur le téléphone sans internet, pour les projets HTML, Site Web, Java, Kotlin et Python. Deuxièmement, Compiler en ligne via GitHub Actions : compile via internet sur GitHub, et peut être utilisé pour tous les types de projets. Les projets Compose ne peuvent être compilés que de la deuxième manière (Compiler en ligne) ou dans Termux avec Gradle, car Compose nécessite les bibliothèques Jetpack Compose, qui ne sont pas disponibles sur l'appareil. Le résultat de la première compilation n'est pas encore signé. Après cela, l'application le signe : automatiquement avec la clé intégrée, ou avec une signature personnelle si la case « Utiliser une signature personnelle » était cochée lors de la création du projet.

Comment installer un APK
Lorsque l'APK est prêt, appuyez sur Installer pour l'installer. Sur Android 8 et versions supérieures, le téléphone demandera d'abord « Autoriser depuis cette source », car cette application installe des APK provenant de l'extérieur du Play Store. Activez cette autorisation une fois dans les Paramètres, puis revenez à l'application : l'installation se poursuivra automatiquement sans avoir besoin d'appuyer à nouveau sur Installer. Si le bouton Installer n'apparaît pas, assurez-vous que la compilation est terminée et que l'APK a été créé.

Comment signer une application
Chaque APK doit être signé pour pouvoir être installé. Deux choix sont disponibles. Premièrement, la clé intégrée : l'application le signe elle-même automatiquement, sans que vous ayez quoi que ce soit à faire. Deuxièmement, une signature personnelle : créez d'abord un keystore via le menu Créer un keystore dans le menu principal, conservez son mot de passe avec soin, puis cochez « Utiliser une signature personnelle » lors de la création du projet. Le keystore est stocké dans Download/project/signing.

Exporter un projet en ZIP
Exporter en ZIP est fourni pour que les projets puissent être partagés avec des amis. Comment procéder : dans Gérer les projets, appuyez longuement sur le nom du projet, puis choisissez Exporter en ZIP. Le résultat est enregistré dans Download/project/<ProjectName>.zip. Le dossier bin n'est pas inclus, donc la taille est petite, seulement quelques dizaines de Ko. Ce fichier ZIP peut être envoyé à des amis ou téléversé sur GitHub.

Extension JAWS
L'Extension JAWS utilise le moteur d'extensions de Jieshuo (CSR), et non son lecteur d'écran. De cette façon, les designs peuvent continuer à fonctionner même si l'utilisateur utilise TalkBack. Comment procéder : ouvrez Extension JAWS dans le menu principal. Comme le clic automatique fonctionne tout seul, le service doit d'abord être activé dans les Paramètres d'accessibilité. Après cela, un nouveau design peut être créé : tapez le nom du design, appuyez sur OK, puis remplissez ses cases.

Liste de clics conservée séparément pour rester ordonnée
À l'intérieur d'un design, il y a deux cases : la case de script et la case Liste de clics. La liste des boutons est stockée séparément dans le fichier daftar_klik.txt, un nom par ligne. Un exemple de son contenu : tombolSimpan, tombolHapus, tombolBuka. Pour ouvrir une application, écrivez simplement >WhatsApp dans cette liste. Les anciens designs qui n'ont pas encore de fichier daftar_klik.txt afficheront cet exemple par défaut.

Fonctions simples fournies
• klikTombol("tombolSimpan") — clique sur un bouton en fonction de son texte.
• klikDaftarTombol(daftar) — clique sur la liste dans daftar_klik.txt, un bouton par ligne, dans l'ordre, puis indique combien ont réussi et combien n'ont pas été trouvés.
• bukaAplikasi("WhatsApp") — ouvre une application par son nom, ou écrivez ">WhatsApp" dans la liste.
• klik(540, 1200) — clique aux coordonnées de l'écran.
Toutes les fonctions sont d'abord rendues simples. Une fois que vous vous y êtes habitué, des fonctions supplémentaires peuvent être ajoutées plus tard.

À propos des lecteurs d'écran
Cette application est conçue pour être conviviale pour les lecteurs d'écran. Chaque champ de saisie a une étiquette et un exemple de remplissage, et tous les boutons peuvent être atteints sans gestes compliqués. L'Extension JAWS est conçue pour continuer à fonctionner même si l'utilisateur utilise TalkBack, car ce qui est utilisé est son moteur d'extensions, et non son lecteur d'écran.

Confidentialité et sécurité
Les projets et les keystores sont stockés sur votre téléphone. Le jeton GitHub n'est utilisé que pour les compilations en ligne et est stocké à l'intérieur de cette application. Ne partagez votre jeton ou le mot de passe de votre keystore avec personne. Si vous utilisez une signature personnelle, conservez le keystore et son mot de passe dans un endroit sûr, car s'ils sont perdus, les anciens APK ne pourront pas être mis à jour avec la même signature.

Exigences
Android 5.0 ou plus récent. Autorisation de stockage : sur Android 11 et versions supérieures, elle utilise l'autorisation d'accès à tous les fichiers ; sur Android 10 et versions inférieures, elle utilise l'autorisation de stockage ordinaire (lecture/écriture du stockage), car Android 10 n'a pas l'autorisation d'accès à tous les fichiers. Compiler sur l'appareil nécessite un téléphone doté d'un processeur ARM (32 ou 64 bits). Compiler en ligne via GitHub Actions nécessite internet et un jeton GitHub. Les projets Kotlin peuvent être compilés sur l'appareil, mais leur première compilation est plus lente et utilise plus de mémoire en raison de la grande taille du compilateur Kotlin. Les projets Compose sont compilés via GitHub Actions ou dans Termux avec Gradle. Les projets Python nécessitent Android 7.0 ou plus récent (SDK minimum 24) et l'APK résultant est plus grand car il inclut l'environnement d'exécution Python (Chaquopy) ainsi que sa bibliothèque standard.

Terminal
Le menu Terminal sur l'écran principal ouvre un terminal à l'intérieur de cette application. Des commandes telles que ls peuvent être utilisées pour afficher le contenu du dossier du projet, cd pour se déplacer entre les dossiers, et git pour gérer le code. La sortie des commandes apparaît sous forme de texte pouvant être lu par un lecteur d'écran, et il y a un bouton Lire le résultat à voix haute pour écouter le dernier résultat. Ce terminal utilise le shell système du téléphone, donc les programmes interactifs tels que nano et vim ne peuvent pas encore être utilisés ici.

Licence (version payante)
Pour vendre une application, cochez « Activer la licence » lors de la création du projet, puis saisissez votre numéro WhatsApp. L'application compilée demandera un code de licence lors de sa première ouverture : l'utilisateur voit l'ID de son appareil, appuie sur le bouton Envoyer l'ID de l'appareil pour envoyer cet ID à votre WhatsApp, puis vous répondez avec le code de licence. Le code de licence est calculé à partir de l'ID de l'appareil et du mot de passe du projet (lisensi_seed dans le fichier de données du projet) — conservez ce mot de passe avec soin et ne le partagez pas. Après la saisie du code correct, l'application s'ouvre et ne demande plus de code.

Créateur d'icônes automatique
Les icônes des nouveaux projets sont encore transparentes, donc un Créateur d'icônes est disponible dans le menu principal. Comment procéder : appuyez sur Créateur d'icônes, écrivez une ou deux lettres (par exemple les initiales du nom de l'application), choisissez une couleur d'arrière-plan et une couleur de texte, regardez l'aperçu, puis appuyez sur Enregistrer dans le projet pour utiliser cette icône dans le projet sélectionné, ou sur Enregistrer dans Téléchargements pour utiliser son fichier PNG ailleurs. Après la création d'un projet, l'application propose également de créer une icône. L'ancienne icône d'un projet peut être remplacée à tout moment depuis le menu du projet dans Gérer les projets (appuyez longuement sur le nom du projet, puis choisissez Changer d'icône).

Modèles de projet prêts à l'emploi
Si vous ne voulez pas partir d'un projet vide, choisissez un modèle lors de la création du projet : Calculatrice (Java), Notes (Java), Liste de tâches (Kotlin), Calculatrice Web (HTML), Site de profil (Site Web) ou Compteur (Compose). Choisir un modèle modifie automatiquement le type de projet pour suivre ce modèle, et le projet est créé avec un code de démarrage prêt à l'emploi — il suffit de l'exécuter ou de le modifier. Si le type de projet est à nouveau modifié manuellement après le choix d'un modèle, le modèle est annulé et le projet redevient vide. Pour les modèles HTML et Site Web, le modèle remplace le contenu de index.html, y compris le script HTML saisi dans le formulaire.

Sauvegarder et restaurer des projets
Pour que les projets ne soient pas perdus, une fonction de sauvegarde est disponible. Comment procéder : dans Gérer les projets, appuyez longuement sur le nom du projet, puis choisissez Sauvegarder. La sauvegarde est enregistrée sous forme de ZIP dans le dossier Download/backup avec le nom du projet et la date, par exemple : GarudaDecode-2026-11-14-123045.zip. Son contenu est le même que Exporter en ZIP (tout le contenu du projet, sans le dossier bin). Pour restaurer : ouvrez le menu dans Gérer les projets, choisissez Restaurer la sauvegarde, puis choisissez le fichier de sauvegarde. Si le nom du projet existe déjà, l'application demandera : Écraser l'ancien projet, ou enregistrer sous un Nouveau nom.

Partager et importer des projets
Pour partager un projet avec des amis : dans Gérer les projets, appuyez longuement sur le nom du projet, puis choisissez Partager. Le projet est envoyé sous forme de ZIP via des applications de partage (WhatsApp, Telegram et autres). Pour recevoir un projet d'un ami : ouvrez le menu dans Gérer les projets, choisissez Importer un projet, puis choisissez le fichier ZIP. Ce fichier ZIP doit contenir un fichier de données de projet — s'il n'y en a pas, le fichier est rejeté avec un message clair, car ce fichier n'est pas un projet Create Aplikasi. Si le nom du projet existe déjà, l'application demandera : Écraser l'ancien projet, ou enregistrer sous un Nouveau nom.

Recherche et filtre de projets
S'il y a déjà beaucoup de projets, dans Gérer les projets il y a une zone de recherche et un filtre de type. Tapez le nom du projet dans la zone de recherche, et la liste est filtrée immédiatement (les lettres majuscules et minuscules ne sont pas différenciées). Le filtre de type limite la liste à un seul type : Tous, HTML, Site Web, Java, Kotlin, Compose ou Python. Le menu de chaque projet peut toujours être ouvert comme d'habitude à partir de la liste déjà filtrée.

Créer des applications à la voix
Si vous ne voulez pas taper, utilisez la voix : touchez Créer à la voix dans le menu principal, puis dites une commande. Commandes que vous pouvez dire : "Buat proyek kalkulator", "Bangun proyek Kalkulator", "Buka proyek Kalkulator", "Jalankan proyek Kalkulator", "Daftar proyek", "Buka ikon", "Kembali" et "Bantuan". L'application répond par la voix et par le texte, donc elle peut encore être utilisée sans regarder l'écran. La reconnaissance vocale utilise l'application de reconnaissance vocale intégrée du téléphone (gratuite ; elle peut fonctionner hors ligne si le pack de langue indonésienne est installé). Si le téléphone n'a pas de reconnaissance vocale, les commandes peuvent être écrites dans la zone de texte du même écran.

Créateur d'applications IA
Tapez ou dictez l'application souhaitée sur l'écran du Créateur d'applications IA, par exemple : « une application de notes avec un bouton enregistrer ». L'application analyse les mots-clés dans le téléphone lui-même (sans internet, sans frais), puis crée un vrai projet à partir du modèle le plus proche : calculatrice, notes, liste de tâches, calculatrice web, site de profil ou compteur. Si votre description n'a pas encore de modèle adapté, l'application crée un projet vide et le dit honnêtement — elle ne fait pas semblant de comprendre. Un projet créé par l'IA peut être ouvert directement dans Gérer les projets.

Aperçu en direct sur le téléphone d'un ami
Pour montrer un projet à un ami avant de le compiler : dans Gérer les projets, appuyez longuement sur le nom du projet, puis choisissez Aperçu vers le téléphone d'un ami. L'application crée un petit paquet d'aperçu contenant les fichiers principaux du projet (index.html, MainActivity ou main.py) plus BACA-SAYA.txt avec les instructions et info.txt. Le paquet est envoyé en ZIP par WhatsApp ou Telegram. L'ami qui le reçoit peut ouvrir l'aperçu tout de suite : les pages HTML s'ouvrent dans le navigateur, le code Java/Kotlin/Python se lit comme du texte.

Place de marché de projets
Le Marché des projets contient des exemples de projets intégrés qui peuvent être installés dans le dossier du projet d'un simple toucher : Calculatrice, Notes, Liste de tâches, Calculatrice web, Site de profil, Compteur, Horloge numérique et Quiz web. Le marché en ligne (télécharger des exemples depuis internet) n'est pas encore disponible, donc ce marché contient des exemples déjà présents dans l'application. Un projet installé peut être ouvert et modifié dans Gérer les projets comme un projet fait par vous-même.

Collaboration directe
Pour travailler sur un projet avec un ami : ouvrez Collaboration dans le menu principal, choisissez le projet, écrivez une note de modification (ce qui a été changé), puis appuyez sur Partager pour collaborer. Le projet est envoyé en ZIP avec un fichier CATATAN.txt à l'intérieur. Votre ami y travaille puis renvoie le ZIP ; vous appuyez sur Recevoir une Réponse, lisez d'abord la note de modification, puis choisissez Appliquer pour écraser l'ancien projet, ou Annuler si vous changez d'avis. Un ZIP sans CATATAN.txt n'est pas un paquet de collaboration — pour un ZIP de projet ordinaire, utilisez Importer un projet dans Gérer les projets.

Traducteur automatique d'applications
Pour traduire le texte d'une application dans une autre langue : ouvrez Traducteur d'applications dans le menu principal, choisissez le projet et la langue cible (anglais, arabe ou javanais), puis appuyez sur Traduire. Le dictionnaire est déjà dans le téléphone (sans internet, sans frais) et contient des mots courants de tous les jours ; le texte de strings.xml, de la mise en page et du code est lu puis traduit. Le résultat est écrit dans le dossier values-langue/strings.xml (si le projet a un strings.xml) et un rapport traduction-langue.txt dans le dossier du projet. Les mots qui ne sont pas encore dans le dictionnaire sont laissés tels quels et signalés — vous savez ainsi quels mots doivent encore être traduits par vous-même.

Créateur de jeux sans code
Pour créer un jeu sans écrire de code : ouvrez Créateur de jeux dans le menu principal, choisissez le type de jeu (Deviner le nombre, Quiz ou Attraper l'étoile), remplissez le nom du jeu, la quantité (niveaux/questions/étoiles) et le message de victoire, puis appuyez sur Créer le Jeu. Le jeu est créé comme un vrai projet qui peut être exécuté directement dans Gérer les projets et compilé en APK comme tout autre projet.

Test automatique d'applications
Pour vérifier un projet avant de le compiler : dans Gérer les projets, appuyez longuement sur le nom du projet puis choisissez Test automatique. L'IDE vérifie 10 choses sans compiler d'APK — les fichiers obligatoires présents (fichier de données du projet, manifeste, fichier principal, mise en page, chaînes), le nom du paquet et la version, les autorisations utilisées, l'icône et l'équilibre des parenthèses du code. Le résultat est affiché par élément (RÉUSSI/ÉCHEC avec un message) et lu à voix haute par Jieshuo. Corrigez d'abord tout ce qui a ÉCHOUÉ, puis appuyez sur Construire le projet.

Vérificateur de Code IA
Pour vérifier le code du projet à la recherche de motifs qui posent souvent problème : ouvrez Vérifier le code dans le menu principal, choisissez le projet, puis appuyez sur Vérifier le code. Le vérificateur fonctionne dans le téléphone (sans internet) et recherche les variables inutilisées, les fonctions vides, les boucles sans fin évidentes, le texte écrit directement dans le code (mieux dans strings.xml), les autorisations et API dangereuses, les marqueurs TODO/FIXME et l'exécution dynamique. Chaque découverte contient le nom du fichier, le numéro de ligne et une suggestion de correction. Ce vérificateur est basé sur des motifs, ce n'est pas une vraie IA — les problèmes qui ne suivent pas de motif peuvent encore passer.

Mode d'apprentissage interactif
Pour apprendre à créer des applications étape par étape : ouvrez Apprendre dans le menu principal. Il y a 5 leçons : Créer votre premier projet, Ajouter un bouton, Changer la couleur, Ajouter du son et Compiler un APK. Touchez une leçon pour lire son explication et sa tâche pratique, faites la tâche, puis appuyez sur Vérifier la tâche — l'IDE vérifie vraiment si la tâche a été faite (en analysant le projet et l'APK sur votre téléphone). Les leçons réussies sont marquées terminées et enregistrées.

Synchronisation cloud
Pour sauvegarder un projet dans le cloud : ouvrez Synchronisation cloud dans le menu principal. Une sauvegarde locale enregistre le ZIP du projet dans le dossier Download/cloud avec un horodatage, et peut être restaurée à tout moment depuis la liste des sauvegardes. Une sauvegarde GitHub envoie le ZIP du projet vers votre dépôt privé (avec le jeton des Paramètres GitHub) et peut être téléchargée de nouveau. Il s'agit d'une sauvegarde et d'une restauration manuelles — la synchronisation automatique complète dans les deux sens nécessite un serveur, elle n'est donc pas encore disponible.

Créateur automatique de backend
Pour créer un backend sans écrire de code serveur : ouvrez Créateur de backend dans le menu principal, choisissez le type de backend (Notes, Liste de tâches ou Tableau de messages), remplissez le nom du projet, puis appuyez sur Créer le Backend. L'IDE crée un vrai projet HTML avec une page de formulaire et une liste de données enregistrées dans le stockage local du téléphone (localStorage) — les données sont enregistrées et peuvent être relues quand l'application est exécutée. Ce backend fonctionne sur un seul téléphone ; deux téléphones ne peuvent pas encore partager les mêmes données car il n'y a pas de serveur internet.

Concepteur de thèmes automatique
Pour donner un thème de couleur à un projet : ouvrez Concepteur de thèmes dans le menu principal, choisissez le projet et le thème (Clair, Sombre, Bleu, Vert, Rouge ou Violet). L'aperçu montre les six couleurs du thème (primaire, primaire sombre, accent, arrière-plan, texte, texte secondaire) et est lu à voix haute par Jieshuo. Appuyez sur Appliquer le Thème — l'IDE écrit colors.xml et styles.xml (style app_theme) dans le projet, utilisés directement quand le projet est exécuté ou compilé.

Créateur d'animations
Pour donner une animation à un projet : ouvrez Créateur d'animations dans le menu principal, choisissez le projet, le type d'animation (Fondu, Glisser, Tourner, Rebondir ou Pulser), la durée (de 100 à 10000 millisecondes) et la cible (bouton, texte ou image), puis appuyez sur Créer une animation. L'IDE écrit un vrai fichier d'animation (res/anim/anim_<type>.xml pour les projets Java/Kotlin/Compose, ou animasi.css pour les projets HTML/Site web) avec un exemple de code d'utilisation affiché à l'écran.

Enregistreur d'actions
Pour répéter le travail automatiquement : l'IDE enregistre les actions effectuées (ouvrir un projet, exécuter, compiler, exporter, sauvegarder, créer un projet, enregistrer un fichier). Ouvrez Enregistreur d'actions dans le menu principal pour voir la liste des actions enregistrées avec leur plan, puis appuyez sur Relecture — l'IDE réexécute les actions qui peuvent être automatisées (sauvegarder et créer un projet s'exécutent sur place ; exécuter, compiler et exporter ouvrent leur écran principal ; ouvrir et enregistrer ouvrent l'éditeur). Les actions qui ne peuvent pas être automatisées sont ignorées et signalées à la fin.

Sécurité automatique
Pour vérifier la sécurité d'un projet : ouvrez Sécurité automatique dans le menu principal, choisissez le projet, puis appuyez sur Vérifier la Sécurité. L'IDE vérifie 8 choses localement (sans internet) : les autorisations dangereuses (localisation, SMS, appels, caméra, microphone, contacts), l'envoi de données par HTTP, l'envoi de SMS, les appels sortants, un mot de passe ou une clé écrit directement dans le code, un WebView sans protection, un composant exporté sans autorisation et une adresse http sans chiffrement. Chaque découverte reçoit un niveau SÛR, AVERTISSEMENT ou DANGER avec une suggestion de correction, et le résumé est lu à voix haute par Jieshuo.

IA hors ligne
Pour utiliser des outils d'aide pour le texte et le code sans internet : ouvrez IA hors ligne dans le menu principal. Il y a 4 outils : Corriger le texte (majuscules, ponctuation et doubles espaces), Résumer le texte (prend les 3 phrases les plus importantes), Créer un nom d'application (à partir de la description écrite) et Suggérer un nom de variable (cherche les noms de variable de 1-2 lettres dans le projet). Ce sont de simples règles dans le téléphone, pas un vrai modèle d'IA. Le résultat de la correction de texte peut être appliqué au strings.xml du projet avec le bouton Appliquer.

Créateur de widgets et fonds d'écran
Pour créer un widget d'écran d'accueil : ouvrez Widgets et fonds d'écran dans le menu principal, choisissez le projet, remplissez le texte du widget, puis appuyez sur Créer un Widget. L'IDE écrit WidgetSaya.java, la mise en page du widget, les informations du widget et ajoute un récepteur au AndroidManifest.xml du projet — compilez le projet, puis installez le widget depuis l'écran d'accueil du téléphone. Pour un fond d'écran : remplissez le texte et les couleurs d'arrière-plan et de texte, créez un aperçu, puis enregistrez-le en PNG dans le dossier Download ou définissez-le directement comme fond d'écran du téléphone.

Intégration des réseaux sociaux
Pour ajouter des boutons de partage à une application : ouvrez Réseaux sociaux dans le menu principal, choisissez le projet, puis ajoutez le partage vers WhatsApp, Facebook ou Telegram (ou les trois à la fois). L'IDE écrit du vrai code de partage dans le fichier principal du projet (MainActivity ou index.html). Le bouton Tester le partage ouvre le sélecteur de partage depuis l'IDE avec un texte d'exemple, pour que le flux puisse être ressenti avant de compiler l'application.

Application à partir d'une image
Pour créer une application de galerie à partir d'une image : ouvrez Application à partir d'une image dans le menu principal, choisissez une image dans la galerie. L'IDE analyse la taille de l'image et la couleur dominante, puis crée un vrai projet d'application de galerie : l'image est copiée dans les assets du projet, la couleur du thème est tirée de la couleur dominante de l'image et le nom de l'application est tiré du nom du fichier image. Ouvrez Gérer les projets pour exécuter ou compiler cette application de galerie.

Terminal interactif (analyseur VT)
Pour utiliser des programmes interactifs dans le Terminal : ouvrez Terminal dans le menu principal, puis exécutez nano, vim, top ou htop. Le Terminal utilise désormais un analyseur VT (un écran en grille de 24 lignes x 80 colonnes) pour que ces programmes s'affichent correctement — le curseur se déplace, les lignes s'effacent et l'écran change comme dans un vrai terminal. Il y a des boutons spéciaux Tab, Flèche haut, Flèche bas et Échap pour contrôler les programmes interactifs. La sortie reste du texte que Jieshuo peut lire ; appuyez sur Lire l'écran à voix haute pour entendre la dernière ligne.

Terminal Exec (binaire de l'application)
Pour exécuter un binaire dans le dossier de l'application (par exemple aapt2, ECJ, D8) depuis le Terminal : tapez la commande comme d'habitude. L'IDE utilise libkautsarexec.so pour que les binaires du dossier de l'application puissent être exécutés sur Android 10 et plus. Appuyez sur Test Exec dans le Terminal pour vérifier si le chemin exec des binaires fonctionne sur ce téléphone — le résultat est affiché tel quel. Si exec est bloqué par le système, les commandes système et les scripts shell fonctionnent toujours ; exécutez le binaire par le menu Construire le projet.

Terminal toujours actif (KeepAlive)
Pour garder le shell en marche en changeant d'écran : ouvrez le Terminal, exécutez une commande, puis appuyez sur Retour ou passez à un autre écran — le shell NE meurt PAS, et la notification du Terminal reste visible pour que vous puissiez revenir d'un simple toucher. Les commandes déjà exécutées sont conservées dans l'historique (bouton Historique, ou les flèches haut/bas dans le champ de commande) et les commandes souvent utilisées peuvent être enregistrées comme favoris (bouton Favori). Appuyez sur Fermer le shell quand vous avez terminé, pour que le shell soit vraiment arrêté. Il y a aussi un bouton Construire dans le Terminal dans le menu du projet et dans le menu de l'éditeur : le Terminal s'ouvre dans le dossier du projet avec la commande de compilation déjà remplie.

Installer les outils du terminal (essai)
Une fonction encore en essai : dans le Terminal il y a un bouton Installer les outils du terminal pour installer un environnement Termux depuis le miroir dans le dépôt alat-termux du développeur (github.com/syudat/alat-termux), comme une autre voie en plus du bouton Installer Termux qui prend la version officielle de Termux. Le contenu du miroir est exactement le même que la version officielle et est vérifié avec SHA-256 pendant l'installation. Une fois l'environnement installé, les commandes pkg update et pkg install peuvent être utilisées, et des outils supplémentaires du dépôt sont aussi installés dans le terminal : info-terminal pour voir les informations de l'environnement, bersih-terminal pour nettoyer le cache et cadangkan-proyek pour archiver le dossier du projet en un seul fichier tar.gz daté. Après cela, l'application installe automatiquement les paquets Linux de base (git, python, curl, wget, nano, openssh, zip, unzip) et les outils de compilation d'APK avec signature (openjdk-21, kotlin, gradle, ecj, aapt2, d8, apksigner, clang, cmake, ninja, make) depuis le dépôt officiel de Termux, donc le terminal est prêt tout de suite à créer des applications. Le téléchargement de gros paquets (des centaines de Mo) peut prendre longtemps. Pendant que l'installation est en cours, la progression et la sortie des commandes apparaissent sur l'écran principal du Terminal, et le résultat final est lu à voix haute par le lecteur d'écran. Si l'installation des paquets n'est pas encore terminée, appuyez de nouveau sur Installer les outils du terminal pour la continuer.

Mode vocal complet
Pour contrôler l'IDE entièrement à la voix : ouvrez Mode vocal dans le menu principal, puis appuyez sur Commencer à Écouter. L'IDE écoute en continu — il n'est pas nécessaire d'appuyer sur un bouton pour chaque commande — exécute la commande et répond à voix haute. Il y a 26 commandes : créer, compiler, ouvrir, exécuter, lister, rechercher, supprimer, tester, vérifier, exporter, sauvegarder, partager, créer une icône, traduire, compiler dans le terminal, lire l'écran, ouvrir tous les écrans (y compris sécurité, IA hors ligne, widget, réseaux sociaux, jeu, apprendre, cloud, backend, thème, animation, enregistreur), revenir, fermer et aide. Si le mode est laissé actif, l'écoute continue automatiquement quand cet écran est rouvert. Appuyez sur Arrêter d'Écouter pour éteindre ce mode. Si le téléphone n'a pas de service de reconnaissance vocale, les commandes peuvent toujours être écrites dans la zone de texte.

Traducteur de code
Pour traduire du code entre langages sans internet : ouvrez Traducteur de code dans le menu principal, choisissez le projet, choisissez le fichier source (.java/.kt), puis choisissez la direction : Java vers Kotlin. Appuyez sur Traduire — le résultat est affiché avec un rapport des lignes qui ne peuvent pas être traduites (ces lignes sont conservées telles quelles et marquées). Appuyez sur Enregistrer le résultat pour écrire un NOUVEAU fichier (nom-traduction.java/.kt) dans le même dossier ; le fichier original n'est jamais écrasé. C'est un traducteur à règles de motifs, pas un compilateur — vérifiez toujours le résultat avant de l'utiliser.

Git dans l'application
Pour utiliser Git dans l'IDE sans Termux : ouvrez Git dans l'application dans le menu principal, choisissez le projet, puis appuyez sur Créer un Dépôt Git pour créer un dépôt local (.git) dans ce projet. Appuyez sur Vérifier le Statut pour voir les fichiers nouveaux, modifiés ou supprimés par rapport au dernier commit ; remplissez le message du commit puis appuyez sur Valider pour enregistrer un instantané du projet ; appuyez sur Voir le Journal des Commits pour voir l'historique des commits. Pousser vers GitHub et Tirer depuis GitHub utilisent des instantanés via un jeton GitHub (le dépôt pembuat-aplikasi-build) — pas le protocole git. Cloner, Pousser (git système) et Tirer (git système) ne fonctionnent que si le binaire git est installé sur le téléphone (en général ce n'est pas le cas). Ce n'est pas du git complet : pas de fusion, de branche ni de diff — chaque commit enregistre un instantané ZIP complet du projet.

Créateur de publicités
Pour ajouter des publicités à une application compilée : ouvrez Créateur de publicités dans le menu principal, choisissez le projet, le fournisseur (AdMob, Unity Ads ou AppLovin) et le type de publicité (Bannière, Interstitiel ou Récompensée). Remplissez l'ID de l'unité publicitaire si vous en avez déjà un — vide signifie utiliser un ID de test (AdMob utilise l'ID de test officiel de Google ; Unity utilise un ID de jeu d'exemple ; AppLovin utilise un emplacement vide). Appuyez sur Créer un Code Publicitaire pour voir le code Java et Kotlin et le guide ; appuyez sur Enregistrer dans le Projet pour écrire le tout dans le fichier pubs-<fournisseur>-<type>.txt du projet. C'est un modèle de code + guide, pas un SDK publicitaire — le SDK n'est pas inclus dans l'IDE ; les vraies publicités n'apparaissent qu'après avoir créé un compte fournisseur, créé une unité publicitaire, collé votre propre ID d'unité et ajouté la dépendance du SDK dans le build.gradle du projet.

Mode enfant
Pour utiliser l'IDE avec un enfant : ouvrez Mode enfant dans le menu principal. L'écran est simplifié avec de gros boutons et seulement 4 actions sûres : Créer le projet (à partir de modèles sûrs : Calculatrice, Deviner le nombre, Quiz, Attraper l'étoile), Ouvrir un Projet, Exécuter et Apprendre. Il n'y a pas de bouton supprimer, exporter, sauvegarder ni de réglage de jeton sur cet écran. À la première entrée, créez un code PIN à 4 chiffres — ce PIN est utilisé par le parent pour quitter le Mode enfant (le bouton Quitter le mode enfant ou le bouton Retour). Ce PIN est une protection légère pour les petits enfants, pas une vraie sécurité.

Créateur d'applications Wear OS et TV
Pour créer une application de montre (Wear OS) ou de TV (Android TV) : ouvrez Wear OS et TV dans le menu principal, choisissez la cible (Wear OS, Android TV ou les deux). Remplissez le nom du projet puis appuyez sur Créer un Nouveau Projet Wear/TV — l'IDE crée un projet Java puis l'ajuste — ou choisissez un projet déjà existant puis appuyez sur Appliquer à Ce Projet. Les ajustements : uses-feature dans le manifeste, la catégorie LEANBACK_LAUNCHER + bannière pour la TV, et une mise en page activity_main.xml ajustée (Wear : petit écran ; TV : grand écran adapté au D-pad). L'explication complète est écrite dans wear-tv.txt dans le projet. C'est un modèle de projet — compiler + tester nécessite encore un appareil/émulateur Wear OS ou Android TV ; la bannière TV (banner.png 320x180) n'est pas créée automatiquement, elle doit être ajoutée par vous-même (par exemple via le Créateur d'icônes).

Carte du projet
Pour voir la structure d'un projet : ouvrez Carte du projet dans le menu principal, choisissez le projet, puis appuyez sur Afficher la carte — l'IDE affiche la liste des dossiers et fichiers avec leurs tailles, la taille totale, la taille par type de fichier et les fichiers importants (fichier principal, manifeste, mise en page, chaînes, icône, page web). Appuyez sur Enregistrer carte-projet.txt pour écrire la même carte à la racine du projet. Le dossier bin/ (résultats de compilation) et le dossier .git/ (dépôt local) ne sont pas cartographiés car leur contenu peut être recréé.

Calculateur de taille d'APK
Pour estimer la taille de l'APK compilé avant de compiler : ouvrez Calculateur de taille d'APK dans le menu principal, choisissez le projet, puis appuyez sur Calculer l'estimation. L'IDE affiche le détail par catégorie (code/DEX, ressources, assets, bibliothèques natives, manifeste + resources.arsc, surcharge), l'estimation totale, les 5 plus gros fichiers et des suggestions pour réduire (par exemple les grandes images sont réduites en résolution, les grands sons sont coupés en durée). C'est une ESTIMATION, pas la taille exacte — la taille réelle peut différer à cause de la compression aapt2, de la suppression du code inutilisé (R8) et des ressources compilées.

Analyseur d'APK
Pour lire le contenu d'un APK déjà terminé (comme l'Analyseur d'APK d'Android Studio) : ouvrez Analyseur d'APK dans le menu principal, choisissez le projet, puis appuyez sur Analyse de l'APK du résultat de compilation. L'IDE lit l'APK le plus récent dans le dossier bin de ce projet et signale le nom du paquet, la version, le SDK minimum et cible, la liste des autorisations utilisées, le nombre de fichiers dex, le détail de taille par partie (code du programme, ressources, assets, bibliothèques natives, signature) et les 10 plus grosses entrées. Utile pour savoir quelle partie rend l'APK gros et quelles autorisations utilise l'application compilée.

Aperçu de la taille d'écran
Pour vérifier l'aspect d'un projet sur plusieurs tailles d'écran à la fois (comme dans Android Studio) : ouvrez Aperçu de la taille d'écran dans le menu principal, choisissez le projet, puis appuyez sur Vérifier la Taille d'Écran. L'IDE lit toutes les mises en page du projet et signale les éléments dont la largeur est écrite fixe (par exemple 400dp) et dépasse la largeur d'écran de 320, 360, 411 ou 480 dp, car sur un téléphone à petit écran un tel élément peut être couvert ou déborder. Les éléments de largeur match_parent ou wrap_content s'ajustent à l'écran automatiquement et n'ont pas besoin d'être vérifiés.

Gestionnaire de ressources
Pour voir et gérer toutes les ressources d'un projet au même endroit (comme le Gestionnaire de ressources d'Android Studio) : ouvrez Gestionnaire de ressources dans le menu principal, choisissez le projet, puis appuyez sur Voir les Ressources. L'IDE signale le nombre et la taille des fichiers par catégorie (drawable, layout, values, mipmap et autres), le contenu de strings.xml, colors.xml et styles.xml. Depuis le même écran, une nouvelle chaîne peut être ajoutée à strings.xml et une nouvelle couleur à colors.xml en remplissant son nom et sa valeur — le nom est vérifié et les doublons sont rejetés, donc le fichier XML n'est pas cassé.

Moniteur de performances léger
Pour surveiller l'utilisation de la RAM et du processeur d'une application en cours d'exécution (comme le Profiler d'Android Studio, version légère) : ouvrez Moniteur de performances léger dans le menu principal, exécutez d'abord l'application à vérifier (par exemple l'application compilée en cours d'essai), remplissez le nom de son paquet — ou choisissez le projet puis appuyez sur Remplir le Nom de Package depuis le Projet — puis appuyez sur Commencer la Surveillance. Toutes les 2 secondes l'IDE enregistre la RAM (PSS) et le CPU de cette application avec la RAM libre du téléphone ; appuyez sur Arrêter pour voir le résumé de la moyenne et du maximum. Sans autorisation supplémentaire. Sur les nouvelles versions d'Android, l'accès en lecture au processeur d'une autre application est limité par le système, donc si le CPU ne peut pas être lu, le rapport le dit tel quel et la RAM reste surveillée.

Audit d'accessibilité
Pour vérifier si la mise en page d'un projet est adaptée au lecteur d'écran (TalkBack/Jieshuo) avant la publication : ouvrez Audit d'accessibilité dans le menu principal, choisissez un projet, puis touchez Charger la liste des mises en page et choisissez un fichier de mise en page. L'IDE lit ce fichier XML et signale les boutons sans libellé avec leurs numéros de ligne, les libellés utilisés plusieurs fois et les éléments qui se recouvrent, puis construit une transcription de l'ordre de focus comme celle que Jieshuo lit à voix haute. Si un bouton n'a pas de libellé, remplissez son libellé puis touchez Insérer les libellés automatiquement — le libellé est écrit dans le fichier de mise en page en tant que contentDescription. Cette vérification ne lit que le XML de mise en page ; les vues Compose et les APK terminés ne sont pas encore analysés.

Autopsie de plantage
Pour savoir pourquoi une application se ferme toute seule à partir d'un journal de plantage avec un ID unique : ouvrez Autopsie de plantage dans le menu principal, choisissez un ID de plantage dans la liste des journaux, puis touchez Vérifier. L'IDE fait correspondre la classe et le numéro de ligne du journal avec la source du projet et explique la cause en indonésien (par exemple une référence vide, une permission pas encore demandée, ou une erreur JSON), avec une suggestion de correctif de code. Touchez Appliquer le correctif seulement si la ligne source est toujours exactement la même que lors du plantage ; si elle a changé, le correctif est refusé et l'IDE vous demande de vérifier vous-même. Pour les plantages d'une application COMPILÉE, touchez Injecter le capteur de plantages dans le projet, puis compilez l'APK comme d'habitude : cette application compilée capture ses propres plantages et écrit son journal sur le téléphone, et ce journal peut être trouvé avec le bouton Rechercher le journal de plantage de l'application compilée. La limite honnête : la copie du journal dans le dossier public Download sous Android 11 et versions supérieures peut échouer sans la permission d'accès à tous les fichiers.

Transpileur inter-paradigmes
Pour convertir du code Java simple en Kotlin, ou une mise en page XML simple en code Compose : ouvrez Transpileur inter-paradigmes dans le menu principal, choisissez un projet et un fichier, puis touchez Aperçu. L'IDE affiche le résultat de la conversion sous forme de texte — vérifiez-le d'abord, car les lignes qu'il ne reconnaît pas sont laissées telles quelles et le mot static de Java est supprimé en Kotlin (vérifiez son sens avant de l'utiliser). La conversion de XML vers Compose ne change que le texte, les indications et l'orientation — la taille, la couleur et les autres attributs ne sont pas encore inclus. Si le résultat est correct, touchez Appliquer au fichier pour écrire le fichier cible ; le fichier source n'est pas modifié. Seuls les motifs courants et sûrs sont convertis.

Serveur micro local
Pour tester une application qui a besoin d'un serveur sans internet : ouvrez Serveur micro local dans le menu principal, écrivez les définitions de routes (par exemple GET /halo puis sa réponse JSON), puis touchez Démarrer le serveur. L'IDE exécute un petit serveur HTTP sur le même téléphone (HTTP seulement, sans TLS, pour le même réseau Wi-Fi) et enregistre chaque requête et réponse à l'écran. Les routes peuvent utiliser des paramètres comme {nama} et une simple clé API. Le serveur peut aussi être empaqueté dans l'APK compilé : touchez Empaqueter le serveur dans le projet, et la source du serveur, les ressources et le manifeste sont injectés dans le projet, de sorte que l'application compilée elle-même devient le serveur quand elle est exécutée. Le serveur de l'IDE s'arrête quand son écran est fermé.

Auditeur de sécurité
Pour vérifier le code d'un projet à la recherche de failles de sécurité avant la publication : ouvrez Auditeur de sécurité dans le menu principal, choisissez un projet, puis touchez Lancer l'analyse. L'IDE analyse le code, le manifeste et la configuration du projet et signale les résultats du risque le plus élevé au plus faible — une clé API laissée ouverte dans le code, un composant exposé sans permission, un WebView qui active JavaScript avec son interface JavaScript, une cryptographie faible (MD5, SHA1, DES), une adresse http sans TLS, et un mot de passe écrit directement dans le code — avec leurs fichiers et numéros de ligne. Pour les résultats dont la correction est sûre (par exemple remplacer MD5 par SHA-256 ou http par https), touchez Appliquer le correctif ; pour les clés API et les mots de passe, l'IDE montre seulement la suggestion de correction car le remplacement doit être décidé par le développeur. L'analyse examine désormais aussi le vrai bytecode DEX dans l'APK compilé (et non seulement les motifs de texte dans le code), de sorte que les API dangereuses appelées et les secrets intégrés dans le DEX sont aussi détectés ; les failles qui ne suivent aucun motif peuvent encore échapper à l'analyse — vérifiez avant d'appliquer.

Robot de test d'interface
Pour tester automatiquement l'écran d'une application par des scénarios en texte : ouvrez Robot de test d'interface dans le menu principal, choisissez un projet, puis touchez Créer un scénario automatiquement. L'IDE lit le manifeste et la mise en page du projet et écrit un scénario sous forme d'étapes en texte (toucher un bouton, remplir un champ, attendre, revenir). Touchez Lancer le dry run pour voir le journal d'exécution du scénario avec ses horodatages — ce dry run reste seulement une simulation de séquence. Pour un vrai test, touchez Injecter l'agent de test dans le projet : l'IDE injecte un agent de test avec les ressources du scénario dans le projet ; compilez l'APK comme d'habitude, installez-le, puis ouvrez l'icône Test — cet agent tourne dans l'application compilée et touche vraiment des boutons, remplit de vrais champs et fait défiler, puis affiche son rapport à l'écran avec les vrais plantages capturés. Touchez Retirer l'agent de test du projet pour retirer cet agent. L'agent tourne dans le processus même de l'application, il n'a donc besoin ni d'un service d'accessibilité ni d'automatisation du système.

Voyage dans le temps du code
Pour ramener un projet à un état antérieur du code sans taper de commandes Git : ouvrez Voyage dans le temps du code dans le menu principal, choisissez un projet, remplissez une étiquette pour le point dans le temps (elle peut rester vide), puis touchez Enregistrer le point dans le temps. L'IDE enregistre une copie des fichiers source du projet avec leurs hash dans le dossier .riwayat à l'intérieur du projet. La liste des points dans le temps les montre tous ; choisissez deux points puis touchez Comparer pour voir les fichiers et fonctions ajoutés, modifiés ou supprimés. Touchez Restaurer pour récupérer un ancien état — avant de restaurer, l'IDE fait toujours d'abord une sauvegarde de l'état actuel, donc rien n'est perdu. Touchez Créer une copie d'expérience pour copier le projet dans un nouveau dossier et essayer des changements sans déranger le projet original. Seuls les fichiers source sont enregistrés.

Fabrique de modules
Pour emballer une partie d'un projet comme un module qu'un autre projet peut utiliser : ouvrez Fabrique de modules dans le menu principal, choisissez un projet source, cochez les fichiers d'écran, de classe, de texte et d'autorisation à emballer, puis touchez Emballer comme module. L'IDE écrit une archive ZIP avec des métadonnées JSON (nom du module, version, textes et autorisations utilisés). Pour installer un module dans un autre projet, ouvrez Fabrique de modules, choisissez le projet cible, puis touchez Installer le module et choisissez le fichier .zip du module — la fusion ajoute des textes et des autorisations sans écraser le code existant, et ne fusionne pas un fichier si son nom est déjà utilisé dans le projet cible. Un module n'apporte ni bibliothèques ni réglages de compilation.

Bouclier polymorphe et coffre de ressources
Pour mélanger les noms d'identifiants et chiffrer les ressources du projet avant la publication : ouvrez Bouclier polymorphe et coffre de ressources dans le menu principal, choisissez un projet, puis touchez Mélanger les noms et chiffrer les ressources. L'IDE analyse les noms de classes et de méthodes dans le code source, crée une table de noms aléatoires, réécrit ces noms À L'INTÉRIEUR des fichiers DEX compilés (les noms de remplacement ont la même longueur que les noms d'origine pour que tous les décalages restent valides, puis la somme de contrôle et la signature SHA-1 de l'en-tête DEX sont recalculées), chiffre les fichiers de ressources du projet avec AES-GCM dans le dossier brankas-aset du projet, et enregistre une table de récupération chiffrée (perisai-peta.brankas) pour pouvoir restaurer les noms d'origine lors de la lecture des journaux de plantage. La clé de chiffrement est désormais dérivée du mot de passe du développeur avec PBKDF2, 20 000 itérations, et non plus du nom du projet. Les noms utilisés aussi comme texte brut, noms d'annotation et noms de débogage ne sont volontairement pas réécrits, et les points d'insertion de la réécriture DEX dans le chemin de compilation attendent encore un test sur un vrai téléphone.

Chaîne de confiance et gardien de l'environnement
Pour vérifier la chaîne de clés de signature et l'environnement du téléphone avant la publication : ouvrez Chaîne de confiance et gardien de l'environnement dans le menu principal, choisissez un projet, puis touchez Vérifier la chaîne et l'environnement. L'IDE construit une chaîne de clés de 5 générations à partir du nom de paquet du projet et vérifie son intégrité, vérifie l'intégrité réelle de la mémoire en comparant le contenu des segments de code en mémoire avec les fichiers sur le disque et signale les mappings anonymes exécutables (RWX), les bibliothèques étrangères et les mappings memfd, puis analyse la carte mémoire de son propre processus et les propriétés de l'appareil à la recherche de traces de Frida, Xposed ou d'un émulateur. La clé du coffre est enveloppée par une clé AES dans l'AndroidKeyStore, qui utilise la puce de sécurité matérielle quand elle est disponible, et la rotation des clés est désormais réelle, grâce à la lignée de certificats de signature du schéma v3 : l'ancienne clé signe la preuve de rotation vers la nouvelle clé et l'APK est re-signé avec cette lignée. Le résultat est un niveau de risque Sûr, Prudence ou Dangereux, avec des preuves en texte. Si le système refuse la lecture de la mémoire, le contrôle est signalé comme impossible à vérifier, et non comme sûr ; et le fait qu'une clé utilise vraiment la puce de sécurité matérielle ne peut être confirmé que sur un appareil réel.

Architecte de mise en page en arbre de texte
Pour concevoir un écran sans le voir : ouvrez Architecte de mise en page en arbre de texte dans le menu principal, choisissez un projet et un fichier de mise en page, puis touchez Vérifier la mise en page. L'IDE lit la mise en page XML comme un arbre de texte et énonce une narration de position pour chaque élément (par exemple en bas à droite, 45 pour cent de la largeur de l'écran), puis signale les chevauchements entre éléments et les éléments qui sortent de l'écran pour une largeur de 360 dp, de façon mathématique. Ce qui est désormais calculé couvre LinearLayout et les tailles dp simples, le ConstraintLayout complet (toutes les contraintes, le biais, les chaînes, les guides, les barrières, les largeurs en pourcentage, le 0dp match_constraint et les rapports de dimensions) ainsi que les écrans Compose (Column, Row et Box avec leurs Modifiers de taille). Seuls MotionLayout et ConstraintSet modifiés à l'exécution sont toujours signalés comme position inconnue, car leurs valeurs n'existent que pendant que l'application tourne.

Studio de système de design
Pour harmoniser les espacements, la typographie et les coins sur tous les écrans et tous les projets : ouvrez Studio de système de design dans le menu principal, choisissez un projet, écrivez les jetons de design (par exemple jarak=8, huruf=16, sudut=12), choisissez un composant, puis touchez Générer des composants. L'IDE valide les jetons — espacement de base de 4 à 16 dp, taille de base de 12 à 20 sp, coins de 0 à 32 dp, et zone tactile minimale de 48 dp — puis écrit des composants XML prêts à l'emploi (komponen-studio.xml) avec un thème XML (tema-studio.xml) et un thème Compose (tema-studio.kt) dans le dossier du projet. Les jetons peuvent aussi être enregistrés comme un ensemble nommé dans la bibliothèque partagée de jetons entre projets, et une seule commande de synchronisation applique les jetons les plus récents de la bibliothèque à tous les projets qui utilisent cet ensemble. Les composants sont générés sous forme de texte à coller dans une mise en page, puis vérifiés avec l'Architecte de mise en page en arbre de texte ; l'ajustement à deux colonnes sur tablette utilise un qualificateur de largeur d'écran, et non la détection de l'appareil à l'exécution.

Refactorisation sémantique et navigation AST
Pour trouver des définitions et renommer des symboles sans casser d'autre code qui porte par hasard le même nom : ouvrez Refactorisation sémantique et navigation AST dans le menu principal, choisissez un projet, puis touchez Analyser les symboles du projet pour voir toutes les classes et méthodes avec leurs fichiers et numéros de ligne. Saisissez le nom d'un symbole, puis touchez de nouveau Analyser les symboles du projet pour voir sa définition et tous les fichiers qui l'appellent. Pour renommer, saisissez le nouveau nom, touchez Aperçu du renommage pour voir le nombre d'occurrences dans chaque fichier, puis touchez Appliquer le renommage. L'indexeur utilise désormais un analyseur AST fait maison (un analyseur lexical et un analyseur récursif pour Java et un sous-ensemble de Kotlin), de sorte que les renommages de méthodes entre fichiers sont résolus et que les appelants des autres fichiers sont aussi modifiés ; le bouton pour extraire un bloc de code en une nouvelle fonction est désormais sur cet écran. Cet analyseur reste minimal : les génériques très complexes, les annotations avec paramètres et les classes anonymes sont analysés tels quels, tandis que les appels par réflexion et par interface ne sont pas résolus.

Débogueur pas à pas et inspecteur de mémoire
Pour inspecter le contenu des variables au milieu du déroulement d'un programme sans deviner à travers les journaux : ouvrez Débogueur pas à pas et inspecteur de mémoire dans le menu principal, choisissez un projet, écrivez la trace d'exécution (une étape par ligne, sous la forme numéro de ligne, code, puis variables et valeurs séparées par |, par exemple 10|int total = harga * jumlah;|harga=5000, jumlah=3, total=15000), saisissez le numéro de ligne du point d'arrêt, puis touchez Exécuter la trace de débogage. L'IDE avance jusqu'au premier point d'arrêt et énonce la ligne active avec ses valeurs de variables par Jieshuo. Touchez Avancer d'une ligne pour avancer d'une ligne, Entrer dans la fonction pour entrer dans la fonction appelée (avec une pile d'appels), ou Continuer le programme pour avancer jusqu'au prochain point d'arrêt. Ce débogueur de trace suit toujours une trace enregistrée ou écrite à la main ; à côté, il existe un client pur Java du protocole filaire JDWP qui peut établir la poignée de main, poser des points d'arrêt, avancer à l'intérieur, par-dessus et à la sortie, et suspendre et reprendre la VM par TCP ou en mode écoute. Suspendre un vrai processus reste impossible en totalité depuis une application ordinaire, car la prise JDWP d'un processus n'est exposée que par adbd — le chemin éprouvé exige le débogage sans fil et le lancement de la cible par le shell, au-delà de ce que l'application elle-même peut faire.

Gestionnaire de dépendances hors ligne
Pour utiliser des bibliothèques tierces sans internet et éviter les conflits de versions avant la compilation : ouvrez Gestionnaire de dépendances hors ligne dans le menu principal, choisissez un projet, puis touchez Vérifier les dépendances. L'IDE lit tous les fichiers .gradle du projet, vérifie le coffre partagé entre projets dans le dossier Download/brankas-bersama, et résout les conflits — si deux bibliothèques demandent des versions différentes du même artefact, la version la plus élevée est utilisée et le conflit est signalé. Pour télécharger une bibliothèque, saisissez ses coordonnées (sous la forme groupe:artefact:version, par exemple com.google.code.gson:gson:2.10.1) puis touchez Vérifier les dépendances : en ligne, les fichiers AAR, JAR ou WHL sont vraiment téléchargés depuis Maven, Google ou PyPI avec leur graphe de dépendances transitives (récursif, cycles coupés, profondeur jusqu'à 25 niveaux), et seuls les fichiers téléchargés avec succès sont enregistrés comme disponibles. Hors ligne, seules les bibliothèques déjà présentes dans le coffre partagé peuvent être utilisées. Les plages de versions Maven ne sont pas résolues, et les fichiers téléchargés sont seulement vérifiés par leur SHA-1, sans vérification PGP.

Inspecteur de base de données et de stockage
Pour inspecter et tester le contenu de la base de données d'un projet sans écrire de code qui imprime le contenu des tables : ouvrez Inspecteur de base de données et de stockage dans le menu principal, choisissez un projet et un fichier de base de données (.db, .sqlite ou .sqlite3), puis touchez Ouvrir la base de données. L'IDE lit le schéma de toutes ses tables avec un analyseur complet de pages SQLite (arbre-B avec pages de débordement) et affiche les 20 premières lignes sous forme de tableau de texte lu à voix haute par Jieshuo. Écrivez une requête SELECT puis touchez Exécuter la requête (par exemple SELECT nama FROM pengguna WHERE kota = 'Makassar') — les requêtes prennent désormais en charge JOIN, GROUP BY, ORDER BY et LIKE, et sur le téléphone elles passent par le vrai moteur SQLite d'Android. Pour modifier une valeur, saisissez le numéro de ligne (1 = première ligne), le nom de colonne et la nouvelle valeur, puis touchez Modifier la valeur de la cellule — cette valeur est réécrite dans le fichier .db. Touchez Enregistrer la sauvegarde pour enregistrer l'état actuel de la table dans un fichier <nom-bd>.cadangan.txt du projet. SharedPreferences et DataStore peuvent aussi être lus. Ce qui ne peut toujours pas être lu : les bases de données chiffrées, les modifications WAL non validées, et les valeurs typées dans DataStore Proto spécial (affichées seulement comme une vue générique des champs).

Fabrique de tests unitaires et fuzzing
Pour trouver les failles de logique avant de partager une application : ouvrez Fabrique de tests unitaires et fuzzing dans le menu principal, choisissez un projet et un fichier de code, puis touchez Créer et exécuter les tests. L'IDE lit les signatures de fonctions du fichier, génère des cas de test normaux et limites (texte vide, null, nombres maximaux, caractères étranges), puis exécute vraiment ces tests : le code du projet est compilé et chaque méthode @Test est exécutée avec une limite de 5 secondes, de sorte que le résultat est fait de réussites et d'échecs réels avec leurs valeurs réelles. Le fuzzing s'exécute aussi vraiment sur les fonctions du projet (par réflexion, 2 secondes par appel, 20 méthodes au maximum), et le pourcentage de couverture des lignes est vraiment calculé par instrumentation qui conserve les numéros de ligne d'origine. Le résultat indique combien de tests ont réussi et échoué, combien de lignes de code et de fonctions ont été trouvées, et les cas de test créés. Les tests générés utilisent exactement la même API que JUnit, mais les définitions d'annotations et d'assertions sont écrites dans le fichier de test généré lui-même, car la vraie bibliothèque JUnit n'est pas fournie dans l'application.

Simulateur de conditions extrêmes de l'appareil et auditeur de fuites mémoire
Pour tester la résistance d'une application quand le système tue son processus, que le réseau tombe, que l'écran pivote ou que l'économiseur de batterie s'active : ouvrez Simulateur de conditions extrêmes de l'appareil et auditeur de fuites mémoire dans le menu principal, choisissez un projet, puis touchez Exécuter la simulation. L'IDE exécute trois scénarios de pression avec une simulation de rotation d'écran et suit les objets toujours retenus en mémoire après la fermeture de leur écran, puis signale les données perdues et les chaînes d'objets qui fuient. L'état de sauvegarde et de restauration est désormais lu dans la source du propre projet de l'utilisateur, et non dans un exemple fixe ; le serveur local de bouclage est vraiment arrêté au milieu du test pour mesurer la coupure du réseau ; un vrai vidage de tas est pris et analysé pour comparer deux vidages et suivre la chaîne de rétention depuis les racines du GC ; et le propre processus de l'application est vraiment tué après l'enregistrement de son état, puis on vérifie quelles données reviennent à la réouverture. Ce qui reste impossible depuis une application ordinaire : éteindre la radio ou le Wi-Fi du téléphone et forcer l'arrêt d'autres applications — les deux exigent une permission système ; à la place, les applications en arrière-plan sont tuées par killBackgroundProcesses, dont la permission est déjà dans le manifeste, avec une étiquette honnête sur l'écran.

Architecte de plans de projet
Pour transformer une grande idée d'application en plan de travail étape par étape : ouvrez Architecte de plans de projet dans le menu principal, choisissez un projet, écrivez l'idée de l'application (par exemple une application de caisse pour une petite épicerie avec paiements en plusieurs fois), puis touchez Créer un plan. L'IDE construit des modules, une liste de fichiers et de petits jalons, puis les enregistre dans cetak-biru.txt dans le dossier du projet. Touchez Marquer le prochain jalon comme terminé chaque fois qu'un jalon est terminé, ou touchez Charger le plan enregistré pour rouvrir un plan enregistré. Si un fournisseur d'IA actif est choisi dans Paramètres IA et que sa clé est disponible, le plan est construit par ce fournisseur ; s'il n'y a pas de clé ou si le fournisseur est injoignable, l'IDE retombe sur les motifs de mots-clés hors ligne et dit cette limite honnêtement. Une réponse du fournisseur est seulement vérifiée pour son format (modules et jalons présents), et non pour la véracité de son contenu — relisez toujours le plan avant de construire.

Narrateur du flux logique du code
Pour comprendre un long code sans écouter la syntaxe ligne par ligne : ouvrez Narrateur du flux logique du code dans le menu principal, choisissez un projet et un fichier de code, puis touchez Narration du code. L'IDE transforme chaque ligne en une phrase en indonésien (par exemple si le total est supérieur à 100000, alors exécuter le bloc suivant), affiche une carte des appels entre méthodes et une analyse de flux de données entre méthodes (valeurs transmises, utilisées ou ignorées), et signale des bogues subtils possibles avec leurs numéros de ligne — String comparé avec ==, un flux ouvert sans être fermé, et une variable écrite dans deux méthodes différentes. Si un fournisseur d'IA actif est choisi dans Paramètres IA, un résumé du flux de ce fournisseur est aussi disponible ; sinon, l'écran utilise la narration hors ligne et dit cette limite. La narration, la carte des appels et le flux de données utilisent une analyse hors ligne par motifs de texte, et non un analyseur AST complet — les méthodes dont l'accolade ouvrante est sur sa propre ligne, les champs de classe et les appels par réflexion ne sont pas suivis — et des avertissements de course de données peuvent apparaître pour une variable qui n'est en réalité utilisée qu'à tour de rôle.

Fabrique de bundles d'application et préparation au Play Store
Pour préparer une application pour le Google Play Store directement depuis le téléphone : ouvrez Fabrique de bundles d'application et préparation au Play Store dans le menu principal, choisissez un projet, puis touchez Créer un bundle AAB. L'IDE construit le fichier .aab à partir du manifeste, des ressources et des actifs du projet avec un vrai BundleConfig.pb, valide la structure du bundle, puis divise le bundle en vrais APK variants (de base, par architecture, par langue et universel) avec des tailles mesurées à partir de cette division, et non estimées. Le bundle est signé en JAR v1 avec la même clé de projet que la signature des APK, et sa chaîne de signature est vérifiée cryptographiquement. Cet écran audite aussi la préparation à Play — un SDK cible inférieur à 35 est marqué Élevé car le Play Store exige 35 ou plus, et une bibliothèque 64 bits manquante est aussi marquée Élevé. Un vrai bundletool ne peut pas tourner sur l'appareil, car bundletool exige une JVM alors qu'Android n'en a pas ; le chemin ci-dessus est le plus proche réel sur l'appareil.

Moteur de mise à jour OTA et déploiements progressifs
Pour envoyer une petite correction sans obliger les utilisateurs à télécharger tout l'APK à nouveau : ouvrez Moteur de mise à jour OTA et déploiements progressifs dans le menu principal, choisissez un projet, écrivez le contenu de l'ancienne et de la nouvelle version, puis touchez Créer un paquet de correctif. L'IDE calcule la différence et crée un paquet de correctif (patch-ota.zip) avec une empreinte SHA-256 du nouveau contenu, puis vérifie si cet appareil fait partie de la première étape de déploiement de 10 pour cent. Les correctifs prennent désormais en charge les deltas binaires sur n'importe quel fichier (y compris DEX et APK), sont empaquetés avec une signature RSA-2048 et vérifiés avec une clé publique de confiance avant d'être appliqués, et peuvent être téléchargés depuis le serveur du développeur avec sa liste de versions ; si l'application échoue, l'ancien fichier reste intact. Appliquer un correctif à l'application en cours d'exécution se fait par une nouvelle signature avec la clé du projet et le PackageInstaller, car remplacer le code d'un processus en cours depuis lui-même est impossible — l'APK est verrouillé et le DEX est déjà chargé.

Studio de révision de code en équipe
Pour relire les modifications d'un collègue et résoudre les conflits de fusion sans lire les marques en flèche de Git : ouvrez Studio de révision de code en équipe dans le menu principal, choisissez un projet, saisissez trois versions de texte (base, locale, collègue), puis touchez Ouvrir la révision d'équipe. L'IDE fusionne les trois en se basant sur les unités syntaxiques Java — deux modifications sur la même ligne mais dans des instructions différentes ne sont plus traitées comme un conflit — et affiche chaque conflit comme un choix de vote : Utiliser la version locale, Utiliser la version du collègue, ou Fusionner les deux — la ligne résultante est insérée à la position d'origine du conflit pour que l'ordre reste correct — puis écrit le résultat dans gabung-hasil.txt dans le projet. En dessous se trouve le tableau des tâches du projet : saisissez le titre d'une tâche puis touchez Ajouter une tâche ; les tâches sont enregistrées comme texte dans le dossier .tugas du projet et synchronisées par des commits dans le Git de l'application, de sorte que le tableau peut être relu depuis n'importe quel historique de commits. Ce découpeur syntaxique n'est pas un analyseur AST complet et le Git de l'application enregistre un instantané complet par commit ; il n'y a pas de serveur de synchronisation spécial.

Dictée de structure de code
Pour écrire du code à la voix dans l'éditeur : ouvrez un projet dans l'éditeur, puis touchez le bouton Dictée de structure de code. Dites des commandes en indonésien, par exemple buat fungsi tambah dengan parameter a angka dan b angka, buat kelas Mobil ou buat variabel teks nama sama dengan Budi — l'IDE transforme la voix en un bloc de code Java, Kotlin, Python ou Compose syntaxiquement valide et l'insère à la position du curseur, puis lit à voix haute un bref résumé via Jieshuo. La dictée utilise le service de saisie vocale intégré du système, sans autorisation de microphone supplémentaire, et ne reconnaît que les motifs de commandes déjà enregistrés ; la voix en dehors de ces motifs n'est pas transformée en code. Les nombres dits avec des mots (par exemple 'lima') ne sont pas encore transformés en chiffres.

Espace de collaboration local (sans internet)
Pour travailler ensemble dans une même pièce sans internet : ouvrez Collaboration dans le menu principal, puis ouvrez la section Espace de collaboration local. Un téléphone ouvre une session (l'IDE affiche une adresse IP locale et un code PIN à 6 chiffres), un autre téléphone rejoint avec cette adresse et ce PIN. Les changements de texte sont envoyés sous forme de différences de lignes, un APK compilé peut être envoyé au téléphone du testeur, et les rapports de plantage du téléphone du testeur sont reçus en retour. Une session est pour un seul ami ; si deux personnes modifient exactement la même ligne en même temps, c'est la dernière modification qui est utilisée. Le PIN est envoyé en texte clair sur le réseau local. Cette salle n'a pas encore été testée sur un vrai téléphone.

Paramètres IA
Pour configurer le fournisseur d'IA et les clés API pour la création d'applications : dans le menu principal, dans le groupe Paramètres, touchez Paramètres IA (à côté du bouton Connecteur). Choisissez le fournisseur à utiliser dans la liste disponible, et cochez Changer de modèle en cas d'erreur du fournisseur pour que, si un modèle échoue, l'IDE essaie automatiquement le modèle suivant du même fournisseur. Touchez Gérer les clés API pour ajouter des clés de secours (saisissez le nom et la clé, puis touchez Enregistrer ; les clés sont affichées masquées, seuls les 4 derniers caractères sont visibles). Les clés sont stockées sur le téléphone et ne sont jamais envoyées ailleurs qu'au fournisseur choisi lors de la création d'une application. Le fournisseur choisi est désormais vraiment utilisé par l'Architecte de plans de projet et le Narrateur du flux logique du code ; la création d'applications sur l'écran Créateur d'applications par IA utilise toujours l'IA locale du téléphone (sans internet).

Connecteur
Pour analyser un APK puis l'envoyer : dans le menu principal, dans le groupe Paramètres, touchez Connecteur (à côté du bouton Paramètres IA). Choisissez un fichier APK sur le téléphone, l'IDE lit son contenu (nom de package, version, liste des activités), puis touchez Envoyer l'APK pour l'envoyer via le menu de partage du système (par exemple WhatsApp ou Drive).

Langue et voix
Pour changer la langue de l'application : ouvrez Paramètres, puis Langue de l'application, puis choisissez une langue ou Suivre le système. L'écran principal et la plupart des écrans passent immédiatement à la langue choisie sans fermer ni redémarrer l'application ; certains écrans (par exemple Terminal, Collaboration, Paramètres IA et Gérer les clés) utilisent encore l'ancienne langue jusqu'à leur réouverture. Si vous choisissez Suivre le système, la langue suit la langue du système du téléphone.

Signature par défaut par projet et Anti Tamper
Depuis la version 5.7, un projet qui n'utilise pas de signature personnelle est signé avec la clé intégrée PROPRE à ce projet (créée une fois dans le dossier tanda-tangan-bawaan à l'intérieur du projet, puis utilisée ensuite), donc la signature intégrée diffère d'un projet à l'autre — ce n'est plus une clé partagée pour toutes les applications. Ne supprimez pas le dossier tanda-tangan-bawaan : sans cette clé, un nouvel APK ne peut pas écraser l'ancien APK du même projet. Les réglages de chaque projet (architecture séparée, signature personnelle, anti-falsification, keystore choisi, SDK) sont désormais enregistrés dans le fichier settings.gradle à l'intérieur du projet et relus chaque fois que le projet est compilé. Dans Paramètres, dans la catégorie Signature, il y a une case Anti-falsification de l'application compilée : si elle est active, l'application compilée sur l'appareil vérifie sa signature et le contenu de son dex chaque fois qu'elle est ouverte ; si elle a été re-signée ou modifiée par quelqu'un d'autre, l'application refuse de fonctionner. Les outils de débogage et d'injection comme Frida/Xposed sont aussi détectés, et la fenêtre de l'application est verrouillée contre l'enregistrement d'écran.

Créateur de vidéo de démonstration
Pour créer une vidéo de démonstration d'une application compilée : ouvrez Créateur de vidéo de démonstration dans le menu principal, choisissez le projet, remplissez le titre de la vidéo, puis appuyez sur Créer un Script de Vidéo Démo — l'IDE écrit video-demo.txt contenant 5 scènes standard (ouverture, vue principale, fonction 1, fonction 2, fermeture) avec le texte de narration et la durée de chaque scène. Appuyez sur Créer un Diaporama HTML pour créer video-demo.html à partir des images du projet (icône + captures d'écran s'il y en a) qui changent automatiquement toutes les 5 secondes. Ce n'est PAS une vidéo .mp4 — pour une vraie vidéo, ouvrez video-demo.html dans le navigateur du téléphone puis enregistrez l'écran, ou lisez la narration dans video-demo.txt tout en enregistrant l'application en cours d'exécution.

Nouvelle apparence façon Android Studio
L'apparence de l'IDE est désormais rangée pour ressembler à Android Studio (seulement l'apparence — tous les boutons, menus et flux restent exactement comme avant) : un fond gris clair, des titres d'écran en gras et noirs, des boutons bleus avec du texte blanc et des zones de saisie blanches avec un bord fin. Le menu principal est regroupé visuellement (Fonctions de création, Cloud, thème et autres, Voix, code et nouvelles fonctions, Outils) sans changer l'ordre des boutons. Le Terminal utilise toujours un panneau sombre comme la fenêtre du Terminal d'Android Studio, et l'éditeur de code a toujours un fond blanc avec du texte noir. Tout le texte reste lu clairement par Jieshuo.

Paramètres
Pour régler l'application : ouvrez le menu Options sur l'écran principal puis appuyez sur Paramètres. À l'intérieur il y a 12 catégories : Paramètres GitHub (sécurité, signature personnelle, historique de compilation et jeton GitHub), Paramètres de compilation d'APK sur l'appareil (enregistrer le mot de passe du keystore et l'historique de compilation sur l'appareil), Thème (couleurs de l'application), Signature (créer un keystore pour une signature personnelle et la case anti-falsification de l'application compilée), Dossier de projets (emplacement du dossier de projets), Langue et voix (langue de l'interface et vitesse de la voix du Mode vocal), Taille du texte et apparence (taille de la police de l'éditeur), Compilation (SDK cible par défaut et division d'architecture par défaut pour l'écran Créer le projet), Notifications (son quand une compilation se termine), Sauvegarde automatique (planning de sauvegarde des projets), Profil du développeur (nom, numéro WhatsApp et compte affichés sur l'écran de don) et Confidentialité et données (réinitialiser les réglages et supprimer les données de l'application). Chaque catégorie a un bouton Retour pour revenir au menu des catégories. Les réglages qui viennent d'être enregistrés (pas encore appliqués) ont leur explication écrite honnêtement à l'écran.

Faire un don au développeur
Pour faire un don ou saluer le développeur : appuyez sur le bouton Faire un don au développeur sur l'écran principal, à côté du bouton À propos de l'outil. Sur l'écran de don il y a un bouton Copier le compte BRI — appuyez pour copier le numéro de compte du développeur, puis collez-le dans votre application bancaire. Il y a aussi une section Saluer le développeur sur WhatsApp : remplissez votre nom et votre ville d'origine, puis appuyez sur Envoyer sur WhatsApp — WhatsApp s'ouvre avec le message de salutation déjà rempli, appuyez simplement sur Envoyer dans WhatsApp puis revenez à l'application. WhatsApp ne permet pas aux autres applications d'envoyer des messages automatiquement, l'envoi se fait donc toujours par vous-même dans WhatsApp.

Commandes favorites du terminal
Pour enregistrer les commandes souvent utilisées dans le Terminal : ouvrez le Terminal puis appuyez sur Favori. Touchez Ajouter un nouveau favori, remplissez le nom (par exemple Voir le fichier) et sa commande (par exemple ls -la), puis appuyez sur Enregistrer — le favori est enregistré définitivement sur le téléphone. Touchez le nom d'un favori pour l'exécuter directement dans le terminal ; touchez Supprimer un favori puis choisissez-en un pour le supprimer (avec confirmation). Il y a déjà 3 favoris intégrés : Voir le fichier (ls -la), Vérifier l'espace (df -h) et Effacer l'écran (clear) — tous peuvent être supprimés. Une commande vide ne peut pas être enregistrée ni exécutée ; le Terminal vous le dit par un message et par la voix si cela arrive.

Analytique et qualité
Pour voir un résumé de l'utilisation de l'application et les rapports de plantage : appuyez sur le bouton Analytique et qualité sur l'écran principal, à côté du bouton Faire un don au développeur. Cet écran montre combien de fois l'application a été ouverte, les écrans les plus souvent ouverts, le nombre de plantages et la liste des derniers plantages avec une brève suggestion de correction. Ces données sont seulement enregistrées sur votre téléphone et ne sont envoyées nulle part. Il y a un bouton Supprimer les données analytiques avec une boîte de confirmation pour supprimer toutes ces données. Le dernier écran n'est enregistré que pour l'écran principal et cet écran.
