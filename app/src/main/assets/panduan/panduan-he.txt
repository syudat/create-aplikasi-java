ברוכים הבאים ל-Create Aplikasi מאת Al Kautsar
Create Aplikasi היא אפליקציה לבניית אפליקציות Android הפועלת ישירות בטלפון, ללא צורך במחשב נייד. אפליקציה זו מאפשרת לכל אחד ליצור אפליקציות Android משלו, כולל משתמשים שרק מתחילים ללמוד ליצור אפליקציות ומשתמשי קורא מסך. המדריך המלא לשימוש באפליקציה זו זמין במסך "אודות הכלי" הזה.

מהי האפליקציה הזו ולמי היא מיועדת
Create Aplikasi היא כלי לבניית אפליקציות Android הפועל בטלפון. אפליקציה זו מיועדת לכל מי שרוצה ליצור אפליקציות Android משלו, כולל מתחילים ומשתמשי קורא מסך. אפליקציה זו מספקת עורך קוד, לחצן "הפעל" לבדיקת פרויקטים, לחצן "בנה" ליצירת APK, ותפריטים לחתימה ולהתקנה של ה-APK.

מטרת האפליקציה הזו
אפליקציה זו נוצרה כדי שכל אחד יוכל ליצור אפליקציות Android משלו בקלות, ישירות מהטלפון. הממשק שלה נעשה פשוט ככל האפשר כדי שגם משתמשים חדשים יוכלו לנסות אותה מיד.

כיצד ליצור פרויקט חדש, צעד אחר צעד
1. לחצו על "צור פרויקט" בתפריט הראשי.
2. בחרו את סוג הפרויקט: HTML, אתר אינטרנט, Java, Kotlin, Compose או Python.
3. מלאו את שם האפליקציה, לדוגמה: Garuda Decode.
4. מלאו את שם החבילה (package name), לדוגמה: com.android.garudadecode. שם החבילה חייב להשתמש באותיות קטנות ולהיות מורכב משני חלקים לפחות המופרדים בנקודות.
5. מלאו את גרסת האפליקציה, לדוגמה: 1.0, ואת קוד הגרסה בצורת מספר, לדוגמה: 1. אם השדה נשאר ריק, הגרסה תמולא אוטומטית ב-1.0 וקוד הגרסה ב-1.
6. מלאו את ה-SDK המינימלי ואת ה-SDK היעד במידת הצורך. אם השדות נשארים ריקים, ייעשה שימוש בערכי ברירת המחדל. ה-SDK המינימלי הוא גרסת ה-Android הנמוכה ביותר הנתמכת, לדוגמה: 21 פירושו Android 5.0. ה-SDK היעד המרבי הוא 36 (Android 16).
7. לחצו על הלחצן "בחר הרשאות" כדי לבחור את הרשאות האפליקציה, לדוגמה: INTERNET. הרשאת INTERNET כבר מסומנת כברירת מחדל. סמנו רק את ההרשאות שהאפליקציה באמת זקוקה להן.
8. אם תרצו, סמנו את "השתמש בארכיטקטורות נפרדות של 64 ביט ו-32 ביט" כדי שגודל ה-APK יהיה קטן יותר, וסמנו את "השתמש בחתימה אישית" אם ברצונכם להשתמש ב-keystore משלכם.
9. לחצו על "צור פרויקט". הפרויקט החדש נשמר בתיקיית Download/project ומופיע מיד ב"נהל פרויקטים".

סוגי הפרויקטים הזמינים
• HTML: תצוגה מתוך index.html, style.css ו-script.js, הפועלת דרך WebView. נבנה ישירות בטלפון.
• אתר אינטרנט: אתר עם תפריט (דף הבית, אודות, צור קשר) מתוך index.html, tentang.html, kontak.html, style.css ו-script.js, הפועל דרך WebView. נבנה ישירות בטלפון.
• Java: נבנה בטלפון. MainActivity נמצא ב-app/src/main/java/<nama-paket>/MainActivity.java. התצוגה מתוך app/src/main/res/layout/activity_main.xml, הטקסט מתוך app/src/main/res/values/strings.xml, והערכה מתוך app/src/main/res/values/styles.xml.
• Kotlin: ניתן לבנות במכשיר (לא מקוון) באמצעות מהדר Kotlin הכלול באפליקציה, או דרך GitHub Actions. MainActivity נמצא ב-app/src/main/java/<nama-paket>/MainActivity.kt, וקובצי ה-res זהים לאלה של פרויקט Java. הבנייה הראשונה של Kotlin איטית יותר בגלל גודלו הגדול של המהדר, וקובצי .java המפנים למחלקות Kotlin עדיין אינם ניתנים לבנייה (קובצי .java מהודרים לפני קובצי .kt).
• Compose: אפליקציית Android מודרנית שהממשק שלה נוצר עם Jetpack Compose (לא פריסת XML). MainActivity נמצא ב-app/src/main/java/<nama-paket>/MainActivity.kt. פרויקטי Compose נבנים דרך GitHub Actions (תפריט "בנה פרויקט", ואז "בנה מקוון") או ב-Termux עם Gradle, מכיוון ש-Compose דורש את ספריות Jetpack Compose שאינן זמינות במכשיר.
• Python: לוגיקת האפליקציה נכתבת בשפת Python (Chaquopy) ב-app/src/main/python/main.py, ומופעלת על ידי המארח MainActivity.java ב-app/src/main/java/<nama-paket>/MainActivity.java. פרויקטי Python ניתנים לבנייה ישירות בטלפון (זמן הריצה של Chaquopy כלול באפליקציה) וגם דרך GitHub Actions. ה-SDK המינימלי של פרויקט Python הוא 24 (Android 7.0).

שנה ארכיטקטורת פרויקט
כדי לשנות את אפשרויות הארכיטקטורה של פרויקט קיים מבלי ליצור פרויקט חדש: לחצו על «שנה ארכיטקטורת פרויקט» בתפריט הראשי, בחרו לאחר מכן את הפרויקט ושנו את תיבת הסימון «בנה APK של 64 סיביות (arm64-v8a)» או «בנה APK של 32 סיביות (armeabi-v7a)»; או לחצו לחיצה ארוכה על שם הפרויקט ב«ניהול פרויקטים» ובחרו «שנה ארכיטקטורה» כדי לפתוח את אותו מסך ישירות עבור אותו פרויקט. הכלל הוא: אם שתי תיבות הסימון מסומנות, הבנייה יוצרת שני קבצי APK נפרדים, אחד של 64 סיביות ואחד של 32 סיביות; אם רק תיבת סימון אחת מסומנת, הבנייה יוצרת קובץ APK אוניברסלי אחד שממשיך לרוץ הן במכשירי 64 סיביות והן במכשירי 32 סיביות. קובץ APK נפרד עבור וריאנט אחד בלבד עדיין אינו נתמך, מכיוון שנתיב הבנייה מכיר רק את הבחירה המפוצלת או האוניברסלית, אך הבחירה של כל וריאנט נשארת שמורה בתוך הפרויקט, כדי שלא תאבד כאשר המסך נפתח שוב.

מבנה הקבצים של פרויקטי Java, HTML, אתר אינטרנט, Kotlin, Compose ו-Python
פרויקטי Java, HTML, אתר אינטרנט, Kotlin, Compose ו-Python מסודרים כמו פרויקטי Android בדרך כלל. בתוך תיקיית app נמצאת תיקיית src, ובתוכה נמצאת תיקיית main. בתוך תיקיית main נמצא AndroidManifest.xml לצד תיקיית java, תיקיית res המכילה את layout/activity_main.xml ואת values/strings.xml וכן values/styles.xml, ועבור HTML ואתר אינטרנט קיימת תיקיית assets המכילה את index.html (לאתר אינטרנט יש גם tentang.html ו-kontak.html). לפרויקטי HTML ואתר אינטרנט יש גם MainActivity משלהם ב-app/src/main/java/<nama-paket>/MainActivity.java, הטוען את index.html ב-WebView ומשמש כמפעיל (launcher) ב-AndroidManifest. לפרויקט Python יש קוד Python ב-app/src/main/python/main.py ומארח MainActivity.java ב-app/src/main/java/<nama-paket>/MainActivity.java. ניתן לפתוח ולשנות את AndroidManifest.xml, הפריסה, strings ו-styles בעורך, בדיוק כמו את MainActivity. פרויקטים ישנים שהמניפסט שלהם עדיין נמצא לצד תיקיית app עדיין ניתנים לבנייה, מכיוון שבזמן הבנייה האפליקציה בודקת תחילה את AndroidManifest.xml ב-app/src/main/, לאחר מכן את זה שלצד תיקיית app, ולבסוף את קובץ נתוני הפרויקט.

כללי ההרשאות (חשוב)
ההרשאות המסומנות בעת יצירת פרויקט נרשמות במקום אחד בלבד, בהתאם לסוג הפרויקט. עבור פרויקטי Java, HTML, אתר אינטרנט, Kotlin, Compose ו-Python, ההרשאות המסומנות נרשמות רק ב-AndroidManifest.xml הנמצא ב-app/src/main/, לצד תיקיית java, בתוך תיקיית הפרויקט. קובץ נתוני הפרויקט עבור פרויקטי Java, HTML, אתר אינטרנט, Kotlin, Compose ו-Python אינו מכיל רשימת הרשאות. אם תבחרו ב-Java ואז תסמנו את INTERNET ואת CAMERA, מה שיירשם ב-AndroidManifest.xml הוא רק INTERNET ו-CAMERA, ללא הרשאות נוספות שיצטרפו. בזמן הבנייה, האפליקציה קוראת את ההרשאות מאותו מקום: מתוך AndroidManifest.xml ב-app/src/main/ עבור פרויקטי Java, HTML, אתר אינטרנט, Kotlin, Compose ו-Python (אם אינו קיים, מתוך AndroidManifest.xml שלצד תיקיית app עבור פרויקטים ישנים), ומתוך קובץ נתוני הפרויקט עבור פרויקטים ישנים.

כיצד להשתמש בעורך
פתחו את "נהל פרויקטים", הקישו על שם הפרויקט כדי לפתוח את העורך. בעורך ניתן לפתוח קבצים, לכתוב קוד ולשמור שינויים. עבור פרויקטי Java, HTML, אתר אינטרנט, Kotlin, Compose ו-Python, הקבצים מסודרים בתוך תיקיית app/src/main. כדי לשתף פרויקט, השתמשו ב"ייצא ZIP" (ראו את הסעיף להלן).

כיצד להפעיל פרויקט
בעורך, לחצו על "הפעל" כדי לבדוק את הפרויקט. עבור פרויקטי HTML ואתר אינטרנט, מה שמופעל הוא index.html דרך WebView. אם מתרחשת שגיאה, קראו את הודעת השגיאה, תקנו את הקוד, ואז הפעילו שוב.

כיצד לבנות APK
בעורך, לחצו על "בנה". ישנן שתי דרכים לבנות. ראשית, בנייה במכשיר: בנייה ישירות בטלפון ללא אינטרנט, עבור פרויקטי HTML, אתר אינטרנט, Java, Kotlin ו-Python. שנית, בנייה מקוונת דרך GitHub Actions: בנייה דרך האינטרנט ב-GitHub, וניתן להשתמש בה עבור כל סוגי הפרויקטים. פרויקטי Compose ניתנים לבנייה רק בדרך השנייה (בנייה מקוונת) או ב-Termux עם Gradle, מכיוון ש-Compose דורש את ספריות Jetpack Compose שאינן זמינות במכשיר. תוצאת הבנייה הראשונה עדיין אינה חתומה. לאחר מכן האפליקציה חותמת עליה: אוטומטית עם מפתח ברירת המחדל, או עם חתימה אישית אם התיבה "השתמש בחתימה אישית" סומנה בעת יצירת הפרויקט.

כיצד להתקין APK
כאשר ה-APK מוכן, לחצו על "התקן" כדי להתקין אותו. ב-Android 8 ומעלה, הטלפון יבקש תחילה "אפשר ממקור זה", מכיוון שאפליקציה זו מתקינה APK מחוץ ל-Play Store. הפעילו את ההרשאה הזו פעם אחת בהגדרות, ואז חזרו לאפליקציה: ההתקנה תמשיך אוטומטית מבלי שתצטרכו ללחוץ שוב על "התקן". אם לחצן "התקן" אינו מופיע, ודאו שהבנייה הסתיימה ושה-APK נוצר.

כיצד לחתום על אפליקציה
כל APK חייב להיות חתום כדי שניתן יהיה להתקין אותו. קיימות שתי אפשרויות. ראשית, מפתח ברירת המחדל: האפליקציה חותמת בעצמה אוטומטית, ללא צורך לעשות דבר. שנית, חתימה אישית: צרו תחילה keystore דרך תפריט "צור Keystore" בתפריט הראשי, שמרו את הסיסמה שלו היטב, ואז סמנו את "השתמש בחתימה אישית" בעת יצירת הפרויקט. ה-keystore נשמר ב-Download/project/signing.

ייצוא פרויקט ל-ZIP
ייצוא ZIP מסופק כדי שניתן יהיה לשתף פרויקטים עם חברים. כך עושים זאת: ב"נהל פרויקטים", לחצו לחיצה ארוכה על שם הפרויקט, ואז בחרו "ייצא ZIP". התוצאה נשמרת ב-Download/project/<NamaProyek>.zip. תיקיית bin אינה כלולה, כך שהגודל קטן, רק כמה עשרות KB. ניתן לשלוח את קובץ ה-ZIP הזה לחברים או להעלות אותו ל-GitHub.

הרחבת JAWS
הרחבת JAWS משתמשת במנוע ההרחבות של Jieshuo (CSR), ולא בקורא המסך שלו. כך, העיצוב עדיין יכול לפעול גם כאשר המשתמש משתמש ב-TalkBack. כך עושים זאת: פתחו את "הרחבת JAWS" בתפריט הראשי. מכיוון שהלחיצה האוטומטית פועלת מעצמה, יש להפעיל תחילה את השירות בהגדרות הנגישות. לאחר מכן ניתן ליצור עיצוב חדש: הקלידו את שם העיצוב, לחצו על OK, ואז מלאו את התיבה שלו.

רשימת הלחיצות מופרדת כדי שיהיה מסודר
בתוך העיצוב ישנן שתי תיבות: תיבת הסקריפט ותיבת רשימת הלחיצות. רשימת הלחצנים נשמרת בנפרד בקובץ daftar_klik.txt, שם אחד בכל שורה. דוגמה לתוכנה: tombolSimpan, tombolHapus, tombolBuka. כדי לפתוח אפליקציה, פשוט כתבו >WhatsApp ברשימה הזו. עיצובים ישנים שעדיין אין להם קובץ daftar_klik.txt יציגו את הדוגמה המובנית הזו.

פונקציות פשוטות המסופקות
• klikTombol("tombolSimpan") — לחיצה על לחצן אחד לפי הטקסט שלו.
• klikDaftarTombol(daftar) — לחיצה על הרשימה שב-daftar_klik.txt, לחצן אחד בכל שורה, לפי הסדר, ואז הודעה כמה הצליחו וכמה לא נמצאו.
• bukaAplikasi("WhatsApp") — פתיחת אפליקציה לפי שמה, או כתיבת ">WhatsApp" ברשימה.
• klik(540, 1200) — לחיצה בקואורדינטות המסך.
כל הפונקציות נעשו פשוטות תחילה. כאשר תתרגלו אליהן, ניתן יהיה להוסיף פונקציות נוספות בהמשך.

אודות קוראי מסך
אפליקציה זו תוכננה להיות ידידותית לקוראי מסך. לכל שדה מילוי יש תווית ודוגמת מילוי, וניתן להגיע לכל הלחצנים ללא מחוות מסובכות. הרחבת JAWS נוצרה כדי שתוכל להמשיך לפעול גם כאשר המשתמש משתמש ב-TalkBack, מכיוון שמה שמשתמשים בו הוא מנוע ההרחבות שלה, ולא קורא המסך שלה.

פרטיות ואבטחה
הפרויקטים וה-keystore שמורים בטלפון שלכם. אסימון GitHub משמש רק לבנייה מקוונת ונשמר בתוך אפליקציה זו. אל תשתפו את האסימון או את סיסמת ה-keystore שלכם עם אף אחד. אם אתם משתמשים בחתימה אישית, שמרו את ה-keystore ואת הסיסמה שלו במקום בטוח, מכיוון שאם הם יאבדו, לא ניתן יהיה לעדכן APK ישן באותה חתימה.

דרישות
Android 5.0 או חדש יותר. הרשאת אחסון: ב-Android 11 ומעלה נעשה שימוש בהרשאת גישה לכל הקבצים, ב-Android 10 ומטה נעשה שימוש בהרשאת אחסון רגילה (קריאה/כתיבה באחסון) מכיוון של-Android 10 אין הרשאת גישה לכל הקבצים. בנייה במכשיר דורשת טלפון עם מעבד ARM (32 או 64 ביט). בנייה מקוונת דרך GitHub Actions דורשת אינטרנט ואסימון GitHub. פרויקטי Kotlin ניתנים לבנייה במכשיר, אך הבנייה הראשונה שלהם איטית יותר ומשתמשת ביותר זיכרון בגלל גודלו הגדול של מהדר Kotlin. פרויקטי Compose נבנים דרך GitHub Actions או ב-Termux עם Gradle. פרויקטי Python דורשים Android 7.0 או חדש יותר (SDK מינימלי 24) וה-APK המתקבל גדול יותר מכיוון שהוא כולל את זמן הריצה של Python (Chaquopy) יחד עם הספרייה הסטנדרטית שלו.

Terminal
תפריט Terminal במסך הראשי פותח מסוף בתוך אפליקציה זו. ניתן להשתמש בפקודות כמו ls כדי לראות את תוכן תיקיית הפרויקט, cd כדי לעבור בין תיקיות, ו-git כדי לנהל קוד. פלט הפקודות מופיע כטקסט שקורא מסך יכול לקרוא, וקיים לחצן "הקרא תוצאה" כדי להאזין לתוצאה האחרונה. מסוף זה משתמש במעטפת המערכת של הטלפון, כך שתוכניות אינטראקטיביות כמו nano ו-vim עדיין אינן ניתנות לשימוש כאן.

רישיון (גרסה בתשלום)
כדי למכור אפליקציה, סמנו את "הפעל רישיון" בעת יצירת הפרויקט, ואז מלאו את מספר ה-WhatsApp שלכם. האפליקציה שתיבנה תבקש קוד רישיון כשתיפתח לראשונה: המשתמש רואה את מזהה המכשיר שלו, לוחץ על הלחצן "שלח מזהה מכשיר" כדי לשלוח את המזהה הזה ל-WhatsApp שלכם, ואז אתם משיבים עם קוד הרישיון שלו. קוד הרישיון מחושב מתוך מזהה המכשיר וסיסמת הפרויקט (lisensi_seed בקובץ נתוני הפרויקט) — שמרו את הסיסמה הזו היטב ואל תשתפו אותה. לאחר שהוזן הקוד הנכון, האפליקציה נפתחת ואינה מבקשת שוב קוד.

יוצר האייקונים האוטומטי
אייקוני פרויקטים חדשים עדיין שקופים, ולכן זמין "יוצר אייקונים" בתפריט הראשי. כך עושים זאת: לחצו על "יוצר אייקונים", כתבו אות אחת או שתיים (לדוגמה ראשי התיבות של שם האפליקציה), בחרו את צבע הרקע ואת צבע הכתב, צפו בתצוגה המקדימה, ואז לחצו על "שמור לפרויקט" כדי להשתמש באייקון הזה בפרויקט שנבחר, או על "שמור ל-Download" כדי להשתמש בקובץ ה-PNG שלו במקום אחר. לאחר יצירת פרויקט, האפליקציה מציעה גם ליצור אייקון. ניתן להחליף את האייקון הישן של פרויקט בכל עת מתפריט הפרויקט ב"נהל פרויקטים" (לחצו לחיצה ארוכה על שם הפרויקט, ואז בחרו "החלף אייקון").

תבניות פרויקטים מוכנות לשימוש
אם אינכם רוצים להתחיל מפרויקט ריק, בחרו תבנית בעת יצירת הפרויקט: מחשבון (Java), הערות (Java), רשימת משימות (Kotlin), מחשבון אינטרנט (HTML), אתר פרופיל (אתר אינטרנט), או מונה (Compose). בחירת תבנית משנה אוטומטית את סוג הפרויקט בהתאם לתבנית, והפרויקט נוצר עם קוד התחלתי מוכן — נשאר רק להפעיל או לשנות אותו. אם סוג הפרויקט משתנה שוב ידנית לאחר בחירת התבנית, התבנית מבוטלת והפרויקט חוזר להיות ריק. עבור תבניות HTML ואתר אינטרנט, התבנית מחליפה את תוכן index.html, כולל סקריפט ה-HTML שהוקלד בטופס.

גיבוי ושחזור פרויקטים
כדי שפרויקטים לא יאבדו, קיימת תכונת גיבוי. כך עושים זאת: ב"נהל פרויקטים", לחצו לחיצה ארוכה על שם הפרויקט, ואז בחרו "גבה". הגיבוי נשמר כ-ZIP בתיקיית Download/backup עם שם הפרויקט והתאריך, לדוגמה: GarudaDecode-2026-11-14-123045.zip. תוכנו זהה לייצוא ZIP (כל תוכן הפרויקט, ללא תיקיית bin). כדי לשחזר: פתחו את התפריט ב"נהל פרויקטים", בחרו "שחזר גיבוי", ואז בחרו את קובץ הגיבוי שלו. אם שם הפרויקט כבר קיים, האפליקציה תשאל: החלף את הפרויקט הישן, או שמור בשם חדש.

שיתוף וייבוא פרויקטים
כדי לשתף פרויקט עם חבר: ב"נהל פרויקטים", לחצו לחיצה ארוכה על שם הפרויקט, ואז בחרו "שתף". הפרויקט נשלח כ-ZIP דרך אפליקציית שיתוף (WhatsApp, Telegram ואחרות). כדי לקבל פרויקט מחבר: פתחו את התפריט ב"נהל פרויקטים", בחרו "ייבא פרויקט", ואז בחרו את קובץ ה-ZIP שלו. קובץ ה-ZIP הזה חייב להכיל קובץ נתוני פרויקט — אם אין בו, הקובץ נדחה עם הודעה ברורה, מכיוון שהקובץ הזה אינו פרויקט של Create Aplikasi. אם שם הפרויקט כבר קיים, האפליקציה תשאל: החלף את הפרויקט הישן, או שמור בשם חדש.

חיפוש וסינון פרויקטים
אם כבר יש פרויקטים רבים, ב"נהל פרויקטים" יש תיבת חיפוש ומסנן סוגים. הקלידו את שם הפרויקט בתיבת החיפוש, והרשימה תסונן מיד (אותיות גדולות וקטנות אינן נבדלות). מסנן הסוגים מגביל את הרשימה לסוג אחד בלבד: הכל, HTML, אתר אינטרנט, Java, Kotlin, Compose או Python. עדיין ניתן לפתוח את התפריט של כל פרויקט כרגיל מהרשימה המסוננת.

בונה אפליקציות AI
כתבו או הכתיבו את האפליקציה הרצויה במסך בונה אפליקציות AI, לדוגמה: «אפליקציית הערות עם כפתור שמירה». האפליקציה מנתחת את מילות המפתח בתוך הטלפון (ללא אינטרנט, ללא עלות) ולאחר מכן יוצרת פרויקט אמיתי מהתבנית המתאימה ביותר: מחשבון, הערות, רשימת משימות, מחשבון אינטרנט, אתר פרופיל או מונה. אם לתיאור שלכם עדיין אין תבנית מתאימה, האפליקציה יוצרת פרויקט ריק ואומרת זאת בכנות — היא לא מעמידה פנים שהיא מבינה. פרויקט שנוצר על ידי AI ניתן לפתיחה ישירות בניהול פרויקטים.

תצוגה מקדימה חיה לטלפון של חבר
כדי להציג פרויקט לחבר לפני בנייתו: בניהול פרויקטים, לחצו לחיצה ארוכה על שם הפרויקט ובחרו לאחר מכן תצוגה מקדימה לטלפון של חבר. האפליקציה יוצרת חבילת תצוגה מקדימה קטנה המכילה את הקבצים הראשיים של הפרויקט (index.html, MainActivity או main.py) יחד עם קובץ קרא-אותי.txt עם הוראות וקובץ info.txt. החבילה נשלחת כ-ZIP דרך WhatsApp או Telegram. החבר שמקבל אותה יכול לפתוח את התצוגה המקדימה ישירות: דפי HTML נפתחים בדפדפן, קוד Java/Kotlin/Python נקרא כטקסט.

שוק פרויקטים
שוק פרויקטים מכיל פרויקטים לדוגמה מובנים שניתן להתקין בתיקיית הפרויקטים בלחיצה אחת: מחשבון, הערות, רשימת משימות, מחשבון אינטרנט, אתר פרופיל, מונה, שעון דיגיטלי וחידון אינטרנט. השוק המקוון (הורדת דוגמאות מהאינטרנט) עדיין לא קיים, ולכן שוק זה מכיל דוגמאות שכבר קיימות באפליקציה. ניתן לפתוח ולשנות פרויקט מותקן בניהול פרויקטים כמו פרויקט שיצרתם בעצמכם.

שיתוף פעולה ישיר
כדי לעבוד על פרויקט יחד עם חבר: פתחו את שיתוף פעולה בתפריט הראשי, בחרו את הפרויקט, כתבו הערת שינוי (מה השתנה) ולאחר מכן לחצו על שתף לשיתוף פעולה. הפרויקט נשלח כ-ZIP יחד עם קובץ CATATAN.txt בתוכו. החבר שלכם עובד עליו ושולח את ה-ZIP בחזרה; אתם לוחצים על קבל תשובה, קוראים תחילה את הערת השינוי ואז בוחרים החל כדי לדרוס את הפרויקט הישן או ביטול אם התחרטתם. ZIP ללא CATATAN.txt אינו חבילת שיתוף פעולה — עבור ZIP רגיל של פרויקט, השתמשו ב-ייבא פרויקט בניהול פרויקטים.

מתרגם אפליקציות אוטומטי
כדי לתרגם את הטקסט של אפליקציה לשפה אחרת: פתחו את מתרגם אפליקציות בתפריט הראשי, בחרו את הפרויקט ואת שפת היעד (אנגלית, ערבית או ג'אוונית) ולאחר מכן לחצו על תרגם. המילון כבר נמצא בתוך הטלפון (ללא אינטרנט, ללא עלות) ומכיל מילים יומיומיות נפוצות; הטקסט נקרא מ-strings.xml, מהפריסה ומהקוד ולאחר מכן מתורגם. התוצאה נכתבת לתיקיית values-שפה/strings.xml (אם לפרויקט יש strings.xml) ולדוח תרגום-שפה.txt בתיקיית הפרויקט. מילים שעדיין אינן במילון נשארות כפי שהן ומדווחות — כדי שתדעו אילו מילים עליכם עדיין לתרגם בעצמכם.

יוצר משחקים ללא קוד
כדי ליצור משחק מבלי לכתוב קוד: פתחו את יוצר משחקים ללא קוד בתפריט הראשי, בחרו את סוג המשחק (נחש את המספר, חידון או תפוס כוכב), מלאו את שם המשחק, את הכמות (שלבים/שאלות/כוכבים) ואת הודעת הניצחון ולאחר מכן לחצו על צור משחק. המשחק נוצר כפרויקט אמיתי שניתן להריץ ישירות בניהול פרויקטים ולבנות כ-APK כמו כל פרויקט אחר.

בדיקת אפליקציה אוטומטית
כדי לבדוק פרויקט לפני בנייתו: בניהול פרויקטים, לחצו לחיצה ארוכה על שם הפרויקט ובחרו לאחר מכן בדיקה אוטומטית. ה-IDE בודק 10 דברים מבלי לבנות APK — קיימים הקבצים הנדרשים (קובץ נתוני הפרויקט, מניפסט, קובץ ראשי, פריסה, מחרוזות), שם החבילה והגרסה, ההרשאות בשימוש, הסמל ואיזון הסוגריים בקוד. התוצאה מוצגת לפי פריט (עבר/נכשל עם הודעה) ומוקראת בקול על ידי Jieshuo. תקנו תחילה את כל מה שנכשל ולאחר מכן לחצו על בנה פרויקט.

AI Pembuat Aplikasi
כדי לבדוק קוד של פרויקט עבור דפוסים שגורמים לעיתים קרובות לבעיות: פתחו את בדיקת קוד בתפריט הראשי, בחרו את הפרויקט ולאחר מכן לחצו על בדיקת קוד. הבודק פועל בתוך הטלפון (ללא אינטרנט) ומחפש משתנים לא מנוצלים, פונקציות ריקות, לולאות אינסופיות ברורות, טקסט שנכתב ישירות בקוד (עדיף ב-strings.xml), הרשאות ו-API מסוכנים, סמני TODO/FIXME וביצוע דינמי. כל ממצא מכיל את שם הקובץ, את מספר השורה והצעת תיקון. בודק זה מבוסס על דפוסים, הוא אינו AI אמיתית — בעיות שאינן עוקבות אחר דפוס עדיין עלולות לחמוק.

מצב למידה אינטראקטיבי
כדי ללמוד ליצור אפליקציות צעד אחר צעד: פתחו את מצב למידה בתפריט הראשי. יש 5 שיעורים: צרו את הפרויקט הראשון שלכם, הוסיפו כפתור, שנו צבע, הוסיפו צליל ובנו APK. הקישו על שיעור כדי לקרוא את ההסבר ואת תרגיל התרגול, בצעו את המשימה ולאחר מכן לחצו על בדוק משימה — ה-IDE אכן בודק אם המשימה בוצעה (על ידי סריקת הפרויקט וה-APK בטלפון). שיעורים שעברו מסומנים כהושלמו ונשמרים.

סנכרון ענן
כדי לגבות פרויקט לענן: פתחו את סנכרון ענן בתפריט הראשי. גיבוי מקומי שומר את ה-ZIP של הפרויקט בתיקיית Download/cloud עם חותמת זמן וניתן לשחזרו בכל עת מרשימת הגיבויים. גיבוי GitHub מעלה את ה-ZIP של הפרויקט למאגר הפרטי שלכם (עם אסימון מהגדרות GitHub) וניתן להורידו שוב. זהו גיבוי ושחזור ידניים — סנכרון דו-כיווני אוטומטי מלא דורש שרת, ולכן עדיין אינו קיים.

יוצר Backend אוטומטי
כדי ליצור Backend מבלי לכתוב קוד שרת: פתחו את בונה Backend בתפריט הראשי, בחרו את סוג ה-Backend (הערות, רשימת משימות או לוח מודעות), מלאו את שם הפרויקט ולאחר מכן לחצו על צור Backend. ה-IDE יוצר פרויקט HTML אמיתי עם דף טופס ורשימת נתונים המאוחסנת באחסון המקומי של הטלפון (localStorage) — הנתונים נשמרים וניתן לקרוא אותם שוב כאשר האפליקציה פועלת. Backend זה פועל על טלפון; שני טלפונים עדיין אינם יכולים לשתף את אותם נתונים מכיוון שאין שרת אינטרנט.

מעצב ערכות נושא אוטומטי
כדי לתת לפרויקט ערכת צבעים: פתחו את מעצב ערכות נושא בתפריט הראשי, בחרו את הפרויקט ואת הערכה (בהיר, כהה, כחול, ירוק, אדום או סגול). התצוגה המקדימה מציגה את ששת הצבעים של הערכה (ראשי, ראשי כהה, הדגשה, רקע, טקסט, טקסט משני) ומוקראת בקול על ידי Jieshuo. לחצו על החל ערכת נושא — ה-IDE כותב את colors.xml ו-styles.xml (סגנון app_theme) לפרויקט, המשמשים ישירות כאשר הפרויקט פועל או נבנה.

יוצר אנימציות
כדי לתת לפרויקט אנימציה: פתחו את יוצר אנימציות בתפריט הראשי, בחרו את הפרויקט, את סוג האנימציה (התפוגגות, החלקה, סיבוב, קפיצה או פעימה), את משך הזמן (100 עד 10000 אלפיות שנייה) ואת היעד (כפתור, טקסט או תמונה) ולאחר מכן לחצו על צור אנימציה. ה-IDE כותב קובץ אנימציה אמיתי (res/anim/anim_<סוג>.xml לפרויקטי Java/Kotlin/Compose, או animasi.css לפרויקטי HTML/אתר) יחד עם קוד לדוגמה לשימוש המוצג על המסך.

מקליט פעולות
כדי לחזור על עבודה באופן אוטומטי: ה-IDE מקליט פעולות שבוצעו (פתיחת פרויקט, הרצה, בנייה, ייצוא, גיבוי, יצירת פרויקט, שמירת קובץ). פתחו את מקליט פעולות בתפריט הראשי כדי לראות את רשימת הפעולות שהוקלטו עם התוכנית שלהן ולאחר מכן לחצו על הפעל שוב — ה-IDE מריץ שוב את הפעולות שניתן להפוך לאוטומטיות (גיבוי ויצירת פרויקט פועלים במקום; הרצה, בנייה וייצוא פותחים את המסך הראשי שלהן; פתיחה ושמירה פותחות את העורך). פעולות שלא ניתן להפוך לאוטומטיות מדלגות ומדווחות בסוף.

אבטחה אוטומטית
כדי לבדוק את האבטחה של פרויקט: פתחו את אבטחה אוטומטית בתפריט הראשי, בחרו את הפרויקט ולאחר מכן לחצו על בדוק אבטחה. ה-IDE בודק 8 דברים באופן מקומי (ללא אינטרנט): הרשאות מסוכנות (מיקום, SMS, שיחות, מצלמה, מיקרופון, אנשי קשר), שליחת נתונים דרך HTTP, שליחת SMS, שיחות יוצאות, סיסמה או מפתח שנכתבו ישירות בקוד, WebView ללא הגנה, רכיב שיוצא ללא הרשאה וכתובת http ללא הצפנה. כל ממצא מקבל את הרמה בטוח, אזהרה או סכנה עם הצעת תיקון, והסיכום מוקרא בקול על ידי Jieshuo.

AI לא מקוון
כדי להשתמש בכלי עזר לטקסט ולקוד ללא אינטרנט: פתחו את AI לא מקוון בתפריט הראשי. יש 4 כלים: תקן טקסט (אותיות רישיות, סימני פיסוק ורווחים כפולים), סכם טקסט (לוקח את 3 המשפטים החשובים ביותר), צור שם אפליקציה (מהתיאור שנכתב) והצע שמות משתנים (מחפש שמות משתנים של 1–2 אותיות בפרויקט). אלו כללים פשוטים בתוך הטלפון, לא מודל AI אמיתי. ניתן להחיל את תוצאת תיקון הטקסט על strings.xml של הפרויקט באמצעות כפתור החל.

יוצר Widget וטפטים
כדי ליצור Widget למסך הבית: פתחו את ווידג'טים וטפטים בתפריט הראשי, בחרו את הפרויקט, מלאו את טקסט ה-Widget ולאחר מכן לחצו על צור Widget. ה-IDE כותב את WidgetSaya.java, את פריסת ה-Widget, את פרטי ה-Widget ומוסיף מקלט ל-AndroidManifest.xml של הפרויקט — בנו את הפרויקט ולאחר מכן התקינו את ה-Widget ממסך הבית של הטלפון. עבור טפט: מלאו את הטקסט ואת צבעי הרקע והטקסט, צרו תצוגה מקדימה ולאחר מכן שמרו אותו כ-PNG לתיקיית Download או הגדירו אותו ישירות כטפט הטלפון.

שילוב רשתות חברתיות
כדי להוסיף כפתורי שיתוף לאפליקציה: פתחו את שילוב רשתות חברתיות בתפריט הראשי, בחרו את הפרויקט ולאחר מכן הוסיפו שיתוף ל-WhatsApp, Facebook או Telegram (או לשלושתם בו זמנית). ה-IDE כותב קוד שיתוף אמיתי לקובץ הראשי של הפרויקט (MainActivity או index.html). כפתור בדיקת שיתוף פותח את בוחר השיתוף מה-IDE עם טקסט לדוגמה, כדי שניתן יהיה להרגיש את הזרימה לפני בניית האפליקציה.

אפליקציה מתמונה
כדי ליצור אפליקציית גלריה מתמונה: פתחו את אפליקציה מתמונה בתפריט הראשי ובחרו תמונה מהגלריה. ה-IDE מנתח את גודל התמונה ואת הצבע הדומיננטי שלה ולאחר מכן יוצר פרויקט אמיתי של אפליקציית גלריה: התמונה מועתקת ל-assets של הפרויקט, צבע הערכה נלקח מהצבע הדומיננטי של התמונה ושם האפליקציה נלקח משם קובץ התמונה. פתחו את ניהול פרויקטים כדי להריץ או לבנות את אפליקציית הגלריה.

מסוף אינטראקטיבי (מנתח VT)
כדי להשתמש בתוכניות אינטראקטיביות במסוף: פתחו את Terminal בתפריט הראשי ולאחר מכן הריצו nano, vim, top או htop. המסוף משתמש כעת במנתח VT (מסך רשת עם 24 שורות x 80 עמודות), כך שתוכניות אלו מוצגות כראוי — הסמן זז, שורות נמחקות והמסך משתנה כמו במסוף אמיתי. יש כפתורים מיוחדים ל-Tab, חץ למעלה, חץ למטה ו-Esc לשליטה בתוכניות אינטראקטיביות. הפלט הוא עדיין טקסט ש-Jieshuo יכול לקרוא; לחצו על הקרא מסך כדי לשמוע את השורה האחרונה.

מסוף Exec (קובץ בינארי של אפליקציה)
כדי להריץ קובץ בינארי בתיקיית האפליקציה (לדוגמה aapt2, ECJ, D8) מהמסוף: כתבו את הפקודה כרגיל. ה-IDE משתמש ב-libkautsarexec.so כדי שניתן יהיה להריץ קבצים בינאריים בתיקיית האפליקציה ב-Android 10 ומעלה. לחצו על בדיקת Exec במסוף כדי לבדוק אם נתיב ה-exec הבינארי עובד בטלפון זה — התוצאה מוצגת כפי שהיא. אם ה-exec נחסם על ידי המערכת, פקודות מערכת וסקריפטי shell עדיין פועלים; הריצו את הקובץ הבינארי דרך תפריט בנה פרויקט במקום זאת.

מסוף נשאר פעיל (KeepAlive)
כדי לשמור על ה-shell פועל כאשר מחליפים מסך: פתחו את Terminal, הריצו פקודה ולאחר מכן לחצו על חזרה או עברו למסך אחר — ה-shell אינו מת, וההתראה של Terminal ממשיכה להופיע כדי שתוכלו לחזור בלחיצה אחת. פקודות שהורצו נשמרות בהיסטוריה (כפתור היסטוריה או החצים למעלה/למטה בשדה הפקודה) ופקודות בשימוש תכוף ניתן לשמור כמועדפים (כפתור מועדפים). לחצו על סגור shell כאשר סיימתם, כדי שה-shell יסתיים באמת. יש גם כפתור בנה במסוף בתפריט הפרויקט ובתפריט העורך: Terminal נפתח בתיקיית הפרויקט עם פקודת הבנייה כבר מלאה.

התקנת כלי מסוף (ניסיון)
תכונה שעדיין נבדקת: במסוף יש כפתור התקן כלי מסוף להתקנת סביבת Termux מהמראה במאגר alat-termux של המפתח (github.com/syudat/alat-termux), כדרך נוספת מלבד כפתור התקן Termux השואב מהמהדורה הרשמית של Termux. תוכן המראה זהה בדיוק למהדורה הרשמית ונבדק עם SHA-256 במהלך ההתקנה. כאשר הסביבה מותקנת, ניתן להשתמש בפקודות pkg update ו-pkg install, וכלים נוספים מהמאגר מותקנים גם הם במסוף: info-terminal לצפייה במידע על הסביבה, bersih-terminal לניקוי המטמון ו-cadangkan-proyek לארכוב תיקיית הפרויקט לקובץ tar.gz יחיד מתוארך. לאחר מכן האפליקציה מתקינה אוטומטית את חבילות הלינוקס הבסיסיות (git, python, curl, wget, nano, openssh, zip, unzip) ואת כלי בניית ה-APK עם חתימה (openjdk-21, kotlin, gradle, ecj, aapt2, d8, apksigner, clang, cmake, ninja, make) מהמאגר הרשמי של Termux, כך שהמסוף מוכן מיד לבניית אפליקציות. הורדת חבילות גדולות (מאות MB) עלולה לקחת זמן רב. בזמן שההתקנה פועלת, ההתקדמות ופלט הפקודה מוצגים במסך הראשי של Terminal, והתוצאה הסופית מוקראת בקול על ידי קורא המסך. אם התקנת החבילות עדיין לא הושלמה, לחצו שוב על התקן כלי מסוף כדי להמשיך.

מצב קול מלא
כדי לשלוט ב-IDE באופן מלא באמצעות קול: פתחו את מצב קול מלא בתפריט הראשי ולאחר מכן לחצו על התחל להאזין. ה-IDE מאזין ברציפות — אין צורך ללחוץ על כפתור עבור כל פקודה — מריץ את הפקודה ועונה בקול. יש 26 פקודות: צור, בנה, פתח, הרץ, רשום, חפש, מחק, בחן, בדוק, ייצא, גבה, שתף, צור אייקון, תרגם, בנה במסוף, הקרא מסך, פתח את כל המסכים (כולל אבטחה, AI לא מקוון, Widget, רשתות חברתיות, משחק, למידה, ענן, Backend, ערכה, אנימציה, מקליט), חזרה, סגור ועזרה. אם המצב נשאר פעיל, ההאזנה ממשיכה אוטומטית כאשר מסך זה נפתח שוב. לחצו על הפסק להאזין כדי לכבות את המצב. אם לטלפון אין שירות זיהוי קולי, עדיין ניתן לכתוב פקודות בתיבת הטקסט.

מתרגם קוד
כדי לתרגם קוד בין שפות ללא אינטרנט: פתחו את מתרגם קוד בתפריט הראשי, בחרו את הפרויקט, בחרו את קובץ המקור (.java/.kt) ולאחר מכן בחרו את הכיוון: Java ל-Kotlin. לחצו על תרגם — התוצאה מוצגת יחד עם דוח של שורות שלא ניתן לתרגם (שורות אלו נשמרות כפי שהן ומסומנות). לחצו על שמור תוצאה כדי לכתוב קובץ חדש (שם-תרגום.java/.kt) באותה תיקייה; הקובץ המקורי לעולם אינו נדרס. זהו מתרגם כללי דפוסים, לא מהדר — בדקו תמיד את התוצאה לפני השימוש.

Git בתוך האפליקציה
כדי להשתמש ב-Git ב-IDE ללא Termux: פתחו את Git בתוך האפליקציה בתפריט הראשי, בחרו את הפרויקט ולאחר מכן לחצו על צור מאגר Git כדי ליצור מאגר מקומי (.git) בפרויקט זה. לחצו על בדוק סטטוס כדי לראות קבצים חדשים, ששונו או נמחקו בהשוואה ל-Commit האחרון; מלאו את הודעת ה-Commit ולאחר מכן לחצו על Commit כדי לשמור תמונת מצב של הפרויקט; לחצו על הצג יומן Commit כדי לראות את היסטוריית ה-Commit. Push ל-GitHub ו-Pull מ-GitHub משתמשים בתמונות מצב דרך אסימון GitHub (מאגר pembuat-aplikasi-build) — לא פרוטוקול git. Clone, Push (system-git) ו-Pull (system-git) פועלים רק כאשר הבינארי git מותקן בטלפון (בדרך כלל לא). זהו לא git מלא: אין merge, branch או diff — כל Commit שומר תמונת מצב ZIP מלאה של הפרויקט.

יוצר מודעות
כדי להוסיף מודעות לאפליקציה שנבנתה: פתחו את יוצר מודעות בתפריט הראשי, בחרו את הפרויקט, את הספק (AdMob, Unity Ads או AppLovin) ואת סוג המודעה (Banner, Interstitial או מתוגמלת). מלאו את מזהה יחידת המודעה אם כבר יש לכם אחד — ריק פירושו שמשתמשים במזהה בדיקה (AdMob משתמש במזהה הבדיקה הרשמי של Google; Unity משתמש ב-Game ID לדוגמה; AppLovin משתמש ברווח ריק). לחצו על צור קוד פרסומת כדי לראות קוד Java ו-Kotlin ואת המדריך; לחצו על שמור לפרויקט כדי לכתוב הכל לקובץ מודעה-<ספק>-<סוג>.txt בפרויקט. זוהי תבנית קוד + מדריך, לא SDK למודעות — ה-SDK אינו כלול ב-IDE; מודעות אמיתיות מופיעות רק כאשר יוצרים חשבון ספק, יוצרים יחידת מודעה, מדביקים את מזהה היחידה שלכם ומוסיפים את תלות ה-SDK ל-build.gradle של הפרויקט.

מצב ילדים
כדי להשתמש ב-IDE יחד עם ילד: פתחו את מצב ילדים בתפריט הראשי. המסך פשוט עם כפתורים גדולים ויש בו רק 4 פעולות בטוחות: יצירת הפרויקט (מתבניות בטוחות: מחשבון, נחש את המספר, חידון, תפוס כוכב), פתח פרויקט, הרץ ומצב למידה. אין כפתור למחיקה, ייצוא, גיבוי או הגדרת אסימון במסך זה. בכניסה הראשונה יוצרים PIN בן 4 ספרות — ה-PIN הזה משמש את ההורה ליציאה ממצב ילדים (כפתור צא ממצב ילדים או כפתור חזרה). PIN זה הוא הגנה קלה לילדים קטנים, לא אבטחה אמיתית.

יוצר אפליקציות Wear OS ו-TV
כדי ליצור אפליקציית שעון (Wear OS) או אפליקציית טלוויזיה (Android TV): פתחו את יוצר אפליקציות Wear OS ו-TV בתפריט הראשי ובחרו את היעד (Wear OS, Android TV או שניהם). מלאו את שם הפרויקט ולאחר מכן לחצו על צור פרויקט חדש Wear/TV — ה-IDE יוצר פרויקט Java ולאחר מכן מתאים אותו — או בחרו פרויקט קיים ולאחר מכן לחצו על החל על פרויקט זה. התאמות: uses-feature במניפסט, קטגוריית LEANBACK_LAUNCHER + באנר לטלוויזיה והפריסה המותאמת activity_main.xml (Wear: מסך קטן; TV: מסך גדול המתאים ל-D-pad). ההסבר המלא נכתב ל-wear-tv.txt בפרויקט. זוהי תבנית פרויקט — בנייה + בדיקה עדיין דורשות מכשיר Wear OS או Android TV/אמולטור; באנר הטלוויזיה (banner.png 320x180) אינו נוצר אוטומטית, יש להוסיף אותו בעצמכם (לדוגמה דרך יוצר אייקונים).

מפת פרויקט
כדי לראות את המבנה של פרויקט: פתחו את מפת פרויקט בתפריט הראשי, בחרו את הפרויקט ולאחר מכן לחצו על הצגת מפה — ה-IDE מציג את רשימת התיקיות והקבצים עם הגדלים שלהם, את הגודל הכולל, את הגודל לפי סוג קובץ ואת הקבצים החשובים (קובץ ראשי, מניפסט, פריסה, מחרוזות, סמל, דף אינטרנט). לחצו על שמור peta-proyek.txt כדי לכתוב את אותה מפה לשורש הפרויקט. תיקיית bin/ (תוצאת הבנייה) ו-.git/ (מאגר מקומי) אינן כלולות במפה מכיוון שניתן ליצור את תוכנן מחדש.

מחשבון גודל APK
כדי להעריך את גודל ה-APK שנבנה לפני הבנייה: פתחו את מחשבון גודל APK בתפריט הראשי, בחרו את הפרויקט ולאחר מכן לחצו על חישוב הערכה. ה-IDE מציג פרטים לפי קטגוריה (קוד/DEX, משאבים, נכסים, ספריות מובנות, מניפסט + resources.arsc, הוצאות כלליות), את ההערכה הכוללת, את 5 הקבצים הגדולים ביותר והצעות לצמצום (לדוגמה, תמונות גדולות מוקטנות ברזולוציה, צלילים גדולים נחתכים באורך). זוהי הערכה, לא גודל מדויק — הגודל האמיתי עשוי להיות שונה בגלל דחיסת aapt2, הסרת קוד לא מנוצל (R8) ומשאבי תוצאת הבנייה.

מנתח APK
כדי לקרוא את התוכן של APK מוכן (כמו מנתח APK ב-Android Studio): פתחו את מנתח APK בתפריט הראשי, בחרו את הפרויקט ולאחר מכן לחצו על ניתוח APK של תוצאת הבנייה. ה-IDE קורא את ה-APK האחרון בתיקיית bin של אותו פרויקט ומדווח על שם החבילה, הגרסה, ה-SDK המינימלי והיעד, רשימת ההרשאות בשימוש, מספר קבצי ה-dex, פרטי גודל לפי חלק (קוד תוכנית, משאבים, נכסים, ספריות מובנות, חתימה) ו-10 הרשומות הגדולות ביותר. שימושי כדי לדעת איזה חלק הופך את ה-APK לגדול ואילו הרשאות משתמשת האפליקציה שנבנתה.

תצוגה מקדימה של גודל מסך
כדי לבדוק את מראה הפרויקט בגדלי מסך רבים בו זמנית (כמו ב-Android Studio): פתחו את תצוגה מקדימה של גודל מסך בתפריט הראשי, בחרו את הפרויקט ולאחר מכן לחצו על בדוק גודל מסך. ה-IDE קורא את כל הפריסות של הפרויקט ומדווח על אלמנטים שרוחבם נכתב קבוע (לדוגמה 400dp) ועולה על רוחב המסך 320, 360, 411 או 480 dp, מכיוון שאלמנט כזה בטלפון עם מסך קטן עלול להיות מכוסה או לגלוש. אלמנטים ברוחב match_parent או wrap_content מתאימים את עצמם אוטומטית למסך ואינם זקוקים לבדיקה.

מנהל משאבים
כדי לראות ולנהל את כל המשאבים של פרויקט במקום אחד (כמו מנהל משאבים ב-Android Studio): פתחו את מנהל משאבים בתפריט הראשי, בחרו את הפרויקט ולאחר מכן לחצו על הצג משאבים. ה-IDE מדווח על מספר הקבצים והגודל לפי קטגוריה (drawable, layout, values, mipmap ואחרים), את תוכן strings.xml, colors.xml ו-styles.xml. מאותו מסך ניתן להוסיף מחרוזת חדשה ל-strings.xml וצבע חדש ל-colors.xml על ידי מילוי שם וערך — השם נבדק וכפילויות נדחות, כדי שקובץ ה-XML לא ייפגע.

מוניטור ביצועים קל
כדי לנטר את השימוש ב-RAM ובמעבד של אפליקציה פועלת (כמו Profiler ב-Android Studio, גרסה קלה): פתחו את מוניטור ביצועים קל בתפריט הראשי, הריצו תחילה את האפליקציה שברצונכם לבדוק (לדוגמה האפליקציה שנבנתה ונבדקת), מלאו את שם החבילה שלה — או בחרו פרויקט ולאחר מכן לחצו על מלא שם חבילה מפרויקט — ולאחר מכן לחצו על התחל ניטור. כל שתי שניות ה-IDE רושם את ה-RAM (PSS) וה-CPU של אותה אפליקציה יחד עם ה-RAM הפנוי של הטלפון; לחצו על עצור כדי לראות סיכום של ממוצע ושיא. אין הרשאה נוספת. בגרסאות Android חדשות, גישת הקריאה למעבד של אפליקציה אחרת מוגבלת על ידי המערכת, כך שאם לא ניתן לקרוא את ה-CPU, הדוח אומר זאת כפי שהיא וניטור ה-RAM נמשך.

ביקורת נגישות
כדי לבדוק אם פריסת פרויקט ידידותית לקוראי מסך (TalkBack/Jieshuo) לפני הפרסום: פתח את ביקורת נגישות בתפריט הראשי, בחר פרויקט, ולאחר מכן לחץ על טעינת רשימת פריסות ובחר קובץ פריסה. ה-IDE קורא את קובץ ה-XML ההוא ומדווח על כפתורים ללא תווית עם מספרי השורות שלהם, תוויות המשמשות שוב ושוב ואלמנטים החופפים זה לזה, ואז בונה תמליל של סדר המיקוד כפי ש-Jieshuo קורא אותו בקול. אם לכפתור חסרה תווית, מלא את התווית שלו ולאחר מכן לחץ על הוספת תוויות אוטומטית — התווית נכתבת בקובץ הפריסה כ-contentDescription. בדיקה זו קוראת רק את ה-XML של הפריסה; תצוגות Compose ו-APK מוגמרים עדיין לא נסרקים.

נתיחת קריסה
כדי לגלות מדוע האפליקציה סוגרת את עצמה מיומן קריסה עם מזהה ייחודי: פתחו את «נתיחת קריסה» בתפריט הראשי, בחרו את מזהה הקריסה מרשימת היומנים, ולאחר מכן לחצו על «בדיקה». ה-IDE מתאים את המחלקה ומספר השורה ביומן למקור הפרויקט ומסביר את הסיבה באינדונזית (לדוגמה הפניה ריקה, הרשאה שטרם התבקשה, או שגיאת JSON), עם הצעת תיקון קוד. לחצו על «החלת התיקון» רק כאשר שורת המקור עדיין כפי שהייתה כאשר התרחשה הקריסה; אם היא השתנתה, התיקון נדחה וה-IDE מבקש מכם לבדוק בעצמכם. עבור קריסות של האפליקציה שנבנתה, לחצו על «הזרק לוכד קריסות לפרויקט» ולאחר מכן בנו את ה-APK כרגיל: האפליקציה שנבנתה לוכדת את הקריסות שלה וכותבת את היומן שלה בטלפון, וניתן למצוא את היומן הזה עם הכפתור «מצא יומן קריסות של אפליקציה שנבנתה». מגבלה כנה: העתקת היומן לתיקיית ה-Download הציבורית ב-Android 11 ומעלה עלולה להיכשל ללא הרשאת גישה לכל הקבצים.

טרנספיילר בין-פרדיגמות
כדי להמיר קוד Java פשוט ל-Kotlin, או פריסת XML פשוטה לקוד Compose: פתח את טרנספיילר בין-פרדיגמות בתפריט הראשי, בחר פרויקט וקובץ, ולאחר מכן לחץ על תצוגה מקדימה. ה-IDE מציג את תוצאת ההמרה כטקסט — בדוק אותה קודם, כי שורות שהוא לא מזהה נשארות כפי שהן, והמילה static ב-Java מושמטת ב-Kotlin (בדוק את משמעותה לפני השימוש). ההמרה מ-XML ל-Compose משנה רק את הטקסט, את הרמזים ואת הכיוון — הגודל, הצבע והתכונות האחרות עדיין אינם נכללים. אם התוצאה נכונה, לחץ על החלה על הקובץ כדי לכתוב את קובץ היעד; קובץ המקור אינו משתנה. רק דפוסים בטוחים ונפוצים מומרים.

מיקרו-שרת מקומי
כדי לבדוק אפליקציה הזקוקה לשרת ללא אינטרנט: פתחו את «מיקרו-שרת מקומי» בתפריט הראשי, כתבו הגדרות נתיב (לדוגמה GET /halo ולאחריו תשובת ה-JSON שלו), ולאחר מכן לחצו על «הפעלת שרת». ה-IDE מריץ שרת HTTP קטן באותו טלפון (HTTP בלבד, ללא TLS, עבור אותה רשת Wi-Fi) ומתעד כל בקשה ותשובה על המסך. נתיבים יכולים להשתמש בפרמטרים כמו {nama} ובמפתח API פשוט. ניתן גם לארוז את השרת ב-APK שנבנה: לחצו על «ארוז שרת בפרויקט», והמקור, הנכסים והמניפסט של השרת מוזרקים לפרויקט, כך שהאפליקציה שנבנתה עצמה הופכת לשרת כאשר היא רצה. השרת ב-IDE עוצר כאשר המסך שלו נסגר.

בודק אבטחה
כדי לבדוק את קוד הפרויקט לאיתור פערי אבטחה לפני הפרסום: פתחו את «בודק אבטחה» בתפריט הראשי, בחרו את הפרויקט, ולאחר מכן לחצו על «התחלת סריקה». ה-IDE סורק את קוד הפרויקט, המניפסט והתצורה, ומדווח על ממצאים מסיכון גבוה לנמוך — מפתח API שנשאר פתוח בקוד, רכיב שנחשף ללא הרשאה, WebView המאפשר JavaScript עם ממשק ה-JavaScript שלו, קריפטו חלש (MD5, SHA1, DES), כתובת http ללא TLS, וסיסמה שנכתבה ישירות בקוד — עם הקבצים ומספרי השורות שלהם. עבור ממצאים שהתיקון שלהם בטוח (לדוגמה החליפו MD5 ב-SHA-256 או http ב-https), לחצו על «החלת תיקון»; עבור מפתחות API וסיסמאות, ה-IDE מציג רק את הצעת התיקון, מכיוון שההחלפה חייבת להיקבע על ידי המפתח עצמו. הסריקה מנתחת כעת גם bytecode DEX אמיתי בתוך ה-APK שנבנה (לא רק תבניות טקסט בקוד), כך ש-API-ים מסוכנים שנקראים וסודות המוטמעים ב-DEX נתפסים גם הם; פערים שאינם עוקבים אחר תבנית עדיין עלולים לחמוק מהסריקה — בדקו לפני החלה.

רובוט בדיקת ממשק
כדי לבדוק מסך אפליקציה באופן אוטומטי דרך תרחישי טקסט: פתחו את «רובוט בדיקת ממשק» בתפריט הראשי, בחרו את הפרויקט, ולאחר מכן לחצו על «יצירת תרחיש אוטומטית». ה-IDE קורא את המניפסט והפריסה של הפרויקט וכותב את התרחיש כצעדי טקסט (לחצו על כפתור, מלאו שדה, המתינו, חזרו). לחצו על «הפעלת הרצת ניסיון» כדי לראות את יומן הריצה של התרחיש עם חותמות הזמן שלו — הרצת ניסיון זו היא עדיין רק סימולציה של הרצף. לבדיקה אמיתית, לחצו על «הזרק סוכן בדיקה לפרויקט»: ה-IDE מזריק את סוכן הבדיקה עם נכסי התרחיש לפרויקט; בנו את ה-APK כרגיל, התקינו אותו, ולאחר מכן פתחו את הסמל «בדיקה» — הסוכן רץ בתוך האפליקציה שנבנתה ולוחץ באמת על כפתורים, ממלא שדות אמיתיים, וגולל, ולאחר מכן מציג את הדוח שלו עם קריסות אמיתיות שנתפסו על המסך. כדי להסיר שוב את הסוכן, לחצו על «הסר סוכן בדיקה מהפרויקט». הסוכן רץ בתוך התהליך של האפליקציה עצמה, כך שאינו זקוק לשירות נגישות או לאוטומציה של המערכת.

מסע בזמן בקוד
כדי להחזיר פרויקט למצב קוד קודם בלי להקליד פקודות Git: פתח את מסע בזמן בקוד בתפריט הראשי, בחר פרויקט, מלא תווית לנקודת הזמן (אפשר להשאיר ריקה), ולאחר מכן לחץ על רישום נקודת זמן. ה-IDE שומר עותק של קבצי המקור של הפרויקט יחד עם ה-hash שלהם בתיקיית .riwayat שבתוך הפרויקט. רשימת נקודות הזמן מציגה את כולן; בחר שתי נקודות ולאחר מכן לחץ על השוואה כדי לראות קבצים ופונקציות שנוספו, שונו או נמחקו. לחץ על שחזור כדי להחזיר מצב ישן — לפני השחזור, ה-IDE תמיד יוצר קודם גיבוי של המצב הנוכחי, כך ששום דבר לא הולך לאיבוד. לחץ על יצירת עותק ניסוי כדי להעתיק את הפרויקט לתיקייה חדשה ולנסות שינויים בלי להפריע לפרויקט המקורי. רק קבצי מקור נרשמים.

מפעל מודולים
כדי לארוז חלק מפרויקט כמודול שפרויקט אחר יכול להשתמש בו: פתח את מפעל מודולים בתפריט הראשי, בחר פרויקט מקור, סמן את קבצי המסך, המחלקה, המחרוזות וההרשאות שייארזו, ולאחר מכן לחץ על אריזה כמודול. ה-IDE כותב ארכיון ZIP יחד עם מטא-נתוני JSON (שם המודול, גרסה, מחרוזות בשימוש והרשאות). כדי להתקין מודול בפרויקט אחר, פתח את מפעל מודולים, בחר את פרויקט היעד, ולאחר מכן לחץ על התקנת מודול ובחר את קובץ ה-.zip של המודול — המיזוג מוסיף מחרוזות והרשאות בלי לדרוס קוד קיים, ואינו ממזג קובץ אם שמו כבר בשימוש בפרויקט היעד. מודול אינו נושא איתו ספריות ואינו נושא הגדרות בנייה.

מגן פולימורפי וכספת נכסים
כדי לערבב שמות מזהים ולהצפין את נכסי הפרויקט לפני הפרסום: פתחו את «מגן פולימורפי וכספת נכסים» בתפריט הראשי, בחרו את הפרויקט, ולאחר מכן לחצו על «ערבוב שמות והצפנת נכסים». ה-IDE סורק את שמות המחלקות והשיטות בקוד המקור, יוצר מפת שמות אקראית, כותב מחדש את השמות האלה בתוך קבצי ה-DEX המהודרים (שמות ההחלפה נעשים באותו אורך כמו המקוריים, כדי שכל ההיסטים יישארו תקפים, ולאחר מכן סכום הביקורת של כותרת ה-DEX וחתימת SHA-1 מחושבים מחדש), מצפין את קבצי הנכסים של הפרויקט עם AES-GCM בתיקיית brankas-aset בתוך הפרויקט, ושומר מפת שחזור מוצפנת (perisai-peta.brankas) כדי שניתן יהיה לשחזר את השמות המקוריים בעת קריאת יומני קריסה. מפתח ההצפנה נגזר כעת מסיסמת המפתח עם PBKDF2, 20,000 איטרציות, לא משם הפרויקט. שמות המשמשים גם כטקסט פשוט, שם הערה ושם איתור באגים אינם נכתבים מחדש בכוונה, ונקודות ההכנסה של כתיבה מחדש של DEX בנתיב הבנייה עדיין ממתינות לבדיקה בטלפון אמיתי.

שרשרת אמון ושומר סביבה
כדי לבדוק את שרשרת מפתחות החתימה ואת סביבת הטלפון לפני הפרסום: פתחו את «שרשרת אמון ושומר סביבה» בתפריט הראשי, בחרו את הפרויקט, ולאחר מכן לחצו על «בדיקת שרשרת וסביבה». ה-IDE בונה שרשרת מפתחות של 5 דורות משם החבילה של הפרויקט ובודק את שלמותה, בודק את שלמות הזיכרון האמיתית על ידי השוואת תוכן קטעי הקוד בזיכרון לקבצים בדיסק ומדווח על מיפויים ניתנים להפעלה (RWX) ללא שם, ספריות זרות ומיפויי memfd, ולאחר מכן סורק את מפת הזיכרון של התהליך שלו ואת מאפייני המכשיר לאיתור עקבות של Frida, Xposed או אמולטור. מפתח הכספת עטוף במפתח AES ב-AndroidKeyStore המשתמש בשבב האבטחה של החומרה כאשר הוא קיים, וסיבוב מפתחות הוא כעת אמיתי עם שושלת אישור חתימה של סכימה v3: המפתח הישן חותם על הוכחת הסיבוב למפתח החדש, וה-APK נחתם מחדש עם אותה שושלת. התוצאה היא רמת סיכון «בטוח», «זהיר» או «מסוכן» עם ראיות טקסט. אם המערכת מסרבת לקריאת זיכרון, הבדיקה מדווחת כ«לא ניתן לאימות», לא בטוחה; ואם מפתח באמת משתמש בשבב האבטחה של החומרה ניתן לאשר רק במכשיר אמיתי.

אדריכל פריסת עץ טקסט
כדי לעצב מסך מבלי לראות אותו: פתחו את «אדריכל פריסת עץ טקסט» בתפריט הראשי, בחרו את הפרויקט ואת קובץ הפריסה, ולאחר מכן לחצו על «בדיקת פריסה». ה-IDE קורא את פריסת ה-XML כעץ טקסט וקורא בקול רם את תיאור המיקום של כל אלמנט (לדוגמה למטה מימין, 45 אחוז מרוחב המסך), ולאחר מכן מדווח מתמטית על חפיפות בין אלמנטים ועל אלמנטים שיוצאים מהמסך ברוחב 360 dp. מה שנספר כעת הוא LinearLayout וגדלי dp פשוטים, ConstraintLayout מלא (כל האילוצים, ההטיה, השרשראות, המדריכים, המכשולים, רוחבי האחוזים, 0dp match_constraint ויחסי הממדים) ומסכי Compose (Column, Row ו-Box עם משני הגודל שלהם). רק MotionLayout ו-ConstraintSet המשתנים במהלך הריצה עדיין מדווחים כמיקום לא ידוע, מכיוון שהערכים שלהם קיימים רק בזמן שהאפליקציה רצה.

סטודיו מערכת עיצוב
כדי להפוך מרחקים, גופנים ופינות לאחידים בכל המסכים והפרויקטים: פתחו את «סטודיו מערכת עיצוב» בתפריט הראשי, בחרו את הפרויקט, כתבו אסימוני עיצוב (לדוגמה jarak=8, huruf=16, sudut=12), בחרו רכיב, ולאחר מכן לחצו על «יצירת רכיבים». ה-IDE מאמת את האסימונים — מרחק בסיסי 4 עד 16 dp, גופן בסיסי 12 עד 20 sp, פינות 0 עד 32 dp, ואזור מגע מינימלי 48 dp — ולאחר מכן כותב רכיבי XML מוכנים לשימוש (komponen-studio.xml) עם ערכת נושא XML (tema-studio.xml) וערכת נושא Compose (tema-studio.kt) בתיקיית הפרויקט. ניתן גם לשמור אסימונים כקבוצה בעלת שם בספריית האסימונים המשותפת בין פרויקטים, ופקודת סנכרון אחת מחילה את האסימונים העדכניים ביותר של הספרייה על כל הפרויקטים המשתמשים בקבוצה זו. רכיבים נוצרים כטקסט המודבק בפריסה ולאחר מכן נבדק עם «אדריכל פריסת עץ טקסט»; ההתאמה לשתי עמודות בטאבלט משתמשת בהסמכת רוחב מסך במקום בזיהוי מכשיר בזמן הריצה.

שינוי מבנה סמנטי וניווט AST
כדי למצוא הגדרות ולשנות שמות של סמלים מבלי לשבור קוד אחר שבמקרה יש לו אותו שם: פתחו את «שינוי מבנה סמנטי וניווט AST» בתפריט הראשי, בחרו את הפרויקט, ולאחר מכן לחצו על «סריקת סמלי פרויקט» כדי לראות את כל המחלקות והשיטות עם הקבצים ומספרי השורות שלהן. הקלידו את שם הסמל, ולאחר מכן לחצו שוב על «סריקת סמלי פרויקט» כדי לראות את ההגדרה שלו ואת כל הקבצים שקוראים לו. כדי לשנות שם, הקלידו את השם החדש, לחצו על «תצוגה מקדימה של שינוי שם» כדי לראות את מספר ההופעות בכל קובץ, ולאחר מכן לחצו על «החל שינוי שם». האינדקס משתמש כעת במנתח AST שנבנה ביד (לקסר ומנתח רקורסיבי עבור תת-קבוצה של Java ו-Kotlin), כך ששינויי שמות של שיטות בין קבצים נפתרים והקוראים בקבצים אחרים משתנים גם הם; הכפתור לחילוץ בלוק קוד לפונקציה חדשה נמצא כעת במסך זה. המנתח הזה עדיין מינימלי: גנריקס מורכבים מאוד, הערות עם פרמטרים ומחלקות אנונימיות נסרקים כפי שהם, בעוד שקריאות דרך השתקפות וממשק אינן נפתרות.

מאתר באגים צעד אחר צעד ובודק זיכרון
כדי לבחון את תוכן המשתנים באמצע זרימת התוכנית מבלי לנחש מיומנים: פתחו את «מאתר באגים צעד אחר צעד ובודק זיכרון» בתפריט הראשי, בחרו את הפרויקט, כתבו מעקב ביצוע (צעד אחד לכל שורה, פורמט מספר שורה, קוד, ולאחר מכן משתנים וערכים מופרדים ב-|, לדוגמה 10|int total = harga * jumlah;|harga=5000, jumlah=3, total=15000), הקלידו את מספר שורת נקודת העצירה, ולאחר מכן לחצו על «הרצת מעקב איתור באגים». ה-IDE רץ עד לנקודת העצירה הראשונה וקורא בקול רם את השורה הפעילה דרך Jieshuo עם ערכי המשתנים שלה. לחצו על «צעד שורה אחת» כדי להתקדם שורה אחת קדימה, לחצו על «היכנס לפונקציה» כדי להיכנס לפונקציה שנקראה (עם מחסנית קריאות), או לחצו על «המשך התוכנית» כדי לעבור לנקודת העצירה הבאה. מאתר הבאגים הזה עדיין עוקב אחר מעקב מוקלט או כתוב ביד; לצידו נמצא לקוח Java טהור לפרוטוקול החוט JDWP שיכול לבצע לחיצת יד, להגדיר נקודות עצירה, לצעוד פנימה, מעל ו החוצה, ולהשהות ולהמשיך את ה-VM דרך TCP או במצב האזנה. השהיית תהליך אמיתי מתוך אפליקציה רגילה עדיין אינה אפשרית לחלוטין, מכיוון ששקע ה-JDWP של תהליך נחשף רק דרך adbd — הדרך המוכחת דורשת איתור באגים אלחוטי והפעלת היעד דרך המעטפת, מה שמעבר למה שהאפליקציה עצמה יכולה לעשות.

מנהל תלויות לא מקוון
כדי להשתמש בספריות צד שלישי ללא אינטרנט ולהימנע מקונפליקטי גרסאות לפני הבנייה: פתחו את «מנהל תלויות לא מקוון» בתפריט הראשי, בחרו את הפרויקט, ולאחר מכן לחצו על «בדיקת תלויות». ה-IDE קורא את כל קבצי ה-.gradle של הפרויקט, בודק את הכספת המשותפת בין פרויקטים בתיקיית Download/brankas-bersama, ופותר קונפליקטים — אם שתי ספריות מבקשות גרסאות שונות של אותו ארטיפקט, משתמשים בגרסה הגבוהה ביותר והקונפליקט מדווח. כדי להוריד ספרייה, הקלידו את הקואורדינטות שלה (פורמט קבוצה:ארטיפקט:גרסה, לדוגמה com.google.code.gson:gson:2.10.1) ולאחר מכן לחצו על «בדיקת תלויות»: כאשר אתם מקוונים, קבצי AAR, JAR או WHL מורדים באמת מ-Maven, Google או PyPI יחד עם גרף התלויות הטרנזיטיבי שלהם (רקורסיבי, מעגלים נחתכים, עומק עד 25 רמות), ורק קבצים שהורדו בהצלחה נרשמים כזמינים. כאשר אתם לא מקוונים, ניתן להשתמש רק בספריות שכבר נמצאות בכספת המשותפת. טווחי גרסאות של Maven אינם נפתרים, וקבצים שהורדו נבדקים רק עם ה-SHA-1 שלהם, ללא אימות PGP.

בודק מסד נתונים ואחסון
כדי לבחון ולבדוק את תוכן מסד הנתונים של הפרויקט מבלי לכתוב קוד שמדפיס את תוכן הטבלה: פתחו את «בודק מסד נתונים ואחסון» בתפריט הראשי, בחרו את הפרויקט ואת קובץ מסד הנתונים (.db, .sqlite או .sqlite3), ולאחר מכן לחצו על «פתיחת מסד נתונים». ה-IDE קורא את הסכמה של כל הטבלאות שלו עם מנתח דפי SQLite מלא (עץ B עם דפי גלישה) ומציג את 20 השורות הראשונות כטבלת טקסט ש-Jieshuo קורא בקול רם. כתבו שאילתת SELECT ולחצו על «הרצת שאילתה» (לדוגמה SELECT nama FROM pengguna WHERE kota = 'Makassar') — שאילתות תומכות כעת ב-JOIN, GROUP BY, ORDER BY ו-LIKE ומופעלות על ידי מנוע ה-Android SQLite האמיתי בטלפון. כדי לשנות ערך, הקלידו את מספר השורה (1 = השורה הראשונה), את שם העמודה ואת הערך החדש, ולאחר מכן לחצו על «שנה את ערך התא» — הערך נכתב בחזרה לקובץ ה-.db. לחצו על «שמור גיבוי» כדי לשמור את המצב הנוכחי של הטבלה כקובץ <שם-מסד-הנתונים>.cadangan.txt בפרויקט. ניתן לקרוא גם את SharedPreferences ו-DataStore. מה שעדיין לא ניתן לקרוא: מסדי נתונים מוצפנים, שינויי WAL לא מאושרים, וערכים מוקלדים ב-DataStore Proto מיוחד (מוצגים רק כתצוגת שדה כללית).

מפעל בדיקות יחידה ו-fuzzing
כדי למצוא פערי לוגיקה לפני שיתוף האפליקציה: פתחו את «מפעל בדיקות יחידה ו-fuzzing» בתפריט הראשי, בחרו את הפרויקט ואת קובץ הקוד, ולאחר מכן לחצו על «יצירת בדיקות והרצתן». ה-IDE קורא את חתימות הפונקציות בקובץ, יוצר מקרי בדיקה רגילים ומקרי גבול (טקסט ריק, null, מספרים מקסימליים, תווים מוזרים), ולאחר מכן באמת מריץ את הבדיקות האלה: קוד הפרויקט מהודר וכל שיטת @Test מופעלת עם מגבלה של 5 שניות, כך שהתוצאה היא הצלחות וכשלונות אמיתיים עם הערכים האמיתיים שלהם. Fuzzing גם באמת רץ על פונקציות הפרויקט (דרך השתקפות, 2 שניות לכל קריאה, מקסימום 20 שיטות), ואחוז כיסוי השורות מחושב באמת דרך אינסטרומנטציה השומרת על מספרי השורות המקוריים. התוצאה מדווחת כמה בדיקות עברו ונכשלו, כמה שורות קוד ופונקציות נמצאו, ואילו מקרי בדיקה נוצרו. הבדיקות שנוצרו משתמשות בדיוק באותו API כמו JUnit, אך הגדרות ההערה והטענה נכתבות בתוך קובץ הבדיקה שנוצר, מכיוון שספריית JUnit האמיתית אינה כלולה באפליקציה.

סימולטור תנאי מכשיר קיצוניים ובודק דליפות זיכרון
כדי לבדוק את עמידות האפליקציה כאשר המערכת הורגת את התהליך שלה, הרשת מתנתקת, המסך מסתובב, או חיסכון בסוללה מופעל: פתחו את «סימולטור תנאי מכשיר קיצוניים ובודק דליפות זיכרון» בתפריט הראשי, בחרו את הפרויקט, ולאחר מכן לחצו על «הרצת סימולציה». ה-IDE מריץ שלושה תרחישי לחץ עם סיבוב מסך מדומה ועוקב אחר אובייקטים המוחזקים בזיכרון גם לאחר סגירת המסך שלהם, ולאחר מכן מדווח על נתונים שאבדו ושרשראות אובייקטים דולפות. מצב השמירה והשחזור נקרא כעת מהמקור של הפרויקט של המשתמש עצמו, לא מדוגמה קבועה; שרת ה-loopback המקומי באמת נעצר באמצע הבדיקה כדי למדוד את ניתוק הרשת; נלקח ומנותח dump אמיתי של heap, שני dumps מושווים ושרשרת ההחזקה נעקבת משורשי ה-GC; והתהליך של האפליקציה עצמה באמת נהרג לאחר שמירת המצב שלו, ולאחר מכן נבדק אילו נתונים חוזרים כאשר הוא נפתח שוב. מה שעדיין בלתי אפשרי מאפליקציה רגילה: כיבוי הרדיו או ה-Wi-Fi של הטלפון ואילוץ עצירה של אפליקציות אחרות — שניהם דורשים הרשאת מערכת; במקום זאת, אפליקציות רקע נהרגות דרך killBackgroundProcesses, שההרשאה שלו כבר קיימת במניפסט, עם תווית כנה על המסך.

אדריכל תכניות פרויקט
כדי להפוך רעיון אפליקציה גדול לתוכנית עבודה צעד אחר צעד: פתחו את «אדריכל תכניות פרויקט» בתפריט הראשי, בחרו את הפרויקט, כתבו את רעיון האפליקציה (לדוגמה אפליקציית קופה קטנה של חנות מכולת עם תשלומים), ולאחר מכן לחצו על «יצירת תכנית». ה-IDE בונה מודולים, רשימת קבצים ואבני דרך קטנות, ולאחר מכן שומר אותם כ-cetak-biru.txt בתיקיית הפרויקט. בכל פעם שאבן דרך הושלמה, לחצו על «סימון אבן הדרך הבאה כהושלמה», או לחצו על «טען שרטוט שמור» כדי לפתוח שוב את התכנית השמורה. אם ספק AI פעיל נבחר ב«הגדרות AI» והמפתח שלו זמין, התכנית נבנית על ידי אותו ספק; אם המפתח חסר או שלא ניתן להגיע לספק, ה-IDE חוזר לתבניות מילות מפתח לא מקוונות ואומר בכנות את המגבלה הזו. תשובת הספק נבדקת רק לגבי הפורמט (מודולים ואבני דרך קיימים), לא לגבי אמיתות התוכן — סקרו תמיד את התכנית לפני הבנייה.

מספר זרימת הלוגיקה של הקוד
כדי להבין קוד ארוך מבלי להאזין לתחביר שורה אחר שורה: פתחו את «מספר זרימת הלוגיקה של הקוד» בתפריט הראשי, בחרו את הפרויקט ואת קובץ הקוד, ולאחר מכן לחצו על «סיפור קוד». ה-IDE הופך כל שורה למשפט אינדונזי (לדוגמה אם הסכום הוא מעל 100000, הריצו את הבלוק הבא), מציג מפת קריאות בין שיטות וניתוח זרימת נתונים בין שיטות (ערכים המועברים הלאה, משומשים או מתעלמים מהם), ומסמן באגים פוטנציאליים עדינים עם מספרי השורות שלהם — String המושווה עם ==, זרם שנפתח מבלי להיסגר, ומשתנה שנכתב בשתי שיטות שונות. אם ספק AI פעיל נבחר ב«הגדרות AI», זמין גם סיכום זרימה מאותו ספק; אם לא קיים, המסך משתמש בסיפור הלא מקוון ואומר את המגבלה הזו. הסיפור, מפת הקריאות וזרימת הנתונים משתמשים בניתוח תבניות טקסט לא מקוון, לא במנתח AST מלא — שיטות שסוגר הפתיחה שלהן נמצא בשורה משלה, שדות מחלקה, וקריאות דרך השתקפות אינם נעקבים — ואזהרות על מרוץ נתונים עלולות להופיע עבור משתנה שבפועל משמש רק לסירוגין.

מפעל חבילות אפליקציה ומוכנות ל-Play Store
כדי להכין אפליקציה ל-Google Play Store ישירות מהטלפון: פתחו את «מפעל חבילות אפליקציה ומוכנות ל-Play Store» בתפריט הראשי, בחרו את הפרויקט, ולאחר מכן לחצו על «בניית חבילת AAB». ה-IDE בונה את קובץ ה-.aab מהמניפסט, המשאבים והנכסים של הפרויקט עם BundleConfig.pb אמיתי, מאמת את מבנה החבילה, ולאחר מכן מחלק את החבילה ל-APK-ים אמיתיים של וריאנטים (בסיסי, לפי ארכיטקטורה, לפי שפה, ואוניברסלי) עם גדלים שנמדדו מהחלוקה הזו, לא הערכות. החבילה נחתמת עם JAR v1 עם אותו מפתח פרויקט המשמש לחתימת APK, ושרשרת החתימה שלה מאומתת קריפטוגרפית. מסך זה גם מבקר את מוכנות ה-Play — SDK יעד מתחת ל-35 מסומן «גבוה», מכיוון ש-Play Store דורש 35 או יותר, וספריית 64 סיביות חסרה מסומנת גם «גבוה». bundletool אמיתי אינו יכול לרוץ במכשיר, מכיוון ש-bundletool דורש JVM בעוד של-Android אין JVM; הדרך לעיל היא הדרך האמיתית הקרובה ביותר במכשיר.

מנוע עדכון OTA והשקות הדרגתיות
כדי לשלוח תיקון קטן מבלי לאלץ משתמשים להוריד שוב את כל ה-APK: פתחו את «מנוע עדכון OTA והשקות הדרגתיות» בתפריט הראשי, בחרו את הפרויקט, כתבו את תוכן הגרסה הישנה והחדשה, ולאחר מכן לחצו על «יצירת חבילת תיקון». ה-IDE מחשב את ההבדל ויוצר חבילת תיקון (patch-ota.zip) עם טביעת האצבע SHA-256 של התוכן החדש, ולאחר מכן בודק אם מכשיר זה נמצא בשלב ההשקה הראשון של 10 אחוז. תיקונים תומכים כעת בדלתא בינארית בכל קובץ (כולל DEX ו-APK), נארזים עם חתימת RSA-2048 ומאומתים עם מפתח ציבורי מהימן לפני החלתם, וניתן להוריד אותם משרת המפתח יחד עם רשימת ההשקות שלו; אם ההחלה נכשלת, הקובץ הישן נשאר שלם. החלת תיקון על אפליקציה רצה נעשית על ידי חתימה מחדש עם מפתח הפרויקט ודרך PackageInstaller, מכיוון שבלתי אפשרי להחליף את הקוד של תהליך רץ מתוך עצמו — ה-APK נעול וה-DEX כבר נטען.

סטודיו סקירת קוד צוות
כדי לסקור את השינויים של עמית ולפתור קונפליקטי מיזוג מבלי לקרוא את חצי Git: פתחו את «סטודיו סקירת קוד צוות» בתפריט הראשי, בחרו את הפרויקט, הקלידו שלוש גרסאות טקסט (בסיסית, מקומית, של עמית), ולאחר מכן לחצו על «פתיחת סקירת צוות». ה-IDE ממזג את שלוש הגרסאות על בסיס יחידות תחביר של Java — שני שינויים באותה שורה אך בהצהרות שונות אינם נחשבים עוד קונפליקט — ומציג כל קונפליקט כבחירת הצבעה: השתמשו בגרסה המקומית, השתמשו בגרסת העמית, או מזגו את שתיהן — שורת התוצאה מוכנסת במיקום הקונפליקט המקורי כדי שסדר השורות יישאר נכון — ולאחר מכן כותב את התוצאה ל-gabung-hasil.txt בפרויקט. למטה נמצא לוח העבודה של הפרויקט: הקלידו כותרת משימה ולאחר מכן לחצו על «הוספת משימה»; משימות נשמרות כטקסט בתיקיית .tugas בתוך הפרויקט ומסונכרנות דרך commits ב-Git בתוך האפליקציה, כך שניתן לקרוא את הלוח שוב מכל היסטוריית commits. חלוקת תחביר זו אינה מנתח AST מלא, ו-Git בתוך האפליקציה שומר תמונת מצב מלאה לכל commit; אין שרת סנכרון נפרד.

הכתבת מבנה קוד
כדי לכתוב קוד בקול בתוך העורך: פתח פרויקט בעורך, ולאחר מכן לחץ על כפתור הכתבת מבנה קוד. דבר פקודות באינדונזית, למשל buat fungsi tambah dengan parameter a angka dan b angka, buat kelas Mobil או buat variabel teks nama sama dengan Budi — ה-IDE הופך את הדיבור לבלוק קוד תקין תחבירית של Java, Kotlin, Python או Compose ומכניס אותו במיקום הסמן, ולאחר מכן קורא בקול סיכום קצר באמצעות Jieshuo. ההכתבה משתמשת בשירות הזנת הקול המובנה של המערכת, ללא הרשאת מיקרופון נוספת, ומזהה רק דפוסי פקודות שכבר נרשמו; דיבור מחוץ לדפוסים אלה אינו הופך לקוד. מספרים הנאמרים כמילים (למשל 'lima') עדיין אינם הופכים לספרות.

מרחב שיתוף מקומי (ללא אינטרנט)
כדי לעבוד יחד בחדר אחד בלי אינטרנט: פתח את שיתוף פעולה בתפריט הראשי, ולאחר מכן פתח את הקטע מרחב שיתוף מקומי. טלפון אחד פותח הפעלה (ה-IDE מציג כתובת IP מקומית ו-PIN בן 6 ספרות), טלפון אחר מצטרף עם הכתובת וה-PIN ההם. שינויי טקסט נשלחים כהבדלי שורות, APK שנבנה יכול להישלח לטלפון של הבודק, ודוחות קריסה מהטלפון של הבודק מתקבלים בחזרה. הפעלה אחת מיועדת רק לחבר אחד; אם שני אנשים משנים בדיוק את אותה שורה באותו זמן, נעשה שימוש בשינוי האחרון. ה-PIN נשלח כטקסט פשוט ברשת המקומית. חדר זה עדיין לא נבדק בטלפון אמיתי.

הגדרות AI
כדי להגדיר ספק AI ומפתחות API לבניית אפליקציות: בתפריט הראשי, בקבוצת ההגדרות, לחצו על «הגדרות AI» (ליד הכפתור «מחבר»). בחרו את הספק לשימוש מהרשימה הזמינה, וסמנו את «החלפת מודל בעת שגיאת ספק» כדי שה-IDE ינסה אוטומטית את המודל הבא מאותו ספק אם מודל נכשל. לחצו על «ניהול מפתחות API» כדי להוסיף מפתחות גיבוי (הקלידו שם ומפתח, ולאחר מכן לחצו על «שמירה»; מפתחות מוצגים מוסווים, רק 4 התווים האחרונים נראים). מפתחות נשמרים בטלפון ולעולם אינם נשלחים לשום מקום אחר מלבד לספק הנבחר בעת בניית האפליקציה. הספק הנבחר משמש כעת באמת על ידי «אדריכל תכניות פרויקט» ו«מספר זרימת הלוגיקה של הקוד»; בניית אפליקציה במסך «בונה אפליקציות AI» עדיין משתמשת ב-AI מקומי בטלפון (ללא אינטרנט).

מחבר
כדי לנתח APK ואז לשלוח אותו: לחץ בתפריט הראשי, בקבוצת הגדרות, על מחבר (ליד כפתור הגדרות AI). בחר קובץ APK מהטלפון, ה-IDE קורא את תוכנו (שם חבילה, גרסה, רשימת פעילויות), ולאחר מכן לחץ על שליחת APK כדי לשלוח אותו דרך תפריט השיתוף של המערכת (למשל WhatsApp או Drive).

שפה וקול
כדי לשנות את שפת האפליקציה: פתח את הגדרות, ואז את שפת האפליקציה, ואז בחר שפה או לפי המערכת. המסך הראשי ורוב המסכים עוברים מיד לשפה הנבחרת בלי לסגור או להפעיל מחדש את האפליקציה; חלק מהמסכים (למשל Terminal, שיתוף פעולה, הגדרות AI וניהול מפתחות) עדיין משתמשים בשפה הישנה עד שהם נפתחים מחדש. אם תבחר לפי המערכת, השפה עוקבת אחר שפת המערכת של הטלפון.

חתימת ברירת מחדל לכל פרויקט ומניעת שיבוש
מגרסה 5.7, פרויקט שאינו משתמש בחתימה אישית נחתם עם המפתח המובנה של הפרויקט עצמו (נוצר פעם אחת בתיקיית tanda-tangan-bawaan בתוך הפרויקט ולאחר מכן משמש הלאה), כך שהחתימה המובנית שונה מפרויקט לפרויקט — כבר לא מפתח משותף לכל האפליקציות. אל תמחקו את תיקיית tanda-tangan-bawaan: ללא מפתח זה, APK חדש אינו יכול לדרוס את ה-APK הישן של אותו פרויקט. ההגדרות של כל פרויקט (ארכיטקטורה נפרדת, חתימה אישית, Anti Tamper, keystore נבחר, SDK) נשמרות כעת בקובץ settings.gradle בתוך הפרויקט ונקראות שוב בכל פעם שהפרויקט נבנה. בהגדרות, בקטגוריית חתימה, יש תיבת סימון Anti Tamper עבור האפליקציה שנבנתה: אם היא פעילה, האפליקציה שנבנתה בודקת במכשיר את החתימה ואת תוכן ה-dex שלה בכל פעם שהיא נפתחת; אם היא נחתמה מחדש או שונתה על ידי מישהו אחר, האפליקציה מסרבת לפעול. גם כלי איתור באגים והזרקה כמו Frida/Xposed מזוהים, וחלון האפליקציה נעול מפני הקלטת מסך.

יוצר סרטוני הדגמה
כדי ליצור סרטון הדגמה של אפליקציה שנבנתה: פתחו את יוצר סרטוני הדגמה בתפריט הראשי, בחרו את הפרויקט, מלאו את כותרת הסרטון ולאחר מכן לחצו על צור סקריפט סרטון הדגמה — ה-IDE כותב את video-demo.txt עם 5 סצנות סטנדרטיות (פתיחה, תצוגה ראשית, תכונה 1, תכונה 2, סיום) יחד עם טקסט קריינות ומשך כל סצנה. לחצו על צור מצגת HTML כדי ליצור את video-demo.html מהתמונות של הפרויקט (סמל + צילומי מסך אם קיימים) המתחלפות אוטומטית כל 5 שניות. זהו אינו סרטון .mp4 — עבור סרטון אמיתי, פתחו את video-demo.html בדפדפן הטלפון ולאחר מכן הקליטו את המסך, או קראו את הקריינות ב-video-demo.txt בזמן שאתם מקליטים את האפליקציה הפועלת.

מראה חדש בסגנון Android Studio
מראה ה-IDE סודר כעת כמו ב-Android Studio (רק המראה — כל הכפתורים, התפריטים והזרימות נשארים בדיוק כפי שהיו): רקע אפור בהיר, כותרות מסך שחורות מודגשות, כפתורים כחולים עם טקסט לבן ושדות קלט לבנים עם מסגרת דקה. התפריט הראשי מקובץ חזותית (תכונות היוצר, ענן, ערכה ואחרים, קול, קוד ותכונות חדשות, כלים) מבלי לשנות את סדר הכפתורים. המסוף עדיין משתמש בלוח כהה כמו חלון Terminal ב-Android Studio, ועורך הקוד עדיין עם רקע לבן וטקסט שחור. כל הטקסט עדיין נקרא בבירור על ידי Jieshuo.

הגדרות
כדי להגדיר את האפליקציה: פתחו את תפריט האפשרויות במסך הראשי ולאחר מכן לחצו על הגדרות. בפנים יש 12 קטגוריות: הגדרות GitHub (אבטחה, חתימה אישית, היסטוריית בנייה ואסימון GitHub), הגדרות בניית APK במכשיר (שמירת סיסמת keystore והיסטוריית בנייה במכשיר), ערכה (צבע האפליקציה), חתימה (יצירת keystore לחתימה אישית ותיבת הסימון Anti Tamper עבור האפליקציה שנבנתה), תיקיית פרויקט (מיקום תיקיית הפרויקט), שפה וקול (שפת הממשק ומהירות הדיבור של מצב קולי), גודל טקסט ומראה (גודל גופן של העורך), בנייה (SDK יעד ברירת מחדל וחלוקת ארכיטקטורה ברירת מחדל למסך יצירת הפרויקט), התראות (צליל כאשר הבנייה הושלמה), גיבוי אוטומטי (לוח זמנים לגיבוי פרויקט), פרופיל מפתח (שם, מספר WhatsApp וחשבון המוצגים במסך התרומה) ופרטיות ונתונים (איפוס הגדרות ומחיקת נתוני אפליקציה). לכל קטגוריה יש כפתור חזרה למסך הקודם כדי לחזור לתפריט הקטגוריות. הגדרות שנשמרו זה עתה (עדיין לא הוחלו) מוסברות בכנות על המסך.

תרומה למפתח
כדי לתרום או לברך את המפתח: לחצו על כפתור תרומה למפתח במסך הראשי, ליד כפתור אודות הכלי. במסך התרומה יש כפתור העתק חשבון BRI — לחצו עליו כדי להעתיק את מספר החשבון של המפתח ולאחר מכן הדביקו אותו באפליקציית הבנק שלכם. יש גם את הקטע ברכו את המפתח ב-WhatsApp: מלאו את שמכם ואת עיר הולדתכם ולאחר מכן לחצו על שלח ב-WhatsApp — WhatsApp נפתח עם הודעת הברכה כבר מלאה, פשוט לחצו על שלח ב-WhatsApp ולאחר מכן חזרו לאפליקציה. WhatsApp אינו מאפשר לאפליקציות אחרות לשלוח הודעות באופן אוטומטי, ולכן השליחה עדיין נעשית על ידכם ב-WhatsApp.

פקודות מועדפות במסוף
כדי לשמור פקודות בשימוש תכוף במסוף: פתחו את Terminal ולאחר מכן לחצו על מועדפים. לחצו על הוסף מועדף חדש, מלאו שם (לדוגמה הצג קובץ) ואת הפקודה שלו (לדוגמה ls -la) ולאחר מכן לחצו על שמירה — המועדף נשמר לצמיתות בטלפון. לחצו על שם המועדף כדי להריץ אותו ישירות במסוף; לחצו על מחק מועדף ולאחר מכן בחרו אחד למחיקה (עם אישור). כבר יש 3 מועדפים מובנים: הצג קובץ (ls -la), בדוק שטח (df -h) ונקה מסך (clear) — את כולם ניתן למחוק. לא ניתן לשמור או להריץ פקודה ריקה; המסוף מודיע לכם באמצעות הודעה וקול אם זה קורה.

אנליטיקה ואיכות
כדי לראות סיכום של שימוש באפליקציה ודוחות קריסה: לחצו על כפתור אנליטיקה ואיכות במסך הראשי, ליד כפתור תרומה למפתח. מסך זה מציג כמה פעמים האפליקציה נפתחה, אילו מסכים נפתחים בתדירות הגבוהה ביותר, את מספר הקריסות ורשימה של הקריסות האחרונות עם הצעות תיקון קצרות. נתונים אלו מאוחסנים רק בטלפון שלכם ואינם נשלחים לשום מקום. יש כפתור מחק נתוני ניתוח עם דיאלוג אישור למחיקת כל הנתונים הללו. המסך האחרון נרשם רק עבור המסך הראשי ומסך זה.
