ברוכים הבאים ל-Create Aplikasi מאת Al Kautsar
Create Aplikasi היא אפליקציה לבניית אפליקציות Android הפועלת ישירות בטלפון, ללא צורך במחשב נייד. אפליקציה זו מאפשרת לכל אחד ליצור אפליקציות Android משלו, כולל משתמשים שרק מתחילים ללמוד ליצור אפליקציות ומשתמשי קורא מסך. המדריך המלא לשימוש באפליקציה זו זמין במסך "אודות הכלי" הזה.

מהי האפליקציה הזו ולמי היא מיועדת
Create Aplikasi היא כלי לבניית אפליקציות Android הפועל בטלפון. אפליקציה זו מיועדת לכל מי שרוצה ליצור אפליקציות Android משלו, כולל מתחילים ומשתמשי קורא מסך. אפליקציה זו מספקת עורך קוד, לחצן "הפעל" לבדיקת פרויקטים, לחצן "בנה" ליצירת APK, ותפריטים לחתימה ולהתקנה של ה-APK.

מטרת האפליקציה הזו
אפליקציה זו נוצרה כדי שכל אחד יוכל ליצור אפליקציות Android משלו בקלות, ישירות מהטלפון. הממשק שלה נעשה פשוט ככל האפשר כדי שגם משתמשים חדשים יוכלו לנסות אותה מיד.

כיצד ליצור פרויקט חדש, צעד אחר צעד
1. לחצו על "צור פרויקט" בתפריט הראשי.
2. בחרו את סוג הפרויקט: HTML, אתר אינטרנט, Java, Kotlin, Compose או Python.
3. מלאו את שם האפליקציה, לדוגמה: Garuda Decode.
4. מלאו את שם החבילה (package name), לדוגמה: com.android.garudadecode. שם החבילה חייב להשתמש באותיות קטנות ולהיות מורכב משני חלקים לפחות המופרדים בנקודות.
5. מלאו את גרסת האפליקציה, לדוגמה: 1.0, ואת קוד הגרסה בצורת מספר, לדוגמה: 1. אם השדה נשאר ריק, הגרסה תמולא אוטומטית ב-1.0 וקוד הגרסה ב-1.
6. מלאו את ה-SDK המינימלי ואת ה-SDK היעד במידת הצורך. אם השדות נשארים ריקים, ייעשה שימוש בערכי ברירת המחדל. ה-SDK המינימלי הוא גרסת ה-Android הנמוכה ביותר הנתמכת, לדוגמה: 21 פירושו Android 5.0. ה-SDK היעד המרבי הוא 36 (Android 16).
7. לחצו על הלחצן "בחר הרשאות" כדי לבחור את הרשאות האפליקציה, לדוגמה: INTERNET. הרשאת INTERNET כבר מסומנת כברירת מחדל. סמנו רק את ההרשאות שהאפליקציה באמת זקוקה להן.
8. אם תרצו, סמנו את "השתמש בארכיטקטורות נפרדות של 64 ביט ו-32 ביט" כדי שגודל ה-APK יהיה קטן יותר, וסמנו את "השתמש בחתימה אישית" אם ברצונכם להשתמש ב-keystore משלכם.
9. לחצו על "צור פרויקט". הפרויקט החדש נשמר בתיקיית Download/project ומופיע מיד ב"נהל פרויקטים".

סוגי הפרויקטים הזמינים
• HTML: תצוגה מתוך index.html, style.css ו-script.js, הפועלת דרך WebView. נבנה ישירות בטלפון.
• אתר אינטרנט: אתר עם תפריט (דף הבית, אודות, צור קשר) מתוך index.html, tentang.html, kontak.html, style.css ו-script.js, הפועל דרך WebView. נבנה ישירות בטלפון.
• Java: נבנה בטלפון. MainActivity נמצא ב-app/src/main/java/<nama-paket>/MainActivity.java. התצוגה מתוך app/src/main/res/layout/activity_main.xml, הטקסט מתוך app/src/main/res/values/strings.xml, והערכה מתוך app/src/main/res/values/styles.xml.
• Kotlin: ניתן לבנות במכשיר (לא מקוון) באמצעות מהדר Kotlin הכלול באפליקציה, או דרך GitHub Actions. MainActivity נמצא ב-app/src/main/java/<nama-paket>/MainActivity.kt, וקובצי ה-res זהים לאלה של פרויקט Java. הבנייה הראשונה של Kotlin איטית יותר בגלל גודלו הגדול של המהדר, וקובצי .java המפנים למחלקות Kotlin עדיין אינם ניתנים לבנייה (קובצי .java מהודרים לפני קובצי .kt).
• Compose: אפליקציית Android מודרנית שהממשק שלה נוצר עם Jetpack Compose (לא פריסת XML). MainActivity נמצא ב-app/src/main/java/<nama-paket>/MainActivity.kt. פרויקטי Compose נבנים דרך GitHub Actions (תפריט "בנה פרויקט", ואז "בנה מקוון") או ב-Termux עם Gradle, מכיוון ש-Compose דורש את ספריות Jetpack Compose שאינן זמינות במכשיר.
• Python: לוגיקת האפליקציה נכתבת בשפת Python (Chaquopy) ב-app/src/main/python/main.py, ומופעלת על ידי המארח MainActivity.java ב-app/src/main/java/<nama-paket>/MainActivity.java. פרויקטי Python ניתנים לבנייה ישירות בטלפון (זמן הריצה של Chaquopy כלול באפליקציה) וגם דרך GitHub Actions. ה-SDK המינימלי של פרויקט Python הוא 24 (Android 7.0).

מבנה הקבצים של פרויקטי Java, HTML, אתר אינטרנט, Kotlin, Compose ו-Python
פרויקטי Java, HTML, אתר אינטרנט, Kotlin, Compose ו-Python מסודרים כמו פרויקטי Android בדרך כלל. בתוך תיקיית app נמצאת תיקיית src, ובתוכה נמצאת תיקיית main. בתוך תיקיית main נמצא AndroidManifest.xml לצד תיקיית java, תיקיית res המכילה את layout/activity_main.xml ואת values/strings.xml וכן values/styles.xml, ועבור HTML ואתר אינטרנט קיימת תיקיית assets המכילה את index.html (לאתר אינטרנט יש גם tentang.html ו-kontak.html). לפרויקטי HTML ואתר אינטרנט יש גם MainActivity משלהם ב-app/src/main/java/<nama-paket>/MainActivity.java, הטוען את index.html ב-WebView ומשמש כמפעיל (launcher) ב-AndroidManifest. לפרויקט Python יש קוד Python ב-app/src/main/python/main.py ומארח MainActivity.java ב-app/src/main/java/<nama-paket>/MainActivity.java. ניתן לפתוח ולשנות את AndroidManifest.xml, הפריסה, strings ו-styles בעורך, בדיוק כמו את MainActivity. פרויקטים ישנים שהמניפסט שלהם עדיין נמצא לצד תיקיית app עדיין ניתנים לבנייה, מכיוון שבזמן הבנייה האפליקציה בודקת תחילה את AndroidManifest.xml ב-app/src/main/, לאחר מכן את זה שלצד תיקיית app, ולבסוף את קובץ נתוני הפרויקט.

כללי ההרשאות (חשוב)
ההרשאות המסומנות בעת יצירת פרויקט נרשמות במקום אחד בלבד, בהתאם לסוג הפרויקט. עבור פרויקטי Java, HTML, אתר אינטרנט, Kotlin, Compose ו-Python, ההרשאות המסומנות נרשמות רק ב-AndroidManifest.xml הנמצא ב-app/src/main/, לצד תיקיית java, בתוך תיקיית הפרויקט. קובץ נתוני הפרויקט עבור פרויקטי Java, HTML, אתר אינטרנט, Kotlin, Compose ו-Python אינו מכיל רשימת הרשאות. אם תבחרו ב-Java ואז תסמנו את INTERNET ואת CAMERA, מה שיירשם ב-AndroidManifest.xml הוא רק INTERNET ו-CAMERA, ללא הרשאות נוספות שיצטרפו. בזמן הבנייה, האפליקציה קוראת את ההרשאות מאותו מקום: מתוך AndroidManifest.xml ב-app/src/main/ עבור פרויקטי Java, HTML, אתר אינטרנט, Kotlin, Compose ו-Python (אם אינו קיים, מתוך AndroidManifest.xml שלצד תיקיית app עבור פרויקטים ישנים), ומתוך קובץ נתוני הפרויקט עבור פרויקטים ישנים.

כיצד להשתמש בעורך
פתחו את "נהל פרויקטים", הקישו על שם הפרויקט כדי לפתוח את העורך. בעורך ניתן לפתוח קבצים, לכתוב קוד ולשמור שינויים. עבור פרויקטי Java, HTML, אתר אינטרנט, Kotlin, Compose ו-Python, הקבצים מסודרים בתוך תיקיית app/src/main. כדי לשתף פרויקט, השתמשו ב"ייצא ZIP" (ראו את הסעיף להלן).

כיצד להפעיל פרויקט
בעורך, לחצו על "הפעל" כדי לבדוק את הפרויקט. עבור פרויקטי HTML ואתר אינטרנט, מה שמופעל הוא index.html דרך WebView. אם מתרחשת שגיאה, קראו את הודעת השגיאה, תקנו את הקוד, ואז הפעילו שוב.

כיצד לבנות APK
בעורך, לחצו על "בנה". ישנן שתי דרכים לבנות. ראשית, בנייה במכשיר: בנייה ישירות בטלפון ללא אינטרנט, עבור פרויקטי HTML, אתר אינטרנט, Java, Kotlin ו-Python. שנית, בנייה מקוונת דרך GitHub Actions: בנייה דרך האינטרנט ב-GitHub, וניתן להשתמש בה עבור כל סוגי הפרויקטים. פרויקטי Compose ניתנים לבנייה רק בדרך השנייה (בנייה מקוונת) או ב-Termux עם Gradle, מכיוון ש-Compose דורש את ספריות Jetpack Compose שאינן זמינות במכשיר. תוצאת הבנייה הראשונה עדיין אינה חתומה. לאחר מכן האפליקציה חותמת עליה: אוטומטית עם מפתח ברירת המחדל, או עם חתימה אישית אם התיבה "השתמש בחתימה אישית" סומנה בעת יצירת הפרויקט.

כיצד להתקין APK
כאשר ה-APK מוכן, לחצו על "התקן" כדי להתקין אותו. ב-Android 8 ומעלה, הטלפון יבקש תחילה "אפשר ממקור זה", מכיוון שאפליקציה זו מתקינה APK מחוץ ל-Play Store. הפעילו את ההרשאה הזו פעם אחת בהגדרות, ואז חזרו לאפליקציה: ההתקנה תמשיך אוטומטית מבלי שתצטרכו ללחוץ שוב על "התקן". אם לחצן "התקן" אינו מופיע, ודאו שהבנייה הסתיימה ושה-APK נוצר.

כיצד לחתום על אפליקציה
כל APK חייב להיות חתום כדי שניתן יהיה להתקין אותו. קיימות שתי אפשרויות. ראשית, מפתח ברירת המחדל: האפליקציה חותמת בעצמה אוטומטית, ללא צורך לעשות דבר. שנית, חתימה אישית: צרו תחילה keystore דרך תפריט "צור Keystore" בתפריט הראשי, שמרו את הסיסמה שלו היטב, ואז סמנו את "השתמש בחתימה אישית" בעת יצירת הפרויקט. ה-keystore נשמר ב-Download/project/signing.

ייצוא פרויקט ל-ZIP
ייצוא ZIP מסופק כדי שניתן יהיה לשתף פרויקטים עם חברים. כך עושים זאת: ב"נהל פרויקטים", לחצו לחיצה ארוכה על שם הפרויקט, ואז בחרו "ייצא ZIP". התוצאה נשמרת ב-Download/project/<NamaProyek>.zip. תיקיית bin אינה כלולה, כך שהגודל קטן, רק כמה עשרות KB. ניתן לשלוח את קובץ ה-ZIP הזה לחברים או להעלות אותו ל-GitHub.

הרחבת JAWS
הרחבת JAWS משתמשת במנוע ההרחבות של Jieshuo (CSR), ולא בקורא המסך שלו. כך, העיצוב עדיין יכול לפעול גם כאשר המשתמש משתמש ב-TalkBack. כך עושים זאת: פתחו את "הרחבת JAWS" בתפריט הראשי. מכיוון שהלחיצה האוטומטית פועלת מעצמה, יש להפעיל תחילה את השירות בהגדרות הנגישות. לאחר מכן ניתן ליצור עיצוב חדש: הקלידו את שם העיצוב, לחצו על OK, ואז מלאו את התיבה שלו.

רשימת הלחיצות מופרדת כדי שיהיה מסודר
בתוך העיצוב ישנן שתי תיבות: תיבת הסקריפט ותיבת רשימת הלחיצות. רשימת הלחצנים נשמרת בנפרד בקובץ daftar_klik.txt, שם אחד בכל שורה. דוגמה לתוכנה: tombolSimpan, tombolHapus, tombolBuka. כדי לפתוח אפליקציה, פשוט כתבו >WhatsApp ברשימה הזו. עיצובים ישנים שעדיין אין להם קובץ daftar_klik.txt יציגו את הדוגמה המובנית הזו.

פונקציות פשוטות המסופקות
• klikTombol("tombolSimpan") — לחיצה על לחצן אחד לפי הטקסט שלו.
• klikDaftarTombol(daftar) — לחיצה על הרשימה שב-daftar_klik.txt, לחצן אחד בכל שורה, לפי הסדר, ואז הודעה כמה הצליחו וכמה לא נמצאו.
• bukaAplikasi("WhatsApp") — פתיחת אפליקציה לפי שמה, או כתיבת ">WhatsApp" ברשימה.
• klik(540, 1200) — לחיצה בקואורדינטות המסך.
כל הפונקציות נעשו פשוטות תחילה. כאשר תתרגלו אליהן, ניתן יהיה להוסיף פונקציות נוספות בהמשך.

אודות קוראי מסך
אפליקציה זו תוכננה להיות ידידותית לקוראי מסך. לכל שדה מילוי יש תווית ודוגמת מילוי, וניתן להגיע לכל הלחצנים ללא מחוות מסובכות. הרחבת JAWS נוצרה כדי שתוכל להמשיך לפעול גם כאשר המשתמש משתמש ב-TalkBack, מכיוון שמה שמשתמשים בו הוא מנוע ההרחבות שלה, ולא קורא המסך שלה.

פרטיות ואבטחה
הפרויקטים וה-keystore שמורים בטלפון שלכם. אסימון GitHub משמש רק לבנייה מקוונת ונשמר בתוך אפליקציה זו. אל תשתפו את האסימון או את סיסמת ה-keystore שלכם עם אף אחד. אם אתם משתמשים בחתימה אישית, שמרו את ה-keystore ואת הסיסמה שלו במקום בטוח, מכיוון שאם הם יאבדו, לא ניתן יהיה לעדכן APK ישן באותה חתימה.

דרישות
Android 5.0 או חדש יותר. הרשאת אחסון: ב-Android 11 ומעלה נעשה שימוש בהרשאת גישה לכל הקבצים, ב-Android 10 ומטה נעשה שימוש בהרשאת אחסון רגילה (קריאה/כתיבה באחסון) מכיוון של-Android 10 אין הרשאת גישה לכל הקבצים. בנייה במכשיר דורשת טלפון עם מעבד ARM (32 או 64 ביט). בנייה מקוונת דרך GitHub Actions דורשת אינטרנט ואסימון GitHub. פרויקטי Kotlin ניתנים לבנייה במכשיר, אך הבנייה הראשונה שלהם איטית יותר ומשתמשת ביותר זיכרון בגלל גודלו הגדול של מהדר Kotlin. פרויקטי Compose נבנים דרך GitHub Actions או ב-Termux עם Gradle. פרויקטי Python דורשים Android 7.0 או חדש יותר (SDK מינימלי 24) וה-APK המתקבל גדול יותר מכיוון שהוא כולל את זמן הריצה של Python (Chaquopy) יחד עם הספרייה הסטנדרטית שלו.

Terminal
תפריט Terminal במסך הראשי פותח מסוף בתוך אפליקציה זו. ניתן להשתמש בפקודות כמו ls כדי לראות את תוכן תיקיית הפרויקט, cd כדי לעבור בין תיקיות, ו-git כדי לנהל קוד. פלט הפקודות מופיע כטקסט שקורא מסך יכול לקרוא, וקיים לחצן "הקרא תוצאה" כדי להאזין לתוצאה האחרונה. מסוף זה משתמש במעטפת המערכת של הטלפון, כך שתוכניות אינטראקטיביות כמו nano ו-vim עדיין אינן ניתנות לשימוש כאן.

רישיון (גרסה בתשלום)
כדי למכור אפליקציה, סמנו את "הפעל רישיון" בעת יצירת הפרויקט, ואז מלאו את מספר ה-WhatsApp שלכם. האפליקציה שתיבנה תבקש קוד רישיון כשתיפתח לראשונה: המשתמש רואה את מזהה המכשיר שלו, לוחץ על הלחצן "שלח מזהה מכשיר" כדי לשלוח את המזהה הזה ל-WhatsApp שלכם, ואז אתם משיבים עם קוד הרישיון שלו. קוד הרישיון מחושב מתוך מזהה המכשיר וסיסמת הפרויקט (lisensi_seed בקובץ נתוני הפרויקט) — שמרו את הסיסמה הזו היטב ואל תשתפו אותה. לאחר שהוזן הקוד הנכון, האפליקציה נפתחת ואינה מבקשת שוב קוד.

יוצר האייקונים האוטומטי
אייקוני פרויקטים חדשים עדיין שקופים, ולכן זמין "יוצר אייקונים" בתפריט הראשי. כך עושים זאת: לחצו על "יוצר אייקונים", כתבו אות אחת או שתיים (לדוגמה ראשי התיבות של שם האפליקציה), בחרו את צבע הרקע ואת צבע הכתב, צפו בתצוגה המקדימה, ואז לחצו על "שמור לפרויקט" כדי להשתמש באייקון הזה בפרויקט שנבחר, או על "שמור ל-Download" כדי להשתמש בקובץ ה-PNG שלו במקום אחר. לאחר יצירת פרויקט, האפליקציה מציעה גם ליצור אייקון. ניתן להחליף את האייקון הישן של פרויקט בכל עת מתפריט הפרויקט ב"נהל פרויקטים" (לחצו לחיצה ארוכה על שם הפרויקט, ואז בחרו "החלף אייקון").

תבניות פרויקטים מוכנות לשימוש
אם אינכם רוצים להתחיל מפרויקט ריק, בחרו תבנית בעת יצירת הפרויקט: מחשבון (Java), הערות (Java), רשימת משימות (Kotlin), מחשבון אינטרנט (HTML), אתר פרופיל (אתר אינטרנט), או מונה (Compose). בחירת תבנית משנה אוטומטית את סוג הפרויקט בהתאם לתבנית, והפרויקט נוצר עם קוד התחלתי מוכן — נשאר רק להפעיל או לשנות אותו. אם סוג הפרויקט משתנה שוב ידנית לאחר בחירת התבנית, התבנית מבוטלת והפרויקט חוזר להיות ריק. עבור תבניות HTML ואתר אינטרנט, התבנית מחליפה את תוכן index.html, כולל סקריפט ה-HTML שהוקלד בטופס.

גיבוי ושחזור פרויקטים
כדי שפרויקטים לא יאבדו, קיימת תכונת גיבוי. כך עושים זאת: ב"נהל פרויקטים", לחצו לחיצה ארוכה על שם הפרויקט, ואז בחרו "גבה". הגיבוי נשמר כ-ZIP בתיקיית Download/backup עם שם הפרויקט והתאריך, לדוגמה: GarudaDecode-2026-11-14-123045.zip. תוכנו זהה לייצוא ZIP (כל תוכן הפרויקט, ללא תיקיית bin). כדי לשחזר: פתחו את התפריט ב"נהל פרויקטים", בחרו "שחזר גיבוי", ואז בחרו את קובץ הגיבוי שלו. אם שם הפרויקט כבר קיים, האפליקציה תשאל: החלף את הפרויקט הישן, או שמור בשם חדש.

שיתוף וייבוא פרויקטים
כדי לשתף פרויקט עם חבר: ב"נהל פרויקטים", לחצו לחיצה ארוכה על שם הפרויקט, ואז בחרו "שתף". הפרויקט נשלח כ-ZIP דרך אפליקציית שיתוף (WhatsApp, Telegram ואחרות). כדי לקבל פרויקט מחבר: פתחו את התפריט ב"נהל פרויקטים", בחרו "ייבא פרויקט", ואז בחרו את קובץ ה-ZIP שלו. קובץ ה-ZIP הזה חייב להכיל קובץ נתוני פרויקט — אם אין בו, הקובץ נדחה עם הודעה ברורה, מכיוון שהקובץ הזה אינו פרויקט של Create Aplikasi. אם שם הפרויקט כבר קיים, האפליקציה תשאל: החלף את הפרויקט הישן, או שמור בשם חדש.

חיפוש וסינון פרויקטים
אם כבר יש פרויקטים רבים, ב"נהל פרויקטים" יש תיבת חיפוש ומסנן סוגים. הקלידו את שם הפרויקט בתיבת החיפוש, והרשימה תסונן מיד (אותיות גדולות וקטנות אינן נבדלות). מסנן הסוגים מגביל את הרשימה לסוג אחד בלבד: הכל, HTML, אתר אינטרנט, Java, Kotlin, Compose או Python. עדיין ניתן לפתוח את התפריט של כל פרויקט כרגיל מהרשימה המסוננת.

בניית אפליקציות באמצעות קול
אם אינך רוצה להקליד, השתמש בקול: לחץ על בנייה בקול בתפריט הראשי, ואז אמור פקודה. פקודות שתוכל לומר: "Buat proyek kalkulator", "Bangun proyek Kalkulator", "Buka proyek Kalkulator", "Jalankan proyek Kalkulator", "Daftar proyek", "Buka ikon", "Kembali" ו-"Bantuan". האפליקציה עונה בקול ובטקסט, כך שאפשר להשתמש בה גם בלי להסתכל על המסך. זיהוי הקול משתמש באפליקציית זיהוי הקול המובנית של הטלפון (חינם; היא יכולה לעבוד במצב לא מקוון אם מותקנת חבילת השפה האינדונזית). אם לטלפון אין זיהוי קול, ניתן להקליד את הפקודות בתיבת הטקסט באותו מסך.

ביקורת נגישות
כדי לבדוק אם פריסת פרויקט ידידותית לקוראי מסך (TalkBack/Jieshuo) לפני הפרסום: פתח את ביקורת נגישות בתפריט הראשי, בחר פרויקט, ולאחר מכן לחץ על טעינת רשימת פריסות ובחר קובץ פריסה. ה-IDE קורא את קובץ ה-XML ההוא ומדווח על כפתורים ללא תווית עם מספרי השורות שלהם, תוויות המשמשות שוב ושוב ואלמנטים החופפים זה לזה, ואז בונה תמליל של סדר המיקוד כפי ש-Jieshuo קורא אותו בקול. אם לכפתור חסרה תווית, מלא את התווית שלו ולאחר מכן לחץ על הוספת תוויות אוטומטית — התווית נכתבת בקובץ הפריסה כ-contentDescription. בדיקה זו קוראת רק את ה-XML של הפריסה; תצוגות Compose ו-APK מוגמרים עדיין לא נסרקים.

נתיחת קריסה
כדי לגלות מדוע אפליקציה נסגרת מעצמה מתוך יומן קריסה עם מזהה ייחודי: פתח את נתיחת קריסה בתפריט הראשי, בחר מזהה קריסה מרשימת היומנים, ולאחר מכן לחץ על בדיקה. ה-IDE מתאים את המחלקה ומספר השורה ביומן למקור הפרויקט ומסביר את הסיבה באינדונזית (למשל הפניה ריקה, הרשאה שעדיין לא התבקשה, או שגיאת JSON), יחד עם תיקון קוד מוצע. לחץ על החלת התיקון רק אם שורת המקור עדיין זהה בדיוק לזו שהייתה בעת הקריסה; אם היא השתנתה, התיקון נדחה וה-IDE מבקש ממך לבדוק בעצמך. מה שנקרא הוא יומן הקריסה של ה-IDE עצמו, לא היומן של אפליקציה שנבנתה.

טרנספיילר בין-פרדיגמות
כדי להמיר קוד Java פשוט ל-Kotlin, או פריסת XML פשוטה לקוד Compose: פתח את טרנספיילר בין-פרדיגמות בתפריט הראשי, בחר פרויקט וקובץ, ולאחר מכן לחץ על תצוגה מקדימה. ה-IDE מציג את תוצאת ההמרה כטקסט — בדוק אותה קודם, כי שורות שהוא לא מזהה נשארות כפי שהן, והמילה static ב-Java מושמטת ב-Kotlin (בדוק את משמעותה לפני השימוש). ההמרה מ-XML ל-Compose משנה רק את הטקסט, את הרמזים ואת הכיוון — הגודל, הצבע והתכונות האחרות עדיין אינם נכללים. אם התוצאה נכונה, לחץ על החלה על הקובץ כדי לכתוב את קובץ היעד; קובץ המקור אינו משתנה. רק דפוסים בטוחים ונפוצים מומרים.

מיקרו-שרת מקומי
כדי לבדוק אפליקציה הזקוקה לשרת בלי אינטרנט: פתח את מיקרו-שרת מקומי בתפריט הראשי, כתוב הגדרת מסלול (למשל GET /halo ואחריה תשובת ה-JSON שלה), ולאחר מכן לחץ על הפעלת שרת. ה-IDE מריץ שרת HTTP קטן באותו טלפון (HTTP בלבד, ללא TLS, עבור אותה רשת Wi-Fi) ורושם כל בקשה ותשובה על המסך. מסלולים יכולים להשתמש בפרמטרים כמו {nama} ובמפתח API פשוט. שרת זה מיועד רק לבדיקות בטלפון; APK שנבנה עדיין לא יכול להפוך לשרת, והשרת נעצר כאשר המסך שלו נסגר.

בודק אבטחה
כדי לבדוק חורים באבטחה בקוד הפרויקט לפני הפרסום: פתח את בודק אבטחה בתפריט הראשי, בחר פרויקט, ולאחר מכן לחץ על התחלת סריקה. ה-IDE סורק את הקוד, את המניפסט ואת תצורת הפרויקט ומדווח על ממצאים מהסיכון הגבוה ביותר לנמוך ביותר — מפתחות API החשופים בקוד, רכיבים החשופים ללא הרשאה, WebView המפעיל JavaScript יחד עם ממשק JavaScript, קריפטו חלש (MD5, SHA1, DES), כתובות http ללא TLS וסיסמאות הכתובות ישירות בקוד — עם הקובץ ומספר השורה של כל ממצא. עבור ממצאים עם תיקון בטוח (למשל החלפת MD5 ב-SHA-256 או http ב-https) לחץ על החלת תיקון; עבור מפתחות API וסיסמאות, ה-IDE מציג רק את התיקון המוצע, כי את ההחלפה צריך להחליט המפתח עצמו. סריקה זו קוראת דפוסי טקסט בקוד, לא bytecode, כך שחלק מהממצאים עשויים להיות בטוחים למעשה, וחור ללא דפוס עשוי לחמוק מהסריקה — בדוק לפני החלה.

רובוט בדיקת ממשק
כדי לבדוק אוטומטית את מראה האפליקציה בעזרת תרחישי טקסט: פתח את רובוט בדיקת ממשק בתפריט הראשי, בחר פרויקט, ולאחר מכן לחץ על יצירת תרחיש אוטומטית. ה-IDE קורא את המניפסט והפריסות של הפרויקט וכותב תרחיש מצעדי טקסט (לחץ על כפתור, מלא שדה, המתן, חזור). לחץ על הפעלת הרצת ניסיון כדי לראות את יומן הריצה של התרחיש עם חותמות הזמן שלו. בשלב זה הרובוט מריץ רק סימולציה (הרצת ניסיון) — לחיצות כפתורים אמיתיות בטלפון ותפיסת קריסות אמיתיות הן השלב הבא, כך שדוח הקריסה כאן עדיין בפורמט לדוגמה.

מסע בזמן בקוד
כדי להחזיר פרויקט למצב קוד קודם בלי להקליד פקודות Git: פתח את מסע בזמן בקוד בתפריט הראשי, בחר פרויקט, מלא תווית לנקודת הזמן (אפשר להשאיר ריקה), ולאחר מכן לחץ על רישום נקודת זמן. ה-IDE שומר עותק של קבצי המקור של הפרויקט יחד עם ה-hash שלהם בתיקיית .riwayat שבתוך הפרויקט. רשימת נקודות הזמן מציגה את כולן; בחר שתי נקודות ולאחר מכן לחץ על השוואה כדי לראות קבצים ופונקציות שנוספו, שונו או נמחקו. לחץ על שחזור כדי להחזיר מצב ישן — לפני השחזור, ה-IDE תמיד יוצר קודם גיבוי של המצב הנוכחי, כך ששום דבר לא הולך לאיבוד. לחץ על יצירת עותק ניסוי כדי להעתיק את הפרויקט לתיקייה חדשה ולנסות שינויים בלי להפריע לפרויקט המקורי. רק קבצי מקור נרשמים.

מפעל מודולים
כדי לארוז חלק מפרויקט כמודול שפרויקט אחר יכול להשתמש בו: פתח את מפעל מודולים בתפריט הראשי, בחר פרויקט מקור, סמן את קבצי המסך, המחלקה, המחרוזות וההרשאות שייארזו, ולאחר מכן לחץ על אריזה כמודול. ה-IDE כותב ארכיון ZIP יחד עם מטא-נתוני JSON (שם המודול, גרסה, מחרוזות בשימוש והרשאות). כדי להתקין מודול בפרויקט אחר, פתח את מפעל מודולים, בחר את פרויקט היעד, ולאחר מכן לחץ על התקנת מודול ובחר את קובץ ה-.zip של המודול — המיזוג מוסיף מחרוזות והרשאות בלי לדרוס קוד קיים, ואינו ממזג קובץ אם שמו כבר בשימוש בפרויקט היעד. מודול אינו נושא איתו ספריות ואינו נושא הגדרות בנייה.

מגן פולימורפי וכספת נכסים
כדי לערבב שמות מזהים ולהצפין את נכסי הפרויקט לפני ההפצה: פתחו את מגן פולימורפי וכספת נכסים בתפריט הראשי, בחרו פרויקט, ואז לחצו על ערבוב שמות והצפנת נכסים. ה-IDE סורק את שמות המחלקות והשיטות בקוד המקור, בונה מפת שמות אקראיים, מצפין את קבצי הנכסים של הפרויקט באמצעות AES-GCM לתיקיית brankas-aset בתוך הפרויקט, ושומר מפת שחזור מוצפנת (perisai-peta.brankas) כדי שניתן יהיה לשחזר את השמות המקוריים בעת קריאת יומני קריסה. מפתח ההצפנה נגזר משם הפרויקט, כך שכל מי שיודע את שם הפרויקט יכול לפתוח את הכספת — זוהי הגנה מפני קריאה סקרנית, לא כספת הנעולה בסיסמה. מה שנבנה כאן הוא מפת שמות וכספת נכסים; כתיבה מחדש של שמות בתוך קובץ ה-DEX המהודר היא שלב הבא, לכן השמות בתוך ה-APK המוגמר עדיין לא עורבבו.

שרשרת אמון ושומר סביבה
כדי לבדוק את שרשרת מפתחות החתימה ואת סביבת הטלפון לפני ההפצה: פתחו את שרשרת אמון ושומר סביבה בתפריט הראשי, בחרו פרויקט, ואז לחצו על בדיקת שרשרת וסביבה. ה-IDE בונה שרשרת מפתחות בת 5 דורות משם החבילה של הפרויקט ובודק את שלמותה, ואז סורק את מפת הזיכרון של התהליך עצמו ואת תכונות המכשיר בחיפוש אחר עקבות של Frida, Xposed או אמולטור. התוצאה היא רמת סיכון בטוח, זהיר או מסוכן, יחד עם ראיות טקסטואליות. בדיקה זו קוראת דפוסי טקסט במפת הזיכרון ובתכונות המערכת, לא את שלמות הזיכרון הגולמי ברמת הספרייה המקורית, ואינה קושרת את המפתחות לשבב האבטחה של החומרה — כלי הזרקה המסתיר את עקבות הטקסט שלו יכול לחמוק מסריקה זו.

אדריכל פריסת עץ טקסט
כדי לעצב מסך מבלי לראות את המסך: פתחו את אדריכל פריסת עץ טקסט בתפריט הראשי, בחרו פרויקט וקובץ פריסה, ואז לחצו על בדיקת פריסה. ה-IDE קורא את פריסת ה-XML כעץ טקסט ומקריא בקול רם סיפור מיקום לכל רכיב (למשל למטה מימין, 45 אחוז מרוחב המסך), ואז מדווח באופן מתמטי על התנגשויות בין רכיבים ועל רכיבים היוצאים מהמסך ברוחב 360 dp. מה שמחושב הוא LinearLayout וגדלי dp פשוטים; ConstraintLayout ומסכי Compose מדווחים כבעלי מיקום לא ודאי, לא מנוחשים.

סטודיו מערכת עיצוב
כדי להשוות את המרחקים, הגופנים והפינות בכל המסכים והפרויקטים: פתחו את סטודיו מערכת עיצוב בתפריט הראשי, בחרו פרויקט, כתבו את אסימוני העיצוב (למשל jarak=8, huruf=16, sudut=12), בחרו רכיב, ואז לחצו על יצירת רכיבים. ה-IDE מאמת את האסימונים — מרחק בסיסי 4 עד 16 dp, גופן בסיסי 12 עד 20 sp, פינות 0 עד 32 dp ואזור מגע מינימלי 48 dp — ואז כותב רכיבי XML מוכנים לשימוש (komponen-studio.xml) יחד עם ערכת נושא XML ‏(tema-studio.xml)‏ וערכת נושא Compose ‏(tema-studio.kt)‏ בתיקיית הפרויקט. הרכיבים נוצרים כטקסט המודבק לפריסה ואז נבדקים באמצעות אדריכל הפריסה; התאמת שני העמודות בטאבלטים משתמשת במסנני רוחב מסך, לא בזיהוי מכשיר בזמן ריצה.

שינוי מבנה סמנטי וניווט AST
כדי למצוא הגדרות ולשנות שמות של סמלים מבלי לשבור קוד אחר שבמקרה נושא אותו שם: פתחו את שינוי מבנה סמנטי וניווט AST בתפריט הראשי, בחרו פרויקט, ואז לחצו על סריקת סמלי פרויקט כדי לראות את כל המחלקות והשיטות עם הקבצים ומספרי השורות שלהם. הקלידו שם סמל, ואז לחצו שוב על סריקת סמלי פרויקט כדי לראות את ההגדרה שלו ואת כל הקבצים הקוראים לו. כדי לשנות שם, הקלידו את השם החדש, לחצו על תצוגה מקדימה של שינוי שם כדי לראות את מספר ההופעות בכל קובץ, ואז לחצו על החל שינוי שם. אינדקס זה משתמש בדפוסי טקסט, לא במנתח AST מלא: שינוי שם של מחלקה חל על כל הקבצים, בעוד ששינוי שם של שיטה חל רק על הקובץ הבעלים שלה — הקוראים בקבצים אחרים אינם משתנים, לכן בדקו את התצוגה המקדימה ואת תוצאות סריקת הקוראים לפני ההחלה. חילוץ בלוק קוד לפונקציה חדשה כבר קיים במנוע הלוגיקה, אך עדיין אין כפתור לכך במסך זה.

מאתר באגים צעד אחר צעד ובודק זיכרון
כדי לבדוק את תוכן המשתנים באמצע זרימת תוכנית מבלי לנחש דרך יומנים: פתחו את מאתר באגים צעד אחר צעד ובודק זיכרון בתפריט הראשי, בחרו פרויקט, כתבו את עקבות הביצוע (צעד אחד בכל שורה, בצורה מספר שורה, קוד, ואז משתנים וערכים מופרדים ב-|, למשל 10|int total = harga * jumlah;|harga=5000, jumlah=3, total=15000), הקלידו את מספר השורה של נקודת העצירה, ואז לחצו על הרצת מעקב איתור באגים. ה-IDE רץ עד נקודת העצירה הראשונה ומקריא בקול רם את השורה הפעילה יחד עם ערכי המשתנים שלה דרך Jieshuo. לחצו על צעד שורה אחת כדי להתקדם שורה אחת, או המשך התוכנית כדי לרוץ עד נקודת העצירה הבאה. זהו מאתר באגים של עקבות: הוא עוקב אחר עקבות ביצוע מוקלטות או כתובות ביד, ואינו משהה אפליקציית Android פועלת — השהיית תהליך אמיתי דורשת גשר איתור באגים שעדיין אינו קיים בשלב זה.

מנהל תלויות לא מקוון
כדי להשתמש בספריות צד שלישי ללא אינטרנט ולהימנע מעימותי גרסאות לפני הבנייה: פתחו את מנהל תלויות לא מקוון בתפריט הראשי, בחרו פרויקט, ואז לחצו על בדיקת תלויות. ה-IDE קורא את כל קבצי ה-.gradle של הפרויקט, בודק את הכספת הלא מקוונת (brankas-maven.txt בתוך הפרויקט) ופותר עימותים — אם שתי ספריות מבקשות גרסאות שונות של אותו חפץ, משתמשים בגרסה הגבוהה ביותר והעימות מדווח. כדי לרשום ספרייה בכספת, הקלידו את הקואורדינטות שלה (צורה קבוצה:חפץ:גרסה, למשל com.google.code.gson:gson:2.10.1) ואז לחצו על בדיקת תלויות. הורדה מ-Maven, Google או PyPI דורשת אינטרנט: במצב לא מקוון ניתן להשתמש רק בספריות שכבר נמצאות בכספת, והוספת קואורדינטות רק רושמת אותן באינדקס — קבצי ה-AAR, JAR או WHL עצמם אינם מורדים אוטומטית. הכספת עדיין נשמרת לכל פרויקט.

בודק מסד נתונים ואחסון
כדי לבדוק ולבחון את תוכן מסד הנתונים של פרויקט מבלי לכתוב קוד המדפיס את תוכן הטבלאות: פתחו את בודק מסד נתונים ואחסון בתפריט הראשי, בחרו פרויקט וקובץ מסד נתונים (.db, .sqlite או .sqlite3), ואז לחצו על פתיחת מסד נתונים. ה-IDE קורא את סכימת הטבלה ומציג את 20 השורות הראשונות כטבלת טקסט ש-Jieshuo מקריא בקול רם. כתבו שאילתת SELECT פשוטה ואז לחצו על הרצת שאילתה (למשל SELECT nama FROM pengguna WHERE kota = 'Makassar'). כדי לשנות ערך, הקלידו את מספר השורה (1 = השורה הראשונה), את שם העמודה ואת הערך החדש, ואז לחצו על שנה את ערך התא — הערך נכתב חזרה לקובץ ה-.db. לחצו על שמור גיבוי כדי לשמור את המצב הנוכחי של הטבלה כקובץ <שם-מסד>.cadangan.txt בפרויקט. רק הטבלה הראשונה נקראת; השאילתות הנתמכות הן רק SELECT פשוט ללא JOIN או GROUP BY; SharedPreferences ו-DataStore עדיין אינם נקראים.

מפעל בדיקות יחידה ו-fuzzing
כדי למצוא חורים בלוגיקה לפני שיתוף אפליקציה: פתחו את מפעל בדיקות יחידה ו-fuzzing בתפריט הראשי, בחרו פרויקט וקובץ קוד, ואז לחצו על יצירת בדיקות והרצתן. ה-IDE קורא את חתימות הפונקציות בקובץ, יוצר מקרי בדיקה רגילים וגבוליים (טקסט ריק, null, מספרים מקסימליים, תווים מוזרים), מריץ fuzzing על פונקציות לדוגמה, וכותב שלד בדיקת JUnit ‏(Uji<שם-מחלקה>.java)‏ בפרויקט. התוצאה מדווחת כמה בדיקות עברו ונכשלו, כמה שורות קוד ופונקציות נמצאו, וכמה מקרי בדיקה נוצרו. הבדיקות שנוצרו עדיין שלדים — את הערכים הצפויים על המפתח לכתוב — ו-fuzzing אמיתי פועל רק על פונקציות לדוגמה, לא על פונקציות הפרויקט; אחוז כיסוי השורות עדיין אינו מחושב.

סימולטור תנאי מכשיר קיצוניים ובודק דליפות זיכרון
כדי לבדוק את עמידות האפליקציה כאשר המערכת הורגת את התהליך שלה, הרשת מתנתקת, המסך מסתובב, או חיסכון בסוללה פעיל: פתחו את סימולטור תנאי מכשיר קיצוניים ובודק דליפות זיכרון בתפריט הראשי, בחרו פרויקט, ואז לחצו על הרצת סימולציה. ה-IDE מריץ שלושה תרחישי לחץ יחד עם סימולציית סיבוב מסך ועוקב אחר אובייקטים המוחזקים בזיכרון לאחר סגירת המסך שלהם, ואז מדווח על נתונים שאבדו ועל שרשראות של אובייקטים דולפים. זוהי סימולציה על מודל מצב, לא הריגה אמיתית של תהליך, לא ניתוק אמיתי של רשת הטלפון ולא heap dump אמיתי; מודל המצב במסך זה עדיין דוגמה קבועה, לא מצב מסכי הפרויקט של המשתמש.

אדריכל תכניות פרויקט
כדי להפוך רעיון גדול לאפליקציה לתוכנית עבודה הדרגתית: פתחו את אדריכל תכניות פרויקט בתפריט הראשי, בחרו פרויקט, כתבו את רעיון האפליקציה (למשל אפליקציית קופה למכולת עם תשלומים), ואז לחצו על יצירת תכנית. ה-IDE מסדר מודולים, רשימת קבצים ואבני דרך קטנות לעבודה, ואז שומר אותם כ-cetak-biru.txt בתיקיית הפרויקט. לחצו על סימון אבן הדרך הבאה כהושלמה בכל פעם שאבן דרך מסתיימת, או לחצו על טען שרטוט שמור כדי לפתוח שוב תכנית שמורה. התכניות נבנות מדפוסי מילות מפתח במכשיר, לא ממודל AI מקוון — רעיונות לא מזוהים משתמשים בשלד כללי (מודל נתונים, אחסון, מסכים, לוגיקה) — ובנייה דרך ספק ה-AI הפעיל אינה קיימת עדיין בשלב זה.

מספר זרימת הלוגיקה של הקוד
כדי להבין קוד ארוך מבלי להאזין לתחביר שורה אחר שורה: פתחו את מספר זרימת הלוגיקה של הקוד בתפריט הראשי, בחרו פרויקט וקובץ קוד, ואז לחצו על סיפור קוד. ה-IDE הופך כל שורה למשפט באינדונזית (למשל אם הסכום גדול מ-100000, הריצו את הבלוק הבא), מציג מפת קריאות בין שיטות, ומסמן באגים עדינים אפשריים יחד עם מספרי השורות שלהם — String המושווה עם ==, זרם שנפתח מבלי להיסגר, ומשתנה שנכתב בשתי שיטות שונות. הסיפור והבדיקה משתמשים בדפוסי טקסט לא מקוונים, לא במודל AI מקוון ולא בניתוח מלא של זרימת נתונים; דפוסים לא מזוהים מסופרים כפי שהם, כשורת קוד, ואזהרות על מרוץ נתונים עשויות להופיע עבור משתנים שבמציאות משמשים רק לסירוגין.

מפעל חבילות אפליקציה ומוכנות ל-Play Store
כדי להכין אפליקציה ל-Google Play Store ישירות מהטלפון: פתחו את מפעל חבילות אפליקציה ומוכנות ל-Play Store בתפריט הראשי, בחרו פרויקט, ואז לחצו על בניית חבילת AAB. ה-IDE מרכיב את קובץ ה-.aab מהמניפסט, המשאבים ונכסי הפרויקט, מדמה גדלי חלקי הורדה לפי ארכיטקטורה (arm64-v8a, armeabi-v7a, x86_64) ושפה, ואז בודק את מוכנות ה-Play — SDK יעד מתחת ל-35 מסומן כגבוה מכיוון ש-Play Store דורש 35 ומעלה, וספריית 64 סיביות חסרה מסומנת גם היא כגבוהה. החבילה המתקבלת היא ארכיון AAB בעל מבנה סטנדרטי; גדלי החלקים הם הערכות מגדלי קבצים, לא תוצאות פיצול אמיתיות של bundletool, וחתימת החבילה ל-Play Console עדיין משתמשת באותו נתיב בנייה כמו ה-APK.

מנוע עדכון OTA והשקות הדרגתיות
כדי לשלוח תיקונים קטנים מבלי לאלץ משתמשים להוריד שוב את כל ה-APK: פתחו את מנוע עדכון OTA והשקות הדרגתיות בתפריט הראשי, בחרו פרויקט, כתבו את תוכן הגרסה הישנה והחדשה, ואז לחצו על יצירת חבילת תיקון. ה-IDE מחשב את הבדלי השורות ויוצר חבילת תיקון (patch-ota.zip) עם טביעת האצבע SHA-256 של התוכן החדש, ואז בודק אם מכשיר זה נמצא בשלב ההשקה המוקדם של 10 אחוזים. התיקונים כאן עובדים רק על קבצי טקסט (סקריפטים, נכסים, תצורה) — תיקוני DEX או APK בינאריים עדיין אינם נתמכים, ותיקון מוחל כאשר האפליקציה נפתחת שוב. טביעת האצבע במניפסט מוכיחה רק את שלמות התוכן, לא את אותנטיות השולח, מכיוון שהיא עדיין אינה משתמשת בחתימת מפתח פרטי.

סטודיו סקירת קוד צוות
כדי לסקור שינויים של עמית ולפתור עימותי מיזוג מבלי לקרוא את סימני החץ של Git: פתחו את סטודיו סקירת קוד צוות בתפריט הראשי, בחרו פרויקט, מלאו שלוש גרסאות טקסט (בסיס, מקומית, עמית), ואז לחצו על פתיחת סקירת צוות. ה-IDE ממזג את שלושתן ומציג כל עימות כבחירה קולית: שימוש בגרסה מקומית, שימוש בגרסת עמית, או מזג את שניהם — שורות התוצאה מוכנסות במיקום המקורי של העימות כדי שסדר השורות יישאר נכון — ואז כותב את התוצאה ל-gabung-hasil.txt בפרויקט. מתחת לכך נמצא לוח המשימות של הפרויקט: הקלידו כותרת משימה ואז לחצו על הוספת משימה; המשימות נשמרות כטקסט בתיקיית .tugas בתוך הפרויקט. המיזוג משתמש בהתאמת שורות, לא בתחביר, כך ששני שינויים באותה שורה תמיד נחשבים עימות גם אם משמעויותיהם אינן מתנגשות; לוח המשימות מסתנכרן על ידי העתקת קובץ הטקסט שלו יחד עם היסטוריית Git, ללא שרת סנכרון ייעודי.

הכתבת מבנה קוד
כדי לכתוב קוד בקול בתוך העורך: פתח פרויקט בעורך, ולאחר מכן לחץ על כפתור הכתבת מבנה קוד. דבר פקודות באינדונזית, למשל buat fungsi tambah dengan parameter a angka dan b angka, buat kelas Mobil או buat variabel teks nama sama dengan Budi — ה-IDE הופך את הדיבור לבלוק קוד תקין תחבירית של Java, Kotlin, Python או Compose ומכניס אותו במיקום הסמן, ולאחר מכן קורא בקול סיכום קצר באמצעות Jieshuo. ההכתבה משתמשת בשירות הזנת הקול המובנה של המערכת, ללא הרשאת מיקרופון נוספת, ומזהה רק דפוסי פקודות שכבר נרשמו; דיבור מחוץ לדפוסים אלה אינו הופך לקוד. מספרים הנאמרים כמילים (למשל 'lima') עדיין אינם הופכים לספרות.

מרחב שיתוף מקומי (ללא אינטרנט)
כדי לעבוד יחד בחדר אחד בלי אינטרנט: פתח את שיתוף פעולה בתפריט הראשי, ולאחר מכן פתח את הקטע מרחב שיתוף מקומי. טלפון אחד פותח הפעלה (ה-IDE מציג כתובת IP מקומית ו-PIN בן 6 ספרות), טלפון אחר מצטרף עם הכתובת וה-PIN ההם. שינויי טקסט נשלחים כהבדלי שורות, APK שנבנה יכול להישלח לטלפון של הבודק, ודוחות קריסה מהטלפון של הבודק מתקבלים בחזרה. הפעלה אחת מיועדת רק לחבר אחד; אם שני אנשים משנים בדיוק את אותה שורה באותו זמן, נעשה שימוש בשינוי האחרון. ה-PIN נשלח כטקסט פשוט ברשת המקומית. חדר זה עדיין לא נבדק בטלפון אמיתי.

הגדרות AI
כדי להגדיר ספק AI ומפתחות API ליצירת אפליקציות: לחץ בתפריט הראשי, בקבוצת הגדרות, על הגדרות AI (ליד כפתור מחבר). בחר את הספק לשימוש מהרשימה הזמינה, וסמן את החלפת מודל בעת שגיאת ספק כדי שה-IDE ינסה אוטומטית את המודל הבא מאותו ספק אם מודל אחד נכשל. לחץ על ניהול מפתחות API כדי להוסיף מפתחות גיבוי (מלא את השם ואת המפתח, ולאחר מכן לחץ על שמירה; המפתחות מוצגים מוסתרים, רק 4 התווים האחרונים נראים). המפתחות נשמרים בטלפון ולעולם לא נשלחים לשום מקום אחר מלבד הספק הנבחר בעת יצירת אפליקציה. שים לב: כרגע, בחירת הספק והמפתח רק נרשמת ומוצגת במסך AI Pembuat Aplikasi — יצירת אפליקציות עדיין משתמשת ב-AI המקומי של הטלפון (ללא אינטרנט); השימוש בספקים מקוונים יגיע בהמשך.

מחבר
כדי לנתח APK ואז לשלוח אותו: לחץ בתפריט הראשי, בקבוצת הגדרות, על מחבר (ליד כפתור הגדרות AI). בחר קובץ APK מהטלפון, ה-IDE קורא את תוכנו (שם חבילה, גרסה, רשימת פעילויות), ולאחר מכן לחץ על שליחת APK כדי לשלוח אותו דרך תפריט השיתוף של המערכת (למשל WhatsApp או Drive).

שפה וקול
כדי לשנות את שפת האפליקציה: פתח את הגדרות, ואז את שפת האפליקציה, ואז בחר שפה או לפי המערכת. המסך הראשי ורוב המסכים עוברים מיד לשפה הנבחרת בלי לסגור או להפעיל מחדש את האפליקציה; חלק מהמסכים (למשל Terminal, שיתוף פעולה, הגדרות AI וניהול מפתחות) עדיין משתמשים בשפה הישנה עד שהם נפתחים מחדש. אם תבחר לפי המערכת, השפה עוקבת אחר שפת המערכת של הטלפון.
