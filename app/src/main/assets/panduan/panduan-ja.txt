Create Aplikasi by Al Kautsar へようこそ
Create Aplikasi は、ノートパソコンを必要とせず、スマートフォン上で直接動作する Android アプリ作成アプリケーションです。このアプリケーションを使えば、アプリ作成を学び始めたばかりのユーザーやスクリーンリーダーのユーザーを含め、誰でも自分の Android アプリを作成できます。このアプリケーションの完全な使用ガイドは、この「このツールについて」画面でご覧いただけます。

このアプリケーションとは何か、誰のためのものか
Create Aplikasi は、スマートフォン上で動作する Android アプリ作成ツールです。このアプリケーションは、初心者やスクリーンリーダーのユーザーを含め、自分の Android アプリを作成したいすべての人を対象としています。このアプリケーションには、コードエディタ、プロジェクトをテストするための「実行」ボタン、APK を作成するための「ビルド」ボタン、そして APK に署名してインストールするためのメニューが用意されています。

このアプリケーションの目的
このアプリケーションは、誰でもスマートフォンから直接、簡単に自分の Android アプリを作成できるようにするために作られました。そのインターフェースは、初めてのユーザーでもすぐに試せるよう、できるだけシンプルに作られています。

新しいプロジェクトの作成方法、ステップバイステップ
1. メインメニューで「プロジェクトを作成」を押します。
2. プロジェクトの種類を選択します：HTML、ウェブサイト、Java、Kotlin、Compose、または Python。
3. アプリ名を入力します。例：Garuda Decode。
4. パッケージ名（package name）を入力します。例：com.android.garudadecode。パッケージ名は小文字を使用し、ドットで区切られた少なくとも2つの部分で構成されなければなりません。
5. アプリのバージョン（例：1.0）と、数字形式のバージョンコード（例：1）を入力します。空欄のままにすると、バージョンは自動的に 1.0、バージョンコードは 1 が入力されます。
6. 必要に応じて、最小 SDK とターゲット SDK を入力します。空欄のままにすると、デフォルト値が使用されます。最小 SDK はサポートされる最も低い Android バージョンで、例：21 は Android 5.0 を意味します。ターゲット SDK の最大は 36（Android 16）です。
7. 「権限を選択」ボタンを押して、アプリの権限を選択します。例：INTERNET。INTERNET 権限はデフォルトですでにチェックされています。アプリが実際に必要とする権限のみをチェックしてください。
8. 必要に応じて、APK サイズを小さくするために「64ビットと32ビットのアーキテクチャを分けて使用する」にチェックを入れ、自分で作成したキーストアを使いたい場合は「個人署名を使用する」にチェックを入れます。
9. 「プロジェクトを作成」を押します。新しいプロジェクトは Download/project フォルダに保存され、「プロジェクトを管理」にすぐに表示されます。

利用可能なプロジェクトの種類
• HTML：index.html、style.css、script.js による表示で、WebView を通じて動作します。スマートフォン上で直接ビルドされます。
• ウェブサイト：index.html、tentang.html、kontak.html、style.css、script.js によるメニュー（ホーム、概要、連絡先）を持つウェブサイトで、WebView を通じて動作します。スマートフォン上で直接ビルドされます。
• Java：スマートフォン上でビルドされます。MainActivity は app/src/main/java/<package-name>/MainActivity.java にあります。表示は app/src/main/res/layout/activity_main.xml から、テキストは app/src/main/res/values/strings.xml から、テーマは app/src/main/res/values/styles.xml から取得されます。
• Kotlin：アプリケーションに含まれる Kotlin コンパイラを使用してデバイス上（オフライン）でビルドすることも、GitHub Actions を通じてビルドすることもできます。MainActivity は app/src/main/java/<package-name>/MainActivity.kt にあり、res ファイルは Java プロジェクトと同じです。Kotlin の初回ビルドはコンパイラのサイズが大きいため遅くなります。また、Kotlin クラスを参照する .java ファイルはまだビルドできません（.java ファイルは .kt ファイルより前にコンパイルされます）。
• Compose：Jetpack Compose でインターフェースが作成されるモダンな Android アプリケーションです（XML レイアウトではありません）。MainActivity は app/src/main/java/<package-name>/MainActivity.kt にあります。Compose プロジェクトは、Compose にはデバイス上で利用できない Jetpack Compose ライブラリが必要なため、GitHub Actions（プロジェクトをビルドメニュー、次にオンラインビルド）を通じて、または Termux で Gradle を使ってビルドされます。
• Python：アプリのロジックは app/src/main/python/main.py に Python 言語（Chaquopy）で記述され、app/src/main/java/<package-name>/MainActivity.java にあるホスト MainActivity.java によって実行されます。Python プロジェクトは、スマートフォン上で直接ビルドすることも（Chaquopy ランタイムがアプリケーションに含まれています）、GitHub Actions を通じてビルドすることもできます。Python プロジェクトの最小 SDK は 24（Android 7.0）です。

プロジェクトのアーキテクチャを変更
既存のプロジェクトのアーキテクチャ設定を新規プロジェクトを作らずに変更するには、メインメニューで「プロジェクトのアーキテクチャを変更」を押し、プロジェクトを選んで「64 ビット APK をビルド（arm64-v8a）」または「32 ビット APK をビルド（armeabi-v7a）」のチェックボックスを変更します。または、プロジェクト管理でプロジェクト名を長押しし、「アーキテクチャを変更」を選ぶと、同じ画面がそのプロジェクト用に直接開きます。規則は次のとおりです。両方のチェックボックスがオンの場合、ビルドは 2 つの別々の APK を生成します。1 つは 64 ビット、もう 1 つは 32 ビットです。1 つのチェックボックスだけがオンの場合、ビルドは 64 ビットと 32 ビットの両方のデバイスで動作する 1 つのユニバーサル APK を生成します。単一バリアントだけの別々の APK はまだサポートされていません。ビルド経路は分割かユニバーサルの選択しか知らないためです。ただし、各バリアントの選択はプロジェクト内に保存されたままなので、画面を再度開いても失われません。

Java、HTML、ウェブサイト、Kotlin、Compose、Python プロジェクトのファイル構成
Java、HTML、ウェブサイト、Kotlin、Compose、Python プロジェクトは、一般的な Android プロジェクトと同じように構成されています。app フォルダの中には src フォルダがあり、その中には main フォルダがあります。main フォルダの中には、java フォルダの隣に AndroidManifest.xml があり、layout/activity_main.xml と values/strings.xml および values/styles.xml を含む res フォルダがあり、HTML とウェブサイトについては index.html を含む assets フォルダがあります（ウェブサイトには tentang.html と kontak.html もあります）。HTML とウェブサイトのプロジェクトには、app/src/main/java/<package-name>/MainActivity.java に独自の MainActivity もあり、これは index.html を WebView に読み込み、AndroidManifest のランチャーになります。Python プロジェクトには、app/src/main/python/main.py に Python コードがあり、app/src/main/java/<package-name>/MainActivity.java にホスト MainActivity.java があります。AndroidManifest.xml、レイアウト、文字列、スタイルは、MainActivity と同様にエディタで開いて変更できます。マニフェストがまだ app フォルダの隣にある古いプロジェクトもビルドできます。ビルド時にアプリケーションは、まず app/src/main/ の AndroidManifest.xml を確認し、次に app フォルダの隣のもの、最後にプロジェクトデータファイルを確認するからです。

権限のルール（重要）
プロジェクト作成時にチェックした権限は、プロジェクトの種類に応じて、1か所にのみ記録されます。Java、HTML、ウェブサイト、Kotlin、Compose、Python プロジェクトについては、チェックした権限は、プロジェクトフォルダ内の app/src/main/ にあり java フォルダの隣にある AndroidManifest.xml にのみ記録されます。Java、HTML、ウェブサイト、Kotlin、Compose、Python プロジェクトのプロジェクトデータファイルには、権限のリストは含まれていません。Java を選択して INTERNET と CAMERA にチェックを入れると、AndroidManifest.xml に記録されるのは INTERNET と CAMERA のみで、他の権限は含まれません。ビルド時にアプリケーションは同じ場所から権限を読み取ります：Java、HTML、ウェブサイト、Kotlin、Compose、Python プロジェクトについては app/src/main/ の AndroidManifest.xml から（存在しない場合は、古いプロジェクトについては app フォルダの隣の AndroidManifest.xml から）、古いプロジェクトについてはプロジェクトデータファイルから読み取ります。

エディタの使い方
「プロジェクトを管理」を開き、プロジェクト名をタップしてエディタを開きます。エディタでは、ファイルを開いたり、コードを書いたり、変更を保存したりできます。Java、HTML、ウェブサイト、Kotlin、Compose、Python プロジェクトについては、ファイルは app/src/main フォルダ内に整理されています。プロジェクトを共有するには、ZIP にエクスポートを使用してください（下記のセクションをご覧ください）。

プロジェクトの実行方法
エディタで「実行」を押してプロジェクトをテストします。HTML とウェブサイトのプロジェクトについては、実行されるのは WebView を通じた index.html です。エラーが発生した場合は、エラーメッセージを読み、コードを修正してから、再度実行してください。

APK のビルド方法
エディタで「ビルド」を押します。ビルド方法は2つあります。1つ目は「デバイス上でビルド」：インターネットなしでスマートフォン上で直接ビルドします。HTML、ウェブサイト、Java、Kotlin、Python プロジェクト用です。2つ目は GitHub Actions を通じた「オンラインビルド」：GitHub 上でインターネットを通じてビルドし、すべてのプロジェクトの種類に使用できます。Compose プロジェクトは、Compose にはデバイス上で利用できない Jetpack Compose ライブラリが必要なため、2つ目の方法（オンラインビルド）か、Termux で Gradle を使ってのみビルドできます。初回ビルドの結果はまだ署名されていません。その後、アプリケーションが署名します：内蔵キーで自動的に署名するか、プロジェクト作成時に「個人署名を使用する」ボックスがチェックされていた場合は個人署名で署名します。

APK のインストール方法
APK が準備できたら、「インストール」を押してインストールします。Android 8 以上では、このアプリケーションは Play ストアの外部から APK をインストールするため、スマートフォンはまず「この提供元を許可」を求めます。設定でその権限を一度有効にしてからアプリケーションに戻ると、インストールは自動的に続行され、「インストール」を再度押す必要はありません。「インストール」ボタンが表示されない場合は、ビルドが完了し、APK が作成されていることを確認してください。

アプリケーションへの署名方法
すべての APK は、インストールできるように署名されなければなりません。選択肢は2つあります。1つ目は内蔵キー：アプリケーションが自動的に自分で署名するので、あなたは何もする必要はありません。2つ目は個人署名：まずメインメニューの「キーストアを作成」メニューからキーストアを作成し、そのパスワードを大切に保存してから、プロジェクト作成時に「個人署名を使用する」にチェックを入れます。キーストアは Download/project/signing に保存されます。

プロジェクトを ZIP にエクスポートする
ZIP にエクスポートは、プロジェクトを友達と共有できるようにするために用意されています。方法：「プロジェクトを管理」でプロジェクト名を長押しし、「ZIP にエクスポート」を選択します。結果は Download/project/<ProjectName>.zip に保存されます。bin フォルダは含まれないため、サイズは小さく、数十 KB のみです。その ZIP ファイルは友達に送信したり、GitHub にアップロードしたりできます。

JAWS 拡張機能
JAWS 拡張機能は、Jieshuo (CSR) のスクリーンリーダーではなく、その拡張エンジンを使用します。そのため、ユーザーが TalkBack を使用していても、デザインは動作し続けることができます。方法：メインメニューで JAWS 拡張機能を開きます。自動クリックは単独で動作するため、まずユーザー補助設定でサービスを有効にしなければなりません。その後、新しいデザインを作成できます：デザイン名を入力し、OK を押してから、そのボックスを入力します。

クリックリストを分けて整理する
デザインの中には、スクリプトボックスとクリックリストボックスの2つのボックスがあります。ボタンのリストは、ファイル daftar_klik.txt に別々に保存され、1行に1つの名前が入ります。その内容の例：tombolSimpan、tombolHapus、tombolBuka。アプリケーションを開くには、そのリストに >WhatsApp と書くだけです。まだ daftar_klik.txt ファイルを持っていない古いデザインは、そのデフォルトの例を表示します。

用意されているシンプルな関数
• klikTombol("tombolSimpan") — テキストに基づいて1つのボタンをクリックします。
• klikDaftarTombol(daftar) — daftar_klik.txt のリストを、1行に1つのボタン、順番にクリックし、成功した数と見つからなかった数を知らせます。
• bukaAplikasi("WhatsApp") — 名前でアプリケーションを開きます。またはリストに ">WhatsApp" と書きます。
• klik(540, 1200) — 画面の座標をクリックします。
すべての関数はまずシンプルに作られています。慣れてきたら、後で追加の関数を追加できます。

スクリーンリーダーについて
このアプリケーションは、スクリーンリーダーに優しいように設計されています。すべての入力フィールドにはラベルと入力例があり、すべてのボタンには複雑なジェスチャーなしで到達できます。JAWS 拡張機能は、使用されるのがそのスクリーンリーダーではなく拡張エンジンであるため、ユーザーが TalkBack を使用していても動作し続けるように作られています。

プライバシーとセキュリティ
プロジェクトとキーストアはあなたのスマートフォンに保存されます。GitHub トークンはオンラインビルドにのみ使用され、このアプリケーション内に保存されます。トークンやキーストアのパスワードを誰とも共有しないでください。個人署名を使用する場合は、キーストアとそのパスワードを安全な場所に保管してください。紛失すると、古い APK を同じ署名で更新できなくなるからです。

要件
Android 5.0 以降。ストレージ権限：Android 11 以上ではすべてのファイルへのアクセス権限を使用し、Android 10 以下では通常のストレージ権限（ストレージの読み取り/書き込み）を使用します。これは、Android 10 にはすべてのファイルへのアクセス権限がないためです。デバイス上でのビルドには、ARM プロセッサ（32ビットまたは64ビット）を搭載したスマートフォンが必要です。GitHub Actions を通じたオンラインビルドには、インターネットと GitHub トークンが必要です。Kotlin プロジェクトはデバイス上でビルドできますが、Kotlin コンパイラのサイズが大きいため、初回ビルドは遅くなり、より多くのメモリを使用します。Compose プロジェクトは GitHub Actions を通じて、または Termux で Gradle を使ってビルドされます。Python プロジェクトには Android 7.0 以降（最小 SDK 24）が必要で、結果の APK は Python ランタイム（Chaquopy）とその標準ライブラリを含むため、より大きくなります。

ターミナル
メイン画面の「ターミナル」メニューは、このアプリケーション内にターミナルを開きます。ls のようなコマンドはプロジェクトフォルダの内容を表示するために、cd はフォルダ間を移動するために、git はコードを管理するために使用できます。コマンドの出力はスクリーンリーダーで読めるテキストとして表示され、最後の結果を聞くための「結果を読み上げる」ボタンがあります。このターミナルはスマートフォンのシステムシェルを使用するため、nano や vim のような対話型プログラムはここではまだ使用できません。

ライセンス（有料版）
アプリケーションを販売するには、プロジェクト作成時に「ライセンスを有効化」にチェックを入れ、あなたの WhatsApp 番号を入力します。ビルドされたアプリケーションは、初めて開いたときにライセンスコードを求めます：ユーザーは自分のデバイス ID を見て、「デバイス ID を送信」ボタンを押してその ID をあなたの WhatsApp に送信し、あなたがライセンスコードで返信します。ライセンスコードは、デバイス ID とプロジェクトのパスワード（プロジェクトデータファイル内の lisensi_seed）から計算されます — そのパスワードを大切に保管し、共有しないでください。正しいコードを入力すると、アプリケーションが開き、再度コードを求めることはありません。

自動アイコンメーカー
新しいプロジェクトのアイコンはまだ透明なので、メインメニューにアイコンメーカーが用意されています。方法：「アイコンメーカー」を押し、1文字または2文字（例えばアプリ名の頭文字）を書き、背景色と文字色を選び、プレビューを見てから、「プロジェクトに保存」を押して選択したプロジェクトにそのアイコンを使用するか、「ダウンロードに保存」を押してその PNG ファイルを別の場所で使用します。プロジェクトが作成された後、アプリケーションはアイコンの作成も提案します。プロジェクトの古いアイコンは、「プロジェクトを管理」のプロジェクトメニューからいつでも交換できます（プロジェクト名を長押しし、「アイコンを変更」を選択します）。

すぐに使えるプロジェクトテンプレート
空のプロジェクトから始めたくない場合は、プロジェクト作成時にテンプレートを選択します：電卓 (Java)、メモ (Java)、ToDo リスト (Kotlin)、ウェブ電卓 (HTML)、プロフィールサイト（ウェブサイト）、またはカウンター (Compose)。テンプレートを選択すると、プロジェクトの種類が自動的にそのテンプレートに合わせて変更され、プロジェクトは既製のスターターコードで作成されます — 実行するか変更するだけです。テンプレートを選択した後にプロジェクトの種類を再び手動で変更すると、テンプレートはキャンセルされ、プロジェクトは空に戻ります。HTML とウェブサイトのテンプレートについては、テンプレートはフォームに入力された HTML スクリプトを含め、index.html の内容を置き換えます。

プロジェクトのバックアップと復元
プロジェクトが失われないように、バックアップ機能が用意されています。方法：「プロジェクトを管理」でプロジェクト名を長押しし、「バックアップ」を選択します。バックアップは、プロジェクト名と日付とともに ZIP として Download/backup フォルダに保存されます。例：GarudaDecode-2026-11-14-123045.zip。その内容は ZIP にエクスポートと同じです（bin フォルダを除くプロジェクトの全内容）。復元するには：「プロジェクトを管理」のメニューを開き、「バックアップを復元」を選択してから、バックアップファイルを選択します。プロジェクト名がすでに存在する場合、アプリケーションは尋ねます：古いプロジェクトを上書きするか、新しい名前で保存するか。

プロジェクトの共有とインポート
プロジェクトを友達と共有するには：「プロジェクトを管理」でプロジェクト名を長押しし、「共有」を選択します。プロジェクトは共有アプリケーション（WhatsApp、Telegram など）を通じて ZIP として送信されます。友達からプロジェクトを受け取るには：「プロジェクトを管理」のメニューを開き、「プロジェクトをインポート」を選択してから、ZIP ファイルを選択します。その ZIP ファイルにはプロジェクトデータファイルが含まれていなければなりません — 含まれていない場合、そのファイルは Create Aplikasi プロジェクトではないため、ファイルは明確なメッセージとともに拒否されます。プロジェクト名がすでに存在する場合、アプリケーションは尋ねます：古いプロジェクトを上書きするか、新しい名前で保存するか。

プロジェクトの検索とフィルター
プロジェクトがすでにたくさんある場合、「プロジェクトを管理」には検索ボックスと種類フィルターがあります。検索ボックスにプロジェクト名を入力すると、リストはすぐにフィルターされます（大文字と小文字は区別されません）。種類フィルターはリストを1つの種類だけに制限します：すべて、HTML、ウェブサイト、Java、Kotlin、Compose、または Python。各プロジェクトのメニューは、フィルターされたリストから通常どおり開くことができます。

音声でアプリをビルドする
入力したくない場合は音声を使います。メインメニューで音声でビルドをタップし、コマンドを話してください。話せるコマンドは次のとおりです。"Buat proyek kalkulator"、"Bangun proyek Kalkulator"、"Buka proyek Kalkulator"、"Jalankan proyek Kalkulator"、"Daftar proyek"、"Buka ikon"、"Kembali"、"Bantuan"。アプリは音声とテキストで応答するので、画面を見なくても使えます。音声認識はスマートフォン内蔵の音声認識アプリを使います（無料。インドネシア語パックがインストールされていればオフラインでも動作します）。スマートフォンに音声認識がない場合は、同じ画面のテキストボックスにコマンドを入力できます。

AIアプリビルダー
AIアプリビルダー画面で作りたいアプリを入力するか音声で伝えてください。例：「保存ボタン付きのメモアプリ」。アプリはスマートフォン内部でキーワードを分析し（インターネット不要、無料）、最も合うテンプレートから本物のプロジェクトを作ります。電卓、メモ、タスクリスト、ウェブ電卓、プロフィールサイト、カウンターなどです。説明に合うテンプレートがまだない場合、アプリは空のプロジェクトを作り、そのことを正直に伝えます。わかったふりはしません。AIが作ったプロジェクトはプロジェクトを管理で直接開けます。

友達のスマートフォンへライブプレビュー
ビルドする前にプロジェクトを友達に見せたい場合：プロジェクトを管理でプロジェクト名を長押しし、友達のスマートフォンへプレビューを選びます。アプリはプロジェクトの主要ファイル（index.html、MainActivity、main.py）と、説明入りのBACA-SAYA.txt、info.txtを含む小さなプレビューパッケージを作ります。パッケージはZIPとしてWhatsAppやTelegramで送られます。受け取った友達はすぐにプレビューを開けます。HTMLページはブラウザで開き、Java/Kotlin/Pythonコードはテキストとして読めます。

プロジェクトマーケット
プロジェクトマーケットには、ワンタップでプロジェクトフォルダにインストールできる内蔵サンプルプロジェクトがあります。電卓、メモ、タスクリスト、ウェブ電卓、プロフィールサイト、カウンター、デジタル時計、ウェブクイズです。オンラインマーケット（インターネットからサンプルをダウンロード）はまだありませんので、このマーケットにはアプリ内部にすでにあるサンプルが入っています。インストール済みのプロジェクトは、自分で作ったプロジェクトと同じようにプロジェクトを管理で開いて変更できます。

直接コラボレーション
友達と一緒にプロジェクトで作業するには：メインメニューでコラボレーションを開き、プロジェクトを選び、変更メモ（何を変更したか）を書いて、コラボレーション用に共有を押します。プロジェクトはCATATAN.txtファイルを同梱してZIPで送られます。友達が作業してZIPを返送します。あなたは返信を受け取るを押し、まず変更メモを読んでから、古いプロジェクトを上書きする場合は適用を、気が変わった場合はキャンセルを選びます。CATATAN.txtを含まないZIPはコラボレーションパッケージではありません。通常のプロジェクトZIPには、プロジェクトを管理のプロジェクトをインポートを使ってください。

自動アプリ翻訳
アプリ内のテキストを他の言語に翻訳するには：メインメニューでアプリ翻訳を開き、プロジェクトと目標言語（英語、アラビア語、ジャワ語）を選び、翻訳を押します。辞書はすでにスマートフォン内部にあり（インターネット不要、無料）、日常の一般的な単語を含んでいます。strings.xml、レイアウト、コードからテキストを読み取って翻訳します。結果はvalues-言語/strings.xmlフォルダに書き込まれ（プロジェクトにstrings.xmlがある場合）、翻訳-言語.txtレポートがプロジェクトフォルダに作られます。辞書にまだない単語はそのまま残され、報告されます。どの単語を自分で翻訳する必要があるかがわかります。

コードなしゲームメーカー
コードを書かずにゲームを作るには：メインメニューでコードなしゲームメーカーを開き、ゲームの種類（数字当て、クイズ、星をキャッチ）を選び、ゲーム名、数量（レベル/問題/星）、勝利メッセージを入力して、ゲームを作成を押します。ゲームは本物のプロジェクトとして作られ、プロジェクトを管理で直接実行でき、他のプロジェクトと同じようにAPKにビルドできます。

自動アプリテスト
ビルドする前にプロジェクトを確認するには：プロジェクトを管理でプロジェクト名を長押しし、自動テストを選びます。IDEはAPKをビルドせずに10項目を確認します。必須ファイルがあること（プロジェクトデータファイル、マニフェスト、主要ファイル、レイアウト、文字列）、パッケージ名とバージョン、使用する権限、アイコン、コードの括弧のバランスです。結果は項目ごとに表示され（合格/不合格とメッセージ付き）、Jieshuoが読み上げます。まず不合格のものをすべて修正してから、プロジェクトをビルドを押してください。

AI コードチェッカー
問題を起こしやすいパターンについてプロジェクトコードを確認するには：メインメニューでコードチェックを開き、プロジェクトを選び、コードチェックを押します。チェッカーはスマートフォン内部で動作し（インターネット不要）、未使用の変数、空の関数、明らかに終わらないループ、コードに直接書かれたテキスト（strings.xmlに入れる方がよい）、危険な権限とAPI、TODO/FIXMEマーカー、動的実行を探します。各発見にはファイル名、行番号、修正提案が含まれます。このチェッカーはパターンベースであり、本物のAIではありません。パターンに当てはまらない問題は見逃されることがあります。

インタラクティブ学習モード
段階的にアプリ作りを学ぶには：メインメニューで学習を開きます。5つのレッスンがあります。最初のプロジェクトを作る、ボタンを追加する、色を変更する、音を追加する、APKをビルドする。レッスンをタップして説明と練習課題を読み、課題を行い、課題を確認を押します。IDEは課題が本当に実行されたかどうかを確認します（スマートフォン上のプロジェクトとAPKをスキャンして）。合格したレッスンは完了としてマークされ保存されます。

クラウド同期
プロジェクトをクラウドにバックアップするには：メインメニューでクラウド同期を開きます。ローカルバックアップはプロジェクトZIPをタイムスタンプ付きでDownload/cloudフォルダに保存し、バックアップリストからいつでも復元できます。GitHubバックアップはプロジェクトZIPをあなたのプライベートリポジトリにアップロードし（GitHub設定のトークンを使用）、再ダウンロードできます。これは手動のバックアップと復元です。完全な自動双方向同期にはサーバーが必要なため、まだ利用できません。

自動バックエンドビルダー
サーバーコードを書かずにバックエンドを作るには：メインメニューでバックエンドビルダーを開き、バックエンドの種類（メモ、タスクリスト、メッセージボード）を選び、プロジェクト名を入力して、バックエンドを作成を押します。IDEはフォームページとスマートフォンのローカルストレージ（localStorage）に保存されたデータリストを持つ本物のHTMLプロジェクトを作ります。データは保存され、アプリ実行時に再度読み取れます。このバックエンドは1台のスマートフォンで動作します。インターネットサーバーがないため、2台のスマートフォンで同じデータを共有することはまだできません。

自動テーマデザイナー
プロジェクトにカラーテーマを与えるには：メインメニューでテーマデザイナーを開き、プロジェクトとテーマ（明るい、暗い、青、緑、赤、紫）を選びます。プレビューはテーマの6色（プライマリ、ダークプライマリ、アクセント、背景、テキスト、セカンダリテキスト）を表示し、Jieshuoが読み上げます。テーマを適用を押します。IDEはcolors.xmlとstyles.xml（app_themeスタイル）をプロジェクトに書き込み、プロジェクトの実行時やビルド時に直接使われます。

アニメーションメーカー
プロジェクトにアニメーションを与えるには：メインメニューでアニメーションメーカーを開き、プロジェクト、アニメーションの種類（フェード、スライド、回転、バウンス、パルス）、時間（100〜10000ミリ秒）、対象（ボタン、テキスト、画像）を選び、アニメーションを作成を押します。IDEは本物のアニメーションファイルを書き込みます（Java/Kotlin/Composeプロジェクトはres/anim/anim_<種類>.xml、HTML/ウェブサイトプロジェクトはanimasi.css）。画面に表示される使用例コードも付いています。

アクションレコーダー
作業を自動的に繰り返すには：IDEは行われたアクションを記録します（プロジェクトを開く、実行、ビルド、エクスポート、バックアップ、プロジェクト作成、ファイル保存）。メインメニューでアクションレコーダーを開いて、記録されたアクションの一覧とその計画を見て、リプレイを押します。IDEは自動化できるアクションを再度実行します（バックアップとプロジェクト作成はその場で実行、実行・ビルド・エクスポートはメイン画面を開く、開く・保存はエディタを開く）。自動化できないアクションはスキップされ、最後に報告されます。

自動セキュリティ
プロジェクトのセキュリティを確認するには：メインメニューで自動セキュリティを開き、プロジェクトを選び、セキュリティを確認を押します。IDEは8項目をローカルで確認します（インターネット不要）。危険な権限（位置情報、SMS、通話、カメラ、マイク、連絡先）、HTTP経由のデータ送信、SMS送信、発信通話、コードに直接書かれたパスワードやキー、保護のないWebView、権限なしでエクスポートされたコンポーネント、暗号化されていないhttpアドレスです。各発見には修正提案とともに安全、警告、危険のレベルが付けられ、要約はJieshuoが読み上げます。

オフラインAI
インターネットなしでテキストとコードの支援ツールを使うには：メインメニューでオフラインAIを開きます。4つのツールがあります。テキストを修正（大文字、句読点、二重スペース）、テキストを要約（最も重要な3文を抽出）、アプリ名を作成（書かれた説明から）、変数名を提案（プロジェクト内の1〜2文字の変数名を探す）です。これらはスマートフォン内部の単純なルールであり、本物のAIモデルではありません。テキスト修正の結果は適用ボタンでプロジェクトのstrings.xmlに適用できます。

ウィジェット＆壁紙メーカー
ホーム画面ウィジェットを作るには：メインメニューでウィジェットと壁紙を開き、プロジェクトを選び、ウィジェットテキストを入力して、ウィジェットを作成を押します。IDEはWidgetSaya.java、ウィジェットレイアウト、ウィジェット情報を書き込み、プロジェクトのAndroidManifest.xmlにレシーバーを追加します。プロジェクトをビルドし、スマートフォンのホーム画面からウィジェットをインストールします。壁紙の場合：文字と背景色・文字色を入力し、プレビューを作って、PNGとしてDownloadフォルダに保存するか、直接スマートフォンの壁紙に設定します。

ソーシャルメディア連携
アプリに共有ボタンを追加するには：メインメニューでソーシャルメディア連携を開き、プロジェクトを選び、WhatsApp、Facebook、Telegramへの共有を追加します（3つ同時も可）。IDEは本物の共有コードをプロジェクトのメインファイル（MainActivityまたはindex.html）に書き込みます。共有テストボタンはIDEからサンプルテキスト付きで共有選択画面を開くので、アプリをビルドする前に流れを体感できます。

画像からアプリ
画像からギャラリーアプリを作るには：メインメニューで画像からアプリを開き、ギャラリーから画像を選びます。IDEは画像のサイズと主要な色を分析し、本物のギャラリーアプリプロジェクトを作ります。画像はプロジェクトのassetsにコピーされ、テーマ色は画像の主要な色から、アプリ名は画像ファイル名から取られます。プロジェクトを管理を開いて、そのギャラリーアプリを実行またはビルドしてください。

インタラクティブターミナル（VTパーサー）
ターミナルで対話型プログラムを使うには：メインメニューでターミナルを開き、nano、vim、top、htopを実行します。ターミナルはVTパーサー（24行×80列のグリッド画面）を使うようになったので、これらのプログラムが正しく表示されます。カーソルが動き、行が消去され、画面は本物のターミナルのように変わります。対話型プログラムを操作するための専用ボタンTab、上矢印、下矢印、Escがあります。出力はJieshuoが読めるテキストのままです。最後の行を聞くには画面を読み上げるを押してください。

Terminal Exec（アプリバイナリ）
ターミナルからアプリフォルダ内のバイナリ（例：aapt2、ECJ、D8）を実行するには：コマンドを通常通り入力します。IDEはlibkautsarexec.soを使うので、アプリフォルダ内のバイナリをAndroid 10以上で実行できます。ターミナルでExec テストを押して、このスマートフォンでバイナリのexecパスが動作するか確認してください。結果はそのまま表示されます。execがシステムにブロックされた場合でも、システムコマンドとシェルスクリプトは動作します。バイナリはプロジェクトをビルドメニューから実行してください。

Terminal 常駐 (KeepAlive)
他の画面に移動してもシェルを実行し続けるには：ターミナルを開き、コマンドを実行して、戻るを押すか他の画面に移動します。シェルは終了しません。ターミナルの通知が表示されたままなので、ワンタップで戻れます。実行したコマンドは履歴に保存されます（履歴ボタン、またはコマンド欄の上下矢印）。よく使うコマンドはお気に入りとして保存できます（お気に入りボタン）。終わったらシェルを閉じるを押して、シェルを完全に終了させてください。プロジェクトメニューとエディタメニューにはターミナルでビルドボタンもあります。ターミナルはプロジェクトフォルダでビルドコマンドがすでに入力された状態で開きます。

ターミナルツールをインストール（試用）
まだ試用中の機能です。ターミナルには、開発者のalat-termuxリポジトリ（github.com/syudat/alat-termux）のミラーからTermux環境をインストールするターミナルツールをインストールボタンがあります。公式Termuxリリースから取得するTermux をインストールボタンに加えたもう一つの方法です。ミラーの内容は公式リリースとまったく同じで、インストール時にSHA-256で検証されます。環境をインストールした後、pkg updateとpkg installコマンドが使えるようになり、リポジトリの追加ツールもターミナルにインストールされます。環境情報を表示するinfo-terminal、キャッシュを消去するbersih-terminal、プロジェクトフォルダを日付付きのtar.gzファイル1つにアーカイブするcadangkan-proyekです。その後、アプリは基本的なLinuxパッケージ（git、python、curl、wget、nano、openssh、zip、unzip）と署名付きAPKビルドツール（openjdk-21、kotlin、gradle、ecj、aapt2、d8、apksigner、clang、cmake、ninja、make）を公式Termuxリポジトリから自動的にインストールするので、ターミナルはすぐにアプリをビルドできる状態になります。大きなパッケージのダウンロード（数百MB）には時間がかかる場合があります。インストール中は、進行状況とコマンド出力がターミナルのメイン画面に表示され、最終結果はスクリーンリーダーが読み上げます。パッケージのインストールがまだ終わっていない場合は、ターミナルツールをインストールをもう一度押して続けてください。

フル音声モード
IDEを完全に音声で操作するには：メインメニューでフル音声モードを開き、聞き取りを開始を押します。IDEは継続的に聞き取ります。コマンドごとにボタンを押す必要はありません。コマンドを実行し、音声で応答します。26のコマンドがあります。作成、ビルド、開く、実行、一覧表示、検索、削除、テスト、確認、エクスポート、バックアップ、共有、アイコン作成、翻訳、ターミナルでビルド、画面を読む、すべての画面を開く（セキュリティ、オフラインAI、ウィジェット、ソーシャルメディア、ゲーム、学習、クラウド、バックエンド、テーマ、アニメーション、レコーダーを含む）、戻る、閉じる、ヘルプです。モードを有効のままにしておくと、この画面を再度開いたときに聞き取りが自動的に続きます。このモードをオフにするには聞き取りを停止を押してください。スマートフォンに音声認識サービスがない場合でも、コマンドはテキストボックスに入力できます。

コード翻訳
インターネットなしで言語間でコードを翻訳するには：メインメニューでコード翻訳を開き、プロジェクトを選び、ソースファイル（.java/.kt）を選んで、方向を選びます。JavaからKotlinへです。翻訳を押します。結果は翻訳できない行のレポートとともに表示されます（その行はそのまま保存され、マークされます）。結果を保存を押すと、同じフォルダに新しいファイル（名前-翻訳.java/.kt）が書き込まれます。元のファイルは上書きされません。これはパターンルールの翻訳機であり、コンパイラではありません。使用前に必ず結果を確認してください。

アプリ内Git
TermuxなしでIDE内でGitを使うには：メインメニューでアプリ内Gitを開き、プロジェクトを選び、Git リポジトリを作成を押して、そのプロジェクトにローカルリポジトリ（.git）を作ります。ステータスを確認を押すと、最後のコミットと比べて新しい・変更された・削除されたファイルが見られます。コミットメッセージを入力してCommitを押すとプロジェクトのスナップショットが保存されます。コミットログを表示を押すとコミット履歴が見られます。GitHubへのPushとGitHubからのPullはGitHubトークン経由のスナップショットを使います（pembuat-aplikasi-buildリポジトリ）。gitプロトコルではありません。Clone、Push（システムgit）、Pull（システムgit）は、gitバイナリがスマートフォンにインストールされている場合にのみ動作します（通常はありません）。これは完全なgitではありません。merge、branch、diffはありません。各コミットはプロジェクト全体のZIPスナップショットを保存します。

広告メーカー
ビルド済みアプリに広告を追加するには：メインメニューで広告メーカーを開き、プロジェクト、プロバイダー（AdMob、Unity Ads、AppLovin）、広告の種類（バナー、インタースティシャル、リワード）を選びます。すでにお持ちの場合は広告ユニットIDを入力してください。空欄の場合はテストIDを使います（AdMobはGoogleの公式テストIDを使用、UnityはサンプルGame IDを使用、AppLovinは空白を使用）。広告コードを作成を押すとJavaとKotlinのコードとガイドが表示されます。プロジェクトに保存を押すと、すべてがプロジェクトの広告-<プロバイダー>-<種類>.txtファイルに書き込まれます。これはコードテンプレート＋ガイドであり、広告SDKではありません。SDKはIDEに含まれていません。本物の広告は、プロバイダーアカウントを作成し、広告ユニットを作成し、自分のユニットIDを貼り付け、プロジェクトのbuild.gradleにSDK依存関係を追加した後に表示されます。

キッズモード
子どもと一緒にIDEを使うには：メインメニューでキッズモードを開きます。画面は大きなボタンで簡素化され、安全なアクションは4つだけです。プロジェクトを作成（安全なテンプレートから：電卓、数字当て、クイズ、星をキャッチ）、プロジェクトを開く、実行、学習です。この画面には削除、エクスポート、バックアップ、トークン設定のボタンはありません。初めて入るときは4桁のPINを作成します。そのPINは保護者がキッズモードを終了するために使います（子供モードを終了ボタンまたは戻るボタン）。このPINは小さな子ども向けの軽い保護であり、本物のセキュリティではありません。

Wear OS & TV アプリメーカー
時計アプリ（Wear OS）やテレビアプリ（Android TV）を作るには：メインメニューでWear OS & TVを開き、対象（Wear OS、Android TV、または両方）を選びます。プロジェクト名を入力して新しい Wear/TV プロジェクトを作成を押します。IDEはJavaプロジェクトを作成して調整します。または、既存のプロジェクトを選んでこのプロジェクトに適用を押します。調整内容：マニフェストのuses-feature、テレビ用のLEANBACK_LAUNCHERカテゴリ＋バナー、調整済みのactivity_main.xmlレイアウト（Wear：小さい画面、TV：D-padに適した大きい画面）です。詳細な説明はプロジェクトのwear-tv.txtに書き込まれます。これはプロジェクトテンプレートです。ビルドとテストにはWear OSまたはAndroid TVのデバイス/エミュレータが依然として必要です。テレビバナー（banner.png 320x180）は自動作成されません。自分で追加する必要があります（例：アイコンメーカー経由）。

プロジェクトマップ
プロジェクトの構造を見るには：メインメニューでプロジェクトマップを開き、プロジェクトを選び、地図を表示を押します。IDEはフォルダとファイルの一覧をサイズ付きで表示し、合計サイズ、ファイル種類ごとのサイズ、重要なファイル（主要ファイル、マニフェスト、レイアウト、文字列、アイコン、ウェブページ）を表示します。peta-proyek.txt を保存を押すと、同じマップがプロジェクトのルートに書き込まれます。bin/フォルダ（ビルド結果）と.git/フォルダ（ローカルリポジトリ）は、内容を再作成できるためマップに含まれません。

APKサイズ計算機
ビルドする前にビルド済みAPKのサイズを見積もるには：メインメニューでAPKサイズ計算機を開き、プロジェクトを選び、見積もりを計算を押します。IDEはカテゴリごとの内訳（コード/DEX、リソース、アセット、ネイティブライブラリ、マニフェスト＋resources.arsc、オーバーヘッド）、合計見積もり、最大の5ファイル、縮小の提案（例：大きな画像は解像度を下げ、大きな音は長さを切る）を表示します。これは見積もりであり、正確なサイズではありません。実際のサイズは、aapt2圧縮、未使用コードの削除（R8）、ビルド結果のリソースにより異なる場合があります。

APKアナライザー
完成したAPKの内容を読むには（Android StudioのAPKアナライザーのように）：メインメニューでAPKアナライザーを開き、プロジェクトを選び、ビルド結果 APK の分析を押します。IDEはそのプロジェクトのbinフォルダにある最新のAPKを読み取り、パッケージ名、バージョン、最小SDKと対象SDK、使用する権限の一覧、dexファイルの数、部分ごとのサイズ内訳（プログラムコード、リソース、アセット、ネイティブライブラリ、署名）、最大の10エントリを報告します。APKを大きくしている部分と、ビルド済みアプリが使う権限を知るのに役立ちます。

画面サイズプレビュー
複数の画面サイズでプロジェクトの外観を一度に確認するには（Android Studioのように）：メインメニューで画面サイズプレビューを開き、プロジェクトを選び、画面サイズを確認を押します。IDEはプロジェクトのすべてのレイアウトを読み取り、幅が固定で書かれ（例：400dp）、320、360、411、480 dpの画面幅を超える要素を報告します。小さい画面のスマートフォンでは、そのような要素が隠れたりはみ出したりする可能性があるためです。match_parentやwrap_content幅の要素は画面に自動的に適応し、確認は不要です。

リソースマネージャー
プロジェクトのすべてのリソースを一か所で見て管理するには（Android Studioのリソースマネージャーのように）：メインメニューでリソースマネージャーを開き、プロジェクトを選び、リソースを表示を押します。IDEはカテゴリごとのファイル数とサイズ（drawable、layout、values、mipmapなど）、strings.xml、colors.xml、styles.xmlの内容を報告します。同じ画面から、名前と値を入力してstrings.xmlに新しい文字列、colors.xmlに新しい色を追加できます。名前は検証され、重複は拒否されるため、XMLファイルは壊れません。

軽量パフォーマンスモニター
実行中のアプリのRAMとプロセッサ使用量を監視するには（Android StudioのProfilerの軽量版）：メインメニューで軽量パフォーマンスモニターを開き、まず確認したいアプリを実行します（例：試しているビルド済みアプリ）。そのパッケージ名を入力します。またはプロジェクトを選んでプロジェクトからパッケージ名を入力を押します。その後、監視を開始を押します。IDEは2秒ごとにそのアプリのRAM（PSS）とCPUをスマートフォンの空きRAMとともに記録します。停止を押すと平均とピークの要約が表示されます。追加の権限は不要です。新しいAndroidバージョンでは、他のアプリのプロセッサ読み取りアクセスがシステムにより制限されるため、CPUが読めない場合、レポートはその旨をそのまま伝え、RAMの監視は続きます。

アクセシビリティ監査
リリース前にプロジェクトのレイアウトがスクリーンリーダー（TalkBack/Jieshuo）にやさしいかどうかを確認するには、メインメニューでアクセシビリティ監査を開き、プロジェクトを選んでからレイアウト一覧を読み込むをタップしてレイアウトファイルを選択します。IDE はその XML ファイルを読み、ラベルのないボタンとその行番号、繰り返し使われているラベル、重なり合っている要素を報告し、Jieshuo が読み上げるようなフォーカス順の記録を作成します。ラベルのないボタンがある場合はラベルを入力してからラベルを自動挿入をタップしてください。ラベルは contentDescription としてレイアウトファイルに書き込まれます。このチェックはレイアウト XML のみを読みます。Compose の画面や完成した APK はまだスキャンされません。

クラッシュの解剖
アプリがなぜ自分で閉じるのかを、一意の ID を持つクラッシュログから知るには、メインメニューで「クラッシュの解剖」を開き、ログリストからクラッシュ ID を選んで「チェック」を押します。IDE はログ内のクラスと行番号をプロジェクトのソースと照合し、原因をインドネシア語で説明します（例：空の参照、まだ要求されていない許可、JSON エラー）。コードパッチの提案も一緒です。「修正を適用」は、ソース行がクラッシュ時にあったものとまだまったく同じ場合にのみ押してください。変更されている場合、パッチは拒否され、IDE は自分でチェックするよう求めます。ビルドされたアプリのクラッシュについては、「クラッシュキャッチャーをプロジェクトに注入」を押し、通常どおり APK をビルドします。そのビルドされたアプリは自分のクラッシュを自分で捕捉し、ログを電話に書き込みます。そのログは「ビルド済みアプリのクラッシュログを検索」ボタンで見つけることができます。正直な制限：Android 11 以上で公開 Download フォルダにログをコピーすることは、すべてのファイルへのアクセス許可がないと失敗する可能性があります。

パラダイム横断トランスパイラ
シンプルな Java コードを Kotlin に変換したり、シンプルな XML レイアウトを Compose コードに変換したりするには、メインメニューでパラダイム横断トランスパイラを開き、プロジェクトとファイルを選んでからプレビューをタップします。IDE は変換結果をテキストで表示します。まず確認してください。認識できない行はそのまま残され、Java の static という単語は Kotlin では削除されます（使う前に意味を確認してください）。XML から Compose への変換ではテキスト、ヒント、向きだけが変わります。サイズ、色、その他の属性はまだ対象外です。結果が正しければファイルに適用をタップして対象ファイルを書き込みます。ソースファイルは変更されません。安全で一般的なパターンのみが変換されます。

ローカルマイクロサーバー
インターネットなしでサーバーを必要とするアプリをテストするには、メインメニューで「ローカルマイクロサーバー」を開き、ルート定義を書き（例：GET /halo、その後その JSON 応答）、「サーバーを開始」を押します。IDE は同じ電話上で小さな HTTP サーバーを実行します（HTTP のみ、TLS なし、同じ Wi-Fi ネットワーク用）。すべてのリクエストと応答を画面に記録します。ルートは {nama} のようなパラメータと単純な API キーを使用できます。サーバーはビルドされた APK にバンドルすることもできます。「サーバーをプロジェクトにバンドル」を押すと、サーバーのソース、アセット、マニフェストがプロジェクトに注入され、ビルドされたアプリ自体が実行時にサーバーになります。IDE 内のサーバーは、その画面が閉じられると停止します。

セキュリティ監査
公開前にプロジェクトのコードのセキュリティ上の隙間をチェックするには、メインメニューで「セキュリティ監査」を開き、プロジェクトを選んで「スキャンを開始」を押します。IDE はプロジェクトのコード、マニフェスト、設定をスキャンし、リスクの高いものから低いものへと所見を報告します。コード内に開いたままにされた API キー、許可なしに公開されたコンポーネント、JavaScript インターフェースとともに JavaScript を有効にする WebView、弱い暗号化（MD5、SHA1、DES）、TLS のない http アドレス、コードに直接書かれたパスワードです。ファイルと行番号も一緒です。修正が安全な所見（例：MD5 を SHA-256 に、http を https に変更する）については「修正を適用」を押します。API キーとパスワードについては、IDE は修正の提案のみを表示します。代替案は開発者自身が決めなければならないためです。スキャンは現在、ビルドされた APK 内の実際の DEX バイトコードも分析します（コード内のテキストパターンだけでなく）。そのため、呼び出された危険な API や DEX に埋め込まれた秘密も捕捉されます。パターンに従わない隙間は、スキャンから逃れる可能性があります。適用前にチェックしてください。

インターフェーステストロボット
テキストシナリオを通じてアプリ画面を自動的にテストするには、メインメニューで「インターフェーステストロボット」を開き、プロジェクトを選んで「シナリオを自動作成」を押します。IDE はプロジェクトのマニフェストとレイアウトを読み、シナリオをテキストのステップとして書きます（ボタンを押す、フィールドに入力する、待つ、戻る）。シナリオ実行のログをタイムスタンプとともに見るには「ドライランを実行」を押します。このドライランはまだ順序のシミュレーションにすぎません。実際のテストには「テストエージェントをプロジェクトに注入」を押します。IDE はシナリオアセットとともにテストエージェントをプロジェクトに注入します。APK を通常どおりビルドし、インストールしてから「テスト」アイコンを開きます。そのエージェントはビルドされたアプリの内部で実行され、実際にボタンを押し、実際のフィールドに入力し、スクロールし、捕捉した実際のクラッシュとともにレポートを画面に表示します。エージェントを再度削除するには「プロジェクトからテストエージェントを外す」を押します。エージェントはアプリ自身のプロセス内で実行されるため、アクセシビリティサービスやシステムの自動化は必要ありません。

コードのタイムトラベル
Git コマンドを入力せずにプロジェクトを以前のコードの状態に戻すには、メインメニューでコードのタイムトラベルを開き、プロジェクトを選び、時点のラベルを入力して（空でもかまいません）、時点を記録をタップします。IDE はプロジェクトのソースファイルのコピーをハッシュとともに、プロジェクト内の .riwayat フォルダーに保存します。時点の一覧にはすべてが表示されます。2 つの時点を選んでから比較をタップすると、追加・変更・削除されたファイルと関数が表示されます。復元をタップすると古い状態に戻ります。復元する前に、IDE は必ず現在の状態のバックアップを先に作成するので、何も失われません。実験コピーを作成をタップすると、プロジェクトを新しいフォルダーにコピーし、元のプロジェクトを乱すことなく変更を試せます。記録されるのはソースファイルのみです。

モジュールファクトリ
プロジェクトの一部を、別のプロジェクトで使えるモジュールとしてパッケージ化するには、メインメニューでモジュールファクトリを開き、ソースプロジェクトを選び、パッケージ化する画面・クラス・文字列・権限ファイルにチェックを付けてからモジュールとしてパッケージ化をタップします。IDE は ZIP アーカイブと JSON メタデータ（モジュール名、バージョン、使用した文字列と権限）を書き込みます。モジュールを別のプロジェクトにインストールするには、モジュールファクトリを開き、対象プロジェクトを選んでからモジュールをインストールをタップしてモジュールの .zip ファイルを選択します。マージ処理では既存のコードを上書きせずに文字列と権限を追加します。ファイル名が対象プロジェクトで既に使われている場合は、そのファイルはマージされません。モジュールはライブラリやビルド設定を持ちません。

ポリモーフィックシールドとアセット保管庫
公開前に識別子名をランダム化し、プロジェクトのアセットを暗号化するには、メインメニューで「ポリモーフィックシールドとアセット保管庫」を開き、プロジェクトを選んで「名前のランダム化とアセットの暗号化」を押します。IDE はソースコード内のクラス名とメソッド名をスキャンし、ランダムな名前マップを作成し、それらの名前をコンパイル済み DEX ファイル内に書き換えます（置換名はすべてのオフセットが有効なままになるよう元の名前と同じ長さで作られ、その後 DEX ヘッダーのチェックサムと SHA-1 署名が再計算されます）。プロジェクトのアセットファイルをプロジェクト内の brankas-aset フォルダで AES-GCM により暗号化し、クラッシュログを読むときに元の名前を復元できるよう暗号化された復旧マップ（perisai-peta.brankas）を保存します。暗号化キーは現在、プロジェクト名ではなく開発者のパスワードから PBKDF2（20,000 回の反復）で導出されます。プレーンテキスト、注釈名、デバッグ名としても使われる名前は意図的に書き換えられず、ビルド経路における DEX 書き換えの挿入点は実際の電話でのテストをまだ待っています。

信頼チェーンと環境ガード
公開前に署名キー・チェーンと電話の環境をチェックするには、メインメニューで「信頼チェーンと環境ガード」を開き、プロジェクトを選んで「チェーンと環境をチェック」を押します。IDE はプロジェクトのパッケージ名から 5 世代のキー・チェーンを構築してその完全性をチェックし、メモリ内のコード部分の内容をディスク上のファイルと比較して実際のメモリの完全性をチェックし、無名の実行可能（RWX）マッピング、外部ライブラリ、memfd マッピングを報告し、次に自身のプロセスのメモリマップとデバイスのプロパティを Frida、Xposed、エミュレータの痕跡についてスキャンします。保管庫のキーは、利用可能な場合にハードウェア・セキュリティチップを使用する AndroidKeyStore 内の AES キーでラップされ、キー・ローテーションは現在、スキーマ v3 署名証明書の系譜を用いて本物です。古いキーが新しいキーへのローテーションの証拠に署名し、APK はその系譜で再署名されます。結果は、テキストによる証拠とともに「安全」「注意」「危険」のリスクレベルです。システムがメモリの読み取りを拒否した場合、チェックは安全ではなく「検証不能」と報告されます。また、キーが実際にハードウェア・セキュリティチップを使用しているかどうかは、実際のデバイスでのみ確認できます。

テキストツリー・レイアウトアーキテクト
画面を見ずに設計するには、メインメニューで「テキストツリー・レイアウトアーキテクト」を開き、プロジェクトとレイアウトファイルを選んで「レイアウトをチェック」を押します。IDE は XML レイアウトをテキストツリーとして読み、各要素の位置の説明を音声で読み上げます（例：右下、画面幅の 45 パーセント）。その後、要素同士の重なりと 360 dp 幅で画面外に出る要素を数学的に報告します。現在計算されるものには、LinearLayout と単純な dp サイズ、完全な ConstraintLayout（すべての制約、バイアス、チェーン、ガイドライン、バリア、パーセント幅、0dp match_constraint、寸法比）、および Compose 画面（サイズ修飾子付きの Column、Row、Box）が含まれます。実行時に変化する MotionLayout と ConstraintSet のみ、位置が不明として報告され続けます。その値はアプリの実行中にしか存在しないためです。

デザインシステムスタジオ
すべての画面とプロジェクトで間隔、フォント、角を統一するには、メインメニューで「デザインシステムスタジオ」を開き、プロジェクトを選び、デザイン・トークンを書き（例：jarak=8, huruf=16, sudut=12）、コンポーネントを選んで「コンポーネントを生成」を押します。IDE はトークンを検証します。基本間隔は 4〜16 dp、基本フォントは 12〜20 sp、角は 0〜32 dp、最小タッチ領域は 48 dp です。その後、すぐに使える XML コンポーネント（komponen-studio.xml）を XML テーマ（tema-studio.xml）および Compose テーマ（tema-studio.kt）とともにプロジェクトフォルダに書き込みます。トークンはプロジェクト間で共有されるトークンライブラリに名前付きセットとして保存することもでき、1 つの同期コマンドがライブラリの最新のトークンをそのセットを使うすべてのプロジェクトに適用します。コンポーネントはレイアウトに貼り付けるテキストとして作成され、その後「テキストツリー・レイアウトアーキテクト」でチェックされます。タブレットでの 2 列調整は、実行時のデバイス検出ではなく画面幅修飾子を使用します。

セマンティックリファクタリングとASTナビゲーション
定義を検索し、偶然同じ名前を持つ他のコードを壊さずにシンボル名を変更するには、メインメニューで「セマンティックリファクタリングとASTナビゲーション」を開き、プロジェクトを選んで「プロジェクトシンボルをスキャン」を押し、すべてのクラスとメソッドをファイルと行番号とともに表示します。シンボル名を入力し、「プロジェクトシンボルをスキャン」をもう一度押して、その定義とそれを呼び出すすべてのファイルを表示します。名前を変更するには、新しい名前を入力し、「名前変更のプレビュー」を押して各ファイルでの出現回数を確認し、「名前変更を適用」を押します。インデクサは現在、手作りの AST パーサ（Java および Kotlin サブセット用のレキサと再帰パーサ）を使用しているため、ファイル間のメソッド名変更が解決され、他のファイルの呼び出し元も変更されます。コードブロックを新しい関数に抽出するボタンは、この画面にあります。このパーサはまだ最小限です。非常に複雑なジェネリクス、パラメータ付きアノテーション、無名クラスはそのままスキャンされ、リフレクションやインターフェース経由の呼び出しは解決されません。

ステップデバッガとメモリインスペクタ
ログから推測せずにプログラムの流れの途中で変数の内容を調べるには、メインメニューで「ステップデバッガとメモリインスペクタ」を開き、プロジェクトを選び、実行トレースを書きます（1 行に 1 ステップ、形式：行番号、コード、次に | で区切られた変数と値、例：10|int total = harga * jumlah;|harga=5000, jumlah=3, total=15000）。ブレークポイントの行番号を入力し、「デバッグトレースを実行」を押します。IDE は最初のブレークポイントまで実行し、Jieshuo を通じてアクティブな行をその変数の値とともに音声で読み上げます。「1行ステップ」を押して 1 行進み、「関数に入る」を押して呼び出された関数に入り（コールスタック付き）、「プログラムを続ける」を押して次のブレークポイントまで進みます。このトレースデバッガは、記録されたトレースまたは手書きのトレースにまだ従います。その横には純粋な Java の JDWP ワイヤプロトコルクライアントがあり、ハンドシェイク、ブレークポイントの設定、ステップイン、ステップオーバー、ステップアウトができ、TCP またはリスニングモードで VM を一時停止および再開できます。通常のアプリの内部から実際のプロセスを停止することは、まだ完全には不可能です。プロセスの JDWP ソケットは adbd 経由でしか公開されないためです。実証された経路では、ワイヤレスデバッグとシェル経由のターゲットの起動が必要であり、アプリ自体ができることの範囲を超えています。

オフライン依存関係マネージャ
インターネットなしでサードパーティライブラリを使い、ビルド前にバージョンの競合を避けるには、メインメニューで「オフライン依存関係マネージャ」を開き、プロジェクトを選んで「依存関係をチェック」を押します。IDE はプロジェクトのすべての .gradle ファイルを読み、Download/brankas-bersama フォルダ内のプロジェクト間で共有される保管庫をチェックし、競合を解決します。2 つのライブラリが同じ成果物の異なるバージョンを要求した場合、最も高いバージョンが使用され、競合が報告されます。ライブラリをダウンロードするには、その座標を入力し（形式：グループ:成果物:バージョン、例：com.google.code.gson:gson:2.10.1）、「依存関係をチェック」を押します。オンラインの場合、AAR、JAR、WHL ファイルは実際に Maven、Google、PyPI から推移的依存関係グラフとともにダウンロードされます（再帰的、サイクルは切断、深さ最大 25 レベル）。正常にダウンロードされたファイルのみが利用可能として記録されます。オフラインの場合、共有保管庫に既にあるライブラリのみ使用できます。Maven のバージョン範囲は解決されず、ダウンロードされたファイルは SHA-1 でのみチェックされ、PGP 検証はありません。

データベースとストレージのインスペクタ
テーブルの内容を出力するコードを書かずにプロジェクトのデータベースの内容を調べ、テストするには、メインメニューで「データベースとストレージのインスペクタ」を開き、プロジェクトとデータベースファイル（.db、.sqlite、.sqlite3）を選んで「データベースを開く」を押します。IDE は完全な SQLite ページパーサ（オーバーフローページ付き B ツリー）ですべてのテーブルのスキーマを読み、最初の 20 行を Jieshuo が音声で読み上げるテキスト表として表示します。SELECT クエリを書いて「クエリを実行」を押します（例：SELECT nama FROM pengguna WHERE kota = 'Makassar'）。クエリは現在 JOIN、GROUP BY、ORDER BY、LIKE をサポートし、電話では実際の Android SQLite エンジンで実行されます。値を変更するには、行番号（1 = 最初の行）、列名、新しい値を入力し、「セルの値を変更」を押します。その値が .db ファイルに書き戻されます。「バックアップを保存」を押すと、テーブルの現在の状態がプロジェクト内に <データベース名>.cadangan.txt ファイルとして保存されます。SharedPreferences と DataStore も読むことができます。まだ読めないもの：暗号化されたデータベース、未コミットの WAL 変更、特別な DataStore Proto 内の型付き値（一般的なフィールドビューとしてのみ表示されます）。

単体テスト工場とファジング
アプリを共有する前に論理の隙間を見つけるには、メインメニューで「単体テスト工場とファジング」を開き、プロジェクトとコードファイルを選んで「テストを作成して実行」を押します。IDE はファイル内の関数シグネチャを読み、通常および境界のテストケースを作成します（空のテキスト、null、最大数、奇妙な文字）。その後、それらのテストを実際に実行します。プロジェクトのコードがコンパイルされ、各 @Test メソッドが 5 秒の制限で実行されるため、結果は実際の値とともに実際の合格と失敗です。ファジングもプロジェクトの関数に対して実際に実行されます（リフレクション経由、呼び出しごとに 2 秒、最大 20 メソッド）。行カバレッジ率は、元の行番号を保持する計測により実際に計算されます。結果は、テストのうちいくつが合格し、いくつが失敗したか、コードの行数と関数がいくつ見つかったか、どのようなテストケースが作成されたかを報告します。作成されたテストは JUnit とまったく同じ API を使用しますが、注釈とアサーションの定義は作成されたテストファイル自体の内部に書かれています。実際の JUnit ライブラリはアプリに含まれていないためです。

極端なデバイス条件シミュレータとメモリリーク監査
システムがプロセスを終了したとき、ネットワークが切断されたとき、画面が回転したとき、またはバッテリー節約がオンになったときにアプリの耐久性をテストするには、メインメニューで「極端なデバイス条件シミュレータとメモリリーク監査」を開き、プロジェクトを選んで「シミュレーションを実行」を押します。IDE は画面回転シミュレーションとともに 3 つのストレスシナリオを実行し、画面が閉じた後もメモリに保持されているオブジェクトを追跡し、失われたデータとリークしているオブジェクトチェーンを報告します。保存と復元の状態は現在、固定された例ではなく、ユーザー自身のプロジェクトソースから読み取られます。ローカルループバックサーバーは、ネットワーク切断を測定するためにテストの途中で実際に停止されます。実際のヒープダンプが取得され分析され、2 つのダンプが比較され、GC ルートからの保持チェーンが追跡されます。アプリ自身のプロセスは、状態を保存した後に実際に終了され、再度開いたときにどのデータが戻るかがチェックされます。通常のアプリからまだ不可能なこと：電話の無線や Wi-Fi をオフにすることと、他のアプリを強制終了することです。どちらもシステム権限が必要です。その代わりに、バックグラウンドアプリは、権限がすでにマニフェストにある killBackgroundProcesses で終了され、画面には正直なラベルが付いています。

プロジェクト設計図アーキテクト
大きなアプリのアイデアを段階的な作業計画に変えるには、メインメニューで「プロジェクト設計図アーキテクト」を開き、プロジェクトを選び、アプリのアイデアを書き（例：分割払い付きの小さな食料品店のレジアプリ）、「設計図を作成」を押します。IDE はモジュール、ファイルリスト、小さなマイルストーンを作成し、それらをプロジェクトフォルダに cetak-biru.txt として保存します。マイルストーンが完了するたびに「次のマイルストーンを完了にする」を押し、保存された設計図を再度開くには「保存された設計図を読み込む」を押します。「AI 設定」で有効な AI プロバイダが選択され、そのキーが利用可能な場合、設計図はそのプロバイダによって作成されます。キーがない場合やプロバイダに到達できない場合、IDE はオフラインのキーワードパターンに戻り、その制限を正直に伝えます。プロバイダの回答は形式についてのみチェックされます（モジュールとマイルストーンが存在するかどうか）。内容の正しさについてはチェックされません。ビルド前に必ず設計図を確認してください。

コード論理フロー・ナレーター
構文を一行ずつ聞かずに長いコードを理解するには、メインメニューで「コード論理フロー・ナレーター」を開き、プロジェクトとコードファイルを選んで「コードの説明」を押します。IDE は各行をインドネシア語の文に変換します（例：合計が 100000 を超える場合、次のブロックを実行する）。メソッド間の呼び出しマップとメソッド間のデータフロー分析（渡された値、使用された値、無視された値）を表示し、微妙な潜在的バグを行番号とともにマークします。== で比較される String、閉じられずに開かれたストリーム、2 つの異なるメソッドに書き込まれた変数です。「AI 設定」で有効な AI プロバイダが選択されている場合、そのプロバイダからのフロー要約も利用できます。利用できない場合、画面はオフラインの説明を使用し、その制限を伝えます。説明、呼び出しマップ、データフローはオフラインのテキストパターン分析を使用し、完全な AST パーサではありません。開きブレースが独自の行にあるメソッド、クラスフィールド、リフレクション経由の呼び出しは追跡されません。データ競合の警告は、実際には交互にしか使用されない変数に対して表示されることがあります。

アプリバンドル工場とPlayストア準備状況
電話から直接 Google Play ストア用にアプリを準備するには、メインメニューで「アプリバンドル工場とPlayストア準備状況」を開き、プロジェクトを選んで「AABバンドルを作成」を押します。IDE は実際の BundleConfig.pb とともにプロジェクトのマニフェスト、リソース、アセットから .aab ファイルを作成し、バンドル構造を検証し、バンドルを実際のバリアント APK（基本、アーキテクチャ別、言語別、ユニバーサル）に分割します。サイズはその分割から測定されたもので、推定ではありません。バンドルは APK 署名に使用されるのと同じプロジェクトキーで JAR v1 により署名され、その署名チェーンは暗号学的に検証されます。この画面は Play の準備状況も監査します。ターゲット SDK が 35 未満の場合、Play ストアが 35 以上を要求するため「高」とマークされ、欠落している 64 ビットライブラリも「高」とマークされます。実際の bundletool はデバイス上で実行できません。bundletool は JVM を必要とするのに対し、Android には JVM がないためです。上記の経路がデバイス上で最も近い実際の経路です。

OTA更新エンジンと段階的リリース
ユーザーに APK 全体を再ダウンロードさせることなく小さな修正を送るには、メインメニューで「OTA更新エンジンと段階的リリース」を開き、プロジェクトを選び、古いバージョンと新しいバージョンの内容を書いて「パッチパッケージを作成」を押します。IDE は差分を計算し、新しい内容の SHA-256 フィンガープリントとともにパッチパッケージ（patch-ota.zip）を作成し、このデバイスが最初の 10 パーセントのロールアウト段階にあるかどうかをチェックします。パッチは現在、すべてのファイルでバイナリ差分をサポートし（DEX と APK を含む）、RSA-2048 署名でパッケージ化され、適用前に信頼できる公開キーで検証され、開発者のサーバーからそのリリースリストとともにダウンロードできます。適用に失敗した場合、古いファイルはそのまま残ります。実行中のアプリへのパッチの適用は、プロジェクトキーによる再署名と PackageInstaller を通じて行われます。実行中のプロセスのコードをその内部から置き換えることは不可能だからです。APK はロックされ、DEX はすでに読み込まれています。

チームコードレビュースタジオ
同僚の変更を確認し、Git の矢印マークを読まずにマージの競合を解決するには、メインメニューで「チームコードレビュースタジオ」を開き、プロジェクトを選び、3 つのテキストバージョン（基本、ローカル、同僚）を入力し、「チームレビューを開く」を押します。IDE は Java の構文単位に基づいて 3 つをマージします。同じ行での 2 つの変更でも、異なる文にある場合はもはや競合とは見なされません。各競合を投票選択として表示します。ローカルバージョンを使用する、同僚のバージョンを使用する、または両方をマージする。結果の行は、順序が正しいままになるよう元の競合位置に挿入され、結果はプロジェクト内の gabung-hasil.txt に書き込まれます。その下にはプロジェクトタスクボードがあります。タスクのタイトルを入力し、「タスクを追加」を押します。タスクはプロジェクト内の .tugas フォルダにテキストとして保存され、アプリ内 Git のコミットを通じて同期されるため、ボードはどのコミット履歴からでも再度読むことができます。この構文分割子は完全な AST パーサではなく、アプリ内 Git は各コミットについて完全なスナップショットを保存します。専用の同期サーバーはありません。

コード構造の音声入力
エディター内で音声でコードを書くには、エディターでプロジェクトを開いてからコード構造の音声入力ボタンをタップします。インドネシア語でコマンドを話してください。例：buat fungsi tambah dengan parameter a angka dan b angka、buat kelas Mobil、buat variabel teks nama sama dengan Budi。IDE は音声を文法的に正しい Java、Kotlin、Python、または Compose のコードブロックに変換し、カーソル位置に挿入してから、Jieshuo を通じて短い要約を読み上げます。音声入力はシステム内蔵の音声入力サービスを使い、追加のマイク権限は不要です。登録済みのコマンドパターンのみを認識します。パターン外の発話はコードに変換されません。単語で話した数字（例：'lima'）はまだ数字に変換されません。

ローカルコラボレーションルーム（インターネットなし）
インターネットなしで同じ部屋で一緒に作業するには、メインメニューでコラボレーションを開いてからローカルコラボレーションルームのセクションを開きます。1 台のスマートフォンがセッションを開き（IDE にはローカル IP アドレスと 6 桁の PIN が表示されます）、別のスマートフォンがそのアドレスと PIN で参加します。テキストの変更は行の差分として送信され、ビルド済み APK をテスターのスマートフォンに送信でき、テスターのスマートフォンからのクラッシュ報告も受け取れます。1 つのセッションは 1 人の友人専用です。2 人がまったく同じ行を同時に変更した場合は、最後の変更が使われます。PIN はローカルネットワーク上で平文として送信されます。このルームはまだ実際のスマートフォンでテストされていません。

AI 設定
アプリを作成するための AI プロバイダと API キーを設定するには、メインメニューで、設定グループ内の「AI 設定」を押します（「コネクタ」ボタンの隣）。使用するプロバイダを一覧から選び、1 つのモデルが失敗した場合に IDE が同じプロバイダの次のモデルを自動的に試すよう「プロバイダーでエラーが発生したらモデルを切り替える」にチェックを入れます。バックアップキーを追加するには「API キーを管理」を押し（名前とキーを入力し、「保存」を押します。キーはマスクされて表示され、最後の 4 文字だけが見えます）。キーは電話に保存され、アプリ作成時に選択されたプロバイダ以外には決して送信されません。選択されたプロバイダは現在、「プロジェクト設計図アーキテクト」と「コード論理フロー・ナレーター」によって実際に使用されています。「AI によるアプリ作成」画面でのアプリ作成は、依然として電話上のローカル AI を使用します（インターネットなし）。

コネクタ
APK を分析してから送信するには、メインメニューで設定グループ内のコネクタをタップします（AI 設定ボタンの隣）。スマートフォンから APK ファイルを選択すると、IDE はその内容（パッケージ名、バージョン、アクティビティ一覧）を読み取ります。次に APK を送信をタップして、システムの共有メニュー（例：WhatsApp や Drive）から送信します。

言語と音声
アプリの言語を変更するには、設定を開いてからアプリの言語を開き、言語またはシステムに従うを選択します。メイン画面とほとんどの画面は、アプリを閉じたり再起動したりしなくても、選択した言語にすぐに変わります。一部の画面（例：ターミナル、コラボレーション、AI 設定、キー管理）は、再度開くまで古い言語のままです。システムに従うを選ぶと、言語はスマートフォンのシステム言語に従います。

プロジェクトごとのデフォルト署名と改ざん防止
バージョン5.7以降、個人署名を使わないプロジェクトは、そのプロジェクト専用の内蔵キーで署名されます（プロジェクト内のtanda-tangan-bawaanフォルダに一度作成され、その後使い続けられます）。そのため内蔵署名はプロジェクトごとに異なります。すべてのアプリで共通のキーを使うことはもうありません。tanda-tangan-bawaanフォルダを削除しないでください。そのキーがないと、新しいAPKは同じプロジェクトの古いAPKを上書きできません。各プロジェクトの設定（分離アーキテクチャ、個人署名、改ざん防止、選択したkeystore、SDK）は、プロジェクト内のsettings.gradleファイルに保存され、プロジェクトがビルドされるたびに再度読み取られます。設定の署名カテゴリに、ビルド済みアプリの改ざん防止チェックボックスがあります。有効な場合、デバイス上のビルド済みアプリは開くたびに自分の署名とdex内容を確認します。再署名されたり他人に変更されたりした場合、アプリは実行を拒否します。Frida/Xposedのようなデバッガやインジェクションツールも検出され、アプリウィンドウは画面録画からロックされます。

デモ動画メーカー
ビルド済みアプリのデモ動画を作るには：メインメニューでデモ動画メーカーを開き、プロジェクトを選び、動画タイトルを入力して、デモ動画スクリプトを作成を押します。IDEはナレーション文と各シーンの長さを含む5つの標準シーン（オープニング、メイン画面、機能1、機能2、エンディング）のvideo-demo.txtを書き込みます。HTML スライドショーを作成を押すと、プロジェクトの画像（アイコン＋あればスクリーンショット）から5秒ごとに自動で切り替わるvideo-demo.htmlが作られます。これは.mp4動画ではありません。本物の動画には、スマートフォンのブラウザでvideo-demo.htmlを開いて画面を録画するか、実行中のアプリを録画しながらvideo-demo.txtのナレーションを読んでください。

Android Studio 風の新しい外観
IDEの外観はAndroid Studioのようにすっきりと整理されました（外観のみ。すべてのボタン、メニュー、流れは以前とまったく同じです）。明るい灰色の背景、太い黒の画面タイトル、白いテキストの青いボタン、細い枠の白い入力ボックスです。メインメニューはボタンの順序を変えずに視覚的にグループ化されています（ビルダー機能、クラウド、テーマとその他、音声、コードと新機能、ツール）。ターミナルはAndroid Studioのターミナルウィンドウのような暗いパネルを使い続け、コードエディタは白い背景と黒いテキストを保ちます。すべてのテキストはJieshuoではっきりと読めます。

設定
アプリを設定するには：メイン画面でオプションメニューを開き、設定を押します。中には12のカテゴリがあります。GitHub 設定（セキュリティ、個人署名、ビルド履歴、GitHubトークン）、デバイスでのAPKビルド設定（keystoreパスワードとビルド履歴をデバイスに保存）、テーマ（アプリの色）、署名（個人署名用のkeystoreを作成、ビルド済みアプリの改ざん防止チェックボックス）、プロジェクトフォルダ（プロジェクトフォルダの場所）、言語と音声（インターフェース言語と音声モードの話速）、テキストサイズと表示（エディタのフォントサイズ）、ビルド（プロジェクト作成画面のデフォルト対象SDKとデフォルトアーキテクチャ分割）、通知（ビルド完了時の音）、自動バックアップ（プロジェクトバックアップのスケジュール）、開発者プロフィール（寄付画面に表示される名前、WhatsApp番号、口座）、プライバシーとデータ（設定をリセット、アプリデータを削除）です。各カテゴリにはカテゴリメニューに戻るための前に戻るボタンがあります。新しく保存されただけの（まだ適用されていない）設定は、画面に正直に説明が書かれています。

開発者に寄付
寄付をする、または開発者に挨拶するには：メイン画面のツールについてボタンの横にある開発者に寄付ボタンを押します。寄付画面にはBRI 口座をコピーボタンがあります。開発者の口座番号をコピーするために押して、銀行アプリに貼り付けてください。WhatsApp で開発者に挨拶セクションもあります。名前と出身地を入力し、WhatsApp で送信を押します。WhatsAppが挨拶メッセージがすでに入力された状態で開きます。WhatsAppで送信を押してアプリに戻ってください。WhatsAppは他のアプリが自動的にメッセージを送信することを許可しないため、送信はWhatsApp内で自分で行います。

ターミナルのお気に入りコマンド
ターミナルでよく使うコマンドを保存するには：ターミナルを開き、お気に入りを押します。新しいお気に入りを追加をタップし、名前（例：ファイルを表示）とコマンド（例：ls -la）を入力して、保存を押します。お気に入りはスマートフォンに永続的に保存されます。お気に入り名をタップするとターミナルで直接実行されます。お気に入りを削除をタップして削除するものを1つ選びます（確認付き）。内蔵のお気に入りはすでに3つあります。ファイルを表示（ls -la）、容量を確認（df -h）、画面をクリア（clear）です。すべて削除できます。空のコマンドは保存も実行もできません。その場合はターミナルがメッセージと音声で知らせます。

分析と品質
アプリ使用の要約とクラッシュレポートを見るには：メイン画面で開発者に寄付ボタンの横にある分析と品質ボタンを押します。この画面には、アプリが開かれた回数、最もよく開かれた画面、クラッシュ数、短い修正提案付きの最新のクラッシュ一覧が表示されます。このデータはスマートフォン内にのみ保存され、どこにも送信されません。すべてのデータを削除するための確認ダイアログ付きの分析データを削除ボタンがあります。最後の画面はメイン画面とこの画面についてのみ記録されます。
