Sugeng rawuh ing Create Aplikasi by Al Kautsar
Create Aplikasi inggih punika aplikasi kangge ndamel aplikasi Android ingkang mlampah langsung wonten ing ponsel, tanpa mbetahaken laptop. Aplikasi punika maringi kalodhangan dhumateng sinten kemawon kangge ndamel aplikasi Android piyambak, kalebet para pangangge ingkang nembé sinau ndamel aplikasi saha para pangangge pamaca layar. Pandhuan jangkep ngginakaken aplikasi punika cumawis wonten ing layar Tentang Alat punika.

Aplikasi punika punapa lan kangge sinten
Create Aplikasi inggih punika piranti kangge ndamel aplikasi Android ingkang mlampah wonten ing ponsel. Aplikasi punika dipunangkah kangge sinten kemawon ingkang ngersakaken ndamel aplikasi Android piyambak, kalebet para pamula saha para pangangge pamaca layar. Aplikasi punika nyawisaken editor kode, tombol Jalankan kangge nyobi proyek, tombol Bangun kangge ndamel APK, saha menu kangge napakastani lan masang APK.

Ancasing aplikasi punika
Aplikasi punika dipundamel supados sinten kemawon saged ndamel aplikasi Android piyambak kanthi gampil, langsung saking ponsel. Tampilanipun dipundamel prasaja sanget supados pangangge enggal ugi saged langsung nyobi.

Cara ndamel proyek enggal, langkah mbaka langkah
1. Pencèt Buat Project wonten ing menu utama.
2. Pilih jinising proyek: HTML, Situs Web, Java, Kotlin, Compose, utawi Python.
3. Isi nama aplikasi, tuladha: Garuda Decode.
4. Isi nama paket (package name), tuladha: com.android.garudadecode. Nama paket kedah ngginakaken aksara alit lan kapérang saking paling sekedhik kalih pérangan ingkang dipunpisah titik.
5. Isi versi aplikasi, tuladha: 1.0, lan kode versi arupi angka, tuladha: 1. Menawi dipunkosongaken, versi badhé dipunisi piyambak kanthi 1.0 lan kode versi 1.
6. Isi SDK minimum lan SDK target menawi dipunbetahaken. Menawi dipunkosongaken, biji baku badhé dipunginakaken. SDK minimum inggih punika versi Android paling andhap ingkang dipunsengkuyung, tuladha: 21 tegesipun Android 5.0. SDK target paling inggil inggih punika 36 (Android 16).
7. Pencèt tombol Pilih Izin kangge milih izin aplikasi, tuladha: INTERNET. Izin INTERNET sampun dipuntengeri saking baku. Tengeri namung izin ingkang saèstu dipunbetahaken déning aplikasi.
8. Menawi dipunkersakaken, tengeri "Gunakan arsitektur terpisah 64 bit dan 32 bit" supados ukuran APK langkung alit, lan tengeri "Gunakan tanda tangan pribadi" menawi ngersakaken ngginakaken keystore damelan piyambak.
9. Pencèt Buat Proyek. Proyek enggal kasimpen wonten ing folder Download/project lan langsung ketingal wonten ing Kelola Project.

Jinising proyek ingkang cumawis
• HTML: tampilan saking index.html, style.css, lan script.js, mlampah ngliwati WebView. Dipundamel langsung wonten ing ponsel.
• Situs Web: website kanthi menu (Beranda, Tentang, Kontak) saking index.html, tentang.html, kontak.html, style.css, lan script.js, mlampah ngliwati WebView. Dipundamel langsung wonten ing ponsel.
• Java: dipundamel wonten ing ponsel. MainActivity mapan wonten ing app/src/main/java/<nama-paket>/MainActivity.java. Tampilan saking app/src/main/res/layout/activity_main.xml, teks saking app/src/main/res/values/strings.xml, lan tema saking app/src/main/res/values/styles.xml.
• Kotlin: saged dipundamel wonten ing piranti (offline) ngginakaken compiler Kotlin ingkang karonce ing aplikasi, utawi ngliwati GitHub Actions. MainActivity mapan wonten ing app/src/main/java/<nama-paket>/MainActivity.kt, lan berkas res sami kaliyan proyek Java. Bangun Kotlin ingkang sepisanan langkung alon amargi ukuran compiler ingkang ageng, lan berkas .java ingkang ngrujuk kelas Kotlin dereng saged dipundamel (berkas .java dipunkompilasi rumiyin sadèrèngipun berkas .kt).
• Compose: aplikasi Android modèren ingkang antarmukanipun dipundamel kanthi Jetpack Compose (sanes layout XML). MainActivity mapan wonten ing app/src/main/java/<nama-paket>/MainActivity.kt. Proyek Compose dipundamel ngliwati GitHub Actions (menu Bangun proyek, lajeng Bangun online) utawi wonten ing Termux kanthi Gradle, amargi Compose mbetahaken pustaka Jetpack Compose ingkang boten cumawis wonten ing piranti.
• Python: logika aplikasi dipunserat mawi basa Python (Chaquopy) wonten ing app/src/main/python/main.py, lan dipunlaksanakaken déning host MainActivity.java wonten ing app/src/main/java/<nama-paket>/MainActivity.java. Proyek Python saged dipundamel langsung wonten ing ponsel (runtime Chaquopy karonce ing aplikasi) utawi ngliwati GitHub Actions. SDK minimum proyek Python inggih punika 24 (Android 7.0).

Tatanan berkas proyek Java, HTML, Situs Web, Kotlin, Compose, lan Python
Proyek Java, HTML, Situs Web, Kotlin, Compose, lan Python katata kados proyek Android lumrahipun. Wonten ing folder app wonten folder src, lan wonten ing salebetipun wonten folder main. Wonten ing folder main wonten AndroidManifest.xml wonten ing sandhingipun folder java, folder res ingkang ngemot layout/activity_main.xml lan values/strings.xml saha values/styles.xml, lan kangge HTML lan Situs Web wonten folder assets ingkang ngemot index.html (Situs Web ugi gadhah tentang.html lan kontak.html). Proyek HTML lan Situs Web ugi gadhah MainActivity piyambak wonten ing app/src/main/java/<nama-paket>/MainActivity.java, ingkang ngemot index.html wonten ing WebView lan dados launcher wonten ing AndroidManifest. Proyek Python gadhah kode Python wonten ing app/src/main/python/main.py lan host MainActivity.java wonten ing app/src/main/java/<nama-paket>/MainActivity.java. AndroidManifest.xml, layout, strings, lan styles saged dipunbikak lan dipunowahi wonten ing editor, sami kaliyan MainActivity. Proyek lami ingkang manifest-ipun taksih mapan wonten ing sandhingipun folder app taksih saged dipundamel, amargi nalika ndamel, aplikasi mriksa AndroidManifest.xml wonten ing app/src/main/ rumiyin, lajeng ingkang wonten ing sandhingipun folder app, lan pungkasanipun berkas data proyek.

Aturan izin (wigati)
Izin ingkang dipuntengeri nalika ndamel proyek namung kacathet wonten ing satunggal papan, miturut jinising proyek. Kangge proyek Java, HTML, Situs Web, Kotlin, Compose, lan Python, izin ingkang dipuntengeri kacathet NAMUNG wonten ing AndroidManifest.xml ingkang mapan wonten ing app/src/main/, wonten ing sandhingipun folder java, wonten ing folder proyek. Berkas data proyek kangge proyek Java, HTML, Situs Web, Kotlin, Compose, lan Python boten ngemot daftar izin. Menawi milih Java lajeng nengeri INTERNET lan CAMERA, ingkang kacathet wonten ing AndroidManifest.xml namung INTERNET lan CAMERA, tanpa izin sanès ingkang tumut. Nalika ndamel, aplikasi maos izin saking papan ingkang sami: saking AndroidManifest.xml wonten ing app/src/main/ kangge proyek Java, HTML, Situs Web, Kotlin, Compose, lan Python (menawi boten wonten, saking AndroidManifest.xml wonten ing sandhingipun folder app kangge proyek lami), lan saking berkas data proyek kangge proyek lami.

Cara ngginakaken editor
Bikak Kelola Project, tutul nama proyek kangge mbikak editor. Wonten ing editor, berkas saged dipunbikak, kode saged dipunserat, lan éwah-éwahan saged dipunsimpen. Kangge proyek Java, HTML, Situs Web, Kotlin, Compose, lan Python, berkas katata wonten ing folder app/src/main. Kangge mbagi proyek, ginakaken Ekspor ZIP (priksani pérangan wonten ing ngandhap).

Cara nglaksanakaken proyek
Wonten ing editor, pencèt Jalankan kangge nyobi proyek. Kangge proyek HTML lan Situs Web, ingkang dipunlaksanakaken inggih punika index.html ngliwati WebView. Menawi wonten kalepatan, waos pesen kalepatanipun, ndandosi kode, lajeng laksanakaken malih.

Cara ndamel APK
Wonten ing editor, pencèt Bangun. Wonten kalih cara ndamel. Sepisanan, Bangun di perangkat: ndamel langsung wonten ing ponsel tanpa internet, kangge proyek HTML, Situs Web, Java, Kotlin, lan Python. Kaping kalih, Bangun online ngliwati GitHub Actions: ndamel ngliwati internet wonten ing GitHub, lan saged dipunginakaken kangge sadaya jinis proyek. Proyek Compose namung saged dipundamel kanthi cara kaping kalih (Bangun online) utawi wonten ing Termux kanthi Gradle, amargi Compose mbetahaken pustaka Jetpack Compose ingkang boten cumawis wonten ing piranti. Asil bangun sepisanan dereng dipuntapakastani. Sasampunipun aplikasi napakastani: piyambak kanthi kunci baku, utawi kanthi tanda tangan pribadi menawi kotak "Gunakan tanda tangan pribadi" dipuntengeri nalika ndamel proyek.

Cara masang APK
Menawi APK sampun dados, pencèt Pasang kangge masang. Wonten ing Android 8 utawi langkung inggil, ponsel badhé nyuwun "Izinkan dari sumber ini" rumiyin, amargi aplikasi punika masang APK saking njawi Play Store. Aktifaken izin punika satunggal wekdal wonten ing Pengaturan, lajeng wangsul dhumateng aplikasi: pemasangan badhé kalajengaken piyambak tanpa kedah mencèt Pasang malih. Menawi tombol Pasang boten ketingal, pesthekaken bangun sampun rampung lan APK sampun dipundamel.

Cara napakastani aplikasi
Saben APK kedah dipuntapakastani supados saged dipunpasang. Cumawis kalih pilihan. Sepisanan, kunci baku: aplikasi napakastani piyambak kanthi otomatis, tanpa kedah nindakaken punapa-punapa. Kaping kalih, tanda tangan pribadi: damel rumiyin keystore ngliwati menu Buat Keystore wonten ing menu utama, simpen sandhinipun kanthi saé, lajeng tengeri "Gunakan tanda tangan pribadi" nalika ndamel proyek. Keystore kasimpen wonten ing Download/project/signing.

Ekspor proyek dados ZIP
Ekspor ZIP dipuncawisaken supados proyek saged dipunbagi dhumateng kanca. Caranipun: wonten ing Kelola Project, penet nama proyek dangu, lajeng pilih Ekspor ZIP. Asilipun kasimpen wonten ing Download/project/<NamaProyek>.zip. Folder bin boten tumut karonce, pramila ukuranipun alit, namung puluhan KB. Berkas ZIP punika saged dipunkirim dhumateng kanca utawi dipununggah dhumateng GitHub.

Ekstensi JAWS
Ekstensi JAWS ngginakaken mesin ekstensi saking Jieshuo (CSR), sanes pamaca layarnipun. Kanthi mekaten, rancangan taksih saged mlampah sanajan pangangge ngginakaken TalkBack. Caranipun: bikak Ekstensi JAWS wonten ing menu utama. Amargi klik otomatis mlampah piyambak, layanan kedah dipunaktifaken rumiyin wonten ing Pengaturan Aksesibilitas. Sasampunipun punika, rancangan enggal saged dipundamel: ketik nama rancangan, pencèt OK, lajeng isi kotakipun.

Daftar Klik dipunpisah supados rapi
Wonten ing rancangan wonten kalih kotak: kotak skrip lan kotak Daftar Klik. Daftar tombol kasimpen kapisah wonten ing berkas daftar_klik.txt, satunggal nama saben larik. Tuladha isinipun: tombolSimpan, tombolHapus, tombolBuka. Kangge mbikak aplikasi, serat kemawon >WhatsApp wonten ing daftar punika. Rancangan lami ingkang dereng gadhah berkas daftar_klik.txt badhé ngetingalaken tuladha baku punika.

Fungsi prasaja ingkang dipuncawisaken
• klikTombol("tombolSimpan") — ngeklik satunggal tombol adhedhasar teksipun.
• klikDaftarTombol(daftar) — ngeklik daftar wonten ing daftar_klik.txt, satunggal tombol saben larik, urut, lajeng maringi pirsa pinten ingkang kasil lan pinten ingkang boten kepanggih.
• bukaAplikasi("WhatsApp") — mbikak aplikasi adhedhasar namanipun, utawi serat ">WhatsApp" wonten ing daftar.
• klik(540, 1200) — ngeklik wonten ing koordinat layar.
Sadaya fungsi dipundamel prasaja rumiyin. Menawi sampun kulina, fungsi tambahan saged dipuntambahaken samangké.

Bab pamaca layar
Aplikasi punika dipunrancang supados ramah pamaca layar. Saben kolom isian gadhah label lan tuladha pangisian, lan sadaya tombol saged dipunjujug tanpa gestur ingkang ruwet. Ekstensi JAWS dipundamel supados taksih mlampah sanajan pangangge ngginakaken TalkBack, amargi ingkang dipunginakaken inggih punika mesin ekstensinipun, sanes pamaca layarnipun.

Privasi lan keamanan
Proyek lan keystore kasimpen wonten ing ponsel panjenengan. Token GitHub namung dipunginakaken kangge bangun online lan kasimpen wonten ing aplikasi punika. Sampun ngantos mbagi token utawi sandhi keystore panjenengan dhumateng sinten kemawon. Menawi ngginakaken tanda tangan pribadi, simpen keystore lan sandhinipun wonten ing papan ingkang aman, amargi menawi ical, APK lami boten saged dipunanyari kanthi tanda tangan ingkang sami.

Kabutuhan
Android 5.0 utawi langkung enggal. Izin panyimpenan: wonten ing Android 11 utawi langkung inggil ngginakaken izin akses sadaya berkas, wonten ing Android 10 utawi langkung andhap ngginakaken izin panyimpenan limrah (maos/nulis panyimpenan) amargi Android 10 boten gadhah izin akses sadaya berkas. Ndamel wonten ing piranti mbetahaken ponsel mawi prosesor ARM (32 utawi 64 bit). Ndamel online ngliwati GitHub Actions mbetahaken internet lan token GitHub. Proyek Kotlin saged dipundamel wonten ing piranti, nanging bangun sepisananipun langkung alon lan ngginakaken memori langkung kathah amargi ukuran compiler Kotlin ingkang ageng. Proyek Compose dipundamel ngliwati GitHub Actions utawi wonten ing Termux kanthi Gradle. Proyek Python mbetahaken Android 7.0 utawi langkung enggal (SDK minimum 24) lan APK asilipun langkung ageng amargi nyertakaken runtime Python (Chaquopy) saha pustaka bakunipun.

Terminal
Menu Terminal wonten ing layar utama mbikak terminal wonten ing aplikasi punika. Perintah kados ls saged dipunginakaken kangge mirsani isi folder proyek, cd kangge pindhah folder, lan git kangge ngelola kode. Wedalan perintah ketingal minangka teks ingkang saged dipunwaos pamaca layar, lan wonten tombol Bacakan hasil kangge mirengaken asil pungkasan. Terminal punika ngginakaken shell sistem ponsel, pramila program interaktif kados nano lan vim dereng saged dipunginakaken wonten ing ngriki.

Lisensi (versi mbayar)
Kangge nyade aplikasi, tengeri "Aktifkan Lisensi" nalika ndamel proyek, lajeng isi nomer WhatsApp panjenengan. Aplikasi asil bangun badhé nyuwun kode lisensi nalika sepisanan dipunbikak: pangangge mirsani ID pirantinipun, mencèt tombol Kirim ID Perangkat kangge ngirim ID punika dhumateng WhatsApp panjenengan, lajeng panjenengan mangsuli kanthi kode lisensinipun. Kode lisensi dipunetang saking ID piranti lan sandhi proyek (lisensi_seed wonten ing berkas data proyek) — simpen sandhi punika kanthi saé lan sampun ngantos dipunbagi. Sasampunipun kode ingkang leres dipunlebetaken, aplikasi kabikak lan boten nyuwun kode malih.

Pembuat Ikon Otomatis
Ikon proyek enggal taksih transparan, pramila cumawis Pembuat Ikon wonten ing menu utama. Caranipun: pencèt Pembuat Ikon, serat satunggal utawi kalih aksara (tuladhanipun inisial nama aplikasi), pilih warna latar lan warna seratan, priksani pratayangipun, lajeng pencèt Simpan ke Proyek kangge ngginakaken ikon punika wonten ing proyek ingkang dipunpilih, utawi Simpan ke Download kangge ngginakaken berkas PNG-nipun wonten ing papan sanès. Sasampunipun proyek dipundamel, aplikasi ugi nawèkaken damel ikon. Ikon lami proyek saged dipungantos kapan kemawon saking menu proyek wonten ing Kelola Project (penet nama proyek dangu, lajeng pilih Ganti Ikon).

Template Proyek Siap Pakai
Menawi boten ngersakaken miwiti saking proyek kosong, pilih template nalika ndamel proyek: Kalkulator (Java), Catatan (Java), Daftar Tugas (Kotlin), Kalkulator Web (HTML), Situs Profil (Situs Web), utawi Penghitung (Compose). Milih template kanthi otomatis ngéwahi jinis proyek ndhèrèk template punika, lan proyek dipundamel kanthi kode wiwitan ingkang sampun dados — kantun dipunlaksanakaken utawi dipunowahi. Menawi jinis proyek dipunéwahi malih kanthi manual sasampunipun milih template, template dipunbatalaken lan proyek wangsul kosong. Kangge template HTML lan Situs Web, template nggantos isi index.html, kalebet skrip HTML ingkang dipunketik wonten ing form.

Cadangan lan Pulihkan Proyek

Cadangan kasimpen minangka ZIP wonten ing folder Download/backup kanthi nama proyek lan tanggal, tuladha: GarudaDecode-2026-11-14-123045.zip. Isinipun sami kaliyan Ekspor ZIP (sadaya isi proyek, tanpa folder bin). Kangge mulihaken: bikak menu wonten ing Kelola Project, pilih Pulihkan cadangan, lajeng pilih berkas cadanganipun. Menawi nama proyek sampun wonten, aplikasi badhé takèn: Timpa proyek lama, utawi simpen kanthi Nama baru.

Menawi nama proyek sampun wonten, aplikasi badhé takèn: Timpa proyek lama, utawi simpen kanthi Nama baru.

Pencarian lan Filter Proyek
Menawi proyek sampun kathah, wonten ing Kelola Project wonten kotak pencarian lan panyaring jinis. Ketik nama proyek wonten ing kotak pencarian, daftar langsung kasaring (aksara ageng lan alit boten dipunbèntenaken). Panyaring jinis mbatesi daftar dhumateng satunggal jinis kemawon: Semua, HTML, Situs Web, Java, Kotlin, Compose, utawi Python. Menu saben proyek taksih saged dipunbikak kados limrah saking daftar ingkang sampun kasaring.

Bangun Aplikasi kanthi swara
Yen ora pengin ngetik, gunakna swanten: pencet Mbangun kanthi Swanten ing menu utama, banjur ucapna prentah. Prentah sing bisa diucapake: "Buat proyek kalkulator", "Bangun proyek Kalkulator", "Buka proyek Kalkulator", "Jalankan proyek Kalkulator", "Daftar proyek", "Buka ikon", "Kembali", lan "Bantuan". Aplikasi mangsuli kanthi swanten lan teks, dadi isih bisa digunakake tanpa ndeleng layar. Pangerten swanten nggunakake aplikasi pangerten swanten gawan HP (gratis; bisa mlaku offline yen paket basa Indonesia wis dipasang). Yen HP ora nduwe pangerten swanten, prentah bisa ditulis ing kothak teks ing layar sing padha.

Audit Aksesibilitas
Kanggo mriksa apa layout proyek ramah pamaca layar (TalkBack/Jieshuo) sadurunge dirilis: bukak Audit Aksesibilitas ing menu utama, pilih proyek, banjur pencet Muat Dhaptar Layout lan pilih berkas layout. IDE maca berkas XML iku lan nglapurake tombol tanpa label karo nomer barise, label sing digunakake bola-bali, lan unsur sing padha nutupi, banjur nyusun transkrip urutan fokus kaya sing diwaca Jieshuo. Yen ana tombol tanpa label, isinen labele banjur pencet Sisipna Label kanthi Otomatis — label ditulis menyang berkas layout minangka contentDescription. Pamriksan iki mung maca layout XML; tampilan Compose lan APK dadi durung dipindai.

Autopsi Crash
Kanggo ngerteni sebabe aplikasi nutup dhewe saka log crash kanthi ID unik: bukak Autopsi Crash ing menu utama, pilih ID crash saka dhaptar log, banjur pencet Priksa. IDE nyocokake kelas lan nomer baris ing log karo sumber proyek lan njlentrehake sebabe nganggo basa Indonesia (umpamane referensi kosong, ijin sing durung dijaluk, utawa galat JSON), karo saran tambalan kode. Pencet Terapna Tambalan mung yen baris sumbere isih persis padha karo nalika crash dumadi; yen wis owah, tambalan ditolak lan IDE njaluk kowe mriksa dhewe. Sing diwaca yaiku log crash IDE dhewe, dudu log aplikasi asil build.

Transpiler Lintas-Paradigma
Kanggo ngowahi kode Java prasaja dadi Kotlin, utawa layout XML prasaja dadi kode Compose: bukak Transpiler Lintas-Paradigma ing menu utama, pilih proyek lan berkas, banjur pencet Pratinjau. IDE nuduhake asil konversi minangka teks — priksanen dhisik, amarga baris sing ora dingerteni ditinggalake apa anane lan tembung static ing Java diilangi ing Kotlin (priksanen tegese sadurunge digunakake). Konversi XML menyang Compose mung ngowahi teks, hint, lan orientasi — ukuran, werna, lan atribut liyane durung melu. Yen asile wis bener, pencet Terapake menyang Berkas kanggo nulis berkas tujuwan; berkas sumber ora diowahi. Mung pola umum sing aman sing dikonversi.

Server Mikro Lokal
Kanggo nguji aplikasi sing butuh server tanpa internet: bukak Server Mikro Lokal ing menu utama, tulis definisi rute (umpamane GET /halo banjur wangsulan JSON-e), banjur pencet Miwiti Server. IDE nglakokake server HTTP cilik ing HP sing padha (mung HTTP, tanpa TLS, kanggo jaringan Wi-Fi sing padha) lan nyathet saben panjaluk lan wangsulan ing layar. Rute bisa nggunakake parameter kaya {nama} lan kunci API prasaja. Server iki mung kanggo pengujian ing HP; APK asil build durung bisa dadi server, lan server mandheg yen layare ditutup.

Auditor Keamanan
Kanggo mriksa bolongan keamanan ing kode proyek sadurunge dirilis: bukak Auditor Keamanan ing menu utama, pilih proyek, banjur pencet Miwiti Pindhaian. IDE mindhai kode, manifest, lan konfigurasi proyek lan nglapurake temuan saka risiko dhuwur menyang endhek — kunci API sing kabukak ing kode, komponen sing kabukak tanpa ijin, WebView sing ngaktifake JavaScript karo antarmuka JavaScript, kripto ringkih (MD5, SHA1, DES), alamat http tanpa TLS, lan tembung sandhi sing ditulis langsung ing kode — karo berkas lan nomer barise. Kanggo temuan sing ndandanane aman (umpamane ganti MD5 dadi SHA-256 utawa http dadi https), pencet Terapna Ndandani; kanggo kunci API lan tembung sandhi, IDE mung nuduhake saran ndandanane amarga panggantine kudu diputusake dhewe dening pangembang. Pindhaian iki maca pola teks ing kode, dudu bytecode, dadi bisa wae ana temuan sing sakjane aman, lan bolongan sing ora duwe pola bisa lolos saka pindhaian — priksanen sadurunge nerapake.

Robot Panguji Antarmuka
Kanggo nguji tampilan aplikasi kanthi otomatis liwat skenario teks: bukak Robot Panguji Antarmuka ing menu utama, pilih proyek, banjur pencet Gawe Skenario Otomatis. IDE maca manifest lan layout proyek banjur nulis skenario awujud langkah-langkah teks (pencet tombol, isi kolom, ngenteni, bali). Pencet Jalanake Dry Run kanggo ndeleng log lumakune skenario karo cap wektune. Ing tataran iki robot mung nglakokake simulasi (dry run) — pencetan tombol tenanan ing HP lan panangkepan crash nyata yaiku tataran sabanjure, dadi laporan crash ing kene isih awujud conto.

Perjalanan Wektu Kode
Kanggo bali menyang kahanan kode proyek sadurunge tanpa ngetik prentah Git: bukak Perjalanan Wektu Kode ing menu utama, pilih proyek, isi label titik wektu (kena kosong), banjur pencet Rekam Titik Wektu. Dhaptar titik wektu nuduhake kabeh; pilih rong titik banjur pencet Bandingna kanggo ndeleng berkas lan fungsi sing ditambah, diowahi, utawa dibusak. Pencet Pulihna kanggo mbalekake kahanan lawas — sadurunge mulihake, IDE mesthi nggawe cadangan kahanan saiki dhisik, dadi ora ana sing ilang. Pencet Gawe Salinan Eksperimen kanggo nyalin proyek menyang folder anyar lan nyoba owah-owahan tanpa ngganggu proyek asli. Mung berkas sumber sing direkam.

Pabrik Modul
Kanggo ngemas perangan proyek dadi modul sing bisa digunakake proyek liya: bukak Pabrik Modul ing menu utama, pilih proyek sumber, centhang berkas layar, kelas, string, lan ijin sing arep dikemas, banjur pencet Kemas minangka Modul. IDE nulis arsip ZIP karo metadata JSON (jeneng modul, versi, string, lan ijin sing digunakake). Kanggo masang modul menyang proyek liya, bukak Pabrik Modul, pilih proyek tujuwan, banjur pencet Pasang Modul lan pilih berkas .zip module — panggabungan nambahake string lan ijin tanpa nimpa kode sing wis ana, lan ora nggabungake berkas yen jenenge wis digunakake ing proyek tujuwan. Modul ora nggawa pustaka utawa setelan build.

Perisai Polimorfik lan Brankas Aset
Kanggo ngacak jeneng pengenal lan enkripsi aset proyek sadurunge dirilis: bukak Perisai Polimorfik lan Brankas Aset ing menu utama, pilih proyek, banjur pencet Acak jeneng lan enkripsi aset. IDE mindhai jeneng kelas lan metode ing kode sumber, nggawe peta jeneng acak, ngenkripsi berkas aset proyek nganggo AES-GCM menyang folder brankas-aset ing njero proyek, lan nyimpen peta pemulihan sing dienkripsi (perisai-peta.brankas) supaya jeneng asli bisa dipulihake nalika maca log crash. Kunci enkripsi diturunake saka jeneng proyek, dadi sapa wae sing ngerti jeneng proyek bisa mbukak brankase — iki pangreksa saka diwaca iseng, dudu brankas sing dikunci nganggo tembung sandi. Sing digawe ing kene yaiku peta jeneng lan brankas aset; nulis ulang jeneng ing njero berkas DEX asil kompilasi iku tahap sabanjure, dadi jeneng ing njero APK sing wis dadi durung melu diacak.

Rantai Kepercayaan lan Penjaga Lingkungan
Kanggo mriksa rantai kunci panandhatangan lan lingkungan HP sadurunge dirilis: bukak Rantai Kepercayaan lan Penjaga Lingkungan ing menu utama, pilih proyek, banjur pencet Priksa Rantai lan Lingkungan. IDE mbangun rantai kunci 5 generasi saka jeneng paket proyek lan mriksa keutuhane, banjur mindhai peta memori prosese dhewe lan properti piranti kanggo tilas Frida, Xposed, utawa emulator. Asile yaiku tingkat risiko Aman, Waspada, utawa Bebaya bebarengan karo bukti tekse. Pamriksan iki maca pola teks ing peta memori lan properti sistem, dudu integritas memori asli ing tingkat pustaka bawaan, lan ora ngiket kunci menyang chip keamanan perangkat keras — piranti injeksi sing ndhelikake tilas tekse bisa lolos saka pamindhaian iki.

Arsitek Tata Letak Wit Teks
Kanggo ngrancang tampilan tanpa ndeleng layar: bukak Arsitek Tata Letak Wit Teks ing menu utama, pilih proyek lan berkas layout, banjur pencet Priksa Tata Letak. IDE maca layout XML minangka wit teks lan maca narasi posisi saben elemen (umpamane ing tengen ngisor, ambane 45 persen layar), banjur nglaporke tabrakan antar-elemen lan elemen sing metu layar ing ambane 360 dp kanthi matematis. Sing diitung yaiku LinearLayout lan ukuran dp prasaja; ConstraintLayout lan tampilan Compose dilaporke posisine ora mesthi, dudu ditebak.

Studio Sistem Desain
Kanggo nyamakake jarak, huruf, lan sudut ing kabeh layar lan proyek: bukak Studio Sistem Desain ing menu utama, pilih proyek, tulis token desain (umpamane jarak=8, huruf=16, sudut=12), pilih komponen, banjur pencet Gawe Komponen. IDE mvalidasi token — jarak dhasar 4 nganti 16 dp, huruf dhasar 12 nganti 20 sp, sudut 0 nganti 32 dp, lan area sentuh minimal 48 dp — banjur nulis komponen XML siap pakai (komponen-studio.xml) bebarengan karo tema XML (tema-studio.xml) lan tema Compose (tema-studio.kt) ing folder proyek. Komponen digawe minangka teks sing ditempelake menyang layout banjur dipriksa nganggo Arsitek Tata Letak; pangaturan loro kolom ing tablet nganggo qualifier ambane layar, dudu deteksi piranti nalika mlaku.

Refactoring Semantik lan Navigasi AST
Kanggo nggoleki definisi lan ngganti jeneng simbol tanpa ngrusak kode liya sing kebetulan jenenge padha: bukak Refactoring Semantik lan Navigasi AST ing menu utama, pilih proyek, banjur pencet Pindai Simbol Proyek kanggo ndeleng kabeh kelas lan metode bebarengan karo berkas lan nomer barise. Isi jeneng simbol banjur pencet Pindai Simbol Proyek maneh kanggo ndeleng definisine lan kabeh berkas sing ngundang. Kanggo ngganti jeneng, isi jeneng anyar, pencet Pratinjau Ganti Jeneng kanggo ndeleng cacah kemunculan ing saben berkas, banjur pencet Trapake Ganti Jeneng. Pengindeks iki nganggo pola teks, dudu parser AST penuh: ganti jeneng kelas berlaku ing kabeh berkas, dene ganti jeneng metode mung ing berkas pemilike — pemanggil ing berkas liya ora melu diubah, dadi priksa pratinjau lan asil pindhai pemanggil sadurunge nerapake. Ekstraksi blok kode dadi fungsi anyar wis ana ing mesin logika, nanging durung ana tombola ing layar iki.

Debugger Langkah lan Inspektur Memori
Kanggo mriksa isi variabel ing tengah alur program tanpa nebak-nebak liwat log: bukak Debugger Langkah lan Inspektur Memori ing menu utama, pilih proyek, tulis jejak eksekusi (siji langkah saben baris, bentuke nomer baris, kode, banjur variabel lan nilaie dipisah tandha |, umpamane 10|int total = harga * jumlah;|harga=5000, jumlah=3, total=15000), isi nomer baris titik henti, banjur pencet Jalanake Jejak Debug. IDE mlaku nganti titik henti kapisan lan maca baris aktif bebarengan karo nilai variabele liwat Jieshuo. Pencet Langkah Siji Baris kanggo maju siji baris, utawa Terusake Program kanggo mlaku nganti titik henti sabanjure. Iki debugger jejak: dheweke nlusuri jejak eksekusi sing direkam utawa ditulis tangan, dudu njeda aplikasi Android sing lagi mlaku — njeda proses tenanan butuh jembatan debug lan durung ana ing tahap iki.

Manajer Dependensi Luring
Kanggo nganggo pustaka pihak katelu tanpa internet lan ngindhari bentrokan versi sadurunge build: bukak Manajer Dependensi Luring ing menu utama, pilih proyek, banjur pencet Priksa Dependensi. IDE maca kabeh berkas .gradle proyek, mriksa brankas luring (brankas-maven.txt ing njero proyek), lan ngrampungake bentrokan — yen loro pustaka njaluk versi beda saka artefak sing padha, versi paling dhuwur sing dienggo lan bentrokane dilaporke. Kanggo nyathet pustaka menyang brankas, isi koordinate (bentuk grup:artefak:versi, umpamane com.google.code.gson:gson:2.10.1) banjur pencet Priksa Dependensi. Ngundhuh saka Maven, Google, utawa PyPI butuh internet: nalika luring mung pustaka sing wis ana ing brankas sing bisa dienggo, lan nambah koordinat mung nyathet menyang indeks — berkas AAR, JAR, utawa WHL-ne durung diundhuh otomatis. Brankas isih disimpen saben proyek.

Inspektur Basis Data lan Panyimpenan
Kanggo mriksa lan nguji isi basis data proyek tanpa nulis kode pencetak isi tabel: bukak Inspektur Basis Data lan Panyimpenan ing menu utama, pilih proyek lan berkas basis data (.db, .sqlite, utawa .sqlite3), banjur pencet Bukak Basis Data. IDE maca skema tabele lan nampilake 20 baris kapisan minangka tabel teks sing diwaca Jieshuo. Tulis kueri SELECT prasaja banjur pencet Jalanake Kueri (umpamane SELECT nama FROM pengguna WHERE kota = 'Makassar'). Kanggo ngowahi nilai, isi nomer baris (1 = baris kapisan), jeneng kolom, lan nilai anyar, banjur pencet Owahana Nilai Sel — nilai kasebut ditulis bali menyang berkas .db. Pencet Simpen Cadangan kanggo nyimpen kahanan tabel wektu iku minangka berkas <nama-db>.cadangan.txt ing proyek. Sing diwaca mung tabel kapisan; kueri sing didhukung mung SELECT prasaja tanpa JOIN utawa GROUP BY; SharedPreferences lan DataStore durung diwaca.

Pabrik Pengujian Unit lan Fuzzing
Kanggo nemokake celah logika sadurunge aplikasi dibagekake: bukak Pabrik Pengujian Unit lan Fuzzing ing menu utama, pilih proyek lan berkas kode, banjur pencet Gawe lan Jalanake Uji. IDE maca tandha tangan fungsi ing berkas, ngasilake kasus uji normal lan wates (teks kosong, null, angka maksimal, karakter aneh), nglakokake fuzzing ing fungsi conto, lan nulis kerangka uji JUnit (Uji<NamaKelas>.java) ing proyek. Asile nglaporke cacah uji lulus lan gagal, cacah baris kode lan fungsi sing ditemokake, sarta kasus uji sing digawe. Uji sing digawe isih kerangka — pangarepan (expected) kudu ditulis pangembang — lan fuzzing tenanan lagi mlaku ing fungsi conto, dudu ing fungsi proyek; persentase cakupan baris durung diitung.

Simulator Kondisi Perangkat Ekstrem lan Auditor Kebocoran Memori
Kanggo nguji ketahanan aplikasi nalika sistem mateni prosese, jaringan pedhot, layar diputer, utawa hemat baterei aktif: bukak Simulator Kondisi Perangkat Ekstrem lan Auditor Kebocoran Memori ing menu utama, pilih proyek, banjur pencet Jalanake Simulasi. IDE nglakokake telu skenario tekanan bebarengan karo simulasi puter layar lan nglacak objek sing ketahan ing memori sawise layare ditutup, banjur nglaporke data sing ilang lan rantai objek sing bocor. Iki simulasi ing model kahanan, dudu mateni proses tenanan, dudu medhot jaringan HP, lan dudu heap dump nyata; model kahanan ing layar iki isih conto tetep, dudu kahanan layar proyek panganggo.

Arsitek Cetak Biru Proyek
Kanggo ngowahi gagasan aplikasi gedhe dadi rencana kerja bertahap: bukak Arsitek Cetak Biru Proyek ing menu utama, pilih proyek, tulis gagasan aplikasie (umpamane aplikasi kasir toko kelontong kanthi cicilan), banjur pencet Gawe Cetak Biru. IDE nyusun modul, dhaptar berkas, lan tonggak kerja cilik, banjur nyimpen minangka cetak-biru.txt ing folder proyek. Pencet Tandhani Tonggak Sabanjure Rampung saben siji tonggak rampung, utawa pencet Muat Cetak Biru sing Disimpen kanggo mbukak maneh cetak biru sing wis disimpen. Cetak biru disusun saka pola tembung kunci ing piranti, dudu saka model AI online — gagasan sing ora dikenali nganggo kerangka umum (model data, panyimpenan, layar, logika) — lan nyusun liwat panyedhiya AI aktif durung ana ing tahap iki.

Narator Alur Logika Kode
Kanggo mangerteni kode dawa tanpa ngrungokake sintaks baris saben baris: bukak Narator Alur Logika Kode ing menu utama, pilih proyek lan berkas kode, banjur pencet Narasi Kode. IDE ngowahi saben baris dadi ukara basa Indonesia (umpamane yen total luwih saka 100000, banjur lakokake blok sabanjure), nampilake peta panggilan antar-metode, lan nandhani potensi bug alus bebarengan karo nomer barise — String dibandhingake nganggo ==, stream sing dibukak tanpa ditutup, lan variabel sing ditulis ing loro metode beda. Narasi lan pamriksan nganggo pola teks luring, dudu model AI online lan dudu analisis aliran data penuh; pola sing ora dikenali dinarasikake apa anane minangka baris kode, lan peringatan balapan data bisa muncul kanggo variabel sing sejatine mung dienggo gantian.

Pabrik App Bundle lan Kesiapan Play Store
Kanggo nyiapake aplikasi menyang Google Play Store langsung saka HP: bukak Pabrik App Bundle lan Kesiapan Play Store ing menu utama, pilih proyek, banjur pencet Gawe Bundel AAB. IDE nyusun berkas .aab saka manifest, sumber daya, lan aset proyek, nyimulasi pecahan ukuran unduhan saben arsitektur (arm64-v8a, armeabi-v7a, x86_64) lan basa, banjur ngaudit kesiapan Play — target SDK ing ngisor 35 ditandhani Dhuwur amarga Play Store mbutuhake 35 utawa luwih, lan pustaka 64-bit sing ilang uga ditandhani Dhuwur. Bundel sing digawe yaiku arsip berstruktur AAB standar; ukuran pecahan yaiku perkiraan saka ukuran berkas, dudu asil pemecahan bundletool tenanan, lan panandhatanganan bundel kanggo Play Console tetep nganggo jalur build sing padha karo APK.

Mesin Pembaruan OTA lan Rilis Bertahap
Kanggo ngirim perbaikan cilik tanpa meksa panganggo ngundhuh ulang kabeh APK: bukak Mesin Pembaruan OTA lan Rilis Bertahap ing menu utama, pilih proyek, tulis isi versi lawas lan versi anyar, banjur pencet Gawe Paket Patch. Patch ing kene mung bisa ing berkas teks (skrip, aset, konfigurasi) — patch biner DEX utawa APK durung didhukung, lan patch ditrapake nalika aplikasi dibukak maneh. Sidik jari ing manifest mung mbuktekake keutuhan isi, dudu keaslian pangirim, amarga durung nganggo tandha tangan kunci privat.

Studio Tinjauan Kode Tim

Penggabungan nganggo pencocokan baris, dudu sintaks, dadi loro owah-owahan ing baris sing padha mesthi dianggep konflik sanajan maknane ora tabrakan; papan tugas tersinkron liwat nyalin berkas tekse bebarengan karo riwayat Git, tanpa server sinkronisasi khusus.

Dikte Struktur Kode

Dikte nggunakake layanan input swanten gawan sistem, tanpa ijin mikrofon tambahan, lan mung ngenali pola prentah sing wis kadhaptar; ucapan ing njaba pola ora diowahi dadi kode. Ruang Kolaborasi Lokal (tanpa internet)
Kanggo makarya bebarengan ing sak ruangan tanpa internet: bukak Kolaborasi ing menu utama, banjur bukak perangan Ruang Kolaborasi Lokal.
