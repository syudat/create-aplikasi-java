Create Aplikasi by Al Kautsar에 오신 것을 환영합니다
Create Aplikasi는 노트북 없이 휴대폰에서 바로 실행되는 Android 앱 제작 애플리케이션입니다. 이 앱을 사용하면 앱 만들기를 처음 배우는 사용자와 화면 낭독기 사용자를 포함해 누구나 자신만의 Android 앱을 만들 수 있습니다. 이 앱의 전체 사용 안내는 이 Tentang Alat(도구 정보) 화면에서 볼 수 있습니다.

이 앱은 무엇이며 누구를 위한 것인가
Create Aplikasi는 휴대폰에서 실행되는 Android 앱 제작 도구입니다. 이 앱은 초보자와 화면 낭독기 사용자를 포함해 자신만의 Android 앱을 만들고 싶은 모든 사람을 위한 것입니다. 이 앱은 코드 편집기, 프로젝트를 테스트하는 Jalankan(실행) 버튼, APK를 만드는 Bangun(빌드) 버튼, 그리고 APK에 서명하고 설치하는 메뉴를 제공합니다.

이 앱의 목적
이 앱은 누구나 휴대폰에서 바로, 쉽게 자신만의 Android 앱을 만들 수 있도록 만들어졌습니다. 화면은 최대한 단순하게 만들어져 있어 처음 사용하는 사용자도 바로 시도해 볼 수 있습니다.

새 프로젝트를 만드는 방법, 단계별 안내
1. 메인 메뉴에서 Buat Project(프로젝트 만들기)를 누릅니다.
2. 프로젝트 종류를 선택합니다: HTML, Situs Web(웹사이트), Java, Kotlin, Compose 또는 Python.
3. 앱 이름을 입력합니다. 예: Garuda Decode.
4. 패키지 이름(package name)을 입력합니다. 예: com.android.garudadecode. 패키지 이름은 소문자를 사용해야 하며 마침표로 구분된 최소 두 부분으로 이루어져야 합니다.
5. 앱 버전을 입력합니다. 예: 1.0, 그리고 숫자로 된 버전 코드를 입력합니다. 예: 1. 비워 두면 버전은 자동으로 1.0, 버전 코드는 1로 채워집니다.
6. 필요하면 최소 SDK와 대상 SDK를 입력합니다. 비워 두면 기본값이 사용됩니다. 최소 SDK는 지원되는 가장 낮은 Android 버전입니다. 예: 21은 Android 5.0을 뜻합니다. 대상 SDK의 최대값은 36(Android 16)입니다.
7. Pilih Izin(권한 선택) 버튼을 눌러 앱 권한을 선택합니다. 예: INTERNET. INTERNET 권한은 기본으로 선택되어 있습니다. 앱에 실제로 필요한 권한만 선택하십시오.
8. 원한다면 "Gunakan arsitektur terpisah 64 bit dan 32 bit"(64비트와 32비트 분리 아키텍처 사용)에 체크하면 APK 크기가 더 작아지고, 직접 만든 keystore를 쓰고 싶다면 "Gunakan tanda tangan pribadi"(개인 서명 사용)에 체크합니다.
9. Buat Proyek(프로젝트 만들기)를 누릅니다. 새 프로젝트는 Download/project 폴더에 저장되고 Kelola Project(프로젝트 관리)에 바로 나타납니다.

사용할 수 있는 프로젝트 종류
• HTML: index.html, style.css, script.js로 이루어진 화면이 WebView를 통해 실행됩니다. 휴대폰에서 바로 빌드됩니다.
• Situs Web: index.html, tentang.html, kontak.html, style.css, script.js로 이루어진 메뉴(Beranda(홈), Tentang(정보), Kontak(연락처))가 있는 웹사이트가 WebView를 통해 실행됩니다. 휴대폰에서 바로 빌드됩니다.
• Java: 휴대폰에서 빌드됩니다. MainActivity는 app/src/main/java/<nama-paket>/MainActivity.java에 있습니다. 화면은 app/src/main/res/layout/activity_main.xml에서, 텍스트는 app/src/main/res/values/strings.xml에서, 테마는 app/src/main/res/values/styles.xml에서 가져옵니다.
• Kotlin: 앱에 포함된 Kotlin 컴파일러를 사용해 기기에서(오프라인으로) 빌드하거나 GitHub Actions를 통해 빌드할 수 있습니다. MainActivity는 app/src/main/java/<nama-paket>/MainActivity.kt에 있고, res 파일은 Java 프로젝트와 같습니다. 첫 Kotlin 빌드는 컴파일러 크기가 커서 더 느리고, Kotlin 클래스를 참조하는 .java 파일은 아직 빌드할 수 없습니다(.java 파일이 .kt 파일보다 먼저 컴파일됩니다).
• Compose: Jetpack Compose(XML 레이아웃이 아님)로 인터페이스를 만드는 현대적인 Android 앱입니다. MainActivity는 app/src/main/java/<nama-paket>/MainActivity.kt에 있습니다. Compose 프로젝트는 Jetpack Compose 라이브러리가 기기에 없어서 GitHub Actions(프로젝트 Bangun 메뉴, 그다음 Bangun online(온라인 빌드))를 통하거나 Gradle과 함께 Termux에서 빌드됩니다.
• Python: 앱 로직을 app/src/main/python/main.py에 Python(Chaquopy) 언어로 작성하고, app/src/main/java/<nama-paket>/MainActivity.java의 호스트 MainActivity.java가 실행합니다. Python 프로젝트는 휴대폰에서 바로 빌드할 수도 있고(Chaquopy 런타임이 앱에 포함되어 있습니다) GitHub Actions를 통해서도 빌드할 수 있습니다. Python 프로젝트의 최소 SDK는 24(Android 7.0)입니다.

Java, HTML, Situs Web, Kotlin, Compose, Python 프로젝트의 파일 구성
Java, HTML, Situs Web, Kotlin, Compose, Python 프로젝트는 일반적인 Android 프로젝트처럼 구성됩니다. app 폴더 안에는 src 폴더가 있고, 그 안에는 main 폴더가 있습니다. main 폴더 안에는 java 폴더 옆에 AndroidManifest.xml이 있고, layout/activity_main.xml과 values/strings.xml 및 values/styles.xml을 담고 있는 res 폴더가 있으며, HTML과 Situs Web의 경우 index.html(Situs Web는 tentang.html과 kontak.html도 있음)을 담고 있는 assets 폴더가 있습니다. HTML과 Situs Web 프로젝트도 app/src/main/java/<nama-paket>/MainActivity.java에 자체 MainActivity가 있어 WebView에 index.html을 불러오고 AndroidManifest에서 런처가 됩니다. Python 프로젝트는 app/src/main/python/main.py에 Python 코드가 있고 app/src/main/java/<nama-paket>/MainActivity.java에 호스트 MainActivity.java가 있습니다. AndroidManifest.xml, layout, strings, styles는 MainActivity와 마찬가지로 편집기에서 열고 수정할 수 있습니다. 매니페스트가 아직 app 폴더 옆에 있는 오래된 프로젝트도 빌드할 수 있습니다. 빌드할 때 앱은 먼저 app/src/main/의 AndroidManifest.xml을 확인하고, 그다음 app 폴더 옆의 것을 확인하며, 마지막으로 프로젝트 데이터 파일을 확인하기 때문입니다.

권한 규칙 (중요)
프로젝트를 만들 때 체크한 권한은 프로젝트 종류에 따라 한 곳에만 기록됩니다. Java, HTML, Situs Web, Kotlin, Compose, Python 프로젝트의 경우 체크한 권한은 프로젝트 폴더 안, java 폴더 옆, app/src/main/에 있는 AndroidManifest.xml에만 기록됩니다. Java, HTML, Situs Web, Kotlin, Compose, Python 프로젝트의 프로젝트 데이터 파일에는 권한 목록이 들어 있지 않습니다. Java를 선택하고 INTERNET과 CAMERA에 체크하면 AndroidManifest.xml에 기록되는 것은 INTERNET과 CAMERA뿐이며 다른 권한은 함께 기록되지 않습니다. 빌드할 때 앱은 같은 곳에서 권한을 읽습니다: Java, HTML, Situs Web, Kotlin, Compose, Python 프로젝트는 app/src/main/의 AndroidManifest.xml에서(없으면 오래된 프로젝트용으로 app 폴더 옆의 AndroidManifest.xml에서), 그리고 오래된 프로젝트는 프로젝트 데이터 파일에서 읽습니다.

편집기 사용 방법
Kelola Project를 열고 프로젝트 이름을 눌러 편집기를 엽니다. 편집기에서는 파일을 열고, 코드를 작성하고, 변경 사항을 저장할 수 있습니다. Java, HTML, Situs Web, Kotlin, Compose, Python 프로젝트의 파일은 app/src/main 폴더 안에 구성되어 있습니다. 프로젝트를 공유하려면 Ekspor ZIP(ZIP 내보내기)을 사용하십시오(아래 부분 참조).

프로젝트 실행 방법
편집기에서 Jalankan을 눌러 프로젝트를 테스트합니다. HTML과 Situs Web 프로젝트에서는 index.html이 WebView를 통해 실행됩니다. 오류가 발생하면 오류 메시지를 읽고 코드를 수정한 뒤 다시 실행하십시오.

APK 빌드 방법
편집기에서 Bangun을 누릅니다. 빌드 방법은 두 가지가 있습니다. 첫째, Bangun di perangkat(기기에서 빌드): 인터넷 없이 휴대폰에서 바로 빌드하며, HTML, Situs Web, Java, Kotlin, Python 프로젝트에 사용됩니다. 둘째, GitHub Actions를 통한 Bangun online(온라인 빌드): GitHub에서 인터넷을 통해 빌드하며 모든 종류의 프로젝트에 사용할 수 있습니다. Compose 프로젝트는 Jetpack Compose 라이브러리가 기기에 없어서 두 번째 방법(온라인 빌드)으로만, 또는 Gradle과 함께 Termux에서만 빌드할 수 있습니다. 첫 빌드 결과는 아직 서명되지 않은 상태입니다. 그 후 앱이 서명합니다: 자동으로 기본 키로 서명하거나, 프로젝트를 만들 때 "Gunakan tanda tangan pribadi" 상자에 체크했다면 개인 서명으로 서명합니다.

APK 설치 방법
APK가 완성되면 Pasang(설치)을 눌러 설치합니다. Android 8 이상에서는 이 앱이 Play Store 외부에서 APK를 설치하기 때문에 휴대폰이 먼저 "Izinkan dari sumber ini"(이 출처 허용)를 요청합니다. Pengaturan(설정)에서 그 권한을 한 번 활성화한 뒤 앱으로 돌아오십시오: Pasang을 다시 누를 필요 없이 설치가 자동으로 계속됩니다. Pasang 버튼이 나타나지 않으면 빌드가 끝났고 APK가 만들어졌는지 확인하십시오.

앱에 서명하는 방법
모든 APK는 설치할 수 있도록 서명되어야 합니다. 선택지는 두 가지입니다. 첫째, 기본 키: 앱이 자동으로 서명하므로 아무것도 할 필요가 없습니다. 둘째, 개인 서명: 먼저 메인 메뉴의 Buat Keystore(keystore 만들기) 메뉴를 통해 keystore를 만들고, 그 비밀번호를 잘 보관한 뒤, 프로젝트를 만들 때 "Gunakan tanda tangan pribadi"에 체크합니다. Keystore는 Download/project/signing에 저장됩니다.

프로젝트를 ZIP으로 내보내기
Ekspor ZIP은 프로젝트를 친구와 공유할 수 있도록 제공됩니다. 방법: Kelola Project에서 프로젝트 이름을 길게 누른 뒤 Ekspor ZIP을 선택합니다. 결과는 Download/project/<NamaProyek>.zip에 저장됩니다. bin 폴더는 포함되지 않아 크기가 수십 KB로 작습니다. 그 ZIP 파일은 친구에게 보내거나 GitHub에 올릴 수 있습니다.

Ekstensi JAWS
Ekstensi JAWS는 Jieshuo(CSR)의 확장 엔진을 사용하며, 그 화면 낭독기 자체를 사용하지 않습니다. 따라서 사용자가 TalkBack을 사용하더라도 설계가 계속 실행될 수 있습니다. 방법: 메인 메뉴에서 Ekstensi JAWS를 엽니다. 자동 클릭이 스스로 실행되므로, 먼저 Pengaturan Aksesibilitas(접근성 설정)에서 서비스를 활성화해야 합니다. 그 후 새 설계를 만들 수 있습니다: 설계 이름을 입력하고 OK를 누른 뒤 그 상자를 채웁니다.

깔끔하게 분리된 Daftar Klik
설계 안에는 두 개의 상자가 있습니다: 스크립트 상자와 Daftar Klik(클릭 목록) 상자입니다. 버튼 목록은 daftar_klik.txt 파일에 따로 저장되며 한 줄에 이름 하나씩 들어갑니다. 내용 예시: tombolSimpan, tombolHapus, tombolBuka. 앱을 열려면 그 목록에 >WhatsApp이라고만 쓰면 됩니다. 아직 daftar_klik.txt 파일이 없는 오래된 설계는 그 기본 예시를 표시합니다.

제공되는 간단한 함수
• klikTombol("tombolSimpan") — 텍스트를 기준으로 버튼 하나를 클릭합니다.
• klikDaftarTombol(daftar) — daftar_klik.txt의 목록을 클릭합니다. 한 줄에 버튼 하나씩, 순서대로 클릭한 뒤 몇 개가 성공했고 몇 개를 찾지 못했는지 알려줍니다.
• bukaAplikasi("WhatsApp") — 이름으로 앱을 엽니다. 또는 목록에 ">WhatsApp"이라고 씁니다.
• klik(540, 1200) — 화면 좌표를 클릭합니다.
모든 함수는 우선 단순하게 만들어졌습니다. 익숙해지면 나중에 함수를 추가할 수 있습니다.

화면 낭독기에 대하여
이 앱은 화면 낭독기에 친화적으로 설계되었습니다. 모든 입력 칸에는 라벨과 입력 예시가 있고, 모든 버튼은 복잡한 제스처 없이 닿을 수 있습니다. Ekstensi JAWS는 사용자가 TalkBack을 사용하더라도 계속 실행되도록 만들어졌습니다. 사용되는 것이 그 화면 낭독기가 아니라 확장 엔진이기 때문입니다.

개인정보와 보안
프로젝트와 keystore는 사용자의 휴대폰에 저장됩니다. GitHub 토큰은 온라인 빌드에만 사용되며 이 앱 안에 저장됩니다. 토큰이나 keystore 비밀번호를 누구와도 공유하지 마십시오. 개인 서명을 사용한다면 keystore와 그 비밀번호를 안전한 곳에 보관하십시오. 잃어버리면 예전 APK를 같은 서명으로 업데이트할 수 없기 때문입니다.

요구 사항
Android 5.0 이상. 저장소 권한: Android 11 이상에서는 모든 파일 접근 권한을 사용하고, Android 10 이하에서는 일반 저장소 권한(저장소 읽기/쓰기)을 사용합니다. Android 10에는 모든 파일 접근 권한이 없기 때문입니다. 기기에서 빌드하려면 ARM 프로세서(32비트 또는 64비트)를 탑재한 휴대폰이 필요합니다. GitHub Actions를 통한 온라인 빌드에는 인터넷과 GitHub 토큰이 필요합니다. Kotlin 프로젝트는 기기에서 빌드할 수 있지만, Kotlin 컴파일러 크기가 커서 첫 빌드가 더 느리고 메모리를 더 많이 사용합니다. Compose 프로젝트는 GitHub Actions를 통하거나 Gradle과 함께 Termux에서 빌드됩니다. Python 프로젝트는 Android 7.0 이상(최소 SDK 24)이 필요하고, Python 런타임(Chaquopy)과 그 표준 라이브러리를 포함하므로 결과 APK가 더 큽니다.

Terminal
메인 화면의 Terminal 메뉴는 이 앱 안에서 터미널을 엽니다. ls 같은 명령으로 프로젝트 폴더의 내용을 보고, cd로 폴더를 이동하고, git으로 코드를 관리할 수 있습니다. 명령 출력은 화면 낭독기가 읽을 수 있는 텍스트로 표시되며, 마지막 결과를 들을 수 있는 Bacakan hasil(결과 읽어주기) 버튼이 있습니다. 이 터미널은 휴대폰의 시스템 셸을 사용하므로 nano와 vim 같은 대화형 프로그램은 아직 여기서 사용할 수 없습니다.

Lisensi (유료 버전)
앱을 판매하려면 프로젝트를 만들 때 "Aktifkan Lisensi"(라이선스 활성화)에 체크한 뒤 WhatsApp 번호를 입력하십시오. 빌드된 앱은 처음 열릴 때 라이선스 코드를 요청합니다: 사용자가 자신의 기기 ID를 보고, Kirim ID Perangkat(기기 ID 보내기) 버튼을 눌러 그 ID를 사용자의 WhatsApp으로 보내면, 사용자가 라이선스 코드로 답합니다. 라이선스 코드는 기기 ID와 프로젝트 비밀번호(프로젝트 데이터 파일의 lisensi_seed)로 계산됩니다 — 그 비밀번호를 잘 보관하고 공유하지 마십시오. 올바른 코드가 입력되면 앱이 열리고 더 이상 코드를 요청하지 않습니다.

Pembuat Ikon Otomatis
새 프로젝트의 아이콘은 아직 투명하므로, 메인 메뉴에 Pembuat Ikon(아이콘 만들기)이 있습니다. 방법: Pembuat Ikon을 누르고, 한두 글자(예: 앱 이름의 이니셜)를 쓰고, 배경색과 글자색을 고르고, 미리보기를 본 뒤, Simpan ke Proyek(프로젝트에 저장)을 눌러 선택한 프로젝트에 그 아이콘을 사용하거나, Simpan ke Download(Download에 저장)를 눌러 그 PNG 파일을 다른 곳에 사용합니다. 프로젝트가 만들어진 후에도 앱이 아이콘 만들기를 제안합니다. 프로젝트의 예전 아이콘은 Kelola Project의 프로젝트 메뉴에서 언제든 바꿀 수 있습니다(프로젝트 이름을 길게 누른 뒤 Ganti Ikon(아이콘 변경)을 선택).

Template Proyek Siap Pakai
빈 프로젝트에서 시작하고 싶지 않다면 프로젝트를 만들 때 템플릿을 선택하십시오: Kalkulator(Java), Catatan(Java), Daftar Tugas(Kotlin), Kalkulator Web(HTML), Situs Profil(Situs Web), 또는 Penghitung(Compose). 템플릿을 선택하면 프로젝트 종류가 자동으로 그 템플릿을 따라 바뀌고, 프로젝트는 이미 완성된 시작 코드로 만들어집니다 — 바로 실행하거나 수정하면 됩니다. 템플릿을 선택한 뒤 프로젝트 종류를 다시 수동으로 바꾸면 템플릿이 취소되고 프로젝트는 다시 비게 됩니다. HTML과 Situs Web 템플릿의 경우, 템플릿은 index.html의 내용을 교체합니다. 여기에는 폼에 입력한 HTML 스크립트도 포함됩니다.

Cadangan dan Pulihkan Proyek
프로젝트가 사라지지 않도록 백업 기능이 있습니다. 방법: Kelola Project에서 프로젝트 이름을 길게 누른 뒤 Cadangkan(백업)을 선택합니다. 백업은 Download/backup 폴더에 프로젝트 이름과 날짜를 붙인 ZIP으로 저장됩니다. 예: GarudaDecode-2026-11-14-123045.zip. 내용은 Ekspor ZIP과 같습니다(프로젝트 전체 내용, bin 폴더 제외). 복원하려면: Kelola Project에서 메뉴를 열고 Pulihkan cadangan(백업 복원)을 선택한 뒤 백업 파일을 고릅니다. 프로젝트 이름이 이미 있으면 앱이 묻습니다: Timpa proyek lama(예전 프로젝트 덮어쓰기), 또는 Nama baru(새 이름)로 저장.

Bagikan dan Impor Proyek
프로젝트를 친구와 공유하려면: Kelola Project에서 프로젝트 이름을 길게 누른 뒤 Bagikan(공유)을 선택합니다. 프로젝트는 공유 앱(WhatsApp, Telegram 등)을 통해 ZIP으로 전송됩니다. 친구에게서 프로젝트를 받으려면: Kelola Project에서 메뉴를 열고 Impor proyek(프로젝트 가져오기)를 선택한 뒤 그 ZIP 파일을 고릅니다. 그 ZIP 파일에는 프로젝트 데이터 파일이 들어 있어야 합니다 — 없으면 그 파일은 Create Aplikasi 프로젝트가 아니므로 명확한 메시지와 함께 파일이 거부됩니다. 프로젝트 이름이 이미 있으면 앱이 묻습니다: Timpa proyek lama, 또는 Nama baru로 저장.

Pencarian dan Filter Proyek
프로젝트가 많아지면 Kelola Project에 검색 상자와 종류 필터가 있습니다. 검색 상자에 프로젝트 이름을 입력하면 목록이 바로 걸러집니다(대소문자는 구분하지 않습니다). 종류 필터는 목록을 한 종류로만 제한합니다: Semua(전체), HTML, Situs Web, Java, Kotlin, Compose 또는 Python. 각 프로젝트의 메뉴는 걸러진 목록에서도 평소와 같이 열 수 있습니다.

음성으로 앱 빌드하기
입력하고 싶지 않다면 음성을 사용하세요. 주 메뉴에서 음성으로 빌드를 누른 뒤 명령을 말하세요. 말할 수 있는 명령: "Buat proyek kalkulator", "Bangun proyek Kalkulator", "Buka proyek Kalkulator", "Jalankan proyek Kalkulator", "Daftar proyek", "Buka ikon", "Kembali", "Bantuan". 앱은 음성과 텍스트로 답하므로 화면을 보지 않고도 사용할 수 있습니다. 음성 인식은 휴대폰에 내장된 음성 인식 앱을 사용합니다(무료. 인도네시아어 언어 팩이 설치되어 있으면 오프라인에서도 동작합니다). 휴대폰에 음성 인식 기능이 없으면 같은 화면의 텍스트 상자에 명령을 입력할 수 있습니다.

접근성 감사
출시 전에 프로젝트 레이아웃이 스크린 리더(TalkBack/Jieshuo)에 친화적인지 확인하려면 주 메뉴에서 접근성 감사를 열고 프로젝트를 선택한 뒤 레이아웃 목록 불러오기를 눌러 레이아웃 파일을 선택하세요. IDE는 해당 XML 파일을 읽어 레이블이 없는 버튼과 그 줄 번호, 반복 사용된 레이블, 서로 겹치는 요소를 보고한 뒤 Jieshuo가 읽어 주는 것과 같은 포커스 순서 기록을 만듭니다. 레이블이 없는 버튼이 있으면 레이블을 입력한 뒤 레이블 자동 삽입을 누르세요. 레이블은 contentDescription으로 레이아웃 파일에 기록됩니다. 이 검사는 레이아웃 XML만 읽습니다. Compose 화면과 완성된 APK는 아직 검사하지 않습니다.

크래시 부검
고유 ID가 있는 충돌 로그에서 앱이 저절로 닫히는 원인을 알아보려면 주 메뉴에서 크래시 부검을 열고 로그 목록에서 충돌 ID를 선택한 뒤 확인을 누르세요. IDE는 로그의 클래스와 줄 번호를 프로젝트 소스와 대조하여 원인을 인도네시아어로 설명합니다(예: 빈 참조, 아직 요청하지 않은 권한, JSON 오류). 코드 패치 제안도 함께 표시됩니다. 소스 줄이 충돌 당시와 정확히 같을 때만 패치 적용을 누르세요. 달라졌다면 패치가 거부되고 IDE가 직접 확인하도록 요청합니다. 읽는 것은 IDE 자체의 충돌 로그이지 빌드된 앱의 로그가 아닙니다.

패러다임 간 트랜스파일러
간단한 Java 코드를 Kotlin으로 변환하거나 간단한 XML 레이아웃을 Compose 코드로 변환하려면 주 메뉴에서 패러다임 간 트랜스파일러를 열고 프로젝트와 파일을 선택한 뒤 미리보기를 누르세요. IDE는 변환 결과를 텍스트로 보여줍니다. 먼저 확인하세요. 인식하지 못하는 줄은 그대로 두며, Java의 static이라는 단어는 Kotlin에서 빠집니다(사용하기 전에 의미를 확인하세요). XML에서 Compose로의 변환은 텍스트, 힌트, 방향만 바꿉니다. 크기, 색상, 기타 속성은 아직 포함되지 않습니다. 결과가 올바르면 파일에 적용을 눌러 대상 파일을 쓰세요. 소스 파일은 변경되지 않습니다. 안전하고 일반적인 패턴만 변환됩니다.

로컬 마이크로 서버
인터넷 없이 서버가 필요한 앱을 테스트하려면 주 메뉴에서 로컬 마이크로 서버를 열고 라우트 정의를 작성한 뒤(예: GET /halo와 그 JSON 답변) 서버 시작을 누르세요. IDE는 같은 휴대폰에서 작은 HTTP 서버를 실행합니다(HTTP만, TLS 없음, 같은 Wi-Fi 네트워크용). 모든 요청과 답변을 화면에 기록합니다. 라우트는 {nama} 같은 매개변수와 간단한 API 키를 사용할 수 있습니다. 이 서버는 휴대폰에서 테스트하기 위한 것입니다. 빌드된 APK는 아직 서버가 될 수 없으며, 화면을 닫으면 서버가 중지됩니다.

보안 감사
출시 전에 프로젝트 코드의 보안 취약점을 확인하려면 주 메뉴에서 보안 감사를 열고 프로젝트를 선택한 뒤 검사 시작을 누르세요. IDE는 코드, 매니페스트, 프로젝트 설정을 검사하여 위험도가 높은 순서대로 결과를 보고합니다. 코드에 노출된 API 키, 권한 없이 노출된 구성 요소, JavaScript 인터페이스와 함께 JavaScript를 활성화하는 WebView, 약한 암호화(MD5, SHA1, DES), TLS가 없는 http 주소, 코드에 직접 적힌 비밀번호 등이며, 각각 파일과 줄 번호가 함께 표시됩니다. 안전한 수정 방법이 있는 결과(예: MD5를 SHA-256으로, http를 https로 바꾸기)는 수정 적용을 누르세요. API 키와 비밀번호에 대해서는 IDE가 제안된 수정 방법만 보여줍니다. 대체 방법은 개발자가 직접 결정해야 하기 때문입니다. 이 검사는 코드의 텍스트 패턴을 읽는 것이지 바이트코드가 아니므로, 실제로는 안전한 결과가 포함될 수도 있고, 패턴이 없는 취약점은 검사를 빠져나갈 수도 있습니다. 적용하기 전에 확인하세요.

인터페이스 테스트 로봇
텍스트 시나리오를 이용해 앱의 외관을 자동으로 테스트하려면 주 메뉴에서 인터페이스 테스트 로봇을 열고 프로젝트를 선택한 뒤 자동 시나리오 만들기를 누르세요. IDE는 프로젝트 매니페스트와 레이아웃을 읽어 텍스트 단계로 이루어진 시나리오를 작성합니다(버튼 누르기, 필드 채우기, 대기, 돌아가기). 드라이 런 실행을 눌러 타임스탬프가 있는 시나리오 실행 로그를 확인하세요. 이 단계에서 로봇은 시뮬레이션(드라이 런)만 실행합니다. 휴대폰에서 실제로 버튼을 누르고 실제 충돌을 포착하는 것은 다음 단계이므로, 여기의 충돌 보고서는 아직 샘플 형식입니다.

코드 시간 여행
Git 명령을 입력하지 않고 프로젝트를 이전 코드 상태로 되돌리려면 주 메뉴에서 코드 시간 여행을 열고 프로젝트를 선택한 뒤 시점 레이블을 입력하고(비워 둘 수 있음) 시점 기록을 누르세요. IDE는 프로젝트 소스 파일의 복사본을 해시와 함께 프로젝트 안의 .riwayat 폴더에 저장합니다. 시점 목록에 모두 표시됩니다. 두 시점을 선택한 뒤 비교를 눌러 추가, 변경, 삭제된 파일과 함수를 확인하세요. 복원을 눌러 이전 상태로 되돌릴 수 있습니다. 복원하기 전에 IDE는 항상 현재 상태를 먼저 백업하므로 아무것도 잃지 않습니다. 실험 복사본 만들기를 눌러 프로젝트를 새 폴더에 복사하고 원본 프로젝트를 건드리지 않고 변경을 시도하세요. 소스 파일만 기록됩니다.

모듈 팩토리
프로젝트의 일부를 다른 프로젝트에서 사용할 수 있는 모듈로 패키징하려면 주 메뉴에서 모듈 팩토리를 열고 소스 프로젝트를 선택한 뒤 패키징할 화면, 클래스, 문자열, 권한 파일에 체크하고 모듈로 패키징을 누르세요. IDE는 ZIP 아카이브와 JSON 메타데이터(모듈 이름, 버전, 사용된 문자열과 권한)를 작성합니다. 모듈을 다른 프로젝트에 설치하려면 모듈 팩토리를 열고 대상 프로젝트를 선택한 뒤 모듈 설치를 누르고 모듈 .zip 파일을 선택하세요. 병합은 기존 코드를 덮어쓰지 않고 문자열과 권한을 추가하며, 파일 이름이 대상 프로젝트에서 이미 사용 중이면 해당 파일을 병합하지 않습니다. 모듈은 라이브러리나 빌드 설정을 포함하지 않습니다.

다형성 방패 및 애셋 보관소
출시 전에 식별자 이름을 무작위화하고 프로젝트 애셋을 암호화하려면: 주 메뉴에서 다형성 방패 및 애셋 보관소를 열고, 프로젝트를 선택한 뒤 이름 무작위화 및 애셋 암호화를 누릅니다. IDE는 소스 코드의 클래스 이름과 메서드 이름을 스캔하고, 무작위 이름 맵을 만들고, 프로젝트 애셋 파일을 AES-GCM으로 프로젝트 안의 brankas-aset 폴더에 암호화하며, 암호화된 복구 맵(perisai-peta.brankas)을 저장하여 충돌 로그를 읽을 때 원래 이름을 복원할 수 있게 합니다. 암호화 키는 프로젝트 이름에서 파생되므로 프로젝트 이름을 아는 사람은 누구나 보관소를 열 수 있습니다. 이는 가벼운 읽기로부터의 보호이지, 비밀번호로 잠긴 보관소가 아닙니다. 여기서 만들어지는 것은 이름 맵과 애셋 보관소입니다. 컴파일된 DEX 파일 안의 이름을 다시 쓰는 것은 다음 단계이므로 완성된 APK 안의 이름은 아직 무작위화되지 않았습니다.

신뢰 체인 및 환경 수호자
출시 전에 서명 키 체인과 휴대폰 환경을 확인하려면: 주 메뉴에서 신뢰 체인 및 환경 수호자를 열고, 프로젝트를 선택한 뒤 체인 및 환경 확인을 누릅니다. IDE는 프로젝트 패키지 이름에서 5세대 키 체인을 만들고 무결성을 확인한 뒤, 자체 프로세스의 메모리 맵과 기기 속성을 스캔하여 Frida, Xposed 또는 에뮬레이터의 흔적을 찾습니다. 결과는 텍스트 증거와 함께 안전, 주의 또는 위험의 위험 수준입니다. 이 검사는 메모리 맵과 시스템 속성의 텍스트 패턴을 읽는 것이지, 네이티브 라이브러리 수준의 원시 메모리 무결성이 아니며, 키를 하드웨어 보안 칩에 묶지도 않습니다. 텍스트 흔적을 숨기는 주입 도구는 이 검사를 피해갈 수 있습니다.

텍스트 트리 레이아웃 설계자
화면을 보지 않고 화면을 설계하려면: 주 메뉴에서 텍스트 트리 레이아웃 설계자를 열고, 프로젝트와 레이아웃 파일을 선택한 뒤 레이아웃 확인을 누릅니다. IDE는 XML 레이아웃을 텍스트 트리로 읽고 각 요소의 위치 설명을 소리 내어 읽습니다(예: 오른쪽 아래, 화면 너비의 45퍼센트). 그런 다음 360dp 너비에서 요소 간의 겹침과 화면 밖으로 나가는 요소를 수학적으로 보고합니다. 계산되는 것은 LinearLayout과 단순한 dp 크기입니다. ConstraintLayout과 Compose 화면은 위치가 불확실하다고 보고되며 추측하지 않습니다.

디자인 시스템 스튜디오
모든 화면과 프로젝트에서 간격, 글꼴, 모서리를 통일하려면: 주 메뉴에서 디자인 시스템 스튜디오를 열고, 프로젝트를 선택하고, 디자인 토큰을 작성한 뒤(예: jarak=8, huruf=16, sudut=12), 컴포넌트를 선택하고 컴포넌트 생성을 누릅니다. IDE는 토큰을 검증합니다. 기본 간격 4~16dp, 기본 글꼴 12~20sp, 모서리 0~32dp, 최소 터치 영역 48dp입니다. 그런 다음 바로 사용할 수 있는 XML 컴포넌트(komponen-studio.xml)와 XML 테마(tema-studio.xml) 및 Compose 테마(tema-studio.kt)를 프로젝트 폴더에 씁니다. 컴포넌트는 레이아웃에 붙여넣는 텍스트로 생성된 뒤 레이아웃 설계자로 검사합니다. 태블릿의 두 열 조정은 런타임 기기 감지가 아니라 화면 너비 한정자를 사용합니다.

의미적 리팩터링 및 AST 탐색
우연히 같은 이름을 가진 다른 코드를 망가뜨리지 않고 정의를 찾아 기호 이름을 바꾸려면: 주 메뉴에서 의미적 리팩터링 및 AST 탐색을 열고, 프로젝트를 선택한 뒤 프로젝트 기호 스캔을 눌러 모든 클래스와 메서드를 파일 및 줄 번호와 함께 봅니다. 기호 이름을 입력하고 프로젝트 기호 스캔을 다시 눌러 정의와 이를 호출하는 모든 파일을 봅니다. 이름을 바꾸려면 새 이름을 입력하고 이름 변경 미리 보기를 눌러 각 파일의 나타난 횟수를 확인한 뒤 이름 변경 적용을 누릅니다. 이 인덱서는 텍스트 패턴을 사용하며 완전한 AST 파서가 아닙니다. 클래스 이름 변경은 모든 파일에 적용되지만, 메서드 이름 변경은 소유 파일에만 적용됩니다. 다른 파일의 호출자는 변경되지 않으므로 적용하기 전에 미리 보기와 호출자 스캔 결과를 확인하십시오. 코드 블록을 새 함수로 추출하는 기능은 이미 논리 엔진에 있지만 이 화면에는 아직 버튼이 없습니다.

단계별 디버거 및 메모리 검사기
로그를 통해 추측하지 않고 프로그램 흐름 중간에 변수 내용을 검사하려면: 주 메뉴에서 단계별 디버거 및 메모리 검사기를 열고, 프로젝트를 선택하고, 실행 추적을 작성합니다(한 줄에 한 단계. 줄 번호, 코드, 그다음 | 로 구분된 변수와 값 형식. 예: 10|int total = harga * jumlah;|harga=5000, jumlah=3, total=15000). 중단점 줄 번호를 입력하고 디버그 추적 실행을 누릅니다. IDE는 첫 번째 중단점까지 실행하고 Jieshuo를 통해 활성 줄과 변수 값을 소리 내어 읽습니다. 한 줄씩 이동을 눌러 한 줄 앞으로 가거나, 프로그램 계속을 눌러 다음 중단점까지 실행합니다. 이는 추적 디버거입니다. 기록되거나 손으로 작성된 실행 추적을 따라가며, 실행 중인 Android 앱을 일시 중지하지 않습니다. 실제 프로세스를 일시 중지하려면 디버그 브리지가 필요하며 이 단계에는 없습니다.

오프라인 종속성 관리자
인터넷 없이 타사 라이브러리를 사용하고 빌드 전에 버전 충돌을 피하려면: 주 메뉴에서 오프라인 종속성 관리자를 열고, 프로젝트를 선택한 뒤 종속성 확인을 누릅니다. IDE는 프로젝트의 모든 .gradle 파일을 읽고, 오프라인 보관소(프로젝트 안의 brankas-maven.txt)를 확인하고, 충돌을 해결합니다. 두 라이브러리가 같은 아티팩트의 다른 버전을 요구하면 가장 높은 버전이 사용되고 충돌이 보고됩니다. 보관소에 라이브러리를 기록하려면 좌표를 입력합니다(group:artifact:version 형식. 예: com.google.code.gson:gson:2.10.1). 그런 다음 종속성 확인을 누릅니다. Maven, Google 또는 PyPI에서 다운로드하려면 인터넷이 필요합니다. 오프라인에서는 보관소에 이미 있는 라이브러리만 사용할 수 있으며, 좌표 추가는 인덱스에 기록만 합니다. AAR, JAR, WHL 파일 자체는 자동으로 다운로드되지 않습니다. 보관소는 여전히 프로젝트별로 저장됩니다.

데이터베이스 및 저장소 검사기
테이블 내용을 출력하는 코드를 작성하지 않고 프로젝트 데이터베이스 내용을 검사하고 테스트하려면: 주 메뉴에서 데이터베이스 및 저장소 검사기를 열고, 프로젝트와 데이터베이스 파일(.db, .sqlite 또는 .sqlite3)을 선택한 뒤 데이터베이스 열기를 누릅니다. IDE는 테이블 스키마를 읽고 처음 20개 행을 Jieshuo가 소리 내어 읽는 텍스트 테이블로 표시합니다. 간단한 SELECT 쿼리를 작성한 뒤 쿼리 실행을 누릅니다(예: SELECT nama FROM pengguna WHERE kota = 'Makassar'). 값을 변경하려면 행 번호(1 = 첫 번째 행), 열 이름, 새 값을 입력하고 셀 값 변경을 누릅니다. 값이 .db 파일에 다시 쓰입니다. 현재 테이블 상태를 프로젝트의 <db 이름>.cadangan.txt 파일로 저장하려면 백업 저장을 누릅니다. 첫 번째 테이블만 읽습니다. 지원되는 쿼리는 JOIN이나 GROUP BY가 없는 간단한 SELECT뿐입니다. SharedPreferences와 DataStore는 아직 읽지 않습니다.

단위 테스트 팩토리 및 퍼징
앱을 공유하기 전에 논리 결함을 찾으려면: 주 메뉴에서 단위 테스트 팩토리 및 퍼징을 열고, 프로젝트와 코드 파일을 선택한 뒤 테스트 만들기 및 실행을 누릅니다. IDE는 파일의 함수 시그니처를 읽고, 일반 및 경계 테스트 케이스(빈 텍스트, null, 최대 숫자, 이상한 문자)를 생성하고, 예제 함수에 대해 퍼징을 실행하며, JUnit 테스트 뼈대(Uji<클래스 이름>.java)를 프로젝트에 씁니다. 결과는 통과 및 실패한 테스트 수, 찾은 코드 줄 수와 함수 수, 생성된 테스트 케이스 수를 보고합니다. 생성된 테스트는 여전히 뼈대입니다. 기대값은 개발자가 작성해야 합니다. 실제 퍼징은 프로젝트 함수가 아니라 예제 함수에 대해서만 실행됩니다. 줄 커버리지 백분율은 아직 계산되지 않습니다.

극단적 기기 조건 시뮬레이터 및 메모리 누수 감사자
시스템이 프로세스를 종료하거나, 네트워크가 끊기거나, 화면이 회전하거나, 배터리 절약 모드가 켜졌을 때 앱의 복원력을 테스트하려면: 주 메뉴에서 극단적 기기 조건 시뮬레이터 및 메모리 누수 감사자를 열고, 프로젝트를 선택한 뒤 시뮬레이션 실행을 누릅니다. IDE는 화면 회전 시뮬레이션과 함께 세 가지 스트레스 시나리오를 실행하고, 화면이 닫힌 뒤 메모리에 남아 있는 객체를 추적한 뒤, 잃어버린 데이터와 누수되는 객체 체인을 보고합니다. 이는 상태 모델에 대한 시뮬레이션이며, 실제로 프로세스를 종료하거나, 실제로 휴대폰 네트워크를 끊거나, 실제 힙 덤프가 아닙니다. 이 화면의 상태 모델은 여전히 고정된 예시이며, 사용자 프로젝트 화면의 상태가 아닙니다.

프로젝트 청사진 설계자
큰 앱 아이디어를 단계별 작업 계획으로 바꾸려면: 주 메뉴에서 프로젝트 청사진 설계자를 열고, 프로젝트를 선택하고, 앱 아이디어를 작성한 뒤(예: 할부가 가능한 식료품점 계산원 앱), 청사진 만들기를 누릅니다. IDE는 모듈, 파일 목록, 작은 작업 마일스톤을 정리하고 프로젝트 폴더의 cetak-biru.txt로 저장합니다. 마일스톤이 완료될 때마다 다음 마일스톤 완료로 표시를 누르거나, 저장된 청사진 불러오기를 눌러 저장된 청사진을 다시 엽니다. 청사진은 기기의 키워드 패턴으로 만들어지며, 온라인 AI 모델에서 만들어지지 않습니다. 인식되지 않는 아이디어는 일반 뼈대(데이터 모델, 저장소, 화면, 논리)를 사용합니다. 활성 AI 제공업체를 통한 구축은 이 단계에 없습니다.

코드 논리 흐름 내레이터
구문을 한 줄씩 듣지 않고 긴 코드를 이해하려면: 주 메뉴에서 코드 논리 흐름 내레이터를 열고, 프로젝트와 코드 파일을 선택한 뒤 코드 설명을 누릅니다. IDE는 각 줄을 인도네시아어 문장으로 바꾸고(예: 합계가 100000보다 크면 다음 블록을 실행), 메서드 간의 호출 맵을 표시하며, 잠재적인 미묘한 버그를 줄 번호와 함께 표시합니다. == 로 비교하는 String, 닫지 않고 연 스트림, 두 개의 다른 메서드에 쓰인 변수입니다. 설명과 검사는 오프라인 텍스트 패턴을 사용하며, 온라인 AI 모델도, 완전한 데이터 흐름 분석도 아닙니다. 인식되지 않는 패턴은 코드 줄 그대로 설명되며, 데이터 경쟁 경고는 실제로 번갈아만 사용되는 변수에도 나타날 수 있습니다.

앱 번들 팩토리 및 Play 스토어 준비 상태
휴대폰에서 직접 Google Play 스토어용 앱을 준비하려면: 주 메뉴에서 앱 번들 팩토리 및 Play 스토어 준비 상태를 열고, 프로젝트를 선택한 뒤 AAB 번들 만들기를 누릅니다. IDE는 프로젝트 매니페스트, 리소스, 애셋에서 .aab 파일을 조립하고, 아키텍처(arm64-v8a, armeabi-v7a, x86_64) 및 언어별 다운로드 분할 크기를 시뮬레이션한 뒤, Play 준비 상태를 감사합니다. 대상 SDK가 35 미만이면 높음으로 표시됩니다. Play 스토어는 35 이상을 요구하기 때문입니다. 누락된 64비트 라이브러리도 높음으로 표시됩니다. 결과 번들은 표준 구조의 AAB 아카이브입니다. 분할 크기는 파일 크기에서 추정한 것이지, 실제 bundletool 분할 결과가 아닙니다. Play Console용 번들 서명은 여전히 APK와 같은 빌드 경로를 사용합니다.

OTA 업데이트 엔진 및 단계적 출시
사용자에게 전체 APK를 다시 다운로드하도록 강요하지 않고 작은 수정 사항을 보내려면: 주 메뉴에서 OTA 업데이트 엔진 및 단계적 출시를 열고, 프로젝트를 선택하고, 이전 버전과 새 버전의 내용을 작성한 뒤 패치 패키지 만들기를 누릅니다. IDE는 줄 차이를 계산하고 새 내용의 SHA-256 지문이 포함된 패치 패키지(patch-ota.zip)를 만든 뒤, 이 기기가 초기 10퍼센트 출시 단계에 있는지 확인합니다. 여기서 패치는 텍스트 파일(스크립트, 애셋, 구성)에 대해서만 동작합니다. 이진 DEX 또는 APK 패치는 아직 지원되지 않으며, 패치는 앱을 다시 열 때 적용됩니다. 매니페스트의 지문은 내용 무결성만 증명하고, 아직 개인 키 서명을 사용하지 않으므로 발신자 진위 여부는 증명하지 않습니다.

팀 코드 리뷰 스튜디오
Git 화살표 표시를 읽지 않고 동료의 변경 사항을 검토하고 병합 충돌을 해결하려면: 주 메뉴에서 팀 코드 리뷰 스튜디오를 열고, 프로젝트를 선택하고, 세 가지 텍스트 버전(기본, 로컬, 동료)을 채운 뒤 팀 리뷰 열기를 누릅니다. IDE는 세 가지를 병합하고 각 충돌을 음성 선택으로 표시합니다. 로컬 버전 사용, 동료 버전 사용 또는 둘 다 병합입니다. 결과 줄은 원래 충돌 위치에 삽입되어 줄 순서가 올바르게 유지됩니다. 그런 다음 결과를 프로젝트의 gabung-hasil.txt에 씁니다. 그 아래에는 프로젝트 작업 보드가 있습니다. 작업 제목을 입력하고 작업 추가를 누릅니다. 작업은 프로젝트 안의 .tugas 폴더에 텍스트로 저장됩니다. 병합은 구문이 아니라 줄 일치를 사용하므로, 같은 줄의 두 변경 사항은 의미가 충돌하지 않더라도 항상 충돌로 처리됩니다. 작업 보드는 텍스트 파일을 Git 기록과 함께 복사하여 동기화되며, 전용 동기화 서버는 없습니다.

코드 구조 받아쓰기
편집기 안에서 음성으로 코드를 작성하려면 편집기에서 프로젝트를 연 뒤 코드 구조 받아쓰기 버튼을 누르세요. 인도네시아어로 명령을 말하세요. 예를 들어 buat fungsi tambah dengan parameter a angka dan b angka, buat kelas Mobil, buat variabel teks nama sama dengan Budi. IDE는 음성을 문법적으로 올바른 Java, Kotlin, Python 또는 Compose 코드 블록으로 변환하여 커서 위치에 삽입한 뒤 Jieshuo를 통해 짧은 요약을 읽어 줍니다. 받아쓰기는 시스템에 내장된 음성 입력 서비스를 사용하며 추가 마이크 권한이 필요 없고, 이미 등록된 명령 패턴만 인식합니다. 패턴 밖의 음성은 코드로 변환되지 않습니다. 단어로 말한 숫자(예: 'lima')는 아직 숫자로 변환되지 않습니다.

로컬 협업 공간(인터넷 없음)
인터넷 없이 한 방에서 함께 작업하려면 주 메뉴에서 협업을 열고 로컬 협업 공간 섹션을 여세요. 한 휴대폰이 세션을 엽니다(IDE에 로컬 IP 주소와 6자리 PIN이 표시됩니다). 다른 휴대폰이 해당 주소와 PIN으로 참여합니다. 텍스트 변경은 줄 차이로 전송되고, 빌드된 APK를 테스터의 휴대폰으로 보낼 수 있으며, 테스터 휴대폰의 충돌 보고서도 다시 받아볼 수 있습니다. 한 세션은 한 친구 전용입니다. 두 사람이 정확히 같은 줄을 동시에 변경하면 마지막 변경이 사용됩니다. PIN은 로컬 네트워크에서 일반 텍스트로 전송됩니다. 이 공간은 아직 실제 휴대폰에서 테스트되지 않았습니다.

AI 설정
앱 생성을 위한 AI 제공업체와 API 키를 설정하려면 주 메뉴의 설정 그룹에서 AI 설정(커넥터 버튼 옆)을 누르세요. 사용 가능한 목록에서 사용할 제공업체를 선택하고, 프로바이더 오류 시 모델 전환에 체크하세요. 한 모델이 실패하면 IDE가 같은 제공업체의 다음 모델을 자동으로 시도합니다. API 키 관리를 눌러 백업 키를 추가하세요(이름과 키를 입력한 뒤 저장을 누릅니다. 키는 마스킹되어 표시되며 마지막 4자만 보입니다). 키는 휴대폰에 저장되며 앱을 만들 때 선택한 제공업체 외에는 어디에도 전송되지 않습니다. 참고: 현재 제공업체와 키 선택은 기록되어 AI Pembuat Aplikasi 화면에만 표시됩니다. 앱 생성은 여전히 휴대폰의 로컬 AI(인터넷 없음)를 사용하며, 온라인 제공업체 사용은 나중에 추가됩니다.

커넥터
APK를 분석한 뒤 보내려면 주 메뉴의 설정 그룹에서 커넥터(AI 설정 버튼 옆)를 누르세요. 휴대폰에서 APK 파일을 선택하면 IDE가 그 내용(패키지 이름, 버전, 액티비티 목록)을 읽은 뒤 APK 보내기를 눌러 시스템 공유 메뉴(예: WhatsApp 또는 Drive)로 보냅니다.

언어 및 음성
앱 언어를 변경하려면 설정을 열고 앱 언어를 연 뒤 언어 또는 시스템 설정 따르기를 선택하세요. 주 화면과 대부분의 화면은 앱을 닫거나 다시 시작하지 않아도 선택한 언어로 즉시 바뀝니다. 일부 화면(예: 터미널, 협업, AI 설정, 키 관리)은 다시 열 때까지 이전 언어를 계속 사용합니다. 시스템 설정 따르기를 선택하면 언어는 휴대폰 시스템 언어를 따릅니다.
