Create Aplikasi by Al Kautsar에 오신 것을 환영합니다
Create Aplikasi는 노트북 없이 휴대폰에서 바로 실행되는 Android 앱 제작 애플리케이션입니다. 이 앱을 사용하면 앱 만들기를 처음 배우는 사용자와 화면 낭독기 사용자를 포함해 누구나 자신만의 Android 앱을 만들 수 있습니다. 이 앱의 전체 사용 안내는 이 Tentang Alat(도구 정보) 화면에서 볼 수 있습니다.

이 앱은 무엇이며 누구를 위한 것인가
Create Aplikasi는 휴대폰에서 실행되는 Android 앱 제작 도구입니다. 이 앱은 초보자와 화면 낭독기 사용자를 포함해 자신만의 Android 앱을 만들고 싶은 모든 사람을 위한 것입니다. 이 앱은 코드 편집기, 프로젝트를 테스트하는 Jalankan(실행) 버튼, APK를 만드는 Bangun(빌드) 버튼, 그리고 APK에 서명하고 설치하는 메뉴를 제공합니다.

이 앱의 목적
이 앱은 누구나 휴대폰에서 바로, 쉽게 자신만의 Android 앱을 만들 수 있도록 만들어졌습니다. 화면은 최대한 단순하게 만들어져 있어 처음 사용하는 사용자도 바로 시도해 볼 수 있습니다.

새 프로젝트를 만드는 방법, 단계별 안내
1. 메인 메뉴에서 Buat Project(프로젝트 만들기)를 누릅니다.
2. 프로젝트 종류를 선택합니다: HTML, Situs Web(웹사이트), Java, Kotlin, Compose 또는 Python.
3. 앱 이름을 입력합니다. 예: Garuda Decode.
4. 패키지 이름(package name)을 입력합니다. 예: com.android.garudadecode. 패키지 이름은 소문자를 사용해야 하며 마침표로 구분된 최소 두 부분으로 이루어져야 합니다.
5. 앱 버전을 입력합니다. 예: 1.0, 그리고 숫자로 된 버전 코드를 입력합니다. 예: 1. 비워 두면 버전은 자동으로 1.0, 버전 코드는 1로 채워집니다.
6. 필요하면 최소 SDK와 대상 SDK를 입력합니다. 비워 두면 기본값이 사용됩니다. 최소 SDK는 지원되는 가장 낮은 Android 버전입니다. 예: 21은 Android 5.0을 뜻합니다. 대상 SDK의 최대값은 36(Android 16)입니다.
7. Pilih Izin(권한 선택) 버튼을 눌러 앱 권한을 선택합니다. 예: INTERNET. INTERNET 권한은 기본으로 선택되어 있습니다. 앱에 실제로 필요한 권한만 선택하십시오.
8. 원한다면 "Gunakan arsitektur terpisah 64 bit dan 32 bit"(64비트와 32비트 분리 아키텍처 사용)에 체크하면 APK 크기가 더 작아지고, 직접 만든 keystore를 쓰고 싶다면 "Gunakan tanda tangan pribadi"(개인 서명 사용)에 체크합니다.
9. Buat Proyek(프로젝트 만들기)를 누릅니다. 새 프로젝트는 Download/project 폴더에 저장되고 Kelola Project(프로젝트 관리)에 바로 나타납니다.

사용할 수 있는 프로젝트 종류
• HTML: index.html, style.css, script.js로 이루어진 화면이 WebView를 통해 실행됩니다. 휴대폰에서 바로 빌드됩니다.
• Situs Web: index.html, tentang.html, kontak.html, style.css, script.js로 이루어진 메뉴(Beranda(홈), Tentang(정보), Kontak(연락처))가 있는 웹사이트가 WebView를 통해 실행됩니다. 휴대폰에서 바로 빌드됩니다.
• Java: 휴대폰에서 빌드됩니다. MainActivity는 app/src/main/java/<nama-paket>/MainActivity.java에 있습니다. 화면은 app/src/main/res/layout/activity_main.xml에서, 텍스트는 app/src/main/res/values/strings.xml에서, 테마는 app/src/main/res/values/styles.xml에서 가져옵니다.
• Kotlin: 앱에 포함된 Kotlin 컴파일러를 사용해 기기에서(오프라인으로) 빌드하거나 GitHub Actions를 통해 빌드할 수 있습니다. MainActivity는 app/src/main/java/<nama-paket>/MainActivity.kt에 있고, res 파일은 Java 프로젝트와 같습니다. 첫 Kotlin 빌드는 컴파일러 크기가 커서 더 느리고, Kotlin 클래스를 참조하는 .java 파일은 아직 빌드할 수 없습니다(.java 파일이 .kt 파일보다 먼저 컴파일됩니다).
• Compose: Jetpack Compose(XML 레이아웃이 아님)로 인터페이스를 만드는 현대적인 Android 앱입니다. MainActivity는 app/src/main/java/<nama-paket>/MainActivity.kt에 있습니다. Compose 프로젝트는 Jetpack Compose 라이브러리가 기기에 없어서 GitHub Actions(프로젝트 Bangun 메뉴, 그다음 Bangun online(온라인 빌드))를 통하거나 Gradle과 함께 Termux에서 빌드됩니다.
• Python: 앱 로직을 app/src/main/python/main.py에 Python(Chaquopy) 언어로 작성하고, app/src/main/java/<nama-paket>/MainActivity.java의 호스트 MainActivity.java가 실행합니다. Python 프로젝트는 휴대폰에서 바로 빌드할 수도 있고(Chaquopy 런타임이 앱에 포함되어 있습니다) GitHub Actions를 통해서도 빌드할 수 있습니다. Python 프로젝트의 최소 SDK는 24(Android 7.0)입니다.

프로젝트 아키텍처 변경
새 프로젝트를 만들지 않고 기존 프로젝트의 아키텍처 옵션을 변경하려면: 기본 메뉴에서 «프로젝트 아키텍처 변경»을 누르고, 프로젝트를 선택한 뒤 «64비트 APK 빌드 (arm64-v8a)» 또는 «32비트 APK 빌드 (armeabi-v7a)» 확인란을 변경합니다. 또는 프로젝트 관리에서 프로젝트 이름을 길게 누르고 «아키텍처 변경»을 선택하면 같은 화면이 해당 프로젝트용으로 직접 열립니다. 규칙은 다음과 같습니다. 두 확인란이 모두 켜져 있으면 빌드는 두 개의 별도 APK를 만듭니다. 하나는 64비트, 다른 하나는 32비트입니다. 하나의 확인란만 켜져 있으면 빌드는 64비트와 32비트 기기 모두에서 계속 실행되는 하나의 범용 APK를 만듭니다. 단일 변형에 대한 별도 APK는 아직 지원되지 않습니다. 빌드 경로는 분할 또는 범용 선택만 알기 때문입니다. 그러나 각 변형의 선택은 프로젝트 안에 저장된 채로 남아 있으므로 화면을 다시 열어도 사라지지 않습니다.

Java, HTML, Situs Web, Kotlin, Compose, Python 프로젝트의 파일 구성
Java, HTML, Situs Web, Kotlin, Compose, Python 프로젝트는 일반적인 Android 프로젝트처럼 구성됩니다. app 폴더 안에는 src 폴더가 있고, 그 안에는 main 폴더가 있습니다. main 폴더 안에는 java 폴더 옆에 AndroidManifest.xml이 있고, layout/activity_main.xml과 values/strings.xml 및 values/styles.xml을 담고 있는 res 폴더가 있으며, HTML과 Situs Web의 경우 index.html(Situs Web는 tentang.html과 kontak.html도 있음)을 담고 있는 assets 폴더가 있습니다. HTML과 Situs Web 프로젝트도 app/src/main/java/<nama-paket>/MainActivity.java에 자체 MainActivity가 있어 WebView에 index.html을 불러오고 AndroidManifest에서 런처가 됩니다. Python 프로젝트는 app/src/main/python/main.py에 Python 코드가 있고 app/src/main/java/<nama-paket>/MainActivity.java에 호스트 MainActivity.java가 있습니다. AndroidManifest.xml, layout, strings, styles는 MainActivity와 마찬가지로 편집기에서 열고 수정할 수 있습니다. 매니페스트가 아직 app 폴더 옆에 있는 오래된 프로젝트도 빌드할 수 있습니다. 빌드할 때 앱은 먼저 app/src/main/의 AndroidManifest.xml을 확인하고, 그다음 app 폴더 옆의 것을 확인하며, 마지막으로 프로젝트 데이터 파일을 확인하기 때문입니다.

권한 규칙 (중요)
프로젝트를 만들 때 체크한 권한은 프로젝트 종류에 따라 한 곳에만 기록됩니다. Java, HTML, Situs Web, Kotlin, Compose, Python 프로젝트의 경우 체크한 권한은 프로젝트 폴더 안, java 폴더 옆, app/src/main/에 있는 AndroidManifest.xml에만 기록됩니다. Java, HTML, Situs Web, Kotlin, Compose, Python 프로젝트의 프로젝트 데이터 파일에는 권한 목록이 들어 있지 않습니다. Java를 선택하고 INTERNET과 CAMERA에 체크하면 AndroidManifest.xml에 기록되는 것은 INTERNET과 CAMERA뿐이며 다른 권한은 함께 기록되지 않습니다. 빌드할 때 앱은 같은 곳에서 권한을 읽습니다: Java, HTML, Situs Web, Kotlin, Compose, Python 프로젝트는 app/src/main/의 AndroidManifest.xml에서(없으면 오래된 프로젝트용으로 app 폴더 옆의 AndroidManifest.xml에서), 그리고 오래된 프로젝트는 프로젝트 데이터 파일에서 읽습니다.

편집기 사용 방법
Kelola Project를 열고 프로젝트 이름을 눌러 편집기를 엽니다. 편집기에서는 파일을 열고, 코드를 작성하고, 변경 사항을 저장할 수 있습니다. Java, HTML, Situs Web, Kotlin, Compose, Python 프로젝트의 파일은 app/src/main 폴더 안에 구성되어 있습니다. 프로젝트를 공유하려면 Ekspor ZIP(ZIP 내보내기)을 사용하십시오(아래 부분 참조).

프로젝트 실행 방법
편집기에서 Jalankan을 눌러 프로젝트를 테스트합니다. HTML과 Situs Web 프로젝트에서는 index.html이 WebView를 통해 실행됩니다. 오류가 발생하면 오류 메시지를 읽고 코드를 수정한 뒤 다시 실행하십시오.

APK 빌드 방법
편집기에서 Bangun을 누릅니다. 빌드 방법은 두 가지가 있습니다. 첫째, Bangun di perangkat(기기에서 빌드): 인터넷 없이 휴대폰에서 바로 빌드하며, HTML, Situs Web, Java, Kotlin, Python 프로젝트에 사용됩니다. 둘째, GitHub Actions를 통한 Bangun online(온라인 빌드): GitHub에서 인터넷을 통해 빌드하며 모든 종류의 프로젝트에 사용할 수 있습니다. Compose 프로젝트는 Jetpack Compose 라이브러리가 기기에 없어서 두 번째 방법(온라인 빌드)으로만, 또는 Gradle과 함께 Termux에서만 빌드할 수 있습니다. 첫 빌드 결과는 아직 서명되지 않은 상태입니다. 그 후 앱이 서명합니다: 자동으로 기본 키로 서명하거나, 프로젝트를 만들 때 "Gunakan tanda tangan pribadi" 상자에 체크했다면 개인 서명으로 서명합니다.

APK 설치 방법
APK가 완성되면 Pasang(설치)을 눌러 설치합니다. Android 8 이상에서는 이 앱이 Play Store 외부에서 APK를 설치하기 때문에 휴대폰이 먼저 "Izinkan dari sumber ini"(이 출처 허용)를 요청합니다. Pengaturan(설정)에서 그 권한을 한 번 활성화한 뒤 앱으로 돌아오십시오: Pasang을 다시 누를 필요 없이 설치가 자동으로 계속됩니다. Pasang 버튼이 나타나지 않으면 빌드가 끝났고 APK가 만들어졌는지 확인하십시오.

앱에 서명하는 방법
모든 APK는 설치할 수 있도록 서명되어야 합니다. 선택지는 두 가지입니다. 첫째, 기본 키: 앱이 자동으로 서명하므로 아무것도 할 필요가 없습니다. 둘째, 개인 서명: 먼저 메인 메뉴의 Buat Keystore(keystore 만들기) 메뉴를 통해 keystore를 만들고, 그 비밀번호를 잘 보관한 뒤, 프로젝트를 만들 때 "Gunakan tanda tangan pribadi"에 체크합니다. Keystore는 Download/project/signing에 저장됩니다.

프로젝트를 ZIP으로 내보내기
Ekspor ZIP은 프로젝트를 친구와 공유할 수 있도록 제공됩니다. 방법: Kelola Project에서 프로젝트 이름을 길게 누른 뒤 Ekspor ZIP을 선택합니다. 결과는 Download/project/<NamaProyek>.zip에 저장됩니다. bin 폴더는 포함되지 않아 크기가 수십 KB로 작습니다. 그 ZIP 파일은 친구에게 보내거나 GitHub에 올릴 수 있습니다.

Ekstensi JAWS
Ekstensi JAWS는 Jieshuo(CSR)의 확장 엔진을 사용하며, 그 화면 낭독기 자체를 사용하지 않습니다. 따라서 사용자가 TalkBack을 사용하더라도 설계가 계속 실행될 수 있습니다. 방법: 메인 메뉴에서 Ekstensi JAWS를 엽니다. 자동 클릭이 스스로 실행되므로, 먼저 Pengaturan Aksesibilitas(접근성 설정)에서 서비스를 활성화해야 합니다. 그 후 새 설계를 만들 수 있습니다: 설계 이름을 입력하고 OK를 누른 뒤 그 상자를 채웁니다.

깔끔하게 분리된 Daftar Klik
설계 안에는 두 개의 상자가 있습니다: 스크립트 상자와 Daftar Klik(클릭 목록) 상자입니다. 버튼 목록은 daftar_klik.txt 파일에 따로 저장되며 한 줄에 이름 하나씩 들어갑니다. 내용 예시: tombolSimpan, tombolHapus, tombolBuka. 앱을 열려면 그 목록에 >WhatsApp이라고만 쓰면 됩니다. 아직 daftar_klik.txt 파일이 없는 오래된 설계는 그 기본 예시를 표시합니다.

제공되는 간단한 함수
• klikTombol("tombolSimpan") — 텍스트를 기준으로 버튼 하나를 클릭합니다.
• klikDaftarTombol(daftar) — daftar_klik.txt의 목록을 클릭합니다. 한 줄에 버튼 하나씩, 순서대로 클릭한 뒤 몇 개가 성공했고 몇 개를 찾지 못했는지 알려줍니다.
• bukaAplikasi("WhatsApp") — 이름으로 앱을 엽니다. 또는 목록에 ">WhatsApp"이라고 씁니다.
• klik(540, 1200) — 화면 좌표를 클릭합니다.
모든 함수는 우선 단순하게 만들어졌습니다. 익숙해지면 나중에 함수를 추가할 수 있습니다.

화면 낭독기에 대하여
이 앱은 화면 낭독기에 친화적으로 설계되었습니다. 모든 입력 칸에는 라벨과 입력 예시가 있고, 모든 버튼은 복잡한 제스처 없이 닿을 수 있습니다. Ekstensi JAWS는 사용자가 TalkBack을 사용하더라도 계속 실행되도록 만들어졌습니다. 사용되는 것이 그 화면 낭독기가 아니라 확장 엔진이기 때문입니다.

개인정보와 보안
프로젝트와 keystore는 사용자의 휴대폰에 저장됩니다. GitHub 토큰은 온라인 빌드에만 사용되며 이 앱 안에 저장됩니다. 토큰이나 keystore 비밀번호를 누구와도 공유하지 마십시오. 개인 서명을 사용한다면 keystore와 그 비밀번호를 안전한 곳에 보관하십시오. 잃어버리면 예전 APK를 같은 서명으로 업데이트할 수 없기 때문입니다.

요구 사항
Android 5.0 이상. 저장소 권한: Android 11 이상에서는 모든 파일 접근 권한을 사용하고, Android 10 이하에서는 일반 저장소 권한(저장소 읽기/쓰기)을 사용합니다. Android 10에는 모든 파일 접근 권한이 없기 때문입니다. 기기에서 빌드하려면 ARM 프로세서(32비트 또는 64비트)를 탑재한 휴대폰이 필요합니다. GitHub Actions를 통한 온라인 빌드에는 인터넷과 GitHub 토큰이 필요합니다. Kotlin 프로젝트는 기기에서 빌드할 수 있지만, Kotlin 컴파일러 크기가 커서 첫 빌드가 더 느리고 메모리를 더 많이 사용합니다. Compose 프로젝트는 GitHub Actions를 통하거나 Gradle과 함께 Termux에서 빌드됩니다. Python 프로젝트는 Android 7.0 이상(최소 SDK 24)이 필요하고, Python 런타임(Chaquopy)과 그 표준 라이브러리를 포함하므로 결과 APK가 더 큽니다.

Terminal
메인 화면의 Terminal 메뉴는 이 앱 안에서 터미널을 엽니다. ls 같은 명령으로 프로젝트 폴더의 내용을 보고, cd로 폴더를 이동하고, git으로 코드를 관리할 수 있습니다. 명령 출력은 화면 낭독기가 읽을 수 있는 텍스트로 표시되며, 마지막 결과를 들을 수 있는 Bacakan hasil(결과 읽어주기) 버튼이 있습니다. 이 터미널은 휴대폰의 시스템 셸을 사용하므로 nano와 vim 같은 대화형 프로그램은 아직 여기서 사용할 수 없습니다.

Lisensi (유료 버전)
앱을 판매하려면 프로젝트를 만들 때 "Aktifkan Lisensi"(라이선스 활성화)에 체크한 뒤 WhatsApp 번호를 입력하십시오. 빌드된 앱은 처음 열릴 때 라이선스 코드를 요청합니다: 사용자가 자신의 기기 ID를 보고, Kirim ID Perangkat(기기 ID 보내기) 버튼을 눌러 그 ID를 사용자의 WhatsApp으로 보내면, 사용자가 라이선스 코드로 답합니다. 라이선스 코드는 기기 ID와 프로젝트 비밀번호(프로젝트 데이터 파일의 lisensi_seed)로 계산됩니다 — 그 비밀번호를 잘 보관하고 공유하지 마십시오. 올바른 코드가 입력되면 앱이 열리고 더 이상 코드를 요청하지 않습니다.

Pembuat Ikon Otomatis
새 프로젝트의 아이콘은 아직 투명하므로, 메인 메뉴에 Pembuat Ikon(아이콘 만들기)이 있습니다. 방법: Pembuat Ikon을 누르고, 한두 글자(예: 앱 이름의 이니셜)를 쓰고, 배경색과 글자색을 고르고, 미리보기를 본 뒤, Simpan ke Proyek(프로젝트에 저장)을 눌러 선택한 프로젝트에 그 아이콘을 사용하거나, Simpan ke Download(Download에 저장)를 눌러 그 PNG 파일을 다른 곳에 사용합니다. 프로젝트가 만들어진 후에도 앱이 아이콘 만들기를 제안합니다. 프로젝트의 예전 아이콘은 Kelola Project의 프로젝트 메뉴에서 언제든 바꿀 수 있습니다(프로젝트 이름을 길게 누른 뒤 Ganti Ikon(아이콘 변경)을 선택).

Template Proyek Siap Pakai
빈 프로젝트에서 시작하고 싶지 않다면 프로젝트를 만들 때 템플릿을 선택하십시오: Kalkulator(Java), Catatan(Java), Daftar Tugas(Kotlin), Kalkulator Web(HTML), Situs Profil(Situs Web), 또는 Penghitung(Compose). 템플릿을 선택하면 프로젝트 종류가 자동으로 그 템플릿을 따라 바뀌고, 프로젝트는 이미 완성된 시작 코드로 만들어집니다 — 바로 실행하거나 수정하면 됩니다. 템플릿을 선택한 뒤 프로젝트 종류를 다시 수동으로 바꾸면 템플릿이 취소되고 프로젝트는 다시 비게 됩니다. HTML과 Situs Web 템플릿의 경우, 템플릿은 index.html의 내용을 교체합니다. 여기에는 폼에 입력한 HTML 스크립트도 포함됩니다.

Cadangan dan Pulihkan Proyek
프로젝트가 사라지지 않도록 백업 기능이 있습니다. 방법: Kelola Project에서 프로젝트 이름을 길게 누른 뒤 Cadangkan(백업)을 선택합니다. 백업은 Download/backup 폴더에 프로젝트 이름과 날짜를 붙인 ZIP으로 저장됩니다. 예: GarudaDecode-2026-11-14-123045.zip. 내용은 Ekspor ZIP과 같습니다(프로젝트 전체 내용, bin 폴더 제외). 복원하려면: Kelola Project에서 메뉴를 열고 Pulihkan cadangan(백업 복원)을 선택한 뒤 백업 파일을 고릅니다. 프로젝트 이름이 이미 있으면 앱이 묻습니다: Timpa proyek lama(예전 프로젝트 덮어쓰기), 또는 Nama baru(새 이름)로 저장.

Bagikan dan Impor Proyek
프로젝트를 친구와 공유하려면: Kelola Project에서 프로젝트 이름을 길게 누른 뒤 Bagikan(공유)을 선택합니다. 프로젝트는 공유 앱(WhatsApp, Telegram 등)을 통해 ZIP으로 전송됩니다. 친구에게서 프로젝트를 받으려면: Kelola Project에서 메뉴를 열고 Impor proyek(프로젝트 가져오기)를 선택한 뒤 그 ZIP 파일을 고릅니다. 그 ZIP 파일에는 프로젝트 데이터 파일이 들어 있어야 합니다 — 없으면 그 파일은 Create Aplikasi 프로젝트가 아니므로 명확한 메시지와 함께 파일이 거부됩니다. 프로젝트 이름이 이미 있으면 앱이 묻습니다: Timpa proyek lama, 또는 Nama baru로 저장.

Pencarian dan Filter Proyek
프로젝트가 많아지면 Kelola Project에 검색 상자와 종류 필터가 있습니다. 검색 상자에 프로젝트 이름을 입력하면 목록이 바로 걸러집니다(대소문자는 구분하지 않습니다). 종류 필터는 목록을 한 종류로만 제한합니다: Semua(전체), HTML, Situs Web, Java, Kotlin, Compose 또는 Python. 각 프로젝트의 메뉴는 걸러진 목록에서도 평소와 같이 열 수 있습니다.

음성으로 앱 빌드하기
입력하고 싶지 않다면 음성을 사용하세요. 주 메뉴에서 음성으로 빌드를 누른 뒤 명령을 말하세요. 말할 수 있는 명령: "Buat proyek kalkulator", "Bangun proyek Kalkulator", "Buka proyek Kalkulator", "Jalankan proyek Kalkulator", "Daftar proyek", "Buka ikon", "Kembali", "Bantuan". 앱은 음성과 텍스트로 답하므로 화면을 보지 않고도 사용할 수 있습니다. 음성 인식은 휴대폰에 내장된 음성 인식 앱을 사용합니다(무료. 인도네시아어 언어 팩이 설치되어 있으면 오프라인에서도 동작합니다). 휴대폰에 음성 인식 기능이 없으면 같은 화면의 텍스트 상자에 명령을 입력할 수 있습니다.

AI 앱 빌더
AI 앱 빌더 화면에서 원하는 앱을 입력하거나 말로 알려 주세요. 예를 들어 «저장 버튼이 있는 메모 앱». 앱은 휴대폰 안에서 키워드를 분석합니다(인터넷 없이, 무료). 그런 다음 가장 잘 맞는 템플릿으로 실제 프로젝트를 만듭니다. 계산기, 메모, 할 일 목록, 웹 계산기, 프로필 사이트, 카운터 등입니다. 설명에 맞는 템플릿이 아직 없으면 앱은 빈 프로젝트를 만들고 그 사실을 솔직히 알려 줍니다. 이해하는 척하지 않습니다. AI로 만든 프로젝트는 프로젝트 관리에서 바로 열 수 있습니다.

친구 휴대폰으로 실시간 미리보기
프로젝트를 빌드하기 전에 친구에게 보여 주려면: 프로젝트 관리에서 프로젝트 이름을 길게 누른 뒤 친구 휴대폰으로 미리보기를 선택하세요. 앱은 프로젝트의 주요 파일(index.html, MainActivity 또는 main.py)과 지침이 담긴 BACA-SAYA.txt, info.txt를 포함한 작은 미리보기 패키지를 만듭니다. 패키지는 ZIP 파일로 WhatsApp 또는 Telegram을 통해 전송됩니다. 받은 친구는 미리보기를 바로 열 수 있습니다. HTML 페이지는 브라우저에서 열리고, Java/Kotlin/Python 코드는 텍스트로 읽힙니다.

프로젝트 마켓
프로젝트 마켓에는 한 번의 탭으로 프로젝트 폴더에 설치할 수 있는 내장 샘플 프로젝트가 있습니다. 계산기, 메모, 할 일 목록, 웹 계산기, 프로필 사이트, 카운터, 디지털 시계, 웹 퀴즈입니다. 온라인 마켓(인터넷에서 샘플 다운로드)은 아직 없으므로, 이 마켓에는 앱 안에 이미 있는 샘플들이 들어 있습니다. 설치된 프로젝트는 직접 만든 프로젝트처럼 프로젝트 관리에서 열고 변경할 수 있습니다.

직접 협업
친구와 함께 프로젝트를 작업하려면: 메인 메뉴에서 협업을 열고, 프로젝트를 선택하고, 변경 메모(무엇이 바뀌었는지)를 작성한 뒤 협업을 위해 공유를 누르세요. 프로젝트는 안에 CATATAN.txt 파일과 함께 ZIP 파일로 전송됩니다. 친구가 작업한 뒤 ZIP 파일을 다시 보내면, 답장 받기를 누르고 먼저 변경 메모를 읽은 뒤, 이전 프로젝트를 덮어쓰려면 적용을 선택하고, 마음이 바뀌면 취소를 선택하세요. CATATAN.txt가 없는 ZIP 파일은 협업 패키지가 아닙니다. 일반 프로젝트 ZIP 파일은 프로젝트 관리의 프로젝트 가져오기를 사용하세요.

자동 앱 번역기
앱 안의 텍스트를 다른 언어로 번역하려면: 메인 메뉴에서 앱 번역기를 열고, 프로젝트와 대상 언어(영어, 아랍어 또는 자바어)를 선택한 뒤 번역을 누르세요. 사전은 이미 휴대폰 안에 있습니다(인터넷 없이, 무료). 일상적인 일반 단어를 포함하고 있습니다. strings.xml, 레이아웃, 코드에서 텍스트를 읽어 번역합니다. 결과는 values-언어/strings.xml 폴더에 기록되고(프로젝트에 strings.xml이 있는 경우), 번역-언어.txt 보고서가 프로젝트 폴더에 만들어집니다. 사전에 아직 없는 단어는 그대로 남겨두고 보고됩니다. 따라서 어떤 단어를 직접 번역해야 하는지 알 수 있습니다.

코드 없는 게임 제작기
코드를 작성하지 않고 게임을 만들려면: 메인 메뉴에서 코드 없는 게임 제작기를 열고, 게임 종류(숫자 맞추기, 퀴즈 또는 별 잡기)를 선택하고, 게임 이름, 수량(레벨/문제/별), 승리 메시지를 입력한 뒤 게임 만들기를 누르세요. 게임은 실제 프로젝트로 만들어지며, 프로젝트 관리에서 바로 실행할 수 있고 다른 프로젝트처럼 APK로 빌드할 수 있습니다.

자동 앱 테스트
프로젝트를 빌드하기 전에 검사하려면: 프로젝트 관리에서 프로젝트 이름을 길게 누른 뒤 자동 테스트를 선택하세요. IDE는 APK를 빌드하지 않고 10가지를 검사합니다. 필수 파일이 있는지(프로젝트 데이터 파일, 매니페스트, 주요 파일, 레이아웃, 문자열), 패키지 이름과 버전, 사용된 권한, 아이콘, 코드 괄호의 균형입니다. 결과는 항목별로 표시되고(통과/실패 및 메시지 포함), Jieshuo가 소리 내어 읽습니다. 먼저 실패한 항목을 모두 수정한 뒤 프로젝트 빌드를 누르세요.

AI 코드 검사기
자주 문제를 일으키는 패턴에 대해 프로젝트 코드를 검사하려면: 메인 메뉴에서 코드 검사를 열고, 프로젝트를 선택한 뒤 코드 검사를 누르세요. 검사기는 휴대폰 안에서 실행되며(인터넷 없이), 사용하지 않는 변수, 빈 함수, 명백히 끝나지 않는 반복, 코드에 직접 작성된 텍스트(strings.xml에 넣는 것이 더 좋습니다), 위험한 권한과 API, TODO/FIXME 표시, 동적 실행을 찾습니다. 각 발견 사항에는 파일 이름, 줄 번호, 수정 제안이 포함됩니다. 이 검사기는 패턴 기반이며, 진짜 AI가 아닙니다. 패턴을 따르지 않는 문제는 여전히 빠져나갈 수 있습니다.

대화형 학습 모드
단계별로 앱 만들기를 배우려면: 메인 메뉴에서 학습을 여세요. 5개의 수업이 있습니다. 첫 프로젝트 만들기, 버튼 추가하기, 색상 변경하기, 소리 추가하기, APK 빌드하기. 수업을 탭하면 설명과 실습 과제를 읽을 수 있습니다. 과제를 수행한 뒤 작업 확인을 누르세요. IDE는 과제가 실제로 수행되었는지 검사합니다(휴대폰의 프로젝트와 APK를 스캔하여). 통과한 수업은 완료로 표시되고 저장됩니다.

클라우드 동기화
프로젝트를 클라우드에 백업하려면: 메인 메뉴에서 클라우드 동기화를 여세요. 로컬 백업은 프로젝트 ZIP 파일을 타임스탬프와 함께 Download/cloud 폴더에 저장하고, 백업 목록에서 언제든지 복원할 수 있습니다. GitHub 백업은 프로젝트 ZIP 파일을 개인 리포지토리에 업로드합니다(GitHub 설정의 토큰 사용). 다시 다운로드할 수 있습니다. 이는 수동 백업과 복원입니다. 완전한 자동 양방향 동기화에는 서버가 필요하므로 아직 사용할 수 없습니다.

자동 백엔드 빌더
서버 코드를 작성하지 않고 백엔드를 만들려면: 메인 메뉴에서 백엔드 빌더를 열고, 백엔드 종류(메모, 할 일 목록 또는 메시지 보드)를 선택하고, 프로젝트 이름을 입력한 뒤 백엔드 만들기를 누르세요. IDE는 양식 페이지와 휴대폰 로컬 저장소(localStorage)에 저장된 데이터 목록을 갖춘 실제 HTML 프로젝트를 만듭니다. 데이터는 저장되고 앱을 실행할 때 다시 읽을 수 있습니다. 이 백엔드는 하나의 휴대폰에서 실행됩니다. 인터넷 서버가 없으므로 두 대의 휴대폰이 아직 같은 데이터를 공유할 수 없습니다.

자동 테마 디자이너
프로젝트에 색상 테마를 적용하려면: 메인 메뉴에서 테마 디자이너를 열고, 프로젝트와 테마(밝음, 어두움, 파랑, 초록, 빨강 또는 보라)를 선택하세요. 미리보기는 테마의 여섯 가지 색상(기본, 어두운 기본, 강조, 배경, 텍스트, 보조 텍스트)을 표시하고 Jieshuo가 소리 내어 읽습니다. 테마 적용을 누르세요. IDE는 colors.xml과 styles.xml(app_theme 스타일)을 프로젝트에 기록하며, 프로젝트를 실행하거나 빌드할 때 바로 사용됩니다.

애니메이션 메이커
프로젝트에 애니메이션을 적용하려면: 메인 메뉴에서 애니메이션 메이커를 열고, 프로젝트, 애니메이션 종류(페이드, 슬라이드, 회전, 바운스 또는 펄스), 지속 시간(100~10000밀리초), 대상(버튼, 텍스트 또는 이미지)을 선택한 뒤 애니메이션 만들기를 누르세요. IDE는 실제 애니메이션 파일을 기록합니다(Java/Kotlin/Compose 프로젝트는 res/anim/anim_<종류>.xml, HTML/웹사이트 프로젝트는 animasi.css). 화면에 표시되는 사용 예제 코드도 함께 제공됩니다.

액션 레코더
작업을 자동으로 반복하려면: IDE는 수행된 동작을 기록합니다(프로젝트 열기, 실행, 빌드, 내보내기, 백업, 프로젝트 만들기, 파일 저장). 메인 메뉴에서 액션 레코더를 열어 기록된 동작 목록과 계획을 확인한 뒤 다시 보기를 누르세요. IDE는 자동화할 수 있는 동작을 다시 실행합니다(백업과 프로젝트 만들기는 그 자리에서 실행, 실행·빌드·내보내기는 해당 메인 화면을 열기, 열기·저장은 편집기를 열기). 자동화할 수 없는 동작은 건너뛰고 마지막에 보고됩니다.

자동 보안
프로젝트의 보안을 검사하려면: 메인 메뉴에서 자동 보안을 열고, 프로젝트를 선택한 뒤 보안 확인을 누르세요. IDE는 8가지를 로컬로 검사합니다(인터넷 없이). 위험한 권한(위치, SMS, 통화, 카메라, 마이크, 연락처), HTTP를 통한 데이터 전송, SMS 전송, 발신 통화, 코드에 직접 작성된 비밀번호나 키, 보호되지 않은 WebView, 권한 없이 내보낸 구성 요소, 암호화되지 않은 http 주소입니다. 각 발견 사항에는 수정 제안과 함께 안전, 경고 또는 위험 수준이 부여되고, 요약은 Jieshuo가 소리 내어 읽습니다.

오프라인 AI
인터넷 없이 텍스트와 코드 도우미 도구를 사용하려면: 메인 메뉴에서 오프라인 AI를 여세요. 4가지 도구가 있습니다. 텍스트 수정(대문자, 구두점, 이중 공백), 텍스트 요약(가장 중요한 3문장 추출), 앱 이름 만들기(작성한 설명에서), 변수 이름 제안(프로젝트에서 1~2자 변수 이름 찾기)입니다. 이는 휴대폰 안의 단순한 규칙이며, 진짜 AI 모델이 아닙니다. 텍스트 수정 결과는 적용 버튼으로 프로젝트의 strings.xml에 적용할 수 있습니다.

위젯 및 배경화면 제작기
홈 화면 위젯을 만들려면: 메인 메뉴에서 위젯 및 배경화면을 열고, 프로젝트를 선택하고, 위젯 텍스트를 입력한 뒤 위젯 만들기를 누르세요. IDE는 WidgetSaya.java, 위젯 레이아웃, 위젯 정보를 기록하고 프로젝트의 AndroidManifest.xml에 리시버를 추가합니다. 프로젝트를 빌드한 뒤 휴대폰 홈 화면에서 위젯을 설치하세요. 배경화면은 글자와 배경 색상 및 텍스트 색상을 입력하고 미리보기를 만든 뒤 PNG 파일로 Download 폴더에 저장하거나 휴대폰 배경화면으로 직접 설정하세요.

소셜 미디어 통합
앱에 공유 버튼을 추가하려면: 메인 메뉴에서 소셜 미디어 통합을 열고, 프로젝트를 선택한 뒤 WhatsApp, Facebook 또는 Telegram 공유를 추가하세요(세 가지 모두 한 번에 가능). IDE는 실제 공유 코드를 프로젝트의 주요 파일(MainActivity 또는 index.html)에 기록합니다. 공유 테스트 버튼은 IDE에서 샘플 텍스트와 함께 공유 선택기를 열므로, 앱을 빌드하기 전에 흐름을 느껴볼 수 있습니다.

이미지로 앱 만들기
이미지로 갤러리 앱을 만들려면: 메인 메뉴에서 이미지로 앱 만들기를 열고, 갤러리에서 이미지를 선택하세요. IDE는 이미지 크기와 지배적인 색상을 분석한 뒤 실제 갤러리 앱 프로젝트를 만듭니다. 이미지는 프로젝트의 assets에 복사되고, 테마 색상은 이미지의 지배적인 색상에서, 앱 이름은 이미지 파일 이름에서 가져옵니다. 프로젝트 관리를 열어 해당 갤러리 앱을 실행하거나 빌드하세요.

대화형 터미널(VT 파서)
터미널에서 대화형 프로그램을 사용하려면: 메인 메뉴에서 터미널을 열고 nano, vim, top 또는 htop을 실행하세요. 터미널은 이제 VT 파서(24행 x 80열 그리드 화면)를 사용하므로 이러한 프로그램이 올바르게 표시됩니다. 커서가 이동하고, 줄이 지워지며, 화면은 실제 터미널처럼 바뀝니다. 대화형 프로그램을 제어하기 위한 전용 Tab, 위쪽 화살표, 아래쪽 화살표, Esc 버튼이 있습니다. 출력은 여전히 Jieshuo가 읽을 수 있는 텍스트입니다. 마지막 줄을 들으려면 화면 읽어 주기를 누르세요.

Terminal Exec (앱 바이너리)
터미널에서 앱 폴더의 바이너리(예: aapt2, ECJ, D8)를 실행하려면: 명령을 평소와 같이 입력하세요. IDE는 libkautsarexec.so를 사용하므로 앱 폴더의 바이너리를 Android 10 이상에서 실행할 수 있습니다. 터미널에서 Exec 테스트를 눌러 이 휴대폰에서 바이너리 exec 경로가 작동하는지 확인하세요. 결과는 그대로 표시됩니다. exec이 시스템에 의해 차단되면 시스템 명령과 셸 스크립트는 여전히 실행됩니다. 바이너리는 프로젝트 빌드 메뉴에서 실행하세요.

터미널 유지 (KeepAlive)
다른 화면으로 이동하는 동안 셸을 계속 실행하려면: 터미널을 열고 명령을 실행한 뒤 뒤로를 누르거나 다른 화면으로 이동하세요. 셸은 종료되지 않습니다. 터미널 알림이 계속 표시되므로 한 번의 탭으로 돌아올 수 있습니다. 실행한 명령은 기록에 저장됩니다(기록 버튼 또는 명령 필드의 위/아래 화살표). 자주 사용하는 명령은 즐겨찾기로 저장할 수 있습니다(즐겨찾기 버튼). 작업이 끝나면 shell 닫기를 눌러 셸을 실제로 종료하세요. 프로젝트 메뉴와 편집기 메뉴에도 터미널에서 빌드 버튼이 있습니다. 터미널은 프로젝트 폴더에서 빌드 명령이 이미 입력된 상태로 열립니다.

터미널 도구 설치 (시험)
아직 시험 중인 기능입니다. 터미널에는 개발자의 alat-termux 리포지토리(github.com/syudat/alat-termux)에 있는 미러에서 Termux 환경을 설치하는 터미널 도구 설치 버튼이 있습니다. 공식 Termux 릴리스에서 가져오는 Termux 설치 버튼 외의 또 다른 경로입니다. 미러 내용은 공식 릴리스와 정확히 동일하며 설치 중에 SHA-256으로 검증됩니다. 환경을 설치한 뒤에는 pkg update와 pkg install 명령을 사용할 수 있으며, 리포지토리의 추가 도구도 터미널에 설치됩니다. 환경 정보를 보는 info-terminal, 캐시를 정리하는 bersih-terminal, 프로젝트 폴더를 날짜가 있는 tar.gz 파일 하나로 보관하는 cadangkan-proyek입니다. 그 후 앱은 기본 Linux 패키지(git, python, curl, wget, nano, openssh, zip, unzip)와 서명이 있는 APK 빌드 도구(openjdk-21, kotlin, gradle, ecj, aapt2, d8, apksigner, clang, cmake, ninja, make)를 공식 Termux 리포지토리에서 자동으로 설치하므로, 터미널은 바로 앱을 빌드할 준비가 됩니다. 큰 패키지를 다운로드하는 데(수백 MB) 시간이 오래 걸릴 수 있습니다. 설치가 진행되는 동안 진행 상황과 명령 출력이 터미널 메인 화면에 표시되고, 최종 결과는 화면 리더가 소리 내어 읽습니다. 패키지 설치가 아직 끝나지 않았으면 터미널 도구 설치를 다시 눌러 계속하세요.

전체 음성 모드
IDE를 음성으로 완전히 제어하려면: 메인 메뉴에서 전체 음성 모드를 열고 듣기 시작을 누르세요. IDE는 계속 듣습니다. 각 명령마다 버튼을 누를 필요가 없습니다. 명령을 실행하고 음성으로 답합니다. 26개의 명령이 있습니다. 만들기, 빌드, 열기, 실행, 나열, 검색, 삭제, 테스트, 검사, 내보내기, 백업, 공유, 아이콘 만들기, 번역, 터미널에서 빌드, 화면 읽기, 모든 화면 열기(보안, 오프라인 AI, 위젯, 소셜 미디어, 게임, 학습, 클라우드, 백엔드, 테마, 애니메이션, 레코더 포함), 뒤로, 닫기, 도움말입니다. 모드를 활성 상태로 두면 이 화면을 다시 열 때 듣기가 자동으로 계속됩니다. 이 모드를 끄려면 듣기 중지를 누르세요. 휴대폰에 음성 인식 서비스가 없어도 명령을 텍스트 상자에 입력할 수 있습니다.

코드 번역기
인터넷 없이 언어 간에 코드를 번역하려면: 메인 메뉴에서 코드 번역기를 열고, 프로젝트를 선택하고, 소스 파일(.java/.kt)을 선택한 뒤 방향을 선택하세요. Java에서 Kotlin으로입니다. 번역을 누르세요. 결과는 번역할 수 없는 줄의 보고서와 함께 표시됩니다(해당 줄은 그대로 유지되고 표시됩니다). 결과 저장을 눌러 같은 폴더에 새 파일(이름-번역.java/.kt)을 기록하세요. 원본 파일은 절대 덮어쓰지 않습니다. 이는 패턴 규칙 번역기이며 컴파일러가 아닙니다. 사용하기 전에 항상 결과를 확인하세요.

앱 내 Git
Termux 없이 IDE 안에서 Git을 사용하려면: 메인 메뉴에서 앱 내 Git을 열고, 프로젝트를 선택한 뒤 Git Repo 만들기를 눌러 해당 프로젝트에 로컬 리포지토리(.git)를 만드세요. 상태 확인을 눌러 마지막 커밋과 비교해 새로 생긴·변경된·삭제된 파일을 확인하세요. 커밋 메시지를 입력한 뒤 Commit을 눌러 프로젝트 스냅샷을 저장하세요. Commit 로그 보기를 눌러 커밋 기록을 확인하세요. GitHub에 Push와 GitHub에서 Pull은 GitHub 토큰을 통한 스냅샷을 사용합니다(pembuat-aplikasi-build 리포지토리). git 프로토콜이 아닙니다. Clone, Push(시스템 git), Pull(시스템 git)은 git 바이너리가 휴대폰에 설치된 경우에만 실행됩니다(일반적으로 없습니다). 이는 완전한 git이 아닙니다. merge, branch, diff가 없습니다. 각 커밋은 프로젝트 전체의 ZIP 스냅샷을 저장합니다.

광고 메이커
빌드된 앱에 광고를 추가하려면: 메인 메뉴에서 광고 메이커를 열고, 프로젝트, 제공업체(AdMob, Unity Ads 또는 AppLovin), 광고 종류(배너, 전면 광고 또는 보상형)를 선택하세요. 이미 가지고 있다면 광고 단위 ID를 입력하세요. 비워 두면 테스트 ID를 사용합니다(AdMob은 Google 공식 테스트 ID 사용, Unity는 샘플 Game ID 사용, AppLovin은 빈칸 사용). 광고 코드 만들기를 눌러 Java와 Kotlin 코드 및 가이드를 확인하세요. 프로젝트에 저장을 눌러 모든 내용을 프로젝트의 광고-<제공업체>-<종류>.txt 파일에 기록하세요. 이는 코드 템플릿 + 가이드이며 광고 SDK가 아닙니다. SDK는 IDE에 포함되어 있지 않습니다. 실제 광고는 제공업체 계정을 만들고, 광고 단위를 만들고, 자신의 단위 ID를 붙여넣고, 프로젝트의 build.gradle에 SDK 종속성을 추가한 뒤에만 표시됩니다.

키즈 모드
아이와 함께 IDE를 사용하려면: 메인 메뉴에서 키즈 모드를 여세요. 화면은 큰 버튼으로 단순화되었고 안전한 동작은 4가지뿐입니다. 프로젝트 만들기(안전한 템플릿에서: 계산기, 숫자 맞추기, 퀴즈, 별 잡기), 프로젝트 열기, 실행, 학습입니다. 이 화면에는 삭제, 내보내기, 백업, 토큰 설정 버튼이 없습니다. 처음 들어갈 때 4자리 PIN을 만드세요. 그 PIN은 부모가 키즈 모드를 종료할 때 사용합니다(어린이 모드 종료 버튼 또는 뒤로 버튼). 이 PIN은 어린아이를 위한 가벼운 보호이며, 진짜 보안이 아닙니다.

Wear OS 및 TV 앱 제작기
시계 앱(Wear OS)이나 TV 앱(Android TV)을 만들려면: 메인 메뉴에서 Wear OS 및 TV를 열고, 대상(Wear OS, Android TV 또는 둘 다)을 선택하세요. 프로젝트 이름을 입력한 뒤 새 Wear/TV 프로젝트 만들기를 누르세요. IDE는 Java 프로젝트를 만들고 조정합니다. 또는 기존 프로젝트를 선택한 뒤 이 프로젝트에 적용을 누르세요. 조정 내용: 매니페스트의 uses-feature, TV용 LEANBACK_LAUNCHER 카테고리 + 배너, 조정된 activity_main.xml 레이아웃(Wear: 작은 화면, TV: D-pad에 적합한 큰 화면)입니다. 전체 설명은 프로젝트의 wear-tv.txt에 기록됩니다. 이는 프로젝트 템플릿입니다. 빌드 + 테스트에는 여전히 Wear OS 또는 Android TV 기기/에뮬레이터가 필요합니다. TV 배너(banner.png 320x180)는 자동으로 만들어지지 않으므로 직접 추가해야 합니다(예: 아이콘 메이커를 통해).

프로젝트 맵
프로젝트 구조를 보려면: 메인 메뉴에서 프로젝트 맵을 열고, 프로젝트를 선택한 뒤 지도 표시를 누르세요. IDE는 폴더와 파일 목록을 크기와 함께 표시하고, 전체 크기, 파일 종류별 크기, 중요한 파일(주요 파일, 매니페스트, 레이아웃, 문자열, 아이콘, 웹 페이지)을 표시합니다. peta-proyek.txt 저장을 눌러 같은 맵을 프로젝트 루트에 기록하세요. bin/ 폴더(빌드 결과)와 .git/ 폴더(로컬 리포지토리)는 내용을 다시 만들 수 있으므로 맵에 포함되지 않습니다.

APK 크기 계산기
빌드하기 전에 빌드된 APK의 크기를 추정하려면: 메인 메뉴에서 APK 크기 계산기를 열고, 프로젝트를 선택한 뒤 예상 계산을 누르세요. IDE는 카테고리별 세부 정보(코드/DEX, 리소스, 에셋, 네이티브 라이브러리, 매니페스트 + resources.arsc, 오버헤드), 전체 예상, 가장 큰 5개 파일, 축소 제안(예: 큰 이미지는 해상도를 낮추고, 큰 소리는 길이를 자름)을 표시합니다. 이는 예상이며 정확한 크기가 아닙니다. 실제 크기는 aapt2 압축, 사용하지 않는 코드 제거(R8), 빌드 결과 리소스로 인해 다를 수 있습니다.

APK 분석기
완성된 APK의 내용을 읽으려면(Android Studio의 APK 분석기처럼): 메인 메뉴에서 APK 분석기를 열고, 프로젝트를 선택한 뒤 빌드 결과 APK 분석을 누르세요. IDE는 해당 프로젝트의 bin 폴더에서 최신 APK를 읽고 패키지 이름, 버전, 최소 및 대상 SDK, 사용된 권한 목록, dex 파일 수, 부분별 크기 세부 정보(프로그램 코드, 리소스, 에셋, 네이티브 라이브러리, 서명), 가장 큰 10개 항목을 보고합니다. APK를 크게 만드는 부분과 빌드된 앱이 사용하는 권한을 아는 데 유용합니다.

화면 크기 미리보기
여러 화면 크기에서 프로젝트의 모양을 한 번에 검사하려면(Android Studio에서처럼): 메인 메뉴에서 화면 크기 미리보기를 열고, 프로젝트를 선택한 뒤 화면 크기 확인을 누르세요. IDE는 프로젝트의 모든 레이아웃을 읽고 너비가 고정으로 작성되고(예: 400dp) 320, 360, 411 또는 480 dp 화면 너비를 초과하는 요소를 보고합니다. 작은 화면의 휴대폰에서는 이러한 요소가 가려지거나 넘칠 수 있기 때문입니다. match_parent 또는 wrap_content 너비의 요소는 화면에 자동으로 적응하므로 검사할 필요가 없습니다.

리소스 관리자
프로젝트의 모든 리소스를 한 곳에서 보고 관리하려면(Android Studio의 리소스 관리자처럼): 메인 메뉴에서 리소스 관리자를 열고, 프로젝트를 선택한 뒤 리소스 보기를 누르세요. IDE는 카테고리별 파일 수와 크기(drawable, layout, values, mipmap 등), strings.xml, colors.xml, styles.xml 내용을 보고합니다. 같은 화면에서 이름과 값을 입력하여 strings.xml에 새 문자열을, colors.xml에 새 색상을 추가할 수 있습니다. 이름이 검사되고 중복은 거부되므로 XML 파일이 손상되지 않습니다.

가벼운 성능 모니터
실행 중인 앱의 RAM과 프로세서 사용량을 모니터링하려면(Android Studio의 Profiler 경량 버전): 메인 메뉴에서 가벼운 성능 모니터를 열고, 먼저 검사할 앱을 실행하세요(예: 시도 중인 빌드된 앱). 패키지 이름을 입력하세요. 또는 프로젝트를 선택한 뒤 프로젝트에서 패키지 이름 입력을 누르세요. 그런 다음 모니터링 시작을 누르세요. IDE는 2초마다 해당 앱의 RAM(PSS)과 CPU를 휴대폰의 빈 RAM과 함께 기록합니다. 중지를 눌러 평균과 최고값 요약을 확인하세요. 추가 권한이 필요 없습니다. 새 Android 버전에서는 다른 앱의 프로세서 읽기 액세스가 시스템에 의해 제한되므로, CPU를 읽을 수 없으면 보고서는 그대로 알려 주고 RAM 모니터링은 계속됩니다.

접근성 감사
출시 전에 프로젝트 레이아웃이 스크린 리더(TalkBack/Jieshuo)에 친화적인지 확인하려면 주 메뉴에서 접근성 감사를 열고 프로젝트를 선택한 뒤 레이아웃 목록 불러오기를 눌러 레이아웃 파일을 선택하세요. IDE는 해당 XML 파일을 읽어 레이블이 없는 버튼과 그 줄 번호, 반복 사용된 레이블, 서로 겹치는 요소를 보고한 뒤 Jieshuo가 읽어 주는 것과 같은 포커스 순서 기록을 만듭니다. 레이블이 없는 버튼이 있으면 레이블을 입력한 뒤 레이블 자동 삽입을 누르세요. 레이블은 contentDescription으로 레이아웃 파일에 기록됩니다. 이 검사는 레이아웃 XML만 읽습니다. Compose 화면과 완성된 APK는 아직 검사하지 않습니다.

크래시 부검
고유 ID가 있는 충돌 로그에서 앱이 스스로 닫히는 이유를 알려면: 기본 메뉴에서 «크래시 부검»을 열고, 로그 목록에서 충돌 ID를 선택한 뒤 «확인»을 누릅니다. IDE는 로그의 클래스와 줄 번호를 프로젝트 소스와 일치시키고 원인을 인도네시아어로 설명합니다(예: 빈 참조, 아직 요청되지 않은 권한, JSON 오류). 코드 패치 제안과 함께 말입니다. «패치 적용»은 소스 줄이 충돌 당시와 여전히 정확히 동일할 때만 누릅니다. 변경된 경우 패치는 거부되고 IDE는 직접 확인하도록 요청합니다. 빌드된 앱의 충돌에 대해서는 «프로젝트에 충돌 캡처 주입»을 누른 뒤 평소대로 APK를 빌드합니다. 해당 빌드된 앱은 자체 충돌을 캡처하고 로그를 전화에 기록합니다. 해당 로그는 «빌드된 앱 충돌 로그 찾기» 버튼으로 찾을 수 있습니다. 정직한 한계: Android 11 이상에서 공개 Download 폴더에 로그를 복사하는 것은 모든 파일 액세스 권한이 없으면 실패할 수 있습니다.

패러다임 간 트랜스파일러
간단한 Java 코드를 Kotlin으로 변환하거나 간단한 XML 레이아웃을 Compose 코드로 변환하려면 주 메뉴에서 패러다임 간 트랜스파일러를 열고 프로젝트와 파일을 선택한 뒤 미리보기를 누르세요. IDE는 변환 결과를 텍스트로 보여줍니다. 먼저 확인하세요. 인식하지 못하는 줄은 그대로 두며, Java의 static이라는 단어는 Kotlin에서 빠집니다(사용하기 전에 의미를 확인하세요). XML에서 Compose로의 변환은 텍스트, 힌트, 방향만 바꿉니다. 크기, 색상, 기타 속성은 아직 포함되지 않습니다. 결과가 올바르면 파일에 적용을 눌러 대상 파일을 쓰세요. 소스 파일은 변경되지 않습니다. 안전하고 일반적인 패턴만 변환됩니다.

로컬 마이크로 서버
인터넷 없이 서버가 필요한 앱을 테스트하려면: 기본 메뉴에서 «로컬 마이크로 서버»를 열고, 경로 정의를 작성한 뒤(예: GET /halo, 그다음 JSON 응답), «서버 시작»을 누릅니다. IDE는 같은 전화에서 작은 HTTP 서버를 실행합니다(HTTP만, TLS 없음, 같은 Wi-Fi 네트워크용). 모든 요청과 응답을 화면에 기록합니다. 경로는 {nama}와 같은 매개변수와 간단한 API 키를 사용할 수 있습니다. 서버는 빌드된 APK에 번들로 넣을 수도 있습니다. «서버를 프로젝트에 번들»을 누르면 서버 소스, 애셋, 매니페스트가 프로젝트에 주입되어 빌드된 앱 자체가 실행될 때 서버가 됩니다. IDE의 서버는 화면이 닫히면 중지됩니다.

보안 감사
출시 전에 프로젝트 코드의 보안 공백을 확인하려면: 기본 메뉴에서 «보안 감사»를 열고, 프로젝트를 선택한 뒤 «검사 시작»을 누릅니다. IDE는 프로젝트 코드, 매니페스트, 구성을 스캔하고 위험이 높은 것부터 낮은 것까지 결과를 보고합니다. 코드에 열린 채로 남겨진 API 키, 권한 없이 노출된 구성 요소, JavaScript 인터페이스와 함께 JavaScript를 활성화하는 WebView, 약한 암호화(MD5, SHA1, DES), TLS가 없는 http 주소, 코드에 직접 작성된 암호입니다. 파일 및 줄 번호와 함께 말입니다. 수정이 안전한 결과(예: MD5를 SHA-256으로 또는 http를 https로 변경)에 대해서는 «수정 적용»을 누릅니다. API 키와 암호에 대해서는 IDE가 수정 제안만 표시합니다. 대체안은 개발자 자신이 결정해야 하기 때문입니다. 스캔은 이제 빌드된 APK 안의 실제 DEX 바이트코드도 분석합니다(코드의 텍스트 패턴만이 아니라). 따라서 호출된 위험한 API와 DEX에 포함된 비밀도 포착됩니다. 패턴을 따르지 않는 공백은 스캔에서 여전히 빠져나갈 수 있습니다. 적용 전에 확인하세요.

인터페이스 테스트 로봇
텍스트 시나리오를 통해 앱 화면을 자동으로 테스트하려면: 기본 메뉴에서 «인터페이스 테스트 로봇»을 열고, 프로젝트를 선택한 뒤 «자동 시나리오 만들기»를 누릅니다. IDE는 프로젝트의 매니페스트와 레이아웃을 읽고 시나리오를 텍스트 단계로 작성합니다(버튼 누르기, 필드 채우기, 기다리기, 돌아가기). 시나리오 실행 로그를 타임스탬프와 함께 보려면 «드라이 런 실행»을 누릅니다. 이 드라이 런은 여전히 순서 시뮬레이션에 불과합니다. 실제 테스트를 하려면 «프로젝트에 테스트 에이전트 주입»을 누릅니다. IDE는 시나리오 애셋과 함께 테스트 에이전트를 프로젝트에 주입합니다. APK를 평소대로 빌드하고 설치한 뒤 «테스트» 아이콘을 엽니다. 해당 에이전트는 빌드된 앱 안에서 실행되며 실제로 버튼을 누르고, 실제 필드를 채우고, 스크롤한 뒤, 캡처한 실제 충돌과 함께 보고서를 화면에 표시합니다. 에이전트를 다시 제거하려면 «프로젝트에서 테스트 에이전트 제거»를 누릅니다. 에이전트는 앱 자체 프로세스 안에서 실행되므로 접근성 서비스나 시스템 자동화가 필요하지 않습니다.

코드 시간 여행
Git 명령을 입력하지 않고 프로젝트를 이전 코드 상태로 되돌리려면 주 메뉴에서 코드 시간 여행을 열고 프로젝트를 선택한 뒤 시점 레이블을 입력하고(비워 둘 수 있음) 시점 기록을 누르세요. IDE는 프로젝트 소스 파일의 복사본을 해시와 함께 프로젝트 안의 .riwayat 폴더에 저장합니다. 시점 목록에 모두 표시됩니다. 두 시점을 선택한 뒤 비교를 눌러 추가, 변경, 삭제된 파일과 함수를 확인하세요. 복원을 눌러 이전 상태로 되돌릴 수 있습니다. 복원하기 전에 IDE는 항상 현재 상태를 먼저 백업하므로 아무것도 잃지 않습니다. 실험 복사본 만들기를 눌러 프로젝트를 새 폴더에 복사하고 원본 프로젝트를 건드리지 않고 변경을 시도하세요. 소스 파일만 기록됩니다.

모듈 팩토리
프로젝트의 일부를 다른 프로젝트에서 사용할 수 있는 모듈로 패키징하려면 주 메뉴에서 모듈 팩토리를 열고 소스 프로젝트를 선택한 뒤 패키징할 화면, 클래스, 문자열, 권한 파일에 체크하고 모듈로 패키징을 누르세요. IDE는 ZIP 아카이브와 JSON 메타데이터(모듈 이름, 버전, 사용된 문자열과 권한)를 작성합니다. 모듈을 다른 프로젝트에 설치하려면 모듈 팩토리를 열고 대상 프로젝트를 선택한 뒤 모듈 설치를 누르고 모듈 .zip 파일을 선택하세요. 병합은 기존 코드를 덮어쓰지 않고 문자열과 권한을 추가하며, 파일 이름이 대상 프로젝트에서 이미 사용 중이면 해당 파일을 병합하지 않습니다. 모듈은 라이브러리나 빌드 설정을 포함하지 않습니다.

다형성 방패 및 애셋 보관소
출시 전에 식별자 이름을 무작위화하고 프로젝트 애셋을 암호화하려면: 기본 메뉴에서 «다형성 방패 및 애셋 보관소»를 열고, 프로젝트를 선택한 뒤 «이름 무작위화 및 애셋 암호화»를 누릅니다. IDE는 소스 코드의 클래스 이름과 메서드 이름을 스캔하고, 무작위 이름 맵을 만들고, 그 이름들을 컴파일된 DEX 파일 안에 다시 씁니다(대체 이름은 모든 오프셋이 유효하게 유지되도록 원래 이름과 같은 길이로 만들어지며, 그 후 DEX 헤더 체크섬과 SHA-1 서명이 다시 계산됩니다). 프로젝트 애셋 파일을 프로젝트 안의 brankas-aset 폴더에 AES-GCM으로 암호화하고, 충돌 로그를 읽을 때 원래 이름을 복원할 수 있도록 암호화된 복구 맵(perisai-peta.brankas)을 저장합니다. 암호화 키는 이제 프로젝트 이름이 아니라 개발자 암호에서 PBKDF2 20,000회 반복으로 유도됩니다. 일반 텍스트, 주석 이름, 디버그 이름으로도 사용되는 이름은 의도적으로 다시 쓰지 않으며, 빌드 경로의 DEX 다시 쓰기 삽입 지점은 아직 실제 전화에서 테스트를 기다리고 있습니다.

신뢰 체인 및 환경 수호자
출시 전에 서명 키 체인과 전화 환경을 확인하려면: 기본 메뉴에서 «신뢰 체인 및 환경 수호자»를 열고, 프로젝트를 선택한 뒤 «체인 및 환경 확인»을 누릅니다. IDE는 프로젝트 패키지 이름에서 5세대 키 체인을 만들고 그 무결성을 확인하며, 메모리 속 코드 섹션 내용을 디스크의 파일과 비교하여 실제 메모리 무결성을 확인하고, 익명의 실행 가능(RWX) 매핑, 외부 라이브러리, memfd 매핑을 보고한 뒤, 자체 프로세스의 메모리 맵과 기기 속성을 Frida, Xposed, 에뮬레이터 흔적에 대해 스캔합니다. 보관소 키는 사용 가능한 경우 하드웨어 보안 칩을 사용하는 AndroidKeyStore의 AES 키로 래핑되며, 키 회전은 이제 스키마 v3 서명 인증서 계보를 사용해 실제입니다. 이전 키가 새 키로의 회전 증거에 서명하고 APK는 그 계보로 다시 서명됩니다. 결과는 텍스트 증거와 함께 «안전», «주의», «위험» 위험 수준입니다. 시스템이 메모리 읽기를 거부하면 검사는 안전이 아닌 «확인 불가»로 보고됩니다. 키가 실제로 하드웨어 보안 칩을 사용하는지는 실제 기기에서만 확인할 수 있습니다.

텍스트 트리 레이아웃 설계자
화면을 보지 않고 설계하려면: 기본 메뉴에서 «텍스트 트리 레이아웃 설계자»를 열고, 프로젝트와 레이아웃 파일을 선택한 뒤 «레이아웃 확인»을 누릅니다. IDE는 XML 레이아웃을 텍스트 트리로 읽고 각 요소의 위치 설명을 소리 내어 읽습니다(예: 오른쪽 아래, 화면 너비의 45퍼센트). 그런 다음 요소 간의 겹침과 360dp 너비에서 화면 밖으로 나가는 요소를 수학적으로 보고합니다. 이제 계산되는 것에는 LinearLayout과 단순한 dp 크기, 전체 ConstraintLayout(모든 제약, 편향, 체인, 가이드라인, 장벽, 백분율 너비, 0dp match_constraint, 치수 비율), Compose 화면(크기 수정자와 함께하는 Column, Row, Box)이 포함됩니다. 실행 중에 변경되는 MotionLayout과 ConstraintSet만 위치를 알 수 없음으로 계속 보고됩니다. 그 값은 앱이 실행 중일 때만 존재하기 때문입니다.

디자인 시스템 스튜디오
모든 화면과 프로젝트에서 간격, 글꼴, 모서리를 통일하려면: 기본 메뉴에서 «디자인 시스템 스튜디오»를 열고, 프로젝트를 선택하고, 디자인 토큰을 작성한 뒤(예: jarak=8, huruf=16, sudut=12), 컴포넌트를 선택하고 «컴포넌트 생성»을 누릅니다. IDE는 토큰을 검증합니다. 기본 간격 4~16dp, 기본 글꼴 12~20sp, 모서리 0~32dp, 최소 터치 영역 48dp입니다. 그런 다음 바로 사용할 수 있는 XML 컴포넌트(komponen-studio.xml)를 XML 테마(tema-studio.xml) 및 Compose 테마(tema-studio.kt)와 함께 프로젝트 폴더에 씁니다. 토큰은 프로젝트 간에 공유되는 토큰 라이브러리에 이름 있는 집합으로 저장할 수도 있으며, 하나의 동기화 명령이 라이브러리의 최신 토큰을 해당 집합을 사용하는 모든 프로젝트에 적용합니다. 컴포넌트는 레이아웃에 붙여넣은 뒤 «텍스트 트리 레이아웃 설계자»로 확인하는 텍스트로 만들어집니다. 태블릿의 두 열 조정은 실행 시 기기 감지가 아니라 화면 너비 한정자를 사용합니다.

의미적 리팩터링 및 AST 탐색
정의를 찾고 우연히 같은 이름을 가진 다른 코드를 손상시키지 않고 기호 이름을 바꾸려면: 기본 메뉴에서 «의미적 리팩터링 및 AST 탐색»을 열고, 프로젝트를 선택한 뒤 «프로젝트 기호 스캔»을 눌러 모든 클래스와 메서드를 파일 및 줄 번호와 함께 봅니다. 기호 이름을 입력한 뒤 «프로젝트 기호 스캔»을 다시 눌러 그 정의와 그것을 호출하는 모든 파일을 봅니다. 이름을 바꾸려면 새 이름을 입력하고, «이름 변경 미리 보기»를 눌러 각 파일의 발생 횟수를 확인한 뒤 «이름 변경 적용»을 누릅니다. 인덱서는 이제 직접 만든 AST 파서(Java 및 Kotlin 하위 집합용 렉서와 재귀 파서)를 사용하므로 파일 간 메서드 이름 변경이 해결되고 다른 파일의 호출자도 변경됩니다. 코드 블록을 새 함수로 추출하는 버튼이 이제 이 화면에 있습니다. 이 파서는 아직 최소 수준입니다. 매우 복잡한 제네릭, 매개변수가 있는 주석, 익명 클래스는 있는 그대로 스캔되며, 리플렉션과 인터페이스를 통한 호출은 해결되지 않습니다.

단계별 디버거 및 메모리 검사기
로그에서 추측하지 않고 프로그램 흐름 중간에 변수 내용을 검사하려면: 기본 메뉴에서 «단계별 디버거 및 메모리 검사기»를 열고, 프로젝트를 선택하고, 실행 추적을 작성합니다(줄당 한 단계, 형식: 줄 번호, 코드, 그다음 |로 구분된 변수와 값, 예: 10|int total = harga * jumlah;|harga=5000, jumlah=3, total=15000). 중단점 줄 번호를 입력한 뒤 «디버그 추적 실행»을 누릅니다. IDE는 첫 번째 중단점까지 실행하고 Jieshuo를 통해 활성 줄을 변수 값과 함께 소리 내어 읽습니다. «한 줄씩 이동»을 눌러 한 줄 앞으로 이동하고, «함수로 들어가기»를 눌러 호출된 함수로 들어갑니다(호출 스택 포함). «프로그램 계속»을 눌러 다음 중단점으로 이동합니다. 이 추적 디버거는 여전히 기록되거나 손으로 작성된 추적을 따릅니다. 그 옆에는 순수 Java JDWP 와이어 프로토콜 클라이언트가 있어 핸드셰이크, 중단점 설정, 안으로/위로/밖으로 단계 이동이 가능하고, TCP 또는 수신 모드로 VM을 일시 중지하고 계속할 수 있습니다. 일반 앱 내부에서 실제 프로세스를 중지하는 것은 아직 완전히 불가능합니다. 프로세스의 JDWP 소켓은 adbd를 통해서만 노출되기 때문입니다. 검증된 경로는 무선 디버깅과 셸을 통한 대상 실행이 필요하며, 앱 자체가 할 수 있는 범위를 벗어납니다.

오프라인 종속성 관리자
인터넷 없이 타사 라이브러리를 사용하고 빌드 전에 버전 충돌을 피하려면: 기본 메뉴에서 «오프라인 종속성 관리자»를 열고, 프로젝트를 선택한 뒤 «종속성 확인»을 누릅니다. IDE는 프로젝트의 모든 .gradle 파일을 읽고, Download/brankas-bersama 폴더의 프로젝트 간 공유 보관소를 확인하며, 충돌을 해결합니다. 두 라이브러리가 같은 아티팩트의 서로 다른 버전을 요청하면 가장 높은 버전이 사용되고 충돌이 보고됩니다. 라이브러리를 다운로드하려면 해당 좌표를 입력합니다(형식: 그룹:아티팩트:버전, 예: com.google.code.gson:gson:2.10.1). 그런 다음 «종속성 확인»을 누릅니다. 온라인 상태에서는 AAR, JAR, WHL 파일이 실제로 Maven, Google, PyPI에서 전이 종속성 그래프와 함께 다운로드됩니다(재귀적, 사이클은 끊김, 깊이 최대 25단계). 성공적으로 다운로드된 파일만 사용 가능으로 기록됩니다. 오프라인 상태에서는 공유 보관소에 이미 있는 라이브러리만 사용할 수 있습니다. Maven 버전 범위는 해결되지 않으며, 다운로드된 파일은 SHA-1으로만 확인되고 PGP 검증은 없습니다.

데이터베이스 및 저장소 검사기
테이블 내용을 인쇄하는 코드를 작성하지 않고 프로젝트 데이터베이스 내용을 검사하고 테스트하려면: 기본 메뉴에서 «데이터베이스 및 저장소 검사기»를 열고, 프로젝트와 데이터베이스 파일(.db, .sqlite, .sqlite3)을 선택한 뒤 «데이터베이스 열기»를 누릅니다. IDE는 완전한 SQLite 페이지 파서(오버플로 페이지가 있는 B-트리)로 모든 테이블의 스키마를 읽고 처음 20개 행을 Jieshuo가 소리 내어 읽는 텍스트 표로 표시합니다. SELECT 쿼리를 작성한 뒤 «쿼리 실행»을 누릅니다(예: SELECT nama FROM pengguna WHERE kota = 'Makassar'). 쿼리는 이제 JOIN, GROUP BY, ORDER BY, LIKE를 지원하며, 전화에서는 실제 Android SQLite 엔진으로 실행됩니다. 값을 변경하려면 행 번호(1 = 첫 번째 행), 열 이름, 새 값을 입력한 뒤 «셀 값 변경»을 누릅니다. 해당 값이 .db 파일에 다시 기록됩니다. «백업 저장»을 누르면 테이블의 현재 상태가 프로젝트에 <데이터베이스 이름>.cadangan.txt 파일로 저장됩니다. SharedPreferences와 DataStore도 읽을 수 있습니다. 아직 읽을 수 없는 것: 암호화된 데이터베이스, 커밋되지 않은 WAL 변경, 특수 DataStore Proto의 형식화된 값(일반 필드 보기로만 표시됨).

단위 테스트 팩토리 및 퍼징
앱을 공유하기 전에 논리 공백을 찾으려면: 기본 메뉴에서 «단위 테스트 팩토리 및 퍼징»을 열고, 프로젝트와 코드 파일을 선택한 뒤 «테스트 만들기 및 실행»을 누릅니다. IDE는 파일의 함수 시그니처를 읽고 일반 및 경계 테스트 케이스를 만듭니다(빈 텍스트, null, 최대 숫자, 이상한 문자). 그런 다음 실제로 해당 테스트를 실행합니다. 프로젝트 코드가 컴파일되고 각 @Test 메서드가 5초 제한으로 실행되므로 결과는 실제 값과 함께 실제 통과와 실패입니다. 퍼징도 프로젝트 함수에 대해 실제로 실행됩니다(리플렉션 경유, 호출당 2초, 최대 20개 메서드). 줄 적용 범위는 원래 줄 번호를 유지하는 계측을 통해 실제로 계산됩니다. 결과는 몇 개의 테스트가 통과하고 실패했는지, 몇 줄의 코드와 함수가 발견되었는지, 어떤 테스트 케이스가 만들어졌는지를 보고합니다. 만들어진 테스트는 JUnit과 정확히 동일한 API를 사용하지만, 주석 및 어설션 정의는 만들어진 테스트 파일 자체 안에 작성됩니다. 실제 JUnit 라이브러리는 앱에 포함되지 않았기 때문입니다.

극단적 기기 조건 시뮬레이터 및 메모리 누수 감사자
시스템이 프로세스를 종료하거나, 네트워크가 끊기거나, 화면이 회전하거나, 배터리 절약이 켜질 때 앱의 내구성을 테스트하려면: 기본 메뉴에서 «극단적 기기 조건 시뮬레이터 및 메모리 누수 감사자»를 열고, 프로젝트를 선택한 뒤 «시뮬레이션 실행»을 누릅니다. IDE는 화면 회전 시뮬레이션과 함께 세 가지 스트레스 시나리오를 실행하고 화면이 닫힌 후에도 메모리에 남아 있는 개체를 추적한 뒤, 손실된 데이터와 누수되는 개체 체인을 보고합니다. 저장 및 복원 상태는 이제 고정된 예가 아니라 사용자 자신의 프로젝트 소스에서 읽습니다. 로컬 루프백 서버는 네트워크 중단을 측정하기 위해 테스트 중간에 실제로 중지됩니다. 실제 힙 덤프를 가져와 분석하고, 두 덤프를 비교하며, GC 루트에서 유지 체인을 추적합니다. 앱 자체 프로세스는 상태를 저장한 뒤 실제로 종료되고, 다시 열었을 때 어떤 데이터가 돌아오는지 확인합니다. 일반 앱에서 여전히 불가능한 것: 전화 라디오나 Wi-Fi를 끄는 것과 다른 앱을 강제 종료하는 것입니다. 둘 다 시스템 권한이 필요합니다. 대신 백그라운드 앱은 권한이 이미 매니페스트에 있는 killBackgroundProcesses로 종료되며, 화면에 정직한 레이블이 있습니다.

프로젝트 청사진 설계자
큰 앱 아이디어를 단계별 작업 계획으로 바꾸려면: 기본 메뉴에서 «프로젝트 청사진 설계자»를 열고, 프로젝트를 선택하고, 앱 아이디어를 작성한 뒤(예: 할부가 있는 작은 식료품점 계산원 앱), «청사진 만들기»를 누릅니다. IDE는 모듈, 파일 목록, 작은 마일스톤을 만들고 이를 프로젝트 폴더에 cetak-biru.txt로 저장합니다. 마일스톤이 완료될 때마다 «다음 마일스톤 완료로 표시»를 누르거나, 저장된 청사진을 다시 열려면 «저장된 청사진 불러오기»를 누릅니다. «AI 설정»에서 활성 AI 공급자가 선택되고 그 키가 사용 가능하면 청사진은 해당 공급자가 만듭니다. 키가 없거나 공급자에 도달할 수 없으면 IDE는 오프라인 키워드 패턴으로 돌아가고 그 한계를 정직하게 말합니다. 공급자 답변은 형식에 대해서만 확인됩니다(모듈과 마일스톤이 존재하는지). 내용의 정확성에 대해서는 확인되지 않습니다. 빌드 전에 항상 청사진을 검토하세요.

코드 논리 흐름 내레이터
구문을 줄마다 듣지 않고 긴 코드를 이해하려면: 기본 메뉴에서 «코드 논리 흐름 내레이터»를 열고, 프로젝트와 코드 파일을 선택한 뒤 «코드 설명»을 누릅니다. IDE는 각 줄을 인도네시아어 문장으로 변환합니다(예: 합계가 100000보다 크면 다음 블록을 실행합니다). 메서드 간 호출 맵과 메서드 간 데이터 흐름 분석(전달된 값, 사용된 값, 무시된 값)을 표시하고, 미묘한 잠재적 버그를 줄 번호와 함께 표시합니다. ==로 비교된 String, 닫지 않고 열린 스트림, 두 개의 서로 다른 메서드에 쓰인 변수입니다. «AI 설정»에서 활성 AI 공급자가 선택되면 해당 공급자의 흐름 요약도 사용할 수 있습니다. 사용할 수 없으면 화면은 오프라인 설명을 사용하고 그 한계를 말합니다. 설명, 호출 맵, 데이터 흐름은 오프라인 텍스트 패턴 분석을 사용하며, 완전한 AST 파서가 아닙니다. 여는 중괄호가 자체 줄에 있는 메서드, 클래스 필드, 리플렉션을 통한 호출은 추적되지 않습니다. 데이터 경쟁 경고는 실제로 번갈아 가며만 사용되는 변수에 대해 나타날 수 있습니다.

앱 번들 팩토리 및 Play 스토어 준비 상태
전화에서 직접 Google Play 스토어용 앱을 준비하려면: 기본 메뉴에서 «앱 번들 팩토리 및 Play 스토어 준비 상태»를 열고, 프로젝트를 선택한 뒤 «AAB 번들 만들기»를 누릅니다. IDE는 실제 BundleConfig.pb와 함께 프로젝트의 매니페스트, 리소스, 애셋에서 .aab 파일을 만들고, 번들 구조를 검증한 뒤, 번들을 실제 변형 APK(기본, 아키텍처별, 언어별, 범용)로 나눕니다. 크기는 해당 분할에서 측정된 것이며, 추정이 아닙니다. 번들은 APK 서명에 사용된 것과 동일한 프로젝트 키로 JAR v1로 서명되며, 그 서명 체인은 암호학적으로 검증됩니다. 이 화면은 Play 준비 상태도 감사합니다. 대상 SDK가 35 미만이면 Play 스토어가 35 이상을 요구하므로 «높음»으로 표시되고, 누락된 64비트 라이브러리도 «높음»으로 표시됩니다. 실제 bundletool은 기기에서 실행할 수 없습니다. bundletool은 JVM이 필요한 반면 Android에는 JVM이 없기 때문입니다. 위의 경로가 기기에서 가장 가까운 실제 경로입니다.

OTA 업데이트 엔진 및 단계적 출시
사용자에게 전체 APK를 다시 다운로드하도록 강요하지 않고 작은 수정을 보내려면: 기본 메뉴에서 «OTA 업데이트 엔진 및 단계적 출시»를 열고, 프로젝트를 선택하고, 이전 버전과 새 버전의 내용을 작성한 뒤 «패치 패키지 만들기»를 누릅니다. IDE는 차이를 계산하고 새 내용의 SHA-256 지문과 함께 패치 패키지(patch-ota.zip)를 만들고, 이 기기가 첫 10퍼센트 출시 단계에 있는지 확인합니다. 패치는 이제 모든 파일에 대해 이진 델타를 지원하며(DEX 및 APK 포함), RSA-2048 서명으로 패키징되고 적용 전에 신뢰할 수 있는 공개 키로 검증되며, 개발자 서버에서 출시 목록과 함께 다운로드할 수 있습니다. 적용에 실패하면 이전 파일은 그대로 남아 있습니다. 실행 중인 앱에 패치를 적용하는 것은 프로젝트 키로 다시 서명하고 PackageInstaller를 통해 수행됩니다. 실행 중인 프로세스의 코드를 그 내부에서 교체하는 것은 불가능하기 때문입니다. APK는 잠겨 있고 DEX는 이미 로드되어 있습니다.

팀 코드 리뷰 스튜디오
동료의 변경을 검토하고 Git 화살표 표시를 읽지 않고 병합 충돌을 해결하려면: 기본 메뉴에서 «팀 코드 리뷰 스튜디오»를 열고, 프로젝트를 선택하고, 세 가지 텍스트 버전(기본, 로컬, 동료)을 입력한 뒤 «팀 리뷰 열기»를 누릅니다. IDE는 Java 구문 단위를 기준으로 세 가지를 병합합니다. 같은 줄의 두 변경이지만 서로 다른 문장에 있는 경우 더 이상 충돌로 간주되지 않습니다. 각 충돌을 투표 선택으로 표시합니다. 로컬 버전 사용, 동료 버전 사용, 또는 둘 다 병합. 결과 줄은 순서가 올바르게 유지되도록 원래 충돌 위치에 삽입되고, 결과는 프로젝트의 gabung-hasil.txt에 기록됩니다. 아래에는 프로젝트 작업 보드가 있습니다. 작업 제목을 입력한 뒤 «작업 추가»를 누릅니다. 작업은 프로젝트 안의 .tugas 폴더에 텍스트로 저장되고 앱 내 Git의 커밋을 통해 동기화되므로, 보드는 어떤 커밋 기록에서도 다시 읽을 수 있습니다. 이 구문 분할기는 완전한 AST 파서가 아니며, 앱 내 Git은 각 커밋마다 전체 스냅샷을 저장합니다. 전용 동기화 서버는 없습니다.

코드 구조 받아쓰기
편집기 안에서 음성으로 코드를 작성하려면 편집기에서 프로젝트를 연 뒤 코드 구조 받아쓰기 버튼을 누르세요. 인도네시아어로 명령을 말하세요. 예를 들어 buat fungsi tambah dengan parameter a angka dan b angka, buat kelas Mobil, buat variabel teks nama sama dengan Budi. IDE는 음성을 문법적으로 올바른 Java, Kotlin, Python 또는 Compose 코드 블록으로 변환하여 커서 위치에 삽입한 뒤 Jieshuo를 통해 짧은 요약을 읽어 줍니다. 받아쓰기는 시스템에 내장된 음성 입력 서비스를 사용하며 추가 마이크 권한이 필요 없고, 이미 등록된 명령 패턴만 인식합니다. 패턴 밖의 음성은 코드로 변환되지 않습니다. 단어로 말한 숫자(예: 'lima')는 아직 숫자로 변환되지 않습니다.

로컬 협업 공간(인터넷 없음)
인터넷 없이 한 방에서 함께 작업하려면 주 메뉴에서 협업을 열고 로컬 협업 공간 섹션을 여세요. 한 휴대폰이 세션을 엽니다(IDE에 로컬 IP 주소와 6자리 PIN이 표시됩니다). 다른 휴대폰이 해당 주소와 PIN으로 참여합니다. 텍스트 변경은 줄 차이로 전송되고, 빌드된 APK를 테스터의 휴대폰으로 보낼 수 있으며, 테스터 휴대폰의 충돌 보고서도 다시 받아볼 수 있습니다. 한 세션은 한 친구 전용입니다. 두 사람이 정확히 같은 줄을 동시에 변경하면 마지막 변경이 사용됩니다. PIN은 로컬 네트워크에서 일반 텍스트로 전송됩니다. 이 공간은 아직 실제 휴대폰에서 테스트되지 않았습니다.

AI 설정
앱을 만들기 위한 AI 공급자와 API 키를 설정하려면: 기본 메뉴의 설정 그룹에서 «AI 설정»을 누릅니다(«커넥터» 버튼 옆). 사용할 공급자를 사용 가능한 목록에서 선택하고, 하나의 모델이 실패하면 IDE가 같은 공급자의 다음 모델을 자동으로 시도하도록 «프로바이더 오류 시 모델 전환»을 선택합니다. 백업 키를 추가하려면 «API 키 관리»를 누릅니다(이름과 키를 입력한 뒤 «저장»을 누릅니다. 키는 마스킹되어 표시되며 마지막 4자만 보입니다). 키는 전화에 저장되며 앱을 만들 때 선택된 공급자 외에는 어디에도 전송되지 않습니다. 선택된 공급자는 이제 «프로젝트 청사진 설계자»와 «코드 논리 흐름 내레이터»가 실제로 사용합니다. «AI로 앱 만들기» 화면에서 앱을 만드는 것은 여전히 전화의 로컬 AI를 사용합니다(인터넷 없음).

커넥터
APK를 분석한 뒤 보내려면 주 메뉴의 설정 그룹에서 커넥터(AI 설정 버튼 옆)를 누르세요. 휴대폰에서 APK 파일을 선택하면 IDE가 그 내용(패키지 이름, 버전, 액티비티 목록)을 읽은 뒤 APK 보내기를 눌러 시스템 공유 메뉴(예: WhatsApp 또는 Drive)로 보냅니다.

언어 및 음성
앱 언어를 변경하려면 설정을 열고 앱 언어를 연 뒤 언어 또는 시스템 설정 따르기를 선택하세요. 주 화면과 대부분의 화면은 앱을 닫거나 다시 시작하지 않아도 선택한 언어로 즉시 바뀝니다. 일부 화면(예: 터미널, 협업, AI 설정, 키 관리)은 다시 열 때까지 이전 언어를 계속 사용합니다. 시스템 설정 따르기를 선택하면 언어는 휴대폰 시스템 언어를 따릅니다.

프로젝트별 기본 서명 및 변조 방지
버전 5.7부터 개인 서명을 사용하지 않는 프로젝트는 해당 프로젝트 전용 내장 키로 서명됩니다(프로젝트 안의 tanda-tangan-bawaan 폴더에 한 번 만들어진 뒤 계속 사용됨). 따라서 내장 서명은 프로젝트마다 다릅니다. 이제 모든 앱에 하나의 공통 키를 사용하지 않습니다. tanda-tangan-bawaan 폴더를 삭제하지 마세요. 해당 키가 없으면 새 APK가 같은 프로젝트의 이전 APK를 덮어쓸 수 없습니다. 각 프로젝트의 설정(분리 아키텍처, 개인 서명, 변조 방지, 선택한 keystore, SDK)은 이제 프로젝트 안의 settings.gradle 파일에 저장되고 프로젝트가 빌드될 때마다 다시 읽힙니다. 설정의 서명 카테고리에 빌드된 앱 변조 방지 확인란이 있습니다. 활성화되면 기기의 빌드된 앱은 열릴 때마다 자신의 서명과 dex 내용을 검사합니다. 다시 서명되었거나 다른 사람이 변경하면 앱은 실행을 거부합니다. Frida/Xposed와 같은 디버거와 주입 도구도 감지되며, 앱 창은 화면 녹화로부터 잠깁니다.

데모 동영상 메이커
빌드된 앱의 데모 동영상을 만들려면: 메인 메뉴에서 데모 동영상 메이커를 열고, 프로젝트를 선택하고, 동영상 제목을 입력한 뒤 데모 비디오 스크립트 만들기를 누르세요. IDE는 내레이션 텍스트와 각 장면의 길이를 포함한 5개의 표준 장면(오프닝, 메인 화면, 기능 1, 기능 2, 엔딩)이 담긴 video-demo.txt를 기록합니다. HTML 슬라이드쇼 만들기를 눌러 프로젝트 이미지(아이콘 + 있는 경우 스크린샷)로 5초마다 자동으로 바뀌는 video-demo.html을 만드세요. 이는 .mp4 동영상이 아닙니다. 실제 동영상을 만들려면 휴대폰 브라우저에서 video-demo.html을 열고 화면을 녹화하거나, 실행 중인 앱을 녹화하면서 video-demo.txt의 내레이션을 읽으세요.

Android Studio 스타일의 새로운 화면
IDE의 모양은 이제 Android Studio처럼 깔끔하게 정리되었습니다(모양만 그렇습니다. 모든 버튼, 메뉴, 흐름은 이전과 정확히 동일합니다). 밝은 회색 배경, 굵은 검은색 화면 제목, 흰색 텍스트의 파란색 버튼, 얇은 테두리의 흰색 입력 상자입니다. 메인 메뉴는 버튼 순서를 바꾸지 않고 시각적으로 그룹화되었습니다(빌더 기능, 클라우드, 테마 및 기타, 음성, 코드 및 새 기능, 도구). 터미널은 여전히 Android Studio의 터미널 창 같은 어두운 패널을 사용하고, 코드 편집기는 여전히 흰색 배경과 검은색 텍스트를 유지합니다. 모든 텍스트는 Jieshuo로 여전히 명확하게 읽힙니다.

설정
앱을 설정하려면: 메인 화면에서 옵션 메뉴를 열고 설정을 누르세요. 안에는 12개의 카테고리가 있습니다. GitHub 설정(보안, 개인 서명, 빌드 기록, GitHub 토큰), 기기에서 APK 빌드 설정(keystore 비밀번호와 빌드 기록을 기기에 저장), 테마(앱 색상), 서명(개인 서명용 keystore 만들기 및 빌드된 앱 변조 방지 확인란), 프로젝트 폴더(프로젝트 폴더 위치), 언어 및 음성(인터페이스 언어와 음성 모드 말하기 속도), 텍스트 크기와 표시(편집기 글꼴 크기), 빌드(프로젝트 만들기 화면의 기본 대상 SDK와 기본 아키텍처 분리), 알림(빌드 완료 시 소리), 자동 백업(프로젝트 백업 일정), 개발자 프로필(기부 화면에 표시되는 이름, WhatsApp 번호, 계좌), 개인정보 및 데이터(설정 초기화 및 앱 데이터 삭제)입니다. 각 카테고리에는 카테고리 메뉴로 돌아가기 위한 이전으로 돌아가기 버튼이 있습니다. 새로 저장된(아직 적용되지 않은) 설정은 화면에 솔직하게 설명이 적혀 있습니다.

개발자에게 기부
기부하거나 개발자에게 인사하려면: 메인 화면의 도구 정보 버튼 옆에 있는 개발자에게 기부 버튼을 누르세요. 기부 화면에는 BRI 계좌 복사 버튼이 있습니다. 개발자의 계좌 번호를 복사하려면 누른 뒤 은행 앱에 붙여넣으세요. WhatsApp으로 개발자에게 인사하기 섹션도 있습니다. 이름과 고향을 입력한 뒤 WhatsApp으로 보내기를 누르세요. WhatsApp이 인사 메시지가 미리 입력된 상태로 열립니다. WhatsApp에서 보내기를 누른 뒤 앱으로 돌아오세요. WhatsApp은 다른 앱이 자동으로 메시지를 보내는 것을 허용하지 않으므로, 전송은 WhatsApp 안에서 직접 해야 합니다.

터미널 즐겨찾기 명령
터미널에서 자주 사용하는 명령을 저장하려면: 터미널을 열고 즐겨찾기를 누르세요. 새 즐겨찾기 추가를 탭하고 이름(예: 파일 보기)과 명령(예: ls -la)을 입력한 뒤 저장을 누르세요. 즐겨찾기는 휴대폰에 영구적으로 저장됩니다. 즐겨찾기 이름을 탭하면 터미널에서 바로 실행됩니다. 즐겨찾기 삭제를 탭한 뒤 삭제할 항목을 하나 선택하세요(확인 포함). 이미 3개의 내장 즐겨찾기가 있습니다. 파일 보기(ls -la), 공간 확인(df -h), 화면 지우기(clear)입니다. 모두 삭제할 수 있습니다. 빈 명령은 저장하거나 실행할 수 없습니다. 그런 경우 터미널이 메시지와 음성으로 알려 줍니다.

분석 및 품질
앱 사용 요약과 충돌 보고서를 보려면: 메인 화면에서 개발자에게 기부 버튼 옆에 있는 분석 및 품질 버튼을 누르세요. 이 화면은 앱이 열린 횟수, 가장 자주 열린 화면, 충돌 횟수, 짧은 수정 제안이 포함된 최근 충돌 목록을 표시합니다. 이 데이터는 휴대폰에만 저장되며 어디에도 전송되지 않습니다. 모든 데이터를 삭제하기 위한 확인 대화 상자가 있는 분석 데이터 삭제 버튼이 있습니다. 마지막 화면은 메인 화면과 이 화면에 대해서만 기록됩니다.
