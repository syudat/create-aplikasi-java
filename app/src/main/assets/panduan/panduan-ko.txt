Create Aplikasi by Al Kautsar에 오신 것을 환영합니다
Create Aplikasi는 노트북 없이 휴대폰에서 바로 실행되는 Android 앱 제작 애플리케이션입니다. 이 앱을 사용하면 앱 만들기를 처음 배우는 사용자와 화면 낭독기 사용자를 포함해 누구나 자신만의 Android 앱을 만들 수 있습니다. 이 앱의 전체 사용 안내는 이 Tentang Alat(도구 정보) 화면에서 볼 수 있습니다.

이 앱은 무엇이며 누구를 위한 것인가
Create Aplikasi는 휴대폰에서 실행되는 Android 앱 제작 도구입니다. 이 앱은 초보자와 화면 낭독기 사용자를 포함해 자신만의 Android 앱을 만들고 싶은 모든 사람을 위한 것입니다. 이 앱은 코드 편집기, 프로젝트를 테스트하는 Jalankan(실행) 버튼, APK를 만드는 Bangun(빌드) 버튼, 그리고 APK에 서명하고 설치하는 메뉴를 제공합니다.

이 앱의 목적
이 앱은 누구나 휴대폰에서 바로, 쉽게 자신만의 Android 앱을 만들 수 있도록 만들어졌습니다. 화면은 최대한 단순하게 만들어져 있어 처음 사용하는 사용자도 바로 시도해 볼 수 있습니다.

새 프로젝트를 만드는 방법, 단계별 안내
1. 메인 메뉴에서 Buat Project(프로젝트 만들기)를 누릅니다.
2. 프로젝트 종류를 선택합니다: HTML, Situs Web(웹사이트), Java, Kotlin, Compose 또는 Python.
3. 앱 이름을 입력합니다. 예: Garuda Decode.
4. 패키지 이름(package name)을 입력합니다. 예: com.android.garudadecode. 패키지 이름은 소문자를 사용해야 하며 마침표로 구분된 최소 두 부분으로 이루어져야 합니다.
5. 앱 버전을 입력합니다. 예: 1.0, 그리고 숫자로 된 버전 코드를 입력합니다. 예: 1. 비워 두면 버전은 자동으로 1.0, 버전 코드는 1로 채워집니다.
6. 필요하면 최소 SDK와 대상 SDK를 입력합니다. 비워 두면 기본값이 사용됩니다. 최소 SDK는 지원되는 가장 낮은 Android 버전입니다. 예: 21은 Android 5.0을 뜻합니다. 대상 SDK의 최대값은 36(Android 16)입니다.
7. Pilih Izin(권한 선택) 버튼을 눌러 앱 권한을 선택합니다. 예: INTERNET. INTERNET 권한은 기본으로 선택되어 있습니다. 앱에 실제로 필요한 권한만 선택하십시오.
8. 원한다면 "Gunakan arsitektur terpisah 64 bit dan 32 bit"(64비트와 32비트 분리 아키텍처 사용)에 체크하면 APK 크기가 더 작아지고, 직접 만든 keystore를 쓰고 싶다면 "Gunakan tanda tangan pribadi"(개인 서명 사용)에 체크합니다.
9. Buat Proyek(프로젝트 만들기)를 누릅니다. 새 프로젝트는 Download/project 폴더에 저장되고 Kelola Project(프로젝트 관리)에 바로 나타납니다.

사용할 수 있는 프로젝트 종류
• HTML: index.html, style.css, script.js로 이루어진 화면이 WebView를 통해 실행됩니다. 휴대폰에서 바로 빌드됩니다.
• Situs Web: index.html, tentang.html, kontak.html, style.css, script.js로 이루어진 메뉴(Beranda(홈), Tentang(정보), Kontak(연락처))가 있는 웹사이트가 WebView를 통해 실행됩니다. 휴대폰에서 바로 빌드됩니다.
• Java: 휴대폰에서 빌드됩니다. MainActivity는 app/src/main/java/<nama-paket>/MainActivity.java에 있습니다. 화면은 app/src/main/res/layout/activity_main.xml에서, 텍스트는 app/src/main/res/values/strings.xml에서, 테마는 app/src/main/res/values/styles.xml에서 가져옵니다.
• Kotlin: 앱에 포함된 Kotlin 컴파일러를 사용해 기기에서(오프라인으로) 빌드하거나 GitHub Actions를 통해 빌드할 수 있습니다. MainActivity는 app/src/main/java/<nama-paket>/MainActivity.kt에 있고, res 파일은 Java 프로젝트와 같습니다. 첫 Kotlin 빌드는 컴파일러 크기가 커서 더 느리고, Kotlin 클래스를 참조하는 .java 파일은 아직 빌드할 수 없습니다(.java 파일이 .kt 파일보다 먼저 컴파일됩니다).
• Compose: Jetpack Compose(XML 레이아웃이 아님)로 인터페이스를 만드는 현대적인 Android 앱입니다. MainActivity는 app/src/main/java/<nama-paket>/MainActivity.kt에 있습니다. Compose 프로젝트는 Jetpack Compose 라이브러리가 기기에 없어서 GitHub Actions(프로젝트 Bangun 메뉴, 그다음 Bangun online(온라인 빌드))를 통하거나 Gradle과 함께 Termux에서 빌드됩니다.
• Python: 앱 로직을 app/src/main/python/main.py에 Python(Chaquopy) 언어로 작성하고, app/src/main/java/<nama-paket>/MainActivity.java의 호스트 MainActivity.java가 실행합니다. Python 프로젝트는 휴대폰에서 바로 빌드할 수도 있고(Chaquopy 런타임이 앱에 포함되어 있습니다) GitHub Actions를 통해서도 빌드할 수 있습니다. Python 프로젝트의 최소 SDK는 24(Android 7.0)입니다.

Java, HTML, Situs Web, Kotlin, Compose, Python 프로젝트의 파일 구성
Java, HTML, Situs Web, Kotlin, Compose, Python 프로젝트는 일반적인 Android 프로젝트처럼 구성됩니다. app 폴더 안에는 src 폴더가 있고, 그 안에는 main 폴더가 있습니다. main 폴더 안에는 java 폴더 옆에 AndroidManifest.xml이 있고, layout/activity_main.xml과 values/strings.xml 및 values/styles.xml을 담고 있는 res 폴더가 있으며, HTML과 Situs Web의 경우 index.html(Situs Web는 tentang.html과 kontak.html도 있음)을 담고 있는 assets 폴더가 있습니다. HTML과 Situs Web 프로젝트도 app/src/main/java/<nama-paket>/MainActivity.java에 자체 MainActivity가 있어 WebView에 index.html을 불러오고 AndroidManifest에서 런처가 됩니다. Python 프로젝트는 app/src/main/python/main.py에 Python 코드가 있고 app/src/main/java/<nama-paket>/MainActivity.java에 호스트 MainActivity.java가 있습니다. AndroidManifest.xml, layout, strings, styles는 MainActivity와 마찬가지로 편집기에서 열고 수정할 수 있습니다. 매니페스트가 아직 app 폴더 옆에 있는 오래된 프로젝트도 빌드할 수 있습니다. 빌드할 때 앱은 먼저 app/src/main/의 AndroidManifest.xml을 확인하고, 그다음 app 폴더 옆의 것을 확인하며, 마지막으로 프로젝트 데이터 파일을 확인하기 때문입니다.

권한 규칙 (중요)
프로젝트를 만들 때 체크한 권한은 프로젝트 종류에 따라 한 곳에만 기록됩니다. Java, HTML, Situs Web, Kotlin, Compose, Python 프로젝트의 경우 체크한 권한은 프로젝트 폴더 안, java 폴더 옆, app/src/main/에 있는 AndroidManifest.xml에만 기록됩니다. Java, HTML, Situs Web, Kotlin, Compose, Python 프로젝트의 프로젝트 데이터 파일에는 권한 목록이 들어 있지 않습니다. Java를 선택하고 INTERNET과 CAMERA에 체크하면 AndroidManifest.xml에 기록되는 것은 INTERNET과 CAMERA뿐이며 다른 권한은 함께 기록되지 않습니다. 빌드할 때 앱은 같은 곳에서 권한을 읽습니다: Java, HTML, Situs Web, Kotlin, Compose, Python 프로젝트는 app/src/main/의 AndroidManifest.xml에서(없으면 오래된 프로젝트용으로 app 폴더 옆의 AndroidManifest.xml에서), 그리고 오래된 프로젝트는 프로젝트 데이터 파일에서 읽습니다.

편집기 사용 방법
Kelola Project를 열고 프로젝트 이름을 눌러 편집기를 엽니다. 편집기에서는 파일을 열고, 코드를 작성하고, 변경 사항을 저장할 수 있습니다. Java, HTML, Situs Web, Kotlin, Compose, Python 프로젝트의 파일은 app/src/main 폴더 안에 구성되어 있습니다. 프로젝트를 공유하려면 Ekspor ZIP(ZIP 내보내기)을 사용하십시오(아래 부분 참조).

프로젝트 실행 방법
편집기에서 Jalankan을 눌러 프로젝트를 테스트합니다. HTML과 Situs Web 프로젝트에서는 index.html이 WebView를 통해 실행됩니다. 오류가 발생하면 오류 메시지를 읽고 코드를 수정한 뒤 다시 실행하십시오.

APK 빌드 방법
편집기에서 Bangun을 누릅니다. 빌드 방법은 두 가지가 있습니다. 첫째, Bangun di perangkat(기기에서 빌드): 인터넷 없이 휴대폰에서 바로 빌드하며, HTML, Situs Web, Java, Kotlin, Python 프로젝트에 사용됩니다. 둘째, GitHub Actions를 통한 Bangun online(온라인 빌드): GitHub에서 인터넷을 통해 빌드하며 모든 종류의 프로젝트에 사용할 수 있습니다. Compose 프로젝트는 Jetpack Compose 라이브러리가 기기에 없어서 두 번째 방법(온라인 빌드)으로만, 또는 Gradle과 함께 Termux에서만 빌드할 수 있습니다. 첫 빌드 결과는 아직 서명되지 않은 상태입니다. 그 후 앱이 서명합니다: 자동으로 기본 키로 서명하거나, 프로젝트를 만들 때 "Gunakan tanda tangan pribadi" 상자에 체크했다면 개인 서명으로 서명합니다.

APK 설치 방법
APK가 완성되면 Pasang(설치)을 눌러 설치합니다. Android 8 이상에서는 이 앱이 Play Store 외부에서 APK를 설치하기 때문에 휴대폰이 먼저 "Izinkan dari sumber ini"(이 출처 허용)를 요청합니다. Pengaturan(설정)에서 그 권한을 한 번 활성화한 뒤 앱으로 돌아오십시오: Pasang을 다시 누를 필요 없이 설치가 자동으로 계속됩니다. Pasang 버튼이 나타나지 않으면 빌드가 끝났고 APK가 만들어졌는지 확인하십시오.

앱에 서명하는 방법
모든 APK는 설치할 수 있도록 서명되어야 합니다. 선택지는 두 가지입니다. 첫째, 기본 키: 앱이 자동으로 서명하므로 아무것도 할 필요가 없습니다. 둘째, 개인 서명: 먼저 메인 메뉴의 Buat Keystore(keystore 만들기) 메뉴를 통해 keystore를 만들고, 그 비밀번호를 잘 보관한 뒤, 프로젝트를 만들 때 "Gunakan tanda tangan pribadi"에 체크합니다. Keystore는 Download/project/signing에 저장됩니다.

프로젝트를 ZIP으로 내보내기
Ekspor ZIP은 프로젝트를 친구와 공유할 수 있도록 제공됩니다. 방법: Kelola Project에서 프로젝트 이름을 길게 누른 뒤 Ekspor ZIP을 선택합니다. 결과는 Download/project/<NamaProyek>.zip에 저장됩니다. bin 폴더는 포함되지 않아 크기가 수십 KB로 작습니다. 그 ZIP 파일은 친구에게 보내거나 GitHub에 올릴 수 있습니다.

Ekstensi JAWS
Ekstensi JAWS는 Jieshuo(CSR)의 확장 엔진을 사용하며, 그 화면 낭독기 자체를 사용하지 않습니다. 따라서 사용자가 TalkBack을 사용하더라도 설계가 계속 실행될 수 있습니다. 방법: 메인 메뉴에서 Ekstensi JAWS를 엽니다. 자동 클릭이 스스로 실행되므로, 먼저 Pengaturan Aksesibilitas(접근성 설정)에서 서비스를 활성화해야 합니다. 그 후 새 설계를 만들 수 있습니다: 설계 이름을 입력하고 OK를 누른 뒤 그 상자를 채웁니다.

깔끔하게 분리된 Daftar Klik
설계 안에는 두 개의 상자가 있습니다: 스크립트 상자와 Daftar Klik(클릭 목록) 상자입니다. 버튼 목록은 daftar_klik.txt 파일에 따로 저장되며 한 줄에 이름 하나씩 들어갑니다. 내용 예시: tombolSimpan, tombolHapus, tombolBuka. 앱을 열려면 그 목록에 >WhatsApp이라고만 쓰면 됩니다. 아직 daftar_klik.txt 파일이 없는 오래된 설계는 그 기본 예시를 표시합니다.

제공되는 간단한 함수
• klikTombol("tombolSimpan") — 텍스트를 기준으로 버튼 하나를 클릭합니다.
• klikDaftarTombol(daftar) — daftar_klik.txt의 목록을 클릭합니다. 한 줄에 버튼 하나씩, 순서대로 클릭한 뒤 몇 개가 성공했고 몇 개를 찾지 못했는지 알려줍니다.
• bukaAplikasi("WhatsApp") — 이름으로 앱을 엽니다. 또는 목록에 ">WhatsApp"이라고 씁니다.
• klik(540, 1200) — 화면 좌표를 클릭합니다.
모든 함수는 우선 단순하게 만들어졌습니다. 익숙해지면 나중에 함수를 추가할 수 있습니다.

화면 낭독기에 대하여
이 앱은 화면 낭독기에 친화적으로 설계되었습니다. 모든 입력 칸에는 라벨과 입력 예시가 있고, 모든 버튼은 복잡한 제스처 없이 닿을 수 있습니다. Ekstensi JAWS는 사용자가 TalkBack을 사용하더라도 계속 실행되도록 만들어졌습니다. 사용되는 것이 그 화면 낭독기가 아니라 확장 엔진이기 때문입니다.

개인정보와 보안
프로젝트와 keystore는 사용자의 휴대폰에 저장됩니다. GitHub 토큰은 온라인 빌드에만 사용되며 이 앱 안에 저장됩니다. 토큰이나 keystore 비밀번호를 누구와도 공유하지 마십시오. 개인 서명을 사용한다면 keystore와 그 비밀번호를 안전한 곳에 보관하십시오. 잃어버리면 예전 APK를 같은 서명으로 업데이트할 수 없기 때문입니다.

요구 사항
Android 5.0 이상. 저장소 권한: Android 11 이상에서는 모든 파일 접근 권한을 사용하고, Android 10 이하에서는 일반 저장소 권한(저장소 읽기/쓰기)을 사용합니다. Android 10에는 모든 파일 접근 권한이 없기 때문입니다. 기기에서 빌드하려면 ARM 프로세서(32비트 또는 64비트)를 탑재한 휴대폰이 필요합니다. GitHub Actions를 통한 온라인 빌드에는 인터넷과 GitHub 토큰이 필요합니다. Kotlin 프로젝트는 기기에서 빌드할 수 있지만, Kotlin 컴파일러 크기가 커서 첫 빌드가 더 느리고 메모리를 더 많이 사용합니다. Compose 프로젝트는 GitHub Actions를 통하거나 Gradle과 함께 Termux에서 빌드됩니다. Python 프로젝트는 Android 7.0 이상(최소 SDK 24)이 필요하고, Python 런타임(Chaquopy)과 그 표준 라이브러리를 포함하므로 결과 APK가 더 큽니다.

Terminal
메인 화면의 Terminal 메뉴는 이 앱 안에서 터미널을 엽니다. ls 같은 명령으로 프로젝트 폴더의 내용을 보고, cd로 폴더를 이동하고, git으로 코드를 관리할 수 있습니다. 명령 출력은 화면 낭독기가 읽을 수 있는 텍스트로 표시되며, 마지막 결과를 들을 수 있는 Bacakan hasil(결과 읽어주기) 버튼이 있습니다. 이 터미널은 휴대폰의 시스템 셸을 사용하므로 nano와 vim 같은 대화형 프로그램은 아직 여기서 사용할 수 없습니다.

Lisensi (유료 버전)
앱을 판매하려면 프로젝트를 만들 때 "Aktifkan Lisensi"(라이선스 활성화)에 체크한 뒤 WhatsApp 번호를 입력하십시오. 빌드된 앱은 처음 열릴 때 라이선스 코드를 요청합니다: 사용자가 자신의 기기 ID를 보고, Kirim ID Perangkat(기기 ID 보내기) 버튼을 눌러 그 ID를 사용자의 WhatsApp으로 보내면, 사용자가 라이선스 코드로 답합니다. 라이선스 코드는 기기 ID와 프로젝트 비밀번호(프로젝트 데이터 파일의 lisensi_seed)로 계산됩니다 — 그 비밀번호를 잘 보관하고 공유하지 마십시오. 올바른 코드가 입력되면 앱이 열리고 더 이상 코드를 요청하지 않습니다.

Pembuat Ikon Otomatis
새 프로젝트의 아이콘은 아직 투명하므로, 메인 메뉴에 Pembuat Ikon(아이콘 만들기)이 있습니다. 방법: Pembuat Ikon을 누르고, 한두 글자(예: 앱 이름의 이니셜)를 쓰고, 배경색과 글자색을 고르고, 미리보기를 본 뒤, Simpan ke Proyek(프로젝트에 저장)을 눌러 선택한 프로젝트에 그 아이콘을 사용하거나, Simpan ke Download(Download에 저장)를 눌러 그 PNG 파일을 다른 곳에 사용합니다. 프로젝트가 만들어진 후에도 앱이 아이콘 만들기를 제안합니다. 프로젝트의 예전 아이콘은 Kelola Project의 프로젝트 메뉴에서 언제든 바꿀 수 있습니다(프로젝트 이름을 길게 누른 뒤 Ganti Ikon(아이콘 변경)을 선택).

Template Proyek Siap Pakai
빈 프로젝트에서 시작하고 싶지 않다면 프로젝트를 만들 때 템플릿을 선택하십시오: Kalkulator(Java), Catatan(Java), Daftar Tugas(Kotlin), Kalkulator Web(HTML), Situs Profil(Situs Web), 또는 Penghitung(Compose). 템플릿을 선택하면 프로젝트 종류가 자동으로 그 템플릿을 따라 바뀌고, 프로젝트는 이미 완성된 시작 코드로 만들어집니다 — 바로 실행하거나 수정하면 됩니다. 템플릿을 선택한 뒤 프로젝트 종류를 다시 수동으로 바꾸면 템플릿이 취소되고 프로젝트는 다시 비게 됩니다. HTML과 Situs Web 템플릿의 경우, 템플릿은 index.html의 내용을 교체합니다. 여기에는 폼에 입력한 HTML 스크립트도 포함됩니다.

Cadangan dan Pulihkan Proyek
프로젝트가 사라지지 않도록 백업 기능이 있습니다. 방법: Kelola Project에서 프로젝트 이름을 길게 누른 뒤 Cadangkan(백업)을 선택합니다. 백업은 Download/backup 폴더에 프로젝트 이름과 날짜를 붙인 ZIP으로 저장됩니다. 예: GarudaDecode-2026-11-14-123045.zip. 내용은 Ekspor ZIP과 같습니다(프로젝트 전체 내용, bin 폴더 제외). 복원하려면: Kelola Project에서 메뉴를 열고 Pulihkan cadangan(백업 복원)을 선택한 뒤 백업 파일을 고릅니다. 프로젝트 이름이 이미 있으면 앱이 묻습니다: Timpa proyek lama(예전 프로젝트 덮어쓰기), 또는 Nama baru(새 이름)로 저장.

Bagikan dan Impor Proyek
프로젝트를 친구와 공유하려면: Kelola Project에서 프로젝트 이름을 길게 누른 뒤 Bagikan(공유)을 선택합니다. 프로젝트는 공유 앱(WhatsApp, Telegram 등)을 통해 ZIP으로 전송됩니다. 친구에게서 프로젝트를 받으려면: Kelola Project에서 메뉴를 열고 Impor proyek(프로젝트 가져오기)를 선택한 뒤 그 ZIP 파일을 고릅니다. 그 ZIP 파일에는 프로젝트 데이터 파일이 들어 있어야 합니다 — 없으면 그 파일은 Create Aplikasi 프로젝트가 아니므로 명확한 메시지와 함께 파일이 거부됩니다. 프로젝트 이름이 이미 있으면 앱이 묻습니다: Timpa proyek lama, 또는 Nama baru로 저장.

Pencarian dan Filter Proyek
프로젝트가 많아지면 Kelola Project에 검색 상자와 종류 필터가 있습니다. 검색 상자에 프로젝트 이름을 입력하면 목록이 바로 걸러집니다(대소문자는 구분하지 않습니다). 종류 필터는 목록을 한 종류로만 제한합니다: Semua(전체), HTML, Situs Web, Java, Kotlin, Compose 또는 Python. 각 프로젝트의 메뉴는 걸러진 목록에서도 평소와 같이 열 수 있습니다.
