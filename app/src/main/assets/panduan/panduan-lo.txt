ຍິນດີຕ້ອນຮັບສູ່ Create Aplikasi by Al Kautsar
Create Aplikasi ແມ່ນແອັບສ້າງແອັບ Android ທີ່ເຮັດວຽກໂດຍກົງໃນໂທລະສັບ ໂດຍບໍ່ຕ້ອງໃຊ້ແລັບທັອບ. ແອັບນີ້ຊ່ວຍໃຫ້ທຸກຄົນສ້າງແອັບ Android ຂອງຕົນເອງໄດ້ ລວມທັງຜູ້ທີ່ຫາກໍ່ເລີ່ມຮຽນສ້າງແອັບ ແລະ ຜູ້ໃຊ້ໂປຣແກຣມອ່ານໜ້າຈໍ. ຄູ່ມືການໃຊ້ແອັບນີ້ແບບເຕັມຮູບແບບມີຢູ່ໃນໜ້າຈໍ Tentang Alat ນີ້.

ແອັບນີ້ແມ່ນຫຍັງ ແລະ ສຳລັບໃຜ
Create Aplikasi ແມ່ນເຄື່ອງມືສ້າງແອັບ Android ທີ່ເຮັດວຽກໃນໂທລະສັບ. ແອັບນີ້ມີໄວ້ສຳລັບທຸກຄົນທີ່ຢາກສ້າງແອັບ Android ຂອງຕົນເອງ ລວມທັງຜູ້ເລີ່ມຕົ້ນ ແລະ ຜູ້ໃຊ້ໂປຣແກຣມອ່ານໜ້າຈໍ. ແອັບນີ້ມີຕົວແກ້ໄຂໂຄດ ປຸ່ມ Jalankan ເພື່ອທົດສອບໂຄງການ ປຸ່ມ Bangun ເພື່ອສ້າງ APK ແລະ ເມນູສຳລັບເຊັນ ແລະ ຕິດຕັ້ງ APK.

ຈຸດປະສົງຂອງແອັບນີ້
ແອັບນີ້ຖືກສ້າງຂຶ້ນເພື່ອໃຫ້ທຸກຄົນສາມາດສ້າງແອັບ Android ຂອງຕົນເອງໄດ້ຢ່າງງ່າຍດາຍ ໂດຍກົງຈາກໂທລະສັບ. ຮູບລັກສະນະຂອງມັນຖືກເຮັດໃຫ້ງ່າຍທີ່ສຸດເທົ່າທີ່ຈະເຮັດໄດ້ ເພື່ອໃຫ້ຜູ້ໃຊ້ໃໝ່ກໍສາມາດລອງໄດ້ທັນທີ.

ວິທີສ້າງໂຄງການໃໝ່ ທີລະຂັ້ນຕອນ
1. ກົດ Buat Project ໃນເມນູຫຼັກ.
2. ເລືອກປະເພດໂຄງການ: HTML, Situs Web, Java, Kotlin, Compose, ຫຼື Python.
3. ຕື່ມຊື່ແອັບ ຕົວຢ່າງ: Garuda Decode.
4. ຕື່ມຊື່ແພັກເກດ (package name) ຕົວຢ່າງ: com.android.garudadecode. ຊື່ແພັກເກດຕ້ອງໃຊ້ຕົວອັກສອນນ້ອຍ ແລະ ປະກອບດ້ວຍຢ່າງໜ້ອຍສອງສ່ວນທີ່ແຍກດ້ວຍຈຸດ.
5. ຕື່ມເວີຊັນແອັບ ຕົວຢ່າງ: 1.0 ແລະ ລະຫັດເວີຊັນເປັນຕົວເລກ ຕົວຢ່າງ: 1. ຖ້າປ່ອຍວ່າງໄວ້ ເວີຊັນຈະຖືກຕື່ມອັດຕະໂນມັດເປັນ 1.0 ແລະ ລະຫັດເວີຊັນ 1.
6. ຕື່ມ SDK ຕ່ຳສຸດ ແລະ SDK ເປົ້າໝາຍ ຖ້າຈຳເປັນ. ຖ້າປ່ອຍວ່າງໄວ້ ຄ່າເລີ່ມຕົ້ນຈະຖືກໃຊ້. SDK ຕ່ຳສຸດແມ່ນເວີຊັນ Android ຕ່ຳສຸດທີ່ຮອງຮັບ ຕົວຢ່າງ: 21 ໝາຍເຖິງ Android 5.0. SDK ເປົ້າໝາຍສູງສຸດແມ່ນ 36 (Android 16).
7. ກົດປຸ່ມ Pilih Izin ເພື່ອເລືອກສິດອະນຸຍາດຂອງແອັບ ຕົວຢ່າງ: INTERNET. ສິດອະນຸຍາດ INTERNET ຖືກໝາຍໄວ້ເປັນຄ່າເລີ່ມຕົ້ນແລ້ວ. ໝາຍສະເພາະສິດອະນຸຍາດທີ່ແອັບຕ້ອງການແທ້ໆເທົ່ານັ້ນ.
8. ຖ້າຕ້ອງການ ໃຫ້ໝາຍ "Gunakan arsitektur terpisah 64 bit dan 32 bit" ເພື່ອໃຫ້ຂະໜາດ APK ນ້ອຍລົງ ແລະ ໝາຍ "Gunakan tanda tangan pribadi" ຖ້າຢາກໃຊ້ keystore ທີ່ສ້າງເອງ.
9. ກົດ Buat Proyek. ໂຄງການໃໝ່ຈະຖືກບັນທຶກໄວ້ໃນໂຟນເດີ Download/project ແລະ ປາກົດທັນທີໃນ Kelola Project.

ປະເພດໂຄງການທີ່ມີໃຫ້
• HTML: ການແດງຜົນຈາກ index.html, style.css, ແລະ script.js ທີ່ເຮັດວຽກຜ່ານ WebView. ສ້າງໂດຍກົງໃນໂທລະສັບ.
• Situs Web: ເວັບໄຊທີ່ມີເມນູ (Beranda, Tentang, Kontak) ຈາກ index.html, tentang.html, kontak.html, style.css, ແລະ script.js ທີ່ເຮັດວຽກຜ່ານ WebView. ສ້າງໂດຍກົງໃນໂທລະສັບ.
• Java: ສ້າງໃນໂທລະສັບ. MainActivity ຢູ່ໃນ app/src/main/java/<nama-paket>/MainActivity.java. ການແດງຜົນມາຈາກ app/src/main/res/layout/activity_main.xml ຂໍ້ຄວາມມາຈາກ app/src/main/res/values/strings.xml ແລະ ຮູບແບບມາຈາກ app/src/main/res/values/styles.xml.
• Kotlin: ສາມາດສ້າງໃນອຸປະກອນ (offline) ໂດຍໃຊ້ຕົວຄອມໄພລ໌ Kotlin ທີ່ລວມຢູ່ໃນແອັບ ຫຼື ຜ່ານ GitHub Actions. MainActivity ຢູ່ໃນ app/src/main/java/<nama-paket>/MainActivity.kt ແລະ ໄຟລ໌ res ກໍຄືກັນກັບໂຄງການ Java. ການສ້າງ Kotlin ຄັ້ງທຳອິດຈະຊ້າກວ່າເນື່ອງຈາກຂະໜາດຂອງຕົວຄອມໄພລ໌ໃຫຍ່ ແລະ ໄຟລ໌ .java ທີ່ອ້າງອີງຫາຄລາດ Kotlin ຍັງບໍ່ສາມາດສ້າງໄດ້ເທື່ອ (ໄຟລ໌ .java ຖືກຄອມໄພລ໌ກ່ອນໄຟລ໌ .kt).
• Compose: ແອັບ Android ສະໄໝໃໝ່ທີ່ສ່ວນຕິດຕໍ່ຂອງມັນຖືກສ້າງດ້ວຍ Jetpack Compose (ບໍ່ແມ່ນ layout XML). MainActivity ຢູ່ໃນ app/src/main/java/<nama-paket>/MainActivity.kt. ໂຄງການ Compose ຖືກສ້າງຜ່ານ GitHub Actions (ເມນູ Bangun proyek ແລ້ວ Bangun online) ຫຼື ໃນ Termux ດ້ວຍ Gradle ເພາະ Compose ຕ້ອງການໄລບຣາຣີ Jetpack Compose ທີ່ບໍ່ມີໃນອຸປະກອນ.
• Python: ເຫດຜົນຂອງແອັບຖືກຂຽນເປັນພາສາ Python (Chaquopy) ໃນ app/src/main/python/main.py ແລະ ຖືກເຮັດວຽກໂດຍ host MainActivity.java ໃນ app/src/main/java/<nama-paket>/MainActivity.java. ໂຄງການ Python ສາມາດສ້າງໄດ້ໂດຍກົງໃນໂທລະສັບ (runtime Chaquopy ລວມຢູ່ໃນແອັບ) ຫຼື ຜ່ານ GitHub Actions. SDK ຕ່ຳສຸດຂອງໂຄງການ Python ແມ່ນ 24 (Android 7.0).

ປ່ຽນສະຖາປັດຕະຍະກຳໂຄງການ
ເພື່ອປ່ຽນທາງເລືອກສະຖາປັດຕະຍະກຳຂອງໂຄງການທີ່ມີຢູ່ແລ້ວໂດຍບໍ່ຕ້ອງສ້າງໂຄງການໃໝ່: ກົດ «ປ່ຽນສະຖາປັດຕະຍະກຳໂຄງການ» ໃນເມນູຫຼັກ ຈາກນັ້ນເລືອກໂຄງການ ແລະປ່ຽນກ່ອງໝາຍ «ສ້າງ APK 64 ບິດ (arm64-v8a)» ຫຼື «ສ້າງ APK 32 ບິດ (armeabi-v7a)»; ຫຼືກົດຄ້າງຊື່ໂຄງການໃນ «ຈັດການໂຄງການ» ແລະເລືອກ «ປ່ຽນສະຖາປັດຕະຍະກຳ» ເພື່ອເປີດໜ້າຈໍດຽວກັນໂດຍກົງສຳລັບໂຄງການນັ້ນ. ກົດເກນແມ່ນ: ຖ້າທັງສອງກ່ອງໝາຍຖືກເປີດ ການສ້າງຈະສ້າງໄຟລ໌ APK ແຍກກັນສອງໄຟລ໌ ໜຶ່ງ 64 ບິດ ແລະໜຶ່ງ 32 ບິດ; ຖ້າມີພຽງກ່ອງໝາຍດຽວຖືກເປີດ ການສ້າງຈະສ້າງໄຟລ໌ APK ສາກົນດຽວທີ່ຍັງສືບຕໍ່ເຮັດວຽກຢູ່ໃນອຸປະກອນ 64 ບິດ ແລະ 32 ບິດທັງສອງ. ໄຟລ໌ APK ແຍກກັນສຳລັບພຽງຕົວແປດຽວຍັງບໍ່ໄດ້ຮັບການສະໜັບສະໜູນ ເພາະວ່າເສັ້ນທາງການສ້າງຮູ້ພຽງແຕ່ທາງເລືອກທີ່ແບ່ງອອກ ຫຼືສາກົນເທົ່ານັ້ນ ແຕ່ທາງເລືອກຂອງແຕ່ລະຕົວແປຍັງຖືກບັນທຶກໄວ້ໃນໂຄງການເພື່ອບໍ່ໃຫ້ສູນຫາຍເມື່ອໜ້າຈໍຖືກເປີດອີກຄັ້ງ.

ໂຄງສ້າງໄຟລ໌ຂອງໂຄງການ Java, HTML, Situs Web, Kotlin, Compose, ແລະ Python
ໂຄງການ Java, HTML, Situs Web, Kotlin, Compose, ແລະ Python ຖືກຈັດລຽງຄືກັບໂຄງການ Android ທົ່ວໄປ. ພາຍໃນໂຟນເດີ app ມີໂຟນເດີ src ແລະ ພາຍໃນນັ້ນມີໂຟນເດີ main. ພາຍໃນໂຟນເດີ main ມີ AndroidManifest.xml ຢູ່ຄຽງຂ້າງໂຟນເດີ java ໂຟນເດີ res ທີ່ມີ layout/activity_main.xml ແລະ values/strings.xml ພ້ອມທັງ values/styles.xml ແລະ ສຳລັບ HTML ແລະ Situs Web ມີໂຟນເດີ assets ທີ່ມີ index.html (Situs Web ຍັງມີ tentang.html ແລະ kontak.html ອີກ). ໂຄງການ HTML ແລະ Situs Web ກໍມີ MainActivity ຂອງຕົນເອງຢູ່ໃນ app/src/main/java/<nama-paket>/MainActivity.java ເຊິ່ງໂຫຼດ index.html ໃນ WebView ແລະ ເປັນ launcher ໃນ AndroidManifest. ໂຄງການ Python ມີໂຄດ Python ຢູ່ໃນ app/src/main/python/main.py ແລະ host MainActivity.java ຢູ່ໃນ app/src/main/java/<nama-paket>/MainActivity.java. AndroidManifest.xml, layout, strings, ແລະ styles ສາມາດເປີດ ແລະ ແກ້ໄຂໃນຕົວແກ້ໄຂໄດ້ ຄືກັນກັບ MainActivity. ໂຄງການເກົ່າທີ່ manifest ຂອງມັນຍັງຢູ່ຄຽງຂ້າງໂຟນເດີ app ກໍຍັງສ້າງໄດ້ ເພາະເວລາສ້າງ ແອັບຈະກວດ AndroidManifest.xml ໃນ app/src/main/ ກ່ອນ ແລ້ວຈຶ່ງອັນທີ່ຢູ່ຄຽງຂ້າງໂຟນເດີ app ແລະ ສຸດທ້າຍແມ່ນໄຟລ໌ຂໍ້ມູນໂຄງການ.

ກົດຂອງສິດອະນຸຍາດ (ສຳຄັນ)
ສິດອະນຸຍາດທີ່ໝາຍໄວ້ເວລາສ້າງໂຄງການຈະຖືກບັນທຶກໄວ້ໃນບ່ອນດຽວເທົ່ານັ້ນ ຕາມປະເພດໂຄງການ. ສຳລັບໂຄງການ Java, HTML, Situs Web, Kotlin, Compose, ແລະ Python ສິດອະນຸຍາດທີ່ໝາຍໄວ້ຈະຖືກບັນທຶກໄວ້ສະເພາະໃນ AndroidManifest.xml ທີ່ຢູ່ໃນ app/src/main/ ຄຽງຂ້າງໂຟນເດີ java ພາຍໃນໂຟນເດີໂຄງການເທົ່ານັ້ນ. ໄຟລ໌ຂໍ້ມູນໂຄງການສຳລັບໂຄງການ Java, HTML, Situs Web, Kotlin, Compose, ແລະ Python ບໍ່ມີລາຍການສິດອະນຸຍາດ. ຖ້າເລືອກ Java ແລ້ວໝາຍ INTERNET ແລະ CAMERA ສິ່ງທີ່ຖືກບັນທຶກໃນ AndroidManifest.xml ຈະມີສະເພາະ INTERNET ແລະ CAMERA ເທົ່ານັ້ນ ໂດຍບໍ່ມີສິດອະນຸຍາດອື່ນປົນມາ. ເວລາສ້າງ ແອັບຈະອ່ານສິດອະນຸຍາດຈາກບ່ອນດຽວກັນນັ້ນ: ຈາກ AndroidManifest.xml ໃນ app/src/main/ ສຳລັບໂຄງການ Java, HTML, Situs Web, Kotlin, Compose, ແລະ Python (ຖ້າບໍ່ມີ ຈາກ AndroidManifest.xml ທີ່ຢູ່ຄຽງຂ້າງໂຟນເດີ app ສຳລັບໂຄງການເກົ່າ) ແລະ ຈາກໄຟລ໌ຂໍ້ມູນໂຄງການສຳລັບໂຄງການເກົ່າ.

ວິທີໃຊ້ຕົວແກ້ໄຂ
ເປີດ Kelola Project ແຕະຊື່ໂຄງການເພື່ອເປີດຕົວແກ້ໄຂ. ໃນຕົວແກ້ໄຂ ສາມາດເປີດໄຟລ໌ ຂຽນໂຄດ ແລະ ບັນທຶກການປ່ຽນແປງໄດ້. ສຳລັບໂຄງການ Java, HTML, Situs Web, Kotlin, Compose, ແລະ Python ໄຟລ໌ຖືກຈັດລຽງຢູ່ໃນໂຟນເດີ app/src/main. ເພື່ອແບ່ງປັນໂຄງການ ໃຫ້ໃຊ້ Ekspor ZIP (ເບິ່ງພາກຂ້າງລຸ່ມ).

ວິທີເຮັດວຽກໂຄງການ
ໃນຕົວແກ້ໄຂ ກົດ Jalankan ເພື່ອທົດສອບໂຄງການ. ສຳລັບໂຄງການ HTML ແລະ Situs Web ສິ່ງທີ່ຖືກເຮັດວຽກແມ່ນ index.html ຜ່ານ WebView. ຖ້າມີຂໍ້ຜິດພາດເກີດຂຶ້ນ ໃຫ້ອ່ານຂໍ້ຄວາມຂໍ້ຜິດພາດ ແກ້ໄຂໂຄດ ແລ້ວເຮັດວຽກອີກຄັ້ງ.

ວິທີສ້າງ APK
ໃນຕົວແກ້ໄຂ ກົດ Bangun. ມີວິທີສ້າງສອງວິທີ. ວິທີທຳອິດ ສ້າງໃນອຸປະກອນ: ສ້າງໂດຍກົງໃນໂທລະສັບໂດຍບໍ່ຕ້ອງໃຊ້ອິນເຕີເນັດ ສຳລັບໂຄງການ HTML, Situs Web, Java, Kotlin, ແລະ Python. ວິທີທີສອງ ສ້າງອອນລາຍຜ່ານ GitHub Actions: ສ້າງຜ່ານອິນເຕີເນັດໃນ GitHub ແລະ ສາມາດໃຊ້ໄດ້ສຳລັບໂຄງການທຸກປະເພດ. ໂຄງການ Compose ສາມາດສ້າງໄດ້ສະເພາະດ້ວຍວິທີທີສອງ (Bangun online) ຫຼື ໃນ Termux ດ້ວຍ Gradle ເພາະ Compose ຕ້ອງການໄລບຣາຣີ Jetpack Compose ທີ່ບໍ່ມີໃນອຸປະກອນ. ຜົນການສ້າງຄັ້ງທຳອິດຍັງບໍ່ທັນໄດ້ເຊັນ. ຈາກນັ້ນແອັບຈະເຊັນໃຫ້: ອັດຕະໂນມັດດ້ວຍກະແຈເລີ່ມຕົ້ນ ຫຼື ດ້ວຍລາຍເຊັນສ່ວນຕົວຖ້າກ່ອງ "Gunakan tanda tangan pribadi" ຖືກໝາຍໄວ້ເວລາສ້າງໂຄງການ.

ວິທີຕິດຕັ້ງ APK
ເມື່ອ APK ພ້ອມແລ້ວ ກົດ Pasang ເພື່ອຕິດຕັ້ງມັນ. ໃນ Android 8 ຂຶ້ນໄປ ໂທລະສັບຈະຂໍ "Izinkan dari sumber ini" ກ່ອນ ເພາະແອັບນີ້ຕິດຕັ້ງ APK ຈາກພາຍນອກ Play Store. ເປີດໃຊ້ສິດອະນຸຍາດນັ້ນໜຶ່ງຄັ້ງໃນ Pengaturan ແລ້ວກັບມາທີ່ແອັບ: ການຕິດຕັ້ງຈະສືບຕໍ່ອັດຕະໂນມັດໂດຍບໍ່ຕ້ອງກົດ Pasang ອີກ. ຖ້າປຸ່ມ Pasang ບໍ່ປາກົດ ໃຫ້ແນ່ໃຈວ່າການສ້າງສຳເລັດແລ້ວ ແລະ APK ຖືກສ້າງແລ້ວ.

ວິທີເຊັນແອັບ
ທຸກ APK ຕ້ອງຖືກເຊັນຈຶ່ງຈະຕິດຕັ້ງໄດ້. ມີສອງທາງເລືອກ. ທາງທຳອິດ ກະແຈເລີ່ມຕົ້ນ: ແອັບເຊັນເອງອັດຕະໂນມັດ ໂດຍບໍ່ຕ້ອງເຮັດຫຍັງເລີຍ. ທາງທີສອງ ລາຍເຊັນສ່ວນຕົວ: ສ້າງ keystore ກ່ອນຜ່ານເມນູ Buat Keystore ໃນເມນູຫຼັກ ເກັບລະຫັດຜ່ານຂອງມັນໄວ້ໃຫ້ດີ ແລ້ວໝາຍ "Gunakan tanda tangan pribadi" ເວລາສ້າງໂຄງການ. Keystore ຖືກເກັບໄວ້ໃນ Download/project/signing.

ສົ່ງອອກໂຄງການເປັນ ZIP
Ekspor ZIP ມີໄວ້ເພື່ອໃຫ້ໂຄງການແບ່ງປັນໃຫ້ໝູ່ໄດ້. ວິທີ: ໃນ Kelola Project ກົດຊື່ໂຄງການຄ້າງໄວ້ດົນ ແລ້ວເລືອກ Ekspor ZIP. ຜົນລັບຈະຖືກບັນທຶກໄວ້ໃນ Download/project/<NamaProyek>.zip. ໂຟນເດີ bin ບໍ່ໄດ້ລວມເຂົ້າໄປ ດັ່ງນັ້ນຂະໜາດຂອງມັນຈຶ່ງນ້ອຍ ພຽງແຕ່ສິບກວ່າ KB ເທົ່ານັ້ນ. ໄຟລ໌ ZIP ນັ້ນສາມາດສົ່ງໃຫ້ໝູ່ ຫຼື ອັບໂຫຼດໄປ GitHub ໄດ້.

Ekstensi JAWS
Ekstensi JAWS ໃຊ້ເຄື່ອງຈັກສ່ວນຂະຫຍາຍຂອງ Jieshuo (CSR) ບໍ່ແມ່ນໂປຣແກຣມອ່ານໜ້າຈໍຂອງມັນ. ດ້ວຍວິທີນີ້ ການອອກແບບຍັງສາມາດເຮັດວຽກໄດ້ເຖິງແມ່ນວ່າຜູ້ໃຊ້ຈະໃຊ້ TalkBack ກໍຕາມ. ວິທີ: ເປີດ Ekstensi JAWS ໃນເມນູຫຼັກ. ເນື່ອງຈາກການຄລິກອັດຕະໂນມັດເຮັດວຽກເອງ ບໍລິການຕ້ອງຖືກເປີດໃຊ້ກ່ອນໃນ Pengaturan Aksesibilitas. ຈາກນັ້ນຈຶ່ງສາມາດສ້າງການອອກແບບໃໝ່ໄດ້: ພິມຊື່ການອອກແບບ ກົດ OK ແລ້ວຕື່ມກ່ອງຂອງມັນ.

Daftar Klik ຖືກແຍກອອກເພື່ອໃຫ້ເປັນລະບຽບ
ພາຍໃນການອອກແບບມີສອງກ່ອງ: ກ່ອງສະຄຣິບ ແລະ ກ່ອງ Daftar Klik. ລາຍການປຸ່ມຖືກເກັບແຍກຕ່າງຫາກໄວ້ໃນໄຟລ໌ daftar_klik.txt ໜຶ່ງຊື່ຕໍ່ໜຶ່ງແຖວ. ຕົວຢ່າງເນື້ອໃນຂອງມັນ: tombolSimpan, tombolHapus, tombolBuka. ເພື່ອເປີດແອັບ ໃຫ້ຂຽນພຽງແຕ່ >WhatsApp ໃນລາຍການນັ້ນ. ການອອກແບບເກົ່າທີ່ຍັງບໍ່ມີໄຟລ໌ daftar_klik.txt ຈະແດງຕົວຢ່າງເລີ່ມຕົ້ນນັ້ນ.

ຟັງຊັນງ່າຍໆທີ່ມີໃຫ້
• klikTombol("tombolSimpan") — ຄລິກປຸ່ມໜຶ່ງຕາມຂໍ້ຄວາມຂອງມັນ.
• klikDaftarTombol(daftar) — ຄລິກລາຍການໃນ daftar_klik.txt ໜຶ່ງປຸ່ມຕໍ່ໜຶ່ງແຖວ ຕາມລຳດັບ ແລ້ວແຈ້ງວ່າມີຈັກອັນທີ່ສຳເລັດ ແລະ ຈັກອັນທີ່ຫາບໍ່ພົບ.
• bukaAplikasi("WhatsApp") — ເປີດແອັບຕາມຊື່ຂອງມັນ ຫຼື ຂຽນ ">WhatsApp" ໃນລາຍການ.
• klik(540, 1200) — ຄລິກທີ່ພິກັດໜ້າຈໍ.
ຟັງຊັນທັງໝົດຖືກເຮັດໃຫ້ງ່າຍໄວ້ກ່ອນ. ເມື່ອຄຸ້ນເຄີຍແລ້ວ ສາມາດເພີ່ມຟັງຊັນເພີ່ມເຕີມໄດ້ໃນພາຍຫຼັງ.

ກ່ຽວກັບໂປຣແກຣມອ່ານໜ້າຈໍ
ແອັບນີ້ຖືກອອກແບບມາໃຫ້ເປັນມິດກັບໂປຣແກຣມອ່ານໜ້າຈໍ. ທຸກຊ່ອງຕື່ມຂໍ້ມູນມີປ້າຍ ແລະ ຕົວຢ່າງການຕື່ມ ແລະ ທຸກປຸ່ມສາມາດເຂົ້າເຖິງໄດ້ໂດຍບໍ່ຕ້ອງໃຊ້ທ່າທາງທີ່ສັບສົນ. Ekstensi JAWS ຖືກສ້າງມາໃຫ້ຍັງເຮັດວຽກໄດ້ເຖິງແມ່ນວ່າຜູ້ໃຊ້ຈະໃຊ້ TalkBack ກໍຕາມ ເພາະສິ່ງທີ່ໃຊ້ແມ່ນເຄື່ອງຈັກສ່ວນຂະຫຍາຍຂອງມັນ ບໍ່ແມ່ນໂປຣແກຣມອ່ານໜ້າຈໍຂອງມັນ.

ໂຄງການ ແລະ keystore ຖືກເກັບໄວ້ໃນໂທລະສັບຂອງທ່ານ. ໂທເຄັນ GitHub ຖືກໃຊ້ສະເພາະສຳລັບການສ້າງອອນລາຍເທົ່ານັ້ນ ແລະ ຖືກເກັບໄວ້ພາຍໃນແອັບນີ້. ຢ່າແບ່ງປັນໂທເຄັນ ຫຼື ລະຫັດຜ່ານ keystore ຂອງທ່ານໃຫ້ໃຜເລີຍ. ຖ້າໃຊ້ລາຍເຊັນສ່ວນຕົວ ໃຫ້ເກັບ keystore ແລະ ລະຫັດຜ່ານຂອງມັນໄວ້ໃນບ່ອນທີ່ປອດໄພ ເພາະຖ້າຫາຍໄປ APK ເກົ່າຈະບໍ່ສາມາດອັບເດດດ້ວຍລາຍເຊັນດຽວກັນໄດ້ອີກ.

ຄວາມຕ້ອງການ
Android 5.0 ຫຼື ໃໝ່ກວ່າ. ສິດອະນຸຍາດບ່ອນເກັບຂໍ້ມູນ: ໃນ Android 11 ຂຶ້ນໄປໃຊ້ສິດອະນຸຍາດເຂົ້າເຖິງໄຟລ໌ທັງໝົດ ໃນ Android 10 ລົງມາໃຊ້ສິດອະນຸຍາດບ່ອນເກັບຂໍ້ມູນປົກກະຕິ (ອ່ານ/ຂຽນບ່ອນເກັບຂໍ້ມູນ) ເພາະ Android 10 ບໍ່ມີສິດອະນຸຍາດເຂົ້າເຖິງໄຟລ໌ທັງໝົດ. ການສ້າງໃນອຸປະກອນຕ້ອງການໂທລະສັບທີ່ມີໂປຣເຊດເຊີ ARM (32 ຫຼື 64 ບິດ). ການສ້າງອອນລາຍຜ່ານ GitHub Actions ຕ້ອງການອິນເຕີເນັດ ແລະ ໂທເຄັນ GitHub. ໂຄງການ Kotlin ສາມາດສ້າງໃນອຸປະກອນໄດ້ ແຕ່ການສ້າງຄັ້ງທຳອິດຂອງມັນຈະຊ້າກວ່າ ແລະ ໃຊ້ໜ່ວຍຄວາມຈຳຫຼາຍກວ່າເນື່ອງຈາກຂະໜາດຂອງຕົວຄອມໄພລ໌ Kotlin ໃຫຍ່. ໂຄງການ Compose ຖືກສ້າງຜ່ານ GitHub Actions ຫຼື ໃນ Termux ດ້ວຍ Gradle. ໂຄງການ Python ຕ້ອງການ Android 7.0 ຫຼື ໃໝ່ກວ່າ (SDK ຕ່ຳສຸດ 24) ແລະ APK ຜົນລັບຈະໃຫຍ່ກວ່າ ເພາະມັນລວມ runtime Python (Chaquopy) ພ້ອມກັບໄລບຣາຣີມາດຕະຖານຂອງມັນໄວ້.

Terminal
ເມນູ Terminal ໃນໜ້າຈໍຫຼັກເປີດ terminal ພາຍໃນແອັບນີ້. ຄຳສັ່ງເຊັ່ນ ls ສາມາດໃຊ້ເພື່ອເບິ່ງເນື້ອໃນຂອງໂຟນເດີໂຄງການ cd ເພື່ອຍ້າຍໂຟນເດີ ແລະ git ເພື່ອຈັດການໂຄດ. ຜົນອອກຂອງຄຳສັ່ງຖືກແດງເປັນຂໍ້ຄວາມທີ່ໂປຣແກຣມອ່ານໜ້າຈໍອ່ານໄດ້ ແລະ ມີປຸ່ມ Bacakan hasil ເພື່ອຟັງຜົນລັບສຸດທ້າຍ. Terminal ນີ້ໃຊ້ shell ຂອງລະບົບໂທລະສັບ ດັ່ງນັ້ນໂປຣແກຣມໂຕ້ຕອບເຊັ່ນ nano ແລະ vim ຍັງບໍ່ສາມາດໃຊ້ຢູ່ນີ້ໄດ້ເທື່ອ.

Lisensi (ເວີຊັນເສຍເງິນ)
ເພື່ອຂາຍແອັບ ໃຫ້ໝາຍ "Aktifkan Lisensi" ເວລາສ້າງໂຄງການ ແລ້ວຕື່ມເບີ WhatsApp ຂອງທ່ານ. ແອັບທີ່ສ້າງແລ້ວຈະຂໍລະຫັດໃບອະນຸຍາດເມື່ອເປີດຄັ້ງທຳອິດ: ຜູ້ໃຊ້ເຫັນ ID ອຸປະກອນຂອງຕົນ ກົດປຸ່ມ Kirim ID Perangkat ເພື່ອສົ່ງ ID ນັ້ນໄປຫາ WhatsApp ຂອງທ່ານ ແລ້ວທ່ານຕອບກັບດ້ວຍລະຫັດໃບອະນຸຍາດຂອງພວກເຂົາ. ລະຫັດໃບອະນຸຍາດຖືກຄຳນວນຈາກ ID ອຸປະກອນ ແລະ ລະຫັດຜ່ານໂຄງການ (lisensi_seed ໃນໄຟລ໌ຂໍ້ມູນໂຄງການ) — ເກັບລະຫັດຜ່ານນັ້ນໄວ້ໃຫ້ດີ ແລະ ຢ່າແບ່ງປັນມັນ. ຫຼັງຈາກລະຫັດທີ່ຖືກຕ້ອງຖືກປ້ອນແລ້ວ ແອັບຈະເປີດ ແລະ ບໍ່ຂໍລະຫັດອີກ.

Pembuat Ikon Otomatis
ໄອຄອນຂອງໂຄງການໃໝ່ຍັງໂປ່ງໃສຢູ່ ດັ່ງນັ້ນ Pembuat Ikon ຈຶ່ງມີຢູ່ໃນເມນູຫຼັກ. ວິທີ: ກົດ Pembuat Ikon ຂຽນຕົວອັກສອນໜຶ່ງ ຫຼື ສອງຕົວ (ຕົວຢ່າງ ຕົວຫຍໍ້ຂອງຊື່ແອັບ) ເລືອກສີພື້ນຫຼັງ ແລະ ສີຂໍ້ຄວາມ ເບິ່ງຕົວຢ່າງສະແດງຂອງມັນ ແລ້ວກົດ Simpan ke Proyek ເພື່ອໃຊ້ໄອຄອນນັ້ນໃນໂຄງການທີ່ເລືອກໄວ້ ຫຼື Simpan ke Download ເພື່ອໃຊ້ໄຟລ໌ PNG ຂອງມັນຢູ່ບ່ອນອື່ນ. ຫຼັງຈາກໂຄງການຖືກສ້າງແລ້ວ ແອັບຍັງສະເໜີໃຫ້ສ້າງໄອຄອນອີກດ້ວຍ. ໄອຄອນເກົ່າຂອງໂຄງການສາມາດປ່ຽນໄດ້ທຸກເວລາຈາກເມນູໂຄງການໃນ Kelola Project (ກົດຊື່ໂຄງການຄ້າງໄວ້ດົນ ແລ້ວເລືອກ Ganti Ikon).

Template Proyek Siap Pakai
ຖ້າບໍ່ຢາກເລີ່ມຈາກໂຄງການວ່າງເປົ່າ ໃຫ້ເລືອກແມ່ແບບເວລາສ້າງໂຄງການ: Kalkulator (Java), Catatan (Java), Daftar Tugas (Kotlin), Kalkulator Web (HTML), Situs Profil (Situs Web), ຫຼື Penghitung (Compose). ການເລືອກແມ່ແບບຈະປ່ຽນປະເພດໂຄງການໂດຍອັດຕະໂນມັດໃຫ້ກົງກັບແມ່ແບບນັ້ນ ແລະ ໂຄງການຈະຖືກສ້າງດ້ວຍໂຄດເລີ່ມຕົ້ນທີ່ພ້ອມແລ້ວ — ເຫຼືອພຽງເຮັດວຽກ ຫຼື ແກ້ໄຂມັນເທົ່ານັ້ນ. ຖ້າປະເພດໂຄງການຖືກປ່ຽນດ້ວຍມືອີກຄັ້ງຫຼັງຈາກເລືອກແມ່ແບບແລ້ວ ແມ່ແບບຈະຖືກຍົກເລີກ ແລະ ໂຄງການກັບໄປວ່າງເປົ່າອີກ. ສຳລັບແມ່ແບບ HTML ແລະ Situs Web ແມ່ແບບຈະປ່ຽນແທນເນື້ອໃນຂອງ index.html ລວມທັງສະຄຣິບ HTML ທີ່ພິມໄວ້ໃນແບບຟອມ.

Cadangan dan Pulihkan Proyek
ເພື່ອບໍ່ໃຫ້ໂຄງການຫາຍໄປ ຄຸນສົມບັດສຳຮອງຂໍ້ມູນມີໃຫ້ໃຊ້. ວິທີ: ໃນ Kelola Project ກົດຊື່ໂຄງການຄ້າງໄວ້ດົນ ແລ້ວເລືອກ Cadangkan. ຂໍ້ມູນສຳຮອງຈະຖືກບັນທຶກເປັນ ZIP ໃນໂຟນເດີ Download/backup ພ້ອມຊື່ໂຄງການ ແລະ ວັນທີ ຕົວຢ່າງ: GarudaDecode-2026-11-14-123045.zip. ເນື້ອໃນຂອງມັນຄືກັນກັບ Ekspor ZIP (ເນື້ອໃນໂຄງການທັງໝົດ ໂດຍບໍ່ມີໂຟນເດີ bin). ເພື່ອກູ້ຄືນ: ເປີດເມນູໃນ Kelola Project ເລືອກ Pulihkan cadangan ແລ້ວເລືອກໄຟລ໌ສຳຮອງຂອງມັນ. ຖ້າຊື່ໂຄງການມີຢູ່ແລ້ວ ແອັບຈະຖາມວ່າ: ຂຽນທັບໂຄງການເກົ່າ ຫຼື ບັນທຶກດ້ວຍຊື່ໃໝ່.

Bagikan dan Impor Proyek
ເພື່ອແບ່ງປັນໂຄງການໃຫ້ໝູ່: ໃນ Kelola Project ກົດຊື່ໂຄງການຄ້າງໄວ້ດົນ ແລ້ວເລືອກ Bagikan. ໂຄງການຈະຖືກສົ່ງເປັນ ZIP ຜ່ານແອັບແບ່ງປັນ (WhatsApp, Telegram, ແລະ ອື່ນໆ). ເພື່ອຮັບໂຄງການຈາກໝູ່: ເປີດເມນູໃນ Kelola Project ເລືອກ Impor proyek ແລ້ວເລືອກໄຟລ໌ ZIP ຂອງມັນ. ໄຟລ໌ ZIP ນັ້ນຕ້ອງມີໄຟລ໌ຂໍ້ມູນໂຄງການ — ຖ້າບໍ່ມີ ໄຟລ໌ຈະຖືກປະຕິເສດດ້ວຍຂໍ້ຄວາມທີ່ຊັດເຈນ ເພາະໄຟລ໌ນັ້ນບໍ່ແມ່ນໂຄງການ Create Aplikasi. ຖ້າຊື່ໂຄງການມີຢູ່ແລ້ວ ແອັບຈະຖາມວ່າ: ຂຽນທັບໂຄງການເກົ່າ ຫຼື ບັນທຶກດ້ວຍຊື່ໃໝ່.

Pencarian dan Filter Proyek
ຖ້າໂຄງການມີຫຼາຍແລ້ວ ໃນ Kelola Project ມີກ່ອງຄົ້ນຫາ ແລະ ຕົວກັ່ນຕອງປະເພດ. ພິມຊື່ໂຄງການໃນກ່ອງຄົ້ນຫາ ລາຍການຈະຖືກກັ່ນຕອງທັນທີ (ຕົວອັກສອນໃຫຍ່ ແລະ ຕົວອັກສອນນ້ອຍບໍ່ໄດ້ແຍກແຍະ). ຕົວກັ່ນຕອງປະເພດຈະຈຳກັດລາຍການໃຫ້ເຫຼືອພຽງປະເພດດຽວ: Semua, HTML, Situs Web, Java, Kotlin, Compose, ຫຼື Python. ເມນູຂອງແຕ່ລະໂຄງການຍັງສາມາດເປີດໄດ້ຕາມປົກກະຕິຈາກລາຍການທີ່ກັ່ນຕອງແລ້ວ.

ສ້າງແອັບດ້ວຍສຽງ
ຖ້າບໍ່ຕ້ອງການພິມ ໃຫ້ໃຊ້ສຽງ: ກົດ ສ້າງດ້ວຍສຽງ ໃນເມນູຫຼັກ ແລ້ວເວົ້າຄຳສັ່ງ. ຄຳສັ່ງທີ່ສາມາດເວົ້າໄດ້: "Buat proyek kalkulator", "Bangun proyek Kalkulator", "Buka proyek Kalkulator", "Jalankan proyek Kalkulator", "Daftar proyek", "Buka ikon", "Kembali" ແລະ "Bantuan". ແອັບຕອບດ້ວຍສຽງ ແລະ ຂໍ້ຄວາມ ດັ່ງນັ້ນຍັງໃຊ້ງານໄດ້ໂດຍບໍ່ຕ້ອງເບິ່ງໜ້າຈໍ. ການຮັບຮູ້ສຽງໃຊ້ແອັບຮັບຮູ້ສຽງທີ່ຕິດຕັ້ງມາໃນໂທລະສັບ (ຟຣີ; ສາມາດເຮັດວຽກອອບລາຍໄດ້ຖ້າຕິດຕັ້ງຊຸດພາສາອິນໂດເນເຊຍແລ້ວ). ຖ້າໂທລະສັບບໍ່ມີການຮັບຮູ້ສຽງ ຄຳສັ່ງສາມາດພິມໃນກ່ອງຂໍ້ຄວາມໃນໜ້າຈໍດຽວກັນໄດ້.

AI ຕົວສ້າງແອັບ
ໃນໜ້າຈໍ AI ຜູ້ສ້າງແອັບ ໃຫ້ພິມ ຫຼື ເວົ້າຜ່ານໄມໂຄຣໂຟນແອັບທີ່ທ່ານຕ້ອງການ, ຕົວຢ່າງ - «ແອັບບັນທຶກທີ່ມີປຸ່ມບັນທຶກ». ແອັບວິເຄາະຄຳສຳຄັນໃນໂທລະສັບ (ໂດຍບໍ່ມີອິນເຕີເນັດ, ບໍ່ເສຍຄ່າ) ແລ້ວສ້າງໂຄງການຈິງຈາກແມ່ແບບທີ່ເໝາະສົມທີ່ສຸດ - ເຄື່ອງຄິດໄລ່, ບັນທຶກ, ລາຍການວຽກ, ເຄື່ອງຄິດໄລ່ເວັບ, ເວັບໄຊໂປຣໄຟລ໌ ຫຼື ເຄື່ອງນັບ. ຖ້າຍັງບໍ່ມີແມ່ແບບທີ່ກົງກັບຄຳອະທິບາຍຂອງທ່ານ ແອັບຈະສ້າງໂຄງການວ່າງ ແລະ ເວົ້າຕາມຄວາມຈິງ — ມັນບໍ່ແກ້ງທຳວ່າເຂົ້າໃຈ. ໂຄງການທີ່ AI ສ້າງສາມາດເປີດໄດ້ໂດຍກົງໃນ ຈັດການໂຄງການ.

ຕົວຢ່າງສົດໄປຫາໂທລະສັບຂອງໝູ່
ເພື່ອສະແດງໂຄງການໃຫ້ໝູ່ກ່ອນສ້າງ — ໃນ ຈັດການໂຄງການ ໃຫ້ກົດຄ້າງຊື່ໂຄງການ ແລະ ເລືອກ ສະແດງຕົວຢ່າງໂດຍກົງໄປຍັງໂທລະສັບຂອງໝູ່. ແອັບສ້າງຊຸດສະແດງຕົວຢ່າງນ້ອຍທີ່ມີໄຟລ໌ຫຼັກຂອງໂຄງການ (index.html, MainActivity ຫຼື main.py) ພ້ອມກັບໄຟລ໌ ອ່ານ-ຂ້ອຍ.txt ແລະ info.txt ທີ່ມີຄຳແນະນຳ. ຊຸດຖືກສົ່ງເປັນ ZIP ຜ່ານ WhatsApp ຫຼື Telegram. ໝູ່ທີ່ໄດ້ຮັບສາມາດເປີດການສະແດງຕົວຢ່າງໄດ້ໂດຍກົງ — ໜ້າ HTML ເປີດໃນບຣາວເຊີ, ລະຫັດ Java/Kotlin/Python ຖືກອ່ານເປັນຂໍ້ຄວາມ.

ຕະຫຼາດໂຄງການ
ຕະຫຼາດໂຄງການ ມີໂຄງການຕົວຢ່າງທີ່ສາມາດເພີ່ມເຂົ້າໂຟລເດີໂຄງການຂອງທ່ານໄດ້ດ້ວຍການກົດດຽວ — ເຄື່ອງຄິດໄລ່, ບັນທຶກ, ລາຍການວຽກ, ເຄື່ອງຄິດໄລ່ເວັບ, ເວັບໄຊໂປຣໄຟລ໌, ເຄື່ອງນັບ, ໂມງດິຈິຕອນ ແລະ ແບບສອບຖາມເວັບ. ຍັງບໍ່ມີຕະຫຼາດອອນໄລນ໌ (ດາວໂຫຼດຕົວຢ່າງຈາກອິນເຕີເນັດ), ສະນັ້ນຕະຫຼາດນີ້ມີຕົວຢ່າງທີ່ມີຢູ່ໃນແອັບແລ້ວ. ໂຄງການທີ່ເພີ່ມເຂົ້າສາມາດເປີດ ແລະ ແກ້ໄຂໄດ້ໃນ ຈັດການໂຄງການ ເຊັ່ນດຽວກັບໂຄງການທີ່ທ່ານສ້າງເອງ.

ການຮ່ວມມືໂດຍກົງ
ເພື່ອເຮັດວຽກໃນໂຄງການໜຶ່ງກັບໝູ່ — ເປີດ ການຮ່ວມມື ໃນເມນູຫຼັກ, ເລືອກໂຄງການ, ຂຽນບັນທຶກການປ່ຽນແປງ (ມີຫຍັງປ່ຽນແປງ) ແລະ ກົດ ແບ່ງປັນສຳລັບການຮ່ວມມື. ໂຄງການຖືກສົ່ງເປັນ ZIP ພ້ອມໄຟລ໌ CATATAN.txt ຢູ່ຂ້າງໃນ. ໝູ່ຂອງທ່ານເຮັດວຽກມັນ ແລະ ສົ່ງ ZIP ກັບຄືນ. ທ່ານກົດ ຮັບຄຳຕອບ, ອ່ານບັນທຶກການປ່ຽນແປງກ່ອນ, ຈາກນັ້ນເລືອກ ນຳໃຊ້ ເພື່ອແທນທີ່ໂຄງການເກົ່າ ຫຼື ຍົກເລີກ ຖ້າທ່ານປ່ຽນໃຈ. ZIP ທີ່ບໍ່ມີ CATATAN.txt ບໍ່ແມ່ນຊຸດການຮ່ວມມື — ສຳລັບ ZIP ໂຄງການທຳມະດາ ໃຫ້ໃຊ້ ນຳເຂົ້າໂຄງການ ໃນ ຈັດການໂຄງການ.

ຕົວແປແອັບອັດຕະໂນມັດ
ເພື່ອແປຂໍ້ຄວາມຂອງແອັບເປັນພາສາອື່ນ — ເປີດ ຜູ້ແປແອັບ ໃນເມນູຫຼັກ, ເລືອກໂຄງການ ແລະ ພາສາເປົ້າໝາຍ (ອັງກິດ, ອາຣັບ ຫຼື ຍີ່ປຸ່ນ) ແລະ ກົດ ແປ. ວັດຈະນານຸກົມມີຢູ່ໃນໂທລະສັບແລ້ວ (ໂດຍບໍ່ມີອິນເຕີເນັດ, ບໍ່ເສຍຄ່າ) ແລະ ມີຄຳສັບປະຈຳວັນ. ຂໍ້ຄວາມຖືກອ່ານຈາກ strings.xml, ຮູບແບບ ແລະ ລະຫັດ ແລະ ຖືກແປ. ຜົນໄດ້ຮັບຖືກຂຽນໃສ່ໂຟລເດີ values-ພາສາ/strings.xml (ຖ້າໂຄງການມີ strings.xml) ແລະ ບົດລາຍງານ terjemahan-ພາສາ.txt ໃນໂຟລເດີໂຄງການ. ຄຳສັບທີ່ຍັງບໍ່ມີໃນວັດຈະນານຸກົມຖືກປະໄວ້ຕາມເດີມ ແລະ ຖືກລາຍງານ — ສະນັ້ນທ່ານຮູ້ວ່າຄຳໃດທີ່ທ່ານຕ້ອງແປເອງ.

ຕົວສ້າງເກມໂດຍບໍ່ຕ້ອງໃຊ້ລະຫັດ
ເພື່ອສ້າງເກມໂດຍບໍ່ຂຽນລະຫັດ — ເປີດ ຜູ້ສ້າງເກມໂດຍບໍ່ມີລະຫັດ ໃນເມນູຫຼັກ, ເລືອກປະເພດເກມ (ເດົາຕົວເລກ, ແບບສອບຖາມ ຫຼື ຈັບດາວ), ຕື່ມຊື່ເກມ, ຈຳນວນ (ລະດັບ/ຄຳຖາມ/ດາວ) ແລະ ຂໍ້ຄວາມຊະນະ ແລະ ກົດ ສ້າງເກມ. ເກມຖືກສ້າງເປັນໂຄງການຈິງທີ່ສາມາດແລ່ນໄດ້ໂດຍກົງໃນ ຈັດການໂຄງການ ແລະ ສ້າງເປັນ APK ເຊັ່ນດຽວກັບໂຄງການອື່ນໆ.

ທົດສອບແອັບອັດຕະໂນມັດ
ເພື່ອກວດສອບໂຄງການກ່ອນສ້າງ — ໃນ ຈັດການໂຄງການ ໃຫ້ກົດຄ້າງຊື່ໂຄງການ ແລະ ເລືອກ ການທົດສອບອັດຕະໂນມັດ. IDE ກວດສອບ 10 ສິ່ງໂດຍບໍ່ສ້າງ APK — ໄຟລ໌ທີ່ຈຳເປັນມີຢູ່ (ໄຟລ໌ຂໍ້ມູນໂຄງການ, manifest, ໄຟລ໌ຫຼັກ, ຮູບແບບ, ສະຕຣິງ), ຊື່ແພັກເກັດ ແລະ ເວີຊັນ, ສິດອະນຸຍາດທີ່ໃຊ້, ໄອຄອນ ແລະ ຄວາມສົມດຸນຂອງວົງເລັບລະຫັດ. ຜົນໄດ້ຮັບຖືກສະແດງລາຍການລະອັນ (ພ້ອມຂໍ້ຄວາມສຳເລັດ/ລົ້ມເຫຼວ) ແລະ Jieshuo ອ່ານມັນດ້ວຍສຽງ. ແກ້ໄຂສິ່ງທີ່ລົ້ມເຫຼວກ່ອນ, ຈາກນັ້ນກົດ ສ້າງໂຄງການ.

AI ກວດສອບລະຫັດ
ເພື່ອກວດສອບລະຫັດໂຄງການສຳລັບຮູບແບບທີ່ມັກກໍ່ໃຫ້ເກີດບັນຫາ — ເປີດ ກວດສອບລະຫັດ ໃນເມນູຫຼັກ, ເລືອກໂຄງການ ແລະ ກົດ ກວດສອບລະຫັດ. ຕົວກວດສອບເຮັດວຽກໃນໂທລະສັບ (ໂດຍບໍ່ມີອິນເຕີເນັດ) ແລະ ຊອກຫາຕົວແປທີ່ບໍ່ໄດ້ໃຊ້, ຟັງຊັນວ່າງ, ລູບທີ່ບໍ່ມີທີ່ສິ້ນສຸດທີ່ຊັດເຈນ, ຂໍ້ຄວາມທີ່ຂຽນໂດຍກົງໃສ່ລະຫັດ (ດີກວ່າໃນ strings.xml), ສິດອະນຸຍາດ ແລະ API ທີ່ອັນຕະລາຍ, ເຄື່ອງໝາຍ TODO/FIXME ແລະ ການເຄື່ອນໄຫວທີ່ກຳລັງແລ່ນ. ການຄົ້ນພົບແຕ່ລະອັນລວມມີຊື່ໄຟລ໌, ເລກແຖວ ແລະ ຄຳແນະນຳສຳລັບການແກ້ໄຂ. ຕົວກວດສອບນີ້ແມ່ນອີງໃສ່ຮູບແບບ ແລະ ບໍ່ແມ່ນ AI ທີ່ແທ້ຈິງ — ບັນຫາທີ່ບໍ່ປະຕິບັດຕາມຮູບແບບອາດຍັງພາດໄດ້.

ໂໝດການຮຽນແບບໂຕ້ຕອບ
ເພື່ອຮຽນຮູ້ການສ້າງແອັບເທື່ອລະຂັ້ນຕອນ — ເປີດ ໂໝດການຮຽນ ໃນເມນູຫຼັກ. ມີບົດຮຽນ 5 ບົດ — ສ້າງໂຄງການທຳອິດຂອງທ່ານ, ເພີ່ມປຸ່ມ, ປ່ຽນສີ, ເພີ່ມສຽງ ແລະ ສ້າງ APK. ແຕະບົດຮຽນເພື່ອອ່ານຄຳອະທິບາຍ ແລະ ວຽກຝຶກຫັດ, ເຮັດວຽກ ແລະ ກົດ ກວດສອບວຽກ — IDE ກວດສອບຢ່າງແທ້ຈິງວ່າວຽກສຳເລັດແລ້ວຫຼືບໍ່ (ໂດຍການສະແກນໂຄງການ ແລະ APK ຂອງທ່ານໃນໂທລະສັບ). ບົດຮຽນທີ່ສຳເລັດຢ່າງສຳເລັດຜົນຖືກໝາຍວ່າສຳເລັດ ແລະ ຖືກບັນທຶກໄວ້.

ຊິ້ງຄ໌ Cloud
ເພື່ອສຳຮອງໂຄງການໄປຍັງ Cloud — ເປີດ ຊິ້ງຄລາວດ໌ ໃນເມນູຫຼັກ. ການສຳຮອງໃນທ້ອງຖິ່ນບັນທຶກໂຄງການ ZIP ທີ່ມີຕາປະທັບເວລາໃສ່ໂຟລເດີ Download/cloud ແລະ ສາມາດກູ້ຄືນໄດ້ທຸກເວລາຈາກລາຍການສຳຮອງ. ການສຳຮອງ GitHub ອັບໂຫຼດໂຄງການ ZIP ໄປຍັງ repo ສ່ວນຕົວຂອງທ່ານ (ໂດຍໃຊ້ໂທເຄັນຈາກ ການຕັ້ງຄ່າ GitHub) ແລະ ສາມາດດາວໂຫຼດກັບຄືນໄດ້. ນີ້ແມ່ນການສຳຮອງ ແລະ ກູ້ຄືນດ້ວຍຕົນເອງ — ການຊິ້ງສອງທາງອັດຕະໂນມັດຢ່າງເຕັມທີ່ຕ້ອງການເຊີບເວີ, ສະນັ້ນຍັງບໍ່ມີເທື່ອ.

ຜູ້ສ້າງ Backend ອັດຕະໂນມັດ
ເພື່ອສ້າງ Backend ໂດຍບໍ່ຂຽນລະຫັດເຊີບເວີ — ເປີດ ຜູ້ສ້າງ Backend ໃນເມນູຫຼັກ, ເລືອກປະເພດ Backend (ບັນທຶກ, ລາຍການວຽກ ຫຼື ກະດານປະກາດ), ຕື່ມຊື່ໂຄງການ ແລະ ກົດ ສ້າງ Backend. IDE ສ້າງໂຄງການ HTML ຈິງທີ່ມີໜ້າຟອມ ແລະ ລາຍການຂໍ້ມູນທີ່ບັນທຶກໄວ້ໃນບ່ອນເກັບຂໍ້ມູນທ້ອງຖິ່ນຂອງໂທລະສັບ (localStorage) — ຂໍ້ມູນຖືກບັນທຶກ ແລະ ອ່ານກັບຄືນເມື່ອແອັບແລ່ນ. Backend ນີ້ເຮັດວຽກຢູ່ໃນໂທລະສັບໜຶ່ງເຄື່ອງ. ບໍ່ມີເຊີບເວີອິນເຕີເນັດ, ສະນັ້ນໂທລະສັບສອງເຄື່ອງຍັງບໍ່ສາມາດແບ່ງປັນຂໍ້ມູນດຽວກັນໄດ້.

ຕົວອອກແບບຮູບແບບອັດຕະໂນມັດ
ເພື່ອໃຫ້ໂຄງການມີສີ Theme — ເປີດ ຕົວອອກແບບຮູບແບບ ໃນເມນູຫຼັກ, ເລືອກໂຄງການ ແລະ Theme (ສະຫວ່າງ, ມືດ, ສີຟ້າ, ສີຂຽວ, ສີແດງ ຫຼື ສີມ່ວງ). ການສະແດງຕົວຢ່າງສະແດງສີ 6 ສີຂອງ Theme (ຫຼັກ, ຫຼັກມືດ, ສຳນຽງ, ພື້ນຫຼັງ, ຂໍ້ຄວາມ, ຂໍ້ຄວາມຮອງ) ແລະ Jieshuo ອ່ານມັນດ້ວຍສຽງ. ກົດ ນຳໃຊ້ Theme — IDE ຂຽນ colors.xml ແລະ styles.xml (ຮູບແບບ app_theme) ເຂົ້າໂຄງການ, ເຊິ່ງຖືກໃຊ້ໂດຍກົງເມື່ອໂຄງການແລ່ນ ຫຼື ຖືກສ້າງ.

ຕົວສ້າງອະນິເມຊັນ
ເພື່ອໃຫ້ໂຄງການມີອະນິເມຊັນ — ເປີດ ຜູ້ສ້າງອະນິເມຊັນ ໃນເມນູຫຼັກ, ເລືອກໂຄງການ, ປະເພດອະນິເມຊັນ (ຈາງ, ເລື່ອນ, ໝຸນ, ເຕັ້ນ ຫຼື ເຕັ້ນຂຶ້ນ), ໄລຍະເວລາ (100 ຫາ 10000 ມິນລິວິນາທີ) ແລະ ເປົ້າໝາຍ (ປຸ່ມ, ຂໍ້ຄວາມ ຫຼື ຮູບພາບ) ແລະ ກົດ ສ້າງອະນິເມຊັນ. IDE ຂຽນໄຟລ໌ອະນິເມຊັນຈິງ (res/anim/anim_<ປະເພດ>.xml ສຳລັບໂຄງການ Java/Kotlin/Compose ຫຼື animasi.css ສຳລັບໂຄງການ HTML/ເວັບໄຊ) ພ້ອມກັບລະຫັດຕົວຢ່າງການໃຊ້ທີ່ສະແດງຢູ່ໃນໜ້າຈໍ.

ຕົວບັນທຶກການກະທຳ
ເພື່ອເຮັດວຽກຊ້ຳອັດຕະໂນມັດ — IDE ບັນທຶກການກະທຳທີ່ທ່ານໄດ້ເຮັດ (ເປີດໂຄງການ, ແລ່ນ, ສ້າງ, ສົ່ງອອກ, ສຳຮອງ, ສ້າງໂຄງການ, ບັນທຶກໄຟລ໌). ເປີດ ຜູ້ບັນທຶກການກະທຳ ໃນເມນູຫຼັກ ແລະ ເບິ່ງລາຍການການກະທຳທີ່ບັນທຶກໄວ້ພ້ອມລຳດັບຂອງມັນ ແລະ ກົດ ຫຼິ້ນຊ້ຳ — IDE ເຮັດການກະທຳທີ່ສາມາດເຮັດອັດຕະໂນມັດຊ້ຳ (ການສຳຮອງ ແລະ ການສ້າງໂຄງການຖືກເຮັດຢູ່ບ່ອນນັ້ນ. ການແລ່ນ, ການສ້າງ ແລະ ການສົ່ງອອກເປີດໜ້າຈໍຫຼັກຂອງມັນ. ການເປີດ ແລະ ການບັນທຶກເປີດຕົວແກ້ໄຂ). ການກະທຳທີ່ບໍ່ສາມາດເຮັດອັດຕະໂນມັດໄດ້ຖືກຂ້າມ ແລະ ຖືກລາຍງານໃນຕອນທ້າຍ.

ຄວາມປອດໄພອັດຕະໂນມັດ
ເພື່ອກວດສອບຄວາມປອດໄພຂອງໂຄງການ — ເປີດ ຄວາມປອດໄພອັດຕະໂນມັດ ໃນເມນູຫຼັກ, ເລືອກໂຄງການ ແລະ ກົດ ກວດສອບຄວາມປອດໄພ. IDE ກວດສອບ 8 ສິ່ງໃນທ້ອງຖິ່ນ (ໂດຍບໍ່ມີອິນເຕີເນັດ) — ສິດອະນຸຍາດທີ່ອັນຕະລາຍ (ສະຖານທີ່, SMS, ການໂທ, ກ້ອງຖ່າຍຮູບ, ໄມໂຄຣໂຟນ, ລາຍຊື່ຜູ້ຕິດຕໍ່), ການສົ່ງຂໍ້ມູນຜ່ານ HTTP, ການສົ່ງ SMS, ການໂທອອກ, ລະຫັດຜ່ານ ຫຼື ກະແຈທີ່ຂຽນໂດຍກົງໃສ່ລະຫັດ, WebView ທີ່ບໍ່ໄດ້ຮັບການປົກປ້ອງ, ສ່ວນປະກອບທີ່ສົ່ງອອກໂດຍບໍ່ມີສິດອະນຸຍາດ ແລະ ທີ່ຢູ່ http ທີ່ບໍ່ໄດ້ເຂົ້າລະຫັດ. ການຄົ້ນພົບແຕ່ລະອັນໄດ້ຮັບລະດັບປອດໄພ, ເຕືອນ ຫຼື ອັນຕະລາຍພ້ອມຄຳແນະນຳສຳລັບການແກ້ໄຂ ແລະ ບົດສະຫຼຸບຖືກ Jieshuo ອ່ານດ້ວຍສຽງ.

AI ອອບລາຍ
ເພື່ອໃຊ້ການຊ່ວຍເຫຼືອຂໍ້ຄວາມ ແລະ ລະຫັດໂດຍບໍ່ມີອິນເຕີເນັດ — ເປີດ AI ອອບໄລນ໌ ໃນເມນູຫຼັກ. ມີເຄື່ອງມື 4 ຢ່າງ — ແກ້ໄຂຂໍ້ຄວາມ (ຕົວອັກສອນໃຫຍ່, ເຄື່ອງໝາຍວັກຕອນ ແລະ ຊ່ອງຫວ່າງສອງເທົ່າ), ສະຫຼຸບຂໍ້ຄວາມ (ເອົາປະໂຫຍກທີ່ສຳຄັນທີ່ສຸດ 3 ປະໂຫຍກ), ສ້າງຊື່ແອັບ (ຈາກຄຳອະທິບາຍທີ່ຂຽນໄວ້) ແລະ ແນະນຳຊື່ຕົວແປ (ຊອກຫາຊື່ຕົວແປ 1–2 ຕົວອັກສອນໃນໂຄງການ). ເຫຼົ່ານີ້ແມ່ນກົດລະບຽບງ່າຍໆໃນໂທລະສັບ, ບໍ່ແມ່ນໂມເດວ AI ທີ່ແທ້ຈິງ. ຜົນໄດ້ຮັບການແກ້ໄຂຂໍ້ຄວາມສາມາດນຳໃຊ້ກັບ strings.xml ຂອງໂຄງການດ້ວຍປຸ່ມ ນຳໃຊ້.

ຕົວສ້າງ Widget & Wallpaper
ເພື່ອສ້າງ Widget ສຳລັບໜ້າຈໍຫຼັກ — ເປີດ Widget ແລະ Wallpaper ໃນເມນູຫຼັກ, ເລືອກໂຄງການ, ຕື່ມຂໍ້ຄວາມ Widget ແລະ ກົດ ສ້າງ Widget. IDE ຂຽນ WidgetSaya.java, ຮູບແບບ Widget, ຂໍ້ມູນ Widget ແລະ ເພີ່ມຕົວຮັບເຂົ້າ AndroidManifest.xml ຂອງໂຄງການ — ສ້າງໂຄງການ ແລະ ເພີ່ມ Widget ຈາກໜ້າຈໍຫຼັກຂອງໂທລະສັບ. ສຳລັບ Wallpaper — ຕື່ມຂໍ້ຄວາມ ແລະ ສີພື້ນຫຼັງ ແລະ ສີຂໍ້ຄວາມ, ເຮັດການສະແດງຕົວຢ່າງ ແລະ ບັນທຶກເປັນ PNG ໃສ່ໂຟລເດີ Download ຫຼື ຕັ້ງໂດຍກົງເປັນ Wallpaper ໂທລະສັບ.

ການເຊື່ອມໂຍງສື່ສັງຄົມ
ເພື່ອເພີ່ມປຸ່ມແບ່ງປັນເຂົ້າແອັບ — ເປີດ ການເຊື່ອມໂຍງສື່ສັງຄົມ ໃນເມນູຫຼັກ, ເລືອກໂຄງການ ແລະ ເພີ່ມການແບ່ງປັນໄປ WhatsApp, Facebook ຫຼື Telegram (ຫຼື ທັງສາມຢ່າງພ້ອມກັນ). IDE ຂຽນລະຫັດແບ່ງປັນຈິງເຂົ້າໄຟລ໌ຫຼັກຂອງໂຄງການ (MainActivity ຫຼື index.html). ປຸ່ມ ທົດສອບການແບ່ງປັນ ເປີດຕົວເລືອກການແບ່ງປັນຈາກ IDE ດ້ວຍຂໍ້ຄວາມຕົວຢ່າງ, ສະນັ້ນທ່ານສາມາດຮູ້ສຶກເຖິງການໄຫຼກ່ອນສ້າງແອັບ.

ແອັບຈາກຮູບພາບ
ເພື່ອສ້າງແອັບຫໍຮູບພາບຈາກຮູບພາບ — ເປີດ ແອັບຈາກຮູບພາບ ໃນເມນູຫຼັກ ແລະ ເລືອກຮູບພາບຈາກຫໍຮູບພາບ. IDE ວິເຄາະຂະໜາດ ແລະ ສີຫຼັກຂອງຮູບພາບ ແລະ ສ້າງໂຄງການແອັບຫໍຮູບພາບຈິງ — ຮູບພາບຖືກຄັດລອກເຂົ້າ assets ຂອງໂຄງການ, ສີ Theme ຖືກເອົາຈາກສີຫຼັກຂອງຮູບພາບ, ຊື່ແອັບຖືກເອົາຈາກຊື່ໄຟລ໌ຮູບພາບ. ເປີດ ຈັດການໂຄງການ ເພື່ອແລ່ນ ຫຼື ສ້າງແອັບຫໍຮູບພາບ.

Terminal ແບບໂຕ້ຕອບ (ຕົວວິເຄາະ VT)
ເພື່ອໃຊ້ໂປຣແກຣມແບບໂຕ້ຕອບໃນ Terminal — ເປີດ Terminal ໃນເມນູຫຼັກ ແລະ ແລ່ນ nano, vim, top ຫຼື htop. Terminal ດຽວນີ້ໃຊ້ຕົວວິເຄາະ VT (ຕາຕະລາງໜ້າຈໍ 24 ແຖວ x 80 ຖັນ) ສະນັ້ນໂປຣແກຣມເຫຼົ່ານີ້ຖືກສະແດງຢ່າງຖືກຕ້ອງ — ຕົວຊີ້ຍ້າຍ, ແຖວຖືກລຶບ, ໜ້າຈໍປ່ຽນແປງເໝືອນ Terminal ຈິງ. ມີປຸ່ມພິເສດສຳລັບ Tab, ລູກສອນຂຶ້ນ, ລູກສອນລົງ ແລະ Esc ເພື່ອຄວບຄຸມໂປຣແກຣມແບບໂຕ້ຕອບ. ຜົນໄດ້ຮັບຍັງຄົງເປັນຂໍ້ຄວາມທີ່ Jieshuo ສາມາດອ່ານໄດ້. ກົດ ອ່ານໜ້າຈໍ ເພື່ອຟັງແຖວສຸດທ້າຍ.

Terminal Exec (ໄບນາຣີແອັບ)
ເພື່ອແລ່ນໄຟລ໌ໄບນາຣີຈາກໂຟລເດີແອັບ (ຕົວຢ່າງ aapt2, ECJ, D8) ຈາກ Terminal — ພິມຄຳສັ່ງຕາມປົກກະຕິ. IDE ໃຊ້ libkautsarexec.so, ສະນັ້ນໄຟລ໌ໄບນາຣີໃນໂຟລເດີແອັບສາມາດແລ່ນໄດ້ໃນ Android 10 ແລະ ໃໝ່ກວ່າ. ເພື່ອກວດສອບວ່າເສັ້ນທາງ exec ໄບນາຣີເຮັດວຽກຢູ່ໃນໂທລະສັບນີ້ຫຼືບໍ່ ໃຫ້ກົດ ທົດສອບ Exec ໃນ Terminal — ຜົນໄດ້ຮັບຖືກສະແດງຕາມທີ່ມັນເປັນ. ຖ້າລະບົບບລັອກ exec, ຄຳສັ່ງລະບົບ ແລະ shell script ຍັງສືບຕໍ່ເຮັດວຽກ. ແລ່ນໄຟລ໌ໄບນາຣີຜ່ານເມນູ ສ້າງໂຄງການ.

Terminal ຍັງເຮັດວຽກຕໍ່ (KeepAlive)
ເພື່ອຮັກສາ shell ໃຫ້ແລ່ນຕໍ່ໄປເມື່ອທ່ານປ່ຽນໜ້າຈໍ — ເປີດ Terminal, ແລ່ນຄຳສັ່ງ ແລະ ກົດ ກັບຄືນ ຫຼື ປ່ຽນໄປໜ້າຈໍອື່ນ — shell ບໍ່ຕາຍ, ການແຈ້ງເຕືອນ Terminal ຍັງສະແດງຢູ່, ສະນັ້ນທ່ານສາມາດກັບຄືນມາໄດ້ດ້ວຍການກົດດຽວ. ຄຳສັ່ງທີ່ແລ້ວຖືກບັນທຶກໄວ້ໃນ ປະຫວັດ (ປຸ່ມ ປະຫວັດ ຫຼື ລູກສອນຂຶ້ນ/ລົງໃນຊ່ອງຄຳສັ່ງ) ແລະ ຄຳສັ່ງທີ່ໃຊ້ເລື້ອຍໆສາມາດບັນທຶກເປັນ ລາຍການທີ່ມັກ (ປຸ່ມ ລາຍການທີ່ມັກ). ເມື່ອສຳເລັດ ໃຫ້ກົດ ປິດ shell ເພື່ອສິ້ນສຸດ shell ຢ່າງແທ້ຈິງ. ເມນູໂຄງການ ແລະ ເມນູຕົວແກ້ໄຂຍັງມີປຸ່ມ ສ້າງໃນ Terminal — Terminal ເປີດໃນໂຟລເດີໂຄງການພ້ອມຄຳສັ່ງສ້າງທີ່ຕື່ມໄວ້ລ່ວງໜ້າ.

ຕິດຕັ້ງເຄື່ອງມື Terminal (ທົດລອງ)
ຄຸນສົມບັດທົດລອງ — ໃນ Terminal ມີປຸ່ມ ຕິດຕັ້ງເຄື່ອງມື Terminal (ທົດລອງ) ເພື່ອຕິດຕັ້ງສະພາບແວດລ້ອມ Termux ຈາກ repo alat-termux ຂອງຜູ້ພັດທະນາ (github.com/syudat/alat-termux) ເປັນເສັ້ນທາງທາງເລືອກເພີ່ມເຕີມນອກເໜືອຈາກປຸ່ມ ຕິດຕັ້ງ Termux ທີ່ເອົາມາຈາກການປ່ອຍ Termux ຢ່າງເປັນທາງການ. ເນື້ອໃນຂອງກະຈົກແມ່ນຄືກັນກັບການປ່ອຍຢ່າງເປັນທາງການ ແລະ ຖືກກວດສອບໂດຍ SHA-256 ໃນລະຫວ່າງການຕິດຕັ້ງ. ຫຼັງຈາກສະພາບແວດລ້ອມຖືກຕິດຕັ້ງ ທ່ານສາມາດໃຊ້ຄຳສັ່ງ pkg update ແລະ pkg install ແລະ ເຄື່ອງມືເພີ່ມເຕີມຈາກ repo ກໍ່ຖືກຕິດຕັ້ງເຂົ້າ terminal — info-terminal ເພື່ອເບິ່ງຂໍ້ມູນສະພາບແວດລ້ອມ, bersih-terminal ເພື່ອລ້າງແຄສ ແລະ cadangkan-proyek ເພື່ອບັນທຶກໂຟລເດີໂຄງການເຂົ້າໄຟລ໌ tar.gz ດຽວທີ່ມີວັນທີ. ຈາກນັ້ນແອັບຈະຕິດຕັ້ງແພັກເກັດ Linux ພື້ນຖານໂດຍອັດຕະໂນມັດ (git, python, curl, wget, nano, openssh, zip, unzip) ແລະ ເຄື່ອງມືສ້າງ APK ທີ່ລົງນາມ (openjdk-21, kotlin, gradle, ecj, aapt2, d8, apksigner, clang, cmake, ninja, make) ຈາກ repo Termux ຢ່າງເປັນທາງການ, ສະນັ້ນ terminal ພ້ອມທັນທີທີ່ຈະສ້າງແອັບ. ການດາວໂຫຼດແພັກເກັດໃຫຍ່ (ຫຼາຍຮ້ອຍ MB) ອາດໃຊ້ເວລາດົນ. ໃນຂະນະທີ່ການຕິດຕັ້ງກຳລັງດຳເນີນຢູ່ ຄວາມຄືບໜ້າ ແລະ ຜົນໄດ້ຮັບຄຳສັ່ງຖືກສະແດງຢູ່ໃນໜ້າຈໍຫຼັກຂອງ Terminal ແລະ ຜົນໄດ້ຮັບສຸດທ້າຍຖືກອ່ານດ້ວຍສຽງໂດຍຕົວອ່ານໜ້າຈໍ. ຖ້າການຕິດຕັ້ງແພັກເກັດຍັງບໍ່ສຳເລັດ ໃຫ້ກົດ ຕິດຕັ້ງເຄື່ອງມື Terminal (ທົດລອງ) ອີກຄັ້ງເພື່ອສືບຕໍ່.

ໂໝດສຽງເຕັມຮູບແບບ
ເພື່ອຄວບຄຸມ IDE ທັງໝົດດ້ວຍສຽງ — ເປີດ ໂໝດສຽງເຕັມ ໃນເມນູຫຼັກ ແລະ ກົດ ເລີ່ມຟັງ. IDE ຟັງຢ່າງຕໍ່ເນື່ອງ — ບໍ່ຈຳເປັນຕ້ອງກົດປຸ່ມສຳລັບຄຳສັ່ງແຕ່ລະອັນ — ດຳເນີນການຄຳສັ່ງ ແລະ ຕອບດ້ວຍສຽງ. ມີຄຳສັ່ງ 26 ຄຳສັ່ງ — ສ້າງ, ສ້າງໂຄງການ, ເປີດ, ແລ່ນ, ລາຍຊື່, ຊອກຫາ, ລຶບ, ທົດສອບ, ກວດສອບ, ສົ່ງອອກ, ສຳຮອງ, ແບ່ງປັນ, ສ້າງໄອຄອນ, ແປ, ສ້າງໃນ Terminal, ອ່ານໜ້າຈໍ, ເປີດໜ້າຈໍທັງໝົດ (ລວມທັງຄວາມປອດໄພ, AI ອອບໄລນ໌, Widget, ສື່ສັງຄົມ, ເກມ, ການຮຽນ, Cloud, Backend, Theme, ອະນິເມຊັນ, ຜູ້ບັນທຶກ), ກັບຄືນ, ປິດ ແລະ ຊ່ວຍເຫຼືອ. ຖ້າໂໝດຍັງຄົງມີການເຄື່ອນໄຫວ ການຟັງຈະສືບຕໍ່ໂດຍອັດຕະໂນມັດເມື່ອທ່ານເປີດໜ້າຈໍນີ້ຄືນ. ເພື່ອປິດໂໝດ ໃຫ້ກົດ ຢຸດຟັງ. ຖ້າໂທລະສັບບໍ່ມີບໍລິການຈຳສຽງ ຄຳສັ່ງຍັງສາມາດພິມໃນໜ້າຂໍ້ຄວາມໄດ້.

ຕົວແປໂຄດ
ເພື່ອແປລະຫັດລະຫວ່າງພາສາໂດຍບໍ່ມີອິນເຕີເນັດ — ເປີດ ຜູ້ແປລະຫັດ ໃນເມນູຫຼັກ, ເລືອກໂຄງການ, ເລືອກໄຟລ໌ຕົ້ນສະບັບ (.java/.kt) ແລະ ເລືອກທິດທາງ — Java ໄປ Kotlin. ກົດ ແປ — ຜົນໄດ້ຮັບຖືກສະແດງພ້ອມບົດລາຍງານຂອງແຖວທີ່ບໍ່ສາມາດແປໄດ້ (ແຖວເຫຼົ່ານີ້ຖືກປະໄວ້ຕາມເດີມ ແລະ ຖືກໝາຍ). ກົດ ບັນທຶກຜົນໄດ້ຮັບ ເພື່ອຂຽນໄຟລ໌ໃໝ່ໃນໂຟລເດີດຽວກັນ (ຊື່-ແປ.java/.kt). ໄຟລ໌ຕົ້ນສະບັບບໍ່ເຄີຍຖືກແທນທີ່. ນີ້ແມ່ນຕົວແປຕາມຮູບແບບ, ບໍ່ແມ່ນຕົວຄອມໄພລ໌ — ກວດສອບຜົນໄດ້ຮັບສະເໝີກ່ອນໃຊ້ມັນ.

Git ໃນແອັບ
ເພື່ອໃຊ້ Git ໃນ IDE ໂດຍບໍ່ຕ້ອງການ Termux — ເປີດ Git ໃນແອັບ ໃນເມນູຫຼັກ, ເລືອກໂຄງການ ແລະ ກົດ ສ້າງ Git Repo ເພື່ອສ້າງ repo ທ້ອງຖິ່ນ (.git) ໃນໂຄງການນັ້ນ. ກົດ ກວດສອບສະຖານະ ເພື່ອເບິ່ງໄຟລ໌ໃໝ່, ປ່ຽນແປງ ຫຼື ລຶບທຽບກັບ Commit ລ່າສຸດ. ຕື່ມຂໍ້ຄວາມ Commit ແລະ ກົດ Commit ເພື່ອບັນທຶກພາບຖ່າຍຂອງໂຄງການ. ກົດ ເບິ່ງ Commit Log ເພື່ອເບິ່ງປະຫວັດ Commit. Push ໄປ GitHub ແລະ Pull ຈາກ GitHub ໃຊ້ພາບຖ່າຍຜ່ານໂທເຄັນ GitHub (repo pembuat-aplikasi-build) — ບໍ່ແມ່ນໂປໂຕຄອນ git. Clone, Push (system-git) ແລະ Pull (system-git) ເຮັດວຽກພຽງແຕ່ເມື່ອໄບນາຣີ git ຖືກຕິດຕັ້ງຢູ່ໃນໂທລະສັບ (ປົກກະຕິບໍ່ມີ). ນີ້ບໍ່ແມ່ນ Git ເຕັມຮູບແບບ — ບໍ່ມີການລວມ, ສາຂາ ຫຼື ຄວາມແຕກຕ່າງ — Commit ແຕ່ລະອັນບັນທຶກພາບຖ່າຍ ZIP ເຕັມຂອງໂຄງການ.

ຕົວສ້າງໂຄສະນາ
ເພື່ອເພີ່ມໂຄສະນາເຂົ້າແອັບທີ່ສ້າງແລ້ວ — ເປີດ ຜູ້ສ້າງໂຄສະນາ ໃນເມນູຫຼັກ, ເລືອກໂຄງການ, ຜູ້ໃຫ້ບໍລິການ (AdMob, Unity Ads ຫຼື AppLovin) ແລະ ປະເພດໂຄສະນາ (Banner, Interstitial ຫຼື ໄດ້ຮັບລາງວັນ). ຕື່ມ ID ໜ່ວຍໂຄສະນາຖ້າທ່ານມີ — ຖ້າວ່າງ ຈະໃຊ້ ID ທົດລອງ (AdMob ໃຊ້ ID ທົດລອງຢ່າງເປັນທາງການຂອງ Google. Unity ໃຊ້ Game ID ຕົວຢ່າງ. AppLovin ໃຊ້ບ່ອນວ່າງ). ກົດ ສ້າງລະຫັດໂຄສະນາ ເພື່ອເບິ່ງລະຫັດ Java ແລະ Kotlin ແລະ ຄຳແນະນຳ. ກົດ ບັນທຶກເຂົ້າໂຄງການ ເພື່ອຂຽນທຸກຢ່າງເຂົ້າໄຟລ໌ iklan-<ຜູ້ໃຫ້ບໍລິການ>-<ປະເພດ>.txt ໃນໂຄງການ. ນີ້ແມ່ນແມ່ແບບລະຫັດ + ຄຳແນະນຳ, ບໍ່ແມ່ນ SDK ໂຄສະນາ — SDK ບໍ່ໄດ້ລວມຢູ່ໃນ IDE. ໂຄສະນາຈິງປະກົດຂຶ້ນພຽງແຕ່ເມື່ອທ່ານສ້າງບັນຊີຜູ້ໃຫ້ບໍລິການ, ສ້າງໜ່ວຍໂຄສະນາ, ວາງ ID ໜ່ວຍຂອງທ່ານ ແລະ ເພີ່ມຄວາມເພິ່ງພາ SDK ເຂົ້າ build.gradle ຂອງໂຄງການ.

ໂໝດເດັກ
ເພື່ອໃຊ້ IDE ກັບເດັກ — ເປີດ ໂໝດເດັກ ໃນເມນູຫຼັກ. ໜ້າຈໍຖືກເຮັດໃຫ້ງ່າຍດາຍດ້ວຍປຸ່ມໃຫຍ່ ແລະ ມີພຽງການກະທຳທີ່ປອດໄພ 4 ຢ່າງ — ສ້າງໂຄງການ (ຈາກແມ່ແບບທີ່ປອດໄພ — ເຄື່ອງຄິດໄລ່, ເດົາຕົວເລກ, ແບບສອບຖາມ, ຈັບດາວ), ເປີດໂຄງການ, ແລ່ນ ແລະ ໂໝດການຮຽນ. ບໍ່ມີປຸ່ມລຶບ, ສົ່ງອອກ, ສຳຮອງ ຫຼື ຕັ້ງໂທເຄັນໃນໜ້າຈໍນີ້. ສ້າງ PIN 4 ຕົວເລກເມື່ອເຂົ້າຄັ້ງທຳອິດ — ພໍ່ແມ່ໃຊ້ PIN ນີ້ເພື່ອອອກຈາກໂໝດເດັກ (ປຸ່ມ ອອກຈາກໂໝດເດັກ ຫຼື ປຸ່ມ ກັບຄືນ). PIN ນີ້ແມ່ນການປົກປ້ອງເບົາສຳລັບເດັກນ້ອຍ, ບໍ່ແມ່ນຄວາມປອດໄພທີ່ແທ້ຈິງ.

ຕົວສ້າງແອັບ Wear OS & TV
ເພື່ອສ້າງແອັບໂມງ (Wear OS) ຫຼື ແອັບໂທລະພາບ (Android TV) — ເປີດ ຜູ້ສ້າງແອັບ Wear OS & TV ໃນເມນູຫຼັກ ແລະ ເລືອກເປົ້າໝາຍ (Wear OS, Android TV ຫຼື ທັງສອງ). ຕື່ມຊື່ໂຄງການ ແລະ ກົດ ສ້າງໂຄງການໃໝ່ Wear/TV — IDE ສ້າງ ແລະ ດັດແປງໂຄງການ Java — ຫຼື ເລືອກໂຄງການທີ່ມີຢູ່ ແລະ ກົດ ນຳໃຊ້ກັບໂຄງການນີ້. ການດັດແປງ — uses-feature ໃນ manifest, ປະເພດ LEANBACK_LAUNCHER ແລະ ແບນເນີສຳລັບ TV ແລະ ຮູບແບບ activity_main.xml ທີ່ຖືກດັດແປງ (Wear - ໜ້າຈໍນ້ອຍ. TV - ໜ້າຈໍໃຫຍ່ທີ່ເໝາະກັບ D-pad). ຄຳອະທິບາຍເຕັມຖືກຂຽນໃສ່ wear-tv.txt ໃນໂຄງການ. ນີ້ແມ່ນແມ່ແບບໂຄງການ — ການສ້າງ + ການທົດສອບຍັງຕ້ອງການອຸປະກອນ Wear OS ຫຼື Android TV/ຕົວຈຳລອງ. ແບນເນີ TV (banner.png 320x180) ບໍ່ໄດ້ຖືກສ້າງອັດຕະໂນມັດ, ຕ້ອງເພີ່ມເອງ (ຕົວຢ່າງຜ່ານ ຜູ້ສ້າງໄອຄອນ).

ແຜນທີ່ໂຄງການ
ເພື່ອເບິ່ງໂຄງສ້າງຂອງໂຄງການ — ເປີດ ແຜນທີ່ໂຄງການ ໃນເມນູຫຼັກ, ເລືອກໂຄງການ ແລະ ກົດ ສະແດງແຜນທີ່ — IDE ສະແດງລາຍການໂຟລເດີ ແລະ ໄຟລ໌ພ້ອມຂະໜາດຂອງມັນ, ຂະໜາດທັງໝົດ, ຂະໜາດຕາມປະເພດໄຟລ໌ ແລະ ໄຟລ໌ສຳຄັນ (ໄຟລ໌ຫຼັກ, manifest, ຮູບແບບ, ສະຕຣິງ, ໄອຄອນ, ໜ້າເວັບ). ກົດ ບັນທຶກ peta-proyek.txt ເພື່ອຂຽນແຜນທີ່ດຽວກັນໃສ່ຮາກໂຄງການ. ໂຟລເດີ bin/ (ຜົນການສ້າງ) ແລະ ໂຟລເດີ .git/ (repo ທ້ອງຖິ່ນ) ບໍ່ໄດ້ລວມຢູ່ໃນແຜນທີ່, ເພາະວ່າເນື້ອໃນຂອງມັນສາມາດສ້າງຄືນໄດ້.

ເຄື່ອງຄິດໄລ່ຂະໜາດ APK
ເພື່ອຄາດຄະເນຂະໜາດຂອງ APK ທີ່ສ້າງແລ້ວກ່ອນສ້າງ — ເປີດ ເຄື່ອງຄິດໄລ່ຂະໜາດ APK ໃນເມນູຫຼັກ, ເລືອກໂຄງການ ແລະ ກົດ ຄິດໄລ່ການຄາດຄະເນ. IDE ສະແດງລາຍລະອຽດຕາມປະເພດ (ລະຫັດ/DEX, ຊັບພະຍາກອນ, ຊັບສິນ, ຫ້ອງສະໝຸດທີ່ຝັງ, manifest + resources.arsc, ຄ່າໃຊ້ຈ່າຍທົ່ວໄປ), ການຄາດຄະເນທັງໝົດ, ໄຟລ໌ໃຫຍ່ທີ່ສຸດ 5 ໄຟລ໌ ແລະ ຄຳແນະນຳສຳລັບການຫຼຸດຜ່ອນ (ຕົວຢ່າງ ຫຼຸດຮູບພາບໃຫຍ່ຕາມຄວາມລະອຽດ, ຕັດສຽງຍາວຕາມໄລຍະເວລາ). ນີ້ແມ່ນການຄາດຄະເນ, ບໍ່ແມ່ນຂະໜາດທີ່ແນ່ນອນ — ຂະໜາດຈິງອາດແຕກຕ່າງກັນຍ້ອນການບີບອັດ aapt2, ການລຶບລະຫັດທີ່ບໍ່ໄດ້ໃຊ້ (R8) ແລະ ຊັບພະຍາກອນຜົນການສ້າງ.

ຕົວວິເຄາະ APK
ເພື່ອອ່ານເນື້ອໃນຂອງ APK ທີ່ສຳເລັດແລ້ວ (ຄືກັບຕົວວິເຄາະ APK ໃນ Android Studio) — ເປີດ ຜູ້ວິເຄາະ APK ໃນເມນູຫຼັກ, ເລືອກໂຄງການ ແລະ ກົດ ວິເຄາະ APK ຜົນການສ້າງ. IDE ອ່ານ APK ລ່າສຸດໃນໂຟລເດີ bin ຂອງໂຄງການນັ້ນ ແລະ ລາຍງານຊື່ແພັກເກັດ, ເວີຊັນ, SDK ຕ່ຳສຸດ ແລະ ເປົ້າໝາຍ, ລາຍການສິດອະນຸຍາດທີ່ໃຊ້, ຈຳນວນໄຟລ໌ dex, ລາຍລະອຽດຂະໜາດຕາມພາກ (ລະຫັດໂປຣແກຣມ, ຊັບພະຍາກອນ, ຊັບສິນ, ຫ້ອງສະໝຸດທີ່ຝັງ, ລາຍເຊັນ) ແລະ ລາຍການທີ່ໃຫຍ່ທີ່ສຸດ 10 ອັນ. ມີປະໂຫຍດສຳລັບການຮູ້ວ່າພາກໃດເຮັດໃຫ້ APK ໃຫຍ່ ແລະ ສິດອະນຸຍາດໃດທີ່ແອັບທີ່ສ້າງແລ້ວໃຊ້.

ເບິ່ງຕົວຢ່າງຂະໜາດໜ້າຈໍ
ເພື່ອກວດສອບຮູບລັກສະນະຂອງໂຄງການໃນຫຼາຍຂະໜາດໜ້າຈໍພ້ອມກັນ (ຄືກັບໃນ Android Studio) — ເປີດ ສະແດງຕົວຢ່າງຂະໜາດໜ້າຈໍ ໃນເມນູຫຼັກ, ເລືອກໂຄງການ ແລະ ກົດ ກວດສອບຂະໜາດໜ້າຈໍ. IDE ອ່ານຮູບແບບທັງໝົດຂອງໂຄງການ ແລະ ລາຍງານອົງປະກອບທີ່ມີຄວາມກວ້າງຄົງທີ່ (ຕົວຢ່າງ 400dp) ແລະ ເກີນຄວາມກວ້າງໜ້າຈໍ 320, 360, 411 ຫຼື 480 dp, ເພາະວ່າຢູ່ໃນໂທລະສັບທີ່ມີໜ້າຈໍນ້ອຍ ອົງປະກອບດັ່ງກ່າວອາດຖືກເຊື່ອງ ຫຼື ລົ້ນ. ອົງປະກອບທີ່ມີຄວາມກວ້າງ match_parent ຫຼື wrap_content ປັບຕົວອັດຕະໂນມັດຕາມໜ້າຈໍ ແລະ ບໍ່ຈຳເປັນຕ້ອງກວດສອບ.

ຕົວຈັດການຊັບພະຍາກອນ
ເພື່ອເບິ່ງ ແລະ ຈັດການຊັບພະຍາກອນທັງໝົດຂອງໂຄງການຢູ່ບ່ອນດຽວ (ຄືກັບຜູ້ຈັດການຊັບພະຍາກອນໃນ Android Studio) — ເປີດ ຜູ້ຈັດການຊັບພະຍາກອນ ໃນເມນູຫຼັກ, ເລືອກໂຄງການ ແລະ ກົດ ເບິ່ງຊັບພະຍາກອນ. IDE ລາຍງານຈຳນວນໄຟລ໌ ແລະ ຂະໜາດຕາມປະເພດ (drawable, layout, values, mipmap ແລະ ອື່ນໆ), ເນື້ອໃນ strings.xml, colors.xml ແລະ styles.xml. ຈາກໜ້າຈໍດຽວກັນ ທ່ານສາມາດເພີ່ມສະຕຣິງໃໝ່ເຂົ້າ strings.xml ແລະ ສີໃໝ່ເຂົ້າ colors.xml ໂດຍການຕື່ມຊື່ ແລະ ຄ່າ — ຊື່ຖືກກວດສອບ ແລະ ຊ້ຳກັນຖືກປະຕິເສດ, ສະນັ້ນໄຟລ໌ XML ບໍ່ເສຍຫາຍ.

ຕົວຕິດຕາມປະສິດທິພາບເບົາ
ເພື່ອຕິດຕາມການໃຊ້ RAM ແລະ ໂປຣເຊສເຊີຂອງແອັບທີ່ກຳລັງແລ່ນ (ຄືກັບ Profiler ໃນ Android Studio, ເວີຊັນເບົາ) — ເປີດ ຜູ້ຕິດຕາມປະສິດທິພາບເບົາ ໃນເມນູຫຼັກ, ທຳອິດແລ່ນແອັບທີ່ທ່ານຕ້ອງການກວດສອບ (ຕົວຢ່າງ ແອັບທີ່ສ້າງແລ້ວທີ່ກຳລັງຖືກທົດສອບ), ຕື່ມຊື່ແພັກເກັດຂອງມັນ — ຫຼື ເລືອກໂຄງການ ແລະ ກົດ ໃສ່ຊື່ Package ຈາກໂຄງການ — ຈາກນັ້ນກົດ ເລີ່ມຕິດຕາມ. ທຸກໆສອງວິນາທີ IDE ບັນທຶກ RAM (PSS) ແລະ CPU ຂອງແອັບນັ້ນພ້ອມກັບ RAM ວ່າງຂອງໂທລະສັບ. ກົດ ຢຸດ ເພື່ອເບິ່ງບົດສະຫຼຸບສະເລ່ຍ ແລະ ສູງສຸດ. ບໍ່ມີສິດອະນຸຍາດເພີ່ມເຕີມ. ໃນເວີຊັນ Android ໃໝ່ ການເຂົ້າເຖິງເພື່ອອ່ານໂປຣເຊສເຊີຂອງແອັບອື່ນຖືກຈຳກັດໂດຍລະບົບ, ສະນັ້ນຖ້າ CPU ບໍ່ສາມາດອ່ານໄດ້ ບົດລາຍງານເວົ້າຢ່າງນັ້ນ ແລະ ການຕິດຕາມ RAM ສືບຕໍ່.

ການກວດສອບການເຂົ້າເຖິງ
ເພື່ອກວດເບິ່ງວ່າຮູບແບບຂອງໂຄງການເປັນເໝາະສຳລັບເຄື່ອງອ່ານໜ້າຈໍ (TalkBack/Jieshuo) ຫຼືບໍ່ ກ່ອນປ່ອຍ: ເປີດ ການກວດສອບການເຂົ້າເຖິງ ໃນເມນູຫຼັກ ເລືອກໂຄງການໜຶ່ງ ແລ້ວກົດ ໂຫຼດລາຍຊື່ເລເອົາ ແລະ ເລືອກໄຟລ໌ຮູບແບບໜຶ່ງ. IDE ອ່ານໄຟລ໌ XML ນັ້ນ ແລະ ລາຍງານປຸ່ມທີ່ບໍ່ມີປ້າຍກຳກັບພ້ອມໝາຍເລກແຖວຂອງມັນ ປ້າຍກຳກັບທີ່ຖືກໃຊ້ຊໍ້າໆ ແລະ ອົງປະກອບທີ່ຊ້ອນກັນ ຈາກນັ້ນສ້າງການຖອດຄວາມຂອງລຳດັບໂຟກັສດັ່ງທີ່ Jieshuo ອ່ານອອກສຽງ. ຖ້າປຸ່ມໜຶ່ງຂາດປ້າຍກຳກັບ ໃຫ້ຕື່ມປ້າຍກຳກັບຂອງມັນ ແລ້ວກົດ ແຊກປ້າຍກຳກັບອັດຕະໂນມັດ — ປ້າຍກຳກັບຖືກຂຽນລົງໃນໄຟລ໌ຮູບແບບເປັນ contentDescription. ການກວດສອບນີ້ຈະອ່ານພຽງ XML ຂອງຮູບແບບເທົ່ານັ້ນ; ມຸມມອງ Compose ແລະ APK ທີ່ສຳເລັດແລ້ວຍັງບໍ່ໄດ້ຖືກສະແກນ.

ການຊັນນະສູດຂໍ້ຂັດຂ້ອງ
ເພື່ອຊອກຫາວ່າເປັນຫຍັງແອັບຈຶ່ງປິດຕົວເອງຈາກບັນທຶກການຂັດຂ້ອງທີ່ມີ ID ທີ່ເປັນເອກະລັກ: ເປີດ «ການຊັນນະສູດຂໍ້ຂັດຂ້ອງ» ໃນເມນູຫຼັກ ເລືອກ ID ການຂັດຂ້ອງຈາກລາຍຊື່ບັນທຶກ ຈາກນັ້ນກົດ «ກວດສອບ». IDE ຈັບຄູ່ຄລາສ ແລະໝາຍເລກແຖວໃນບັນທຶກກັບແຫຼ່ງໂຄງການ ແລະອະທິບາຍສາເຫດເປັນພາສາອິນໂດເນເຊຍ (ຕົວຢ່າງການອ້າງອີງວ່າງ ການອະນຸຍາດທີ່ຍັງບໍ່ໄດ້ຂໍ ຫຼືຂໍ້ຜິດພາດ JSON) ພ້ອມກັບຄຳແນະນຳແພັດໂຄ້ດ. ກົດ «ນຳໃຊ້ແພັດ» ພຽງແຕ່ເມື່ອແຖວແຫຼ່ງຍັງຄົງເປັນຄືກັບເວລາທີ່ການຂັດຂ້ອງເກີດຂຶ້ນ; ຖ້າມັນປ່ຽນແປງ ແພັດຈະຖືກປະຕິເສດ ແລະ IDE ຂໍໃຫ້ທ່ານກວດສອບດ້ວຍຕົວເອງ. ສຳລັບການຂັດຂ້ອງຂອງແອັບທີ່ຖືກສ້າງ ກົດ «ໃສ່ຕົວຈັບການຂັດຂ້ອງເຂົ້າໃນໂຄງການ» ຈາກນັ້ນສ້າງ APK ຕາມປົກກະຕິ: ແອັບທີ່ຖືກສ້າງຈັບການຂັດຂ້ອງຂອງຕົນເອງ ແລະຂຽນບັນທຶກຂອງມັນລົງໃນໂທລະສັບ ແລະສາມາດພົບບັນທຶກນັ້ນໄດ້ດ້ວຍປຸ່ມ «ຊອກຫາບັນທຶກການຂັດຂ້ອງຂອງແອັບທີ່ສ້າງແລ້ວ». ຂໍ້ຈຳກັດທີ່ຊື່ສັດ: ການຄັດລອກບັນທຶກໄປຍັງໂຟລເດີ Download ສາທາລະນະໃນ Android 11 ແລະສູງກວ່າອາດລົ້ມເຫຼວໂດຍບໍ່ມີການອະນຸຍາດເຂົ້າເຖິງໄຟລ໌ທັງໝົດ.

ຕົວແປງພາສາຂ້າມແບບແຜນ
ເພື່ອປ່ຽນລະຫັດ Java ງ່າຍໆເປັນ Kotlin ຫຼື ຮູບແບບ XML ງ່າຍໆເປັນ ລະຫັດ Compose: ເປີດ ຕົວແປງພາສາຂ້າມແບບແຜນ ໃນເມນູຫຼັກ ເລືອກໂຄງການ ແລະ ໄຟລ໌ໜຶ່ງ ແລ້ວກົດ ຕົວຢ່າງ. IDE ສະແດງຜົນການປ່ຽນເປັນ ຂໍ້ຄວາມ — ກວດເບິ່ງມັນກ່ອນ ເພາະວ່າແຖວທີ່ມັນບໍ່ຮັບຮູ້ຈະຖືກປະໄວ້ຄືເກົ່າ ແລະ ຄຳວ່າ static ໃນ Java ຈະຖືກລຶບໃນ Kotlin (ກວດເບິ່ງຄວາມໝາຍຂອງມັນກ່ອນໃຊ້). ການປ່ຽນຈາກ XML ໄປ Compose ປ່ຽນພຽງຂໍ້ຄວາມ ຄຳແນະນຳ ແລະ ທິດທາງເທົ່ານັ້ນ — ຂະໜາດ ສີ ແລະ ຄຸນສົມບັດອື່ນໆຍັງບໍ່ລວມ. ຖ້າຜົນຖືກຕ້ອງ ກົດ ນຳໃຊ້ກັບໄຟລ໌ ເພື່ອຂຽນໄຟລ໌ເປົ້າໝາຍ; ໄຟລ໌ແຫຼ່ງບໍ່ປ່ຽນແປງ. ມີພຽງແບບແຜນທີ່ປອດໄພ ແລະ ທົ່ວໄປເທົ່ານັ້ນທີ່ຖືກປ່ຽນ.

ເຊີບເວີຈຸລະພາກທ້ອງຖິ່ນ
ເພື່ອທົດສອບແອັບທີ່ຕ້ອງການເຊີບເວີໂດຍບໍ່ມີອິນເຕີເນັດ: ເປີດ «ເຊີບເວີຈຸລະພາກທ້ອງຖິ່ນ» ໃນເມນູຫຼັກ ຂຽນຄຳນິຍາມເສັ້ນທາງ (ຕົວຢ່າງ GET /halo ຕາມດ້ວຍຄຳຕອບ JSON ຂອງມັນ) ຈາກນັ້ນກົດ «ເລີ່ມເຊີບເວີ». IDE ດຳເນີນເຊີບເວີ HTTP ນ້ອຍໆຢູ່ໃນໂທລະສັບດຽວກັນ (HTTP ເທົ່ານັ້ນ ບໍ່ມີ TLS ສຳລັບເຄືອຂ່າຍ Wi-Fi ດຽວກັນ) ແລະບັນທຶກທຸກຄຳຮ້ອງ ແລະ ຄຳຕອບຢູ່ໃນໜ້າຈໍ. ເສັ້ນທາງສາມາດໃຊ້ພາລາມິເຕີເຊັ່ນ {nama} ແລະກະແຈ API ງ່າຍໆ. ເຊີບເວີຍັງສາມາດຖືກຫໍ່ໃນ APK ທີ່ຖືກສ້າງ: ກົດ «ຫໍ່ເຊີບເວີເຂົ້າໃນໂຄງການ» ແລະແຫຼ່ງເຊີບເວີ ຊັບສິນ ແລະ manifest ຖືກໃສ່ເຂົ້າໃນໂຄງການ ດັ່ງນັ້ນແອັບທີ່ຖືກສ້າງເອງຈະກາຍເປັນເຊີບເວີເມື່ອມັນເຮັດວຽກ. ເຊີບເວີໃນ IDE ຢຸດເມື່ອໜ້າຈໍຂອງມັນຖືກປິດ.

ຜູ້ກວດສອບຄວາມປອດໄພ
ເພື່ອກວດສອບໂຄ້ດໂຄງການສຳລັບຊ່ອງວ່າງຄວາມປອດໄພກ່ອນການພິມ: ເປີດ «ຜູ້ກວດສອບຄວາມປອດໄພ» ໃນເມນູຫຼັກ ເລືອກໂຄງການ ຈາກນັ້ນກົດ «ເລີ່ມສະແກນ». IDE ສະແກນໂຄ້ດໂຄງການ manifest ແລະການຕັ້ງຄ່າ ແລະແຈ້ງການຄົ້ນພົບຈາກຄວາມສ່ຽງສູງຫາຕ່ຳ — ກະແຈ API ທີ່ຖືກປະໄວ້ເປີດໃນໂຄ້ດ ອົງປະກອບທີ່ຖືກເປີດເຜີຍໂດຍບໍ່ມີການອະນຸຍາດ WebView ທີ່ເປີດ JavaScript ດ້ວຍອິນເຕີເຟດ JavaScript ຂອງມັນ crypto ທີ່ອ່ອນແອ (MD5 SHA1 DES) ທີ່ຢູ່ http ທີ່ບໍ່ມີ TLS ແລະລະຫັດຜ່ານທີ່ຖືກຂຽນໂດຍກົງໃນໂຄ້ດ — ພ້ອມກັບໄຟລ໌ ແລະໝາຍເລກແຖວຂອງພວກເຂົາ. ສຳລັບການຄົ້ນພົບທີ່ການແກ້ໄຂປອດໄພ (ຕົວຢ່າງປ່ຽນ MD5 ເປັນ SHA-256 ຫຼື http ເປັນ https) ກົດ «ນຳໃຊ້ການແກ້ໄຂ»; ສຳລັບກະແຈ API ແລະລະຫັດຜ່ານ IDE ສະແດງພຽງຄຳແນະນຳການແກ້ໄຂເທົ່ານັ້ນ ເພາະວ່າການທົດແທນຕ້ອງຖືກຕັດສິນໂດຍນັກພັດທະນາເອງ. ການສະແກນຕອນນີ້ຍັງວິເຄາະ bytecode DEX ທີ່ແທ້ຈິງພາຍໃນ APK ທີ່ຖືກສ້າງ (ບໍ່ແມ່ນພຽງຮູບແບບຂໍ້ຄວາມໃນໂຄ້ດເທົ່ານັ້ນ) ດັ່ງນັ້ນ API ທີ່ອັນຕະລາຍທີ່ຖືກເອີ້ນ ແລະຄວາມລັບທີ່ຝັງຢູ່ໃນ DEX ກໍຖືກຈັບເຊັ່ນກັນ; ຊ່ອງວ່າງທີ່ບໍ່ປະຕິບັດຕາມຮູບແບບຍັງອາດຫຼົບໜີການສະແກນໄດ້ — ກວດສອບກ່ອນການນຳໃຊ້.

ຫຸ່ນຍົນທົດສອບອິນເຕີເຟດ
ເພື່ອທົດສອບໜ້າຈໍແອັບໂດຍອັດຕະໂນມັດຜ່ານສະຖານະການຂໍ້ຄວາມ: ເປີດ «ຫຸ່ນຍົນທົດສອບອິນເຕີເຟດ» ໃນເມນູຫຼັກ ເລືອກໂຄງການ ຈາກນັ້ນກົດ «ສ້າງສະຖານະການອັດຕະໂນມັດ». IDE ອ່ານ manifest ແລະຮູບແບບຂອງໂຄງການ ແລະຂຽນສະຖານະການເປັນຂັ້ນຕອນຂໍ້ຄວາມ (ກົດປຸ່ມ ຕື່ມຂໍ້ມູນໃສ່ຊ່ອງ ລໍຖ້າ ກັບຄືນ). ກົດ «ດຳເນີນການທົດລອງແຫ້ງ» ເພື່ອເບິ່ງບັນທຶກການດຳເນີນການຂອງສະຖານະການພ້ອມກັບເວລາຂອງມັນ — ການທົດລອງແຫ້ງນີ້ຍັງເປັນພຽງການຈຳລອງຂອງລຳດັບເທົ່ານັ້ນ. ສຳລັບການທົດສອບທີ່ແທ້ຈິງ ກົດ «ໃສ່ຕົວແທນທົດສອບເຂົ້າໃນໂຄງການ»: IDE ໃສ່ຕົວແທນທົດສອບພ້ອມກັບຊັບສິນສະຖານະການເຂົ້າໃນໂຄງການ; ສ້າງ APK ຕາມປົກກະຕິ ຕິດຕັ້ງມັນ ຈາກນັ້ນເປີດໄອຄອນ «ທົດສອບ» — ຕົວແທນເຮັດວຽກຢູ່ພາຍໃນແອັບທີ່ຖືກສ້າງ ແລະກົດປຸ່ມຢ່າງແທ້ຈິງ ຕື່ມຂໍ້ມູນໃສ່ຊ່ອງຈິງ ແລະເລື່ອນ ຈາກນັ້ນສະແດງລາຍງານຂອງມັນພ້ອມກັບການຂັດຂ້ອງທີ່ແທ້ຈິງທີ່ຖືກຈັບໄດ້ຢູ່ໃນໜ້າຈໍ. ເພື່ອເອົາຕົວແທນອອກອີກຄັ້ງ ກົດ «ເອົາຕົວແທນທົດສອບອອກຈາກໂຄງການ». ຕົວແທນເຮັດວຽກຢູ່ພາຍໃນຂະບວນການຂອງແອັບເອງ ດັ່ງນັ້ນມັນບໍ່ຕ້ອງການບໍລິການເຂົ້າເຖິງ ຫຼືອັດຕະໂນມັດຂອງລະບົບ.

ການເດີນທາງຂ້າມເວລາຂອງລະຫັດ
ເພື່ອກັບຄືນໂຄງການໄປສູ່ສະຖານະລະຫັດເກົ່າໂດຍບໍ່ຕ້ອງພິມຄຳສັ່ງ Git: ເປີດ ການເດີນທາງຂ້າມເວລາຂອງລະຫັດ ໃນເມນູຫຼັກ ເລືອກໂຄງການໜຶ່ງ ຕື່ມປ້າຍກຳກັບສຳລັບຈຸດເວລາ (ສາມາດປະໄວ້ຫວ່າງໄດ້) ແລ້ວກົດ ບັນທຶກຈຸດປະຈຸບັນ. IDE ບັນທຶກສຳເນົາຂອງໄຟລ໌ແຫຼ່ງຂອງໂຄງການພ້ອມຄ່າ hash ຂອງມັນໃນໂຟລເດີ .riwayat ພາຍໃນໂຄງການ. ລາຍຊື່ຈຸດເວລາສະແດງທັງໝົດ; ເລືອກສອງຈຸດ ແລ້ວກົດ ປຽບທຽບ ເພື່ອເບິ່ງໄຟລ໌ ແລະ ຟັງຊັນທີ່ຖືກເພີ່ມ ປ່ຽນແປງ ຫຼື ລຶບ. ກົດ ກູ້ຄືນ ເພື່ອນຳສະຖານະເກົ່າກັບຄືນມາ — ກ່ອນກູ້ຄືນ IDE ຈະສ້າງສຳເນົາສຳຮອງຂອງສະຖານະປະຈຸບັນກ່ອນສະເໝີ ດັ່ງນັ້ນບໍ່ມີຫຍັງສູນຫາຍ. ກົດ ສ້າງສຳເນົາທົດລອງ ເພື່ອສຳເນົາໂຄງການໄປໂຟລເດີໃໝ່ ແລະ ລອງການປ່ຽນແປງໂດຍບໍ່ລົບກວນໂຄງການຕົ້ນສະບັບ. ມີພຽງໄຟລ໌ແຫຼ່ງເທົ່ານັ້ນທີ່ຖືກບັນທຶກ.

ໂຮງງານໂມດູນ
ເພື່ອຫໍ່ສ່ວນໜຶ່ງຂອງໂຄງການເປັນໂມດູນທີ່ໂຄງການອື່ນສາມາດໃຊ້ໄດ້: ເປີດ ໂຮງງານໂມດູນ ໃນເມນູຫຼັກ ເລືອກໂຄງການແຫຼ່ງໜຶ່ງ ໝາຍໄຟລ໌ໜ້າຈໍ ຊັ້ນ ສະຕຣິງ ແລະ ການອະນຸຍາດທີ່ຈະຫໍ່ ແລ້ວກົດ ຫໍ່ເປັນໂມດູນ. IDE ຂຽນຄັງເກັບ ZIP ພ້ອມເມຕາເດຕາ JSON (ຊື່ໂມດູນ ເວີຊັນ ສະຕຣິງທີ່ໃຊ້ ແລະ ການອະນຸຍາດ). ເພື່ອຕິດຕັ້ງໂມດູນໃນໂຄງການອື່ນ ເປີດ ໂຮງງານໂມດູນ ເລືອກໂຄງການເປົ້າໝາຍ ແລ້ວກົດ ຕິດຕັ້ງໂມດູນ ແລະ ເລືອກໄຟລ໌ .zip ຂອງໂມດູນ — ການລວມເຂົ້າກັນເພີ່ມສະຕຣິງ ແລະ ການອະນຸຍາດໂດຍບໍ່ຂຽນທັບລະຫັດທີ່ມີຢູ່ ແລະ ບໍ່ລວມໄຟລ໌ໜຶ່ງຖ້າຊື່ຂອງມັນຖືກໃຊ້ແລ້ວໃນໂຄງການເປົ້າໝາຍ. ໂມດູນໜຶ່ງບໍ່ໄດ້ນຳຫ້ອງສະໝຸດ ຫຼື ການຕັ້ງຄ່າການສ້າງມານຳ.

ໄສ້ໂພລີມໍຟິກ ແລະຫ້ອງຊັບສິນ
ເພື່ອສຸ່ມຊື່ຕົວລະບຸ ແລະເຂົ້າລະຫັດຊັບສິນຂອງໂຄງການກ່ອນການພິມ: ເປີດ «ໄສ້ໂພລີມໍຟິກ ແລະຫ້ອງຊັບສິນ» ໃນເມນູຫຼັກ ເລືອກໂຄງການ ຈາກນັ້ນກົດ «ສຸ່ມຊື່ ແລະເຂົ້າລະຫັດຊັບສິນ». IDE ສະແກນຊື່ຄລາສ ແລະວິທີການໃນໂຄ້ດຕົ້ນສະບັບ ສ້າງແຜນທີ່ຊື່ສຸ່ມ ຂຽນຊື່ເຫຼົ່ານັ້ນຄືນໃໝ່ພາຍໃນໄຟລ໌ DEX ທີ່ຖືກລວບລວມແລ້ວ (ຊື່ທົດແທນຖືກເຮັດໃຫ້ຍາວເທົ່າກັບຕົ້ນສະບັບເພື່ອໃຫ້ offsets ທັງໝົດຍັງຖືກຕ້ອງ ຈາກນັ້ນຜົນລວມກວດສອບຫົວ DEX ແລະລາຍເຊັນ SHA-1 ຖືກຄຳນວນຄືນໃໝ່) ເຂົ້າລະຫັດໄຟລ໌ຊັບສິນຂອງໂຄງການດ້ວຍ AES-GCM ໃນໂຟລເດີ brankas-aset ພາຍໃນໂຄງການ ແລະບັນທຶກແຜນທີ່ກູ້ຄືນທີ່ຖືກເຂົ້າລະຫັດ (perisai-peta.brankas) ເພື່ອໃຫ້ຊື່ຕົ້ນສະບັບສາມາດກູ້ຄືນໄດ້ເມື່ອອ່ານບັນທຶກການຂັດຂ້ອງ. ກະແຈເຂົ້າລະຫັດຕອນນີ້ໄດ້ມາຈາກລະຫັດຜ່ານຂອງນັກພັດທະນາດ້ວຍ PBKDF2 20,000 ຄັ້ງ ບໍ່ແມ່ນຈາກຊື່ໂຄງການ. ຊື່ທີ່ຖືກໃຊ້ເປັນຂໍ້ຄວາມທຳມະດາ ຊື່ຄຳອະທິບາຍ ແລະຊື່ດີບັກບໍ່ໄດ້ຖືກຂຽນຄືນໃໝ່ໂດຍເຈດຕະນາ ແລະຈຸດແຊກຂອງການຂຽນ DEX ຄືນໃໝ່ໃນເສັ້ນທາງການສ້າງຍັງລໍຖ້າການທົດສອບຢູ່ໃນໂທລະສັບຈິງ.

ຕ່ອງໂສ້ຄວາມໄວ້ວາງໃຈ ແລະຜູ້ປົກປ້ອງສະພາບແວດລ້ອມ
ເພື່ອກວດສອບຕ່ອງໂສ້ກະແຈລາຍເຊັນ ແລະສະພາບແວດລ້ອມຂອງໂທລະສັບກ່ອນການພິມ: ເປີດ «ຕ່ອງໂສ້ຄວາມໄວ້ວາງໃຈ ແລະຜູ້ປົກປ້ອງສະພາບແວດລ້ອມ» ໃນເມນູຫຼັກ ເລືອກໂຄງການ ຈາກນັ້ນກົດ «ກວດສອບຕ່ອງໂສ້ ແລະສະພາບແວດລ້ອມ». IDE ສ້າງຕ່ອງໂສ້ກະແຈ 5 ລຸ້ນຈາກຊື່ແພັກເກັດຂອງໂຄງການ ແລະກວດສອບຄວາມສົມບູນຂອງມັນ ກວດສອບຄວາມສົມບູນຂອງໜ່ວຍຄວາມຈຳທີ່ແທ້ຈິງໂດຍການປຽບທຽບເນື້ອໃນຂອງສ່ວນໂຄ້ດໃນໜ່ວຍຄວາມຈຳກັບໄຟລ໌ໃນດິສ ແລະແຈ້ງການຈັບຄູ່ທີ່ສາມາດປະຕິບັດໄດ້ (RWX) ທີ່ບໍ່ມີຊື່ ຫໍສະໝຸດກຕ່າງປະເທດ ແລະການຈັບຄູ່ memfd ຈາກນັ້ນສະແກນແຜນທີ່ໜ່ວຍຄວາມຈຳຂະບວນການຂອງຕົນເອງ ແລະຄຸນສົມບັດຂອງອຸປະກອນສຳລັບຮ່ອງຮອຍຂອງ Frida Xposed ຫຼືຕົວຈຳລອງ. ກະແຈຫ້ອງເກັບຖືກຫໍ່ດ້ວຍກະແຈ AES ໃນ AndroidKeyStore ທີ່ໃຊ້ຊິບຄວາມປອດໄພຂອງຮາດແວເມື່ອມີ ແລະການຫມູນວຽນຂອງກະແຈຕອນນີ້ເປັນຈິງດ້ວຍສາຍພັນໃບຮັບຮອງລາຍເຊັນແບບ v3: ກະແຈເກົ່າລົງນາມໃນຫຼັກຖານຂອງການຫມູນວຽນໄປຫາກະແຈໃໝ່ ແລະ APK ຖືກລົງນາມຄືນໃໝ່ດ້ວຍສາຍພັນນັ້ນ. ຜົນໄດ້ຮັບແມ່ນລະດັບຄວາມສ່ຽງ «ປອດໄພ» «ລະມັດລະວັງ» ຫຼື «ອັນຕະລາຍ» ພ້ອມກັບຫຼັກຖານຂໍ້ຄວາມ. ຖ້າລະບົບປະຕິເສດການອ່ານໜ່ວຍຄວາມຈຳ ການກວດສອບຈະຖືກແຈ້ງວ່າ «ບໍ່ສາມາດກວດສອບໄດ້» ບໍ່ແມ່ນປອດໄພ; ແລະວ່າກະແຈໃຊ້ຊິບຄວາມປອດໄພຂອງຮາດແວແທ້ໆຫຼືບໍ່ສາມາດຢືນຢັນໄດ້ພຽງແຕ່ຢູ່ໃນອຸປະກອນຈິງເທົ່ານັ້ນ.

ສະຖາປະນິກຮູບແບບຕົ້ນໄມ້ຂໍ້ຄວາມ
ເພື່ອອອກແບບໜ້າຈໍໂດຍບໍ່ຕ້ອງເຫັນມັນ: ເປີດ «ສະຖາປະນິກຮູບແບບຕົ້ນໄມ້ຂໍ້ຄວາມ» ໃນເມນູຫຼັກ ເລືອກໂຄງການ ແລະໄຟລ໌ຮູບແບບ ຈາກນັ້ນກົດ «ກວດສອບຮູບແບບ». IDE ອ່ານຮູບແບບ XML ເປັນຕົ້ນໄມ້ຂໍ້ຄວາມ ແລະອ່ານຄຳອະທິບາຍຕຳແໜ່ງຂອງແຕ່ລະອົງປະກອບອອກສຽງດັງ (ຕົວຢ່າງຢູ່ລຸ່ມຂວາ 45 ເປີເຊັນຂອງຄວາມກວ້າງຂອງໜ້າຈໍ) ຈາກນັ້ນແຈ້ງທາງຄະນິດສາດກ່ຽວກັບການທັບຊ້ອນກັນລະຫວ່າງອົງປະກອບ ແລະອົງປະກອບທີ່ອອກໄປນອກໜ້າຈໍທີ່ຄວາມກວ້າງ 360 dp. ສິ່ງທີ່ຖືກນັບຕອນນີ້ແມ່ນ LinearLayout ແລະຂະໜາດ dp ງ່າຍໆ ConstraintLayout ເຕັມຮູບແບບ (ຂໍ້ຈຳກັດທັງໝົດ ອະຄະຕິ ຕ່ອງໂສ້ ຄຳແນະນຳ ອຸປະສັກ ຄວາມກວ້າງເປັນເປີເຊັນ 0dp match_constraint ແລະອັດຕາສ່ວນຂະໜາດ) ແລະໜ້າຈໍ Compose (Column Row ແລະ Box ພ້ອມກັບຕົວປັບຂະໜາດຂອງພວກເຂົາ). ມີພຽງ MotionLayout ແລະ ConstraintSet ທີ່ປ່ຽນແປງໃນຂະນະທີ່ກຳລັງເຮັດວຽກເທົ່ານັ້ນທີ່ຍັງຖືກແຈ້ງວ່າເປັນຕຳແໜ່ງທີ່ບໍ່ຮູ້ຈັກ ເພາະວ່າຄ່າຂອງພວກເຂົາມີຢູ່ພຽງແຕ່ໃນຂະນະທີ່ແອັບກຳລັງເຮັດວຽກເທົ່ານັ້ນ.

ສະຕູດິໂອລະບົບອອກແບບ
ເພື່ອເຮັດໃຫ້ໄລຍະຫ່າງ ຟອນ ແລະມຸມເປັນເອກະພາບໃນທຸກໜ້າຈໍ ແລະໂຄງການ: ເປີດ «ສະຕູດິໂອລະບົບອອກແບບ» ໃນເມນູຫຼັກ ເລືອກໂຄງການ ຂຽນ token ອອກແບບ (ຕົວຢ່າງ jarak=8 huruf=16 sudut=12) ເລືອກອົງປະກອບ ຈາກນັ້ນກົດ «ສ້າງອົງປະກອບ». IDE ກວດສອບ token — ໄລຍະພື້ນຖານ 4 ຫາ 16 dp ຟອນພື້ນຖານ 12 ຫາ 20 sp ມຸມ 0 ຫາ 32 dp ແລະເຂດສຳຜັດຕ່ຳສຸດ 48 dp — ຈາກນັ້ນຂຽນອົງປະກອບ XML ທີ່ພ້ອມໃຊ້ (komponen-studio.xml) ພ້ອມກັບຫົວຂໍ້ XML (tema-studio.xml) ແລະຫົວຂໍ້ Compose (tema-studio.kt) ໃນໂຟລເດີໂຄງການ. Token ຍັງສາມາດຖືກບັນທຶກເປັນຊຸດທີ່ມີຊື່ໃນຫ້ອງສະໝຸດ token ທີ່ແບ່ງປັນລະຫວ່າງໂຄງການ ແລະຄຳສັ່ງ sync ດຽວນຳໃຊ້ token ຫຼ້າສຸດຂອງຫ້ອງສະໝຸດກັບໂຄງການທັງໝົດທີ່ໃຊ້ຊຸດນັ້ນ. ອົງປະກອບຖືກສ້າງເປັນຂໍ້ຄວາມທີ່ຖືກວາງລົງໃນຮູບແບບ ແລະຈາກນັ້ນກວດສອບດ້ວຍ «ສະຖາປະນິກຮູບແບບຕົ້ນໄມ້ຂໍ້ຄວາມ»; ການປັບສອງຖັນເທິງແທັບເລັດໃຊ້ຄຸນສົມບັດຄວາມກວ້າງຂອງໜ້າຈໍແທນການລະບຸອຸປະກອນໃນຂະນະທີ່ກຳລັງເຮັດວຽກ.

SharedPreferences ແລະ DataStore ກໍສາມາດອ່ານໄດ້. ສິ່ງທີ່ຍັງອ່ານບໍ່ໄດ້: ຖານຂໍ້ມູນທີ່ຖືກເຂົ້າລະຫັດ ການປ່ຽນແປງ WAL ທີ່ບໍ່ໄດ້ຢືນຢັນ ແລະຄ່າທີ່ພິມໃນ DataStore Proto ທີ່ຊ່ຽວຊານ (ສະແດງເປັນມຸມມອງຊ່ອງດຽວທົ່ວໄປເທົ່ານັ້ນ).

ໂຮງງານທົດສອບໜ່ວຍ ແລະ Fuzzing
ເພື່ອຊອກຫາຊ່ອງວ່າງຂອງເຫດຜົນກ່ອນການແບ່ງປັນແອັບ: ເປີດ «ໂຮງງານທົດສອບໜ່ວຍ ແລະ Fuzzing» ໃນເມນູຫຼັກ ເລືອກໂຄງການ ແລະໄຟລ໌ໂຄ້ດ ຈາກນັ້ນກົດ «ສ້າງ ແລະທົດສອບ». IDE ອ່ານລາຍເຊັນຟັງຊັນໃນໄຟລ໌ ສ້າງກໍລະນີທົດສອບທຳມະດາ ແລະຂອບເຂດ (ຂໍ້ຄວາມວ່າງ null ຕົວເລກສູງສຸດ ຕົວອັກສອນແປກ) ຈາກນັ້ນດຳເນີນການທົດສອບເຫຼົ່ານັ້ນຢ່າງແທ້ຈິງ: ໂຄ້ດໂຄງການຖືກລວບລວມ ແລະແຕ່ລະວິທີ @Test ຖືກປະຕິບັດດ້ວຍຂີດຈຳກັດ 5 ວິນາທີ ດັ່ງນັ້ນຜົນໄດ້ຮັບແມ່ນການຜ່ານ ແລະລົ້ມເຫຼວທີ່ແທ້ຈິງພ້ອມກັບຄ່າຕົວຈິງຂອງພວກເຂົາ. Fuzzing ກໍດຳເນີນການຢ່າງແທ້ຈິງໃນຟັງຊັນໂຄງການ (ຜ່ານການສະທ້ອນ 2 ວິນາທີຕໍ່ການເອີ້ນ ສູງສຸດ 20 ວິທີ) ແລະເປີເຊັນການຄຸ້ມຄອງແຖວຖືກຄຳນວນຢ່າງແທ້ຈິງຜ່ານ instrumentation ທີ່ຮັກສາໝາຍເລກແຖວຕົ້ນສະບັບ. ຜົນໄດ້ຮັບແຈ້ງວ່າມີການທົດສອບຈັກເທື່ອທີ່ຜ່ານ ແລະລົ້ມເຫຼວ ມີແຖວໂຄ້ດ ແລະຟັງຊັນຈັກເທື່ອທີ່ພົບ ແລະກໍລະນີທົດສອບໃດຖືກສ້າງຂຶ້ນ. ການທົດສອບທີ່ຖືກສ້າງໃຊ້ API ດຽວກັນຢ່າງແນ່ນອນກັບ JUnit ແຕ່ຄຳນິຍາມຄຳອະທິບາຍ ແລະການຢືນຢັນຖືກຂຽນພາຍໃນໄຟລ໌ທົດສອບທີ່ຖືກສ້າງ ເພາະວ່າຫໍສະໝຸດ JUnit ທີ່ແທ້ຈິງບໍ່ໄດ້ລວມຢູ່ໃນແອັບ.

ຕົວຈຳລອງສະພາບອຸປະກອນທີ່ຮຸນແຮງ ແລະຜູ້ກວດສອບການຮົ່ວໄຫຼຂອງໜ່ວຍຄວາມຈຳ
ເພື່ອທົດສອບຄວາມອົດທົນຂອງແອັບເມື່ອລະບົບຂ້າຂະບວນການຂອງມັນ ເຄືອຂ່າຍຂາດ ໜ້າຈໍໝຸນ ຫຼືການປະຢັດແບັດເຕີຣີຖືກເປີດ: ເປີດ «ຕົວຈຳລອງສະພາບອຸປະກອນທີ່ຮຸນແຮງ ແລະຜູ້ກວດສອບການຮົ່ວໄຫຼຂອງໜ່ວຍຄວາມຈຳ» ໃນເມນູຫຼັກ ເລືອກໂຄງການ ຈາກນັ້ນກົດ «ດຳເນີນການຈຳລອງ». IDE ດຳເນີນການສະຖານະການຄວາມກົດດັນສາມຢ່າງພ້ອມກັບການຈຳລອງການຫມຸນໜ້າຈໍ ແລະຕິດຕາມວັດຖຸທີ່ຖືກເກັບໄວ້ໃນໜ່ວຍຄວາມຈຳເຖິງແມ່ນວ່າຫຼັງຈາກໜ້າຈໍຂອງພວກເຂົາຖືກປິດ ແລະຈາກນັ້ນແຈ້ງຂໍ້ມູນທີ່ສູນຫາຍ ແລະຕ່ອງໂສ້ວັດຖຸທີ່ຮົ່ວໄຫຼ. ສະຖານະບັນທຶກ ແລະກູ້ຄືນຕອນນີ້ຖືກອ່ານຈາກແຫຼ່ງໂຄງການຂອງຜູ້ໃຊ້ເອງ ບໍ່ແມ່ນຈາກຕົວຢ່າງທີ່ກຳນົດ; ເຊີບເວີ loopback ທ້ອງຖິ່ນຖືກຢຸດຢ່າງແທ້ຈິງໃນກາງການທົດສອບເພື່ອວັດແທກການຂາດເຄືອຂ່າຍ; heap dump ທີ່ແທ້ຈິງຖືກເອົາ ແລະວິເຄາະ dump ສອງອັນຖືກປຽບທຽບ ແລະຕ່ອງໂສ້ການຖືກຕິດຕາມຈາກຮາກ GC; ແລະຂະບວນການຂອງແອັບເອງຖືກຂ້າຢ່າງແທ້ຈິງຫຼັງຈາກສະຖານະຂອງມັນຖືກບັນທຶກ ຈາກນັ້ນກວດສອບວ່າຂໍ້ມູນໃດຈະກັບຄືນມາເມື່ອມັນຖືກເປີດອີກຄັ້ງ. ສິ່ງທີ່ຍັງເປັນໄປບໍ່ໄດ້ຈາກແອັບທຳມະດາ: ການປິດວິທະຍຸໂທລະສັບ ຫຼື Wi-Fi ແລະການບັງຄັບຢຸດແອັບອື່ນ — ທັງສອງຕ້ອງການການອະນຸຍາດຂອງລະບົບ; ແທນທີ່ຈະເປັນແນວນັ້ນ ແອັບພື້ນຫຼັງຖືກຂ້າຜ່ານ killBackgroundProcesses ທີ່ການອະນຸຍາດຂອງມັນມີຢູ່ແລ້ວໃນ manifest ພ້ອມກັບປ້າຍທີ່ຊື່ສັດຢູ່ໃນໜ້າຈໍ.

ສະຖາປະນິກແຜນຜັງໂຄງການ
ເພື່ອປ່ຽນແນວຄິດແອັບໃຫຍ່ໃຫ້ເປັນແຜນການເຮັດວຽກເທື່ອລະຂັ້ນ: ເປີດ «ສະຖາປະນິກແຜນຜັງໂຄງການ» ໃນເມນູຫຼັກ ເລືອກໂຄງການ ຂຽນແນວຄິດແອັບ (ຕົວຢ່າງແອັບເຄົາເຕີຮ້ານຂາຍເຄື່ອງຍ່ອຍຂະໜາດນ້ອຍທີ່ມີການຜ່ອນຊຳລະ) ຈາກນັ້ນກົດ «ສ້າງແຜນຜັງ». IDE ສ້າງໂມດູນ ລາຍຊື່ໄຟລ໌ ແລະຈຸດໝາຍນ້ອຍໆ ຈາກນັ້ນບັນທຶກພວກເຂົາເປັນ cetak-biru.txt ໃນໂຟລເດີໂຄງການ. ທຸກຄັ້ງທີ່ຈຸດໝາຍສຳເລັດ ກົດ «ໝາຍຈຸດໝາຍຕໍ່ໄປວ່າສຳເລັດແລ້ວ» ຫຼືກົດ «ໂຫຼດແຜນຜັງທີ່ບັນທຶກໄວ້» ເພື່ອເປີດແຜນຜັງທີ່ບັນທຶກໄວ້ອີກຄັ້ງ. ຖ້າຜູ້ໃຫ້ບໍລິການ AI ທີ່ກຳລັງໃຊ້ງານຖືກເລືອກໃນ «ການຕັ້ງຄ່າ AI» ແລະກະແຈຂອງມັນມີຢູ່ ແຜນຜັງຈະຖືກສ້າງໂດຍຜູ້ໃຫ້ບໍລິການນັ້ນ; ຖ້າກະແຈຫາຍໄປ ຫຼືຜູ້ໃຫ້ບໍລິການບໍ່ສາມາດເຂົ້າເຖິງໄດ້ IDE ຈະກັບໄປຫາຮູບແບບຄຳສຳຄັນແບບອອບລາຍ ແລະບອກຂໍ້ຈຳກັດນັ້ນຢ່າງຊື່ສັດ. ຄຳຕອບຂອງຜູ້ໃຫ້ບໍລິການຖືກກວດສອບພຽງແຕ່ສຳລັບຮູບແບບ (ໂມດູນ ແລະຈຸດໝາຍມີຢູ່) ບໍ່ແມ່ນສຳລັບຄວາມຈິງຂອງເນື້ອຫາ — ກວດສອບແຜນຜັງສະເໝີກ່ອນການສ້າງ.

ຜູ້ບັນຍາຍການໄຫຼຂອງເຫດຜົນໂຄ້ດ
ເພື່ອເຂົ້າໃຈໂຄ້ດທີ່ຍາວໂດຍບໍ່ຕ້ອງຟັງ syntax ທີລະແຖວ: ເປີດ «ຜູ້ບັນຍາຍການໄຫຼຂອງເຫດຜົນໂຄ້ດ» ໃນເມນູຫຼັກ ເລືອກໂຄງການ ແລະໄຟລ໌ໂຄ້ດ ຈາກນັ້ນກົດ «ຄຳບັນຍາຍໂຄ້ດ». IDE ປ່ຽນແຕ່ລະແຖວເປັນປະໂຫຍກອິນໂດເນເຊຍ (ຕົວຢ່າງຖ້າຜົນລວມເກີນ 100000 ໃຫ້ດຳເນີນການບລັອກຕໍ່ໄປ) ສະແດງແຜນທີ່ການເອີ້ນລະຫວ່າງວິທີການ ແລະການວິເຄາະການໄຫຼຂອງຂໍ້ມູນລະຫວ່າງວິທີການ (ຄ່າທີ່ຖືກສົ່ງຕໍ່ ໃຊ້ ຫຼືຖືກລະເລີຍ) ແລະໝາຍຂໍ້ຜິດພາດທີ່ອາດເກີດຂຶ້ນແບບລະອຽດພ້ອມກັບໝາຍເລກແຖວຂອງພວກເຂົາ — String ທີ່ປຽບທຽບກັບ == stream ທີ່ເປີດໂດຍບໍ່ປິດ ແລະຕົວແປທີ່ຖືກຂຽນໃນສອງວິທີທີ່ແຕກຕ່າງກັນ. ຖ້າຜູ້ໃຫ້ບໍລິການ AI ທີ່ກຳລັງໃຊ້ງານຖືກເລືອກໃນ «ການຕັ້ງຄ່າ AI» ສະຫຼຸບການໄຫຼຈາກຜູ້ໃຫ້ບໍລິການນັ້ນກໍມີໃຫ້; ຖ້າບໍ່ມີ ໜ້າຈໍຈະໃຊ້ຄຳບັນຍາຍແບບອອບລາຍ ແລະບອກຂໍ້ຈຳກັດນັ້ນ. ຄຳບັນຍາຍ ແຜນທີ່ການເອີ້ນ ແລະການໄຫຼຂອງຂໍ້ມູນໃຊ້ການວິເຄາະຮູບແບບຂໍ້ຄວາມແບບອອບລາຍ ບໍ່ແມ່ນຕົວວິເຄາະ AST ທີ່ສົມບູນ — ວິທີການທີ່ວົງເລັບເປີດຂອງພວກເຂົາຢູ່ໃນແຖວຂອງຕົນເອງ ຊ່ອງຄລາສ ແລະການເອີ້ນຜ່ານການສະທ້ອນບໍ່ໄດ້ຖືກຕິດຕາມ — ແລະການເຕືອນການແຂ່ງຂັນຂໍ້ມູນອາດປາກົດສຳລັບຕົວແປທີ່ໃນຄວາມເປັນຈິງໃຊ້ພຽງແຕ່ສະຫຼັບກັນເທົ່ານັ້ນ.

ໂຮງງານຊຸດແອັບ ແລະຄວາມພ້ອມຂອງ Play Store
ເພື່ອກະກຽມແອັບສຳລັບ Google Play Store ໂດຍກົງຈາກໂທລະສັບ: ເປີດ «ໂຮງງານຊຸດແອັບ ແລະຄວາມພ້ອມຂອງ Play Store» ໃນເມນູຫຼັກ ເລືອກໂຄງການ ຈາກນັ້ນກົດ «ສ້າງຊຸດ AAB». IDE ສ້າງໄຟລ໌ .aab ຈາກ manifest ຊັບພະຍາກອນ ແລະຊັບສິນຂອງໂຄງການດ້ວຍ BundleConfig.pb ທີ່ແທ້ຈິງ ກວດສອບໂຄງສ້າງຊຸດ ຈາກນັ້ນແບ່ງຊຸດອອກເປັນ APK ຕົວແປທີ່ແທ້ຈິງ (ພື້ນຖານ ຕາມສະຖາປັດຕະຍະກຳ ຕາມພາສາ ແລະສາກົນ) ພ້ອມກັບຂະໜາດທີ່ວັດແທກຈາກການແບ່ງນັ້ນ ບໍ່ແມ່ນການຄາດຄະເນ. ຊຸດຖືກລົງນາມດ້ວຍ JAR v1 ດ້ວຍກະແຈໂຄງການດຽວກັນທີ່ໃຊ້ສຳລັບການລົງນາມ APK ແລະຕ່ອງໂສ້ລາຍເຊັນຂອງມັນຖືກກວດສອບທາງຄຣິບໂຕກຣາຟ. ໜ້າຈໍນີ້ຍັງກວດສອບຄວາມພ້ອມຂອງ Play — SDK ເປົ້າໝາຍຕ່ຳກວ່າ 35 ຖືກໝາຍວ່າ «ສູງ» ເພາະວ່າ Play Store ຕ້ອງການ 35 ຫຼືຫຼາຍກວ່ານັ້ນ ແລະຫໍສະໝຸດ 64 ບິດທີ່ຫາຍໄປກໍຖືກໝາຍວ່າ «ສູງ» ເຊັ່ນກັນ. bundletool ທີ່ແທ້ຈິງບໍ່ສາມາດເຮັດວຽກຢູ່ໃນອຸປະກອນໄດ້ ເພາະວ່າ bundletool ຕ້ອງການ JVM ໃນຂະນະທີ່ Android ບໍ່ມີ JVM; ເສັ້ນທາງຂ້າງເທິງແມ່ນເສັ້ນທາງທີ່ແທ້ຈິງທີ່ໃກ້ທີ່ສຸດຢູ່ໃນອຸປະກອນ.

ເຄື່ອງຈັກອັບເດດ OTA ແລະການປ່ອຍແບບເທື່ອລະຂັ້ນ
ເພື່ອສົ່ງການແກ້ໄຂນ້ອຍໆໂດຍບໍ່ຕ້ອງບັງຄັບໃຫ້ຜູ້ໃຊ້ດາວໂຫຼດ APK ທັງໝົດຄືນໃໝ່: ເປີດ «ເຄື່ອງຈັກອັບເດດ OTA ແລະການປ່ອຍແບບເທື່ອລະຂັ້ນ» ໃນເມນູຫຼັກ ເລືອກໂຄງການ ຂຽນເນື້ອໃນເວີຊັນເກົ່າ ແລະໃໝ່ ຈາກນັ້ນກົດ «ສ້າງແພັກເກັດແພັດ». IDE ຄຳນວນຄວາມແຕກຕ່າງ ແລະສ້າງແພັກເກັດແພັດ (patch-ota.zip) ດ້ວຍລາຍນິ້ວມື SHA-256 ຂອງເນື້ອໃໝ່ ຈາກນັ້ນກວດສອບວ່າອຸປະກອນນີ້ຢູ່ໃນຂັ້ນຕອນການປ່ອຍ 10 ເປີເຊັນທຳອິດຫຼືບໍ່. ແພັດຕອນນີ້ຮອງຮັບ binary delta ໃນໄຟລ໌ໃດກໍໄດ້ (ລວມທັງ DEX ແລະ APK) ຖືກຫໍ່ດ້ວຍລາຍເຊັນ RSA-2048 ແລະກວດສອບດ້ວຍກະແຈສາທາລະນະທີ່ເຊື່ອຖືໄດ້ກ່ອນການນຳໃຊ້ ແລະສາມາດດາວໂຫຼດໄດ້ຈາກເຊີບເວີຂອງນັກພັດທະນາພ້ອມກັບລາຍຊື່ການປ່ອຍຂອງມັນ; ຖ້າການສະໝັກລົ້ມເຫຼວ ໄຟລ໌ເກົ່າຈະຍັງຄົງຢູ່. ການນຳໃຊ້ແພັດກັບແອັບທີ່ກຳລັງເຮັດວຽກຖືກເຮັດໂດຍການລົງນາມຄືນໃໝ່ດ້ວຍກະແຈໂຄງການ ແລະຜ່ານ PackageInstaller ເພາະວ່າມັນເປັນໄປບໍ່ໄດ້ທີ່ຈະປ່ຽນໂຄ້ດຂອງຂະບວນການທີ່ກຳລັງເຮັດວຽກຈາກພາຍໃນຕົວມັນເອງ — APK ຖືກລັອກ ແລະ DEX ຖືກໂຫຼດແລ້ວ.

ສະຕູດິໂອທົບທວນໂຄ້ດຂອງທີມ
ເພື່ອທົບທວນການປ່ຽນແປງຂອງເພື່ອນຮ່ວມງານ ແລະແກ້ໄຂຂໍ້ຂັດແຍ່ງຂອງການລວມໂດຍບໍ່ຕ້ອງອ່ານລູກສອນ Git: ເປີດ «ສະຕູດິໂອທົບທວນໂຄ້ດຂອງທີມ» ໃນເມນູຫຼັກ ເລືອກໂຄງການ ພິມເວີຊັນຂໍ້ຄວາມສາມຢ່າງ (ພື້ນຖານ ທ້ອງຖິ່ນ ເພື່ອນຮ່ວມງານ) ຈາກນັ້ນກົດ «ເປີດການທົບທວນຂອງທີມ». IDE ລວມທັງສາມຢ່າງໂດຍອີງໃສ່ໜ່ວຍ syntax ຂອງ Java — ການປ່ຽນແປງສອງຢ່າງຢູ່ໃນແຖວດຽວກັນແຕ່ໃນຄຳຖະແຫຼງທີ່ແຕກຕ່າງກັນບໍ່ຖືກຖືວ່າເປັນຂໍ້ຂັດແຍ່ງອີກຕໍ່ໄປ — ແລະສະແດງແຕ່ລະຂໍ້ຂັດແຍ່ງເປັນທາງເລືອກລົງຄະແນນສຽງ: ໃຊ້ເວີຊັນທ້ອງຖິ່ນ ໃຊ້ເວີຊັນຂອງເພື່ອນຮ່ວມງານ ຫຼືລວມທັງສອງຢ່າງ — ແຖວຜົນໄດ້ຮັບຖືກແຊກໃນຕຳແໜ່ງຂໍ້ຂັດແຍ່ງຕົ້ນສະບັບເພື່ອໃຫ້ລຳດັບແຖວຍັງຖືກຕ້ອງ — ຈາກນັ້ນຂຽນຜົນໄດ້ຮັບລົງໃນ gabung-hasil.txt ໃນໂຄງການ. ຂ້າງລຸ່ມນີ້ແມ່ນກະດານວຽກຂອງໂຄງການ: ພິມຫົວຂໍ້ວຽກ ຈາກນັ້ນກົດ «ເພີ່ມວຽກ»; ວຽກຖືກບັນທຶກເປັນຂໍ້ຄວາມໃນໂຟລເດີ .tugas ພາຍໃນໂຄງການ ແລະຖືກ sync ຜ່ານ commits ໃນ Git ພາຍໃນແອັບ ດັ່ງນັ້ນກະດານສາມາດຖືກອ່ານຄືນໄດ້ຈາກປະຫວັດ commit ໃດກໍໄດ້. ການແບ່ງ syntax ນີ້ບໍ່ແມ່ນຕົວວິເຄາະ AST ທີ່ສົມບູນ ແລະ Git ພາຍໃນແອັບບັນທຶກພາບຖ່າຍເຕັມຮູບແບບຕໍ່ commit; ບໍ່ມີເຊີບເວີ sync ແຍກຕ່າງຫາກ.

ການບອກລະຫັດດ້ວຍສຽງ
ເພື່ອຂຽນລະຫັດດ້ວຍສຽງພາຍໃນເຄື່ອງແກ້ໄຂ: ເປີດໂຄງການໜຶ່ງໃນຕົວແກ້ໄຂ ແລ້ວກົດປຸ່ມ ການບອກລະຫັດດ້ວຍສຽງ. ເວົ້າຄຳສັ່ງເປັນພາສາອິນໂດເນເຊຍ ຕົວຢ່າງ buat fungsi tambah dengan parameter a angka dan b angka, buat kelas Mobil ຫຼື buat variabel teks nama sama dengan Budi — IDE ປ່ຽນຄຳເວົ້າເປັນ ບລັອກລະຫັດ Java, Kotlin, Python ຫຼື Compose ທີ່ຖືກຕ້ອງຕາມໄວຍາກອນ ແລະ ແຊກມັນໃນຕຳແໜ່ງເຄີເຊີ ແລ້ວອ່ານບົດສະຫຼຸບສັ້ນໆອອກສຽງຜ່ານ Jieshuo. ການບອກລະຫັດໃຊ້ບໍລິການປ້ອນສຽງທີ່ຕິດຕັ້ງມາໃນລະບົບ ໂດຍບໍ່ມີການອະນຸຍາດໄມໂຄຣໂຟນເພີ່ມເຕີມ ແລະ ຮັບຮູ້ພຽງແບບແຜນຄຳສັ່ງທີ່ລົງທະບຽນແລ້ວເທົ່ານັ້ນ; ຄຳເວົ້ານອກແບບແຜນເຫຼົ່ານັ້ນບໍ່ຖືກປ່ຽນເປັນລະຫັດ. ຕົວເລກທີ່ເວົ້າເປັນຄຳ (ຕົວຢ່າງ 'lima') ຍັງບໍ່ຖືກປ່ຽນເປັນຕົວເລກ.

ຫ້ອງຮ່ວມມືທ້ອງຖິ່ນ (ໂດຍບໍ່ໃຊ້ອິນເຕີເນັດ)
ເພື່ອເຮັດວຽກຮ່ວມກັນໃນຫ້ອງດຽວໂດຍບໍ່ມີອິນເຕີເນັດ: ເປີດ ການຮ່ວມມື ໃນເມນູຫຼັກ ແລ້ວເປີດສ່ວນ ຫ້ອງຮ່ວມມືທ້ອງຖິ່ນ. ໂທລະສັບໜຶ່ງເປີດເຊສຊັນໜຶ່ງ (IDE ສະແດງທີ່ຢູ່ IP ທ້ອງຖິ່ນ ແລະ PIN 6 ຫຼັກ) ໂທລະສັບອື່ນເຂົ້າຮ່ວມດ້ວຍທີ່ຢູ່ ແລະ PIN ນັ້ນ. ການປ່ຽນແປງຂໍ້ຄວາມຖືກສົ່ງເປັນຄວາມແຕກຕ່າງຂອງແຖວ APK ທີ່ສ້າງຂຶ້ນສາມາດສົ່ງໄປໂທລະສັບຂອງຜູ້ທົດສອບໄດ້ ແລະ ລາຍງານຂໍ້ຂັດຂ້ອງຈາກໂທລະສັບຂອງຜູ້ທົດສອບຖືກຮັບກັບຄືນມາ. ເຊສຊັນໜຶ່ງແມ່ນສຳລັບໝູ່ຄົນໜຶ່ງເທົ່ານັ້ນ; ຖ້າສອງຄົນປ່ຽນແຖວດຽວກັນແນ່ນອນໃນເວລາດຽວກັນ ການປ່ຽນແປງສຸດທ້າຍຈະຖືກໃຊ້. PIN ຖືກສົ່ງເປັນຂໍ້ຄວາມທຳມະດາໃນເຄືອຂ່າຍທ້ອງຖິ່ນ. ຫ້ອງນີ້ຍັງບໍ່ໄດ້ຖືກທົດສອບໃນໂທລະສັບແທ້.

ການຕັ້ງຄ່າ AI
ເພື່ອຕັ້ງຄ່າຜູ້ໃຫ້ບໍລິການ AI ແລະກະແຈ API ສຳລັບການສ້າງແອັບ: ໃນເມນູຫຼັກ ໃນກຸ່ມການຕັ້ງຄ່າ ກົດ «ການຕັ້ງຄ່າ AI» (ຂ້າງປຸ່ມ «ຕົວເຊື່ອມຕໍ່»). ເລືອກຜູ້ໃຫ້ບໍລິການທີ່ຈະໃຊ້ຈາກລາຍຊື່ທີ່ມີ ແລະກວດ «ປ່ຽນໂມເດລເມື່ອຜູ້ໃຫ້ບໍລິການຜິດພາດ» ເພື່ອໃຫ້ IDE ລອງໂມເດນຕໍ່ໄປຈາກຜູ້ໃຫ້ບໍລິການດຽວກັນໂດຍອັດຕະໂນມັດຖ້າໂມເດນລົ້ມເຫຼວ. ກົດ «ຈັດການກະແຈ API» ເພື່ອເພີ່ມກະແຈສຳຮອງ (ພິມຊື່ ແລະກະແຈ ຈາກນັ້ນກົດ «ບັນທຶກ»; ກະແຈຖືກສະແດງແບບປິດບັງ ມີພຽງ 4 ຕົວອັກສອນສຸດທ້າຍທີ່ເຫັນໄດ້). ກະແຈຖືກບັນທຶກໃນໂທລະສັບ ແລະບໍ່ເຄີຍຖືກສົ່ງໄປບ່ອນອື່ນນອກຈາກຜູ້ໃຫ້ບໍລິການທີ່ເລືອກເມື່ອສ້າງແອັບ. ຜູ້ໃຫ້ບໍລິການທີ່ເລືອກຕອນນີ້ຖືກໃຊ້ຢ່າງແທ້ຈິງໂດຍ «ສະຖາປະນິກແຜນຜັງໂຄງການ» ແລະ «ຜູ້ບັນຍາຍການໄຫຼຂອງເຫດຜົນໂຄ້ດ»; ການສ້າງແອັບຢູ່ໃນໜ້າຈໍ «AI ຕົວສ້າງແອັບ» ຍັງໃຊ້ AI ທ້ອງຖິ່ນໃນໂທລະສັບ (ໂດຍບໍ່ມີອິນເຕີເນັດ).

ຕົວເຊື່ອມຕໍ່
ເພື່ອວິເຄາະ APK ແລ້ວສົ່ງມັນ: ກົດໃນເມນູຫຼັກ ໃນກຸ່ມ ການຕັ້ງຄ່າ ທີ່ ຕົວເຊື່ອມຕໍ່ (ຂ້າງປຸ່ມ ການຕັ້ງຄ່າ AI). ເລືອກໄຟລ໌ APK ຈາກໂທລະສັບ IDE ອ່ານເນື້ອໃນຂອງມັນ (ຊື່ຊຸດ ເວີຊັນ ລາຍການກິດຈະກຳ) ແລ້ວກົດ ສົ່ງ APK ເພື່ອສົ່ງມັນຜ່ານເມນູແບ່ງປັນຂອງລະບົບ (ຕົວຢ່າງ WhatsApp ຫຼື Drive).

ພາສາ ແລະ ສຽງ
ເພື່ອປ່ຽນພາສາຂອງແອັບ: ເປີດ ການຕັ້ງຄ່າ ແລ້ວ ພາສາແອັບ ແລ້ວເລືອກພາສາໜຶ່ງ ຫຼື ຕາມລະບົບ. ໜ້າຈໍຫຼັກ ແລະ ໜ້າຈໍສ່ວນໃຫຍ່ຈະປ່ຽນໄປພາສາທີ່ເລືອກທັນທີໂດຍບໍ່ຕ້ອງປິດ ຫຼື ເປີດແອັບຄືນໃໝ່; ໜ້າຈໍບາງອັນ (ຕົວຢ່າງ Terminal, ການຮ່ວມມື, ການຕັ້ງຄ່າ AI ແລະ ຈັດການກະແຈ) ຍັງໃຊ້ພາສາເກົ່າຈົນກວ່າຈະເປີດຄືນໃໝ່. ຖ້າເລືອກ ຕາມລະບົບ ພາສາຈະຕາມພາສາລະບົບຂອງໂທລະສັບ.

ລາຍເຊັນເລີ່ມຕົ້ນຕໍ່ໂຄງການ ແລະ Anti Tamper
ນັບແຕ່ເວີຊັນ 5.7 ໂຄງການທີ່ບໍ່ໃຊ້ລາຍເຊັນຂອງຕົນເອງຖືກລົງນາມດ້ວຍກະແຈທີ່ຝັງຂອງໂຄງການເອງ (ສ້າງຄັ້ງດຽວໃນໂຟລເດີ tanda-tangan-bawaan ໃນໂຄງການ ແລະ ໃຊ້ຕໍ່ໄປ), ສະນັ້ນລາຍເຊັນທີ່ຝັງຕ່າງກັນຈາກໂຄງການໜຶ່ງໄປຫາອີກໂຄງການໜຶ່ງ — ບໍ່ແມ່ນກະແຈທີ່ແບ່ງປັນສຳລັບແອັບທັງໝົດອີກຕໍ່ໄປ. ຢ່າລຶບໂຟລເດີ tanda-tangan-bawaan — ໂດຍບໍ່ມີກະແຈນັ້ນ APK ໃໝ່ບໍ່ສາມາດແທນ APK ເກົ່າສຳລັບໂຄງການດຽວກັນໄດ້. ການຕັ້ງຄ່າຂອງແຕ່ລະໂຄງການ (ສະຖາປັດຕະຍະກຳແຍກ, ລາຍເຊັນຂອງຕົນເອງ, Anti Tamper, keystore ທີ່ເລືອກ, SDK) ດຽວນີ້ຖືກບັນທຶກໄວ້ໃນໄຟລ໌ settings.gradle ໃນໂຄງການ ແລະ ຖືກອ່ານຄືນທຸກຄັ້ງທີ່ໂຄງການຖືກສ້າງ. ໃນ ການຕັ້ງຄ່າ, ປະເພດລາຍເຊັນ ມີກ່ອງໝາຍ Anti Tamper ສຳລັບແອັບທີ່ສ້າງແລ້ວ — ຖ້າມີການເຄື່ອນໄຫວ ແອັບທີ່ສ້າງແລ້ວຈະກວດສອບລາຍເຊັນ ແລະ ເນື້ອໃນ dex ຂອງມັນຢູ່ໃນອຸປະກອນທຸກຄັ້ງທີ່ມັນເປີດ. ຖ້າຜູ້ອື່ນລົງນາມຄືນ ຫຼື ດັດແປງມັນ ແອັບຈະປະຕິເສດທີ່ຈະແລ່ນ. ເຄື່ອງມືດີບັກ ແລະ ສີດເຊັ່ນ Frida/Xposed ກໍ່ຖືກກວດພົບ ແລະ ປ່ອງຢ້ຽມແອັບຖືກລັອກຈາກການບັນທຶກໜ້າຈໍ.

ຕົວສ້າງວິດີໂອສາທິດ
ເພື່ອສ້າງວິດີໂອຕົວຢ່າງຂອງແອັບທີ່ສ້າງແລ້ວ — ເປີດ ຜູ້ສ້າງວິດີໂອຕົວຢ່າງ ໃນເມນູຫຼັກ, ເລືອກໂຄງການ, ຕື່ມຫົວຂໍ້ວິດີໂອ ແລະ ກົດ ສ້າງສະຄຣິບວິດີໂອຕົວຢ່າງ — IDE ຂຽນ video-demo.txt ພ້ອມສາກ ມາດຕະຖານ 5 ສາກ (ການເປີດ, ມຸມມອງຫຼັກ, ການກະທຳ 1, ການກະທຳ 2, ການປິດ) ພ້ອມຂໍ້ຄວາມບັນຍາຍ ແລະ ໄລຍະເວລາຂອງສາກແຕ່ລະສາກ. ກົດ ສ້າງ HTML Slideshow ເພື່ອສ້າງ video-demo.html ຈາກຮູບພາບຂອງໂຄງການ (ໄອຄອນ + ພາບໜ້າຈໍ, ຖ້າມີ), ປ່ຽນແປງອັດຕະໂນມັດທຸກໆ 5 ວິນາທີ. ນີ້ບໍ່ແມ່ນວິດີໂອ .mp4 — ສຳລັບວິດີໂອຈິງ ໃຫ້ເປີດ video-demo.html ໃນບຣາວເຊີໂທລະສັບ ແລະ ບັນທຶກໜ້າຈໍ ຫຼື ອ່ານບົດບັນຍາຍໃນ video-demo.txt ໃນຂະນະທີ່ບັນທຶກແອັບທີ່ກຳລັງແລ່ນ.

ຮູບລັກສະນະໃໝ່ແບບ Android Studio
ຮູບລັກສະນະຂອງ IDE ດຽວນີ້ຖືກເຮັດໃຫ້ສະອາດຄືກັບ Android Studio (ພຽງຮູບລັກສະນະ — ປຸ່ມ, ເມນູ ແລະ ການໄຫຼທັງໝົດຍັງຄົງຄືເກົ່າ) — ພື້ນຫຼັງສີເທົາອ່ອນ, ຫົວຂໍ້ໜ້າຈໍສີດຳໜາ, ປຸ່ມສີຟ້າທີ່ມີຂໍ້ຄວາມສີຂາວ ແລະ ຊ່ອງປ້ອນຂໍ້ມູນສີຂາວທີ່ມີຂອບບາງ. ເມນູຫຼັກຖືກຈັດເປັນກຸ່ມດ້ວຍສາຍຕາ (ການກະທຳຂອງຜູ້ສ້າງ, Cloud, Theme ແລະ ອື່ນໆ, ສຽງ, ລະຫັດ ແລະ ການກະທຳໃໝ່, ເຄື່ອງມື) ໂດຍບໍ່ປ່ຽນລຳດັບປຸ່ມ. Terminal ຍັງໃຊ້ແຜງດຳຄືກັບປ່ອງຢ້ຽມ Terminal ໃນ Android Studio ແລະ ຕົວແກ້ໄຂລະຫັດຍັງມີພື້ນຫຼັງສີຂາວ ແລະ ຂໍ້ຄວາມສີດຳ. ຂໍ້ຄວາມທັງໝົດຍັງຖືກ Jieshuo ອ່ານຢ່າງຈະແຈ້ງ.

ການຕັ້ງຄ່າ
ເພື່ອກຳນົດຄ່າແອັບ — ເປີດເມນູຕົວເລືອກໃນໜ້າຈໍຫຼັກ ແລະ ກົດ ການຕັ້ງຄ່າ. ພາຍໃນມີປະເພດ 12 ປະເພດ — ການຕັ້ງຄ່າ GitHub (ຄວາມປອດໄພ, ລາຍເຊັນຂອງຕົນເອງ, ບັນທຶກການສ້າງ ແລະ ໂທເຄັນ GitHub), ການຕັ້ງຄ່າການສ້າງ APK ໃນອຸປະກອນ (ລະຫັດຜ່ານ keystore ແລະ ການບັນທຶກບັນທຶກການສ້າງໃນອຸປະກອນ), Theme (ສີແອັບ), ລາຍເຊັນ (ການສ້າງ keystore ສຳລັບລາຍເຊັນຂອງຕົນເອງ ແລະ ກ່ອງໝາຍ Anti Tamper ສຳລັບແອັບທີ່ສ້າງແລ້ວ), ໂຟລເດີໂຄງການ (ສະຖານທີ່ໂຟລເດີໂຄງການ), ພາສາ ແລະ ສຽງ (ພາສາອິນເຕີເຟດ ແລະ ຄວາມໄວການເວົ້າຂອງໂໝດສຽງ), ຂະໜາດຂໍ້ຄວາມ ແລະ ຮູບລັກສະນະ (ຂະໜາດຟອນຂອງຕົວແກ້ໄຂ), ການສ້າງ (SDK ເປົ້າໝາຍເລີ່ມຕົ້ນ ແລະ ການແຍກສະຖາປັດຕະຍະກຳເລີ່ມຕົ້ນສຳລັບໜ້າຈໍສ້າງໂຄງການ), ການແຈ້ງເຕືອນ (ສຽງເມື່ອການສ້າງສຳເລັດ), ສຳຮອງອັດຕະໂນມັດ (ຕາຕະລາງສຳຮອງໂຄງການ), ໂປຣໄຟລ໌ຜູ້ພັດທະນາ (ຊື່, ເບີ WhatsApp ແລະ ບັນຊີທີ່ສະແດງຢູ່ໃນໜ້າຈໍບໍລິຈາກ) ແລະ ຄວາມເປັນສ່ວນຕົວ ແລະ ຂໍ້ມູນ (ການຕັ້ງຄ່າການຕັ້ງຄ່າຄືນໃໝ່ ແລະ ການລຶບຂໍ້ມູນແອັບ). ແຕ່ລະປະເພດມີປຸ່ມ ກັບຄືນໄປກ່ອນໜ້າ ເພື່ອກັບຄືນໄປເມນູປະເພດ. ການຕັ້ງຄ່າທີ່ບັນທຶກໄວ້ໃນປັດຈຸບັນ (ຍັງບໍ່ໄດ້ນຳໃຊ້) ຖືກອະທິບາຍຢ່າງຊື່ສັດຢູ່ໃນໜ້າຈໍ.

ບໍລິຈາກໃຫ້ນັກພັດທະນາ
ເພື່ອບໍລິຈາກໃຫ້ຜູ້ພັດທະນາ ຫຼື ທັກທາຍລາວ — ກົດປຸ່ມ ບໍລິຈາກໃຫ້ຜູ້ພັດທະນາ ຢູ່ໃກ້ປຸ່ມ ກ່ຽວກັບເຄື່ອງມື ໃນໜ້າຈໍຫຼັກ. ໜ້າຈໍບໍລິຈາກມີປຸ່ມ ຄັດລອກບັນຊີ BRI — ກົດມັນເພື່ອຄັດລອກເລກບັນຊີຂອງຜູ້ພັດທະນາ ແລະ ວາງມັນເຂົ້າແອັບທະນາຄານຂອງທ່ານ. ຍັງມີພາກ ທັກທາຍຜູ້ພັດທະນາໃນ WhatsApp — ຕື່ມຊື່ ແລະ ບ້ານເກີດຂອງທ່ານ ແລະ ກົດ ສົ່ງໃນ WhatsApp — WhatsApp ເປີດພ້ອມຂໍ້ຄວາມທັກທາຍທີ່ຕື່ມໄວ້ລ່ວງໜ້າ, ກົດ ສົ່ງໃນ WhatsApp ເທົ່ານັ້ນ ແລະ ກັບຄືນໄປແອັບ. WhatsApp ບໍ່ອະນຸຍາດໃຫ້ແອັບອື່ນສົ່ງຂໍ້ຄວາມອັດຕະໂນມັດ, ສະນັ້ນການສົ່ງຈະສືບຕໍ່ໂດຍທ່ານເອງໃນ WhatsApp.

ຄຳສັ່ງທີ່ມັກຂອງ Terminal
ເພື່ອບັນທຶກຄຳສັ່ງທີ່ໃຊ້ເລື້ອຍໆໃນ Terminal — ເປີດ Terminal ແລະ ກົດ ລາຍການທີ່ມັກ. ກົດ ເພີ່ມລາຍການທີ່ມັກໃໝ່, ຕື່ມຊື່ (ຕົວຢ່າງ ເບິ່ງໄຟລ໌) ແລະ ຄຳສັ່ງຂອງມັນ (ຕົວຢ່າງ ls -la) ແລະ ກົດ ບັນທຶກ — ລາຍການທີ່ມັກຖືກບັນທຶກໄວ້ຢ່າງຖາວອນໃນໂທລະສັບ. ກົດຊື່ລາຍການທີ່ມັກເພື່ອແລ່ນມັນໂດຍກົງໃນ terminal. ກົດ ລຶບລາຍການທີ່ມັກ ແລະ ເລືອກອັນໜຶ່ງເພື່ອລຶບ (ພ້ອມການຢືນຢັນ). ມີລາຍການທີ່ມັກທີ່ຕິດຕັ້ງໄວ້ລ່ວງໜ້າ 3 ອັນແລ້ວ — ເບິ່ງໄຟລ໌ (ls -la), ກວດສອບພື້ນທີ່ວ່າງ (df -h) ແລະ ລ້າງໜ້າຈໍ (clear) — ທັງໝົດສາມາດລຶບໄດ້. ຄຳສັ່ງວ່າງບໍ່ສາມາດບັນທຶກ ຫຼື ແລ່ນໄດ້. Terminal ແຈ້ງເຕືອນກ່ຽວກັບເລື່ອງນີ້ດ້ວຍຂໍ້ຄວາມ ແລະ ສຽງຖ້າມັນເກີດຂຶ້ນ.

ການວິເຄາະ ແລະ ຄຸນນະພາບ
ເພື່ອເບິ່ງບົດສະຫຼຸບຂອງການໃຊ້ແອັບ ແລະ ບົດລາຍງານການຂັດຂ້ອງ — ກົດປຸ່ມ ການວິເຄາະ ແລະ ຄຸນນະພາບ ຢູ່ໃກ້ປຸ່ມ ບໍລິຈາກໃຫ້ຜູ້ພັດທະນາ ໃນໜ້າຈໍຫຼັກ. ໜ້າຈໍນີ້ສະແດງຈຳນວນຄັ້ງທີ່ແອັບຖືກເປີດ, ໜ້າຈໍທີ່ເປີດຫຼາຍທີ່ສຸດ, ຈຳນວນການຂັດຂ້ອງ ແລະ ລາຍການການຂັດຂ້ອງລ່າສຸດ ພ້ອມຄຳແນະນຳການແກ້ໄຂສັ້ນໆ. ຂໍ້ມູນນີ້ຖືກບັນທຶກໄວ້ໃນໂທລະສັບຂອງທ່ານເທົ່ານັ້ນ ແລະ ບໍ່ໄດ້ຖືກສົ່ງໄປບ່ອນໃດ. ມີປຸ່ມ ລຶບຂໍ້ມູນການວິເຄາະ ພ້ອມການສົນທະນາຢືນຢັນເພື່ອລຶບຂໍ້ມູນທັງໝົດນີ້. ພຽງແຕ່ໜ້າຈໍລ່າສຸດຖືກບັນທຶກສຳລັບໜ້າຈໍຫຼັກ ແລະ ໜ້າຈໍນີ້.
