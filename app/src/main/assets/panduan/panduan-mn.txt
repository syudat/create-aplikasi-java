Create Aplikasi by Al Kautsar-д тавтай морилно уу
Create Aplikasi бол зөөврийн компьютер шаардлагагүйгээр утсан дээр шууд ажилладаг Android апп бүтээгч апп юм. Энэхүү апп нь хэн бүхэнд өөрийн Android аппыг бүтээх боломжийг олгодог бөгөөд апп бүтээж сурч эхэлж буй хүмүүс болон дэлгэц уншигч хэрэглэгчид ч мөн багтана. Энэхүү аппыг ашиглах бүрэн заавар энэ Tentang Alat дэлгэцэн дээр байна.

Энэ апп гэж юу вэ, хэнд зориулагдсан бэ
Create Aplikasi бол утсан дээр ажилладаг Android апп бүтээх хэрэгсэл юм. Энэхүү апп нь өөрийн Android аппыг бүтээхийг хүссэн хэн бүхэнд зориулагдсан бөгөөд анхлан суралцагчид болон дэлгэц уншигч хэрэглэгчид ч багтана. Энэхүү апп нь код засварлагч, төслийг турших Jalankan товч, APK бүтээх Bangun товч, мөн APK-д гарын үсэг зурах болон суулгах цэснүүдийг санал болгодог.

Энэ аппын зорилго
Энэ апп нь хэн бүхэн өөрийн Android аппыг утаснаасаа шууд хялбархан бүтээж чаддаг байхын тулд бүтээгдсэн. Түүний харагдах байдал нь шинэ хэрэглэгчид ч шууд туршиж үзэх боломжтой байхаар аль болох энгийн болгосон.

Шинэ төсөл бүтээх, алхам алхмаар
1. Үндсэн цэсэнд Buat Project-г дарна уу.
2. Төслийн төрлийг сонгоно уу: HTML, Situs Web, Java, Kotlin, Compose, эсвэл Python.
3. Аппын нэрийг бөглөнө үү, жишээ нь: Garuda Decode.
4. Багцын нэрийг (package name) бөглөнө үү, жишээ нь: com.android.garudadecode. Багцын нэр нь жижиг үсэг ашиглах ёстой бөгөөд цэгээр тусгаарлагдсан дор хаяж хоёр хэсгээс бүрдэх ёстой.
5. Аппын хувилбарыг бөглөнө үү, жишээ нь: 1.0, болон тоон хэлбэрээр хувилбарын кодыг, жишээ нь: 1. Хоосон орхивол хувилбар нь автоматаар 1.0, хувилбарын код нь 1 гэж бөглөгдөнө.
6. Шаардлагатай бол хамгийн бага SDK болон зорилтот SDK-г бөглөнө үү. Хоосон орхивол анхдагч утгуудыг ашиглана. Хамгийн бага SDK нь дэмжигддэг хамгийн доод Android хувилбар бөгөөд жишээ нь: 21 гэдэг нь Android 5.0 гэсэн үг. Зорилтот SDK-ийн дээд хэмжээ нь 36 (Android 16).
7. Аппын зөвшөөрлүүдийг сонгохын тулд Pilih Izin товчийг дарна уу, жишээ нь: INTERNET. INTERNET зөвшөөрөл нь аль хэдийн анхдагчаар тэмдэглэгдсэн байна. Зөвхөн аппад үнэхээр хэрэгтэй зөвшөөрлүүдийг л тэмдэглэнэ үү.
8. Хүсвэл APK-ийн хэмжээг жижиг болгохын тулд "Gunakan arsitektur terpisah 64 bit dan 32 bit"-г тэмдэглэнэ үү, мөн өөрөө бүтээсэн keystore ашиглахыг хүсвэл "Gunakan tanda tangan pribadi"-г тэмдэглэнэ үү.
9. Buat Proyek-г дарна уу. Шинэ төсөл Download/project хавтаст хадгалагдаж, Kelola Project дотор шууд харагдана.

Боломжтой төслийн төрлүүд
• HTML: WebView-ээр ажилладаг index.html, style.css, болон script.js-аас бүрдсэн харагдац. Утсан дээр шууд бүтээгдэнэ.
• Situs Web: WebView-ээр ажилладаг index.html, tentang.html, kontak.html, style.css, болон script.js-аас бүрдсэн, цэстэй (Beranda, Tentang, Kontak) вэбсайт. Утсан дээр шууд бүтээгдэнэ.
• Java: утсан дээр бүтээгдэнэ. MainActivity нь app/src/main/java/<nama-paket>/MainActivity.java дотор байрладаг. Харагдац нь app/src/main/res/layout/activity_main.xml-аас, текст нь app/src/main/res/values/strings.xml-аас, сэдэв нь app/src/main/res/values/styles.xml-аас ирдэг.
• Kotlin: аппад багтсан Kotlin хөрвүүлэгчийг ашиглан төхөөрөмж дээр (offline) эсвэл GitHub Actions-аар бүтээж болно. MainActivity нь app/src/main/java/<nama-paket>/MainActivity.kt дотор байрлах бөгөөд res файлууд нь Java төслийнхтэй ижил байна. Хөрвүүлэгчийн хэмжээ том учраас анхны Kotlin бүтээлт удаан бөгөөд Kotlin классуудад ханддаг .java файлуудыг одоохондоо бүтээх боломжгүй (.java файлууд нь .kt файлуудаас өмнө хөрвүүлэгддэг).
• Compose: интерфэйсийг нь Jetpack Compose-оор бүтээсэн орчин үеийн Android апп (XML байршил биш). MainActivity нь app/src/main/java/<nama-paket>/MainActivity.kt дотор байрладаг. Compose төслүүдийг GitHub Actions-аар (Bangun proyek цэс, дараа нь Bangun online) эсвэл Gradle ашиглан Termux дотор бүтээдэг, учир нь Compose нь төхөөрөмж дээр байхгүй Jetpack Compose сангуудыг шаарддаг.
• Python: аппын логик нь Python хэлээр (Chaquopy) app/src/main/python/main.py дотор бичигдэж, app/src/main/java/<nama-paket>/MainActivity.java доторх MainActivity хостоор ажиллуулагддаг. Python төслүүдийг утсан дээр шууд (Chaquopy ажиллах орчин аппад багтсан) эсвэл GitHub Actions-аар бүтээж болно. Python төслийн хамгийн бага SDK нь 24 (Android 7.0).

Төслийн архитектур өөрчлөх
Шинэ төсөл үүсгэхгүйгээр байгаа төслийн архитектурын сонголтыг өөрчлөхийн тулд: үндсэн цэсэнд «Төслийн архитектурыг өөрчлөх» дээр товшоод, төслөө сонгож, «64 битийн APK бүтээх (arm64-v8a)» эсвэл «32 битийн APK бүтээх (armeabi-v7a)» тэмдэглэгээг өөрчлөх; эсвэл «Төслүүдийг удирдах» хэсэгт төслийн нэр дээр удаан дарж, тухайн төслийн хувьд ижил дэлгэцийг шууд нээх «Архитектурыг өөрчлөх»-ийг сонгоно уу. Дүрэм нь: хоёр тэмдэглэгээ хоёулаа асаалттай бол бүтээн байгуулалт нь хоёр тусдаа APK файл үүсгэнэ, нэг нь 64 битийн, нэг нь 32 битийн; ганц тэмдэглэгээ асаалттай бол бүтээн байгуулалт нь 64 битийн болон 32 битийн төхөөрөмж дээр үргэлжлүүлэн ажилладаг нэг түгээмэл APK файл үүсгэнэ. Зөвхөн нэг хувилбарт зориулсан тусдаа APK одоогоор дэмжигдээгүй байна, учир нь бүтээн байгуулалтын зам нь зөвхөн хуваагдсан эсвэл түгээмэл сонголтыг мэддэг боловч хувилбар бүрийн сонголт нь дэлгэцийг дахин нээхэд алдагдахгүйн тулд төсөл дотор хадгалагдсан хэвээр байна.

Java, HTML, Situs Web, Kotlin, Compose, болон Python төслүүдийн файлын бүтэц
Java, HTML, Situs Web, Kotlin, Compose, болон Python төслүүд нь ердийн Android төслүүд шиг зохион байгуулагдсан байдаг. app хавтасны дотор src хавтас, түүний дотор main хавтас байна. main хавтасны дотор java хавтасны хажууд AndroidManifest.xml, layout/activity_main.xml болон values/strings.xml мөн values/styles.xml агуулсан res хавтас, мөн HTML болон Situs Web-д зориулсан index.html агуулсан assets хавтас (Situs Web нь tentang.html болон kontak.html-тэй ч бас байна) байна. HTML болон Situs Web төслүүд нь мөн app/src/main/java/<nama-paket>/MainActivity.java дотор өөрийн MainActivity-тай бөгөөд энэ нь index.html-ийг WebView дотор ачаалж, AndroidManifest дотор эхлүүлэгч (launcher) болдог. Python төслийн Python код нь app/src/main/python/main.py дотор, хост MainActivity.java нь app/src/main/java/<nama-paket>/MainActivity.java дотор байрладаг. AndroidManifest.xml, layout, strings, болон styles-ийг MainActivity шиг засварлагч дотор нээж өөрчилж болно. Манифест нь app хавтасны хажууд хэвээрээ байгаа хуучин төслүүдийг ч бүтээж болно, учир нь бүтээх үед апп нь эхлээд app/src/main/ доторх AndroidManifest.xml-ийг, дараа нь app хавтасны хажууд байгаа нэгийг, эцэст нь төслийн өгөгдлийн файлыг шалгадаг.

Зөвшөөрлийн дүрэм (чухал)
Төсөл бүтээх үед тэмдэглэсэн зөвшөөрлүүд нь төслийн төрлөөс хамааран зөвхөн нэг газарт бүртгэгддэг. Java, HTML, Situs Web, Kotlin, Compose, болон Python төслүүдийн хувьд тэмдэглэсэн зөвшөөрлүүд нь ЗӨВХӨН төслийн хавтасны доторх java хавтасны хажууд, app/src/main/ доторх AndroidManifest.xml дотор бүртгэгддэг. Java, HTML, Situs Web, Kotlin, Compose, болон Python төслүүдийн төслийн өгөгдлийн файлд зөвшөөрлийн жагсаалт агуулагддаггүй. Хэрэв та Java-г сонгоод INTERNET болон CAMERA-г тэмдэглэвэл AndroidManifest.xml дотор бүртгэгдэх зүйл нь өөр зөвшөөрөл нэмэгдэлгүйгээр зөвхөн INTERNET болон CAMERA л байна. Бүтээх үед апп нь зөвшөөрлүүдийг тэр газраас л уншдаг: Java, HTML, Situs Web, Kotlin, Compose, болон Python төслүүдийн хувьд app/src/main/ доторх AndroidManifest.xml-аас (хэрэв байхгүй бол хуучин төслүүдийн хувьд app хавтасны хажууд байгаа AndroidManifest.xml-аас), хуучин төслүүдийн хувьд төслийн өгөгдлийн файлаас.

Засварлагчийг ашиглах арга
Kelola Project-ийг нээж, засварлагчийг нээхийн тулд төслийн нэр дээр дарна уу. Засварлагч дотор файлуудыг нээж, код бичиж, өөрчлөлтүүдийг хадгалж болно. Java, HTML, Situs Web, Kotlin, Compose, болон Python төслүүдийн хувьд файлууд нь app/src/main хавтасны дотор зохион байгуулагдсан байна. Төслийг хуваалцахын тулд Ekspor ZIP-ийг ашиглана уу (доорх хэсгийг үзнэ үү).

Төслийг ажиллуулах арга
Засварлагч дотор төслийг туршихын тулд Jalankan-г дарна уу. HTML болон Situs Web төслүүдийн хувьд ажиллуулагдах зүйл нь WebView-ээр дамжсан index.html юм. Хэрэв алдаа гарвал алдааны мэдэгдлийг уншиж, кодыг засч, дараа нь дахин ажиллуулна уу.

APK бүтээх арга
Засварлагч дотор Bangun-г дарна уу. Бүтээх хоёр арга бий. Эхнийх нь төхөөрөмж дээр бүтээх: HTML, Situs Web, Java, Kotlin, болон Python төслүүдийн хувьд интернетгүйгээр утсан дээр шууд бүтээнэ. Хоёр дахь нь GitHub Actions-аар онлайн бүтээх: интернетээр GitHub дээр бүтээх бөгөөд бүх төрлийн төсөлд ашиглаж болно. Compose төслүүдийг зөвхөн хоёр дахь аргаар (Bangun online) эсвэл Gradle ашиглан Termux дотор бүтээж болно, учир нь Compose нь төхөөрөмж дээр байхгүй Jetpack Compose сангуудыг шаарддаг. Эхний бүтээлтийн үр дүнд хараахан гарын үсэг зураагүй байна. Дараа нь апп түүнд гарын үсэг зурдаг: анхдагч түлхүүрээр автоматаар, эсвэл төсөл бүтээх үед "Gunakan tanda tangan pribadi" нүдийг тэмдэглэсэн бол хувийн гарын үсгээр.

APK суулгах арга
APK бэлэн болсон үед түүнийг суулгахын тулд Pasang-г дарна уу. Android 8 болон түүнээс дээш хувилбарт утас эхлээд "Izinkan dari sumber ini"-г шаардах болно, учир нь энэ апп нь APK-г Play Store-оос гаднаас суулгадаг. Тэр зөвшөөрлийг Pengaturan дотор нэг удаа идэвхжүүлээд, дараа нь апп руугаа буцна уу: суулгалт нь Pasang-г дахин дарах шаардлагагүйгээр автоматаар үргэлжилнэ. Хэрэв Pasang товч харагдахгүй бол бүтээлт дууссан бөгөөд APK бүтээгдсэн эсэхийг шалгана уу.

Аппад гарын үсэг зурах арга
Суулгаж болохын тулд APK бүрийг гарын үсэг зурсан байх ёстой. Хоёр сонголт бий. Эхнийх нь анхдагч түлхүүр: апп нь юу ч хийх шаардлагагүйгээр автоматаар өөрөө гарын үсэг зурдаг. Хоёр дахь нь хувийн гарын үсэг: эхлээд үндсэн цэсний Buat Keystore цэсээр keystore бүтээж, түүний нууц үгийг сайтар хадгалаад, дараа нь төсөл бүтээх үед "Gunakan tanda tangan pribadi"-г тэмдэглэнэ үү. Keystore нь Download/project/signing дотор хадгалагддаг.

Төслийг ZIP болгон экспортлох
Ekspor ZIP нь төслийг найзуудтайгаа хуваалцах боломжтой байлгахын тулд санал болгогддог. Арга нь: Kelola Project дотор төслийн нэрийг удаан дарж, дараа нь Ekspor ZIP-ийг сонгоно уу. Үр дүн нь Download/project/<NamaProyek>.zip гэж хадгалагдана. bin хавтас нь багтаагүй тул хэмжээ нь жижиг, ердөө хэдэн арван KB л байна. Тэр ZIP файлыг найзууд руугаа илгээх эсвэл GitHub руу байршуулж болно.

Ekstensi JAWS
Ekstensi JAWS нь Jieshuo (CSR)-ийн өргөтгөлийн хөдөлгүүрийг ашигладаг бөгөөд түүний дэлгэц уншигчийг биш. Ингэснээр хэрэглэгч TalkBack ашиглаж байсан ч загвар ажиллах боломжтой хэвээр байна. Арга нь: үндсэн цэсэнд Ekstensi JAWS-ийг нээнэ үү. Автомат даралт нь өөрөө ажилладаг тул үйлчилгээг эхлээд Pengaturan Aksesibilitas дотор идэвхжүүлэх ёстой. Дараа нь шинэ загвар бүтээж болно: загварын нэрийг бичиж, OK-г дараад, дараа нь түүний нүдийг бөглөнө үү.

Daftar Klik нь цэгцтэй байлгахын тулд тусгаарлагдсан
Загварын дотор хоёр нүд бий: скриптийн нүд болон Daftar Klik нүд. Товчнуудын жагсаалт нь daftar_klik.txt файлд тусад нь хадгалагддаг бөгөөд нэг мөрөнд нэг нэр байна. Түүний агуулгын жишээ: tombolSimpan, tombolHapus, tombolBuka. Апп нээхийн тулд тэр жагсаалтад >WhatsApp гэж бичнэ үү. daftar_klik.txt файл хараахан байхгүй хуучин загварууд тэр анхдагч жишээг харуулна.

Санал болгож буй энгийн функцүүд
• klikTombol("tombolSimpan") — түүний текстэд үндэслэн нэг товчийг дардаг.
• klikDaftarTombol(daftar) — daftar_klik.txt доторх жагсаалтыг дардаг, нэг мөрөнд нэг товч, дэс дараалан, дараа нь хэд нь амжилттай болсон, хэд нь олдоогүйг мэдэгддэг.
• bukaAplikasi("WhatsApp") — аппыг түүний нэрээр нээдэг, эсвэл жагсаалтад ">WhatsApp" гэж бичдэг.
• klik(540, 1200) — дэлгэцийн координат дээр дардаг.
Бүх функц нь эхлээд энгийн болгосон байна. Та дассан үедээ нэмэлт функцүүдийг дараа нь нэмж болно.

Дэлгэц уншигчийн тухай
Энэ апп нь дэлгэц уншигчид ээлтэй байхаар зохион бүтээгдсэн. Бөглөх талбар бүрт шошго болон бөглөх жишээ байгаа бөгөөд бүх товчинд төвөгтэй хөдөлгөөн хийхгүйгээр хүрч болно. Ekstensi JAWS нь хэрэглэгч TalkBack ашиглаж байсан ч ажиллах боломжтой хэвээр байхаар бүтээгдсэн, учир нь ашиглаж байгаа зүйл нь түүний өргөтгөлийн хөдөлгүүр бөгөөд дэлгэц уншигч нь биш юм.

Нууцлал ба аюулгүй байдал
Төслүүд болон keystore нь таны утсанд хадгалагддаг. GitHub токеныг зөвхөн онлайн бүтээлтэд ашигладаг бөгөөд энэ апп дотор хадгалагддаг. Токен эсвэл keystore-ийн нууц үгээ хэнтэй ч бүү хуваалцаарай. Хэрэв та хувийн гарын үсэг ашигладаг бол keystore болон түүний нууц үгийг аюулгүй газар хадгалаарай, учир нь тэдгээр нь алдагдвал хуучин APK-г ижил гарын үсгээр шинэчлэх боломжгүй болно.

Шаардлагууд
Android 5.0 эсвэл түүнээс шинэ. Хадгалах зөвшөөрөл: Android 11 болон түүнээс дээш хувилбарт бүх файлд хандах зөвшөөрлийг ашигладаг, Android 10 болон түүнээс доош хувилбарт энгийн хадгалах зөвшөөрлийг (хадгалалтыг унших/бичих) ашигладаг, учир нь Android 10-т бүх файлд хандах зөвшөөрөл байхгүй. Төхөөрөмж дээр бүтээхэд ARM процессортой (32 эсвэл 64 бит) утас шаардлагатай. GitHub Actions-аар онлайн бүтээхэд интернет болон GitHub токен шаардлагатай. Kotlin төслүүдийг төхөөрөмж дээр бүтээж болох боловч Kotlin хөрвүүлэгчийн хэмжээ том учраас тэдгээрийн анхны бүтээлт удаан бөгөөд илүү их санах ой ашигладаг. Compose төслүүдийг GitHub Actions-аар эсвэл Gradle ашиглан Termux дотор бүтээдэг. Python төслүүд нь Android 7.0 эсвэл түүнээс шинэ (хамгийн бага SDK 24) шаардлагатай бөгөөд үр дүнгийн APK нь Python ажиллах орчин (Chaquopy) болон түүний стандарт санг агуулдаг тул том хэмжээтэй байдаг.

Terminal

Командын гаралт нь дэлгэц уншигчаар уншиж болох текст хэлбэрээр харагдах бөгөөд эцсийн үр дүнг сонсох Bacakan hasil товч байна. Энэ терминал нь утасны системийн shell-ийг ашигладаг тул nano болон vim гэх мэт интерактив програмуудыг энд одоохондоо ашиглах боломжгүй.

Lisensi (төлбөртэй хувилбар)
Аппуудыг зарахын тулд төсөл бүтээх үед "Aktifkan Lisensi"-г тэмдэглээд, дараа нь WhatsApp дугаараа бөглөнө үү. Бүтээгдсэн апп нь анх нээгдэхдээ лицензийн код шаардах болно: хэрэглэгч төхөөрөмжийн ID-гаа харж, Kirim ID Perangkat товчийг дарж тэр ID-г таны WhatsApp руу илгээх бөгөөд дараа нь та тэдний лицензийн кодыг хариу илгээнэ. Лицензийн код нь төхөөрөмжийн ID болон төслийн нууц үгээс (төслийн өгөгдлийн файлд байгаа lisensi_seed) тооцоологддог — тэр нууц үгийг сайтар хадгалж, бүү хуваалцаарай. AI апп бүтээгч
AI апп бүтээгч дэлгэц дээр хүссэн аппаа бичих буюу дуу хоолойгоор хэлнэ үү, жишээ нь - «хадгалах товчлууртай тэмдэглэлийн програм». Апп нь утасны дотор түлхүүр үгсийг шинжилж (интернетгүй, үнэгүй) дараа нь хамгийн тохиромжтой загвараас жинхэнэ төсөл үүсгэнэ - тооны машин, тэмдэглэл, хийх жагсаалт, вэб тооны машин, танилцуулга вэбсайт эсвэл тоолуур. Хэрэв таны тайлбарт тохирох загвар хараахан байхгүй бол апп нь хоосон төсөл үүсгэж, шударгаар хэлнэ - ойлгосон мэт дүр эсгэхгүй. AI-ийн үүсгэсэн төслийг Төсөл удирдах хэсэгт шууд нээж болно.

Апп нь төслийн үндсэн файлууд (index.html, MainActivity эсвэл main.py) болон заавар бүхий BACA-SAYA.txt болон info.txt файлуудыг агуулсан жижиг урьдчилж харах багцыг үүсгэнэ. Багцыг WhatsApp эсвэл Telegram-аар ZIP хэлбэрээр илгээнэ. Хүлээн авсан найз нь урьдчилж харахыг шууд нээж болно - HTML хуудсууд хөтөч дээр нээгдэж, Java/Kotlin/Python кодыг текст хэлбэрээр уншина.

Төслийн зах зээл

Онлайн зах зээл (интернетээс жишээ татах) хараахан байхгүй тул энэ зах зээлд апп дотор аль хэдийн байгаа жишээнүүд орно. Нэмсэн төслийг өөрийн үүсгэсэн төсөлтэй адил Төсөл удирдах хэсэгт нээж, өөрчилж болно.

Шууд хамтын ажиллагаа
Найзтайгаа нэг төсөл дээр ажиллахын тулд - үндсэн цэснээс Хамтын ажиллагаа гэснийг нээж, төслөө сонгож, өөрчлөлтийн тэмдэглэл (юу өөрчлөгдсөн) бичиж, Хамтран ажиллахын тулд хуваалцаарай гэснийг дарна уу. Төслийг дотор нь CATATAN.txt файл бүхий ZIP хэлбэрээр илгээнэ. Таны найз түүн дээр ажиллаж, ZIP-ийг буцааж илгээнэ. Та Хариу хүлээн авах гэснийг дарж, эхлээд өөрчлөлтийн тэмдэглэлийг уншиж, дараа нь хуучин төслийг солихын тулд Хэрэглэх гэснийг сонгох буюу санаа бодлоо өөрчилсөн бол Цуцлах гэснийг сонгоно уу. CATATAN.txt-гүй ZIP нь хамтын ажиллагааны багц биш - энгийн төслийн ZIP-ийн хувьд Төсөл удирдах хэсэгт байгаа Импортын төсөл гэснийг ашиглана уу.

Автомат програмын орчуулагч
Аппын текстийг өөр хэл рүү орчуулахын тулд - үндсэн цэснээс Апп орчуулагч гэснийг нээж, төсөл болон зорилтот хэл (англи, араб эсвэл япон) сонгож, Орчуулах гэснийг дарна уу. Толь бичиг нь утасны дотор аль хэдийн байгаа (интернетгүй, үнэгүй) бөгөөд өдөр тутмын үгсийг агуулдаг. Текстийг strings.xml, зохион байгуулалт болон кодоос уншиж орчуулна. Үр дүнг values-хэл/strings.xml хавтас руу (төсөлд strings.xml байгаа бол) болон төслийн хавтас дахь terjemahan-хэл.txt тайланд бичнэ. Толь бичигт хараахан ороогүй үгсийг байгаагаар нь үлдээж, тайлагнана - ингэснээр та өөрөө ямар үгсийг орчуулах ёстойгоо мэднэ.

Кодгүй тоглоом бүтээгч
Код бичихгүйгээр тоглоом үүсгэхийн тулд - үндсэн цэснээс Кодгүй тоглоом бүтээгч гэснийг нээж, тоглоомын төрөл (Тоо таах, Асуулт хариулт эсвэл Од барих) сонгож, тоглоомын нэр, тоо (түвшин/асуулт/од) болон ялалтын мессежийг бөглөж, Тоглоом үүсгэх гэснийг дарна уу. Тоглоомыг Төсөл удирдах хэсэгт шууд ажиллуулж болох бөгөөд бусад төсөлтэй адил APK хэлбэрээр бүтээж болох жинхэнэ төсөл болгон үүсгэнэ.

Автомат програмын тест
Төслийг бүтээхээсээ өмнө шалгахын тулд - Төсөл удирдах хэсэгт төслийн нэрийг удаан дарж, Автомат Тест гэснийг сонгоно уу. Код шалгагч AI
Төслийн кодыг асуудал үүсгэдэг хэв маягийн хувьд шалгахын тулд - үндсэн цэснээс Код шалгах гэснийг нээж, төслөө сонгож, Код шалгах гэснийг дарна уу. Шалгагч нь утасны дотор ажилладаг (интернетгүй) бөгөөд ашиглагдаагүй хувьсагчид, хоосон функцууд, тодорхой төгсгөлгүй давталтууд, кодонд шууд бичсэн текст (strings.xml-д илүү дээр), аюултай зөвшөөрлүүд болон API-ууд, TODO/FIXME тэмдэглэгээнүүд болон хөдөлж буй хөдөлгөөнт дүрсийг хайна. Олдвор бүрд файлын нэр, мөрийн дугаар болон засах зөвлөмж орно. Энэхүү шалгагч нь хэв маягт суурилсан бөгөөд жинхэнэ хиймэл оюун ухаан биш - хэв маягийг дагахгүй асуудлууд орхигдож болзошгүй.

Амжилттай дууссан хичээлүүдийг дууссан гэж тэмдэглэж, хадгална.

Үүл синхрончлол
Төслийг үүлэн рүү нөөцлөхийн тулд - үндсэн цэснээс Үүл синхрончлол гэснийг нээнэ үү. Орон нутгийн нөөцлөлт нь цаг хугацааны тэмдэг бүхий төслийн ZIP-ийг Download/cloud хавтас руу хадгалж, нөөцлөлтийн жагсаалтаас хэдийд ч сэргээж болно. GitHub нөөцлөлт нь төслийн ZIP-ийг таны хувийн repo руу байршуулдаг (GitHub тохиргоо хэсгээс токен ашиглаж) бөгөөд дахин татаж авч болно. Энэ бол гараар нөөцлөх болон сэргээх явдал - бүрэн автомат хоёр талын синхрончлолд сервер шаардлагатай тул хараахан байхгүй.

Автомат Backend бүтээгч
Серверийн код бичихгүйгээр Backend үүсгэхийн тулд - үндсэн цэснээс Backend бүтээгч гэснийг нээж, Backend төрөл (тэмдэглэл, хийх жагсаалт эсвэл зарлалын самбар) сонгож, төслийн нэрийг бөглөж, Backend үүсгэх гэснийг дарна уу. IDE нь маягтын хуудас болон утасны орон нутгийн хадгалалт (localStorage) дахь хадгалагдсан өгөгдлийн жагсаалт бүхий жинхэнэ HTML төслийг үүсгэнэ - апп ажиллах үед өгөгдлийг хадгалж, дахин уншина. Энэхүү Backend нь нэг утсан дээр ажилладаг. Интернет сервер байхгүй тул хоёр утас хараахан ижил өгөгдлийг хуваалцаж чадахгүй.

Автомат загвар зохион бүтээгч
Төсөлд өнгөт сэдэв өгөхийн тулд - үндсэн цэснээс Сэдвийн дизайнер гэснийг нээж, төсөл болон сэдэв (цайвар, харанхуй, цэнхэр, ногоон, улаан эсвэл нил ягаан) сонгоно уу. Урьдчилж харах нь сэдвийн 6 өнгийг (үндсэн, харанхуй үндсэн, онцлох, дэвсгэр, текст, хоёрдогч текст) харуулж, Jieshuo дуу хоолойгоор уншина. Загвар хэрэглэх гэснийг дарна уу - IDE нь colors.xml болон styles.xml (app_theme загвар) -ийг төсөлд бичих бөгөөд төсөл ажиллах буюу бүтээх үед шууд ашиглагдана.

Анимэйшн бүтээгч
Төсөлд хөдөлгөөнт дүрс өгөхийн тулд - үндсэн цэснээс Анимэйшн бүтээгч гэснийг нээж, төсөл, хөдөлгөөнт дүрсийн төрөл (бүдгэрэх, гулсах, эргэх, үсрэх эсвэл харайх), хугацаа (100-аас 10000 миллисекунд) болон зорилт (товчлуур, текст эсвэл зураг) сонгож, Анимац үүсгэх гэснийг дарна уу. IDE нь жинхэнэ хөдөлгөөнт дүрсийн файл бичнэ (Java/Kotlin/Compose төслүүдэд res/anim/anim_<төрөл>.xml эсвэл HTML/вэбсайт төслүүдэд animasi.css) бөгөөд дэлгэц дээр харуулсан хэрэглээний жишээ кодтой.

Үйлдэл бичигч
Ажлыг автоматаар давтахын тулд - IDE нь таны хийсэн үйлдлүүдийг тэмдэглэнэ (төсөл нээх, ажиллуулах, бүтээх, экспортлох, нөөцлөх, төсөл үүсгэх, файл хадгалах). Үндсэн цэснээс Үйлдэл бичигч гэснийг нээж, тэмдэглэгдсэн үйлдлүүдийн жагсаалтыг дарааллаар нь харж, Дахин тоглуулах гэснийг дарна уу - IDE нь автоматжуулж болох үйлдлүүдийг дахин гүйцэтгэнэ (нөөцлөлт болон төсөл үүсгэх нь тэндээ хийгдэнэ. Ажиллуулах, бүтээх болон экспортлох нь тэдгээрийн үндсэн дэлгэцийг нээнэ. Нээх болон хадгалах нь засварлагчийг нээнэ). Автоматжуулж болохгүй үйлдлүүдийг алгасч, төгсгөлд нь тайлагнана.

Автомат аюулгүй байдал
Төслийн аюулгүй байдлыг шалгахын тулд - үндсэн цэснээс Автомат аюулгүй байдал гэснийг нээж, төслөө сонгож, Аюулгүй байдлыг шалгана уу гэснийг дарна уу. IDE нь 8 зүйлийг орон нутгаар шалгана (интернетгүй) - аюултай зөвшөөрлүүд (байршил, SMS, дуудлага, камер, микрофон, харилцагчид), HTTP-ээр өгөгдөл илгээх, SMS илгээх, гарах дуудлагууд, кодонд шууд бичсэн нууц үг эсвэл түлхүүр, хамгаалалтгүй WebView, зөвшөөрөлгүйгээр экспортлосон бүрэлдэхүүн хэсэг болон шифрлэгдээгүй http хаяг. Олдвор бүрд засах зөвлөмжтэй хамт аюулгүй, анхааруулга эсвэл аюултай түвшин олгогдож, хураангуйг Jieshuo дуу хоолойгоор уншина.

AI офлайн
Интернетгүйгээр текст болон кодын тусламжийг ашиглахын тулд - үндсэн цэснээс AI офлайн гэснийг нээнэ үү. 4 хэрэгсэл бий - Текстийг сайжруулах (том үсэг, цэг тэмдэг болон давхар зай), Текст хураангуйлах (хамгийн чухал 3 өгүүлбэрийг авна), Програмын нэр үүсгэх (бичсэн тайлбараас) болон Хувьсагчийн нэр санал болгох (төсөл дэх 1–2 үсэгтэй хувьсагчийн нэрийг хайна). Эдгээр нь утасны доторх энгийн дүрмүүд бөгөөд жинхэнэ хиймэл оюун ухааны загвар биш юм. Текст засах үр дүнг Хэрэглэх товчлуураар төслийн strings.xml-д хэрэглэж болно.

Widget ба Wallpaper бүтээгч
Нүүр дэлгэцийн виджет үүсгэхийн тулд - үндсэн цэснээс Виджет ба дэлгэцийн зураг гэснийг нээж, төслөө сонгож, виджетийн текстийг бөглөж, Виджет үүсгэх гэснийг дарна уу. IDE нь WidgetSaya.java, виджетийн зохион байгуулалт, виджетийн мэдээллийг бичиж, төслийн AndroidManifest.xml-д хүлээн авагчийг нэмнэ - төслийг бүтээж, утасны нүүр дэлгэцээс виджет нэмнэ үү. Дэлгэцийн зургийн хувьд - текст болон дэвсгэр болон текстийн өнгийг бөглөж, урьдчилж хараад PNG хэлбэрээр Download хавтас руу хадгална уу эсвэл утасны дэлгэцийн зураг болгон шууд тохируулна уу.

Нийгмийн Сүлжээний Интеграци
Апп-д хуваалцах товчлууруудыг нэмэхийн тулд - үндсэн цэснээс Нийгмийн Сүлжээний Интеграци гэснийг нээж, төслөө сонгож, WhatsApp, Facebook эсвэл Telegram руу хуваалцахыг нэмнэ үү (эсвэл гурвууланг нь нэг дор). IDE нь төслийн үндсэн файл (MainActivity эсвэл index.html) руу жинхэнэ хуваалцах кодыг бичнэ. Хуваалцах Тест товчлуур нь IDE-ээс жишээ текст бүхий хуваалцах сонгогчийг нээх тул апп бүтээхээсээ өмнө урсгалыг мэдэрч болно.

Зургаас апп
Зургаас зургийн цомгийн апп үүсгэхийн тулд - үндсэн цэснээс Зургаас апп гэснийг нээж, зургийн цомгоос зураг сонгоно уу. IDE нь зургийн хэмжээ болон давамгайлсан өнгийг шинжилж, жинхэнэ зургийн цомгийн апп төслийг үүсгэнэ - зургийг төслийн assets руу хуулж, сэдвийн өнгийг зургийн давамгайлсан өнгөнөөс авна, аппын нэрийг зургийн файлын нэрнээс авна. Зургийн цомгийн аппыг ажиллуулах эсвэл бүтээхийн тулд Төсөл удирдах гэснийг нээнэ үү.

Харилцан Терминал (VT задлан шинжлэгч)
Терминал дээр харилцан програмуудыг ашиглахын тулд - үндсэн цэснээс Терминал гэснийг нээж, nano, vim, top эсвэл htop ажиллуулна уу. Терминал нь одоо VT задлан шинжлэгчийг ашигладаг (24 мөр x 80 багана дэлгэцийн тор) тул эдгээр програмууд зөв харагдана - курсор хөдөлж, мөрүүд устаж, дэлгэц нь жинхэнэ терминал шиг өөрчлөгдөнө. Харилцан програмуудыг хянахын тулд Tab, дээш сум, доош сум болон Esc-д зориулсан тусгай товчлуурууд бий. Үр дүн нь Jieshuo уншиж болох текст хэвээр байна. Сүүлийн мөрийг сонсохын тулд Дэлгэцийг уншина уу гэснийг дарна уу.

Terminal Exec (Програмын хоёртын хувилбар)
Апп хавтас дахь хоёртын файлыг (жишээ нь aapt2, ECJ, D8) Терминалаас ажиллуулахын тулд - командыг ердийн байдлаар бичнэ үү. IDE нь libkautsarexec.so ашигладаг тул апп хавтас дахь хоёртын файлуудыг Android 10 болон түүнээс хойшхи хувилбаруудад ажиллуулж болно. Энэ утсан дээр хоёртын exec зам ажиллаж байгаа эсэхийг шалгахын тулд Терминал дахь Exec Тест гэснийг дарна уу - үр дүнг байгаагаар нь харуулна. Хэрэв систем exec-ийг хориглосон бол системийн командууд болон shell скриптүүд үргэлжлүүлэн ажиллана. Хоёртын файлыг Төслийг бий болгох цэсээр ажиллуулна уу.

Терминал Амьд байлгах (KeepAlive)
Дэлгэц солих үед shell-ийг үргэлжлүүлэн ажиллуулахын тулд - Терминал нээж, команд ажиллуулж, Буцах гэснийг дарна уу эсвэл өөр дэлгэц рүү шилжинэ үү - shell үхэхгүй, Терминалын мэдэгдэл үргэлжлэн харагдаж байх тул нэг товшилтоор буцаж болно. Ажиллуулсан командуудыг Түүх хэсэгт хадгална (Түүх товчлуур эсвэл командын талбар дахь дээш/доош сумнууд) бөгөөд байнга ашигладаг командуудыг Дуртай хэлбэрээр хадгалж болно (Дуртай товчлуур). Дууссаны дараа shell-ийг үнэхээр дуусгахын тулд Бүрхүүлийг хаа гэснийг дарна уу. Төслийн цэс болон засварлагчийн цэсэнд мөн Терминал дээр бүтээх товчлуур бий - Терминал нь бүтээх команд урьдчилан бөглөсөн төслийн хавтас дотор нээгдэнэ.

Терминал хэрэгслийг суулгах (туршилт)
Туршилтын онцлог - Терминал дотор хөгжүүлэгчийн alat-termux repo (github.com/syudat/alat-termux) -оос Termux орчныг суулгах Терминал хэрэгслийг суулгах (туршилт) товчлуур байгаа бөгөөд энэ нь албан ёсны Termux хувилбараас авдаг Termux суулгана уу товчлуураас гадна нэмэлт зам юм. Толин тусгалын агуулга нь албан ёсны хувилбартай яг ижил бөгөөд суулгах явцад SHA-256-аар шалгагддаг. Орчин суулгасны дараа та pkg update болон pkg install командуудыг ашиглаж болох бөгөөд repo-оос нэмэлт хэрэгслүүдийг терминал руу суулгана - info-terminal орчны мэдээллийг харах, bersih-terminal кэшийг цэвэрлэх болон cadangkan-proyek төслийн хавтсыг огноотой нэг tar.gz файл руу хадгалах. Дараа нь апп нь үндсэн Linux багцууд (git, python, curl, wget, nano, openssh, zip, unzip) болон гарын үсэгтэй APK бүтээх хэрэгслүүд (openjdk-21, kotlin, gradle, ecj, aapt2, d8, apksigner, clang, cmake, ninja, make) -ийг албан ёсны Termux repo-оос автоматаар суулгадаг тул терминал нь апп бүтээхэд шууд бэлэн болно. Том багцуудыг (хэдэн зуун MB) татахад хугацаа шаардагдаж магадгүй. Суулгалт ажиллаж байх үед явц болон командын үр дүнг Терминалын үндсэн дэлгэц дээр харуулж, эцсийн үр дүнг дэлгэц уншигч дуу хоолойгоор уншина. Хэрэв багцын суулгалт хараахан дуусаагүй бол үргэлжлүүлэхийн тулд Терминал хэрэгслийг суулгах (туршилт) гэснийг дахин дарна уу.

Бүрэн дууны горим
IDE-ийг дуу хоолойгоор бүрэн хянахын тулд - үндсэн цэснээс Бүрэн дууны горим гэснийг нээж, Сонсож эхлэх гэснийг дарна уу. IDE нь тасралтгүй сонсдог - команд бүрд товчлуур дарах шаардлагагүй - командыг гүйцэтгэж, дуу хоолойгоор хариулдаг. 26 команд бий - үүсгэх, бүтээх, нээх, ажиллуулах, жагсаах, хайх, устгах, шалгах, шалгах, экспортлох, нөөцлөх, хуваалцах, дүрс үүсгэх, орчуулах, Терминал дээр бүтээх, Дэлгэцийг уншина уу, бүх дэлгэцийг нээх (аюулгүй байдал, AI офлайн, виджет, нийгмийн сүлжээ, тоглоом, сурах, үүл, Backend, сэдэв, хөдөлгөөнт дүрс, бичигч зэрэг), Буцах, Хаах болон тусламж. Хэрэв горим идэвхтэй хэвээр байвал энэ дэлгэцийг дахин нээхэд сонсох нь автоматаар үргэлжилнэ. Горимыг унтраахын тулд Сонсохоо боль гэснийг дарна уу. Хэрэв утсанд дуу хоолой таних үйлчилгээ байхгүй бол командуудыг текст талбарт бичиж болно.

Код орчуулагч
Интернетгүйгээр хэл хооронд код орчуулахын тулд - үндсэн цэснээс Код орчуулагч гэснийг нээж, төслөө сонгож, эх файлыг (.java/.kt) сонгож, чиглэлийг сонгоно уу - Java-аас Kotlin руу. Орчуулах гэснийг дарна уу - үр дүнг орчуулах боломжгүй мөрүүдийн тайлантай хамт харуулна (эдгээр мөрүүдийг байгаагаар нь үлдээж, тэмдэглэнэ). Ижил хавтас дотор шинэ файл (нэр-орчуулсан.java/.kt) бичихийн тулд Үр дүнг хадгалах гэснийг дарна уу. Эх файл хэзээ ч солигдохгүй. Энэ бол хэв маягийн дүрмийн орчуулагч бөгөөд хөрвүүлэгч биш - ашиглахаасаа өмнө үр дүнг үргэлж шалгана уу.

Апп доторх Git
Termux-гүйгээр IDE дотор Git ашиглахын тулд - үндсэн цэснээс Апп доторх Git гэснийг нээж, төслөө сонгож, Git Repo үүсгэх гэснийг дарж, тухайн төсөлд орон нутгийн repo (.git) үүсгэнэ үү. Сүүлийн Commit-тэй харьцуулж шинэ, өөрчлөгдсөн эсвэл устгасан файлуудыг харахын тулд Статус шалгах гэснийг дарна уу. Commit мессежийг бөглөж, төслийн агшин зургийг хадгалахын тулд Commit гэснийг дарна уу. Commit түүхийг харахын тулд Commit Log харах гэснийг дарна уу. GitHub руу Push хийх болон GitHub-аас Pull хийх нь GitHub токен (pembuat-aplikasi-build repo) -оор дамжуулан агшин зургуудыг ашигладаг - git протокол биш. Clone, Push (системийн git) болон Pull (системийн git) нь утсан дээр git хоёртын файл суулгасан тохиолдолд л ажиллана (ихэвчлэн байдаггүй). Энэ бол бүрэн Git биш - нэгтгэх, салбарлах, ялгах зүйл байхгүй - Commit бүр төслийн бүрэн ZIP агшин зургийг хадгалдаг.

Зар бүтээгч
Бүтээгдсэн апп-д зар нэмэхийн тулд - үндсэн цэснээс Зар бүтээгч гэснийг нээж, төсөл, нийлүүлэгч (AdMob, Unity Ads эсвэл AppLovin) болон зарын төрөл (Banner, Interstitial эсвэл шагналт) сонгоно уу. Хэрэв байгаа бол зарын нэгжийн ID-г бөглөнө үү - хоосон бол туршилтын ID-г ашиглана (AdMob нь Google-ийн албан ёсны туршилтын ID-г ашигладаг. Unity нь жишээ Game ID-г ашигладаг. AppLovin нь хоосон зай ашигладаг). Java болон Kotlin код болон зааврыг харахын тулд Зарын код үүсгэх гэснийг дарна уу. Бүгдийг төсөл дэх iklan-<нийлүүлэгч>-<төрөл>.txt файл руу бичихийн тулд Төсөлд хадгалах гэснийг дарна уу. Энэ бол кодын загвар + заавар бөгөөд зарын SDK биш - SDK нь IDE-д ороогүй болно. Жинхэнэ зарууд зөвхөн нийлүүлэгчийн данс үүсгэх, зарын нэгж үүсгэх, өөрийн нэгжийн ID-г буулгах болон SDK хамаарлыг төслийн build.gradle-д нэмэх үед л гарч ирнэ.

Хүүхдийн горим
IDE-ийг хүүхэдтэй хамт ашиглахын тулд - үндсэн цэснээс Хүүхдийн горим гэснийг нээнэ үү. Дэлгэцийг том товчлууруудаар хялбаршуулж, зөвхөн 4 аюулгүй үйлдэл бий - Төсөл үүсгэх (аюулгүй загваруудаас - тооны машин, Тоо таах, Асуулт хариулт, Од барих), Төсөл нээх, ажиллуулах болон Сурах Горим. Энэ дэлгэц дээр устгах, экспортлох, нөөцлөх эсвэл токен тохируулах товчлуур байхгүй. Анх орохдоо 4 оронтой PIN үүсгэнэ үү - эцэг эхчүүд энэ PIN-ийг хүүхдийн горимоос гарахдаа ашигладаг (Хүүхдийн горимоос гарах товчлуур эсвэл Буцах товчлуур). Энэ PIN нь бага насны хүүхдүүдэд зориулсан хөнгөн хамгаалалт бөгөөд жинхэнэ аюулгүй байдал биш юм.

Wear OS & TV App Creator
Цагны апп (Wear OS) эсвэл ТВ апп (Android TV) үүсгэхийн тулд - үндсэн цэснээс Wear OS ба TV апп бүтээгч гэснийг нээж, зорилтоо (Wear OS, Android TV эсвэл хоёуланг нь) сонгоно уу. Төслийн нэрийг бөглөж, Шинэ Wear/TV төсөл үүсгэх гэснийг дарна уу - IDE нь Java төслийг үүсгэж, өөрчилнө - эсвэл байгаа төслийг сонгож, Энэ төсөлд хэрэглэх гэснийг дарна уу. Өөрчлөлтүүд - манифест дахь uses-feature, ТВ-д зориулсан LEANBACK_LAUNCHER төрөл болон баннер, мөн өөрчлөгдсөн activity_main.xml зохион байгуулалт (Wear - жижиг дэлгэц. ТВ - D-pad-д тохирсон том дэлгэц). Бүрэн тайлбарыг төсөл дэх wear-tv.txt руу бичнэ. Энэ бол төслийн загвар - бүтээх + шалгахын тулд Wear OS эсвэл Android TV төхөөрөмж/эмулятор шаардлагатай хэвээр байна. ТВ баннер (banner.png 320x180) автоматаар үүсгэгддэггүй, өөрөө нэмэх ёстой (жишээ нь Дүрс бүтээгч-ээр дамжуулан).

Төслийн газрын зураг
Төслийн бүтцийг харахын тулд - үндсэн цэснээс Төслийн газрын зураг гэснийг нээж, төслөө сонгож, Газрын зураг харуулах гэснийг дарна уу - IDE нь хавтас болон файлуудын жагсаалтыг тэдгээрийн хэмжээ, нийт хэмжээ, файлын төрлөөрх хэмжээ болон чухал файлууд (үндсэн файл, манифест, зохион байгуулалт, мөрүүд, дүрс, вэб хуудас) -тай хамт харуулна. Ижил газрын зургийг төслийн үндэс рүү бичихийн тулд peta-proyek.txt-г хадгал гэснийг дарна уу. bin/ хавтас (бүтээлийн үр дүн) болон .git/ хавтас (орон нутгийн repo) нь газрын зурагт ороогүй болно, учир нь тэдгээрийн агуулгыг дахин үүсгэж болно.

APK хэмжээний тооцоолуур
Бүтээхээсээ өмнө бүтээгдсэн APK-ийн хэмжээг тооцоолохын тулд - үндсэн цэснээс APK хэмжээний тооцоолуур гэснийг нээж, төслөө сонгож, Тооцооллыг тооцоолох гэснийг дарна уу. IDE нь төрлөөр дэлгэрэнгүй мэдээлэл (код/DEX, нөөц, хөрөнгө, суулгагдсан сангууд, манифест + resources.arsc, ерөнхий зардал), нийт тооцоолол, хамгийн том 5 файл болон бууруулах зөвлөмжүүд (жишээ нь том зургийг нягтралаар багасгах, урт дууг хугацаагаар таслах) -ийг харуулна. Энэ бол тооцоолол бөгөөд яг хэмжээ биш - жинхэнэ хэмжээ нь aapt2 шахалт, ашиглагдаагүй кодыг арилгах (R8) болон бүтээлийн үр дүнгийн нөөцөөс шалтгаалан ялгаатай байж болно.

APK шинжлэгч
Дууссан APK-ийн агуулгыг уншихын тулд (Android Studio дахь APK шинжлэгчтэй адил) - үндсэн цэснээс APK шинжлэгч гэснийг нээж, төслөө сонгож, Бүтээлийн үр дүнгийн APK шинжилгээ гэснийг дарна уу. IDE нь тухайн төслийн bin хавтас дахь хамгийн сүүлийн APK-ийг уншиж, багцын нэр, хувилбар, хамгийн бага болон зорилтот SDK, ашигласан зөвшөөрлүүдийн жагсаалт, dex файлуудын тоо, хэсэгчилсэн хэмжээний дэлгэрэнгүй мэдээлэл (програмын код, нөөц, хөрөнгө, суулгагдсан сангууд, гарын үсэг) болон хамгийн том 10 оруулалтыг тайлагнана. Аль хэсэг нь APK-ийг том болгож, бүтээгдсэн апп ямар зөвшөөрөл ашигладаг болохыг мэдэхэд хэрэгтэй.

Дэлгэцийн хэмжээний урьдчилж харах
Төслийн харагдах байдлыг олон дэлгэцийн хэмжээн дээр нэгэн зэрэг шалгахын тулд (Android Studio дахь шиг) - үндсэн цэснээс Дэлгэцийн хэмжээний урьдчилж харах гэснийг нээж, төслөө сонгож, Дэлгэцийн хэмжээг шалгана уу гэснийг дарна уу. IDE нь төслийн бүх зохион байгуулалтыг уншиж, тогтмол өргөнтэй (жишээ нь 400dp) болон 320, 360, 411 эсвэл 480 dp дэлгэцийн өргөнөөс хэтэрсэн элементүүдийг тайлагнана, учир нь жижиг дэлгэцтэй утсан дээр ийм элемент нуугдаж эсвэл хальж болзошгүй. match_parent эсвэл wrap_content өргөнтэй элементүүд дэлгэцэнд автоматаар дасан зохицож, шалгах шаардлагагүй.

Нөөц менежер
Төслийн бүх нөөцийг нэг газарт харж, удирдахын тулд (Android Studio дахь нөөц менежертэй адил) - үндсэн цэснээс Нөөц менежер гэснийг нээж, төслөө сонгож, Нөөцүүдийг харах гэснийг дарна уу. IDE нь төрлөөр файлын тоо болон хэмжээ (drawable, layout, values, mipmap болон бусад), strings.xml, colors.xml болон styles.xml агуулгыг тайлагнана. Ижил дэлгэцээс нэр болон утгыг бөглөж strings.xml-д шинэ мөр болон colors.xml-д шинэ өнгө нэмж болно - нэрийг шалгаж, давхардлыг татгалздаг тул XML файл эвдэрдэггүй.

Хөнгөн гүйцэтгэлийн хяналт
Ажиллаж байгаа аппын RAM болон процессорын хэрэглээг хянахын тулд (Android Studio дахь Profiler шиг, хөнгөн хувилбар) - үндсэн цэснээс Хөнгөн гүйцэтгэлийн хяналт гэснийг нээж, эхлээд шалгахыг хүссэн аппаа ажиллуулна уу (жишээ нь шалгаж байгаа бүтээгдсэн апп), түүний багцын нэрийг бөглөнө үү - эсвэл төсөл сонгож, Төслийн багцын нэрийг бөглөнө үү гэснийг дарна уу - дараа нь Хяналтыг эхлүүлэх гэснийг дарна уу. Хоёр секунд тутамд IDE нь тухайн аппын RAM (PSS) болон CPU-ийг утасны чөлөөт RAM-тай хамт тэмдэглэнэ. Дундаж болон дээд хэмжээний хураангуйг харахын тулд Зогс гэснийг дарна уу. Нэмэлт зөвшөөрөл байхгүй. Шинэ Android хувилбаруудад өөр аппын процессорыг унших хандалтыг систем хязгаарладаг тул CPU-г уншиж чадахгүй бол тайлан үүнийг хэлж, RAM хяналт үргэлжилнэ.

Хүртээмжийн аудит
Төслийг гаргахаасаа өмнө түүний байршил нь дэлгэц уншигчдад ээлтэй (TalkBack/Jieshuo) эсэхийг шалгахын тулд: үндсэн цэсэнд Хүртээмжийн аудит хэсгийг нээгээд төсөл сонгоод дараа нь Байршлын жагсаалтыг ачаалах товчийг дараад байршлын файл сонгоно уу. IDE нь тухайн XML файлыг уншиж, шошгогүй товчлууруудыг тэдгээрийн мөрийн дугаартай хамт, дахин дахин ашиглагдсан шошгууд болон бие биенээ давхцаж буй элементүүдийг мэдээлж, дараа нь Jieshuo чангаар уншдаг шиг фокусын дарааллын хуулбарыг бүтээнэ. Хэрэв товчлуур шошгогүй бол түүний шошгыг бөглөөд дараа нь Шошгыг автоматаар оруулах товчийг дарна уу — шошго нь байршлын файлд contentDescription хэлбэрээр бичигдэнэ. Энэ шалгалт нь зөвхөн байршлын XML-ийг уншдаг; Compose харагдац болон дууссан APK файлууд хараахан скан хийгдээгүй байна.

Гацалтын задлан шинжилгээ
Өвөрмөц ID-тэй эвдрэлийн бүртгэлээс апп яагаад өөрөө хаагдсаныг мэдэхийн тулд: үндсэн цэсэнд «Эвдрэлийн задлан»-ийг нээж, бүртгэлийн жагсаалтаас эвдрэлийн ID-г сонгоод, «Шалгах» дээр товшоорой. IDE нь бүртгэл дэх анги болон мөрийн дугаарыг төслийн эх үүсвэртэй тааруулж, шалтгааныг Индонез хэлээр тайлбарладаг (жишээлбэл хоосон лавлагаа, хараахан хүсээгүй зөвшөөрөл эсвэл JSON алдаа), кодын нөхөөсийн саналтай хамт. Эх мөрийн мөр нь эвдрэл гарах үед байсан хэвээрээ байгаа үед л «Нөхөөсийг хэрэглэх» дээр товшоорой; өөрчлөгдсөн бол нөхөөсийг татгалзаж, IDE танаас өөрөө шалгахыг хүсдэг. Бүтээгдсэн аппын эвдрэлийн хувьд «Эвдрэл баригчийг төсөлд оруулах» дээр товшоод, дараа нь APK-г ердийнхөөрөө бүтээнэ үү: бүтээгдсэн апп өөрийн эвдрэлийг барьж, бүртгэлээ утсан дээр бичдэг бөгөөд тухайн бүртгэлийг «Бүтээгдсэн аппын эвдрэлийн бүртгэлийг олох» товчлуураар олж болно. Шударга хязгаарлалт: бүртгэлийг Android 11 болон түүнээс дээш хувилбарт нийтийн Download хавтсанд хуулах нь бүх файлд хандах зөвшөөрөлгүйгээр бүтэлгүйтэж болзошгүй.

Парадигм хоорондын хөрвүүлэгч
Энгийн Java кодыг Kotlin руу эсвэл энгийн XML байршлыг Compose код руу хөрвүүлэхийн тулд: үндсэн цэсэнд Парадигм хоорондын хөрвүүлэгч хэсгийг нээгээд төсөл болон файл сонгоод дараа нь Урьдчилан харах товчийг дарна уу. IDE нь хөрвүүлэлтийн үр дүнг текст хэлбэрээр харуулдаг — эхлээд үүнийг шалгаарай, учир нь танихгүй мөрүүд хэвээрээ үлдэж, Java дахь static үг нь Kotlin-д хасагддаг (ашиглахаасаа өмнө утгыг нь шалгаарай). XML-ээс Compose руу хөрвүүлэх нь зөвхөн текст, зөвлөмж болон чиглэлийг өөрчилдөг — хэмжээ, өнгө болон бусад шинж чанарууд хараахан ороогүй байна. Хэрэв үр дүн зөв бол зорилтот файлыг бичихийн тулд Файлд хэрэглэх товчийг дарна уу; эх файл өөрчлөгдөхгүй. Зөвхөн аюулгүй, нийтлэг хэв маягийг хөрвүүлдэг.

Орон нутгийн бичил сервер
Интернетгүйгээр сервер шаарддаг аппыг туршихын тулд: үндсэн цэсэнд «Орон нутгийн микро сервер»-ийг нээж, маршрутын тодорхойлолтыг бичнэ үү (жишээлбэл GET /halo, дараа нь түүний JSON хариулт) дараа нь «Серверийг эхлүүлэх» дээр товшоорой. IDE нь ижил утсан дээр жижиг HTTP сервер ажиллуулдаг (зөвхөн HTTP, TLS байхгүй, ижил Wi-Fi сүлжээнд зориулсан) бөгөөд хүсэлт болон хариулт бүрийг дэлгэцэн дээр бүртгэдэг. Маршрутууд нь {nama} гэх мэт параметр болон энгийн API түлхүүрийг ашиглаж болно. Серверийг бүтээгдсэн APK-д мөн багцалж болно: «Серверийг төсөлд багцлах» дээр товшоод, серверийн эх үүсвэр, хөрөнгө болон manifest нь төсөлд оруулагддаг тул бүтээгдсэн апп ажиллах үед өөрөө сервер болдог. IDE дахь сервер нь түүний дэлгэц хаагдах үед зогсдог.

Аюулгүй байдлын аудитор
Нийтлэхээсээ өмнө төслийн кодын аюулгүй байдлын цоорхойг шалгахын тулд: үндсэн цэсэнд «Аюулгүй байдлын аудитор»-ийг нээж, төслөө сонгоод, «Скан хийж эхлэх» дээр товшоорой. IDE нь төслийн код, manifest болон тохиргоог скан хийж, өндөрөөс бага эрсдэл хүртэлх олдворыг мэдээлдэг — кодонд нээлттэй үлдсэн API түлхүүр, зөвшөөрөлгүйгээр илэрсэн бүрэлдэхүүн хэсэг, JavaScript интерфейсээрээ JavaScript-г идэвхжүүлдэг WebView, сул крипто (MD5, SHA1, DES), TLS-гүй http хаяг болон кодонд шууд бичсэн нууц үг — тэдгээрийн файл болон мөрийн дугаартай хамт. Засвар нь аюулгүй олдворын хувьд (жишээлбэл MD5-г SHA-256 руу эсвэл http-г https руу өөрчлөх) «Засварыг хэрэглэх» дээр товшоорой; API түлхүүр болон нууц үгийн хувьд IDE нь зөвхөн засварын санал харуулдаг, учир нь орлуулалтыг хөгжүүлэгч өөрөө шийдэх ёстой. Скан нь одоо бүтээгдсэн APK доторх бодит DEX байткодыг мөн шинжилдэг (код дахь текст загвар л биш), тул дуудагдсан аюултай API болон DEX-д суулгасан нууцууд ч баригддаг; загварыг дагадаггүй цоорхой нь сканнаас одоогоор зугтаж болно — хэрэглэхээсээ өмнө шалгаарай.

Интерфэйс турших робот
Текст хувилбараар дамжуулан апп дэлгэцийг автоматаар туршихын тулд: үндсэн цэсэнд «Интерфэйс туршилтын робот»-ийг нээж, төслөө сонгоод, «Хувилбарыг автоматаар үүсгэх» дээр товшоорой. IDE нь төслийн manifest болон зохион байгуулалтыг уншиж, хувилбарыг текст алхам хэлбэрээр бичдэг (товчлуур дарах, талбар бөглөх, хүлээх, буцах). Хувилбарын гүйцэтгэлийн бүртгэлийг түүний цаг хугацааны тэмдэгтэй хамт харахын тулд «Хуурай ажиллуулах» дээр товшоорой — энэ хуурай ажиллуулалт нь одоогоор дарааллын симуляци л юм. Бодит туршилтын хувьд «Туршилтын агентыг төсөлд оруулах» дээр товшоорой: IDE нь хувилбарын хөрөнгөтэй туршилтын агентыг төсөлд оруулдаг; APK-г ердийнхөөрөө бүтээж, суулгаж, дараа нь «Туршилт» дүрсийг нээнэ үү — агент нь бүтээгдсэн апп дотор ажиллаж, товчлуурыг бодитоор дарж, бодит талбарыг бөглөж, гүйлгэж, дараа нь дэлгэцэн дээр баригдсан бодит эвдрэлтэй тайлангаа харуулдаг. Агентыг дахин арилгахын тулд «Туршилтын агентыг төслөөс хасах» дээр товшоорой. Агент нь аппын өөрийн процесс дотор ажилладаг тул хүртээмжтэй үйлчилгээ эсвэл системийн автоматжуулалт шаардлагагүй.

Кодын цаг хугацааны аялал
Git тушаал бичихгүйгээр төслийг өмнөх код төлөвт буцаахын тулд: үндсэн цэсэнд Кодын цаг хугацааны аялал хэсгийг нээгээд төсөл сонгоод цагийн цэгт шошго бөглөнө үү (хоосон орхиж болно) дараа нь Одоогийн цэгийг бүртгэх товчийг дарна уу. IDE нь төслийн эх файлуудын хуулбарыг тэдгээрийн hash утгуудтай хамт төсөл доторх .riwayat хавтсанд хадгалдаг. Цагийн цэгүүдийн жагсаалт бүгдийг харуулдаг; хоёр цэг сонгоод дараа нь нэмсэн, өөрчилсөн эсвэл устгасан файл болон функцүүдийг харахын тулд Харьцуулах товчийг дарна уу. Хуучин төлөвийг буцааж авахын тулд Сэргээх товчийг дарна уу — сэргээхээс өмнө IDE үргэлж эхлээд одоогийн төлөвийн нөөц хуулбарыг үүсгэдэг тул юу ч алдагдахгүй. Төслийг шинэ хавтас руу хуулж, анхны төслийг саад бололгүйгээр өөрчлөлтүүдийг туршихын тулд Туршилтын хуулбар үүсгэх товчийг дарна уу. Зөвхөн эх файлуудыг бүртгэдэг.

Модулийн үйлдвэр
Төслийн нэг хэсгийг өөр төслийн ашиглаж болох модуль болгон багцлахын тулд: үндсэн цэсэнд Модулийн үйлдвэр хэсгийг нээгээд эх төсөл сонгоод багцлах дэлгэц, анги, мөр болон зөвшөөрлийн файлуудыг тэмдэглээд дараа нь Модуль болгон багцлах товчийг дарна уу. IDE нь JSON мета өгөгдөлтэй хамт ZIP архив бичдэг (модулийн нэр, хувилбар, ашигласан мөрүүд болон зөвшөөрөл). Модулийг өөр төсөлд суулгахын тулд Модулийн үйлдвэр хэсгийг нээгээд зорилтот төсөл сонгоод дараа нь Модуль суулгах товчийг дарж, модулийн .zip файлыг сонгоно уу — нэгтгэх нь байгаа кодыг дарж бичихгүйгээр мөр болон зөвшөөрлийг нэмж, файлын нэр нь зорилтот төсөлд аль хэдийн ашиглагдаж байгаа бол файлыг нэгтгэдэггүй. Модуль нь номын сан эсвэл бүтээх тохиргоог өөртөө авч явахгүй.

Полиморф бамбай болон хөрөнгийн агуулах
Нийтлэхээсээ өмнө таних тэмдгийн нэрийг санамсаргүй болгож, төслийн хөрөнгийг шифрлэхийн тулд: үндсэн цэсэнд «Олон хэлбэрт бамбай ба хөрөнгийн агуулах»-ийг нээж, төслөө сонгоод, «Нэрийг санамсаргүй болгож, хөрөнгийг шифрлэх» дээр товшоорой. IDE нь эх кодын анги болон аргын нэрийг скан хийж, санамсаргүй нэрийн зураглалыг үүсгэж, тэдгээр нэрийг эмхэтгэсэн DEX файлуудын дотор дахин бичдэг (орлуулах нэрийг эх нэрийнхээ урттай ижил болгосон тул бүх офсет хүчинтэй хэвээр үлдэж, дараа нь DEX толгойн шалгах нийлбэр болон SHA-1 гарын үсгийг дахин тооцоолно), төслийн хөрөнгийн файлуудыг төсөл доторх brankas-aset хавтсанд AES-GCM ашиглан шифрлэж, шифрлэгдсэн сэргээх зураглалыг (perisai-peta.brankas) хадгалдаг тул эвдрэлийн бүртгэлийг унших үед анхны нэрийг сэргээж болно. Шифрлэлтийн түлхүүр нь одоо төслийн нэрээс биш, хөгжүүлэгчийн нууц үгээс PBKDF2, 20,000 давталтаар гаргаж авсан байна. Энгийн текст, тэмдэглэгээний нэр болон дибаг хийх нэр болгон ашигладаг нэрийг санаатайгаар дахин бичдэггүй бөгөөд бүтээн байгуулалтын зам дахь DEX дахин бичих оруулах цэгүүд нь бодит утсан дээр туршигдахыг хүлээж байна.

Итгэлийн гинж болон орчны хамгаалагч
Нийтлэхээсээ өмнө гарын үсэг зурах түлхүүрийн гинж болон утасны орчныг шалгахын тулд: үндсэн цэсэнд «Итгэлцлийн гинж ба орчны хамгаалагч»-ийг нээж, төслөө сонгоод, «Гинж ба орчныг шалгах» дээр товшоорой. IDE нь төслийн багцын нэрээс 5 үеийн түлхүүрийн гинж үүсгэж, түүний бүрэн бүтэн байдлыг шалгаж, санах ой дахь кодын хэсгүүдийн агуулгыг диск дээрх файлуудтай харьцуулан бодит санах ойн бүрэн бүтэн байдлыг шалгаж, нэргүй гүйцэтгэгдэх боломжтой (RWX) зураглал, гадаад номын сан болон memfd зураглалыг мэдээлж, дараа нь өөрийн процессын санах ойн зураглал болон төхөөрөмжийн шинж чанарыг Frida, Xposed эсвэл эмуляторын ул мөрийн хувьд скан хийдэг. Агуулахын түлхүүр нь боломжтой үед техник хангамжийн аюулгүй байдлын чип ашигладаг AndroidKeyStore дахь AES түлхүүрээр ороогдсон бөгөөд түлхүүр эргэлт нь одоо v3 схемийн гарын үсэг зурах гэрчилгээний удам угсаатай бодит болсон: хуучин түлхүүр нь шинэ түлхүүр рүү эргэлтийн нотолгоонд гарын үсэг зурж, APK нь тухайн удам угсаагаар дахин гарын үсэг зурсан байна. Үр дүн нь текст нотолгоотой «аюулгүй», «болгоомжтой» эсвэл «аюултай» эрсдэлийн түвшин байна. Систем санах ой уншихыг татгалзвал шалгалтыг аюулгүй гэж биш «баталгаажуулж боломжгүй» гэж мэдээлнэ; мөн түлхүүр нь техник хангамжийн аюулгүй байдлын чипийг үнэхээр ашигладаг эсэхийг зөвхөн бодит төхөөрөмж дээр баталгаажуулж болно.

Текст модны байршлын архитектор
Дэлгэцийг харахгүйгээр дизайн хийхийн тулд: үндсэн цэсэнд «Текст модны зохион байгуулалтын архитектор»-ийг нээж, төсөл болон зохион байгуулалтын файлаа сонгоод, «Зохион байгуулалтыг шалгах» дээр товшоорой. IDE нь XML зохион байгуулалтыг текст мод болгон уншиж, элемент бүрийн байрлалын тодорхойлолтыг чангаар уншдаг (жишээлбэл доод баруун, дэлгэцийн өргөний 45 хувь), дараа нь элементүүдийн хоорондох давхцал болон 360 dp өргөнтэй дэлгэцээс гарсан элементүүдийн талаар математикийн аргаар мэдээлдэг. Одоо тоолж байгаа зүйл бол LinearLayout болон энгийн dp хэмжээ, бүрэн ConstraintLayout (бүх хязгаарлалт, хазайлт, гинж, удирдамж, саад, хувийн өргөн, 0dp match_constraint болон хэмжээсийн харьцаа) болон Compose дэлгэц (Column, Row болон Box тэдгээрийн хэмжээ өөрчлөгчтэй) юм. Ажиллах явцад өөрчлөгддөг MotionLayout болон ConstraintSet л үл мэдэгдэх байрлал гэж мэдээлсээр байна, учир нь тэдгээрийн утга нь апп ажиллаж байх үед л байдаг.

Дизайн системийн студи
Бүх дэлгэц болон төслүүдэд зай, фонт болон булангуудыг жигд болгохын тулд: үндсэн цэсэнд «Дизайн системийн студи»-ийг нээж, төслөө сонгож, дизайн токенуудыг бичнэ үү (жишээлбэл jarak=8, huruf=16, sudut=12), бүрэлдэхүүн хэсгийг сонгоод, «Бүрэлдэхүүн хэсэг үүсгэх» дээр товшоорой. IDE нь токенуудыг баталгаажуулдаг — суурь зай 4-өөс 16 dp, суурь фонт 12-оос 20 sp, булан 0-оос 32 dp, хамгийн бага хүрэх талбай 48 dp — дараа нь төслийн хавтсанд ашиглахад бэлэн XML бүрэлдэхүүн хэсгүүдийг (komponen-studio.xml) XML сэдэв (tema-studio.xml) болон Compose сэдэв (tema-studio.kt)-тэй хамт бичдэг. Токенуудыг төслүүд хооронд хуваалцсан токен номын санд нэрлэсэн багц хэлбэрээр хадгалж болох бөгөөд нэг синхрончлолын команд нь номын сангийн хамгийн сүүлийн токенуудыг тухайн багцыг ашигладаг бүх төсөлд хэрэглэнэ. Бүрэлдэхүүн хэсгүүдийг зохион байгуулалтанд нааж, дараа нь «Текст модны зохион байгуулалтын архитектор»-оор шалгадаг текст хэлбэрээр үүсгэдэг; таблет дээрх хоёр баганын тохируулга нь ажиллах явцад төхөөрөмж танихын оронд дэлгэцийн өргөний чанарыг ашигладаг.

Семантик рефакторинг болон AST навигаци
Тодорхойлолтыг олж, санамсаргүйгээр ижил нэртэй бусад кодыг эвдэхгүйгээр тэмдэгтийн нэрийг өөрчлөхийн тулд: үндсэн цэсэнд «Семантик дахин бүтэц ба AST навигаци»-ийг нээж, төслөө сонгоод, бүх анги болон аргыг тэдгээрийн файл болон мөрийн дугаартай хамт харахын тулд «Төслийн тэмдэгтийг скан хийх» дээр товшоорой. Тэмдэгтийн нэрийг бичиж, дараа нь түүний тодорхойлолт болон түүнийг дууддаг бүх файлыг харахын тулд «Төслийн тэмдэгтийг скан хийх» дээр дахин товшоорой. Нэрийг өөрчлөхийн тулд шинэ нэрийг бичиж, файл бүрийн тохиолдлын тоог харахын тулд «Нэр өөрчлөх урьдчилсан үзлэг» дээр товшоод, дараа нь «Нэр өөрчлөлтийг хэрэглэх» дээр товшоорой. Индекс нь одоо гараар бүтээсэн AST задлан (Java болон Kotlin дэд олонлогт зориулсан лексер болон рекурсив задлан) ашигладаг тул файлуудын хоорондох аргын нэр өөрчлөлт шийдэгдэж, бусад файл дахь дуудагчид ч өөрчлөгддөг; кодын блокыг шинэ функц руу гаргах товчлуур одоо энэ дэлгэцэн дээр байна. Энэ задлан одоогоор хамгийн бага байна: маш нарийн төвөгтэй generics, параметр бүхий тэмдэглэгээ болон нэргүй ангиудыг байгаагаар нь скан хийдэг бол тусгал болон интерфэйсээр дамжих дуудлагыг шийддэггүй.

Алхам алхмаар дибаг хийх болон санах ой шалгагч
Бүртгэлээс таамаглахгүйгээр програмын урсгалын дунд хувьсагчийн агуулгыг шалгахын тулд: үндсэн цэсэнд «Алхам алхмаар дибаг хийх ба санах ойн шалгагч»-ийг нээж, төслөө сонгож, гүйцэтгэлийн мөрийг бичнэ үү (мөр бүрт нэг алхам, формат мөрийн дугаар, код, дараа нь | -ээр тусгаарлагдсан хувьсагч болон утгууд, жишээлбэл 10|int total = harga * jumlah;|harga=5000, jumlah=3, total=15000), таслах цэгийн мөрийн дугаарыг бичээд, «Дибаг хийх мөрийг гүйцэтгэх» дээр товшоорой. IDE нь эхний таслах цэг хүртэл ажиллаж, Jieshuo-гоор дамжуулан идэвхтэй мөрийг хувьсагчийн утгуудтай хамт чангаар уншдаг. Нэг мөр урагшлахын тулд «Нэг мөрийн алхам» дээр товшоод, дуудагдсан функц руу орохын тулд «Функц руу орох» дээр товшоорой (дуудлагын стектэй), эсвэл дараагийн таслах цэг рүү очихын тулд «Програмыг үргэлжлүүлэх» дээр товшоорой. Энэ мөр дибаг хийх хэрэгсэл нь бүртгэгдсэн эсвэл гараар бичсэн мөрийг дагаж мөрддөг; түүний хажууд JDWP утас протоколд зориулсан цэвэр Java клиент байгаа бөгөөд гар барих, таслах цэг тогтоох, дотогш, дээгүүр болон гадагш алхах, TCP-ээр эсвэл сонсох горимд VM-ийг түдгэлзүүлж, үргэлжлүүлж болно. Энгийн апп дотроос бодит процессыг түдгэлзүүлэх нь одоогоор бүрэн боломжгүй байна, учир нь процессын JDWP сокет нь зөвхөн adbd-ээр илэрдэг — батлагдсан зам нь утасгүй дибаг хийх болон бүрхүүлээр дамжуулан зорилтыг эхлүүлэхийг шаарддаг бөгөөд энэ нь апп өөрөө хийж чадахаас хэтэрсэн байна.

Офлайн хамаарлын менежер
Интернетгүйгээр гуравдагч этгээдийн номын санг ашиглах, бүтээхээсээ өмнө хувилбарын зөрчлөөс зайлсхийхийн тулд: үндсэн цэсэнд «Оффлайн хамаарлын менежер»-ийг нээж, төслөө сонгоод, «Хамаарлыг шалгах» дээр товшоорой. IDE нь төслийн бүх .gradle файлуудыг уншиж, Download/brankas-bersama хавтсанд төслүүд хооронд хуваалцсан агууланг шалгаж, зөрчлийг шийддэг — хоёр номын сан ижил олдворын өөр хувилбарыг хүсвэл хамгийн өндөр хувилбарыг ашиглаж, зөрчлийг мэдээлнэ. Номын сан татаж авахын тулд түүний координатыг бичнэ үү (формат бүлэг:олдвор:хувилбар, жишээлбэл com.google.code.gson:gson:2.10.1), дараа нь «Хамаарлыг шалгах» дээр товшоорой: онлайн үед AAR, JAR эсвэл WHL файлуудыг Maven, Google эсвэл PyPI-ээс тэдгээрийн дамжин өнгөрөх хамаарлын графтай (рекурсив, мөчлөг таслагдсан, гүн 25 түвшин хүртэл) бодитоор татаж авч, зөвхөн амжилттай татаж авсан файлуудыг байгаа гэж бүртгэдэг. Оффлайн үед хуваалцсан агуулахад аль хэдийн байгаа номын санг л ашиглаж болно. Maven хувилбарын хүрээг шийддэггүй бөгөөд татаж авсан файлуудыг зөвхөн SHA-1-ээр шалгадаг, PGP баталгаажуулалтгүй.

Мэдээллийн сан болон хадгалалт шалгагч
Хүснэгтийн агуулгыг хэвлэдэг код бичихгүйгээр төслийн мэдээллийн сангийн агуулгыг шалгаж, туршихын тулд: үндсэн цэсэнд «Мэдээллийн сан ба хадгалалт шалгагч»-ийг нээж, төсөл болон мэдээллийн сангийн файлаа (.db, .sqlite эсвэл .sqlite3) сонгоод, «Мэдээллийн санг нээх» дээр товшоорой. IDE нь түүний бүх хүснэгтийн схемийг бүрэн SQLite хуудас задлан (хэтэрсэн хуудастай B-мод) ашиглан уншиж, эхний 20 мөрийг Jieshuo чангаар уншдаг текст хүснэгт хэлбэрээр харуулдаг. SELECT асуулга бичиж, «Асуулгыг гүйцэтгэх» дээр товшоорой (жишээлбэл SELECT nama FROM pengguna WHERE kota = 'Makassar') — асуулга одоо JOIN, GROUP BY, ORDER BY болон LIKE-г дэмждэг бөгөөд утсан дээрх бодит Android SQLite хөдөлгүүрээр гүйцэтгэдэг. Утгыг өөрчлөхийн тулд мөрийн дугаар (1 = эхний мөр), баганын нэр болон шинэ утгыг бичиж, дараа нь «Нүдний утгыг өөрчлөх» дээр товшоорой — утга нь .db файл руу буцаж бичигдэнэ. Хүснэгтийн одоогийн байдлыг төсөлд <мэдээллийн сан-нэрийн>.cadangan.txt файл болгон хадгалахын тулд «Нөөцлөлтийг хадгалах» дээр товшоорой. SharedPreferences болон DataStore-г мөн уншиж болно. Одоогоор уншиж боломжгүй зүйлүүд: шифрлэгдсэн мэдээллийн сан, баталгаажаагүй WAL өөрчлөлт болон мэргэшсэн DataStore Proto дахь бичсэн утгууд (зөвхөн ерөнхий талбарын харагдац хэлбэрээр харуулдаг).

Нэгж туршилтын үйлдвэр болон фаззинг
Аппыг хуваалцахаасаа өмнө логикийн цоорхойг олохын тулд: үндсэн цэсэнд «Нэгж тест үйлдвэр ба Fuzzing»-ийг нээж, төсөл болон кодын файлаа сонгоод, «Тест үүсгэж, гүйцэтгэх» дээр товшоорой. IDE нь файлын функцийн гарын үсгийг уншиж, энгийн болон хилийн тест тохиолдлуудыг үүсгэнэ (хоосон текст, null, хамгийн их тоо, хачин тэмдэгт) дараа нь эдгээр тестийг бодитоор гүйцэтгэнэ: төслийн код эмхэтгэгдэж, @Test арга бүрийг 5 секундын хязгаартай гүйцэтгэдэг тул үр дүн нь тэдгээрийн бодит утгуудтай бодит дамжсан болон бүтэлгүйтсэн үр дүн байна. Fuzzing нь төслийн функцүүд дээр бодитоор гүйцэтгэгддэг (тусгалаар дамжуулан, дуудлага бүрт 2 секунд, хамгийн ихдээ 20 арга) бөгөөд мөрийн хамрах хувийг анхны мөрийн дугаарыг хадгалдаг багаж хэрэгслээр бодитоор тооцоолдог. Үр дүн нь хэдэн тест дамжиж, бүтэлгүйтсэн, хэдэн кодын мөр болон функц олсон, ямар тест тохиолдол үүсгэсэн талаар мэдээлдэг. Үүсгэсэн тестүүд нь JUnit-тэй яг ижил API ашигладаг боловч тэмдэглэгээ болон баталгааны тодорхойлолтыг үүсгэсэн тест файл дотор бичсэн байдаг, учир нь бодит JUnit номын сан апп-д ороогүй байна.

Төхөөрөмжийн хэт нөхцөлийн загварчлагч болон санах ойн гоожлын аудитор
Систем түүний процессыг устгах, сүлжээ тасрах, дэлгэц эргэх эсвэл батерей хэмнэлт асаах үед аппын тэсвэрлэх чадварыг туршихын тулд: үндсэн цэсэнд «Төхөөрөмжийн хэт нөхцөлийн симулятор ба санах ойн алдагдлын аудитор»-ийг нээж, төслөө сонгоод, «Симуляцийг гүйцэтгэх» дээр товшоорой. IDE нь дэлгэцийн эргэлтийн симуляцитай гурван стрессийн хувилбарыг ажиллуулж, тэдгээрийн дэлгэц хаагдсан ч санах ойд хадгалагдсан объектуудыг хянаж, дараа нь алдагдсан өгөгдөл болон алдагдсан объектын гинжийг мэдээлдэг. Хадгалах болон сэргээх төлөв нь одоо тогтмол дээжээс биш, хэрэглэгчийн өөрийн төслийн эх үүсвэрээс уншигддаг; сүлжээний тасралтыг хэмжихийн тулд туршилтын дунд орон нутгийн loopback серверийг бодитоор зогсоодог; бодит heap dump авч, дүн шинжилгээ хийж, хоёр dump-ийг харьцуулж, барих гинжийг GC үндэснээс мөрлөдөг; мөн аппын өөрийн процессыг төлөв нь хадгалагдсаны дараа бодитоор устгаж, дараа нь дахин нээхэд ямар өгөгдөл буцаж ирэхийг шалгадаг. Энгийн аппаас одоогоор боломжгүй зүйлүүд: утасны радио эсвэл Wi-Fi-г унтраах болон бусад аппыг хүчээр зогсоох — хоёулаа системийн зөвшөөрөл шаарддаг; үүний оронд арын аппыг killBackgroundProcesses-ээр устгадаг бөгөөд түүний зөвшөөрөл нь manifest-д аль хэдийн байгаа бөгөөд дэлгэц дээр шударга шошготой байна.

Төслийн зураг төслийн архитектор
Том апп санааг алхам алхмаар ажлын төлөвлөгөө болгон хувиргахын тулд: үндсэн цэсэнд «Төслийн төлөвлөгөөний архитектор»-ийг нээж, төслөө сонгож, апп санааг бичнэ үү (жишээлбэл хэсэгчлэн төлбөртэй жижиг хүнсний дэлгүүрийн кассын апп) дараа нь «Төлөвлөгөө үүсгэх» дээр товшоорой. IDE нь модулиуд, файлын жагсаалт болон жижиг үе шатуудыг бүтээж, дараа нь тэдгээрийг төслийн хавтсанд cetak-biru.txt хэлбэрээр хадгалдаг. Үе шат бүрийг дуусгах бүрт «Дараагийн үе шатыг дууссан гэж тэмдэглэх» дээр товшоод, эсвэл хадгалагдсан төлөвлөгөөг дахин нээхийн тулд «Хадгалагдсан төлөвлөгөөг ачаалах» дээр товшоорой. Хэрэв «AI тохиргоо» хэсэгт идэвхтэй AI нийлүүлэгчийг сонгосон бөгөөд түүний түлхүүр байгаа бол төлөвлөгөөг тухайн нийлүүлэгч бүтээнэ; түлхүүр дутуу эсвэл нийлүүлэгчид хүрч чадахгүй бол IDE нь оффлайн түлхүүр үгийн загвар руу буцаж, тухайн хязгаарлалтыг шударгаар хэлдэг. Нийлүүлэгчийн хариултыг зөвхөн форматад нь шалгадаг (модулиуд болон үе шатууд байгаа), агуулгын үнэн зөв байдалд нь биш — бүтээхээсээ өмнө төлөвлөгөөг үргэлж шалгаарай.

Код логикийн урсгалын өгүүлэгч
Синтаксийг мөр мөрөөр сонсохгүйгээр урт кодыг ойлгохын тулд: үндсэн цэсэнд «Кодын логик урсгалын өгүүлэгч»-ийг нээж, төсөл болон кодын файлаа сонгоод, «Кодын өгүүлэмж» дээр товшоорой. IDE нь мөр бүрийг Индонез өгүүлбэр болгон хувиргадаг (жишээлбэл нийт нь 100000-ээс их бол дараагийн блокыг гүйцэтгэнэ), аргуудын хоорондох дуудлагын зураглал болон аргуудын хоорондох өгөгдлийн урсгалын шинжилгээг (дамжуулсан, ашигласан эсвэл үл тоомсорлосон утгууд) харуулж, нарийн боломжтой алдаануудыг тэдгээрийн мөрийн дугаартай хамт тэмдэглэдэг — ==-тэй харьцуулсан String, хаагдаагүй нээгдсэн урсгал болон хоёр өөр аргад бичигдсэн хувьсагч. Хэрэв «AI тохиргоо» хэсэгт идэвхтэй AI нийлүүлэгчийг сонгосон бол тухайн нийлүүлэгчээс урсгалын хураангуй мөн боломжтой; үгүй бол дэлгэц нь оффлайн өгүүлэмжийг ашиглаж, тухайн хязгаарлалтыг хэлдэг. Өгүүлэмж, дуудлагын зураглал болон өгөгдлийн урсгал нь бүрэн AST задлан биш, оффлайн текст загварын шинжилгээг ашигладаг — нээх хаалт нь өөрийн мөрөнд байгаа аргууд, ангийн талбарууд болон тусгалаар дамжих дуудлагыг мөрлөдөггүй — бөгөөд өгөгдлийн уралдааны сэрэмжлүүлэг нь үнэн хэрэгтээ ээлжлэн л ашиглагддаг хувьсагчийн хувьд л гарч болзошгүй.

Апп багцын үйлдвэр болон Play Store бэлэн байдал
Утнаасаа шууд Google Play Store-д зориулж апп бэлтгэхийн тулд: үндсэн цэсэнд «Апп багц үйлдвэр ба Play Store бэлэн байдал»-ийг нээж, төслөө сонгоод, «AAB багц бүтээх» дээр товшоорой. IDE нь бодит BundleConfig.pb-тэй төслийн manifest, нөөц болон хөрөнгөөс .aab файл бүтээж, багцын бүтцийг баталгаажуулж, дараа нь багцыг бодит хувилбар APK-ууд (суурь, архитектур, хэл, түгээмэл) болгон тухайн хуваалтаас хэмжсэн хэмжээтэй хувааж, таамаглал биш. Багц нь APK гарын үсэг зурахад ашигладаг ижил төслийн түлхүүрээр JAR v1-ээр гарын үсэг зурсан бөгөөд түүний гарын үсгийн гинжийг криптографийн аргаар баталгаажуулдаг. Энэ дэлгэц нь Play бэлэн байдлыг мөн аудит хийдэг — зорилтот SDK 35-аас доош бол «өндөр» гэж тэмдэглэдэг, учир нь Play Store нь 35 ба түүнээс дээш шаардлагатай бөгөөд дутуу 64 битийн номын санг мөн «өндөр» гэж тэмдэглэдэг. Бодит bundletool нь төхөөрөмж дээр ажиллах боломжгүй, учир нь bundletool нь JVM шаарддаг бол Android-д JVM байхгүй; дээрх зам нь төхөөрөмж дээрх хамгийн ойрын бодит зам юм.

OTA шинэчлэлтийн хөдөлгүүр болон үе шаттай гаргалтууд
Хэрэглэгчдийг бүх APK-г дахин татаж авахыг албадахгүйгээр жижиг засвар илгээхийн тулд: үндсэн цэсэнд «OTA шинэчлэлтийн хөдөлгүүр ба үе шаттай гаргалт»-ийг нээж, төслөө сонгож, хуучин болон шинэ хувилбарын агуулгыг бичээд, «Нөхөөсийн багц үүсгэх» дээр товшоорой. IDE нь ялгааг тооцоолж, шинэ агуулгын SHA-256 хурууны хээтэй нөхөөсийн багцыг (patch-ota.zip) үүсгэж, дараа нь энэ төхөөрөмж эхний 10 хувийн гаргалтын алхамд байгаа эсэхийг шалгадаг. Нөхөөсүүд нь одоо ямар ч файлд хоёртын дельтаг дэмждэг (DEX болон APK орно), RSA-2048 гарын үсгээр багцлагдсан бөгөөд хэрэглэхээсээ өмнө итгэмжлэгдсэн нийтийн түлхүүрээр баталгаажуулдаг бөгөөд хөгжүүлэгчийн серверээс түүний гаргалтын жагсаалттай татаж авч болно; хэрэглээ бүтэлгүйтвэл хуучин файл хөндөгдөөгүй хэвээр байна. Ажиллаж байгаа апп дээр нөхөөс хэрэглэх нь төслийн түлхүүрээр дахин гарын үсэг зурж, PackageInstaller-ээр дамжуулан хийгддэг, учир нь ажиллаж байгаа процессын кодыг дотроос нь солих боломжгүй — APK түгжигдсэн бөгөөд DEX аль хэдийн ачаалагдсан байна.

Багийн код хяналтын студи
Хамтран ажиллагчийн өөрчлөлтийг шалгаж, Git сумыг уншихгүйгээр нэгтгэх зөрчлийг шийдвэрлэхийн тулд: үндсэн цэсэнд «Багийн кодын шалгалтын студи»-ийг нээж, төслөө сонгож, гурван текст хувилбарыг бичнэ үү (суурь, орон нутгийн, хамтран ажиллагч) дараа нь «Багийн шалгалтыг нээх» дээр товшоорой. IDE нь гурвыг Java синтакс нэгж дээр үндэслэн нэгтгэдэг — ижил мөрөнд хоёр өөрчлөлт байгаа боловч өөр мэдэгдэлд байгаа нь цаашид зөрчил гэж тооцогдохгүй — мөн зөрчил бүрийг санал өгөх сонголт хэлбэрээр харуулдаг: орон нутгийн хувилбарыг ашиглах, хамтран ажиллагчийн хувилбарыг ашиглах, эсвэл хоёуланг нь нэгтгэх — үр дүнгийн мөрийг мөр дарааллыг зөв байлгахын тулд анхны зөрчлийн байрлалд оруулдаг — дараа нь үр дүнг төсөлд gabung-hasil.txt руу бичнэ. Доор нь төслийн ажлын самбар байна: ажлын гарчгийг бичиж, дараа нь «Ажил нэмэх» дээр товшоорой; ажлуудыг төсөл доторх .tugas хавтсанд текст хэлбэрээр хадгалж, апп доторх Git-д commit-ээр дамжуулан синк хийдэг тул самбарыг ямар ч commit түүхээс дахин уншиж болно. Энэ синтакс хуваалт нь бүрэн AST задлан биш бөгөөд апп доторх Git нь commit бүрт бүрэн агшин зураг хадгалдаг; тусдаа синк сервер байхгүй.

Кодын бүтцийг дуугаар бичих
Засварлагч дотор дуу хоолойгоор код бичихийн тулд: төслийг Засварлагчид нээгээд дараа нь Кодын бүтцийг дуугаар бичих товчийг дарна уу. Тушаалуудыг Индонез хэлээр хэлнэ үү, жишээлбэл buat fungsi tambah dengan parameter a angka dan b angka, buat kelas Mobil эсвэл buat variabel teks nama sama dengan Budi — IDE нь яриаг синтаксийн хувьд зөв Java, Kotlin, Python эсвэл Compose код блок болгон хувиргаж, курсорын байрлалд оруулж, дараа нь Jieshuo-гоор дамжуулан товч хураангуйг чангаар уншина. Дуугаар бичих нь системийн суулгасан дуу хоолой оруулах үйлчилгээг ашигладаг, нэмэлт микрофон зөвшөөрөлгүйгээр бөгөөд зөвхөн өмнө нь бүртгэгдсэн тушаалын хэв маягийг таньдаг; эдгээр хэв маягаас гадуурх яриа код болж хувирдаггүй. Үгээр хэлсэн тоонууд (жишээлбэл, 'lima') хараахан цифр болж хувирдаггүй.

Орон нутгийн хамтын ажиллагааны өрөө (интернетгүйгээр)
Интернетгүйгээр нэг өрөөнд хамтран ажиллахын тулд: үндсэн цэсэнд Хамтын ажиллагаа хэсгийг нээгээд дараа нь Орон нутгийн хамтын ажиллагааны өрөө хэсгийг нээнэ үү. Нэг утас сесс нээнэ (IDE нь орон нутгийн IP хаяг болон 6 оронтой PIN харуулдаг) өөр утас тухайн хаяг болон PIN-ээр нэгдэнэ. Текст өөрчлөлтүүдийг мөрийн ялгаа хэлбэрээр илгээдэг, бүтээгдсэн APK-ийг туршигчийн утас руу илгээж болох бөгөөд туршигчийн утаснаас ирсэн гацалтын тайлангуудыг буцааж хүлээн авдаг. Нэг сесс нь зөвхөн нэг найзад зориулагдсан; хэрэв хоёр хүн яг ижил мөрийг нэгэн зэрэг өөрчилвөл сүүлчийн өөрчлөлтийг ашиглана. PIN нь орон нутгийн сүлжээнд энгийн текст хэлбэрээр илгээгддэг. Энэ өрөөг бодит утсан дээр хараахан туршиж үзээгүй байна.

AI тохиргоо
Апп бүтээхэд зориулсан AI нийлүүлэгч болон API түлхүүрийг тохируулахын тулд: үндсэн цэсэнд, тохиргооны бүлэгт «AI тохиргоо» дээр товшоорой («Холбогч» товчлуурын хажууд). Боломжтой жагсаалтаас ашиглах нийлүүлэгчийг сонгож, загвар бүтэлгүйтвэл IDE нь ижил нийлүүлэгчээс дараагийн загварыг автоматаар туршиж үзэхийн тулд «Нийлүүлэгч алдаа гаргах үед загварыг өөрчлөх»-ийг тэмдэглэнэ үү. Нөөц түлхүүр нэмэхийн тулд «API түлхүүрийг удирдах» дээр товшоорой (нэр болон түлхүүрийг бичээд, дараа нь «Хадгалах» дээр товшоорой; түлхүүрүүдийг далдлан харуулдаг, зөвхөн сүүлийн 4 тэмдэгт нь харагдана). Түлхүүрүүдийг утсан дээр хадгалдаг бөгөөд апп бүтээх үед сонгосон нийлүүлэгчээс өөр газар хэзээ ч илгээгддэггүй. Сонгосон нийлүүлэгчийг одоо «Төслийн төлөвлөгөөний архитектор» болон «Кодын логик урсгалын өгүүлэгч» бодитоор ашигладаг; «AI апп бүтээгч» дэлгэц дээр апп бүтээх нь одоогоор утсан дээрх орон нутгийн AI-г ашигладаг (интернетгүй).

Холбогч
APK-г шинжлэн дараа нь илгээхийн тулд: үндсэн цэсэнд, Тохиргоо бүлэгт, Холбогч товчийг дарна уу (AI тохиргоо товчны хажууд). Утаснаас APK файл сонгоно уу, IDE түүний агуулгыг уншина (багцын нэр, хувилбар, үйл ажиллагааны жагсаалт) дараа нь системийн хуваалцах цэсээр илгээхийн тулд APK илгээх товчийг дарна уу (жишээлбэл, WhatsApp эсвэл Drive).

Хэл ба дуу хоолой
Аппын хэлийг өөрчлөхийн тулд: Тохиргоо хэсгийг нээгээд дараа нь Апп хэл хэсгийг нээгээд хэл эсвэл Системийг дагах сонголтыг сонгоно уу. Үндсэн дэлгэц болон ихэнх дэлгэц нь аппыг хаах эсвэл дахин эхлүүлэхгүйгээр сонгосон хэл рүү шууд шилждэг; зарим дэлгэц (жишээлбэл, Терминал, Хамтын ажиллагаа, AI тохиргоо болон Түлхүүр удирдах) дахин нээгдэх хүртэл хуучин хэлийг ашигласаар байна. Хэрэв та Системийг дагах сонголтыг сонговол хэл нь утасны системийн хэлийг дагана.

Төсөлд тусгагдсан гарын үсэг, хөндлөнгийн хамгаалалт
5.7 хувилбараас эхлэн өөрийн гарын үсгийг ашигладаггүй төслийг төслийн өөрийн суулгагдсан түлхүүрээр гарын үсэг зурдаг (төсөл доторх tanda-tangan-bawaan хавтасд нэг удаа үүсгэж, үргэлжлүүлэн ашигладаг) тул суулгагдсан гарын үсэг нь төслөөс төсөлд ялгаатай байдаг - бүх апп-д зориулсан хуваалцсан түлхүүр байхаа больсон. tanda-tangan-bawaan хавтсыг бүү устга - тэр түлхүүргүйгээр шинэ APK нь ижил төслийн хуучин APK-ийг орлож чадахгүй. Төсөл бүрийн тохиргоо (тусдаа архитектур, өөрийн гарын үсэг, Anti Tamper, сонгосон keystore, SDK) одоо төсөл доторх settings.gradle файлд хадгалагдаж, төсөл бүтээх бүрт дахин уншигддаг. Тохиргоо хэсэгт, гарын үсгийн төрөлд бүтээгдсэн апп-д зориулсан Anti Tamper шалгах нүд бий - идэвхтэй бол бүтээгдсэн апп нь төхөөрөмж дээр нээгдэх бүрт өөрийн гарын үсэг болон dex агуулгыг шалгана. Хэрэв өөр хэн нэгэн дахин гарын үсэг зурж эсвэл өөрчилсөн бол апп ажиллахаас татгалзана. Frida/Xposed зэрэг дибаг хийх болон тарилгын хэрэгслүүдийг мөн илрүүлж, аппын цонхыг дэлгэц бичлэгээс түгждэг.

Демо видео бүтээгч
Бүтээгдсэн аппын демо видео үүсгэхийн тулд - үндсэн цэснээс Демо видео бүтээгч гэснийг нээж, төслөө сонгож, видеоны гарчгийг бөглөж, Демо видео скрипт үүсгэх гэснийг дарна уу - IDE нь стандарт 5 үзэгдэл (нээлт, үндсэн үзэгдэл, үйлдэл 1, үйлдэл 2, хаалт) бүхий video-demo.txt-ийг өгүүллэгийн текст болон үзэгдэл бүрийн хугацаатай хамт бичнэ. Төслийн зургуудаас (дүрс + дэлгэцийн зураг, байгаа бол) video-demo.html үүсгэхийн тулд Slideshow HTML үүсгэх гэснийг дарна уу, 5 секунд тутамд автоматаар өөрчлөгдөнө. Энэ бол .mp4 видео биш - жинхэнэ видеоны хувьд утасны хөтөч дээр video-demo.html-г нээж, дэлгэцийг бичнэ үү эсвэл ажиллаж байгаа аппыг бичиж байхдаа video-demo.txt дахь өгүүллэгийг уншина уу.

Android Studio-ийн шинэ дүр төрх
IDE-ийн дүр төрхийг одоо Android Studio шиг цэвэрхэн болгосон (зөвхөн дүр төрх - товчлуурууд, цэснүүд болон урсгалууд бүгд яг хэвээрээ) - цайвар саарал дэвсгэр, тод хар дэлгэцийн гарчиг, цагаан текст бүхий цэнхэр товчлуурууд болон нимгэн хүрээтэй цагаан оролтын талбарууд. Үндсэн цэсийг харааны хувьд бүлэглэсэн (бүтээгчийн үйлдлүүд, үүл, сэдэв болон бусад, дуу хоолой, код болон шинэ үйлдлүүд, хэрэгслүүд) бөгөөд товчлуурын дарааллыг өөрчлөхгүй. Терминал нь Android Studio дахь Терминал цонх шиг харанхуй самбарыг үргэлжлүүлэн ашигладаг бөгөөд код засварлагч нь цагаан дэвсгэр болон хар тексттэй хэвээр байна. Бүх текстийг Jieshuo тодорхой уншсаар байна.

Тохиргоо
Аппыг тохируулахын тулд - нүүр дэлгэц дээрх сонголтын цэсийг нээж, Тохиргоо гэснийг дарна уу. Дотор нь 12 ангилал бий - GitHub тохиргоо (аюулгүй байдал, өөрийн гарын үсэг, бүтээлийн бүртгэл болон GitHub токен), Төхөөрөмж дээр APK бүтээх тохиргоо (keystore нууц үг болон төхөөрөмж дээр бүтээлийн бүртгэл хадгалах), Сэдэв (аппын өнгө), Гарын үсэг (өөрийн гарын үсэгт зориулсан keystore үүсгэх болон бүтээгдсэн апп-д зориулсан Anti Tamper шалгах нүд), Төслийн хавтас (төслийн хавтсын байршил), Хэл ба дуу хоолой (интерфэйсийн хэл болон дууны горимын ярих хурд), Текст болон дэлгэцийн хэмжээ (засварлагчийн фонтын хэмжээ), Бүтээх (төсөл үүсгэх дэлгэцийн анхдагч зорилтот SDK болон анхдагч архитектурын хуваалт), Мэдэгдэл (бүтээл дуусахад дуугарна), Автомат нөөцлөлт (төслийн нөөцлөлтийн хуваарь), Хөгжүүлэгчийн профайл (нэр, WhatsApp дугаар болон хандивын дэлгэц дээр харуулсан данс) болон Нууцлал ба өгөгдөл (тохиргоог дахин тохируулах болон аппын өгөгдлийг устгах). Ангилал бүрд ангиллын цэс рүү буцах Өмнөх рүү буцах товчлуур бий. Одоо хадгалагдсан тохиргоонууд (хараахан хэрэглэгдээгүй) дэлгэц дээр шударгаар тайлбарлагдсан байдаг.

Хөгжүүлэгчид хандивлах
Хөгжүүлэгчид хандивлах эсвэл мэндчлэхийн тулд - нүүр дэлгэц дээрх Хэрэгслийн тухай товчлуурын ойролцоох Хөгжүүлэгчид хандивлах товчлуурыг дарна уу. Хандивын дэлгэц дээр BRI данс хуулах товчлуур бий - хөгжүүлэгчийн дансны дугаарыг хуулахын тулд түүнийг дарж, банкны апп руугаа буулгана уу. WhatsApp дээр хөгжүүлэгчидтэй мэндчилээрэй гэсэн хэсэг мөн бий - нэр болон төрөлх хотоо бөглөж, WhatsApp дээр илгээнэ үү гэснийг дарна уу - WhatsApp нь урьдчилан бөглөсөн мэндчилгээний мессежтэй нээгдэж, WhatsApp дээр илгээнэ үү гэснийг л дарж, апп руу буцна уу. WhatsApp нь бусад апп-д мессежийг автоматаар илгээхийг зөвшөөрдөггүй тул илгээх ажлыг WhatsApp дотор та өөрөө үргэлжлүүлнэ.

Терминалын дуртай командууд
Терминал дээр байнга ашигладаг командуудыг хадгалахын тулд - Терминал нээж, Дуртай гэснийг дарна уу. Шинэ дуртай зүйл нэмэх гэснийг дарж, нэр (жишээ нь Файлыг үзэх) болон түүний командыг (жишээ нь ls -la) бөглөж, Хадгалах гэснийг дарна уу - дуртай зүйл утсан дээр байнга хадгалагдана. Терминал дээр шууд ажиллуулахын тулд дуртай зүйлийн нэрийг дарна уу. Дуртай зүйлсийг устгах гэснийг дарж, устгах нэгийг сонгоно уу (баталгаажуулалттай). Урьдчилан суулгасан 3 дуртай зүйл аль хэдийн бий - Файлыг үзэх (ls -la), Зай шалгах (df -h) болон Дэлгэцийг цэвэрлэ (clear) - бүгдийг устгаж болно. Хоосон командыг хадгалах эсвэл ажиллуулах боломжгүй. Терминал нь энэ талаар мессеж болон дуу хоолойгоор мэдэгдэнэ.

Шинжилгээ ба чанар
Апп ашиглалт болон эвдрэлийн тайлангийн хураангуйг харахын тулд - нүүр дэлгэц дээрх Хөгжүүлэгчид хандивлах товчлуурын ойролцоох Шинжилгээ ба чанар товчлуурыг дарна уу. Энэ дэлгэц нь апп хэдэн удаа нээгдсэн, хамгийн их нээгдсэн дэлгэцүүд, эвдрэлийн тоо болон богино засах зөвлөмж бүхий хамгийн сүүлийн эвдрэлүүдийн жагсаалтыг харуулна. Энэ өгөгдлийг зөвхөн таны утсан дээр хадгалдаг бөгөөд хаашаа ч илгээдэггүй. Энэ бүх өгөгдлийг устгахын тулд баталгаажуулалтын харилцан яриа бүхий Аналитик өгөгдлийг устгах товчлуур бий. Зөвхөн сүүлийн дэлгэцийг нүүр дэлгэц болон энэ дэлгэцийн хувьд тэмдэглэнэ.
