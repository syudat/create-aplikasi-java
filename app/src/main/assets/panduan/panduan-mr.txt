Create Aplikasi by Al Kautsar मध्ये आपले स्वागत आहे
Create Aplikasi हे एक Android अॅप बनवणारे अॅप आहे जे लॅपटॉपची गरज न लागता थेट फोनवर चालते. हे अॅप कोणालाही स्वतःचे Android अॅप बनवण्याची परवानगी देते, ज्यामध्ये अॅप बनवायला शिकू लागलेले वापरकर्ते आणि स्क्रीन रीडर वापरकर्ते यांचाही समावेश आहे. हे अॅप वापरण्यासाठीची संपूर्ण मार्गदर्शिका या Tentang Alat स्क्रीनवर उपलब्ध आहे.

हे अॅप काय आहे आणि ते कोणासाठी आहे
Create Aplikasi हे एक Android अॅप बनवण्याचे साधन आहे जे फोनवर चालते. हे अॅप स्वतःचे Android अॅप बनवू इच्छिणाऱ्या कोणासाठीही आहे, ज्यामध्ये नवशिक्या आणि स्क्रीन रीडर वापरकर्त्यांचाही समावेश आहे. हे अॅप एक कोड संपादक, प्रकल्पाची चाचणी करण्यासाठी Jalankan बटण, APK बनवण्यासाठी Bangun बटण, आणि APK वर स्वाक्षरी करण्यासाठी व स्थापित करण्यासाठी मेनू प्रदान करते.

या अॅपचा उद्देश
हे अॅप बनवले गेले आहे जेणेकरून कोणीही सहजपणे, थेट आपल्या फोनवरून स्वतःचे Android अॅप बनवू शकेल. त्याचा देखावा शक्य तितका सोपा बनवला आहे जेणेकरून नवीन वापरकर्तेही लगेच प्रयत्न करू शकतील.

टप्प्याटप्प्याने नवीन प्रकल्प कसा बनवायचा

3. अॅपचे नाव भरा, उदाहरण: Garuda Decode.

5. अॅपची आवृत्ती भरा, उदाहरण: 1.0, आणि संख्येच्या स्वरूपात आवृत्ती कोड भरा, उदाहरण: 1. रिकामे ठेवल्यास, आवृत्ती आपोआप 1.0 आणि आवृत्ती कोड 1 ने भरली जाईल.
6. आवश्यक असल्यास किमान SDK आणि लक्ष्य SDK भरा. रिकामे ठेवल्यास, पूर्वनिर्धारित मूल्ये वापरली जातील. किमान SDK म्हणजे समर्थित सर्वात कमी Android आवृत्ती, उदाहरण: 21 म्हणजे Android 5.0. कमाल लक्ष्य SDK 36 (Android 16) आहे.
7. अॅपच्या परवानग्या निवडण्यासाठी Pilih Izin बटण दाबा, उदाहरण: INTERNET. INTERNET परवानगी पूर्वनिर्धारितपणे आधीच चिन्हांकित केलेली असते. फक्त अॅपला खरोखर आवश्यक असलेल्या परवानग्याच चिन्हांकित करा.
8. इच्छा असल्यास, APK चा आकार लहान होण्यासाठी "Gunakan arsitektur terpisah 64 bit dan 32 bit" चिन्हांकित करा, आणि स्वतः बनवलेला keystore वापरायचा असल्यास "Gunakan tanda tangan pribadi" चिन्हांकित करा.
9. Buat Proyek दाबा. नवीन प्रकल्प Download/project फोल्डरमध्ये जतन होतो आणि लगेच Kelola Project मध्ये दिसतो.

उपलब्ध प्रकल्प प्रकार
• HTML: index.html, style.css, आणि script.js मधून देखावा, WebView द्वारे चालते. थेट फोनवर बनवले जाते.
• Situs Web: index.html, tentang.html, kontak.html, style.css, आणि script.js मधून मेनूसह (Beranda, Tentang, Kontak) वेबसाइट, WebView द्वारे चालते. थेट फोनवर बनवले जाते.
• Java: फोनवर बनवले जाते. MainActivity app/src/main/java/<nama-paket>/MainActivity.java मध्ये असते. देखावा app/src/main/res/layout/activity_main.xml मधून, मजकूर app/src/main/res/values/strings.xml मधून, आणि थीम app/src/main/res/values/styles.xml मधून येते.
• Kotlin: अॅपमध्ये समाविष्ट असलेल्या Kotlin कंपायलरचा वापर करून डिव्हाइसवर (ऑफलाइन) बनवता येते, किंवा GitHub Actions द्वारे बनवता येते. MainActivity app/src/main/java/<nama-paket>/MainActivity.kt मध्ये असते, आणि res फाइल्स Java प्रकल्पासारख्याच असतात. कंपायलरच्या मोठ्या आकारामुळे पहिले Kotlin बिल्ड संथ असते, आणि Kotlin वर्गांचा संदर्भ देणाऱ्या .java फाइल्स अजून बनवता येत नाहीत (.java फाइल्स .kt फाइल्सच्या आधी कंपाइल केल्या जातात).
• Compose: आधुनिक Android अॅप ज्याचा इंटरफेस Jetpack Compose ने बनवला आहे (XML लेआउट नाही). MainActivity app/src/main/java/<nama-paket>/MainActivity.kt मध्ये असते. Compose प्रकल्प GitHub Actions द्वारे (Bangun proyek मेनू, नंतर Bangun online) किंवा Termux मध्ये Gradle ने बनवले जातात, कारण Compose ला Jetpack Compose लायब्ररी आवश्यक असतात ज्या डिव्हाइसवर उपलब्ध नाहीत.
• Python: अॅपचे तर्क Python भाषेत (Chaquopy) app/src/main/python/main.py मध्ये लिहिले जाते, आणि app/src/main/java/<nama-paket>/MainActivity.java मधील होस्ट MainActivity.java द्वारे चालवले जाते. Python प्रकल्प थेट फोनवर बनवता येतात (Chaquopy रनटाइम अॅपमध्ये समाविष्ट आहे) किंवा GitHub Actions द्वारेही बनवता येतात. Python प्रकल्पांसाठी किमान SDK 24 (Android 7.0) आहे.

Java, HTML, Situs Web, Kotlin, Compose, आणि Python प्रकल्पांची फाइल रचना
Java, HTML, Situs Web, Kotlin, Compose, आणि Python प्रकल्प सामान्यतः Android प्रकल्पांप्रमाणेच रचलेले असतात. app फोल्डरच्या आत src फोल्डर असते, आणि त्याच्या आत main फोल्डर असते. main फोल्डरच्या आत java फोल्डरच्या शेजारी AndroidManifest.xml असते, res फोल्डर असते ज्यामध्ये layout/activity_main.xml आणि values/strings.xml आणि values/styles.xml असतात, आणि HTML व Situs Web साठी assets फोल्डर असते ज्यामध्ये index.html असते (Situs Web मध्ये tentang.html आणि kontak.html देखील असतात). HTML आणि Situs Web प्रकल्पांची स्वतःची MainActivity देखील app/src/main/java/<nama-paket>/MainActivity.java मध्ये असते, जी WebView मध्ये index.html लोड करते आणि AndroidManifest मध्ये लॉन्चर म्हणून असते. Python प्रकल्पांमध्ये Python कोड app/src/main/python/main.py मध्ये आणि होस्ट MainActivity.java app/src/main/java/<nama-paket>/MainActivity.java मध्ये असते. AndroidManifest.xml, लेआउट, strings, आणि styles संपादकात उघडता व बदलता येतात, MainActivity प्रमाणेच. ज्या जुन्या प्रकल्पांचा मॅनिफेस्ट अजूनही app फोल्डरच्या शेजारी आहे ते देखील बनवता येतात, कारण बनवताना, अॅप आधी app/src/main/ मध्ये AndroidManifest.xml तपासते, नंतर app फोल्डरच्या शेजारी असलेले, आणि शेवटी प्रकल्प डेटा फाइल तपासते.

परवानगीचे नियम (महत्त्वाचे)
प्रकल्प बनवताना चिन्हांकित केलेल्या परवानग्या, प्रकल्पाच्या प्रकारानुसार, फक्त एकाच ठिकाणी नोंदवल्या जातात. Java, HTML, Situs Web, Kotlin, Compose, आणि Python प्रकल्पांसाठी, चिन्हांकित केलेल्या परवानग्या प्रकल्प फोल्डरच्या आत, java फोल्डरच्या शेजारी, app/src/main/ मधील AndroidManifest.xml मध्येच नोंदवल्या जातात. Java, HTML, Situs Web, Kotlin, Compose, आणि Python प्रकल्पांसाठीच्या प्रकल्प डेटा फाइलमध्ये परवानग्यांची यादी नसते. तुम्ही Java निवडून INTERNET आणि CAMERA चिन्हांकित केल्यास, AndroidManifest.xml मध्ये फक्त INTERNET आणि CAMERA च नोंदवले जातील, इतर कोणतीही परवानगी जोडली जाणार नाही. बनवताना, अॅप त्याच ठिकाणाहून परवानग्या वाचते: Java, HTML, Situs Web, Kotlin, Compose, आणि Python प्रकल्पांसाठी app/src/main/ मधील AndroidManifest.xml मधून (नसल्यास, जुन्या प्रकल्पांसाठी app फोल्डरच्या शेजारी असलेल्या AndroidManifest.xml मधून), आणि जुन्या प्रकल्पांसाठी प्रकल्प डेटा फाइलमधून.

संपादक कसा वापरायचा
Kelola Project उघडा, संपादक उघडण्यासाठी प्रकल्पाच्या नावावर टॅप करा. संपादकात, फाइल्स उघडता येतात, कोड लिहिता येतो, आणि बदल जतन करता येतात. Java, HTML, Situs Web, Kotlin, Compose, आणि Python प्रकल्पांसाठी, फाइल्स app/src/main फोल्डरच्या आत रचलेल्या असतात. प्रकल्प शेअर करण्यासाठी, Ekspor ZIP वापरा (खालील विभाग पहा).

प्रकल्प कसा चालवायचा
संपादकात, प्रकल्पाची चाचणी करण्यासाठी Jalankan दाबा. HTML आणि Situs Web प्रकल्पांसाठी, चालवले जाणारे WebView द्वारे index.html असते. एखादी त्रुटी आल्यास, त्रुटी संदेश वाचा, कोड दुरुस्त करा, नंतर पुन्हा चालवा.

APK कसा बनवायचा
संपादकात, Bangun दाबा. बनवण्याचे दोन मार्ग आहेत. पहिला, Bangun di perangkat: इंटरनेटशिवाय थेट फोनवर बनवणे, HTML, Situs Web, Java, Kotlin, आणि Python प्रकल्पांसाठी. दुसरा, GitHub Actions द्वारे Bangun online: इंटरनेटद्वारे GitHub वर बनवणे, आणि सर्व प्रकारच्या प्रकल्पांसाठी वापरता येते. Compose प्रकल्प फक्त दुसऱ्या मार्गाने (Bangun online) किंवा Termux मध्ये Gradle ने बनवता येतात, कारण Compose ला Jetpack Compose लायब्ररी आवश्यक असतात ज्या डिव्हाइसवर उपलब्ध नाहीत. पहिल्या बिल्डचा निकाल अजून स्वाक्षरी केलेला नसतो. त्यानंतर अॅप त्यावर स्वाक्षरी करते: पूर्वनिर्धारित कीने आपोआप, किंवा प्रकल्प बनवताना "Gunakan tanda tangan pribadi" बॉक्स चिन्हांकित केला असल्यास वैयक्तिक स्वाक्षरीने.

APK कसे स्थापित करायचे
APK तयार झाल्यावर, ते स्थापित करण्यासाठी Pasang दाबा. Android 8 आणि त्यावरील आवृत्त्यांमध्ये, हे अॅप Play Store च्या बाहेरून APK स्थापित करते म्हणून, फोन आधी "Izinkan dari sumber ini" मागेल. Pengaturan मध्ये ती परवानगी एकदा सक्षम करा, नंतर अॅपकडे परत या: Pasang पुन्हा दाबण्याची गरज न लागता स्थापना आपोआप सुरू राहील. Pasang बटण दिसत नसल्यास, बिल्ड पूर्ण झाले आहे आणि APK बनवले गेले आहे याची खात्री करा.

अॅपमध्ये स्वाक्षरी कशी करायची
प्रत्येक APK स्थापित करण्यासाठी स्वाक्षरी केलेले असणे आवश्यक आहे. दोन पर्याय उपलब्ध आहेत. पहिला, पूर्वनिर्धारित की: तुम्हाला काहीही करावे न लागता, अॅप आपोआप स्वाक्षरी करते. दुसरा, वैयक्तिक स्वाक्षरी: आधी मुख्य मेनूमधील Buat Keystore मेनूद्वारे एक keystore बनवा, त्याचा पासवर्ड नीट जतन करा, नंतर प्रकल्प बनवताना "Gunakan tanda tangan pribadi" चिन्हांकित करा. Keystore Download/project/signing मध्ये जतन होते.

प्रकल्प ZIP म्हणून निर्यात करणे
प्रकल्प मित्रांसोबत शेअर करता यावेत म्हणून Ekspor ZIP दिले आहे. पद्धत: Kelola Project मध्ये, प्रकल्पाचे नाव बराच वेळ दाबून ठेवा, नंतर Ekspor ZIP निवडा. निकाल Download/project/<NamaProyek>.zip मध्ये जतन होतो. bin फोल्डर समाविष्ट नसल्यामुळे, आकार लहान असतो, फक्त काही दहा KB. ती ZIP फाइल मित्राला पाठवता येते किंवा GitHub वर अपलोड करता येते.

JAWS विस्तार
JAWS विस्तार Jieshuo (CSR) चे विस्तार इंजिन वापरते, त्याचा स्क्रीन रीडर नाही. यामुळे, वापरकर्ता TalkBack वापरत असला तरी डिझाइन चालू शकते. पद्धत: मुख्य मेनूमध्ये Ekstensi JAWS उघडा. स्वयंचलित क्लिक स्वतःहून चालते म्हणून, सेवा आधी Pengaturan Aksesibilitas मध्ये सक्षम करावी लागते. त्यानंतर, नवीन डिझाइन बनवता येते: डिझाइनचे नाव टाइप करा, OK दाबा, नंतर त्याचे बॉक्स भरा.

स्वच्छतेसाठी Daftar Klik वेगळे ठेवले आहे
डिझाइनच्या आत दोन बॉक्स असतात: स्क्रिप्ट बॉक्स आणि Daftar Klik बॉक्स. बटणांची यादी daftar_klik.txt फाइलमध्ये वेगळी जतन केली जाते, प्रत्येक ओळीत एक नाव. त्याच्या मजकुराचे उदाहरण: tombolSimpan, tombolHapus, tombolBuka. एखादे अॅप उघडण्यासाठी, त्या यादीत फक्त >WhatsApp लिहा. ज्या जुन्या डिझाइनमध्ये अजून daftar_klik.txt फाइल नाही, त्या ते पूर्वनिर्धारित उदाहरण दाखवतील.

स्क्रीन रीडरबद्दल
हे अॅप स्क्रीन रीडरला अनुकूल असे डिझाइन केले आहे. प्रत्येक इनपुट क्षेत्राला एक लेबल आणि भरण्याचे उदाहरण असते, आणि सर्व बटणे गुंतागुंतीच्या हावभावांशिवाय गाठता येतात. JAWS विस्तार अशा प्रकारे बनवले आहे की वापरकर्ता TalkBack वापरत असला तरी ते चालते, कारण वापरले जाणारे त्याचे विस्तार इंजिन आहे, त्याचा स्क्रीन रीडर नाही.

गोपनीयता आणि सुरक्षा
प्रकल्प आणि keystore तुमच्या फोनवर जतन होतात. GitHub टोकन फक्त ऑनलाइन बिल्डसाठी वापरले जाते आणि या अॅपमध्येच जतन होते. तुमचे टोकन किंवा keystore पासवर्ड कोणाशीही शेअर करू नका. वैयक्तिक स्वाक्षरी वापरत असल्यास, keystore आणि त्याचा पासवर्ड सुरक्षित ठिकाणी ठेवा, कारण ते हरवल्यास, जुने APK त्याच स्वाक्षरीने अद्यतनित करता येणार नाही.

आवश्यकता
Android 5.0 किंवा त्यापेक्षा नवीन. संग्रहण परवानगी: Android 11 आणि त्यावरील आवृत्त्यांमध्ये सर्व फाइल्सच्या प्रवेशाची परवानगी वापरते, Android 10 आणि त्याखालील आवृत्त्यांमध्ये सामान्य संग्रहण परवानगी (संग्रहण वाचणे/लिहिणे) वापरते कारण Android 10 मध्ये सर्व फाइल्सच्या प्रवेशाची परवानगी नाही. डिव्हाइसवर बनवण्यासाठी ARM प्रोसेसर (32 किंवा 64 बिट) असलेला फोन आवश्यक आहे. GitHub Actions द्वारे ऑनलाइन बनवण्यासाठी इंटरनेट आणि GitHub टोकन आवश्यक आहे. Kotlin प्रकल्प डिव्हाइसवर बनवता येतात, परंतु Kotlin कंपायलरच्या मोठ्या आकारामुळे त्याचे पहिले बिल्ड संथ असते आणि जास्त मेमरी वापरते. Compose प्रकल्प GitHub Actions द्वारे किंवा Termux मध्ये Gradle ने बनवले जातात. Python प्रकल्पांसाठी Android 7.0 किंवा त्यापेक्षा नवीन (किमान SDK 24) आवश्यक आहे आणि परिणामी APK मोठे असते कारण त्यात Python रनटाइम (Chaquopy) आणि त्याची प्रमाणित लायब्ररी असते.

Terminal
मुख्य स्क्रीनवरील Terminal मेनू या अॅपच्या आत एक टर्मिनल उघडते. प्रकल्प फोल्डरमधील मजकूर पाहण्यासाठी ls, फोल्डर बदलण्यासाठी cd, आणि कोड व्यवस्थापित करण्यासाठी git यासारख्या आज्ञा वापरता येतात. आज्ञांचे आउटपुट स्क्रीन रीडरने वाचता येईल अशा मजकुराच्या रूपात दिसते, आणि शेवटचा निकाल ऐकण्यासाठी Bacakan hasil बटण असते. हे टर्मिनल फोनचे सिस्टम शेल वापरते, त्यामुळे nano आणि vim सारखे परस्परसंवादी प्रोग्राम येथे अजून वापरता येत नाहीत.

परवाना (सशुल्क आवृत्ती)
अॅप्स विकण्यासाठी, प्रकल्प बनवताना "Aktifkan Lisensi" चिन्हांकित करा, नंतर तुमचा WhatsApp नंबर भरा. बिल्डचा निकाल असलेले अॅप पहिल्यांदा उघडल्यावर परवाना कोड मागेल: वापरकर्ता त्याचा डिव्हाइस ID पाहतो, तो ID तुमच्या WhatsApp वर पाठवण्यासाठी Kirim ID Perangkat बटण दाबतो, नंतर तुम्ही परवाना कोडने उत्तर देता. परवाना कोड डिव्हाइस ID आणि प्रकल्प पासवर्ड (प्रकल्प डेटा फाइलमधील lisensi_seed) वरून मोजला जातो — तो पासवर्ड नीट जतन करा आणि शेअर करू नका. योग्य कोड टाकल्यानंतर, अॅप उघडते आणि पुन्हा कोड मागत नाही.

Pembuat Ikon Otomatis
नवीन प्रकल्पांची चिन्हे अजूनही पारदर्शक असतात, म्हणून मुख्य मेनूमध्ये Pembuat Ikon उपलब्ध आहे. पद्धत: Pembuat Ikon दाबा, एक किंवा दोन अक्षरे लिहा (उदाहरणार्थ, अॅपच्या नावाची आद्याक्षरे), पार्श्वभूमीचा रंग आणि मजकुराचा रंग निवडा, त्याचे पूर्वावलोकन पहा, नंतर निवडलेल्या प्रकल्पात ते चिन्ह वापरण्यासाठी Simpan ke Proyek दाबा, किंवा त्याची PNG फाइल इतरत्र वापरण्यासाठी Simpan ke Download दाबा. प्रकल्प बनवल्यानंतर, अॅप चिन्ह बनवण्याची ऑफर देखील देते. जुन्या प्रकल्पांची चिन्हे Kelola Project मधील प्रकल्प मेनूमधून कधीही बदलता येतात (प्रकल्पाचे नाव बराच वेळ दाबून ठेवा, नंतर Ganti Ikon निवडा).

तयार प्रकल्प टेम्पलेट्स
रिकाम्या प्रकल्पापासून सुरुवात करायची नसल्यास, प्रकल्प बनवताना एक टेम्पलेट निवडा: Kalkulator (Java), Catatan (Java), Daftar Tugas (Kotlin), Kalkulator Web (HTML), Situs Profil (Situs Web), किंवा Penghitung (Compose). टेम्पलेट निवडल्याने प्रकल्पाचा प्रकार आपोआप त्या टेम्पलेटनुसार बदलतो, आणि प्रकल्प तयार सुरुवातीच्या कोडसह बनवला जातो — तो फक्त चालवायचा किंवा बदलायचा बाकी असतो. टेम्पलेट निवडल्यानंतर प्रकल्पाचा प्रकार पुन्हा हाताने बदलल्यास, टेम्पलेट रद्द होते आणि प्रकल्प पुन्हा रिकामा होतो. HTML आणि Situs Web टेम्पलेट्ससाठी, टेम्पलेट index.html चा मजकूर बदलते, फॉर्ममध्ये टाइप केलेल्या HTML स्क्रिप्टसह.

प्रकल्प शोध आणि गाळणी
प्रकल्प खूप झाले तर, Kelola Project मध्ये एक शोध बॉक्स आणि प्रकार गाळणी असते. शोध बॉक्समध्ये प्रकल्पाचे नाव टाइप करा, यादी लगेच गाळली जाते (मोठी आणि लहान अक्षरे वेगळी मानली जात नाहीत). प्रकार गाळणी यादीला फक्त एका प्रकारापुरती मर्यादित करते: Semua, HTML, Situs Web, Java, Kotlin, Compose, किंवा Python. गाळलेल्या यादीतूनही प्रत्येक प्रकल्पाचा मेनू नेहमीप्रमाणे उघडता येतो.

आवाजाने ॲप बनवा
तुम्हाला टाइप करायचे नसेल तर आवाज वापरा: मुख्य मेनूमध्ये आवाजाने बिल्ड करा वर टॅप करा, मग एक आदेश बोला. बोलता येणारे आदेश: "Buat proyek kalkulator", "Bangun proyek Kalkulator", "Buka proyek Kalkulator", "Jalankan proyek Kalkulator", "Daftar proyek", "Buka ikon", "Kembali" आणि "Bantuan". अॅप आवाजाने व मजकुराने उत्तर देते, त्यामुळे स्क्रीनकडे न पाहताही ते वापरता येते. आवाज ओळखण्यासाठी फोनचे अंगभूत स्पीच रेकग्निशन अॅप वापरले जाते (विनामूल्य; इंडोनेशियन भाषा पॅक स्थापित असेल तर ते ऑफलाइनही चालू शकते). फोनमध्ये आवाज ओळख नसेल तर आदेश त्याच स्क्रीनवरील मजकूर चौकटीत लिहिता येतात.

अ‍ॅक्सेसिबिलिटी ऑडिट
प्रकाशनाआधी एखाद्या प्रकल्पाचे लेआउट स्क्रीन रीडरसाठी (TalkBack/Jieshuo) अनुकूल आहे का हे तपासण्यासाठी: मुख्य मेनूमध्ये अ‍ॅक्सेसिबिलिटी ऑडिट उघडा, प्रकल्प निवडा, मग लेआउट यादी लोड करा वर टॅप करून लेआउट फाइल निवडा. IDE ती XML फाइल वाचतो आणि लेबल नसलेली बटणे त्यांच्या ओळ क्रमांकांसह, वारंवार वापरलेली लेबले आणि एकमेकांना झाकणारे घटक यांचा अहवाल देतो, मग Jieshuo मोठ्याने वाचतो तसा फोकस क्रमाचा उतारा तयार करतो. एखाद्या बटणाला लेबल नसेल तर त्याचे लेबल भरा मग लेबल आपोआप घाला वर टॅप करा — लेबल contentDescription म्हणून लेआउट फाइलमध्ये लिहिले जाते. ही तपासणी फक्त लेआउट XML वाचते; Compose दृश्ये व तयार APK अद्याप स्कॅन केले जात नाहीत.

क्रॅश शवविच्छेदन
अद्वितीय आयडी असलेल्या क्रॅश लॉगवरून अॅप स्वतःच का बंद होते हे जाणून घेण्यासाठी: मुख्य मेनूमध्ये क्रॅश शवविच्छेदन उघडा, लॉग यादीतून क्रॅश आयडी निवडा, मग तपासा वर टॅप करा. IDE लॉगमधील वर्ग व ओळ क्रमांक प्रकल्पाच्या स्रोताशी जुळवतो आणि कारण इंडोनेशियन भाषेत समजावतो (उदाहरणार्थ रिकामा संदर्भ, अद्याप न मागितलेली परवानगी, किंवा JSON त्रुटी), कोड दुरुस्तीच्या सूचनेसह. स्रोत ओळ क्रॅश झाला तेव्हा होती तशीच अजूनही असेल तरच दुरुस्ती लागू करा वर टॅप करा; ती बदलली असेल तर दुरुस्ती नाकारली जाते आणि IDE तुम्हाला स्वतः तपासायला सांगतो. वाचला जाणारा लॉग IDE चा स्वतःचा क्रॅश लॉग आहे, तयार केलेल्या अॅपचा लॉग नाही.

आंतर-प्रतिमान ट्रान्सपायलर
साधा Java कोड Kotlin मध्ये, किंवा साधा XML लेआउट Compose कोडमध्ये बदलण्यासाठी: मुख्य मेनूमध्ये आंतर-प्रतिमान ट्रान्सपायलर उघडा, प्रकल्प व फाइल निवडा, मग पूर्वावलोकन वर टॅप करा. IDE रूपांतरणाचा निकाल मजकूर म्हणून दाखवतो — आधी तो तपासा, कारण ज्या ओळी तो ओळखत नाही त्या जशाच्या तशा राहतात आणि Java मधील static हा शब्द Kotlin मध्ये काढला जातो (वापरण्याआधी त्याचा अर्थ तपासा). XML ते Compose रूपांतरण फक्त मजकूर, इशारे व दिशा बदलते — आकार, रंग व इतर गुणधर्म अद्याप समाविष्ट नाहीत. निकाल बरोबर असेल तर लक्ष्य फाइल लिहिण्यासाठी फाइलवर लागू करा वर टॅप करा; स्रोत फाइल बदलत नाही. फक्त सुरक्षित, सामान्य नमुने रूपांतरित केले जातात.

स्थानिक सूक्ष्म सर्व्हर
इंटरनेटशिवाय सर्व्हर लागणारे अॅप तपासण्यासाठी: मुख्य मेनूमध्ये स्थानिक सूक्ष्म सर्व्हर उघडा, मार्ग व्याख्या लिहा (उदाहरणार्थ GET /halo आणि मग त्याचे JSON उत्तर), मग सर्व्हर सुरू करा वर टॅप करा. IDE त्याच फोनवर एक छोटा HTTP सर्व्हर चालवतो (फक्त HTTP, TLS शिवाय, त्याच Wi-Fi नेटवर्कसाठी) आणि प्रत्येक विनंती व उत्तर स्क्रीनवर नोंदवतो. मार्ग {nama} सारखे पॅरामीटर व साधी API की वापरू शकतात. हा सर्व्हर फक्त फोनवर तपासणीसाठी आहे; तयार केलेला APK अद्याप सर्व्हर होऊ शकत नाही, आणि त्याची स्क्रीन बंद होताच सर्व्हर थांबतो.

सुरक्षा ऑडिटर
प्रकाशनाआधी प्रकल्प कोडमधील सुरक्षा त्रुटी तपासण्यासाठी: मुख्य मेनूमध्ये सुरक्षा ऑडिटर उघडा, प्रकल्प निवडा, मग स्कॅन सुरू करा वर टॅप करा. IDE कोड, मॅनिफेस्ट व प्रकल्प संरचना स्कॅन करतो आणि जास्त धोक्यापासून कमी धोक्यापर्यंत निष्कर्ष कळवतो — कोडमध्ये उघड्या API की, परवानगीशिवाय उघडे घटक, JavaScript इंटरफेससह JavaScript सक्षम करणारा WebView, कमकुवत क्रिप्टो (MD5, SHA1, DES), TLS नसलेले http पत्ते, आणि कोडमध्ये थेट लिहिलेले पासवर्ड — प्रत्येकासह त्याची फाइल व ओळ क्रमांक. सुरक्षित दुरुस्ती असलेल्या निष्कर्षांसाठी (उदाहरणार्थ MD5 ऐवजी SHA-256 किंवा http ऐवजी https) दुरुस्ती लागू करा वर टॅप करा; API की व पासवर्डसाठी IDE फक्त सुचवलेली दुरुस्ती दाखवतो कारण बदल स्वतः विकासकानेच ठरवायचा असतो. हे स्कॅन कोडमधील मजकूर नमुने वाचते, बाइटकोड नाही, त्यामुळे काही निष्कर्ष प्रत्यक्षात सुरक्षित असू शकतात, आणि नमुना नसलेली त्रुटी स्कॅनमधून सुटू शकते — लागू करण्यापूर्वी तपासा.

इंटरफेस चाचणी रोबोट
मजकूर परिस्थितींनी अॅपचे स्वरूप आपोआप तपासण्यासाठी: मुख्य मेनूमध्ये इंटरफेस चाचणी रोबोट उघडा, प्रकल्प निवडा, मग आपोआप परिस्थिती बनवा वर टॅप करा. IDE प्रकल्पाचे मॅनिफेस्ट व लेआउट वाचतो आणि मजकूर पायऱ्यांची परिस्थिती लिहितो (बटण टॅप करा, क्षेत्र भरा, प्रतीक्षा करा, परत जा). परिस्थितीच्या अंमलबजावणीचा लॉग वेळखुणांसह पाहण्यासाठी ड्राय रन चालवा वर टॅप करा. या टप्प्यात रोबोट फक्त अनुकरण चालवतो (ड्राय रन) — फोनवर बटणे खरोखर दाबणे व खरे क्रॅश पकडणे हा पुढचा टप्पा आहे, त्यामुळे इथला क्रॅश अहवाल अद्याप नमुना स्वरूपातच आहे.

कोड वेळ प्रवास
Git आदेश न टाइप करता प्रकल्पाला आधीच्या कोड स्थितीत परत नेण्यासाठी: मुख्य मेनूमध्ये कोड वेळ प्रवास उघडा, प्रकल्प निवडा, वेळबिंदूचे लेबल भरा (रिकामे राहू शकते), मग वेळबिंदू नोंदवा वर टॅप करा. IDE प्रकल्पाच्या स्रोत फाइल्सची प्रत त्यांच्या hash सह प्रकल्पातील .riwayat फोल्डरमध्ये जतन करतो. वेळबिंदू यादी त्या सर्वांना दाखवते; दोन बिंदू निवडा मग जोडलेल्या, बदललेल्या किंवा काढलेल्या फाइल्स व कार्ये पाहण्यासाठी तुलना करा वर टॅप करा. जुनी स्थिती परत मिळवण्यासाठी पुनर्स्थापित करा वर टॅप करा — पुनर्स्थापित करण्यापूर्वी IDE नेहमी आधी सध्याच्या स्थितीचा बॅकअप बनवतो, त्यामुळे काहीही हरवत नाही. मूळ प्रकल्पाला त्रास न देता बदल आजमावण्यासाठी प्रकल्प नवीन फोल्डरमध्ये कॉपी करण्यासाठी प्रयोग प्रत बनवा वर टॅप करा. फक्त स्रोत फाइल्स नोंदवल्या जातात.

मॉड्यूल कारखाना
प्रकल्पाचा एखादा भाग दुसऱ्या प्रकल्पाला वापरता येईल असे मॉड्यूल म्हणून पॅक करण्यासाठी: मुख्य मेनूमध्ये मॉड्यूल कारखाना उघडा, स्रोत प्रकल्प निवडा, पॅक करायच्या स्क्रीन, वर्ग, स्ट्रिंग व परवानगी फाइल्सवर खूण करा, मग मॉड्यूल म्हणून पॅक करा वर टॅप करा. IDE JSON मेटाडेटासह (मॉड्यूलचे नाव, आवृत्ती, वापरलेल्या स्ट्रिंग व परवानग्या) ZIP संग्रह लिहितो. दुसऱ्या प्रकल्पात मॉड्यूल बसवण्यासाठी मॉड्यूल कारखाना उघडा, लक्ष्य प्रकल्प निवडा, मग मॉड्यूल बसवा वर टॅप करून मॉड्यूलची .zip फाइल निवडा — विलीनीकरण विद्यमान कोड न लिहिता स्ट्रिंग व परवानग्या जोडते, आणि लक्ष्य प्रकल्पात नाव आधीच वापरले असेल तर फाइल विलीन करत नाही. मॉड्यूल लायब्ररी किंवा बिल्ड सेटिंग्ज सोबत नेत नाही.

बहुरूपी ढाल आणि मालमत्ता तिजोरी
प्रकाशनापूर्वी ओळखीची नावे यादृच्छिक करण्यासाठी व प्रकल्प मालमत्ता एन्क्रिप्ट करण्यासाठी: मुख्य मेनूमध्ये बहुरूपी ढाल आणि मालमत्ता तिजोरी उघडा, प्रकल्प निवडा, मग नावे यादृच्छिक करा आणि मालमत्ता एन्क्रिप्ट करा दाबा. IDE स्रोत कोडमधील वर्ग व पद्धतींची नावे स्कॅन करते, यादृच्छिक नावांचा नकाशा तयार करते, प्रकल्प मालमत्ता फायली AES-GCM ने प्रकल्पातील brankas-aset फोल्डरमध्ये एन्क्रिप्ट करते, आणि एन्क्रिप्ट केलेला पुनर्प्राप्ती नकाशा (perisai-peta.brankas) जतन करते जेणेकरून क्रॅश लॉग वाचताना मूळ नावे परत मिळवता येतील. एन्क्रिप्शन की प्रकल्पाच्या नावावरून तयार होते, त्यामुळे प्रकल्पाचे नाव माहीत असलेला कोणीही तिजोरी उघडू शकतो — हे सहज वाचनापासून संरक्षण आहे, पासवर्डने कुलूपबंद तिजोरी नाही. इथे जे तयार होते ते नावांचा नकाशा व मालमत्ता तिजोरी आहे; संकलित DEX फाइलमधील नावे पुन्हा लिहिणे पुढचे टप्पे आहे, त्यामुळे तयार APK मधील नावे अजून यादृच्छिक झालेली नाहीत.

विश्वास साखळी आणि वातावरण रक्षक
प्रकाशनापूर्वी स्वाक्षरी की साखळी व फोनचे वातावरण तपासण्यासाठी: मुख्य मेनूमध्ये विश्वास साखळी आणि वातावरण रक्षक उघडा, प्रकल्प निवडा, मग साखळी आणि वातावरण तपासा दाबा. मजकूर वृक्ष मांडणी वास्तुविशारद

डिझाइन प्रणाली स्टुडिओ
सर्व पडदे व प्रकल्पांमध्ये अंतर, अक्षर व कोन एकसारखे करण्यासाठी: मुख्य मेनूमध्ये डिझाइन प्रणाली स्टुडिओ उघडा, प्रकल्प निवडा, डिझाइन टोकन लिहा (उदाहरणार्थ jarak=8, huruf=16, sudut=12), घटक निवडा, मग घटक तयार करा दाबा. IDE टोकन तपासते — मूळ अंतर ४ ते १६ dp, मूळ अक्षर १२ ते २० sp, कोन ० ते ३२ dp, व किमान स्पर्श क्षेत्र ४८ dp — मग वापरण्यास तयार XML घटक (komponen-studio.xml) XML थीम (tema-studio.xml) व Compose थीम (tema-studio.kt) सह प्रकल्प फोल्डरमध्ये लिहिते. घटक मजकूर म्हणून तयार होतात, जे मांडणीत चिकटवले जातात व नंतर मांडणी वास्तुविशारदाने तपासले जातात; टॅब्लेटवरील दोन स्तंभांचे समायोजन पडदा रुंदी पात्रता वापरते, चालू असताना उपकरण ओळख नाही.

अर्थपूर्ण पुनर्रचना आणि AST नेव्हिगेशन
व्याख्या शोधण्यासाठी व चिन्हांची नावे बदलण्यासाठी, योगायोगाने तेच नाव असलेला दुसरा कोड न मोडता: मुख्य मेनूमध्ये अर्थपूर्ण पुनर्रचना आणि AST नेव्हिगेशन उघडा, प्रकल्प निवडा, मग सर्व वर्ग व पद्धती त्यांच्या फायली व ओळ क्रमांकांसह पाहण्यासाठी प्रकल्प चिन्हे स्कॅन करा दाबा. चिन्हाचे नाव लिहा, मग त्याची व्याख्या व त्याला बोलावणाऱ्या सर्व फायली पाहण्यासाठी पुन्हा प्रकल्प चिन्हे स्कॅन करा दाबा. नाव बदलण्यासाठी नवीन नाव लिहा, प्रत्येक फाइलमध्ये किती वेळा आले ते पाहण्यासाठी नाव बदलण्याचे पूर्वावलोकन दाबा, मग नाव बदल लागू करा दाबा. ही सूची मजकूर नमुने वापरते, पूर्ण AST पार्सर नाही: वर्गाचे नाव बदल सर्व फायलींना लागू होते, तर पद्धतीचे नाव बदल फक्त तिच्या मालक फाइलला — इतर फायलींमधील बोलावणारे बदलत नाहीत, त्यामुळे लागू करण्यापूर्वी पूर्वावलोकन व बोलावणाऱ्यांचे स्कॅन निकाल तपासा. कोड ब्लॉक नवीन फंक्शनमध्ये काढणे तर्क इंजिनमध्ये आधीच आहे, पण या पडद्यावर त्याचे बटण अजून नाही.

टप्प्याटप्प्याने डीबगर आणि मेमरी निरीक्षक

ऑफलाइन अवलंबित्व व्यवस्थापक
इंटरनेटशिवाय तृतीय पक्ष लायब्ररी वापरण्यासाठी व बांधणीपूर्वी आवृत्ती संघर्ष टाळण्यासाठी: मुख्य मेनूमध्ये ऑफलाइन अवलंबित्व व्यवस्थापक उघडा, प्रकल्प निवडा, मग अवलंबित्व तपासा दाबा. IDE प्रकल्पातील सर्व .gradle फायली वाचते, ऑफलाइन तिजोरी (प्रकल्पातील brankas-maven.txt) तपासते, व संघर्ष सोडवते — दोन लायब्ररी एकाच आर्टिफॅक्टच्या वेगळ्या आवृत्त्या मागितल्यास सर्वोच्च आवृत्ती वापरली जाते व संघर्ष कळवला जातो. लायब्ररी तिजोरीत नोंदवण्यासाठी तिचे निर्देशांक लिहा (स्वरूप गट:आर्टिफॅक्ट:आवृत्ती, उदाहरणार्थ com.google.code.gson:gson:2.10.1) मग अवलंबित्व तपासा दाबा. Maven, Google किंवा PyPI वरून डाउनलोडसाठी इंटरनेट लागते: ऑफलाइन असताना फक्त तिजोरीत आधीच असलेल्या लायब्ररी वापरता येतात, व निर्देशांक जोडणे फक्त सूचीत नोंदवते — AAR, JAR किंवा WHL फायली स्वतःहून डाउनलोड होत नाहीत. तिजोरी अजून प्रत्येक प्रकल्पासाठी जतन केली जाते.

डेटाबेस आणि संचयन निरीक्षक
तक्त्याचा आशय छापणारा कोड न लिहिता प्रकल्प डेटाबेसचा आशय तपासण्यासाठी व चाचण्यासाठी: मुख्य मेनूमध्ये डेटाबेस आणि संचयन निरीक्षक उघडा, प्रकल्प व डेटाबेस फाइल (.db, .sqlite किंवा .sqlite3) निवडा, मग डेटाबेस उघडा दाबा. IDE तक्त्याची रचना वाचते व पहिल्या २० ओळी मजकूर तक्ता म्हणून दाखवते, जे Jieshuo मोठ्याने वाचते. साधी SELECT क्वेरी लिहा मग क्वेरी चालवा दाबा (उदाहरणार्थ SELECT nama FROM pengguna WHERE kota = 'Makassar'). मूल्य बदलण्यासाठी ओळ क्रमांक (१ = पहिली ओळ), स्तंभाचे नाव व नवीन मूल्य लिहा, मग सेलचे मूल्य बदला दाबा — मूल्य .db फाइलमध्ये परत लिहिले जाते. तक्त्याची सध्याची स्थिती प्रकल्पात <डेटाबेस-नाव>.cadangan.txt फाइल म्हणून जतन करण्यासाठी बॅकअप जतन करा दाबा. फक्त पहिली तक्ता वाचली जाते; समर्थित क्वेरी फक्त JOIN किंवा GROUP BY शिवाय साधी SELECT आहेत; SharedPreferences व DataStore अजून वाचले जात नाहीत.

युनिट चाचणी कारखाना आणि फझिंग
अॅप वाटण्यापूर्वी तर्कातील पोकळी शोधण्यासाठी: मुख्य मेनूमध्ये युनिट चाचणी कारखाना आणि फझिंग उघडा, प्रकल्प व कोड फाइल निवडा, मग चाचण्या तयार करा आणि चालवा दाबा. IDE फाइलमधील फंक्शन स्वाक्षऱ्या वाचते, सामान्य व सीमा चाचणी प्रकरणे तयार करते (रिकामे मजकूर, null, कमाल संख्या, विचित्र अक्षरे), नमुना फंक्शनवर फझिंग चालवते, व JUnit चाचणी सांगाडा (Uji<वर्ग नाव>.java) प्रकल्पात लिहिते. निकाल कळवतो किती चाचण्या पास व नापास झाल्या, किती कोड ओळी व फंक्शन सापडले, व किती चाचणी प्रकरणे तयार झाली. तयार चाचण्या अजून सांगाडे आहेत — अपेक्षित मूल्ये विकासकाने लिहायची आहेत — व खरे फझिंग फक्त नमुना फंक्शनवर चालते, प्रकल्प फंक्शनवर नाही; ओळ व्याप्तीची टक्केवारी अजून मोजली जात नाही.

अत्यंत उपकरण स्थिती अनुकरणकर्ता आणि मेमरी गळती लेखापरीक्षक
प्रणाली त्याची प्रक्रिया मारते, नेटवर्क तुटते, पडदा फिरतो, किंवा बॅटरी बचत सक्रिय असते तेव्हा अॅपची सहनशीलता तपासण्यासाठी: मुख्य मेनूमध्ये अत्यंत उपकरण स्थिती अनुकरणकर्ता आणि मेमरी गळती लेखापरीक्षक उघडा, प्रकल्प निवडा, मग अनुकरण चालवा दाबा. IDE पडदा फिरण्याच्या अनुकरणासह तीन ताण परिस्थिती चालवते व त्यांचा पडदा बंद झाल्यानंतर मेमरीत अडकलेल्या वस्तूंचा मागोवा घेते, मग हरवलेला डेटा व गळणाऱ्या वस्तूंच्या साखळ्या कळवते. हे स्थिती मॉडेलवरील अनुकरण आहे, खरोखर प्रक्रिया मारणे नाही, खरोखर फोनचे नेटवर्क तोडणे नाही, व खरा heap dump नाही; या पडद्यावरील स्थिती मॉडेल अजून स्थिर उदाहरण आहे, वापरकर्त्याच्या प्रकल्प पडद्यांची स्थिती नाही.

प्रकल्प आराखडा वास्तुविशारद
मोठ्या अॅपची कल्पना टप्प्याटप्प्याने कामाच्या योजनेत बदलण्यासाठी: मुख्य मेनूमध्ये प्रकल्प आराखडा वास्तुविशारद उघडा, प्रकल्प निवडा, अॅपची कल्पना लिहा (उदाहरणार्थ हप्त्यांसह किराणा दुकान कॅशियर अॅप), मग आराखडा तयार करा दाबा. IDE मॉड्यूल, फाइल यादी व लहान कामाचे टप्पे मांडते, मग ते प्रकल्प फोल्डरमध्ये cetak-biru.txt म्हणून जतन करते. प्रत्येक टप्पा पूर्ण झाल्यावर पुढील टप्पा पूर्ण म्हणून चिन्हांकित करा दाबा, किंवा जतन केलेला आराखडा पुन्हा उघडण्यासाठी जतन केलेला आराखडा लोड करा दाबा. आराखडे उपकरणावरील मुख्य शब्द नमुन्यांवरून तयार होतात, ऑनलाइन AI मॉडेलवरून नाहीत — न ओळखलेल्या कल्पना सामान्य सांगाडा वापरतात (डेटा मॉडेल, संचयन, पडदे, तर्क) — व सक्रिय AI पुरवठादारामार्फत तयार करणे या टप्प्यात नाही.

कोड तर्क प्रवाह कथाकार
ओळीओळीने वाक्यरचना न ऐकता लांब कोड समजण्यासाठी: मुख्य मेनूमध्ये कोड तर्क प्रवाह कथाकार उघडा, प्रकल्प व कोड फाइल निवडा, मग कोड कथन दाबा. IDE प्रत्येक ओळ इंडोनेशियन वाक्यात बदलते (उदाहरणार्थ एकूण 100000 पेक्षा जास्त असल्यास, पुढील ब्लॉक चालवा), पद्धतींमधील बोलावण्याचा नकाशा दाखवते, व सूक्ष्म चुकांची शक्यता त्यांच्या ओळ क्रमांकांसह चिन्हांकित करते — == ने तुलना केलेला String, न बंद करता उघडलेला stream, व दोन वेगळ्या पद्धतींमध्ये लिहिलेला चल. कथन व तपासणी ऑफलाइन मजकूर नमुने वापरतात, ऑनलाइन AI मॉडेल नाही व पूर्ण डेटा प्रवाह विश्लेषणही नाही; न ओळखलेले नमुने जसे आहेत तसे कोड ओळ म्हणून कथन केले जातात, व डेटा शर्यतीच्या इशाऱ्यांमुळे खरे तर फक्त आळीपाळीने वापरल्या जाणाऱ्या चलांसाठीही इशारे येऊ शकतात.

अॅप बंडल कारखाना आणि Play Store तयारी
थेट फोनवरून Google Play Store साठी अॅप तयार करण्यासाठी: मुख्य मेनूमध्ये अॅप बंडल कारखाना आणि Play Store तयारी उघडा, प्रकल्प निवडा, मग AAB बंडल तयार करा दाबा. IDE मॅनिफेस्ट, संसाधने व प्रकल्प मालमत्तांमधून .aab फाइल जोडते, वास्तुकला (arm64-v8a, armeabi-v7a, x86_64) व भाषेनुसार डाउनलोड भाग आकारांचे अनुकरण करते, मग Play तयारीचे लेखापरीक्षण करते — लक्ष्य SDK ३५ पेक्षा कमी असल्यास उच्च म्हणून चिन्हांकित होते कारण Play Store ला ३५ किंवा अधिक हवे असते, व हरवलेली ६४-बिट लायब्ररीही उच्च म्हणून चिन्हांकित होते. तयार बंडल मानक रचनेचे AAB संग्रह आहे; भाग आकार फाइल आकारांवरून अंदाज आहेत, bundletool विभाजनाचे खरे निकाल नाहीत, व Play Console साठी बंडल स्वाक्षरी अजून APK चाचाच बांधणी मार्ग वापरते.

OTA अद्यतन इंजिन आणि टप्प्याटप्प्याने प्रकाशने
वापरकर्त्यांना संपूर्ण APK पुन्हा डाउनलोड करण्यास भाग न पाडता छोट्या दुरुस्त्या पाठवण्यासाठी: मुख्य मेनूमध्ये OTA अद्यतन इंजिन आणि टप्प्याटप्प्याने प्रकाशने उघडा, प्रकल्प निवडा, जुन्या व नवीन आवृत्तीचा आशय लिहा, मग पॅच पॅकेज तयार करा दाबा. IDE ओळींमधील फरक मोजते व नवीन आशयाच्या SHA-256 बोटांच्या ठशासह पॅच पॅकेज (patch-ota.zip) तयार करते, मग हे उपकरण सुरुवातीच्या १० टक्के प्रकाशन टप्प्यात आहे का ते तपासते. इथले पॅच फक्त मजकूर फायलींवर काम करतात (स्क्रिप्ट, मालमत्ता, कॉन्फिगरेशन) — बायनरी DEX किंवा APK पॅच अजून समर्थित नाहीत, व अॅप पुन्हा उघडल्यावर पॅच लागू होतो. मॅनिफेस्टमधील बोटांचा ठसा फक्त आशयाची अखंडता सिद्ध करतो, पाठवणाऱ्याची सत्यता नाही, कारण अजून खाजगी की स्वाक्षरी वापरली जात नाही.

संघ कोड पुनरावलोकन स्टुडिओ
Git चे बाण चिन्ह न वाचता सहकाऱ्याचे बदल तपासण्यासाठी व विलीनीकरण संघर्ष सोडवण्यासाठी: मुख्य मेनूमध्ये संघ कोड पुनरावलोकन स्टुडिओ उघडा, प्रकल्प निवडा, तीन मजकूर आवृत्त्या भरा (पाया, स्थानिक, सहकारी), मग संघ पुनरावलोकन उघडा दाबा. IDE तिन्ही एकत्र करते व प्रत्येक संघर्ष आवाज निवड म्हणून दाखवते: स्थानिक आवृत्ती वापरा, सहकाऱ्याची आवृत्ती वापरा, किंवा दोन्ही एकत्र करा — निकाल ओळी ओळ क्रम योग्य राहण्यासाठी संघर्षाच्या मूळ जागी घातल्या जातात — मग निकाल प्रकल्पात gabung-hasil.txt मध्ये लिहिते. त्याखाली प्रकल्प काम फलक आहे: कामाचे शीर्षक लिहा मग काम जोडा दाबा; कामे प्रकल्पातील .tugas फोल्डरमध्ये मजकूर म्हणून जतन केली जातात. विलीनीकरण वाक्यरचना नव्हे तर ओळ जुळणी वापरते, त्यामुळे एकाच ओळीवरील दोन बदल त्यांचा अर्थ न जुळला तरी नेहमी संघर्ष मानले जातात; काम फलक त्याची मजकूर फाइल Git इतिहासासह नकल करून समक्रमित होतो, विशेष समक्रमण सर्व्हरशिवाय.

कोड रचना डिक्टेशन
एडिटरमध्ये आवाजाने कोड लिहिण्यासाठी: एडिटरमध्ये प्रकल्प उघडा, मग कोड रचना डिक्टेशन बटण वर टॅप करा. इंडोनेशियन भाषेत आदेश बोला, उदाहरणार्थ buat fungsi tambah dengan parameter a angka dan b angka, buat kelas Mobil, किंवा buat variabel teks nama sama dengan Budi — IDE बोलणे व्याकरणदृष्ट्या बरोबर Java, Kotlin, Python किंवा Compose कोड गटात बदलतो आणि कर्सरच्या जागी घालतो, मग Jieshuo द्वारे संक्षिप्त सारांश मोठ्याने वाचतो. डिक्टेशन प्रणालीची अंगभूत आवाज इनपुट सेवा वापरते, अतिरिक्त मायक्रोफोन परवानगीशिवाय, आणि फक्त आधीच नोंदवलेले आदेश नमुने ओळखते; त्या नमुन्यांबाहेरील बोलणे कोडमध्ये बदलत नाही. शब्दांत बोललेले आकडे (उदाहरणार्थ 'lima') अद्याप अंकांत बदलत नाहीत.

स्थानिक सहकार कक्ष (इंटरनेटशिवाय)
इंटरनेटशिवाय एकाच खोलीत एकत्र काम करण्यासाठी: मुख्य मेनूमध्ये सहकार्य उघडा, मग स्थानिक सहकार कक्ष विभाग उघडा. एक फोन सत्र उघडतो (IDE स्थानिक IP पत्ता व ६ अंकी PIN दाखवतो), दुसरा फोन त्या पत्त्याने व PIN ने सामील होतो. मजकूर बदल ओळ फरक म्हणून पाठवले जातात, तयार केलेला APK परीक्षकाच्या फोनवर पाठवता येतो, आणि परीक्षकाच्या फोनवरून क्रॅश अहवाल परत मिळतात. एक सत्र फक्त एका मित्रासाठी आहे; दोन लोकांनी अगदी तीच ओळ एकाच वेळी बदलली तर शेवटचा बदल वापरला जातो. PIN स्थानिक नेटवर्कवर साधा मजकूर म्हणून पाठवला जातो. हा कक्ष अद्याप खऱ्या फोनवर तपासलेला नाही.

AI सेटिंग्ज
अॅप तयार करण्यासाठी AI पुरवठादार व API की सेट करण्यासाठी: मुख्य मेनूमध्ये, सेटिंग्ज गटात, AI सेटिंग्ज वर टॅप करा (कनेक्टर बटणाजवळ). उपलब्ध यादीतून वापरायचा पुरवठादार निवडा, आणि प्रोव्हायडर त्रुटी आल्यास मॉडेल बदला वर खूण करा जेणेकरून एक मॉडेल अयशस्वी झाले तर IDE त्याच पुरवठादाराचे पुढचे मॉडेल आपोआप आजमावेल. बॅकअप की जोडण्यासाठी API की व्यवस्थापित करा वर टॅप करा (नाव व की भरा, मग जतन करा वर टॅप करा; की झाकून दाखवल्या जातात, फक्त शेवटची ४ अक्षरे दिसतात). की फोनवर जतन केल्या जातात आणि अॅप तयार करताना निवडलेल्या पुरवठादाराशिवाय कुठेही पाठवल्या जात नाहीत. टीप: सध्या पुरवठादार व कीची निवड फक्त नोंदवली जाते आणि AI Pembuat Aplikasi स्क्रीनवर दाखवली जाते — अॅप तयार करणे अजूनही फोनवरील स्थानिक AI (इंटरनेटशिवाय) वापरते; ऑनलाइन पुरवठादारांचा वापर नंतर येईल.

कनेक्टर
APK विश्लेषण करून मग पाठवण्यासाठी: मुख्य मेनूमध्ये, सेटिंग्ज गटात, कनेक्टर वर टॅप करा (AI सेटिंग्ज बटणाजवळ). फोनवरून APK फाइल निवडा, IDE त्यातील मजकूर वाचतो (पॅकेजचे नाव, आवृत्ती, क्रियांची यादी), मग प्रणाली शेअर मेनूद्वारे (उदाहरणार्थ WhatsApp किंवा Drive) पाठवण्यासाठी APK पाठवा वर टॅप करा.

भाषा आणि आवाज
अॅपची भाषा बदलण्यासाठी: सेटिंग्ज उघडा, मग अॅपची भाषा, मग भाषा किंवा सिस्टमचे अनुसरण करा निवडा. मुख्य स्क्रीन व बहुतेक स्क्रीन अॅप बंद किंवा पुन्हा सुरू न करताच निवडलेल्या भाषेत लगेच बदलतात; काही स्क्रीन (उदाहरणार्थ Terminal, सहकार्य, AI सेटिंग्ज व की व्यवस्थापन) पुन्हा उघडल्याशिवाय जुनीच भाषा वापरतात. सिस्टमचे अनुसरण करा निवडल्यास भाषा फोनच्या सिस्टम भाषेचे अनुसरण करते.
