Create Aplikasi by Al Kautsar मध्ये आपले स्वागत आहे
Create Aplikasi हे एक Android अॅप बनवणारे अॅप आहे जे लॅपटॉपची गरज न लागता थेट फोनवर चालते. हे अॅप कोणालाही स्वतःचे Android अॅप बनवण्याची परवानगी देते, ज्यामध्ये अॅप बनवायला शिकू लागलेले वापरकर्ते आणि स्क्रीन रीडर वापरकर्ते यांचाही समावेश आहे. हे अॅप वापरण्यासाठीची संपूर्ण मार्गदर्शिका या Tentang Alat स्क्रीनवर उपलब्ध आहे.

हे अॅप काय आहे आणि ते कोणासाठी आहे
Create Aplikasi हे एक Android अॅप बनवण्याचे साधन आहे जे फोनवर चालते. हे अॅप स्वतःचे Android अॅप बनवू इच्छिणाऱ्या कोणासाठीही आहे, ज्यामध्ये नवशिक्या आणि स्क्रीन रीडर वापरकर्त्यांचाही समावेश आहे. हे अॅप एक कोड संपादक, प्रकल्पाची चाचणी करण्यासाठी Jalankan बटण, APK बनवण्यासाठी Bangun बटण, आणि APK वर स्वाक्षरी करण्यासाठी व स्थापित करण्यासाठी मेनू प्रदान करते.

या अॅपचा उद्देश
हे अॅप बनवले गेले आहे जेणेकरून कोणीही सहजपणे, थेट आपल्या फोनवरून स्वतःचे Android अॅप बनवू शकेल. त्याचा देखावा शक्य तितका सोपा बनवला आहे जेणेकरून नवीन वापरकर्तेही लगेच प्रयत्न करू शकतील.

टप्प्याटप्प्याने नवीन प्रकल्प कसा बनवायचा
1. मुख्य मेनूमध्ये Buat Project दाबा.
2. प्रकल्पाचा प्रकार निवडा: HTML, Situs Web, Java, Kotlin, Compose, किंवा Python.
3. अॅपचे नाव भरा, उदाहरण: Garuda Decode.
4. पॅकेजचे नाव (package name) भरा, उदाहरण: com.android.garudadecode. पॅकेजच्या नावात लहान अक्षरे वापरली पाहिजेत आणि त्यात बिंदूने वेगळे केलेले किमान दोन भाग असले पाहिजेत.
5. अॅपची आवृत्ती भरा, उदाहरण: 1.0, आणि संख्येच्या स्वरूपात आवृत्ती कोड भरा, उदाहरण: 1. रिकामे ठेवल्यास, आवृत्ती आपोआप 1.0 आणि आवृत्ती कोड 1 ने भरली जाईल.
6. आवश्यक असल्यास किमान SDK आणि लक्ष्य SDK भरा. रिकामे ठेवल्यास, पूर्वनिर्धारित मूल्ये वापरली जातील. किमान SDK म्हणजे समर्थित सर्वात कमी Android आवृत्ती, उदाहरण: 21 म्हणजे Android 5.0. कमाल लक्ष्य SDK 36 (Android 16) आहे.
7. अॅपच्या परवानग्या निवडण्यासाठी Pilih Izin बटण दाबा, उदाहरण: INTERNET. INTERNET परवानगी पूर्वनिर्धारितपणे आधीच चिन्हांकित केलेली असते. फक्त अॅपला खरोखर आवश्यक असलेल्या परवानग्याच चिन्हांकित करा.
8. इच्छा असल्यास, APK चा आकार लहान होण्यासाठी "Gunakan arsitektur terpisah 64 bit dan 32 bit" चिन्हांकित करा, आणि स्वतः बनवलेला keystore वापरायचा असल्यास "Gunakan tanda tangan pribadi" चिन्हांकित करा.
9. Buat Proyek दाबा. नवीन प्रकल्प Download/project फोल्डरमध्ये जतन होतो आणि लगेच Kelola Project मध्ये दिसतो.

उपलब्ध प्रकल्प प्रकार
• HTML: index.html, style.css, आणि script.js मधून देखावा, WebView द्वारे चालते. थेट फोनवर बनवले जाते.
• Situs Web: index.html, tentang.html, kontak.html, style.css, आणि script.js मधून मेनूसह (Beranda, Tentang, Kontak) वेबसाइट, WebView द्वारे चालते. थेट फोनवर बनवले जाते.
• Java: फोनवर बनवले जाते. MainActivity app/src/main/java/<nama-paket>/MainActivity.java मध्ये असते. देखावा app/src/main/res/layout/activity_main.xml मधून, मजकूर app/src/main/res/values/strings.xml मधून, आणि थीम app/src/main/res/values/styles.xml मधून येते.
• Kotlin: अॅपमध्ये समाविष्ट असलेल्या Kotlin कंपायलरचा वापर करून डिव्हाइसवर (ऑफलाइन) बनवता येते, किंवा GitHub Actions द्वारे बनवता येते. MainActivity app/src/main/java/<nama-paket>/MainActivity.kt मध्ये असते, आणि res फाइल्स Java प्रकल्पासारख्याच असतात. कंपायलरच्या मोठ्या आकारामुळे पहिले Kotlin बिल्ड संथ असते, आणि Kotlin वर्गांचा संदर्भ देणाऱ्या .java फाइल्स अजून बनवता येत नाहीत (.java फाइल्स .kt फाइल्सच्या आधी कंपाइल केल्या जातात).
• Compose: आधुनिक Android अॅप ज्याचा इंटरफेस Jetpack Compose ने बनवला आहे (XML लेआउट नाही). MainActivity app/src/main/java/<nama-paket>/MainActivity.kt मध्ये असते. Compose प्रकल्प GitHub Actions द्वारे (Bangun proyek मेनू, नंतर Bangun online) किंवा Termux मध्ये Gradle ने बनवले जातात, कारण Compose ला Jetpack Compose लायब्ररी आवश्यक असतात ज्या डिव्हाइसवर उपलब्ध नाहीत.
• Python: अॅपचे तर्क Python भाषेत (Chaquopy) app/src/main/python/main.py मध्ये लिहिले जाते, आणि app/src/main/java/<nama-paket>/MainActivity.java मधील होस्ट MainActivity.java द्वारे चालवले जाते. Python प्रकल्प थेट फोनवर बनवता येतात (Chaquopy रनटाइम अॅपमध्ये समाविष्ट आहे) किंवा GitHub Actions द्वारेही बनवता येतात. Python प्रकल्पांसाठी किमान SDK 24 (Android 7.0) आहे.

प्रकल्पाचे आर्किटेक्चर बदला
नवीन प्रकल्प तयार न करता विद्यमान प्रकल्पाच्या आर्किटेक्चर पसंती बदलण्यासाठी: मुख्य मेनूमध्ये «प्रकल्पाचे आर्किटेक्चर बदला» दाबा, नंतर प्रकल्प निवडा आणि «64-बिट APK तयार करा (arm64-v8a)» किंवा «32-बिट APK तयार करा (armeabi-v7a)» चेकबॉक्स बदला; किंवा «प्रोजेक्ट व्यवस्थापित करा» मध्ये प्रकल्पाच्या नावावर दीर्घकाळ दाबा आणि तीच स्क्रीन त्या प्रकल्पासाठी थेट उघडण्यासाठी «आर्किटेक्चर बदला» निवडा. नियम असा आहे: दोन्ही चेकबॉक्स चालू असल्यास, बिल्ड दोन स्वतंत्र APK तयार करते, एक 64-बिट आणि एक 32-बिट; फक्त एक चेकबॉक्स चालू असल्यास, बिल्ड एकच सार्वत्रिक APK तयार करते जे 64-बिट आणि 32-बिट दोन्ही उपकरणांवर चालू राहते. फक्त एका प्रकारासाठी स्वतंत्र APK अद्याप समर्थित नाही, कारण बिल्ड मार्ग फक्त विभाजित किंवा सार्वत्रिक पसंती ओळखतो, परंतु प्रत्येक प्रकाराची पसंती प्रकल्पाच्या आत जतन केलेली राहते जेणेकरून स्क्रीन पुन्हा उघडल्यावर ती हरवणार नाही.

Java, HTML, Situs Web, Kotlin, Compose, आणि Python प्रकल्पांची फाइल रचना
Java, HTML, Situs Web, Kotlin, Compose, आणि Python प्रकल्प सामान्यतः Android प्रकल्पांप्रमाणेच रचलेले असतात. app फोल्डरच्या आत src फोल्डर असते, आणि त्याच्या आत main फोल्डर असते. main फोल्डरच्या आत java फोल्डरच्या शेजारी AndroidManifest.xml असते, res फोल्डर असते ज्यामध्ये layout/activity_main.xml आणि values/strings.xml आणि values/styles.xml असतात, आणि HTML व Situs Web साठी assets फोल्डर असते ज्यामध्ये index.html असते (Situs Web मध्ये tentang.html आणि kontak.html देखील असतात). HTML आणि Situs Web प्रकल्पांची स्वतःची MainActivity देखील app/src/main/java/<nama-paket>/MainActivity.java मध्ये असते, जी WebView मध्ये index.html लोड करते आणि AndroidManifest मध्ये लॉन्चर म्हणून असते. Python प्रकल्पांमध्ये Python कोड app/src/main/python/main.py मध्ये आणि होस्ट MainActivity.java app/src/main/java/<nama-paket>/MainActivity.java मध्ये असते. AndroidManifest.xml, लेआउट, strings, आणि styles संपादकात उघडता व बदलता येतात, MainActivity प्रमाणेच. ज्या जुन्या प्रकल्पांचा मॅनिफेस्ट अजूनही app फोल्डरच्या शेजारी आहे ते देखील बनवता येतात, कारण बनवताना, अॅप आधी app/src/main/ मध्ये AndroidManifest.xml तपासते, नंतर app फोल्डरच्या शेजारी असलेले, आणि शेवटी प्रकल्प डेटा फाइल तपासते.

परवानगीचे नियम (महत्त्वाचे)
प्रकल्प बनवताना चिन्हांकित केलेल्या परवानग्या, प्रकल्पाच्या प्रकारानुसार, फक्त एकाच ठिकाणी नोंदवल्या जातात. Java, HTML, Situs Web, Kotlin, Compose, आणि Python प्रकल्पांसाठी, चिन्हांकित केलेल्या परवानग्या प्रकल्प फोल्डरच्या आत, java फोल्डरच्या शेजारी, app/src/main/ मधील AndroidManifest.xml मध्येच नोंदवल्या जातात. Java, HTML, Situs Web, Kotlin, Compose, आणि Python प्रकल्पांसाठीच्या प्रकल्प डेटा फाइलमध्ये परवानग्यांची यादी नसते. तुम्ही Java निवडून INTERNET आणि CAMERA चिन्हांकित केल्यास, AndroidManifest.xml मध्ये फक्त INTERNET आणि CAMERA च नोंदवले जातील, इतर कोणतीही परवानगी जोडली जाणार नाही. बनवताना, अॅप त्याच ठिकाणाहून परवानग्या वाचते: Java, HTML, Situs Web, Kotlin, Compose, आणि Python प्रकल्पांसाठी app/src/main/ मधील AndroidManifest.xml मधून (नसल्यास, जुन्या प्रकल्पांसाठी app फोल्डरच्या शेजारी असलेल्या AndroidManifest.xml मधून), आणि जुन्या प्रकल्पांसाठी प्रकल्प डेटा फाइलमधून.

संपादक कसा वापरायचा
Kelola Project उघडा, संपादक उघडण्यासाठी प्रकल्पाच्या नावावर टॅप करा. संपादकात, फाइल्स उघडता येतात, कोड लिहिता येतो, आणि बदल जतन करता येतात. Java, HTML, Situs Web, Kotlin, Compose, आणि Python प्रकल्पांसाठी, फाइल्स app/src/main फोल्डरच्या आत रचलेल्या असतात. प्रकल्प शेअर करण्यासाठी, Ekspor ZIP वापरा (खालील विभाग पहा).

प्रकल्प कसा चालवायचा
संपादकात, प्रकल्पाची चाचणी करण्यासाठी Jalankan दाबा. HTML आणि Situs Web प्रकल्पांसाठी, चालवले जाणारे WebView द्वारे index.html असते. एखादी त्रुटी आल्यास, त्रुटी संदेश वाचा, कोड दुरुस्त करा, नंतर पुन्हा चालवा.

APK कसा बनवायचा
संपादकात, Bangun दाबा. बनवण्याचे दोन मार्ग आहेत. पहिला, Bangun di perangkat: इंटरनेटशिवाय थेट फोनवर बनवणे, HTML, Situs Web, Java, Kotlin, आणि Python प्रकल्पांसाठी. दुसरा, GitHub Actions द्वारे Bangun online: इंटरनेटद्वारे GitHub वर बनवणे, आणि सर्व प्रकारच्या प्रकल्पांसाठी वापरता येते. Compose प्रकल्प फक्त दुसऱ्या मार्गाने (Bangun online) किंवा Termux मध्ये Gradle ने बनवता येतात, कारण Compose ला Jetpack Compose लायब्ररी आवश्यक असतात ज्या डिव्हाइसवर उपलब्ध नाहीत. पहिल्या बिल्डचा निकाल अजून स्वाक्षरी केलेला नसतो. त्यानंतर अॅप त्यावर स्वाक्षरी करते: पूर्वनिर्धारित कीने आपोआप, किंवा प्रकल्प बनवताना "Gunakan tanda tangan pribadi" बॉक्स चिन्हांकित केला असल्यास वैयक्तिक स्वाक्षरीने.

APK कसे स्थापित करायचे
APK तयार झाल्यावर, ते स्थापित करण्यासाठी Pasang दाबा. Android 8 आणि त्यावरील आवृत्त्यांमध्ये, हे अॅप Play Store च्या बाहेरून APK स्थापित करते म्हणून, फोन आधी "Izinkan dari sumber ini" मागेल. Pengaturan मध्ये ती परवानगी एकदा सक्षम करा, नंतर अॅपकडे परत या: Pasang पुन्हा दाबण्याची गरज न लागता स्थापना आपोआप सुरू राहील. Pasang बटण दिसत नसल्यास, बिल्ड पूर्ण झाले आहे आणि APK बनवले गेले आहे याची खात्री करा.

अॅपमध्ये स्वाक्षरी कशी करायची
प्रत्येक APK स्थापित करण्यासाठी स्वाक्षरी केलेले असणे आवश्यक आहे. दोन पर्याय उपलब्ध आहेत. पहिला, पूर्वनिर्धारित की: तुम्हाला काहीही करावे न लागता, अॅप आपोआप स्वाक्षरी करते. दुसरा, वैयक्तिक स्वाक्षरी: आधी मुख्य मेनूमधील Buat Keystore मेनूद्वारे एक keystore बनवा, त्याचा पासवर्ड नीट जतन करा, नंतर प्रकल्प बनवताना "Gunakan tanda tangan pribadi" चिन्हांकित करा. Keystore Download/project/signing मध्ये जतन होते.

आवश्यकता
Android 5.0 किंवा त्यापेक्षा नवीन. संग्रहण परवानगी: Android 11 आणि त्यावरील आवृत्त्यांमध्ये सर्व फाइल्सच्या प्रवेशाची परवानगी वापरते, Android 10 आणि त्याखालील आवृत्त्यांमध्ये सामान्य संग्रहण परवानगी (संग्रहण वाचणे/लिहिणे) वापरते कारण Android 10 मध्ये सर्व फाइल्सच्या प्रवेशाची परवानगी नाही. डिव्हाइसवर बनवण्यासाठी ARM प्रोसेसर (32 किंवा 64 बिट) असलेला फोन आवश्यक आहे. GitHub Actions द्वारे ऑनलाइन बनवण्यासाठी इंटरनेट आणि GitHub टोकन आवश्यक आहे. Kotlin प्रकल्प डिव्हाइसवर बनवता येतात, परंतु Kotlin कंपायलरच्या मोठ्या आकारामुळे त्याचे पहिले बिल्ड संथ असते आणि जास्त मेमरी वापरते. Compose प्रकल्प GitHub Actions द्वारे किंवा Termux मध्ये Gradle ने बनवले जातात. Python प्रकल्पांसाठी Android 7.0 किंवा त्यापेक्षा नवीन (किमान SDK 24) आवश्यक आहे आणि परिणामी APK मोठे असते कारण त्यात Python रनटाइम (Chaquopy) आणि त्याची प्रमाणित लायब्ररी असते.

Terminal
मुख्य स्क्रीनवरील Terminal मेनू या अॅपच्या आत एक टर्मिनल उघडते. प्रकल्प फोल्डरमधील मजकूर पाहण्यासाठी ls, फोल्डर बदलण्यासाठी cd, आणि कोड व्यवस्थापित करण्यासाठी git यासारख्या आज्ञा वापरता येतात. आज्ञांचे आउटपुट स्क्रीन रीडरने वाचता येईल अशा मजकुराच्या रूपात दिसते, आणि शेवटचा निकाल ऐकण्यासाठी Bacakan hasil बटण असते. हे टर्मिनल फोनचे सिस्टम शेल वापरते, त्यामुळे nano आणि vim सारखे परस्परसंवादी प्रोग्राम येथे अजून वापरता येत नाहीत.

परवाना (सशुल्क आवृत्ती)
अॅप्स विकण्यासाठी, प्रकल्प बनवताना "Aktifkan Lisensi" चिन्हांकित करा, नंतर तुमचा WhatsApp नंबर भरा. बिल्डचा निकाल असलेले अॅप पहिल्यांदा उघडल्यावर परवाना कोड मागेल: वापरकर्ता त्याचा डिव्हाइस ID पाहतो, तो ID तुमच्या WhatsApp वर पाठवण्यासाठी Kirim ID Perangkat बटण दाबतो, नंतर तुम्ही परवाना कोडने उत्तर देता. परवाना कोड डिव्हाइस ID आणि प्रकल्प पासवर्ड (प्रकल्प डेटा फाइलमधील lisensi_seed) वरून मोजला जातो — तो पासवर्ड नीट जतन करा आणि शेअर करू नका. योग्य कोड टाकल्यानंतर, अॅप उघडते आणि पुन्हा कोड मागत नाही.

HTML आणि Situs Web टेम्पलेट्ससाठी, टेम्पलेट index.html चा मजकूर बदलते, फॉर्ममध्ये टाइप केलेल्या HTML स्क्रिप्टसह.

AI अॅप बिल्डर
AI अॅप बिल्डर स्क्रीनवर हवे असलेले अॅप लिहा किंवा बोलून सांगा, उदाहरणार्थ: «सेव्ह बटण असलेले नोट्स अॅप». अॅप फोनमध्येच कीवर्डचे विश्लेषण करते (इंटरनेटशिवाय, शुल्काशिवाय), मग सर्वात योग्य टेम्पलेटमधून खरे प्रोजेक्ट तयार करते: कॅल्क्युलेटर, नोट्स, कामांची यादी, वेब कॅल्क्युलेटर, प्रोफाइल साइट किंवा काउंटर. तुमच्या वर्णनासाठी अजून योग्य टेम्पलेट नसेल तर अॅप रिकामा प्रोजेक्ट तयार करते आणि ते प्रामाणिकपणे सांगते — समजल्याचे नाटक करत नाही. AI ने तयार केलेले प्रोजेक्ट प्रोजेक्ट व्यवस्थापित करा मध्ये थेट उघडता येते.

बिल्ड करण्यापूर्वी प्रोजेक्ट मित्राला दाखवण्यासाठी: प्रोजेक्ट व्यवस्थापित करा मध्ये प्रोजेक्टचे नाव दीर्घकाळ दाबा, मग मित्राच्या फोनवर पूर्वावलोकन निवडा. अॅप प्रोजेक्टच्या मुख्य फाइल्स (index.html, MainActivity किंवा main.py) आणि सूचना असलेली BACA-SAYA.txt व info.txt असलेले छोटे पूर्वावलोकन पॅकेज तयार करते. पॅकेज ZIP म्हणून WhatsApp किंवा Telegram द्वारे पाठवले जाते. ते मिळवणारा मित्र पूर्वावलोकन लगेच उघडू शकतो: HTML पृष्ठे ब्राउझरमध्ये उघडतात, Java/Kotlin/Python कोड मजकूर म्हणून वाचला जातो.

प्रोजेक्ट मार्केटमध्ये एका टॅपने प्रोजेक्ट फोल्डरमध्ये स्थापित करता येणारे अंगभूत नमुना प्रोजेक्ट आहेत: कॅल्क्युलेटर, नोट्स, कामांची यादी, वेब कॅल्क्युलेटर, प्रोफाइल साइट, काउंटर, डिजिटल घड्याळ आणि वेब क्विझ. ऑनलाइन मार्केट (इंटरनेटवरून नमुने डाउनलोड करणे) अजून उपलब्ध नाही, त्यामुळे या मार्केटमध्ये अॅपमध्ये आधीच असलेले नमुने आहेत. स्थापित केलेला प्रोजेक्ट स्वतः तयार केलेल्या प्रोजेक्टप्रमाणे प्रोजेक्ट व्यवस्थापित करा मध्ये उघडता व बदलता येतो.

थेट सहकार्य
मित्रासोबत प्रोजेक्टवर काम करण्यासाठी: मुख्य मेनूमध्ये सहकार्य उघडा, प्रोजेक्ट निवडा, बदलाची नोंद लिहा (काय बदलले), मग सहकार्यासाठी शेअर करा दाबा. प्रोजेक्ट त्यातील CATATAN.txt फाइलसह ZIP म्हणून पाठवला जातो. तुमचा मित्र त्यावर काम करतो आणि ZIP परत पाठवतो; तुम्ही उत्तर स्वीकारा दाबा, आधी बदलाची नोंद वाचा, मग जुना प्रोजेक्ट ओव्हरराइट करण्यासाठी लागू करा निवडा किंवा मन बदलल्यास रद्द करा निवडा. CATATAN.txt नसलेला ZIP हा सहकार्य पॅकेज नाही — सामान्य प्रोजेक्ट ZIP साठी, प्रोजेक्ट व्यवस्थापित करा मध्ये प्रकल्प आयात करा वापरा.

स्वयंचलित ॲप अनुवादक
अॅपमधील मजकूर दुसऱ्या भाषेत भाषांतरित करण्यासाठी: मुख्य मेनूमध्ये अॅप अनुवादक उघडा, प्रोजेक्ट आणि लक्ष्य भाषा (इंग्रजी, अरबी किंवा जावानी) निवडा, मग भाषांतर करा दाबा. शब्दकोश आधीच फोनमध्ये आहे (इंटरनेटशिवाय, शुल्काशिवाय) आणि त्यात दैनंदिन सामान्य शब्द आहेत; strings.xml, लेआउट आणि कोडमधील मजकूर वाचला जातो मग भाषांतरित केला जातो. निकाल values-भाषा/strings.xml फोल्डरमध्ये लिहिला जातो (प्रोजेक्टमध्ये strings.xml असल्यास) आणि भाषांतर-भाषा.txt अहवाल प्रोजेक्ट फोल्डरमध्ये. शब्दकोशात अजून नसलेले शब्द जसेच्या तसे ठेवले जातात आणि नोंदवले जातात — त्यामुळे कोणते शब्द तुम्हाला स्वतः भाषांतरित करावे लागतील हे तुम्हाला कळते.

कोडशिवाय Game बनवणारा
कोड न लिहिता गेम तयार करण्यासाठी: मुख्य मेनूमध्ये कोडशिवाय Game बनवणारा उघडा, गेमचा प्रकार निवडा (संख्या ओळखा, क्विझ किंवा तारा पकडा), गेमचे नाव, प्रमाण (लेव्हल/प्रश्न/तारे) आणि जिंकण्याचा संदेश भरा, मग गेम बनवा दाबा. गेम खरा प्रोजेक्ट म्हणून तयार केला जातो जो प्रोजेक्ट व्यवस्थापित करा मध्ये थेट चालवता येतो आणि इतर कोणत्याही प्रोजेक्टप्रमाणे APK मध्ये बिल्ड करता येतो.

स्वयंचलित ॲप चाचणी
बिल्ड करण्यापूर्वी प्रोजेक्ट तपासण्यासाठी: प्रोजेक्ट व्यवस्थापित करा मध्ये प्रोजेक्टचे नाव दीर्घकाळ दाबा मग स्वयंचलित चाचणी निवडा. IDE APK न बिल्डता 10 गोष्टी तपासते — आवश्यक फाइल्स आहेत (प्रोजेक्ट डेटा फाइल, मॅनिफेस्ट, मुख्य फाइल, लेआउट, स्ट्रिंग्ज), पॅकेज नाव आणि आवृत्ती, वापरलेल्या परवानग्या, आयकॉन आणि कोड कंसांचे संतुलन. निकाल प्रत्येक आयटमसाठी दाखवला जातो (पास/फेल संदेशासह) आणि Jieshuo द्वारे मोठ्याने वाचला जातो. आधी फेल झालेल्या सर्व गोष्टी दुरुस्त करा, मग प्रकल्प बनवा दाबा.

AI Pemeriksa Kode
अनेकदा समस्या निर्माण करणाऱ्या पॅटर्नसाठी प्रोजेक्ट कोड तपासण्यासाठी: मुख्य मेनूमध्ये कोड तपासा उघडा, प्रोजेक्ट निवडा, मग कोड तपासा दाबा. तपासक फोनमध्ये चालतो (इंटरनेटशिवाय) आणि न वापरलेले व्हेरिएबल्स, रिकामी फंक्शन्स, स्पष्टपणे अंतहीन लूप्स, कोडमध्ये थेट लिहिलेला मजकूर (strings.xml मध्ये असणे चांगले), धोकादायक परवानग्या आणि API, TODO/FIXME चिन्हे आणि डायनॅमिक अंमलबजावणी शोधतो. प्रत्येक शोधात फाइलचे नाव, ओळ क्रमांक आणि दुरुस्तीची सूचना असते. हा तपासक पॅटर्नवर आधारित आहे, खरा AI नाही — पॅटर्नचे पालन न करणाऱ्या समस्या तरीही सुटू शकतात.

परस्परसंवादी शिकण्याचा मोड
टप्प्याटप्प्याने अॅप तयार करायला शिकण्यासाठी: मुख्य मेनूमध्ये शिकण्याचा मोड उघडा. 5 धडे आहेत: पहिला प्रोजेक्ट तयार करणे, बटण जोडणे, रंग बदलणे, आवाज जोडणे आणि APK बिल्ड करणे. स्पष्टीकरण आणि सराव कार्य वाचण्यासाठी एक धडा टॅप करा, कार्य करा, मग काम तपासा दाबा — IDE कार्य खरोखर झाले आहे का ते तपासते (तुमच्या फोनवरील प्रोजेक्ट आणि APK स्कॅन करून). पास झालेले धडे पूर्ण म्हणून चिन्हांकित केले जातात आणि जतन केले जातात.

क्लाउड सिंक
प्रोजेक्टचा क्लाउड बॅकअप तयार करण्यासाठी: मुख्य मेनूमध्ये क्लाउड सिंक उघडा. स्थानिक बॅकअप प्रोजेक्ट ZIP वेळेच्या शिक्क्यासह Download/cloud फोल्डरमध्ये जतन करते आणि बॅकअप यादीतून कधीही पुनर्संचयित करता येते. GitHub बॅकअप प्रोजेक्ट ZIP तुमच्या खाजगी रेपोमध्ये अपलोड करते (GitHub सेटिंग्जमधील टोकन वापरून) आणि पुन्हा डाउनलोड करता येते. हा मॅन्युअल बॅकअप आणि पुनर्संचय आहे — पूर्ण स्वयंचलित द्विमार्गी सिंकसाठी सर्व्हर आवश्यक आहे, त्यामुळे अजून उपलब्ध नाही.

स्वयंचलित बॅकएंड बिल्डर
सर्व्हर कोड न लिहिता बॅकएंड तयार करण्यासाठी: मुख्य मेनूमध्ये बॅकएंड बिल्डर उघडा, बॅकएंडचा प्रकार निवडा (नोट्स, कामांची यादी किंवा संदेश फलक), प्रोजेक्टचे नाव भरा, मग Backend बनवा दाबा. IDE फॉर्म पृष्ठ आणि फोनच्या स्थानिक स्टोरेजमध्ये (localStorage) जतन केलेल्या डेटा यादीसह खरा HTML प्रोजेक्ट तयार करते — डेटा जतन केला जातो आणि अॅप चालवल्यावर पुन्हा वाचता येतो. हा बॅकएंड एका फोनवर चालतो; इंटरनेट सर्व्हर नसल्यामुळे दोन फोन अजून समान डेटा शेअर करू शकत नाहीत.

स्वयंचलित थीम डिझायनर
प्रोजेक्टला रंग थीम देण्यासाठी: मुख्य मेनूमध्ये थीम डिझायनर उघडा, प्रोजेक्ट आणि थीम निवडा (उजळ, गडद, निळा, हिरवा, लाल किंवा जांभळा). पूर्वावलोकन थीमचे सहा रंग दाखवते (प्राथमिक, गडद प्राथमिक, अॅक्सेंट, पार्श्वभूमी, मजकूर, दुय्यम मजकूर) आणि Jieshuo द्वारे मोठ्याने वाचले जाते. थीम लागू करा दाबा — IDE colors.xml आणि styles.xml (app_theme शैली) प्रोजेक्टमध्ये लिहिते, जे प्रोजेक्ट चालवल्यावर किंवा बिल्ड केल्यावर थेट वापरले जाते.

अॅनिमेशन मेकर
प्रोजेक्टला अॅनिमेशन देण्यासाठी: मुख्य मेनूमध्ये अॅनिमेशन मेकर उघडा, प्रोजेक्ट, अॅनिमेशनचा प्रकार (फेड, स्लाइड, फिरवणे, बाउन्स किंवा पल्स), कालावधी (100 ते 10000 मिलिसेकंद) आणि लक्ष्य (बटण, मजकूर किंवा प्रतिमा) निवडा, मग ॲनिमेशन बनवा दाबा. IDE खरी अॅनिमेशन फाइल लिहिते (Java/Kotlin/Compose प्रोजेक्टसाठी res/anim/anim_<प्रकार>.xml, किंवा HTML/वेबसाइट प्रोजेक्टसाठी animasi.css) स्क्रीनवर दाखवलेल्या वापराच्या नमुना कोडसह.

अॅक्शन रेकॉर्डर
काम आपोआप पुन्हा करण्यासाठी: IDE केलेल्या क्रिया नोंदवते (प्रोजेक्ट उघडणे, चालवणे, बिल्ड करणे, निर्यात करणे, बॅकअप घेणे, प्रोजेक्ट तयार करणे, फाइल जतन करणे). मुख्य मेनूमध्ये अॅक्शन रेकॉर्डर उघडा, नोंदवलेल्या क्रियांची यादी त्यांच्या योजनेसह पहा, मग पुन्हा चालवा दाबा — IDE ज्या क्रिया स्वयंचलित करता येतात त्या पुन्हा चालवते (बॅकअप आणि प्रोजेक्ट तयार करणे जागेवरच चालते; चालवणे, बिल्ड करणे आणि निर्यात करणे त्यांची मुख्य स्क्रीन उघडतात; उघडणे आणि जतन करणे एडिटर उघडतात). ज्या क्रिया स्वयंचलित करता येत नाहीत त्या वगळल्या जातात आणि शेवटी नोंदवल्या जातात.

ऑटो सुरक्षा
प्रोजेक्टची सुरक्षा तपासण्यासाठी: मुख्य मेनूमध्ये ऑटो सुरक्षा उघडा, प्रोजेक्ट निवडा, मग सुरक्षा तपासा दाबा. IDE 8 गोष्टी स्थानिक पातळीवर तपासते (इंटरनेटशिवाय): धोकादायक परवानग्या (स्थान, SMS, कॉल, कॅमेरा, मायक्रोफोन, संपर्क), HTTP द्वारे डेटा पाठवणे, SMS पाठवणे, बाहेर जाणारे कॉल, कोडमध्ये थेट लिहिलेला पासवर्ड किंवा की, संरक्षण नसलेले WebView, परवानगीशिवाय निर्यात केलेला घटक आणि एन्क्रिप्शन नसलेला http पत्ता. प्रत्येक शोधाला दुरुस्तीच्या सूचनेसह सुरक्षित, इशारा किंवा धोका पातळी दिली जाते आणि सारांश Jieshuo द्वारे मोठ्याने वाचला जातो.

AI ऑफलाइन
इंटरनेटशिवाय मजकूर आणि कोड सहाय्य साधने वापरण्यासाठी: मुख्य मेनूमध्ये AI ऑफलाइन उघडा. 4 साधने आहेत: मजकूर दुरुस्त करा (मोठी अक्षरे, विरामचिन्हे आणि दुहेरी जागा), मजकूर सारांश करा (3 सर्वात महत्त्वाची वाक्ये घेते), ॲपचे नाव बनवा (लिहिलेल्या वर्णनावरून) आणि व्हेरिएबल नाव सुचवा (प्रोजेक्टमध्ये 1-2 अक्षरांची व्हेरिएबल नावे शोधते). हे फोनमधील साधे नियम आहेत, खरे AI मॉडेल नाही. मजकूर दुरुस्तीचा निकाल लागू करा बटणाने प्रोजेक्टच्या strings.xml वर लागू करता येतो.

विजेट आणि वॉलपेपर निर्माता
होम स्क्रीन विजेट तयार करण्यासाठी: मुख्य मेनूमध्ये विजेट्स आणि वॉलपेपर उघडा, प्रोजेक्ट निवडा, विजेट मजकूर भरा, मग Widget बनवा दाबा. IDE WidgetSaya.java, विजेट लेआउट, विजेट माहिती लिहिते आणि प्रोजेक्टच्या AndroidManifest.xml मध्ये रिसीव्हर जोडते — प्रोजेक्ट बिल्ड करा, मग फोनच्या होम स्क्रीनवरून विजेट स्थापित करा. वॉलपेपरसाठी: लेखन आणि पार्श्वभूमी व मजकूर रंग भरा, पूर्वावलोकन तयार करा, मग ते PNG म्हणून Download फोल्डरमध्ये जतन करा किंवा थेट फोन वॉलपेपर म्हणून सेट करा.

सोशल मीडिया एकत्रीकरण
अॅपमध्ये शेअर बटणे जोडण्यासाठी: मुख्य मेनूमध्ये सोशल मीडिया एकत्रीकरण उघडा, प्रोजेक्ट निवडा, मग WhatsApp, Facebook किंवा Telegram वर शेअरिंग जोडा (किंवा तिन्ही एकत्र). IDE खरा शेअरिंग कोड प्रोजेक्टच्या मुख्य फाइलमध्ये (MainActivity किंवा index.html) लिहिते. शेअर चाचणी बटण IDE मधून नमुना मजकुरासह शेअरिंग चूझर उघडते, जेणेकरून अॅप बिल्ड करण्यापूर्वी प्रवाह जाणवू शकेल.

प्रतिमेवरून अॅप
प्रतिमेवरून गॅलरी अॅप तयार करण्यासाठी: मुख्य मेनूमध्ये प्रतिमेवरून अॅप उघडा, गॅलरीतून प्रतिमा निवडा. IDE प्रतिमेचा आकार आणि प्रमुख रंग विश्लेषण करते, मग खरा गॅलरी अॅप प्रोजेक्ट तयार करते: प्रतिमा प्रोजेक्टच्या assets मध्ये कॉपी केली जाते, थीम रंग प्रतिमेच्या प्रमुख रंगावरून घेतला जातो आणि अॅपचे नाव प्रतिमा फाइलच्या नावावरून घेतले जाते. ती गॅलरी अॅप चालवण्यासाठी किंवा बिल्ड करण्यासाठी प्रोजेक्ट व्यवस्थापित करा उघडा.

परस्परसंवादी टर्मिनल (VT पार्सर)
Terminal मध्ये परस्परसंवादी प्रोग्राम वापरण्यासाठी: मुख्य मेनूमध्ये Terminal उघडा, मग nano, vim, top किंवा htop चालवा. Terminal आता VT पार्सर वापरते (24 ओळी x 80 स्तंभ ग्रिड स्क्रीन) जेणेकरून ते प्रोग्राम योग्यरित्या दिसतात — कर्सर हलतो, ओळी पुसल्या जातात आणि स्क्रीन खऱ्या टर्मिनलप्रमाणे बदलते. परस्परसंवादी प्रोग्राम नियंत्रित करण्यासाठी विशेष Tab, वरचा बाण, खालचा बाण आणि Esc बटणे आहेत. आउटपुट अजूनही Jieshuo वाचू शकणारा मजकूर आहे; शेवटची ओळ ऐकण्यासाठी स्क्रीन वाचा दाबा.

Terminal Exec (ॲप बायनरी)
Terminal मधून अॅप फोल्डरमधील बायनरी (उदा. aapt2, ECJ, D8) चालवण्यासाठी: आज्ञा नेहमीप्रमाणे टाइप करा. IDE libkautsarexec.so वापरते जेणेकरून अॅप फोल्डरमधील बायनरी Android 10 आणि त्यावरील आवृत्त्यांवर चालवता येतील. या फोनवर बायनरी exec मार्ग चालतो का ते तपासण्यासाठी Terminal मध्ये Exec चाचणी दाबा — निकाल जसा आहे तसा दाखवला जातो. exec सिस्टीमने ब्लॉक केल्यास, सिस्टीम आज्ञा आणि शेल स्क्रिप्ट अजूनही चालतात; बायनरी प्रकल्प बनवा मेनूमधून चालवा.

Terminal जिवंत ठेवा (KeepAlive)
दुसऱ्या स्क्रीनवर जाताना shell चालू ठेवण्यासाठी: Terminal उघडा, आज्ञा चालवा, मग मागे दाबा किंवा दुसऱ्या स्क्रीनवर जा — shell मरत नाही आणि Terminal अधिसूचना दिसत राहते जेणेकरून तुम्ही एका टॅपने परत येऊ शकता. चालवलेल्या आज्ञा इतिहासात जतन केल्या जातात (इतिहास बटण किंवा आज्ञा क्षेत्रातील वर/खालील बाण) आणि वारंवार वापरल्या जाणाऱ्या आज्ञा आवडते म्हणून जतन करता येतात (आवडते बटण). पूर्ण झाल्यावर Shell बंद करा दाबा जेणेकरून shell खरोखर संपेल. प्रोजेक्ट मेनू आणि एडिटर मेनूमध्ये Terminal मध्ये बनवा बटणही आहे: Terminal प्रोजेक्ट फोल्डरमध्ये बिल्ड आज्ञा आधीच भरलेली असताना उघडते.

Terminal साधने स्थापित करा (चाचणी)
अजून चाचणीत असलेले वैशिष्ट्य: Terminal मध्ये विकसकाच्या alat-termux रेपो (github.com/syudat/alat-termux) मधील आरशातून Termux वातावरण स्थापित करण्यासाठी Terminal साधने स्थापित करा बटण आहे, हे अधिकृत Termux रिलीजमधून घेणाऱ्या Termux स्थापित करा बटणाव्यतिरिक्त आणखी एक मार्ग आहे. आरशाची सामग्री अधिकृत रिलीजसारखीच आहे आणि स्थापनेदरम्यान SHA-256 ने तपासली जाते. वातावरण स्थापित झाल्यावर, pkg update आणि pkg install आज्ञा वापरता येतात आणि रेपोमधील अतिरिक्त साधनेही टर्मिनलमध्ये स्थापित होतात: वातावरण माहिती पाहण्यासाठी info-terminal, कॅश साफ करण्यासाठी bersih-terminal आणि प्रोजेक्ट फोल्डर तारीख असलेल्या एका tar.gz फाइलमध्ये संग्रहित करण्यासाठी cadangkan-proyek. त्यानंतर अॅप मूलभूत Linux पॅकेजेस (git, python, curl, wget, nano, openssh, zip, unzip) आणि स्वाक्षरीसह APK बिल्ड साधने (openjdk-21, kotlin, gradle, ecj, aapt2, d8, apksigner, clang, cmake, ninja, make) अधिकृत Termux रेपोमधून आपोआप स्थापित करते, जेणेकरून टर्मिनल लगेच अॅप तयार करण्यासाठी तयार होते. मोठे पॅकेज डाउनलोड करण्यास (शेकडो MB) बराच वेळ लागू शकतो. स्थापना चालू असताना, प्रगती आणि आज्ञा आउटपुट Terminal मुख्य स्क्रीनवर दिसतात आणि अंतिम निकाल स्क्रीन रीडर मोठ्याने वाचतो. पॅकेज स्थापना अजून पूर्ण झाली नसेल तर पुढे चालू ठेवण्यासाठी Terminal साधने स्थापित करा पुन्हा दाबा.

पूर्ण आवाज मोड
IDE पूर्णपणे आवाजाने नियंत्रित करण्यासाठी: मुख्य मेनूमध्ये पूर्ण आवाज मोड उघडा, मग ऐकणे सुरू करा दाबा. IDE सतत ऐकते — प्रत्येक आज्ञेसाठी बटण दाबण्याची गरज नाही — आज्ञा चालवते आणि आवाजाने उत्तर देते. 26 आज्ञा आहेत: तयार करा, बिल्ड करा, उघडा, चालवा, यादी करा, शोधा, हटवा, चाचणी करा, तपासा, निर्यात करा, बॅकअप घ्या, शेअर करा, आयकॉन तयार करा, भाषांतर करा, टर्मिनलमध्ये बनवा, स्क्रीन वाचा, सर्व स्क्रीन उघडा (सुरक्षा, AI ऑफलाइन, विजेट, सोशल मीडिया, गेम, शिकणे, क्लाउड, बॅकएंड, थीम, अॅनिमेशन, रेकॉर्डर यांसह), मागे, बंद करा आणि मदत. मोड सक्रिय ठेवल्यास, ही स्क्रीन पुन्हा उघडल्यावर ऐकणे आपोआप सुरू राहते. हा मोड बंद करण्यासाठी ऐकणे थांबवा दाबा. फोनमध्ये आवाज ओळख सेवा नसल्यास, आज्ञा मजकूर चौकटीत लिहिता येतात.

कोड अनुवादक
इंटरनेटशिवाय भाषांमध्ये कोड भाषांतरित करण्यासाठी: मुख्य मेनूमध्ये कोड अनुवादक उघडा, प्रोजेक्ट निवडा, स्रोत फाइल (.java/.kt) निवडा, मग दिशा निवडा: Java ते Kotlin. भाषांतर करा दाबा — निकाल भाषांतरित करता न येणाऱ्या ओळींच्या अहवालासह दाखवला जातो (त्या ओळी जशाच्या तशा ठेवल्या जातात आणि चिन्हांकित केल्या जातात). त्याच फोल्डरमध्ये नवीन फाइल (नाव-भाषांतर.java/.kt) लिहिण्यासाठी परिणाम जतन करा दाबा; मूळ फाइल कधीही ओव्हरराइट होत नाही. हा पॅटर्न नियम अनुवादक आहे, कंपाइलर नाही — वापरण्यापूर्वी नेहमी निकाल तपासा.

अॅपमध्ये Git
Termux शिवाय IDE मध्ये Git वापरण्यासाठी: मुख्य मेनूमध्ये अॅपमध्ये Git उघडा, प्रोजेक्ट निवडा, मग त्या प्रोजेक्टमध्ये स्थानिक रेपो (.git) तयार करण्यासाठी Git Repo बनवा दाबा. शेवटच्या commit च्या तुलनेत नवीन, बदललेल्या किंवा हटवलेल्या फाइल्स पाहण्यासाठी स्थिती तपासा दाबा; commit संदेश भरा मग प्रोजेक्टचा स्नॅपशॉट जतन करण्यासाठी Commit दाबा; commit इतिहास पाहण्यासाठी Commit Log पहा दाबा. GitHub वर Push आणि GitHub वरून Pull GitHub टोकनद्वारे स्नॅपशॉट वापरतात (pembuat-aplikasi-build रेपो) — git प्रोटोकॉल नाही. Clone, Push (सिस्टीम git) आणि Pull (सिस्टीम git) फक्त git बायनरी फोनवर स्थापित असल्यास चालतात (सहसा नसते). हे पूर्ण git नाही: merge, branch किंवा diff नाही — प्रत्येक commit प्रोजेक्टचा पूर्ण ZIP स्नॅपशॉट जतन करते.

जाहिरात मेकर
बिल्ड केलेल्या अॅपमध्ये जाहिराती जोडण्यासाठी: मुख्य मेनूमध्ये जाहिरात मेकर उघडा, प्रोजेक्ट, प्रदाता (AdMob, Unity Ads किंवा AppLovin) आणि जाहिरात प्रकार (बॅनर, इंटरस्टिशियल किंवा रिवॉर्डेड) निवडा. आधीच असल्यास जाहिरात युनिट ID भरा — रिकामे म्हणजे चाचणी ID वापरणे (AdMob Google ची अधिकृत चाचणी ID वापरते; Unity नमुना Game ID वापरते; AppLovin रिकामी जागा वापरते). Java आणि Kotlin कोड आणि मार्गदर्शक पाहण्यासाठी जाहिरात कोड बनवा दाबा; सर्व काही प्रोजेक्टमधील जाहिरात-<प्रदाता>-<प्रकार>.txt फाइलमध्ये लिहिण्यासाठी प्रकल्पावर जतन करा दाबा. हा कोड टेम्पलेट + मार्गदर्शक आहे, जाहिरात SDK नाही — SDK IDE मध्ये समाविष्ट नाही; प्रदाता खाते तयार केल्यावर, जाहिरात युनिट तयार केल्यावर, स्वतःचा युनिट ID चिकटवल्यावर आणि प्रोजेक्टच्या build.gradle मध्ये SDK अवलंबित्व जोडल्यावरच खऱ्या जाहिराती दिसतात.

मुलांचा मोड
मुलासोबत IDE वापरण्यासाठी: मुख्य मेनूमध्ये मुलांचा मोड उघडा. स्क्रीन मोठ्या बटणांसह सोपी केली आहे आणि फक्त 4 सुरक्षित क्रिया आहेत: प्रकल्प तयार करा (सुरक्षित टेम्पलेटमधून: कॅल्क्युलेटर, संख्या ओळखा, क्विझ, तारा पकडा), प्रकल्प उघडा, चालवा आणि शिकण्याचा मोड. या स्क्रीनवर हटवा, निर्यात करा, बॅकअप किंवा टोकन सेटिंग्ज बटण नाही. पहिल्यांदा प्रवेश करताना 4 अंकी PIN तयार करा — तो PIN पालक Mode Anak मधून बाहेर पडण्यासाठी वापरतात (Mode Anak मधून बाहेर पडा बटण किंवा मागे बटण). हा PIN लहान मुलांसाठी हलके संरक्षण आहे, खरी सुरक्षा नाही.

Wear OS आणि TV ॲप बनवणारा
घड्याळ अॅप (Wear OS) किंवा TV अॅप (Android TV) तयार करण्यासाठी: मुख्य मेनूमध्ये Wear OS & TV उघडा, लक्ष्य निवडा (Wear OS, Android TV किंवा दोन्ही). प्रोजेक्टचे नाव भरा मग नवीन Wear/TV प्रकल्प बनवा दाबा — IDE Java प्रोजेक्ट तयार करते मग ते समायोजित करते — किंवा आधीच असलेला प्रोजेक्ट निवडा मग या प्रकल्पावर लागू करा दाबा. समायोजने: मॅनिफेस्टमध्ये uses-feature, TV साठी LEANBACK_LAUNCHER श्रेणी + बॅनर आणि समायोजित activity_main.xml लेआउट (Wear: लहान स्क्रीन; TV: D-pad साठी योग्य मोठी स्क्रीन). संपूर्ण स्पष्टीकरण प्रोजेक्टमध्ये wear-tv.txt मध्ये लिहिले जाते. हे प्रोजेक्ट टेम्पलेट आहे — बिल्ड + चाचणीसाठी अजूनही Wear OS किंवा Android TV डिव्हाइस/एम्युलेटर आवश्यक आहे; TV बॅनर (banner.png 320x180) आपोआप तयार होत नाही, ते स्वतः जोडावे लागेल (उदाहरणार्थ आयकॉन मेकरद्वारे).

प्रोजेक्ट नकाशा
प्रोजेक्टची रचना पाहण्यासाठी: मुख्य मेनूमध्ये प्रोजेक्ट नकाशा उघडा, प्रोजेक्ट निवडा, मग नकाशा दाखवा दाबा — IDE फोल्डर आणि फाइल्सची यादी त्यांच्या आकारांसह, एकूण आकार, फाइल प्रकारानुसार आकार आणि महत्त्वाच्या फाइल्स (मुख्य फाइल, मॅनिफेस्ट, लेआउट, स्ट्रिंग्ज, आयकॉन, वेब पृष्ठ) दाखवते. तोच नकाशा प्रोजेक्टच्या मुळात लिहिण्यासाठी peta-proyek.txt जतन करा दाबा. bin/ फोल्डर (बिल्ड निकाल) आणि .git/ फोल्डर (स्थानिक रेपो) नकाशात समाविष्ट नाहीत कारण त्यांची सामग्री पुन्हा तयार करता येते.

APK आकार कॅल्क्युलेटर
बिल्ड करण्यापूर्वी बिल्ड केलेल्या APK चा आकार अंदाज लावण्यासाठी: मुख्य मेनूमध्ये APK आकार कॅल्क्युलेटर उघडा, प्रोजेक्ट निवडा, मग अंदाज मोजा दाबा. IDE श्रेणीनुसार तपशील दाखवते (कोड/DEX, संसाधने, अॅसेट्स, नेटिव्ह लायब्ररी, मॅनिफेस्ट + resources.arsc, ओव्हरहेड), एकूण अंदाज, 5 सर्वात मोठ्या फाइल्स आणि लहान करण्याच्या सूचना (उदाहरणार्थ मोठ्या प्रतिमा रिझोल्यूशनमध्ये लहान केल्या जातात, मोठे आवाज कालावधीत कापले जातात). हा अंदाज आहे, अचूक आकार नाही — खरा आकार aapt2 संपीडन, न वापरलेला कोड काढणे (R8) आणि बिल्ड निकाल संसाधनांमुळे वेगळा असू शकतो.

APK विश्लेषक
तयार APK ची सामग्री वाचण्यासाठी (Android Studio मधील APK विश्लेषकाप्रमाणे): मुख्य मेनूमध्ये APK विश्लेषक उघडा, प्रोजेक्ट निवडा, मग बिल्ड निकालाच्या APK चे विश्लेषण दाबा. IDE त्या प्रोजेक्टच्या bin फोल्डरमधील नवीनतम APK वाचते आणि पॅकेज नाव, आवृत्ती, किमान आणि लक्ष्य SDK, वापरलेल्या परवानग्यांची यादी, dex फाइल्सची संख्या, भागानुसार आकार तपशील (प्रोग्राम कोड, संसाधने, अॅसेट्स, नेटिव्ह लायब्ररी, स्वाक्षरी) आणि 10 सर्वात मोठ्या नोंदी नोंदवते. APK कोणता भाग मोठा करतो आणि बिल्ड केलेले अॅप कोणत्या परवानग्या वापरते हे जाणून घेण्यासाठी हे उपयुक्त आहे.

स्क्रीन आकार पूर्वावलोकन
अनेक स्क्रीन आकारांवर प्रोजेक्टचे स्वरूप एकाच वेळी तपासण्यासाठी (Android Studio प्रमाणे): मुख्य मेनूमध्ये स्क्रीन आकार पूर्वावलोकन उघडा, प्रोजेक्ट निवडा, मग स्क्रीन आकार तपासा दाबा. IDE प्रोजेक्टचे सर्व लेआउट वाचते आणि रुंदी स्थिर लिहिलेली (उदाहरणार्थ 400dp) आणि 320, 360, 411 किंवा 480 dp स्क्रीन रुंदीपेक्षा जास्त असलेले घटक नोंदवते, कारण लहान स्क्रीन असलेल्या फोनवर असा घटक झाकला जाऊ शकतो किंवा बाहेर पडू शकतो. match_parent किंवा wrap_content रुंदी असलेले घटक स्क्रीननुसार आपोआप समायोजित होतात आणि तपासण्याची गरज नाही.

संसाधन व्यवस्थापक
प्रोजेक्टची सर्व संसाधने एकाच ठिकाणी पाहण्यासाठी आणि व्यवस्थापित करण्यासाठी (Android Studio मधील संसाधन व्यवस्थापकाप्रमाणे): मुख्य मेनूमध्ये संसाधन व्यवस्थापक उघडा, प्रोजेक्ट निवडा, मग संसाधने पहा दाबा. IDE श्रेणीनुसार फाइल्सची संख्या आणि आकार (drawable, layout, values, mipmap आणि इतर), strings.xml, colors.xml आणि styles.xml ची सामग्री नोंदवते. त्याच स्क्रीनवरून, नाव आणि मूल्य भरून strings.xml मध्ये नवीन स्ट्रिंग आणि colors.xml मध्ये नवीन रंग जोडता येतो — नाव तपासले जाते आणि नक्कल नाकारल्या जातात, जेणेकरून XML फाइल खराब होणार नाही.

हलका कार्यप्रदर्शन मॉनिटर
चालू असलेल्या अॅपच्या RAM आणि प्रोसेसर वापरावर लक्ष ठेवण्यासाठी (Android Studio मधील Profiler प्रमाणे, हलकी आवृत्ती): मुख्य मेनूमध्ये हलका कार्यप्रदर्शन मॉनिटर उघडा, आधी तपासायचे अॅप चालवा (उदाहरणार्थ प्रयत्न केले जात असलेले बिल्ड केलेले अॅप), त्याचे पॅकेज नाव भरा — किंवा प्रोजेक्ट निवडा मग प्रकल्पातून पॅकेज नाव भरा दाबा — मग तपासणी सुरू करा दाबा. दर 2 सेकंदांनी IDE त्या अॅपची RAM (PSS) आणि CPU फोनच्या मोकळ्या RAM सह नोंदवते; सरासरी आणि शिखराचा सारांश पाहण्यासाठी थांबवा दाबा. अतिरिक्त परवानगी नाही. Android च्या नवीन आवृत्त्यांमध्ये दुसऱ्या अॅपचा प्रोसेसर वाचण्याचा प्रवेश सिस्टीमद्वारे मर्यादित आहे, त्यामुळे CPU वाचता आला नाही तर अहवाल ते जसे आहे तसे सांगतो आणि RAM तपासणी सुरू राहते.

अ‍ॅक्सेसिबिलिटी ऑडिट
प्रकाशनाआधी एखाद्या प्रकल्पाचे लेआउट स्क्रीन रीडरसाठी (TalkBack/Jieshuo) अनुकूल आहे का हे तपासण्यासाठी: मुख्य मेनूमध्ये अ‍ॅक्सेसिबिलिटी ऑडिट उघडा, प्रकल्प निवडा, मग लेआउट यादी लोड करा वर टॅप करून लेआउट फाइल निवडा. IDE ती XML फाइल वाचतो आणि लेबल नसलेली बटणे त्यांच्या ओळ क्रमांकांसह, वारंवार वापरलेली लेबले आणि एकमेकांना झाकणारे घटक यांचा अहवाल देतो, मग Jieshuo मोठ्याने वाचतो तसा फोकस क्रमाचा उतारा तयार करतो. एखाद्या बटणाला लेबल नसेल तर त्याचे लेबल भरा मग लेबल आपोआप घाला वर टॅप करा — लेबल contentDescription म्हणून लेआउट फाइलमध्ये लिहिले जाते. ही तपासणी फक्त लेआउट XML वाचते; Compose दृश्ये व तयार APK अद्याप स्कॅन केले जात नाहीत.

क्रॅश शवविच्छेदन
अद्वितीय ID असलेल्या क्रॅश लॉगमधून अॅप स्वतः का बंद होते हे जाणून घेण्यासाठी: मुख्य मेनूमध्ये «क्रॅश शवविच्छेदन» उघडा, लॉग यादीतून क्रॅश ID निवडा, नंतर «तपासा» दाबा. IDE लॉगमधील वर्ग आणि ओळ क्रमांक प्रकल्प स्रोताशी जुळवते आणि कारण इंडोनेशियनमध्ये स्पष्ट करते (उदाहरणार्थ रिकामा संदर्भ, अद्याप न मागितलेली परवानगी, किंवा JSON त्रुटी), कोड पॅच सूचनेसह. स्रोत ओळ क्रॅश झाला तेव्हा होती तशीच अजूनही असल्यासच «दुरुस्ती लागू करा» दाबा; ती बदलली असल्यास, पॅच नाकारला जातो आणि IDE तुम्हाला स्वतः तपासण्यास सांगते. तयार केलेल्या अॅपच्या क्रॅशसाठी, «प्रकल्पात क्रॅश पकडणारा घाला» दाबा, नंतर APK नेहमीप्रमाणे तयार करा: ते तयार केलेले अॅप स्वतःचे क्रॅश पकडते आणि त्याचा लॉग फोनवर लिहिते, आणि तो लॉग «तयार केलेल्या अ‍ॅपचा क्रॅश लॉग शोधा» बटणाने सापडू शकतो. प्रामाणिक मर्यादा: Android 11 आणि वरील सार्वजनिक Download फोल्डरमध्ये लॉग कॉपी करणे सर्व फायलींमध्ये प्रवेश परवानगीशिवाय अयशस्वी होऊ शकते.

आंतर-प्रतिमान ट्रान्सपायलर
साधा Java कोड Kotlin मध्ये, किंवा साधा XML लेआउट Compose कोडमध्ये बदलण्यासाठी: मुख्य मेनूमध्ये आंतर-प्रतिमान ट्रान्सपायलर उघडा, प्रकल्प व फाइल निवडा, मग पूर्वावलोकन वर टॅप करा. IDE रूपांतरणाचा निकाल मजकूर म्हणून दाखवतो — आधी तो तपासा, कारण ज्या ओळी तो ओळखत नाही त्या जशाच्या तशा राहतात आणि Java मधील static हा शब्द Kotlin मध्ये काढला जातो (वापरण्याआधी त्याचा अर्थ तपासा). XML ते Compose रूपांतरण फक्त मजकूर, इशारे व दिशा बदलते — आकार, रंग व इतर गुणधर्म अद्याप समाविष्ट नाहीत. निकाल बरोबर असेल तर लक्ष्य फाइल लिहिण्यासाठी फाइलवर लागू करा वर टॅप करा; स्रोत फाइल बदलत नाही. फक्त सुरक्षित, सामान्य नमुने रूपांतरित केले जातात.

स्थानिक सूक्ष्म सर्व्हर
इंटरनेटशिवाय सर्व्हरची आवश्यकता असलेले अॅप चाचणीसाठी: मुख्य मेनूमध्ये «स्थानिक सूक्ष्म सर्व्हर» उघडा, मार्ग व्याख्या लिहा (उदाहरणार्थ GET /halo नंतर त्याचे JSON उत्तर), नंतर «सर्व्हर सुरू करा» दाबा. IDE त्याच फोनवर लहान HTTP सर्व्हर चालवते (फक्त HTTP, TLS शिवाय, त्याच Wi-Fi नेटवर्कसाठी) आणि प्रत्येक विनंती आणि उत्तर स्क्रीनवर नोंदवते. मार्ग {nama} सारखे पॅरामीटर आणि साधी API की वापरू शकतात. सर्व्हर तयार केलेल्या APK मध्येही पॅक केला जाऊ शकतो: «सर्व्हर प्रकल्पात पॅक करा» दाबा, आणि सर्व्हर स्रोत, मालमत्ता आणि मेनिफेस्ट प्रकल्पात घातले जातात, त्यामुळे तयार केलेले अॅप चालू असताना स्वतः सर्व्हर बनते. IDE मधील सर्व्हर त्याची स्क्रीन बंद झाल्यावर थांबतो.

सुरक्षा ऑडिटर
प्रकाशनापूर्वी प्रकल्प कोडमध्ये सुरक्षा अंतर तपासण्यासाठी: मुख्य मेनूमध्ये «सुरक्षा ऑडिटर» उघडा, प्रकल्प निवडा, नंतर «स्कॅन सुरू करा» दाबा. IDE प्रकल्प कोड, मेनिफेस्ट आणि संरचना स्कॅन करते आणि उच्च ते कमी जोखीमपर्यंत निष्कर्ष नोंदवते — कोडमध्ये उघडे ठेवलेली API की, परवानगीशिवाय उघड केलेला घटक, JavaScript इंटरफेससह JavaScript सक्षम करणारा WebView, कमकुवत क्रिप्टो (MD5, SHA1, DES), TLS शिवाय http पत्ता, आणि कोडमध्ये थेट लिहिलेला पासवर्ड — त्यांच्या फायली आणि ओळ क्रमांकांसह. दुरुस्ती सुरक्षित असलेल्या निष्कर्षांसाठी (उदाहरणार्थ MD5 ला SHA-256 किंवा http ला https मध्ये बदला), «दुरुस्ती लागू करा» दाबा; API की आणि पासवर्डसाठी, IDE फक्त दुरुस्ती सूचना दाखवते कारण पर्याय विकसकानेच ठरवायचा आहे. स्कॅन आता तयार केलेल्या APK मधील खरा DEX बाइटकोडही विश्लेषण करते (फक्त कोडमधील मजकूर नमुने नव्हे), त्यामुळे बोलावलेले धोकादायक API आणि DEX मध्ये अंतर्भूत गुपितेही पकडली जातात; नमुना न पाळणारी अंतर स्कॅनमधून अद्याप सुटू शकतात — लागू करण्यापूर्वी तपासा.

इंटरफेस चाचणी रोबोट
मजकूर परिस्थितींद्वारे अॅप स्क्रीन स्वयंचलितपणे चाचणीसाठी: मुख्य मेनूमध्ये «इंटरफेस चाचणी रोबोट» उघडा, प्रकल्प निवडा, नंतर «आपोआप परिस्थिती बनवा» दाबा. IDE प्रकल्प मेनिफेस्ट आणि मांडणी वाचते आणि परिस्थिती मजकूर पायऱ्या म्हणून लिहिते (बटण दाबा, फील्ड भरा, प्रतीक्षा करा, परत जा). परिस्थिती चालण्याचा लॉग त्याच्या वेळ मुद्रांसह पाहण्यासाठी «ड्राय रन चालवा» दाबा — हा ड्राय रन अद्याप फक्त क्रम अनुकरण आहे. खरी चाचणीसाठी, «प्रकल्पात चाचणी एजंट घाला» दाबा: IDE परिस्थिती मालमत्तांसह चाचणी एजंट प्रकल्पात घालते; APK नेहमीप्रमाणे तयार करा, स्थापित करा, नंतर «चाचणी» चिन्ह उघडा — तो एजंट तयार केलेल्या अॅपच्या आत चालतो आणि खरोखर बटणे दाबतो, खरी फील्ड भरतो, आणि स्क्रोल करतो, नंतर त्याचा अहवाल स्क्रीनवर पकडलेल्या खऱ्या क्रॅशसह दाखवतो. तो एजंट पुन्हा काढण्यासाठी «प्रकल्पातून चाचणी एजंट काढा» दाबा. एजंट अॅपच्या स्वतःच्या प्रक्रियेच्या आत चालतो, त्यामुळे त्याला प्रवेश सेवा किंवा प्रणाली स्वयंचलनाची आवश्यकता नाही.

कोड वेळ प्रवास
Git आदेश न टाइप करता प्रकल्पाला आधीच्या कोड स्थितीत परत नेण्यासाठी: मुख्य मेनूमध्ये कोड वेळ प्रवास उघडा, प्रकल्प निवडा, वेळबिंदूचे लेबल भरा (रिकामे राहू शकते), मग वेळबिंदू नोंदवा वर टॅप करा. IDE प्रकल्पाच्या स्रोत फाइल्सची प्रत त्यांच्या hash सह प्रकल्पातील .riwayat फोल्डरमध्ये जतन करतो. वेळबिंदू यादी त्या सर्वांना दाखवते; दोन बिंदू निवडा मग जोडलेल्या, बदललेल्या किंवा काढलेल्या फाइल्स व कार्ये पाहण्यासाठी तुलना करा वर टॅप करा. जुनी स्थिती परत मिळवण्यासाठी पुनर्स्थापित करा वर टॅप करा — पुनर्स्थापित करण्यापूर्वी IDE नेहमी आधी सध्याच्या स्थितीचा बॅकअप बनवतो, त्यामुळे काहीही हरवत नाही. मूळ प्रकल्पाला त्रास न देता बदल आजमावण्यासाठी प्रकल्प नवीन फोल्डरमध्ये कॉपी करण्यासाठी प्रयोग प्रत बनवा वर टॅप करा. फक्त स्रोत फाइल्स नोंदवल्या जातात.

मॉड्यूल कारखाना
प्रकल्पाचा एखादा भाग दुसऱ्या प्रकल्पाला वापरता येईल असे मॉड्यूल म्हणून पॅक करण्यासाठी: मुख्य मेनूमध्ये मॉड्यूल कारखाना उघडा, स्रोत प्रकल्प निवडा, पॅक करायच्या स्क्रीन, वर्ग, स्ट्रिंग व परवानगी फाइल्सवर खूण करा, मग मॉड्यूल म्हणून पॅक करा वर टॅप करा. IDE JSON मेटाडेटासह (मॉड्यूलचे नाव, आवृत्ती, वापरलेल्या स्ट्रिंग व परवानग्या) ZIP संग्रह लिहितो. दुसऱ्या प्रकल्पात मॉड्यूल बसवण्यासाठी मॉड्यूल कारखाना उघडा, लक्ष्य प्रकल्प निवडा, मग मॉड्यूल बसवा वर टॅप करून मॉड्यूलची .zip फाइल निवडा — विलीनीकरण विद्यमान कोड न लिहिता स्ट्रिंग व परवानग्या जोडते, आणि लक्ष्य प्रकल्पात नाव आधीच वापरले असेल तर फाइल विलीन करत नाही. मॉड्यूल लायब्ररी किंवा बिल्ड सेटिंग्ज सोबत नेत नाही.

बहुरूपी ढाल आणि मालमत्ता तिजोरी
प्रकाशनापूर्वी ओळखकर्ता नावे यादृच्छिक करण्यासाठी आणि प्रकल्प मालमत्ता एन्क्रिप्ट करण्यासाठी: मुख्य मेनूमध्ये «बहुरूपी ढाल आणि मालमत्ता तिजोरी» उघडा, प्रकल्प निवडा, नंतर «नावे यादृच्छिक करा आणि मालमत्ता एन्क्रिप्ट करा» दाबा. IDE स्रोत कोडमधील वर्ग आणि पद्धत नावे स्कॅन करते, यादृच्छिक नाव नकाशा तयार करते, ती नावे संकलित DEX फायलींमध्ये पुन्हा लिहिते (पर्यायी नावे सर्व ऑफसेट वैध राहतील यासाठी मूळ नावांइतकीच लांब तयार केली जातात, नंतर DEX शीर्षलेख चेकसम आणि SHA-1 स्वाक्षरी पुन्हा मोजली जाते), प्रकल्प मालमत्ता फायली प्रकल्पातील brankas-aset फोल्डरमध्ये AES-GCM ने एन्क्रिप्ट करते, आणि क्रॅश लॉग वाचताना मूळ नावे पुनर्संचयित करता यावीत म्हणून एन्क्रिप्टेड पुनर्प्राप्ती नकाशा (perisai-peta.brankas) जतन करते. एन्क्रिप्शन की आता प्रकल्पाच्या नावावरून नव्हे, तर विकसकाच्या पासवर्डवरून PBKDF2, 20,000 पुनरावृत्तींसह मिळवली जाते. साधा मजकूर, भाष्य नाव आणि डीबग नाव म्हणूनही वापरली जाणारी नावे जाणूनबुजून पुन्हा लिहिली जात नाहीत, आणि बिल्ड मार्गातील DEX पुन्हा लिहिण्याचे समावेशन बिंदू अद्याप खऱ्या फोनवर चाचणीची प्रतीक्षा करत आहेत.

विश्वास साखळी आणि वातावरण रक्षक
प्रकाशनापूर्वी स्वाक्षरी की साखळी आणि फोनचे वातावरण तपासण्यासाठी: मुख्य मेनूमध्ये «विश्वास साखळी आणि वातावरण रक्षक» उघडा, प्रकल्प निवडा, नंतर «साखळी आणि वातावरण तपासा» दाबा. IDE प्रकल्पाच्या पॅकेज नावावरून 5 पिढ्यांची की साखळी तयार करते आणि तिची अखंडता तपासते, मेमरीतील कोड भागांच्या सामग्रीची डिस्कवरील फायलींशी तुलना करून खरी मेमरी अखंडता तपासते आणि नाव नसलेली कार्यान्वित करण्यायोग्य (RWX) मॅपिंग, परदेशी लायब्ररी आणि memfd मॅपिंग नोंदवते, नंतर स्वतःच्या प्रक्रियेचा मेमरी नकाशा आणि उपकरण गुणधर्म Frida, Xposed किंवा एम्युलेटरच्या खुणांसाठी स्कॅन करते. तिजोरी की AndroidKeyStore मधील AES कीने गुंडाळली जाते जी उपलब्ध असल्यास हार्डवेअर सुरक्षा चिप वापरते, आणि की फिरवणे आता खरे आहे, स्कीमा v3 स्वाक्षरी प्रमाणपत्र वंशावली वापरून: जुनी की नवीन कीकडे फिरवण्याच्या पुराव्यावर स्वाक्षरी करते आणि APK त्या वंशावलीने पुन्हा स्वाक्षरी केली जाते. परिणाम मजकूर पुराव्यासह «सुरक्षित», «सावध» किंवा «धोकादायक» जोखीम पातळी आहे. प्रणालीने मेमरी वाचण्यास नकार दिल्यास, तपासणी सुरक्षित म्हणून नव्हे तर «सत्यापित करता येत नाही» म्हणून नोंदवली जाते; आणि की खरोखर हार्डवेअर सुरक्षा चिप वापरते का हे फक्त खऱ्या उपकरणावरच खात्री करता येते.

मजकूर वृक्ष मांडणी वास्तुविशारद
न पाहता स्क्रीन डिझाइन करण्यासाठी: मुख्य मेनूमध्ये «मजकूर वृक्ष मांडणी वास्तुविशारद» उघडा, प्रकल्प आणि मांडणी फाइल निवडा, नंतर «मांडणी तपासा» दाबा. IDE XML मांडणी मजकूर वृक्ष म्हणून वाचते आणि प्रत्येक घटकाच्या स्थानाचे वर्णन मोठ्याने वाचते (उदाहरणार्थ खाली उजवीकडे, स्क्रीन रुंदीच्या 45 टक्के), नंतर घटकांमधील आच्छादन आणि 360 dp रुंदीवर स्क्रीनबाहेर जाणारे घटक गणितीयदृष्ट्या नोंदवते. आता मोजले जाणाऱ्या गोष्टींमध्ये LinearLayout आणि साधे dp आकार, पूर्ण ConstraintLayout (सर्व निर्बंध, पक्षपात, साखळ्या, मार्गदर्शक, अडथळे, टक्केवारी रुंदी, 0dp match_constraint आणि मिती गुणोत्तर) आणि Compose स्क्रीन (त्यांच्या आकार सुधारकांसह Column, Row आणि Box) समाविष्ट आहेत. चालू असताना बदलणारे MotionLayout आणि ConstraintSet हेच स्थान अज्ञात म्हणून नोंदवले जात राहतात, कारण त्यांची मूल्ये अॅप चालू असतानाच अस्तित्वात असतात.

डिझाइन प्रणाली स्टुडिओ
सर्व स्क्रीन आणि प्रकल्पांमध्ये अंतर, फॉन्ट आणि कोपरे एकसारखे करण्यासाठी: मुख्य मेनूमध्ये «डिझाइन प्रणाली स्टुडिओ» उघडा, प्रकल्प निवडा, डिझाइन टोकन लिहा (उदाहरणार्थ jarak=8, huruf=16, sudut=12), घटक निवडा, नंतर «घटक तयार करा» दाबा. IDE टोकन प्रमाणित करते — पायाभूत अंतर 4 ते 16 dp, पायाभूत फॉन्ट 12 ते 20 sp, कोपरे 0 ते 32 dp, आणि किमान स्पर्श क्षेत्र 48 dp — नंतर वापरण्यासाठी तयार XML घटक (komponen-studio.xml) XML थीम (tema-studio.xml) आणि Compose थीम (tema-studio.kt) सह प्रकल्प फोल्डरमध्ये लिहिते. टोकन प्रकल्पांमध्ये सामायिक टोकन लायब्ररीमध्ये नाव दिलेला संच म्हणूनही जतन केले जाऊ शकतात, आणि एक समक्रमण आदेश लायब्ररीचे नवीनतम टोकन त्या संचाचा वापर करणाऱ्या सर्व प्रकल्पांना लागू करते. घटक मांडणीत चिकटवले जाणारे आणि नंतर «मजकूर वृक्ष मांडणी वास्तुविशारद» ने तपासले जाणारे मजकूर म्हणून तयार केले जातात; टॅबलेटवरील दोन-स्तंभ समायोजन चालू असताना उपकरण ओळखण्याऐवजी स्क्रीन रुंदी पात्रता वापरते.

अर्थपूर्ण पुनर्रचना आणि AST नेव्हिगेशन
व्याख्या शोधण्यासाठी आणि योगायोगाने तेच नाव असलेला दुसरा कोड न तोडता चिन्ह नावे बदलण्यासाठी: मुख्य मेनूमध्ये «अर्थपूर्ण पुनर्रचना आणि AST नेव्हिगेशन» उघडा, प्रकल्प निवडा, नंतर सर्व वर्ग आणि पद्धती त्यांच्या फायली आणि ओळ क्रमांकांसह पाहण्यासाठी «प्रकल्प चिन्हे स्कॅन करा» दाबा. चिन्हाचे नाव टाइप करा, नंतर त्याची व्याख्या आणि त्याला बोलावणाऱ्या सर्व फायली पाहण्यासाठी «प्रकल्प चिन्हे स्कॅन करा» पुन्हा दाबा. नाव बदलण्यासाठी, नवीन नाव टाइप करा, प्रत्येक फाइलमधील घटनांची संख्या पाहण्यासाठी «नाव बदलण्याचे पूर्वावलोकन» दाबा, नंतर «नाव बदल लागू करा» दाबा. निर्देशक आता हाताने तयार केलेला AST पार्सर वापरतो (Java आणि Kotlin उपसंचासाठी लेक्सर आणि पुनरावर्ती पार्सर), त्यामुळे फायलींमधील पद्धत नाव बदल सोडवले जातात आणि इतर फायलींमधील बोलावणारेही बदलतात; कोड ब्लॉक नवीन फंक्शनमध्ये काढण्याचे बटण आता या स्क्रीनवर आहे. हा पार्सर अद्याप किमान आहे: खूप गुंतागुंतीचे जेनेरिक, पॅरामीटर असलेली भाष्ये आणि अनामिक वर्ग जसे आहेत तसे स्कॅन केले जातात, तर प्रतिबिंब आणि इंटरफेसद्वारे कॉल सोडवले जात नाहीत.

टप्प्याटप्प्याने डीबगर आणि मेमरी निरीक्षक
लॉगमधून अंदाज न लावता कार्यक्रम प्रवाहाच्या मध्यभागी चल सामग्री तपासण्यासाठी: मुख्य मेनूमध्ये «टप्प्याटप्प्याने डीबगर आणि मेमरी निरीक्षक» उघडा, प्रकल्प निवडा, अंमलबजावणी मागोवा लिहा (प्रत्येक ओळीला एक पाऊल, स्वरूप ओळ क्रमांक, कोड, नंतर | ने वेगळे केलेले चल आणि मूल्ये, उदाहरणार्थ 10|int total = harga * jumlah;|harga=5000, jumlah=3, total=15000), थांबा बिंदू ओळ क्रमांक टाइप करा, नंतर «डीबग मागोवा चालवा» दाबा. IDE पहिल्या थांबा बिंदूपर्यंत चालते आणि Jieshuo द्वारे सक्रिय ओळ तिच्या चल मूल्यांसह मोठ्याने वाचते. एक ओळ पुढे जाण्यासाठी «एक ओळ पुढे जा» दाबा, बोलावलेल्या फंक्शनमध्ये प्रवेश करण्यासाठी «फंक्शनमध्ये प्रवेश करा» दाबा (कॉल स्टॅकसह), किंवा पुढील थांबा बिंदूपर्यंत जाण्यासाठी «कार्यक्रम सुरू ठेवा» दाबा. हा मागोवा डीबगर अद्याप नोंदवलेला किंवा हाताने लिहिलेला मागोवा पाळतो; त्याच्या शेजारी JDWP वायर प्रोटोकॉलचा शुद्ध Java क्लायंट आहे जो हस्तांदोलन करू शकतो, थांबा बिंदू ठेवू शकतो, आत, वर आणि बाहेर पाऊल टाकू शकतो, आणि TCP द्वारे किंवा ऐकण्याच्या मोडमध्ये VM थांबवू आणि सुरू ठेवू शकतो. सामान्य अॅपच्या आतून खरी प्रक्रिया थांबवणे अद्याप पूर्णपणे शक्य नाही, कारण प्रक्रियेचा JDWP सॉकेट फक्त adbd द्वारे उघड होतो — सिद्ध झालेल्या मार्गाला वायरलेस डीबगिंग आणि शेलद्वारे लक्ष्य सुरू करणे आवश्यक आहे, जे अॅप स्वतः करू शकते त्यापलीकडे आहे.

ऑफलाइन अवलंबित्व व्यवस्थापक
इंटरनेटशिवाय तृतीय-पक्ष लायब्ररी वापरण्यासाठी आणि बिल्डपूर्वी आवृत्ती संघर्ष टाळण्यासाठी: मुख्य मेनूमध्ये «ऑफलाइन अवलंबित्व व्यवस्थापक» उघडा, प्रकल्प निवडा, नंतर «अवलंबित्व तपासा» दाबा. IDE प्रकल्पाच्या सर्व .gradle फायली वाचते, Download/brankas-bersama फोल्डरमधील प्रकल्पांमध्ये सामायिक तिजोरी तपासते, आणि संघर्ष सोडवते — दोन लायब्ररींनी एकाच कलाकृतीच्या वेगवेगळ्या आवृत्त्या मागितल्यास, सर्वोच्च आवृत्ती वापरली जाते आणि संघर्ष नोंदवला जातो. लायब्ररी डाउनलोड करण्यासाठी, तिचे निर्देशांक टाइप करा (स्वरूप गट:कलाकृती:आवृत्ती, उदाहरणार्थ com.google.code.gson:gson:2.10.1) नंतर «अवलंबित्व तपासा» दाबा: ऑनलाइन असताना, AAR, JAR किंवा WHL फायली खरोखर Maven, Google किंवा PyPI वरून त्यांच्या संक्रमण अवलंबित्व आलेखासह (पुनरावर्ती, चक्र तुटलेली, खोली 25 पातळ्यांपर्यंत) डाउनलोड होतात, आणि फक्त यशस्वीपणे डाउनलोड झालेल्या फायली उपलब्ध म्हणून नोंदवल्या जातात. ऑफलाइन असताना फक्त सामायिक तिजोरीत आधीच असलेल्या लायब्ररी वापरता येतात. Maven आवृत्ती श्रेणी सोडवल्या जात नाहीत, आणि डाउनलोड झालेल्या फायली फक्त त्यांच्या SHA-1 ने तपासल्या जातात, PGP पडताळणीशिवाय.

डेटाबेस आणि संचयन निरीक्षक
सारणी सामग्री छापणारा कोड न लिहिता प्रकल्प डेटाबेस सामग्री तपासण्यासाठी आणि चाचणीसाठी: मुख्य मेनूमध्ये «डेटाबेस आणि संचयन निरीक्षक» उघडा, प्रकल्प आणि डेटाबेस फाइल (.db, .sqlite किंवा .sqlite3) निवडा, नंतर «डेटाबेस उघडा» दाबा. IDE पूर्ण SQLite पृष्ठ पार्सर (ओव्हरफ्लो पृष्ठांसह B-वृक्ष) ने तिच्या सर्व सारणींची योजना वाचते आणि पहिल्या 20 ओळी Jieshuo मोठ्याने वाचतो अशी मजकूर सारणी म्हणून दाखवते. SELECT क्वेरी लिहा नंतर «क्वेरी चालवा» दाबा (उदाहरणार्थ SELECT nama FROM pengguna WHERE kota = 'Makassar') — क्वेरी आता JOIN, GROUP BY, ORDER BY आणि LIKE ला समर्थन देतात, आणि फोनवर खऱ्या Android SQLite इंजिनद्वारे चालतात. मूल्य बदलण्यासाठी, ओळ क्रमांक (1 = पहिली ओळ), स्तंभ नाव आणि नवीन मूल्य टाइप करा, नंतर «सेलचे मूल्य बदला» दाबा — ते मूल्य .db फाइलमध्ये परत लिहिले जाते. सारणीची सध्याची स्थिती प्रकल्पात <डेटाबेस-नाव>.cadangan.txt फाइल म्हणून जतन करण्यासाठी «बॅकअप जतन करा» दाबा. SharedPreferences आणि DataStore ही वाचता येतात. जे अद्याप वाचता येत नाही: एन्क्रिप्टेड डेटाबेस, न केलेले WAL बदल, आणि विशेष DataStore Proto मधील प्रकारित मूल्ये (फक्त सामान्य फील्ड दृश्य म्हणून दाखवली जातात).

युनिट चाचणी कारखाना आणि फझिंग
अॅप सामायिक करण्यापूर्वी तर्क अंतर शोधण्यासाठी: मुख्य मेनूमध्ये «युनिट चाचणी कारखाना आणि फझिंग» उघडा, प्रकल्प आणि कोड फाइल निवडा, नंतर «चाचण्या तयार करा आणि चालवा» दाबा. IDE फाइलमधील फंक्शन स्वाक्षऱ्या वाचते, सामान्य आणि सीमा चाचणी प्रकरणे तयार करते (रिक्त मजकूर, null, कमाल संख्या, विचित्र वर्ण), नंतर खरोखर त्या चाचण्या चालवते: प्रकल्प कोड संकलित होतो आणि प्रत्येक @Test पद्धत 5 सेकंद मर्यादेसह कार्यान्वित होते, त्यामुळे परिणाम त्यांच्या वास्तविक मूल्यांसह खरे उत्तीर्ण आणि अयशस्वी आहेत. फझिंगही प्रकल्प फंक्शनवर खरोखर चालते (प्रतिबिंबाद्वारे, प्रत्येक कॉलला 2 सेकंद, कमाल 20 पद्धती), आणि ओळ व्याप्ती टक्केवारी मूळ ओळ क्रमांक जपणाऱ्या साधनांद्वारे खरोखर मोजली जाते. परिणाम किती चाचण्या उत्तीर्ण आणि अयशस्वी झाल्या, किती कोड ओळी आणि फंक्शन सापडले, आणि कोणती चाचणी प्रकरणे तयार केली हे नोंदवते. तयार केलेल्या चाचण्या JUnit सारख्याच API वापरतात, परंतु भाष्य आणि प्रतिपादन व्याख्या तयार केलेल्या चाचणी फाइलच्या आतच लिहिल्या जातात, कारण खरी JUnit लायब्ररी अॅपमध्ये समाविष्ट नाही.

अत्यंत उपकरण स्थिती अनुकरणकर्ता आणि मेमरी गळती लेखापरीक्षक
प्रणाली तिची प्रक्रिया मारते तेव्हा, नेटवर्क तुटते तेव्हा, स्क्रीन फिरते तेव्हा, किंवा बॅटरी बचत चालू असते तेव्हा अॅपची सहनशीलता तपासण्यासाठी: मुख्य मेनूमध्ये «अत्यंत उपकरण स्थिती अनुकरणकर्ता आणि मेमरी गळती लेखापरीक्षक» उघडा, प्रकल्प निवडा, नंतर «अनुकरण चालवा» दाबा. IDE स्क्रीन फिरवणे अनुकरणासह तीन दाब परिस्थिती चालवते आणि त्यांची स्क्रीन बंद झाल्यानंतरही मेमरीत धरलेल्या वस्तूंचा मागोवा घेते, नंतर हरवलेला डेटा आणि गळणाऱ्या वस्तू साखळ्या नोंदवते. जतन आणि पुनर्संचयित स्थिती आता स्थिर उदाहरणातून नव्हे, तर वापरकर्त्याच्या स्वतःच्या प्रकल्प स्रोतातून वाचली जाते; स्थानिक लूपबॅक सर्व्हर नेटवर्क कट मोजण्यासाठी चाचणीच्या मध्यभागी खरोखर थांबवला जातो; खरा हीप डंप घेतला आणि विश्लेषण केला जातो, दोन डंप तुलना करण्यासाठी आणि GC मुळांपासून धरण्याची साखळी मागोवा घेण्यासाठी; आणि अॅपची स्वतःची प्रक्रिया तिची स्थिती जतन केल्यानंतर खरोखर मारली जाते, नंतर पुन्हा उघडल्यावर कोणता डेटा परत येतो हे तपासले जाते. सामान्य अॅपमधून अद्याप अशक्य असलेल्या गोष्टी: फोन रेडिओ किंवा Wi-Fi बंद करणे आणि इतर अॅप जबरदस्तीने थांबवणे — दोन्हींना प्रणाली परवानगी आवश्यक आहे; त्याऐवजी, पार्श्वभूमी अॅप killBackgroundProcesses द्वारे मारले जातात, ज्याची परवानगी आधीच मेनिफेस्टमध्ये आहे, स्क्रीनवर प्रामाणिक लेबलसह.

प्रकल्प आराखडा वास्तुविशारद
मोठ्या अॅप कल्पनेला टप्प्याटप्प्याने काम योजनेत बदलण्यासाठी: मुख्य मेनूमध्ये «प्रकल्प आराखडा वास्तुविशारद» उघडा, प्रकल्प निवडा, अॅप कल्पना लिहा (उदाहरणार्थ हप्त्यांसह लहान किराणा दुकान कॅशियर अॅप), नंतर «आराखडा तयार करा» दाबा. IDE मॉड्यूल, फाइल यादी आणि लहान टप्पे तयार करते, नंतर त्यांना प्रकल्प फोल्डरमध्ये cetak-biru.txt म्हणून जतन करते. टप्पा पूर्ण होईल तेव्हा «पुढील टप्पा पूर्ण म्हणून चिन्हांकित करा» दाबा, किंवा जतन केलेला आराखडा पुन्हा उघडण्यासाठी «जतन केलेला आराखडा लोड करा» दाबा. «AI सेटिंग्ज» मध्ये सक्रिय AI प्रदाता निवडला असल्यास आणि त्याची की उपलब्ध असल्यास, आराखडा त्या प्रदात्याकडून तयार होतो; की नसल्यास किंवा प्रदात्यापर्यंत पोहोचता येत नसल्यास, IDE ऑफलाइन कीवर्ड नमुन्यांकडे परत जाते आणि ती मर्यादा प्रामाणिकपणे सांगते. प्रदात्याचे उत्तर फक्त स्वरूपासाठी तपासले जाते (मॉड्यूल आणि टप्पे अस्तित्वात आहेत), सामग्रीच्या सत्यतेसाठी नाही — तयार करण्यापूर्वी नेहमी आराखड्याचे पुनरावलोकन करा.

कोड तर्क प्रवाह कथाकार
वाक्यरचना ओळीने ओळ ऐकल्याशिवाय लांब कोड समजून घेण्यासाठी: मुख्य मेनूमध्ये «कोड तर्क प्रवाह कथाकार» उघडा, प्रकल्प आणि कोड फाइल निवडा, नंतर «कोड कथन» दाबा. IDE प्रत्येक ओळ इंडोनेशियन वाक्यात बदलते (उदाहरणार्थ एकूण 100000 पेक्षा जास्त असल्यास, पुढील ब्लॉक चालवा), पद्धतींमधील कॉल नकाशा आणि पद्धतींमधील डेटा प्रवाह विश्लेषण (पुढे पाठवलेली, वापरलेली किंवा दुर्लक्षित केलेली मूल्ये) दाखवते, आणि सूक्ष्म संभाव्य बग त्यांच्या ओळ क्रमांकांसह चिन्हांकित करते — == ने तुलना केलेला String, बंद न करता उघडलेला प्रवाह, आणि दोन वेगवेगळ्या पद्धतींमध्ये लिहिलेला चल. «AI सेटिंग्ज» मध्ये सक्रिय AI प्रदाता निवडला असल्यास, त्या प्रदात्याकडून प्रवाह सारांशही उपलब्ध आहे; उपलब्ध नसल्यास, स्क्रीन ऑफलाइन कथन वापरते आणि ती मर्यादा सांगते. कथन, कॉल नकाशा आणि डेटा प्रवाह ऑफलाइन मजकूर नमुना विश्लेषण वापरतात, पूर्ण AST पार्सर नव्हे — उघडणारा कंस स्वतःच्या ओळीवर असलेल्या पद्धती, वर्ग फील्ड, आणि प्रतिबिंबाद्वारे कॉल मागोवा घेतले जात नाहीत — आणि डेटा शर्यत इशारे प्रत्यक्षात फक्त आलटूनपालटून वापरल्या जाणाऱ्या चलासाठी दिसू शकतात.

अॅप बंडल कारखाना आणि Play Store तयारी
फोनवरून थेट Google Play Store साठी अॅप तयार करण्यासाठी: मुख्य मेनूमध्ये «अॅप बंडल कारखाना आणि Play Store तयारी» उघडा, प्रकल्प निवडा, नंतर «AAB बंडल तयार करा» दाबा. IDE खऱ्या BundleConfig.pb सह प्रकल्प मेनिफेस्ट, संसाधने आणि मालमत्तांमधून .aab फाइल तयार करते, बंडल रचना प्रमाणित करते, नंतर बंडलला खऱ्या प्रकार APK मध्ये विभाजित करते (मूलभूत, आर्किटेक्चरनुसार, भाषेनुसार, आणि सार्वत्रिक) त्या विभाजनातून मोजलेल्या आकारांसह, अंदाज नव्हे. बंडल APK स्वाक्षरीसाठी वापरलेल्या त्याच प्रकल्प कीने JAR v1 ने स्वाक्षरी केला जातो, आणि तिची स्वाक्षरी साखळी क्रिप्टोग्राफिकदृष्ट्या सत्यापित केली जाते. ही स्क्रीन Play तयारीचे लेखापरीक्षणही करते — लक्ष्य SDK 35 खाली असल्यास «उच्च» म्हणून चिन्हांकित केले जाते कारण Play Store ला 35 किंवा अधिक आवश्यक आहे, आणि गहाळ 64-बिट लायब्ररीही «उच्च» म्हणून चिन्हांकित केली जाते. खरे bundletool उपकरणावर चालू शकत नाही, कारण bundletool ला JVM आवश्यक आहे तर Android कडे JVM नाही; वरील मार्ग उपकरणावरील सर्वात जवळचा खरा मार्ग आहे.

OTA अद्यतन इंजिन आणि टप्प्याटप्प्याने प्रकाशने
वापरकर्त्यांना संपूर्ण APK पुन्हा डाउनलोड करण्यास भाग न पाडता लहान दुरुस्ती पाठवण्यासाठी: मुख्य मेनूमध्ये «OTA अद्यतन इंजिन आणि टप्प्याटप्प्याने प्रकाशने» उघडा, प्रकल्प निवडा, जुनी आणि नवीन आवृत्ती सामग्री लिहा, नंतर «पॅच पॅकेज तयार करा» दाबा. IDE फरक मोजते आणि नवीन सामग्रीच्या SHA-256 फिंगरप्रिंटसह पॅच पॅकेज (patch-ota.zip) तयार करते, नंतर हे उपकरण पहिल्या 10 टक्के प्रकाशन टप्प्यात आहे का हे तपासते. पॅच आता कोणत्याही फाइलवर बायनरी डेल्टाला समर्थन देतात (DEX आणि APK सह), RSA-2048 स्वाक्षरीने पॅक केले जातात आणि लागू करण्यापूर्वी विश्वासार्ह सार्वजनिक कीने सत्यापित केले जातात, आणि विकसकाच्या सर्व्हरवरून त्याच्या प्रकाशन यादीसह डाउनलोड केले जाऊ शकतात; लागू करणे अयशस्वी झाल्यास, जुनी फाइल अबाधित राहते. चालू अॅपवर पॅच लागू करणे प्रकल्प कीने पुन्हा स्वाक्षरी करून आणि PackageInstaller द्वारे केले जाते, कारण चालू प्रक्रियेचा कोड स्वतःच्या आतून बदलणे अशक्य आहे — APK लॉक केलेले आहे आणि DEX आधीच लोड केलेले आहे.

संघ कोड पुनरावलोकन स्टुडिओ
सहकाऱ्याचे बदल पुनरावलोकन करण्यासाठी आणि Git बाण चिन्हे न वाचता विलीनीकरण संघर्ष सोडवण्यासाठी: मुख्य मेनूमध्ये «संघ कोड पुनरावलोकन स्टुडिओ» उघडा, प्रकल्प निवडा, तीन मजकूर आवृत्त्या टाइप करा (मूलभूत, स्थानिक, सहकारी), नंतर «संघ पुनरावलोकन उघडा» दाबा. IDE तिन्ही Java वाक्यरचना एककांवर आधारित विलीन करते — एकाच ओळीवर दोन बदल परंतु वेगवेगळ्या विधानांमध्ये आता संघर्ष मानले जात नाहीत — आणि प्रत्येक संघर्ष मतदान पर्याय म्हणून दाखवते: स्थानिक आवृत्ती वापरा, सहकारी आवृत्ती वापरा, किंवा दोन्ही विलीन करा — परिणाम ओळ क्रम योग्य राहील यासाठी मूळ संघर्ष स्थानावर घातली जाते — नंतर परिणाम प्रकल्पात gabung-hasil.txt मध्ये लिहिते. खाली प्रकल्प कार्य फलक आहे: कार्य शीर्षक टाइप करा नंतर «काम जोडा» दाबा; कार्ये प्रकल्पातील .tugas फोल्डरमध्ये मजकूर म्हणून जतन केली जातात आणि अॅपमधील Git मध्ये कमिटद्वारे समक्रमित केली जातात, त्यामुळे फलक कोणत्याही कमिट इतिहासातून पुन्हा वाचता येतो. हा वाक्यरचना विभाजक पूर्ण AST पार्सर नाही आणि अॅपमधील Git प्रत्येक कमिटसाठी पूर्ण स्नॅपशॉट जतन करते; विशेष समक्रमण सर्व्हर नाही.

कोड रचना डिक्टेशन
एडिटरमध्ये आवाजाने कोड लिहिण्यासाठी: एडिटरमध्ये प्रकल्प उघडा, मग कोड रचना डिक्टेशन बटण वर टॅप करा. इंडोनेशियन भाषेत आदेश बोला, उदाहरणार्थ buat fungsi tambah dengan parameter a angka dan b angka, buat kelas Mobil, किंवा buat variabel teks nama sama dengan Budi — IDE बोलणे व्याकरणदृष्ट्या बरोबर Java, Kotlin, Python किंवा Compose कोड गटात बदलतो आणि कर्सरच्या जागी घालतो, मग Jieshuo द्वारे संक्षिप्त सारांश मोठ्याने वाचतो. डिक्टेशन प्रणालीची अंगभूत आवाज इनपुट सेवा वापरते, अतिरिक्त मायक्रोफोन परवानगीशिवाय, आणि फक्त आधीच नोंदवलेले आदेश नमुने ओळखते; त्या नमुन्यांबाहेरील बोलणे कोडमध्ये बदलत नाही. शब्दांत बोललेले आकडे (उदाहरणार्थ 'lima') अद्याप अंकांत बदलत नाहीत.

स्थानिक सहकार कक्ष (इंटरनेटशिवाय)
इंटरनेटशिवाय एकाच खोलीत एकत्र काम करण्यासाठी: मुख्य मेनूमध्ये सहकार्य उघडा, मग स्थानिक सहकार कक्ष विभाग उघडा. एक फोन सत्र उघडतो (IDE स्थानिक IP पत्ता व ६ अंकी PIN दाखवतो), दुसरा फोन त्या पत्त्याने व PIN ने सामील होतो. मजकूर बदल ओळ फरक म्हणून पाठवले जातात, तयार केलेला APK परीक्षकाच्या फोनवर पाठवता येतो, आणि परीक्षकाच्या फोनवरून क्रॅश अहवाल परत मिळतात. एक सत्र फक्त एका मित्रासाठी आहे; दोन लोकांनी अगदी तीच ओळ एकाच वेळी बदलली तर शेवटचा बदल वापरला जातो. PIN स्थानिक नेटवर्कवर साधा मजकूर म्हणून पाठवला जातो. हा कक्ष अद्याप खऱ्या फोनवर तपासलेला नाही.

AI सेटिंग्ज
अॅप तयार करण्यासाठी AI प्रदाता आणि API की सेट करण्यासाठी: मुख्य मेनूमध्ये, सेटिंग्ज गटात, «AI सेटिंग्ज» दाबा («कनेक्टर» बटणाच्या शेजारी). उपलब्ध यादीतून वापरायचा प्रदाता निवडा, आणि एक मॉडेल अयशस्वी झाल्यास IDE आपोआप त्याच प्रदात्याचे पुढील मॉडेल प्रयत्न करेल यासाठी «प्रोव्हायडर त्रुटी आल्यास मॉडेल बदला» तपासा. बॅकअप की जोडण्यासाठी «API की व्यवस्थापित करा» दाबा (नाव आणि की टाइप करा, नंतर «जतन करा» दाबा; की झाकलेल्या दाखवल्या जातात, फक्त शेवटची 4 वर्ण दिसतात). की फोनवर जतन केल्या जातात आणि अॅप तयार करताना निवडलेल्या प्रदात्याशिवाय कुठेही पाठवल्या जात नाहीत. निवडलेला प्रदाता आता खरोखर «प्रकल्प आराखडा वास्तुविशारद» आणि «कोड तर्क प्रवाह कथाकार» द्वारे वापरला जातो; «AI अॅप बिल्डर» स्क्रीनवर अॅप तयार करणे अद्याप फोनवरील स्थानिक AI वापरते (इंटरनेटशिवाय).

कनेक्टर
APK विश्लेषण करून मग पाठवण्यासाठी: मुख्य मेनूमध्ये, सेटिंग्ज गटात, कनेक्टर वर टॅप करा (AI सेटिंग्ज बटणाजवळ). फोनवरून APK फाइल निवडा, IDE त्यातील मजकूर वाचतो (पॅकेजचे नाव, आवृत्ती, क्रियांची यादी), मग प्रणाली शेअर मेनूद्वारे (उदाहरणार्थ WhatsApp किंवा Drive) पाठवण्यासाठी APK पाठवा वर टॅप करा.

भाषा आणि आवाज
अॅपची भाषा बदलण्यासाठी: सेटिंग्ज उघडा, मग अॅपची भाषा, मग भाषा किंवा सिस्टमचे अनुसरण करा निवडा. मुख्य स्क्रीन व बहुतेक स्क्रीन अॅप बंद किंवा पुन्हा सुरू न करताच निवडलेल्या भाषेत लगेच बदलतात; काही स्क्रीन (उदाहरणार्थ Terminal, सहकार्य, AI सेटिंग्ज व की व्यवस्थापन) पुन्हा उघडल्याशिवाय जुनीच भाषा वापरतात. सिस्टमचे अनुसरण करा निवडल्यास भाषा फोनच्या सिस्टम भाषेचे अनुसरण करते.

प्रत्येक प्रकल्पासाठी डीफॉल्ट स्वाक्षरी आणि Anti Tamper
आवृत्ती 5.7 पासून, वैयक्तिक स्वाक्षरी न वापरणारा प्रोजेक्ट त्या प्रोजेक्टच्या स्वतःच्या अंगभूत की ने स्वाक्षरी केला जातो (प्रोजेक्टमधील tanda-tangan-bawaan फोल्डरमध्ये एकदा तयार केला जातो, मग पुढे वापरला जातो), त्यामुळे अंगभूत स्वाक्षरी प्रोजेक्टनुसार वेगळी असते — आता सर्व अॅप्ससाठी एक सामायिक की नाही. tanda-tangan-bawaan फोल्डर हटवू नका: त्या कीशिवाय, नवीन APK त्याच प्रोजेक्टच्या जुन्या APK वर ओव्हरराइट करू शकत नाही. प्रत्येक प्रोजेक्टच्या सेटिंग्ज (वेगळी आर्किटेक्चर, वैयक्तिक स्वाक्षरी, Anti Tamper, निवडलेले keystore, SDK) आता प्रोजेक्टमधील settings.gradle फाइलमध्ये जतन केल्या जातात आणि प्रोजेक्ट बिल्ड होताना प्रत्येक वेळी पुन्हा वाचल्या जातात. सेटिंग्जमध्ये, स्वाक्षरी श्रेणीत, बिल्ड केलेल्या अॅपची Anti Tamper चेकबॉक्स आहे: सक्रिय असल्यास, डिव्हाइसवरील बिल्ड केलेले अॅप प्रत्येक वेळी उघडल्यावर स्वतःची स्वाक्षरी आणि dex सामग्री तपासते; पुन्हा स्वाक्षरी केली गेली किंवा दुसऱ्याने बदलली तर अॅप चालण्यास नकार देते. Frida/Xposed सारखे डीबगर आणि इंजेक्शन साधनेही पकडली जातात आणि अॅप विंडो स्क्रीन रेकॉर्डिंगपासून लॉक केली जाते.

डेमो व्हिडिओ मेकर
बिल्ड केलेल्या अॅपचा डेमो व्हिडिओ तयार करण्यासाठी: मुख्य मेनूमध्ये डेमो व्हिडिओ मेकर उघडा, प्रोजेक्ट निवडा, व्हिडिओ शीर्षक भरा, मग Demo व्हिडिओ स्क्रिप्ट बनवा दाबा — IDE कथन मजकूर आणि प्रत्येक दृश्याच्या कालावधीसह 5 मानक दृश्ये (उघडणे, मुख्य दृश्य, वैशिष्ट्य 1, वैशिष्ट्य 2, समारोप) असलेली video-demo.txt लिहिते. प्रोजेक्टच्या प्रतिमांमधून (आयकॉन + असल्यास स्क्रीनशॉट) दर 5 सेकंदांनी आपोआप बदलणारी video-demo.html तयार करण्यासाठी HTML Slideshow बनवा दाबा. हा .mp4 व्हिडिओ नाही — खऱ्या व्हिडिओसाठी, फोन ब्राउझरमध्ये video-demo.html उघडा मग स्क्रीन रेकॉर्ड करा, किंवा चालू असलेले अॅप रेकॉर्ड करताना video-demo.txt मधील कथन वाचा.

Android Studio सारखे नवीन स्वरूप
IDE चे स्वरूप आता Android Studio सारखे नीटनेटके केले आहे (फक्त स्वरूप — सर्व बटणे, मेनू आणि प्रवाह अगदी पूर्वीसारखेच राहतात): हलकी राखाडी पार्श्वभूमी, ठळक काळी स्क्रीन शीर्षके, पांढऱ्या मजकुरासह निळी बटणे आणि पातळ चौकटीसह पांढऱ्या इनपुट चौकटी. मुख्य मेनू बटण क्रम न बदलता दृश्यमानपणे गटबद्ध केला आहे (बनवणाऱ्याची वैशिष्ट्ये, क्लाउड, थीम आणि इतर, आवाज, कोड आणि नवीन वैशिष्ट्ये, साधने). Terminal अजूनही Android Studio मधील Terminal विंडोप्रमाणे गडद पॅनेल वापरते आणि कोड एडिटर अजूनही पांढरी पार्श्वभूमी आणि काळा मजकूर ठेवतो. सर्व मजकूर Jieshuo द्वारे अजूनही स्पष्टपणे वाचला जातो.

सेटिंग्ज
अॅप सेट करण्यासाठी: मुख्य स्क्रीनवर पर्याय मेनू उघडा मग सेटिंग्ज दाबा. त्यात 12 श्रेण्या आहेत: GitHub सेटिंग्ज (सुरक्षा, वैयक्तिक स्वाक्षरी, बिल्ड इतिहास आणि GitHub टोकन), डिव्हाइसवर APK बिल्ड सेटिंग्ज (keystore पासवर्ड आणि बिल्ड इतिहास डिव्हाइसवर जतन करा), थीम (अॅप रंग), स्वाक्षरी (वैयक्तिक स्वाक्षरीसाठी keystore तयार करा आणि बिल्ड केलेल्या अॅपची Anti Tamper चेकबॉक्स), प्रोजेक्ट फोल्डर (प्रोजेक्ट फोल्डरचे स्थान), भाषा आणि आवाज (इंटरफेस भाषा आणि व्हॉइस मोड बोलण्याचा वेग), मजकूर आकार आणि स्वरूप (एडिटर फॉन्ट आकार), बिल्ड (प्रोजेक्ट तयार करा स्क्रीनसाठी डीफॉल्ट लक्ष्य SDK आणि डीफॉल्ट आर्किटेक्चर विभाजन), सूचना (बिल्ड पूर्ण झाल्यावर आवाज), स्वयंचलित बॅकअप (प्रोजेक्ट बॅकअप वेळापत्रक), विकसक प्रोफाइल (देणगी स्क्रीनवर दिसणारे नाव, WhatsApp क्रमांक आणि खाते) आणि गोपनीयता आणि डेटा (सेटिंग्ज रीसेट करा आणि अॅप डेटा हटवा). प्रत्येक श्रेणीत श्रेणी मेनूवर परत जाण्यासाठी मागील पानावर परत जा बटण आहे. नुकत्याच जतन केलेल्या (अजून लागू न झालेल्या) सेटिंग्जचे स्पष्टीकरण स्क्रीनवर प्रामाणिकपणे लिहिले जाते.

विकसकाला देणगी द्या
देणगी देण्यासाठी किंवा विकसकाला नमस्कार करण्यासाठी: मुख्य स्क्रीनवर साधनाबद्दल बटणाच्या बाजूला असलेले विकसकाला देणगी द्या बटण दाबा. देणगी स्क्रीनवर BRI खाते कॉपी करा बटण आहे — विकसकाचा खाते क्रमांक कॉपी करण्यासाठी ते दाबा, मग तुमच्या बँक अॅपमध्ये चिकटवा. WhatsApp वर विकसकाला नमस्कार करा विभागही आहे: तुमचे नाव आणि मूळ शहर भरा, मग WhatsApp वर पाठवा दाबा — WhatsApp नमस्कार संदेश आधीच भरलेला असताना उघडते, WhatsApp वर पाठवा दाबा मग अॅपवर परत या. WhatsApp इतर अॅप्सना आपोआप संदेश पाठवण्याची परवानगी देत नाही, त्यामुळे पाठवणे अजूनही WhatsApp मध्ये तुम्ही स्वतः करता.

टर्मिनलच्या आवडत्या आज्ञा
Terminal मध्ये वारंवार वापरल्या जाणाऱ्या आज्ञा जतन करण्यासाठी: Terminal उघडा मग आवडते दाबा. नवीन आवडते जोडा टॅप करा, नाव (उदाहरणार्थ फाइल पहा) आणि त्याची आज्ञा (उदाहरणार्थ ls -la) भरा, मग जतन करा दाबा — आवडते फोनवर कायमचे जतन होते. आवडते नाव टॅप करा ते थेट टर्मिनलमध्ये चालवण्यासाठी; आवडते हटवा टॅप करा मग हटवण्यासाठी एक निवडा (पुष्टीकरणासह). आधीच 3 अंगभूत आवडते आहेत: फाइल पहा (ls -la), जागा तपासा (df -h) आणि स्क्रीन साफ करा (clear) — सर्व हटवता येतात. रिकामी आज्ञा जतन किंवा चालवता येत नाही; तसे झाल्यास Terminal संदेश आणि आवाजाद्वारे तुम्हाला सांगते.

विश्लेषण आणि गुणवत्ता
अॅप वापराचा सारांश आणि क्रॅश अहवाल पाहण्यासाठी: मुख्य स्क्रीनवर विकसकाला देणगी द्या बटणाच्या बाजूला असलेले विश्लेषण आणि गुणवत्ता बटण दाबा. ही स्क्रीन अॅप किती वेळा उघडले गेले, कोणत्या स्क्रीन सर्वाधिक उघडल्या गेल्या, क्रॅशची संख्या आणि संक्षिप्त दुरुस्ती सूचनेसह अलीकडील क्रॅशची यादी दाखवते. हा डेटा फक्त तुमच्या फोनवर जतन केला जातो आणि कुठेही पाठवला जात नाही. तो सर्व डेटा हटवण्यासाठी पुष्टीकरण संवादासह विश्लेषण डेटा हटवा बटण आहे. शेवटची स्क्रीन फक्त मुख्य स्क्रीन आणि या स्क्रीनसाठी नोंदवली जाते.
