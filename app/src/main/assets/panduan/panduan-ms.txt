Selamat datang ke Create Aplikasi by Al Kautsar
Create Aplikasi ialah aplikasi pembuat aplikasi Android yang berjalan terus pada telefon, tanpa memerlukan komputer riba. Aplikasi ini membolehkan sesiapa sahaja membuat aplikasi Android sendiri, termasuk pengguna yang baru belajar membuat aplikasi dan pengguna pembaca skrin. Panduan lengkap penggunaan aplikasi ini tersedia pada skrin Tentang Alat ini.

Apakah aplikasi ini dan untuk siapa
Create Aplikasi ialah alat pembuat aplikasi Android yang berjalan pada telefon. Aplikasi ini ditujukan kepada sesiapa sahaja yang ingin membuat aplikasi Android sendiri, termasuk pemula dan pengguna pembaca skrin. Aplikasi ini menyediakan editor kod, butang Jalankan untuk menguji projek, butang Bangun untuk membuat APK, serta menu untuk menandatangani dan memasang APK.

Tujuan aplikasi ini
Aplikasi ini dibuat supaya sesiapa sahaja dapat membuat aplikasi Android sendiri dengan mudah, terus daripada telefon. Paparannya dibuat sesederhana mungkin supaya pengguna baharu pun dapat terus mencuba.

Cara membuat projek baharu, langkah demi langkah
1. Tekan Buat Project pada menu utama.
2. Pilih jenis projek: HTML, Situs Web, Java, Kotlin, Compose, atau Python.
3. Isi nama aplikasi, contoh: Garuda Decode.
4. Isi nama pakej (package name), contoh: com.android.garudadecode. Nama pakej mesti menggunakan huruf kecil dan terdiri daripada sekurang-kurangnya dua bahagian yang dipisahkan oleh titik.
5. Isi versi aplikasi, contoh: 1.0, dan kod versi dalam bentuk angka, contoh: 1. Jika dikosongkan, versi akan diisi secara automatik dengan 1.0 dan kod versi 1.
6. Isi SDK minimum dan SDK sasaran jika diperlukan. Jika dikosongkan, nilai lalai akan digunakan. SDK minimum ialah versi Android terendah yang disokong, contoh: 21 bermakna Android 5.0. SDK sasaran maksimum ialah 36 (Android 16).
7. Tekan butang Pilih Izin untuk memilih kebenaran aplikasi, contoh: INTERNET. Kebenaran INTERNET sudah ditandakan secara lalai. Tandakan hanya kebenaran yang memang diperlukan oleh aplikasi.
8. Jika dikehendaki, tandakan "Gunakan arsitektur terpisah 64 bit dan 32 bit" supaya saiz APK lebih kecil, dan tandakan "Gunakan tanda tangan pribadi" jika ingin menggunakan keystore buatan sendiri.
9. Tekan Buat Proyek. Projek baharu tersimpan dalam folder Download/project dan terus kelihatan pada Kelola Project.

Jenis projek yang tersedia
• HTML: paparan daripada index.html, style.css, dan script.js, berjalan melalui WebView. Dibina terus pada telefon.
• Situs Web: laman web dengan menu (Beranda, Tentang, Kontak) daripada index.html, tentang.html, kontak.html, style.css, dan script.js, berjalan melalui WebView. Dibina terus pada telefon.
• Java: dibina pada telefon. MainActivity berada di app/src/main/java/<nama-paket>/MainActivity.java. Paparan daripada app/src/main/res/layout/activity_main.xml, teks daripada app/src/main/res/values/strings.xml, dan tema daripada app/src/main/res/values/styles.xml.
• Kotlin: dapat dibina pada peranti (luar talian) menggunakan pengkompil Kotlin yang disertakan dalam aplikasi, atau melalui GitHub Actions. MainActivity berada di app/src/main/java/<nama-paket>/MainActivity.kt, dan fail res sama seperti projek Java. Binaan Kotlin pertama lebih perlahan kerana saiz pengkompil yang besar, dan fail .java yang merujuk kelas Kotlin belum dapat dibina (fail .java dikompil terlebih dahulu sebelum fail .kt).
• Compose: aplikasi Android moden yang antara mukanya dibuat dengan Jetpack Compose (bukan susun atur XML). MainActivity berada di app/src/main/java/<nama-paket>/MainActivity.kt. Projek Compose dibina melalui GitHub Actions (menu Bangun proyek, kemudian Bangun online) atau di Termux dengan Gradle, kerana Compose memerlukan pustaka Jetpack Compose yang tidak tersedia pada peranti.
• Python: logik aplikasi ditulis dalam bahasa Python (Chaquopy) di app/src/main/python/main.py, dan dijalankan oleh hos MainActivity.java di app/src/main/java/<nama-paket>/MainActivity.java. Projek Python dapat dibina terus pada telefon (runtime Chaquopy disertakan dalam aplikasi) mahupun melalui GitHub Actions. SDK minimum projek Python ialah 24 (Android 7.0).

Tukar Arkitektur Projek
Untuk menukar pilihan seni bina projek sedia ada tanpa membina projek baharu: dalam menu utama, tekan «Tukar Arkitektur Projek», kemudian pilih projek dan tukar kotak semak «Bina APK 64 bit (arm64-v8a)» atau «Bina APK 32 bit (armeabi-v7a)»; atau dalam «Urus Projek», tekan lama nama projek dan pilih «Tukar Arkitektur» untuk membuka skrin yang sama terus bagi projek itu. Peraturannya: jika kedua-dua kotak semak dihidupkan, binaan menghasilkan dua APK berasingan, satu 64 bit dan satu 32 bit; jika hanya satu kotak semak dihidupkan, binaan menghasilkan satu APK universal yang terus berjalan pada peranti 64 bit dan 32 bit. APK berasingan untuk satu varian sahaja belum disokong, kerana laluan binaan hanya mengenali pilihan berpecah atau universal, tetapi pilihan setiap varian kekal disimpan di dalam projek supaya tidak hilang apabila skrin dibuka semula.

Susunan fail projek Java, HTML, Situs Web, Kotlin, Compose, dan Python
Projek Java, HTML, Situs Web, Kotlin, Compose, dan Python tersusun seperti projek Android pada umumnya. Di dalam folder app terdapat folder src, dan di dalamnya terdapat folder main. Di dalam folder main terdapat AndroidManifest.xml di samping folder java, folder res yang berisi layout/activity_main.xml dan values/strings.xml serta values/styles.xml, dan untuk HTML dan Situs Web terdapat folder assets yang berisi index.html (Situs Web juga mempunyai tentang.html dan kontak.html). Projek HTML dan Situs Web juga mempunyai MainActivity sendiri di app/src/main/java/<nama-paket>/MainActivity.java, yang memuatkan index.html dalam WebView dan menjadi pelancar dalam AndroidManifest. Projek Python mempunyai kod Python di app/src/main/python/main.py dan hos MainActivity.java di app/src/main/java/<nama-paket>/MainActivity.java. AndroidManifest.xml, susun atur, strings, dan styles dapat dibuka dan diubah dalam editor, sama seperti MainActivity. Projek lama yang manifestnya masih berada di samping folder app tetap dapat dibina, kerana pada masa membina, aplikasi memeriksa AndroidManifest.xml di app/src/main/ terlebih dahulu, kemudian yang di samping folder app, dan terakhir fail data projek.

Peraturan kebenaran (penting)
Kebenaran yang ditandakan semasa membuat projek hanya dicatatkan di satu tempat, mengikut jenis projeknya. Untuk projek Java, HTML, Situs Web, Kotlin, Compose, dan Python, kebenaran yang ditandakan dicatatkan HANYA dalam AndroidManifest.xml yang berada di app/src/main/, di samping folder java, di dalam folder projek. Fail data projek untuk projek Java, HTML, Situs Web, Kotlin, Compose, dan Python tidak berisi senarai kebenaran. Jika memilih Java kemudian menandakan INTERNET dan CAMERA, yang tercatat dalam AndroidManifest.xml hanyalah INTERNET dan CAMERA, tanpa kebenaran lain yang ikut serta. Pada masa membina, aplikasi membaca kebenaran daripada tempat yang sama: daripada AndroidManifest.xml di app/src/main/ untuk projek Java, HTML, Situs Web, Kotlin, Compose, dan Python (jika tiada, daripada AndroidManifest.xml di samping folder app untuk projek lama), dan daripada fail data projek untuk projek lama.

Cara menggunakan editor
Buka Kelola Project, ketik nama projek untuk membuka editor. Dalam editor, fail dapat dibuka, kod dapat ditulis, dan perubahan dapat disimpan. Untuk projek Java, HTML, Situs Web, Kotlin, Compose, dan Python, fail tersusun di dalam folder app/src/main. Untuk berkongsi projek, gunakan Ekspor ZIP (lihat bahagian di bawah).

Cara menjalankan projek
Dalam editor, tekan Jalankan untuk menguji projek. Untuk projek HTML dan Situs Web, yang dijalankan ialah index.html melalui WebView. Jika berlaku ralat, baca mesej ralatnya, betulkan kod, kemudian jalankan lagi.

Cara membina APK
Dalam editor, tekan Bangun. Terdapat dua cara membina. Pertama, Bangun di perangkat: membina terus pada telefon tanpa internet, untuk projek HTML, Situs Web, Java, Kotlin, dan Python. Kedua, Bangun online melalui GitHub Actions: membina melalui internet di GitHub, dan dapat digunakan untuk semua jenis projek. Projek Compose hanya dapat dibina dengan cara kedua (Bangun online) atau di Termux dengan Gradle, kerana Compose memerlukan pustaka Jetpack Compose yang tidak tersedia pada peranti. Hasil binaan pertama belum ditandatangani. Selepas itu aplikasi menandatanganinya: secara automatik dengan kunci lalai, atau dengan tanda tangan peribadi jika kotak "Gunakan tanda tangan pribadi" ditandakan semasa membuat projek.

Cara memasang APK
Jika APK sudah siap, tekan Pasang untuk memasangnya. Pada Android 8 ke atas, telefon akan meminta "Izinkan dari sumber ini" terlebih dahulu, kerana aplikasi ini memasang APK dari luar Play Store. Aktifkan kebenaran tersebut satu kali dalam Pengaturan, kemudian kembali ke aplikasi: pemasangan akan berterusan secara automatik tanpa perlu menekan Pasang lagi. Jika butang Pasang tidak muncul, pastikan binaan sudah selesai dan APK sudah dibuat.

Cara menandatangani aplikasi
Setiap APK mesti ditandatangani supaya dapat dipasang. Tersedia dua pilihan. Pertama, kunci lalai: aplikasi menandatangani sendiri secara automatik, tanpa perlu melakukan apa-apa. Kedua, tanda tangan peribadi: buat terlebih dahulu keystore melalui menu Buat Keystore pada menu utama, simpan kata laluannya dengan baik, kemudian tandakan "Gunakan tanda tangan pribadi" semasa membuat projek. Keystore tersimpan di Download/project/signing.

Eksport projek menjadi ZIP
Ekspor ZIP disediakan supaya projek dapat dikongsi dengan rakan. Caranya: dalam Kelola Project, tekan lama nama projek, kemudian pilih Ekspor ZIP. Hasilnya tersimpan di Download/project/<NamaProyek>.zip. Folder bin tidak disertakan, jadi saiznya kecil, hanya puluhan KB. Fail ZIP tersebut dapat dihantar kepada rakan atau dimuat naik ke GitHub.

Sambungan JAWS
Sambungan JAWS menggunakan enjin sambungan daripada Jieshuo (CSR), bukan pembaca skrinnya. Dengan demikian, reka bentuk tetap dapat berjalan walaupun pengguna menggunakan TalkBack. Caranya: buka Ekstensi JAWS pada menu utama. Kerana klik automatik berjalan sendiri, perkhidmatan mesti diaktifkan terlebih dahulu dalam Pengaturan Aksesibilitas. Selepas itu, reka bentuk baharu dapat dibuat: taip nama reka bentuk, tekan OK, kemudian isi kotaknya.

Daftar Klik dipisahkan supaya kemas
Di dalam reka bentuk terdapat dua kotak: kotak skrip dan kotak Daftar Klik. Senarai butang disimpan berasingan dalam fail daftar_klik.txt, satu nama setiap baris. Contoh isinya: tombolSimpan, tombolHapus, tombolBuka. Untuk membuka aplikasi, tulis sahaja >WhatsApp dalam senarai tersebut. Reka bentuk lama yang belum mempunyai fail daftar_klik.txt akan memaparkan contoh lalai tersebut.

Fungsi mudah yang disediakan
• klikTombol("tombolSimpan") — mengklik satu butang berdasarkan teksnya.
• klikDaftarTombol(daftar) — mengklik senarai dalam daftar_klik.txt, satu butang setiap baris, secara berurutan, kemudian memberitahu berapa yang berjaya dan berapa yang tidak ditemui.
• bukaAplikasi("WhatsApp") — membuka aplikasi berdasarkan namanya, atau tulis ">WhatsApp" dalam senarai.
• klik(540, 1200) — mengklik pada koordinat skrin.
Semua fungsi dibuat mudah terlebih dahulu. Jika sudah terbiasa, fungsi tambahan dapat ditambah kemudian.

Tentang pembaca skrin
Aplikasi ini direka bentuk supaya mesra pembaca skrin. Setiap ruangan isian mempunyai label dan contoh pengisian, dan semua butang dapat dicapai tanpa gerak isyarat yang rumit. Sambungan JAWS dibuat supaya tetap berjalan walaupun pengguna menggunakan TalkBack, kerana yang digunakan ialah enjin sambungannya, bukan pembaca skrinnya.

Privasi dan keselamatan
Projek dan keystore tersimpan pada telefon anda. Token GitHub hanya digunakan untuk binaan dalam talian dan disimpan di dalam aplikasi ini. Jangan kongsi token atau kata laluan keystore anda dengan sesiapa pun. Jika menggunakan tanda tangan peribadi, simpan keystore dan kata laluannya di tempat yang selamat, kerana jika hilang, APK lama tidak dapat dikemas kini dengan tanda tangan yang sama.

Keperluan
Android 5.0 atau lebih baharu. Kebenaran storan: pada Android 11 ke atas menggunakan kebenaran capaian semua fail, pada Android 10 ke bawah menggunakan kebenaran storan biasa (baca/tulis storan) kerana Android 10 tidak mempunyai kebenaran capaian semua fail. Membina pada peranti memerlukan telefon berprosesor ARM (32 atau 64 bit). Membina dalam talian melalui GitHub Actions memerlukan internet dan token GitHub. Projek Kotlin dapat dibina pada peranti, tetapi binaan pertamanya lebih perlahan dan menggunakan lebih banyak memori kerana saiz pengkompil Kotlin yang besar. Projek Compose dibina melalui GitHub Actions atau di Termux dengan Gradle. Projek Python memerlukan Android 7.0 atau lebih baharu (SDK minimum 24) dan APK hasilnya lebih besar kerana menyertakan runtime Python (Chaquopy) berserta pustaka piawainya.

Terminal
Menu Terminal pada skrin utama membuka terminal di dalam aplikasi ini. Perintah seperti ls dapat digunakan untuk melihat isi folder projek, cd untuk berpindah folder, dan git untuk menguruskan kod. Output perintah dipaparkan sebagai teks yang dapat dibaca oleh pembaca skrin, dan terdapat butang Bacakan hasil untuk mendengar hasil terakhir. Terminal ini menggunakan shell sistem telefon, jadi program interaktif seperti nano dan vim belum dapat digunakan di sini.

Lesen (versi berbayar)
Untuk menjual aplikasi, tandakan "Aktifkan Lisensi" semasa membuat projek, kemudian isi nombor WhatsApp anda. Aplikasi hasil binaan akan meminta kod lesen semasa pertama kali dibuka: pengguna melihat ID perantinya, menekan butang Kirim ID Perangkat untuk menghantar ID tersebut ke WhatsApp anda, kemudian anda membalas kod lesennya. Kod lesen dikira daripada ID peranti dan kata laluan projek (lisensi_seed dalam fail data projek) — simpan kata laluan tersebut dengan baik dan jangan dikongsi. Selepas kod yang betul dimasukkan, aplikasi terbuka dan tidak meminta kod lagi.

Pembuat Ikon Otomatis
Ikon projek baharu masih lutsinar, jadi tersedia Pembuat Ikon pada menu utama. Caranya: tekan Pembuat Ikon, tulis satu atau dua huruf (misalnya huruf awal nama aplikasi), pilih warna latar dan warna tulisan, lihat pratontonnya, kemudian tekan Simpan ke Proyek untuk menggunakan ikon tersebut pada projek yang dipilih, atau Simpan ke Download untuk menggunakan fail PNG-nya di tempat lain. Selepas projek dibuat, aplikasi juga menawarkan pembuatan ikon. Ikon lama projek dapat diganti pada bila-bila masa daripada menu projek dalam Kelola Project (tekan lama nama projek, kemudian pilih Ganti Ikon).

Templat Projek Sedia Guna
Jika tidak ingin bermula daripada projek kosong, pilih templat semasa membuat projek: Kalkulator (Java), Catatan (Java), Daftar Tugas (Kotlin), Kalkulator Web (HTML), Situs Profil (Situs Web), atau Penghitung (Compose). Memilih templat secara automatik mengubah jenis projek mengikut templat tersebut, dan projek dibuat dengan kod awal yang sudah siap — hanya tinggal dijalankan atau diubah. Jika jenis projek diubah lagi secara manual selepas memilih templat, templat dibatalkan dan projek kembali kosong. Untuk templat HTML dan Situs Web, templat menggantikan isi index.html, termasuk skrip HTML yang ditaip dalam borang.

Sandaran dan Pulihkan Projek
Supaya projek tidak hilang, tersedia ciri sandaran. Caranya: dalam Kelola Project, tekan lama nama projek, kemudian pilih Cadangkan. Sandaran tersimpan sebagai ZIP dalam folder Download/backup dengan nama projek dan tarikh, contoh: GarudaDecode-2026-11-14-123045.zip. Isinya sama seperti Ekspor ZIP (keseluruhan isi projek, tanpa folder bin). Untuk memulihkan: buka menu dalam Kelola Project, pilih Pulihkan cadangan, kemudian pilih fail sandarannya. Jika nama projek sudah wujud, aplikasi akan bertanya: Timpa proyek lama, atau simpan dengan Nama baru.

Kongsi dan Import Projek
Untuk berkongsi projek dengan rakan: dalam Kelola Project, tekan lama nama projek, kemudian pilih Bagikan. Projek dihantar sebagai ZIP melalui aplikasi perkongsian (WhatsApp, Telegram, dan lain-lain). Untuk menerima projek daripada rakan: buka menu dalam Kelola Project, pilih Impor proyek, kemudian pilih fail ZIP-nya. Fail ZIP tersebut mesti berisi fail data projek — jika tiada, fail ditolak dengan mesej yang jelas, kerana fail tersebut bukan projek Create Aplikasi. Jika nama projek sudah wujud, aplikasi akan bertanya: Timpa proyek lama, atau simpan dengan Nama baru.

Carian dan Penapis Projek
Jika projek sudah banyak, dalam Kelola Project terdapat kotak carian dan penapis jenis. Taip nama projek dalam kotak carian, senarai terus ditapis (huruf besar dan kecil tidak dibezakan). Penapis jenis mengehadkan senarai kepada satu jenis sahaja: Semua, HTML, Situs Web, Java, Kotlin, Compose, atau Python. Menu setiap projek tetap dapat dibuka seperti biasa daripada senarai yang sudah ditapis.

Bina Aplikasi dengan Suara
Jika anda tidak mahu menaip, gunakan suara: tekan Bina dengan Suara dalam menu utama, kemudian ucapkan arahan. Arahan yang boleh diucapkan: "Buat proyek kalkulator", "Bangun proyek Kalkulator", "Buka proyek Kalkulator", "Jalankan proyek Kalkulator", "Daftar proyek", "Buka ikon", "Kembali" dan "Bantuan". Aplikasi menjawab dengan suara dan teks, jadi ia masih boleh digunakan tanpa melihat skrin. Pengecaman suara menggunakan aplikasi pengecaman suara terbina dalam telefon (percuma; boleh berjalan luar talian jika pek bahasa Indonesia dipasang). Jika telefon tiada pengecaman suara, arahan boleh ditaip dalam kotak teks pada skrin yang sama.

AI Pembina Aplikasi
Tulis atau dikte aplikasi yang dikehendaki pada skrin AI Pembina Aplikasi, contohnya: «aplikasi catatan dengan butang simpan». Aplikasi menganalisis kata kuncinya di dalam HP sendiri (tanpa internet, tanpa kos), kemudian mencipta projek sebenar daripada templat yang paling sesuai: kalkulator, catatan, senarai tugas, kalkulator web, tapak profil, atau pembilang. Jika huraian anda belum mempunyai templat yang sesuai, aplikasi mencipta projek kosong dan menjelaskannya dengan jujur — tidak berpura-pura faham. Projek hasil AI boleh dibuka terus dalam Urus Projek.

Pratonton Langsung ke HP Rakan
Untuk menunjukkan projek kepada rakan sebelum dibina: dalam Urus Projek, tekan lama nama projek, kemudian pilih Pratonton ke HP Rakan. Aplikasi mencipta pakej pratonton kecil yang mengandungi fail utama projek (index.html, MainActivity, atau main.py) beserta BACA-SAYA.txt yang mengandungi arahan dan info.txt. Pakej tersebut dihantar sebagai ZIP melalui WhatsApp atau Telegram. Rakan yang menerima boleh terus membuka pratonton: halaman HTML terbuka dalam pelayar, kod Java/Kotlin/Python dibaca sebagai teks.

Pasaran Projek
Pasaran Projek mengandungi projek contoh terbina dalam aplikasi yang boleh dipasang ke folder projek dengan satu ketikan: Kalkulator, Catatan, Senarai Tugas, Kalkulator Web, Tapak Profil, Pembilang, Jam Digital, dan Kuiz Web. Pasaran dalam talian (muat turun contoh dari internet) belum tersedia, jadi pasaran ini mengandungi contoh yang sudah ada dalam aplikasi. Projek yang sudah dipasang boleh dibuka dan diubah dalam Urus Projek seperti projek buatan sendiri.

Kerjasama Langsung
Untuk mengerjakan projek bersama rakan: buka Kerjasama dalam menu utama, pilih projek, tulis catatan perubahan (apa yang diubah), kemudian tekan Kongsikan untuk Kolaborasi. Projek dihantar sebagai ZIP beserta fail CATATAN.txt di dalamnya. Rakan anda mengerjakannya lalu membalas ZIP-nya; anda menekan Terima Balasan, membaca dahulu catatan perubahannya, kemudian memilih Guna untuk menimpa projek lama atau Batal jika tidak jadi. ZIP yang tidak mengandungi CATATAN.txt bukan pakej kerjasama — untuk ZIP projek biasa, gunakan Import projek dalam Urus Projek.

Penterjemah Aplikasi Automatik
Untuk menterjemah teks dalam aplikasi ke bahasa lain: buka Penterjemah Aplikasi dalam menu utama, pilih projek dan bahasa sasaran (Inggeris, Arab, atau Jawa), kemudian tekan Terjemah. Kamus sudah ada dalam HP (tanpa internet, tanpa kos) dan mengandungi kata umum harian; teks daripada strings.xml, susun atur, dan kod dibaca kemudian diterjemah. Hasilnya ditulis ke folder values-bahasa/strings.xml (jika projek mempunyai strings.xml) dan laporan terjemahan-bahasa.txt dalam folder projek. Kata yang belum ada dalam kamus dibiarkan seadanya dan dilaporkan — supaya anda tahu kata mana yang masih perlu diterjemah sendiri.

Pembuat Permainan Tanpa Kod
Untuk membuat permainan tanpa menulis kod: buka Pembuat Permainan Tanpa Kod dalam menu utama, pilih jenis permainan (Teka Nombor, Kuiz, atau Tangkap Bintang), isi nama permainan, jumlah (aras/soalan/bintang), dan pesanan menang, kemudian tekan Buat Permainan. Permainan dibuat sebagai projek sebenar yang boleh terus dijalankan dalam Urus Projek dan dibina menjadi APK seperti projek lain.

Uji Aplikasi Automatik
Untuk memeriksa projek sebelum dibina: dalam Urus Projek, tekan lama nama projek kemudian pilih Ujian Automatik. IDE memeriksa 10 perkara tanpa membina APK — fail wajib ada (fail data projek, manifest, fail utama, susun atur, strings), nama pakej dan versi, kebenaran yang dipakai, ikon, dan keseimbangan kurungan kod. Hasilnya dipaparkan bagi setiap item (LULUS/GAGAL beserta pesanan) dan dibacakan oleh Jieshuo. Baiki dahulu semua yang GAGAL, kemudian tekan Bina projek.

AI Penyemak Kod
Untuk memeriksa kod projek daripada corak yang sering bermasalah: buka Semak Kod dalam menu utama, pilih projek, kemudian tekan Semak Kod. Penyemak berjalan dalam HP (tanpa internet) dan mencari pemboleh ubah tidak dipakai, fungsi kosong, gelung tanpa henti yang jelas, teks yang ditulis terus dalam kod (lebih baik dalam strings.xml), kebenaran dan API berbahaya, penanda TODO/FIXME, dan pelaksanaan dinamik. Setiap penemuan mengandungi nama fail, nombor baris, dan cadangan pembaikan. Penyemak ini berasaskan corak, bukan AI sebenar — masalah yang tidak bercorak tetap boleh terlepas.

Mod Belajar Interaktif
Untuk belajar membuat aplikasi langkah demi langkah: buka Belajar dalam menu utama. Terdapat 5 pelajaran: Membuat projek pertama, Menambah butang, Mengubah warna, Menambah bunyi, dan Membina APK. Ketik satu pelajaran untuk membaca penjelasannya dan tugas amalannya, lakukan tugas itu, kemudian tekan Semak tugas — IDE memeriksa dengan sebenar sama ada tugas sudah dilakukan (dengan mengimbas projek dan APK dalam HP anda). Pelajaran yang lulus ditanda selesai dan disimpan.

Segerak Cloud
Untuk membuat sandaran projek ke awan: buka Segerak Cloud dalam menu utama. Sandaran tempatan menyimpan ZIP projek ke folder Download/cloud dengan cap waktu, dan boleh dipulihkan pada bila-bila masa daripada senarai sandaran. Sandaran GitHub memuat naik ZIP projek ke repo peribadi anda (menggunakan token daripada Tetapan GitHub) dan boleh dimuat turun semula. Ini sandaran dan pemulihan manual — penyegerakan automatik dua hala sepenuhnya memerlukan pelayan, jadi belum tersedia.

Pembina Backend Automatik
Untuk membuat backend tanpa menulis kod pelayan: buka Pembina Backend dalam menu utama, pilih jenis backend (Catatan, Senarai Tugas, atau Papan Pesanan), isi nama projek, kemudian tekan Buat Backend. IDE membuat projek HTML sebenar dengan halaman borang dan senarai data yang tersimpan dalam storan tempatan HP (localStorage) — data tersimpan dan boleh dibaca semula apabila aplikasi dijalankan. Backend ini berjalan pada satu HP; dua HP belum dapat berkongsi data yang sama kerana tiada pelayan internet.

Pereka Tema Automatik
Untuk memberi tema warna pada projek: buka Pereka Tema dalam menu utama, pilih projek dan tema (Cerah, Gelap, Biru, Hijau, Merah, atau Ungu). Pratonton menunjukkan enam warna tema (primer, primer gelap, aksen, latar, teks, teks sekunder) dan dibacakan oleh Jieshuo. Tekan Kenakan Tema — IDE menulis colors.xml dan styles.xml (gaya app_theme) ke projek, dipakai terus apabila projek dijalankan atau dibina.

Pembuat Animasi
Untuk memberi animasi pada projek: buka Pembuat Animasi dalam menu utama, pilih projek, jenis animasi (Pudar, Gelongsor, Putar, Lantun, atau Denyut), tempoh (100 hingga 10000 milisaat), dan sasaran (butang, teks, atau gambar), kemudian tekan Buat Animasi. IDE menulis fail animasi sebenar (res/anim/anim_<jenis>.xml untuk projek Java/Kotlin/Compose, atau animasi.css untuk projek HTML/Tapak Web) beserta contoh kod penggunaannya yang dipaparkan pada skrin.

Perakam Tindakan
Untuk mengulang kerja secara automatik: IDE merekodkan tindakan yang dilakukan (buka projek, jalankan, bina, eksport, sandar, buat projek, simpan fail). Buka Perakam Tindakan dalam menu utama untuk melihat senarai tindakan yang direkod beserta rancangannya, kemudian tekan Main Semula — IDE menjalankan semula tindakan yang boleh diautomatikkan (sandar dan buat projek dijalankan di tempat; jalankan, bina, dan eksport membuka skrin utamanya; buka dan simpan membuka editor). Tindakan yang tidak boleh diautomatikkan dilangkau dan dilaporkan pada akhirnya.

Keselamatan Automatik
Untuk memeriksa keselamatan projek: buka Keselamatan Automatik dalam menu utama, pilih projek, kemudian tekan Semak Keselamatan. IDE memeriksa 8 perkara secara tempatan (tanpa internet): kebenaran berbahaya (lokasi, SMS, panggilan, kamera, mikrofon, kenalan), menghantar data melalui HTTP, menghantar SMS, panggilan keluar, kata laluan atau kunci yang ditulis terus dalam kod, WebView tanpa perlindungan, komponen yang dieksport tanpa kebenaran, dan alamat http tanpa penyulitan. Setiap penemuan diberi aras SELAMAT, AMARAN, atau BAHAYA beserta cadangan pembaikan, dan ringkasannya dibacakan oleh Jieshuo.

AI Luar Talian
Untuk memakai alat bantu teks dan kod tanpa internet: buka AI Luar Talian dalam menu utama. Terdapat 4 alat: Baiki Teks (huruf besar, tanda baca, dan ruang berganda), Ringkaskan Teks (mengambil 3 ayat yang paling penting), Buat Nama Aplikasi (daripada huraian yang ditulis), dan Cadangan Nama Pemboleh Ubah (mencari nama pemboleh ubah 1-2 huruf dalam projek). Ini peraturan ringkas dalam HP, bukan model AI sebenar. Hasil pembaikan teks boleh diterapkan pada strings.xml projek dengan butang Guna.

Pembuat Widget & Wallpaper
Untuk membuat widget skrin utama: buka Widget & Kertas Dinding dalam menu utama, pilih projek, isi teks widget, kemudian tekan Buat Widget. IDE menulis WidgetSaya.java, susun atur widget, maklumat widget, dan menambah penerima pada AndroidManifest.xml projek — bina projek, kemudian pasang widget daripada skrin utama HP. Untuk kertas dinding: isi tulisan dan warna latar serta warna tulisan, buat pratonton, kemudian simpan sebagai PNG ke folder Download atau terus pasang sebagai kertas dinding HP.

Integrasi Media Sosial
Untuk menambah butang perkongsian pada aplikasi: buka Integrasi Media Sosial dalam menu utama, pilih projek, kemudian tambah perkongsian ke WhatsApp, Facebook, atau Telegram (atau ketiga-tiganya sekali). IDE menulis kod perkongsian sebenar ke fail utama projek (MainActivity atau index.html). Butang Ujian Kongsi membuka pemilih perkongsian daripada IDE dengan teks contoh, supaya alirannya dapat dirasai sebelum membina aplikasi.

Aplikasi daripada Gambar
Untuk membuat aplikasi galeri daripada gambar: buka Aplikasi daripada Gambar dalam menu utama, pilih gambar daripada galeri. IDE menganalisis saiz dan warna dominan gambar, kemudian membuat projek aplikasi galeri sebenar: gambar disalin ke assets projek, warna tema diambil daripada warna dominan gambar, dan nama aplikasi diambil daripada nama fail gambar. Buka Urus Projek untuk menjalankan atau membina aplikasi galeri tersebut.

Terminal Interaktif (Penghurai VT)
Untuk memakai program interaktif dalam Terminal: buka Terminal dalam menu utama, kemudian jalankan nano, vim, top, atau htop. Terminal kini memakai penghurai VT (skrin grid 24 baris x 80 lajur) supaya program tersebut dipaparkan dengan betul — kursor bergerak, baris dipadam, dan skrin bertukar seperti dalam terminal sebenar. Terdapat butang khas Tab, Anak Panah Atas, Anak Panah Bawah, dan Esc untuk mengawal program interaktif. Keluaran tetap berupa teks yang boleh dibaca Jieshuo; tekan Bacakan skrin untuk mendengar baris terakhir.

Terminal Exec (Binari Aplikasi)
Untuk menjalankan binari dalam folder aplikasi (misalnya aapt2, ECJ, D8) daripada Terminal: taip perintahnya seperti biasa. IDE memakai libkautsarexec.so supaya binari dalam folder aplikasi boleh dilaksanakan pada Android 10 ke atas. Tekan Ujian Exec dalam Terminal untuk memeriksa sama ada laluan exec binari berjalan pada HP ini — hasilnya dipaparkan seadanya. Jika exec disekat oleh sistem, perintah sistem dan skrip shell tetap berjalan; jalankan binari melalui menu Bina projek sebaliknya.

Terminal Tetap Hidup (KeepAlive)
Untuk membiarkan shell terus berjalan semasa berpindah skrin: buka Terminal, jalankan perintah, kemudian tekan Kembali atau berpindah ke skrin lain — shell TIDAK mati, dan pemberitahuan Terminal tetap terpapar supaya anda boleh kembali dengan satu ketikan. Perintah yang sudah dijalankan tersimpan dalam sejarah (butang Sejarah, atau anak panah atas/bawah dalam ruangan perintah) dan perintah yang kerap dipakai boleh disimpan sebagai kegemaran (butang Kegemaran). Tekan Tutup shell apabila sudah selesai, supaya shell benar-benar dimatikan. Terdapat juga butang Bina di Terminal dalam menu projek dan dalam menu editor: Terminal dibuka dalam folder projek dengan perintah bina yang sudah diisi.

Pasang Alat Terminal (Uji Cuba)
Ciri yang masih dalam percubaan: dalam Terminal terdapat butang Pasang Alat Terminal untuk memasang persekitaran Termux daripada cermin dalam repositori alat-termux milik pembangun (github.com/syudat/alat-termux), sebagai laluan lain selain butang Pasang Termux yang mengambil daripada keluaran rasmi Termux. Kandungan cerminnya sama tepat dengan keluaran rasmi dan diperiksa dengan SHA-256 semasa pemasangan. Selepas persekitaran dipasang, perintah pkg update dan pkg install boleh dipakai, dan alat tambahan daripada repositori turut dipasang ke terminal: info-terminal untuk melihat maklumat persekitaran, bersih-terminal untuk membersihkan cache, dan cadangkan-proyek untuk mengarkibkan folder projek menjadi satu fail tar.gz bertarikh. Selepas itu aplikasi memasang automatik pakej Linux asas (git, python, curl, wget, nano, openssh, zip, unzip) dan alat bina APK beserta tanda tangan (openjdk-21, kotlin, gradle, ecj, aapt2, d8, apksigner, clang, cmake, ninja, make) daripada repositori rasmi Termux, jadi terminal terus bersedia dipakai membina aplikasi. Muat turun pakej besar (ratusan MB) boleh mengambil masa yang lama. Semasa pemasangan berjalan, kemajuan dan keluaran perintah terpapar pada skrin utama Terminal, dan hasil akhirnya dibacakan oleh pembaca skrin. Jika pemasangan pakej belum selesai, tekan Pasang Alat Terminal sekali lagi untuk meneruskannya.

Mod Suara Penuh
Untuk mengawal IDE sepenuhnya dengan suara: buka Mod Suara Penuh dalam menu utama, kemudian tekan Mula Mendengar. IDE mendengar secara berterusan — tidak perlu menekan butang bagi setiap perintah — menjalankan perintah dan menjawab dengan suara. Terdapat 26 perintah: buat, bina, buka, jalankan, senarai, cari, padam, uji, periksa, eksport, sandar, kongsi, buat ikon, terjemah, bina dalam terminal, baca skrin, buka semua skrin (termasuk keselamatan, AI luar talian, widget, media sosial, permainan, belajar, awan, backend, tema, animasi, perakam), kembali, tutup, dan bantuan. Jika mod ditinggalkan aktif, mendengar diteruskan automatik apabila skrin ini dibuka semula. Tekan Berhenti Mendengar untuk mematikan mod ini. Jika HP tidak mempunyai perkhidmatan pengecaman suara, perintah tetap boleh ditulis dalam kotak teks.

Penterjemah Kod
Untuk menterjemah kod antara bahasa tanpa internet: buka Penterjemah Kod dalam menu utama, pilih projek, pilih fail sumber (.java/.kt), kemudian pilih arah: Java ke Kotlin. Tekan Terjemah — hasilnya dipaparkan beserta laporan baris yang tidak dapat diterjemah (baris tersebut disimpan seadanya dan ditanda). Tekan Simpan hasil untuk menulis fail BAHARU (nama-terjemahan.java/.kt) dalam folder yang sama; fail asal tidak pernah ditimpa. Ini penterjemah peraturan corak, bukan pengkompil — sentiasa periksa hasil sebelum dipakai.

Git dalam Aplikasi
Untuk memakai Git dalam IDE tanpa Termux: buka Git dalam Aplikasi dalam menu utama, pilih projek, kemudian tekan Buat Repo Git untuk membuat repo tempatan (.git) dalam projek tersebut. Tekan Semak Status untuk melihat fail baharu, berubah, atau dipadam berbanding commit terakhir; isi pesanan commit kemudian tekan Commit untuk menyimpan snapshot projek; tekan Lihat Log Commit untuk melihat sejarah commit. Push ke GitHub dan Pull dari GitHub memakai snapshot melalui token GitHub (repo pembuat-aplikasi-build) — bukan protokol git. Clone, Push (git sistem), dan Pull (git sistem) hanya berjalan jika binari git terpasang pada HP (biasanya tiada). Ini bukan git penuh: tiada merge, branch, atau diff — setiap commit menyimpan snapshot ZIP penuh projek.

Pembuat Iklan
Untuk menambah iklan pada aplikasi hasil: buka Pembuat Iklan dalam menu utama, pilih projek, penyedia (AdMob, Unity Ads, atau AppLovin), dan jenis iklan (Banner, Interstitial, atau Rewarded). Isi ID unit iklan jika sudah ada — kosong bermaksud memakai ID ujian (AdMob memakai ID ujian rasmi Google; Unity memakai Game ID contoh; AppLovin memakai ruang kosong). Tekan Buat Kod Iklan untuk melihat kod Java, Kotlin, dan panduan; tekan Simpan ke Projek untuk menulis semuanya ke fail iklan-<penyedia>-<jenis>.txt dalam projek. Ini templat kod + panduan, bukan SDK iklan — SDK tidak disertakan dalam IDE; iklan sebenar hanya tampil selepas anda membuat akaun penyedia, membuat unit iklan, menampal ID unit sendiri, dan menambah kebergantungan SDK dalam build.gradle projek.

Mod Kanak-kanak
Untuk memakai IDE bersama anak: buka Mod Kanak-kanak dalam menu utama. Skrinnya dipermudahkan dengan butang besar dan hanya 4 tindakan selamat: Cipta Projek (daripada templat selamat: Kalkulator, Teka Nombor, Kuiz, Tangkap Bintang), Buka Projek, Jalankan, dan Belajar. Tiada butang padam, eksport, sandaran, atau tetapan token pada skrin ini. Apabila pertama kali masuk, buat PIN 4 angka — PIN tersebut dipakai ibu bapa untuk keluar daripada Mod Kanak-kanak (butang Keluar dari Mod Kanak-kanak atau butang Kembali). PIN ini perlindungan ringan untuk kanak-kanak kecil, bukan keselamatan sebenar.

Pembuat Aplikasi Wear OS & TV
Untuk membuat aplikasi jam (Wear OS) atau TV (Android TV): buka Wear OS & TV dalam menu utama, pilih sasaran (Wear OS, Android TV, atau kedua-duanya). Isi nama projek kemudian tekan Buat Projek Baru Wear/TV — IDE membuat projek Java kemudian menyesuaikannya — atau pilih projek yang sudah ada kemudian tekan Kenakan pada Projek Ini. Penyesuaian: uses-feature dalam manifest, kategori LEANBACK_LAUNCHER + banner untuk TV, dan susun atur activity_main.xml yang disesuaikan (Wear: skrin kecil; TV: skrin besar mesra D-pad). Penjelasan lengkap ditulis ke wear-tv.txt dalam projek. Ini templat projek — bina + uji tetap memerlukan peranti/emulator Wear OS atau Android TV; banner TV (banner.png 320x180) tidak dibuat automatik, perlu ditambah sendiri (contohnya melalui Pembuat Ikon).

Peta Projek
Untuk melihat struktur sesebuah projek: buka Peta Projek dalam menu utama, pilih projek, kemudian tekan Tunjukkan Peta — IDE menampilkan senarai folder dan fail beserta saiznya, jumlah saiz, saiz mengikut jenis fail, dan fail penting (fail utama, manifest, susun atur, strings, ikon, halaman web). Tekan Simpan peta-proyek.txt untuk menulis peta yang sama ke akar projek. Folder bin/ (hasil bina) dan .git/ (repo tempatan) tidak dipetakan kerana kandungannya boleh dibuat semula.

Kalkulator Saiz APK
Untuk menganggarkan saiz APK hasil bina sebelum membina: buka Kalkulator Saiz APK dalam menu utama, pilih projek, kemudian tekan Kira Anggaran. IDE menampilkan perincian mengikut kategori (kod/DEX, sumber, aset, pustaka native, manifest + resources.arsc, overhed), jumlah anggaran, 5 fail terbesar, dan cadangan mengecilkan (contohnya gambar besar dikecilkan resolusinya, bunyi besar dipotong tempohnya). Ini ANGGARAN, bukan saiz tepat — saiz sebenar boleh berbeza kerana pemampatan aapt2, pemadaman kod tidak dipakai (R8), dan sumber hasil bina.

Penganalisis APK
Untuk membaca kandungan APK yang sudah siap (seperti Penganalisis APK dalam Android Studio): buka Penganalisis APK dalam menu utama, pilih projek, kemudian tekan Analisis APK Hasil Binaan. IDE membaca APK terkini dalam folder bin projek itu dan melaporkan nama pakej, versi, SDK minimum dan sasaran, senarai kebenaran yang dipakai, bilangan fail dex, perincian saiz mengikut bahagian (kod program, sumber, aset, pustaka native, tanda tangan), dan 10 entri terbesar. Berguna untuk mengetahui bahagian mana yang menjadikan APK besar dan kebenaran apa yang dipakai aplikasi hasil.

Pratonton Saiz Skrin
Untuk memeriksa penampilan projek pada banyak saiz skrin sekaligus (seperti dalam Android Studio): buka Pratonton Saiz Skrin dalam menu utama, pilih projek, kemudian tekan Semak Saiz Skrin. IDE membaca semua susun atur projek dan melaporkan elemen yang lebarnya ditulis tetap (contohnya 400dp) dan melebihi lebar skrin 320, 360, 411, atau 480 dp, kerana pada HP berskrin kecil elemen seperti itu boleh tertutup atau melimpah. Elemen dengan lebar match_parent atau wrap_content menyesuaikan skrin secara automatik dan tidak perlu diperiksa.

Pengurus Sumber
Untuk melihat dan mengurus semua sumber projek di satu tempat (seperti Pengurus Sumber dalam Android Studio): buka Pengurus Sumber dalam menu utama, pilih projek, kemudian tekan Lihat Sumber. IDE melaporkan bilangan dan saiz fail mengikut kategori (drawable, layout, values, mipmap, dan lain-lain), kandungan strings.xml, colors.xml, dan styles.xml. Daripada skrin yang sama, rentetan baharu boleh ditambah ke strings.xml dan warna baharu ke colors.xml dengan mengisi nama dan nilainya — nama diperiksa dan pendua ditolak, supaya fail XML tidak rosak.

Pemantau Prestasi Ringan
Untuk memantau penggunaan RAM dan pemproses aplikasi yang sedang berjalan (seperti Profiler dalam Android Studio, versi ringan): buka Pemantau Prestasi Ringan dalam menu utama, jalankan dahulu aplikasi yang hendak diperiksa (contohnya aplikasi hasil bina yang sedang dicuba), isi nama pakejnya — atau pilih projek kemudian tekan Isi Nama Pakej dari Projek — kemudian tekan Mula Pantau. Setiap 2 saat IDE mencatat RAM (PSS) dan CPU aplikasi itu beserta RAM HP yang bebas; tekan Berhenti untuk melihat ringkasan purata dan puncaknya. Tanpa kebenaran tambahan. Dalam Android versi baharu, akses baca pemproses aplikasi lain dihadkan sistem, jadi jika CPU tidak terbaca, laporan menyebutnya seadanya dan RAM tetap terpantau.

Audit Kebolehcapaian
Untuk memeriksa sama ada susun atur projek mesra pembaca skrin (TalkBack/Jieshuo) sebelum dikeluarkan: buka Audit Kebolehcapaian dalam menu utama, pilih projek, kemudian tekan Muatkan Senarai Susun Atur dan pilih fail susun atur. IDE membaca fail XML itu dan melaporkan butang tanpa label berserta nombor barisnya, label yang digunakan berulang kali, dan elemen yang saling bertindih, kemudian menyusun transkrip susunan fokus seperti yang dibacakan oleh Jieshuo. Jika ada butang tanpa label, isikan labelnya kemudian tekan Sisipkan Label Secara Automatik — label ditulis ke dalam fail susun atur sebagai contentDescription. Pemeriksaan ini hanya membaca XML susun atur; paparan Compose dan APK yang sudah siap belum diimbas.

Autopsi Ranap
Untuk mengetahui mengapa aplikasi menutup sendiri, daripada log ranap dengan ID unik: buka «Autopsi Ranap» dalam menu utama, pilih ID ranap daripada senarai log, kemudian tekan «Periksa». IDE memadankan kelas dan nombor baris dalam log dengan sumber projek dan menerangkan sebabnya dalam bahasa Indonesia (contohnya rujukan kosong, kebenaran belum diminta, atau ralat JSON), beserta cadangan tampalan kod. Tekan «Terapkan Tampalan» hanya apabila baris sumber masih sama persis seperti ketika ranap berlaku; jika ia berubah, tampalan ditolak dan IDE meminta anda memeriksa sendiri. Bagi ranap aplikasi yang dibina, tekan «Suntik Penangkap Ranap ke dalam Projek», kemudian bina APK seperti biasa: aplikasi yang dibina itu menangkap ranapnya sendiri dan menulis lognya pada telefon, dan log itu boleh ditemui dengan butang «Cari Log Ranap Aplikasi yang Dibina». Had yang jujur: menyalin log ke folder Download awam pada Android 11 ke atas boleh gagal tanpa kebenaran akses semua fail.

Transpiler Lintas Paradigma
Untuk menukar kod Java yang mudah kepada Kotlin, atau susun atur XML yang mudah kepada kod Compose: buka Transpiler Lintas Paradigma dalam menu utama, pilih projek dan fail, kemudian tekan Pratonton. IDE memaparkan hasil penukaran sebagai teks — semak dahulu, kerana baris yang tidak dikenali dibiarkan begitu sahaja dan perkataan static dalam Java digugurkan dalam Kotlin (semak maknanya sebelum menggunakannya). Penukaran XML kepada Compose hanya mengubah teks, pembayang dan orientasi — saiz, warna dan atribut lain belum disertakan. Jika hasilnya sudah betul, tekan Terapkan ke Fail untuk menulis fail sasaran; fail sumber tidak diubah. Hanya pola umum yang selamat ditukar.

Pelayan Mikro Tempatan
Untuk menguji aplikasi yang memerlukan pelayan tanpa internet: buka «Pelayan Mikro Tempatan» dalam menu utama, tulis takrifan laluan (contohnya GET /halo kemudian jawapan JSONnya), kemudian tekan «Mula Pelayan». IDE menjalankan pelayan HTTP kecil pada telefon yang sama (HTTP sahaja, tanpa TLS, untuk rangkaian Wi-Fi yang sama) dan merekodkan setiap permintaan dan jawapan pada skrin. Laluan boleh menggunakan parameter seperti {nama} dan kunci API mudah. Pelayan juga boleh dibungkus ke dalam APK yang dibina: tekan «Pakej Pelayan ke dalam Projek», dan sumber pelayan, aset dan manifes disuntik ke dalam projek, jadi aplikasi yang dibina itu sendiri menjadi pelayan apabila berjalan. Pelayan dalam IDE berhenti apabila skrinnya ditutup.

Pengaudit Keselamatan
Untuk memeriksa kod projek bagi jurang keselamatan sebelum keluaran: buka «Pengaudit Keselamatan» dalam menu utama, pilih projek, kemudian tekan «Mula Imbasan». IDE mengimbas kod projek, manifes dan konfigurasi dan melaporkan dapatan daripada risiko tinggi ke rendah — kunci API yang ditinggalkan terbuka dalam kod, komponen yang didedahkan tanpa kebenaran, WebView yang mendayakan JavaScript bersama antara muka JavaScriptnya, kripto lemah (MD5, SHA1, DES), alamat http tanpa TLS, dan kata laluan yang ditulis terus dalam kod — beserta fail dan nombor barisnya. Bagi dapatan yang pembaikannya selamat (contohnya tukar MD5 kepada SHA-256 atau http kepada https), tekan «Terapkan Pembaikan»; bagi kunci API dan kata laluan, IDE hanya memaparkan cadangan pembaikan kerana penggantinya mesti diputuskan oleh pembangun sendiri. Imbasan kini juga menganalisis bytecode DEX sebenar di dalam APK yang dibina (bukan hanya corak teks dalam kod), jadi API berbahaya yang dipanggil dan rahsia yang terbenam dalam DEX juga ditangkap; jurang yang tidak mengikut corak masih boleh terlepas daripada imbasan — periksa sebelum digunakan.

Robot Penguji Antara Muka
Untuk menguji skrin aplikasi secara automatik melalui senario teks: buka «Robot Penguji Antara Muka» dalam menu utama, pilih projek, kemudian tekan «Buat Senario Automatik». IDE membaca manifes dan susun atur projek dan menulis senario sebagai langkah teks (tekan butang, isi medan, tunggu, kembali). Tekan «Jalankan Dry Run» untuk melihat log larian senario bersama cap waktunya — dry run ini masih hanya simulasi urutan. Untuk ujian sebenar, tekan «Suntik Ejen Ujian ke dalam Projek»: IDE menyuntik ejen ujian bersama aset senario ke dalam projek; bina APK seperti biasa, pasang, kemudian buka ikon «Ujian» — ejen itu berjalan di dalam aplikasi yang dibina dan benar-benar menekan butang, mengisi medan sebenar, dan menatal, kemudian memaparkan laporannya pada skrin bersama ranap sebenar yang ditangkapnya. Tekan «Buang Ejen Ujian dari Projek» untuk membuang ejen itu semula. Ejen berjalan di dalam proses aplikasi itu sendiri, jadi ia tidak memerlukan perkhidmatan kebolehcapaian atau automasi sistem.

Perjalanan Masa Kod
Untuk mengembalikan projek kepada keadaan kod sebelumnya tanpa menaip arahan Git: buka Perjalanan Masa Kod dalam menu utama, pilih projek, isi label titik masa (boleh kosong), kemudian tekan Rekod Titik Masa. IDE menyimpan salinan fail sumber projek berserta hash-nya dalam folder .riwayat di dalam projek. Senarai titik masa memaparkan semuanya; pilih dua titik kemudian tekan Bandingkan untuk melihat fail dan fungsi yang ditambah, diubah atau dipadam. Tekan Pulihkan untuk mengembalikan keadaan lama — sebelum memulihkan, IDE sentiasa membuat sandaran keadaan semasa dahulu, jadi tiada apa-apa yang hilang. Tekan Buat Salinan Uji Kaji untuk menyalin projek ke folder baharu dan mencuba perubahan tanpa mengganggu projek asal. Hanya fail sumber direkodkan.

Kilang Modul
Untuk membungkus sebahagian projek menjadi modul yang boleh digunakan oleh projek lain: buka Kilang Modul dalam menu utama, pilih projek sumber, tandakan fail skrin, kelas, rentetan dan kebenaran yang mahu dibungkus, kemudian tekan Bungkus sebagai Modul. IDE menulis arkib ZIP berserta metadata JSON (nama modul, versi, rentetan dan kebenaran yang digunakan). Untuk memasang modul ke projek lain, buka Kilang Modul, pilih projek sasaran, kemudian tekan Pasang Modul dan pilih fail .zip modul itu — penggabungan menambah rentetan dan kebenaran tanpa menimpa kod yang sudah ada, dan tidak menggabungkan fail jika namanya sudah digunakan dalam projek sasaran. Modul tidak membawa pustaka atau tetapan binaan.

Perisai Polimorfik dan Peti Besi Aset
Untuk merawakkan nama pengecam dan mengenkripsi aset projek sebelum keluaran: buka «Perisai Polimorfik dan Peti Besi Aset» dalam menu utama, pilih projek, kemudian tekan «Rawakkan nama dan enkripsi aset». IDE mengimbas nama kelas dan kaedah dalam kod sumber, membina peta nama rawak, menulis semula nama itu di dalam fail DEX yang telah dikompilasi (nama gantian dibuat sama panjang dengan nama asal supaya semua offset kekal sah, kemudian checksum dan tandatangan SHA-1 pengepala DEX dikira semula), mengenkripsi fail aset projek dengan AES-GCM dalam folder brankas-aset di dalam projek, dan menyimpan peta pemulihan terenkripsi (perisai-peta.brankas) supaya nama asal dapat dipulihkan ketika membaca log ranap. Kunci enkripsi kini diterbitkan daripada kata laluan pembangun menggunakan PBKDF2 sebanyak 20,000 lelaran, bukan lagi daripada nama projek. Nama yang juga digunakan sebagai teks biasa, nama anotasi dan nama penyahpepijatan sengaja tidak ditulis semula, dan titik sisipan penulisan semula DEX dalam laluan binaan masih menunggu ujian pada telefon sebenar.

Rantai Kepercayaan dan Penjaga Persekitaran
Untuk memeriksa rantaian kunci tandatangan dan persekitaran telefon sebelum keluaran: buka «Rantai Kepercayaan dan Penjaga Persekitaran» dalam menu utama, pilih projek, kemudian tekan «Periksa Rantai dan Persekitaran». IDE membina rantaian kunci 5 generasi daripada nama pakej projek dan memeriksa keutuhannya, memeriksa keutuhan memori sebenar dengan membandingkan kandungan bahagian kod dalam memori dengan fail pada cakera dan melaporkan pemetaan boleh laku tanpa nama (RWX), pustaka asing dan pemetaan memfd, kemudian mengimbas peta memori prosesnya sendiri dan sifat peranti untuk jejak Frida, Xposed atau emulator. Kunci peti besi dibalut dengan kunci AES dalam AndroidKeyStore yang menggunakan cip keselamatan perkakasan apabila tersedia, dan putaran kunci kini benar, menggunakan keturunan sijil tandatangan skema v3: kunci lama menandatangani bukti putaran kepada kunci baharu dan APK ditandatangani semula dengan keturunan itu. Hasilnya ialah tahap risiko «selamat», «berhati-hati» atau «berbahaya» berserta bukti teks. Jika sistem menolak membaca memori, pemeriksaan dilaporkan sebagai «tidak dapat disahkan», bukan selamat; dan sama ada kunci benar-benar menggunakan cip keselamatan perkakasan hanya boleh disahkan pada peranti sebenar.

Arkitek Susun Atur Pepohon Teks
Untuk mereka bentuk skrin tanpa melihatnya: buka «Arkitek Susun Atur Pepohon Teks» dalam menu utama, pilih projek dan fail susun atur, kemudian tekan «Periksa Susun Atur». IDE membaca susun atur XML sebagai pepohon teks dan membacakan dengan lantang naratif kedudukan setiap elemen (contohnya bawah kanan, 45 peratus lebar skrin), kemudian melaporkan secara matematik pertindihan antara elemen dan elemen yang keluar dari skrin pada lebar 360 dp. Apa yang kini dikira termasuk LinearLayout dan saiz dp ringkas, ConstraintLayout penuh (semua kekangan, berat sebelah, rantaian, panduan, halangan, lebar peratusan, 0dp match_constraint dan nisbah dimensi) dan skrin Compose (Column, Row dan Box beserta pengubah saiznya). Hanya MotionLayout dan ConstraintSet yang berubah semasa berjalan masih dilaporkan sebagai kedudukan tidak diketahui, kerana nilainya hanya wujud ketika aplikasi sedang berjalan.

Studio Sistem Reka Bentuk
Untuk menyelaraskan jarak, huruf dan sudut pada semua skrin dan projek: buka «Studio Sistem Reka Bentuk» dalam menu utama, pilih projek, tulis token reka bentuk (contohnya jarak=8, huruf=16, sudut=12), pilih komponen, kemudian tekan «Hasilkan Komponen». IDE mengesahkan token — jarak asas 4 hingga 16 dp, huruf asas 12 hingga 20 sp, sudut 0 hingga 32 dp, dan kawasan sentuh minimum 48 dp — kemudian menulis komponen XML sedia guna (komponen-studio.xml) bersama tema XML (tema-studio.xml) dan tema Compose (tema-studio.kt) ke dalam folder projek. Token juga boleh disimpan sebagai set bernama dalam pustaka token yang dikongsi antara projek, dan satu arahan selaras menggunakan token terkini pustaka pada semua projek yang menggunakan set itu. Komponen dibina sebagai teks yang ditampal ke dalam susun atur kemudian diperiksa dengan «Arkitek Susun Atur Pepohon Teks»; pelarasan dua lajur pada tablet menggunakan pengkelas lebar skrin, bukan pengesanan peranti semasa berjalan.

Pemfaktoran Semula Semantik dan Navigasi AST
Untuk mencari takrifan dan menukar nama simbol tanpa merosakkan kod lain yang kebetulan mempunyai nama sama: buka «Pemfaktoran Semula Semantik dan Navigasi AST» dalam menu utama, pilih projek, kemudian tekan «Imbas Simbol Projek» untuk melihat semua kelas dan kaedah beserta fail dan nombor barisnya. Taip nama simbol, kemudian tekan «Imbas Simbol Projek» sekali lagi untuk melihat takrifannya dan semua fail yang memanggilnya. Untuk menukar nama, taip nama baharu, tekan «Pratonton Tukar Nama» untuk melihat bilangan kemunculan dalam setiap fail, kemudian tekan «Terapkan Tukar Nama». Pengindeks kini menggunakan penghurai AST buatan sendiri (penganalisis leksikal dan penghurai rekursif untuk Java dan subset Kotlin), jadi penukaran nama kaedah antara fail diselesaikan dan pemanggil dalam fail lain juga berubah; butang mengeluarkan blok kod kepada fungsi baharu kini ada pada skrin ini. Penghurai ini masih minimum: generik yang sangat kompleks, anotasi berparameter dan kelas tanpa nama diimbas seadanya, manakala panggilan melalui refleksi dan melalui antara muka tidak diselesaikan.

Penyahpepijat Langkah dan Pemeriksa Memori
Untuk memeriksa kandungan pemboleh ubah di tengah aliran program tanpa meneka daripada log: buka «Penyahpepijat Langkah dan Pemeriksa Memori» dalam menu utama, pilih projek, tulis jejak pelaksanaan (satu langkah setiap baris, bentuk nombor baris, kod, kemudian pemboleh ubah dan nilai dipisahkan dengan |, contohnya 10|int total = harga * jumlah;|harga=5000, jumlah=3, total=15000), taip nombor baris titik henti, kemudian tekan «Jalankan Jejak Penyahpepijatan». IDE berjalan sehingga titik henti pertama dan membacakan dengan lantang baris aktif beserta nilai pemboleh ubahnya melalui Jieshuo. Tekan «Langkah Satu Baris» untuk mara satu baris, «Masuk ke fungsi» untuk masuk ke fungsi yang dipanggil (dengan timbunan panggilan), atau «Teruskan Program» untuk mara ke titik henti seterusnya. Penyahpepijat jejak ini masih mengikut jejak yang dirakam atau ditulis tangan; di sampingnya ada pelanggan Java tulen bagi protokol wayar JDWP yang boleh berjabat tangan, menetapkan titik henti, melangkah masuk, melangkah atas dan melangkah keluar, serta menghentikan dan meneruskan VM melalui TCP atau dalam mod mendengar. Menghentikan proses sebenar dari dalam aplikasi biasa masih belum mungkin sepenuhnya, kerana soket JDWP sesuatu proses hanya didedahkan melalui adbd — laluan yang terbukti memerlukan penyahpepijatan wayarles dan pelancaran sasaran melalui shell, di luar apa yang aplikasi sendiri boleh lakukan.

Pengurus Kebergantungan Luar Talian
Untuk menggunakan pustaka pihak ketiga tanpa internet dan mengelakkan konflik versi sebelum binaan: buka «Pengurus Kebergantungan Luar Talian» dalam menu utama, pilih projek, kemudian tekan «Periksa Kebergantungan». IDE membaca semua fail .gradle projek, memeriksa peti besi yang dikongsi antara projek dalam folder Download/brankas-bersama, dan menyelesaikan konflik — jika dua pustaka meminta versi berbeza bagi artifak yang sama, versi tertinggi digunakan dan konflik dilaporkan. Untuk memuat turun pustaka, taip koordinatnya (bentuk kumpulan:artifak:versi, contohnya com.google.code.gson:gson:2.10.1) kemudian tekan «Periksa Kebergantungan»: ketika dalam talian, fail AAR, JAR atau WHL benar-benar dimuat turun dari Maven, Google atau PyPI bersama graf kebergantungan transitifnya (rekursif, kitaran diputuskan, kedalaman sehingga 25 aras), dan hanya fail yang berjaya dimuat turun direkodkan sebagai tersedia. Ketika luar talian hanya pustaka yang sudah ada dalam peti besi dikongsi boleh digunakan. Julat versi Maven tidak diselesaikan, dan fail yang dimuat turun hanya diperiksa dengan SHA-1nya, tanpa pengesahan PGP.

Pemeriksa Pangkalan Data dan Storan
Untuk memeriksa dan menguji kandungan pangkalan data projek tanpa menulis kod yang mencetak kandungan jadual: buka «Pemeriksa Pangkalan Data dan Storan» dalam menu utama, pilih projek dan fail pangkalan data (.db, .sqlite atau .sqlite3), kemudian tekan «Buka Pangkalan Data». IDE membaca skema semua jadualnya dengan penghurai halaman SQLite penuh (pohon-B dengan halaman limpahan) dan memaparkan 20 baris pertama sebagai jadual teks yang dibacakan dengan lantang oleh Jieshuo. Tulis pertanyaan SELECT kemudian tekan «Jalankan Pertanyaan» (contohnya SELECT nama FROM pengguna WHERE kota = 'Makassar') — pertanyaan kini menyokong JOIN, GROUP BY, ORDER BY dan LIKE, dan pada telefon berjalan melalui enjin SQLite sebenar Android. Untuk menukar nilai, taip nombor baris (1 = baris pertama), nama lajur dan nilai baharu, kemudian tekan «Tukar Nilai Sel» — nilai itu ditulis semula ke dalam fail .db. Tekan «Simpan Sandaran» untuk menyimpan keadaan semasa jadual sebagai fail <nama-pangkalan-data>.cadangan.txt dalam projek. SharedPreferences dan DataStore juga boleh dibaca. Apa yang masih tidak boleh dibaca: pangkalan data terenkripsi, perubahan WAL yang belum dikomit, dan nilai bertipe dalam DataStore Proto khas (hanya dipaparkan sebagai pandangan medan umum).

Kilang Ujian Unit dan Fuzzing
Untuk mencari jurang logik sebelum berkongsi aplikasi: buka «Kilang Ujian Unit dan Fuzzing» dalam menu utama, pilih projek dan fail kod, kemudian tekan «Bina dan Jalankan Ujian». IDE membaca tandatangan fungsi dalam fail, membina kes ujian biasa dan sempadan (teks kosong, null, nombor maksimum, aksara pelik), kemudian benar-benar menjalankan ujian itu: kod projek dikompilasi dan setiap kaedah @Test dilaksanakan dengan had 5 saat, jadi hasilnya ialah lulus dan gagal sebenar beserta nilai sebenarnya. Fuzzing juga benar-benar berjalan ke atas fungsi projek (melalui refleksi, 2 saat setiap panggilan, maksimum 20 kaedah), dan peratusan liputan baris benar-benar dikira melalui instrumentasi yang mengekalkan nombor baris asal. Hasilnya melaporkan berapa ujian lulus dan gagal, berapa baris kod dan fungsi ditemui, dan kes ujian apa yang dibina. Ujian yang dibina menggunakan API yang sama persis seperti JUnit, tetapi takrifan anotasi dan penegasan ditulis di dalam fail ujian yang dibina itu sendiri, kerana pustaka JUnit sebenar tidak disertakan dalam aplikasi.

Simulator Keadaan Peranti Melampau dan Auditor Kebocoran Memori
Untuk menguji ketahanan aplikasi apabila sistem mematikan prosesnya, rangkaian terputus, skrin berputar, atau penjimatan bateri dihidupkan: buka «Simulator Keadaan Peranti Melampau dan Auditor Kebocoran Memori» dalam menu utama, pilih projek, kemudian tekan «Jalankan Simulasi». IDE menjalankan tiga senario tekanan bersama simulasi putaran skrin dan menjejaki objek yang masih dipegang dalam memori selepas skrinnya ditutup, kemudian melaporkan data yang hilang dan rantaian objek yang bocor. Keadaan simpan dan pulih kini dibaca daripada sumber projek pengguna sendiri, bukan contoh tetap; pelayan loopback tempatan benar-benar dihentikan di tengah ujian untuk mengukur putusan rangkaian; heap dump sebenar diambil dan dianalisis untuk membandingkan dua dump dan menjejaki rantaian pegangan daripada akar GC; dan proses aplikasi itu sendiri benar-benar dimatikan selepas menyimpan keadaannya, kemudian diperiksa data apa yang kembali apabila dibuka semula. Apa yang masih mustahil daripada aplikasi biasa: mematikan radio atau Wi-Fi telefon dan menghentikan paksa aplikasi lain — kedua-duanya memerlukan kebenaran sistem; sebaliknya, aplikasi latar belakang dimatikan melalui killBackgroundProcesses yang kebenarannya sudah ada dalam manifes, dengan label jujur pada skrin.

Arkitek Pelan Tindakan Projek
Untuk menukar idea aplikasi besar kepada pelan kerja langkah demi langkah: buka «Arkitek Pelan Tindakan Projek» dalam menu utama, pilih projek, tulis idea aplikasi (contohnya aplikasi juruwang kedai runcit kecil dengan ansuran), kemudian tekan «Bina Pelan Tindakan». IDE membina modul, senarai fail dan pencapaian kecil, kemudian menyimpannya sebagai cetak-biru.txt dalam folder projek. Setiap kali pencapaian selesai, tekan «Tandakan Pencapaian Seterusnya Selesai», atau tekan «Muat Pelan Tindakan Tersimpan» untuk membuka semula pelan tindakan yang disimpan. Jika penyedia AI aktif dipilih dalam «Tetapan AI» dan kuncinya tersedia, pelan tindakan dibina oleh penyedia itu; jika tiada kunci atau penyedia tidak dapat dicapai, IDE kembali kepada corak kata kunci luar talian dan menyatakan had itu dengan jujur. Jawapan penyedia hanya diperiksa dari segi format (modul dan pencapaian wujud), bukan kebenaran kandungannya — sentiasa semak pelan tindakan sebelum membina.

Pencerita Aliran Logik Kod
Untuk memahami kod yang panjang tanpa mendengar sintaks baris demi baris: buka «Pencerita Aliran Logik Kod» dalam menu utama, pilih projek dan fail kod, kemudian tekan «Narasi Kod». IDE menukar setiap baris kepada ayat Indonesia (contohnya jika jumlah melebihi 100000, jalankan blok seterusnya), memaparkan peta panggilan antara kaedah dan analisis aliran data antara kaedah (nilai yang diteruskan, digunakan atau diabaikan), dan menandakan pepijat halus yang mungkin beserta nombor barisnya — String yang dibandingkan dengan ==, strim yang dibuka tanpa ditutup, dan pemboleh ubah yang ditulis dalam dua kaedah berbeza. Jika penyedia AI aktif dipilih dalam «Tetapan AI», ringkasan aliran daripada penyedia itu juga tersedia; jika tidak tersedia, skrin menggunakan narasi luar talian dan menyatakan had itu. Narasi, peta panggilan dan aliran data menggunakan analisis corak teks luar talian, bukan penghurai AST penuh — kaedah yang kurungan pembukanya berada pada baris sendiri, medan kelas, dan panggilan melalui refleksi tidak dijejak — dan amaran perlumbaan data boleh muncul untuk pemboleh ubah yang sebenarnya hanya digunakan bergilir-gilir.

Kilang Himpunan Aplikasi dan Kesediaan Play Store
Untuk menyediakan aplikasi bagi Google Play Store terus dari telefon: buka «Kilang Himpunan Aplikasi dan Kesediaan Play Store» dalam menu utama, pilih projek, kemudian tekan «Bina Himpunan AAB». IDE membina fail .aab daripada manifes, sumber dan aset projek bersama BundleConfig.pb sebenar, mengesahkan struktur himpunan, kemudian membahagikan himpunan kepada APK varian sebenar (asas, mengikut seni bina, mengikut bahasa, dan universal) dengan saiz yang diukur daripada pembahagian itu, bukan anggaran. Himpunan ditandatangani dengan JAR v1 menggunakan kunci projek yang sama yang digunakan untuk menandatangani APK, dan rantaian tandatangannya disahkan secara kriptografi. Skrin ini juga mengaudit kesediaan Play — SDK sasaran di bawah 35 ditandakan «tinggi» kerana Play Store memerlukan 35 atau lebih, dan pustaka 64 bit yang hilang juga ditandakan «tinggi». bundletool sebenar tidak boleh berjalan pada peranti, kerana bundletool memerlukan JVM sedangkan Android tidak mempunyai JVM; laluan di atas ialah laluan sebenar yang paling hampir pada peranti.

Enjin Kemas Kini OTA dan Keluaran Berperingkat
Untuk menghantar pembaikan kecil tanpa memaksa pengguna memuat turun semula seluruh APK: buka «Enjin Kemas Kini OTA dan Keluaran Berperingkat» dalam menu utama, pilih projek, tulis kandungan versi lama dan baharu, kemudian tekan «Bina Pakej Tampalan». IDE mengira perbezaan dan membina pakej tampalan (patch-ota.zip) bersama cap jari SHA-256 kandungan baharu, kemudian memeriksa sama ada peranti ini berada dalam fasa pertama pelancaran 10 peratus. Tampalan kini menyokong delta binari pada mana-mana fail (termasuk DEX dan APK), dibungkus dengan tandatangan RSA-2048 dan disahkan dengan kunci awam dipercayai sebelum digunakan, dan boleh dimuat turun dari pelayan pembangun bersama senarai keluarannya; jika penggunaan gagal, fail lama kekal utuh. Penggunaan tampalan pada aplikasi yang sedang berjalan dilakukan melalui tandatangan semula dengan kunci projek dan PackageInstaller, kerana menggantikan kod proses yang sedang berjalan dari dalam dirinya sendiri adalah mustahil — APK terkunci dan DEX sudah dimuat.

Studio Tinjauan Kod Pasukan
Untuk menyemak perubahan rakan sekerja dan menyelesaikan konflik gabungan tanpa membaca anak panah Git: buka «Studio Tinjauan Kod Pasukan» dalam menu utama, pilih projek, taip tiga versi teks (asas, tempatan, rakan sekerja), kemudian tekan «Buka Tinjauan Pasukan». IDE menggabungkan ketiga-tiganya berdasarkan unit sintaks Java — dua perubahan pada baris yang sama tetapi dalam pernyataan berbeza tidak lagi dikira sebagai konflik — dan memaparkan setiap konflik sebagai pilihan undian: gunakan versi tempatan, gunakan versi rakan sekerja, atau gabungkan kedua-duanya — baris hasil dimasukkan pada kedudukan konflik asal supaya susunan kekal betul — kemudian menulis hasil ke dalam gabung-hasil.txt dalam projek. Di bawahnya ialah papan tugas projek: taip tajuk tugas kemudian tekan «Tambah Tugas»; tugas disimpan sebagai teks dalam folder .tugas di dalam projek dan diselaraskan melalui komit dalam Git dalam aplikasi, jadi papan boleh dibaca semula daripada mana-mana sejarah komit. Pembahagi sintaks ini bukan penghurai AST penuh dan Git dalam aplikasi menyimpan syot kilat penuh bagi setiap komit; tiada pelayan selaras khas.

Imbasan Struktur Kod
Untuk menulis kod dengan suara di dalam editor: buka projek dalam Editor, kemudian tekan butang Imbasan Struktur Kod. Ucapkan arahan dalam bahasa Indonesia, contohnya buat fungsi tambah dengan parameter a angka dan b angka, buat kelas Mobil, atau buat variabel teks nama sama dengan Budi — IDE menukar ucapan menjadi blok kod Java, Kotlin, Python atau Compose yang sah sintaksis dan menyisipkannya pada kedudukan kursor, kemudian membacakan ringkasannya melalui Jieshuo. Imbasan menggunakan perkhidmatan input suara terbina dalam sistem, tanpa kebenaran mikrofon tambahan, dan hanya mengenali pola arahan yang sudah didaftarkan; ucapan di luar pola tidak ditukar menjadi kod. Angka yang diucapkan dengan perkataan (contohnya 'lima') belum ditukar menjadi digit.

Bilik Kerjasama Tempatan (tanpa internet)
Untuk bekerja bersama dalam satu bilik tanpa internet: buka Kerjasama dalam menu utama, kemudian buka bahagian Bilik Kerjasama Tempatan. Satu telefon membuka sesi (IDE memaparkan alamat IP tempatan dan PIN 6 digit), telefon lain menyertai dengan alamat dan PIN itu. Perubahan teks dihantar sebagai perbezaan baris, APK hasil binaan boleh dihantar ke telefon penguji, dan laporan ranap daripada telefon penguji diterima kembali. Satu sesi hanya untuk seorang rakan; jika dua orang mengubah baris yang sama tepat pada masa yang sama, perubahan terakhir digunakan. PIN dihantar sebagai teks biasa dalam rangkaian tempatan. Bilik ini belum diuji pada telefon sebenar.

Tetapan AI
Untuk menetapkan penyedia AI dan kunci API bagi membina aplikasi: dalam menu utama, dalam kumpulan tetapan, tekan «Tetapan AI» (di sebelah butang «Konektor»). Pilih penyedia yang hendak digunakan daripada senarai yang tersedia, dan tandakan «Tukar model apabila provider ralat» supaya jika satu model gagal, IDE secara automatik mencuba model seterusnya daripada penyedia yang sama. Tekan «Urus Kunci API» untuk menambah kunci sandaran (taip nama dan kunci, kemudian tekan «Simpan»; kunci dipaparkan bertopeng, hanya 4 aksara terakhir kelihatan). Kunci disimpan pada telefon dan tidak pernah dihantar ke mana-mana kecuali penyedia yang dipilih ketika membina aplikasi. Penyedia yang dipilih kini benar-benar digunakan oleh «Arkitek Pelan Tindakan Projek» dan «Pencerita Aliran Logik Kod»; membina aplikasi pada skrin «Pembuat Aplikasi AI» masih menggunakan AI tempatan pada telefon (tanpa internet).

Konektor
Untuk menganalisis APK kemudian menghantarnya: dalam menu utama, dalam kumpulan Tetapan, tekan Konektor (di sebelah butang Tetapan AI). Pilih fail APK daripada telefon, IDE membaca kandungannya (nama pakej, versi, senarai aktiviti), kemudian tekan Hantar APK untuk menghantarnya melalui menu perkongsian sistem (contohnya WhatsApp atau Drive).

Bahasa dan Suara
Untuk menukar bahasa aplikasi: buka Tetapan, kemudian Bahasa Aplikasi, kemudian pilih bahasa atau Ikut Sistem. Skrin utama dan kebanyakan skrin bertukar serta-merta kepada bahasa yang dipilih tanpa perlu menutup atau memulakan semula aplikasi; sesetengah skrin (contohnya Terminal, Kerjasama, Tetapan AI dan Urus Kunci) masih menggunakan bahasa lama sehingga dibuka semula. Jika anda memilih Ikut Sistem, bahasa mengikut bahasa sistem telefon.

Tandatangan Lalai per Projek dan Anti Tamper
Sejak versi 5.7, projek yang tidak memakai tanda tangan peribadi ditandatangani dengan kunci terbina KHUSUS projek itu sendiri (dibuat sekali dalam folder tanda-tangan-bawaan dalam projek, kemudian dipakai seterusnya), jadi tanda tangan terbina berbeza-beza antara projek — tidak lagi satu kunci bersama untuk semua aplikasi. Jangan padam folder tanda-tangan-bawaan: tanpa kunci itu, APK baharu tidak boleh menimpa APK lama projek yang sama. Tetapan setiap projek (seni bina berasingan, tanda tangan peribadi, anti tamper, keystore terpilih, SDK) kini tersimpan dalam fail settings.gradle dalam projek dan dibaca semula setiap kali projek dibina. Dalam Tetapan kategori Tanda Tangan terdapat tanda centang Anti tamper aplikasi hasil build: jika aktif, aplikasi hasil bina pada peranti memeriksa tanda tangan dan isi dex-nya setiap kali dibuka; jika ditandatangani semula atau diubah orang lain, aplikasi menolak berjalan. Debugger dan alat suntikan seperti Frida/Xposed juga dikesan, dan tetingkap aplikasi dikunci daripada rakaman skrin.

Pembuat Video Demo
Untuk membuat video demo aplikasi hasil: buka Pembuat Video Demo dalam menu utama, pilih projek, isi tajuk video, kemudian tekan Buat Skrip Video Demo — IDE menulis video-demo.txt yang mengandungi 5 babak baku (pembuka, paparan utama, ciri 1, ciri 2, penutup) beserta teks narasi dan tempoh setiap babak. Tekan Buat Slideshow HTML untuk membuat video-demo.html daripada gambar-gambar projek (ikon + tangkapan skrin jika ada) yang bertukar automatik setiap 5 saat. Ini BUKAN video .mp4 — untuk video sebenar, buka video-demo.html dalam pelayar HP kemudian rakam skrin, atau baca narasi dalam video-demo.txt sambil merakam aplikasi yang sedang berjalan.

Paparan Baru ala Android Studio
Paparan IDE kini dirapikan menyerupai Android Studio (hanya paparannya sahaja — semua butang, menu, dan aliran tetap sama seperti sebelumnya): latar kelabu cerah, tajuk skrin tebal berwarna hitam, butang biru dengan teks putih, dan kotak isi putih berbingkai nipis. Menu utama dikelompokkan secara visual (Ciri Pembina, Cloud Tema & Lain-lain, Suara Kod & Ciri Baharu, Alat) tanpa mengubah susunan butang. Terminal tetap memakai panel gelap seperti tetingkap Terminal dalam Android Studio, dan editor kod tetap berlatar putih dengan teks hitam. Semua teks tetap terbaca jelas oleh Jieshuo.

Tetapan
Untuk menetapkan aplikasi: buka menu Pilihan pada skrin utama kemudian tekan Tetapan. Di dalamnya terdapat 12 kategori: Tetapan GitHub (keselamatan, tanda tangan peribadi, sejarah bina, dan token GitHub), Tetapan Bina APK Peranti (simpan kata laluan keystore dan sejarah bina pada peranti), Tema (warna aplikasi), Tanda Tangan (buat keystore untuk tanda tangan peribadi dan tanda centang anti tamper aplikasi hasil build), Folder Projek (lokasi folder projek), Bahasa dan Suara (bahasa antara muka dan kelajuan suara Mod Suara), Saiz Teks dan Paparan (saiz fon editor), Build (SDK sasaran lalai dan pisah seni bina lalai untuk skrin Cipta Projek), Pemberitahuan (bunyi apabila bina selesai), Sandaran Automatik (jadual sandaran projek), Profil Pembangun (nama, nombor WhatsApp, dan akaun yang terpapar pada skrin Derma), serta Privasi dan Data (set semula tetapan dan padam data aplikasi). Setiap kategori mempunyai butang Kembali ke Sebelumnya untuk kembali ke menu kategori. Tetapan yang baru disimpan sahaja (belum diterapkan) ditulis keterangannya pada skrin dengan jujur.

Derma kepada Pembangun
Untuk menderma atau menyapa pembangun: tekan butang Derma kepada Pembangun pada skrin utama, di samping butang Perihal Alat. Pada skrin derma terdapat butang Salin Akaun BRI — tekan untuk menyalin nombor akaun pembangun, kemudian tampal dalam aplikasi bank anda. Terdapat juga bahagian Sapa Pembangun di WhatsApp: isi nama dan bandar asal, kemudian tekan Hantar di WhatsApp — WhatsApp terbuka dengan pesanan sapaan sudah terisi automatik, tinggal tekan Hantar di WhatsApp kemudian kembali ke aplikasi. WhatsApp tidak membenarkan aplikasi lain menghantar pesanan secara automatik, jadi penghantaran tetap dilakukan sendiri dalam WhatsApp.

Perintah Kegemaran Terminal
Untuk menyimpan perintah yang kerap dipakai dalam Terminal: buka Terminal kemudian tekan Kegemaran. Ketik Tambah kegemaran baru, isi nama (contohnya Lihat fail) dan perintahnya (contohnya ls -la), kemudian tekan Simpan — kegemaran tersimpan kekal dalam HP. Ketik nama kegemaran untuk menjalankannya terus dalam terminal; ketik Padam kegemaran kemudian pilih satu untuk memadamnya (dengan pengesahan). Sudah terdapat 3 kegemaran terbina: Lihat fail (ls -la), Semak ruang (df -h), dan Bersihkan skrin (clear) — semuanya boleh dipadam. Perintah kosong tidak boleh disimpan atau dijalankan; Terminal memberitahu melalui pesanan dan suara jika perkara itu berlaku.

Analitik & Kualiti
Untuk melihat ringkasan penggunaan aplikasi dan laporan crash: tekan butang Analitik & Kualiti pada skrin utama, di samping butang Derma kepada Pembangun. Skrin ini menampilkan berapa kali aplikasi dibuka, skrin yang paling kerap dibuka, bilangan crash, dan senarai crash terkini beserta cadangan pembaikan ringkas. Data ini hanya tersimpan dalam HP anda dan tidak dihantar ke mana-mana. Terdapat butang Padam Data Analitik dengan dialog pengesahan untuk memadam semua data tersebut. Skrin terakhir hanya tercatat untuk skrin utama dan skrin ini.
