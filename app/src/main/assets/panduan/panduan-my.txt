Create Aplikasi by Al Kautsar သို့ ကြိုဆိုပါသည်
Create Aplikasi သည် လက်ပ်တော့မလိုအပ်ဘဲ ဖုန်းပေါ်တွင် တိုက်ရိုက်အလုပ်လုပ်သော Android အက်ပ်ဖန်တီးရေး အက်ပ်တစ်ခုဖြစ်သည်။ ဤအက်ပ်သည် မည်သူမဆို မိမိကိုယ်ပိုင် Android အက်ပ်ကို ဖန်တီးနိုင်စေပြီး အက်ပ်ဖန်တီးခြင်း စတင်လေ့လာနေသူများနှင့် မျက်နှာပြင်ဖတ်စက် (screen reader) အသုံးပြုသူများလည်း ပါဝင်သည်။ ဤအက်ပ်အသုံးပြုပုံ လမ်းညွှန်အပြည့်အစုံကို ဤ Tentang Alat မျက်နှာပြင်တွင် ရရှိနိုင်ပါသည်။

ဤအက်ပ်က ဘာလဲ၊ ဘယ်သူတွေအတွက်လဲ
Create Aplikasi သည် ဖုန်းပေါ်တွင် အလုပ်လုပ်သော Android အက်ပ်ဖန်တီးရေး ကိရိယာတစ်ခုဖြစ်သည်။ ဤအက်ပ်သည် မိမိကိုယ်ပိုင် Android အက်ပ်ကို ဖန်တီးလိုသော မည်သူမဆို အတွက်ဖြစ်ပြီး အစပြုသူများနှင့် မျက်နှာပြင်ဖတ်စက် အသုံးပြုသူများလည်း ပါဝင်သည်။ ဤအက်ပ်တွင် ကုဒ်တည်းဖြတ်စနစ်၊ ပရောဂျက်ကို စမ်းသပ်ရန် Jalankan ခလုတ်၊ APK တည်ဆောက်ရန် Bangun ခလုတ်၊ ထို့ပြင် APK ကို လက်မှတ်ထိုးရန်နှင့် ထည့်သွင်းရန် မီနူးများ ပါဝင်သည်။

ဤအက်ပ်၏ ရည်ရွယ်ချက်
ဤအက်ပ်ကို မည်သူမဆို မိမိကိုယ်ပိုင် Android အက်ပ်ကို ဖုန်းမှ တိုက်ရိုက် အလွယ်တကူ ဖန်တီးနိုင်ရန် ပြုလုပ်ထားသည်။ ၎င်း၏ ပုံပန်းသွင်ပြင်ကို အသုံးပြုသူအသစ်များပင် ချက်ချင်း စမ်းသုံးနိုင်ရန် တတ်နိုင်သမျှ ရိုးရှင်းအောင် ပြုလုပ်ထားသည်။

ပရောဂျက်အသစ် ဖန်တီးနည်း အဆင့်ဆင့်
1. ပင်မမီနူးတွင် Buat Project ကို နှိပ်ပါ။
2. ပရောဂျက်အမျိုးအစားကို ရွေးပါ: HTML, Situs Web, Java, Kotlin, Compose, သို့မဟုတ် Python။
3. အက်ပ်အမည်ကို ဖြည့်ပါ၊ ဥပမာ: Garuda Decode။
4. ပက်ကေ့ဂျ်အမည် (package name) ကို ဖြည့်ပါ၊ ဥပမာ: com.android.garudadecode။ ပက်ကေ့ဂျ်အမည်သည် စာလုံးအသေးများသာ ပါဝင်ရမည်ဖြစ်ပြီး အစက်ဖြင့် ခြားထားသော အပိုင်းအနည်းဆုံး နှစ်ပိုင်း ပါဝင်ရမည်။
5. အက်ပ်ဗားရှင်းကို ဖြည့်ပါ၊ ဥပမာ: 1.0၊ နှင့် ဂဏန်းဖြင့် ဗားရှင်းကုဒ်ကို ဖြည့်ပါ၊ ဥပမာ: 1။ ဗလာထားပါက ဗားရှင်းသည် 1.0 နှင့် ဗားရှင်းကုဒ် 1 အဖြစ် အလိုအလျောက် ဖြည့်သွားမည်။
6. လိုအပ်ပါက အနည်းဆုံး SDK နှင့် ပစ်မှတ် SDK ကို ဖြည့်ပါ။ ဗလာထားပါက မူလတန်ဖိုးများကို အသုံးပြုမည်။ အနည်းဆုံး SDK သည် ထောက်ပံ့သော အနိမ့်ဆုံး Android ဗားရှင်းဖြစ်သည်၊ ဥပမာ: 21 ဆိုသည်မှာ Android 5.0 ဖြစ်သည်။ ပစ်မှတ် SDK ၏ အများဆုံးမှာ 36 (Android 16) ဖြစ်သည်။
7. အက်ပ်ခွင့်ပြုချက်များကို ရွေးရန် Pilih Izin ကို နှိပ်ပါ၊ ဥပမာ: INTERNET။ INTERNET ခွင့်ပြုချက်သည် မူလအတိုင်း အမှန်ခြစ်ထားပြီးဖြစ်သည်။ အက်ပ်အတွက် အမှန်တကယ် လိုအပ်သော ခွင့်ပြုချက်များကိုသာ အမှန်ခြစ်ပါ။
8. ဆန္ဒရှိပါက APK အရွယ်အစား သေးငယ်စေရန် "Gunakan arsitektur terpisah 64 bit dan 32 bit" ကို အမှန်ခြစ်ပါ၊ နှင့် ကိုယ်ပိုင်ဖန်တီးထားသော keystore ကို သုံးလိုပါက "Gunakan tanda tangan pribadi" ကို အမှန်ခြစ်ပါ။
9. Buat Proyek ကို နှိပ်ပါ။ ပရောဂျက်အသစ်သည် Download/project ဖိုလ်ဒါတွင် သိမ်းဆည်းပြီး Kelola Project တွင် ချက်ချင်း ပေါ်လာမည်။

ရရှိနိုင်သော ပရောဂျက်အမျိုးအစားများ
• HTML: WebView မှတစ်ဆင့် အလုပ်လုပ်သော index.html, style.css နှင့် script.js တို့ဖြင့် ပြသမှု။ ဖုန်းပေါ်တွင် တိုက်ရိုက် တည်ဆောက်သည်။
• Situs Web: WebView မှတစ်ဆင့် အလုပ်လုပ်သော index.html, tentang.html, kontak.html, style.css နှင့် script.js တို့ပါဝင်ပြီး မီနူး (Beranda, Tentang, Kontak) ပါသော ဝက်ဘ်ဆိုက်။ ဖုန်းပေါ်တွင် တိုက်ရိုက် တည်ဆောက်သည်။
• Java: ဖုန်းပေါ်တွင် တည်ဆောက်သည်။ MainActivity သည် app/src/main/java/<nama-paket>/MainActivity.java တွင် ရှိသည်။ ပြသမှုသည် app/src/main/res/layout/activity_main.xml မှ၊ စာသားသည် app/src/main/res/values/strings.xml မှ၊ အပြင်အဆင်သည် app/src/main/res/values/styles.xml မှ ရယူသည်။
• Kotlin: အက်ပ်တွင် ပါဝင်သော Kotlin compiler ကို သုံး၍ စက်ပေါ်တွင် (offline) သို့မဟုတ် GitHub Actions မှတစ်ဆင့် တည်ဆောက်နိုင်သည်။ MainActivity သည် app/src/main/java/<nama-paket>/MainActivity.kt တွင် ရှိပြီး res ဖိုင်များသည် Java ပရောဂျက်နှင့် အတူတူဖြစ်သည်။ Compiler အရွယ်အစား ကြီးမားသောကြောင့် ပထမဆုံး Kotlin တည်ဆောက်မှုသည် ပိုနှေးပြီး Kotlin class များကို ရည်ညွှန်းသော .java ဖိုင်များကို လောလောဆယ် တည်ဆောက်၍ မရသေးပါ (.java ဖိုင်များကို .kt ဖိုင်များမတိုင်မီ compile လုပ်သည်)။
• Compose: အင်တာဖေ့စ်ကို Jetpack Compose ဖြင့် ဖန်တီးထားသော ခေတ်မီ Android အက်ပ် (XML layout မဟုတ်ပါ)။ MainActivity သည် app/src/main/java/<nama-paket>/MainActivity.kt တွင် ရှိသည်။ Compose ပရောဂျက်များကို GitHub Actions မှတစ်ဆင့် (Bangun proyek မီနူး၊ ထို့နောက် Bangun online) သို့မဟုတ် Gradle ဖြင့် Termux တွင် တည်ဆောက်သည်၊ အကြောင်းမှာ Compose သည် စက်ပေါ်တွင် မရရှိနိုင်သော Jetpack Compose library များ လိုအပ်သောကြောင့်ဖြစ်သည်။
• Python: အက်ပ်လော့ဂျစ်ကို Python ဘာသာစကား (Chaquopy) ဖြင့် app/src/main/python/main.py တွင် ရေးသားပြီး app/src/main/java/<nama-paket>/MainActivity.java ရှိ MainActivity host က run ပေးသည်။ Python ပရောဂျက်များကို ဖုန်းပေါ်တွင် တိုက်ရိုက် (Chaquopy runtime သည် အက်ပ်တွင် ပါဝင်သည်) သို့မဟုတ် GitHub Actions မှတစ်ဆင့် တည်ဆောက်နိုင်သည်။ Python ပရောဂျက်၏ အနည်းဆုံး SDK မှာ 24 (Android 7.0) ဖြစ်သည်။

Java, HTML, Situs Web, Kotlin, Compose နှင့် Python ပရောဂျက်များ၏ ဖိုင်ဖွဲ့စည်းပုံ
Java, HTML, Situs Web, Kotlin, Compose နှင့် Python ပရောဂျက်များသည် ပုံမှန် Android ပရောဂျက်များကဲ့သို့ ဖွဲ့စည်းထားသည်။ app ဖိုလ်ဒါအတွင်းတွင် src ဖိုလ်ဒါရှိပြီး ၎င်းအတွင်းတွင် main ဖိုလ်ဒါရှိသည်။ main ဖိုလ်ဒါအတွင်းတွင် java ဖိုလ်ဒါ၏ ဘေးတွင် AndroidManifest.xml၊ layout/activity_main.xml နှင့် values/strings.xml နှင့် values/styles.xml တို့ပါဝင်သော res ဖိုလ်ဒါ၊ HTML နှင့် Situs Web အတွက် index.html ပါဝင်သော assets ဖိုလ်ဒါ (Situs Web တွင် tentang.html နှင့် kontak.html လည်း ရှိသည်) တို့ ရှိသည်။ HTML နှင့် Situs Web ပရောဂျက်များတွင်လည်း app/src/main/java/<nama-paket>/MainActivity.java တွင် ကိုယ်ပိုင် MainActivity ရှိပြီး ၎င်းသည် index.html ကို WebView တွင် load လုပ်ကာ AndroidManifest တွင် launcher ဖြစ်သည်။ Python ပရောဂျက်၏ Python ကုဒ်သည် app/src/main/python/main.py တွင်ရှိပြီး host MainActivity.java သည် app/src/main/java/<nama-paket>/MainActivity.java တွင် ရှိသည်။ AndroidManifest.xml, layout, strings နှင့် styles တို့ကို MainActivity ကဲ့သို့ပင် editor တွင် ဖွင့်၍ ပြင်ဆင်နိုင်သည်။ Manifest သည် app ဖိုလ်ဒါ၏ ဘေးတွင်ပင် ရှိနေသေးသော ပရောဂျက်အဟောင်းများကိုလည်း တည်ဆောက်နိုင်သည်၊ အကြောင်းမှာ တည်ဆောက်ချိန်တွင် အက်ပ်သည် app/src/main/ ရှိ AndroidManifest.xml ကို ဦးစွာ စစ်ဆေးပြီး ထို့နောက် app ဖိုလ်ဒါ၏ ဘေးရှိကို စစ်ဆေးကာ နောက်ဆုံးတွင် ပရောဂျက်ဒေတာဖိုင်ကို စစ်ဆေးသောကြောင့်ဖြစ်သည်။

ခွင့်ပြုချက် စည်းမျဉ်းများ (အရေးကြီး)
ပရောဂျက်ဖန်တီးစဉ် အမှန်ခြစ်ထားသော ခွင့်ပြုချက်များသည် ပရောဂျက်အမျိုးအစားအလိုက် တစ်နေရာတည်းတွင်သာ မှတ်တမ်းတင်ထားသည်။ Java, HTML, Situs Web, Kotlin, Compose နှင့် Python ပရောဂျက်များအတွက် အမှန်ခြစ်ထားသော ခွင့်ပြုချက်များသည် ပရောဂျက်ဖိုလ်ဒါအတွင်းရှိ java ဖိုလ်ဒါ၏ ဘေးတွင်၊ app/src/main/ အတွင်းရှိ AndroidManifest.xml တွင်သာ မှတ်တမ်းတင်ထားသည်။ Java, HTML, Situs Web, Kotlin, Compose နှင့် Python ပရောဂျက်များ၏ ပရောဂျက်ဒေတာဖိုင်တွင် ခွင့်ပြုချက်စာရင်း မပါဝင်ပါ။ Java ကို ရွေး၍ INTERNET နှင့် CAMERA ကို အမှန်ခြစ်ပါက AndroidManifest.xml တွင် အခြားခွင့်ပြုချက်များ ထပ်မပါဘဲ INTERNET နှင့် CAMERA သာ မှတ်တမ်းတင်ထားမည်။ တည်ဆောက်ချိန်တွင် အက်ပ်သည် ခွင့်ပြုချက်များကို ထိုနေရာမှပင် ဖတ်သည်: Java, HTML, Situs Web, Kotlin, Compose နှင့် Python ပရောဂျက်များအတွက် app/src/main/ ရှိ AndroidManifest.xml မှ (မရှိပါက ပရောဂျက်အဟောင်းများအတွက် app ဖိုလ်ဒါ၏ ဘေးရှိ AndroidManifest.xml မှ)၊ ပရောဂျက်အဟောင်းများအတွက် ပရောဂျက်ဒေတာဖိုင်မှ ဖြစ်သည်။

Kelola Project ကို ဖွင့်ပြီး editor ကို ဖွင့်ရန် ပရောဂျက်အမည်ကို တို့ပါ။ Editor တွင် ဖိုင်များကို ဖွင့်နိုင်သည်၊ ကုဒ်ရေးနိုင်သည်၊ ပြောင်းလဲမှုများကို သိမ်းဆည်းနိုင်သည်။ Java, HTML, Situs Web, Kotlin, Compose နှင့် Python ပရောဂျက်များအတွက် ဖိုင်များသည် app/src/main ဖိုလ်ဒါအတွင်းတွင် ရှိသည်။ ပရောဂျက်ကို မျှဝေရန် Ekspor ZIP ကို သုံးပါ (အောက်ပါအပိုင်းကို ကြည့်ပါ)။

ပရောဂျက် run နည်း
Editor တွင် ပရောဂျက်ကို စမ်းသပ်ရန် Jalankan ကို နှိပ်ပါ။ HTML နှင့် Situs Web ပရောဂျက်များအတွက် index.html ကို WebView မှတစ်ဆင့် run သည်။ အမှားတစ်ခု ဖြစ်ပေါ်ပါက အမှားမက်ဆေ့ချ်ကို ဖတ်ပါ၊ ကုဒ်ကို ပြင်ပါ၊ ထို့နောက် ပြန် run ပါ။

APK တည်ဆောက်နည်း
Editor တွင် Bangun ကို နှိပ်ပါ။ တည်ဆောက်နည်း နှစ်နည်း ရှိသည်။ ပထမနည်းမှာ စက်ပေါ်တွင် တည်ဆောက်ခြင်း: HTML, Situs Web, Java, Kotlin နှင့် Python ပရောဂျက်များအတွက် အင်တာနက်မလိုဘဲ ဖုန်းပေါ်တွင် တိုက်ရိုက် တည်ဆောက်သည်။ ဒုတိယနည်းမှာ GitHub Actions မှတစ်ဆင့် အွန်လိုင်း တည်ဆောက်ခြင်း: အင်တာနက်မှတစ်ဆင့် GitHub တွင် တည်ဆောက်ပြီး ပရောဂျက်အမျိုးအစားအားလုံးအတွက် သုံးနိုင်သည်။ Compose ပရောဂျက်များကို ဒုတိယနည်း (Bangun online) ဖြင့်သာ သို့မဟုတ် Gradle ဖြင့် Termux တွင်သာ တည်ဆောက်နိုင်သည်၊ အကြောင်းမှာ Compose သည် စက်ပေါ်တွင် မရရှိနိုင်သော Jetpack Compose library များ လိုအပ်သောကြောင့်ဖြစ်သည်။ ပထမတည်ဆောက်မှု ရလဒ်ကို လက်မှတ်မထိုးရသေးပါ။ ထို့နောက် အက်ပ်က ၎င်းကို လက်မှတ်ထိုးသည်: မူလကီးဖြင့် အလိုအလျောက် သို့မဟုတ် ပရောဂျက်ဖန်တီးစဉ် "Gunakan tanda tangan pribadi" ကို အမှန်ခြစ်ထားပါက ကိုယ်ပိုင်လက်မှတ်ဖြင့် ဖြစ်သည်။

APK ထည့်သွင်းနည်း
APK အဆင်သင့်ဖြစ်သောအခါ ၎င်းကို ထည့်သွင်းရန် Pasang ကို နှိပ်ပါ။ Android 8 နှင့်အထက်တွင် ဖုန်းသည် ဦးစွာ "Izinkan dari sumber ini" ကို တောင်းဆိုမည်၊ အကြောင်းမှာ ဤအက်ပ်သည် APK ကို Play Store အပြင်ဘက်မှ ထည့်သွင်းသောကြောင့်ဖြစ်သည်။ Pengaturan တွင် ထိုခွင့်ပြုချက်ကို တစ်ကြိမ် ဖွင့်ပါ၊ ထို့နောက် အက်ပ်သို့ ပြန်လာပါ: ထည့်သွင်းမှုသည် Pasang ကို ထပ်နှိပ်စရာမလိုဘဲ အလိုအလျောက် ဆက်လက်လုပ်ဆောင်မည်။ Pasang ခလုတ် မပေါ်ပါက တည်ဆောက်မှု ပြီးစီးပြီး APK ဖန်တီးပြီးကြောင်း သေချာပါစေ။

အက်ပ်ကို လက်မှတ်ထိုးနည်း
ထည့်သွင်းနိုင်ရန် APK တိုင်းကို လက်မှတ်ထိုးရမည်။ ရွေးချယ်စရာ နှစ်ခု ရှိသည်။ ပထမမှာ မူလကီး: အက်ပ်သည် ဘာမှ လုပ်စရာမလိုဘဲ အလိုအလျောက် လက်မှတ်ထိုးပေးသည်။ ဒုတိယမှာ ကိုယ်ပိုင်လက်မှတ်: ဦးစွာ ပင်မမီနူးရှိ Buat Keystore မီနူးမှတစ်ဆင့် keystore ဖန်တီးပါ၊ ၎င်း၏ စကားဝှက်ကို ကောင်းစွာ သိမ်းဆည်းပါ၊ ထို့နောက် ပရောဂျက်ဖန်တီးစဉ် "Gunakan tanda tangan pribadi" ကို အမှန်ခြစ်ပါ။ Keystore သည် Download/project/signing တွင် သိမ်းဆည်းထားသည်။

ပရောဂျက်ကို ZIP အဖြစ် ထုတ်ယူနည်း
Ekspor ZIP ကို ပရောဂျက်ကို သူငယ်ချင်းများနှင့် မျှဝေနိုင်ရန် ပံ့ပိုးထားသည်။ နည်းလမ်းမှာ: Kelola Project တွင် ပရောဂျက်အမည်ကို ကြာကြာ နှိပ်ထားပြီး Ekspor ZIP ကို ရွေးပါ။ ရလဒ်သည် Download/project/<NamaProyek>.zip အဖြစ် သိမ်းဆည်းသည်။ bin ဖိုလ်ဒါ မပါဝင်သောကြောင့် အရွယ်အစား သေးငယ်ပြီး KB ဆယ်ဂဏန်းမျှသာ ရှိသည်။ ထို ZIP ဖိုင်ကို သူငယ်ချင်းများထံ ပို့နိုင်သည် သို့မဟုတ် GitHub သို့ တင်နိုင်သည်။

Ekstensi JAWS
Ekstensi JAWS သည် Jieshuo (CSR) ၏ extension engine ကို သုံးပြီး ၎င်း၏ မျက်နှာပြင်ဖတ်စက်ကို မသုံးပါ။ ထို့ကြောင့် အသုံးပြုသူသည် TalkBack ကို သုံးနေသော်လည်း ဒီဇိုင်းသည် အလုပ်လုပ်နိုင်ဆဲဖြစ်သည်။ နည်းလမ်းမှာ: ပင်မမီနူးတွင် Ekstensi JAWS ကို ဖွင့်ပါ။ အလိုအလျောက် ကလစ်သည် သူ့အလိုလို အလုပ်လုပ်သောကြောင့် ဝန်ဆောင်မှုကို Pengaturan Aksesibilitas တွင် ဦးစွာ ဖွင့်ရမည်။ ထို့နောက် ဒီဇိုင်းအသစ် ဖန်တီးနိုင်သည်: ဒီဇိုင်းအမည်ကို ရိုက်ပါ၊ OK ကို နှိပ်ပါ၊ ထို့နောက် ၎င်း၏ အကွက်ကို ဖြည့်ပါ။

Daftar Klik ကို သပ်ရပ်စေရန် ခွဲထားသည်
ဒီဇိုင်းအတွင်းတွင် အကွက်နှစ်ခု ရှိသည်: script အကွက်နှင့် Daftar Klik အကွက်။ ခလုတ်စာရင်းကို daftar_klik.txt ဖိုင်တွင် သီးခြား သိမ်းဆည်းထားပြီး တစ်ကြောင်းလျှင် အမည်တစ်ခုစီ ဖြစ်သည်။ ၎င်း၏ ဥပမာ အကြောင်းအရာမှာ: tombolSimpan, tombolHapus, tombolBuka။ အက်ပ်တစ်ခုကို ဖွင့်ရန် ထိုစာရင်းတွင် >WhatsApp ဟု ရေးပါ။ daftar_klik.txt ဖိုင် မရှိသေးသော ဒီဇိုင်းအဟောင်းများသည် ထို မူလဥပမာကို ပြသမည်။

ပံ့ပိုးထားသော ရိုးရှင်းသော function များ
• klikTombol("tombolSimpan") — ၎င်း၏ စာသားအပေါ် အခြေခံ၍ ခလုတ်တစ်ခုကို ကလစ်လုပ်သည်။
• klikDaftarTombol(daftar) — daftar_klik.txt ရှိ စာရင်းကို ကလစ်လုပ်သည်၊ တစ်ကြောင်းလျှင် ခလုတ်တစ်ခုစီ အစဉ်လိုက်၊ ထို့နောက် မည်မျှ အောင်မြင်ကြောင်းနှင့် မည်မျှ မတွေ့ကြောင်း အသိပေးသည်။
• bukaAplikasi("WhatsApp") — အက်ပ်တစ်ခုကို ၎င်း၏ အမည်ဖြင့် ဖွင့်သည်၊ သို့မဟုတ် စာရင်းတွင် ">WhatsApp" ဟု ရေးသည်။
• klik(540, 1200) — မျက်နှာပြင် ကိုဩဒိနိတ်များတွင် ကလစ်လုပ်သည်။
Function အားလုံးကို ဦးစွာ ရိုးရှင်းအောင် ပြုလုပ်ထားသည်။ အသုံးပြုရတာ ကျွမ်းကျင်လာသောအခါ နောက်ထပ် function များကို နောင်တွင် ထပ်ထည့်နိုင်သည်။

မျက်နှာပြင်ဖတ်စက် အကြောင်း
ဤအက်ပ်ကို မျက်နှာပြင်ဖတ်စက်နှင့် အဆင်ပြေအောင် ဒီဇိုင်းဆွဲထားသည်။ ဖြည့်သွင်းမှု အကွက်တိုင်းတွင် အညွှန်းနှင့် ဖြည့်သွင်းပုံ ဥပမာ ရှိပြီး ခလုတ်အားလုံးကို ရှုပ်ထွေးသော အမူအရာများ မလိုဘဲ ရောက်ရှိနိုင်သည်။ Ekstensi JAWS ကို အသုံးပြုသူသည် TalkBack ကို သုံးနေသော်လည်း ဆက်လက် အလုပ်လုပ်နိုင်အောင် ပြုလုပ်ထားသည်၊ အကြောင်းမှာ သုံးထားသည်မှာ ၎င်း၏ extension engine ဖြစ်ပြီး မျက်နှာပြင်ဖတ်စက် မဟုတ်သောကြောင့်ဖြစ်သည်။

ကိုယ်ရေးကိုယ်တာနှင့် လုံခြုံရေး
ပရောဂျက်များနှင့် keystore သည် သင့်ဖုန်းတွင် သိမ်းဆည်းထားသည်။ GitHub token ကို အွန်လိုင်း တည်ဆောက်မှုအတွက်သာ သုံးပြီး ဤအက်ပ်အတွင်းတွင် သိမ်းဆည်းထားသည်။ သင့် token သို့မဟုတ် keystore စကားဝှက်ကို မည်သူနှင့်မျှ မမျှဝေပါနှင့်။ ကိုယ်ပိုင်လက်မှတ်ကို သုံးပါက keystore နှင့် ၎င်း၏ စကားဝှက်ကို လုံခြုံသောနေရာတွင် သိမ်းဆည်းပါ၊ အကြောင်းမှာ ပျောက်ဆုံးသွားပါက APK အဟောင်းကို တူညီသော လက်မှတ်ဖြင့် update လုပ်၍ မရနိုင်သောကြောင့်ဖြစ်သည်။

Android 5.0 သို့မဟုတ် ပိုသစ်။ သိုလှောင်မှု ခွင့်ပြုချက်: Android 11 နှင့်အထက်တွင် ဖိုင်အားလုံး ဝင်ရောက်ခွင့်ကို သုံးပြီး Android 10 နှင့်အောက်တွင် ပုံမှန် သိုလှောင်မှု ခွင့်ပြုချက် (သိုလှောင်မှု ဖတ်/ရေး) ကို သုံးသည်၊ အကြောင်းမှာ Android 10 တွင် ဖိုင်အားလုံး ဝင်ရောက်ခွင့် မရှိသောကြောင့်ဖြစ်သည်။ စက်ပေါ်တွင် တည်ဆောက်ရန် ARM processor (32 သို့မဟုတ် 64 bit) ပါသော ဖုန်း လိုအပ်သည်။ GitHub Actions မှတစ်ဆင့် အွန်လိုင်း တည်ဆောက်ရန် အင်တာနက်နှင့် GitHub token လိုအပ်သည်။ Kotlin ပရောဂျက်များကို စက်ပေါ်တွင် တည်ဆောက်နိုင်သော်လည်း Kotlin compiler အရွယ်အစား ကြီးမားသောကြောင့် ပထမတည်ဆောက်မှုသည် ပိုနှေးပြီး မှတ်ဉာဏ် ပိုသုံးသည်။ Compose ပရောဂျက်များကို GitHub Actions မှတစ်ဆင့် သို့မဟုတ် Gradle ဖြင့် Termux တွင် တည်ဆောက်သည်။ Python ပရောဂျက်များသည် Android 7.0 သို့မဟုတ် ပိုသစ် (အနည်းဆုံး SDK 24) လိုအပ်ပြီး ရလဒ် APK သည် Python runtime (Chaquopy) နှင့် ၎င်း၏ standard library ပါဝင်သောကြောင့် ပိုကြီးသည်။

Terminal
ပင်မမျက်နှာပြင်ရှိ Terminal မီနူးသည် ဤအက်ပ်အတွင်းတွင် terminal တစ်ခု ဖွင့်ပေးသည်။ ls ကဲ့သို့သော command များကို ပရောဂျက်ဖိုလ်ဒါ၏ အကြောင်းအရာကို ကြည့်ရန်၊ cd ကို ဖိုလ်ဒါများ ပြောင်းရန်၊ git ကို ကုဒ်ကို စီမံရန် သုံးနိုင်သည်။ Command အထွက်ကို မျက်နှာပြင်ဖတ်စက် ဖတ်နိုင်သော စာသားအဖြစ် ပြသပြီး နောက်ဆုံးရလဒ်ကို နားထောင်ရန် Bacakan hasil ခလုတ် ရှိသည်။ ဤ terminal သည် ဖုန်း၏ system shell ကို သုံးသောကြောင့် nano နှင့် vim ကဲ့သို့သော interactive program များကို ဤနေရာတွင် လောလောဆယ် သုံး၍ မရသေးပါ။

Lisensi (အခပေးဗားရှင်း)
အက်ပ်များကို ရောင်းချရန် ပရောဂျက်ဖန်တီးစဉ် "Aktifkan Lisensi" ကို အမှန်ခြစ်ပြီး သင့် WhatsApp နံပါတ်ကို ဖြည့်ပါ။ တည်ဆောက်ပြီးသော အက်ပ်သည် ပထမဆုံး ဖွင့်သောအခါ လိုင်စင်ကုဒ်ကို တောင်းဆိုမည်: အသုံးပြုသူသည် မိမိ၏ စက် ID ကို မြင်ရပြီး Kirim ID Perangkat ခလုတ်ကို နှိပ်၍ ထို ID ကို သင့် WhatsApp သို့ ပို့ကာ ထို့နောက် သင်က ၎င်း၏ လိုင်စင်ကုဒ်ကို ပြန်ပို့ပေးသည်။ လိုင်စင်ကုဒ်ကို စက် ID နှင့် ပရောဂျက် စကားဝှက် (ပရောဂျက်ဒေတာဖိုင်ရှိ lisensi_seed) တို့မှ တွက်ချက်သည် — ထို စကားဝှက်ကို ကောင်းစွာ သိမ်းဆည်းပြီး မမျှဝေပါနှင့်။ မှန်ကန်သော ကုဒ်ကို ထည့်ပြီးနောက် အက်ပ် ပွင့်လာပြီး ကုဒ်ကို ထပ်မတောင်းတော့ပါ။

Pembuat Ikon Otomatis
ပရောဂျက်အသစ်၏ icon သည် ဖောက်ထွင်းမြင်နိုင်ဆဲ (transparent) ဖြစ်သောကြောင့် ပင်မမီနူးတွင် Pembuat Ikon ရရှိနိုင်သည်။ နည်းလမ်းမှာ: Pembuat Ikon ကို နှိပ်ပါ၊ စာလုံး တစ်လုံး သို့မဟုတ် နှစ်လုံး ရေးပါ (ဥပမာ အက်ပ်အမည်၏ အတိုကောက်)၊ နောက်ခံအရောင်နှင့် စာသားအရောင်ကို ရွေးပါ၊ ၎င်း၏ preview ကို ကြည့်ပါ၊ ထို့နောက် ရွေးထားသော ပရောဂျက်တွင် icon ကို သုံးရန် Simpan ke Proyek ကို သို့မဟုတ် ၎င်း၏ PNG ဖိုင်ကို အခြားနေရာတွင် သုံးရန် Simpan ke Download ကို နှိပ်ပါ။ ပရောဂျက် ဖန်တီးပြီးနောက် အက်ပ်သည် icon ဖန်တီးရန်လည်း ကမ်းလှမ်းသည်။ ပရောဂျက်၏ icon အဟောင်းကို Kelola Project ရှိ ပရောဂျက်မီနူးမှ အချိန်မရွေး ပြောင်းနိုင်သည် (ပရောဂျက်အမည်ကို ကြာကြာ နှိပ်ထားပြီး Ganti Ikon ကို ရွေးပါ)။

Template Proyek Siap Pakai
ဗလာပရောဂျက်မှ မစတင်လိုပါက ပရောဂျက်ဖန်တီးစဉ် template ကို ရွေးပါ: Kalkulator (Java), Catatan (Java), Daftar Tugas (Kotlin), Kalkulator Web (HTML), Situs Profil (Situs Web), သို့မဟုတ် Penghitung (Compose)။ Template ကို ရွေးခြင်းသည် ပရောဂျက်အမျိုးအစားကို ထို template အလိုက် အလိုအလျောက် ပြောင်းပြီး ပရောဂျက်ကို အဆင်သင့် စတင်ကုဒ်ဖြင့် ဖန်တီးသည် — run ရန် သို့မဟုတ် ပြင်ဆင်ရန်သာ ကျန်သည်။ Template ရွေးပြီးနောက် ပရောဂျက်အမျိုးအစားကို လက်ဖြင့် ထပ်ပြောင်းပါက template ပယ်ဖျက်ပြီး ပရောဂျက်သည် ပြန်လည် ဗလာဖြစ်သွားမည်။ HTML နှင့် Situs Web template များအတွက် template သည် index.html ၏ အကြောင်းအရာကို အစားထိုးပြီး form တွင် ရိုက်ထားသော HTML script လည်း ပါဝင်သည်။

Cadangan dan Pulihkan Proyek
ပရောဂျက်များ မပျောက်ဆုံးစေရန် backup လုပ်ဆောင်ချက် ရရှိနိုင်သည်။ နည်းလမ်းမှာ: Kelola Project တွင် ပရောဂျက်အမည်ကို ကြာကြာ နှိပ်ထားပြီး Cadangkan ကို ရွေးပါ။ Backup ကို Download/backup ဖိုလ်ဒါတွင် ပရောဂျက်အမည်နှင့် ရက်စွဲပါသော ZIP အဖြစ် သိမ်းဆည်းပြီး ဥပမာ: GarudaDecode-2026-11-14-123045.zip။ ၎င်း၏ အကြောင်းအရာသည် Ekspor ZIP နှင့် အတူတူဖြစ်သည် (ပရောဂျက် အကြောင်းအရာ အားလုံး၊ bin ဖိုလ်ဒါ မပါဘဲ)။ ပြန်လည်ရယူရန်: Kelola Project တွင် မီနူးကို ဖွင့်ပါ၊ Pulihkan cadangan ကို ရွေးပါ၊ ထို့နောက် ၎င်း၏ backup ဖိုင်ကို ရွေးပါ။ ပရောဂျက်အမည် ရှိပြီးသားဖြစ်ပါက အက်ပ်က မေးမည်: ပရောဂျက်အဟောင်းကို အစားထိုးမလား၊ သို့မဟုတ် အမည်အသစ်ဖြင့် သိမ်းမလား။

Bagikan dan Impor Proyek
ပရောဂျက်ကို သူငယ်ချင်းနှင့် မျှဝေရန်: Kelola Project တွင် ပရောဂျက်အမည်ကို ကြာကြာ နှိပ်ထားပြီး Bagikan ကို ရွေးပါ။ ပရောဂျက်ကို မျှဝေရေး အက်ပ်များ (WhatsApp, Telegram နှင့် အခြားများ) မှတစ်ဆင့် ZIP အဖြစ် ပို့သည်။ သူငယ်ချင်းထံမှ ပရောဂျက်ကို လက်ခံရန်: Kelola Project တွင် မီနူးကို ဖွင့်ပါ၊ Impor proyek ကို ရွေးပါ၊ ထို့နောက် ၎င်း၏ ZIP ဖိုင်ကို ရွေးပါ။ ထို ZIP ဖိုင်တွင် ပရောဂျက်ဒေတာဖိုင် ပါဝင်ရမည် — မပါဝင်ပါက ဖိုင်ကို ရှင်းလင်းသော မက်ဆေ့ချ်ဖြင့် ငြင်းပယ်မည်၊ အကြောင်းမှာ ထိုဖိုင်သည် Create Aplikasi ပရောဂျက် မဟုတ်သောကြောင့်ဖြစ်သည်။ ပရောဂျက်အမည် ရှိပြီးသားဖြစ်ပါက အက်ပ်က မေးမည်: ပရောဂျက်အဟောင်းကို အစားထိုးမလား၊ သို့မဟုတ် အမည်အသစ်ဖြင့် သိမ်းမလား။

Pencarian dan Filter Proyek
ပရောဂျက်များ များလာပါက Kelola Project တွင် ရှာဖွေရေး အကွက်နှင့် အမျိုးအစား စစ်ထုတ်စနစ် ရှိသည်။ ရှာဖွေရေး အကွက်တွင် ပရောဂျက်အမည်ကို ရိုက်ပါ၊ စာရင်းသည် ချက်ချင်း စစ်ထုတ်သွားမည် (စာလုံးအကြီးအသေး မခွဲခြားပါ)။ အမျိုးအစား စစ်ထုတ်စနစ်သည် စာရင်းကို အမျိုးအစား တစ်ခုတည်းသာ ကန့်သတ်သည်: Semua, HTML, Situs Web, Java, Kotlin, Compose, သို့မဟုတ် Python။ ပရောဂျက်တိုင်း၏ မီနူးကို စစ်ထုတ်ထားသော စာရင်းမှလည်း ပုံမှန်အတိုင်း ဖွင့်နိုင်ဆဲဖြစ်သည်။
