Create Aplikasi by Al Kautsar သို့ ကြိုဆိုပါသည်
Create Aplikasi သည် လက်ပ်တော့မလိုအပ်ဘဲ ဖုန်းပေါ်တွင် တိုက်ရိုက်အလုပ်လုပ်သော Android အက်ပ်ဖန်တီးရေး အက်ပ်တစ်ခုဖြစ်သည်။ ဤအက်ပ်သည် မည်သူမဆို မိမိကိုယ်ပိုင် Android အက်ပ်ကို ဖန်တီးနိုင်စေပြီး အက်ပ်ဖန်တီးခြင်း စတင်လေ့လာနေသူများနှင့် မျက်နှာပြင်ဖတ်စက် (screen reader) အသုံးပြုသူများလည်း ပါဝင်သည်။ ဤအက်ပ်အသုံးပြုပုံ လမ်းညွှန်အပြည့်အစုံကို ဤ Tentang Alat မျက်နှာပြင်တွင် ရရှိနိုင်ပါသည်။

ဤအက်ပ်က ဘာလဲ၊ ဘယ်သူတွေအတွက်လဲ
Create Aplikasi သည် ဖုန်းပေါ်တွင် အလုပ်လုပ်သော Android အက်ပ်ဖန်တီးရေး ကိရိယာတစ်ခုဖြစ်သည်။ ဤအက်ပ်သည် မိမိကိုယ်ပိုင် Android အက်ပ်ကို ဖန်တီးလိုသော မည်သူမဆို အတွက်ဖြစ်ပြီး အစပြုသူများနှင့် မျက်နှာပြင်ဖတ်စက် အသုံးပြုသူများလည်း ပါဝင်သည်။ ဤအက်ပ်တွင် ကုဒ်တည်းဖြတ်စနစ်၊ ပရောဂျက်ကို စမ်းသပ်ရန် Jalankan ခလုတ်၊ APK တည်ဆောက်ရန် Bangun ခလုတ်၊ ထို့ပြင် APK ကို လက်မှတ်ထိုးရန်နှင့် ထည့်သွင်းရန် မီနူးများ ပါဝင်သည်။

ဤအက်ပ်၏ ရည်ရွယ်ချက်
ဤအက်ပ်ကို မည်သူမဆို မိမိကိုယ်ပိုင် Android အက်ပ်ကို ဖုန်းမှ တိုက်ရိုက် အလွယ်တကူ ဖန်တီးနိုင်ရန် ပြုလုပ်ထားသည်။ ၎င်း၏ ပုံပန်းသွင်ပြင်ကို အသုံးပြုသူအသစ်များပင် ချက်ချင်း စမ်းသုံးနိုင်ရန် တတ်နိုင်သမျှ ရိုးရှင်းအောင် ပြုလုပ်ထားသည်။

ပရောဂျက်အသစ် ဖန်တီးနည်း အဆင့်ဆင့်
1. ပင်မမီနူးတွင် Buat Project ကို နှိပ်ပါ။
2. ပရောဂျက်အမျိုးအစားကို ရွေးပါ: HTML, Situs Web, Java, Kotlin, Compose, သို့မဟုတ် Python။
3. အက်ပ်အမည်ကို ဖြည့်ပါ၊ ဥပမာ: Garuda Decode။
4. ပက်ကေ့ဂျ်အမည် (package name) ကို ဖြည့်ပါ၊ ဥပမာ: com.android.garudadecode။ ပက်ကေ့ဂျ်အမည်သည် စာလုံးအသေးများသာ ပါဝင်ရမည်ဖြစ်ပြီး အစက်ဖြင့် ခြားထားသော အပိုင်းအနည်းဆုံး နှစ်ပိုင်း ပါဝင်ရမည်။
5. အက်ပ်ဗားရှင်းကို ဖြည့်ပါ၊ ဥပမာ: 1.0၊ နှင့် ဂဏန်းဖြင့် ဗားရှင်းကုဒ်ကို ဖြည့်ပါ၊ ဥပမာ: 1။ ဗလာထားပါက ဗားရှင်းသည် 1.0 နှင့် ဗားရှင်းကုဒ် 1 အဖြစ် အလိုအလျောက် ဖြည့်သွားမည်။
6. လိုအပ်ပါက အနည်းဆုံး SDK နှင့် ပစ်မှတ် SDK ကို ဖြည့်ပါ။ ဗလာထားပါက မူလတန်ဖိုးများကို အသုံးပြုမည်။ အနည်းဆုံး SDK သည် ထောက်ပံ့သော အနိမ့်ဆုံး Android ဗားရှင်းဖြစ်သည်၊ ဥပမာ: 21 ဆိုသည်မှာ Android 5.0 ဖြစ်သည်။ ပစ်မှတ် SDK ၏ အများဆုံးမှာ 36 (Android 16) ဖြစ်သည်။
7. အက်ပ်ခွင့်ပြုချက်များကို ရွေးရန် Pilih Izin ကို နှိပ်ပါ၊ ဥပမာ: INTERNET။ INTERNET ခွင့်ပြုချက်သည် မူလအတိုင်း အမှန်ခြစ်ထားပြီးဖြစ်သည်။ အက်ပ်အတွက် အမှန်တကယ် လိုအပ်သော ခွင့်ပြုချက်များကိုသာ အမှန်ခြစ်ပါ။
8. ဆန္ဒရှိပါက APK အရွယ်အစား သေးငယ်စေရန် "Gunakan arsitektur terpisah 64 bit dan 32 bit" ကို အမှန်ခြစ်ပါ၊ နှင့် ကိုယ်ပိုင်ဖန်တီးထားသော keystore ကို သုံးလိုပါက "Gunakan tanda tangan pribadi" ကို အမှန်ခြစ်ပါ။
9. Buat Proyek ကို နှိပ်ပါ။ ပရောဂျက်အသစ်သည် Download/project ဖိုလ်ဒါတွင် သိမ်းဆည်းပြီး Kelola Project တွင် ချက်ချင်း ပေါ်လာမည်။

ရရှိနိုင်သော ပရောဂျက်အမျိုးအစားများ
• HTML: WebView မှတစ်ဆင့် အလုပ်လုပ်သော index.html, style.css နှင့် script.js တို့ဖြင့် ပြသမှု။ ဖုန်းပေါ်တွင် တိုက်ရိုက် တည်ဆောက်သည်။
• Situs Web: WebView မှတစ်ဆင့် အလုပ်လုပ်သော index.html, tentang.html, kontak.html, style.css နှင့် script.js တို့ပါဝင်ပြီး မီနူး (Beranda, Tentang, Kontak) ပါသော ဝက်ဘ်ဆိုက်။ ဖုန်းပေါ်တွင် တိုက်ရိုက် တည်ဆောက်သည်။
• Java: ဖုန်းပေါ်တွင် တည်ဆောက်သည်။ MainActivity သည် app/src/main/java/<nama-paket>/MainActivity.java တွင် ရှိသည်။ ပြသမှုသည် app/src/main/res/layout/activity_main.xml မှ၊ စာသားသည် app/src/main/res/values/strings.xml မှ၊ အပြင်အဆင်သည် app/src/main/res/values/styles.xml မှ ရယူသည်။
• Kotlin: အက်ပ်တွင် ပါဝင်သော Kotlin compiler ကို သုံး၍ စက်ပေါ်တွင် (offline) သို့မဟုတ် GitHub Actions မှတစ်ဆင့် တည်ဆောက်နိုင်သည်။ MainActivity သည် app/src/main/java/<nama-paket>/MainActivity.kt တွင် ရှိပြီး res ဖိုင်များသည် Java ပရောဂျက်နှင့် အတူတူဖြစ်သည်။ Compiler အရွယ်အစား ကြီးမားသောကြောင့် ပထမဆုံး Kotlin တည်ဆောက်မှုသည် ပိုနှေးပြီး Kotlin class များကို ရည်ညွှန်းသော .java ဖိုင်များကို လောလောဆယ် တည်ဆောက်၍ မရသေးပါ (.java ဖိုင်များကို .kt ဖိုင်များမတိုင်မီ compile လုပ်သည်)။
• Compose: အင်တာဖေ့စ်ကို Jetpack Compose ဖြင့် ဖန်တီးထားသော ခေတ်မီ Android အက်ပ် (XML layout မဟုတ်ပါ)။ MainActivity သည် app/src/main/java/<nama-paket>/MainActivity.kt တွင် ရှိသည်။ Compose ပရောဂျက်များကို GitHub Actions မှတစ်ဆင့် (Bangun proyek မီနူး၊ ထို့နောက် Bangun online) သို့မဟုတ် Gradle ဖြင့် Termux တွင် တည်ဆောက်သည်၊ အကြောင်းမှာ Compose သည် စက်ပေါ်တွင် မရရှိနိုင်သော Jetpack Compose library များ လိုအပ်သောကြောင့်ဖြစ်သည်။
• Python: အက်ပ်လော့ဂျစ်ကို Python ဘာသာစကား (Chaquopy) ဖြင့် app/src/main/python/main.py တွင် ရေးသားပြီး app/src/main/java/<nama-paket>/MainActivity.java ရှိ MainActivity host က run ပေးသည်။ Python ပရောဂျက်များကို ဖုန်းပေါ်တွင် တိုက်ရိုက် (Chaquopy runtime သည် အက်ပ်တွင် ပါဝင်သည်) သို့မဟုတ် GitHub Actions မှတစ်ဆင့် တည်ဆောက်နိုင်သည်။ Python ပရောဂျက်၏ အနည်းဆုံး SDK မှာ 24 (Android 7.0) ဖြစ်သည်။

ပရောဂျက် ဗိသုကာ ပြောင်းလဲရန်
ပရောဂျက် အသစ် မဖန်တီးဘဲ ရှိပြီးသား ပရောဂျက်၏ ဗိသုကာ ရွေးချယ်မှုများကို ပြောင်းလဲရန်: ပင်မမီနူးတွင် «ပရောဂျက် ဗိသုကာ ပြောင်းလဲရန်» ကို နှိပ်ပါ၊ ထို့နောက် ပရောဂျက်ကို ရွေးချယ်ပြီး «64-bit APK တည်ဆောက်ပါ (arm64-v8a)» သို့မဟုတ် «32-bit APK တည်ဆောက်ပါ (armeabi-v7a)» အမှန်ခြစ်ကွက်ကို ပြောင်းလဲပါ၊ သို့မဟုတ် «ပရောဂျက်များ စီမံရန်» တွင် ပရောဂျက်အမည်ကို ကြာကြာနှိပ်ပြီး ထိုပရောဂျက်အတွက် အတူတူပင် မျက်နှာပြင်ကို တိုက်ရိုက်ဖွင့်ရန် «ဗိသုကာ ပြောင်းလဲပါ» ကို ရွေးချယ်ပါ။ စည်းမျဉ်းမှာ: အမှန်ခြစ်ကွက် နှစ်ခုလုံး ဖွင့်ထားလျှင် တည်ဆောက်မှုသည် သီးခြား APK ဖိုင် နှစ်ခု ဖန်တီးသည်၊ တစ်ခုမှာ 64-bit နှင့် တစ်ခုမှာ 32-bit၊ အမှန်ခြစ်ကွက် တစ်ခုသာ ဖွင့်ထားလျှင် တည်ဆောက်မှုသည် 64-bit နှင့် 32-bit စက်နှစ်မျိုးလုံးတွင် ဆက်လက် အလုပ်လုပ်သော တစ်ခုတည်းသော universal APK ဖိုင် ဖန်တီးသည်။ မျိုးကွဲတစ်ခုတည်းအတွက်သာ သီးခြား APK ကို ယခုထိ မပံ့ပိုးသေးပါ၊ အဘယ်ကြောင့်ဆိုသော် တည်ဆောက်မှုလမ်းကြောင်းသည် ခွဲထားသော သို့မဟုတ် universal ရွေးချယ်မှုကိုသာ သိသောကြောင့် ဖြစ်သည်၊ သို့သော် မျိုးကွဲတစ်ခုစီ၏ ရွေးချယ်မှုသည် မျက်နှာပြင် ပြန်ဖွင့်သောအခါ မပျောက်စေရန် ပရောဂျက်အတွင်း သိမ်းဆည်းထားဆဲ ဖြစ်သည်။

Java, HTML, Situs Web, Kotlin, Compose နှင့် Python ပရောဂျက်များ၏ ဖိုင်ဖွဲ့စည်းပုံ
Java, HTML, Situs Web, Kotlin, Compose နှင့် Python ပရောဂျက်များသည် ပုံမှန် Android ပရောဂျက်များကဲ့သို့ ဖွဲ့စည်းထားသည်။ app ဖိုလ်ဒါအတွင်းတွင် src ဖိုလ်ဒါရှိပြီး ၎င်းအတွင်းတွင် main ဖိုလ်ဒါရှိသည်။ main ဖိုလ်ဒါအတွင်းတွင် java ဖိုလ်ဒါ၏ ဘေးတွင် AndroidManifest.xml၊ layout/activity_main.xml နှင့် values/strings.xml နှင့် values/styles.xml တို့ပါဝင်သော res ဖိုလ်ဒါ၊ HTML နှင့် Situs Web အတွက် index.html ပါဝင်သော assets ဖိုလ်ဒါ (Situs Web တွင် tentang.html နှင့် kontak.html လည်း ရှိသည်) တို့ ရှိသည်။ HTML နှင့် Situs Web ပရောဂျက်များတွင်လည်း app/src/main/java/<nama-paket>/MainActivity.java တွင် ကိုယ်ပိုင် MainActivity ရှိပြီး ၎င်းသည် index.html ကို WebView တွင် load လုပ်ကာ AndroidManifest တွင် launcher ဖြစ်သည်။ Python ပရောဂျက်၏ Python ကုဒ်သည် app/src/main/python/main.py တွင်ရှိပြီး host MainActivity.java သည် app/src/main/java/<nama-paket>/MainActivity.java တွင် ရှိသည်။ AndroidManifest.xml, layout, strings နှင့် styles တို့ကို MainActivity ကဲ့သို့ပင် editor တွင် ဖွင့်၍ ပြင်ဆင်နိုင်သည်။ Manifest သည် app ဖိုလ်ဒါ၏ ဘေးတွင်ပင် ရှိနေသေးသော ပရောဂျက်အဟောင်းများကိုလည်း တည်ဆောက်နိုင်သည်၊ အကြောင်းမှာ တည်ဆောက်ချိန်တွင် အက်ပ်သည် app/src/main/ ရှိ AndroidManifest.xml ကို ဦးစွာ စစ်ဆေးပြီး ထို့နောက် app ဖိုလ်ဒါ၏ ဘေးရှိကို စစ်ဆေးကာ နောက်ဆုံးတွင် ပရောဂျက်ဒေတာဖိုင်ကို စစ်ဆေးသောကြောင့်ဖြစ်သည်။

ခွင့်ပြုချက် စည်းမျဉ်းများ (အရေးကြီး)
ပရောဂျက်ဖန်တီးစဉ် အမှန်ခြစ်ထားသော ခွင့်ပြုချက်များသည် ပရောဂျက်အမျိုးအစားအလိုက် တစ်နေရာတည်းတွင်သာ မှတ်တမ်းတင်ထားသည်။ Java, HTML, Situs Web, Kotlin, Compose နှင့် Python ပရောဂျက်များအတွက် အမှန်ခြစ်ထားသော ခွင့်ပြုချက်များသည် ပရောဂျက်ဖိုလ်ဒါအတွင်းရှိ java ဖိုလ်ဒါ၏ ဘေးတွင်၊ app/src/main/ အတွင်းရှိ AndroidManifest.xml တွင်သာ မှတ်တမ်းတင်ထားသည်။ Java, HTML, Situs Web, Kotlin, Compose နှင့် Python ပရောဂျက်များ၏ ပရောဂျက်ဒေတာဖိုင်တွင် ခွင့်ပြုချက်စာရင်း မပါဝင်ပါ။ Java ကို ရွေး၍ INTERNET နှင့် CAMERA ကို အမှန်ခြစ်ပါက AndroidManifest.xml တွင် အခြားခွင့်ပြုချက်များ ထပ်မပါဘဲ INTERNET နှင့် CAMERA သာ မှတ်တမ်းတင်ထားမည်။ တည်ဆောက်ချိန်တွင် အက်ပ်သည် ခွင့်ပြုချက်များကို ထိုနေရာမှပင် ဖတ်သည်: Java, HTML, Situs Web, Kotlin, Compose နှင့် Python ပရောဂျက်များအတွက် app/src/main/ ရှိ AndroidManifest.xml မှ (မရှိပါက ပရောဂျက်အဟောင်းများအတွက် app ဖိုလ်ဒါ၏ ဘေးရှိ AndroidManifest.xml မှ)၊ ပရောဂျက်အဟောင်းများအတွက် ပရောဂျက်ဒေတာဖိုင်မှ ဖြစ်သည်။

Editor အသုံးပြုနည်း
Kelola Project ကို ဖွင့်ပြီး editor ကို ဖွင့်ရန် ပရောဂျက်အမည်ကို တို့ပါ။ Editor တွင် ဖိုင်များကို ဖွင့်နိုင်သည်၊ ကုဒ်ရေးနိုင်သည်၊ ပြောင်းလဲမှုများကို သိမ်းဆည်းနိုင်သည်။ Java, HTML, Situs Web, Kotlin, Compose နှင့် Python ပရောဂျက်များအတွက် ဖိုင်များသည် app/src/main ဖိုလ်ဒါအတွင်းတွင် ရှိသည်။ ပရောဂျက်ကို မျှဝေရန် Ekspor ZIP ကို သုံးပါ (အောက်ပါအပိုင်းကို ကြည့်ပါ)။

ပရောဂျက် run နည်း
Editor တွင် ပရောဂျက်ကို စမ်းသပ်ရန် Jalankan ကို နှိပ်ပါ။ HTML နှင့် Situs Web ပရောဂျက်များအတွက် index.html ကို WebView မှတစ်ဆင့် run သည်။ အမှားတစ်ခု ဖြစ်ပေါ်ပါက အမှားမက်ဆေ့ချ်ကို ဖတ်ပါ၊ ကုဒ်ကို ပြင်ပါ၊ ထို့နောက် ပြန် run ပါ။

APK တည်ဆောက်နည်း
Editor တွင် Bangun ကို နှိပ်ပါ။ တည်ဆောက်နည်း နှစ်နည်း ရှိသည်။ ပထမနည်းမှာ စက်ပေါ်တွင် တည်ဆောက်ခြင်း: HTML, Situs Web, Java, Kotlin နှင့် Python ပရောဂျက်များအတွက် အင်တာနက်မလိုဘဲ ဖုန်းပေါ်တွင် တိုက်ရိုက် တည်ဆောက်သည်။ ဒုတိယနည်းမှာ GitHub Actions မှတစ်ဆင့် အွန်လိုင်း တည်ဆောက်ခြင်း: အင်တာနက်မှတစ်ဆင့် GitHub တွင် တည်ဆောက်ပြီး ပရောဂျက်အမျိုးအစားအားလုံးအတွက် သုံးနိုင်သည်။ Compose ပရောဂျက်များကို ဒုတိယနည်း (Bangun online) ဖြင့်သာ သို့မဟုတ် Gradle ဖြင့် Termux တွင်သာ တည်ဆောက်နိုင်သည်၊ အကြောင်းမှာ Compose သည် စက်ပေါ်တွင် မရရှိနိုင်သော Jetpack Compose library များ လိုအပ်သောကြောင့်ဖြစ်သည်။ ပထမတည်ဆောက်မှု ရလဒ်ကို လက်မှတ်မထိုးရသေးပါ။ ထို့နောက် အက်ပ်က ၎င်းကို လက်မှတ်ထိုးသည်: မူလကီးဖြင့် အလိုအလျောက် သို့မဟုတ် ပရောဂျက်ဖန်တီးစဉ် "Gunakan tanda tangan pribadi" ကို အမှန်ခြစ်ထားပါက ကိုယ်ပိုင်လက်မှတ်ဖြင့် ဖြစ်သည်။

APK ထည့်သွင်းနည်း
APK အဆင်သင့်ဖြစ်သောအခါ ၎င်းကို ထည့်သွင်းရန် Pasang ကို နှိပ်ပါ။ Android 8 နှင့်အထက်တွင် ဖုန်းသည် ဦးစွာ "Izinkan dari sumber ini" ကို တောင်းဆိုမည်၊ အကြောင်းမှာ ဤအက်ပ်သည် APK ကို Play Store အပြင်ဘက်မှ ထည့်သွင်းသောကြောင့်ဖြစ်သည်။ Pengaturan တွင် ထိုခွင့်ပြုချက်ကို တစ်ကြိမ် ဖွင့်ပါ၊ ထို့နောက် အက်ပ်သို့ ပြန်လာပါ: ထည့်သွင်းမှုသည် Pasang ကို ထပ်နှိပ်စရာမလိုဘဲ အလိုအလျောက် ဆက်လက်လုပ်ဆောင်မည်။ Pasang ခလုတ် မပေါ်ပါက တည်ဆောက်မှု ပြီးစီးပြီး APK ဖန်တီးပြီးကြောင်း သေချာပါစေ။

အက်ပ်ကို လက်မှတ်ထိုးနည်း
ထည့်သွင်းနိုင်ရန် APK တိုင်းကို လက်မှတ်ထိုးရမည်။ ရွေးချယ်စရာ နှစ်ခု ရှိသည်။ ပထမမှာ မူလကီး: အက်ပ်သည် ဘာမှ လုပ်စရာမလိုဘဲ အလိုအလျောက် လက်မှတ်ထိုးပေးသည်။ ဒုတိယမှာ ကိုယ်ပိုင်လက်မှတ်: ဦးစွာ ပင်မမီနူးရှိ Buat Keystore မီနူးမှတစ်ဆင့် keystore ဖန်တီးပါ၊ ၎င်း၏ စကားဝှက်ကို ကောင်းစွာ သိမ်းဆည်းပါ၊ ထို့နောက် ပရောဂျက်ဖန်တီးစဉ် "Gunakan tanda tangan pribadi" ကို အမှန်ခြစ်ပါ။ Keystore သည် Download/project/signing တွင် သိမ်းဆည်းထားသည်။

ပရောဂျက်ကို ZIP အဖြစ် ထုတ်ယူနည်း
Ekspor ZIP ကို ပရောဂျက်ကို သူငယ်ချင်းများနှင့် မျှဝေနိုင်ရန် ပံ့ပိုးထားသည်။ နည်းလမ်းမှာ: Kelola Project တွင် ပရောဂျက်အမည်ကို ကြာကြာ နှိပ်ထားပြီး Ekspor ZIP ကို ရွေးပါ။ ရလဒ်သည် Download/project/<NamaProyek>.zip အဖြစ် သိမ်းဆည်းသည်။ bin ဖိုလ်ဒါ မပါဝင်သောကြောင့် အရွယ်အစား သေးငယ်ပြီး KB ဆယ်ဂဏန်းမျှသာ ရှိသည်။ ထို ZIP ဖိုင်ကို သူငယ်ချင်းများထံ ပို့နိုင်သည် သို့မဟုတ် GitHub သို့ တင်နိုင်သည်။

Ekstensi JAWS
Ekstensi JAWS သည် Jieshuo (CSR) ၏ extension engine ကို သုံးပြီး ၎င်း၏ မျက်နှာပြင်ဖတ်စက်ကို မသုံးပါ။ ထို့ကြောင့် အသုံးပြုသူသည် TalkBack ကို သုံးနေသော်လည်း ဒီဇိုင်းသည် အလုပ်လုပ်နိုင်ဆဲဖြစ်သည်။ နည်းလမ်းမှာ: ပင်မမီနူးတွင် Ekstensi JAWS ကို ဖွင့်ပါ။ အလိုအလျောက် ကလစ်သည် သူ့အလိုလို အလုပ်လုပ်သောကြောင့် ဝန်ဆောင်မှုကို Pengaturan Aksesibilitas တွင် ဦးစွာ ဖွင့်ရမည်။ ထို့နောက် ဒီဇိုင်းအသစ် ဖန်တီးနိုင်သည်: ဒီဇိုင်းအမည်ကို ရိုက်ပါ၊ OK ကို နှိပ်ပါ၊ ထို့နောက် ၎င်း၏ အကွက်ကို ဖြည့်ပါ။

Daftar Klik ကို သပ်ရပ်စေရန် ခွဲထားသည်
ဒီဇိုင်းအတွင်းတွင် အကွက်နှစ်ခု ရှိသည်: script အကွက်နှင့် Daftar Klik အကွက်။ ခလုတ်စာရင်းကို daftar_klik.txt ဖိုင်တွင် သီးခြား သိမ်းဆည်းထားပြီး တစ်ကြောင်းလျှင် အမည်တစ်ခုစီ ဖြစ်သည်။ ၎င်း၏ ဥပမာ အကြောင်းအရာမှာ: tombolSimpan, tombolHapus, tombolBuka။ အက်ပ်တစ်ခုကို ဖွင့်ရန် ထိုစာရင်းတွင် >WhatsApp ဟု ရေးပါ။ daftar_klik.txt ဖိုင် မရှိသေးသော ဒီဇိုင်းအဟောင်းများသည် ထို မူလဥပမာကို ပြသမည်။

ပံ့ပိုးထားသော ရိုးရှင်းသော function များ
• klikTombol("tombolSimpan") — ၎င်း၏ စာသားအပေါ် အခြေခံ၍ ခလုတ်တစ်ခုကို ကလစ်လုပ်သည်။
• klikDaftarTombol(daftar) — daftar_klik.txt ရှိ စာရင်းကို ကလစ်လုပ်သည်၊ တစ်ကြောင်းလျှင် ခလုတ်တစ်ခုစီ အစဉ်လိုက်၊ ထို့နောက် မည်မျှ အောင်မြင်ကြောင်းနှင့် မည်မျှ မတွေ့ကြောင်း အသိပေးသည်။
• bukaAplikasi("WhatsApp") — အက်ပ်တစ်ခုကို ၎င်း၏ အမည်ဖြင့် ဖွင့်သည်၊ သို့မဟုတ် စာရင်းတွင် ">WhatsApp" ဟု ရေးသည်။
• klik(540, 1200) — မျက်နှာပြင် ကိုဩဒိနိတ်များတွင် ကလစ်လုပ်သည်။
Function အားလုံးကို ဦးစွာ ရိုးရှင်းအောင် ပြုလုပ်ထားသည်။ အသုံးပြုရတာ ကျွမ်းကျင်လာသောအခါ နောက်ထပ် function များကို နောင်တွင် ထပ်ထည့်နိုင်သည်။

မျက်နှာပြင်ဖတ်စက် အကြောင်း
ဤအက်ပ်ကို မျက်နှာပြင်ဖတ်စက်နှင့် အဆင်ပြေအောင် ဒီဇိုင်းဆွဲထားသည်။ ဖြည့်သွင်းမှု အကွက်တိုင်းတွင် အညွှန်းနှင့် ဖြည့်သွင်းပုံ ဥပမာ ရှိပြီး ခလုတ်အားလုံးကို ရှုပ်ထွေးသော အမူအရာများ မလိုဘဲ ရောက်ရှိနိုင်သည်။ Ekstensi JAWS ကို အသုံးပြုသူသည် TalkBack ကို သုံးနေသော်လည်း ဆက်လက် အလုပ်လုပ်နိုင်အောင် ပြုလုပ်ထားသည်၊ အကြောင်းမှာ သုံးထားသည်မှာ ၎င်း၏ extension engine ဖြစ်ပြီး မျက်နှာပြင်ဖတ်စက် မဟုတ်သောကြောင့်ဖြစ်သည်။

ကိုယ်ရေးကိုယ်တာနှင့် လုံခြုံရေး
ပရောဂျက်များနှင့် keystore သည် သင့်ဖုန်းတွင် သိမ်းဆည်းထားသည်။ GitHub token ကို အွန်လိုင်း တည်ဆောက်မှုအတွက်သာ သုံးပြီး ဤအက်ပ်အတွင်းတွင် သိမ်းဆည်းထားသည်။ သင့် token သို့မဟုတ် keystore စကားဝှက်ကို မည်သူနှင့်မျှ မမျှဝေပါနှင့်။ ကိုယ်ပိုင်လက်မှတ်ကို သုံးပါက keystore နှင့် ၎င်း၏ စကားဝှက်ကို လုံခြုံသောနေရာတွင် သိမ်းဆည်းပါ၊ အကြောင်းမှာ ပျောက်ဆုံးသွားပါက APK အဟောင်းကို တူညီသော လက်မှတ်ဖြင့် update လုပ်၍ မရနိုင်သောကြောင့်ဖြစ်သည်။

လိုအပ်ချက်များ
Android 5.0 သို့မဟုတ် ပိုသစ်။ သိုလှောင်မှု ခွင့်ပြုချက်: Android 11 နှင့်အထက်တွင် ဖိုင်အားလုံး ဝင်ရောက်ခွင့်ကို သုံးပြီး Android 10 နှင့်အောက်တွင် ပုံမှန် သိုလှောင်မှု ခွင့်ပြုချက် (သိုလှောင်မှု ဖတ်/ရေး) ကို သုံးသည်၊ အကြောင်းမှာ Android 10 တွင် ဖိုင်အားလုံး ဝင်ရောက်ခွင့် မရှိသောကြောင့်ဖြစ်သည်။ စက်ပေါ်တွင် တည်ဆောက်ရန် ARM processor (32 သို့မဟုတ် 64 bit) ပါသော ဖုန်း လိုအပ်သည်။ GitHub Actions မှတစ်ဆင့် အွန်လိုင်း တည်ဆောက်ရန် အင်တာနက်နှင့် GitHub token လိုအပ်သည်။ Kotlin ပရောဂျက်များကို စက်ပေါ်တွင် တည်ဆောက်နိုင်သော်လည်း Kotlin compiler အရွယ်အစား ကြီးမားသောကြောင့် ပထမတည်ဆောက်မှုသည် ပိုနှေးပြီး မှတ်ဉာဏ် ပိုသုံးသည်။ Compose ပရောဂျက်များကို GitHub Actions မှတစ်ဆင့် သို့မဟုတ် Gradle ဖြင့် Termux တွင် တည်ဆောက်သည်။ Python ပရောဂျက်များသည် Android 7.0 သို့မဟုတ် ပိုသစ် (အနည်းဆုံး SDK 24) လိုအပ်ပြီး ရလဒ် APK သည် Python runtime (Chaquopy) နှင့် ၎င်း၏ standard library ပါဝင်သောကြောင့် ပိုကြီးသည်။

Terminal
ပင်မမျက်နှာပြင်ရှိ Terminal မီနူးသည် ဤအက်ပ်အတွင်းတွင် terminal တစ်ခု ဖွင့်ပေးသည်။ ls ကဲ့သို့သော command များကို ပရောဂျက်ဖိုလ်ဒါ၏ အကြောင်းအရာကို ကြည့်ရန်၊ cd ကို ဖိုလ်ဒါများ ပြောင်းရန်၊ git ကို ကုဒ်ကို စီမံရန် သုံးနိုင်သည်။ Command အထွက်ကို မျက်နှာပြင်ဖတ်စက် ဖတ်နိုင်သော စာသားအဖြစ် ပြသပြီး နောက်ဆုံးရလဒ်ကို နားထောင်ရန် Bacakan hasil ခလုတ် ရှိသည်။ ဤ terminal သည် ဖုန်း၏ system shell ကို သုံးသောကြောင့် nano နှင့် vim ကဲ့သို့သော interactive program များကို ဤနေရာတွင် လောလောဆယ် သုံး၍ မရသေးပါ။

Lisensi (အခပေးဗားရှင်း)
အက်ပ်များကို ရောင်းချရန် ပရောဂျက်ဖန်တီးစဉ် "Aktifkan Lisensi" ကို အမှန်ခြစ်ပြီး သင့် WhatsApp နံပါတ်ကို ဖြည့်ပါ။ တည်ဆောက်ပြီးသော အက်ပ်သည် ပထမဆုံး ဖွင့်သောအခါ လိုင်စင်ကုဒ်ကို တောင်းဆိုမည်: အသုံးပြုသူသည် မိမိ၏ စက် ID ကို မြင်ရပြီး Kirim ID Perangkat ခလုတ်ကို နှိပ်၍ ထို ID ကို သင့် WhatsApp သို့ ပို့ကာ ထို့နောက် သင်က ၎င်း၏ လိုင်စင်ကုဒ်ကို ပြန်ပို့ပေးသည်။ လိုင်စင်ကုဒ်ကို စက် ID နှင့် ပရောဂျက် စကားဝှက် (ပရောဂျက်ဒေတာဖိုင်ရှိ lisensi_seed) တို့မှ တွက်ချက်သည် — ထို စကားဝှက်ကို ကောင်းစွာ သိမ်းဆည်းပြီး မမျှဝေပါနှင့်။ မှန်ကန်သော ကုဒ်ကို ထည့်ပြီးနောက် အက်ပ် ပွင့်လာပြီး ကုဒ်ကို ထပ်မတောင်းတော့ပါ။

Pembuat Ikon Otomatis
ပရောဂျက်အသစ်၏ icon သည် ဖောက်ထွင်းမြင်နိုင်ဆဲ (transparent) ဖြစ်သောကြောင့် ပင်မမီနူးတွင် Pembuat Ikon ရရှိနိုင်သည်။ နည်းလမ်းမှာ: Pembuat Ikon ကို နှိပ်ပါ၊ စာလုံး တစ်လုံး သို့မဟုတ် နှစ်လုံး ရေးပါ (ဥပမာ အက်ပ်အမည်၏ အတိုကောက်)၊ နောက်ခံအရောင်နှင့် စာသားအရောင်ကို ရွေးပါ၊ ၎င်း၏ preview ကို ကြည့်ပါ၊ ထို့နောက် ရွေးထားသော ပရောဂျက်တွင် icon ကို သုံးရန် Simpan ke Proyek ကို သို့မဟုတ် ၎င်း၏ PNG ဖိုင်ကို အခြားနေရာတွင် သုံးရန် Simpan ke Download ကို နှိပ်ပါ။ ပရောဂျက် ဖန်တီးပြီးနောက် အက်ပ်သည် icon ဖန်တီးရန်လည်း ကမ်းလှမ်းသည်။ ပရောဂျက်၏ icon အဟောင်းကို Kelola Project ရှိ ပရောဂျက်မီနူးမှ အချိန်မရွေး ပြောင်းနိုင်သည် (ပရောဂျက်အမည်ကို ကြာကြာ နှိပ်ထားပြီး Ganti Ikon ကို ရွေးပါ)။

Template Proyek Siap Pakai
ဗလာပရောဂျက်မှ မစတင်လိုပါက ပရောဂျက်ဖန်တီးစဉ် template ကို ရွေးပါ: Kalkulator (Java), Catatan (Java), Daftar Tugas (Kotlin), Kalkulator Web (HTML), Situs Profil (Situs Web), သို့မဟုတ် Penghitung (Compose)။ Template ကို ရွေးခြင်းသည် ပရောဂျက်အမျိုးအစားကို ထို template အလိုက် အလိုအလျောက် ပြောင်းပြီး ပရောဂျက်ကို အဆင်သင့် စတင်ကုဒ်ဖြင့် ဖန်တီးသည် — run ရန် သို့မဟုတ် ပြင်ဆင်ရန်သာ ကျန်သည်။ Template ရွေးပြီးနောက် ပရောဂျက်အမျိုးအစားကို လက်ဖြင့် ထပ်ပြောင်းပါက template ပယ်ဖျက်ပြီး ပရောဂျက်သည် ပြန်လည် ဗလာဖြစ်သွားမည်။ HTML နှင့် Situs Web template များအတွက် template သည် index.html ၏ အကြောင်းအရာကို အစားထိုးပြီး form တွင် ရိုက်ထားသော HTML script လည်း ပါဝင်သည်။

Cadangan dan Pulihkan Proyek
ပရောဂျက်များ မပျောက်ဆုံးစေရန် backup လုပ်ဆောင်ချက် ရရှိနိုင်သည်။ နည်းလမ်းမှာ: Kelola Project တွင် ပရောဂျက်အမည်ကို ကြာကြာ နှိပ်ထားပြီး Cadangkan ကို ရွေးပါ။ Backup ကို Download/backup ဖိုလ်ဒါတွင် ပရောဂျက်အမည်နှင့် ရက်စွဲပါသော ZIP အဖြစ် သိမ်းဆည်းပြီး ဥပမာ: GarudaDecode-2026-11-14-123045.zip။ ၎င်း၏ အကြောင်းအရာသည် Ekspor ZIP နှင့် အတူတူဖြစ်သည် (ပရောဂျက် အကြောင်းအရာ အားလုံး၊ bin ဖိုလ်ဒါ မပါဘဲ)။ ပြန်လည်ရယူရန်: Kelola Project တွင် မီနူးကို ဖွင့်ပါ၊ Pulihkan cadangan ကို ရွေးပါ၊ ထို့နောက် ၎င်း၏ backup ဖိုင်ကို ရွေးပါ။ ပရောဂျက်အမည် ရှိပြီးသားဖြစ်ပါက အက်ပ်က မေးမည်: ပရောဂျက်အဟောင်းကို အစားထိုးမလား၊ သို့မဟုတ် အမည်အသစ်ဖြင့် သိမ်းမလား။

Bagikan dan Impor Proyek
ပရောဂျက်ကို သူငယ်ချင်းနှင့် မျှဝေရန်: Kelola Project တွင် ပရောဂျက်အမည်ကို ကြာကြာ နှိပ်ထားပြီး Bagikan ကို ရွေးပါ။ ပရောဂျက်ကို မျှဝေရေး အက်ပ်များ (WhatsApp, Telegram နှင့် အခြားများ) မှတစ်ဆင့် ZIP အဖြစ် ပို့သည်။ သူငယ်ချင်းထံမှ ပရောဂျက်ကို လက်ခံရန်: Kelola Project တွင် မီနူးကို ဖွင့်ပါ၊ Impor proyek ကို ရွေးပါ၊ ထို့နောက် ၎င်း၏ ZIP ဖိုင်ကို ရွေးပါ။ ထို ZIP ဖိုင်တွင် ပရောဂျက်ဒေတာဖိုင် ပါဝင်ရမည် — မပါဝင်ပါက ဖိုင်ကို ရှင်းလင်းသော မက်ဆေ့ချ်ဖြင့် ငြင်းပယ်မည်၊ အကြောင်းမှာ ထိုဖိုင်သည် Create Aplikasi ပရောဂျက် မဟုတ်သောကြောင့်ဖြစ်သည်။ ပရောဂျက်အမည် ရှိပြီးသားဖြစ်ပါက အက်ပ်က မေးမည်: ပရောဂျက်အဟောင်းကို အစားထိုးမလား၊ သို့မဟုတ် အမည်အသစ်ဖြင့် သိမ်းမလား။

Pencarian dan Filter Proyek
ပရောဂျက်များ များလာပါက Kelola Project တွင် ရှာဖွေရေး အကွက်နှင့် အမျိုးအစား စစ်ထုတ်စနစ် ရှိသည်။ ရှာဖွေရေး အကွက်တွင် ပရောဂျက်အမည်ကို ရိုက်ပါ၊ စာရင်းသည် ချက်ချင်း စစ်ထုတ်သွားမည် (စာလုံးအကြီးအသေး မခွဲခြားပါ)။ အမျိုးအစား စစ်ထုတ်စနစ်သည် စာရင်းကို အမျိုးအစား တစ်ခုတည်းသာ ကန့်သတ်သည်: Semua, HTML, Situs Web, Java, Kotlin, Compose, သို့မဟုတ် Python။ ပရောဂျက်တိုင်း၏ မီနူးကို စစ်ထုတ်ထားသော စာရင်းမှလည်း ပုံမှန်အတိုင်း ဖွင့်နိုင်ဆဲဖြစ်သည်။

အသံဖြင့် အက်ပ် တည်ဆောက်ခြင်း
စာရိုက်ဖို့ မလိုချင်ရင် အသံကို အသုံးပြုပါ- ပင်မမီနူးတွင် အသံဖြင့် တည်ဆောက်ရန် ကို နှိပ်ပြီး အမိန့်တစ်ခု ပြောပါ။ ပြောနိုင်သော အမိန့်များမှာ "Buat proyek kalkulator", "Bangun proyek Kalkulator", "Buka proyek Kalkulator", "Jalankan proyek Kalkulator", "Daftar proyek", "Buka ikon", "Kembali" နှင့် "Bantuan" တို့ ဖြစ်သည်။ အက်ပ်က အသံနှင့် စာသားဖြင့် ပြန်ဖြေသောကြောင့် မျက်နှာပြင်ကို မကြည့်ဘဲ ဆက်သုံးနိုင်သည်။ အသံမှတ်သားခြင်းသည် ဖုန်းတွင် ထည့်သွင်းထားသော အသံမှတ်သားအက်ပ်ကို အသုံးပြုသည် (အခမဲ့၊ အင်ဒိုနီးရှား ဘာသာစကား ပက်ကေ့ဂျ် ထည့်သွင်းထားလျှင် အော့ဖ်လိုင်း အလုပ်လုပ်နိုင်သည်)။ ဖုန်းတွင် အသံမှတ်သားခြင်း မရှိလျှင် အမိန့်များကို တူညီသော မျက်နှာပြင်ရှိ စာသားအကွက်တွင် ရိုက်ထည့်နိုင်သည်။

AI အက်ပ် ဖန်တီးသူ
AI အက်ပ် ဖန်တီးသူ မျက်နှာပြင်တွင် သင်လိုချင်သော အက်ပ်ကို ရိုက်ထည့်ပါ သို့မဟုတ် အသံဖြင့် ပြောပါ၊ ဥပမာ - «သိမ်းဆည်းရန် ခလုတ်ပါသော မှတ်စု အက်ပ်»။ အက်ပ်သည် ဖုန်းအတွင်း၌ အဓိက စကားလုံးများကို ခွဲခြမ်းစိတ်ဖြာသည် (အင်တာနက် မလိုဘဲ၊ အခမဲ့) ထို့နောက် အကိုက်ညီဆုံး ပုံစံမှ အစစ်အမှန် ပရောဂျက်ကို ဖန်တီးသည် - ဂဏန်းတွက်စက်၊ မှတ်စုများ၊ လုပ်ငန်းစာရင်း၊ ဝက်ဘ် ဂဏန်းတွက်စက်၊ ပရိုဖိုင် ဝက်ဘ်ဆိုက် သို့မဟုတ် ရေတွက်စက်။ သင့်ဖော်ပြချက်နှင့် ကိုက်ညီသော ပုံစံ မရှိသေးပါက အက်ပ်သည် ဗလာ ပရောဂျက်ကို ဖန်တီးပြီး ရိုးရိုးသားသား ပြောသည် — နားလည်သလို ဟန်မဆောင်ပါ။ AI က ဖန်တီးသော ပရောဂျက်ကို ပရောဂျက်များ စီမံရန် တွင် တိုက်ရိုက် ဖွင့်နိုင်သည်။

သူငယ်ချင်း၏ဖုန်းသို့ တိုက်ရိုက် အစမ်းကြည့်ခြင်း
ပရောဂျက်ကို မတည်ဆောက်မီ သူငယ်ချင်းကို ပြသရန် - ပရောဂျက်များ စီမံရန် တွင် ပရောဂျက် အမည်ကို ကြာကြာ ဖိပြီး သူငယ်ချင်း၏ဖုန်းသို့ အစမ်းကြည့်ခြင်း ကို ရွေးချယ်ပါ။ အက်ပ်သည် ပရောဂျက်၏ အဓိက ဖိုင်များ (index.html၊ MainActivity သို့မဟုတ် main.py) နှင့် ညွှန်ကြားချက်များပါသော ဖတ်ပါ-ကျွန်ုပ်.txt ဖိုင်နှင့် info.txt ဖိုင်တို့ ပါဝင်သော အစမ်းကြည့်ခြင်း အထုပ်ငယ်ကို ဖန်တီးသည်။ အထုပ်ကို ZIP အဖြစ် WhatsApp သို့မဟုတ် Telegram ဖြင့် ပို့သည်။ လက်ခံရရှိသော သူငယ်ချင်းသည် အစမ်းကြည့်ခြင်းကို တိုက်ရိုက် ဖွင့်နိုင်သည် - HTML စာမျက်နှာများ ဘရောက်ဇာတွင် ပွင့်သည်၊ Java/Kotlin/Python ကုဒ်ကို စာသားအဖြစ် ဖတ်သည်။

ပရောဂျက် ဈေးကွက်
ပရောဂျက် ဈေးကွက်တွင် တစ်ချက်နှိပ်ရုံဖြင့် ပရောဂျက် ဖိုင်တွဲသို့ ထည့်သွင်းနိုင်သော နမူနာ ပရောဂျက်များ ပါဝင်သည် - ဂဏန်းတွက်စက်၊ မှတ်စုများ၊ လုပ်ငန်းစာရင်း၊ ဝက်ဘ် ဂဏန်းတွက်စက်၊ ပရိုဖိုင် ဝက်ဘ်ဆိုက်၊ ရေတွက်စက်၊ ဒစ်ဂျစ်တယ် နာရီ နှင့် ဝက်ဘ် မေးခွန်းလွှာ။ အွန်လိုင်း ဈေးကွက် (အင်တာနက်မှ နမူနာများ ဒေါင်းလုဒ်လုပ်ခြင်း) မရှိသေးပါ၊ ထို့ကြောင့် ဤဈေးကွက်တွင် အက်ပ်အတွင်း ရှိပြီးသား နမူနာများ ပါဝင်သည်။ ထည့်သွင်းထားသော ပရောဂျက်ကို သင်ကိုယ်တိုင် ဖန်တီးသော ပရောဂျက်ကဲ့သို့ ပရောဂျက်များ စီမံရန် တွင် ဖွင့်၍ ပြောင်းလဲနိုင်သည်။

တိုက်ရိုက် ပူးပေါင်းဆောင်ရွက်မှု
သူငယ်ချင်းနှင့် အတူ ပရောဂျက်တစ်ခုတွင် လုပ်ဆောင်ရန် - အဓိက မီနူးတွင် ပူးပေါင်းဆောင်ရွက်မှု ကို ဖွင့်ပါ၊ ပရောဂျက်ကို ရွေးချယ်ပါ၊ ပြောင်းလဲမှု မှတ်စု (ဘာပြောင်းလဲခဲ့သလဲ) ကို ရေးပြီး ပူးပေါင်းဆောင်ရွက်မှုအတွက် မျှဝေပါ ကို နှိပ်ပါ။ ပရောဂျက်ကို အတွင်း၌ CATATAN.txt ဖိုင်ပါသော ZIP အဖြစ် ပို့သည်။ သင့်သူငယ်ချင်းသည် ၎င်းပေါ်တွင် လုပ်ဆောင်ပြီး ZIP ကို ပြန်ပို့သည်။ သင်သည် အဖြေ လက်ခံပါ ကို နှိပ်ပြီး ပထမဦးစွာ ပြောင်းလဲမှု မှတ်စုကို ဖတ်ကာ ထို့နောက် ပရောဂျက်အဟောင်းကို အစားထိုးရန် အသုံးပြုပါ ကို ရွေးချယ်ပါ သို့မဟုတ် စိတ်ပြောင်းပါက ပယ်ဖျက်ရန် ကို ရွေးချယ်ပါ။ CATATAN.txt မပါသော ZIP သည် ပူးပေါင်းဆောင်ရွက်မှု အထုပ် မဟုတ်ပါ — သာမန် ပရောဂျက် ZIP အတွက် ပရောဂျက်များ စီမံရန် ရှိ ပရောဂျက် တင်သွင်းပါ ကို အသုံးပြုပါ။

အလိုအလျောက် အက်ပ် ဘာသာပြန်စက်
အက်ပ်၏ စာသားကို အခြားဘာသာစကားသို့ ဘာသာပြန်ရန် - အဓိက မီနူးတွင် အက်ပ် ဘာသာပြန် ကို ဖွင့်ပါ၊ ပရောဂျက်နှင့် ပစ်မှတ် ဘာသာစကား (အင်္ဂလိပ်၊ အာရဗီ သို့မဟုတ် ဂျာဗားနီးစ်) ကို ရွေးချယ်ပြီး ဘာသာပြန်ပါ ကို နှိပ်ပါ။ အဘိဓာန်သည် ဖုန်းအတွင်း၌ ရှိပြီးသားဖြစ်သည် (အင်တာနက် မလိုဘဲ၊ အခမဲ့) နှင့် နေ့စဉ် အသုံးများသော စကားလုံးများ ပါဝင်သည်။ စာသားကို strings.xml၊ အပြင်အဆင် နှင့် ကုဒ်မှ ဖတ်၍ ဘာသာပြန်သည်။ ရလဒ်ကို values-ဘာသာစကား/strings.xml ဖိုင်တွဲ (ပရောဂျက်တွင် strings.xml ရှိပါက) နှင့် ပရောဂျက် ဖိုင်တွဲရှိ ဘာသာပြန်-ဘာသာစကား.txt အစီရင်ခံစာသို့ ရေးသည်။ အဘိဓာန်တွင် မရှိသေးသော စကားလုံးများကို အတိုင်းထားပြီး အစီရင်ခံသည် — ထို့ကြောင့် မည်သည့်စကားလုံးများကို သင်ကိုယ်တိုင် ဘာသာပြန်ရမည်ကို သိသည်။

ကုဒ်မပါဘဲ ဂိမ်း ဖန်တီးစက်
ကုဒ် မရေးဘဲ ဂိမ်း ဖန်တီးရန် - အဓိက မီနူးတွင် ကုဒ်မပါဘဲ ဂိမ်း ဖန်တီးစက် ကို ဖွင့်ပါ၊ ဂိမ်း အမျိုးအစား (နံပါတ် ခန့်မှန်းပါ၊ မေးခွန်းလွှာ သို့မဟုတ် ကြယ်ကို ဖမ်းပါ) ကို ရွေးချယ်ပါ၊ ဂိမ်း အမည်၊ ပမာဏ (အဆင့်များ/မေးခွန်းများ/ကြယ်များ) နှင့် အနိုင်ရ မက်ဆေ့ချ်ကို ဖြည့်ပြီး ဂိမ်း ဖန်တီးပါ ကို နှိပ်ပါ။ ဂိမ်းကို ပရောဂျက်များ စီမံရန် တွင် တိုက်ရိုက် လုပ်ဆောင်နိုင်ပြီး အခြား ပရောဂျက်တိုင်းကဲ့သို့ APK အဖြစ် တည်ဆောက်နိုင်သော အစစ်အမှန် ပရောဂျက်အဖြစ် ဖန်တီးသည်။

အလိုအလျောက် အက်ပ် စမ်းသပ်ခြင်း
ပရောဂျက်ကို မတည်ဆောက်မီ စစ်ဆေးရန် - ပရောဂျက်များ စီမံရန် တွင် ပရောဂျက် အမည်ကို ကြာကြာ ဖိပြီး အလိုအလျောက် စမ်းသပ်ချက် ကို ရွေးချယ်ပါ။ IDE သည် APK မတည်ဆောက်ဘဲ အရာ ၁၀ ခုကို စစ်ဆေးသည် — မဖြစ်မနေ ဖိုင်များ ရှိသည် (ပရောဂျက် ဒေတာ ဖိုင်၊ မန်နီဖက်စ်၊ အဓိက ဖိုင်၊ အပြင်အဆင်၊ စာကြောင်းများ)၊ ပက်ကေ့ဂျ် အမည်နှင့် ဗားရှင်း၊ အသုံးပြုသော ခွင့်ပြုချက်များ၊ အိုင်ကွန်နှင့် ကုဒ် ကွင်းစကွင်းပိတ်များ၏ ဟန်ချက်ညီမှု။ ရလဒ်ကို အချက်တစ်ခုချင်းစီ ပြသည် (အောင်မြင်/ကျရှုံး မက်ဆေ့ချ်နှင့်အတူ) နှင့် Jieshuo က အသံဖြင့် ဖတ်ပြသည်။ ပထမဦးစွာ ကျရှုံးခဲ့သမျှကို ပြင်ပြီး ပရောဂျက် တည်ဆောက်ပါ ကို နှိပ်ပါ။

ပရောဂျက် ကုဒ်ကို ပြဿနာများ မကြာခဏ ဖြစ်စေသော ပုံစံများအတွက် စစ်ဆေးရန် - အဓိက မီနူးတွင် ကုဒ် စစ်ဆေးရန် ကို ဖွင့်ပါ၊ ပရောဂျက်ကို ရွေးချယ်ပြီး ကုဒ် စစ်ဆေးရန် ကို နှိပ်ပါ။ စစ်ဆေးသူသည် ဖုန်းအတွင်း၌ အလုပ်လုပ်သည် (အင်တာနက် မလိုဘဲ) နှင့် အသုံးမပြုသော ကိန်းရှင်များ၊ ဗလာ လုပ်ဆောင်ချက်များ၊ သိသာထင်ရှားသော အဆုံးမရှိ ကွင်းများ၊ ကုဒ်ထဲသို့ တိုက်ရိုက် ရေးထားသော စာသား (strings.xml တွင် ပိုကောင်းသည်)၊ အန္တရာယ်ရှိသော ခွင့်ပြုချက်များနှင့် API များ၊ TODO/FIXME အမှတ်အသားများနှင့် ရွေ့လျားသော လုပ်ဆောင်မှုကို ရှာဖွေသည်။ တွေ့ရှိချက်တိုင်းတွင် ဖိုင် အမည်၊ လိုင်းနံပါတ်နှင့် ပြင်ဆင်ရန် အကြံပြုချက် ပါဝင်သည်။ ဤစစ်ဆေးသူသည် ပုံစံအခြေခံဖြစ်ပြီး AI အစစ်အမှန် မဟုတ်ပါ — ပုံစံကို မလိုက်နာသော ပြဿနာများ လွတ်သွားနိုင်သေးသည်။

အပြန်အလှန် သင်ယူမှု မုဒ်
အက်ပ်များ ဖန်တီးရန် အဆင့်ဆင့် သင်ယူရန် - အဓိက မီနူးတွင် သင်ယူမှု မုဒ် ကို ဖွင့်ပါ။ သင်ခန်းစာ ၅ ခု ရှိသည် - သင့်ပထမဆုံး ပရောဂျက်ကို ဖန်တီးပါ၊ ခလုတ် ထည့်ပါ၊ အရောင် ပြောင်းပါ၊ အသံ ထည့်ပါ နှင့် APK တည်ဆောက်ပါ။ ရှင်းလင်းချက်နှင့် လေ့ကျင့်ခန်း လုပ်ငန်းကို ဖတ်ရန် သင်ခန်းစာကို ထိပါ၊ လုပ်ငန်းကို လုပ်ပြီး လုပ်ငန်း စစ်ဆေးပါ ကို နှိပ်ပါ — IDE သည် လုပ်ငန်း ပြီးမြောက်ခဲ့ခြင်း ရှိ/မရှိကို အမှန်တကယ် စစ်ဆေးသည် (သင့်ဖုန်းရှိ ပရောဂျက်နှင့် APK ကို စကင်ဖတ်ခြင်းဖြင့်)။ အောင်မြင်သော သင်ခန်းစာများကို ပြီးမြောက်ပြီးအဖြစ် အမှတ်အသားပြုပြီး သိမ်းဆည်းသည်။

Cloud စင့်ခ်လုပ်ရန်
ပရောဂျက်ကို Cloud သို့ အရန်ကူးရန် - အဓိက မီနူးတွင် Cloud စင့်ခ်လုပ်ရန် ကို ဖွင့်ပါ။ ဒေသတွင်း အရန်ကူးသည် ပရောဂျက် ZIP ကို အချိန်တံဆိပ်တုံးဖြင့် Download/cloud ဖိုင်တွဲသို့ သိမ်းဆည်းပြီး အရန်ကူးစာရင်းမှ အချိန်မရွေး ပြန်လည်ရယူနိုင်သည်။ GitHub အရန်ကူးသည် ပရောဂျက် ZIP ကို သင့်သီးသန့် repo သို့ တင်သည် (GitHub ဆက်တင်များမှ တိုကင်ကို အသုံးပြု၍) နှင့် ပြန်လည် ဒေါင်းလုဒ်လုပ်နိုင်သည်။ ဤသည်မှာ ကိုယ်တိုင် အရန်ကူးခြင်းနှင့် ပြန်လည်ရယူခြင်း ဖြစ်သည် — အပြည့်အဝ အလိုအလျောက် နှစ်လမ်းသွား စင့်ခ်လုပ်ခြင်းအတွက် ဆာဗာ လိုအပ်သည်၊ ထို့ကြောင့် မရှိသေးပါ။

အလိုအလျောက် Backend ဖန်တီးသူ
ဆာဗာ ကုဒ် မရေးဘဲ Backend ဖန်တီးရန် - အဓိက မီနူးတွင် Backend ဖန်တီးသူ ကို ဖွင့်ပါ၊ Backend အမျိုးအစား (မှတ်စုများ၊ လုပ်ငန်းစာရင်း သို့မဟုတ် ကြေညာဘုတ်) ကို ရွေးချယ်ပါ၊ ပရောဂျက် အမည်ကို ဖြည့်ပြီး Backend ဖန်တီးပါ ကို နှိပ်ပါ။ IDE သည် ဖောင်စာမျက်နှာနှင့် ဖုန်း၏ ဒေသတွင်း သိုလှောင်မှု (localStorage) တွင် သိမ်းဆည်းထားသော ဒေတာ စာရင်းပါသော အစစ်အမှန် HTML ပရောဂျက်ကို ဖန်တီးသည် — ဒေတာကို သိမ်းဆည်းပြီး အက်ပ် လုပ်ဆောင်သောအခါ ပြန်လည် ဖတ်နိုင်သည်။ ဤ Backend သည် ဖုန်းတစ်လုံးပေါ်တွင် လုပ်ဆောင်သည်။ အင်တာနက် ဆာဗာ မရှိသောကြောင့် ဖုန်းနှစ်လုံးသည် တူညီသော ဒေတာကို မမျှဝေနိုင်သေးပါ။

အလိုအလျောက် အပြင်အဆင် ဒီဇိုင်နာ
ပရောဂျက်ကို အရောင် အပြင်အဆင် ပေးရန် - အဓိက မီနူးတွင် Theme ဒီဇိုင်နာ ကို ဖွင့်ပါ၊ ပရောဂျက်နှင့် အပြင်အဆင် (အလင်းရောင်၊ အမှောင်ရောင်၊ အပြာရောင်၊ အစိမ်းရောင်၊ အနီရောင် သို့မဟုတ် ခရမ်းရောင်) ကို ရွေးချယ်ပါ။ အစမ်းကြည့်ခြင်းတွင် အပြင်အဆင်၏ အရောင် ခြောက်ခု (အဓိက၊ အမှောင် အဓိက၊ လေယူလေသိမ်း၊ နောက်ခံ၊ စာသား၊ ဒုတိယ စာသား) ကို ပြသပြီး Jieshuo က အသံဖြင့် ဖတ်ပြသည်။ အပြင်အဆင် အသုံးချပါ ကို နှိပ်ပါ — IDE သည် colors.xml နှင့် styles.xml (app_theme ပုံစံ) ကို ပရောဂျက်သို့ ရေးသည်၊ ပရောဂျက် လုပ်ဆောင်သည့်အခါ သို့မဟုတ် တည်ဆောက်သည့်အခါ တိုက်ရိုက် အသုံးပြုသည်။

အန်နီမေးရှင်း ဖန်တီးသူ
ပရောဂျက်ကို Animation ပေးရန် - အဓိက မီနူးတွင် အန်နီမေးရှင်း ဖန်တီးသူ ကို ဖွင့်ပါ၊ ပရောဂျက်၊ Animation အမျိုးအစား (မှေးမှိန်၊ လျှောကျ၊ လည်၊ ခုန် သို့မဟုတ် ခုန်လှုပ်)၊ ကြာချိန် (၁၀၀ မှ ၁၀၀၀၀ မီလီစက္ကန့်) နှင့် ပစ်မှတ် (ခလုတ်၊ စာသား သို့မဟုတ် ပုံ) ကို ရွေးချယ်ပြီး Animation ဖန်တီးပါ ကို နှိပ်ပါ။ IDE သည် အစစ်အမှန် Animation ဖိုင်ကို ရေးသည် (Java/Kotlin/Compose ပရောဂျက်များအတွက် res/anim/anim_<အမျိုးအစား>.xml သို့မဟုတ် HTML/ဝက်ဘ်ဆိုက် ပရောဂျက်များအတွက် animasi.css) နှင့် မျက်နှာပြင်တွင် ပြသထားသော အသုံးပြုမှု နမူနာ ကုဒ်နှင့်အတူ။

လုပ်ဆောင်ချက် မှတ်တမ်းတင်သူ
အလုပ်ကို အလိုအလျောက် ပြန်လုပ်ရန် - IDE သည် လုပ်ဆောင်ခဲ့သော လုပ်ဆောင်ချက်များကို မှတ်တမ်းတင်သည် (ပရောဂျက် ဖွင့်ခြင်း၊ လုပ်ဆောင်ခြင်း၊ တည်ဆောက်ခြင်း၊ ထုတ်ယူခြင်း၊ အရန်ကူးခြင်း၊ ပရောဂျက် ဖန်တီးခြင်း၊ ဖိုင် သိမ်းဆည်းခြင်း)။ အဓိက မီနူးတွင် လုပ်ဆောင်ချက် မှတ်တမ်းတင်သူ ကို ဖွင့်ပြီး မှတ်တမ်းတင်ထားသော လုပ်ဆောင်ချက်များ စာရင်းကို ၎င်းတို့၏ အစီအစဉ်နှင့်အတူ ကြည့်ပြီး ပြန်ဖွင့်ပါ ကို နှိပ်ပါ — IDE သည် အလိုအလျောက် ပြုလုပ်နိုင်သော လုပ်ဆောင်ချက်များကို ပြန်လည် လုပ်ဆောင်သည် (အရန်ကူးခြင်းနှင့် ပရောဂျက် ဖန်တီးခြင်းကို ထိုနေရာ၌ လုပ်ဆောင်သည်။ လုပ်ဆောင်ခြင်း၊ တည်ဆောက်ခြင်းနှင့် ထုတ်ယူခြင်းတို့သည် ၎င်းတို့၏ အဓိက မျက်နှာပြင်ကို ဖွင့်သည်။ ဖွင့်ခြင်းနှင့် သိမ်းဆည်းခြင်းတို့သည် တည်းဖြတ်သူကို ဖွင့်သည်)။ အလိုအလျောက် ပြုလုပ်၍ မရသော လုပ်ဆောင်ချက်များကို ကျော်သွားပြီး အဆုံးတွင် အစီရင်ခံသည်။

အလိုအလျောက် လုံခြုံရေး
ပရောဂျက်၏ လုံခြုံရေးကို စစ်ဆေးရန် - အဓိက မီနူးတွင် အလိုအလျောက် လုံခြုံရေး ကို ဖွင့်ပါ၊ ပရောဂျက်ကို ရွေးချယ်ပြီး လုံခြုံရေး စစ်ဆေးပါ ကို နှိပ်ပါ။ IDE သည် အရာ ၈ ခုကို ဒေသတွင်း စစ်ဆေးသည် (အင်တာနက် မလိုဘဲ) - အန္တရာယ်ရှိသော ခွင့်ပြုချက်များ (တည်နေရာ၊ SMS၊ ခေါ်ဆိုမှုများ၊ ကင်မရာ၊ မိုက်ခရိုဖုန်း၊ အဆက်အသွယ်များ)၊ HTTP မှတစ်ဆင့် ဒေတာ ပို့ခြင်း၊ SMS ပို့ခြင်း၊ အထွက် ခေါ်ဆိုမှုများ၊ ကုဒ်ထဲသို့ တိုက်ရိုက် ရေးထားသော စကားဝှက် သို့မဟုတ် သော့၊ အကာအကွယ်မဲ့ WebView၊ ခွင့်ပြုချက်မရှိဘဲ ထုတ်ယူထားသော အစိတ်အပိုင်း နှင့် စာဝှက်မထားသော http လိပ်စာ။ တွေ့ရှိချက်တိုင်းသည် ပြင်ဆင်ရန် အကြံပြုချက်နှင့်အတူ လုံခြုံ၊ သတိပေးချက် သို့မဟုတ် အန္တရာယ် အဆင့်ကို ရရှိပြီး အကျဉ်းချုပ်ကို Jieshuo က အသံဖြင့် ဖတ်ပြသည်။

AI အော့ဖ်လိုင်း
အင်တာနက် မလိုဘဲ စာသားနှင့် ကုဒ် အကူအညီများကို အသုံးပြုရန် - အဓိက မီနူးတွင် AI အော့ဖ်လိုင်း ကို ဖွင့်ပါ။ ကိရိယာ ၄ ခု ရှိသည် - စာသား ပြင်ပါ (အကြီးစာလုံးများ၊ ပုဒ်ဖြတ်ပုဒ်ရပ်များနှင့် နှစ်ထပ် နေရာလွတ်များ)၊ စာသား အကျဉ်းချုပ်ပါ (အရေးကြီးဆုံး စာကြောင်း ၃ ကြောင်းကို ယူသည်)၊ အက်ပ်အမည် ဖန်တီးပါ (ရေးသားထားသော ဖော်ပြချက်မှ) နှင့် ကိန်းရှင် အမည်များ အကြံပြုပါ (ပရောဂျက်ရှိ ၁–၂ စာလုံး ကိန်းရှင် အမည်များကို ရှာသည်)။ ဤသည်မှာ ဖုန်းအတွင်းရှိ ရိုးရှင်းသော စည်းမျဉ်းများ ဖြစ်ပြီး AI မော်ဒယ် အစစ်အမှန် မဟုတ်ပါ။ စာသား ပြင်ဆင်မှု ရလဒ်ကို အသုံးပြုပါ ခလုတ်ဖြင့် ပရောဂျက်၏ strings.xml တွင် အသုံးချနိုင်သည်။

Widget နှင့် Wallpaper ဖန်တီးသူ
ပင်မ မျက်နှာပြင်အတွက် Widget ဖန်တီးရန် - အဓိက မီနူးတွင် Widget နှင့် နောက်ခံပုံ ကို ဖွင့်ပါ၊ ပရောဂျက်ကို ရွေးချယ်ပါ၊ Widget စာသားကို ဖြည့်ပြီး Widget ဖန်တီးပါ ကို နှိပ်ပါ။ IDE သည် WidgetSaya.java၊ Widget အပြင်အဆင်၊ Widget အချက်အလက်များကို ရေးပြီး ပရောဂျက်၏ AndroidManifest.xml သို့ လက်ခံသူကို ထည့်သည် — ပရောဂျက်ကို တည်ဆောက်ပြီး ဖုန်း၏ ပင်မ မျက်နှာပြင်မှ Widget ကို ထည့်သွင်းပါ။ နောက်ခံပုံအတွက် - စာသားနှင့် နောက်ခံနှင့် စာသား အရောင်များကို ဖြည့်ပါ၊ အစမ်းကြည့်ခြင်းကို ပြုလုပ်ပြီး PNG အဖြစ် Download ဖိုင်တွဲသို့ သိမ်းဆည်းပါ သို့မဟုတ် ဖုန်း နောက်ခံပုံအဖြစ် တိုက်ရိုက် သတ်မှတ်ပါ။

လူမှုမီဒီယာ ပေါင်းစပ်မှု
အက်ပ်သို့ မျှဝေခြင်း ခလုတ်များ ထည့်ရန် - အဓိက မီနူးတွင် လူမှုမီဒီယာ ပေါင်းစပ်မှု ကို ဖွင့်ပါ၊ ပရောဂျက်ကို ရွေးချယ်ပြီး WhatsApp၊ Facebook သို့မဟုတ် Telegram သို့ မျှဝေခြင်း (သို့မဟုတ် သုံးခုလုံးကို တစ်ပြိုင်နက်) ထည့်ပါ။ IDE သည် ပရောဂျက်၏ အဓိက ဖိုင် (MainActivity သို့မဟုတ် index.html) သို့ အစစ်အမှန် မျှဝေခြင်း ကုဒ်ကို ရေးသည်။ မျှဝေမှု စမ်းသပ်ချက် ခလုတ်သည် IDE မှ နမူနာ စာသားဖြင့် မျှဝေခြင်း ရွေးချယ်သူကို ဖွင့်သည်၊ ထို့ကြောင့် အက်ပ် မတည်ဆောက်မီ စီးဆင်းမှုကို ခံစားနိုင်သည်။

ပုံမှ အက်ပ်
ပုံမှ ဓာတ်ပုံ ပြခန်း အက်ပ် ဖန်တီးရန် - အဓိက မီနူးတွင် ပုံမှ အက်ပ် ကို ဖွင့်ပြီး ဓာတ်ပုံ ပြခန်းမှ ပုံကို ရွေးချယ်ပါ။ IDE သည် ပုံ၏ အရွယ်အစားနှင့် အဓိက အရောင်ကို ခွဲခြမ်းစိတ်ဖြာပြီး အစစ်အမှန် ဓာတ်ပုံ ပြခန်း အက်ပ် ပရောဂျက်ကို ဖန်တီးသည် - ပုံကို ပရောဂျက်၏ assets သို့ ကူးယူသည်၊ အပြင်အဆင် အရောင်ကို ပုံ၏ အဓိက အရောင်မှ ယူသည်၊ အက်ပ် အမည်ကို ပုံ ဖိုင် အမည်မှ ယူသည်။ ဓာတ်ပုံ ပြခန်း အက်ပ်ကို လုပ်ဆောင်ရန် သို့မဟုတ် တည်ဆောက်ရန် ပရောဂျက်များ စီမံရန် ကို ဖွင့်ပါ။

အပြန်အလှန် Terminal (VT ခွဲခြမ်းစိတ်ဖြာသူ)
Terminal တွင် အပြန်အလှန် ပရိုဂရမ်များကို အသုံးပြုရန် - အဓိက မီနူးတွင် Terminal ကို ဖွင့်ပြီး nano၊ vim၊ top သို့မဟုတ် htop ကို လုပ်ဆောင်ပါ။ Terminal သည် ယခု VT ခွဲခြမ်းစိတ်ဖြာသူကို အသုံးပြုသည် (၂၄ တန်း x ၈၀ ကော်လံ ဇယားကွက် မျက်နှာပြင်) ထို့ကြောင့် ဤပရိုဂရမ်များကို မှန်ကန်စွာ ပြသသည် — ကာဆာ ရွေ့လျားသည်၊ လိုင်းများ ဖျက်ပစ်သည်၊ မျက်နှာပြင်သည် အစစ်အမှန် terminal ကဲ့သို့ ပြောင်းလဲသည်။ အပြန်အလှန် ပရိုဂရမ်များကို ထိန်းချုပ်ရန် Tab၊ အထက် မြှား၊ အောက် မြှား နှင့် Esc အတွက် အထူး ခလုတ်များ ရှိသည်။ ရလဒ်သည် Jieshuo ဖတ်နိုင်သော စာသားအဖြစ် ကျန်ရှိသည်။ နောက်ဆုံး လိုင်းကို ကြားရန် မျက်နှာပြင် ဖတ်ပြပါ ကို နှိပ်ပါ။

Terminal Exec (အက်ပ် Binary)
အက်ပ် ဖိုင်တွဲရှိ ဘိုင်နရီ ဖိုင် (ဥပမာ aapt2၊ ECJ၊ D8) ကို Terminal မှ လုပ်ဆောင်ရန် - အမိန့်ကို ပုံမှန်အတိုင်း ရိုက်ထည့်ပါ။ IDE သည် libkautsarexec.so ကို အသုံးပြုသည်၊ ထို့ကြောင့် အက်ပ် ဖိုင်တွဲရှိ ဘိုင်နရီ ဖိုင်များကို Android 10 နှင့် အသစ်များတွင် လုပ်ဆောင်နိုင်သည်။ ဤဖုန်းတွင် ဘိုင်နရီ exec လမ်းကြောင်း အလုပ်လုပ်ခြင်း ရှိ/မရှိ စစ်ဆေးရန် Terminal ရှိ Exec စမ်းသပ်ချက် ကို နှိပ်ပါ — ရလဒ်ကို ရှိသည့်အတိုင်း ပြသသည်။ exec ကို စနစ်က ပိတ်ဆို့ထားပါက စနစ် အမိန့်များနှင့် shell script များ ဆက်လက် လုပ်ဆောင်သည်။ ဘိုင်နရီ ဖိုင်ကို ပရောဂျက် တည်ဆောက်ပါ မီနူးမှတစ်ဆင့် လုပ်ဆောင်ပါ။

Terminal အမြဲအသက်ဝင်နေခြင်း (KeepAlive)
မျက်နှာပြင် ပြောင်းသည့်အခါ shell ကို ဆက်လက် လုပ်ဆောင်နေစေရန် - Terminal ကို ဖွင့်ပါ၊ အမိန့်ကို လုပ်ဆောင်ပြီး နောက်သို့ ကို နှိပ်ပါ သို့မဟုတ် အခြား မျက်နှာပြင်သို့ ပြောင်းပါ — shell သည် မသေပါ၊ Terminal အကြောင်းကြားစာ ဆက်လက် ပြသနေသည်၊ ထို့ကြောင့် တစ်ချက်နှိပ်ရုံဖြင့် ပြန်သွားနိုင်သည်။ လုပ်ဆောင်ခဲ့သော အမိန့်များကို မှတ်တမ်း (မှတ်တမ်း ခလုတ် သို့မဟုတ် အမိန့် အကွက်ရှိ အထက်/အောက် မြှားများ) တွင် သိမ်းဆည်းပြီး မကြာခဏ အသုံးပြုသော အမိန့်များကို အကြိုက်ဆုံးများ အဖြစ် သိမ်းဆည်းနိုင်သည် (အကြိုက်ဆုံးများ ခလုတ်)။ ပြီးဆုံးပါက shell အမှန်တကယ် ပြီးဆုံးစေရန် Shell ပိတ်ပါ ကို နှိပ်ပါ။ ပရောဂျက် မီနူးနှင့် တည်းဖြတ်သူ မီနူးတွင်လည်း Terminal မှာ တည်ဆောက်ပါ ခလုတ် ရှိသည် - Terminal သည် တည်ဆောက်ခြင်း အမိန့် ဖြည့်ပြီးသား ပရောဂျက် ဖိုင်တွဲတွင် ပွင့်သည်။

Terminal ကိရိယာများ ထည့်သွင်းခြင်း (စမ်းသပ်မှု)
စမ်းသပ်ဆဲဖြစ်သော လုပ်ဆောင်ချက် - Terminal တွင် ဆော့ဖ်ဝဲရေးသူ၏ alat-termux repo (github.com/syudat/alat-termux) မှ Termux ပတ်ဝန်းကျင်ကို ထည့်သွင်းရန် Terminal ကိရိယာများ ထည့်သွင်းခြင်း (စမ်းသပ်မှု) ခလုတ် ရှိသည်၊ တရားဝင် Termux ထုတ်ဝေမှုမှ ရယူသော Termux ထည့်သွင်းပါ ခလုတ်အပြင် အခြား လမ်းကြောင်းအဖြစ်။ ကြေးမုံ၏ အကြောင်းအရာသည် တရားဝင် ထုတ်ဝေမှုနှင့် အတိအကျ တူညီပြီး ထည့်သွင်းစဉ် SHA-256 ဖြင့် စစ်ဆေးသည်။ ပတ်ဝန်းကျင် ထည့်သွင်းပြီးပါက pkg update နှင့် pkg install အမိန့်များကို အသုံးပြုနိုင်ပြီး repo မှ အပို ကိရိယာများကိုလည်း terminal သို့ ထည့်သွင်းသည် - info-terminal ပတ်ဝန်းကျင် အချက်အလက်ကို ကြည့်ရန်၊ bersih-terminal cache ကို ရှင်းလင်းရန် နှင့် cadangkan-proyek ပရောဂျက် ဖိုင်တွဲကို ရက်စွဲပါသော tar.gz ဖိုင်တစ်ခုတည်းသို့ သိမ်းဆည်းရန်။ ထို့နောက် အက်ပ်သည် အခြေခံ Linux ပက်ကေ့ဂျ်များ (git, python, curl, wget, nano, openssh, zip, unzip) နှင့် လက်မှတ်ပါသော APK တည်ဆောက်ခြင်း ကိရိယာများ (openjdk-21, kotlin, gradle, ecj, aapt2, d8, apksigner, clang, cmake, ninja, make) ကို တရားဝင် Termux repo မှ အလိုအလျောက် ထည့်သွင်းသည်၊ ထို့ကြောင့် terminal သည် အက်ပ်များ တည်ဆောက်ရန် ချက်ချင်း အဆင်သင့် ဖြစ်နေသည်။ ကြီးမားသော ပက်ကေ့ဂျ်များ (ရာဂဏန်း MB) ဒေါင်းလုဒ်လုပ်ရန် အချိန်ကြာနိုင်သည်။ ထည့်သွင်းမှု လုပ်ဆောင်နေစဉ် တိုးတက်မှုနှင့် အမိန့် ရလဒ်ကို Terminal ၏ အဓိက မျက်နှာပြင်တွင် ပြသပြီး နောက်ဆုံး ရလဒ်ကို မျက်နှာပြင် ဖတ်သူမှ အသံဖြင့် ဖတ်ပြသည်။ ပက်ကေ့ဂျ် ထည့်သွင်းမှု မပြီးသေးပါက ဆက်လက်လုပ်ဆောင်ရန် Terminal ကိရိယာများ ထည့်သွင်းခြင်း (စမ်းသပ်မှု) ကို ထပ်မံ နှိပ်ပါ။

အသံ Mode အပြည့်
IDE ကို အသံဖြင့် လုံးဝ ထိန်းချုပ်ရန် - အဓိက မီနူးတွင် အသံ Mode အပြည့် ကို ဖွင့်ပြီး နားထောင် စတင်ပါ ကို နှိပ်ပါ။ IDE သည် စဉ်ဆက်မပြတ် နားထောင်သည် — အမိန့်တိုင်းအတွက် ခလုတ် နှိပ်ရန် မလိုအပ်ပါ — အမိန့်ကို လုပ်ဆောင်ပြီး အသံဖြင့် ဖြေကြားသည်။ အမိန့် ၂၆ ခု ရှိသည် - ဖန်တီးပါ၊ တည်ဆောက်ပါ၊ ဖွင့်ပါ၊ လုပ်ဆောင်ပါ၊ စာရင်းပြုစုပါ၊ ရှာပါ၊ ဖျက်ပါ၊ စမ်းသပ်ပါ၊ စစ်ဆေးပါ၊ ထုတ်ယူပါ၊ အရန်ကူးပါ၊ မျှဝေပါ၊ အိုင်ကွန် ဖန်တီးပါ၊ ဘာသာပြန်ပါ၊ Terminal မှာ တည်ဆောက်ပါ၊ မျက်နှာပြင် ဖတ်ပါ၊ မျက်နှာပြင်အားလုံးကို ဖွင့်ပါ (လုံခြုံရေး၊ AI အော့ဖ်လိုင်း၊ Widget၊ လူမှုမီဒီယာ၊ ဂိမ်း၊ သင်ယူမှု၊ Cloud၊ Backend၊ အပြင်အဆင်၊ Animation၊ မှတ်တမ်းတင်သူ အပါအဝင်)၊ နောက်သို့၊ ပိတ်ပါ နှင့် အကူအညီ။ မုဒ်ကို တက်ကြွနေစေပါက ဤမျက်နှာပြင်ကို ပြန်ဖွင့်သည့်အခါ နားထောင်ခြင်းသည် အလိုအလျောက် ဆက်လက်လုပ်ဆောင်သည်။ မုဒ်ကို ပိတ်ရန် နားထောင် ရပ်ပါ ကို နှိပ်ပါ။ ဖုန်းတွင် အသံ မှတ်မိခြင်း ဝန်ဆောင်မှု မရှိပါက အမိန့်များကို စာသား အကွက်တွင် ရိုက်ထည့်နိုင်သေးသည်။

ကုဒ် ဘာသာပြန်
ကုဒ်ကို ဘာသာစကားများအကြား အင်တာနက် မလိုဘဲ ဘာသာပြန်ရန် - အဓိက မီနူးတွင် ကုဒ် ဘာသာပြန် ကို ဖွင့်ပါ၊ ပရောဂျက်ကို ရွေးချယ်ပါ၊ အရင်းအမြစ် ဖိုင် (.java/.kt) ကို ရွေးချယ်ပြီး ဦးတည်ချက် ရွေးချယ်ပါ - Java မှ Kotlin သို့။ ဘာသာပြန်ပါ ကို နှိပ်ပါ — ရလဒ်ကို ဘာသာပြန်၍ မရသော လိုင်းများ၏ အစီရင်ခံစာနှင့်အတူ ပြသသည် (ဤလိုင်းများကို အတိုင်းထားပြီး အမှတ်အသားပြုသည်)။ တူညီသော ဖိုင်တွဲတွင် ဖိုင်အသစ် (အမည်-ဘာသာပြန်.java/.kt) ရေးရန် ရလဒ် သိမ်းပါ ကို နှိပ်ပါ။ မူရင်း ဖိုင်ကို ဘယ်တော့မှ အစားမထိုးပါ။ ဤသည်မှာ ပုံစံ စည်းမျဉ်း ဘာသာပြန်သူ ဖြစ်ပြီး ကွန်ပိုင်လာ မဟုတ်ပါ — အသုံးမပြုမီ ရလဒ်ကို အမြဲ စစ်ဆေးပါ။

အက်ပ်အတွင်း Git
Termux မလိုဘဲ IDE တွင် Git အသုံးပြုရန် - အဓိက မီနူးတွင် အက်ပ်အတွင်း Git ကို ဖွင့်ပါ၊ ပရောဂျက်ကို ရွေးချယ်ပြီး Git Repo ဖန်တီးပါ ကို နှိပ်ကာ ထိုပရောဂျက်တွင် ဒေသတွင်း repo (.git) ဖန်တီးပါ။ နောက်ဆုံး Commit နှင့် နှိုင်းယှဉ်ပြီး အသစ်၊ ပြောင်းလဲထားသော သို့မဟုတ် ဖျက်ထားသော ဖိုင်များကို ကြည့်ရန် Status စစ်ဆေးပါ ကို နှိပ်ပါ။ Commit မက်ဆေ့ချ်ကို ဖြည့်ပြီး ပရောဂျက်၏ လျှပ်တစ်ပြက် ပုံကို သိမ်းဆည်းရန် Commit ကို နှိပ်ပါ။ Commit မှတ်တမ်းကို ကြည့်ရန် Commit Log ကြည့်ပါ ကို နှိပ်ပါ။ GitHub သို့ Push နှင့် GitHub မှ Pull တို့သည် GitHub တိုကင် (pembuat-aplikasi-build repo) မှတစ်ဆင့် လျှပ်တစ်ပြက် ပုံများကို အသုံးပြုသည် — git ပရိုတိုကော မဟုတ်ပါ။ Clone၊ Push (system-git) နှင့် Pull (system-git) တို့သည် ဖုန်းတွင် git ဘိုင်နရီ ထည့်သွင်းထားမှသာ လုပ်ဆောင်သည် (များသောအားဖြင့် မရှိပါ)။ ဤသည်မှာ Git အပြည့်အစုံ မဟုတ်ပါ - ပေါင်းစည်းခြင်း၊ အကိုင်းအခက် သို့မဟုတ် ကွာခြားချက် မရှိပါ — Commit တိုင်းသည် ပရောဂျက်၏ အပြည့်အစုံ ZIP လျှပ်တစ်ပြက် ပုံကို သိမ်းဆည်းသည်။

ကြော်ငြာ ဖန်တီးသူ
တည်ဆောက်ထားသော အက်ပ်သို့ ကြော်ငြာများ ထည့်ရန် - အဓိက မီနူးတွင် ကြော်ငြာ ဖန်တီးသူ ကို ဖွင့်ပါ၊ ပရောဂျက်၊ ပေးသွင်းသူ (AdMob၊ Unity Ads သို့မဟုတ် AppLovin) နှင့် ကြော်ငြာ အမျိုးအစား (Banner၊ Interstitial သို့မဟုတ် ဆုလာဘ်ရသော) ကို ရွေးချယ်ပါ။ ကြော်ငြာ ယူနစ် ID ရှိပါက ဖြည့်ပါ — ဗလာဖြစ်ပါက စမ်းသပ်မှု ID ကို အသုံးပြုသည် (AdMob သည် Google ၏ တရားဝင် စမ်းသပ်မှု ID ကို အသုံးပြုသည်။ Unity သည် နမူနာ Game ID ကို အသုံးပြုသည်။ AppLovin သည် ဗလာ နေရာကို အသုံးပြုသည်)။ Java နှင့် Kotlin ကုဒ်နှင့် လမ်းညွှန်ကို ကြည့်ရန် ကြော်ငြာ ကုဒ် ဖန်တီးပါ ကို နှိပ်ပါ။ အားလုံးကို ပရောဂျက်ရှိ ကြော်ငြာ-<ပေးသွင်းသူ>-<အမျိုးအစား>.txt ဖိုင်သို့ ရေးရန် ပရောဂျက်သို့ သိမ်းပါ ကို နှိပ်ပါ။ ဤသည်မှာ ကုဒ် ပုံစံ + လမ်းညွှန် ဖြစ်ပြီး ကြော်ငြာ SDK မဟုတ်ပါ — SDK သည် IDE တွင် မပါဝင်ပါ။ အစစ်အမှန် ကြော်ငြာများသည် ပေးသွင်းသူ အကောင့် ဖန်တီးသည့်အခါ၊ ကြော်ငြာ ယူနစ် ဖန်တီးသည့်အခါ၊ သင့်ကိုယ်ပိုင် ယူနစ် ID ကို ကပ်သည့်အခါ နှင့် SDK မှီခိုမှုကို ပရောဂျက်၏ build.gradle သို့ ထည့်သည့်အခါမှသာ ပေါ်လာသည်။

ကလေး မုဒ်
IDE ကို ကလေးနှင့် အတူ အသုံးပြုရန် - အဓိက မီနူးတွင် ကလေး မုဒ် ကို ဖွင့်ပါ။ မျက်နှာပြင်ကို ခလုတ်ကြီးများဖြင့် ရိုးရှင်းစေပြီး လုံခြုံသော လုပ်ဆောင်ချက် ၄ ခုသာ ရှိသည် - ပရောဂျက် ဖန်တီးရန် (လုံခြုံသော ပုံစံများမှ - ဂဏန်းတွက်စက်၊ နံပါတ် ခန့်မှန်းပါ၊ မေးခွန်းလွှာ၊ ကြယ်ကို ဖမ်းပါ)၊ ပရောဂျက် ဖွင့်ပါ၊ လုပ်ဆောင်ပါ နှင့် သင်ယူမှု မုဒ်။ ဤမျက်နှာပြင်တွင် ဖျက်ရန်၊ ထုတ်ယူရန်၊ အရန်ကူးရန် သို့မဟုတ် တိုကင် သတ်မှတ်ရန် ခလုတ် မရှိပါ။ ပထမဆုံး ဝင်ရောက်စဉ် ဂဏန်း ၄ လုံး PIN ကို ဖန်တီးပါ — ဤ PIN ကို မိဘက ကလေး မုဒ် မှ ထွက်ရန် အသုံးပြုသည် (Mode Anak မှ ထွက်ပါ ခလုတ် သို့မဟုတ် နောက်သို့ ခလုတ်)။ ဤ PIN သည် ကလေးငယ်များအတွက် ပေါ့ပါးသော အကာအကွယ် ဖြစ်ပြီး အစစ်အမှန် လုံခြုံရေး မဟုတ်ပါ။

Wear OS & TV အက်ပ် ဖန်တီးစက်
နာရီ အက်ပ် (Wear OS) သို့မဟုတ် တီဗီ အက်ပ် (Android TV) ဖန်တီးရန် - အဓိက မီနူးတွင် Wear OS & TV အက်ပ် ဖန်တီးစက် ကို ဖွင့်ပြီး ပစ်မှတ် (Wear OS၊ Android TV သို့မဟုတ် နှစ်ခုလုံး) ကို ရွေးချယ်ပါ။ ပရောဂျက် အမည်ကို ဖြည့်ပြီး Wear/TV ပရောဂျက်အသစ် ဖန်တီးပါ ကို နှိပ်ပါ — IDE သည် Java ပရောဂျက်ကို ဖန်တီးပြီး ပြုပြင်သည် — သို့မဟုတ် ရှိပြီးသား ပရောဂျက်ကို ရွေးချယ်ပြီး ဒီပရောဂျက်သို့ အသုံးချပါ ကို နှိပ်ပါ။ ပြုပြင်မှုများ - မန်နီဖက်စ်တွင် uses-feature၊ TV အတွက် LEANBACK_LAUNCHER အမျိုးအစားနှင့် ဘန်နာ နှင့် ပြုပြင်ထားသော activity_main.xml အပြင်အဆင် (Wear - မျက်နှာပြင်ငယ်။ TV - D-pad နှင့် ကိုက်ညီသော မျက်နှာပြင်ကြီး)။ အပြည့်အစုံ ရှင်းလင်းချက်ကို ပရောဂျက်ရှိ wear-tv.txt သို့ ရေးသည်။ ဤသည်မှာ ပရောဂျက် ပုံစံ ဖြစ်သည် — တည်ဆောက်ခြင်း + စမ်းသပ်ခြင်းအတွက် Wear OS သို့မဟုတ် Android TV စက်ပစ္စည်း/အတုယူစက် လိုအပ်သေးသည်။ TV ဘန်နာ (banner.png 320x180) ကို အလိုအလျောက် မဖန်တီးပါ၊ ကိုယ်တိုင် ထည့်ရမည် (ဥပမာ အိုင်ကွန် ဖန်တီးသူ မှတစ်ဆင့်)။

ပရောဂျက် မြေပုံ
ပရောဂျက်၏ ဖွဲ့စည်းပုံကို ကြည့်ရန် - အဓိက မီနူးတွင် ပရောဂျက် မြေပုံ ကို ဖွင့်ပါ၊ ပရောဂျက်ကို ရွေးချယ်ပြီး မြေပုံ ပြရန် ကို နှိပ်ပါ — IDE သည် ဖိုင်တွဲများနှင့် ဖိုင်များ စာရင်းကို ၎င်းတို့၏ အရွယ်အစားများ၊ စုစုပေါင်း အရွယ်အစား၊ ဖိုင် အမျိုးအစားအလိုက် အရွယ်အစားနှင့် အရေးကြီးသော ဖိုင်များ (အဓိက ဖိုင်၊ မန်နီဖက်စ်၊ အပြင်အဆင်၊ စာကြောင်းများ၊ အိုင်ကွန်၊ ဝက်ဘ်စာမျက်နှာ) နှင့်အတူ ပြသသည်။ တူညီသော မြေပုံကို ပရောဂျက် အမြစ်သို့ ရေးရန် peta-proyek.txt သိမ်းပါ ကို နှိပ်ပါ။ bin/ ဖိုင်တွဲ (တည်ဆောက်မှု ရလဒ်) နှင့် .git/ ဖိုင်တွဲ (ဒေသတွင်း repo) တို့ကို မြေပုံတွင် မထည့်ပါ၊ အကြောင်းမှာ ၎င်းတို့၏ အကြောင်းအရာကို ပြန်လည် ဖန်တီးနိုင်သောကြောင့် ဖြစ်သည်။

APK အရွယ်အစား ဂဏန်းတွက်စက်
တည်ဆောက်ထားသော APK ၏ အရွယ်အစားကို မတည်ဆောက်မီ ခန့်မှန်းရန် - အဓိက မီနူးတွင် APK အရွယ်အစား ဂဏန်းတွက်စက် ကို ဖွင့်ပါ၊ ပရောဂျက်ကို ရွေးချယ်ပြီး ခန့်မှန်းချက် တွက်ချက်ရန် ကို နှိပ်ပါ။ IDE သည် အမျိုးအစားအလိုက် အသေးစိတ်များ (ကုဒ်/DEX၊ အရင်းအမြစ်များ၊ ပိုင်ဆိုင်မှုများ၊ ထည့်သွင်းထားသော စာကြည့်တိုက်များ၊ မန်နီဖက်စ် + resources.arsc၊ အထွေထွေ ကုန်ကျစရိတ်များ)၊ စုစုပေါင်း ခန့်မှန်းချက်၊ အကြီးဆုံး ဖိုင် ၅ ခု နှင့် လျှော့ချရန် အကြံပြုချက်များ (ဥပမာ ကြီးမားသော ပုံများကို ရုပ်ထွက်တွင် လျှော့ချသည်၊ ကြီးမားသော အသံများကို အရှည်တွင် ဖြတ်သည်) ကို ပြသသည်။ ဤသည်မှာ ခန့်မှန်းချက် ဖြစ်ပြီး တိကျသော အရွယ်အစား မဟုတ်ပါ — အစစ်အမှန် အရွယ်အစားသည် aapt2 ချုံ့ခြင်း၊ အသုံးမပြုသော ကုဒ် ဖယ်ရှားခြင်း (R8) နှင့် တည်ဆောက်မှု ရလဒ် အရင်းအမြစ်များကြောင့် ကွာခြားနိုင်သည်။

APK ခွဲခြမ်းစိတ်ဖြာသူ
အဆင်သင့် APK ၏ အကြောင်းအရာကို ဖတ်ရန် (Android Studio ရှိ APK ခွဲခြမ်းစိတ်ဖြာသူ ကဲ့သို့) - အဓိက မီနူးတွင် APK ခွဲခြမ်းစိတ်ဖြာသူ ကို ဖွင့်ပါ၊ ပရောဂျက်ကို ရွေးချယ်ပြီး တည်ဆောက်မှု ရလဒ် APK ခွဲခြမ်းစိတ်ဖြာခြင်း ကို နှိပ်ပါ။ IDE သည် ထိုပရောဂျက်၏ bin ဖိုင်တွဲရှိ နောက်ဆုံး APK ကို ဖတ်ပြီး ပက်ကေ့ဂျ် အမည်၊ ဗားရှင်း၊ အနိမ့်ဆုံးနှင့် ပစ်မှတ် SDK၊ အသုံးပြုသော ခွင့်ပြုချက်များ စာရင်း၊ dex ဖိုင်များ အရေအတွက်၊ အပိုင်းအလိုက် အရွယ်အစား အသေးစိတ်များ (ပရိုဂရမ် ကုဒ်၊ အရင်းအမြစ်များ၊ ပိုင်ဆိုင်မှုများ၊ ထည့်သွင်းထားသော စာကြည့်တိုက်များ၊ လက်မှတ်) နှင့် အကြီးဆုံး ထည့်သွင်းမှု ၁၀ ခုကို အစီရင်ခံသည်။ APK ကို မည်သည့်အပိုင်းက ကြီးမားစေသလဲ နှင့် တည်ဆောက်ထားသော အက်ပ်က မည်သည့်ခွင့်ပြုချက်များကို အသုံးပြုသလဲ သိရန် အသုံးဝင်သည်။

မျက်နှာပြင် အရွယ်အစား အစမ်းကြည့်ရန်
ပရောဂျက်၏ အသွင်အပြင်ကို မျက်နှာပြင် အရွယ်အစား အများအပြားတွင် တစ်ပြိုင်နက် စစ်ဆေးရန် (Android Studio တွင်ကဲ့သို့) - အဓိက မီနူးတွင် မျက်နှာပြင် အရွယ်အစား အစမ်းကြည့်ရန် ကို ဖွင့်ပါ၊ ပရောဂျက်ကို ရွေးချယ်ပြီး မျက်နှာပြင် အရွယ်အစား စစ်ဆေးပါ ကို နှိပ်ပါ။ IDE သည် ပရောဂျက်၏ အပြင်အဆင်အားလုံးကို ဖတ်ပြီး အကျယ် ပုံသေရေးထားသော (ဥပမာ 400dp) နှင့် မျက်နှာပြင် အကျယ် 320၊ 360၊ 411 သို့မဟုတ် 480 dp ကို ကျော်လွန်သော အစိတ်အပိုင်းများကို အစီရင်ခံသည်၊ အကြောင်းမှာ မျက်နှာပြင်ငယ်ရှိသော ဖုန်းတွင် ထိုကဲ့သို့သော အစိတ်အပိုင်းကို ဖုံးကွယ်နိုင်သည် သို့မဟုတ် လျှံနိုင်သောကြောင့် ဖြစ်သည်။ match_parent သို့မဟုတ် wrap_content အကျယ်ရှိသော အစိတ်အပိုင်းများသည် မျက်နှာပြင်သို့ အလိုအလျောက် လိုက်လျောညီထွေဖြစ်ပြီး စစ်ဆေးရန် မလိုအပ်ပါ။

ရင်းမြစ် စီမံခန့်ခွဲသူ
ပရောဂျက်၏ အရင်းအမြစ်အားလုံးကို တစ်နေရာတည်းတွင် ကြည့်ရှုရန်နှင့် စီမံရန် (Android Studio ရှိ ရင်းမြစ် စီမံခန့်ခွဲသူ ကဲ့သို့) - အဓိက မီနူးတွင် ရင်းမြစ် စီမံခန့်ခွဲသူ ကို ဖွင့်ပါ၊ ပရောဂျက်ကို ရွေးချယ်ပြီး အရင်းအမြစ်များ ကြည့်ပါ ကို နှိပ်ပါ။ IDE သည် ဖိုင်အရေအတွက်နှင့် အရွယ်အစားကို အမျိုးအစားအလိုက် (drawable၊ layout၊ values၊ mipmap နှင့် အခြားများ)၊ strings.xml၊ colors.xml နှင့် styles.xml အကြောင်းအရာများကို အစီရင်ခံသည်။ တူညီသော မျက်နှာပြင်မှ အမည်နှင့် တန်ဖိုးကို ဖြည့်ခြင်းဖြင့် strings.xml သို့ စာကြောင်းအသစ် နှင့် colors.xml သို့ အရောင်အသစ် ထည့်နိုင်သည် — အမည်ကို စစ်ဆေးပြီး ထပ်နေသည်များကို ငြင်းပယ်သည်၊ ထို့ကြောင့် XML ဖိုင် မပျက်စီးပါ။

ပေါ့ပါးသော စွမ်းဆောင်ရည် စောင့်ကြည့်မှု
လုပ်ဆောင်နေသော အက်ပ်၏ RAM နှင့် ပရိုဆက်ဆာ အသုံးပြုမှုကို စောင့်ကြည့်ရန် (Android Studio ရှိ Profiler ကဲ့သို့၊ ပေါ့ပါးသော ဗားရှင်း) - အဓိက မီနူးတွင် ပေါ့ပါးသော စွမ်းဆောင်ရည် စောင့်ကြည့်မှု ကို ဖွင့်ပါ၊ ပထမဦးစွာ စစ်ဆေးလိုသော အက်ပ်ကို လုပ်ဆောင်ပါ (ဥပမာ စမ်းသပ်နေသော တည်ဆောက်ထားသော အက်ပ်)၊ ၎င်း၏ ပက်ကေ့ဂျ် အမည်ကို ဖြည့်ပါ — သို့မဟုတ် ပရောဂျက်ကို ရွေးချယ်ပြီး ပရောဂျက်မှ Package အမည် ဖြည့်ပါ ကို နှိပ်ပါ — ထို့နောက် စောင့်ကြည့် စတင်ပါ ကို နှိပ်ပါ။ နှစ်စက္ကန့်တိုင်း IDE သည် ထိုအက်ပ်၏ RAM (PSS) နှင့် CPU ကို ဖုန်း၏ လွတ်လပ်သော RAM နှင့်အတူ မှတ်တမ်းတင်သည်။ ပျမ်းမျှနှင့် အမြင့်ဆုံး အကျဉ်းချုပ်ကို ကြည့်ရန် ရပ်ပါ ကို နှိပ်ပါ။ ထပ်ဆောင်းခွင့်ပြုချက် မရှိပါ။ Android ဗားရှင်းအသစ်များတွင် အခြား အက်ပ်၏ ပရိုဆက်ဆာကို ဖတ်ရန် ဝင်ရောက်မှုကို စနစ်က ကန့်သတ်ထားသည်၊ ထို့ကြောင့် CPU ကို ဖတ်၍ မရပါက အစီရင်ခံစာက ထိုအတိုင်း ပြောပြီး RAM စောင့်ကြည့်မှု ဆက်လက်လုပ်ဆောင်သည်။

သုံးစွဲနိုင်မှု စစ်ဆေးခြင်း
ပရောဂျက်တစ်ခုကို ထုတ်ပြန်ခြင်းမပြုမီ ၎င်း၏ အပြင်အဆင်သည် မျက်နှာပြင် ဖတ်သူများနှင့် (TalkBack/Jieshuo) အဆင်ပြေမှုရှိမရှိ စစ်ဆေးရန်- ပင်မမီနူးတွင် သုံးစွဲနိုင်မှု စစ်ဆေးခြင်း ကို ဖွင့်ပါ၊ ပရောဂျက်တစ်ခု ရွေးပါ၊ ထို့နောက် အပြင်အဆင်စာရင်းကို တင်ပါ ကို နှိပ်ပြီး အပြင်အဆင် ဖိုင်တစ်ခု ရွေးပါ။ IDE က ထို XML ဖိုင်ကို ဖတ်ပြီး အညွှန်းမပါသော ခလုတ်များကို ၎င်းတို့၏ လိုင်းနံပါတ်များနှင့်အတူ၊ ထပ်ခါတလဲလဲ အသုံးပြုသော အညွှန်းများနှင့် တစ်ဖက်နှင့်တစ်ဖက် ထပ်နေသော အစိတ်အပိုင်းများကို အစီရင်ခံပြီး Jieshuo အသံကျယ်ကျယ် ဖတ်သကဲ့သို့ အာရုံစူးစိုက်မှု အစီအစဉ်၏ မှတ်တမ်းကို တည်ဆောက်သည်။ ခလုတ်တစ်ခု အညွှန်း မရှိလျှင် ၎င်း၏ အညွှန်းကို ဖြည့်ပြီး အညွှန်းကို အလိုအလျောက် ထည့်ပါ ကို နှိပ်ပါ — အညွှန်းကို အပြင်အဆင် ဖိုင်တွင် contentDescription အဖြစ် ရေးသားသည်။ ဤစစ်ဆေးမှုသည် အပြင်အဆင် XML ကိုသာ ဖတ်သည်၊ Compose မြင်ကွင်းများနှင့် ပြီးစီးသော APK များကို မစကင်ဖတ်သေးပါ။

Crash ခွဲခြမ်းစိတ်ဖြာခြင်း
ထူးခြားသော ID ပါသော ပျက်ကျမှုမှတ်တမ်းမှ အက်ပ်သည် အဘယ်ကြောင့် သူ့ဘာသာ ပိတ်သွားသည်ကို သိရှိရန်: ပင်မမီနူးတွင် «Crash ခွဲခြမ်းစိတ်ဖြာခြင်း» ကို ဖွင့်ပါ၊ မှတ်တမ်းစာရင်းမှ ပျက်ကျမှု ID ကို ရွေးချယ်ပါ၊ ထို့နောက် «စစ်ဆေးပါ» ကို နှိပ်ပါ။ IDE သည် မှတ်တမ်းထဲက အတန်းနှင့် လိုင်းနံပါတ်ကို ပရောဂျက် အရင်းအမြစ်နှင့် ကိုက်ညီစေပြီး အကြောင်းရင်းကို အင်ဒိုနီးရှားဘာသာဖြင့် ရှင်းပြသည် (ဥပမာ ဗလာကိုးကားချက်၊ မတောင်းရသေးသော ခွင့်ပြုချက်၊ သို့မဟုတ် JSON အမှား)၊ ကုဒ် patch အကြံပြုချက်နှင့်အတူ။ မူရင်းလိုင်းသည် ပျက်ကျမှု ဖြစ်ပွားသောအခါ ရှိခဲ့သည့်အတိုင်း ရှိနေသေးမှသာ «ပြင်ဆင်ချက်ကို အသုံးပြုပါ» ကို နှိပ်ပါ၊ ပြောင်းလဲသွားပါက patch ကို ငြင်းပယ်ပြီး IDE က သင့်ကိုယ်တိုင် စစ်ဆေးရန် တောင်းဆိုသည်။ တည်ဆောက်ထားသော အက်ပ်၏ ပျက်ကျမှုများအတွက် «ပျက်ကျမှု ဖမ်းယူသူကို ပရောဂျက်ထဲသို့ ထည့်ပါ» ကို နှိပ်ပါ၊ ထို့နောက် APK ကို ပုံမှန်အတိုင်း တည်ဆောက်ပါ: တည်ဆောက်ထားသော အက်ပ်သည် ၎င်း၏ ကိုယ်ပိုင် ပျက်ကျမှုများကို ဖမ်းယူပြီး ၎င်း၏ မှတ်တမ်းကို ဖုန်းပေါ်တွင် ရေးသည်၊ ထိုမှတ်တမ်းကို «တည်ဆောက်ထားသော အက်ပ် ပျက်ကျမှု မှတ်တမ်း ရှာဖွေပါ» ခလုတ်ဖြင့် ရှာတွေ့နိုင်သည်။ ရိုးသားသော ကန့်သတ်ချက်: မှတ်တမ်းကို Android 11 နှင့်အထက် အများပြည်သူ Download ဖိုင်တွဲသို့ ကူးယူခြင်းသည် ဖိုင်အားလုံး ဝင်ရောက်ခွင့် ခွင့်ပြုချက်မရှိဘဲ မအောင်မြင်နိုင်ပါ။

ဘာသာစကားမျိုးစုံ ပြောင်းလဲပေးသည့် Transpiler
ရိုးရှင်းသော Java ကုဒ်ကို Kotlin သို့ သို့မဟုတ် ရိုးရှင်းသော XML အပြင်အဆင်ကို Compose ကုဒ်သို့ ပြောင်းရန်- ပင်မမီနူးတွင် ဘာသာစကားမျိုးစုံ ပြောင်းလဲပေးသည့် Transpiler ကို ဖွင့်ပါ၊ ပရောဂျက်နှင့် ဖိုင်တစ်ခု ရွေးပါ၊ ထို့နောက် အစမ်းကြည့်ပါ ကို နှိပ်ပါ။ IDE က ပြောင်းလဲမှု ရလဒ်ကို စာသားအဖြစ် ပြသသည် — အရင် စစ်ဆေးပါ၊ အဘယ်ကြောင့်ဆိုသော် ၎င်းမသိသော လိုင်းများကို အတိုင်းပင် ထားရှိပြီး Java ရှိ static စကားလုံးကို Kotlin တွင် ချန်လှပ်ထားသောကြောင့် ဖြစ်သည် (အသုံးမပြုမီ ၎င်း၏ အဓိပ္ပာယ်ကို စစ်ဆေးပါ)။ XML မှ Compose သို့ ပြောင်းလဲခြင်းသည် စာသား၊ အကြံပြုချက်များနှင့် ဦးတည်ရာကိုသာ ပြောင်းလဲသည် — အရွယ်အစား၊ အရောင်နှင့် အခြား အရည်အချင်းများ မပါဝင်သေးပါ။ ရလဒ် မှန်ကန်လျှင် ပစ်မှတ် ဖိုင်ကို ရေးသားရန် ဖိုင်သို့ အသုံးပြုပါ ကို နှိပ်ပါ၊ ရင်းမြစ် ဖိုင်ကို မပြောင်းလဲပါ။ လုံခြုံသော၊ သာမန် ပုံစံများကိုသာ ပြောင်းလဲသည်။

ဒေသတွင်း မိုက်ခရို ဆာဗာ
အင်တာနက်မရှိဘဲ ဆာဗာ လိုအပ်သော အက်ပ်ကို စမ်းသပ်ရန်: ပင်မမီနူးတွင် «ဒေသတွင်း မိုက်ခရို ဆာဗာ» ကို ဖွင့်ပါ၊ လမ်းကြောင်း သတ်မှတ်ချက်များကို ရေးပါ (ဥပမာ GET /halo နှင့် ၎င်း၏ JSON အဖြေ)၊ ထို့နောက် «ဆာဗာကို စတင်ပါ» ကို နှိပ်ပါ။ IDE သည် တူညီသော ဖုန်းပေါ်တွင် HTTP ဆာဗာအသေးစားကို လုပ်ဆောင်သည် (HTTP သာ၊ TLS မရှိ၊ တူညီသော Wi-Fi ကွန်ရက်အတွက်) နှင့် တောင်းဆိုမှုနှင့် အဖြေတစ်ခုစီကို မျက်နှာပြင်ပေါ်တွင် မှတ်တမ်းတင်သည်။ လမ်းကြောင်းများသည် {nama} ကဲ့သို့ ကန့်သတ်ချက်များနှင့် ရိုးရှင်းသော API သော့ကို အသုံးပြုနိုင်သည်။ ဆာဗာကို တည်ဆောက်ထားသော APK ထဲတွင်လည်း ထုပ်ပိုးနိုင်သည်: «ဆာဗာကို ပရောဂျက်ထဲသို့ ထုပ်ပိုးပါ» ကို နှိပ်ပါ၊ ဆာဗာ အရင်းအမြစ်၊ အက်ဆက်များနှင့် manifest ကို ပရောဂျက်ထဲသို့ ထည့်သည်၊ ထို့ကြောင့် တည်ဆောက်ထားသော အက်ပ်ကိုယ်တိုင် လုပ်ဆောင်နေစဉ် ဆာဗာ ဖြစ်လာသည်။ IDE ရှိ ဆာဗာသည် ၎င်း၏ မျက်နှာပြင် ပိတ်သောအခါ ရပ်တန့်သည်။

လုံခြုံရေး စစ်ဆေးသူ
ထုတ်ဝေခြင်းမပြုမီ ပရောဂျက်ကုဒ်တွင် လုံခြုံရေး ကွာဟချက်များကို စစ်ဆေးရန်: ပင်မမီနူးတွင် «လုံခြုံရေး စစ်ဆေးသူ» ကို ဖွင့်ပါ၊ ပရောဂျက်ကို ရွေးချယ်ပါ၊ ထို့နောက် «စကင်ဖတ်ခြင်းကို စတင်ပါ» ကို နှိပ်ပါ။ IDE သည် ပရောဂျက်ကုဒ်၊ manifest နှင့် ဖွဲ့စည်းပုံကို စကင်န်ဖတ်ပြီး မြင့်မားသော အန္တရာယ်မှ နိမ့်သော အန္တရာယ်အထိ တွေ့ရှိချက်များကို အစီရင်ခံသည် — ကုဒ်တွင် ပွင့်လန်းကျန်ခဲ့သော API သော့၊ ခွင့်ပြုချက်မရှိဘဲ ထုတ်ဖော်ထားသော အစိတ်အပိုင်း၊ ၎င်း၏ JavaScript interface ဖြင့် JavaScript ကို ဖွင့်ထားသော WebView၊ အားနည်းသော crypto (MD5, SHA1, DES)၊ TLS မပါသော http လိပ်စာ၊ ကုဒ်တွင် တိုက်ရိုက်ရေးသားထားသော စကားဝှက် — ၎င်းတို့၏ ဖိုင်များနှင့် လိုင်းနံပါတ်များနှင့်အတူ။ ပြင်ဆင်မှု လုံခြုံသော တွေ့ရှိချက်များအတွက် (ဥပမာ MD5 ကို SHA-256 သို့မဟုတ် http ကို https သို့ ပြောင်းပါ) «ပြင်ဆင်ချက်ကို အသုံးပြုပါ» ကို နှိပ်ပါ၊ API သော့များနှင့် စကားဝှက်များအတွက် IDE သည် ပြင်ဆင်မှု အကြံပြုချက်ကိုသာ ပြသသည်၊ အဘယ်ကြောင့်ဆိုသော် အစားထိုးမှုကို ဖန်တီးသူကိုယ်တိုင် ဆုံးဖြတ်ရသောကြောင့် ဖြစ်သည်။ စကင်န်ဖတ်ခြင်းသည် ယခု တည်ဆောက်ထားသော APK အတွင်း တကယ့် DEX bytecode ကိုလည်း ခွဲခြမ်းစိတ်ဖြာသည် (ကုဒ်ထဲက စာသားပုံစံများသာ မဟုတ်)၊ ထို့ကြောင့် ခေါ်ဆိုထားသော အန္တရာယ်ရှိသော API များနှင့် DEX ထဲ မြှုပ်ထားသော လျှို့ဝှက်ချက်များကိုလည်း ဖမ်းမိသည်၊ ပုံစံကို မလိုက်နာသော ကွာဟချက်များသည် စကင်န်ဖတ်ခြင်းမှ ယခုထိ လွတ်မြောက်နိုင်သည် — အသုံးမပြုမီ စစ်ဆေးပါ။

မျက်နှာပြင် စမ်းသပ်စက်ရုပ်
စာသား ဇာတ်လမ်းပုံစံများမှတဆင့် အက်ပ်မျက်နှာပြင်ကို အလိုအလျောက် စမ်းသပ်ရန်: ပင်မမီနူးတွင် «မျက်နှာပြင် စမ်းသပ်စက်ရုပ်» ကို ဖွင့်ပါ၊ ပရောဂျက်ကို ရွေးချယ်ပါ၊ ထို့နောက် «ဇာတ်လမ်းပုံစံကို အလိုအလျောက် ဖန်တီးပါ» ကို နှိပ်ပါ။ IDE သည် ပရောဂျက် manifest နှင့် အပြင်အဆင်ကို ဖတ်ပြီး ဇာတ်လမ်းပုံစံကို စာသားအဆင့်များအဖြစ် ရေးသည် (ခလုတ်နှိပ်ပါ၊ အကွက်ဖြည့်ပါ၊ စောင့်ပါ၊ ပြန်သွားပါ)။ ဇာတ်လမ်းပုံစံ လုပ်ဆောင်မှု မှတ်တမ်းကို ၎င်း၏ အချိန်တံဆိပ်များနှင့်အတူ မြင်ရန် «Dry Run ကို လုပ်ဆောင်ပါ» ကို နှိပ်ပါ — ဤ dry run သည် ယခုထိ အစီအစဉ်၏ ပုံစံတူလုပ်ဆောင်မှုသာ ဖြစ်သည်။ တကယ့် စမ်းသပ်မှုအတွက် «စမ်းသပ်မှု အေးဂျင့်ကို ပရောဂျက်ထဲသို့ ထည့်ပါ» ကို နှိပ်ပါ: IDE သည် ဇာတ်လမ်းပုံစံ အက်ဆက်များနှင့်အတူ စမ်းသပ်မှု အေးဂျင့်ကို ပရောဂျက်ထဲသို့ ထည့်သည်၊ APK ကို ပုံမှန်အတိုင်း တည်ဆောက်ပါ၊ တပ်ဆင်ပါ၊ ထို့နောက် «စမ်းသပ်မှု» အိုင်ကွန်ကို ဖွင့်ပါ — အေးဂျင့်သည် တည်ဆောက်ထားသော အက်ပ်အတွင်း လုပ်ဆောင်ပြီး ခလုတ်များကို တကယ်နှိပ်သည်၊ တကယ့် အကွက်များကို ဖြည့်သည်၊ လှိမ့်သည်၊ ထို့နောက် ၎င်း၏ အစီရင်ခံစာကို မျက်နှာပြင်ပေါ်တွင် ဖမ်းမိသော တကယ့် ပျက်ကျမှုများနှင့်အတူ ပြသသည်။ အေးဂျင့်ကို ပြန်ဖယ်ရှားရန် «စမ်းသပ်မှု အေးဂျင့်ကို ပရောဂျက်မှ ဖယ်ရှားပါ» ကို နှိပ်ပါ။ အေးဂျင့်သည် အက်ပ်၏ ကိုယ်ပိုင် လုပ်ငန်းစဉ်အတွင်း လုပ်ဆောင်သည်၊ ထို့ကြောင့် ၎င်းသည် သုံးစွဲနိုင်မှု ဝန်ဆောင်မှု သို့မဟုတ် စနစ် အလိုအလျောက်စနစ် မလိုအပ်ပါ။

ကုဒ် အချိန်ခရီးသွားခြင်း
Git အမိန့်များကို ရိုက်ထည့်ခြင်းမရှိဘဲ ပရောဂျက်တစ်ခုကို ယခင် ကုဒ် အခြေအနေသို့ ပြန်ရောက်စေရန်- ပင်မမီနူးတွင် ကုဒ် အချိန်ခရီးသွားခြင်း ကို ဖွင့်ပါ၊ ပရောဂျက်တစ်ခု ရွေးပါ၊ အချိန်မှတ်အတွက် အညွှန်းတစ်ခု ဖြည့်ပါ (ဗလာထားနိုင်သည်)၊ ထို့နောက် ယခုအချိန်မှတ်ကို မှတ်တမ်းတင်ပါ ကို နှိပ်ပါ။ IDE က ပရောဂျက်၏ ရင်းမြစ် ဖိုင်များ၏ မိတ္တူကို ၎င်းတို့၏ hash တန်ဖိုးများနှင့်အတူ ပရောဂျက်အတွင်းရှိ .riwayat ဖိုဒါတွင် သိမ်းဆည်းသည်။ အချိန်မှတ်များ စာရင်းက ၎င်းတို့အားလုံးကို ပြသသည်၊ အမှတ်နှစ်ခု ရွေးပါ၊ ထို့နောက် ထည့်သွင်းထားသော၊ ပြောင်းလဲထားသော သို့မဟုတ် ဖျက်လိုက်သော ဖိုင်များနှင့် လုပ်ဆောင်ချက်များကို ကြည့်ရန် နှိုင်းယှဉ်ပါ ကို နှိပ်ပါ။ အဟောင်း အခြေအနေကို ပြန်ယူရန် ပြန်လည်ရယူပါ ကို နှိပ်ပါ — ပြန်လည်ရယူခြင်းမပြုမီ IDE က လက်ရှိ အခြေအနေ၏ အရန်မိတ္တူကို အမြဲဦးစွာ ပြုလုပ်သည်၊ ထို့ကြောင့် မည်သည့်အရာမျှ မပျောက်ပါ။ ပရောဂျက်ကို ဖိုဒါအသစ်တစ်ခုသို့ ကူးယူပြီး မူရင်း ပရောဂျက်ကို မနှောင့်ယှက်ဘဲ ပြောင်းလဲမှုများကို စမ်းသပ်ရန် စမ်းသပ်မှု မိတ္တူ ဖန်တီးပါ ကို နှိပ်ပါ။ ရင်းမြစ် ဖိုင်များကိုသာ မှတ်တမ်းတင်သည်။

မော်ဂျူး စက်ရုံ
ပရောဂျက်တစ်ခု၏ အစိတ်အပိုင်းတစ်ခုကို အခြား ပရောဂျက်တစ်ခု အသုံးပြုနိုင်သော မော်ဂျူးအဖြစ် ထုပ်ပိုးရန်- ပင်မမီနူးတွင် မော်ဂျူး စက်ရုံ ကို ဖွင့်ပါ၊ ရင်းမြစ် ပရောဂျက်တစ်ခု ရွေးပါ၊ ထုပ်ပိုးမည့် မျက်နှာပြင်၊ အတန်း၊ စာကြောင်းနှင့် ခွင့်ပြုချက် ဖိုင်များကို အမှတ်အသားပြုပါ၊ ထို့နောက် မော်ဂျူးအဖြစ် ထုပ်ပိုးပါ ကို နှိပ်ပါ။ IDE က JSON မက်တာဒေတာနှင့်အတူ ZIP မှတ်တမ်း ရေးသားသည် (မော်ဂျူး အမည်၊ ဗားရှင်း၊ အသုံးပြုထားသော စာကြောင်းများနှင့် ခွင့်ပြုချက်များ)။ မော်ဂျူးတစ်ခုကို အခြား ပရောဂျက်တစ်ခုတွင် တပ်ဆင်ရန် မော်ဂျူး စက်ရုံ ကို ဖွင့်ပါ၊ ပစ်မှတ် ပရောဂျက်ကို ရွေးပါ၊ ထို့နောက် မော်ဂျူး တပ်ဆင်ပါ ကို နှိပ်ပြီး မော်ဂျူး၏ .zip ဖိုင်ကို ရွေးပါ — ပေါင်းစည်းခြင်းသည် ရှိပြီးသား ကုဒ်ကို ထပ်မရေးဘဲ စာကြောင်းများနှင့် ခွင့်ပြုချက်များကို ပေါင်းထည့်ပြီး ၎င်း၏ အမည်ကို ပစ်မှတ် ပရောဂျက်တွင် အသုံးပြုပြီးဖြစ်လျှင် ဖိုင်ကို မပေါင်းစည်းပါ။ မော်ဂျူးတစ်ခုသည် စာကြည့်တိုက်များကိုဖြစ်စေ တည်ဆောက်မှု ဆက်တင်များကိုဖြစ်စေ သယ်ဆောင်မသွားပါ။

ပုံစံပြောင်းဒိုင်းနှင့် အက်ဆက်ခန်း
ထုတ်ဝေခြင်းမပြုမီ အမှတ်အသားအမည်များကို ကျပန်းပြောင်းပြီး ပရောဂျက် အက်ဆက်များကို စာဝှက်ရန်: ပင်မမီနူးတွင် «ပုံစံပြောင်းဒိုင်းနှင့် အက်ဆက်ခန်း» ကို ဖွင့်ပါ၊ ပရောဂျက်ကို ရွေးချယ်ပါ၊ ထို့နောက် «အမည်များကို ကျပန်းပြောင်းပြီး အက်ဆက်များကို စာဝှက်ပါ» ကို နှိပ်ပါ။ IDE သည် မူရင်းကုဒ်ထဲက အတန်းနှင့် နည်းလမ်းအမည်များကို စကင်န်ဖတ်သည်၊ ကျပန်းအမည်မြေပုံ ဖန်တီးသည်၊ ထိုအမည်များကို စုစည်းထားသော DEX ဖိုင်များအတွင်း ပြန်ရေးသည် (အစားထိုးအမည်များကို မူရင်းအမည်များနှင့် အရှည်တူ ပြုလုပ်ထားသည်၊ ထို့ကြောင့် offset အားလုံး တရားဝင်ကျန်သည်၊ ထို့နောက် DEX ခေါင်းစဉ် checksum နှင့် SHA-1 လက်မှတ်ကို ပြန်တွက်သည်)၊ ပရောဂျက် အက်ဆက်ဖိုင်များကို ပရောဂျက်အတွင်းရှိ brankas-aset ဖိုင်တွဲတွင် AES-GCM ဖြင့် စာဝှက်သည်၊ ပျက်ကျမှုမှတ်တမ်းများကို ဖတ်သောအခါ မူရင်းအမည်များကို ပြန်လည်ရယူနိုင်စေရန် စာဝှက်ထားသော ပြန်လည်ရယူရေးမြေပုံ (perisai-peta.brankas) ကို သိမ်းဆည်းသည်။ စာဝှက်သော့သည် ယခု ပရောဂျက်အမည်မှ မဟုတ်ဘဲ ဖန်တီးသူ၏ စကားဝှက်မှ PBKDF2, 20,000 ကြိမ် ဖြင့် ဆင်းသက်လာသည်။ ရိုးရိုးစာသား၊ မှတ်ချက်အမည်နှင့် အမှားရှာအမည်အဖြစ်လည်း အသုံးပြုသော အမည်များကို ရည်ရွယ်ချက်ရှိရှိ ပြန်မရေးပါ၊ တည်ဆောက်မှုလမ်းကြောင်းတွင် DEX ပြန်ရေးခြင်း ထည့်သွင်းသည့်နေရာများသည် တကယ့်ဖုန်းပေါ်တွင် စမ်းသပ်ခြင်းကို ယခုထိ စောင့်ဆိုင်းနေဆဲ ဖြစ်သည်။

ယုံကြည်မှု ကွင်းဆက်နှင့် ပတ်ဝန်းကျင် စောင့်ကြည့်သူ
ထုတ်ဝေခြင်းမပြုမီ လက်မှတ်သော့ကွင်းဆက်နှင့် ဖုန်း ပတ်ဝန်းကျင်ကို စစ်ဆေးရန်: ပင်မမီနူးတွင် «ယုံကြည်မှု ကွင်းဆက်နှင့် ပတ်ဝန်းကျင် စောင့်ကြည့်သူ» ကို ဖွင့်ပါ၊ ပရောဂျက်ကို ရွေးချယ်ပါ၊ ထို့နောက် «ကွင်းဆက်နှင့် ပတ်ဝန်းကျင်ကို စစ်ဆေးပါ» ကို နှိပ်ပါ။ IDE သည် ပရောဂျက် ပက်ကေ့ဂျ်အမည်မှ 5 မျိုးဆက် သော့ကွင်းဆက်ကို တည်ဆောက်ပြီး ၎င်း၏ ခိုင်မာမှုကို စစ်ဆေးသည်၊ မှတ်ဉာဏ်ထဲက ကုဒ်အပိုင်းများ၏ အကြောင်းအရာကို ဒစ်ပေါ်ရှိ ဖိုင်များနှင့် နှိုင်းယှဉ်ခြင်းဖြင့် တကယ့် မှတ်ဉာဏ် ခိုင်မာမှုကို စစ်ဆေးပြီး အမည်မရှိသော အကောင်အထည်ဖော်နိုင်သော (RWX) မြေပုံများ၊ နိုင်ငံခြား စာကြည့်တိုက်များနှင့် memfd မြေပုံများကို အစီရင်ခံသည်၊ ထို့နောက် ၎င်း၏ ကိုယ်ပိုင် လုပ်ငန်းစဉ် မှတ်ဉာဏ်မြေပုံနှင့် စက်ပစ္စည်း ဂုဏ်သတ္တိများကို Frida, Xposed သို့မဟုတ် emulator ခြေရာများအတွက် စကင်န်ဖတ်သည်။ ခန်းသော့သည် ရရှိနိုင်သည့်အခါ ဟာ့ဒ်ဝဲ လုံခြုံရေးချစ်ပ်ကို အသုံးပြုသော AndroidKeyStore ရှိ AES သော့ဖြင့် ထုပ်ပိုးထားပြီး၊ သော့ လှည့်ခြင်းသည် ယခု အစီအစဉ် v3 လက်မှတ် လက်မှတ် မျိုးရိုးဖြင့် တကယ်ဖြစ်သည်: သော့အဟောင်းသည် သော့အသစ်သို့ လှည့်ခြင်း၏ သက်သေကို လက်မှတ်ထိုးပြီး APK ကို ထိုမျိုးရိုးဖြင့် ပြန်လည်လက်မှတ်ထိုးသည်။ ရလဒ်မှာ စာသားသက်သေဖြင့် «လုံခြုံသည်», «သတိထားပါ» သို့မဟုတ် «အန္တရာယ်ရှိသည်» အန္တရာယ်အဆင့် ဖြစ်သည်။ စနစ်က မှတ်ဉာဏ်ဖတ်ခြင်းကို ငြင်းပယ်ပါက စစ်ဆေးမှုကို လုံခြုံသည်ဟု မဟုတ်ဘဲ «အတည်ပြု၍ မရပါ» ဟု အစီရင်ခံသည်၊ သော့သည် ဟာ့ဒ်ဝဲ လုံခြုံရေးချစ်ပ်ကို တကယ်အသုံးပြုသည်ဆိုသည်ကို တကယ့်စက်ပေါ်တွင်သာ အတည်ပြုနိုင်သည်။

စာသားသစ်ပင် အပြင်အဆင် ဗိသုကာပညာရှင်
မျက်နှာပြင်ကို မမြင်ဘဲ ဒီဇိုင်းဆွဲရန်: ပင်မမီနူးတွင် «စာသားသစ်ပင် အပြင်အဆင် ဗိသုကာပညာရှင်» ကို ဖွင့်ပါ၊ ပရောဂျက်နှင့် အပြင်အဆင်ဖိုင်ကို ရွေးချယ်ပါ၊ ထို့နောက် «အပြင်အဆင်ကို စစ်ဆေးပါ» ကို နှိပ်ပါ။ IDE သည် XML အပြင်အဆင်ကို စာသားသစ်ပင်အဖြစ် ဖတ်ပြီး အစိတ်အပိုင်းတစ်ခုစီ၏ တည်နေရာဖော်ပြချက်ကို အသံကျယ်စွာ ဖတ်သည် (ဥပမာ အောက်ညာဘက်၊ မျက်နှာပြင်အကျယ်၏ 45 ရာခိုင်နှုန်း)၊ ထို့နောက် အစိတ်အပိုင်းများကြား ထပ်နေခြင်းနှင့် 360 dp အကျယ်တွင် မျက်နှာပြင်မှ ထွက်သွားသော အစိတ်အပိုင်းများကို သင်္ချာနည်းဖြင့် အစီရင်ခံသည်။ ယခု ရေတွက်သောအရာများမှာ LinearLayout နှင့် ရိုးရိုး dp အရွယ်အစားများ၊ ConstraintLayout အပြည့်အစုံ (ကန့်သတ်ချက်များအားလုံး၊ ဘက်လိုက်မှု၊ ကွင်းဆက်များ၊ လမ်းညွှန်များ၊ အတားအဆီးများ၊ ရာခိုင်နှုန်း အကျယ်များ၊ 0dp match_constraint နှင့် အချိုးများ) နှင့် Compose မျက်နှာပြင်များ (Column, Row နှင့် Box တို့၏ အရွယ်အစား ပြင်ဆင်မှုများနှင့်အတူ) ဖြစ်သည်။ လုပ်ဆောင်နေစဉ် ပြောင်းလဲနေသော MotionLayout နှင့် ConstraintSet သာ အမည်မသိ တည်နေရာအဖြစ် ဆက်လက် အစီရင်ခံသည်၊ အဘယ်ကြောင့်ဆိုသော် ၎င်းတို့၏ တန်ဖိုးများသည် အက်ပ် လုပ်ဆောင်နေစဉ်သာ ရှိသောကြောင့် ဖြစ်သည်။

ဒီဇိုင်းစနစ် စတူဒီယို
မျက်နှာပြင်များနှင့် ပရောဂျက်များအားလုံးတွင် အကွာအဝေးများ၊ ဖောင့်များနှင့် ထောင့်များကို တစ်သမတ်တည်း ဖြစ်စေရန်: ပင်မမီနူးတွင် «ဒီဇိုင်းစနစ် စတူဒီယို» ကို ဖွင့်ပါ၊ ပရောဂျက်ကို ရွေးချယ်ပါ၊ ဒီဇိုင်းတိုကင်များ ရေးပါ (ဥပမာ jarak=8, huruf=16, sudut=12)၊ အစိတ်အပိုင်းကို ရွေးချယ်ပါ၊ ထို့နောက် «အစိတ်အပိုင်းများ ဖန်တီးပါ» ကို နှိပ်ပါ။ IDE သည် တိုကင်များကို အတည်ပြုသည် — အခြေခံ အကွာအဝေး 4 မှ 16 dp, အခြေခံ ဖောင့် 12 မှ 20 sp, ထောင့် 0 မှ 32 dp, နှင့် အနည်းဆုံး ထိတွေ့ဧရိယာ 48 dp — ထို့နောက် အသုံးပြုရန် အဆင်သင့် XML အစိတ်အပိုင်းများ (komponen-studio.xml) ကို XML အပြင်အဆင် (tema-studio.xml) နှင့် Compose အပြင်အဆင် (tema-studio.kt) တို့နှင့် ပရောဂျက်ဖိုင်တွဲတွင် ရေးသည်။ တိုကင်များကို ပရောဂျက်များကြား မျှဝေထားသော တိုကင် စာကြည့်တိုက်တွင် အမည်ပေးထားသော အစုအဖြစ် သိမ်းဆည်းနိုင်ပြီး၊ တစ်ခုတည်းသော စင့်ခ်လုပ်သည့် အမိန့်သည် စာကြည့်တိုက်၏ နောက်ဆုံးတိုကင်များကို ထိုအစုကို အသုံးပြုသော ပရောဂျက်များအားလုံးတွင် အသုံးပြုသည်။ အစိတ်အပိုင်းများကို အပြင်အဆင်တွင် ကပ်ပြီး «စာသားသစ်ပင် အပြင်အဆင် ဗိသုကာပညာရှင်» ဖြင့် စစ်ဆေးသည့် စာသားအဖြစ် ဖန်တီးသည်၊ တက်ဘလက်ပေါ်ရှိ ကော်လံနှစ်ခု ညှိခြင်းသည် လုပ်ဆောင်နေစဉ် စက်ပစ္စည်း အထောက်အထားအစား မျက်နှာပြင်အကျယ် အရည်အချင်းကို အသုံးပြုသည်။

အဓိပ္ပာယ်ဆိုင်ရာ ပြန်လည်ဖွဲ့စည်းခြင်းနှင့် AST လမ်းညွှန်မှု
အဓိပ္ပာယ်ဖွင့်ဆိုချက်များကို ရှာဖွေပြီး တိုက်ဆိုင်စွာ အမည်တူ အခြားကုဒ်ကို မဖျက်ဘဲ သင်္ကေတအမည်များကို ပြောင်းလဲရန်: ပင်မမီနူးတွင် «အဓိပ္ပာယ်ဆိုင်ရာ ပြန်လည်ဖွဲ့စည်းခြင်းနှင့် AST လမ်းညွှန်မှု» ကို ဖွင့်ပါ၊ ပရောဂျက်ကို ရွေးချယ်ပါ၊ ထို့နောက် အတန်းများနှင့် နည်းလမ်းများအားလုံးကို ၎င်းတို့၏ ဖိုင်များနှင့် လိုင်းနံပါတ်များနှင့်အတူ မြင်ရန် «ပရောဂျက် သင်္ကေတများကို စကင်န်ဖတ်ပါ» ကို နှိပ်ပါ။ သင်္ကေတအမည်ကို ရိုက်ထည့်ပါ၊ ထို့နောက် ၎င်း၏ အဓိပ္ပာယ်ဖွင့်ဆိုချက်နှင့် ၎င်းကို ခေါ်သော ဖိုင်များအားလုံးကို မြင်ရန် «ပရောဂျက် သင်္ကေတများကို စကင်န်ဖတ်ပါ» ကို ထပ်နှိပ်ပါ။ အမည်ပြောင်းရန် အမည်အသစ်ကို ရိုက်ထည့်ပါ၊ ဖိုင်တစ်ခုစီတွင် ဖြစ်ပွားမှုအရေအတွက်ကို မြင်ရန် «အမည်ပြောင်းခြင်း အစမ်းကြည့်ခြင်း» ကို နှိပ်ပါ၊ ထို့နောက် «အမည်ပြောင်းခြင်းကို အသုံးပြုပါ» ကို နှိပ်ပါ။ အညွှန်းသည် ယခု လက်ဖြင့် တည်ဆောက်ထားသော AST parser (Java နှင့် Kotlin အစုခွဲအတွက် lexer နှင့် recursive parser) ကို အသုံးပြုသည်၊ ထို့ကြောင့် ဖိုင်များကြား နည်းလမ်းအမည်ပြောင်းခြင်းများကို ဖြေရှင်းပြီး အခြားဖိုင်များတွင် ခေါ်သူများလည်း ပြောင်းလဲသည်၊ ကုဒ်ဘလောက်ကို လုပ်ဆောင်ချက်အသစ်သို့ ထုတ်ယူသည့် ခလုတ်သည် ယခု ဤမျက်နှာပြင်ပေါ်တွင် ရှိသည်။ ဤ parser သည် ယခုထိ အနည်းဆုံးဖြစ်သည်: အလွန်ရှုပ်ထွေးသော generics, ဘောင်ပါသော မှတ်ချက်များနှင့် အမည်မသိ အတန်းများကို ရှိသည့်အတိုင်း စကင်န်ဖတ်သည်၊ reflection နှင့် interface မှတဆင့် ခေါ်ဆိုမှုများကို မဖြေရှင်းပါ။

အဆင့်ဆင့် အမှားရှာသူနှင့် မှတ်ဉာဏ်စစ်ဆေးသူ
မှတ်တမ်းများမှ ခန့်မှန်းခြင်းမရှိဘဲ ပရိုဂရမ် စီးဆင်းမှု အလယ်တွင် ကိန်းရှင်အကြောင်းအရာများကို စစ်ဆေးရန်: ပင်မမီနူးတွင် «အဆင့်ဆင့် အမှားရှာသူနှင့် မှတ်ဉာဏ်စစ်ဆေးသူ» ကို ဖွင့်ပါ၊ ပရောဂျက်ကို ရွေးချယ်ပါ၊ လုပ်ဆောင်မှု ခြေရာကို ရေးပါ (တစ်ကြောင်းလျှင် တစ်ဆင့်၊ ပုံစံ လိုင်းနံပါတ်၊ ကုဒ်၊ ထို့နောက် | ဖြင့် ခြားထားသော ကိန်းရှင်များနှင့် တန်ဖိုးများ၊ ဥပမာ 10|int total = harga * jumlah;|harga=5000, jumlah=3, total=15000)၊ ရပ်နားမှတ် လိုင်းနံပါတ်ကို ရိုက်ထည့်ပါ၊ ထို့နောက် «အမှားရှာ ခြေရာကို လုပ်ဆောင်ပါ» ကို နှိပ်ပါ။ IDE သည် ပထမရပ်နားမှတ်အထိ လုပ်ဆောင်ပြီး Jieshuo မှတဆင့် တက်ကြွသော လိုင်းကို ၎င်း၏ ကိန်းရှင်တန်ဖိုးများနှင့်အတူ အသံကျယ်စွာ ဖတ်သည်။ တစ်ကြောင်းရှေ့သို့ ရွှေ့ရန် «တစ်ကြောင်းအဆင့်» ကို နှိပ်ပါ၊ ခေါ်ဆိုထားသော လုပ်ဆောင်ချက်ထဲသို့ ဝင်ရန် «လုပ်ဆောင်ချက်ထဲသို့ ဝင်ပါ» ကို နှိပ်ပါ (ခေါ်ဆိုမှု stack နှင့်အတူ) သို့မဟုတ် နောက်ရပ်နားမှတ်သို့ သွားရန် «ပရိုဂရမ်ကို ဆက်လုပ်ပါ» ကို နှိပ်ပါ။ ဤခြေရာ အမှားရှာသူ အခြေအနေ မှတ်တမ်းတင်ထားသော သို့မဟုတ် လက်ရေးဖြင့် ရေးထားသော ခြေရာကို ဆက်လက် လိုက်နာသည်၊ ၎င်း၏ အနားတွင် JDWP ဝိုင်ယာ ပရိုတိုကောအတွက် သန့်ရှင်းသော Java client ရှိသည်၊ ၎င်းသည် handshake လုပ်နိုင်သည်၊ ရပ်နားမှတ်များ သတ်မှတ်နိုင်သည်၊ အထဲ၊ အပေါ် နှင့် အပြင် ခြေလှမ်းနိုင်သည်၊ TCP မှတဆင့် သို့မဟုတ် နားထောင်မုဒ်တွင် VM ကို ရပ်နားပြီး ဆက်လက်လုပ်ဆောင်နိုင်သည်။ သာမန် အက်ပ်အတွင်းမှ တကယ့်လုပ်ငန်းစဉ်ကို ရပ်နားခြင်းသည် ယခုထိ အပြည့်အဝ မဖြစ်နိုင်သေးပါ၊ အဘယ်ကြောင့်ဆိုသော် လုပ်ငန်းစဉ်၏ JDWP socket ကို adbd မှတဆင့်သာ ဖော်ပြသောကြောင့် ဖြစ်သည် — သက်သေပြထားသော လမ်းကြောင်းသည် ကြိုးမဲ့ အမှားရှာခြင်းနှင့် shell မှတဆင့် ပစ်မှတ်ကို စတင်ခြင်းကို လိုအပ်သည်၊ ၎င်းသည် အက်ပ်ကိုယ်တိုင် လုပ်နိုင်သည်ထက် ကျော်လွန်သည်။

အင်တာနက်မဲ့ မှီခိုမှု မန်နေဂျာ
အင်တာနက်မရှိဘဲ တတိယပါတီ စာကြည့်တိုက်များကို အသုံးပြုရန်နှင့် တည်ဆောက်ခြင်းမပြုမီ ဗားရှင်း ပဋိပက္ခများကို ရှောင်ရှားရန်: ပင်မမီနူးတွင် «အင်တာနက်မဲ့ မှီခိုမှု မန်နေဂျာ» ကို ဖွင့်ပါ၊ ပရောဂျက်ကို ရွေးချယ်ပါ၊ ထို့နောက် «မှီခိုမှုများကို စစ်ဆေးပါ» ကို နှိပ်ပါ။ IDE သည် ပရောဂျက်၏ .gradle ဖိုင်များအားလုံးကို ဖတ်သည်၊ Download/brankas-bersama ဖိုင်တွဲတွင် ပရောဂျက်များကြား မျှဝေထားသော ခန်းကို စစ်ဆေးပြီး ပဋိပက္ခများကို ဖြေရှင်းသည် — စာကြည့်တိုက်နှစ်ခုက တူညီသော artifact ၏ ဗားရှင်းကွဲများကို တောင်းဆိုပါက အမြင့်ဆုံး ဗားရှင်းကို အသုံးပြုပြီး ပဋိပက္ခကို အစီရင်ခံသည်။ စာကြည့်တိုက်ကို ဒေါင်းလုဒ်လုပ်ရန် ၎င်း၏ သြဒီနိတ်များကို ရိုက်ထည့်ပါ (ပုံစံ အုပ်စု:artifact:ဗားရှင်း၊ ဥပမာ com.google.code.gson:gson:2.10.1) ထို့နောက် «မှီခိုမှုများကို စစ်ဆေးပါ» ကို နှိပ်ပါ: အွန်လိုင်းဖြစ်သည့်အခါ AAR, JAR သို့မဟုတ် WHL ဖိုင်များကို Maven, Google သို့မဟုတ် PyPI မှ ၎င်းတို့၏ transitive dependency graph (အကြိမ်ကြိမ်၊ စက်ဝန်းများ ဖြတ်တောက်ထားသည်၊ အနက် 25 အဆင့်အထိ) ဖြင့် တကယ်ဒေါင်းလုဒ်လုပ်သည်၊ အောင်မြင်စွာ ဒေါင်းလုဒ်လုပ်ထားသော ဖိုင်များသာ ရရှိနိုင်သည်ဟု မှတ်ပုံတင်သည်။ အွန်လိုင်းမဖြစ်သည့်အခါ မျှဝေထားသော ခန်းတွင် ရှိနှင့်ပြီးသား စာကြည့်တိုက်များကိုသာ အသုံးပြုနိုင်သည်။ Maven ဗားရှင်း အပိုင်းအခြားများကို မဖြေရှင်းပါ၊ ဒေါင်းလုဒ်လုပ်ထားသော ဖိုင်များကို ၎င်းတို့၏ SHA-1 ဖြင့်သာ စစ်ဆေးသည်၊ PGP အတည်ပြုခြင်းမရှိပါ။

ဒေတာဘေ့စ်နှင့် သိုလှောင်မှု စစ်ဆေးသူ
ဇယားအကြောင်းအရာကို ပုံနှိပ်သော ကုဒ်ကို မရေးဘဲ ပရောဂျက် ဒေတာဘေ့စ် အကြောင်းအရာကို စစ်ဆေးပြီး စမ်းသပ်ရန်: ပင်မမီနူးတွင် «ဒေတာဘေ့စ်နှင့် သိုလှောင်မှု စစ်ဆေးသူ» ကို ဖွင့်ပါ၊ ပရောဂျက်နှင့် ဒေတာဘေ့စ်ဖိုင် (.db, .sqlite သို့မဟုတ် .sqlite3) ကို ရွေးချယ်ပါ၊ ထို့နောက် «ဒေတာဘေ့စ်ကို ဖွင့်ပါ» ကို နှိပ်ပါ။ IDE သည် ၎င်း၏ ဇယားများအားလုံး၏ schema ကို SQLite စာမျက်နှာ parser အပြည့်အစုံ (overflow စာမျက်နှာများပါသော B-tree) ဖြင့် ဖတ်ပြီး ပထမ အတန်း 20 ကို Jieshuo အသံကျယ်စွာ ဖတ်သော စာသားဇယားအဖြစ် ပြသသည်။ SELECT မေးခွန်း ရေးပြီး «မေးခွန်းကို လုပ်ဆောင်ပါ» ကို နှိပ်ပါ (ဥပမာ SELECT nama FROM pengguna WHERE kota = 'Makassar') — မေးခွန်းများသည် ယခု JOIN, GROUP BY, ORDER BY နှင့် LIKE ကို ပံ့ပိုးပြီး ဖုန်းပေါ်ရှိ တကယ့် Android SQLite အင်ဂျင်ဖြင့် လုပ်ဆောင်သည်။ တန်ဖိုးကို ပြောင်းလဲရန် အတန်းနံပါတ် (1 = ပထမအတန်း)၊ ကော်လံအမည်နှင့် တန်ဖိုးအသစ်ကို ရိုက်ထည့်ပါ၊ ထို့နောက် «ဆဲလ်တန်ဖိုး ပြောင်းပါ» ကို နှိပ်ပါ — တန်ဖိုးကို .db ဖိုင်ထဲသို့ ပြန်ရေးသည်။ ဇယား၏ လက်ရှိအခြေအနေကို ပရောဂျက်တွင် <ဒေတာဘေ့စ်-အမည်>.cadangan.txt ဖိုင်အဖြစ် သိမ်းဆည်းရန် «အရန်သိမ်းဆည်းပါ» ကို နှိပ်ပါ။ SharedPreferences နှင့် DataStore ကိုလည်း ဖတ်နိုင်သည်။ ယခုထိ ဖတ်၍ မရသေးသောအရာများ: စာဝှက်ထားသော ဒေတာဘေ့စ်များ၊ အတည်မပြုရသေးသော WAL ပြောင်းလဲမှုများ၊ အထူးပြု DataStore Proto ရှိ ရိုက်ထားသော တန်ဖိုးများ (အထွေထွေ အကွက်မြင်ကွင်းအဖြစ်သာ ပြသသည်)။

ယူနစ်စမ်းသပ်မှု စက်ရုံနှင့် Fuzzing
အက်ပ်ကို မျှဝေခြင်းမပြုမီ ယုတ္တိဗေဒ ကွာဟချက်များကို ရှာဖွေရန်: ပင်မမီနူးတွင် «ယူနစ်စမ်းသပ်မှု စက်ရုံနှင့် Fuzzing» ကို ဖွင့်ပါ၊ ပရောဂျက်နှင့် ကုဒ်ဖိုင်ကို ရွေးချယ်ပါ၊ ထို့နောက် «စမ်းသပ်မှုများ ဖန်တီးပြီး လုပ်ဆောင်ပါ» ကို နှိပ်ပါ။ IDE သည် ဖိုင်ထဲက လုပ်ဆောင်ချက် လက်မှတ်များကို ဖတ်သည်၊ သာမန်နှင့် နယ်နိမိတ် စမ်းသပ်မှု ကိစ္စများကို ဖန်တီးသည် (စာသားဗလာ၊ null၊ အများဆုံး နံပါတ်များ၊ ထူးဆန်းသော အက္ခရာများ)၊ ထို့နောက် ထိုစမ်းသပ်မှုများကို တကယ်လုပ်ဆောင်သည်: ပရောဂျက်ကုဒ်ကို စုစည်းပြီး @Test နည်းလမ်းတစ်ခုစီကို 5 စက္ကန့် ကန့်သတ်ချက်ဖြင့် လုပ်ဆောင်သည်၊ ထို့ကြောင့် ရလဒ်မှာ ၎င်းတို့၏ တကယ့်တန်ဖိုးများနှင့်အတူ တကယ့် အောင်မြင်မှုများနှင့် ကျရှုံးမှုများ ဖြစ်သည်။ Fuzzing ကိုလည်း ပရောဂျက် လုပ်ဆောင်ချက်များပေါ်တွင် တကယ်လုပ်ဆောင်သည် (reflection မှတဆင့်၊ ခေါ်ဆိုမှုတစ်ခုလျှင် 2 စက္ကန့်၊ အများဆုံး နည်းလမ်း 20)၊ လိုင်းလွှမ်းခြုံမှု ရာခိုင်နှုန်းကို မူရင်း လိုင်းနံပါတ်များကို ထိန်းသိမ်းထားသော တူရိယာဖြင့် တကယ်တွက်ချက်သည်။ ရလဒ်မှာ စမ်းသပ်မှုဘယ်နှခု အောင်မြင်ပြီး ကျရှုံးသည်၊ ကုဒ်လိုင်းနှင့် လုပ်ဆောင်ချက် ဘယ်နှခု တွေ့ရှိသည်၊ မည်သည့် စမ်းသပ်မှု ကိစ္စများ ဖန်တီးခဲ့သည်ကို အစီရင်ခံသည်။ ဖန်တီးထားသော စမ်းသပ်မှုများသည် JUnit နှင့် အတိအကျ တူညီသော API ကို အသုံးပြုသည်၊ သို့သော် မှတ်ချက်နှင့် အခိုင်အမာ သတ်မှတ်ချက်များကို ဖန်တီးထားသော စမ်းသပ်မှုဖိုင်အတွင်း ရေးသားထားသည်၊ အဘယ်ကြောင့်ဆိုသော် တကယ့် JUnit စာကြည့်တိုက်ကို အက်ပ်တွင် မထည့်သွင်းထားသောကြောင့် ဖြစ်သည်။

စက်ပစ္စည်း ပြင်းထန်သော အခြေအနေ ပုံစံတူလုပ်ဆောင်သူနှင့် မှတ်ဉာဏ် ယိုစိမ့်မှု စာရင်းစစ်သူ
စနစ်က ၎င်း၏ လုပ်ငန်းစဉ်ကို သတ်လိုက်သောအခါ၊ ကွန်ရက် ပြတ်တောက်သောအခါ၊ မျက်နှာပြင် လှည့်သောအခါ၊ သို့မဟုတ် ဘက်ထရီ ချွေတာမှု ဖွင့်သောအခါ အက်ပ်၏ ခံနိုင်ရည်ကို စမ်းသပ်ရန်: ပင်မမီနူးတွင် «စက်ပစ္စည်း ပြင်းထန်သော အခြေအနေ ပုံစံတူလုပ်ဆောင်သူနှင့် မှတ်ဉာဏ် ယိုစိမ့်မှု စာရင်းစစ်သူ» ကို ဖွင့်ပါ၊ ပရောဂျက်ကို ရွေးချယ်ပါ၊ ထို့နောက် «ပုံစံတူလုပ်ဆောင်မှုကို လုပ်ဆောင်ပါ» ကို နှိပ်ပါ။ IDE သည် မျက်နှာပြင် လှည့်ခြင်း ပုံစံတူလုပ်ဆောင်မှုဖြင့် ဖိအားအခြေအနေ သုံးခုကို လုပ်ဆောင်ပြီး ၎င်းတို့၏ မျက်နှာပြင် ပိတ်ပြီးနောက်တွင်ပင် မှတ်ဉာဏ်တွင် ကိုင်ထားသော အရာဝတ္ထုများကို ခြေရာခံသည်၊ ထို့နောက် ပျောက်ဆုံးသွားသော ဒေတာနှင့် ယိုစိမ့်နေသော အရာဝတ္ထု ကွင်းဆက်များကို အစီရင်ခံသည်။ သိမ်းဆည်းခြင်းနှင့် ပြန်လည်ရယူခြင်း အခြေအနေကို ယခု ပုံသေနမူနာမှ မဟုတ်ဘဲ အသုံးပြုသူ၏ ကိုယ်ပိုင် ပရောဂျက် အရင်းအမြစ်မှ ဖတ်သည်၊ ဒေသတွင်း loopback ဆာဗာကို ကွန်ရက်ပြတ်တောက်မှုကို တိုင်းတာရန် စမ်းသပ်မှု အလယ်တွင် တကယ်ရပ်တန့်သည်၊ တကယ့် heap dump ကို ယူပြီး ခွဲခြမ်းစိတ်ဖြာသည်၊ dump နှစ်ခုကို နှိုင်းယှဉ်ပြီး ကိုင်ထားသည့် ကွင်းဆက်ကို GC အမြစ်များမှ ခြေရာခံသည်၊ အက်ပ်၏ ကိုယ်ပိုင် လုပ်ငန်းစဉ်ကို ၎င်း၏ အခြေအနေကို သိမ်းဆည်းပြီးနောက် တကယ်သတ်သည်၊ ထို့နောက် ပြန်ဖွင့်သောအခါ မည်သည့်ဒေတာ ပြန်လာသည်ကို စစ်ဆေးသည်။ သာမန် အက်ပ်မှ ယခုထိ မဖြစ်နိုင်သောအရာများ: ဖုန်း ရေဒီယို သို့မဟုတ် Wi-Fi ပိတ်ခြင်းနှင့် အခြားအက်ပ်များကို အတင်းရပ်တန့်ခြင်း — နှစ်ခုလုံးသည် စနစ်ခွင့်ပြုချက် လိုအပ်သည်၊ အစားထိုး၍ နောက်ခံအက်ပ်များကို killBackgroundProcesses မှတဆင့် သတ်သည်၊ ၎င်း၏ ခွင့်ပြုချက်သည် manifest တွင် ရှိနှင့်ပြီးဖြစ်သည်၊ မျက်နှာပြင်ပေါ်တွင် ရိုးသားသော တံဆိပ်နှင့်အတူ။

ပရောဂျက် ပုံစံငယ် ဗိသုကာပညာရှင်
ကြီးမားသော အက်ပ်စိတ်ကူးကို အဆင့်ဆင့် အလုပ်အစီအစဉ်အဖြစ်သို့ ပြောင်းလဲရန်: ပင်မမီနူးတွင် «ပရောဂျက် ပုံစံငယ် ဗိသုကာပညာရှင်» ကို ဖွင့်ပါ၊ ပရောဂျက်ကို ရွေးချယ်ပါ၊ အက်ပ်စိတ်ကူးကို ရေးပါ (ဥပမာ အရစ်ကျနှင့်အတူ ကုန်စုံဆိုင် ငွေကောင်တာ အက်ပ်ငယ်)၊ ထို့နောက် «ပုံစံငယ် ဖန်တီးပါ» ကို နှိပ်ပါ။ IDE သည် module များ၊ ဖိုင်စာရင်းနှင့် မှတ်တိုင်ငယ်များကို တည်ဆောက်ပြီး ၎င်းတို့ကို ပရောဂျက်ဖိုင်တွဲတွင် cetak-biru.txt အဖြစ် သိမ်းဆည်းသည်။ မှတ်တိုင်တစ်ခု ပြီးဆုံးတိုင်း «နောက်မှတ်တိုင်ကို ပြီးဆုံးပြီဟု အမှတ်အသားပြုပါ» ကို နှိပ်ပါ၊ သို့မဟုတ် သိမ်းဆည်းထားသော ပုံစံငယ်ကို ပြန်ဖွင့်ရန် «သိမ်းဆည်းထားသော ပုံစံငယ်ကို တင်ပါ» ကို နှိပ်ပါ။ တက်ကြွသော AI ပရိုဗိုက်ဒါကို «AI ဆက်တင်များ» တွင် ရွေးချယ်ပြီး ၎င်း၏သော့ ရရှိနိုင်ပါက ပုံစံငယ်ကို ထိုပရိုဗိုက်ဒါမှ တည်ဆောက်သည်၊ သော့ ပျောက်နေပါက သို့မဟုတ် ပရိုဗိုက်ဒါကို ဆက်သွယ်၍ မရပါက IDE သည် အော့ဖ်လိုင်း သော့ချက်စကားလုံး ပုံစံများသို့ ပြန်သွားပြီး ထိုကန့်သတ်ချက်ကို ရိုးသားစွာ ပြောသည်။ ပရိုဗိုက်ဒါ၏ အဖြေကို ပုံစံအတွက်သာ စစ်ဆေးသည် (module များနှင့် မှတ်တိုင်များ ရှိသည်)၊ အကြောင်းအရာ အမှန်တရားအတွက်မဟုတ် — တည်ဆောက်ခြင်းမပြုမီ ပုံစံငယ်ကို အမြဲ ပြန်လည်သုံးသပ်ပါ။

ကုဒ် ယုတ္တိစီးဆင်းမှု ဇာတ်ကြောင်းပြောသူ
ဝါကျတည်ဆောက်ပုံကို တစ်ကြောင်းချင်း နားထောင်ခြင်းမရှိဘဲ ရှည်လျားသော ကုဒ်ကို နားလည်ရန်: ပင်မမီနူးတွင် «ကုဒ် ယုတ္တိစီးဆင်းမှု ဇာတ်ကြောင်းပြောသူ» ကို ဖွင့်ပါ၊ ပရောဂျက်နှင့် ကုဒ်ဖိုင်ကို ရွေးချယ်ပါ၊ ထို့နောက် «ကုဒ် ဇာတ်ကြောင်း» ကို နှိပ်ပါ။ IDE သည် လိုင်းတစ်ခုစီကို အင်ဒိုနီးရှား ဝါကျအဖြစ် ပြောင်းလဲသည် (ဥပမာ စုစုပေါင်းသည် 100000 ထက် ကျော်လွန်ပါက နောက်ဘလောက်ကို လုပ်ဆောင်ပါ)၊ နည်းလမ်းများကြား ခေါ်ဆိုမှုမြေပုံနှင့် နည်းလမ်းများကြား ဒေတာ စီးဆင်းမှု ခွဲခြမ်းစိတ်ဖြာမှု (ရှေ့သို့ ပေးပို့သော၊ အသုံးပြုသော သို့မဟုတ် လျစ်လျူရှုထားသော တန်ဖိုးများ) ကို ပြသပြီး သိမ်မွေ့သော ဖြစ်နိုင်ခြေရှိသည့် bug များကို ၎င်းတို့၏ လိုင်းနံပါတ်များနှင့်အတူ အမှတ်အသားပြုသည် — == နှင့် နှိုင်းယှဉ်ထားသော String၊ မပိတ်ဘဲ ဖွင့်ထားသော stream နှင့် နည်းလမ်းနှစ်ခုကွဲပြားစွာ ရေးသားထားသော ကိန်းရှင်။ တက်ကြွသော AI ပရိုဗိုက်ဒါကို «AI ဆက်တင်များ» တွင် ရွေးချယ်ပါက ထိုပရိုဗိုက်ဒါမှ စီးဆင်းမှု အကျဉ်းချုပ်လည်း ရရှိနိုင်သည်၊ မရှိပါက မျက်နှာပြင်သည် အော့ဖ်လိုင်း ဇာတ်ကြောင်းကို အသုံးပြုပြီး ထိုကန့်သတ်ချက်ကို ပြောသည်။ ဇာတ်ကြောင်း၊ ခေါ်ဆိုမှုမြေပုံနှင့် ဒေတာ စီးဆင်းမှုသည် အော့ဖ်လိုင်း စာသားပုံစံ ခွဲခြမ်းစိတ်ဖြာမှုကို အသုံးပြုသည်၊ AST parser အပြည့်အစုံ မဟုတ် — အဖွင့် bracket ၎င်း၏ ကိုယ်ပိုင် လိုင်းပေါ်တွင် ရှိသော နည်းလမ်းများ၊ အတန်း အကွက်များ၊ reflection မှတဆင့် ခေါ်ဆိုမှုများကို ခြေရာမခံပါ — ဒေတာ ပြိုင်ပွဲ သတိပေးချက်များသည် တကယ်တွင် အလှည့်ကျ အသုံးပြုသော ကိန်းရှင်အတွက်သာ ပေါ်လာနိုင်သည်။

အက်ပ်အထုပ် စက်ရုံနှင့် Play Store အဆင်သင့်ဖြစ်မှု
ဖုန်းမှ တိုက်ရိုက် Google Play Store အတွက် အက်ပ်ကို ပြင်ဆင်ရန်: ပင်မမီနူးတွင် «အက်ပ်အထုပ် စက်ရုံနှင့် Play Store အဆင်သင့်ဖြစ်မှု» ကို ဖွင့်ပါ၊ ပရောဂျက်ကို ရွေးချယ်ပါ၊ ထို့နောက် «AAB အထုပ်ကို တည်ဆောက်ပါ» ကို နှိပ်ပါ။ IDE သည် တကယ့် BundleConfig.pb ဖြင့် ပရောဂျက် manifest, အရင်းအမြစ်များနှင့် အက်ဆက်များမှ .aab ဖိုင်ကို တည်ဆောက်သည်၊ အထုပ်ဖွဲ့စည်းပုံကို အတည်ပြုသည်၊ ထို့နောက် အထုပ်ကို တကယ့် မျိုးကွဲ APK များ (အခြေခံ၊ ဗိသုကာအရ၊ ဘာသာစကားအရ၊ universal) အဖြစ် ထိုခွဲဝေမှုမှ တိုင်းတာသော အရွယ်အစားများဖြင့် ခွဲခြားသည်၊ ခန့်မှန်းချက်များ မဟုတ်။ အထုပ်ကို APK လက်မှတ်ထိုးရန် အသုံးပြုသော တူညီသော ပရောဂျက်သော့ဖြင့် JAR v1 ဖြင့် လက်မှတ်ထိုးပြီး ၎င်း၏ လက်မှတ်ကွင်းဆက်ကို လျှို့ဝှက်နည်းဖြင့် အတည်ပြုသည်။ ဤမျက်နှာပြင်သည် Play အဆင်သင့်ဖြစ်မှုကိုလည်း စစ်ဆေးသည် — ပစ်မှတ် SDK 35 အောက်တွင် ရှိပါက «မြင့်မားသည်» ဟု အမှတ်အသားပြုသည်၊ အဘယ်ကြောင့်ဆိုသော် Play Store က 35 သို့မဟုတ် ထို့ထက်ပိုမို လိုအပ်သောကြောင့် ဖြစ်သည်၊ ပျောက်နေသော 64-bit စာကြည့်တိုက်ကိုလည်း «မြင့်မားသည်» ဟု အမှတ်အသားပြုသည်။ တကယ့် bundletool သည် စက်ပေါ်တွင် လုပ်ဆောင်၍ မရပါ၊ အဘယ်ကြောင့်ဆိုသော် bundletool က JVM လိုအပ်ပြီး Android တွင် JVM မရှိသောကြောင့် ဖြစ်သည်၊ အထက်လမ်းကြောင်းသည် စက်ပေါ်ရှိ အနီးဆုံး တကယ့်လမ်းကြောင်း ဖြစ်သည်။

OTA အပ်ဒိတ်အင်ဂျင်နှင့် အဆင့်လိုက် ထုတ်ဝေမှုများ
အသုံးပြုသူများကို APK တစ်ခုလုံးကို ပြန်လည်ဒေါင်းလုဒ်လုပ်ရန် အတင်းအကျပ် မလုပ်ဘဲ ပြင်ဆင်မှု အသေးစားကို ပေးပို့ရန်: ပင်မမီနူးတွင် «OTA အပ်ဒိတ်အင်ဂျင်နှင့် အဆင့်လိုက် ထုတ်ဝေမှုများ» ကို ဖွင့်ပါ၊ ပရောဂျက်ကို ရွေးချယ်ပါ၊ ဗားရှင်းအဟောင်းနှင့် အသစ် အကြောင်းအရာကို ရေးပါ၊ ထို့နောက် «Patch အထုပ် ဖန်တီးပါ» ကို နှိပ်ပါ။ IDE သည် ကွာခြားချက်ကို တွက်ချက်ပြီး အကြောင်းအရာအသစ်၏ SHA-256 လက်ဗွေဖြင့် patch အထုပ် (patch-ota.zip) ကို ဖန်တီးသည်၊ ထို့နောက် ဤစက်သည် ပထမ 10 ရာခိုင်နှုန်း ထုတ်ဝေမှု အဆင့်တွင် ရှိမရှိ စစ်ဆေးသည်။ Patch များသည် ယခု မည်သည့်ဖိုင်တွင်မဆို binary delta ကို ပံ့ပိုးသည် (DEX နှင့် APK အပါအဝင်)၊ RSA-2048 လက်မှတ်ဖြင့် ထုပ်ပိုးပြီး အသုံးမပြုမီ ယုံကြည်ရသော အများပိုင်သော့ဖြင့် အတည်ပြုသည်၊ ဖန်တီးသူ၏ ဆာဗာမှ ၎င်း၏ ထုတ်ဝေမှုစာရင်းနှင့်အတူ ဒေါင်းလုဒ်လုပ်နိုင်သည်၊ အသုံးပြုခြင်း မအောင်မြင်ပါက ဖိုင်အဟောင်းသည် မထိမခိုက်ကျန်သည်။ လုပ်ဆောင်နေသော အက်ပ်တွင် patch ကို အသုံးပြုခြင်းကို ပရောဂျက်သော့ဖြင့် ပြန်လည်လက်မှတ်ထိုးခြင်းနှင့် PackageInstaller မှတဆင့် ပြုလုပ်သည်၊ အဘယ်ကြောင့်ဆိုသော် လုပ်ဆောင်နေသော လုပ်ငန်းစဉ်၏ ကုဒ်ကို ၎င်းအတွင်းမှ အစားထိုးခြင်းသည် မဖြစ်နိုင်သောကြောင့် ဖြစ်သည် — APK ကို သော့ခတ်ထားပြီး DEX ကို ဝန်တင်ပြီးဖြစ်သည်။

အဖွဲ့ ကုဒ် ပြန်လည်သုံးသပ်မှု စတူဒီယို
လုပ်ဖော်ကိုင်ဖက်၏ ပြောင်းလဲမှုများကို ပြန်လည်သုံးသပ်ရန်နှင့် Git မြှားများကို မဖတ်ဘဲ ပေါင်းစည်းမှု ပဋိပက္ခများကို ဖြေရှင်းရန်: ပင်မမီနူးတွင် «အဖွဲ့ ကုဒ် ပြန်လည်သုံးသပ်မှု စတူဒီယို» ကို ဖွင့်ပါ၊ ပရောဂျက်ကို ရွေးချယ်ပါ၊ စာသားဗားရှင်း သုံးခု (အခြေခံ၊ ဒေသတွင်း၊ လုပ်ဖော်ကိုင်ဖက်) ကို ရိုက်ထည့်ပါ၊ ထို့နောက် «အဖွဲ့ ပြန်လည်သုံးသပ်မှုကို ဖွင့်ပါ» ကို နှိပ်ပါ။ IDE သည် သုံးခုကို Java ဝါကျတည်ဆောက်ပုံ ယူနစ်များအပေါ် အခြေခံ၍ ပေါင်းစည်းသည် — တူညီသော လိုင်းပေါ်တွင် ပြောင်းလဲမှု နှစ်ခု ရှိသော်လည်း ကွဲပြားသော ကြေညာချက်များတွင် ပဋိပက္ခဟု မသတ်မှတ်တော့ပါ — ပဋိပက္ခတစ်ခုစီကို မဲပေးရွေးချယ်မှုအဖြစ် ပြသသည်: ဒေသတွင်း ဗားရှင်းကို အသုံးပြုပါ၊ လုပ်ဖော်ကိုင်ဖက် ဗားရှင်းကို အသုံးပြုပါ၊ သို့မဟုတ် နှစ်ခုလုံးကို ပေါင်းစည်းပါ — ရလဒ်လိုင်းကို လိုင်းအစီအစဉ် မှန်ကန်နေစေရန် မူရင်း ပဋိပက္ခ တည်နေရာတွင် ထည့်သွင်းသည် — ထို့နောက် ရလဒ်ကို ပရောဂျက်တွင် gabung-hasil.txt သို့ ရေးသည်။ အောက်တွင် ပရောဂျက် အလုပ်ဘုတ်ရှိသည်: အလုပ်ခေါင်းစဉ်ကို ရိုက်ထည့်ပါ ထို့နောက် «အလုပ်ထည့်ပါ» ကို နှိပ်ပါ၊ အလုပ်များကို ပရောဂျက်အတွင်းရှိ .tugas ဖိုင်တွဲတွင် စာသားအဖြစ် သိမ်းဆည်းပြီး အက်ပ်အတွင်း Git တွင် commit များမှတဆင့် စင့်ခ်လုပ်သည်၊ ထို့ကြောင့် ဘုတ်ကို မည်သည့် commit မှတ်တမ်းမှမဆို ပြန်ဖတ်နိုင်သည်။ ဤဝါကျတည်ဆောက်ပုံ ခွဲခြားမှုသည် AST parser အပြည့်အစုံ မဟုတ်ပါ၊ အက်ပ်အတွင်း Git သည် commit တစ်ခုစီအတွက် အပြည့်အစုံ လျှပ်တစ်ပြက် ပုံရိပ်ကို သိမ်းဆည်းသည်၊ သီးခြား စင့်ခ်လုပ်သည့် ဆာဗာ မရှိပါ။

ကုဒ်ဖွဲ့စည်းပုံ အသံဖြင့် ညွှန်ကြားခြင်း
အယ်ဒီတာအတွင်း အသံဖြင့် ကုဒ်ရေးရန်- ပရောဂျက်တစ်ခုကို အယ်ဒီတာတွင် ဖွင့်ပါ၊ ထို့နောက် ကုဒ်ဖွဲ့စည်းပုံ အသံဖြင့် ညွှန်ကြားခြင်း ခလုတ်ကို နှိပ်ပါ။ အမိန့်များကို အင်ဒိုနီးရှား ဘာသာစကားဖြင့် ပြောပါ၊ ဥပမာ buat fungsi tambah dengan parameter a angka dan b angka, buat kelas Mobil သို့မဟုတ် buat variabel teks nama sama dengan Budi — IDE က အပြောကို အထားအသို မှန်ကန်သော Java၊ Kotlin၊ Python သို့မဟုတ် Compose ကုဒ် ဘလောက်တစ်ခုအဖြစ် ပြောင်းလဲပြီး ကာဆာ အနေအထားတွင် ထည့်သွင်းကာ Jieshuo မှတစ်ဆင့် အကျဉ်းချုပ် အကျဉ်းကို အသံကျယ်ကျယ် ဖတ်ပြသည်။ အသံဖြင့် ညွှန်ကြားခြင်းသည် စနစ်၏ ထည့်သွင်းထားသော အသံ ထည့်သွင်းမှု ဝန်ဆောင်မှုကို အသုံးပြုသည်၊ နောက်ထပ် မိုက်ခရိုဖုန်း ခွင့်ပြုချက် မလိုအပ်ပါ၊ မှတ်ပုံတင်ထားပြီးသော အမိန့် ပုံစံများကိုသာ မှတ်မိသည်၊ ထိုပုံစံများပြင်ပရှိ အပြောသည် ကုဒ်အဖြစ် မပြောင်းလဲပါ။ စကားလုံးများအဖြစ် ပြောသော ဂဏန်းများ (ဥပမာ 'lima') သည် ဂဏန်းများအဖြစ် မပြောင်းလဲသေးပါ။

ဒေသတွင်း ပူးပေါင်းဆောင်ရွက်မှု အခန်း (အင်တာနက်မလိုပါ)
အင်တာနက်မရှိဘဲ အခန်းတစ်ခုတွင် အတူတကွ လုပ်ဆောင်ရန်- ပင်မမီနူးတွင် ပူးပေါင်းဆောင်ရွက်မှု ကို ဖွင့်ပါ၊ ထို့နောက် ဒေသတွင်း ပူးပေါင်းဆောင်ရွက်မှု အခန်း အပိုင်းကို ဖွင့်ပါ။ ဖုန်းတစ်လုံးက ဆက်ရှင်တစ်ခု ဖွင့်သည် (IDE က ဒေသတွင်း IP လိပ်စာနှင့် 6 လုံး PIN ကို ပြသသည်)၊ အခြား ဖုန်းတစ်လုံးက ထိုလိပ်စာနှင့် PIN ဖြင့် ပါဝင်သည်။ စာသား ပြောင်းလဲမှုများကို လိုင်း ကွာခြားချက်များအဖြစ် ပေးပို့သည်၊ တည်ဆောက်ပြီးသား APK ကို စမ်းသပ်သူ၏ ဖုန်းသို့ ပေးပို့နိုင်သည်၊ စမ်းသပ်သူ၏ ဖုန်းမှ Crash အစီရင်ခံစာများကို ပြန်လည် လက်ခံရရှိသည်။ ဆက်ရှင်တစ်ခုသည် သူငယ်ချင်းတစ်ဦးအတွက်သာ ဖြစ်သည်၊ လူနှစ်ဦးက အတိအကျ တူညီသော လိုင်းကို တစ်ချိန်တည်းတွင် ပြောင်းလဲလျှင် နောက်ဆုံး ပြောင်းလဲမှုကို အသုံးပြုသည်။ PIN ကို ဒေသတွင်း ကွန်ရက်ပေါ်တွင် ရိုးရှင်းသော စာသားအဖြစ် ပေးပို့သည်။ ဤအခန်းကို အမှန်တကယ် ဖုန်းပေါ်တွင် မစမ်းသပ်ရသေးပါ။

AI ဆက်တင်များ
အက်ပ်များ တည်ဆောက်ရန် AI ပရိုဗိုက်ဒါနှင့် API သော့များကို သတ်မှတ်ရန်: ပင်မမီနူးတွင် ဆက်တင်အုပ်စုတွင် «AI ဆက်တင်များ» ကို နှိပ်ပါ («ကွန်နက်တာ» ခလုတ်ဘေးတွင်)။ ရရှိနိုင်သော စာရင်းမှ အသုံးပြုမည့် ပရိုဗိုက်ဒါကို ရွေးချယ်ပါ၊ မော်ဒယ်တစ်ခု မအောင်မြင်ပါက IDE သည် တူညီသော ပရိုဗိုက်ဒါမှ နောက်မော်ဒယ်ကို အလိုအလျောက် စမ်းသပ်စေရန် «ပရိုဗိုက်ဒါ အမှားဖြစ်လျှင် မော်ဒယ် ပြောင်းရန်» ကို အမှန်ခြစ်ပါ။ အရန်သော့များ ထည့်ရန် «API သော့များ စီမံခန့်ခွဲရန်» ကို နှိပ်ပါ (အမည်နှင့် သော့ကို ရိုက်ထည့်ပါ၊ ထို့နောက် «သိမ်းဆည်းရန်» ကို နှိပ်ပါ၊ သော့များကို ဖုံးကွယ်ထားသည်၊ နောက်ဆုံး 4 လုံးသာ မြင်ရသည်)။ သော့များကို ဖုန်းပေါ်တွင် သိမ်းဆည်းထားပြီး အက်ပ်ကို တည်ဆောက်သည့်အခါ ရွေးချယ်ထားသော ပရိုဗိုက်ဒါမှလွဲ၍ အခြားနေရာသို့ ဘယ်တော့မှ မပို့ပါ။ ရွေးချယ်ထားသော ပရိုဗိုက်ဒါကို ယခု «ပရောဂျက် ပုံစံငယ် ဗိသုကာပညာရှင်» နှင့် «ကုဒ် ယုတ္တိစီးဆင်းမှု ဇာတ်ကြောင်းပြောသူ» တို့က တကယ်အသုံးပြုသည်၊ «AI အက်ပ် ဖန်တီးသူ» မျက်နှာပြင်တွင် အက်ပ် တည်ဆောက်ခြင်းသည် ဖုန်းပေါ်ရှိ ဒေသတွင်း AI ကို ယခုထိ အသုံးပြုသည် (အင်တာနက်မရှိ)။

ကွန်နက်တာ
APK တစ်ခုကို ခွဲခြမ်းစိတ်ဖြာပြီး ပေးပို့ရန်- ပင်မမီနူးတွင် ဆက်တင်များ အုပ်စုတွင် ကွန်နက်တာ ကို နှိပ်ပါ (AI ဆက်တင်များ ခလုတ် အနားတွင်)။ ဖုန်းမှ APK ဖိုင်တစ်ခု ရွေးပါ၊ IDE က ၎င်း၏ အကြောင်းအရာကို ဖတ်သည် (အထုပ် အမည်၊ ဗားရှင်း၊ လုပ်ဆောင်ချက်များ စာရင်း)၊ ထို့နောက် စနစ် မျှဝေမှု မီနူးမှတစ်ဆင့် ပေးပို့ရန် APK ပေးပို့ရန် ကို နှိပ်ပါ (ဥပမာ WhatsApp သို့မဟုတ် Drive)။

ဘာသာစကားနှင့် အသံ
အက်ပ်၏ ဘာသာစကားကို ပြောင်းရန်- ဆက်တင်များ ကို ဖွင့်ပါ၊ ထို့နောက် အက်ပ် ဘာသာစကား ကို ဖွင့်ပြီး ဘာသာစကားတစ်ခု သို့မဟုတ် စနစ်အတိုင်း လိုက်နာရန် ကို ရွေးပါ။ ပင်မမျက်နှာပြင်နှင့် မျက်နှာပြင် အများစုသည် အက်ပ်ကို ပိတ်ခြင်း သို့မဟုတ် ပြန်လည်စတင်ခြင်းမရှိဘဲ ရွေးချယ်ထားသော ဘာသာစကားသို့ ချက်ချင်း ပြောင်းလဲသည်၊ အချို့သော မျက်နှာပြင်များ (ဥပမာ Terminal၊ ပူးပေါင်းဆောင်ရွက်မှု၊ AI ဆက်တင်များနှင့် သော့များ စီမံခန့်ခွဲခြင်း) ကို ပြန်ဖွင့်သည်အထိ အဟောင်း ဘာသာစကားကို ဆက်လက် အသုံးပြုနေဆဲဖြစ်သည်။ စနစ်အတိုင်း လိုက်နာရန် ကို ရွေးချယ်လျှင် ဘာသာစကားသည် ဖုန်း၏ စနစ် ဘာသာစကားကို လိုက်နာသည်။

ပရောဂျက်အလိုက် မူရင်း လက်မှတ်နှင့် Anti Tamper
ဗားရှင်း 5.7 မှစ၍ ကိုယ်ပိုင် လက်မှတ်ကို အသုံးမပြုသော ပရောဂျက်ကို ပရောဂျက်၏ ကိုယ်ပိုင် ထည့်သွင်းထားသော သော့ဖြင့် လက်မှတ်ထိုးသည် (ပရောဂျက်အတွင်းရှိ tanda-tangan-bawaan ဖိုင်တွဲတွင် တစ်ကြိမ် ဖန်တီးပြီး ဆက်လက် အသုံးပြုသည်)၊ ထို့ကြောင့် ထည့်သွင်းထားသော လက်မှတ်သည် ပရောဂျက်တစ်ခုမှ တစ်ခုသို့ ကွာခြားသည် — အက်ပ်အားလုံးအတွက် မျှဝေထားသော သော့ မဟုတ်တော့ပါ။ tanda-tangan-bawaan ဖိုင်တွဲကို မဖျက်ပါနှင့် - ထိုသော့ မရှိပါက APK အသစ်သည် တူညီသော ပရောဂျက်အတွက် APK အဟောင်းကို အစားထိုး၍ မရပါ။ ပရောဂျက်တိုင်း၏ ဆက်တင်များ (သီးခြား ဗိသုကာ၊ ကိုယ်ပိုင် လက်မှတ်၊ Anti Tamper၊ ရွေးချယ်ထားသော keystore၊ SDK) ကို ယခု ပရောဂျက်အတွင်းရှိ settings.gradle ဖိုင်တွင် သိမ်းဆည်းပြီး ပရောဂျက် တည်ဆောက်တိုင်း ပြန်လည် ဖတ်သည်။ ဆက်တင်များ၊ လက်မှတ် အမျိုးအစားတွင် တည်ဆောက်ထားသော အက်ပ်အတွက် Anti Tamper အမှန်ခြစ်ကွက် ရှိသည် - တက်ကြွနေပါက တည်ဆောက်ထားသော အက်ပ်သည် စက်ပစ္စည်းပေါ်တွင် ၎င်း၏ လက်မှတ်နှင့် dex အကြောင်းအရာကို ဖွင့်တိုင်း စစ်ဆေးသည်။ အခြားသူတစ်ဦးက ပြန်လည် လက်မှတ်ထိုးခြင်း သို့မဟုတ် ပြောင်းလဲခြင်းပြုလုပ်ပါက အက်ပ်သည် လုပ်ဆောင်ရန် ငြင်းဆိုသည်။ Frida/Xposed ကဲ့သို့သော အမှားရှာဖွေခြင်းနှင့် ထိုးသွင်းခြင်း ကိရိယာများကိုလည်း တွေ့ရှိပြီး အက်ပ် ဝင်းဒိုးကို မျက်နှာပြင် မှတ်တမ်းတင်ခြင်းမှ သော့ခတ်ထားသည်။

နမူနာ ဗီဒီယို ဖန်တီးသူ
တည်ဆောက်ထားသော အက်ပ်၏ နမူနာ ဗီဒီယို ဖန်တီးရန် - အဓိက မီနူးတွင် နမူနာ ဗီဒီယို ဖန်တီးသူ ကို ဖွင့်ပါ၊ ပရောဂျက်ကို ရွေးချယ်ပါ၊ ဗီဒီယို ခေါင်းစဉ်ကို ဖြည့်ပြီး Demo Video Script ဖန်တီးပါ ကို နှိပ်ပါ — IDE သည် စံမြင်ကွင်း ၅ ခု (အဖွင့်၊ အဓိက မြင်ကွင်း၊ လုပ်ဆောင်ချက် ၁၊ လုပ်ဆောင်ချက် ၂၊ အပိတ်) ပါသော video-demo.txt ကို ဇာတ်ကြောင်းစာသားနှင့် မြင်ကွင်းတစ်ခုစီ၏ ကြာချိန်နှင့်အတူ ရေးသည်။ ပရောဂျက်၏ ပုံများ (အိုင်ကွန် + မျက်နှာပြင် ရိုက်ကူးမှုများ၊ ရှိပါက) မှ video-demo.html ဖန်တီးရန် HTML Slideshow ဖန်တီးပါ ကို နှိပ်ပါ၊ ၅ စက္ကန့်တိုင်း အလိုအလျောက် ပြောင်းလဲသည်။ ဤသည်မှာ .mp4 ဗီဒီယို မဟုတ်ပါ — အစစ်အမှန် ဗီဒီယိုအတွက် ဖုန်း ဘရောက်ဇာတွင် video-demo.html ကို ဖွင့်ပြီး မျက်နှာပြင်ကို မှတ်တမ်းတင်ပါ သို့မဟုတ် လုပ်ဆောင်နေသော အက်ပ်ကို မှတ်တမ်းတင်နေစဉ် video-demo.txt ရှိ ဇာတ်ကြောင်းကို ဖတ်ပါ။

Android Studio ပုံစံ အသွင်အပြင်အသစ်
IDE ၏ အသွင်အပြင်ကို ယခု Android Studio ကဲ့သို့ သပ်ရပ်စွာ ပြုလုပ်ထားသည် (အသွင်အပြင်သာ — ခလုတ်များ၊ မီနူးများနှင့် စီးဆင်းမှုများ အားလုံး အတိအကျ အတိုင်းအတာ ကျန်ရှိသည်) - အလင်းရောင် မီးခိုးရောင် နောက်ခံ၊ ရဲရင့်သော အနက်ရောင် မျက်နှာပြင် ခေါင်းစဉ်များ၊ အဖြူရောင် စာသားပါသော အပြာရောင် ခလုတ်များနှင့် ပါးလွှာသော ဘောင်ပါသော အဖြူရောင် ထည့်သွင်းမှု အကွက်များ။ အဓိက မီနူးကို အမြင်အာရုံဖြင့် အုပ်စုဖွဲ့ထားသည် (ဖန်တီးသူ၏ လုပ်ဆောင်ချက်များ၊ Cloud၊ အပြင်အဆင် နှင့် အခြားများ၊ အသံ၊ ကုဒ် နှင့် လုပ်ဆောင်ချက်အသစ်များ၊ ကိရိယာများ) ခလုတ်များ၏ အစဉ်ကို မပြောင်းလဲဘဲ။ Terminal သည် Android Studio ရှိ Terminal ဝင်းဒိုးကဲ့သို့ အမှောင် အကန့်ကို ဆက်လက် အသုံးပြုပြီး ကုဒ် တည်းဖြတ်သူတွင် အဖြူရောင် နောက်ခံနှင့် အနက်ရောင် စာသား ရှိသေးသည်။ စာသားအားလုံးကို Jieshuo က ရှင်းလင်းစွာ ဖတ်ပြနေဆဲဖြစ်သည်။

ဆက်တင်များ
အက်ပ်ကို သတ်မှတ်ရန် - ပင်မ မျက်နှာပြင်ရှိ ရွေးချယ်စရာ မီနူးကို ဖွင့်ပြီး ဆက်တင်များ ကို နှိပ်ပါ။ အတွင်း၌ အမျိုးအစား ၁၂ ခု ရှိသည် - GitHub ဆက်တင်များ (လုံခြုံရေး၊ ကိုယ်ပိုင် လက်မှတ်၊ တည်ဆောက်မှု မှတ်တမ်း နှင့် GitHub တိုကင်)၊ စက်ပစ္စည်းပေါ်တွင် APK တည်ဆောက်ခြင်း ဆက်တင်များ (keystore စကားဝှက်နှင့် တည်ဆောက်မှု မှတ်တမ်းကို စက်ပစ္စည်းပေါ်တွင် သိမ်းဆည်းခြင်း)၊ အပြင်အဆင် (အက်ပ် အရောင်)၊ လက်မှတ် (ကိုယ်ပိုင် လက်မှတ်အတွက် keystore ဖန်တီးခြင်းနှင့် တည်ဆောက်ထားသော အက်ပ်အတွက် Anti Tamper အမှန်ခြစ်ကွက်)၊ ပရောဂျက် ဖိုင်တွဲ (ပရောဂျက် ဖိုင်တွဲ တည်နေရာ)၊ ဘာသာစကားနှင့် အသံ (အင်တာဖေ့စ် ဘာသာစကားနှင့် အသံ မုဒ်၏ ပြောဆိုမှု အမြန်နှုန်း)၊ စာသား အရွယ်အစားနှင့် အသွင်အပြင် (တည်းဖြတ်သူ၏ ဖောင့် အရွယ်အစား)၊ တည်ဆောက်ခြင်း (ပရောဂျက် ဖန်တီးရန် မျက်နှာပြင်အတွက် မူရင်း ပစ်မှတ် SDK နှင့် မူရင်း ဗိသုကာ ခွဲခြားခြင်း)၊ အကြောင်းကြားစာ (တည်ဆောက်ခြင်း ပြီးဆုံးသည့်အခါ အသံ)၊ အလိုအလျောက် အရန်ကူးခြင်း (ပရောဂျက် အရန်ကူးခြင်း အချိန်ဇယား)၊ ဆော့ဖ်ဝဲထုတ်လုပ်သူ ပရိုဖိုင် (အမည်၊ WhatsApp နံပါတ် နှင့် လှူဒါန်းမှု မျက်နှာပြင်တွင် ပြသထားသော အကောင့်) နှင့် ကိုယ်ရေးကိုယ်တာနှင့် ဒေတာ (ဆက်တင်များ ပြန်လည်သတ်မှတ်ခြင်းနှင့် အက်ပ် ဒေတာ ဖျက်ခြင်း)။ အမျိုးအစားတိုင်းတွင် အမျိုးအစား မီနူးသို့ ပြန်သွားရန် ယခင်သို့ ပြန်သွားရန် ခလုတ် ရှိသည်။ ယခုမှ သိမ်းဆည်းထားသော ဆက်တင်များ (မကျင့်သုံးရသေးသော) ကို မျက်နှာပြင်တွင် ရိုးရိုးသားသား ရှင်းပြထားသည်။

ဆော့ဖ်ဝဲရေးသူကို လှူဒါန်းရန်
ဆော့ဖ်ဝဲရေးသူကို လှူဒါန်းရန် သို့မဟုတ် နှုတ်ဆက်ရန် - ပင်မ မျက်နှာပြင်ရှိ ကိရိယာ အကြောင်း ခလုတ် အနားရှိ ဆော့ဖ်ဝဲရေးသူကို လှူဒါန်းရန် ခလုတ်ကို နှိပ်ပါ။ လှူဒါန်းမှု မျက်နှာပြင်တွင် BRI အကောင့် ကူးယူပါ ခလုတ် ရှိသည် — ဆော့ဖ်ဝဲရေးသူ၏ အကောင့် နံပါတ်ကို ကူးယူရန် ၎င်းကို နှိပ်ပြီး သင့်ဘဏ် အက်ပ်သို့ ကပ်ပါ။ WhatsApp မှာ Developer ကို နှုတ်ဆက်ပါ အပိုင်းလည်း ရှိသည် - သင့်အမည်နှင့် ဇာတိမြို့ကို ဖြည့်ပြီး WhatsApp မှာ ပို့ပါ ကို နှိပ်ပါ — WhatsApp သည် နှုတ်ဆက်ခြင်း မက်ဆေ့ချ် ဖြည့်ပြီးသား ပွင့်လာသည်၊ WhatsApp မှာ ပို့ပါ ကိုသာ နှိပ်ပြီး အက်ပ်သို့ ပြန်သွားပါ။ WhatsApp သည် အခြား အက်ပ်များကို မက်ဆေ့ချ်များ အလိုအလျောက် ပို့ခွင့် မပြုပါ၊ ထို့ကြောင့် ပို့ဆောင်မှုကို WhatsApp တွင် သင်ကိုယ်တိုင် ဆက်လက် ပြုလုပ်သည်။

Terminal ၏ အကြိုက်ဆုံး အမိန့်များ
Terminal တွင် မကြာခဏ အသုံးပြုသော အမိန့်များကို သိမ်းဆည်းရန် - Terminal ကို ဖွင့်ပြီး အကြိုက်ဆုံးများ ကို နှိပ်ပါ။ အကြိုက်ဆုံး အသစ် ထည့်ပါ ကို နှိပ်ပါ၊ အမည် (ဥပမာ ဖိုင် ကြည့်ပါ) နှင့် ၎င်း၏ အမိန့် (ဥပမာ ls -la) ကို ဖြည့်ပြီး သိမ်းဆည်းရန် ကို နှိပ်ပါ — အကြိုက်ဆုံးကို ဖုန်းတွင် အမြဲတမ်း သိမ်းဆည်းသည်။ terminal တွင် တိုက်ရိုက် လုပ်ဆောင်ရန် အကြိုက်ဆုံး အမည်ကို နှိပ်ပါ။ အကြိုက်ဆုံး ဖျက်ပါ ကို နှိပ်ပြီး ဖျက်ရန် တစ်ခုကို ရွေးချယ်ပါ (အတည်ပြုချက်ဖြင့်)။ ထည့်သွင်းပြီးသား အကြိုက်ဆုံး ၃ ခု ရှိပြီးဖြစ်သည် - ဖိုင် ကြည့်ပါ (ls -la)၊ နေရာလွတ် စစ်ဆေးပါ (df -h) နှင့် မျက်နှာပြင် ရှင်းပါ (clear) — အားလုံးကို ဖျက်နိုင်သည်။ ဗလာ အမိန့်ကို သိမ်းဆည်း၍လည်း မရ၊ လုပ်ဆောင်၍လည်း မရပါ။ Terminal သည် ဤသို့ ဖြစ်ပွားပါက မက်ဆေ့ချ်နှင့် အသံဖြင့် အသိပေးသည်။

ခွဲခြမ်းစိတ်ဖြာမှု နှင့် အရည်အသွေး
အက်ပ် အသုံးပြုမှုနှင့် ပျက်ကျမှု အစီရင်ခံစာများ၏ အကျဉ်းချုပ်ကို ကြည့်ရန် - ပင်မ မျက်နှာပြင်ရှိ ဆော့ဖ်ဝဲရေးသူကို လှူဒါန်းရန် ခလုတ် အနားရှိ ခွဲခြမ်းစိတ်ဖြာမှု နှင့် အရည်အသွေး ခလုတ်ကို နှိပ်ပါ။ ဤမျက်နှာပြင်သည် အက်ပ် ဖွင့်ခဲ့သည့် အကြိမ်အရေအတွက်၊ အများဆုံး ဖွင့်သော မျက်နှာပြင်များ၊ ပျက်ကျမှု အရေအတွက် နှင့် အတိုချုံး ပြင်ဆင်ရန် အကြံပြုချက်များနှင့်အတူ နောက်ဆုံး ပျက်ကျမှုများ စာရင်းကို ပြသသည်။ ဤဒေတာကို သင့်ဖုန်းတွင်သာ သိမ်းဆည်းပြီး မည်သည့်နေရာသို့မှ မပို့ပါ။ ဤဒေတာ အားလုံးကို ဖျက်ရန် အတည်ပြုချက် ဆွေးနွေးမှုပါသော Analytics Data ဖျက်ပါ ခလုတ် ရှိသည်။ နောက်ဆုံး မျက်နှာပြင်ကို ပင်မ မျက်နှာပြင်နှင့် ဤမျက်နှာပြင်အတွက်သာ မှတ်တမ်းတင်သည်။
