Create Aplikasi by Al Kautsar သို့ ကြိုဆိုပါသည်
Create Aplikasi သည် လက်ပ်တော့မလိုအပ်ဘဲ ဖုန်းပေါ်တွင် တိုက်ရိုက်အလုပ်လုပ်သော Android အက်ပ်ဖန်တီးရေး အက်ပ်တစ်ခုဖြစ်သည်။ ဤအက်ပ်သည် မည်သူမဆို မိမိကိုယ်ပိုင် Android အက်ပ်ကို ဖန်တီးနိုင်စေပြီး အက်ပ်ဖန်တီးခြင်း စတင်လေ့လာနေသူများနှင့် မျက်နှာပြင်ဖတ်စက် (screen reader) အသုံးပြုသူများလည်း ပါဝင်သည်။ ဤအက်ပ်အသုံးပြုပုံ လမ်းညွှန်အပြည့်အစုံကို ဤ Tentang Alat မျက်နှာပြင်တွင် ရရှိနိုင်ပါသည်။

ဤအက်ပ်က ဘာလဲ၊ ဘယ်သူတွေအတွက်လဲ
Create Aplikasi သည် ဖုန်းပေါ်တွင် အလုပ်လုပ်သော Android အက်ပ်ဖန်တီးရေး ကိရိယာတစ်ခုဖြစ်သည်။ ဤအက်ပ်သည် မိမိကိုယ်ပိုင် Android အက်ပ်ကို ဖန်တီးလိုသော မည်သူမဆို အတွက်ဖြစ်ပြီး အစပြုသူများနှင့် မျက်နှာပြင်ဖတ်စက် အသုံးပြုသူများလည်း ပါဝင်သည်။ ဤအက်ပ်တွင် ကုဒ်တည်းဖြတ်စနစ်၊ ပရောဂျက်ကို စမ်းသပ်ရန် Jalankan ခလုတ်၊ APK တည်ဆောက်ရန် Bangun ခလုတ်၊ ထို့ပြင် APK ကို လက်မှတ်ထိုးရန်နှင့် ထည့်သွင်းရန် မီနူးများ ပါဝင်သည်။

ဤအက်ပ်၏ ရည်ရွယ်ချက်
ဤအက်ပ်ကို မည်သူမဆို မိမိကိုယ်ပိုင် Android အက်ပ်ကို ဖုန်းမှ တိုက်ရိုက် အလွယ်တကူ ဖန်တီးနိုင်ရန် ပြုလုပ်ထားသည်။ ၎င်း၏ ပုံပန်းသွင်ပြင်ကို အသုံးပြုသူအသစ်များပင် ချက်ချင်း စမ်းသုံးနိုင်ရန် တတ်နိုင်သမျှ ရိုးရှင်းအောင် ပြုလုပ်ထားသည်။

ပရောဂျက်အသစ် ဖန်တီးနည်း အဆင့်ဆင့်
1. ပင်မမီနူးတွင် Buat Project ကို နှိပ်ပါ။
2. ပရောဂျက်အမျိုးအစားကို ရွေးပါ: HTML, Situs Web, Java, Kotlin, Compose, သို့မဟုတ် Python။
3. အက်ပ်အမည်ကို ဖြည့်ပါ၊ ဥပမာ: Garuda Decode။
4. ပက်ကေ့ဂျ်အမည် (package name) ကို ဖြည့်ပါ၊ ဥပမာ: com.android.garudadecode။ ပက်ကေ့ဂျ်အမည်သည် စာလုံးအသေးများသာ ပါဝင်ရမည်ဖြစ်ပြီး အစက်ဖြင့် ခြားထားသော အပိုင်းအနည်းဆုံး နှစ်ပိုင်း ပါဝင်ရမည်။
5. အက်ပ်ဗားရှင်းကို ဖြည့်ပါ၊ ဥပမာ: 1.0၊ နှင့် ဂဏန်းဖြင့် ဗားရှင်းကုဒ်ကို ဖြည့်ပါ၊ ဥပမာ: 1။ ဗလာထားပါက ဗားရှင်းသည် 1.0 နှင့် ဗားရှင်းကုဒ် 1 အဖြစ် အလိုအလျောက် ဖြည့်သွားမည်။
6. လိုအပ်ပါက အနည်းဆုံး SDK နှင့် ပစ်မှတ် SDK ကို ဖြည့်ပါ။ ဗလာထားပါက မူလတန်ဖိုးများကို အသုံးပြုမည်။ အနည်းဆုံး SDK သည် ထောက်ပံ့သော အနိမ့်ဆုံး Android ဗားရှင်းဖြစ်သည်၊ ဥပမာ: 21 ဆိုသည်မှာ Android 5.0 ဖြစ်သည်။ ပစ်မှတ် SDK ၏ အများဆုံးမှာ 36 (Android 16) ဖြစ်သည်။
7. အက်ပ်ခွင့်ပြုချက်များကို ရွေးရန် Pilih Izin ကို နှိပ်ပါ၊ ဥပမာ: INTERNET။ INTERNET ခွင့်ပြုချက်သည် မူလအတိုင်း အမှန်ခြစ်ထားပြီးဖြစ်သည်။ အက်ပ်အတွက် အမှန်တကယ် လိုအပ်သော ခွင့်ပြုချက်များကိုသာ အမှန်ခြစ်ပါ။
8. ဆန္ဒရှိပါက APK အရွယ်အစား သေးငယ်စေရန် "Gunakan arsitektur terpisah 64 bit dan 32 bit" ကို အမှန်ခြစ်ပါ၊ နှင့် ကိုယ်ပိုင်ဖန်တီးထားသော keystore ကို သုံးလိုပါက "Gunakan tanda tangan pribadi" ကို အမှန်ခြစ်ပါ။
9. Buat Proyek ကို နှိပ်ပါ။ ပရောဂျက်အသစ်သည် Download/project ဖိုလ်ဒါတွင် သိမ်းဆည်းပြီး Kelola Project တွင် ချက်ချင်း ပေါ်လာမည်။

ရရှိနိုင်သော ပရောဂျက်အမျိုးအစားများ
• HTML: WebView မှတစ်ဆင့် အလုပ်လုပ်သော index.html, style.css နှင့် script.js တို့ဖြင့် ပြသမှု။ ဖုန်းပေါ်တွင် တိုက်ရိုက် တည်ဆောက်သည်။
• Situs Web: WebView မှတစ်ဆင့် အလုပ်လုပ်သော index.html, tentang.html, kontak.html, style.css နှင့် script.js တို့ပါဝင်ပြီး မီနူး (Beranda, Tentang, Kontak) ပါသော ဝက်ဘ်ဆိုက်။ ဖုန်းပေါ်တွင် တိုက်ရိုက် တည်ဆောက်သည်။
• Java: ဖုန်းပေါ်တွင် တည်ဆောက်သည်။ MainActivity သည် app/src/main/java/<nama-paket>/MainActivity.java တွင် ရှိသည်။ ပြသမှုသည် app/src/main/res/layout/activity_main.xml မှ၊ စာသားသည် app/src/main/res/values/strings.xml မှ၊ အပြင်အဆင်သည် app/src/main/res/values/styles.xml မှ ရယူသည်။
• Kotlin: အက်ပ်တွင် ပါဝင်သော Kotlin compiler ကို သုံး၍ စက်ပေါ်တွင် (offline) သို့မဟုတ် GitHub Actions မှတစ်ဆင့် တည်ဆောက်နိုင်သည်။ MainActivity သည် app/src/main/java/<nama-paket>/MainActivity.kt တွင် ရှိပြီး res ဖိုင်များသည် Java ပရောဂျက်နှင့် အတူတူဖြစ်သည်။ Compiler အရွယ်အစား ကြီးမားသောကြောင့် ပထမဆုံး Kotlin တည်ဆောက်မှုသည် ပိုနှေးပြီး Kotlin class များကို ရည်ညွှန်းသော .java ဖိုင်များကို လောလောဆယ် တည်ဆောက်၍ မရသေးပါ (.java ဖိုင်များကို .kt ဖိုင်များမတိုင်မီ compile လုပ်သည်)။
• Compose: အင်တာဖေ့စ်ကို Jetpack Compose ဖြင့် ဖန်တီးထားသော ခေတ်မီ Android အက်ပ် (XML layout မဟုတ်ပါ)။ MainActivity သည် app/src/main/java/<nama-paket>/MainActivity.kt တွင် ရှိသည်။ Compose ပရောဂျက်များကို GitHub Actions မှတစ်ဆင့် (Bangun proyek မီနူး၊ ထို့နောက် Bangun online) သို့မဟုတ် Gradle ဖြင့် Termux တွင် တည်ဆောက်သည်၊ အကြောင်းမှာ Compose သည် စက်ပေါ်တွင် မရရှိနိုင်သော Jetpack Compose library များ လိုအပ်သောကြောင့်ဖြစ်သည်။
• Python: အက်ပ်လော့ဂျစ်ကို Python ဘာသာစကား (Chaquopy) ဖြင့် app/src/main/python/main.py တွင် ရေးသားပြီး app/src/main/java/<nama-paket>/MainActivity.java ရှိ MainActivity host က run ပေးသည်။ Python ပရောဂျက်များကို ဖုန်းပေါ်တွင် တိုက်ရိုက် (Chaquopy runtime သည် အက်ပ်တွင် ပါဝင်သည်) သို့မဟုတ် GitHub Actions မှတစ်ဆင့် တည်ဆောက်နိုင်သည်။ Python ပရောဂျက်၏ အနည်းဆုံး SDK မှာ 24 (Android 7.0) ဖြစ်သည်။

Java, HTML, Situs Web, Kotlin, Compose နှင့် Python ပရောဂျက်များ၏ ဖိုင်ဖွဲ့စည်းပုံ
Java, HTML, Situs Web, Kotlin, Compose နှင့် Python ပရောဂျက်များသည် ပုံမှန် Android ပရောဂျက်များကဲ့သို့ ဖွဲ့စည်းထားသည်။ app ဖိုလ်ဒါအတွင်းတွင် src ဖိုလ်ဒါရှိပြီး ၎င်းအတွင်းတွင် main ဖိုလ်ဒါရှိသည်။ main ဖိုလ်ဒါအတွင်းတွင် java ဖိုလ်ဒါ၏ ဘေးတွင် AndroidManifest.xml၊ layout/activity_main.xml နှင့် values/strings.xml နှင့် values/styles.xml တို့ပါဝင်သော res ဖိုလ်ဒါ၊ HTML နှင့် Situs Web အတွက် index.html ပါဝင်သော assets ဖိုလ်ဒါ (Situs Web တွင် tentang.html နှင့် kontak.html လည်း ရှိသည်) တို့ ရှိသည်။ HTML နှင့် Situs Web ပရောဂျက်များတွင်လည်း app/src/main/java/<nama-paket>/MainActivity.java တွင် ကိုယ်ပိုင် MainActivity ရှိပြီး ၎င်းသည် index.html ကို WebView တွင် load လုပ်ကာ AndroidManifest တွင် launcher ဖြစ်သည်။ Python ပရောဂျက်၏ Python ကုဒ်သည် app/src/main/python/main.py တွင်ရှိပြီး host MainActivity.java သည် app/src/main/java/<nama-paket>/MainActivity.java တွင် ရှိသည်။ AndroidManifest.xml, layout, strings နှင့် styles တို့ကို MainActivity ကဲ့သို့ပင် editor တွင် ဖွင့်၍ ပြင်ဆင်နိုင်သည်။ Manifest သည် app ဖိုလ်ဒါ၏ ဘေးတွင်ပင် ရှိနေသေးသော ပရောဂျက်အဟောင်းများကိုလည်း တည်ဆောက်နိုင်သည်၊ အကြောင်းမှာ တည်ဆောက်ချိန်တွင် အက်ပ်သည် app/src/main/ ရှိ AndroidManifest.xml ကို ဦးစွာ စစ်ဆေးပြီး ထို့နောက် app ဖိုလ်ဒါ၏ ဘေးရှိကို စစ်ဆေးကာ နောက်ဆုံးတွင် ပရောဂျက်ဒေတာဖိုင်ကို စစ်ဆေးသောကြောင့်ဖြစ်သည်။

ခွင့်ပြုချက် စည်းမျဉ်းများ (အရေးကြီး)
ပရောဂျက်ဖန်တီးစဉ် အမှန်ခြစ်ထားသော ခွင့်ပြုချက်များသည် ပရောဂျက်အမျိုးအစားအလိုက် တစ်နေရာတည်းတွင်သာ မှတ်တမ်းတင်ထားသည်။ Java, HTML, Situs Web, Kotlin, Compose နှင့် Python ပရောဂျက်များအတွက် အမှန်ခြစ်ထားသော ခွင့်ပြုချက်များသည် ပရောဂျက်ဖိုလ်ဒါအတွင်းရှိ java ဖိုလ်ဒါ၏ ဘေးတွင်၊ app/src/main/ အတွင်းရှိ AndroidManifest.xml တွင်သာ မှတ်တမ်းတင်ထားသည်။ Java, HTML, Situs Web, Kotlin, Compose နှင့် Python ပရောဂျက်များ၏ ပရောဂျက်ဒေတာဖိုင်တွင် ခွင့်ပြုချက်စာရင်း မပါဝင်ပါ။ Java ကို ရွေး၍ INTERNET နှင့် CAMERA ကို အမှန်ခြစ်ပါက AndroidManifest.xml တွင် အခြားခွင့်ပြုချက်များ ထပ်မပါဘဲ INTERNET နှင့် CAMERA သာ မှတ်တမ်းတင်ထားမည်။ တည်ဆောက်ချိန်တွင် အက်ပ်သည် ခွင့်ပြုချက်များကို ထိုနေရာမှပင် ဖတ်သည်: Java, HTML, Situs Web, Kotlin, Compose နှင့် Python ပရောဂျက်များအတွက် app/src/main/ ရှိ AndroidManifest.xml မှ (မရှိပါက ပရောဂျက်အဟောင်းများအတွက် app ဖိုလ်ဒါ၏ ဘေးရှိ AndroidManifest.xml မှ)၊ ပရောဂျက်အဟောင်းများအတွက် ပရောဂျက်ဒေတာဖိုင်မှ ဖြစ်သည်။

Kelola Project ကို ဖွင့်ပြီး editor ကို ဖွင့်ရန် ပရောဂျက်အမည်ကို တို့ပါ။ Editor တွင် ဖိုင်များကို ဖွင့်နိုင်သည်၊ ကုဒ်ရေးနိုင်သည်၊ ပြောင်းလဲမှုများကို သိမ်းဆည်းနိုင်သည်။ Java, HTML, Situs Web, Kotlin, Compose နှင့် Python ပရောဂျက်များအတွက် ဖိုင်များသည် app/src/main ဖိုလ်ဒါအတွင်းတွင် ရှိသည်။ ပရောဂျက်ကို မျှဝေရန် Ekspor ZIP ကို သုံးပါ (အောက်ပါအပိုင်းကို ကြည့်ပါ)။

ပရောဂျက် run နည်း
Editor တွင် ပရောဂျက်ကို စမ်းသပ်ရန် Jalankan ကို နှိပ်ပါ။ HTML နှင့် Situs Web ပရောဂျက်များအတွက် index.html ကို WebView မှတစ်ဆင့် run သည်။ အမှားတစ်ခု ဖြစ်ပေါ်ပါက အမှားမက်ဆေ့ချ်ကို ဖတ်ပါ၊ ကုဒ်ကို ပြင်ပါ၊ ထို့နောက် ပြန် run ပါ။

APK တည်ဆောက်နည်း
Editor တွင် Bangun ကို နှိပ်ပါ။ တည်ဆောက်နည်း နှစ်နည်း ရှိသည်။ ပထမနည်းမှာ စက်ပေါ်တွင် တည်ဆောက်ခြင်း: HTML, Situs Web, Java, Kotlin နှင့် Python ပရောဂျက်များအတွက် အင်တာနက်မလိုဘဲ ဖုန်းပေါ်တွင် တိုက်ရိုက် တည်ဆောက်သည်။ ဒုတိယနည်းမှာ GitHub Actions မှတစ်ဆင့် အွန်လိုင်း တည်ဆောက်ခြင်း: အင်တာနက်မှတစ်ဆင့် GitHub တွင် တည်ဆောက်ပြီး ပရောဂျက်အမျိုးအစားအားလုံးအတွက် သုံးနိုင်သည်။ Compose ပရောဂျက်များကို ဒုတိယနည်း (Bangun online) ဖြင့်သာ သို့မဟုတ် Gradle ဖြင့် Termux တွင်သာ တည်ဆောက်နိုင်သည်၊ အကြောင်းမှာ Compose သည် စက်ပေါ်တွင် မရရှိနိုင်သော Jetpack Compose library များ လိုအပ်သောကြောင့်ဖြစ်သည်။ ပထမတည်ဆောက်မှု ရလဒ်ကို လက်မှတ်မထိုးရသေးပါ။ ထို့နောက် အက်ပ်က ၎င်းကို လက်မှတ်ထိုးသည်: မူလကီးဖြင့် အလိုအလျောက် သို့မဟုတ် ပရောဂျက်ဖန်တီးစဉ် "Gunakan tanda tangan pribadi" ကို အမှန်ခြစ်ထားပါက ကိုယ်ပိုင်လက်မှတ်ဖြင့် ဖြစ်သည်။

APK ထည့်သွင်းနည်း
APK အဆင်သင့်ဖြစ်သောအခါ ၎င်းကို ထည့်သွင်းရန် Pasang ကို နှိပ်ပါ။ Android 8 နှင့်အထက်တွင် ဖုန်းသည် ဦးစွာ "Izinkan dari sumber ini" ကို တောင်းဆိုမည်၊ အကြောင်းမှာ ဤအက်ပ်သည် APK ကို Play Store အပြင်ဘက်မှ ထည့်သွင်းသောကြောင့်ဖြစ်သည်။ Pengaturan တွင် ထိုခွင့်ပြုချက်ကို တစ်ကြိမ် ဖွင့်ပါ၊ ထို့နောက် အက်ပ်သို့ ပြန်လာပါ: ထည့်သွင်းမှုသည် Pasang ကို ထပ်နှိပ်စရာမလိုဘဲ အလိုအလျောက် ဆက်လက်လုပ်ဆောင်မည်။ Pasang ခလုတ် မပေါ်ပါက တည်ဆောက်မှု ပြီးစီးပြီး APK ဖန်တီးပြီးကြောင်း သေချာပါစေ။

အက်ပ်ကို လက်မှတ်ထိုးနည်း
ထည့်သွင်းနိုင်ရန် APK တိုင်းကို လက်မှတ်ထိုးရမည်။ ရွေးချယ်စရာ နှစ်ခု ရှိသည်။ ပထမမှာ မူလကီး: အက်ပ်သည် ဘာမှ လုပ်စရာမလိုဘဲ အလိုအလျောက် လက်မှတ်ထိုးပေးသည်။ ဒုတိယမှာ ကိုယ်ပိုင်လက်မှတ်: ဦးစွာ ပင်မမီနူးရှိ Buat Keystore မီနူးမှတစ်ဆင့် keystore ဖန်တီးပါ၊ ၎င်း၏ စကားဝှက်ကို ကောင်းစွာ သိမ်းဆည်းပါ၊ ထို့နောက် ပရောဂျက်ဖန်တီးစဉ် "Gunakan tanda tangan pribadi" ကို အမှန်ခြစ်ပါ။ Keystore သည် Download/project/signing တွင် သိမ်းဆည်းထားသည်။

ပရောဂျက်ကို ZIP အဖြစ် ထုတ်ယူနည်း
Ekspor ZIP ကို ပရောဂျက်ကို သူငယ်ချင်းများနှင့် မျှဝေနိုင်ရန် ပံ့ပိုးထားသည်။ နည်းလမ်းမှာ: Kelola Project တွင် ပရောဂျက်အမည်ကို ကြာကြာ နှိပ်ထားပြီး Ekspor ZIP ကို ရွေးပါ။ ရလဒ်သည် Download/project/<NamaProyek>.zip အဖြစ် သိမ်းဆည်းသည်။ bin ဖိုလ်ဒါ မပါဝင်သောကြောင့် အရွယ်အစား သေးငယ်ပြီး KB ဆယ်ဂဏန်းမျှသာ ရှိသည်။ ထို ZIP ဖိုင်ကို သူငယ်ချင်းများထံ ပို့နိုင်သည် သို့မဟုတ် GitHub သို့ တင်နိုင်သည်။

Ekstensi JAWS
Ekstensi JAWS သည် Jieshuo (CSR) ၏ extension engine ကို သုံးပြီး ၎င်း၏ မျက်နှာပြင်ဖတ်စက်ကို မသုံးပါ။ ထို့ကြောင့် အသုံးပြုသူသည် TalkBack ကို သုံးနေသော်လည်း ဒီဇိုင်းသည် အလုပ်လုပ်နိုင်ဆဲဖြစ်သည်။ နည်းလမ်းမှာ: ပင်မမီနူးတွင် Ekstensi JAWS ကို ဖွင့်ပါ။ အလိုအလျောက် ကလစ်သည် သူ့အလိုလို အလုပ်လုပ်သောကြောင့် ဝန်ဆောင်မှုကို Pengaturan Aksesibilitas တွင် ဦးစွာ ဖွင့်ရမည်။ ထို့နောက် ဒီဇိုင်းအသစ် ဖန်တီးနိုင်သည်: ဒီဇိုင်းအမည်ကို ရိုက်ပါ၊ OK ကို နှိပ်ပါ၊ ထို့နောက် ၎င်း၏ အကွက်ကို ဖြည့်ပါ။

Daftar Klik ကို သပ်ရပ်စေရန် ခွဲထားသည်
ဒီဇိုင်းအတွင်းတွင် အကွက်နှစ်ခု ရှိသည်: script အကွက်နှင့် Daftar Klik အကွက်။ ခလုတ်စာရင်းကို daftar_klik.txt ဖိုင်တွင် သီးခြား သိမ်းဆည်းထားပြီး တစ်ကြောင်းလျှင် အမည်တစ်ခုစီ ဖြစ်သည်။ ၎င်း၏ ဥပမာ အကြောင်းအရာမှာ: tombolSimpan, tombolHapus, tombolBuka။ အက်ပ်တစ်ခုကို ဖွင့်ရန် ထိုစာရင်းတွင် >WhatsApp ဟု ရေးပါ။ daftar_klik.txt ဖိုင် မရှိသေးသော ဒီဇိုင်းအဟောင်းများသည် ထို မူလဥပမာကို ပြသမည်။

ပံ့ပိုးထားသော ရိုးရှင်းသော function များ
• klikTombol("tombolSimpan") — ၎င်း၏ စာသားအပေါ် အခြေခံ၍ ခလုတ်တစ်ခုကို ကလစ်လုပ်သည်။
• klikDaftarTombol(daftar) — daftar_klik.txt ရှိ စာရင်းကို ကလစ်လုပ်သည်၊ တစ်ကြောင်းလျှင် ခလုတ်တစ်ခုစီ အစဉ်လိုက်၊ ထို့နောက် မည်မျှ အောင်မြင်ကြောင်းနှင့် မည်မျှ မတွေ့ကြောင်း အသိပေးသည်။
• bukaAplikasi("WhatsApp") — အက်ပ်တစ်ခုကို ၎င်း၏ အမည်ဖြင့် ဖွင့်သည်၊ သို့မဟုတ် စာရင်းတွင် ">WhatsApp" ဟု ရေးသည်။
• klik(540, 1200) — မျက်နှာပြင် ကိုဩဒိနိတ်များတွင် ကလစ်လုပ်သည်။
Function အားလုံးကို ဦးစွာ ရိုးရှင်းအောင် ပြုလုပ်ထားသည်။ အသုံးပြုရတာ ကျွမ်းကျင်လာသောအခါ နောက်ထပ် function များကို နောင်တွင် ထပ်ထည့်နိုင်သည်။

မျက်နှာပြင်ဖတ်စက် အကြောင်း
ဤအက်ပ်ကို မျက်နှာပြင်ဖတ်စက်နှင့် အဆင်ပြေအောင် ဒီဇိုင်းဆွဲထားသည်။ ဖြည့်သွင်းမှု အကွက်တိုင်းတွင် အညွှန်းနှင့် ဖြည့်သွင်းပုံ ဥပမာ ရှိပြီး ခလုတ်အားလုံးကို ရှုပ်ထွေးသော အမူအရာများ မလိုဘဲ ရောက်ရှိနိုင်သည်။ Ekstensi JAWS ကို အသုံးပြုသူသည် TalkBack ကို သုံးနေသော်လည်း ဆက်လက် အလုပ်လုပ်နိုင်အောင် ပြုလုပ်ထားသည်၊ အကြောင်းမှာ သုံးထားသည်မှာ ၎င်း၏ extension engine ဖြစ်ပြီး မျက်နှာပြင်ဖတ်စက် မဟုတ်သောကြောင့်ဖြစ်သည်။

ကိုယ်ရေးကိုယ်တာနှင့် လုံခြုံရေး
ပရောဂျက်များနှင့် keystore သည် သင့်ဖုန်းတွင် သိမ်းဆည်းထားသည်။ GitHub token ကို အွန်လိုင်း တည်ဆောက်မှုအတွက်သာ သုံးပြီး ဤအက်ပ်အတွင်းတွင် သိမ်းဆည်းထားသည်။ သင့် token သို့မဟုတ် keystore စကားဝှက်ကို မည်သူနှင့်မျှ မမျှဝေပါနှင့်။ ကိုယ်ပိုင်လက်မှတ်ကို သုံးပါက keystore နှင့် ၎င်း၏ စကားဝှက်ကို လုံခြုံသောနေရာတွင် သိမ်းဆည်းပါ၊ အကြောင်းမှာ ပျောက်ဆုံးသွားပါက APK အဟောင်းကို တူညီသော လက်မှတ်ဖြင့် update လုပ်၍ မရနိုင်သောကြောင့်ဖြစ်သည်။

Android 5.0 သို့မဟုတ် ပိုသစ်။ သိုလှောင်မှု ခွင့်ပြုချက်: Android 11 နှင့်အထက်တွင် ဖိုင်အားလုံး ဝင်ရောက်ခွင့်ကို သုံးပြီး Android 10 နှင့်အောက်တွင် ပုံမှန် သိုလှောင်မှု ခွင့်ပြုချက် (သိုလှောင်မှု ဖတ်/ရေး) ကို သုံးသည်၊ အကြောင်းမှာ Android 10 တွင် ဖိုင်အားလုံး ဝင်ရောက်ခွင့် မရှိသောကြောင့်ဖြစ်သည်။ စက်ပေါ်တွင် တည်ဆောက်ရန် ARM processor (32 သို့မဟုတ် 64 bit) ပါသော ဖုန်း လိုအပ်သည်။ GitHub Actions မှတစ်ဆင့် အွန်လိုင်း တည်ဆောက်ရန် အင်တာနက်နှင့် GitHub token လိုအပ်သည်။ Kotlin ပရောဂျက်များကို စက်ပေါ်တွင် တည်ဆောက်နိုင်သော်လည်း Kotlin compiler အရွယ်အစား ကြီးမားသောကြောင့် ပထမတည်ဆောက်မှုသည် ပိုနှေးပြီး မှတ်ဉာဏ် ပိုသုံးသည်။ Compose ပရောဂျက်များကို GitHub Actions မှတစ်ဆင့် သို့မဟုတ် Gradle ဖြင့် Termux တွင် တည်ဆောက်သည်။ Python ပရောဂျက်များသည် Android 7.0 သို့မဟုတ် ပိုသစ် (အနည်းဆုံး SDK 24) လိုအပ်ပြီး ရလဒ် APK သည် Python runtime (Chaquopy) နှင့် ၎င်း၏ standard library ပါဝင်သောကြောင့် ပိုကြီးသည်။

Terminal
ပင်မမျက်နှာပြင်ရှိ Terminal မီနူးသည် ဤအက်ပ်အတွင်းတွင် terminal တစ်ခု ဖွင့်ပေးသည်။ ls ကဲ့သို့သော command များကို ပရောဂျက်ဖိုလ်ဒါ၏ အကြောင်းအရာကို ကြည့်ရန်၊ cd ကို ဖိုလ်ဒါများ ပြောင်းရန်၊ git ကို ကုဒ်ကို စီမံရန် သုံးနိုင်သည်။ Command အထွက်ကို မျက်နှာပြင်ဖတ်စက် ဖတ်နိုင်သော စာသားအဖြစ် ပြသပြီး နောက်ဆုံးရလဒ်ကို နားထောင်ရန် Bacakan hasil ခလုတ် ရှိသည်။ ဤ terminal သည် ဖုန်း၏ system shell ကို သုံးသောကြောင့် nano နှင့် vim ကဲ့သို့သော interactive program များကို ဤနေရာတွင် လောလောဆယ် သုံး၍ မရသေးပါ။

Lisensi (အခပေးဗားရှင်း)
အက်ပ်များကို ရောင်းချရန် ပရောဂျက်ဖန်တီးစဉ် "Aktifkan Lisensi" ကို အမှန်ခြစ်ပြီး သင့် WhatsApp နံပါတ်ကို ဖြည့်ပါ။ တည်ဆောက်ပြီးသော အက်ပ်သည် ပထမဆုံး ဖွင့်သောအခါ လိုင်စင်ကုဒ်ကို တောင်းဆိုမည်: အသုံးပြုသူသည် မိမိ၏ စက် ID ကို မြင်ရပြီး Kirim ID Perangkat ခလုတ်ကို နှိပ်၍ ထို ID ကို သင့် WhatsApp သို့ ပို့ကာ ထို့နောက် သင်က ၎င်း၏ လိုင်စင်ကုဒ်ကို ပြန်ပို့ပေးသည်။ လိုင်စင်ကုဒ်ကို စက် ID နှင့် ပရောဂျက် စကားဝှက် (ပရောဂျက်ဒေတာဖိုင်ရှိ lisensi_seed) တို့မှ တွက်ချက်သည် — ထို စကားဝှက်ကို ကောင်းစွာ သိမ်းဆည်းပြီး မမျှဝေပါနှင့်။ မှန်ကန်သော ကုဒ်ကို ထည့်ပြီးနောက် အက်ပ် ပွင့်လာပြီး ကုဒ်ကို ထပ်မတောင်းတော့ပါ။

Pembuat Ikon Otomatis
ပရောဂျက်အသစ်၏ icon သည် ဖောက်ထွင်းမြင်နိုင်ဆဲ (transparent) ဖြစ်သောကြောင့် ပင်မမီနူးတွင် Pembuat Ikon ရရှိနိုင်သည်။ နည်းလမ်းမှာ: Pembuat Ikon ကို နှိပ်ပါ၊ စာလုံး တစ်လုံး သို့မဟုတ် နှစ်လုံး ရေးပါ (ဥပမာ အက်ပ်အမည်၏ အတိုကောက်)၊ နောက်ခံအရောင်နှင့် စာသားအရောင်ကို ရွေးပါ၊ ၎င်း၏ preview ကို ကြည့်ပါ၊ ထို့နောက် ရွေးထားသော ပရောဂျက်တွင် icon ကို သုံးရန် Simpan ke Proyek ကို သို့မဟုတ် ၎င်း၏ PNG ဖိုင်ကို အခြားနေရာတွင် သုံးရန် Simpan ke Download ကို နှိပ်ပါ။ ပရောဂျက် ဖန်တီးပြီးနောက် အက်ပ်သည် icon ဖန်တီးရန်လည်း ကမ်းလှမ်းသည်။ ပရောဂျက်၏ icon အဟောင်းကို Kelola Project ရှိ ပရောဂျက်မီနူးမှ အချိန်မရွေး ပြောင်းနိုင်သည် (ပရောဂျက်အမည်ကို ကြာကြာ နှိပ်ထားပြီး Ganti Ikon ကို ရွေးပါ)။

Template Proyek Siap Pakai
ဗလာပရောဂျက်မှ မစတင်လိုပါက ပရောဂျက်ဖန်တီးစဉ် template ကို ရွေးပါ: Kalkulator (Java), Catatan (Java), Daftar Tugas (Kotlin), Kalkulator Web (HTML), Situs Profil (Situs Web), သို့မဟုတ် Penghitung (Compose)။ Template ကို ရွေးခြင်းသည် ပရောဂျက်အမျိုးအစားကို ထို template အလိုက် အလိုအလျောက် ပြောင်းပြီး ပရောဂျက်ကို အဆင်သင့် စတင်ကုဒ်ဖြင့် ဖန်တီးသည် — run ရန် သို့မဟုတ် ပြင်ဆင်ရန်သာ ကျန်သည်။ Template ရွေးပြီးနောက် ပရောဂျက်အမျိုးအစားကို လက်ဖြင့် ထပ်ပြောင်းပါက template ပယ်ဖျက်ပြီး ပရောဂျက်သည် ပြန်လည် ဗလာဖြစ်သွားမည်။ HTML နှင့် Situs Web template များအတွက် template သည် index.html ၏ အကြောင်းအရာကို အစားထိုးပြီး form တွင် ရိုက်ထားသော HTML script လည်း ပါဝင်သည်။

Cadangan dan Pulihkan Proyek
ပရောဂျက်များ မပျောက်ဆုံးစေရန် backup လုပ်ဆောင်ချက် ရရှိနိုင်သည်။ နည်းလမ်းမှာ: Kelola Project တွင် ပရောဂျက်အမည်ကို ကြာကြာ နှိပ်ထားပြီး Cadangkan ကို ရွေးပါ။ Backup ကို Download/backup ဖိုလ်ဒါတွင် ပရောဂျက်အမည်နှင့် ရက်စွဲပါသော ZIP အဖြစ် သိမ်းဆည်းပြီး ဥပမာ: GarudaDecode-2026-11-14-123045.zip။ ၎င်း၏ အကြောင်းအရာသည် Ekspor ZIP နှင့် အတူတူဖြစ်သည် (ပရောဂျက် အကြောင်းအရာ အားလုံး၊ bin ဖိုလ်ဒါ မပါဘဲ)။ ပြန်လည်ရယူရန်: Kelola Project တွင် မီနူးကို ဖွင့်ပါ၊ Pulihkan cadangan ကို ရွေးပါ၊ ထို့နောက် ၎င်း၏ backup ဖိုင်ကို ရွေးပါ။ ပရောဂျက်အမည် ရှိပြီးသားဖြစ်ပါက အက်ပ်က မေးမည်: ပရောဂျက်အဟောင်းကို အစားထိုးမလား၊ သို့မဟုတ် အမည်အသစ်ဖြင့် သိမ်းမလား။

Bagikan dan Impor Proyek
ပရောဂျက်ကို သူငယ်ချင်းနှင့် မျှဝေရန်: Kelola Project တွင် ပရောဂျက်အမည်ကို ကြာကြာ နှိပ်ထားပြီး Bagikan ကို ရွေးပါ။ ပရောဂျက်ကို မျှဝေရေး အက်ပ်များ (WhatsApp, Telegram နှင့် အခြားများ) မှတစ်ဆင့် ZIP အဖြစ် ပို့သည်။ သူငယ်ချင်းထံမှ ပရောဂျက်ကို လက်ခံရန်: Kelola Project တွင် မီနူးကို ဖွင့်ပါ၊ Impor proyek ကို ရွေးပါ၊ ထို့နောက် ၎င်း၏ ZIP ဖိုင်ကို ရွေးပါ။ ထို ZIP ဖိုင်တွင် ပရောဂျက်ဒေတာဖိုင် ပါဝင်ရမည် — မပါဝင်ပါက ဖိုင်ကို ရှင်းလင်းသော မက်ဆေ့ချ်ဖြင့် ငြင်းပယ်မည်၊ အကြောင်းမှာ ထိုဖိုင်သည် Create Aplikasi ပရောဂျက် မဟုတ်သောကြောင့်ဖြစ်သည်။ ပရောဂျက်အမည် ရှိပြီးသားဖြစ်ပါက အက်ပ်က မေးမည်: ပရောဂျက်အဟောင်းကို အစားထိုးမလား၊ သို့မဟုတ် အမည်အသစ်ဖြင့် သိမ်းမလား။

Pencarian dan Filter Proyek
ပရောဂျက်များ များလာပါက Kelola Project တွင် ရှာဖွေရေး အကွက်နှင့် အမျိုးအစား စစ်ထုတ်စနစ် ရှိသည်။ ရှာဖွေရေး အကွက်တွင် ပရောဂျက်အမည်ကို ရိုက်ပါ၊ စာရင်းသည် ချက်ချင်း စစ်ထုတ်သွားမည် (စာလုံးအကြီးအသေး မခွဲခြားပါ)။ အမျိုးအစား စစ်ထုတ်စနစ်သည် စာရင်းကို အမျိုးအစား တစ်ခုတည်းသာ ကန့်သတ်သည်: Semua, HTML, Situs Web, Java, Kotlin, Compose, သို့မဟုတ် Python။ ပရောဂျက်တိုင်း၏ မီနူးကို စစ်ထုတ်ထားသော စာရင်းမှလည်း ပုံမှန်အတိုင်း ဖွင့်နိုင်ဆဲဖြစ်သည်။

အသံဖြင့် အက်ပ် တည်ဆောက်ခြင်း
စာရိုက်ဖို့ မလိုချင်ရင် အသံကို အသုံးပြုပါ- ပင်မမီနူးတွင် အသံဖြင့် တည်ဆောက်ရန် ကို နှိပ်ပြီး အမိန့်တစ်ခု ပြောပါ။ ပြောနိုင်သော အမိန့်များမှာ "Buat proyek kalkulator", "Bangun proyek Kalkulator", "Buka proyek Kalkulator", "Jalankan proyek Kalkulator", "Daftar proyek", "Buka ikon", "Kembali" နှင့် "Bantuan" တို့ ဖြစ်သည်။ အက်ပ်က အသံနှင့် စာသားဖြင့် ပြန်ဖြေသောကြောင့် မျက်နှာပြင်ကို မကြည့်ဘဲ ဆက်သုံးနိုင်သည်။ အသံမှတ်သားခြင်းသည် ဖုန်းတွင် ထည့်သွင်းထားသော အသံမှတ်သားအက်ပ်ကို အသုံးပြုသည် (အခမဲ့၊ အင်ဒိုနီးရှား ဘာသာစကား ပက်ကေ့ဂျ် ထည့်သွင်းထားလျှင် အော့ဖ်လိုင်း အလုပ်လုပ်နိုင်သည်)။ ဖုန်းတွင် အသံမှတ်သားခြင်း မရှိလျှင် အမိန့်များကို တူညီသော မျက်နှာပြင်ရှိ စာသားအကွက်တွင် ရိုက်ထည့်နိုင်သည်။

သုံးစွဲနိုင်မှု စစ်ဆေးခြင်း
ပရောဂျက်တစ်ခုကို ထုတ်ပြန်ခြင်းမပြုမီ ၎င်း၏ အပြင်အဆင်သည် မျက်နှာပြင် ဖတ်သူများနှင့် (TalkBack/Jieshuo) အဆင်ပြေမှုရှိမရှိ စစ်ဆေးရန်- ပင်မမီနူးတွင် သုံးစွဲနိုင်မှု စစ်ဆေးခြင်း ကို ဖွင့်ပါ၊ ပရောဂျက်တစ်ခု ရွေးပါ၊ ထို့နောက် အပြင်အဆင်စာရင်းကို တင်ပါ ကို နှိပ်ပြီး အပြင်အဆင် ဖိုင်တစ်ခု ရွေးပါ။ IDE က ထို XML ဖိုင်ကို ဖတ်ပြီး အညွှန်းမပါသော ခလုတ်များကို ၎င်းတို့၏ လိုင်းနံပါတ်များနှင့်အတူ၊ ထပ်ခါတလဲလဲ အသုံးပြုသော အညွှန်းများနှင့် တစ်ဖက်နှင့်တစ်ဖက် ထပ်နေသော အစိတ်အပိုင်းများကို အစီရင်ခံပြီး Jieshuo အသံကျယ်ကျယ် ဖတ်သကဲ့သို့ အာရုံစူးစိုက်မှု အစီအစဉ်၏ မှတ်တမ်းကို တည်ဆောက်သည်။ ခလုတ်တစ်ခု အညွှန်း မရှိလျှင် ၎င်း၏ အညွှန်းကို ဖြည့်ပြီး အညွှန်းကို အလိုအလျောက် ထည့်ပါ ကို နှိပ်ပါ — အညွှန်းကို အပြင်အဆင် ဖိုင်တွင် contentDescription အဖြစ် ရေးသားသည်။ ဤစစ်ဆေးမှုသည် အပြင်အဆင် XML ကိုသာ ဖတ်သည်၊ Compose မြင်ကွင်းများနှင့် ပြီးစီးသော APK များကို မစကင်ဖတ်သေးပါ။

Crash ခွဲခြမ်းစိတ်ဖြာခြင်း
အက်ပ်တစ်ခု ဘာကြောင့် သူ့ဘာသာ ပိတ်သွားသည်ကို ထူးခြားသော ID ပါသော Crash မှတ်တမ်းမှ သိရန်- ပင်မမီနူးတွင် Crash ခွဲခြမ်းစိတ်ဖြာခြင်း ကို ဖွင့်ပါ၊ မှတ်တမ်းစာရင်းမှ Crash ID တစ်ခုကို ရွေးပါ၊ ထို့နောက် စစ်ဆေးရန် ကို နှိပ်ပါ။ IDE က မှတ်တမ်းထဲရှိ အတန်းနှင့် လိုင်းနံပါတ်ကို ပရောဂျက်၏ ရင်းမြစ်နှင့် ကိုက်ညီစေပြီး အကြောင်းရင်းကို အင်ဒိုနီးရှား ဘာသာစကားဖြင့် ရှင်းပြသည် (ဥပမာ ဗလာကိုးကားချက်၊ မတောင်းရသေးသော ခွင့်ပြုချက်၊ သို့မဟုတ် JSON အမှား)၊ အကြံပြုထားသော ကုဒ် ပြင်ဆင်ချက်နှင့်အတူ။ ပြင်ဆင်ချက်ကို အသုံးပြုပါ ကို ရင်းမြစ် လိုင်းသည် Crash ဖြစ်ပွားချိန်ကကဲ့သို့ အတိအကျ တူညီနေမှသာ နှိပ်ပါ၊ ပြောင်းလဲသွားလျှင် ပြင်ဆင်ချက်ကို ပယ်ချပြီး IDE က သင်ကိုယ်တိုင် စစ်ဆေးရန် တောင်းဆိုသည်။ ဖတ်နေသည်မှာ IDE ၏ ကိုယ်ပိုင် Crash မှတ်တမ်းဖြစ်သည်၊ တည်ဆောက်ပြီးသား အက်ပ်၏ မှတ်တမ်း မဟုတ်ပါ။

ဘာသာစကားမျိုးစုံ ပြောင်းလဲပေးသည့် Transpiler
ရိုးရှင်းသော Java ကုဒ်ကို Kotlin သို့ သို့မဟုတ် ရိုးရှင်းသော XML အပြင်အဆင်ကို Compose ကုဒ်သို့ ပြောင်းရန်- ပင်မမီနူးတွင် ဘာသာစကားမျိုးစုံ ပြောင်းလဲပေးသည့် Transpiler ကို ဖွင့်ပါ၊ ပရောဂျက်နှင့် ဖိုင်တစ်ခု ရွေးပါ၊ ထို့နောက် အစမ်းကြည့်ပါ ကို နှိပ်ပါ။ IDE က ပြောင်းလဲမှု ရလဒ်ကို စာသားအဖြစ် ပြသသည် — အရင် စစ်ဆေးပါ၊ အဘယ်ကြောင့်ဆိုသော် ၎င်းမသိသော လိုင်းများကို အတိုင်းပင် ထားရှိပြီး Java ရှိ static စကားလုံးကို Kotlin တွင် ချန်လှပ်ထားသောကြောင့် ဖြစ်သည် (အသုံးမပြုမီ ၎င်း၏ အဓိပ္ပာယ်ကို စစ်ဆေးပါ)။ XML မှ Compose သို့ ပြောင်းလဲခြင်းသည် စာသား၊ အကြံပြုချက်များနှင့် ဦးတည်ရာကိုသာ ပြောင်းလဲသည် — အရွယ်အစား၊ အရောင်နှင့် အခြား အရည်အချင်းများ မပါဝင်သေးပါ။ ရလဒ် မှန်ကန်လျှင် ပစ်မှတ် ဖိုင်ကို ရေးသားရန် ဖိုင်သို့ အသုံးပြုပါ ကို နှိပ်ပါ၊ ရင်းမြစ် ဖိုင်ကို မပြောင်းလဲပါ။ လုံခြုံသော၊ သာမန် ပုံစံများကိုသာ ပြောင်းလဲသည်။

ဒေသတွင်း မိုက်ခရို ဆာဗာ
အင်တာနက်မရှိဘဲ ဆာဗာ လိုအပ်သော အက်ပ်တစ်ခုကို စမ်းသပ်ရန်- ပင်မမီနူးတွင် ဒေသတွင်း မိုက်ခရို ဆာဗာ ကို ဖွင့်ပါ၊ လမ်းကြောင်း အဓိပ္ပာယ်ဖွင့်ဆိုချက် ရေးပါ (ဥပမာ GET /halo နှင့် ၎င်း၏ JSON အဖြေ)၊ ထို့နောက် ဆာဗာကို စတင်ပါ ကို နှိပ်ပါ။ IDE က တူညီသော ဖုန်းပေါ်တွင် သေးငယ်သော HTTP ဆာဗာကို အလုပ်လုပ်စေသည် (HTTP သာ၊ TLS မပါ၊ တူညီသော Wi-Fi ကွန်ရက်အတွက်) နှင့် တောင်းဆိုမှုနှင့် အဖြေတိုင်းကို မျက်နှာပြင်ပေါ်တွင် မှတ်တမ်းတင်သည်။ လမ်းကြောင်းများသည် {nama} ကဲ့သို့သော ကန့်သတ်ချက်များနှင့် ရိုးရှင်းသော API သော့ကို အသုံးပြုနိုင်သည်။ ဤဆာဗာသည် ဖုန်းပေါ်တွင် စမ်းသပ်ရန်အတွက်သာ ဖြစ်သည်၊ တည်ဆောက်ပြီးသား APK သည် ဆာဗာဖြစ်နိုင်ခြင်း မရှိသေးပါ၊ ၎င်း၏ မျက်နှာပြင် ပိတ်လိုက်သောအခါ ဆာဗာ ရပ်တန့်သည်။

လုံခြုံရေး စစ်ဆေးသူ
ပရောဂျက်တစ်ခုကို ထုတ်ပြန်ခြင်းမပြုမီ ပရောဂျက် ကုဒ်ရှိ လုံခြုံရေး ကွက်လပ်များကို စစ်ဆေးရန်- ပင်မမီနူးတွင် လုံခြုံရေး စစ်ဆေးသူ ကို ဖွင့်ပါ၊ ပရောဂျက်တစ်ခု ရွေးပါ၊ ထို့နောက် စကင်ဖတ်ခြင်းကို စတင်ပါ ကို နှိပ်ပါ။ IDE က ကုဒ်၊ manifest နှင့် ပရောဂျက် ဖွဲ့စည်းပုံကို စကင်ဖတ်ပြီး တွေ့ရှိချက်များကို အမြင့်ဆုံး အန္တရာယ်မှ အနိမ့်ဆုံး အန္တရာယ်အထိ အစီရင်ခံသည် — ကုဒ်တွင် ဖော်ပြထားသော API သော့များ၊ ခွင့်ပြုချက်မရှိဘဲ ဖော်ပြထားသော အစိတ်အပိုင်းများ၊ JavaScript အင်တာဖေ့စ်နှင့်အတူ JavaScript ကို ဖွင့်ထားသော WebView၊ အားနည်းသော ကုဒ်ဝှက်စနစ် (MD5၊ SHA1၊ DES)၊ TLS မပါသော http လိပ်စာများနှင့် ကုဒ်တွင် တိုက်ရိုက် ရေးသားထားသော စကားဝှက်များ — တွေ့ရှိချက်တစ်ခုစီ၏ ဖိုင်နှင့် လိုင်းနံပါတ်နှင့်အတူ။ လုံခြုံသော ပြင်ဆင်ချက်ရှိသည့် တွေ့ရှိချက်များအတွက် (ဥပမာ MD5 ကို SHA-256 ဖြင့် သို့မဟုတ် http ကို https ဖြင့် အစားထိုးခြင်း) ပြင်ဆင်ချက်ကို အသုံးပြုပါ ကို နှိပ်ပါ၊ API သော့များနှင့် စကားဝှက်များအတွက် IDE က အကြံပြုထားသော ပြင်ဆင်ချက်ကိုသာ ပြသသည်၊ အဘယ်ကြောင့်ဆိုသော် အစားထိုးမှုကို ဖန်တီးသူကိုယ်တိုင် ဆုံးဖြတ်ရသောကြောင့် ဖြစ်သည်။ ဤစကင်ဖတ်ခြင်းသည် ကုဒ်ရှိ စာသား ပုံစံများကို ဖတ်သည်၊ bytecode မဟုတ်ပါ၊ ထို့ကြောင့် အချို့သော တွေ့ရှိချက်များသည် အမှန်တကယ် လုံခြုံနိုင်ပြီး ပုံစံမရှိသော ကွက်လပ်တစ်ခုသည် စကင်ဖတ်ခြင်းမှ လွတ်သွားနိုင်သည် — အသုံးမပြုမီ စစ်ဆေးပါ။

မျက်နှာပြင် စမ်းသပ်စက်ရုပ်
အက်ပ်တစ်ခု၏ အသွင်အပြင်ကို စာသား ဇာတ်လမ်းပုံစံများဖြင့် အလိုအလျောက် စမ်းသပ်ရန်- ပင်မမီနူးတွင် မျက်နှာပြင် စမ်းသပ်စက်ရုပ် ကို ဖွင့်ပါ၊ ပရောဂျက်တစ်ခု ရွေးပါ၊ ထို့နောက် ဇာတ်လမ်းပုံစံကို အလိုအလျောက် ဖန်တီးပါ ကို နှိပ်ပါ။ IDE က ပရောဂျက်၏ manifest နှင့် အပြင်အဆင်များကို ဖတ်ပြီး စာသား အဆင့်များဖြင့် ဇာတ်လမ်းပုံစံတစ်ခု ရေးသားသည် (ခလုတ်တစ်ခု နှိပ်ပါ၊ အကွက်တစ်ခု ဖြည့်ပါ၊ စောင့်ပါ၊ ပြန်သွားပါ)။ ဇာတ်လမ်းပုံစံ၏ လုပ်ဆောင်မှု မှတ်တမ်းကို ၎င်း၏ အချိန်တံဆိပ်များနှင့်အတူ ကြည့်ရန် Dry Run ကို လုပ်ဆောင်ပါ ကို နှိပ်ပါ။ ဤအဆင့်တွင် စက်ရုပ်သည် ပုံတူကူးယူခြင်း (dry run) ကိုသာ လုပ်ဆောင်သည် — ဖုန်းပေါ်တွင် ခလုတ်များကို အမှန်တကယ် နှိပ်ခြင်းနှင့် အမှန်တကယ် Crash များကို ဖမ်းယူခြင်းသည် နောက်အဆင့်ဖြစ်သည်၊ ထို့ကြောင့် ဤနေရာရှိ Crash အစီရင်ခံစာသည် နမူနာ ဖော်မတ်သာ ဖြစ်သည်။

ကုဒ် အချိန်ခရီးသွားခြင်း
Git အမိန့်များကို ရိုက်ထည့်ခြင်းမရှိဘဲ ပရောဂျက်တစ်ခုကို ယခင် ကုဒ် အခြေအနေသို့ ပြန်ရောက်စေရန်- ပင်မမီနူးတွင် ကုဒ် အချိန်ခရီးသွားခြင်း ကို ဖွင့်ပါ၊ ပရောဂျက်တစ်ခု ရွေးပါ၊ အချိန်မှတ်အတွက် အညွှန်းတစ်ခု ဖြည့်ပါ (ဗလာထားနိုင်သည်)၊ ထို့နောက် ယခုအချိန်မှတ်ကို မှတ်တမ်းတင်ပါ ကို နှိပ်ပါ။ IDE က ပရောဂျက်၏ ရင်းမြစ် ဖိုင်များ၏ မိတ္တူကို ၎င်းတို့၏ hash တန်ဖိုးများနှင့်အတူ ပရောဂျက်အတွင်းရှိ .riwayat ဖိုဒါတွင် သိမ်းဆည်းသည်။ အချိန်မှတ်များ စာရင်းက ၎င်းတို့အားလုံးကို ပြသသည်၊ အမှတ်နှစ်ခု ရွေးပါ၊ ထို့နောက် ထည့်သွင်းထားသော၊ ပြောင်းလဲထားသော သို့မဟုတ် ဖျက်လိုက်သော ဖိုင်များနှင့် လုပ်ဆောင်ချက်များကို ကြည့်ရန် နှိုင်းယှဉ်ပါ ကို နှိပ်ပါ။ အဟောင်း အခြေအနေကို ပြန်ယူရန် ပြန်လည်ရယူပါ ကို နှိပ်ပါ — ပြန်လည်ရယူခြင်းမပြုမီ IDE က လက်ရှိ အခြေအနေ၏ အရန်မိတ္တူကို အမြဲဦးစွာ ပြုလုပ်သည်၊ ထို့ကြောင့် မည်သည့်အရာမျှ မပျောက်ပါ။ ပရောဂျက်ကို ဖိုဒါအသစ်တစ်ခုသို့ ကူးယူပြီး မူရင်း ပရောဂျက်ကို မနှောင့်ယှက်ဘဲ ပြောင်းလဲမှုများကို စမ်းသပ်ရန် စမ်းသပ်မှု မိတ္တူ ဖန်တီးပါ ကို နှိပ်ပါ။ ရင်းမြစ် ဖိုင်များကိုသာ မှတ်တမ်းတင်သည်။

မော်ဂျူး စက်ရုံ
ပရောဂျက်တစ်ခု၏ အစိတ်အပိုင်းတစ်ခုကို အခြား ပရောဂျက်တစ်ခု အသုံးပြုနိုင်သော မော်ဂျူးအဖြစ် ထုပ်ပိုးရန်- ပင်မမီနူးတွင် မော်ဂျူး စက်ရုံ ကို ဖွင့်ပါ၊ ရင်းမြစ် ပရောဂျက်တစ်ခု ရွေးပါ၊ ထုပ်ပိုးမည့် မျက်နှာပြင်၊ အတန်း၊ စာကြောင်းနှင့် ခွင့်ပြုချက် ဖိုင်များကို အမှတ်အသားပြုပါ၊ ထို့နောက် မော်ဂျူးအဖြစ် ထုပ်ပိုးပါ ကို နှိပ်ပါ။ IDE က JSON မက်တာဒေတာနှင့်အတူ ZIP မှတ်တမ်း ရေးသားသည် (မော်ဂျူး အမည်၊ ဗားရှင်း၊ အသုံးပြုထားသော စာကြောင်းများနှင့် ခွင့်ပြုချက်များ)။ မော်ဂျူးတစ်ခုကို အခြား ပရောဂျက်တစ်ခုတွင် တပ်ဆင်ရန် မော်ဂျူး စက်ရုံ ကို ဖွင့်ပါ၊ ပစ်မှတ် ပရောဂျက်ကို ရွေးပါ၊ ထို့နောက် မော်ဂျူး တပ်ဆင်ပါ ကို နှိပ်ပြီး မော်ဂျူး၏ .zip ဖိုင်ကို ရွေးပါ — ပေါင်းစည်းခြင်းသည် ရှိပြီးသား ကုဒ်ကို ထပ်မရေးဘဲ စာကြောင်းများနှင့် ခွင့်ပြုချက်များကို ပေါင်းထည့်ပြီး ၎င်း၏ အမည်ကို ပစ်မှတ် ပရောဂျက်တွင် အသုံးပြုပြီးဖြစ်လျှင် ဖိုင်ကို မပေါင်းစည်းပါ။ မော်ဂျူးတစ်ခုသည် စာကြည့်တိုက်များကိုဖြစ်စေ တည်ဆောက်မှု ဆက်တင်များကိုဖြစ်စေ သယ်ဆောင်မသွားပါ။

ပုံစံပြောင်းဒိုင်းနှင့် အက်ဆက်ခန်း
ထုတ်ဝေခြင်းမပြုမီ ဖော်ထုတ်သူအမည်များကို ကျပန်းပြောင်းရန်နှင့် ပရောဂျက်အက်ဆက်များကို စာဝှက်ရန်အတွက်- အဓိကမီနူးတွင် ပုံစံပြောင်းဒိုင်းနှင့် အက်ဆက်ခန်း ကိုဖွင့်ပါ၊ ပရောဂျက်ကို ရွေးချယ်ပါ၊ ထို့နောက် အမည်များကို ကျပန်းပြောင်းပြီး အက်ဆက်များကို စာဝှက်ပါ ကိုနှိပ်ပါ။ IDE သည် ရင်းမြစ်ကုဒ်ရှိ အတန်းနှင့် နည်းလမ်းအမည်များကို စကင်န်ဖတ်ပြီး၊ ကျပန်းအမည်မြေပုံကို တည်ဆောက်ကာ၊ ပရောဂျက်အက်ဆက်ဖိုင်များကို AES-GCM ဖြင့် ပရောဂျက်အတွင်းရှိ brankas-aset ဖိုင်တွဲသို့ စာဝှက်ပြီး၊ စာဝှက်ထားသော ပြန်လည်ရယူရေးမြေပုံ (perisai-peta.brankas) ကို သိမ်းဆည်းပေးသည်၊ ထို့ကြောင့် ပျက်ကျမှုမှတ်တမ်းများကို ဖတ်သောအခါ မူရင်းအမည်များကို ပြန်လည်ရယူနိုင်သည်။ စာဝှက်သော့သည် ပရောဂျက်အမည်မှ ဆင်းသက်လာသည်၊ ထို့ကြောင့် ပရောဂျက်အမည်ကို သိသူမည်သူမဆို ခန်းကို ဖွင့်နိုင်သည် — ၎င်းသည် စပ်စုစွာဖတ်ခြင်းမှ ကာကွယ်ခြင်းဖြစ်ပြီး၊ စကားဝှက်ဖြင့် သော့ခတ်ထားသော ခန်းမဟုတ်ပါ။ ဤနေရာတွင် ဖန်တီးသည်မှာ အမည်မြေပုံနှင့် အက်ဆက်ခန်းဖြစ်သည်။ စုစည်းထားသော DEX ဖိုင်အတွင်း အမည်များကို ပြန်လည်ရေးခြင်းသည် နောက်အဆင့်ဖြစ်ပြီး၊ ထို့ကြောင့် ပြီးစီးသော APK အတွင်းရှိ အမည်များကို ကျပန်းမပြောင်းရသေးပါ။

ယုံကြည်မှု ကွင်းဆက်နှင့် ပတ်ဝန်းကျင် စောင့်ကြည့်သူ
ထုတ်ဝေခြင်းမပြုမီ လက်မှတ်ထိုးသော့ချိတ်နှင့် ဖုန်းပတ်ဝန်းကျင်ကို စစ်ဆေးရန်အတွက်- အဓိကမီနူးတွင် ယုံကြည်မှု ကွင်းဆက်နှင့် ပတ်ဝန်းကျင် စောင့်ကြည့်သူ ကိုဖွင့်ပါ၊ ပရောဂျက်ကို ရွေးချယ်ပါ၊ ထို့နောက် ကွင်းဆက်နှင့် ပတ်ဝန်းကျင်ကို စစ်ဆေးပါ ကိုနှိပ်ပါ။ IDE သည် ပရောဂျက်ပက်ကေ့ဂျ်အမည်မှ မျိုးဆက် ၅ ခုပါ သော့ချိတ်ကို တည်ဆောက်ပြီး ၎င်း၏ ခိုင်မာမှုကို စစ်ဆေးကာ၊ ထို့နောက် မိမိ၏လုပ်ငန်းစဉ်၏ မှတ်ဉာဏ်မြေပုံနှင့် စက်ပစ္စည်းဂုဏ်သတ္တိများကို Frida၊ Xposed သို့မဟုတ် အတုစက်၏ ခြေရာများအတွက် စကင်န်ဖတ်သည်။ ရလဒ်မှာ လုံခြုံသည်၊ သတိထားပါ သို့မဟုတ် အန္တရာယ်ရှိသည် ဟူသော အန္တရာယ်အဆင့်ဖြစ်ပြီး၊ စာသားသက်သေများနှင့်အတူ ဖြစ်သည်။ ဤစစ်ဆေးမှုသည် မှတ်ဉာဏ်မြေပုံနှင့် စနစ်ဂုဏ်သတ္တိများရှိ စာသားပုံစံများကို ဖတ်သည်၊ မူလစာကြည့်တိုက် အဆင့်ရှိ မှတ်ဉာဏ်အကြမ်း၏ ခိုင်မာမှုကို မဟုတ်ပါ၊ နှင့် သော့များကို ဟာ့ဒ်ဝဲလုံခြုံရေးချစ်ပ်နှင့် မချည်နှောင်ပါ — စာသားခြေရာများကို ဖုံးကွယ်ထားသော ထိုးသွင်းကိရိယာသည် ဤစကင်န်မှ လွတ်မြောက်နိုင်သည်။

စာသားသစ်ပင် အပြင်အဆင် ဗိသုကာပညာရှင်
မျက်နှာပြင်ကို မကြည့်ဘဲ မျက်နှာပြင်ကို ဒီဇိုင်းဆွဲရန်အတွက်- အဓိကမီနူးတွင် စာသားသစ်ပင် အပြင်အဆင် ဗိသုကာပညာရှင် ကိုဖွင့်ပါ၊ ပရောဂျက်နှင့် အပြင်အဆင်ဖိုင်ကို ရွေးချယ်ပါ၊ ထို့နောက် အပြင်အဆင်ကို စစ်ဆေးပါ ကိုနှိပ်ပါ။ IDE သည် XML အပြင်အဆင်ကို စာသားသစ်ပင်အဖြစ် ဖတ်ပြီး ဒြပ်စင်တစ်ခုချင်းစီ၏ တည်နေရာဇာတ်ကြောင်းကို အသံကျယ်စွာ ဖတ်သည် (ဥပမာ အောက်ညာဘက်၊ မျက်နှာပြင်အကျယ်၏ ၄၅ ရာခိုင်နှုန်း)၊ ထို့နောက် ၃၆၀ dp အကျယ်တွင် ဒြပ်စင်များအကြား တိုက်မိမှုများနှင့် မျက်နှာပြင်အပြင်သို့ ထွက်သွားသော ဒြပ်စင်များကို သင်္ချာနည်းဖြင့် အစီရင်ခံသည်။ တွက်ချက်သည်မှာ LinearLayout နှင့် ရိုးရှင်းသော dp အတိုင်းအတာများဖြစ်သည်။ ConstraintLayout နှင့် Compose မျက်နှာပြင်များ၏ တည်နေရာသည် မသေချာဟု အစီရင်ခံသည်၊ ခန့်မှန်းခြင်းမဟုတ်ပါ။

ဒီဇိုင်းစနစ် စတူဒီယို
မျက်နှာပြင်များနှင့် ပရောဂျက်အားလုံးတွင် အကွာအဝေး၊ စာလုံးနှင့် ထောင့်များကို တူညီစေရန်အတွက်- အဓိကမီနူးတွင် ဒီဇိုင်းစနစ် စတူဒီယို ကိုဖွင့်ပါ၊ ပရောဂျက်ကို ရွေးချယ်ပါ၊ ဒီဇိုင်းတိုကင်များကို ရေးပါ (ဥပမာ jarak=8, huruf=16, sudut=12)၊ အစိတ်အပိုင်းကို ရွေးချယ်ပါ၊ ထို့နောက် အစိတ်အပိုင်းများ ဖန်တီးပါ ကိုနှိပ်ပါ။ IDE သည် တိုကင်များကို အတည်ပြုသည် — အခြေခံအကွာအဝေး ၄ မှ ၁၆ dp၊ အခြေခံစာလုံး ၁၂ မှ ၂၀ sp၊ ထောင့် ၀ မှ ၃၂ dp နှင့် အနည်းဆုံး ထိတွေ့ဧရိယာ ၄၈ dp — ထို့နောက် အသုံးပြုရန် အသင့်ဖြစ်သော XML အစိတ်အပိုင်းများ (komponen-studio.xml) ကို XML အပြင်အဆင် (tema-studio.xml) နှင့် Compose အပြင်အဆင် (tema-studio.kt) တို့နှင့်အတူ ပရောဂျက်ဖိုင်တွဲတွင် ရေးသားသည်။ အစိတ်အပိုင်းများကို အပြင်အဆင်တွင် ကပ်သော စာသားအဖြစ် ဖန်တီးပြီး ထို့နောက် အပြင်အဆင် ဗိသုကာပညာရှင်ဖြင့် စစ်ဆေးသည်။ တက်ဘလက်များတွင် ကော်လံနှစ်ခုချိန်ညှိမှုသည် မျက်နှာပြင်အကျယ် အရည်အချင်းများကို အသုံးပြုသည်၊ လုပ်ဆောင်နေစဉ် စက်ပစ္စည်းကို သိရှိခြင်းမဟုတ်ပါ။

အဓိပ္ပာယ်ဆိုင်ရာ ပြန်လည်ဖွဲ့စည်းခြင်းနှင့် AST လမ်းညွှန်မှု
အဓိပ္ပာယ်ဖွင့်ဆိုချက်များကို ရှာဖွေရန်နှင့် သင်္ကေတအမည်များကို ပြောင်းလဲရန်အတွက်၊ တိုက်ဆိုင်စွာ အမည်တူသော အခြားကုဒ်ကို မပျက်စီးစေဘဲ- အဓိကမီနူးတွင် အဓိပ္ပာယ်ဆိုင်ရာ ပြန်လည်ဖွဲ့စည်းခြင်းနှင့် AST လမ်းညွှန်မှု ကိုဖွင့်ပါ၊ ပရောဂျက်ကို ရွေးချယ်ပါ၊ ထို့နောက် အတန်းများနှင့် နည်းလမ်းအားလုံးကို ၎င်းတို့၏ဖိုင်များနှင့် လိုင်းနံပါတ်များနှင့်အတူ မြင်ရန် ပရောဂျက် သင်္ကေတများကို စကင်န်ဖတ်ပါ ကိုနှိပ်ပါ။ သင်္ကေတအမည်ကို ထည့်ပါ၊ ထို့နောက် ၎င်း၏အဓိပ္ပာယ်ဖွင့်ဆိုချက်နှင့် ၎င်းကို ခေါ်ဆိုသော ဖိုင်အားလုံးကို မြင်ရန် ပရောဂျက် သင်္ကေတများကို စကင်န်ဖတ်ပါ ကိုထပ်နှိပ်ပါ။ အမည်ပြောင်းရန် အမည်အသစ်ကို ထည့်ပါ၊ ဖိုင်တစ်ခုချင်းစီတွင် ပေါ်ပေါက်မှုအရေအတွက်ကို မြင်ရန် အမည်ပြောင်းခြင်း အစမ်းကြည့်ခြင်း ကိုနှိပ်ပါ၊ ထို့နောက် အမည်ပြောင်းခြင်းကို အသုံးပြုပါ ကိုနှိပ်ပါ။ ဤအညွှန်းသည် စာသားပုံစံများကို အသုံးပြုသည်၊ AST အကွဲအပြအပြည့်အစုံမဟုတ်ပါ။ အတန်းအမည်ပြောင်းခြင်းသည် ဖိုင်အားလုံးတွင် အကျုံးဝင်ပြီး၊ နည်းလမ်းအမည်ပြောင်းခြင်းသည် ၎င်း၏ပိုင်ရှင်ဖိုင်အတွက်သာ အကျုံးဝင်သည် — အခြားဖိုင်များရှိ ခေါ်ဆိုသူများ မပြောင်းလဲပါ၊ ထို့ကြောင့် အသုံးမပြုမီ အစမ်းကြည့်ခြင်းနှင့် ခေါ်ဆိုသူ စကင်န်ရလဒ်များကို စစ်ဆေးပါ။ ကုဒ်အပိုင်းကို လုပ်ဆောင်ချက်အသစ်အဖြစ် ထုတ်ယူခြင်းသည် ယုတ္တိအင်ဂျင်တွင် ရှိနေပြီဖြစ်သည်၊ သို့သော် ဤမျက်နှာပြင်တွင် ၎င်းအတွက် ခလုတ်မရှိသေးပါ။

အဆင့်ဆင့် အမှားရှာသူနှင့် မှတ်ဉာဏ်စစ်ဆေးသူ
မှတ်တမ်းများမှတစ်ဆင့် ခန့်မှန်းခြင်းမပြုဘဲ ပရိုဂရမ်၏စီးဆင်းမှုအလယ်တွင် ကိန်းရှင်များ၏ အကြောင်းအရာကို စစ်ဆေးရန်အတွက်- အဓိကမီနူးတွင် အဆင့်ဆင့် အမှားရှာသူနှင့် မှတ်ဉာဏ်စစ်ဆေးသူ ကိုဖွင့်ပါ၊ ပရောဂျက်ကို ရွေးချယ်ပါ၊ လုပ်ဆောင်မှု ခြေရာကို ရေးပါ (တစ်ကြောင်းလျှင် တစ်ဆင့်၊ ပုံစံမှာ လိုင်းနံပါတ်၊ ကုဒ်၊ ထို့နောက် ကိန်းရှင်များနှင့် တန်ဖိုးများကို | ဖြင့် ခွဲခြားထားသည်၊ ဥပမာ 10|int total = harga * jumlah;|harga=5000, jumlah=3, total=15000)၊ ရပ်တန့်သည့်အမှတ်၏ လိုင်းနံပါတ်ကို ထည့်ပါ၊ ထို့နောက် အမှားရှာ ခြေရာကို လုပ်ဆောင်ပါ ကိုနှိပ်ပါ။ IDE သည် ပထမရပ်တန့်သည့်အမှတ်အထိ လုပ်ဆောင်ပြီး Jieshuo မှတစ်ဆင့် လက်ရှိလိုင်းကို ၎င်း၏ကိန်းရှင်တန်ဖိုးများနှင့်အတူ အသံကျယ်စွာ ဖတ်သည်။ တစ်ကြောင်းရှေ့သို့ ရွှေ့ရန် တစ်ကြောင်းအဆင့် ကိုနှိပ်ပါ၊ သို့မဟုတ် နောက်ရပ်တန့်သည့်အမှတ်အထိ လုပ်ဆောင်ရန် ပရိုဂရမ်ကို ဆက်လုပ်ပါ ကိုနှိပ်ပါ။ ၎င်းသည် ခြေရာအမှားရှာသူဖြစ်သည်။ မှတ်တမ်းတင်ထားသော သို့မဟုတ် လက်ရေးဖြင့် ရေးထားသော လုပ်ဆောင်မှု ခြေရာကို လိုက်နာပြီး၊ လုပ်ဆောင်နေသော Android အက်ပ်ကို ရပ်တန့်ခြင်းမပြုပါ — အစစ်အမှန် လုပ်ငန်းစဉ်ကို ရပ်တန့်ရန် အမှားရှာတံတား လိုအပ်ပြီး၊ ၎င်းသည် ဤအဆင့်တွင် မရှိသေးပါ။

အင်တာနက်မဲ့ မှီခိုမှု မန်နေဂျာ
အင်တာနက်မရှိဘဲ ပြင်ပစာကြည့်တိုက်များကို အသုံးပြုရန်နှင့် တည်ဆောက်ခြင်းမပြုမီ ဗားရှင်းပဋိပက္ခများကို ရှောင်ရှားရန်အတွက်- အဓိကမီနူးတွင် အင်တာနက်မဲ့ မှီခိုမှု မန်နေဂျာ ကိုဖွင့်ပါ၊ ပရောဂျက်ကို ရွေးချယ်ပါ၊ ထို့နောက် မှီခိုမှုများကို စစ်ဆေးပါ ကိုနှိပ်ပါ။ IDE သည် ပရောဂျက်၏ .gradle ဖိုင်အားလုံးကို ဖတ်ပြီး၊ အင်တာနက်မဲ့ ခန်း (ပရောဂျက်အတွင်းရှိ brankas-maven.txt) ကို စစ်ဆေးကာ၊ ပဋိပက္ခများကို ဖြေရှင်းပေးသည် — စာကြည့်တိုက်နှစ်ခုက အက်ဆက်တစ်ခုတည်း၏ ဗားရှင်းအမျိုးမျိုးကို တောင်းဆိုပါက၊ အမြင့်ဆုံးဗားရှင်းကို အသုံးပြုပြီး ပဋိပက္ခကို အစီရင်ခံသည်။ စာကြည့်တိုက်ကို ခန်းတွင် မှတ်ပုံတင်ရန် ၎င်း၏ကိုဩဒိနိတ်များကို ထည့်ပါ (ပုံစံ အုပ်စု:အက်ဆက်:ဗားရှင်း၊ ဥပမာ com.google.code.gson:gson:2.10.1) ထို့နောက် မှီခိုမှုများကို စစ်ဆေးပါ ကိုနှိပ်ပါ။ Maven၊ Google သို့မဟုတ် PyPI မှ ဒေါင်းလုဒ်လုပ်ရန် အင်တာနက်လိုအပ်သည်။ အင်တာနက်မဲ့အချိန်တွင် ခန်းတွင် ရှိနေပြီးသော စာကြည့်တိုက်များကိုသာ အသုံးပြုနိုင်ပြီး၊ ကိုဩဒိနိတ်ထည့်ခြင်းသည် ၎င်းတို့ကို အညွှန်းတွင်သာ မှတ်ပုံတင်သည် — AAR၊ JAR သို့မဟုတ် WHL ဖိုင်များကိုယ်တိုင် အလိုအလျောက် ဒေါင်းလုဒ်မလုပ်ပါ။ ခန်းကို ပရောဂျက်တစ်ခုချင်းစီအတွက် သိမ်းဆည်းထားဆဲဖြစ်သည်။

ဒေတာဘေ့စ်နှင့် သိုလှောင်မှု စစ်ဆေးသူ
ဇယားအကြောင်းအရာကို ရိုက်ထုတ်သော ကုဒ်မရေးဘဲ ပရောဂျက်ဒေတာဘေ့စ်၏ အကြောင်းအရာကို စစ်ဆေးပြီး စမ်းသပ်ရန်အတွက်- အဓိကမီနူးတွင် ဒေတာဘေ့စ်နှင့် သိုလှောင်မှု စစ်ဆေးသူ ကိုဖွင့်ပါ၊ ပရောဂျက်နှင့် ဒေတာဘေ့စ်ဖိုင် (.db၊ .sqlite သို့မဟုတ် .sqlite3) ကို ရွေးချယ်ပါ၊ ထို့နောက် ဒေတာဘေ့စ်ကို ဖွင့်ပါ ကိုနှိပ်ပါ။ IDE သည် ဇယားအစီအစဉ်ကို ဖတ်ပြီး ပထမလိုင်း ၂၀ ကို Jieshuo က အသံကျယ်စွာ ဖတ်သော စာသားဇယားအဖြစ် ပြသသည်။ ရိုးရှင်းသော SELECT မေးခွန်းကို ရေးပြီး မေးခွန်းကို လုပ်ဆောင်ပါ ကိုနှိပ်ပါ (ဥပမာ SELECT nama FROM pengguna WHERE kota = 'Makassar')။ တန်ဖိုးကို ပြောင်းလဲရန် လိုင်းနံပါတ် (၁ = ပထမလိုင်း)၊ ကော်လံအမည်နှင့် တန်ဖိုးအသစ်ကို ထည့်ပါ၊ ထို့နောက် ဆဲလ်တန်ဖိုး ပြောင်းပါ ကိုနှိပ်ပါ — တန်ဖိုးကို .db ဖိုင်သို့ ပြန်လည်ရေးသားသည်။ ဇယား၏ လက်ရှိအခြေအနေကို ပရောဂျက်တွင် <db-အမည်>.cadangan.txt ဖိုင်အဖြစ် သိမ်းဆည်းရန် အရန်သိမ်းဆည်းပါ ကိုနှိပ်ပါ။ ပထမဇယားကိုသာ ဖတ်သည်။ ပံ့ပိုးပေးသော မေးခွန်းများမှာ JOIN သို့မဟုတ် GROUP BY မပါသော ရိုးရှင်းသော SELECT များသာ ဖြစ်သည်။ SharedPreferences နှင့် DataStore ကို မဖတ်ရသေးပါ။

ယူနစ်စမ်းသပ်မှု စက်ရုံနှင့် Fuzzing
အက်ပ်ကို မျှဝေခြင်းမပြုမီ ယုတ္တိဗေဒကွက်လပ်များကို ရှာဖွေရန်အတွက်- အဓိကမီနူးတွင် ယူနစ်စမ်းသပ်မှု စက်ရုံနှင့် Fuzzing ကိုဖွင့်ပါ၊ ပရောဂျက်နှင့် ကုဒ်ဖိုင်ကို ရွေးချယ်ပါ၊ ထို့နောက် စမ်းသပ်မှုများ ဖန်တီးပြီး လုပ်ဆောင်ပါ ကိုနှိပ်ပါ။ IDE သည် ဖိုင်ရှိ လုပ်ဆောင်ချက်လက်မှတ်များကို ဖတ်ပြီး၊ ပုံမှန်နှင့် နယ်နိမိတ်စမ်းသပ်မှုဖြစ်ရပ်များ (ဗလာစာသား၊ null၊ အများဆုံးဂဏန်းများ၊ ထူးဆန်းသော အက္ခရာများ) ကို ဖန်တီးကာ၊ နမူနာလုပ်ဆောင်ချက်များတွင် fuzzing ကို လုပ်ဆောင်ပြီး၊ JUnit စမ်းသပ်မှုအရိုးစု (Uji<အတန်းအမည်>.java) ကို ပရောဂျက်တွင် ရေးသားသည်။ ရလဒ်က စမ်းသပ်မှုဘယ်နှစ်ခု အောင်မြင်ပြီး ကျရှုံးခဲ့သည်၊ ကုဒ်လိုင်းဘယ်နှစ်ကြောင်းနှင့် လုပ်ဆောင်ချက်ဘယ်နှစ်ခု တွေ့ရှိခဲ့သည်၊ နှင့် စမ်းသပ်မှုဖြစ်ရပ်ဘယ်နှစ်ခု ဖန်တီးခဲ့သည်ကို အစီရင်ခံသည်။ ဖန်တီးထားသော စမ်းသပ်မှုများသည် အရိုးစုများသာ ဖြစ်သည် — မျှော်လင့်ထားသော တန်ဖိုးများကို တီထွင်သူက ရေးသားရမည် — နှင့် အစစ်အမှန် fuzzing သည် နမူနာလုပ်ဆောင်ချက်များတွင်သာ လုပ်ဆောင်သည်၊ ပရောဂျက်လုပ်ဆောင်ချက်များတွင် မဟုတ်ပါ။ လိုင်းလွှမ်းခြုံမှု ရာခိုင်နှုန်းကို မတွက်ချက်ရသေးပါ။

စက်ပစ္စည်း ပြင်းထန်သော အခြေအနေ ပုံစံတူလုပ်ဆောင်သူနှင့် မှတ်ဉာဏ် ယိုစိမ့်မှု စာရင်းစစ်သူ
စနစ်က ၎င်း၏လုပ်ငန်းစဉ်ကို သတ်ဖြတ်သောအခါ၊ ကွန်ရက်ပြတ်တောက်သောအခါ၊ မျက်နှာပြင်လှည့်သောအခါ၊ သို့မဟုတ် ဘက်ထရီချွေတာမှု အသက်ဝင်သောအခါ အက်ပ်၏ ခံနိုင်ရည်ကို စမ်းသပ်ရန်အတွက်- အဓိကမီနူးတွင် စက်ပစ္စည်း ပြင်းထန်သော အခြေအနေ ပုံစံတူလုပ်ဆောင်သူနှင့် မှတ်ဉာဏ် ယိုစိမ့်မှု စာရင်းစစ်သူ ကိုဖွင့်ပါ၊ ပရောဂျက်ကို ရွေးချယ်ပါ၊ ထို့နောက် ပုံစံတူလုပ်ဆောင်မှုကို လုပ်ဆောင်ပါ ကိုနှိပ်ပါ။ IDE သည် မျက်နှာပြင်လှည့်ခြင်း ပုံစံတူလုပ်ဆောင်မှုနှင့်အတူ ဖိအားအခြေအနေ သုံးခုကို လုပ်ဆောင်ပြီး ၎င်းတို့၏မျက်နှာပြင်များ ပိတ်ပြီးနောက် မှတ်ဉာဏ်တွင် ထိန်းသိမ်းထားသော အရာဝတ္ထုများကို ခြေရာခံကာ၊ ထို့နောက် ပျောက်ဆုံးသွားသော ဒေတာနှင့် ယိုစိမ့်နေသော အရာဝတ္ထုများ၏ ကွင်းဆက်များကို အစီရင်ခံသည်။ ၎င်းသည် အခြေအနေမော်ဒယ်ပေါ်တွင် ပုံစံတူလုပ်ဆောင်ခြင်းဖြစ်ပြီး၊ လုပ်ငန်းစဉ်ကို အမှန်တကယ် သတ်ဖြတ်ခြင်းမဟုတ်၊ ဖုန်းကွန်ရက်ကို အမှန်တကယ် ဖြတ်တောက်ခြင်းမဟုတ်၊ အစစ်အမှန် heap dump လည်း မဟုတ်ပါ။ ဤမျက်နှာပြင်ရှိ အခြေအနေမော်ဒယ်သည် ပုံသေနမူနာသာ ဖြစ်ပြီး၊ အသုံးပြုသူ၏ ပရောဂျက်မျက်နှာပြင်များ၏ အခြေအနေ မဟုတ်ပါ။

ပရောဂျက် ပုံစံငယ် ဗိသုကာပညာရှင်
ကြီးမားသော အက်ပ်စိတ်ကူးကို အဆင့်လိုက် အလုပ်အစီအစဉ်အဖြစ်သို့ ပြောင်းလဲရန်အတွက်- အဓိကမီနူးတွင် ပရောဂျက် ပုံစံငယ် ဗိသုကာပညာရှင် ကိုဖွင့်ပါ၊ ပရောဂျက်ကို ရွေးချယ်ပါ၊ အက်ပ်စိတ်ကူးကို ရေးပါ (ဥပမာ အရစ်ကျဖြင့် ကုန်စုံဆိုင်ငွေကိုင်အက်ပ်)၊ ထို့နောက် ပုံစံငယ် ဖန်တီးပါ ကိုနှိပ်ပါ။ IDE သည် မော်ဂျူးများ၊ ဖိုင်စာရင်းနှင့် အလုပ်မှတ်တိုင်ငယ်များကို စီစဉ်ပြီး၊ ထို့နောက် ၎င်းတို့ကို ပရောဂျက်ဖိုင်တွဲတွင် cetak-biru.txt အဖြစ် သိမ်းဆည်းသည်။ မှတ်တိုင်တစ်ခုပြီးဆုံးတိုင်း နောက်မှတ်တိုင်ကို ပြီးဆုံးပြီဟု အမှတ်အသားပြုပါ ကိုနှိပ်ပါ၊ သို့မဟုတ် သိမ်းဆည်းထားသော ပုံစံငယ်ကို ပြန်ဖွင့်ရန် သိမ်းဆည်းထားသော ပုံစံငယ်ကို တင်ပါ ကိုနှိပ်ပါ။ ပုံစံငယ်များကို စက်ပစ္စည်းပေါ်ရှိ အဓိကစကားလုံးပုံစံများမှ တည်ဆောက်သည်၊ အွန်လိုင်း AI မော်ဒယ်မှ မဟုတ်ပါ — မသိသော စိတ်ကူးများသည် ယေဘုယျအရိုးစု (ဒေတာမော်ဒယ်၊ သိုလှောင်မှု၊ မျက်နှာပြင်များ၊ ယုတ္တိဗေဒ) ကို အသုံးပြုသည် — နှင့် တက်ကြွသော AI ဝန်ဆောင်မှုပေးသူမှတစ်ဆင့် တည်ဆောက်ခြင်းသည် ဤအဆင့်တွင် မရှိသေးပါ။

ကုဒ် ယုတ္တိစီးဆင်းမှု ဇာတ်ကြောင်းပြောသူ
လိုင်းအလိုက် အထားအသိုကို နားထောင်ခြင်းမပြုဘဲ ရှည်လျားသော ကုဒ်ကို နားလည်ရန်အတွက်- အဓိကမီနူးတွင် ကုဒ် ယုတ္တိစီးဆင်းမှု ဇာတ်ကြောင်းပြောသူ ကိုဖွင့်ပါ၊ ပရောဂျက်နှင့် ကုဒ်ဖိုင်ကို ရွေးချယ်ပါ၊ ထို့နောက် ကုဒ် ဇာတ်ကြောင်း ကိုနှိပ်ပါ။ IDE သည် လိုင်းတစ်ခုချင်းစီကို အင်ဒိုနီးရှားဝါကျအဖြစ် ပြောင်းလဲသည် (ဥပမာ စုစုပေါင်းက 100000 ထက် ကြီးပါက၊ နောက်ပိုင်းဘလောက်ကို လုပ်ဆောင်ပါ)၊ နည်းလမ်းများအကြား ခေါ်ဆိုမှုမြေပုံကို ပြသပြီး၊ သိမ်မွေ့သော အမှားအယွင်းများကို ၎င်းတို့၏လိုင်းနံပါတ်များနှင့်အတူ အမှတ်အသားပြုသည် — == နှင့် နှိုင်းယှဉ်ထားသော String၊ မပိတ်ဘဲ ဖွင့်ထားသော stream နှင့် မတူညီသော နည်းလမ်းနှစ်ခုတွင် ရေးသားထားသော ကိန်းရှင်။ ဇာတ်ကြောင်းနှင့် စစ်ဆေးမှုသည် အင်တာနက်မဲ့ စာသားပုံစံများကို အသုံးပြုသည်၊ အွန်လိုင်း AI မော်ဒယ်မဟုတ်ပါ၊ ဒေတာစီးဆင်းမှု အပြည့်အစုံ ခွဲခြမ်းစိတ်ဖြာမှုလည်း မဟုတ်ပါ။ မသိသော ပုံစံများကို ရှိသည့်အတိုင်း ကုဒ်လိုင်းအဖြစ် ဇာတ်ကြောင်းပြောသည်၊ နှင့် ဒေတာပြိုင်ပွဲသတိပေးချက်များသည် အမှန်တကယ် အလှည့်ကျသာ အသုံးပြုသော ကိန်းရှင်များအတွက်လည်း ပေါ်လာနိုင်သည်။

အက်ပ်အထုပ် စက်ရုံနှင့် Play Store အဆင်သင့်ဖြစ်မှု
ဖုန်းမှ တိုက်ရိုက်အက်ပ်ကို Google Play Store အတွက် ပြင်ဆင်ရန်အတွက်- အဓိကမီနူးတွင် အက်ပ်အထုပ် စက်ရုံနှင့် Play Store အဆင်သင့်ဖြစ်မှု ကိုဖွင့်ပါ၊ ပရောဂျက်ကို ရွေးချယ်ပါ၊ ထို့နောက် AAB အထုပ်ကို တည်ဆောက်ပါ ကိုနှိပ်ပါ။ IDE သည် manifest၊ အရင်းအမြစ်များနှင့် ပရောဂျက်အက်ဆက်များမှ .aab ဖိုင်ကို စုစည်းပြီး၊ ဗိသုကာ (arm64-v8a, armeabi-v7a, x86_64) နှင့် ဘာသာစကားအလိုက် ဒေါင်းလုဒ်အပိုင်းအရွယ်အစားများကို ပုံစံတူလုပ်ဆောင်ကာ၊ ထို့နောက် Play အဆင်သင့်ဖြစ်မှုကို စစ်ဆေးသည် — ပစ်မှတ် SDK က ၃၅ အောက်ဖြစ်ပါက မြင့်မားသည်ဟု အမှတ်အသားပြုသည်၊ အကြောင်းမှာ Play Store က ၃၅ သို့မဟုတ် ထို့ထက်ပိုရန် လိုအပ်ပြီး၊ ပျောက်ဆုံးနေသော 64-bit စာကြည့်တိုက်ကိုလည်း မြင့်မားသည်ဟု အမှတ်အသားပြုသည်။ ရရှိသော အထုပ်သည် စံဖွဲ့စည်းပုံရှိ AAB မော်ကွန်းဖြစ်သည်။ အပိုင်းအရွယ်အစားများသည် ဖိုင်အရွယ်အစားများမှ ခန့်မှန်းချက်များဖြစ်ပြီး၊ bundletool ခွဲခြမ်းခြင်း၏ အစစ်အမှန်ရလဒ်များ မဟုတ်ပါ၊ နှင့် Play Console အတွက် အထုပ်လက်မှတ်ထိုးခြင်းသည် APK နှင့် အတူတူပင် တည်ဆောက်မှုလမ်းကြောင်းကို အသုံးပြုဆဲဖြစ်သည်။

OTA အပ်ဒိတ်အင်ဂျင်နှင့် အဆင့်လိုက် ထုတ်ဝေမှုများ
အသုံးပြုသူများကို APK အပြည့်အစုံကို ပြန်လည်ဒေါင်းလုဒ်လုပ်ရန် အတင်းအကျပ်မခိုင်းဘဲ အသေးစားပြင်ဆင်မှုများကို ပေးပို့ရန်အတွက်- အဓိကမီနူးတွင် OTA အပ်ဒိတ်အင်ဂျင်နှင့် အဆင့်လိုက် ထုတ်ဝေမှုများ ကိုဖွင့်ပါ၊ ပရောဂျက်ကို ရွေးချယ်ပါ၊ ဗားရှင်းအဟောင်းနှင့် အသစ်၏ အကြောင်းအရာကို ရေးပါ၊ ထို့နောက် Patch အထုပ် ဖန်တီးပါ ကိုနှိပ်ပါ။ IDE သည် လိုင်းကွာခြားချက်များကို တွက်ချက်ပြီး အကြောင်းအရာအသစ်၏ SHA-256 လက်ဗွေနှင့်အတူ patch အထုပ် (patch-ota.zip) ကို ဖန်တီးကာ၊ ထို့နောက် ဤစက်ပစ္စည်းသည် အစောပိုင်း ၁၀ ရာခိုင်နှုန်း ထုတ်ဝေမှုအဆင့်တွင် ရှိ၊ မရှိ စစ်ဆေးသည်။ ဤနေရာရှိ patch များသည် စာသားဖိုင်များတွင်သာ အလုပ်လုပ်သည် (စကရစ်များ၊ အက်ဆက်များ၊ ဖွဲ့စည်းပုံ) — ဒွိ DEX သို့မဟုတ် APK patch များကို မပံ့ပိုးသေးပါ၊ နှင့် အက်ပ်ကို ပြန်လည်ဖွင့်သောအခါ patch ကို အသုံးပြုသည်။ manifest ရှိ လက်ဗွေသည် အကြောင်းအရာ၏ ခိုင်မာမှုကိုသာ သက်သေပြပြီး၊ ပေးပို့သူ၏ စစ်မှန်မှုကို မဟုတ်ပါ၊ အကြောင်းမှာ ၎င်းသည် သီးသန့်သော့လက်မှတ်ကို မသုံးသေးသောကြောင့် ဖြစ်သည်။

အဖွဲ့ ကုဒ် ပြန်လည်သုံးသပ်မှု စတူဒီယို
လုပ်ဖော်ကိုင်ဖက်၏ ပြောင်းလဲမှုများကို ပြန်လည်သုံးသပ်ရန်နှင့် Git မြှားအမှတ်အသားများကို မဖတ်ဘဲ ပေါင်းစည်းမှု ပဋိပက္ခများကို ဖြေရှင်းရန်အတွက်- အဓိကမီနူးတွင် အဖွဲ့ ကုဒ် ပြန်လည်သုံးသပ်မှု စတူဒီယို ကိုဖွင့်ပါ၊ ပရောဂျက်ကို ရွေးချယ်ပါ၊ စာသားဗားရှင်း သုံးခုကို ဖြည့်ပါ (အခြေခံ၊ ဒေသတွင်း၊ လုပ်ဖော်ကိုင်ဖက်)၊ ထို့နောက် အဖွဲ့ ပြန်လည်သုံးသပ်မှုကို ဖွင့်ပါ ကိုနှိပ်ပါ။ IDE သည် သုံးခုလုံးကို ပေါင်းစည်းပြီး ပဋိပက္ခတစ်ခုချင်းစီကို အသံရွေးချယ်မှုအဖြစ် ပြသသည်- ဒေသတွင်း ဗားရှင်းကို သုံးပါ၊ လုပ်ဖော်ကိုင်ဖက် ဗားရှင်းကို သုံးပါ၊ သို့မဟုတ် နှစ်ခုလုံးကို ပေါင်းပါ — ရလဒ်လိုင်းများကို လိုင်းအစီအစဉ် မှန်ကန်စေရန် ပဋိပက္ခ၏ မူရင်းနေရာတွင် ထည့်သွင်းသည် — ထို့နောက် ရလဒ်ကို ပရောဂျက်တွင် gabung-hasil.txt သို့ ရေးသားသည်။ ၎င်း၏အောက်တွင် ပရောဂျက်အလုပ်ဘုတ် ရှိသည်- အလုပ်ခေါင်းစဉ်ကို ထည့်ပါ ထို့နောက် အလုပ်ထည့်ပါ ကိုနှိပ်ပါ။ အလုပ်များကို ပရောဂျက်အတွင်းရှိ .tugas ဖိုင်တွဲတွင် စာသားအဖြစ် သိမ်းဆည်းသည်။ ပေါင်းစည်းခြင်းသည် အထားအသိုမဟုတ်ဘဲ လိုင်းကိုက်ညီမှုကို အသုံးပြုသည်၊ ထို့ကြောင့် တူညီသောလိုင်းပေါ်ရှိ ပြောင်းလဲမှုနှစ်ခုသည် ၎င်းတို့၏အဓိပ္ပာယ်များ မတိုက်ဆိုင်သော်လည်း အမြဲတမ်း ပဋိပက္ခအဖြစ် သတ်မှတ်သည်။ အလုပ်ဘုတ်သည် ၎င်း၏စာသားဖိုင်ကို Git မှတ်တမ်းနှင့်အတူ ကူးယူခြင်းဖြင့် ထပ်တူပြုပြီး၊ သီးခြားထပ်တူပြုဆာဗာ မရှိပါ။

ကုဒ်ဖွဲ့စည်းပုံ အသံဖြင့် ညွှန်ကြားခြင်း
အယ်ဒီတာအတွင်း အသံဖြင့် ကုဒ်ရေးရန်- ပရောဂျက်တစ်ခုကို အယ်ဒီတာတွင် ဖွင့်ပါ၊ ထို့နောက် ကုဒ်ဖွဲ့စည်းပုံ အသံဖြင့် ညွှန်ကြားခြင်း ခလုတ်ကို နှိပ်ပါ။ အမိန့်များကို အင်ဒိုနီးရှား ဘာသာစကားဖြင့် ပြောပါ၊ ဥပမာ buat fungsi tambah dengan parameter a angka dan b angka, buat kelas Mobil သို့မဟုတ် buat variabel teks nama sama dengan Budi — IDE က အပြောကို အထားအသို မှန်ကန်သော Java၊ Kotlin၊ Python သို့မဟုတ် Compose ကုဒ် ဘလောက်တစ်ခုအဖြစ် ပြောင်းလဲပြီး ကာဆာ အနေအထားတွင် ထည့်သွင်းကာ Jieshuo မှတစ်ဆင့် အကျဉ်းချုပ် အကျဉ်းကို အသံကျယ်ကျယ် ဖတ်ပြသည်။ အသံဖြင့် ညွှန်ကြားခြင်းသည် စနစ်၏ ထည့်သွင်းထားသော အသံ ထည့်သွင်းမှု ဝန်ဆောင်မှုကို အသုံးပြုသည်၊ နောက်ထပ် မိုက်ခရိုဖုန်း ခွင့်ပြုချက် မလိုအပ်ပါ၊ မှတ်ပုံတင်ထားပြီးသော အမိန့် ပုံစံများကိုသာ မှတ်မိသည်၊ ထိုပုံစံများပြင်ပရှိ အပြောသည် ကုဒ်အဖြစ် မပြောင်းလဲပါ။ စကားလုံးများအဖြစ် ပြောသော ဂဏန်းများ (ဥပမာ 'lima') သည် ဂဏန်းများအဖြစ် မပြောင်းလဲသေးပါ။

ဒေသတွင်း ပူးပေါင်းဆောင်ရွက်မှု အခန်း (အင်တာနက်မလိုပါ)
အင်တာနက်မရှိဘဲ အခန်းတစ်ခုတွင် အတူတကွ လုပ်ဆောင်ရန်- ပင်မမီနူးတွင် ပူးပေါင်းဆောင်ရွက်မှု ကို ဖွင့်ပါ၊ ထို့နောက် ဒေသတွင်း ပူးပေါင်းဆောင်ရွက်မှု အခန်း အပိုင်းကို ဖွင့်ပါ။ ဖုန်းတစ်လုံးက ဆက်ရှင်တစ်ခု ဖွင့်သည် (IDE က ဒေသတွင်း IP လိပ်စာနှင့် 6 လုံး PIN ကို ပြသသည်)၊ အခြား ဖုန်းတစ်လုံးက ထိုလိပ်စာနှင့် PIN ဖြင့် ပါဝင်သည်။ စာသား ပြောင်းလဲမှုများကို လိုင်း ကွာခြားချက်များအဖြစ် ပေးပို့သည်၊ တည်ဆောက်ပြီးသား APK ကို စမ်းသပ်သူ၏ ဖုန်းသို့ ပေးပို့နိုင်သည်၊ စမ်းသပ်သူ၏ ဖုန်းမှ Crash အစီရင်ခံစာများကို ပြန်လည် လက်ခံရရှိသည်။ ဆက်ရှင်တစ်ခုသည် သူငယ်ချင်းတစ်ဦးအတွက်သာ ဖြစ်သည်၊ လူနှစ်ဦးက အတိအကျ တူညီသော လိုင်းကို တစ်ချိန်တည်းတွင် ပြောင်းလဲလျှင် နောက်ဆုံး ပြောင်းလဲမှုကို အသုံးပြုသည်။ PIN ကို ဒေသတွင်း ကွန်ရက်ပေါ်တွင် ရိုးရှင်းသော စာသားအဖြစ် ပေးပို့သည်။ ဤအခန်းကို အမှန်တကယ် ဖုန်းပေါ်တွင် မစမ်းသပ်ရသေးပါ။

AI ဆက်တင်များ
အက်ပ်များ ဖန်တီးရန် AI ပရိုဗိုက်ဒါနှင့် API သော့များကို သတ်မှတ်ရန်- ပင်မမီနူးတွင် ဆက်တင်များ အုပ်စုတွင် AI ဆက်တင်များ ကို နှိပ်ပါ (ကွန်နက်တာ ခလုတ် အနားတွင်)။ ရရှိနိုင်သော စာရင်းမှ အသုံးပြုမည့် ပရိုဗိုက်ဒါကို ရွေးပါ၊ မော်ဒယ်တစ်ခု ပျက်ကွက်လျှင် IDE က တူညီသော ပရိုဗိုက်ဒါမှ နောက်မော်ဒယ်ကို အလိုအလျောက် စမ်းသပ်နိုင်ရန် ပရိုဗိုက်ဒါ အမှားဖြစ်လျှင် မော်ဒယ် ပြောင်းရန် ကို အမှတ်အသားပြုပါ။ အရန်သော့များ ထည့်ရန် API သော့များ စီမံခန့်ခွဲရန် ကို နှိပ်ပါ (အမည်နှင့် သော့ကို ဖြည့်ပြီး သိမ်းဆည်းရန် ကို နှိပ်ပါ၊ သော့များကို ဖုံးကွယ်ထားပြီး နောက်ဆုံး စာလုံး 4 လုံးသာ မြင်နိုင်သည်)။ သော့များကို ဖုန်းတွင် သိမ်းဆည်းထားပြီး အက်ပ်တစ်ခု ဖန်တီးသည့်အခါ ရွေးချယ်ထားသော ပရိုဗိုက်ဒါမှလွဲ၍ အခြားမည်သည့်နေရာသို့မျှ ပေးပို့ခြင်း မရှိပါ။ မှတ်ချက်- လက်ရှိတွင် ပရိုဗိုက်ဒါနှင့် သော့ ရွေးချယ်မှုကို မှတ်တမ်းတင်ပြီး AI Pembuat Aplikasi မျက်နှာပြင်တွင် ပြသခြင်းသာ ဖြစ်သည် — အက်ပ်များ ဖန်တီးခြင်းသည် ဖုန်းပေါ်ရှိ ဒေသတွင်း AI ကို ဆက်လက် အသုံးပြုနေဆဲဖြစ်သည် (အင်တာနက်မရှိဘဲ)၊ အွန်လိုင်း ပရိုဗိုက်ဒါများကို အသုံးပြုခြင်းသည် နောက်မှ ရောက်လာမည်။

ကွန်နက်တာ
APK တစ်ခုကို ခွဲခြမ်းစိတ်ဖြာပြီး ပေးပို့ရန်- ပင်မမီနူးတွင် ဆက်တင်များ အုပ်စုတွင် ကွန်နက်တာ ကို နှိပ်ပါ (AI ဆက်တင်များ ခလုတ် အနားတွင်)။ ဖုန်းမှ APK ဖိုင်တစ်ခု ရွေးပါ၊ IDE က ၎င်း၏ အကြောင်းအရာကို ဖတ်သည် (အထုပ် အမည်၊ ဗားရှင်း၊ လုပ်ဆောင်ချက်များ စာရင်း)၊ ထို့နောက် စနစ် မျှဝေမှု မီနူးမှတစ်ဆင့် ပေးပို့ရန် APK ပေးပို့ရန် ကို နှိပ်ပါ (ဥပမာ WhatsApp သို့မဟုတ် Drive)။

ဘာသာစကားနှင့် အသံ
အက်ပ်၏ ဘာသာစကားကို ပြောင်းရန်- ဆက်တင်များ ကို ဖွင့်ပါ၊ ထို့နောက် အက်ပ် ဘာသာစကား ကို ဖွင့်ပြီး ဘာသာစကားတစ်ခု သို့မဟုတ် စနစ်အတိုင်း လိုက်နာရန် ကို ရွေးပါ။ ပင်မမျက်နှာပြင်နှင့် မျက်နှာပြင် အများစုသည် အက်ပ်ကို ပိတ်ခြင်း သို့မဟုတ် ပြန်လည်စတင်ခြင်းမရှိဘဲ ရွေးချယ်ထားသော ဘာသာစကားသို့ ချက်ချင်း ပြောင်းလဲသည်၊ အချို့သော မျက်နှာပြင်များ (ဥပမာ Terminal၊ ပူးပေါင်းဆောင်ရွက်မှု၊ AI ဆက်တင်များနှင့် သော့များ စီမံခန့်ခွဲခြင်း) ကို ပြန်ဖွင့်သည်အထိ အဟောင်း ဘာသာစကားကို ဆက်လက် အသုံးပြုနေဆဲဖြစ်သည်။ စနစ်အတိုင်း လိုက်နာရန် ကို ရွေးချယ်လျှင် ဘာသာစကားသည် ဖုန်း၏ စနစ် ဘာသာစကားကို လိုက်နာသည်။
