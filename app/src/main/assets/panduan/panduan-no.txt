Velkommen til Create Aplikasi by Al Kautsar
Create Aplikasi er en app for å lage Android-apper som kjører direkte på telefonen, uten å trenge en bærbar datamaskin. Appen lar hvem som helst lage sin egen Android-app, inkludert brukere som nettopp har begynt å lære å lage apper og brukere av skjermlesere. Den fullstendige veiledningen for bruk av denne appen er tilgjengelig på denne Tentang Alat-skjermen.

Hva denne appen er og hvem den er for
Create Aplikasi er et verktøy for å lage Android-apper som kjører på telefonen. Appen er beregnet på alle som ønsker å lage sin egen Android-app, inkludert nybegynnere og brukere av skjermlesere. Appen tilbyr en koderedigerer, en Jalankan-knapp for å teste prosjekter, en Bangun-knapp for å lage en APK, samt menyer for å signere og installere APK-en.

Formålet med denne appen
Denne appen ble laget slik at hvem som helst enkelt kan lage sin egen Android-app, direkte fra telefonen. Utseendet ble gjort så enkelt som mulig slik at også nye brukere kan prøve med en gang.

Slik lager du et nytt prosjekt, trinn for trinn
1. Trykk på Buat Project i hovedmenyen.
2. Velg prosjekttype: HTML, Situs Web, Java, Kotlin, Compose eller Python.
3. Fyll inn appens navn, eksempel: Garuda Decode.
4. Fyll inn pakkenavnet (package name), eksempel: com.android.garudadecode. Pakkenavnet må bruke små bokstaver og bestå av minst to deler atskilt med punktum.
5. Fyll inn appens versjon, eksempel: 1.0, og versjonskoden i form av et tall, eksempel: 1. Hvis det står tomt, fylles versjonen automatisk inn med 1.0 og versjonskoden med 1.
6. Fyll inn minste SDK og mål-SDK om nødvendig. Hvis det står tomt, brukes standardverdiene. Minste SDK er den laveste Android-versjonen som støttes, eksempel: 21 betyr Android 5.0. Maksimal mål-SDK er 36 (Android 16).
7. Trykk på knappen Pilih Izin for å velge appens tillatelser, eksempel: INTERNET. Tillatelsen INTERNET er allerede merket som standard. Merk bare tillatelsene appen virkelig trenger.
8. Hvis du ønsker det, merk "Gunakan arsitektur terpisah 64 bit dan 32 bit" slik at APK-ens størrelse blir mindre, og merk "Gunakan tanda tangan pribadi" hvis du vil bruke en keystore du har laget selv.
9. Trykk på Buat Proyek. Det nye prosjektet lagres i mappen Download/project og vises umiddelbart i Kelola Project.

Tilgjengelige prosjekttyper
• HTML: utseende fra index.html, style.css og script.js, kjører via WebView. Bygges direkte på telefonen.
• Situs Web: nettsted med meny (Beranda, Tentang, Kontak) fra index.html, tentang.html, kontak.html, style.css og script.js, kjører via WebView. Bygges direkte på telefonen.
• Java: bygges på telefonen. MainActivity ligger i app/src/main/java/<nama-paket>/MainActivity.java. Utseendet kommer fra app/src/main/res/layout/activity_main.xml, teksten fra app/src/main/res/values/strings.xml og temaet fra app/src/main/res/values/styles.xml.
• Kotlin: kan bygges på enheten (frakoblet) med Kotlin-kompilatoren som følger med appen, eller via GitHub Actions. MainActivity ligger i app/src/main/java/<nama-paket>/MainActivity.kt, og res-filene er de samme som i et Java-prosjekt. Den første Kotlin-byggingen er tregere på grunn av kompilatorens store størrelse, og .java-filer som refererer til Kotlin-klasser kan ennå ikke bygges (.java-filer kompileres først, før .kt-filer).
• Compose: en moderne Android-app der grensesnittet lages med Jetpack Compose (ikke XML-oppsett). MainActivity ligger i app/src/main/java/<nama-paket>/MainActivity.kt. Compose-prosjekter bygges via GitHub Actions (menyen Bangun proyek, deretter Bangun online) eller i Termux med Gradle, fordi Compose krever Jetpack Compose-biblioteker som ikke er tilgjengelige på enheten.
• Python: appens logikk skrives på språket Python (Chaquopy) i app/src/main/python/main.py og kjøres av verten MainActivity.java i app/src/main/java/<nama-paket>/MainActivity.java. Python-prosjekter kan bygges direkte på telefonen (Chaquopy-kjøretid følger med appen) eller via GitHub Actions. Minste SDK for Python-prosjekter er 24 (Android 7.0).

Endre prosjektarkitektur
For å endre arkitekturvalgene til et eksisterende prosjekt uten å opprette et nytt prosjekt: trykk på «Endre prosjektarkitektur» i hovedmenyen, velg deretter prosjektet og endre avmerkingsboksen «Bygg 64-biters APK (arm64-v8a)» eller «Bygg 32-biters APK (armeabi-v7a)»; eller trykk lenge på prosjektnavnet i «Administrer prosjekt» og velg «Endre arkitektur» for å åpne den samme skjermen direkte for det prosjektet. Regelen er: hvis begge avmerkingsbokser er på, lager bygget to separate APK-filer, én 64-biters og én 32-biters; hvis bare én avmerkingsboks er på, lager bygget én enkelt universell APK som fortsetter å kjøre på både 64- og 32-biters enheter. En separat APK for bare én variant støttes ennå ikke, fordi byggestien bare kjenner det delte eller universelle valget, men hvert variantvalg forblir lagret i prosjektet slik at det ikke går tapt når skjermen åpnes igjen.

Filstruktur for prosjekter i Java, HTML, Situs Web, Kotlin, Compose og Python
Prosjekter i Java, HTML, Situs Web, Kotlin, Compose og Python er satt opp som Android-prosjekter generelt. Inne i mappen app finnes mappen src, og inne i den finnes mappen main. Inne i mappen main finnes AndroidManifest.xml ved siden av mappen java, mappen res som inneholder layout/activity_main.xml og values/strings.xml samt values/styles.xml, og for HTML og Situs Web finnes mappen assets som inneholder index.html (Situs Web har også tentang.html og kontak.html). HTML- og Situs Web-prosjekter har også sin egen MainActivity i app/src/main/java/<nama-paket>/MainActivity.java, som laster index.html i WebView og er startprogram i AndroidManifest. Python-prosjekter har Python-kode i app/src/main/python/main.py og verten MainActivity.java i app/src/main/java/<nama-paket>/MainActivity.java. AndroidManifest.xml, oppsett, strings og styles kan åpnes og endres i redigereren, akkurat som MainActivity. Gamle prosjekter der manifestet fortsatt ligger ved siden av mappen app kan fortsatt bygges, fordi appen ved bygging først sjekker AndroidManifest.xml i app/src/main/, deretter den ved siden av mappen app, og til slutt prosjektdatafilen.

Tillatelsesregler (viktig)
Tillatelser som merkes når et prosjekt lages, registreres bare på ett sted, avhengig av prosjekttypen. For prosjekter i Java, HTML, Situs Web, Kotlin, Compose og Python registreres de merkede tillatelsene KUN i AndroidManifest.xml som ligger i app/src/main/, ved siden av mappen java, inne i prosjektmappen. Prosjektdatafilen for prosjekter i Java, HTML, Situs Web, Kotlin, Compose og Python inneholder ingen liste over tillatelser. Hvis du velger Java og deretter merker INTERNET og CAMERA, registreres bare INTERNET og CAMERA i AndroidManifest.xml, uten at noen annen tillatelse følger med. Ved bygging leser appen tillatelsene fra samme sted: fra AndroidManifest.xml i app/src/main/ for prosjekter i Java, HTML, Situs Web, Kotlin, Compose og Python (hvis den ikke finnes, fra AndroidManifest.xml ved siden av mappen app for gamle prosjekter), og fra prosjektdatafilen for gamle prosjekter.

Slik bruker du redigereren
Åpne Kelola Project, trykk på prosjektets navn for å åpne redigereren. I redigereren kan filer åpnes, kode skrives og endringer lagres. For prosjekter i Java, HTML, Situs Web, Kotlin, Compose og Python er filene ordnet inne i mappen app/src/main. For å dele et prosjekt, bruk Ekspor ZIP (se avsnittet nedenfor).

Slik kjører du et prosjekt
I redigereren trykker du på Jalankan for å teste prosjektet. For HTML- og Situs Web-prosjekter er det index.html som kjøres via WebView. Hvis det oppstår en feil, les feilmeldingen, rett koden, og kjør deretter igjen.

Slik bygger du en APK
I redigereren trykker du på Bangun. Det finnes to måter å bygge på. Den første, Bangun di perangkat: bygge direkte på telefonen uten internett, for prosjekter i HTML, Situs Web, Java, Kotlin og Python. Den andre, Bangun online via GitHub Actions: bygge via internett på GitHub, og kan brukes for alle prosjekttyper. Compose-prosjekter kan bare bygges på den andre måten (Bangun online) eller i Termux med Gradle, fordi Compose krever Jetpack Compose-biblioteker som ikke er tilgjengelige på enheten. Resultatet av den første byggingen er ennå ikke signert. Deretter signerer appen det: automatisk med standardnøkkelen, eller med en personlig signatur hvis boksen "Gunakan tanda tangan pribadi" ble merket da prosjektet ble laget.

Slik installerer du en APK
Når APK-en er klar, trykk på Pasang for å installere den. På Android 8 og nyere vil telefonen først be om "Izinkan dari sumber ini", fordi denne appen installerer APK-er fra utenfor Play Store. Aktiver den tillatelsen én gang i Pengaturan, og gå deretter tilbake til appen: installasjonen fortsetter automatisk uten at du trenger å trykke på Pasang igjen. Hvis Pasang-knappen ikke vises, forsikre deg om at byggingen er ferdig og at APK-en er laget.

Slik signerer du en app
Hver APK må signeres for å kunne installeres. Det finnes to alternativer. Det første, standardnøkkelen: appen signerer selv automatisk, uten at du trenger å gjøre noe. Det andre, personlig signatur: lag først en keystore via menyen Buat Keystore i hovedmenyen, oppbevar passordet godt, og merk deretter "Gunakan tanda tangan pribadi" når du lager prosjektet. Keystore lagres i Download/project/signing.

Eksportere et prosjekt som ZIP
Ekspor ZIP tilbys slik at prosjekter kan deles med venner. Slik gjør du det: i Kelola Project, trykk lenge på prosjektets navn, og velg deretter Ekspor ZIP. Resultatet lagres i Download/project/<NamaProyek>.zip. Mappen bin tas ikke med, så størrelsen er liten, bare noen titalls KB. Den ZIP-filen kan sendes til en venn eller lastes opp til GitHub.

JAWS-utvidelsen
JAWS-utvidelsen bruker utvidelsesmotoren fra Jieshuo (CSR), ikke skjermleseren. På den måten kan designet fortsatt kjøre selv om brukeren bruker TalkBack. Slik gjør du det: åpne Ekstensi JAWS i hovedmenyen. Fordi det automatiske klikket kjører av seg selv, må tjenesten først aktiveres i Pengaturan Aksesibilitas. Deretter kan et nytt design lages: skriv designets navn, trykk på OK, og fyll deretter inn boksene.

Daftar Klik er atskilt for ordenens skyld
Inne i designet finnes to bokser: skriptboksen og Daftar Klik-boksen. Listen over knapper lagres separat i filen daftar_klik.txt, ett navn per linje. Eksempel på innholdet: tombolSimpan, tombolHapus, tombolBuka. For å åpne en app, skriv bare >WhatsApp i den listen. Gamle design som ennå ikke har noen daftar_klik.txt-fil, vil vise det standardexemplet.

Enkle funksjoner som tilbys
• klikTombol("tombolSimpan") — klikker på en knapp basert på teksten.
• klikDaftarTombol(daftar) — klikker på listen i daftar_klik.txt, én knapp per linje, i rekkefølge, og forteller deretter hvor mange som lyktes og hvor mange som ikke ble funnet.
• bukaAplikasi("WhatsApp") — åpner en app basert på navnet, eller skriv ">WhatsApp" i listen.
• klik(540, 1200) — klikker på skjermkoordinater.
Alle funksjoner ble gjort enkle først. Når du har vent deg til dem, kan flere funksjoner legges til senere.

Om skjermlesere
Denne appen er utformet for å være vennlig mot skjermlesere. Hvert inndatafelt har en etikett og et utfyllingseksempel, og alle knapper kan nås uten kompliserte bevegelser. JAWS-utvidelsen er laget for å fortsatt kjøre selv om brukeren bruker TalkBack, fordi det som brukes er utvidelsesmotoren, ikke skjermleseren.

Personvern og sikkerhet
Prosjekter og keystore lagres på telefonen din. GitHub-token brukes bare til bygging på nett og lagres inne i denne appen. Ikke del tokenet ditt eller keystore-passordet ditt med noen. Hvis du bruker en personlig signatur, oppbevar keystore og passordet på et trygt sted, fordi den gamle APK-en ikke kan oppdateres med samme signatur hvis de går tapt.

Krav
Android 5.0 eller nyere. Lagringstillatelse: på Android 11 og nyere brukes tillatelse for tilgang til alle filer, på Android 10 og eldre brukes vanlig lagringstillatelse (lese/skrive lagring) fordi Android 10 ikke har tillatelse for tilgang til alle filer. Å bygge på enheten krever en telefon med ARM-prosessor (32 eller 64 bit). Å bygge på nett via GitHub Actions krever internett og et GitHub-token. Kotlin-prosjekter kan bygges på enheten, men den første byggingen er tregere og bruker mer minne på grunn av Kotlin-kompilatorens store størrelse. Compose-prosjekter bygges via GitHub Actions eller i Termux med Gradle. Python-prosjekter krever Android 7.0 eller nyere (minste SDK 24), og den resulterende APK-en er større fordi den inneholder Python-kjøretid (Chaquopy) sammen med standardbiblioteket.

Terminal
Menyen Terminal på hovedskjermen åpner en terminal inne i denne appen. Kommandoer som ls kan brukes for å se innholdet i prosjektmappen, cd for å bytte mappe og git for å administrere kode. Kommandoenes utdata vises som tekst som kan leses av skjermleseren, og det finnes en Bacakan hasil-knapp for å lytte til det siste resultatet. Denne terminalen bruker telefonens systemskall, så interaktive programmer som nano og vim kan ennå ikke brukes her.

Lisens (betalingsversjon)
For å selge apper, merk "Aktifkan Lisensi" når du lager prosjektet, og fyll deretter inn WhatsApp-nummeret ditt. Appen som blir resultatet av byggingen, vil be om en lisenskode når den åpnes for første gang: brukeren ser enhetens ID, trykker på knappen Kirim ID Perangkat for å sende den ID-en til WhatsApp-en din, og deretter svarer du med lisenskoden. Lisenskoden beregnes fra enhetens ID og prosjektets passord (lisensi_seed i prosjektdatafilen) — oppbevar det passordet godt og ikke del det. Etter at riktig kode er skrevet inn, åpnes appen og ber ikke om koden igjen.

Pembuat Ikon Otomatis
Nye prosjektikoner er fortsatt gjennomsiktige, så Pembuat Ikon er tilgjengelig i hovedmenyen. Slik gjør du det: trykk på Pembuat Ikon, skriv én eller to bokstaver (for eksempel initialene i appens navn), velg bakgrunnsfarge og tekstfarge, se på forhåndsvisningen, og trykk deretter på Simpan ke Proyek for å bruke det ikonet i det valgte prosjektet, eller Simpan ke Download for å bruke PNG-filen et annet sted. Etter at et prosjekt er laget, tilbyr appen også å lage et ikon. Gamle prosjektikoner kan byttes når som helst fra prosjektmenyen i Kelola Project (trykk lenge på prosjektets navn, og velg deretter Ganti Ikon).

Ferdige prosjektmaler
Hvis du ikke vil begynne fra et tomt prosjekt, velg en mal når du lager prosjektet: Kalkulator (Java), Catatan (Java), Daftar Tugas (Kotlin), Kalkulator Web (HTML), Situs Profil (Situs Web) eller Penghitung (Compose). Å velge en mal endrer automatisk prosjekttypen slik at den følger den malen, og prosjektet lages med ferdig startkode — det gjenstår bare å kjøre eller endre det. Hvis prosjekttypen endres manuelt igjen etter at en mal er valgt, avbrytes malen og prosjektet blir tomt igjen. For maler i HTML og Situs Web erstatter malen innholdet i index.html, inkludert HTML-skriptet som skrives i skjemaet.

Sikkerhetskopiering og gjenoppretting av prosjekter
For at prosjekter ikke skal gå tapt, finnes en sikkerhetskopieringsfunksjon. Slik gjør du det: i Kelola Project, trykk lenge på prosjektets navn, og velg deretter Cadangkan. Sikkerhetskopien lagres som ZIP i mappen Download/backup med prosjektets navn og dato, eksempel: GarudaDecode-2026-11-14-123045.zip. Innholdet er det samme som Ekspor ZIP (hele prosjektets innhold, uten mappen bin). For å gjenopprette: åpne menyen i Kelola Project, velg Pulihkan cadangan, og velg deretter sikkerhetskopifilen. Hvis prosjektets navn allerede finnes, vil appen spørre: Timpa proyek lama, eller lagre med Nama baru.

Dele og importere prosjekter
For å dele et prosjekt med en venn: i Kelola Project, trykk lenge på prosjektets navn, og velg deretter Bagikan. Prosjektet sendes som ZIP via delingsapper (WhatsApp, Telegram og flere). For å motta et prosjekt fra en venn: åpne menyen i Kelola Project, velg Impor proyek, og velg deretter ZIP-filen. Den ZIP-filen må inneholde en prosjektdatafil — hvis den ikke finnes, avvises filen med en tydelig melding, fordi den filen ikke er et Create Aplikasi-prosjekt. Hvis prosjektets navn allerede finnes, vil appen spørre: Timpa proyek lama, eller lagre med Nama baru.

Prosjektsøk og filter
Hvis prosjektene har blitt mange, finnes det i Kelola Project en søkeboks og et typefilter. Skriv prosjektets navn i søkeboksen, så filtreres listen umiddelbart (store og små bokstaver skilles ikke). Typefilteret begrenser listen til bare én type: Semua, HTML, Situs Web, Java, Kotlin, Compose eller Python. Hvert prosjekts meny kan fortsatt åpnes som vanlig fra den filtrerte listen.

Bygg apper med stemmen
Hvis du ikke vil skrive, bruker du stemmen: trykk på Bygg med stemme i hovedmenyen og si deretter en kommando. Kommandoer du kan si: "Buat proyek kalkulator", "Bangun proyek Kalkulator", "Buka proyek Kalkulator", "Jalankan proyek Kalkulator", "Daftar proyek", "Buka ikon", "Kembali" og "Bantuan". Appen svarer med stemme og tekst, slik at den fortsatt kan brukes uten å se på skjermen. Talegjenkjenning bruker telefonens innebygde talegjenkjenningsapp (gratis; den kan fungere offline hvis den indonesiske språkpakken er installert). Hvis telefonen ikke har talegjenkjenning, kan kommandoene skrives i tekstboksen på samme skjerm.

AI-appbygger
Skriv eller dikter appen du ønsker på skjermen AI-appskaper, for eksempel: «en notatapp med en lagringsknapp». Appen analyserer nøkkelordene inne i telefonen (uten internett, uten kostnad) og lager deretter et ekte prosjekt fra den best matchende malen: kalkulator, notater, oppgaveliste, nettkalkulator, profilsnettsted eller teller. Hvis beskrivelsen din ennå ikke har en matchende mal, lager appen et tomt prosjekt og sier det ærlig — den later ikke som om den forstår. Et prosjekt laget av AI kan åpnes direkte i Håndter prosjekt.

Direkte forhåndsvisning til en venns telefon
For å vise et prosjekt til en venn før det bygges: i Håndter prosjekt, trykk lenge på prosjektnavnet og velg deretter Forhåndsvisning på venns mobil. Appen lager en liten forhåndsvisningspakke som inneholder prosjektets hovedfiler (index.html, MainActivity eller main.py) pluss LES-MEG.txt med instruksjoner og info.txt. Pakken sendes som en ZIP via WhatsApp eller Telegram. Mottakeren kan åpne forhåndsvisningen direkte: HTML-sider åpnes i nettleseren, Java/Kotlin/Python-kode leses som tekst.

Prosjektmarked
Prosjektmarkedet inneholder innebygde eksempelprosjekter som kan installeres i prosjektmappen med ett trykk: Kalkulator, Notater, Oppgaveliste, Nettkalkulator, Profilsnettsted, Teller, Digital klokke og Nettquiz. Nettmarkedet (last ned eksempler fra internett) finnes ennå ikke, så dette markedet inneholder eksempler som allerede finnes i appen. Et installert prosjekt kan åpnes og endres i Håndter prosjekt som et prosjekt du laget selv.

Direkte samarbeid
For å arbeide med et prosjekt sammen med en venn: åpne Samarbeid i hovedmenyen, velg prosjektet, skriv en endringsnotat (hva som ble endret) og trykk deretter på Del for samarbeid. Prosjektet sendes som en ZIP sammen med en CATATAN.txt-fil inni. Vennen din arbeider med det og sender ZIP-filen tilbake; du trykker på Motta svar, leser først endringsnotatet og velger deretter Bruk for å skrive over det gamle prosjektet eller Avbryt hvis du angrer. En ZIP uten CATATAN.txt er ikke en samarbeidspakke — for en vanlig prosjekt-ZIP, bruk Importer prosjekt i Håndter prosjekt.

Automatisk appoversetter
For å oversette teksten i en app til et annet språk: åpne Appoversetter i hovedmenyen, velg prosjektet og målspråket (engelsk, arabisk eller javanesisk) og trykk deretter på Oversett. Ordboken finnes allerede inne i telefonen (uten internett, uten kostnad) og inneholder vanlige hverdagsord; tekst fra strings.xml, layout og kode leses og oversettes deretter. Resultatet skrives til mappen values-språk/strings.xml (hvis prosjektet har en strings.xml) og en oversettelse-språk.txt-rapport i prosjektmappen. Ord som ennå ikke finnes i ordboken blir stående som de er og rapporteres — slik at du vet hvilke ord du fortsatt må oversette selv.

Spillmaker uten kode
For å lage et spill uten å skrive kode: åpne Spillskaper uten kode i hovedmenyen, velg spilltype (Gjett tallet, Quiz eller Fang stjernen), fyll inn spillnavn, mengde (nivåer/spørsmål/stjerner) og vinningsmelding og trykk deretter på Lag spill. Spillet lages som et ekte prosjekt som kan kjøres direkte i Håndter prosjekt og bygges til en APK som alle andre prosjekter.

Automatisk apptesting
For å sjekke et prosjekt før det bygges: i Håndter prosjekt, trykk lenge på prosjektnavnet og velg deretter Automatisk test. IDE-en sjekker 10 ting uten å bygge en APK — obligatoriske filer finnes (prosjektdatafil, manifest, hovedfil, layout, strenger), pakkenavn og versjon, brukte tillatelser, ikon og balanse i kodeparenteser. Resultatet vises per post (BESTÅTT/IKKE BESTÅTT med en melding) og leses opp av Jieshuo. Fiks først alt som IKKE BESTOD og trykk deretter på Bygg prosjekt.

AI-kodekontroll
For å sjekke prosjektkode for mønstre som ofte forårsaker problemer: åpne Sjekk kode i hovedmenyen, velg prosjektet og trykk deretter på Sjekk kode. Sjekkeren kjører inne i telefonen (uten internett) og leter etter ubrukte variabler, tomme funksjoner, åpenbart uendelige løkker, tekst skrevet direkte i koden (bedre i strings.xml), farlige tillatelser og API-er, TODO/FIXME-markører og dynamisk kjøring. Hvert funn inneholder filnavn, linjenummer og forslag til tiltak. Denne sjekkeren er mønsterbasert, ikke ekte AI — problemer som ikke følger et mønster kan fortsatt slippe gjennom.

Interaktiv læringsmodus
For å lære å lage apper trinn for trinn: åpne Læringsmodus i hovedmenyen. Det finnes 5 leksjoner: Lag ditt første prosjekt, Legg til en knapp, Endre farge, Legg til lyd og Bygg en APK. Trykk på en leksjon for å lese forklaringen og øvingsoppgaven, gjør oppgaven og trykk deretter på Sjekk oppgaven — IDE-en sjekker virkelig om oppgaven er gjort (ved å skanne prosjektet og APK-en på telefonen). Leksjoner som består markeres som ferdige og lagres.

Skysynkronisering
For å sikkerhetskopiere et prosjekt til skyen: åpne Skysynkronisering i hovedmenyen. En lokal sikkerhetskopi lagrer prosjekt-ZIP-en til mappen Download/cloud med et tidsstempel og kan gjenopprettes når som helst fra sikkerhetskopilisten. En GitHub-sikkerhetskopi laster opp prosjekt-ZIP-en til din private repo (med token fra GitHub-innstillinger) og kan lastes ned igjen. Dette er manuell sikkerhetskopiering og gjenoppretting — full automatisk toveis synkronisering trenger en server, så den finnes ennå ikke.

Automatisk backend-skaper
For å lage en backend uten å skrive serverkode: åpne Backend-skaper i hovedmenyen, velg backend-type (Notater, Oppgaveliste eller Oppslagstavle), fyll inn prosjektnavnet og trykk deretter på Lag backend. IDE-en lager et ekte HTML-prosjekt med en skjemaside og en dataliste som lagres i telefonens lokale lagring (localStorage) — data lagres og kan leses igjen når appen kjøres. Denne backenden kjører på en telefon; to telefoner kan ennå ikke dele samme data fordi det ikke finnes en internettserver.

Automatisk temadesigner
For å gi et prosjekt et fargetema: åpne Temadesigner i hovedmenyen, velg prosjektet og temaet (Lyst, Mørkt, Blått, Grønt, Rødt eller Lilla). Forhåndsvisningen viser temaets seks farger (primær, mørk primær, aksent, bakgrunn, tekst, sekundær tekst) og leses opp av Jieshuo. Trykk på Bruk tema — IDE-en skriver colors.xml og styles.xml (app_theme-stil) til prosjektet, som brukes direkte når prosjektet kjøres eller bygges.

Animasjonsmaker
For å gi et prosjekt animasjon: åpne Animasjonsskaper i hovedmenyen, velg prosjektet, animasjonstype (Fade, Gli, Roter, Sprette eller Pulsere), varighet (100 til 10000 millisekunder) og mål (knapp, tekst eller bilde) og trykk deretter på Lag animasjon. IDE-en skriver en ekte animasjonsfil (res/anim/anim_<type>.xml for Java/Kotlin/Compose-prosjekter, eller animasi.css for HTML-/nettstedsprosjekter) sammen med eksempelkode for bruk som vises på skjermen.

Handlingsopptaker
For å gjenta arbeid automatisk: IDE-en spiller inn handlinger som utføres (åpne et prosjekt, kjøre, bygge, eksportere, sikkerhetskopiere, lage et prosjekt, lagre en fil). Åpne Handlingsopptaker i hovedmenyen for å se listen over innspilte handlinger med planen deres og trykk deretter på Spill av igjen — IDE-en kjører handlingene som kan automatiseres igjen (sikkerhetskopiere og lage prosjekt kjøres på stedet; kjøre, bygge og eksportere åpner hovedskjermen sin; åpne og lagre åpner redigereren). Handlinger som ikke kan automatiseres hoppes over og rapporteres til slutt.

Automatisk sikkerhet
For å sjekke et prosjekts sikkerhet: åpne Automatisk sikkerhet i hovedmenyen, velg prosjektet og trykk deretter på Sjekk sikkerhet. IDE-en sjekker 8 ting lokalt (uten internett): farlige tillatelser (posisjon, SMS, samtaler, kamera, mikrofon, kontakter), sending av data via HTTP, sending av SMS, utgående samtaler, et passord eller en nøkkel skrevet direkte i koden, en WebView uten beskyttelse, en komponent eksportert uten tillatelse og en http-adresse uten kryptering. Hvert funn får nivået SIKKER, ADVARSEL eller FARE med et forslag til tiltak, og sammendraget leses opp av Jieshuo.

AI frakoblet
For å bruke tekst- og kodehjelpemidler uten internett: åpne AI offline i hovedmenyen. Det finnes 4 verktøy: Korriger tekst (store bokstaver, skilletegn og doble mellomrom), Oppsummer tekst (tar de 3 viktigste setningene), Lag appnavn (fra den skrevne beskrivelsen) og Foreslå variabelnavn (leter etter 1–2 bokstavs variabelnavn i prosjektet). Disse er enkle regler inne i telefonen, ikke en ekte AI-modell. Resultatet av tekstkorrigeringen kan brukes på prosjektets strings.xml med knappen Bruk.

Widget- og bakgrunnsbygger
For å lage en widget for hjemmeskjermen: åpne Widgeter og bakgrunn i hovedmenyen, velg prosjektet, fyll inn widgetteksten og trykk deretter på Lag widget. IDE-en skriver WidgetSaya.java, widgetlayout, widgetinfo og legger til en mottaker i prosjektets AndroidManifest.xml — bygg prosjektet og installer deretter widgeten fra telefonens hjemmeskjerm. For en bakgrunn: fyll inn teksten og bakgrunns- og tekstfargene, lag en forhåndsvisning og lagre den deretter som en PNG til mappen Download eller sett den direkte som telefonbakgrunn.

Integrasjon med sosiale medier
For å legge til delingsknapper i en app: åpne Integrasjon med sosiale medier i hovedmenyen, velg prosjektet og legg deretter til deling til WhatsApp, Facebook eller Telegram (eller alle tre samtidig). IDE-en skriver ekte delingskode til prosjektets hovedfil (MainActivity eller index.html). Knappen Delingstest åpner delingsvelgeren fra IDE-en med en eksempeltekst, slik at flyten kan kjennes før appen bygges.

App fra bilde
For å lage en galleriapp fra et bilde: åpne App fra bilde i hovedmenyen og velg et bilde fra galleriet. IDE-en analyserer bildets størrelse og dominerende farge og lager deretter et ekte galleriappprosjekt: bildet kopieres til prosjektets assets, temafargen tas fra bildets dominerende farge og appnavnet tas fra bildefilens navn. Åpne Håndter prosjekt for å kjøre eller bygge den galleriappen.

Interaktiv terminal (VT-tolker)
For å bruke interaktive programmer i Terminal: åpne Terminal i hovedmenyen og kjør deretter nano, vim, top eller htop. Terminalen bruker nå en VT-tolker (et rutenettskjerm med 24 rader x 80 kolonner) slik at disse programmene vises korrekt — markøren beveger seg, linjer slettes og skjermen endres som i en ekte terminal. Det finnes spesielle knapper for Tab, Opp-pil, Ned-pil og Esc for å styre interaktive programmer. Utdata er fortsatt tekst som Jieshuo kan lese; trykk på Les opp skjermen for å høre den siste linjen.

Terminal Exec (appbinær)
For å kjøre en binærfil i appmappen (for eksempel aapt2, ECJ, D8) fra Terminal: skriv kommandoen som vanlig. IDE-en bruker libkautsarexec.so slik at binærfiler i appmappen kan kjøres på Android 10 og nyere. Trykk på Exec-test i Terminal for å sjekke om den binære exec-banen fungerer på denne telefonen — resultatet vises som det er. Hvis exec blokkeres av systemet, kjører systemkommandoer og shellskript fortsatt; kjør binærfilen via menyen Bygg prosjekt i stedet.

Terminal holdes i live (KeepAlive)
For å holde skallet i gang når du bytter skjerm: åpne Terminal, kjør en kommando og trykk deretter på Tilbake eller bytt til en annen skjerm — skallet dør IKKE, og Terminal-varselet fortsetter å vises slik at du kan komme tilbake med ett trykk. Kommandoer som er kjørt lagres i historikken (Historikk-knappen eller opp-/nedpilene i kommandofeltet) og kommandoer som brukes ofte kan lagres som favoritter (Favoritter-knappen). Trykk på Lukk skallet når du er ferdig, slik at skallet virkelig avsluttes. Det finnes også en knapp for Bygg i terminalen i prosjektmenyen og i redigerermenyen: Terminal åpnes i prosjektmappen med byggekommandoen allerede fylt inn.

Installer terminalverktøy (prøveversjon)
En funksjon som fortsatt testes: i Terminal finnes en knapp for Installer terminalverktøy for å installere et Termux-miljø fra speilet i utviklerens alat-termux-repo (github.com/syudat/alat-termux), som en annen vei utenom knappen Installer Termux som henter fra den offisielle Termux-utgaven. Speilets innhold er nøyaktig det samme som den offisielle utgaven og kontrolleres med SHA-256 under installasjonen. Når miljøet er installert, kan kommandoene pkg update og pkg install brukes, og ytterligere verktøy fra repoet installeres også i terminalen: info-terminal for å se miljøinformasjon, bersih-terminal for å tømme cache og cadangkan-proyek for å arkivere prosjektmappen til en enkelt datert tar.gz-fil. Deretter installerer appen automatisk de grunnleggende Linux-pakkene (git, python, curl, wget, nano, openssh, zip, unzip) og APK-byggeverktøyene med signering (openjdk-21, kotlin, gradle, ecj, aapt2, d8, apksigner, clang, cmake, ninja, make) fra det offisielle Termux-repoet, slik at terminalen straks er klar til å bygge apper. Nedlasting av store pakker (hundrevis av MB) kan ta lang tid. Mens installasjonen kjører, vises framdrift og kommandoutdata på Terminals hovedskjerm, og sluttresultatet leses opp av skjermleseren. Hvis pakkeinstallasjonen ennå ikke er ferdig, trykker du på Installer terminalverktøy igjen for å fortsette.

Full stemmemodus
For å styre IDE-en helt med stemme: åpne Full stemmemodus i hovedmenyen og trykk deretter på Start lytting. IDE-en lytter kontinuerlig — det er ikke nødvendig å trykke på en knapp for hver kommando — kjører kommandoen og svarer med stemme. Det finnes 26 kommandoer: lag, bygg, åpne, kjør, list, søk, slett, test, sjekk, eksporter, sikkerhetskopier, del, lag ikon, oversett, bygg i terminalen, les skjerm, åpne alle skjermer (inkludert sikkerhet, offline-AI, widget, sosiale medier, spill, læring, sky, backend, tema, animasjon, opptaker), tilbake, lukk og hjelp. Hvis modusen forlates aktivt, fortsetter lyttingen automatisk når denne skjermen åpnes igjen. Trykk på Stopp lytting for å slå av modusen. Hvis telefonen mangler talegjenkjenningstjeneste, kan kommandoer fortsatt skrives i tekstboksen.

Kodeoversetter
For å oversette kode mellom språk uten internett: åpne Kodeoversetter i hovedmenyen, velg prosjektet, velg kildefilen (.java/.kt) og velg deretter retning: Java til Kotlin. Trykk på Oversett — resultatet vises sammen med en rapport over linjer som ikke kan oversettes (disse linjene beholdes som de er og markeres). Trykk på Lagre resultatet for å skrive en NY fil (navn-oversettelse.java/.kt) i samme mappe; originalfilen skrives aldri over. Dette er en mønsterregeloversetter, ikke en kompilator — sjekk alltid resultatet før det brukes.

Git i appen
For å bruke Git i IDE-en uten Termux: åpne Git i appen i hovedmenyen, velg prosjektet og trykk deretter på Lag Git-repo for å lage et lokalt repo (.git) i det prosjektet. Trykk på Sjekk status for å se nye, endrede eller slettede filer sammenlignet med den siste committen; fyll inn commitmeldingen og trykk deretter på Commit for å lagre et øyeblikksbilde av prosjektet; trykk på Vis commit-logg for å se commit-historikken. Push til GitHub og Pull fra GitHub bruker øyeblikksbilder via GitHub-token (repot pembuat-aplikasi-build) — ikke git-protokollen. Clone, Push (system-git) og Pull (system-git) kjøres bare når git-binæren er installert på telefonen (vanligvis ikke). Dette er ikke fullstendig git: ingen merge, branch eller diff — hver commit lagrer et fullstendig ZIP-øyeblikksbilde av prosjektet.

Annonsemaker
For å legge til annonser i en bygget app: åpne Annonseskaper i hovedmenyen, velg prosjektet, leverandøren (AdMob, Unity Ads eller AppLovin) og annonsetypen (Banner, Interstitial eller Belønnet). Fyll inn annonsenhets-ID hvis du allerede har en — tomt betyr at test-ID brukes (AdMob bruker Googles offisielle test-ID; Unity bruker et eksempel-Game ID; AppLovin bruker et tomrom). Trykk på Lag annonsekode for å se Java- og Kotlin-kode og veiledningen; trykk på Lagre til prosjekt for å skrive alt til filen annons-<leverandør>-<type>.txt i prosjektet. Dette er en kodemal + veiledning, ikke en annons-SDK — SDK-et er ikke inkludert i IDE-en; ekte annonser vises først når du oppretter en leverandørkonto, oppretter en annonsenhet, limer inn din egen enhets-ID og legger til SDK-avhengigheten i prosjektets build.gradle.

Barnemodus
For å bruke IDE-en sammen med et barn: åpne Barnemodus i hovedmenyen. Skjermen er forenklet med store knapper og har bare 4 sikre handlinger: Lag prosjekt (fra sikre maler: Kalkulator, Gjett tallet, Quiz, Fang stjernen), Åpne prosjekt, Kjør og Læringsmodus. Det finnes ingen knapp for å slette, eksportere, sikkerhetskopiere eller stille inn token på denne skjermen. Ved første inngang oppretter du en 4-sifret PIN — den PIN-koden bruker forelderen for å forlate Barnemodus (knappen Avslutt barnemodus eller knappen Tilbake). Denne PIN-koden er et lett vern for små barn, ikke ekte sikkerhet.

Appmaker for Wear OS og TV
For å lage en klokkeapp (Wear OS) eller TV-app (Android TV): åpne Wear OS og TV i hovedmenyen og velg mål (Wear OS, Android TV eller begge). Fyll inn prosjektnavnet og trykk deretter på Lag nytt Wear/TV-prosjekt — IDE-en oppretter et Java-prosjekt og tilpasser det deretter — eller velg et eksisterende prosjekt og trykk deretter på Bruk på dette prosjektet. Tilpasninger: uses-feature i manifestet, kategorien LEANBACK_LAUNCHER + banner for TV og den tilpassede layouten activity_main.xml (Wear: liten skjerm; TV: stor skjerm som passer D-pad). Den fullstendige forklaringen skrives til wear-tv.txt i prosjektet. Dette er en prosjektmal — bygging + testing trenger fortsatt en Wear OS- eller Android TV-enhet/emulator; TV-banneret (banner.png 320x180) opprettes ikke automatisk, det må legges til selv (for eksempel via Ikonskaper).

Prosjektkart
For å se strukturen for et prosjekt: åpne Prosjektkart i hovedmenyen, velg prosjektet og trykk deretter på Vis kart — IDE-en viser listen over mapper og filer med størrelsene deres, total størrelse, størrelse per filtype og viktige filer (hovedfil, manifest, layout, strenger, ikon, nettside). Trykk på Lagre peta-proyek.txt for å skrive samme kart til prosjektets rot. Mappen bin/ (byggeresultat) og .git/ (lokalt repo) er ikke med i kartet fordi innholdet deres kan gjenskapes.

Kalkulator for APK-størrelse
For å anslå størrelsen på den bygde APK-en før du bygger: åpne APK-størrelseskalkulator i hovedmenyen, velg prosjektet og trykk deretter på Beregn estimat. IDE-en viser detaljer per kategori (kode/DEX, ressurser, eiendeler, innebygde biblioteker, manifest + resources.arsc, overhead), total estimat, de 5 største filene og forslag til å krympe (for eksempel store bilder reduseres i oppløsning, store lyder klippes i lengde). Dette er et ESTIMAT, ikke en nøyaktig størrelse — den virkelige størrelsen kan avvike på grunn av aapt2-komprimering, fjerning av ubrukt kode (R8) og byggeresultatets ressurser.

APK-analysator
For å lese innholdet i en ferdig APK (som APK-analysatoren i Android Studio): åpne APK-analysator i hovedmenyen, velg prosjektet og trykk deretter på Analyse av bygget APK. IDE-en leser den nyeste APK-en i det prosjektets bin-mappe og rapporterer pakkenavn, versjon, laveste og mål-SDK, listen over brukte tillatelser, antall dex-filer, størrelsesdetaljer per del (programkode, ressurser, eiendeler, innebygde biblioteker, signatur) og de 10 største oppføringene. Nyttig for å vite hvilken del som gjør APK-en stor og hvilke tillatelser den bygde appen bruker.

Forhåndsvisning av skjermstørrelse
For å sjekke et prosjekts utseende på mange skjermstørrelser samtidig (som i Android Studio): åpne Forhåndsvisning av skjermstørrelse i hovedmenyen, velg prosjektet og trykk deretter på Sjekk skjermstørrelse. IDE-en leser alle prosjektets layouter og rapporterer elementer hvis bredde er skrevet fast (for eksempel 400dp) og overskrider skjermbredden 320, 360, 411 eller 480 dp, fordi et slikt element på en telefon med liten skjerm kan dekkes over eller renne over. Elementer med bredden match_parent eller wrap_content tilpasser seg automatisk til skjermen og trenger ikke sjekkes.

Ressursforvalter
For å se og håndtere alle ressurser i et prosjekt på ett sted (som Ressursbehandleren i Android Studio): åpne Ressursbehandler i hovedmenyen, velg prosjektet og trykk deretter på Vis ressurser. IDE-en rapporterer antall filer og størrelse per kategori (drawable, layout, values, mipmap og andre), innholdet i strings.xml, colors.xml og styles.xml. Fra samme skjerm kan en ny streng legges til i strings.xml og en ny farge i colors.xml ved å fylle inn navn og verdi — navnet kontrolleres og dubletter avvises, slik at XML-filen ikke skades.

Lett ytelsesmonitor
For å overvåke RAM- og prosessorbruken for en app som kjører (som Profiler i Android Studio, lett versjon): åpne Lett ytelsesovervåker i hovedmenyen, kjør først appen du vil sjekke (for eksempel den bygde appen som testes), fyll inn pakkenavnet — eller velg et prosjekt og trykk deretter på Fyll inn pakkenavn fra prosjekt — og trykk deretter på Start overvåking. Hvert andre sekund registrerer IDE-en den appens RAM (PSS) og CPU sammen med telefonens ledige RAM; trykk på Stopp for å se et sammendrag av gjennomsnitt og topp. Ingen ekstra tillatelse. I nye Android-versjoner er lesetilgangen til en annen apps prosessor begrenset av systemet, så hvis CPU ikke kan leses, sier rapporten det som det er og RAM-overvåkingen fortsetter.

Tilgjengelighetsrevisjon
For å sjekke om en prosjektlayout er skjermleservennlig (TalkBack/Jieshuo) før utgivelse: åpne Tilgjengelighetsrevisjon i hovedmenyen, velg et prosjekt og trykk deretter på Last inn layoutliste og velg en layoutfil. IDE-en leser XML-filen og rapporterer knapper uten etikett med linjenumrene deres, etiketter som brukes gjentatte ganger og elementer som overlapper hverandre, og bygger deretter et transkript av fokusrekkefølgen slik Jieshuo leser den høyt. Hvis en knapp mangler etikett, fyller du inn etiketten og trykker deretter på Sett inn etikett automatisk — etiketten skrives inn i layoutfilen som contentDescription. Denne kontrollen leser bare layout-XML; Compose-visninger og ferdige APK-er skannes foreløpig ikke.

Krasjobduksjon
For å finne ut hvorfor appen lukker seg selv fra en krasjlogg med en unik ID: åpne «Krasjobduksjon» i hovedmenyen, velg krasj-ID-en fra logglisten, og trykk deretter på «Kontroller». IDE-en matcher klassen og linjenummeret i loggen mot prosjektkilden og forklarer årsaken på indonesisk (for eksempel tom referanse, ennå ikke bedt om tillatelse, eller JSON-feil), med et kodepatchforslag. Trykk bare på «Bruk lapp» når kildelinjen fortsatt er som den var da krasjen skjedde; hvis den er endret, avvises lappen og IDE-en ber deg kontrollere selv. For krasj i den bygde appen, trykk på «Injiser krasjfanger i prosjektet» og bygg deretter APK-en som vanlig: den bygde appen fanger sine egne krasj og skriver loggen på telefonen, og den loggen kan finnes med knappen «Finn bygd app-krasjlogg». Ærlig begrensning: å kopiere loggen til den offentlige Download-mappen på Android 11 og nyere kan mislykkes uten tillatelsen for tilgang til alle filer.

Transpiler mellom paradigmer
For å konvertere enkel Java-kode til Kotlin, eller en enkel XML-layout til Compose-kode: åpne Transpiler mellom paradigmer i hovedmenyen, velg et prosjekt og en fil og trykk deretter på Forhåndsvisning. IDE-en viser konverteringsresultatet som tekst — sjekk det først, for linjer den ikke kjenner igjen blir stående som de er, og ordet static i Java droppes i Kotlin (sjekk betydningen før du bruker det). Konvertering fra XML til Compose endrer bare tekst, hint og retning — størrelse, farge og andre attributter er foreløpig ikke med. Hvis resultatet er riktig, trykker du på Bruk på fil for å skrive målfilen; kildefilen endres ikke. Bare trygge, vanlige mønstre konverteres.

Lokal mikroserver
For å teste en app som trenger en server uten internett: åpne «Lokal mikroserver» i hovedmenyen, skriv rutedefinisjoner (for eksempel GET /halo etterfulgt av JSON-svaret), og trykk deretter på «Start server». IDE-en kjører en liten HTTP-server på samme telefon (bare HTTP, ingen TLS, for samme Wi-Fi-nettverk) og logger hver forespørsel og svar på skjermen. Ruter kan bruke parametere som {nama} og en enkel API-nøkkel. Serveren kan også pakkes i den bygde APK-en: trykk på «Pakk server i prosjektet», og serverkilden, ressursene og manifestet injiseres i prosjektet, slik at den bygde appen selv blir serveren når den kjører. Serveren i IDE-en stopper når skjermen lukkes.

Sikkerhetsrevisor
For å kontrollere prosjektkoden for sikkerhetshull før publisering: åpne «Sikkerhetsrevisor» i hovedmenyen, velg prosjektet, og trykk deretter på «Start skanning». IDE-en skanner prosjektkoden, manifestet og konfigurasjonen, og rapporterer funn fra høy til lav risiko — en API-nøkkel som er igjen åpen i koden, en komponent som er eksponert uten tillatelse, en WebView som aktiverer JavaScript med JavaScript-grensesnittet, svak krypto (MD5, SHA1, DES), en http-adresse uten TLS, og et passord skrevet direkte i koden — med filene og linjenumrene deres. For funn hvis utbedring er trygg (for eksempel endre MD5 til SHA-256 eller http til https), trykk på «Bruk utbedring»; for API-nøkler og passord viser IDE-en bare utbedringsforslaget, fordi erstatningen må bestemmes av utvikleren selv. Skanningen analyserer nå også ekte DEX-bytekode inne i den bygde APK-en (ikke bare tekstmønstre i koden), slik at kalte farlige API-er og hemmeligheter innebygd i DEX også fanges; hull som ikke følger et mønster kan fortsatt unnslippe skanningen — kontroller før du bruker.

Grensesnittstestrobot
For å teste en appskjerm automatisk via tekstscenarier: åpne «Grensesnittstestrobot» i hovedmenyen, velg prosjektet, og trykk deretter på «Opprett scenario automatisk». IDE-en leser prosjektmanifestet og oppsettet og skriver scenariet som teksttrinn (trykk på knapp, fyll ut felt, vent, gå tilbake). Trykk på «Kjør tørrkjøring» for å se scenariets kjøringslogg med tidsstemplene — denne tørrkjøringen er fortsatt bare en simulering av sekvensen. For ekte testing, trykk på «Injiser testagent i prosjektet»: IDE-en injiserer testagenten med scenarieressurser i prosjektet; bygg APK-en som vanlig, installer den, og åpne deretter ikonet «Test» — agenten kjører inne i den bygde appen og trykker virkelig på knapper, fyller ut ekte felt, og ruller, og viser deretter rapporten med ekte krasj som ble fanget på skjermen. For å fjerne agenten igjen, trykk på «Fjern testagent fra prosjektet». Agenten kjører inne i appens egen prosess, så den trenger ingen tilgjengelighetstjeneste eller systemautomatisering.

Tidsreise i kode
For å sette et prosjekt tilbake til en tidligere kodetilstand uten å skrive Git-kommandoer: åpne Tidsreise i kode i hovedmenyen, velg et prosjekt, fyll inn en etikett for tidspunktet (den kan stå tom) og trykk deretter på Spill inn tidspunkt. IDE-en lagrer en kopi av prosjektets kildefiler sammen med hashverdiene deres i mappen .riwayat inne i prosjektet. Tidspunktlisten viser dem alle; velg to punkter og trykk deretter på Sammenlign for å se filer og funksjoner som er lagt til, endret eller fjernet. Trykk på Gjenopprett for å hente tilbake en gammel tilstand — før gjenoppretting lager IDE-en alltid først en sikkerhetskopi av den nåværende tilstanden, så ingenting går tapt. Trykk på Opprett eksperimentkopi for å kopiere prosjektet til en ny mappe og prøve endringer uten å forstyrre det opprinnelige prosjektet. Bare kildefiler spilles inn.

Modulfabrikk
For å pakke en del av et prosjekt som en modul som et annet prosjekt kan bruke: åpne Modulfabrikk i hovedmenyen, velg et kildeprosjekt, kryss av for de skjerm-, klasse-, streng- og tillatelsesfilene som skal pakkes og trykk deretter på Pakk som modul. IDE-en skriver et ZIP-arkiv sammen med JSON-metadata (modulnavn, versjon, strenger og tillatelser som er brukt). For å installere en modul i et annet prosjekt, åpner du Modulfabrikk, velger målprosjektet og trykker deretter på Installer modul og velger modulens .zip-fil — sammenslåingen legger til strenger og tillatelser uten å overskrive eksisterende kode, og slår ikke sammen en fil hvis navnet allerede brukes i målprosjektet. En modul tar verken med seg biblioteker eller bygginnstillinger.

Polymorft skjold og ressurshvelv
For å gjøre identifikatornavn tilfeldige og kryptere prosjektressurser før publisering: åpne «Polymorft skjold og ressurshvelv» i hovedmenyen, velg prosjektet, og trykk deretter på «Gjør navn tilfeldige og krypter ressurser». IDE-en skanner klasse- og metodenavn i kildekoden, lager et tilfeldig navnekart, skriver disse navnene om inne i de kompilerte DEX-filene (erstatningsnavnene lages like lange som originalene slik at alle forskyvninger forblir gyldige, deretter beregnes DEX-hodets sjekksum og SHA-1-signatur på nytt), krypterer prosjektressursfiler med AES-GCM i mappen brankas-aset inne i prosjektet, og lagrer et kryptert gjenopprettingskart (perisai-peta.brankas) slik at de opprinnelige navnene kan gjenopprettes når krasjlogger leses. Krypteringsnøkkelen avledes nå fra utviklerens passord med PBKDF2, 20 000 iterasjoner, ikke fra prosjektnavnet. Navn som også brukes som ren tekst, merknadsnavn og feilsøkingsnavn skrives bevisst ikke om, og innsettingspunktene for DEX-omskriving i byggestien venter fortsatt på testing på en ekte telefon.

Tillitskjede og miljøvokter
For å kontrollere signaturnøkkelkjeden og telefonens miljø før publisering: åpne «Tillitskjede og miljøvokter» i hovedmenyen, velg prosjektet, og trykk deretter på «Kontroller kjede og miljø». IDE-en bygger en nøkkelkjede på 5 generasjoner fra prosjektets pakkenavn og kontrollerer dens integritet, kontrollerer ekte minneintegritet ved å sammenligne innholdet i kodesegmentene i minnet med filene på disken og rapporterer navnløse kjørbare (RWX) tilordninger, fremmede biblioteker og memfd-tilordninger, og skanner deretter sitt eget prosessminnekart og enhetsegenskaper etter spor av Frida, Xposed eller emulator. Hvelvnøkkelen pakkes inn med en AES-nøkkel i AndroidKeyStore som bruker maskinvarens sikkerhetsbrikke når den finnes, og nøkkelrotasjon er nå ekte med skjema v3-signatursertifikatlinje: den gamle nøkkelen signerer beviset på rotasjon til den nye nøkkelen, og APK-en signeres på nytt med den linjen. Resultatet er et risikonivå «sikker», «forsiktig» eller «farlig» med tekstbevis. Hvis systemet nekter minnelesing, rapporteres kontrollen som «kan ikke verifiseres», ikke sikker; og om en nøkkel virkelig bruker maskinvarens sikkerhetsbrikke kan bare bekreftes på en ekte enhet.

Teksttre-layoutarkitekt
For å utforme en skjerm uten å se den: åpne «Teksttre-layoutarkitekt» i hovedmenyen, velg prosjektet og layoutfilen, og trykk deretter på «Kontroller oppsett». IDE-en leser XML-oppsettet som et teksttre og leser hver elementposisjonsbeskrivelse høyt (for eksempel nederst til høyre, 45 prosent av skjermbredden), og rapporterer deretter matematisk overlappinger mellom elementer og elementer som går utenfor skjermen ved 360 dp bredde. Det som nå telles med er LinearLayout og enkle dp-størrelser, full ConstraintLayout (alle begrensninger, bias, kjeder, retningslinjer, hindringer, prosentbredder, 0dp match_constraint og dimensjonsforhold) og Compose-skjermer (Column, Row og Box med deres størrelsesmodifikatorer). Bare MotionLayout og ConstraintSet som endres under kjøring rapporteres fortsatt som ukjent posisjon, fordi verdiene deres bare finnes mens appen kjører.

Designsystemstudio
For å gjøre avstander, skrifter og hjørner ensartede på alle skjermer og prosjekter: åpne «Designsystemstudio» i hovedmenyen, velg prosjektet, skriv designtokens (for eksempel jarak=8, huruf=16, sudut=12), velg en komponent, og trykk deretter på «Generer komponenter». IDE-en validerer tokens — grunnleggende avstand 4 til 16 dp, grunnleggende skrift 12 til 20 sp, hjørner 0 til 32 dp, og minste berøringsområde 48 dp — og skriver deretter ferdige XML-komponenter (komponen-studio.xml) med et XML-tema (tema-studio.xml) og et Compose-tema (tema-studio.kt) i prosjektmappen. Tokens kan også lagres som et navngitt sett i det delte tokenbiblioteket mellom prosjekter, og én enkelt synkroniseringskommando bruker bibliotekets nyeste tokens på alle prosjekter som bruker det settet. Komponenter lages som tekst som limes inn i oppsettet og deretter kontrolleres med «Teksttre-layoutarkitekt»; justeringen til to kolonner på nettbrett bruker skjermbreddekvalifisering i stedet for enhetsidentifikasjon mens den kjører.

Semantisk refaktorering og AST-navigasjon
For å finne definisjoner og endre navn på symboler uten å ødelegge annen kode som tilfeldigvis har samme navn: åpne «Semantisk refaktorering og AST-navigasjon» i hovedmenyen, velg prosjektet, og trykk deretter på «Skann prosjektsymboler» for å se alle klasser og metoder med filene og linjenumrene deres. Skriv symbolnavnet, og trykk deretter på «Skann prosjektsymboler» igjen for å se definisjonen og alle filer som kaller den. For å gi nytt navn, skriv det nye navnet, trykk på «Forhåndsvis omdøping» for å se antall forekomster i hver fil, og trykk deretter på «Bruk omdøping». Indeksen bruker nå en håndbygd AST-parser (lexer og rekursiv parser for en Java- og Kotlin-delmenge), slik at metodeomdøpinger på tvers av filer løses og kallere i andre filer også endres; knappen for å trekke ut en kodeblokk til en ny funksjon er nå på denne skjermen. Denne parseren er fortsatt minimal: svært komplekse generics, parametriserte merknader og anonyme klasser skannes som de er, mens kall via refleksjon og grensesnitt ikke løses.

Steg-for-steg-feilsøker og minneinspektør
For å undersøke variabelinnhold midt i programflyten uten å gjette fra logger: åpne «Steg-for-steg-feilsøker og minneinspektør» i hovedmenyen, velg prosjektet, skriv et kjøringsspor (ett trinn per linje, format linjenummer, kode, deretter variabler og verdier atskilt med |, for eksempel 10|int total = harga * jumlah;|harga=5000, jumlah=3, total=15000), skriv brytpunktlinjenummeret, og trykk deretter på «Kjør feilsøkingsspor». IDE-en kjører til det første brytpunktet og leser den aktive linjen høyt via Jieshuo med variabelverdiene. Trykk på «Gå én linje fram» for å gå én linje framover, trykk på «Gå inn i funksjon» for å gå inn i en kalt funksjon (med kallstakk), eller trykk på «Fortsett programmet» for å gå til neste brytpunkt. Denne sporfeilsøkeren følger fortsatt et innspilt eller håndskrevet spor; ved siden av den finnes en ren Java-klient for JDWP-trådprotokollen som kan håndhilse, sette brytpunkter, gå inn, over og ut, og pause og fortsette VM-en via TCP eller i lyttemodus. Å pause en ekte prosess innenfra en vanlig app er fortsatt ikke fullt mulig, fordi en prosess JDWP-sokkel bare eksponeres via adbd — den beviste veien krever trådløs feilsøking og å starte målet via skallet, noe som ligger utenfor det appen selv kan gjøre.

Frakoblet avhengighetsbehandler
For å bruke tredjepartsbiblioteker uten internett og unngå versjonskonflikter før bygget: åpne «Frakoblet avhengighetsbehandler» i hovedmenyen, velg prosjektet, og trykk deretter på «Kontroller avhengigheter». IDE-en leser alle .gradle-filer i prosjektet, kontrollerer det delte hvelvet mellom prosjekter i mappen Download/brankas-bersama, og løser konflikter — hvis to biblioteker ber om ulike versjoner av samme artefakt, brukes den høyeste versjonen og konflikten rapporteres. For å laste ned et bibliotek, skriv koordinatene (format gruppe:artefakt:versjon, for eksempel com.google.code.gson:gson:2.10.1) og trykk deretter på «Kontroller avhengigheter»: når man er på nett, lastes AAR-, JAR- eller WHL-filer virkelig ned fra Maven, Google eller PyPI med deres transitive avhengighetsgraf (rekursiv, sykluser brytes, dybde opp til 25 nivåer), og bare filer som lastes ned vellykket registreres som tilgjengelige. Når man er frakoblet, kan bare biblioteker som allerede finnes i det delte hvelvet brukes. Maven-versjonsintervaller løses ikke, og nedlastede filer kontrolleres bare med SHA-1, uten PGP-verifisering.

Database- og lagringsinspektør
For å undersøke og teste innholdet i prosjektets database uten å skrive kode som skriver ut tabellinnhold: åpne «Database- og lagringsinspektør» i hovedmenyen, velg prosjektet og databasefilen (.db, .sqlite eller .sqlite3), og trykk deretter på «Åpne database». IDE-en leser skjemaet for alle tabellene med en fullstendig SQLite-sideparser (B-tre med overløpssiders) og viser de første 20 radene som en teksttabell som Jieshuo leser høyt. Skriv en SELECT-spørring og trykk på «Kjør spørring» (for eksempel SELECT nama FROM pengguna WHERE kota = 'Makassar') — spørringer støtter nå JOIN, GROUP BY, ORDER BY og LIKE, og kjøres av den ekte Android SQLite-motoren på telefonen. For å endre en verdi, skriv radnummeret (1 = første rad), kolonnenavnet og den nye verdien, og trykk deretter på «Endre celleverdi» — verdien skrives tilbake til .db-filen. Trykk på «Lagre sikkerhetskopi» for å lagre tabellens nåværende tilstand som en fil <database-navn>.cadangan.txt i prosjektet. SharedPreferences og DataStore kan også leses. Det som ennå ikke kan leses: krypterte databaser, ubekreftede WAL-endringer, og typede verdier i spesialiserte DataStore Proto (vises bare som en generell feltvisning).

Enhetstestfabrikk og fuzzing
For å finne logiske hull før appen deles: åpne «Enhetstestfabrikk og fuzzing» i hovedmenyen, velg prosjektet og kodefilen, og trykk deretter på «Lag og kjør tester». IDE-en leser funksjonssignaturene i filen, lager vanlige og grensetesttilfeller (tom tekst, null, maksimale tall, merkelige tegn), og kjører deretter virkelig disse testene: prosjektkoden kompileres og hver @Test-metode kjøres med en grense på 5 sekunder, slik at resultatet er ekte bestått og mislykket med deres faktiske verdier. Fuzzing kjøres også virkelig på prosjektfunksjoner (via refleksjon, 2 sekunder per kall, maksimalt 20 metoder), og linje-dekningsprosenten beregnes virkelig gjennom instrumentering som bevarer de opprinnelige linjenumrene. Resultatet rapporterer hvor mange tester som besto og mislyktes, hvor mange kodelinjer og funksjoner som ble funnet, og hvilke testtilfeller som ble opprettet. De opprettede testene bruker nøyaktig samme API som JUnit, men merknads- og påstandsdefinisjonene skrives inne i den opprettede testfilen, fordi det ekte JUnit-biblioteket ikke er inkludert i appen.

Simulator for ekstreme enhetsforhold og minnelekkasjerevisor
For å teste appens utholdenhet når systemet dreper prosessen, nettverket brytes, skjermen roteres, eller batterisparing slås på: åpne «Simulator for ekstreme enhetsforhold og minnelekkasjerevisor» i hovedmenyen, velg prosjektet, og trykk deretter på «Kjør simulering». IDE-en kjører tre stresscenarier med simulert skjermrotasjon og sporer objekter som holdes i minnet selv etter at skjermen er lukket, og rapporterer deretter tapt data og lekkende objektkjeder. Lagre- og gjenopprettingstilstanden leses nå fra brukerens egen prosjektkilde, ikke fra et fast eksempel; den lokale loopback-serveren stoppes virkelig midt i testen for å måle nettverksbruddet; en ekte heap-dump tas og analyseres, der to dumper sammenlignes og holde-kjeden spores fra GC-røttene; og appens egen prosess drepes virkelig etter at tilstanden er lagret, deretter kontrolleres hvilke data som kommer tilbake når den åpnes igjen. Det som fortsatt er umulig fra en vanlig app: å slå av telefonens radio eller Wi-Fi og tvangsstoppe andre apper — begge krever systemtillatelse; i stedet drepes bakgrunnsapper via killBackgroundProcesses, hvis tillatelse allerede finnes i manifestet, med en ærlig etikett på skjermen.

Prosjektplantegningsarkitekt
For å gjøre en stor appidé om til en trinn-for-trinn arbeidsplan: åpne «Prosjektplantegningsarkitekt» i hovedmenyen, velg prosjektet, skriv appidéen (for eksempel en liten dagligvarebutikk-kasseapp med avbetaling), og trykk deretter på «Lag plan». IDE-en bygger moduler, en filliste og små milepæler, og lagrer dem deretter som cetak-biru.txt i prosjektmappen. Hver gang en milepæl er fullført, trykk på «Marker neste milepæl som fullført», eller trykk på «Last inn lagret tegning» for å åpne den lagrede planen igjen. Hvis en aktiv AI-leverandør er valgt i «AI-innstillinger» og nøkkelen er tilgjengelig, bygges planen av den leverandøren; hvis nøkkelen mangler eller leverandøren ikke kan nås, faller IDE-en tilbake til offline-nøkkelordmønstre og forteller ærlig om den begrensningen. Leverandørens svar kontrolleres bare for format (moduler og milepæler finnes), ikke for innholdssannhet — gjennomgå alltid planen før du bygger.

Forteller av kodens logiske flyt
For å forstå lang kode uten å lytte til syntaks linje for linje: åpne «Forteller av kodens logiske flyt» i hovedmenyen, velg prosjektet og kodefilen, og trykk deretter på «Kodefortelling». IDE-en gjør hver linje om til en indonesisk setning (for eksempel hvis totalen er over 100000, kjør neste blokk), viser et kallkart mellom metoder og en dataflytanalyse mellom metoder (verdier som sendes videre, brukes eller ignoreres), og markerer subtile potensielle feil med linjenumrene deres — String sammenlignet med ==, en strøm som åpnes uten å lukkes, og en variabel som skrives i to forskjellige metoder. Hvis en aktiv AI-leverandør er valgt i «AI-innstillinger», er også en flytsammendrag fra den leverandøren tilgjengelig; hvis den ikke finnes, bruker skjermen offline-fortellingen og forteller om den begrensningen. Fortellingen, kallkartet og dataflyten bruker offline-tekstmønsteranalyse, ikke en fullstendig AST-parser — metoder hvis åpningsklammer er på sin egen linje, klassefelt, og kall via refleksjon spores ikke — og advarsler om datakapp kan vises for en variabel som faktisk bare brukes vekselvis.

App-pakkefabrikk og Play Store-beredskap
For å forberede en app for Google Play Store direkte fra telefonen: åpne «App-pakkefabrikk og Play Store-beredskap» i hovedmenyen, velg prosjektet, og trykk deretter på «Bygg AAB-pakke». IDE-en bygger .aab-filen fra prosjektmanifestet, ressursene og eiendelene med en ekte BundleConfig.pb, validerer pakkestrukturen, og deler deretter pakken i ekte variant-APK-er (grunnleggende, etter arkitektur, etter språk, og universell) med størrelser målt fra den delingen, ikke estimater. Pakken signeres med JAR v1 med samme prosjektnøkkel som brukes for APK-signering, og signaturkjeden verifiseres kryptografisk. Denne skjermen reviderer også Play-beredskap — mål-SDK under 35 markeres «høy», fordi Play Store krever 35 eller mer, og et manglende 64-biters bibliotek markeres også «høy». Ekte bundletool kan ikke kjøre på enheten, fordi bundletool krever en JVM mens Android ikke har noen JVM; veien over er den nærmeste ekte veien på enheten.

OTA-oppdateringsmotor og trinnvise lanseringer
For å sende en liten rettelse uten å tvinge brukere til å laste ned hele APK-en på nytt: åpne «OTA-oppdateringsmotor og trinnvise lanseringer» i hovedmenyen, velg prosjektet, skriv det gamle og nye versjonsinnholdet, og trykk deretter på «Lag patchpakke». IDE-en beregner forskjellen og oppretter en patchpakke (patch-ota.zip) med det nye innholdets SHA-256-fingeravtrykk, og kontrollerer deretter om denne enheten befinner seg i det første 10 prosent lanseringstrinnet. Patchpakker støtter nå binær delta på enhver fil (inkludert DEX og APK), pakkes med en RSA-2048-signatur og verifiseres med en betrodd offentlig nøkkel før de brukes, og kan lastes ned fra utviklerens server med lanseringslisten; hvis bruken mislykkes, forblir den gamle filen intakt. Å bruke en patch på en kjørende app gjøres ved å signere på nytt med prosjektnøkkelen og PackageInstaller, fordi det er umulig å erstatte koden til en kjørende prosess innenfra seg selv — APK-en er låst og DEX-en er allerede lastet.

Teamkodegjennomgangsstudio
For å gjennomgå en kollegas endringer og løse sammenslåingskonflikter uten å lese Git-piler: åpne «Teamkodegjennomgangsstudio» i hovedmenyen, velg prosjektet, skriv tre tekstversjoner (grunnleggende, lokal, kollega), og trykk deretter på «Åpne teamgjennomgang». IDE-en slår sammen de tre basert på Java-syntaksenheter — to endringer på samme linje, men i ulike setninger, telles ikke lenger som en konflikt — og viser hver konflikt som et stemmevalg: bruk den lokale versjonen, bruk kollegas versjon, eller slå sammen begge — resultatlinjen settes inn på den opprinnelige konfliktposisjonen slik at linjerekkefølgen forblir riktig — og skriver deretter resultatet til gabung-hasil.txt i prosjektet. Nedenfor er prosjektets arbeidsbrett: skriv en oppgavetittel og trykk deretter på «Legg til oppgave»; oppgaver lagres som tekst i .tugas-mappen inne i prosjektet og synkroniseres via commits i Git inne i appen, slik at brettet kan leses på nytt fra hvilken som helst commithistorikk. Denne syntaksdelingen er ikke en fullstendig AST-parser, og Git inne i appen lagrer et fullstendig øyeblikksbilde per commit; det finnes ingen separat synkroniseringsserver.

Diktat av kodestruktur
For å skrive kode med stemmen inne i editoren: åpne et prosjekt i Editoren og trykk deretter på knappen Diktat av kodestruktur. Si kommandoer på indonesisk, for eksempel buat fungsi tambah dengan parameter a angka dan b angka, buat kelas Mobil eller buat variabel teks nama sama dengan Budi — IDE-en gjør talen om til en syntaktisk gyldig Java-, Kotlin-, Python- eller Compose-kodeblokk og setter den inn ved markørposisjonen, og leser deretter opp et kort sammendrag via Jieshuo. Diktering bruker systemets innebygde taleinndatatjeneste, uten ekstra mikrofontillatelse, og gjenkjenner bare allerede registrerte kommandomønstre; tale utenfor disse mønstrene gjøres ikke om til kode. Tall som sies som ord (for eksempel 'lima') gjøres foreløpig ikke om til sifre.

Lokalt samarbeidsrom (uten internett)
For å jobbe sammen i ett rom uten internett: åpne Samarbeid i hovedmenyen og åpne deretter delen Lokalt samarbeidsrom. Én telefon åpner en økt (IDE-en viser en lokal IP-adresse og en 6-sifret PIN), en annen telefon blir med med den adressen og PIN-koden. Tekstendringer sendes som linjeforskjeller, en bygd APK kan sendes til testerens telefon, og krasjrapporter fra testerens telefon mottas tilbake. Én økt er bare for én venn; hvis to personer endrer nøyaktig samme linje samtidig, brukes den siste endringen. PIN-koden sendes som ren tekst på det lokale nettverket. Dette rommet er foreløpig ikke testet på en ekte telefon.

AI-innstillinger
For å sette opp AI-leverandør og API-nøkler for å bygge apper: i hovedmenyen, i innstillingsgruppen, trykk på «AI-innstillinger» (ved siden av knappen «Konnektor»). Velg leverandøren som skal brukes fra den tilgjengelige listen, og kryss av for «Bytt modell ved leverandørfeil» slik at IDE-en automatisk prøver neste modell fra samme leverandør hvis en modell mislykkes. Trykk på «Administrer API-nøkler» for å legge til reservenøkler (skriv navn og nøkkel, og trykk deretter på «Lagre»; nøkler vises maskert, bare de siste 4 tegnene vises). Nøkler lagres på telefonen og sendes aldri noe annet sted enn til den valgte leverandøren når appen bygges. Den valgte leverandøren brukes nå virkelig av «Prosjektplantegningsarkitekt» og «Forteller av kodens logiske flyt»; å bygge en app på skjermen «AI-appbygger» bruker fortsatt lokal AI på telefonen (uten internett).

Konnektor
For å analysere en APK og deretter sende den: trykk i hovedmenyen, i gruppen Innstillinger, på Konnektor (ved siden av knappen AI-innstillinger). Velg en APK-fil fra telefonen, IDE-en leser innholdet (pakkenavn, versjon, liste over aktiviteter) og trykk deretter på Send APK for å sende den via systemets delingsmeny (for eksempel WhatsApp eller Drive).

Språk og stemme
For å endre språket i appen: åpne Innstillinger, deretter Appspråk og velg deretter et språk eller Følg systemet. Hovedskjermen og de fleste skjermer bytter umiddelbart til det valgte språket uten å lukke eller starte appen på nytt; enkelte skjermer (for eksempel Terminal, Samarbeid, AI-innstillinger og Administrer nøkler) bruker fortsatt det gamle språket til de åpnes igjen. Hvis du velger Følg systemet, følger språket telefonens systemspråk.

Standard signatur per prosjekt og Anti Tamper
Siden versjon 5.7 signeres et prosjekt som ikke bruker en personlig signatur med prosjektets egen innebygde nøkkel (opprettet én gang i mappen tanda-tangan-bawaan inne i prosjektet og deretter brukt videre), slik at den innebygde signaturen er forskjellig fra prosjekt til prosjekt — ikke lenger en felles nøkkel for alle apper. Ikke slett mappen tanda-tangan-bawaan: uten den nøkkelen kan en ny APK ikke skrive over den gamle APK-en for samme prosjekt. Hvert prosjekts innstillinger (separat arkitektur, personlig signatur, Anti Tamper, valgt keystore, SDK) lagres nå i filen settings.gradle inne i prosjektet og leses igjen hver gang prosjektet bygges. I Innstillinger, kategorien Signatur, finnes avkrysningsboksen Anti Tamper for bygget app: hvis den er aktiv, kontrollerer den bygde appen på enheten sin signatur og sitt dex-innhold hver gang den åpnes; hvis den er signert om eller endret av noen andre, nekter appen å kjøre. Feilsøkere og injeksjonsverktøy som Frida/Xposed oppdages også, og appvinduet er låst fra skjermopptak.

Demovideomaker
For å lage en demovideo av en bygget app: åpne Demovideoskaper i hovedmenyen, velg prosjektet, fyll inn videotittelen og trykk deretter på Lag demovideomanus — IDE-en skriver video-demo.txt med 5 standardscener (åpning, hovedvisning, funksjon 1, funksjon 2, avslutning) sammen med fortellertekst og hver scenes varighet. Trykk på Lag HTML-lysbildevisning for å lage video-demo.html fra prosjektets bilder (ikon + skjermbilder hvis slike finnes) som byttes automatisk hvert 5. sekund. Dette er IKKE en .mp4-video — for en ekte video, åpne video-demo.html i telefonens nettleser og spill deretter inn skjermen, eller les fortellingen i video-demo.txt mens du spiller inn appen som kjøres.

Ny visning i Android Studio-stil
IDE-ens utseende er nå gjort pent som Android Studio (bare utseendet — alle knapper, menyer og flyter forblir nøyaktig som før): lysegrå bakgrunn, fete svarte skjermtitler, blå knapper med hvit tekst og hvite inndataruter med tynn ramme. Hovedmenyen er visuelt gruppert (Skaperens funksjoner, Sky, Tema og annet, Stemme, Kode og nye funksjoner, Verktøy) uten å endre knappenes rekkefølge. Terminalen bruker fortsatt et mørkt panel som Terminal-vinduet i Android Studio, og koderedigereren har fortsatt hvit bakgrunn og svart tekst. All tekst leses fortsatt tydelig av Jieshuo.

Innstillinger
For å stille inn appen: åpne alternativmenyen på hovedskjermen og trykk deretter på Innstillinger. Inni finnes 12 kategorier: GitHub-innstillinger (sikkerhet, personlig signatur, byggehistorikk og GitHub-token), Innstillinger for APK-bygging på enheten (lagre keystore-passord og byggehistorikk på enheten), Tema (appfarge), Signatur (lag keystore for personlig signatur og avkrysningsboksen Anti Tamper for bygget app), Prosjektmappe (prosjektmappens plassering), Språk og stemme (grensesnittspråk og stemmemodusens talehastighet), Tekststørrelse og utseende (redigererens tegnstørrelse), Bygging (standardmål-SDK og standardarkitekturdeling for skjermen Lag prosjekt), Varsler (lyd når byggingen er ferdig), Automatisk sikkerhetskopi (tidsplan for prosjektsikkerhetskopiering), Utviklerprofil (navn, WhatsApp-nummer og konto som vises på donasjonsskjermen) og Personvern og data (tilbakestill innstillinger og slett appdata). Hver kategori har en knapp for Tilbake til forrige for å gå tilbake til kategorimenyen. Innstillinger som nettopp er lagret (ennå ikke tatt i bruk) forklares ærlig på skjermen.

Doner til utvikleren
For å donere eller hilse på utvikleren: trykk på knappen Doner til utvikleren på hovedskjermen, ved siden av knappen Om verktøyet. På donasjonsskjermen finnes knappen Kopier BRI-konto — trykk på den for å kopiere utviklerens kontonummer og lim deretter inn det i bankappen din. Det finnes også delen Hils på utvikleren på WhatsApp: fyll inn ditt navn og din hjemby og trykk deretter på Send på WhatsApp — WhatsApp åpnes med hilsningsmeldingen allerede fylt inn, trykk bare på Send i WhatsApp og gå deretter tilbake til appen. WhatsApp tillater ikke andre apper å sende meldinger automatisk, så sendingen gjøres fortsatt av deg selv i WhatsApp.

Terminalfavoritter
For å lagre kommandoer som brukes ofte i Terminal: åpne Terminal og trykk deretter på Favoritter. Trykk på Legg til ny favoritt, fyll inn navn (for eksempel Vis fil) og dens kommando (for eksempel ls -la) og trykk deretter på Lagre — favoritten lagres permanent på telefonen. Trykk på favorittnavnet for å kjøre det direkte i terminalen; trykk på Slett favoritt og velg deretter en å slette (med bekreftelse). Det finnes allerede 3 innebygde favoritter: Vis fil (ls -la), Sjekk plass (df -h) og Tøm skjermen (clear) — alle kan slettes. En tom kommando kan verken lagres eller kjøres; Terminal varsler deg med melding og stemme hvis det skjer.

Analyse og kvalitet
For å se et sammendrag av appbruk og krasjrapporter: trykk på knappen Analyse og kvalitet på hovedskjermen, ved siden av knappen Doner til utvikleren. Denne skjermen viser hvor mange ganger appen er åpnet, hvilke skjermer som åpnes oftest, antall krasjer og en liste over de siste krasjene med korte forslag til tiltak. Disse dataene lagres bare på telefonen din og sendes ingensteds. Det finnes en knapp for Slett analysedata med en bekreftelsesdialog for å slette alle disse dataene. Den siste skjermen registreres bare for hovedskjermen og denne skjermen.
