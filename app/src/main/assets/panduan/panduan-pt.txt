Bem-vindo ao Create Aplikasi by Al Kautsar
Create Aplikasi é um aplicativo criador de aplicativos Android que funciona diretamente no telefone, sem precisar de um notebook. Este aplicativo permite que qualquer pessoa crie seus próprios aplicativos Android, incluindo usuários que estão apenas começando a aprender a criar aplicativos e usuários de leitores de tela. O guia completo de uso deste aplicativo está disponível nesta tela Sobre esta ferramenta.

O que é este aplicativo e para quem ele é
Create Aplikasi é uma ferramenta criadora de aplicativos Android que funciona no telefone. Este aplicativo é destinado a qualquer pessoa que queira criar seus próprios aplicativos Android, incluindo iniciantes e usuários de leitores de tela. Este aplicativo oferece um editor de código, um botão Executar para testar projetos, um botão Compilar para criar um APK, e menus para assinar e instalar o APK.

Objetivo deste aplicativo
Este aplicativo foi feito para que qualquer pessoa possa criar seus próprios aplicativos Android com facilidade, diretamente do telefone. Sua interface foi feita o mais simples possível para que até usuários novos possam experimentá-lo imediatamente.

Como criar um novo projeto, passo a passo
1. Toque em Criar projeto no menu principal.
2. Escolha o tipo de projeto: HTML, Site, Java, Kotlin, Compose ou Python.
3. Preencha o nome do aplicativo, por exemplo: Garuda Decode.
4. Preencha o nome do pacote (package name), por exemplo: com.android.garudadecode. O nome do pacote deve usar letras minúsculas e consistir em pelo menos duas partes separadas por pontos.
5. Preencha a versão do aplicativo, por exemplo: 1.0, e um código de versão na forma de número, por exemplo: 1. Se ficar vazio, a versão será preenchida automaticamente com 1.0 e o código de versão 1.
6. Preencha o SDK mínimo e o SDK de destino, se necessário. Se ficarem vazios, os valores padrão serão usados. O SDK mínimo é a versão mais baixa do Android suportada, por exemplo: 21 significa Android 5.0. O SDK de destino máximo é 36 (Android 16).
7. Toque no botão Selecionar permissões para escolher as permissões do aplicativo, por exemplo: INTERNET. A permissão INTERNET já está marcada por padrão. Marque apenas as permissões de que o aplicativo realmente precisa.
8. Se desejar, marque "Usar arquiteturas separadas de 64 bits e 32 bits" para que o tamanho do APK fique menor, e marque "Usar assinatura pessoal" se quiser usar um keystore feito por você.
9. Toque em Criar projeto. O novo projeto é salvo na pasta Download/project e aparece imediatamente em Gerenciar projetos.

Tipos de projeto disponíveis
• HTML: exibição a partir de index.html, style.css e script.js, executando por meio do WebView. Compilado diretamente no telefone.
• Site: um site com menus (Início, Sobre, Contato) a partir de index.html, tentang.html, kontak.html, style.css e script.js, executando por meio do WebView. Compilado diretamente no telefone.
• Java: compilado no telefone. MainActivity está localizado em app/src/main/java/<nome-do-pacote>/MainActivity.java. A exibição vem de app/src/main/res/layout/activity_main.xml, o texto de app/src/main/res/values/strings.xml e o tema de app/src/main/res/values/styles.xml.
• Kotlin: pode ser compilado no dispositivo (offline) usando o compilador Kotlin incluído no aplicativo, ou por meio do GitHub Actions. MainActivity está localizado em app/src/main/java/<nome-do-pacote>/MainActivity.kt, e os arquivos res são os mesmos de um projeto Java. A primeira compilação em Kotlin é mais lenta devido ao grande tamanho do compilador, e arquivos .java que referenciam classes Kotlin ainda não podem ser compilados (arquivos .java são compilados antes dos arquivos .kt).
• Compose: um aplicativo Android moderno cuja interface é criada com Jetpack Compose (não layouts XML). MainActivity está localizado em app/src/main/java/<nome-do-pacote>/MainActivity.kt. Projetos Compose são compilados por meio do GitHub Actions (o menu Compilar projeto, depois Compilar online) ou no Termux com Gradle, porque o Compose requer as bibliotecas do Jetpack Compose, que não estão disponíveis no dispositivo.
• Python: a lógica do aplicativo é escrita na linguagem Python (Chaquopy) em app/src/main/python/main.py, e é executada pelo host MainActivity.java em app/src/main/java/<nome-do-pacote>/MainActivity.java. Projetos Python podem ser compilados diretamente no telefone (o runtime do Chaquopy está incluído no aplicativo) ou por meio do GitHub Actions. O SDK mínimo para projetos Python é 24 (Android 7.0).

Estrutura de arquivos dos projetos Java, HTML, Site, Kotlin, Compose e Python
Os projetos Java, HTML, Site, Kotlin, Compose e Python são estruturados como os projetos Android em geral. Dentro da pasta app há a pasta src, e dentro dela há a pasta main. Dentro da pasta main há AndroidManifest.xml ao lado da pasta java, a pasta res contendo layout/activity_main.xml e values/strings.xml, bem como values/styles.xml, e para HTML e Site há a pasta assets contendo index.html (Site também tem tentang.html e kontak.html). Os projetos HTML e Site também têm seu próprio MainActivity em app/src/main/java/<nome-do-pacote>/MainActivity.java, que carrega index.html em um WebView e se torna o launcher no AndroidManifest. Os projetos Python têm o código Python em app/src/main/python/main.py e o host MainActivity.java em app/src/main/java/<nome-do-pacote>/MainActivity.java. AndroidManifest.xml, layouts, strings e estilos podem ser abertos e alterados no editor, assim como MainActivity. Projetos antigos cujo manifesto ainda está ao lado da pasta app ainda podem ser compilados, porque ao compilar, o aplicativo verifica primeiro AndroidManifest.xml em app/src/main/, depois o que está ao lado da pasta app, e por último o arquivo de dados do projeto.

Regras de permissões (importante)
As permissões marcadas ao criar um projeto são registradas em apenas um lugar, de acordo com o tipo de projeto. Para projetos Java, HTML, Site, Kotlin, Compose e Python, as permissões marcadas são registradas APENAS em AndroidManifest.xml localizado em app/src/main/, ao lado da pasta java, dentro da pasta do projeto. O arquivo de dados do projeto para projetos Java, HTML, Site, Kotlin, Compose e Python não contém uma lista de permissões. Se você escolher Java e depois marcar INTERNET e CAMERA, o que é registrado em AndroidManifest.xml é apenas INTERNET e CAMERA, sem nenhuma outra permissão incluída. Ao compilar, o aplicativo lê as permissões do mesmo lugar: de AndroidManifest.xml em app/src/main/ para projetos Java, HTML, Site, Kotlin, Compose e Python (se não houver nenhum, de AndroidManifest.xml ao lado da pasta app para projetos antigos), e do arquivo de dados do projeto para projetos antigos.

Como usar o editor
Abra Gerenciar projetos, toque no nome de um projeto para abrir o editor. No editor, arquivos podem ser abertos, código pode ser escrito e alterações podem ser salvas. Para projetos Java, HTML, Site, Kotlin, Compose e Python, os arquivos são organizados dentro da pasta app/src/main. Para compartilhar um projeto, use Exportar ZIP (veja a seção abaixo).

Como executar um projeto
No editor, toque em Executar para testar o projeto. Para projetos HTML e Site, o que é executado é index.html por meio do WebView. Se ocorrer um erro, leia a mensagem de erro, corrija o código e execute novamente.

Como compilar um APK
No editor, toque em Compilar. Há duas maneiras de compilar. Primeira, Compilar no dispositivo: compila diretamente no telefone sem internet, para projetos HTML, Site, Java, Kotlin e Python. Segunda, Compilar online por meio do GitHub Actions: compila pela internet no GitHub e pode ser usada para todos os tipos de projeto. Projetos Compose só podem ser compilados da segunda maneira (Compilar online) ou no Termux com Gradle, porque o Compose requer as bibliotecas do Jetpack Compose, que não estão disponíveis no dispositivo. O resultado da primeira compilação ainda não está assinado. Depois disso, o aplicativo o assina: automaticamente com a chave incorporada, ou com uma assinatura pessoal se a caixa "Usar assinatura pessoal" estava marcada ao criar o projeto.

Como instalar um APK
Quando o APK estiver pronto, toque em Instalar para instalá-lo. No Android 8 e superior, o telefone pedirá primeiro "Permitir desta fonte", porque este aplicativo instala APKs de fora da Play Store. Ative essa permissão uma vez nas Configurações e depois volte ao aplicativo: a instalação continuará automaticamente sem precisar tocar em Instalar novamente. Se o botão Instalar não aparecer, certifique-se de que a compilação terminou e o APK foi criado.

Como assinar um aplicativo
Todo APK deve ser assinado para poder ser instalado. Há duas opções disponíveis. Primeira, a chave incorporada: o aplicativo assina por si só automaticamente, sem que você precise fazer nada. Segunda, uma assinatura pessoal: primeiro crie um keystore por meio do menu Criar keystore no menu principal, guarde sua senha com cuidado e depois marque "Usar assinatura pessoal" ao criar o projeto. O keystore é armazenado em Download/project/signing.

Exportar um projeto para ZIP
Exportar ZIP é fornecido para que os projetos possam ser compartilhados com amigos. Como fazer: em Gerenciar projetos, pressione e segure o nome do projeto, depois escolha Exportar ZIP. O resultado é salvo em Download/project/<NomeDoProjeto>.zip. A pasta bin não é incluída, então o tamanho é pequeno, apenas dezenas de KB. Esse arquivo ZIP pode ser enviado a amigos ou carregado para o GitHub.

Extensão JAWS
A Extensão JAWS usa o mecanismo de extensões do Jieshuo (CSR), não o seu leitor de tela. Dessa forma, os designs podem continuar funcionando mesmo que o usuário use o TalkBack. Como fazer: abra Extensão JAWS no menu principal. Como o clique automático funciona sozinho, o serviço deve primeiro ser ativado nas Configurações de acessibilidade. Depois disso, um novo design pode ser criado: digite o nome do design, toque em OK e preencha suas caixas.

Lista de Cliques mantida separada para ficar organizada
Dentro de um design há duas caixas: a caixa de script e a caixa Lista de Cliques. A lista de botões é armazenada separadamente no arquivo daftar_klik.txt, um nome por linha. Um exemplo de seu conteúdo: tombolSimpan, tombolHapus, tombolBuka. Para abrir um aplicativo, basta escrever >WhatsApp nessa lista. Designs antigos que ainda não têm um arquivo daftar_klik.txt exibirão esse exemplo padrão.

Funções simples fornecidas
• klikTombol("tombolSimpan") — clica em um botão com base em seu texto.
• klikDaftarTombol(daftar) — clica na lista em daftar_klik.txt, um botão por linha, em ordem, e depois informa quantos tiveram sucesso e quantos não foram encontrados.
• bukaAplikasi("WhatsApp") — abre um aplicativo pelo nome, ou escreva ">WhatsApp" na lista.
• klik(540, 1200) — clica nas coordenadas da tela.
Todas as funções são feitas simples primeiro. Quando você se acostumar com elas, funções adicionais podem ser adicionadas depois.

Sobre leitores de tela
Este aplicativo foi projetado para ser amigável a leitores de tela. Cada campo de entrada tem um rótulo e um exemplo de preenchimento, e todos os botões podem ser alcançados sem gestos complicados. A Extensão JAWS foi feita para continuar funcionando mesmo que o usuário use o TalkBack, porque o que é usado é o seu mecanismo de extensões, não o seu leitor de tela.

Privacidade e segurança
Projetos e keystores são armazenados no seu telefone. O token do GitHub é usado apenas para compilações online e é armazenado dentro deste aplicativo. Não compartilhe seu token ou a senha do seu keystore com ninguém. Se você usar uma assinatura pessoal, guarde o keystore e sua senha em um lugar seguro, porque se forem perdidos, APKs antigos não poderão ser atualizados com a mesma assinatura.

Requisitos
Android 5.0 ou mais recente. Permissão de armazenamento: no Android 11 e superior, usa a permissão de acesso a todos os arquivos; no Android 10 e inferior, usa a permissão de armazenamento comum (ler/escrever armazenamento), porque o Android 10 não tem a permissão de acesso a todos os arquivos. Compilar no dispositivo requer um telefone com processador ARM (32 ou 64 bits). Compilar online por meio do GitHub Actions requer internet e um token do GitHub. Projetos Kotlin podem ser compilados no dispositivo, mas a primeira compilação é mais lenta e usa mais memória devido ao grande tamanho do compilador Kotlin. Projetos Compose são compilados por meio do GitHub Actions ou no Termux com Gradle. Projetos Python requerem Android 7.0 ou mais recente (SDK mínimo 24) e o APK resultante é maior porque inclui o runtime do Python (Chaquopy) junto com sua biblioteca padrão.

Terminal
O menu Terminal na tela principal abre um terminal dentro deste aplicativo. Comandos como ls podem ser usados para ver o conteúdo da pasta do projeto, cd para se mover entre pastas e git para gerenciar o código. A saída dos comandos aparece como texto que pode ser lido por um leitor de tela, e há um botão Ler resultado em voz alta para ouvir o último resultado. Este terminal usa o shell do sistema do telefone, então programas interativos como nano e vim ainda não podem ser usados aqui.

Licença (versão paga)
Para vender um aplicativo, marque "Ativar licença" ao criar o projeto e depois preencha seu número de WhatsApp. O aplicativo compilado pedirá um código de licença quando for aberto pela primeira vez: o usuário vê seu ID de dispositivo, toca no botão Enviar ID do dispositivo para enviar esse ID ao seu WhatsApp, e então você responde com o código de licença. O código de licença é calculado a partir do ID do dispositivo e da senha do projeto (lisensi_seed no arquivo de dados do projeto) — guarde essa senha com cuidado e não a compartilhe. Depois que o código correto é inserido, o aplicativo abre e não pede um código novamente.

Criador Automático de Ícones
Os ícones de novos projetos ainda são transparentes, então um Criador de ícones está disponível no menu principal. Como fazer: toque em Criador de ícones, escreva uma ou duas letras (por exemplo, as iniciais do nome do aplicativo), escolha uma cor de fundo e uma cor de texto, veja a prévia e depois toque em Salvar no projeto para usar esse ícone no projeto selecionado, ou Salvar em Downloads para usar seu arquivo PNG em outro lugar. Depois que um projeto é criado, o aplicativo também oferece a criação de um ícone. O ícone antigo de um projeto pode ser substituído a qualquer momento pelo menu do projeto em Gerenciar projetos (pressione e segure o nome do projeto, depois escolha Alterar ícone).

Modelos de Projeto Prontos para Uso
Se você não quiser começar de um projeto vazio, escolha um modelo ao criar um projeto: Calculadora (Java), Notas (Java), Lista de Tarefas (Kotlin), Calculadora Web (HTML), Site de Perfil (Site) ou Contador (Compose). Escolher um modelo altera automaticamente o tipo de projeto para seguir esse modelo, e o projeto é criado com código inicial pronto — basta executá-lo ou alterá-lo. Se o tipo de projeto for alterado manualmente novamente depois de escolher um modelo, o modelo é cancelado e o projeto volta a ficar vazio. Para modelos HTML e Site, o modelo substitui o conteúdo de index.html, incluindo o script HTML digitado no formulário.

Backup e Restauração de Projetos
Para que os projetos não se percam, há um recurso de backup disponível. Como fazer: em Gerenciar projetos, pressione e segure o nome do projeto, depois escolha Fazer backup. O backup é salvo como um ZIP na pasta Download/backup com o nome do projeto e a data, por exemplo: GarudaDecode-2026-11-14-123045.zip. Seu conteúdo é o mesmo de Exportar ZIP (todo o conteúdo do projeto, sem a pasta bin). Para restaurar: abra o menu em Gerenciar projetos, escolha Restaurar backup e depois escolha o arquivo de backup. Se o nome do projeto já existir, o aplicativo perguntará: Sobrescrever o projeto antigo, ou salvar com um Novo nome.

Compartilhar e Importar Projetos
Para compartilhar um projeto com amigos: em Gerenciar projetos, pressione e segure o nome do projeto, depois escolha Compartilhar. O projeto é enviado como um ZIP por meio de aplicativos de compartilhamento (WhatsApp, Telegram e outros). Para receber um projeto de um amigo: abra o menu em Gerenciar projetos, escolha Importar projeto e depois escolha o arquivo ZIP. Esse arquivo ZIP deve conter um arquivo de dados do projeto — se não houver nenhum, o arquivo é rejeitado com uma mensagem clara, porque esse arquivo não é um projeto do Create Aplikasi. Se o nome do projeto já existir, o aplicativo perguntará: Sobrescrever o projeto antigo, ou salvar com um Novo nome.

Busca e Filtro de Projetos
Se já houver muitos projetos, em Gerenciar projetos há uma caixa de busca e um filtro de tipo. Digite o nome do projeto na caixa de busca e a lista é filtrada imediatamente (letras maiúsculas e minúsculas não são diferenciadas). O filtro de tipo limita a lista a apenas um tipo: Todos, HTML, Site, Java, Kotlin, Compose ou Python. O menu de cada projeto ainda pode ser aberto como de costume a partir da lista já filtrada.

Criar Aplicativos com a Voz
Se não quiser digitar, use a voz: toque em Criar com a voz no menu principal e depois diga um comando. Comandos que pode dizer: "Buat proyek kalkulator", "Bangun proyek Kalkulator", "Buka proyek Kalkulator", "Jalankan proyek Kalkulator", "Daftar proyek", "Buka ikon", "Kembali" e "Bantuan". O aplicativo responde com voz e texto, por isso continua a poder ser usado sem olhar para o ecrã. O reconhecimento de voz usa a aplicação de reconhecimento de voz integrada do telemóvel (gratuita; pode funcionar offline se o pacote de idioma indonésio estiver instalado). Se o telemóvel não tiver reconhecimento de voz, os comandos podem ser escritos na caixa de texto do mesmo ecrã.

Auditoria de Acessibilidade
Para verificar se o layout de um projeto é amigável para o leitor de ecrã (TalkBack/Jieshuo) antes de publicar: abra Auditoria de Acessibilidade no menu principal, escolha um projeto e depois toque em Carregar Lista de Layouts e escolha um ficheiro de layout. O IDE lê esse ficheiro XML e indica os botões sem rótulo com os respetivos números de linha, os rótulos usados repetidamente e os elementos que se sobrepõem, e depois constrói uma transcrição da ordem de foco como a que o Jieshuo lê em voz alta. Se um botão não tiver rótulo, preencha o rótulo e depois toque em Inserir Rótulo Automaticamente — o rótulo é escrito no ficheiro de layout como contentDescription. Esta verificação lê apenas XML de layout; as vistas Compose e os APK terminados ainda não são analisados.

Autópsia de Falha
Para descobrir por que uma aplicação se fecha sozinha a partir de um registo de falha com ID único: abra Autópsia de Falha no menu principal, escolha um ID de falha na lista de registos e depois toque em Verificar. O IDE compara a classe e o número da linha no registo com o código-fonte do projeto e explica a causa em indonésio (por exemplo, uma referência vazia, uma permissão ainda não pedida ou um erro JSON), juntamente com uma sugestão de correção de código. Toque em Aplicar Correção apenas se a linha de código continuar exatamente igual a quando ocorreu a falha; se mudou, a correção é recusada e o IDE pede-lhe que verifique por si. O que é lido é o registo de falhas do próprio IDE, não o registo de uma aplicação compilada.

Transpilador Entre Paradigmas
Para converter código Java simples em Kotlin, ou um layout XML simples em código Compose: abra Transpilador Entre Paradigmas no menu principal, escolha um projeto e um ficheiro e depois toque em Pré-visualizar. O IDE mostra o resultado da conversão como texto — verifique-o primeiro, porque as linhas que não reconhece são deixadas como estão e a palavra static do Java é retirada no Kotlin (verifique o seu significado antes de a usar). A conversão de XML para Compose só muda o texto, as sugestões e a orientação — o tamanho, a cor e outros atributos ainda não são incluídos. Se o resultado estiver correto, toque em Aplicar ao Arquivo para escrever o ficheiro de destino; o ficheiro de origem não é alterado. Só os padrões comuns e seguros são convertidos.

Servidor Micro Local
Para testar uma aplicação que precisa de um servidor sem internet: abra Servidor Micro Local no menu principal, escreva uma definição de rota (por exemplo, GET /halo seguida da sua resposta JSON) e depois toque em Iniciar Servidor. O IDE executa um pequeno servidor HTTP no mesmo telemóvel (só HTTP, sem TLS, para a mesma rede Wi-Fi) e regista cada pedido e resposta no ecrã. As rotas podem usar parâmetros como {nama} e uma chave API simples. Este servidor serve apenas para testar no telemóvel; um APK compilado ainda não pode ser servidor, e o servidor para quando o seu ecrã é fechado.

Auditor de Segurança
Para verificar se há falhas de segurança no código do projeto antes de publicar: abra Auditor de Segurança no menu principal, escolha um projeto e depois toque em Iniciar Verificação. O IDE analisa o código, o manifesto e a configuração do projeto e indica os achados do maior para o menor risco — chaves API expostas no código, componentes expostos sem permissão, um WebView que ativa JavaScript juntamente com uma interface JavaScript, criptografia fraca (MD5, SHA1, DES), endereços http sem TLS e palavras-passe escritas diretamente no código — juntamente com o ficheiro e o número da linha de cada um. Para os achados com uma correção segura (por exemplo, trocar MD5 por SHA-256 ou http por https), toque em Aplicar Correção; para chaves API e palavras-passe, o IDE só mostra a correção sugerida porque a substituição tem de ser decidida pelo próprio programador. Esta análise lê padrões de texto no código, não bytecode, por isso pode haver achados que na verdade são seguros, e uma falha sem padrão pode escapar à análise — verifique antes de aplicar.

Robô de Teste de Interface
Para testar automaticamente o aspeto de uma aplicação através de cenários de texto: abra Robô de Teste de Interface no menu principal, escolha um projeto e depois toque em Criar Cenário Automaticamente. O IDE lê o manifesto e os layouts do projeto e escreve um cenário de passos de texto (tocar num botão, preencher um campo, esperar, voltar). Toque em Executar Dry Run para ver o registo de execução do cenário com as respetivas marcas de tempo. Nesta fase, o robô só executa uma simulação (dry run) — os toques reais em botões no telemóvel e a captura de falhas reais são a próxima fase, por isso o relatório de falhas aqui continua a ser um formato de exemplo.

Viagem no Tempo do Código
Para devolver um projeto a um estado anterior do código sem escrever comandos Git: abra Viagem no Tempo do Código no menu principal, escolha um projeto, preencha um rótulo para o ponto no tempo (pode ficar vazio) e depois toque em Registar ponto no tempo. O IDE guarda uma cópia dos ficheiros de código-fonte do projeto juntamente com os respetivos hashes na pasta .riwayat dentro do projeto. A lista de pontos no tempo mostra-os todos; escolha dois pontos e depois toque em Comparar para ver os ficheiros e funções adicionados, alterados ou removidos. Toque em Restaurar para recuperar um estado antigo — antes de restaurar, o IDE faz sempre primeiro uma cópia de segurança do estado atual, por isso nada se perde. Toque em Criar Cópia de Experimento para copiar o projeto para uma pasta nova e experimentar alterações sem incomodar o projeto original. Só os ficheiros de código-fonte são registados.

Fábrica de Módulos
Para empacotar parte de um projeto como um módulo que outro projeto possa usar: abra Fábrica de Módulos no menu principal, escolha um projeto de origem, marque os ficheiros de ecrã, classe, texto e permissões a empacotar e depois toque em Empacotar como Módulo. O IDE escreve um arquivo ZIP juntamente com metadados JSON (nome do módulo, versão, textos e permissões usados). Para instalar um módulo noutro projeto, abra Fábrica de Módulos, escolha o projeto de destino e depois toque em Instalar Módulo e escolha o ficheiro .zip do módulo — a fusão adiciona textos e permissões sem substituir o código existente, e não funde um ficheiro se o seu nome já for usado no projeto de destino. Um módulo não traz bibliotecas nem definições de compilação.

Escudo polimórfico e cofre de recursos
Para embaralhar nomes de identificadores e criptografar recursos do projeto antes do lançamento: abra Escudo polimórfico e cofre de recursos no menu principal, escolha um projeto e toque em Embaralhar nomes e criptografar recursos. O IDE examina os nomes de classes e métodos no código-fonte, cria um mapa de nomes aleatórios, criptografa os arquivos de recursos do projeto com AES-GCM na pasta brankas-aset dentro do projeto e salva um mapa de recuperação criptografado (perisai-peta.brankas) para que os nomes originais possam ser restaurados ao ler registros de falhas. A chave de criptografia é derivada do nome do projeto, então qualquer pessoa que conheça o nome do projeto pode abrir o cofre: é uma proteção contra leitura casual, não um cofre trancado com senha. O que é criado aqui é um mapa de nomes e um cofre de recursos; reescrever nomes dentro do arquivo DEX compilado é uma etapa posterior, então os nomes dentro do APK final ainda não foram embaralhados.

Cadeia de confiança e guardião do ambiente
Para verificar a cadeia de chaves de assinatura e o ambiente do telefone antes do lançamento: abra Cadeia de confiança e guardião do ambiente no menu principal, escolha um projeto e toque em Verificar cadeia e ambiente. O IDE constrói uma cadeia de chaves de 5 gerações a partir do nome do pacote do projeto e verifica sua integridade, depois examina o mapa de memória do próprio processo e as propriedades do dispositivo em busca de vestígios de Frida, Xposed ou emulador. O resultado é um nível de risco Seguro, Cuidado ou Perigoso, junto com a evidência em texto. Esta verificação lê padrões de texto no mapa de memória e nas propriedades do sistema, não a integridade da memória bruta no nível da biblioteca nativa, e não vincula as chaves ao chip de segurança do hardware: uma ferramenta de injeção que esconda seus vestígios de texto pode passar despercebida.

Arquiteto de layout em árvore de texto
Para desenhar uma tela sem vê-la: abra Arquiteto de layout em árvore de texto no menu principal, escolha um projeto e um arquivo de layout e toque em Verificar layout. O IDE lê o layout XML como uma árvore de texto e lê em voz alta uma narração da posição de cada elemento (por exemplo, embaixo à direita, 45 por cento da largura da tela), depois informa sobreposições entre elementos e elementos que saem da tela com largura de 360 dp, de forma matemática. O que é calculado é LinearLayout e tamanhos dp simples; ConstraintLayout e telas Compose são informados com posição incerta, não adivinhados.

Estúdio de sistema de design
Para igualar espaçamento, tipografia e cantos em todas as telas e projetos: abra Estúdio de sistema de design no menu principal, escolha um projeto, escreva os tokens de design (por exemplo jarak=8, huruf=16, sudut=12), escolha um componente e toque em Gerar componentes. O IDE valida os tokens — espaçamento base de 4 a 16 dp, tipografia base de 12 a 20 sp, cantos de 0 a 32 dp e área de toque mínima de 48 dp — e então escreve componentes XML prontos para uso (komponen-studio.xml) junto com um tema XML (tema-studio.xml) e um tema Compose (tema-studio.kt) na pasta do projeto. Os componentes são gerados como texto que é colado em um layout e depois verificado com o Arquiteto de Layout; o ajuste de duas colunas em tablets usa qualificadores de largura de tela, não detecção de dispositivo em tempo de execução.

Refatoração semântica e navegação AST
Para encontrar definições e renomear símbolos sem quebrar outro código que por acaso compartilha o nome: abra Refatoração semântica e navegação AST no menu principal, escolha um projeto e toque em Verificar símbolos do projeto para ver todas as classes e métodos com seus arquivos e números de linha. Digite o nome de um símbolo e toque em Verificar símbolos do projeto novamente para ver sua definição e todos os arquivos que o chamam. Para renomear, digite o novo nome, toque em Pré-visualizar renomeação para ver o número de ocorrências em cada arquivo e depois toque em Aplicar renomeação. Este índice usa padrões de texto, não um analisador AST completo: renomear uma classe se aplica a todos os arquivos, enquanto renomear um método só se aplica ao seu arquivo proprietário — os chamadores em outros arquivos não são alterados, então verifique a pré-visualização e os resultados da verificação de chamadores antes de aplicar. Extrair um bloco de código como uma nova função já existe no motor lógico, mas ainda não há botão para isso nesta tela.

Depurador passo a passo e inspetor de memória
Para inspecionar o conteúdo de variáveis no meio do fluxo de um programa sem adivinhar pelos registros: abra Depurador passo a passo e inspetor de memória no menu principal, escolha um projeto, escreva o rastreamento de execução (um passo por linha, no formato número da linha, código, depois variáveis e valores separados por |, por exemplo 10|int total = harga * jumlah;|harga=5000, jumlah=3, total=15000), digite o número da linha do ponto de interrupção e toque em Executar rastreamento de depuração. O IDE avança até o primeiro ponto de interrupção e lê em voz alta a linha ativa junto com os valores de suas variáveis pelo Jieshuo. Toque em Avançar uma linha para avançar uma linha, ou em Continuar programa para correr até o próximo ponto de interrupção. Isto é um depurador de rastreamento: ele percorre um rastreamento de execução gravado ou escrito à mão, não pausa um aplicativo Android em execução — pausar um processo real precisa de uma ponte de depuração e ainda não existe nesta etapa.

Gerenciador de dependências offline
Para usar bibliotecas de terceiros sem internet e evitar conflitos de versão antes de compilar: abra Gerenciador de dependências offline no menu principal, escolha um projeto e toque em Verificar dependências. O IDE lê todos os arquivos .gradle do projeto, verifica o cofre offline (brankas-maven.txt dentro do projeto) e resolve conflitos — se duas bibliotecas pedirem versões diferentes do mesmo artefato, a versão mais alta é usada e o conflito é relatado. Para registrar uma biblioteca no cofre, digite suas coordenadas (formato grupo:artefato:versão, por exemplo com.google.code.gson:gson:2.10.1) e toque em Verificar dependências. Baixar do Maven, Google ou PyPI precisa de internet: offline, só as bibliotecas que já estão no cofre podem ser usadas, e adicionar coordenadas apenas as registra no índice — os arquivos AAR, JAR ou WHL em si não são baixados automaticamente. O cofre continua sendo guardado por projeto.

Inspetor de banco de dados e armazenamento
Para inspecionar e testar o conteúdo do banco de dados de um projeto sem escrever código que imprima o conteúdo das tabelas: abra Inspetor de banco de dados e armazenamento no menu principal, escolha um projeto e um arquivo de banco de dados (.db, .sqlite ou .sqlite3) e toque em Abrir banco de dados. O IDE lê o esquema da tabela e mostra as primeiras 20 linhas como uma tabela de texto lida em voz alta pelo Jieshuo. Escreva uma consulta SELECT simples e toque em Executar consulta (por exemplo SELECT nama FROM pengguna WHERE kota = 'Makassar'). Para alterar um valor, digite o número da linha (1 = primeira linha), o nome da coluna e o novo valor e toque em Alterar valor da célula — o valor é escrito de volta no arquivo .db. Toque em Salvar cópia de segurança para salvar o estado atual da tabela como um arquivo <nome-db>.cadangan.txt no projeto. Só a primeira tabela é lida; as consultas suportadas são apenas SELECT simples, sem JOIN ou GROUP BY; SharedPreferences e DataStore ainda não são lidos.

Fábrica de testes de unidade e fuzzing
Para encontrar falhas de lógica antes de compartilhar um aplicativo: abra Fábrica de testes de unidade e fuzzing no menu principal, escolha um projeto e um arquivo de código e toque em Criar e executar testes. O IDE lê as assinaturas de função no arquivo, gera casos de teste normais e de limite (texto vazio, null, números máximos, caracteres estranhos), executa fuzzing sobre funções de exemplo e escreve um esqueleto de teste JUnit (Uji<NomeDaClasse>.java) no projeto. O resultado informa quantos testes passaram e falharam, quantas linhas de código e funções foram encontradas e quantos casos de teste foram criados. Os testes gerados ainda são esqueletos — os valores esperados devem ser escritos pelo desenvolvedor — e o fuzzing real só roda sobre as funções de exemplo, não sobre as funções do projeto; a porcentagem de cobertura de linhas ainda não é calculada.

Simulador de condições extremas do dispositivo e auditor de vazamento de memória
Para testar a resistência do aplicativo quando o sistema mata seu processo, a rede cai, a tela gira ou a economia de bateria está ativa: abra Simulador de condições extremas do dispositivo e auditor de vazamento de memória no menu principal, escolha um projeto e toque em Executar simulação. O IDE executa três cenários de estresse junto com uma simulação de rotação de tela e rastreia objetos retidos na memória depois que sua tela é fechada, depois informa dados perdidos e cadeias de objetos com vazamento. Isto é uma simulação sobre um modelo de estado, não mata realmente um processo, não corta realmente a rede do telefone e não é um despejo de memória real; o modelo de estado nesta tela ainda é um exemplo fixo, não o estado das telas do projeto do usuário.

Arquiteto de plantas de projeto
Para transformar uma ideia de aplicativo grande em um plano de trabalho passo a passo: abra Arquiteto de plantas de projeto no menu principal, escolha um projeto, escreva a ideia do aplicativo (por exemplo, um aplicativo de caixa de mercearia com parcelamento) e toque em Criar planta. O IDE organiza módulos, uma lista de arquivos e pequenos marcos de trabalho e os salva como cetak-biru.txt na pasta do projeto. Toque em Marcar próximo marco como concluído sempre que um marco terminar, ou toque em Carregar plano salvo para abrir novamente uma planta salva. As plantas são construídas a partir de padrões de palavras-chave no dispositivo, não a partir de um modelo de IA online — ideias não reconhecidas usam um esqueleto geral (modelo de dados, armazenamento, telas, lógica) — e construir pelo provedor de IA ativo ainda não existe nesta etapa.

Narrador do fluxo lógico do código
Para entender código longo sem ouvir a sintaxe linha por linha: abra Narrador do fluxo lógico do código no menu principal, escolha um projeto e um arquivo de código e toque em Narração de código. O IDE transforma cada linha em uma frase em indonésio (por exemplo, se o total for maior que 100000, execute o bloco seguinte), mostra um mapa de chamadas entre métodos e marca possíveis erros sutis com seus números de linha — String comparado com ==, um stream aberto sem ser fechado e uma variável escrita em dois métodos diferentes. A narração e a verificação usam padrões de texto offline, não um modelo de IA online nem uma análise completa de fluxo de dados; padrões não reconhecidos são narrados como estão, como uma linha de código, e avisos de corrida de dados podem aparecer para variáveis que na verdade só são usadas alternadamente.

Fábrica de pacotes de aplicativo e prontidão para a Play Store
Para preparar um aplicativo para a Google Play Store direto do telefone: abra Fábrica de pacotes de aplicativo e prontidão para a Play Store no menu principal, escolha um projeto e toque em Criar pacote AAB. O IDE monta o arquivo .aab a partir do manifesto, dos recursos e dos ativos do projeto, simula os tamanhos de download divididos por arquitetura (arm64-v8a, armeabi-v7a, x86_64) e idioma e depois audita a prontidão para o Play — um SDK alvo abaixo de 35 é marcado como Alto porque a Play Store exige 35 ou mais, e uma biblioteca de 64 bits ausente também é marcada como Alto. O pacote resultante é um arquivo AAB com estrutura padrão; os tamanhos divididos são estimativas a partir dos tamanhos dos arquivos, não resultados reais de divisão do bundletool, e assinar o pacote para o Play Console continua usando o mesmo caminho de compilação do APK.

Mecanismo de atualização OTA e lançamentos graduais
Para enviar pequenas correções sem obrigar os usuários a baixar novamente todo o APK: abra Mecanismo de atualização OTA e lançamentos graduais no menu principal, escolha um projeto, escreva o conteúdo da versão antiga e da nova e toque em Criar pacote de patch. O IDE calcula as diferenças de linhas e cria um pacote de patch (patch-ota.zip) com a impressão digital SHA-256 do conteúdo novo e depois verifica se este dispositivo está na etapa inicial de 10 por cento do lançamento. Os patches aqui só funcionam sobre arquivos de texto (scripts, recursos, configuração) — patches binários DEX ou APK ainda não são suportados, e um patch é aplicado quando o aplicativo é reaberto. A impressão digital no manifesto só prova a integridade do conteúdo, não a autenticidade do remetente, porque ainda não usa uma assinatura de chave privada.

Estúdio de revisão de código em equipe
Para revisar as alterações de um colega e resolver conflitos de mesclagem sem ler as marcas de seta do Git: abra Estúdio de revisão de código em equipe no menu principal, escolha um projeto, preencha três versões de texto (base, local, colega) e toque em Abrir revisão da equipe. O IDE mescla as três e mostra cada conflito como uma opção de voz: Usar versão local, Usar versão do colega ou Mesclar os dois — as linhas resultantes são inseridas na posição original do conflito para que a ordem das linhas continue correta — e depois escreve o resultado em gabung-hasil.txt no projeto. Abaixo fica o quadro de tarefas do projeto: digite o título de uma tarefa e toque em Adicionar tarefa; as tarefas são salvas como texto na pasta .tugas dentro do projeto. A mesclagem usa correspondência de linhas, não sintaxe, então duas alterações na mesma linha sempre são tratadas como conflito mesmo que seus significados não colidam; o quadro de tarefas sincroniza copiando seu arquivo de texto junto com o histórico do Git, sem um servidor de sincronização dedicado.

Ditado de Estrutura de Código
Para escrever código por voz dentro do editor: abra um projeto no Editor e depois toque no botão Ditado de Estrutura de Código. Diga comandos em indonésio, por exemplo buat fungsi tambah dengan parameter a angka dan b angka, buat kelas Mobil ou buat variabel teks nama sama dengan Budi — o IDE converte a voz num bloco de código Java, Kotlin, Python ou Compose sintaticamente válido e insere-o na posição do cursor, e depois lê em voz alta um breve resumo através do Jieshuo. O ditado usa o serviço de entrada de voz integrado do sistema, sem permissão adicional de microfone, e só reconhece padrões de comandos já registados; a voz fora desses padrões não é convertida em código. Os números ditos por extenso (por exemplo 'lima') ainda não são convertidos em dígitos.

Espaço de Colaboração Local (sem internet)
Para trabalhar em conjunto numa mesma sala sem internet: abra Colaboração no menu principal e depois abra a secção Espaço de Colaboração Local. Um telemóvel abre uma sessão (o IDE mostra um endereço IP local e um PIN de 6 dígitos), outro telemóvel junta-se com esse endereço e esse PIN. As alterações de texto são enviadas como diferenças de linhas, um APK compilado pode ser enviado para o telemóvel do testador e os relatórios de falha do telemóvel do testador são recebidos de volta. Uma sessão é só para um amigo; se duas pessoas alterarem exatamente a mesma linha ao mesmo tempo, é usada a última alteração. O PIN é enviado como texto simples na rede local. Esta sala ainda não foi testada num telemóvel real.

Configurações de IA
Para definir o fornecedor de IA e as chaves API para criar aplicações: no menu principal, no grupo Configurações, toque em Configurações de IA (ao lado do botão Conector). Escolha o fornecedor a usar na lista disponível e marque Trocar de modelo quando o provedor falhar para que, se um modelo falhar, o IDE tente automaticamente o modelo seguinte do mesmo fornecedor. Toque em Gerenciar chaves API para adicionar chaves de reserva (preencha o nome e a chave e depois toque em Salvar; as chaves são mostradas ocultas, só os últimos 4 caracteres são visíveis). As chaves são guardadas no telemóvel e nunca são enviadas para lado nenhum exceto para o fornecedor escolhido ao criar uma aplicação. Nota: por enquanto, a escolha de fornecedor e chave só é registada e mostrada no ecrã AI Pembuat Aplikasi — a criação de aplicações continua a usar a IA local do telemóvel (sem internet); o uso de fornecedores online virá depois.

Conector
Para analisar um APK e depois enviá-lo: no menu principal, no grupo Configurações, toque em Conector (ao lado do botão Configurações de IA). Escolha um ficheiro APK do telemóvel, o IDE lê o seu conteúdo (nome do pacote, versão, lista de atividades) e depois toque em Enviar APK para o enviar através do menu de partilha do sistema (por exemplo, WhatsApp ou Drive).

Idioma e voz
Para mudar o idioma da aplicação: abra Configurações, depois Idioma do app e depois escolha um idioma ou Seguir o sistema. O ecrã principal e a maioria dos ecrãs mudam para o idioma escolhido imediatamente, sem fechar nem reiniciar a aplicação; alguns ecrãs (por exemplo, Terminal, Colaboração, Configurações de IA e Gerenciar chaves) continuam a usar o idioma antigo até serem reabertos. Se escolher Seguir o sistema, o idioma segue o idioma do sistema do telemóvel.
