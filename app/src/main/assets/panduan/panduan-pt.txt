Bem-vindo ao Create Aplikasi by Al Kautsar
Create Aplikasi é um aplicativo criador de aplicativos Android que funciona diretamente no telefone, sem precisar de um notebook. Este aplicativo permite que qualquer pessoa crie seus próprios aplicativos Android, incluindo usuários que estão apenas começando a aprender a criar aplicativos e usuários de leitores de tela. O guia completo de uso deste aplicativo está disponível nesta tela Sobre esta ferramenta.

O que é este aplicativo e para quem ele é
Create Aplikasi é uma ferramenta criadora de aplicativos Android que funciona no telefone. Este aplicativo é destinado a qualquer pessoa que queira criar seus próprios aplicativos Android, incluindo iniciantes e usuários de leitores de tela. Este aplicativo oferece um editor de código, um botão Executar para testar projetos, um botão Compilar para criar um APK, e menus para assinar e instalar o APK.

Objetivo deste aplicativo
Este aplicativo foi feito para que qualquer pessoa possa criar seus próprios aplicativos Android com facilidade, diretamente do telefone. Sua interface foi feita o mais simples possível para que até usuários novos possam experimentá-lo imediatamente.

Como criar um novo projeto, passo a passo
1. Toque em Criar projeto no menu principal.
2. Escolha o tipo de projeto: HTML, Site, Java, Kotlin, Compose ou Python.
3. Preencha o nome do aplicativo, por exemplo: Garuda Decode.
4. Preencha o nome do pacote (package name), por exemplo: com.android.garudadecode. O nome do pacote deve usar letras minúsculas e consistir em pelo menos duas partes separadas por pontos.
5. Preencha a versão do aplicativo, por exemplo: 1.0, e um código de versão na forma de número, por exemplo: 1. Se ficar vazio, a versão será preenchida automaticamente com 1.0 e o código de versão 1.
6. Preencha o SDK mínimo e o SDK de destino, se necessário. Se ficarem vazios, os valores padrão serão usados. O SDK mínimo é a versão mais baixa do Android suportada, por exemplo: 21 significa Android 5.0. O SDK de destino máximo é 36 (Android 16).
7. Toque no botão Selecionar permissões para escolher as permissões do aplicativo, por exemplo: INTERNET. A permissão INTERNET já está marcada por padrão. Marque apenas as permissões de que o aplicativo realmente precisa.
8. Se desejar, marque "Usar arquiteturas separadas de 64 bits e 32 bits" para que o tamanho do APK fique menor, e marque "Usar assinatura pessoal" se quiser usar um keystore feito por você.
9. Toque em Criar projeto. O novo projeto é salvo na pasta Download/project e aparece imediatamente em Gerenciar projetos.

Tipos de projeto disponíveis
• HTML: exibição a partir de index.html, style.css e script.js, executando por meio do WebView. Compilado diretamente no telefone.
• Site: um site com menus (Início, Sobre, Contato) a partir de index.html, tentang.html, kontak.html, style.css e script.js, executando por meio do WebView. Compilado diretamente no telefone.
• Java: compilado no telefone. MainActivity está localizado em app/src/main/java/<nome-do-pacote>/MainActivity.java. A exibição vem de app/src/main/res/layout/activity_main.xml, o texto de app/src/main/res/values/strings.xml e o tema de app/src/main/res/values/styles.xml.
• Kotlin: pode ser compilado no dispositivo (offline) usando o compilador Kotlin incluído no aplicativo, ou por meio do GitHub Actions. MainActivity está localizado em app/src/main/java/<nome-do-pacote>/MainActivity.kt, e os arquivos res são os mesmos de um projeto Java. A primeira compilação em Kotlin é mais lenta devido ao grande tamanho do compilador, e arquivos .java que referenciam classes Kotlin ainda não podem ser compilados (arquivos .java são compilados antes dos arquivos .kt).
• Compose: um aplicativo Android moderno cuja interface é criada com Jetpack Compose (não layouts XML). MainActivity está localizado em app/src/main/java/<nome-do-pacote>/MainActivity.kt. Projetos Compose são compilados por meio do GitHub Actions (o menu Compilar projeto, depois Compilar online) ou no Termux com Gradle, porque o Compose requer as bibliotecas do Jetpack Compose, que não estão disponíveis no dispositivo.
• Python: a lógica do aplicativo é escrita na linguagem Python (Chaquopy) em app/src/main/python/main.py, e é executada pelo host MainActivity.java em app/src/main/java/<nome-do-pacote>/MainActivity.java. Projetos Python podem ser compilados diretamente no telefone (o runtime do Chaquopy está incluído no aplicativo) ou por meio do GitHub Actions. O SDK mínimo para projetos Python é 24 (Android 7.0).

Alterar arquitetura do projeto
Para alterar as opções de arquitetura de um projeto existente sem criar um novo: no menu principal, toque em Alterar arquitetura do projeto, depois escolha um projeto e altere a caixa Compilar APK de 64 bits (arm64-v8a) ou Compilar APK de 32 bits (armeabi-v7a); ou em Gerenciar projetos, pressione longamente o nome de um projeto e escolha Alterar arquitetura para abrir a mesma tela diretamente para esse projeto. A regra é: se as duas caixas estiverem marcadas, a compilação produz dois APKs separados, um de 64 bits e um de 32 bits; se apenas uma caixa estiver marcada, a compilação produz um único APK universal que continua funcionando em dispositivos de 64 bits e de 32 bits. Um APK separado para uma única variante ainda não é suportado, porque o caminho de compilação só conhece a escolha dividida ou universal, mas a escolha de cada variante permanece salva dentro do projeto para não se perder ao reabrir a tela.

Estrutura de arquivos dos projetos Java, HTML, Site, Kotlin, Compose e Python
Os projetos Java, HTML, Site, Kotlin, Compose e Python são estruturados como os projetos Android em geral. Dentro da pasta app há a pasta src, e dentro dela há a pasta main. Dentro da pasta main há AndroidManifest.xml ao lado da pasta java, a pasta res contendo layout/activity_main.xml e values/strings.xml, bem como values/styles.xml, e para HTML e Site há a pasta assets contendo index.html (Site também tem tentang.html e kontak.html). Os projetos HTML e Site também têm seu próprio MainActivity em app/src/main/java/<nome-do-pacote>/MainActivity.java, que carrega index.html em um WebView e se torna o launcher no AndroidManifest. Os projetos Python têm o código Python em app/src/main/python/main.py e o host MainActivity.java em app/src/main/java/<nome-do-pacote>/MainActivity.java. AndroidManifest.xml, layouts, strings e estilos podem ser abertos e alterados no editor, assim como MainActivity. Projetos antigos cujo manifesto ainda está ao lado da pasta app ainda podem ser compilados, porque ao compilar, o aplicativo verifica primeiro AndroidManifest.xml em app/src/main/, depois o que está ao lado da pasta app, e por último o arquivo de dados do projeto.

Regras de permissões (importante)
As permissões marcadas ao criar um projeto são registradas em apenas um lugar, de acordo com o tipo de projeto. Para projetos Java, HTML, Site, Kotlin, Compose e Python, as permissões marcadas são registradas APENAS em AndroidManifest.xml localizado em app/src/main/, ao lado da pasta java, dentro da pasta do projeto. O arquivo de dados do projeto para projetos Java, HTML, Site, Kotlin, Compose e Python não contém uma lista de permissões. Se você escolher Java e depois marcar INTERNET e CAMERA, o que é registrado em AndroidManifest.xml é apenas INTERNET e CAMERA, sem nenhuma outra permissão incluída. Ao compilar, o aplicativo lê as permissões do mesmo lugar: de AndroidManifest.xml em app/src/main/ para projetos Java, HTML, Site, Kotlin, Compose e Python (se não houver nenhum, de AndroidManifest.xml ao lado da pasta app para projetos antigos), e do arquivo de dados do projeto para projetos antigos.

Como usar o editor
Abra Gerenciar projetos, toque no nome de um projeto para abrir o editor. No editor, arquivos podem ser abertos, código pode ser escrito e alterações podem ser salvas. Para projetos Java, HTML, Site, Kotlin, Compose e Python, os arquivos são organizados dentro da pasta app/src/main. Para compartilhar um projeto, use Exportar ZIP (veja a seção abaixo).

Como executar um projeto
No editor, toque em Executar para testar o projeto. Para projetos HTML e Site, o que é executado é index.html por meio do WebView. Se ocorrer um erro, leia a mensagem de erro, corrija o código e execute novamente.

Como compilar um APK
No editor, toque em Compilar. Há duas maneiras de compilar. Primeira, Compilar no dispositivo: compila diretamente no telefone sem internet, para projetos HTML, Site, Java, Kotlin e Python. Segunda, Compilar online por meio do GitHub Actions: compila pela internet no GitHub e pode ser usada para todos os tipos de projeto. Projetos Compose só podem ser compilados da segunda maneira (Compilar online) ou no Termux com Gradle, porque o Compose requer as bibliotecas do Jetpack Compose, que não estão disponíveis no dispositivo. O resultado da primeira compilação ainda não está assinado. Depois disso, o aplicativo o assina: automaticamente com a chave incorporada, ou com uma assinatura pessoal se a caixa "Usar assinatura pessoal" estava marcada ao criar o projeto.

Como instalar um APK
Quando o APK estiver pronto, toque em Instalar para instalá-lo. No Android 8 e superior, o telefone pedirá primeiro "Permitir desta fonte", porque este aplicativo instala APKs de fora da Play Store. Ative essa permissão uma vez nas Configurações e depois volte ao aplicativo: a instalação continuará automaticamente sem precisar tocar em Instalar novamente. Se o botão Instalar não aparecer, certifique-se de que a compilação terminou e o APK foi criado.

Como assinar um aplicativo
Todo APK deve ser assinado para poder ser instalado. Há duas opções disponíveis. Primeira, a chave incorporada: o aplicativo assina por si só automaticamente, sem que você precise fazer nada. Segunda, uma assinatura pessoal: primeiro crie um keystore por meio do menu Criar keystore no menu principal, guarde sua senha com cuidado e depois marque "Usar assinatura pessoal" ao criar o projeto. O keystore é armazenado em Download/project/signing.

Exportar um projeto para ZIP
Exportar ZIP é fornecido para que os projetos possam ser compartilhados com amigos. Como fazer: em Gerenciar projetos, pressione e segure o nome do projeto, depois escolha Exportar ZIP. O resultado é salvo em Download/project/<NomeDoProjeto>.zip. A pasta bin não é incluída, então o tamanho é pequeno, apenas dezenas de KB. Esse arquivo ZIP pode ser enviado a amigos ou carregado para o GitHub.

Extensão JAWS
A Extensão JAWS usa o mecanismo de extensões do Jieshuo (CSR), não o seu leitor de tela. Dessa forma, os designs podem continuar funcionando mesmo que o usuário use o TalkBack. Como fazer: abra Extensão JAWS no menu principal. Como o clique automático funciona sozinho, o serviço deve primeiro ser ativado nas Configurações de acessibilidade. Depois disso, um novo design pode ser criado: digite o nome do design, toque em OK e preencha suas caixas.

Lista de Cliques mantida separada para ficar organizada
Dentro de um design há duas caixas: a caixa de script e a caixa Lista de Cliques. A lista de botões é armazenada separadamente no arquivo daftar_klik.txt, um nome por linha. Um exemplo de seu conteúdo: tombolSimpan, tombolHapus, tombolBuka. Para abrir um aplicativo, basta escrever >WhatsApp nessa lista. Designs antigos que ainda não têm um arquivo daftar_klik.txt exibirão esse exemplo padrão.

Funções simples fornecidas
• klikTombol("tombolSimpan") — clica em um botão com base em seu texto.
• klikDaftarTombol(daftar) — clica na lista em daftar_klik.txt, um botão por linha, em ordem, e depois informa quantos tiveram sucesso e quantos não foram encontrados.
• bukaAplikasi("WhatsApp") — abre um aplicativo pelo nome, ou escreva ">WhatsApp" na lista.
• klik(540, 1200) — clica nas coordenadas da tela.
Todas as funções são feitas simples primeiro. Quando você se acostumar com elas, funções adicionais podem ser adicionadas depois.

Sobre leitores de tela
Este aplicativo foi projetado para ser amigável a leitores de tela. Cada campo de entrada tem um rótulo e um exemplo de preenchimento, e todos os botões podem ser alcançados sem gestos complicados. A Extensão JAWS foi feita para continuar funcionando mesmo que o usuário use o TalkBack, porque o que é usado é o seu mecanismo de extensões, não o seu leitor de tela.

Privacidade e segurança
Projetos e keystores são armazenados no seu telefone. O token do GitHub é usado apenas para compilações online e é armazenado dentro deste aplicativo. Não compartilhe seu token ou a senha do seu keystore com ninguém. Se você usar uma assinatura pessoal, guarde o keystore e sua senha em um lugar seguro, porque se forem perdidos, APKs antigos não poderão ser atualizados com a mesma assinatura.

Requisitos
Android 5.0 ou mais recente. Permissão de armazenamento: no Android 11 e superior, usa a permissão de acesso a todos os arquivos; no Android 10 e inferior, usa a permissão de armazenamento comum (ler/escrever armazenamento), porque o Android 10 não tem a permissão de acesso a todos os arquivos. Compilar no dispositivo requer um telefone com processador ARM (32 ou 64 bits). Compilar online por meio do GitHub Actions requer internet e um token do GitHub. Projetos Kotlin podem ser compilados no dispositivo, mas a primeira compilação é mais lenta e usa mais memória devido ao grande tamanho do compilador Kotlin. Projetos Compose são compilados por meio do GitHub Actions ou no Termux com Gradle. Projetos Python requerem Android 7.0 ou mais recente (SDK mínimo 24) e o APK resultante é maior porque inclui o runtime do Python (Chaquopy) junto com sua biblioteca padrão.

Terminal
O menu Terminal na tela principal abre um terminal dentro deste aplicativo. Comandos como ls podem ser usados para ver o conteúdo da pasta do projeto, cd para se mover entre pastas e git para gerenciar o código. A saída dos comandos aparece como texto que pode ser lido por um leitor de tela, e há um botão Ler resultado em voz alta para ouvir o último resultado. Este terminal usa o shell do sistema do telefone, então programas interativos como nano e vim ainda não podem ser usados aqui.

Licença (versão paga)
Para vender um aplicativo, marque "Ativar licença" ao criar o projeto e depois preencha seu número de WhatsApp. O aplicativo compilado pedirá um código de licença quando for aberto pela primeira vez: o usuário vê seu ID de dispositivo, toca no botão Enviar ID do dispositivo para enviar esse ID ao seu WhatsApp, e então você responde com o código de licença. O código de licença é calculado a partir do ID do dispositivo e da senha do projeto (lisensi_seed no arquivo de dados do projeto) — guarde essa senha com cuidado e não a compartilhe. Depois que o código correto é inserido, o aplicativo abre e não pede um código novamente.

Criador Automático de Ícones
Os ícones de novos projetos ainda são transparentes, então um Criador de ícones está disponível no menu principal. Como fazer: toque em Criador de ícones, escreva uma ou duas letras (por exemplo, as iniciais do nome do aplicativo), escolha uma cor de fundo e uma cor de texto, veja a prévia e depois toque em Salvar no projeto para usar esse ícone no projeto selecionado, ou Salvar em Downloads para usar seu arquivo PNG em outro lugar. Depois que um projeto é criado, o aplicativo também oferece a criação de um ícone. O ícone antigo de um projeto pode ser substituído a qualquer momento pelo menu do projeto em Gerenciar projetos (pressione e segure o nome do projeto, depois escolha Alterar ícone).

Modelos de Projeto Prontos para Uso
Se você não quiser começar de um projeto vazio, escolha um modelo ao criar um projeto: Calculadora (Java), Notas (Java), Lista de Tarefas (Kotlin), Calculadora Web (HTML), Site de Perfil (Site) ou Contador (Compose). Escolher um modelo altera automaticamente o tipo de projeto para seguir esse modelo, e o projeto é criado com código inicial pronto — basta executá-lo ou alterá-lo. Se o tipo de projeto for alterado manualmente novamente depois de escolher um modelo, o modelo é cancelado e o projeto volta a ficar vazio. Para modelos HTML e Site, o modelo substitui o conteúdo de index.html, incluindo o script HTML digitado no formulário.

Backup e Restauração de Projetos
Para que os projetos não se percam, há um recurso de backup disponível. Como fazer: em Gerenciar projetos, pressione e segure o nome do projeto, depois escolha Fazer backup. O backup é salvo como um ZIP na pasta Download/backup com o nome do projeto e a data, por exemplo: GarudaDecode-2026-11-14-123045.zip. Seu conteúdo é o mesmo de Exportar ZIP (todo o conteúdo do projeto, sem a pasta bin). Para restaurar: abra o menu em Gerenciar projetos, escolha Restaurar backup e depois escolha o arquivo de backup. Se o nome do projeto já existir, o aplicativo perguntará: Sobrescrever o projeto antigo, ou salvar com um Novo nome.

Compartilhar e Importar Projetos
Para compartilhar um projeto com amigos: em Gerenciar projetos, pressione e segure o nome do projeto, depois escolha Compartilhar. O projeto é enviado como um ZIP por meio de aplicativos de compartilhamento (WhatsApp, Telegram e outros). Para receber um projeto de um amigo: abra o menu em Gerenciar projetos, escolha Importar projeto e depois escolha o arquivo ZIP. Esse arquivo ZIP deve conter um arquivo de dados do projeto — se não houver nenhum, o arquivo é rejeitado com uma mensagem clara, porque esse arquivo não é um projeto do Create Aplikasi. Se o nome do projeto já existir, o aplicativo perguntará: Sobrescrever o projeto antigo, ou salvar com um Novo nome.

Busca e Filtro de Projetos
Se já houver muitos projetos, em Gerenciar projetos há uma caixa de busca e um filtro de tipo. Digite o nome do projeto na caixa de busca e a lista é filtrada imediatamente (letras maiúsculas e minúsculas não são diferenciadas). O filtro de tipo limita a lista a apenas um tipo: Todos, HTML, Site, Java, Kotlin, Compose ou Python. O menu de cada projeto ainda pode ser aberto como de costume a partir da lista já filtrada.

Criar Aplicativos com a Voz
Se não quiser digitar, use a voz: toque em Criar com a voz no menu principal e depois diga um comando. Comandos que pode dizer: "Buat proyek kalkulator", "Bangun proyek Kalkulator", "Buka proyek Kalkulator", "Jalankan proyek Kalkulator", "Daftar proyek", "Buka ikon", "Kembali" e "Bantuan". O aplicativo responde com voz e texto, por isso continua a poder ser usado sem olhar para o ecrã. O reconhecimento de voz usa a aplicação de reconhecimento de voz integrada do telemóvel (gratuita; pode funcionar offline se o pacote de idioma indonésio estiver instalado). Se o telemóvel não tiver reconhecimento de voz, os comandos podem ser escritos na caixa de texto do mesmo ecrã.

Criador de apps com IA
Digite ou dite o aplicativo que você deseja na tela do Criador de apps com IA, por exemplo: "um aplicativo de notas com um botão de salvar". O aplicativo analisa as palavras-chave dentro do próprio telefone (sem internet, sem custo) e depois cria um projeto real a partir do modelo mais adequado: calculadora, notas, lista de tarefas, calculadora web, site de perfil ou contador. Se a sua descrição ainda não tiver um modelo adequado, o aplicativo cria um projeto vazio e diz isso com honestidade — não finge entender. Um projeto criado pela IA pode ser aberto diretamente em Gerenciar projetos.

Pré-visualização Direta no Celular de um Amigo
Para mostrar um projeto a um amigo antes de compilá-lo: em Gerenciar projetos, pressione e segure o nome do projeto e escolha Prévia para o telefone de um amigo. O aplicativo cria um pequeno pacote de prévia com os arquivos principais do projeto (index.html, MainActivity ou main.py) mais BACA-SAYA.txt com instruções e info.txt. O pacote é enviado como ZIP pelo WhatsApp ou Telegram. O amigo que o recebe pode abrir a prévia imediatamente: as páginas HTML abrem no navegador, o código Java/Kotlin/Python é lido como texto.

Mercado de projetos
O Mercado de projetos contém projetos de exemplo embutidos que podem ser instalados na pasta do projeto com um toque: Calculadora, Notas, Lista de tarefas, Calculadora web, Site de perfil, Contador, Relógio digital e Quiz web. O mercado online (baixar exemplos da internet) ainda não está disponível, por isso este mercado contém exemplos que já estão dentro do aplicativo. Um projeto instalado pode ser aberto e alterado em Gerenciar projetos como um projeto feito por você mesmo.

Colaboração direta
Para trabalhar em um projeto junto com um amigo: abra Colaboração no menu principal, escolha o projeto, escreva uma nota de alteração (o que foi alterado) e pressione Compartilhar para colaborar. O projeto é enviado como ZIP junto com um arquivo CATATAN.txt dentro. Seu amigo trabalha nele e devolve o ZIP; você pressiona Receber Resposta, primeiro lê a nota de alteração e depois escolhe Aplicar para substituir o projeto antigo, ou Cancelar se mudar de ideia. Um ZIP sem CATATAN.txt não é um pacote de colaboração — para um ZIP de projeto comum, use Importar projeto em Gerenciar projetos.

Tradutor Automático de Aplicativos
Para traduzir o texto de um aplicativo para outro idioma: abra Tradutor de aplicativos no menu principal, escolha o projeto e o idioma de destino (inglês, árabe ou javanês) e pressione Traduzir. O dicionário já está dentro do telefone (sem internet, sem custo) e contém palavras comuns do dia a dia; o texto de strings.xml, do layout e do código é lido e depois traduzido. O resultado é escrito na pasta values-idioma/strings.xml (se o projeto tiver um strings.xml) e em um relatório traducao-idioma.txt na pasta do projeto. As palavras que ainda não estão no dicionário são deixadas como estão e relatadas — assim você sabe quais palavras ainda precisam ser traduzidas por você mesmo.

Criador de Jogos Sem Código
Para criar um jogo sem escrever código: abra Criador de jogos no menu principal, escolha o tipo de jogo (Adivinhe o número, Quiz ou Pegue a estrela), preencha o nome do jogo, a quantidade (níveis/perguntas/estrelas) e a mensagem de vitória e pressione Criar jogo. O jogo é criado como um projeto real que pode ser executado diretamente em Gerenciar projetos e compilado em APK como qualquer outro projeto.

Teste Automático de Aplicativos
Para verificar um projeto antes de compilá-lo: em Gerenciar projetos, pressione e segure o nome do projeto e escolha Teste Automático. A IDE verifica 10 coisas sem compilar um APK — arquivos obrigatórios presentes (arquivo de dados do projeto, manifesto, arquivo principal, layout, strings), nome do pacote e versão, permissões usadas, ícone e equilíbrio dos parênteses do código. O resultado é exibido por item (APROVADO/REPROVADO com uma mensagem) e lido em voz alta pelo Jieshuo. Corrija primeiro tudo o que foi REPROVADO e depois pressione Compilar projeto.

AI Verificador de Código
Para verificar o código do projeto em busca de padrões que costumam causar problemas: abra Verificar código no menu principal, escolha o projeto e pressione Verificar código. O verificador roda dentro do telefone (sem internet) e procura variáveis sem uso, funções vazias, loops sem fim evidentes, texto escrito diretamente no código (melhor em strings.xml), permissões e APIs perigosas, marcadores TODO/FIXME e execução dinâmica. Cada achado contém o nome do arquivo, o número da linha e uma sugestão de correção. Este verificador é baseado em padrões, não é uma IA real — problemas que não seguem um padrão ainda podem passar.

Modo de aprendizagem interativo
Para aprender a criar aplicativos passo a passo: abra Aprender no menu principal. Há 5 lições: Criar seu primeiro projeto, Adicionar um botão, Mudar a cor, Adicionar som e Compilar um APK. Toque em uma lição para ler sua explicação e sua tarefa prática, faça a tarefa e depois pressione Verificar tarefa — a IDE verifica de verdade se a tarefa já foi feita (escaneando o projeto e o APK no seu telefone). As lições aprovadas são marcadas como concluídas e salvas.

Sincronização na nuvem
Para fazer backup de um projeto na nuvem: abra Sincronização na nuvem no menu principal. Um backup local salva o ZIP do projeto na pasta Download/cloud com um carimbo de data e hora, e pode ser restaurado a qualquer momento a partir da lista de backups. Um backup no GitHub envia o ZIP do projeto para o seu repositório privado (usando o token das Configurações do GitHub) e pode ser baixado novamente. Isto é backup e restauração manual — a sincronização automática completa nos dois sentidos precisa de um servidor, por isso ainda não está disponível.

Criador automático de backend
Para criar um backend sem escrever código de servidor: abra Criador de backend no menu principal, escolha o tipo de backend (Notas, Lista de tarefas ou Quadro de mensagens), preencha o nome do projeto e pressione Criar Backend. A IDE cria um projeto HTML real com uma página de formulário e uma lista de dados salva no armazenamento local do telefone (localStorage) — os dados são salvos e podem ser lidos novamente quando o aplicativo é executado. Este backend roda em um só telefone; dois telefones ainda não podem compartilhar os mesmos dados porque não há um servidor de internet.

Designer Automático de Temas
Para dar um tema de cor a um projeto: abra Designer de temas no menu principal, escolha o projeto e o tema (Claro, Escuro, Azul, Verde, Vermelho ou Roxo). A prévia mostra as seis cores do tema (primária, primária escura, destaque, fundo, texto, texto secundário) e é lida em voz alta pelo Jieshuo. Pressione Aplicar Tema — a IDE escreve colors.xml e styles.xml (estilo app_theme) no projeto, usados diretamente quando o projeto é executado ou compilado.

Criador de animações
Para dar animação a um projeto: abra Criador de animações no menu principal, escolha o projeto, o tipo de animação (Fade, Deslizar, Girar, Saltar ou Pulsar), a duração (100 a 10000 milissegundos) e o alvo (botão, texto ou imagem) e pressione Criar Animação. A IDE escreve um arquivo de animação real (res/anim/anim_<tipo>.xml para projetos Java/Kotlin/Compose, ou animasi.css para projetos HTML/Site web) junto com um exemplo de código de uso exibido na tela.

Gravador de ações
Para repetir o trabalho automaticamente: a IDE registra as ações realizadas (abrir um projeto, executar, compilar, exportar, fazer backup, criar um projeto, salvar um arquivo). Abra Gravador de ações no menu principal para ver a lista de ações gravadas com seu plano e pressione Repetir — a IDE executa novamente as ações que podem ser automatizadas (fazer backup e criar um projeto executam no local; executar, compilar e exportar abrem sua tela principal; abrir e salvar abrem o editor). As ações que não podem ser automatizadas são ignoradas e relatadas no final.

Segurança automática
Para verificar a segurança de um projeto: abra Segurança automática no menu principal, escolha o projeto e pressione Verificar Segurança. A IDE verifica 8 coisas localmente (sem internet): permissões perigosas (localização, SMS, chamadas, câmera, microfone, contatos), envio de dados por HTTP, envio de SMS, chamadas de saída, uma senha ou chave escrita diretamente no código, um WebView sem proteção, um componente exportado sem permissão e um endereço http sem criptografia. Cada achado recebe um nível SEGURO, AVISO ou PERIGO com uma sugestão de correção, e o resumo é lido em voz alta pelo Jieshuo.

IA offline
Para usar ferramentas de ajuda de texto e código sem internet: abra IA offline no menu principal. Há 4 ferramentas: Corrigir Texto (maiúsculas, pontuação e espaços duplos), Resumir Texto (pega as 3 frases mais importantes), Criar Nome de Aplicativo (a partir da descrição escrita) e Sugerir Nome de Variável (procura nomes de variável de 1-2 letras no projeto). Estas são regras simples dentro do telefone, não um modelo de IA real. O resultado da correção de texto pode ser aplicado ao strings.xml do projeto com o botão Aplicar.

Criador de Widgets e Papéis de Parede
Para criar um widget da tela inicial: abra Widgets e papéis de parede no menu principal, escolha o projeto, preencha o texto do widget e pressione Criar Widget. A IDE escreve WidgetSaya.java, o layout do widget, as informações do widget e adiciona um receptor ao AndroidManifest.xml do projeto — compile o projeto e depois instale o widget a partir da tela inicial do telefone. Para um papel de parede: preencha o texto e as cores de fundo e de texto, crie uma prévia e depois salve-o como PNG na pasta Download ou defina-o diretamente como papel de parede do telefone.

Integração com redes sociais
Para adicionar botões de compartilhamento a um aplicativo: abra Redes sociais no menu principal, escolha o projeto e adicione o compartilhamento para WhatsApp, Facebook ou Telegram (ou os três de uma vez). A IDE escreve código real de compartilhamento no arquivo principal do projeto (MainActivity ou index.html). O botão Testar Compartilhamento abre o seletor de compartilhamento a partir da IDE com um texto de exemplo, para que o fluxo possa ser sentido antes de compilar o aplicativo.

App a partir de imagem
Para criar um aplicativo de galeria a partir de uma imagem: abra App a partir de imagem no menu principal e escolha uma imagem da galeria. A IDE analisa o tamanho da imagem e a cor dominante e depois cria um projeto real de aplicativo de galeria: a imagem é copiada para os assets do projeto, a cor do tema é tirada da cor dominante da imagem e o nome do aplicativo é tirado do nome do arquivo de imagem. Abra Gerenciar projetos para executar ou compilar esse aplicativo de galeria.

Terminal interativo (analisador VT)
Para usar programas interativos no Terminal: abra Terminal no menu principal e execute nano, vim, top ou htop. O Terminal agora usa um analisador VT (uma tela de grade de 24 linhas x 80 colunas) para que esses programas sejam exibidos corretamente — o cursor se move, as linhas são apagadas e a tela muda como em um terminal real. Há botões especiais Tab, Seta para cima, Seta para baixo e Esc para controlar programas interativos. A saída continua sendo texto que o Jieshuo pode ler; pressione Ler a tela em voz alta para ouvir a última linha.

Terminal Exec (Binário do Aplicativo)
Para executar um binário na pasta do aplicativo (por exemplo aapt2, ECJ, D8) a partir do Terminal: digite o comando como sempre. A IDE usa libkautsarexec.so para que os binários da pasta do aplicativo possam ser executados no Android 10 e acima. Pressione Teste de Exec no Terminal para verificar se o caminho exec de binários funciona neste telefone — o resultado é exibido como é. Se o exec for bloqueado pelo sistema, os comandos do sistema e os scripts de shell continuam funcionando; execute o binário pelo menu Compilar projeto.

Terminal Sempre Ativo (KeepAlive)
Para manter o shell em execução ao mudar de tela: abra o Terminal, execute um comando e depois pressione Voltar ou mude para outra tela — o shell NÃO morre, e a notificação do Terminal continua visível para que você possa voltar com um toque. Os comandos já executados são guardados no histórico (botão Histórico, ou as setas para cima/baixo no campo de comando) e os comandos usados com frequência podem ser salvos como favoritos (botão Favoritos). Pressione Fechar shell quando terminar, para que o shell seja realmente encerrado. Há também um botão Compilar no Terminal no menu do projeto e no menu do editor: o Terminal abre na pasta do projeto com o comando de compilação já preenchido.

Instalar Ferramentas do Terminal (Teste)
Um recurso ainda em teste: no Terminal há um botão Instalar Ferramentas do Terminal para instalar um ambiente Termux a partir do espelho no repositório alat-termux do desenvolvedor (github.com/syudat/alat-termux), como outro caminho além do botão Instalar Termux que pega da versão oficial do Termux. O conteúdo do espelho é exatamente o mesmo da versão oficial e é verificado com SHA-256 durante a instalação. Depois que o ambiente é instalado, os comandos pkg update e pkg install podem ser usados, e ferramentas extras do repositório também são instaladas no terminal: info-terminal para ver informações do ambiente, bersih-terminal para limpar o cache e cadangkan-proyek para arquivar a pasta do projeto em um único arquivo tar.gz datado. Depois disso, o aplicativo instala automaticamente os pacotes básicos do Linux (git, python, curl, wget, nano, openssh, zip, unzip) e as ferramentas de compilação de APK com assinatura (openjdk-21, kotlin, gradle, ecj, aapt2, d8, apksigner, clang, cmake, ninja, make) a partir do repositório oficial do Termux, para que o terminal fique pronto de imediato para criar aplicativos. Baixar pacotes grandes (centenas de MB) pode demorar muito. Enquanto a instalação está em andamento, o progresso e a saída dos comandos aparecem na tela principal do Terminal, e o resultado final é lido em voz alta pelo leitor de tela. Se a instalação dos pacotes ainda não estiver concluída, pressione Instalar Ferramentas do Terminal novamente para continuá-la.

Modo de Voz Completo
Para controlar a IDE completamente por voz: abra Modo de voz no menu principal e pressione Começar a Ouvir. A IDE ouve continuamente — não é preciso pressionar um botão para cada comando — executa o comando e responde por voz. Há 26 comandos: criar, compilar, abrir, executar, listar, pesquisar, excluir, testar, verificar, exportar, fazer backup, compartilhar, criar ícone, traduzir, compilar no terminal, ler a tela, abrir todas as telas (incluindo segurança, IA offline, widget, redes sociais, jogo, aprender, nuvem, backend, tema, animação, gravador), voltar, fechar e ajuda. Se o modo for deixado ativo, a escuta continua automaticamente quando esta tela é aberta novamente. Pressione Parar de Ouvir para desligar este modo. Se o telefone não tiver serviço de reconhecimento de voz, os comandos ainda podem ser escritos na caixa de texto.

Tradutor de código
Para traduzir código entre linguagens sem internet: abra Tradutor de código no menu principal, escolha o projeto, escolha o arquivo de origem (.java/.kt) e depois escolha a direção: Java para Kotlin. Pressione Traduzir — o resultado é exibido junto com um relatório das linhas que não podem ser traduzidas (essas linhas são mantidas como estão e marcadas). Pressione Salvar resultado para escrever um arquivo NOVO (nome-traducao.java/.kt) na mesma pasta; o arquivo original nunca é sobrescrito. Este é um tradutor de regras de padrões, não um compilador — verifique sempre o resultado antes de usá-lo.

Git dentro do app
Para usar o Git dentro da IDE sem Termux: abra Git dentro do app no menu principal, escolha o projeto e pressione Criar Repositório Git para criar um repositório local (.git) nesse projeto. Pressione Verificar Status para ver arquivos novos, alterados ou excluídos em comparação com o último commit; preencha a mensagem do commit e pressione Confirmar para salvar um instantâneo do projeto; pressione Ver Log de Commits para ver o histórico de commits. Enviar ao GitHub e Baixar do GitHub usam instantâneos por meio de um token do GitHub (o repositório pembuat-aplikasi-build) — não o protocolo git. Clonar, Enviar (git do sistema) e Baixar (git do sistema) só funcionam se o binário git estiver instalado no telefone (geralmente não está). Isto não é o git completo: não há merge, branch ou diff — cada commit guarda um instantâneo ZIP completo do projeto.

Criador de anúncios
Para adicionar anúncios a um aplicativo compilado: abra Criador de anúncios no menu principal, escolha o projeto, o provedor (AdMob, Unity Ads ou AppLovin) e o tipo de anúncio (Banner, Intersticial ou Recompensado). Preencha o ID da unidade de anúncio se você já tiver um — vazio significa usar um ID de teste (o AdMob usa o ID de teste oficial do Google; o Unity usa um ID de jogo de exemplo; o AppLovin usa um posicionamento vazio). Pressione Criar Código de Anúncio para ver o código Java e Kotlin e o guia; pressione Salvar no Projeto para escrever tudo no arquivo anuncios-<provedor>-<tipo>.txt do projeto. Isto é um modelo de código + guia, não um SDK de anúncios — o SDK não está incluído na IDE; os anúncios reais só aparecem depois que você cria uma conta de provedor, cria uma unidade de anúncio, cola seu próprio ID de unidade e adiciona a dependência do SDK no build.gradle do projeto.

Modo infantil
Para usar a IDE junto com uma criança: abra Modo infantil no menu principal. A tela é simplificada com botões grandes e apenas 4 ações seguras: Criar projeto (a partir de modelos seguros: Calculadora, Adivinhe o número, Quiz, Pegue a estrela), Abrir Projeto, Executar e Aprender. Não há botão de excluir, exportar, fazer backup ou de configurações de token nesta tela. Ao entrar pela primeira vez, crie um PIN de 4 dígitos — esse PIN é usado pelos pais para sair do Modo infantil (o botão Sair do modo infantil ou o botão Voltar). Este PIN é uma proteção leve para crianças pequenas, não uma segurança real.

Criador de Aplicativos Wear OS e TV
Para criar um aplicativo de relógio (Wear OS) ou de TV (Android TV): abra Wear OS e TV no menu principal e escolha o alvo (Wear OS, Android TV ou ambos). Preencha o nome do projeto e pressione Criar Novo Projeto Wear/TV — a IDE cria um projeto Java e depois o ajusta — ou escolha um projeto que já exista e pressione Aplicar a Este Projeto. Os ajustes: uses-feature no manifesto, a categoria LEANBACK_LAUNCHER + banner para TV, e um layout activity_main.xml ajustado (Wear: tela pequena; TV: tela grande amigável ao D-pad). A explicação completa é escrita em wear-tv.txt no projeto. Isto é um modelo de projeto — compilar + testar ainda precisa de um dispositivo/emulador Wear OS ou Android TV; o banner de TV (banner.png 320x180) não é criado automaticamente, deve ser adicionado por você mesmo (por exemplo, pelo Criador de ícones).

Mapa do projeto
Para ver a estrutura de um projeto: abra Mapa do projeto no menu principal, escolha o projeto e pressione Mostrar Mapa — a IDE mostra a lista de pastas e arquivos com seus tamanhos, o tamanho total, o tamanho por tipo de arquivo e os arquivos importantes (arquivo principal, manifesto, layout, strings, ícone, página web). Pressione Salvar mapa-projeto.txt para escrever o mesmo mapa na raiz do projeto. A pasta bin/ (resultados de compilação) e a pasta .git/ (repositório local) não são mapeadas porque seu conteúdo pode ser criado novamente.

Calculadora de tamanho de APK
Para estimar o tamanho do APK compilado antes de compilar: abra Calculadora de tamanho de APK no menu principal, escolha o projeto e pressione Calcular estimativa. A IDE mostra o detalhamento por categoria (código/DEX, recursos, assets, bibliotecas nativas, manifesto + resources.arsc, sobrecarga), a estimativa total, os 5 maiores arquivos e sugestões para reduzir (por exemplo, imagens grandes têm a resolução reduzida, sons grandes têm a duração cortada). Isto é uma ESTIMATIVA, não o tamanho exato — o tamanho real pode diferir por causa da compressão do aapt2, da remoção de código não usado (R8) e dos recursos compilados.

Analisador de APK
Para ler o conteúdo de um APK já pronto (como o Analisador de APK do Android Studio): abra Analisador de APK no menu principal, escolha o projeto e pressione Análise do APK do resultado da compilação. A IDE lê o APK mais recente na pasta bin desse projeto e relata o nome do pacote, a versão, o SDK mínimo e alvo, a lista de permissões usadas, o número de arquivos dex, o detalhamento de tamanho por parte (código do programa, recursos, assets, bibliotecas nativas, assinatura) e as 10 maiores entradas. Útil para saber qual parte deixa o APK grande e quais permissões o aplicativo compilado usa.

Prévia do tamanho da tela
Para verificar a aparência de um projeto em muitos tamanhos de tela de uma só vez (como no Android Studio): abra Prévia do tamanho da tela no menu principal, escolha o projeto e pressione Verificar Tamanho da Tela. A IDE lê todos os layouts do projeto e relata elementos cuja largura está escrita fixa (por exemplo 400dp) e excede a largura da tela de 320, 360, 411 ou 480 dp, porque em um telefone de tela pequena um elemento assim pode ficar coberto ou transbordar. Elementos com largura match_parent ou wrap_content se ajustam à tela automaticamente e não precisam ser verificados.

Gerenciador de recursos
Para ver e gerenciar todos os recursos de um projeto em um só lugar (como o Gerenciador de recursos do Android Studio): abra Gerenciador de recursos no menu principal, escolha o projeto e pressione Ver Recursos. A IDE relata o número e o tamanho dos arquivos por categoria (drawable, layout, values, mipmap e outros), o conteúdo de strings.xml, colors.xml e styles.xml. A partir da mesma tela, uma nova string pode ser adicionada a strings.xml e uma nova cor a colors.xml preenchendo seu nome e valor — o nome é verificado e duplicatas são rejeitadas, para que o arquivo XML não seja quebrado.

Monitor de desempenho leve
Para monitorar o uso de RAM e processador de um aplicativo em execução (como o Profiler do Android Studio, versão leve): abra Monitor de desempenho leve no menu principal, primeiro execute o aplicativo a ser verificado (por exemplo, o aplicativo compilado que está sendo testado), preencha o nome do seu pacote — ou escolha o projeto e pressione Preencher Nome do Pacote a partir do Projeto — e depois pressione Iniciar Monitoramento. A cada 2 segundos a IDE registra a RAM (PSS) e a CPU desse aplicativo junto com a RAM livre do telefone; pressione Parar para ver o resumo da média e do pico. Sem permissão extra. Nas versões mais novas do Android, o acesso de leitura ao processador de outro aplicativo é limitado pelo sistema, por isso, se a CPU não puder ser lida, o relatório diz isso como é e a RAM continua sendo monitorada.

Auditoria de Acessibilidade
Para verificar se o layout de um projeto é amigável para o leitor de ecrã (TalkBack/Jieshuo) antes de publicar: abra Auditoria de Acessibilidade no menu principal, escolha um projeto e depois toque em Carregar Lista de Layouts e escolha um ficheiro de layout. O IDE lê esse ficheiro XML e indica os botões sem rótulo com os respetivos números de linha, os rótulos usados repetidamente e os elementos que se sobrepõem, e depois constrói uma transcrição da ordem de foco como a que o Jieshuo lê em voz alta. Se um botão não tiver rótulo, preencha o rótulo e depois toque em Inserir Rótulo Automaticamente — o rótulo é escrito no ficheiro de layout como contentDescription. Esta verificação lê apenas XML de layout; as vistas Compose e os APK terminados ainda não são analisados.

Autópsia de Falha
Para descobrir por que um aplicativo fecha sozinho a partir de um registro de falha com um ID único: abra Autópsia de Falha no menu principal, escolha um ID de falha na lista de registros e toque em Verificar. O IDE corresponde a classe e o número de linha no registro com a fonte do projeto e explica a causa em indonésio (por exemplo uma referência vazia, uma permissão ainda não solicitada, ou um erro JSON), com uma sugestão de correção de código. Toque em Aplicar Correção somente se a linha de origem continuar exatamente a mesma de quando a falha aconteceu; se ela mudou, a correção é recusada e o IDE pede que você verifique por conta própria. Para falhas de um aplicativo COMPILADO, toque em Injetar capturador de falhas no projeto e depois compile o APK como sempre: esse aplicativo compilado captura suas próprias falhas e escreve seu registro no telefone, e esse registro pode ser encontrado com o botão Buscar registro de falhas do aplicativo compilado. O limite honesto: copiar o registro para a pasta pública Download no Android 11 ou superior pode falhar sem a permissão de acesso a todos os arquivos.

Transpilador Entre Paradigmas
Para converter código Java simples em Kotlin, ou um layout XML simples em código Compose: abra Transpilador Entre Paradigmas no menu principal, escolha um projeto e um ficheiro e depois toque em Pré-visualizar. O IDE mostra o resultado da conversão como texto — verifique-o primeiro, porque as linhas que não reconhece são deixadas como estão e a palavra static do Java é retirada no Kotlin (verifique o seu significado antes de a usar). A conversão de XML para Compose só muda o texto, as sugestões e a orientação — o tamanho, a cor e outros atributos ainda não são incluídos. Se o resultado estiver correto, toque em Aplicar ao Arquivo para escrever o ficheiro de destino; o ficheiro de origem não é alterado. Só os padrões comuns e seguros são convertidos.

Servidor Micro Local
Para testar um aplicativo que precisa de um servidor sem internet: abra Servidor Micro Local no menu principal, escreva as definições de rota (por exemplo GET /halo e depois sua resposta JSON) e toque em Iniciar Servidor. O IDE executa um pequeno servidor HTTP no mesmo telefone (apenas HTTP, sem TLS, para a mesma rede Wi-Fi) e registra cada solicitação e resposta na tela. As rotas podem usar parâmetros como {nama} e uma chave API simples. O servidor também pode ser empacotado no APK compilado: toque em Empacotar servidor no projeto, e a fonte do servidor, os recursos e o manifesto são injetados no projeto, de modo que o próprio aplicativo compilado se torna o servidor quando é executado. O servidor no IDE para quando sua tela é fechada.

Auditor de Segurança
Para verificar o código de um projeto em busca de falhas de segurança antes do lançamento: abra Auditor de Segurança no menu principal, escolha um projeto e toque em Iniciar Verificação. O IDE examina o código, o manifesto e a configuração do projeto e informa achados de risco alto a baixo — uma chave API deixada aberta no código, um componente exposto sem permissão, um WebView que ativa JavaScript com sua interface JavaScript, criptografia fraca (MD5, SHA1, DES), um endereço http sem TLS, e uma senha escrita diretamente no código — com seus arquivos e números de linha. Para achados cuja correção é segura (por exemplo trocar MD5 por SHA-256 ou http por https), toque em Aplicar Correção; para chaves API e senhas, o IDE apenas mostra a sugestão de correção porque a substituição deve ser decidida pelo desenvolvedor. A verificação agora também analisa o bytecode DEX real dentro do APK compilado (e não apenas padrões de texto no código), de modo que APIs perigosas que são chamadas e segredos embutidos no DEX também são detectados; falhas que não seguem nenhum padrão ainda podem escapar da verificação — verifique antes de aplicar.

Robô de Teste de Interface
Para testar a tela de um aplicativo automaticamente por meio de cenários de texto: abra Robô de Teste de Interface no menu principal, escolha um projeto e toque em Criar Cenário Automaticamente. O IDE lê o manifesto e o layout do projeto e escreve um cenário como passos de texto (tocar em um botão, preencher um campo, aguardar, voltar). Toque em Executar Dry Run para ver o registro de execução do cenário com seus carimbos de data e hora — este dry run continua sendo apenas uma simulação de sequência. Para testes reais, toque em Injetar agente de teste no projeto: o IDE injeta um agente de teste com os recursos do cenário no projeto; compile o APK como sempre, instale-o e abra o ícone Teste — esse agente é executado dentro do aplicativo compilado e realmente toca em botões, preenche campos reais e rola a tela, e depois mostra seu relatório na tela com as falhas reais que capturou. Toque em Remover agente de teste do projeto para remover esse agente novamente. O agente é executado dentro do próprio processo do aplicativo, por isso não precisa de serviço de acessibilidade nem de automação do sistema.

Viagem no Tempo do Código
Para devolver um projeto a um estado anterior do código sem escrever comandos Git: abra Viagem no Tempo do Código no menu principal, escolha um projeto, preencha um rótulo para o ponto no tempo (pode ficar vazio) e depois toque em Registar ponto no tempo. O IDE guarda uma cópia dos ficheiros de código-fonte do projeto juntamente com os respetivos hashes na pasta .riwayat dentro do projeto. A lista de pontos no tempo mostra-os todos; escolha dois pontos e depois toque em Comparar para ver os ficheiros e funções adicionados, alterados ou removidos. Toque em Restaurar para recuperar um estado antigo — antes de restaurar, o IDE faz sempre primeiro uma cópia de segurança do estado atual, por isso nada se perde. Toque em Criar Cópia de Experimento para copiar o projeto para uma pasta nova e experimentar alterações sem incomodar o projeto original. Só os ficheiros de código-fonte são registados.

Fábrica de Módulos
Para empacotar parte de um projeto como um módulo que outro projeto possa usar: abra Fábrica de Módulos no menu principal, escolha um projeto de origem, marque os ficheiros de ecrã, classe, texto e permissões a empacotar e depois toque em Empacotar como Módulo. O IDE escreve um arquivo ZIP juntamente com metadados JSON (nome do módulo, versão, textos e permissões usados). Para instalar um módulo noutro projeto, abra Fábrica de Módulos, escolha o projeto de destino e depois toque em Instalar Módulo e escolha o ficheiro .zip do módulo — a fusão adiciona textos e permissões sem substituir o código existente, e não funde um ficheiro se o seu nome já for usado no projeto de destino. Um módulo não traz bibliotecas nem definições de compilação.

Escudo polimórfico e cofre de recursos
Para embaralhar nomes de identificadores e criptografar os recursos do projeto antes do lançamento: abra Escudo polimórfico e cofre de recursos no menu principal, escolha um projeto e toque em Embaralhar nomes e criptografar recursos. O IDE examina os nomes de classes e métodos no código-fonte, cria um mapa de nomes aleatórios, reescreve esses nomes DENTRO dos arquivos DEX compilados (os nomes substitutos são feitos com o mesmo comprimento dos nomes originais para que todos os deslocamentos continuem válidos, e depois a soma de verificação e a impressão digital SHA-1 do cabeçalho DEX são recalculadas), criptografa os arquivos de recursos do projeto com AES-GCM na pasta brankas-aset dentro do projeto, e salva um mapa de recuperação criptografado (perisai-peta.brankas) para que os nomes originais possam ser restaurados ao ler registros de falhas. A chave de criptografia agora é derivada da senha do desenvolvedor com PBKDF2, 20.000 iterações, e não mais do nome do projeto. Nomes que também são usados como texto simples, nomes de anotação e nomes de depuração não são reescritos de propósito, e os pontos de inserção da reescrita DEX no caminho de compilação ainda aguardam um teste em um telefone real.

Cadeia de confiança e guardião do ambiente
Para verificar a cadeia de chaves de assinatura e o ambiente do telefone antes do lançamento: abra Cadeia de confiança e guardião do ambiente no menu principal, escolha um projeto e toque em Verificar cadeia e ambiente. O IDE constrói uma cadeia de chaves de 5 gerações a partir do nome de pacote do projeto e verifica sua integridade, verifica a integridade real da memória comparando o conteúdo dos segmentos de código na memória com os arquivos no disco e informa mapeamentos anônimos executáveis (RWX), bibliotecas estranhas e mapeamentos memfd, e depois examina o mapa de memória do seu próprio processo e as propriedades do dispositivo em busca de vestígios de Frida, Xposed ou emulador. A chave do cofre é envolvida por uma chave AES no AndroidKeyStore, que usa o chip de segurança de hardware quando disponível, e a rotação de chaves agora é real, usando a linhagem de certificados de assinatura do esquema v3: a chave antiga assina a prova de rotação para a chave nova e o APK é assinado novamente com essa linhagem. O resultado é um nível de risco Seguro, Cautela ou Perigoso, com evidências em texto. Se o sistema recusar a leitura de memória, a verificação é informada como não pode ser verificada, e não como segura; e se uma chave realmente usa o chip de segurança de hardware só pode ser confirmado em um dispositivo real.

Arquiteto de layout em árvore de texto
Para projetar uma tela sem vê-la: abra Arquiteto de layout em árvore de texto no menu principal, escolha um projeto e um arquivo de layout, e toque em Verificar layout. O IDE lê o layout XML como uma árvore de texto e lê em voz alta uma narração de posição para cada elemento (por exemplo embaixo à direita, 45 por cento da largura da tela), e depois informa sobreposições entre elementos e elementos que saem da tela com largura de 360 dp, de forma matemática. O que agora é calculado inclui LinearLayout e tamanhos dp simples, ConstraintLayout completo (todas as restrições, viés, cadeias, guias, barreiras, larguras em porcentagem, 0dp match_constraint e proporções de dimensão) e telas Compose (Column, Row e Box com seus modificadores de tamanho). Apenas MotionLayout e ConstraintSet alterados em execução continuam informados como posição desconhecida, porque seus valores só existem enquanto o aplicativo está em execução.

Estúdio de sistema de design
Para igualar espaçamentos, tipos e cantos em todas as telas e projetos: abra Estúdio de sistema de design no menu principal, escolha um projeto, escreva os tokens de design (por exemplo jarak=8, huruf=16, sudut=12), escolha um componente e toque em Gerar componentes. O IDE valida os tokens — espaçamento base de 4 a 16 dp, tipo base de 12 a 20 sp, cantos de 0 a 32 dp, e uma área de toque mínima de 48 dp — e depois escreve componentes XML prontos para uso (komponen-studio.xml) com um tema XML (tema-studio.xml) e um tema Compose (tema-studio.kt) na pasta do projeto. Os tokens também podem ser salvos como um conjunto nomeado na biblioteca compartilhada de tokens entre projetos, e um único comando de sincronização aplica os tokens mais recentes da biblioteca a todos os projetos que usam esse conjunto. Os componentes são gerados como texto que é colado em um layout e depois verificado com o Arquiteto de layout em árvore de texto; o ajuste de duas colunas em tablet usa um qualificador de largura de tela, e não detecção de dispositivo em execução.

Refatoração semântica e navegação AST
Para encontrar definições e renomear símbolos sem quebrar outro código que por acaso compartilha o nome: abra Refatoração semântica e navegação AST no menu principal, escolha um projeto e toque em Verificar símbolos do projeto para ver todas as classes e métodos com seus arquivos e números de linha. Digite o nome de um símbolo e toque novamente em Verificar símbolos do projeto para ver sua definição e todos os arquivos que o chamam. Para renomear, digite o novo nome, toque em Pré-visualizar renomeação para ver o número de ocorrências em cada arquivo, e depois toque em Aplicar renomeação. O indexador agora usa um analisador AST feito à mão (um analisador léxico e um analisador recursivo para Java e um subconjunto de Kotlin), de modo que renomeações de métodos entre arquivos são resolvidas e os chamadores de outros arquivos também são alterados; o botão para extrair um bloco de código em uma nova função já está nesta tela. Este analisador ainda é mínimo: genéricos muito complexos, anotações com parâmetros e classes anônimas são examinados como estão, enquanto chamadas por reflexão e por interface não são resolvidas.

Depurador passo a passo e inspetor de memória
Para inspecionar o conteúdo de variáveis no meio do fluxo de um programa sem adivinhar através de registros: abra Depurador passo a passo e inspetor de memória no menu principal, escolha um projeto, escreva o rastreamento de execução (um passo por linha, na forma número da linha, código, e depois variáveis e valores separados por |, por exemplo 10|int total = harga * jumlah;|harga=5000, jumlah=3, total=15000), digite o número da linha do ponto de interrupção e toque em Executar rastreamento de depuração. O IDE avança até o primeiro ponto de interrupção e lê em voz alta a linha ativa com seus valores de variáveis através do Jieshuo. Toque em Avançar uma linha para avançar uma linha, Entrar na função para entrar na função chamada (com uma pilha de chamadas), ou Continuar programa para avançar até o próximo ponto de interrupção. Este depurador de rastreamento continua seguindo um rastreamento gravado ou escrito à mão; ao lado dele há um cliente Java puro do protocolo de fio JDWP que pode fazer o handshake, definir pontos de interrupção, entrar, passar por cima e sair, e suspender e retomar a VM por TCP ou em modo de escuta. Suspender um processo real continua não sendo totalmente possível de dentro de um aplicativo comum, porque o soquete JDWP de um processo só é exposto através do adbd — o caminho comprovado precisa de depuração sem fio e do lançamento do alvo através do shell, além do que o próprio aplicativo pode fazer.

Gerenciador de dependências offline
Para usar bibliotecas de terceiros sem internet e evitar conflitos de versão antes de compilar: abra Gerenciador de dependências offline no menu principal, escolha um projeto e toque em Verificar dependências. O IDE lê todos os arquivos .gradle do projeto, verifica o cofre compartilhado entre projetos na pasta Download/brankas-bersama, e resolve conflitos — se duas bibliotecas pedirem versões diferentes do mesmo artefato, a versão mais alta é usada e o conflito é informado. Para baixar uma biblioteca, digite suas coordenadas (na forma grupo:artefato:versão, por exemplo com.google.code.gson:gson:2.10.1) e toque em Verificar dependências: quando online, arquivos AAR, JAR ou WHL são realmente baixados do Maven, Google ou PyPI junto com seu grafo de dependências transitivas (recursivo, ciclos cortados, profundidade de até 25 níveis), e apenas arquivos baixados com sucesso são registrados como disponíveis. Quando offline, apenas bibliotecas que já estão no cofre compartilhado podem ser usadas. Intervalos de versão do Maven não são resolvidos, e arquivos baixados só são verificados pelo seu SHA-1, sem verificação PGP.

Inspetor de banco de dados e armazenamento
Para inspecionar e testar o conteúdo do banco de dados de um projeto sem escrever código que imprima o conteúdo das tabelas: abra Inspetor de banco de dados e armazenamento no menu principal, escolha um projeto e um arquivo de banco de dados (.db, .sqlite ou .sqlite3), e toque em Abrir banco de dados. O IDE lê o esquema de todas as suas tabelas com um analisador completo de páginas SQLite (árvore-B com páginas de overflow) e mostra as primeiras 20 linhas como uma tabela de texto lida em voz alta pelo Jieshuo. Escreva uma consulta SELECT e toque em Executar consulta (por exemplo SELECT nama FROM pengguna WHERE kota = 'Makassar') — as consultas agora suportam JOIN, GROUP BY, ORDER BY e LIKE, e no telefone elas passam pelo mecanismo SQLite real do Android. Para alterar um valor, digite o número da linha (1 = primeira linha), o nome da coluna e o novo valor, e toque em Alterar valor da célula — esse valor é escrito de volta no arquivo .db. Toque em Salvar cópia de segurança para salvar o estado atual da tabela como um arquivo <nome-bd>.cadangan.txt no projeto. SharedPreferences e DataStore também podem ser lidos. O que ainda não pode ser lido: bancos de dados criptografados, alterações WAL não confirmadas, e valores tipados em DataStore Proto especial (mostrados apenas como uma visão genérica de campos).

Fábrica de testes de unidade e fuzzing
Para encontrar falhas de lógica antes de compartilhar um aplicativo: abra Fábrica de testes de unidade e fuzzing no menu principal, escolha um projeto e um arquivo de código, e toque em Criar e executar testes. O IDE lê as assinaturas de função no arquivo, gera casos de teste normais e de limite (texto vazio, null, números máximos, caracteres estranhos), e depois realmente executa esses testes: o código do projeto é compilado e cada método @Test é executado com um limite de 5 segundos, de modo que o resultado são aprovações e falhas reais com seus valores reais. O fuzzing também é executado de verdade sobre funções do projeto (por reflexão, 2 segundos por chamada, no máximo 20 métodos), e a porcentagem de cobertura de linhas é realmente calculada por instrumentação que mantém os números de linha originais. O resultado informa quantos testes passaram e falharam, quantas linhas de código e funções foram encontradas, e os casos de teste criados. Os testes gerados usam exatamente a mesma API do JUnit, mas as definições de anotações e asserções são escritas dentro do próprio arquivo de teste gerado, porque a biblioteca JUnit real não é incluída no aplicativo.

Simulador de condições extremas do dispositivo e auditor de vazamento de memória
Para testar a resistência de um aplicativo quando o sistema mata seu processo, a rede cai, a tela gira ou o economizador de bateria é ativado: abra Simulador de condições extremas do dispositivo e auditor de vazamento de memória no menu principal, escolha um projeto e toque em Executar simulação. O IDE executa três cenários de pressão com uma simulação de rotação de tela e rastreia objetos ainda retidos na memória depois que sua tela é fechada, e depois informa dados perdidos e cadeias de objetos com vazamento. O estado de salvar e restaurar agora é lido da fonte do próprio projeto do usuário, e não de um exemplo fixo; o servidor local de loopback é realmente parado no meio do teste para medir o corte de rede; um despejo de heap real é coletado e analisado para comparar dois despejos e rastrear a cadeia de retenção a partir das raízes do GC; e o próprio processo do aplicativo é realmente encerrado depois que seu estado é salvo, e depois é verificado quais dados voltam ao abri-lo novamente. O que continua impossível a partir de um aplicativo comum: desligar o rádio ou o Wi-Fi do telefone e forçar a parada de outros aplicativos — ambos precisam de permissão de sistema; em vez disso, aplicativos em segundo plano são encerrados por killBackgroundProcesses, cuja permissão já está no manifesto, com um rótulo honesto na tela.

Arquiteto de plantas de projeto
Para transformar uma grande ideia de aplicativo em um plano de trabalho passo a passo: abra Arquiteto de plantas de projeto no menu principal, escolha um projeto, escreva a ideia do aplicativo (por exemplo um aplicativo de caixa para uma pequena mercearia com pagamentos parcelados) e toque em Criar planta. O IDE constrói módulos, uma lista de arquivos e pequenos marcos, e os salva como cetak-biru.txt na pasta do projeto. Toque em Marcar próximo marco como concluído cada vez que um marco for concluído, ou toque em Carregar plano salvo para abrir novamente um plano salvo. Se um provedor de IA ativo for escolhido em Configurações de IA e sua chave estiver disponível, a planta é construída por esse provedor; se não houver chave ou o provedor não puder ser alcançado, o IDE volta aos padrões de palavras-chave offline e diz esse limite com honestidade. Uma resposta do provedor só é verificada quanto ao formato (módulos e marcos presentes), e não quanto à veracidade de seu conteúdo — revise sempre a planta antes de construir.

Narrador do fluxo lógico do código
Para entender código longo sem ouvir a sintaxe linha por linha: abra Narrador do fluxo lógico do código no menu principal, escolha um projeto e um arquivo de código, e toque em Narração de código. O IDE transforma cada linha em uma frase em indonésio (por exemplo se o total for maior que 100000, então execute o bloco seguinte), mostra um mapa de chamadas entre métodos e uma análise de fluxo de dados entre métodos (valores passados, usados ou ignorados), e marca possíveis bugs sutis com seus números de linha — String comparado com ==, um stream aberto sem ser fechado, e uma variável escrita em dois métodos diferentes. Se um provedor de IA ativo for escolhido em Configurações de IA, um resumo de fluxo desse provedor também está disponível; se não estiver disponível, a tela usa a narração offline e diz esse limite. A narração, o mapa de chamadas e o fluxo de dados usam análise offline de padrões de texto, e não um analisador AST completo — métodos cuja chave de abertura está em sua própria linha, campos de classe e chamadas por reflexão não são rastreados — e avisos de corrida de dados podem aparecer para uma variável que na verdade só é usada em turnos.

Fábrica de pacotes de aplicativo e prontidão para a Play Store
Para preparar um aplicativo para a Google Play Store diretamente do telefone: abra Fábrica de pacotes de aplicativo e prontidão para a Play Store no menu principal, escolha um projeto e toque em Criar pacote AAB. O IDE constrói o arquivo .aab a partir do manifesto, dos recursos e dos ativos do projeto junto com um BundleConfig.pb real, valida a estrutura do pacote, e depois divide o pacote em APKs variantes reais (base, por arquitetura, por idioma e universal) com tamanhos medidos a partir dessa divisão, e não estimados. O pacote é assinado com JAR v1 usando a mesma chave de projeto da assinatura de APK, e sua cadeia de assinatura é verificada criptograficamente. Esta tela também audita a prontidão para a Play — um SDK alvo abaixo de 35 é marcado como Alto porque a Play Store exige 35 ou mais, e uma biblioteca de 64 bits ausente também é marcada como Alto. Um bundletool real não pode ser executado no dispositivo, porque o bundletool precisa de uma JVM enquanto o Android não tem JVM; o caminho acima é o mais próximo real no dispositivo.

Mecanismo de atualização OTA e lançamentos graduais
Para enviar uma pequena correção sem obrigar os usuários a baixar todo o APK novamente: abra Mecanismo de atualização OTA e lançamentos graduais no menu principal, escolha um projeto, escreva o conteúdo da versão antiga e da nova, e toque em Criar pacote de patch. O IDE calcula a diferença e cria um pacote de patch (patch-ota.zip) com uma impressão digital SHA-256 do novo conteúdo, e depois verifica se este dispositivo está na primeira etapa de lançamento de 10 por cento. Os patches agora suportam deltas binários sobre qualquer arquivo (incluindo DEX e APK), são empacotados com uma assinatura RSA-2048 e verificados com uma chave pública confiável antes de serem aplicados, e podem ser baixados do servidor do desenvolvedor junto com sua lista de lançamentos; se a aplicação falhar, o arquivo antigo permanece intacto. Aplicar um patch ao aplicativo que está em execução é feito por meio de nova assinatura com a chave do projeto e o PackageInstaller, porque substituir o código de um processo em execução de dentro de si mesmo é impossível — o APK está bloqueado e o DEX já está carregado.

Estúdio de revisão de código em equipe
Para revisar as alterações de um colega e resolver conflitos de mesclagem sem ler as marcas de seta do Git: abra Estúdio de revisão de código em equipe no menu principal, escolha um projeto, digite três versões de texto (base, local, colega) e toque em Abrir revisão da equipe. O IDE mescla as três com base em unidades sintáticas Java — duas alterações na mesma linha mas em instruções diferentes não são mais tratadas como conflito — e mostra cada conflito como uma opção de voto: Usar versão local, Usar versão do colega, ou Mesclar ambas — a linha resultante é inserida na posição original do conflito para que a ordem permaneça correta — e depois escreve o resultado em gabung-hasil.txt no projeto. Abaixo está o quadro de tarefas do projeto: digite o título de uma tarefa e toque em Adicionar tarefa; as tarefas são salvas como texto na pasta .tugas dentro do projeto e sincronizadas por meio de commits no Git do aplicativo, de modo que o quadro pode ser lido novamente a partir de qualquer histórico de commits. Este divisor sintático não é um analisador AST completo e o Git do aplicativo armazena um instantâneo completo por commit; não há servidor de sincronização especial.

Ditado de Estrutura de Código
Para escrever código por voz dentro do editor: abra um projeto no Editor e depois toque no botão Ditado de Estrutura de Código. Diga comandos em indonésio, por exemplo buat fungsi tambah dengan parameter a angka dan b angka, buat kelas Mobil ou buat variabel teks nama sama dengan Budi — o IDE converte a voz num bloco de código Java, Kotlin, Python ou Compose sintaticamente válido e insere-o na posição do cursor, e depois lê em voz alta um breve resumo através do Jieshuo. O ditado usa o serviço de entrada de voz integrado do sistema, sem permissão adicional de microfone, e só reconhece padrões de comandos já registados; a voz fora desses padrões não é convertida em código. Os números ditos por extenso (por exemplo 'lima') ainda não são convertidos em dígitos.

Espaço de Colaboração Local (sem internet)
Para trabalhar em conjunto numa mesma sala sem internet: abra Colaboração no menu principal e depois abra a secção Espaço de Colaboração Local. Um telemóvel abre uma sessão (o IDE mostra um endereço IP local e um PIN de 6 dígitos), outro telemóvel junta-se com esse endereço e esse PIN. As alterações de texto são enviadas como diferenças de linhas, um APK compilado pode ser enviado para o telemóvel do testador e os relatórios de falha do telemóvel do testador são recebidos de volta. Uma sessão é só para um amigo; se duas pessoas alterarem exatamente a mesma linha ao mesmo tempo, é usada a última alteração. O PIN é enviado como texto simples na rede local. Esta sala ainda não foi testada num telemóvel real.

Configurações de IA
Para configurar o provedor de IA e as chaves API para criação de aplicativos: no menu principal, no grupo Configurações, toque em Configurações de IA (ao lado do botão Conector). Escolha o provedor a ser usado na lista disponível, e marque Trocar de modelo quando o provedor falhar para que, se um modelo falhar, o IDE tente automaticamente o próximo modelo do mesmo provedor. Toque em Gerenciar chaves API para adicionar chaves de reserva (digite o nome e a chave, e toque em Salvar; as chaves são mostradas mascaradas, apenas os últimos 4 caracteres visíveis). As chaves são armazenadas no telefone e nunca são enviadas para nenhum lugar, exceto para o provedor escolhido ao criar um aplicativo. O provedor escolhido agora é realmente usado pelo Arquiteto de plantas de projeto e pelo Narrador do fluxo lógico do código; a criação de aplicativos na tela Criador de aplicativos com IA continua usando a IA local do telefone (sem internet).

Conector
Para analisar um APK e depois enviá-lo: no menu principal, no grupo Configurações, toque em Conector (ao lado do botão Configurações de IA). Escolha um ficheiro APK do telemóvel, o IDE lê o seu conteúdo (nome do pacote, versão, lista de atividades) e depois toque em Enviar APK para o enviar através do menu de partilha do sistema (por exemplo, WhatsApp ou Drive).

Idioma e voz
Para mudar o idioma da aplicação: abra Configurações, depois Idioma do app e depois escolha um idioma ou Seguir o sistema. O ecrã principal e a maioria dos ecrãs mudam para o idioma escolhido imediatamente, sem fechar nem reiniciar a aplicação; alguns ecrãs (por exemplo, Terminal, Colaboração, Configurações de IA e Gerenciar chaves) continuam a usar o idioma antigo até serem reabertos. Se escolher Seguir o sistema, o idioma segue o idioma do sistema do telemóvel.

Assinatura Padrão por Projeto e Anti Tamper
Desde a versão 5.7, um projeto que não usa uma assinatura pessoal é assinado com a chave embutida PRÓPRIA desse projeto (criada uma vez na pasta tanda-tangan-bawaan dentro do projeto e depois usada sempre), por isso a assinatura embutida difere de projeto para projeto — não é mais uma chave compartilhada para todos os aplicativos. Não exclua a pasta tanda-tangan-bawaan: sem essa chave, um novo APK não pode substituir o APK antigo do mesmo projeto. As configurações de cada projeto (arquitetura separada, assinatura pessoal, anti-adulteração, keystore escolhido, SDK) agora são salvas no arquivo settings.gradle dentro do projeto e lidas novamente toda vez que o projeto é compilado. Em Configurações, na categoria Assinatura, há uma caixa Anti-adulteração do aplicativo compilado: se estiver ativa, o aplicativo compilado no dispositivo verifica sua assinatura e o conteúdo do seu dex toda vez que é aberto; se foi assinado novamente ou alterado por outra pessoa, o aplicativo se recusa a executar. Ferramentas de depuração e injeção como Frida/Xposed também são detectadas, e a janela do aplicativo é bloqueada contra gravação de tela.

Criador de vídeo de demonstração
Para criar um vídeo de demonstração de um aplicativo compilado: abra Criador de vídeo de demonstração no menu principal, escolha o projeto, preencha o título do vídeo e pressione Criar Roteiro de Vídeo de Demonstração — a IDE escreve video-demo.txt com 5 cenas padrão (abertura, vista principal, recurso 1, recurso 2, encerramento) junto com o texto de narração e a duração de cada cena. Pressione Criar Slideshow HTML para criar video-demo.html a partir das imagens do projeto (ícone + capturas de tela, se houver) que mudam automaticamente a cada 5 segundos. Isto NÃO é um vídeo .mp4 — para um vídeo real, abra video-demo.html no navegador do telefone e depois grave a tela, ou leia a narração em video-demo.txt enquanto grava o aplicativo em execução.

Nova Aparência no Estilo Android Studio
A aparência da IDE agora está arrumada para se parecer com o Android Studio (apenas a aparência — todos os botões, menus e fluxos permanecem exatamente como antes): um fundo cinza claro, títulos de tela em negrito e pretos, botões azuis com texto branco e caixas de entrada brancas com uma borda fina. O menu principal é agrupado visualmente (Recursos de criação, Nuvem, tema e outros, Voz, código e novos recursos, Ferramentas) sem mudar a ordem dos botões. O Terminal continua usando um painel escuro como a janela do Terminal do Android Studio, e o editor de código continua com fundo branco e texto preto. Todo o texto continua sendo lido claramente pelo Jieshuo.

Configurações
Para configurar o aplicativo: abra o menu Opções na tela principal e pressione Configurações. Dentro há 12 categorias: Configurações do GitHub (segurança, assinatura pessoal, histórico de compilação e token do GitHub), Configurações de compilação de APK no dispositivo (salvar a senha do keystore e o histórico de compilação no dispositivo), Tema (cores do aplicativo), Assinatura (criar um keystore para uma assinatura pessoal e a caixa anti-adulteração do aplicativo compilado), Pasta de projetos (localização da pasta de projetos), Idioma e voz (idioma da interface e velocidade de voz do Modo de voz), Tamanho do texto e aparência (tamanho da fonte do editor), Compilação (SDK alvo padrão e divisão de arquitetura padrão para a tela Criar projeto), Notificações (som quando uma compilação termina), Backup automático (agendamento de backup de projetos), Perfil do desenvolvedor (nome, número de WhatsApp e conta exibidos na tela Doar) e Privacidade e dados (redefinir configurações e excluir dados do aplicativo). Cada categoria tem um botão Voltar para retornar ao menu de categorias. As configurações que acabaram de ser salvas (ainda não aplicadas) têm sua explicação escrita com honestidade na tela.

Doar ao desenvolvedor
Para doar ou cumprimentar o desenvolvedor: pressione o botão Doar ao desenvolvedor na tela principal, ao lado do botão Sobre a ferramenta. Na tela de doação há um botão Copiar Conta BRI — pressione-o para copiar o número da conta do desenvolvedor e depois cole-o no seu aplicativo bancário. Há também uma seção Cumprimentar o Desenvolvedor no WhatsApp: preencha seu nome e cidade de origem e pressione Enviar no WhatsApp — o WhatsApp abre com a mensagem de saudação já preenchida, basta pressionar Enviar no WhatsApp e depois voltar ao aplicativo. O WhatsApp não permite que outros aplicativos enviem mensagens automaticamente, por isso o envio continua sendo feito por você mesmo no WhatsApp.

Comandos favoritos do terminal
Para salvar comandos usados com frequência no Terminal: abra o Terminal e pressione Favoritos. Toque em Adicionar novo favorito, preencha o nome (por exemplo Ver arquivo) e seu comando (por exemplo ls -la) e pressione Salvar — o favorito é salvo permanentemente no telefone. Toque no nome de um favorito para executá-lo diretamente no terminal; toque em Excluir favorito e escolha um para excluí-lo (com confirmação). Já há 3 favoritos embutidos: Ver arquivo (ls -la), Verificar espaço (df -h) e Limpar tela (clear) — todos podem ser excluídos. Um comando vazio não pode ser salvo nem executado; o Terminal avisa por meio de uma mensagem e por voz se isso acontecer.

Análise e qualidade
Para ver um resumo do uso do aplicativo e os relatórios de falhas: pressione o botão Análise e qualidade na tela principal, ao lado do botão Doar ao desenvolvedor. Esta tela mostra quantas vezes o aplicativo foi aberto, as telas abertas com mais frequência, o número de falhas e a lista das falhas mais recentes com uma breve sugestão de correção. Estes dados só são guardados no seu telefone e não são enviados para lugar nenhum. Há um botão Excluir Dados de Análise com um diálogo de confirmação para excluir todos esses dados. A última tela só é registrada para a tela principal e esta tela.
