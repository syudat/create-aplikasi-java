Bine ați venit la Create Aplikasi by Al Kautsar
Create Aplikasi este o aplicație de creare de aplicații Android care rulează direct pe telefon, fără a avea nevoie de un laptop. Această aplicație permite oricui să își creeze propria aplicație Android, inclusiv utilizatorilor care abia învață să creeze aplicații și utilizatorilor de cititoare de ecran. Ghidul complet de utilizare a acestei aplicații este disponibil pe acest ecran Tentang Alat.

Ce este această aplicație și pentru cine este
Create Aplikasi este un instrument de creare de aplicații Android care rulează pe telefon. Această aplicație se adresează oricui dorește să își creeze propria aplicație Android, inclusiv începătorilor și utilizatorilor de cititoare de ecran. Această aplicație oferă un editor de cod, un buton Jalankan pentru testarea proiectelor, un buton Bangun pentru crearea unui APK, precum și meniuri pentru semnarea și instalarea APK-ului.

Scopul acestei aplicații
Această aplicație a fost creată pentru ca oricine să își poată crea cu ușurință propria aplicație Android, direct de pe telefon. Aspectul său a fost făcut cât mai simplu posibil, astfel încât chiar și utilizatorii noi să o poată încerca imediat.

Cum se creează un proiect nou, pas cu pas
1. Apăsați Buat Project în meniul principal.
2. Alegeți tipul de proiect: HTML, Situs Web, Java, Kotlin, Compose sau Python.
3. Completați numele aplicației, exemplu: Garuda Decode.
4. Completați numele pachetului (package name), exemplu: com.android.garudadecode. Numele pachetului trebuie să folosească litere mici și să fie format din cel puțin două părți separate printr-un punct.
5. Completați versiunea aplicației, exemplu: 1.0, și codul versiunii ca număr, exemplu: 1. Dacă este lăsat necompletat, versiunea va fi completată automat cu 1.0, iar codul versiunii cu 1.
6. Completați SDK-ul minim și SDK-ul țintă, dacă este necesar. Dacă sunt lăsate necompletate, vor fi folosite valorile implicite. SDK-ul minim este cea mai joasă versiune Android acceptată, exemplu: 21 înseamnă Android 5.0. SDK-ul țintă maxim este 36 (Android 16).
7. Apăsați butonul Pilih Izin pentru a alege permisiunile aplicației, exemplu: INTERNET. Permisiunea INTERNET este bifată în mod implicit. Bifați doar permisiunile de care aplicația are cu adevărat nevoie.
8. Dacă doriți, bifați „Gunakan arsitektur terpisah 64 bit dan 32 bit" pentru ca dimensiunea APK-ului să fie mai mică și bifați „Gunakan tanda tangan pribadi" dacă doriți să folosiți un keystore creat de dumneavoastră.
9. Apăsați Buat Proyek. Noul proiect este salvat în dosarul Download/project și apare imediat în Kelola Project.

Tipuri de proiecte disponibile
• HTML: afișare din index.html, style.css și script.js, rulează prin WebView. Se construiește direct pe telefon.
• Situs Web: un site web cu meniuri (Beranda, Tentang, Kontak) din index.html, tentang.html, kontak.html, style.css și script.js, rulează prin WebView. Se construiește direct pe telefon.
• Java: se construiește pe telefon. MainActivity se află în app/src/main/java/<nama-paket>/MainActivity.java. Afișarea provine din app/src/main/res/layout/activity_main.xml, textul din app/src/main/res/values/strings.xml și tema din app/src/main/res/values/styles.xml.
• Kotlin: poate fi construit pe dispozitiv (offline) folosind compilatorul Kotlin inclus în aplicație sau prin GitHub Actions. MainActivity se află în app/src/main/java/<nama-paket>/MainActivity.kt, iar fișierele res sunt aceleași ca într-un proiect Java. Prima construire Kotlin este mai lentă din cauza dimensiunii mari a compilatorului, iar fișierele .java care fac referire la clase Kotlin nu pot fi încă construite (fișierele .java sunt compilate înaintea fișierelor .kt).
• Compose: o aplicație Android modernă a cărei interfață este creată cu Jetpack Compose (nu cu aspect XML). MainActivity se află în app/src/main/java/<nama-paket>/MainActivity.kt. Proiectele Compose sunt construite prin GitHub Actions (meniul Bangun proyek, apoi Bangun online) sau în Termux cu Gradle, deoarece Compose necesită bibliotecile Jetpack Compose care nu sunt disponibile pe dispozitiv.
• Python: logica aplicației este scrisă în Python (Chaquopy) în app/src/main/python/main.py și este rulată de gazda MainActivity.java din app/src/main/java/<nama-paket>/MainActivity.java. Proiectele Python pot fi construite direct pe telefon (mediul de rulare Chaquopy este inclus în aplicație) sau prin GitHub Actions. SDK-ul minim pentru proiectele Python este 24 (Android 7.0).

Schimbă arhitectura proiectului
Pentru a schimba opțiunile de arhitectură ale unui proiect existent fără a crea un proiect nou: apăsați «Schimbă arhitectura proiectului» în meniul principal, selectați apoi proiectul și modificați caseta de selectare «Construiește APK 64 biți (arm64-v8a)» sau «Construiește APK 32 biți (armeabi-v7a)»; sau apăsați lung pe numele proiectului în «Gestionează proiecte» și selectați «Schimbă arhitectura» pentru a deschide același ecran direct pentru acel proiect. Regula este: dacă ambele casete de selectare sunt bifate, construcția creează două fișiere APK separate, unul de 64 biți și unul de 32 biți; dacă este bifată doar o casetă de selectare, construcția creează un singur fișier APK universal care continuă să ruleze atât pe dispozitive de 64 biți, cât și pe dispozitive de 32 biți. Un APK separat doar pentru o variantă nu este încă acceptat, deoarece calea de construcție cunoaște doar alegerea divizată sau universală, dar alegerea fiecărei variante rămâne salvată în interiorul proiectului, astfel încât să nu se piardă când ecranul este deschis din nou.

Structura fișierelor proiectelor Java, HTML, Situs Web, Kotlin, Compose și Python
Proiectele Java, HTML, Situs Web, Kotlin, Compose și Python sunt organizate ca proiectele Android în general. În interiorul dosarului app se află dosarul src, iar în interiorul acestuia se află dosarul main. În interiorul dosarului main se află AndroidManifest.xml lângă dosarul java, dosarul res care conține layout/activity_main.xml și values/strings.xml, precum și values/styles.xml, iar pentru HTML și Situs Web există dosarul assets care conține index.html (Situs Web are și tentang.html și kontak.html). Proiectele HTML și Situs Web au, de asemenea, propriul MainActivity în app/src/main/java/<nama-paket>/MainActivity.java, care încarcă index.html în WebView și devine lansatorul (launcher) în AndroidManifest. Proiectele Python au cod Python în app/src/main/python/main.py și gazda MainActivity.java în app/src/main/java/<nama-paket>/MainActivity.java. AndroidManifest.xml, aspectul, strings și styles pot fi deschise și modificate în editor, la fel ca MainActivity. Proiectele mai vechi al căror manifest se află încă lângă dosarul app pot fi construite în continuare, deoarece la construire aplicația verifică mai întâi AndroidManifest.xml din app/src/main/, apoi pe cel de lângă dosarul app și, în final, fișierul de date al proiectului.

Reguli privind permisiunile (important)
Permisiunile bifate la crearea unui proiect sunt înregistrate într-un singur loc, în funcție de tipul proiectului. Pentru proiectele Java, HTML, Situs Web, Kotlin, Compose și Python, permisiunile bifate sunt înregistrate NUMAI în AndroidManifest.xml aflat în app/src/main/, lângă dosarul java, în interiorul dosarului proiectului. Fișierul de date al proiectului pentru proiectele Java, HTML, Situs Web, Kotlin, Compose și Python nu conține o listă de permisiuni. Dacă alegeți Java și apoi bifați INTERNET și CAMERA, cele înregistrate în AndroidManifest.xml sunt doar INTERNET și CAMERA, fără alte permisiuni care să le însoțească. La construire, aplicația citește permisiunile din același loc: din AndroidManifest.xml din app/src/main/ pentru proiectele Java, HTML, Situs Web, Kotlin, Compose și Python (dacă nu există, din AndroidManifest.xml de lângă dosarul app pentru proiectele mai vechi) și din fișierul de date al proiectului pentru proiectele mai vechi.

Cum se folosește editorul
Deschideți Kelola Project, atingeți numele unui proiect pentru a deschide editorul. În editor, fișierele pot fi deschise, codul poate fi scris și modificările pot fi salvate. Pentru proiectele Java, HTML, Situs Web, Kotlin, Compose și Python, fișierele se află în interiorul dosarului app/src/main. Pentru a partaja un proiect, folosiți Ekspor ZIP (vedeți secțiunea de mai jos).

Cum se rulează un proiect
În editor, apăsați Jalankan pentru a testa proiectul. Pentru proiectele HTML și Situs Web, cel care rulează este index.html prin WebView. Dacă apare o eroare, citiți mesajul de eroare, corectați codul și rulați din nou.

Cum se construiește un APK
În editor, apăsați Bangun. Există două moduri de construire. Primul, Bangun di perangkat: construiește direct pe telefon, fără internet, pentru proiectele HTML, Situs Web, Java, Kotlin și Python. Al doilea, Bangun online prin GitHub Actions: construiește prin internet pe GitHub și poate fi folosit pentru toate tipurile de proiecte. Proiectele Compose pot fi construite doar în al doilea mod (Bangun online) sau în Termux cu Gradle, deoarece Compose necesită bibliotecile Jetpack Compose care nu sunt disponibile pe dispozitiv. Rezultatul primei construiri nu este încă semnat. Apoi aplicația îl semnează: automat cu cheia implicită sau cu o semnătură personală, dacă câmpul „Gunakan tanda tangan pribadi" a fost bifat la crearea proiectului.

Cum se instalează un APK
Când APK-ul este gata, apăsați Pasang pentru a-l instala. Pe Android 8 și versiunile mai noi, telefonul va cere mai întâi „Izinkan dari sumber ini", deoarece această aplicație instalează APK-uri din afara Play Store. Activați această permisiune o singură dată în Setări, apoi reveniți în aplicație: instalarea va continua automat, fără a mai fi nevoie să apăsați Pasang din nou. Dacă butonul Pasang nu apare, asigurați-vă că construirea s-a încheiat și că APK-ul a fost creat.

Cum se semnează o aplicație
Fiecare APK trebuie semnat pentru a putea fi instalat. Există două opțiuni. Prima, cheia implicită: aplicația semnează singură, automat, fără a fi nevoie să faceți nimic. A doua, semnătura personală: creați mai întâi un keystore prin meniul Buat Keystore din meniul principal, păstrați-i bine parola, apoi bifați „Gunakan tanda tangan pribadi" la crearea unui proiect. Keystore-ul este salvat în Download/project/signing.

Exportarea unui proiect ca ZIP
Ekspor ZIP este oferit pentru ca proiectele să poată fi partajate cu prietenii. Modul de folosire: în Kelola Project, apăsați lung numele unui proiect, apoi alegeți Ekspor ZIP. Rezultatul este salvat în Download/project/<NamaProyek>.zip. Dosarul bin nu este inclus, așa că dimensiunea este mică, doar câteva zeci de KB. Fișierul ZIP poate fi trimis unui prieten sau încărcat pe GitHub.

Ekstensi JAWS
Ekstensi JAWS folosește motorul de extensie al Jieshuo (CSR), nu cititorul său de ecran. În acest fel, schema poate continua să funcționeze chiar dacă utilizatorul folosește TalkBack. Modul de folosire: deschideți Ekstensi JAWS în meniul principal. Deoarece clicurile automate rulează singure, serviciul trebuie mai întâi activat în Setările de accesibilitate. După aceea, poate fi creată o schemă nouă: tastați numele schemei, apăsați OK, apoi completați câmpurile sale.

Daftar Klik este separat pentru ordine
În interiorul schemei există două câmpuri: câmpul de script și câmpul Daftar Klik. Lista de butoane este salvată separat în fișierul daftar_klik.txt, câte un nume pe linie. Exemplu de conținut: tombolSimpan, tombolHapus, tombolBuka. Pentru a deschide o aplicație, scrieți pur și simplu >WhatsApp în acea listă. Schemele mai vechi care nu au încă un fișier daftar_klik.txt vor afișa acest exemplu implicit.

Funcții simple oferite
• klikTombol("tombolSimpan") — face clic pe un buton pe baza textului său.
• klikDaftarTombol(daftar) — face clic pe lista din daftar_klik.txt, câte un buton pe linie, în ordine, apoi anunță câte au reușit și câte nu au fost găsite.
• bukaAplikasi("WhatsApp") — deschide o aplicație pe baza numelui său sau scrieți „>WhatsApp" în listă.
• klik(540, 1200) — face clic la coordonatele ecranului.
Toate funcțiile au fost făcute simple la început. După ce vă obișnuiți cu ele, funcții suplimentare pot fi adăugate ulterior.

Despre cititoarele de ecran
Această aplicație este concepută pentru a fi prietenoasă cu cititoarele de ecran. Fiecare câmp de completare are o etichetă și un exemplu de completare, iar toate butoanele pot fi accesate fără gesturi complicate. Ekstensi JAWS este creat pentru a continua să funcționeze chiar dacă utilizatorul folosește TalkBack, deoarece cel folosit este motorul său de extensie, nu cititorul său de ecran.

Confidențialitate și securitate
Proiectele și keystore-urile sunt salvate pe telefonul dumneavoastră. Tokenul GitHub este folosit doar pentru construirile online și este salvat în această aplicație. Nu partajați tokenul sau parola keystore-ului dumneavoastră cu nimeni. Dacă folosiți o semnătură personală, păstrați keystore-ul și parola sa într-un loc sigur, deoarece, dacă se pierd, vechiul APK nu poate fi actualizat cu aceeași semnătură.

Cerințe
Android 5.0 sau mai nou. Permisiunea de stocare: pe Android 11 și versiunile mai noi se folosește permisiunea de acces la toate fișierele, pe Android 10 și versiunile mai vechi se folosește permisiunea obișnuită de stocare (citire/scriere stocare), deoarece Android 10 nu are permisiunea de acces la toate fișierele. Construirea pe dispozitiv necesită un telefon cu procesor ARM (32 sau 64 de biți). Construirea online prin GitHub Actions necesită internet și un token GitHub. Proiectele Kotlin pot fi construite pe dispozitiv, dar prima lor construire este mai lentă și folosește mai multă memorie din cauza dimensiunii mari a compilatorului Kotlin. Proiectele Compose sunt construite prin GitHub Actions sau în Termux cu Gradle. Proiectele Python necesită Android 7.0 sau mai nou (SDK minim 24), iar APK-ul rezultat este mai mare deoarece include mediul de rulare Python (Chaquopy) împreună cu biblioteca sa standard.

Terminal
Meniul Terminal de pe ecranul principal deschide un terminal în interiorul acestei aplicații. Comenzi precum ls pot fi folosite pentru a vedea conținutul dosarului proiectului, cd pentru a schimba dosarul și git pentru a gestiona codul. Rezultatul comenzilor este afișat ca text care poate fi citit de un cititor de ecran și există un buton Bacakan hasil pentru a asculta ultimul rezultat. Acest terminal folosește shell-ul de sistem al telefonului, așa că programele interactive precum nano și vim nu pot fi încă folosite aici.

Licență (versiune plătită)
Pentru a vinde o aplicație, bifați „Aktifkan Lisensi" la crearea unui proiect, apoi completați numărul dumneavoastră de WhatsApp. Aplicația construită va cere un cod de licență la prima deschidere: utilizatorul își vede ID-ul dispozitivului, apasă butonul Kirim ID Perangkat pentru a trimite acel ID la WhatsApp-ul dumneavoastră, iar dumneavoastră răspundeți cu codul de licență. Codul de licență este calculat din ID-ul dispozitivului și parola proiectului (lisensi_seed în fișierul de date al proiectului) — păstrați bine această parolă și nu o partajați. După introducerea codului corect, aplicația se deschide și nu mai cere codul.

Creator automat de pictograme
Pictograma proiectelor noi este încă transparentă, așa că Pembuat Ikon este disponibil în meniul principal. Modul de folosire: apăsați Pembuat Ikon, scrieți una sau două litere (de exemplu inițialele numelui aplicației), alegeți o culoare de fundal și o culoare a textului, vedeți previzualizarea, apoi apăsați Simpan ke Proyek pentru a folosi pictograma în proiectul ales sau Simpan ke Download pentru a folosi fișierul său PNG în altă parte. După crearea unui proiect, aplicația oferă, de asemenea, crearea unei pictograme. Pictograma veche a unui proiect poate fi înlocuită oricând din meniul proiectului din Kelola Project (apăsați lung numele proiectului, apoi alegeți Ganti Ikon).

Șabloane de proiecte gata de folosit
Dacă nu doriți să porniți de la un proiect gol, alegeți un șablon la crearea unui proiect: Kalkulator (Java), Catatan (Java), Daftar Tugas (Kotlin), Kalkulator Web (HTML), Situs Profil (Situs Web) sau Penghitung (Compose). Alegerea unui șablon schimbă automat tipul de proiect pentru a urma șablonul, iar proiectul este creat cu cod de pornire gata făcut — gata de rulat sau de modificat. Dacă tipul de proiect este schimbat din nou manual după alegerea unui șablon, șablonul este anulat și proiectul revine la gol. Pentru șabloanele HTML și Situs Web, șablonul înlocuiește conținutul lui index.html, inclusiv scriptul HTML tastat în formular.

Copierea de rezervă și restaurarea proiectelor
Pentru ca proiectele să nu se piardă, este disponibilă o funcție de copie de rezervă. Modul de folosire: în Kelola Project, apăsați lung numele unui proiect, apoi alegeți Cadangkan. Copia de rezervă este salvată ca ZIP în dosarul Download/backup cu numele proiectului și data, exemplu: GarudaDecode-2026-11-14-123045.zip. Conținutul său este același ca la Ekspor ZIP (întregul conținut al proiectului, fără dosarul bin). Pentru restaurare: deschideți meniul în Kelola Project, alegeți Pulihkan cadangan, apoi alegeți fișierul copiei de rezervă. Dacă numele proiectului există deja, aplicația va întreba: Suprascrieți proiectul vechi sau salvați cu un nume nou.

Partajarea și importul proiectelor
Pentru a partaja un proiect cu un prieten: în Kelola Project, apăsați lung numele unui proiect, apoi alegeți Bagikan. Proiectul este trimis ca ZIP prin aplicațiile de partajare (WhatsApp, Telegram și altele). Pentru a primi un proiect de la un prieten: deschideți meniul în Kelola Project, alegeți Impor proyek, apoi alegeți fișierul său ZIP. Fișierul ZIP trebuie să conțină un fișier de date al proiectului — dacă nu îl conține, fișierul este respins cu un mesaj clar, deoarece acel fișier nu este un proiect Create Aplikasi. Dacă numele proiectului există deja, aplicația va întreba: Suprascrieți proiectul vechi sau salvați cu un nume nou.

Căutarea și filtrarea proiectelor
Dacă proiectele sunt deja multe, în Kelola Project există o casetă de căutare și un filtru de tip. Tastați un nume de proiect în caseta de căutare și lista se filtrează imediat (nu se face distincție între litere mari și mici). Filtrul de tip limitează lista la un singur tip: Toate, HTML, Situs Web, Java, Kotlin, Compose sau Python. Meniul fiecărui proiect poate fi deschis în continuare ca de obicei din lista filtrată.

Creați aplicații cu vocea
Dacă nu vrei să tastezi, folosește vocea: apasă pe Construiește cu vocea în meniul principal și apoi rostește o comandă. Comenzi pe care le poți rosti: "Buat proyek kalkulator", "Bangun proyek Kalkulator", "Buka proyek Kalkulator", "Jalankan proyek Kalkulator", "Daftar proyek", "Buka ikon", "Kembali" și "Bantuan". Aplicația răspunde cu voce și text, astfel încât poate fi folosită în continuare fără să te uiți la ecran. Recunoașterea vocală folosește aplicația de recunoaștere vocală încorporată a telefonului (gratuită; poate funcționa offline dacă este instalat pachetul de limbă indoneziană). Dacă telefonul nu are recunoaștere vocală, comenzile pot fi tastate în caseta de text de pe același ecran.

Creator de aplicații AI
Scrieți sau dictați aplicația pe care o doriți pe ecranul Creator de aplicații AI, de exemplu: «o aplicație de notițe cu buton de salvare». Aplicația analizează cuvintele-cheie în interiorul telefonului (fără internet, fără cost) și apoi creează un proiect real din șablonul cel mai potrivit: calculator, notițe, listă de sarcini, calculator web, site de profil sau contor. Dacă descrierea dvs. nu are încă un șablon potrivit, aplicația creează un proiect gol și spune acest lucru sincer — nu se preface că înțelege. Un proiect creat de AI poate fi deschis direct în Gestionează proiecte.

Previzualizare live pe telefonul unui prieten
Pentru a arăta un proiect unui prieten înainte de a-l construi: în Gestionează proiecte, apăsați lung pe numele proiectului și alegeți apoi Previzualizare pe telefonul unui prieten. Aplicația creează un mic pachet de previzualizare care conține fișierele principale ale proiectului (index.html, MainActivity sau main.py) împreună cu fișierul CITEȘTE-MĂ.txt cu instrucțiuni și info.txt. Pachetul este trimis ca ZIP prin WhatsApp sau Telegram. Prietenul care îl primește poate deschide previzualizarea direct: paginile HTML se deschid în browser, codul Java/Kotlin/Python se citește ca text.

Piață de proiecte
Piața de proiecte conține proiecte-exemplu încorporate care pot fi instalate în dosarul de proiecte cu o singură apăsare: Calculator, Notițe, Listă de sarcini, Calculator web, Site de profil, Contor, Ceas digital și Chestionar web. Piața online (descărcarea de exemple de pe internet) nu există încă, deci această piață conține exemple care există deja în aplicație. Un proiect instalat poate fi deschis și modificat în Gestionează proiecte ca un proiect creat de dvs.

Colaborare directă
Pentru a lucra la un proiect împreună cu un prieten: deschideți Colaborare în meniul principal, alegeți proiectul, scrieți o notă de modificare (ce s-a schimbat) și apăsați apoi Partajați pentru colaborare. Proiectul este trimis ca ZIP împreună cu un fișier CATATAN.txt în interior. Prietenul dvs. lucrează la el și trimite ZIP-ul înapoi; dvs. apăsați Primiți răspuns, citiți mai întâi nota de modificare și alegeți apoi Aplică pentru a suprascrie proiectul vechi sau Anulează dacă vă răzgândiți. Un ZIP fără CATATAN.txt nu este un pachet de colaborare — pentru un ZIP obișnuit de proiect, folosiți Importați un proiect în Gestionează proiecte.

Traducător automat de aplicații
Pentru a traduce textul unei aplicații într-o altă limbă: deschideți Traducător de aplicații în meniul principal, alegeți proiectul și limba țintă (engleză, arabă sau javaneză) și apăsați apoi Tradu. Dicționarul se află deja în interiorul telefonului (fără internet, fără cost) și conține cuvinte obișnuite de zi cu zi; textul este citit din strings.xml, din aspect și din cod și apoi tradus. Rezultatul este scris în dosarul values-limbă/strings.xml (dacă proiectul are strings.xml) și într-un raport traducere-limbă.txt în dosarul proiectului. Cuvintele care nu se află încă în dicționar sunt lăsate așa cum sunt și raportate — astfel încât să știți ce cuvinte trebuie să traduceți singuri.

Creator de jocuri fără cod
Pentru a crea un joc fără a scrie cod: deschideți Creator de jocuri fără cod în meniul principal, alegeți tipul de joc (Ghicește numărul, Chestionar sau Prinde steaua), completați numele jocului, cantitatea (niveluri/întrebări/stele) și mesajul de câștig și apăsați apoi Creați jocul. Jocul este creat ca un proiect real care poate fi rulat direct în Gestionează proiecte și construit ca APK ca orice alt proiect.

Testare automată a aplicațiilor
Pentru a verifica un proiect înainte de a-l construi: în Gestionează proiecte, apăsați lung pe numele proiectului și alegeți apoi Test automat. IDE verifică 10 lucruri fără a construi un APK — există fișierele obligatorii (fișierul de date al proiectului, manifestul, fișierul principal, aspectul, șirurile), numele pachetului și versiunea, permisiunile utilizate, pictograma și echilibrul parantezelor din cod. Rezultatul este afișat pe elemente (TRECUT/NEPROMOVAT cu un mesaj) și citit cu voce tare de Jieshuo. Corectați mai întâi tot ce a fost NEPROMOVAT și apăsați apoi Construiți proiectul.

AI Verificator de cod

Verificatorul rulează în interiorul telefonului (fără internet) și caută variabile neutilizate, funcții goale, bucle evident infinite, text scris direct în cod (mai bine în strings.xml), permisiuni și API-uri periculoase, marcaje TODO/FIXME și execuție dinamică. Fiecare constatare conține numele fișierului, numărul liniei și o sugestie de corectare. Mod de învățare interactiv

Atingeți o lecție pentru a citi explicația și sarcina de exercițiu, faceți sarcina și apăsați apoi Verificați sarcina — IDE verifică într-adevăr dacă sarcina a fost făcută (scanând proiectul și APK-ul de pe telefon). Lecțiile promovate sunt marcate ca finalizate și salvate.

Sincronizare cloud
Pentru a face o copie de rezervă a unui proiect în cloud: deschideți Sincronizare cloud în meniul principal. O copie de rezervă GitHub încarcă ZIP-ul proiectului în repo-ul dvs. privat (cu token din Setări GitHub) și poate fi descărcată din nou. Aceasta este copiere de rezervă și restaurare manuală — sincronizarea automată completă în două sensuri are nevoie de un server, deci nu există încă.

Creator de backend automat

Designer automat de teme

Creator de animații

Înregistrator de acțiuni

Deschideți Înregistrator de acțiuni în meniul principal pentru a vedea lista acțiunilor înregistrate cu planul lor și apăsați apoi Redați din nou — IDE execută din nou acțiunile care pot fi automatizate (copierea de rezervă și crearea proiectului se execută pe loc; rularea, construirea și exportul deschid ecranul lor principal; deschiderea și salvarea deschid editorul). Securitate automată
Pentru a verifica securitatea unui proiect: deschideți Securitate automată în meniul principal, alegeți proiectul și apăsați apoi Verificați securitatea. IDE verifică 8 lucruri local (fără internet): permisiuni periculoase (locație, SMS, apeluri, cameră, microfon, contacte), trimiterea de date prin HTTP, trimiterea de SMS-uri, apeluri efectuate, o parolă sau o cheie scrisă direct în cod, un WebView fără protecție, o componentă exportată fără permisiune și o adresă http fără criptare. Fiecare constatare primește nivelul SIGUR, AVERTISMENT sau PERICOL cu o sugestie de corectare, iar rezumatul este citit cu voce tare de Jieshuo.

AI offline

Integrare rețele sociale

Terminal interactiv (analizator VT)
Pentru a utiliza programe interactive în Terminal: deschideți Terminal în meniul principal și rulați apoi nano, vim, top sau htop. Terminalul folosește acum un analizator VT (un ecran grilă cu 24 de rânduri x 80 de coloane), astfel încât aceste programe să se afișeze corect — cursorul se mișcă, liniile sunt șterse, iar ecranul se schimbă ca într-un terminal real. Terminal Exec (binar al aplicației)

Terminal menținut activ (KeepAlive)
Pentru a menține shell-ul în funcțiune când schimbați ecranul: deschideți Terminal, rulați o comandă și apăsați apoi Înapoi sau treceți la un alt ecran — shell-ul NU moare, iar notificarea Terminal continuă să fie afișată, astfel încât să puteți reveni cu o singură apăsare. Comenzile rulate sunt salvate în istoric (butonul Istoric sau săgețile sus/jos din câmpul de comandă), iar comenzile folosite des pot fi salvate ca favorite (butonul Favorit). Apăsați Închideți shell-ul când ați terminat, astfel încât shell-ul să se încheie cu adevărat. Există, de asemenea, un buton Construiți în Terminal în meniul proiectului și în meniul editorului: Terminalul se deschide în dosarul proiectului cu comanda de construire deja completată.

Instalați Instrumentul Terminal (Probă)
O funcție care încă este testată: în Terminal există un buton Instalați Instrumentul Terminal (Probă) pentru a instala un mediu Termux din oglinda din repo-ul alat-termux al dezvoltatorului (github.com/syudat/alat-termux), ca o altă cale în afară de butonul Instalați Termux care preia din ediția oficială Termux. Conținutul oglinzii este exact același ca ediția oficială și este verificat cu SHA-256 în timpul instalării. Când mediul este instalat, comenzile pkg update și pkg install pot fi utilizate, iar instrumente suplimentare din repo sunt instalate, de asemenea, în terminal: info-terminal pentru a vedea informații despre mediu, bersih-terminal pentru a goli memoria cache și cadangkan-proyek pentru a arhiva dosarul proiectului într-un singur fișier tar.gz datat. Apoi aplicația instalează automat pachetele Linux de bază (git, python, curl, wget, nano, openssh, zip, unzip) și instrumentele de construire APK cu semnare (openjdk-21, kotlin, gradle, ecj, aapt2, d8, apksigner, clang, cmake, ninja, make) din repo-ul oficial Termux, astfel încât terminalul să fie imediat gata să construiască aplicații. Descărcarea pachetelor mari (sute de MB) poate dura mult. În timp ce rulează instalarea, progresul și ieșirea comenzii sunt afișate pe ecranul principal al Terminalului, iar rezultatul final este citit cu voce tare de cititorul de ecran. Dacă instalarea pachetelor nu este încă finalizată, apăsați din nou Instalați Instrumentul Terminal (Probă) pentru a continua.

Mod vocal complet

Există 26 de comenzi: creează, construiește, deschide, rulează, listează, caută, șterge, testează, verifică, exportă, copiază de rezervă, partajează, creează pictogramă, traduce, construiește în terminal, citește ecranul, deschide toate ecranele (inclusiv securitate, AI offline, widget, rețele sociale, joc, învățare, cloud, backend, temă, animație, înregistrator), înapoi, închide și ajutor. Dacă modul este lăsat activ, ascultarea continuă automat când acest ecran este deschis din nou. Apăsați Opriți ascultarea pentru a dezactiva modul. Dacă telefonul nu are serviciu de recunoaștere vocală, comenzile pot fi totuși scrise în caseta de text.

Traducător de cod
Pentru a traduce cod între limbi fără internet: deschideți Traducător de cod în meniul principal, alegeți proiectul, alegeți fișierul sursă (.java/.kt) și alegeți apoi direcția: Java în Kotlin. Git în aplicație
Pentru a utiliza Git în IDE fără Termux: deschideți Git în aplicație în meniul principal, alegeți proiectul și apăsați apoi Creați repo Git pentru a crea un repo local (.git) în acel proiect. Apăsați Verificați starea pentru a vedea fișiere noi, modificate sau șterse comparativ cu ultimul commit; completați mesajul de commit și apăsați apoi Commit pentru a salva o imagine instantanee a proiectului; apăsați Vedeți jurnalul de commit-uri pentru a vedea istoricul commit-urilor. Push către GitHub și Pull din GitHub utilizează imagini instantanee prin token GitHub (repo pembuat-aplikasi-build) — nu protocolul git. Clone, Push (system-git) și Pull (system-git) rulează numai când binarul git este instalat pe telefon (de obicei nu). Acesta nu este git complet: nicio îmbinare, ramură sau diferență — fiecare commit salvează o imagine instantanee ZIP completă a proiectului.

Creator de reclame

Calculator dimensiune APK

Previzualizare dimensiune ecran

Manager de resurse
Pentru a vedea și a gestiona toate resursele unui proiect într-un singur loc (ca Managerul de resurse din Android Studio): deschideți Manager de resurse în meniul principal, alegeți proiectul și apăsați apoi Vedeți resursele. Monitor de performanță ușor
Pentru a monitoriza utilizarea RAM și a procesorului unei aplicații care rulează (ca Profiler în Android Studio, versiune ușoară): deschideți Monitor de performanță ușor în meniul principal, rulați mai întâi aplicația pe care doriți să o verificați (de exemplu aplicația construită care este testată), completați numele pachetului acesteia — sau alegeți un proiect și apăsați apoi Completați numele pachetului din proiect — și apăsați apoi Începeți monitorizarea. La fiecare două secunde IDE înregistrează RAM-ul (PSS) și CPU-ul acelei aplicații împreună cu RAM-ul liber al telefonului; apăsați Opriți pentru a vedea un rezumat al mediei și al vârfului. Nicio permisiune suplimentară. Audit de Accesibilitate
Pentru a verifica dacă aspectul unui proiect este prietenos cu cititoarele de ecran (TalkBack/Jieshuo) înainte de lansare: deschide Audit de Accesibilitate în meniul principal, alege un proiect și apoi apasă pe Încarcă Lista Aspectelor și alege un fișier de aspect. Autopsia Blocării
Pentru a afla de ce aplicația se închide singură dintr-un jurnal de blocare cu un ID unic: deschideți «Autopsia Blocării» în meniul principal, selectați ID-ul blocării din lista de jurnale, apoi apăsați «Verifică». IDE potrivește clasa și numărul liniei din jurnal cu sursa proiectului și explică cauza în indoneziană (de exemplu referință goală, permisiune încă necerută sau eroare JSON), cu o sugestie de corecție a codului. Apăsați «Aplică Corecția» numai atunci când linia sursă este încă așa cum era când a avut loc blocarea; dacă s-a schimbat, corecția este respinsă și IDE vă cere să verificați singur. Pentru blocările aplicației construite, apăsați «Injectează captatorul de blocări în proiect», apoi construiți APK-ul ca de obicei: aplicația construită își captează propriile blocări și își scrie jurnalul pe telefon, iar acel jurnal poate fi găsit cu butonul «Găsește jurnalul de blocări al aplicației construite». Limitare onestă: copierea jurnalului în folderul public Download pe Android 11 și mai nou poate eșua fără permisiunea de acces la toate fișierele.

Transpilator Între Paradigme
Pentru a converti cod Java simplu în Kotlin sau un aspect XML simplu în cod Compose: deschide Transpilator Între Paradigme în meniul principal, alege un proiect și un fișier și apoi apasă pe Previzualizare. IDE-ul afișează rezultatul conversiei sub formă de text — verifică-l mai întâi, pentru că liniile pe care nu le recunoaște sunt lăsate așa cum sunt, iar cuvântul static din Java este eliminat în Kotlin (verifică-i sensul înainte de a-l folosi). Conversia din XML în Compose modifică doar textul, sugestiile și orientarea — dimensiunea, culoarea și alte atribute nu sunt încă incluse. Dacă rezultatul este corect, apasă pe Aplică în Fișier pentru a scrie fișierul țintă; fișierul sursă nu este modificat. Doar modelele sigure și obișnuite sunt convertite.

Microserver Local
Pentru a testa o aplicație care are nevoie de un server fără internet: deschideți «Microserver Local» în meniul principal, scrieți definiții de rută (de exemplu GET /halo urmat de răspunsul său JSON), apoi apăsați «Pornește Serverul». IDE rulează un mic server HTTP pe același telefon (numai HTTP, fără TLS, pentru aceeași rețea Wi-Fi) și înregistrează fiecare cerere și răspuns pe ecran. Rutele pot folosi parametri precum {nama} și o cheie API simplă. Serverul poate fi, de asemenea, împachetat în APK-ul construit: apăsați «Împachetează serverul în proiect», iar sursa, activele și manifestul serverului sunt injectate în proiect, astfel încât aplicația construită însăși devine serverul când rulează. Serverul din IDE se oprește când ecranul său este închis.

Auditor de Securitate
Pentru a verifica codul proiectului pentru lacune de securitate înainte de publicare: deschideți «Auditor de Securitate» în meniul principal, selectați proiectul, apoi apăsați «Pornește Scanarea». IDE scanează codul proiectului, manifestul și configurația și raportează constatări de la risc ridicat la risc scăzut — o cheie API lăsată deschisă în cod, o componentă expusă fără permisiune, un WebView care activează JavaScript cu interfața sa JavaScript, criptare slabă (MD5, SHA1, DES), o adresă http fără TLS și o parolă scrisă direct în cod — cu fișierele și numerele lor de linie. Pentru constatările a căror corecție este sigură (de exemplu schimbați MD5 în SHA-256 sau http în https), apăsați «Aplică Corecția»; pentru cheile API și parole, IDE afișează doar sugestia de corecție, deoarece înlocuirea trebuie decisă de dezvoltatorul însuși. Scanarea analizează acum și bytecode DEX real din interiorul APK-ului construit (nu doar modele de text din cod), astfel încât API-urile periculoase apelate și secretele încorporate în DEX sunt, de asemenea, prinse; lacunele care nu urmează un model pot încă scăpa de scanare — verificați înainte de a aplica.

Robotul de Testare a Interfeței
Pentru a testa automat un ecran de aplicație prin scenarii de text: deschideți «Robotul de Testare a Interfeței» în meniul principal, selectați proiectul, apoi apăsați «Creează Scenariu Automat». IDE citește manifestul și aspectul proiectului și scrie scenariul ca pași de text (apăsați butonul, completați câmpul, așteptați, reveniți). Apăsați «Rulează Proba» pentru a vedea jurnalul de execuție al scenariului cu marcajele sale de timp — această probă este încă doar o simulare a secvenței. Pentru testare reală, apăsați «Injectează agentul de test în proiect»: IDE injectează agentul de test cu activele scenariului în proiect; construiți APK-ul ca de obicei, instalați-l, apoi deschideți pictograma «Test» — agentul rulează în interiorul aplicației construite și apasă cu adevărat butoane, completează câmpuri reale și derulează, apoi își afișează raportul cu blocări reale prinse pe ecran. Pentru a elimina din nou agentul, apăsați «Elimină agentul de test din proiect». Agentul rulează în interiorul procesului propriu al aplicației, deci nu are nevoie de un serviciu de accesibilitate sau de automatizare a sistemului.

Călătoria în Timp a Codului
Pentru a readuce un proiect la o stare anterioară a codului fără a tasta comenzi Git: deschide Călătoria în Timp a Codului în meniul principal, alege un proiect, completează o etichetă pentru momentul de timp (poate rămâne goală) și apoi apasă pe Înregistrează Momentul. IDE-ul salvează o copie a fișierelor sursă ale proiectului împreună cu hash-urile lor în dosarul .riwayat din interiorul proiectului. Lista momentelor le arată pe toate; alege două puncte și apoi apasă pe Compară pentru a vedea fișierele și funcțiile adăugate, modificate sau eliminate. Apasă pe Restaurează pentru a aduce înapoi o stare veche — înainte de restaurare, IDE-ul face întotdeauna mai întâi o copie de rezervă a stării curente, astfel încât nimic nu se pierde. Apasă pe Creează Copie de Experiment pentru a copia proiectul într-un dosar nou și a încerca modificări fără a deranja proiectul original. Doar fișierele sursă sunt înregistrate.

Fabrica de Module
Pentru a împacheta o parte a unui proiect ca modul pe care un alt proiect îl poate folosi: deschide Fabrica de Module în meniul principal, alege un proiect sursă, bifează fișierele de ecran, clasă, șiruri și permisiuni care urmează să fie împachetate și apoi apasă pe Împachetează ca Modul. IDE-ul scrie o arhivă ZIP împreună cu metadate JSON (numele modulului, versiunea, șirurile utilizate și permisiunile). Pentru a instala un modul într-un alt proiect, deschide Fabrica de Module, alege proiectul țintă și apoi apasă pe Instalează Modulul și alege fișierul .zip al modulului — fuziunea adaugă șiruri și permisiuni fără a suprascrie codul existent și nu fuzionează un fișier dacă numele acestuia este deja utilizat în proiectul țintă. Un modul nu aduce cu sine nici biblioteci, nici setări de construire.

Scut polimorf și seif de resurse
Pentru a amesteca aleatoriu numele identificatorilor și a cripta resursele proiectului înainte de publicare: deschideți «Scut polimorf și seif de resurse» în meniul principal, selectați proiectul, apoi apăsați «Amestecă numele și criptează resursele». IDE scanează numele claselor și metodelor din codul sursă, creează o hartă aleatorie a numelor, rescrie aceste nume în interiorul fișierelor DEX compilate (numele de înlocuire sunt făcute la fel de lungi ca originalele, astfel încât toate decalajele să rămână valide, apoi suma de control a antetului DEX și semnătura SHA-1 sunt recalculate), criptează fișierele de resurse ale proiectului cu AES-GCM în folderul brankas-aset din interiorul proiectului și salvează o hartă de recuperare criptată (perisai-peta.brankas), astfel încât numele originale să poată fi restaurate la citirea jurnalelor de blocare. Cheia de criptare este acum derivată din parola dezvoltatorului cu PBKDF2, 20.000 de iterații, nu din numele proiectului. Numele care sunt folosite și ca text simplu, nume de adnotare și nume de depanare nu sunt rescrise în mod deliberat, iar punctele de inserare ale rescrierii DEX în calea de construcție încă așteaptă testarea pe un telefon real.

Lanț de încredere și gardian al mediului
Pentru a verifica lanțul cheilor de semnătură și mediul telefonului înainte de publicare: deschideți «Lanț de încredere și gardian al mediului» în meniul principal, selectați proiectul, apoi apăsați «Verifică lanțul și mediul». IDE construiește un lanț de chei de 5 generații din numele pachetului proiectului și îi verifică integritatea, verifică integritatea reală a memoriei comparând conținutul segmentelor de cod din memorie cu fișierele de pe disc și raportează mapări executabile (RWX) fără nume, biblioteci străine și mapări memfd, apoi scanează propria hartă de memorie a procesului și proprietățile dispozitivului pentru urme de Frida, Xposed sau emulator. Cheia seifului este înfășurată cu o cheie AES în AndroidKeyStore care folosește cipul de securitate hardware atunci când există, iar rotația cheilor este acum reală, folosind linia de certificate de semnătură a schemei v3: cheia veche semnează dovada rotației către cheia nouă, iar APK-ul este semnat din nou cu acea linie. Rezultatul este un nivel de risc «sigur», «prudent» sau «periculos» cu dovezi textuale. Dacă sistemul refuză citirea memoriei, verificarea este raportată ca «nu poate fi verificată», nu sigură; și dacă o cheie folosește cu adevărat cipul de securitate hardware poate fi confirmat doar pe un dispozitiv real.

Arhitect de aspect în arbore de text
Pentru a proiecta un ecran fără a-l vedea: deschideți «Arhitect de aspect în arbore de text» în meniul principal, selectați proiectul și fișierul de aspect, apoi apăsați «Verifică aspectul». IDE citește aspectul XML ca arbore de text și citește cu voce tare descrierea poziției fiecărui element (de exemplu jos la dreapta, 45 la sută din lățimea ecranului) și apoi raportează matematic suprapunerile dintre elemente și elementele care ies în afara ecranului la lățimea de 360 dp. Ceea ce se numără acum este LinearLayout și dimensiunile simple dp, ConstraintLayout complet (toate constrângerile, părtinirea, lanțurile, ghidajele, obstacolele, lățimile procentuale, 0dp match_constraint și rapoartele de dimensiune) și ecranele Compose (Column, Row și Box cu modificatorii lor de dimensiune). Doar MotionLayout și ConstraintSet care se schimbă în timpul execuției sunt raportate în continuare ca poziție necunoscută, deoarece valorile lor există doar în timp ce aplicația rulează.

Studio de sistem de design
Pentru a face distanțele, fonturile și colțurile uniforme pe toate ecranele și proiectele: deschideți «Studio de sistem de design» în meniul principal, selectați proiectul, scrieți jetoanele de design (de exemplu jarak=8, huruf=16, sudut=12), selectați o componentă, apoi apăsați «Generează componente». IDE validează jetoanele — distanța de bază 4 până la 16 dp, fontul de bază 12 până la 20 sp, colțurile 0 până la 32 dp și zona minimă de atingere 48 dp — și apoi scrie componente XML gata de utilizare (komponen-studio.xml) cu o temă XML (tema-studio.xml) și o temă Compose (tema-studio.kt) în folderul proiectului. Jetoanele pot fi, de asemenea, salvate ca set denumit în biblioteca comună de jetoane dintre proiecte, iar o singură comandă de sincronizare aplică cele mai recente jetoane ale bibliotecii tuturor proiectelor care folosesc acel set. Componentele sunt create ca text care este lipit în aspect și apoi verificat cu «Arhitect de aspect în arbore de text»; ajustarea la două coloane pe tabletă folosește calificarea lățimii ecranului în locul identificării dispozitivului în timpul execuției.

Refactorizare semantică și navigare AST
Pentru a găsi definiții și a redenumi simboluri fără a rupe alt cod care întâmplător are același nume: deschideți «Refactorizare semantică și navigare AST» în meniul principal, selectați proiectul, apoi apăsați «Scanează simbolurile proiectului» pentru a vedea toate clasele și metodele cu fișierele și numerele lor de linie. Tastați numele simbolului, apoi apăsați din nou «Scanează simbolurile proiectului» pentru a vedea definiția acestuia și toate fișierele care îl apelează. Pentru a redenumi, tastați noul nume, apăsați «Previzualizare redenumire» pentru a vedea numărul de apariții în fiecare fișier, apoi apăsați «Aplică redenumirea». Indexul folosește acum un analizator AST construit manual (lexer și analizator recursiv pentru un subset Java și Kotlin), astfel încât redenumirile metodelor între fișiere sunt rezolvate, iar apelanții din alte fișiere se schimbă și ei; butonul pentru extragerea unui bloc de cod într-o funcție nouă se află acum pe acest ecran. Acest analizator este încă minim: genericele foarte complexe, adnotările parametrizate și clasele anonime sunt scanate ca atare, în timp ce apelurile prin reflecție și interfață nu sunt rezolvate.

Depanator pas cu pas și inspector de memorie
Pentru a examina conținutul variabilelor în mijlocul fluxului programului fără a ghici din jurnale: deschideți «Depanator pas cu pas și inspector de memorie» în meniul principal, selectați proiectul, scrieți o urmă de execuție (un pas pe linie, format numărul liniei, codul, apoi variabilele și valorile separate prin |, de exemplu 10|int total = harga * jumlah;|harga=5000, jumlah=3, total=15000), tastați numărul liniei punctului de întrerupere, apoi apăsați «Rulează urma de depanare». IDE rulează până la primul punct de întrerupere și citește cu voce tare linia activă prin Jieshuo împreună cu valorile variabilelor sale. Apăsați «Pas cu o linie» pentru a avansa cu o linie, apăsați «Intră în funcție» pentru a intra într-o funcție apelată (cu stiva de apeluri) sau apăsați «Continuă programul» pentru a trece la următorul punct de întrerupere. Acest depanator de urme urmează încă o urmă înregistrată sau scrisă de mână; alături de el se află un client Java pur pentru protocolul de fir JDWP care poate face handshake, poate seta puncte de întrerupere, poate păși în interior, peste și în afară și poate întrerupe și relua VM prin TCP sau în modul de ascultare. Întreruperea unui proces real din interiorul unei aplicații obișnuite nu este încă pe deplin posibilă, deoarece socketul JDWP al unui proces este expus doar prin adbd — calea dovedită necesită depanare fără fir și pornirea țintei prin shell, ceea ce depășește ceea ce poate face aplicația însăși.

Manager de dependențe offline
Pentru a folosi biblioteci terțe fără internet și a evita conflictele de versiune înainte de construcție: deschideți «Manager de dependențe offline» în meniul principal, selectați proiectul, apoi apăsați «Verifică dependențele». IDE citește toate fișierele .gradle ale proiectului, verifică seiful comun între proiecte în folderul Download/brankas-bersama și rezolvă conflictele — dacă două biblioteci cer versiuni diferite ale aceluiași artefact, se folosește cea mai mare versiune și conflictul este raportat. Pentru a descărca o bibliotecă, tastați coordonatele sale (format grup:artefact:versiune, de exemplu com.google.code.gson:gson:2.10.1), apoi apăsați «Verifică dependențele»: când sunteți online, fișierele AAR, JAR sau WHL sunt descărcate cu adevărat de la Maven, Google sau PyPI împreună cu graficul lor tranzitiv de dependențe (recursiv, ciclurile sunt tăiate, adâncime de până la 25 de niveluri), iar numai fișierele descărcate cu succes sunt înregistrate ca disponibile. Când sunteți offline, pot fi folosite doar bibliotecile deja existente în seiful comun. Intervalele de versiuni Maven nu sunt rezolvate, iar fișierele descărcate sunt verificate doar cu SHA-1, fără verificare PGP.

Inspector de baze de date și stocare
Pentru a examina și testa conținutul bazei de date a proiectului fără a scrie cod care imprimă conținutul tabelelor: deschideți «Inspector de baze de date și stocare» în meniul principal, selectați proiectul și fișierul bazei de date (.db, .sqlite sau .sqlite3), apoi apăsați «Deschide baza de date». IDE citește schema tuturor tabelelor sale cu un analizator complet de pagini SQLite (arbore B cu pagini de revărsare) și afișează primele 20 de rânduri ca tabel de text pe care Jieshuo îl citește cu voce tare. Scrieți o interogare SELECT și apăsați «Rulează interogarea» (de exemplu SELECT nama FROM pengguna WHERE kota = 'Makassar') — interogările acceptă acum JOIN, GROUP BY, ORDER BY și LIKE și sunt executate de motorul real Android SQLite de pe telefon. Pentru a modifica o valoare, tastați numărul rândului (1 = primul rând), numele coloanei și noua valoare, apoi apăsați «Modifică valoarea celulei» — valoarea este scrisă înapoi în fișierul .db. Apăsați «Salvează copia de rezervă» pentru a salva starea actuală a tabelului ca fișier <nume-bază-de-date>.cadangan.txt în proiect. SharedPreferences și DataStore pot fi, de asemenea, citite. Ceea ce nu poate fi citit încă: baze de date criptate, modificări WAL neconfirmate și valori tipizate în DataStore Proto specializat (afișate doar ca vizualizare generală a câmpului).

Fabrică de teste unitare și fuzzing
Pentru a găsi lacune de logică înainte de a partaja aplicația: deschideți «Fabrică de teste unitare și fuzzing» în meniul principal, selectați proiectul și fișierul de cod, apoi apăsați «Creează și rulează teste». IDE citește semnăturile funcțiilor din fișier, creează cazuri de test obișnuite și la limită (text gol, null, numere maxime, caractere ciudate) și apoi execută cu adevărat aceste teste: codul proiectului este compilat și fiecare metodă @Test este executată cu o limită de 5 secunde, astfel încât rezultatul este treceri și eșecuri reale cu valorile lor reale. Fuzzingul este, de asemenea, executat cu adevărat pe funcțiile proiectului (prin reflecție, 2 secunde pe apel, maximum 20 de metode), iar procentul de acoperire a liniilor este calculat cu adevărat prin instrumentare care păstrează numerele originale de linie. Rezultatul raportează câte teste au trecut și au eșuat, câte linii de cod și funcții au fost găsite și ce cazuri de test au fost create. Testele create folosesc exact același API ca JUnit, dar definițiile de adnotare și afirmație sunt scrise în interiorul fișierului de test creat, deoarece biblioteca reală JUnit nu este inclusă în aplicație.

Simulator de condiții extreme ale dispozitivului și auditor de scurgeri de memorie
Pentru a testa rezistența aplicației atunci când sistemul îi ucide procesul, rețeaua se întrerupe, ecranul se rotește sau economisirea bateriei este activată: deschideți «Simulator de condiții extreme ale dispozitivului și auditor de scurgeri de memorie» în meniul principal, selectați proiectul, apoi apăsați «Rulează simularea». IDE rulează trei scenarii de stres cu rotație simulată a ecranului și urmărește obiectele ținute în memorie chiar și după închiderea ecranului lor, apoi raportează datele pierdute și lanțurile de obiecte care se scurg. Starea de salvare și restaurare este acum citită din sursa proprie a proiectului utilizatorului, nu dintr-un exemplu fix; serverul local loopback este oprit cu adevărat la mijlocul testului pentru a măsura întreruperea rețelei; este luat și analizat un dump real de heap, două dumpuri sunt comparate și lanțul de reținere este urmărit de la rădăcinile GC; iar procesul propriu al aplicației este ucis cu adevărat după ce starea sa este salvată, apoi se verifică ce date revin când este deschis din nou. Ceea ce este încă imposibil dintr-o aplicație obișnuită: oprirea radioului sau a Wi-Fi-ului telefonului și oprirea forțată a altor aplicații — ambele necesită permisiune de sistem; în schimb, aplicațiile din fundal sunt ucise prin killBackgroundProcesses, a cărei permisiune există deja în manifest, cu o etichetă onestă pe ecran.

Arhitect de planuri de proiect
Pentru a transforma o idee mare de aplicație într-un plan de lucru pas cu pas: deschideți «Arhitect de planuri de proiect» în meniul principal, selectați proiectul, scrieți ideea aplicației (de exemplu o aplicație mică de casă de marcat pentru magazin alimentar cu rate) și apăsați apoi «Creează plan». IDE construiește module, o listă de fișiere și repere mici, apoi le salvează ca cetak-biru.txt în folderul proiectului. De fiecare dată când un reper este finalizat, apăsați «Marchează următorul reper ca finalizat» sau apăsați «Încarcă planul salvat» pentru a redeschide planul salvat. Dacă un furnizor AI activ este selectat în «Setări AI» și cheia sa este disponibilă, planul este construit de acel furnizor; dacă cheia lipsește sau furnizorul nu poate fi contactat, IDE revine la modele de cuvinte cheie offline și spune sincer această limitare. Răspunsul furnizorului este verificat doar pentru format (există module și repere), nu pentru adevărul conținutului — revizuiți întotdeauna planul înainte de a construi.

Narator al fluxului logic al codului
Pentru a înțelege codul lung fără a asculta sintaxa linie cu linie: deschideți «Narator al fluxului logic al codului» în meniul principal, selectați proiectul și fișierul de cod, apoi apăsați «Narațiune de cod». IDE transformă fiecare linie într-o propoziție indoneziană (de exemplu dacă totalul este peste 100000, executați următorul bloc), afișează o hartă a apelurilor între metode și o analiză a fluxului de date între metode (valori transmise mai departe, utilizate sau ignorate) și marchează erori potențiale subtile cu numerele lor de linie — String comparat cu ==, un flux deschis fără a fi închis și o variabilă scrisă în două metode diferite. Dacă un furnizor AI activ este selectat în «Setări AI», este disponibil și un rezumat al fluxului de la acel furnizor; dacă nu există, ecranul folosește narațiunea offline și spune această limitare. Narațiunea, harta apelurilor și fluxul de date folosesc analiza de modele de text offline, nu un analizator AST complet — metodele a căror acoladă de deschidere se află pe propria linie, câmpurile de clasă și apelurile prin reflecție nu sunt urmărite — iar avertismentele de cursă de date pot apărea pentru o variabilă care, în realitate, este folosită doar alternativ.

Fabrică de pachete de aplicații și pregătire pentru Play Store
Pentru a pregăti o aplicație pentru Google Play Store direct de pe telefon: deschideți «Fabrică de pachete de aplicații și pregătire pentru Play Store» în meniul principal, selectați proiectul, apoi apăsați «Creează pachet AAB». IDE construiește fișierul .aab din manifestul, resursele și activele proiectului cu un BundleConfig.pb real, validează structura pachetului, apoi împarte pachetul în APK-uri reale de variantă (de bază, după arhitectură, după limbă și universal) cu dimensiuni măsurate din acea împărțire, nu estimări. Pachetul este semnat cu JAR v1 cu aceeași cheie de proiect folosită pentru semnarea APK, iar lanțul său de semnături este verificat criptografic. Acest ecran auditează și pregătirea pentru Play — SDK-ul țintă sub 35 este marcat «ridicat», deoarece Play Store necesită 35 sau mai mult, iar o bibliotecă de 64 biți lipsă este, de asemenea, marcată «ridicat». Bundletool real nu poate rula pe dispozitiv, deoarece bundletool necesită JVM, în timp ce Android nu are JVM; calea de mai sus este cea mai apropiată cale reală pe dispozitiv.

Motor de actualizare OTA și lansări treptate
Pentru a trimite o mică corecție fără a-i forța pe utilizatori să descarce din nou întregul APK: deschideți «Motor de actualizare OTA și lansări treptate» în meniul principal, selectați proiectul, scrieți conținutul versiunii vechi și noi, apoi apăsați «Creează pachet de corecție». IDE calculează diferența și creează un pachet de corecție (patch-ota.zip) cu amprenta SHA-256 a conținutului nou, apoi verifică dacă acest dispozitiv se află în primul pas de lansare de 10 la sută. Corecțiile acceptă acum delta binar pe orice fișier (inclusiv DEX și APK), sunt împachetate cu o semnătură RSA-2048 și verificate cu o cheie publică de încredere înainte de a fi aplicate și pot fi descărcate de pe serverul dezvoltatorului împreună cu lista sa de lansări; dacă aplicarea eșuează, fișierul vechi rămâne intact. Aplicarea unei corecții pe o aplicație în execuție se face prin resemnare cu cheia proiectului și prin PackageInstaller, deoarece este imposibil să înlocuiești codul unui proces în execuție din interiorul său — APK-ul este blocat și DEX-ul este deja încărcat.

Studio de revizuire a codului în echipă
Pentru a revizui modificările unui coleg și a rezolva conflictele de îmbinare fără a citi săgețile Git: deschideți «Studio de revizuire a codului în echipă» în meniul principal, selectați proiectul, tastați trei versiuni de text (de bază, locală, a colegului), apoi apăsați «Deschide revizuirea echipei». IDE îmbină cele trei pe baza unităților de sintaxă Java — două modificări pe aceeași linie, dar în declarații diferite, nu mai sunt considerate conflict — și afișează fiecare conflict ca opțiune de vot: folosiți versiunea locală, folosiți versiunea colegului sau îmbinați ambele — linia rezultat este inserată în poziția inițială a conflictului, astfel încât ordinea liniilor să rămână corectă — apoi scrie rezultatul în gabung-hasil.txt în proiect. Mai jos se află tabla de lucru a proiectului: tastați un titlu de sarcină, apoi apăsați «Adaugă sarcină»; sarcinile sunt salvate ca text în folderul .tugas din interiorul proiectului și sincronizate prin commituri în Git din interiorul aplicației, astfel încât tabla poate fi citită din nou din orice istoric de commituri. Această împărțire a sintaxei nu este un analizator AST complet, iar Git din interiorul aplicației salvează un instantaneu complet pentru fiecare commit; nu există un server separat de sincronizare.

Dictarea Structurii Codului
Pentru a scrie cod cu vocea în interiorul editorului: deschide un proiect în Editor și apoi apasă pe butonul Dictarea Structurii Codului. Rostește comenzi în indoneziană, de exemplu buat fungsi tambah dengan parameter a angka dan b angka, buat kelas Mobil sau buat variabel teks nama sama dengan Budi — IDE-ul transformă vorbirea într-un bloc de cod Java, Kotlin, Python sau Compose valid sintactic și îl inserează la poziția cursorului, apoi citește cu voce tare un scurt rezumat prin Jieshuo. Dictarea folosește serviciul de introducere vocală încorporat al sistemului, fără permisiune suplimentară pentru microfon, și recunoaște doar modelele de comandă deja înregistrate; vorbirea din afara acestor modele nu este transformată în cod. Numerele rostite ca cuvinte (de exemplu 'lima') nu sunt încă transformate în cifre.

Spațiu de Colaborare Local (fără internet)
Pentru a lucra împreună într-o singură cameră fără internet: deschide Colaborare în meniul principal și apoi deschide secțiunea Spațiu de Colaborare Local. Un telefon deschide o sesiune (IDE-ul afișează o adresă IP locală și un PIN din 6 cifre), un alt telefon se alătură cu acea adresă și acel PIN. Modificările de text sunt trimise ca diferențe de linie, un APK construit poate fi trimis la telefonul testerului, iar rapoartele de blocare de pe telefonul testerului sunt primite înapoi. O sesiune este doar pentru un prieten; dacă două persoane modifică exact aceeași linie în același timp, este folosită ultima modificare. PIN-ul este trimis ca text simplu în rețeaua locală. Această cameră nu a fost încă testată pe un telefon real.

Setări AI
Pentru a configura furnizorul AI și cheile API pentru construirea de aplicații: în meniul principal, în grupul de setări, apăsați «Setări AI» (lângă butonul «Conector»). Selectați furnizorul care va fi folosit din lista disponibilă și bifați «Comută modelul la eroarea furnizorului», astfel încât IDE să încerce automat următorul model de la același furnizor dacă un model eșuează. Apăsați «Gestionează cheile API» pentru a adăuga chei de rezervă (tastați numele și cheia, apoi apăsați «Salvează»; cheile sunt afișate mascate, doar ultimele 4 caractere sunt vizibile). Cheile sunt salvate pe telefon și nu sunt trimise niciodată în altă parte decât furnizorului selectat la construirea aplicației. Furnizorul selectat este acum folosit cu adevărat de «Arhitect de planuri de proiect» și «Narator al fluxului logic al codului»; construirea unei aplicații pe ecranul «Creator de aplicații AI» folosește încă AI locală pe telefon (fără internet).

Conector
Pentru a analiza un APK și apoi a-l trimite: apasă în meniul principal, în grupul Setări, pe Conector (lângă butonul Setări AI). Alege un fișier APK de pe telefon, IDE-ul citește conținutul acestuia (numele pachetului, versiunea, lista de activități) și apoi apasă pe Trimiteți APK pentru a-l trimite prin meniul de partajare al sistemului (de exemplu WhatsApp sau Drive).

Limbă și sunet
Pentru a schimba limba aplicației: deschide Setări, apoi Limba aplicației și apoi alege o limbă sau Conform sistemului. Ecranul principal și majoritatea ecranelor trec imediat la limba aleasă fără a închide sau a reporni aplicația; unele ecrane (de exemplu Terminal, Colaborare, Setări AI și Gestionarea cheilor) folosesc în continuare vechea limbă până când sunt redeschise. Dacă alegi Conform sistemului, limba urmează limba de sistem a telefonului.

Semnătură implicită per proiect și Anti Tamper
Din versiunea 5.7, un proiect care nu utilizează o semnătură personală este semnat cu propria cheie încorporată a proiectului (creată o dată în dosarul tanda-tangan-bawaan din interiorul proiectului și apoi utilizată mai departe), astfel încât semnătura încorporată diferă de la proiect la proiect — nu mai este o cheie comună pentru toate aplicațiile. Nu ștergeți dosarul tanda-tangan-bawaan: fără acea cheie, un nou APK nu poate suprascrie vechiul APK pentru același proiect. Setările fiecărui proiect (arhitectură separată, semnătură personală, Anti Tamper, keystore ales, SDK) sunt acum salvate în fișierul settings.gradle din interiorul proiectului și citite din nou de fiecare dată când proiectul este construit. În Setări, categoria Semnătură, există caseta de selectare Anti Tamper pentru aplicația construită: dacă este activă, aplicația construită verifică pe dispozitiv semnătura și conținutul dex de fiecare dată când este deschisă; dacă a fost resemnată sau modificată de altcineva, aplicația refuză să ruleze. Sunt detectate, de asemenea, instrumente de depanare și injectare precum Frida/Xposed, iar fereastra aplicației este blocată de la înregistrarea ecranului.

Creator de videoclipuri demo
Pentru a crea un videoclip demonstrativ al unei aplicații construite: deschideți Creator de videoclipuri demo în meniul principal, alegeți proiectul, completați titlul videoclipului și apăsați apoi Creați scriptul videoclipului demonstrativ — IDE scrie video-demo.txt cu 5 scene standard (deschidere, vizualizare principală, funcția 1, funcția 2, încheiere) împreună cu textul de narațiune și durata fiecărei scene. Apăsați Creați slideshow HTML pentru a crea video-demo.html din imaginile proiectului (pictogramă + capturi de ecran dacă există) care se schimbă automat la fiecare 5 secunde. Acesta NU este un videoclip .mp4 — pentru un videoclip real, deschideți video-demo.html în browserul telefonului și înregistrați apoi ecranul, sau citiți narațiunea din video-demo.txt în timp ce înregistrați aplicația care rulează.

Aspect nou în stil Android Studio
Aspectul IDE a fost acum aranjat ca în Android Studio (doar aspectul — toate butoanele, meniurile și fluxurile rămân exact ca înainte): fundal gri deschis, titluri de ecran negre îngroșate, butoane albastre cu text alb și câmpuri de introducere albe cu ramă subțire. Meniul principal este grupat vizual (Funcțiile Creatorului, Cloud, Temă și altele, Voce, Cod și funcții noi, Instrumente) fără a schimba ordinea butoanelor. Terminalul utilizează în continuare un panou întunecat ca fereastra Terminal din Android Studio, iar editorul de cod are în continuare fundal alb și text negru. Tot textul este citit în continuare clar de Jieshuo.

Setări
Pentru a seta aplicația: deschideți meniul de opțiuni de pe ecranul principal și apăsați apoi Setări. În interior există 12 categorii: Setări GitHub (securitate, semnătură personală, istoric de construire și token GitHub), Setări de construire APK pe dispozitiv (salvarea parolei keystore și a istoricului de construire pe dispozitiv), Temă (culoarea aplicației), Semnătură (crearea keystore pentru semnătură personală și caseta de selectare Anti Tamper pentru aplicația construită), Dosar proiect (locația dosarului de proiect), Limbă și sunet (limba interfeței și viteza de vorbire a modului vocal), Dimensiune text și aspect (dimensiunea fontului editorului), Construire (SDK țintă implicit și împărțire implicită a arhitecturii pentru ecranul Creează proiectul), Notificări (sunet când construirea este finalizată), Copie de rezervă automată (programul de copiere de rezervă a proiectului), Profil dezvoltator (nume, număr WhatsApp și cont afișat pe ecranul de donație) și Confidențialitate și date (resetarea setărilor și ștergerea datelor aplicației). Fiecare categorie are un buton Înapoi la ecranul anterior pentru a reveni la meniul de categorii. Setările care tocmai au fost salvate (încă neaplicate) sunt explicate sincer pe ecran.

Donează dezvoltatorului
Pentru a dona sau a saluta dezvoltatorul: apăsați butonul Donează dezvoltatorului de pe ecranul principal, lângă butonul Despre instrument. Pe ecranul de donație există butonul Copiați contul BRI — apăsați-l pentru a copia numărul de cont al dezvoltatorului și lipiți-l apoi în aplicația dvs. bancară. Există, de asemenea, secțiunea Salutați dezvoltatorul pe WhatsApp: completați numele dvs. și orașul natal și apăsați apoi Trimiteți pe WhatsApp — WhatsApp se deschide cu mesajul de salut deja completat, apăsați doar Trimiteți pe WhatsApp și reveniți apoi la aplicație. WhatsApp nu permite altor aplicații să trimită mesaje automat, deci trimiterea este făcută în continuare de dvs. înșivă în WhatsApp.

Comenzi favorite din terminal
Pentru a salva comenzi folosite des în Terminal: deschideți Terminal și apăsați apoi Favorit. Apăsați Adăugați un favorit nou, completați numele (de exemplu Vedeți fișierul) și comanda acestuia (de exemplu ls -la) și apăsați apoi Salvează — favoritul este salvat permanent pe telefon. Apăsați numele favoritului pentru a-l rula direct în terminal; apăsați Ștergeți favoritul și alegeți apoi unul de șters (cu confirmare). Există deja 3 favorite încorporate: Vedeți fișierul (ls -la), Verificați spațiul (df -h) și Curățați ecranul (clear) — toate pot fi șterse. O comandă goală nu poate fi nici salvată, nici rulată; Terminalul vă anunță prin mesaj și voce dacă se întâmplă acest lucru.

Analize și calitate
Pentru a vedea un rezumat al utilizării aplicației și al rapoartelor de blocare: apăsați butonul Analize și calitate de pe ecranul principal, lângă butonul Donează dezvoltatorului. Acest ecran arată de câte ori a fost deschisă aplicația, ce ecrane sunt deschise cel mai des, numărul de blocări și o listă a celor mai recente blocări cu sugestii scurte de corectare. Aceste date sunt stocate numai pe telefonul dvs. și nu sunt trimise nicăieri. Există un buton Ștergeți datele analitice cu un dialog de confirmare pentru a șterge toate aceste date. Cel mai recent ecran este înregistrat numai pentru ecranul principal și acest ecran.
