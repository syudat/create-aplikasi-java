Добро пожаловать в Create Aplikasi by Al Kautsar
Create Aplikasi — это приложение для создания Android-приложений, которое работает прямо на телефоне, без необходимости в ноутбуке. Это приложение позволяет любому создавать собственные Android-приложения, включая пользователей, которые только начинают учиться создавать приложения, и пользователей программ чтения с экрана. Полное руководство по использованию этого приложения доступно на этом экране «Об этом инструменте».

Что это за приложение и для кого оно
Create Aplikasi — это инструмент для создания Android-приложений, который работает на телефоне. Это приложение предназначено для всех, кто хочет создавать собственные Android-приложения, включая новичков и пользователей программ чтения с экрана. Это приложение предоставляет редактор кода, кнопку «Запустить» для тестирования проектов, кнопку «Собрать» для создания APK, а также меню для подписи и установки APK.

Цель этого приложения
Это приложение было создано для того, чтобы любой мог легко создавать собственные Android-приложения прямо с телефона. Его интерфейс сделан максимально простым, чтобы даже новые пользователи могли сразу попробовать.

Как создать новый проект, шаг за шагом
1. Нажмите «Создать проект» в главном меню.
2. Выберите тип проекта: HTML, Веб-сайт, Java, Kotlin, Compose или Python.
3. Введите название приложения, например: Garuda Decode.
4. Введите имя пакета (package name), например: com.android.garudadecode. Имя пакета должно использовать строчные буквы и состоять как минимум из двух частей, разделённых точками.
5. Введите версию приложения, например: 1.0, и код версии в виде числа, например: 1. Если оставить пустым, версия будет автоматически заполнена значением 1.0, а код версии — 1.
6. При необходимости введите минимальный SDK и целевой SDK. Если оставить пустым, будут использованы значения по умолчанию. Минимальный SDK — это самая низкая поддерживаемая версия Android, например: 21 означает Android 5.0. Максимальный целевой SDK — 36 (Android 16).
7. Нажмите кнопку «Выбрать разрешения», чтобы выбрать разрешения приложения, например: INTERNET. Разрешение INTERNET уже отмечено по умолчанию. Отмечайте только те разрешения, которые приложению действительно нужны.
8. При желании отметьте «Использовать отдельные архитектуры 64 бит и 32 бит», чтобы размер APK был меньше, и отметьте «Использовать личную подпись», если хотите использовать собственное хранилище ключей.
9. Нажмите «Создать проект». Новый проект сохраняется в папке Download/project и сразу появляется в разделе «Управление проектами».

Доступные типы проектов
• HTML: отображение из index.html, style.css и script.js, работает через WebView. Собирается прямо на телефоне.
• Веб-сайт: веб-сайт с меню (Главная, О нас, Контакты) из index.html, tentang.html, kontak.html, style.css и script.js, работает через WebView. Собирается прямо на телефоне.
• Java: собирается на телефоне. MainActivity находится в app/src/main/java/<package-name>/MainActivity.java. Отображение берётся из app/src/main/res/layout/activity_main.xml, текст — из app/src/main/res/values/strings.xml, а тема — из app/src/main/res/values/styles.xml.
• Kotlin: может собираться на устройстве (офлайн) с помощью компилятора Kotlin, включённого в приложение, или через GitHub Actions. MainActivity находится в app/src/main/java/<package-name>/MainActivity.kt, а файлы res такие же, как в проекте Java. Первая сборка Kotlin происходит медленнее из-за большого размера компилятора, а файлы .java, ссылающиеся на классы Kotlin, пока не могут быть собраны (файлы .java компилируются раньше файлов .kt).
• Compose: современное Android-приложение, интерфейс которого создаётся с помощью Jetpack Compose (а не XML-разметки). MainActivity находится в app/src/main/java/<package-name>/MainActivity.kt. Проекты Compose собираются через GitHub Actions (меню «Собрать проект», затем «Собрать онлайн») или в Termux с помощью Gradle, потому что Compose требует библиотек Jetpack Compose, которых нет на устройстве.
• Python: логика приложения пишется на языке Python (Chaquopy) в app/src/main/python/main.py и запускается хостом MainActivity.java в app/src/main/java/<package-name>/MainActivity.java. Проекты Python можно собирать прямо на телефоне (среда выполнения Chaquopy включена в приложение) или через GitHub Actions. Минимальный SDK для проектов Python — 24 (Android 7.0).

Изменить архитектуру проекта
Чтобы изменить настройки архитектуры существующего проекта, не создавая новый: в главном меню нажмите «Изменить архитектуру проекта», затем выберите проект и измените флажок «Собрать 64-битный APK (arm64-v8a)» или «Собрать 32-битный APK (armeabi-v7a)»; или в «Управлении проектами» долго нажмите имя проекта и выберите «Изменить архитектуру», чтобы открыть тот же экран сразу для этого проекта. Правило такое: если оба флажка включены, сборка даёт два отдельных APK — 64-битный и 32-битный; если включён только один флажок, сборка даёт один универсальный APK, который по-прежнему работает и на 64-битных, и на 32-битных устройствах. Отдельный APK только для одного варианта пока не поддерживается, потому что путь сборки знает только выбор «раздельно» или «универсально», но выбор каждого варианта сохраняется внутри проекта, чтобы не потеряться при повторном открытии экрана.

Структура файлов проектов Java, HTML, Веб-сайт, Kotlin, Compose и Python
Проекты Java, HTML, Веб-сайт, Kotlin, Compose и Python структурированы так же, как Android-проекты в целом. Внутри папки app находится папка src, а внутри неё — папка main. Внутри папки main находится AndroidManifest.xml рядом с папкой java, папка res, содержащая layout/activity_main.xml и values/strings.xml, а также values/styles.xml, а для HTML и Веб-сайта — папка assets, содержащая index.html (у Веб-сайта также есть tentang.html и kontak.html). У проектов HTML и Веб-сайт также есть собственный MainActivity в app/src/main/java/<package-name>/MainActivity.java, который загружает index.html в WebView и становится лаунчером в AndroidManifest. У проектов Python код Python находится в app/src/main/python/main.py, а хост MainActivity.java — в app/src/main/java/<package-name>/MainActivity.java. AndroidManifest.xml, разметку, строки и стили можно открывать и изменять в редакторе, как и MainActivity. Старые проекты, манифест которых всё ещё находится рядом с папкой app, по-прежнему можно собирать, потому что при сборке приложение сначала проверяет AndroidManifest.xml в app/src/main/, затем тот, что рядом с папкой app, и, наконец, файл данных проекта.

Правила разрешений (важно)
Разрешения, отмеченные при создании проекта, записываются только в одном месте, в зависимости от типа проекта. Для проектов Java, HTML, Веб-сайт, Kotlin, Compose и Python отмеченные разрешения записываются ТОЛЬКО в AndroidManifest.xml, расположенный в app/src/main/, рядом с папкой java, внутри папки проекта. Файл данных проекта для проектов Java, HTML, Веб-сайт, Kotlin, Compose и Python не содержит списка разрешений. Если вы выберете Java, а затем отметите INTERNET и CAMERA, в AndroidManifest.xml будет записано только INTERNET и CAMERA, без включения каких-либо других разрешений. При сборке приложение читает разрешения из того же места: из AndroidManifest.xml в app/src/main/ для проектов Java, HTML, Веб-сайт, Kotlin, Compose и Python (если его нет — из AndroidManifest.xml рядом с папкой app для старых проектов) и из файла данных проекта для старых проектов.

Как пользоваться редактором
Откройте «Управление проектами», коснитесь названия проекта, чтобы открыть редактор. В редакторе можно открывать файлы, писать код и сохранять изменения. Для проектов Java, HTML, Веб-сайт, Kotlin, Compose и Python файлы расположены внутри папки app/src/main. Чтобы поделиться проектом, используйте «Экспорт в ZIP» (см. раздел ниже).

Как запустить проект
В редакторе нажмите «Запустить», чтобы протестировать проект. Для проектов HTML и Веб-сайт запускается index.html через WebView. Если произойдёт ошибка, прочитайте сообщение об ошибке, исправьте код, а затем запустите снова.

Как собрать APK
В редакторе нажмите «Собрать». Есть два способа сборки. Первый — «Собрать на устройстве»: собирает прямо на телефоне без интернета, для проектов HTML, Веб-сайт, Java, Kotlin и Python. Второй — «Собрать онлайн» через GitHub Actions: собирает через интернет на GitHub и может использоваться для всех типов проектов. Проекты Compose можно собирать только вторым способом («Собрать онлайн») или в Termux с помощью Gradle, потому что Compose требует библиотек Jetpack Compose, которых нет на устройстве. Результат первой сборки ещё не подписан. После этого приложение подписывает его: автоматически встроенным ключом или личной подписью, если при создании проекта был отмечен флажок «Использовать личную подпись».

Как установить APK
Когда APK будет готов, нажмите «Установить», чтобы установить его. На Android 8 и выше телефон сначала запросит «Разрешить из этого источника», потому что это приложение устанавливает APK не из Play Store. Включите это разрешение один раз в Настройках, затем вернитесь в приложение: установка продолжится автоматически, без необходимости снова нажимать «Установить». Если кнопка «Установить» не появляется, убедитесь, что сборка завершена и APK создан.

Как подписать приложение
Каждый APK должен быть подписан, чтобы его можно было установить. Доступны два варианта. Первый — встроенный ключ: приложение подписывает его само автоматически, вам не нужно ничего делать. Второй — личная подпись: сначала создайте хранилище ключей через меню «Создать хранилище ключей» в главном меню, надёжно сохраните его пароль, затем отметьте «Использовать личную подпись» при создании проекта. Хранилище ключей хранится в Download/project/signing.

Экспорт проекта в ZIP
Экспорт в ZIP предусмотрен для того, чтобы проектами можно было делиться с друзьями. Как это сделать: в разделе «Управление проектами» нажмите и удерживайте название проекта, затем выберите «Экспорт в ZIP». Результат сохраняется в Download/project/<ProjectName>.zip. Папка bin не включается, поэтому размер небольшой, всего десятки КБ. Этот ZIP-файл можно отправить друзьям или загрузить на GitHub.

Расширение JAWS
Расширение JAWS использует движок расширений Jieshuo (CSR), а не его программу чтения с экрана. Таким образом, макеты могут продолжать работать, даже если пользователь использует TalkBack. Как это сделать: откройте «Расширение JAWS» в главном меню. Поскольку автоматический щелчок работает сам по себе, сначала необходимо включить службу в Настройках специальных возможностей. После этого можно создать новый макет: введите название макета, нажмите OK, затем заполните его поля.

Список щелчков хранится отдельно для порядка
Внутри макета есть два поля: поле скрипта и поле «Список щелчков». Список кнопок хранится отдельно в файле daftar_klik.txt, по одному имени в строке. Пример его содержимого: tombolSimpan, tombolHapus, tombolBuka. Чтобы открыть приложение, просто напишите >WhatsApp в этом списке. Старые макеты, у которых ещё нет файла daftar_klik.txt, будут показывать этот пример по умолчанию.

Предоставляемые простые функции
• klikTombol("tombolSimpan") — нажимает одну кнопку по её тексту.
• klikDaftarTombol(daftar) — нажимает список в daftar_klik.txt, по одной кнопке в строке, по порядку, а затем сообщает, сколько удалось и сколько не найдено.
• bukaAplikasi("WhatsApp") — открывает приложение по его названию, или напишите ">WhatsApp" в списке.
• klik(540, 1200) — нажимает по координатам экрана.
Все функции сначала сделаны простыми. Когда вы к ним привыкнете, позже можно будет добавить дополнительные функции.

О программах чтения с экрана
Это приложение разработано так, чтобы быть удобным для программ чтения с экрана. У каждого поля ввода есть подпись и пример заполнения, и до всех кнопок можно добраться без сложных жестов. Расширение JAWS сделано так, чтобы продолжать работать, даже если пользователь использует TalkBack, потому что используется его движок расширений, а не его программа чтения с экрана.

Конфиденциальность и безопасность
Проекты и хранилища ключей хранятся на вашем телефоне. Токен GitHub используется только для онлайн-сборок и хранится внутри этого приложения. Не делитесь своим токеном или паролем хранилища ключей ни с кем. Если вы используете личную подпись, храните хранилище ключей и его пароль в безопасном месте, потому что если они будут потеряны, старые APK нельзя будет обновить той же подписью.

Требования
Android 5.0 или новее. Разрешение на хранение: на Android 11 и выше используется разрешение на доступ ко всем файлам, на Android 10 и ниже используется обычное разрешение на хранение (чтение/запись хранилища), потому что в Android 10 нет разрешения на доступ ко всем файлам. Для сборки на устройстве требуется телефон с процессором ARM (32 или 64 бит). Для онлайн-сборки через GitHub Actions требуются интернет и токен GitHub. Проекты Kotlin можно собирать на устройстве, но первая сборка происходит медленнее и использует больше памяти из-за большого размера компилятора Kotlin. Проекты Compose собираются через GitHub Actions или в Termux с помощью Gradle. Проекты Python требуют Android 7.0 или новее (минимальный SDK 24), а итоговый APK больше, потому что он включает среду выполнения Python (Chaquopy) вместе с её стандартной библиотекой.

Терминал
Меню «Терминал» на главном экране открывает терминал внутри этого приложения. Такие команды, как ls, можно использовать для просмотра содержимого папки проекта, cd — для перемещения между папками, а git — для управления кодом. Вывод команд отображается в виде текста, который может прочитать программа чтения с экрана, и есть кнопка «Прочитать результат вслух», чтобы прослушать последний результат. Этот терминал использует системную оболочку телефона, поэтому интерактивные программы, такие как nano и vim, здесь пока нельзя использовать.

Лицензия (платная версия)
Чтобы продавать приложение, отметьте «Включить лицензию» при создании проекта, затем введите свой номер WhatsApp. Собранное приложение при первом открытии запросит лицензионный код: пользователь видит ID своего устройства, нажимает кнопку «Отправить ID устройства», чтобы отправить этот ID на ваш WhatsApp, а затем вы отвечаете лицензионным кодом. Лицензионный код вычисляется из ID устройства и пароля проекта (lisensi_seed в файле данных проекта) — надёжно храните этот пароль и не делитесь им. После ввода правильного кода приложение открывается и больше не запрашивает код.

Автоматический создатель значков
Значки новых проектов всё ещё прозрачны, поэтому в главном меню доступен Создатель значков. Как это сделать: нажмите «Создатель значков», напишите одну или две буквы (например, инициалы названия приложения), выберите цвет фона и цвет текста, посмотрите предварительный просмотр, затем нажмите «Сохранить в проект», чтобы использовать этот значок в выбранном проекте, или «Сохранить в загрузки», чтобы использовать его PNG-файл в другом месте. После создания проекта приложение также предлагает создать значок. Старый значок проекта можно заменить в любое время из меню проекта в разделе «Управление проектами» (нажмите и удерживайте название проекта, затем выберите «Сменить значок»).

Готовые шаблоны проектов
Если вы не хотите начинать с пустого проекта, выберите шаблон при создании проекта: Калькулятор (Java), Заметки (Java), Список дел (Kotlin), Веб-калькулятор (HTML), Сайт-профиль (Веб-сайт) или Счётчик (Compose). Выбор шаблона автоматически меняет тип проекта в соответствии с этим шаблоном, и проект создаётся с уже готовым начальным кодом — просто запустите или измените его. Если тип проекта снова изменить вручную после выбора шаблона, шаблон отменяется, и проект снова становится пустым. Для шаблонов HTML и Веб-сайт шаблон заменяет содержимое index.html, включая HTML-скрипт, введённый в форме.

Резервное копирование и восстановление проектов
Чтобы проекты не потерялись, доступна функция резервного копирования. Как это сделать: в разделе «Управление проектами» нажмите и удерживайте название проекта, затем выберите «Создать резервную копию». Резервная копия сохраняется в виде ZIP в папке Download/backup с названием проекта и датой, например: GarudaDecode-2026-11-14-123045.zip. Её содержимое такое же, как при экспорте в ZIP (всё содержимое проекта, без папки bin). Для восстановления: откройте меню в разделе «Управление проектами», выберите «Восстановить резервную копию», затем выберите файл резервной копии. Если название проекта уже существует, приложение спросит: Перезаписать старый проект или сохранить с Новым именем.

Поделиться проектами и импортировать проекты
Чтобы поделиться проектом с друзьями: в разделе «Управление проектами» нажмите и удерживайте название проекта, затем выберите «Поделиться». Проект отправляется в виде ZIP через приложения для обмена (WhatsApp, Telegram и другие). Чтобы получить проект от друга: откройте меню в разделе «Управление проектами», выберите «Импортировать проект», затем выберите ZIP-файл. Этот ZIP-файл должен содержать файл данных проекта — если его нет, файл отклоняется с понятным сообщением, потому что этот файл не является проектом Create Aplikasi. Если название проекта уже существует, приложение спросит: Перезаписать старый проект или сохранить с Новым именем.

Поиск и фильтр проектов
Если проектов уже много, в разделе «Управление проектами» есть поле поиска и фильтр по типу. Введите название проекта в поле поиска, и список сразу отфильтруется (прописные и строчные буквы не различаются). Фильтр по типу ограничивает список только одним типом: Все, HTML, Веб-сайт, Java, Kotlin, Compose или Python. Меню каждого проекта по-прежнему можно открыть как обычно из уже отфильтрованного списка.

Создание приложений голосом
Если вы не хотите печатать, используйте голос: нажмите «Сборка голосом» в главном меню, а затем произнесите команду. Команды, которые можно произнести: "Buat proyek kalkulator", "Bangun proyek Kalkulator", "Buka proyek Kalkulator", "Jalankan proyek Kalkulator", "Daftar proyek", "Buka ikon", "Kembali" и "Bantuan". Приложение отвечает голосом и текстом, поэтому им можно пользоваться, не глядя на экран. Распознавание голоса использует встроенное приложение распознавания речи телефона (бесплатно; может работать без интернета, если установлен индонезийский языковой пакет). Если в телефоне нет распознавания речи, команды можно ввести в текстовое поле на том же экране.

Конструктор приложений с ИИ
Введите или продиктуйте нужное приложение на экране Конструктора приложений с ИИ, например: «приложение заметок с кнопкой сохранить». Приложение анализирует ключевые слова внутри самого телефона (без интернета, без затрат), а затем создаёт настоящий проект из наиболее подходящего шаблона: калькулятор, заметки, список дел, веб-калькулятор, сайт профиля или счётчик. Если для вашего описания ещё нет подходящего шаблона, приложение создаёт пустой проект и честно говорит об этом — оно не притворяется, что поняло. Проект, созданный ИИ, можно открыть напрямую в разделе Управление проектами.

Прямой предпросмотр на телефоне друга
Чтобы показать проект другу до сборки: в разделе Управление проектами долго нажмите на имя проекта, затем выберите Предпросмотр на телефон друга. Приложение создаёт небольшой пакет предпросмотра с основными файлами проекта (index.html, MainActivity или main.py) плюс BACA-SAYA.txt с инструкциями и info.txt. Пакет отправляется как ZIP через WhatsApp или Telegram. Друг, получивший его, может сразу открыть предпросмотр: HTML-страницы открываются в браузере, код Java/Kotlin/Python читается как текст.

Магазин проектов
Рынок проектов содержит встроенные образцы проектов, которые можно установить в папку проекта одним касанием: Калькулятор, Заметки, Список дел, Веб-калькулятор, Сайт профиля, Счётчик, Цифровые часы и Веб-викторина. Онлайн-рынок (скачивание образцов из интернета) пока недоступен, поэтому этот рынок содержит образцы, уже находящиеся в приложении. Установленный проект можно открыть и изменить в разделе Управление проектами, как проект, сделанный самостоятельно.

Прямая совместная работа
Чтобы работать над проектом вместе с другом: откройте Совместная работа в главном меню, выберите проект, напишите заметку об изменениях (что было изменено), затем нажмите Поделиться для совместной работы. Проект отправляется как ZIP вместе с файлом CATATAN.txt внутри. Ваш друг работает над ним и отправляет ZIP обратно; вы нажимаете Получить ответ, сначала читаете заметку об изменениях, затем выбираете Применить, чтобы перезаписать старый проект, или Отмена, если передумали. ZIP без CATATAN.txt — не пакет совместной работы; для обычного ZIP проекта используйте Импорт проекта в разделе Управление проектами.

Автоматический переводчик приложений
Чтобы перевести текст в приложении на другой язык: откройте Переводчик приложений в главном меню, выберите проект и целевой язык (английский, арабский или яванский), затем нажмите Перевести. Словарь уже находится в телефоне (без интернета, без затрат) и содержит повседневные распространённые слова; текст из strings.xml, разметки и кода читается, а затем переводится. Результат записывается в папку values-язык/strings.xml (если у проекта есть strings.xml) и отчёт перевод-язык.txt в папке проекта. Слова, которых ещё нет в словаре, оставляются как есть и сообщаются — так вы знаете, какие слова ещё нужно перевести самостоятельно.

Создатель игр без кода
Чтобы сделать игру, не написав кода: откройте Создатель игр в главном меню, выберите тип игры (Угадай число, Викторина или Поймай звезду), заполните имя игры, количество (уровни/вопросы/звёзды) и сообщение о победе, затем нажмите Создать игру. Игра создаётся как настоящий проект, который можно запустить напрямую в разделе Управление проектами и собрать в APK, как любой другой проект.

Автоматическое тестирование приложений
Чтобы проверить проект перед сборкой: в разделе Управление проектами долго нажмите на имя проекта, затем выберите Автоматический тест. IDE проверяет 10 вещей, не собирая APK: наличие обязательных файлов (файл данных проекта, манифест, главный файл, разметка, строки), имя пакета и версию, используемые разрешения, значок и баланс скобок кода. Результат показывается по каждому пункту (ПРОЙДЕНО/НЕ ПРОЙДЕНО с сообщением) и читается вслух программой Jieshuo. Сначала исправьте всё, что НЕ ПРОЙДЕНО, затем нажмите Собрать проект.

AI Pemeriksa Kode
Чтобы проверить код проекта на шаблоны, которые часто вызывают проблемы: откройте Проверка кода в главном меню, выберите проект, затем нажмите Проверка кода. Проверяющий работает внутри телефона (без интернета) и ищет неиспользуемые переменные, пустые функции, явно бесконечные циклы, текст, написанный прямо в коде (лучше в strings.xml), опасные разрешения и API, маркеры TODO/FIXME и динамическое выполнение. Каждая находка содержит имя файла, номер строки и предложение по исправлению. Этот проверяющий основан на шаблонах, это не настоящий ИИ — проблемы, не следующие шаблону, всё ещё могут пройти.

Интерактивный режим обучения
Чтобы учиться создавать приложения шаг за шагом: откройте Обучение в главном меню. Есть 5 уроков: Создание первого проекта, Добавление кнопки, Изменение цвета, Добавление звука и Сборка APK. Коснитесь урока, чтобы прочитать его объяснение и практическое задание, выполните задание, затем нажмите Проверить задание — IDE действительно проверяет, выполнено ли задание (сканируя проект и APK на вашем телефоне). Пройденные уроки отмечаются как завершённые и сохраняются.

Синхронизация с облаком
Чтобы сделать резервную копию проекта в облако: откройте Синхронизация с облаком в главном меню. Локальная резервная копия сохраняет ZIP проекта в папку Download/cloud с отметкой времени и может быть восстановлена в любое время из списка резервных копий. Резервная копия GitHub загружает ZIP проекта в ваш приватный репозиторий (используя токен из настроек GitHub) и может быть скачана снова. Это ручное резервное копирование и восстановление — полная автоматическая двусторонняя синхронизация требует сервера, поэтому пока недоступна.

Автоматический конструктор бэкенда
Чтобы сделать бэкенд, не написав код сервера: откройте Конструктор бэкенда в главном меню, выберите тип бэкенда (Заметки, Список дел или Доска сообщений), заполните имя проекта, затем нажмите Создать Backend. IDE создаёт настоящий HTML-проект со страницей формы и списком данных, сохранённых в локальном хранилище телефона (localStorage), — данные сохраняются и могут быть прочитаны снова при запуске приложения. Этот бэкенд работает на одном телефоне; два телефона пока не могут делиться одними данными, так как нет интернет-сервера.

Автоматический дизайнер тем
Чтобы придать проекту цветовую тему: откройте Дизайнер тем в главном меню, выберите проект и тему (Светлая, Тёмная, Синяя, Зелёная, Красная или Фиолетовая). Предпросмотр показывает шесть цветов темы (основной, тёмный основной, акцент, фон, текст, вторичный текст) и читается вслух программой Jieshuo. Нажмите Применить тему — IDE записывает colors.xml и styles.xml (стиль app_theme) в проект, они используются напрямую при запуске или сборке проекта.

Создатель анимаций
Чтобы придать проекту анимацию: откройте Создатель анимаций в главном меню, выберите проект, тип анимации (Затухание, Сдвиг, Вращение, Отскок или Пульсация), длительность (от 100 до 10000 миллисекунд) и цель (кнопка, текст или изображение), затем нажмите Создать анимацию. IDE записывает настоящий файл анимации (res/anim/anim_<тип>.xml для проектов Java/Kotlin/Compose или animasi.css для проектов HTML/Веб-сайт) вместе с примером кода использования, показанным на экране.

Запись действий
Чтобы повторять работу автоматически: IDE записывает выполненные действия (открыть проект, запустить, собрать, экспортировать, сделать резервную копию, создать проект, сохранить файл). Откройте Запись действий в главном меню, чтобы увидеть список записанных действий с их планом, затем нажмите Повторить — IDE снова выполняет действия, которые можно автоматизировать (резервное копирование и создание проекта выполняются на месте; запуск, сборка и экспорт открывают свой главный экран; открытие и сохранение открывают редактор). Действия, которые нельзя автоматизировать, пропускаются и сообщаются в конце.

Автоматическая безопасность
Чтобы проверить безопасность проекта: откройте Автоматическая безопасность в главном меню, выберите проект, затем нажмите Проверить безопасность. IDE проверяет 8 вещей локально (без интернета): опасные разрешения (местоположение, SMS, звонки, камера, микрофон, контакты), отправку данных по HTTP, отправку SMS, исходящие звонки, пароль или ключ, написанный прямо в коде, WebView без защиты, компонент, экспортированный без разрешения, и http-адрес без шифрования. Каждой находке присваивается уровень БЕЗОПАСНО, ПРЕДУПРЕЖДЕНИЕ или ОПАСНО с предложением по исправлению, а сводка читается вслух программой Jieshuo.

Офлайн ИИ
Чтобы использовать вспомогательные инструменты для текста и кода без интернета: откройте Офлайн ИИ в главном меню. Есть 4 инструмента: Исправить текст (заглавные буквы, пунктуация и двойные пробелы), Сократить текст (берёт 3 самых важных предложения), Создать имя приложения (из написанного описания) и Предложить имя переменной (ищет имена переменных из 1-2 букв в проекте). Это простые правила внутри телефона, а не настоящая модель ИИ. Результат исправления текста можно применить к strings.xml проекта кнопкой Применить.

Создатель виджетов и обоев
Чтобы создать виджет главного экрана: откройте Виджеты и обои в главном меню, выберите проект, заполните текст виджета, затем нажмите Создать виджет. IDE записывает WidgetSaya.java, разметку виджета, информацию о виджете и добавляет приёмник в AndroidManifest.xml проекта — соберите проект, затем установите виджет с главного экрана телефона. Для обоев: заполните надпись и цвета фона и текста, сделайте предпросмотр, затем сохраните как PNG в папку Download или сразу установите как обои телефона.

Интеграция социальных сетей
Чтобы добавить кнопки «поделиться» в приложение: откройте Социальные сети в главном меню, выберите проект, затем добавьте обмен в WhatsApp, Facebook или Telegram (или все три сразу). IDE записывает настоящий код обмена в главный файл проекта (MainActivity или index.html). Кнопка Проверить обмен открывает выбор обмена из IDE с примером текста, чтобы поток можно было ощутить перед сборкой приложения.

Приложение из изображения
Чтобы сделать приложение-галерею из изображения: откройте Приложение из изображения в главном меню, выберите изображение из галереи. IDE анализирует размер изображения и доминирующий цвет, затем создаёт настоящий проект приложения-галереи: изображение копируется в assets проекта, цвет темы берётся из доминирующего цвета изображения, а имя приложения — из имени файла изображения. Откройте Управление проектами, чтобы запустить или собрать это приложение-галерею.

Интерактивный терминал (VT-парсер)
Чтобы использовать интерактивные программы в Терминале: откройте Терминал в главном меню, затем запустите nano, vim, top или htop. Терминал теперь использует VT-парсер (экран-сетка 24 строки x 80 столбцов), поэтому эти программы отображаются правильно — курсор движется, строки стираются, а экран меняется, как в настоящем терминале. Есть специальные кнопки Tab, Стрелка вверх, Стрелка вниз и Esc для управления интерактивными программами. Вывод по-прежнему является текстом, который может читать Jieshuo; нажмите Прочитать экран вслух, чтобы услышать последнюю строку.

Terminal Exec (бинарный файл приложения)
Чтобы запустить бинарный файл в папке приложения (например, aapt2, ECJ, D8) из Терминала: введите команду как обычно. IDE использует libkautsarexec.so, чтобы бинарные файлы в папке приложения могли выполняться на Android 10 и выше. Нажмите Тест Exec в Терминале, чтобы проверить, работает ли путь exec бинарных файлов на этом телефоне, — результат показывается как есть. Если exec заблокирован системой, системные команды и shell-скрипты всё равно работают; запустите бинарный файл через меню Собрать проект.

Терминал остаётся активным (KeepAlive)
Чтобы shell продолжал работать при переходе на другой экран: откройте Терминал, выполните команду, затем нажмите Назад или перейдите на другой экран — shell НЕ умирает, а уведомление Терминала остаётся видимым, чтобы вы могли вернуться одним касанием. Уже выполненные команды сохраняются в истории (кнопка История или стрелки вверх/вниз в поле команды), а часто используемые команды можно сохранить как избранные (кнопка Избранное). Нажмите Закрыть shell, когда закончите, чтобы shell действительно завершился. Есть также кнопка Собрать в Терминале в меню проекта и в меню редактора: Терминал открывается в папке проекта с уже заполненной командой сборки.

Установка инструментов терминала (пробная)
Функция, всё ещё находящаяся в пробной эксплуатации: в Терминале есть кнопка Установить инструменты терминала, чтобы установить среду Termux из зеркала в репозитории alat-termux разработчика (github.com/syudat/alat-termux), как ещё один путь помимо кнопки Установить Termux, которая берёт официальную версию Termux. Содержимое зеркала точно такое же, как официальная версия, и проверяется с помощью SHA-256 во время установки. После установки среды можно использовать команды pkg update и pkg install, а дополнительные инструменты из репозитория также устанавливаются в терминал: info-terminal — для просмотра информации о среде, bersih-terminal — для очистки кэша, и cadangkan-proyek — для архивирования папки проекта в один датированный файл tar.gz. После этого приложение автоматически устанавливает базовые пакеты Linux (git, python, curl, wget, nano, openssh, zip, unzip) и инструменты сборки APK с подписью (openjdk-21, kotlin, gradle, ecj, aapt2, d8, apksigner, clang, cmake, ninja, make) из официального репозитория Termux, поэтому терминал сразу готов создавать приложения. Скачивание больших пакетов (сотни МБ) может занять много времени. Во время установки прогресс и вывод команд отображаются на главном экране Терминала, а конечный результат читается вслух программой чтения с экрана. Если установка пакетов ещё не завершена, нажмите Установить инструменты терминала ещё раз, чтобы продолжить её.

Полный голосовой режим
Чтобы полностью управлять IDE голосом: откройте Голосовой режим в главном меню, затем нажмите Начать слушать. IDE слушает непрерывно — не нужно нажимать кнопку для каждой команды, — выполняет команду и отвечает голосом. Есть 26 команд: создать, собрать, открыть, запустить, перечислить, найти, удалить, проверить, проконтролировать, экспортировать, сделать резервную копию, поделиться, создать значок, перевести, собрать в терминале, прочитать экран, открыть все экраны (включая безопасность, офлайн ИИ, виджет, социальные сети, игру, обучение, облако, бэкенд, тему, анимацию, запись), назад, закрыть и помощь. Если режим оставить активным, прослушивание продолжается автоматически при повторном открытии этого экрана. Нажмите Перестать слушать, чтобы выключить этот режим. Если на телефоне нет службы распознавания голоса, команды всё равно можно писать в текстовое поле.

Переводчик кода
Чтобы переводить код между языками без интернета: откройте Переводчик кода в главном меню, выберите проект, выберите исходный файл (.java/.kt), затем выберите направление: Java в Kotlin. Нажмите Перевести — результат показывается вместе с отчётом о строках, которые нельзя перевести (эти строки сохраняются как есть и помечаются). Нажмите Сохранить результат, чтобы записать НОВЫЙ файл (имя-перевод.java/.kt) в той же папке; исходный файл никогда не перезаписывается. Это переводчик по правилам шаблонов, а не компилятор — всегда проверяйте результат перед использованием.

Git внутри приложения
Чтобы использовать Git внутри IDE без Termux: откройте Git внутри приложения в главном меню, выберите проект, затем нажмите Создать репозиторий Git, чтобы создать локальный репозиторий (.git) в этом проекте. Нажмите Проверить статус, чтобы увидеть новые, изменённые или удалённые файлы по сравнению с последним коммитом; заполните сообщение коммита, затем нажмите Коммит, чтобы сохранить снимок проекта; нажмите Посмотреть журнал коммитов, чтобы увидеть историю коммитов. Отправка в GitHub и Получение из GitHub используют снимки через токен GitHub (репозиторий pembuat-aplikasi-build) — не протокол git. Клонирование, Отправка (системный git) и Получение (системный git) работают только если бинарный файл git установлен на телефоне (обычно нет). Это не полный git: нет слияния, веток или diff — каждый коммит сохраняет полный ZIP-снимок проекта.

Создатель рекламы
Чтобы добавить рекламу в собранное приложение: откройте Создатель рекламы в главном меню, выберите проект, поставщика (AdMob, Unity Ads или AppLovin) и тип рекламы (Баннер, Межстраничная или С вознаграждением). Заполните ID рекламного блока, если он у вас уже есть, — пустое поле означает использование тестового ID (AdMob использует официальный тестовый ID Google; Unity использует пример ID игры; AppLovin использует пустое размещение). Нажмите Создать рекламный код, чтобы увидеть код Java и Kotlin и руководство; нажмите Сохранить в проект, чтобы записать всё в файл реклама-<поставщик>-<тип>.txt в проекте. Это шаблон кода + руководство, а не рекламный SDK — SDK не включён в IDE; настоящая реклама появится только после того, как вы создадите учётную запись поставщика, создадите рекламный блок, вставите свой собственный ID блока и добавите зависимость SDK в build.gradle проекта.

Детский режим
Чтобы использовать IDE вместе с ребёнком: откройте Детский режим в главном меню. Экран упрощён, с большими кнопками и только 4 безопасными действиями: Создать проект (из безопасных шаблонов: Калькулятор, Угадай число, Викторина, Поймай звезду), Открыть проект, Запустить и Обучение. На этом экране нет кнопки удаления, экспорта, резервного копирования или настроек токена. При первом входе создайте 4-значный PIN — этот PIN используется родителем для выхода из Детского режима (кнопка Выйти из детского режима или кнопка Назад). Этот PIN — лёгкая защита для маленьких детей, а не настоящая безопасность.

Создатель приложений Wear OS и TV
Чтобы создать приложение для часов (Wear OS) или телевизора (Android TV): откройте Wear OS и ТВ в главном меню, выберите цель (Wear OS, Android TV или оба). Заполните имя проекта, затем нажмите Создать новый проект Wear/TV — IDE создаёт Java-проект, а затем настраивает его, — или выберите уже существующий проект, затем нажмите Применить к этому проекту. Настройки: uses-feature в манифесте, категория LEANBACK_LAUNCHER + баннер для ТВ и настроенная разметка activity_main.xml (Wear: маленький экран; ТВ: большой экран, удобный для D-pad). Полное объяснение записывается в wear-tv.txt в проекте. Это шаблон проекта — сборка + тестирование по-прежнему требуют устройства/эмулятора Wear OS или Android TV; ТВ-баннер (banner.png 320x180) не создаётся автоматически, его нужно добавить самостоятельно (например, через Создатель значков).

Карта проекта
Чтобы увидеть структуру проекта: откройте Карта проекта в главном меню, выберите проект, затем нажмите Показать карту — IDE показывает список папок и файлов с их размерами, общий размер, размер по типу файлов и важные файлы (главный файл, манифест, разметка, строки, значок, веб-страница). Нажмите Сохранить карта-проект.txt, чтобы записать ту же карту в корень проекта. Папка bin/ (результаты сборки) и папка .git/ (локальный репозиторий) не картируются, так как их содержимое можно создать заново.

Калькулятор размера APK
Чтобы оценить размер собранного APK перед сборкой: откройте Калькулятор размера APK в главном меню, выберите проект, затем нажмите Рассчитать оценку. IDE показывает разбивку по категориям (код/DEX, ресурсы, ассеты, нативные библиотеки, манифест + resources.arsc, накладные расходы), общую оценку, 5 самых больших файлов и предложения по уменьшению (например, большие изображения уменьшаются в разрешении, большие звуки сокращаются по длительности). Это ОЦЕНКА, а не точный размер — реальный размер может отличаться из-за сжатия aapt2, удаления неиспользуемого кода (R8) и собранных ресурсов.

Анализатор APK
Чтобы прочитать содержимое готового APK (как Анализатор APK в Android Studio): откройте Анализатор APK в главном меню, выберите проект, затем нажмите Анализ APK результата сборки. IDE читает самый новый APK в папке bin этого проекта и сообщает имя пакета, версию, минимальный и целевой SDK, список используемых разрешений, количество dex-файлов, разбивку размера по частям (код программы, ресурсы, ассеты, нативные библиотеки, подпись) и 10 самых больших записей. Полезно, чтобы узнать, какая часть делает APK большим и какие разрешения использует собранное приложение.

Предпросмотр размера экрана
Чтобы проверить внешний вид проекта на многих размерах экрана сразу (как в Android Studio): откройте Предпросмотр размера экрана в главном меню, выберите проект, затем нажмите Проверить размер экрана. IDE читает все разметки проекта и сообщает об элементах, ширина которых написана фиксированной (например, 400dp) и превышает ширину экрана 320, 360, 411 или 480 dp, потому что на телефоне с маленьким экраном такой элемент может быть закрыт или выйти за пределы. Элементы с шириной match_parent или wrap_content автоматически подстраиваются под экран и не нуждаются в проверке.

Менеджер ресурсов
Чтобы увидеть и управлять всеми ресурсами проекта в одном месте (как Менеджер ресурсов в Android Studio): откройте Менеджер ресурсов в главном меню, выберите проект, затем нажмите Посмотреть ресурсы. IDE сообщает количество и размер файлов по категориям (drawable, layout, values, mipmap и другие), содержимое strings.xml, colors.xml и styles.xml. С того же экрана новую строку можно добавить в strings.xml, а новый цвет — в colors.xml, заполнив их имя и значение — имя проверяется, а дубликаты отклоняются, поэтому XML-файл не повреждается.

Лёгкий монитор производительности
Чтобы отслеживать использование RAM и процессора работающего приложения (как Профайлер в Android Studio, лёгкая версия): откройте Лёгкий монитор производительности в главном меню, сначала запустите проверяемое приложение (например, собранное приложение, которое тестируется), заполните имя его пакета — или выберите проект, затем нажмите Заполнить имя пакета из проекта, — затем нажмите Начать отслеживание. Каждые 2 секунды IDE записывает RAM (PSS) и CPU этого приложения вместе со свободной RAM телефона; нажмите Стоп, чтобы увидеть сводку среднего и пикового значений. Без дополнительных разрешений. В новых версиях Android доступ на чтение процессора другого приложения ограничен системой, поэтому если CPU не читается, отчёт говорит об этом как есть, а RAM продолжает отслеживаться.

Аудит доступности
Чтобы перед выпуском проверить, удобен ли макет проекта для программ чтения с экрана (TalkBack/Jieshuo): откройте «Аудит доступности» в главном меню, выберите проект, затем нажмите «Загрузить список макетов» и выберите файл макета. IDE читает этот XML-файл и сообщает о кнопках без подписей с номерами их строк, о подписях, используемых повторно, и об элементах, которые перекрывают друг друга, а затем строит расшифровку порядка фокуса, как её читает вслух Jieshuo. Если у кнопки нет подписи, заполните её, а затем нажмите «Вставить подписи автоматически» — подпись будет записана в файл макета как contentDescription. Эта проверка читает только XML макетов; представления Compose и готовые APK пока не сканируются.

Вскрытие сбоя
Чтобы узнать, почему приложение само закрывается, из журнала сбоя с уникальным ID: откройте «Вскрытие сбоя» в главном меню, выберите ID сбоя из списка журналов и нажмите «Проверить». IDE сопоставляет класс и номер строки в журнале с исходником проекта и объясняет причину на индонезийском (например, пустая ссылка, ещё не запрошенное разрешение или ошибка JSON) с предложенным исправлением кода. Нажимайте «Применить исправление» только если строка исходника всё ещё точно такая же, как в момент сбоя; если она изменилась, исправление отклоняется, и IDE просит вас проверить самостоятельно. Для сбоев СОБРАННОГО приложения нажмите «Внедрить перехватчик сбоев в проект», затем соберите APK как обычно: это собранное приложение перехватывает собственные сбои и записывает свой журнал на телефон, а этот журнал можно найти кнопкой «Найти журнал сбоев собранного приложения». Честное ограничение: копирование журнала в публичную папку Download на Android 11 и выше может не удаться без разрешения на доступ ко всем файлам.

Транспилятор между парадигмами
Чтобы преобразовать простой код Java в Kotlin или простой XML-макет в код Compose: откройте «Транспилятор между парадигмами» в главном меню, выберите проект и файл, а затем нажмите «Предпросмотр». IDE показывает результат преобразования в виде текста — сначала проверьте его, потому что незнакомые строки остаются как есть, а слово static из Java в Kotlin опускается (проверьте его смысл перед использованием). Преобразование XML в Compose меняет только текст, подсказки и ориентацию — размер, цвет и другие атрибуты пока не учитываются. Если результат правильный, нажмите «Применить к файлу», чтобы записать целевой файл; исходный файл не изменяется. Преобразуются только безопасные распространённые шаблоны.

Локальный микросервер
Чтобы тестировать приложение, которому нужен сервер, без интернета: откройте «Локальный микросервер» в главном меню, запишите определения маршрутов (например, GET /halo, затем его JSON-ответ) и нажмите «Запустить сервер». IDE запускает небольшой HTTP-сервер на том же телефоне (только HTTP, без TLS, для той же сети Wi-Fi) и записывает каждый запрос и ответ на экране. Маршруты могут использовать параметры вроде {nama} и простой ключ API. Сервер также можно встроить в собранный APK: нажмите «Встроить сервер в проект», и исходник сервера, ресурсы и манифест внедряются в проект, так что само собранное приложение становится сервером при запуске. Сервер в IDE останавливается, когда его экран закрывается.

Аудитор безопасности
Чтобы проверить код проекта на пробелы безопасности перед выпуском: откройте «Аудитор безопасности» в главном меню, выберите проект и нажмите «Начать сканирование». IDE сканирует код проекта, манифест и конфигурацию и сообщает о находках от высокого риска к низкому — ключ API, оставленный открытым в коде, компонент, открытый без разрешения, WebView, включающий JavaScript с его JavaScript-интерфейсом, слабая криптография (MD5, SHA1, DES), http-адрес без TLS и пароль, написанный прямо в коде — с их файлами и номерами строк. Для находок, исправление которых безопасно (например, заменить MD5 на SHA-256 или http на https), нажмите «Применить исправление»; для ключей API и паролей IDE только показывает предложение исправления, потому что замену должен решить сам разработчик. Сканирование теперь также разбирает настоящий DEX-байткод внутри собранного APK (а не только текстовые шаблоны в коде), поэтому опасные вызываемые API и секреты, встроенные в DEX, тоже обнаруживаются; пробелы, не следующие шаблону, всё ещё могут ускользнуть от сканирования — проверьте перед применением.

Робот-тестировщик интерфейса
Чтобы автоматически тестировать экран приложения с помощью текстовых сценариев: откройте «Робот-тестировщик интерфейса» в главном меню, выберите проект и нажмите «Создать сценарий автоматически». IDE читает манифест и разметку проекта и записывает сценарий как текстовые шаги (нажать кнопку, заполнить поле, подождать, вернуться). Нажмите «Запустить пробный запуск», чтобы увидеть журнал выполнения сценария с отметками времени — этот пробный запуск по-прежнему только моделирование последовательности. Для настоящего тестирования нажмите «Внедрить тестового агента в проект»: IDE внедряет тестового агента с ресурсами сценария в проект; соберите APK как обычно, установите его, затем откройте значок «Тест» — этот агент работает внутри собранного приложения и действительно нажимает кнопки, заполняет настоящие поля и прокручивает, а затем показывает свой отчёт на экране с реальными пойманными сбоями. Нажмите «Удалить тестового агента из проекта», чтобы снова удалить этого агента. Агент работает внутри самого процесса приложения, поэтому ему не нужны ни служба доступности, ни системная автоматизация.

Путешествие во времени кода
Чтобы вернуть проект к более раннему состоянию кода, не вводя команды Git: откройте «Путешествие во времени кода» в главном меню, выберите проект, заполните метку момента времени (можно оставить пустой), а затем нажмите «Записать момент времени». IDE сохраняет копию исходных файлов проекта вместе с их хешами в папке .riwayat внутри проекта. Список моментов времени показывает их все; выберите два момента, а затем нажмите «Сравнить», чтобы увидеть добавленные, изменённые или удалённые файлы и функции. Нажмите «Восстановить», чтобы вернуть старое состояние — перед восстановлением IDE всегда сначала делает резервную копию текущего состояния, поэтому ничего не теряется. Нажмите «Создать экспериментальную копию», чтобы скопировать проект в новую папку и пробовать изменения, не трогая исходный проект. Записываются только исходные файлы.

Фабрика модулей
Чтобы упаковать часть проекта как модуль, который сможет использовать другой проект: откройте «Фабрика модулей» в главном меню, выберите исходный проект, отметьте файлы экранов, классов, строк и разрешений для упаковки, а затем нажмите «Упаковать как модуль». IDE записывает ZIP-архив вместе с метаданными JSON (имя модуля, версия, использованные строки и разрешения). Чтобы установить модуль в другой проект, откройте «Фабрика модулей», выберите целевой проект, а затем нажмите «Установить модуль» и выберите .zip-файл модуля — слияние добавляет строки и разрешения, не перезаписывая существующий код, и не сливает файл, если его имя уже используется в целевом проекте. Модуль не несёт библиотек или настроек сборки.

Полиморфный щит и хранилище ресурсов
Чтобы перемешать имена идентификаторов и зашифровать ресурсы проекта перед выпуском: откройте «Полиморфный щит и хранилище ресурсов» в главном меню, выберите проект и нажмите «Перемешать имена и зашифровать ресурсы». IDE сканирует имена классов и методов в исходном коде, строит карту случайных имён, переписывает эти имена ВНУТРИ скомпилированных файлов DEX (имена-замены делаются той же длины, что и исходные, чтобы все смещения оставались верными, затем пересчитываются контрольная сумма и подпись SHA-1 заголовка DEX), шифрует файлы ресурсов проекта с помощью AES-GCM в папку brankas-aset внутри проекта и сохраняет зашифрованную карту восстановления (perisai-peta.brankas), чтобы исходные имена можно было восстановить при чтении журналов сбоев. Ключ шифрования теперь выводится из пароля разработчика с помощью PBKDF2, 20 000 итераций, а не из имени проекта. Имена, которые также используются как обычный текст, имена аннотаций и отладочные имена, намеренно не переписываются, а точки вставки переписи DEX в пути сборки ещё ждут проверки на реальном телефоне.

Цепочка доверия и страж среды
Чтобы проверить цепочку ключей подписи и среду телефона перед выпуском: откройте «Цепочка доверия и страж среды» в главном меню, выберите проект и нажмите «Проверить цепочку и среду». IDE строит цепочку ключей из 5 поколений из имени пакета проекта и проверяет её целостность, проверяет настоящую целостность памяти, сравнивая содержимое сегментов кода в памяти с файлами на диске, и сообщает об анонимных исполняемых (RWX) отображениях, чужих библиотеках и отображениях memfd, а затем сканирует карту памяти собственного процесса и свойства устройства в поисках следов Frida, Xposed или эмулятора. Ключ хранилища оборачивается ключом AES в AndroidKeyStore, который использует аппаратный чип безопасности, когда он доступен, а ротация ключей теперь настоящая, с использованием lineage сертификатов подписи схемы v3: старый ключ подписывает доказательство ротации к новому ключу, и APK переподписывается с этим lineage. Результат — уровень риска «Безопасно», «Осторожно» или «Опасно» с текстовыми доказательствами. Если система отказывает в чтении памяти, проверка сообщается как «невозможно проверить», а не как безопасная; а использует ли ключ на самом деле аппаратный чип безопасности, можно подтвердить только на реальном устройстве.

Архитектор разметки на основе текстового дерева
Чтобы спроектировать экран, не видя его: откройте «Архитектор разметки на основе текстового дерева» в главном меню, выберите проект и файл разметки, затем нажмите «Проверить разметку». IDE читает XML-разметку как текстовое дерево и вслух описывает положение каждого элемента (например, внизу справа, 45 процентов ширины экрана), а затем математически сообщает о наложениях элементов и об элементах, выходящих за экран при ширине 360 dp. То, что теперь вычисляется, включает LinearLayout и простые размеры dp, полный ConstraintLayout (все ограничения, смещение, цепочки, направляющие, барьеры, процентные ширины, 0dp match_constraint и соотношения сторон), а также экраны Compose (Column, Row и Box с их модификаторами размера). Только MotionLayout и ConstraintSet, изменяемые во время выполнения, по-прежнему сообщаются как «положение неизвестно», потому что их значения существуют только пока приложение работает.

Студия системы дизайна
Чтобы сделать отступы, шрифты и углы одинаковыми на всех экранах и проектах: откройте «Студия системы дизайна» в главном меню, выберите проект, запишите токены дизайна (например, jarak=8, huruf=16, sudut=12), выберите компонент и нажмите «Создать компоненты». IDE проверяет токены — базовый отступ от 4 до 16 dp, базовый шрифт от 12 до 20 sp, углы от 0 до 32 dp и минимальная область касания 48 dp — а затем записывает готовые XML-компоненты (komponen-studio.xml) с XML-темой (tema-studio.xml) и темой Compose (tema-studio.kt) в папку проекта. Токены также можно сохранить как именованный набор в общей межпроектной библиотеке токенов, а одна команда синхронизации применяет новейшие токены библиотеки ко всем проектам, использующим этот набор. Компоненты создаются как текст, который вставляется в разметку, а затем проверяется «Архитектором разметки на основе текстового дерева»; двухколоночная настройка на планшете использует квалификатор ширины экрана, а не определение устройства во время выполнения.

Семантический рефакторинг и навигация по AST
Чтобы находить определения и переименовывать символы, не ломая другой код, который случайно носит то же имя: откройте «Семантический рефакторинг и навигация по AST» в главном меню, выберите проект и нажмите «Сканировать символы проекта», чтобы увидеть все классы и методы с их файлами и номерами строк. Введите имя символа и снова нажмите «Сканировать символы проекта», чтобы увидеть его определение и все файлы, которые его вызывают. Чтобы переименовать, введите новое имя, нажмите «Предпросмотр переименования», чтобы увидеть число вхождений в каждом файле, а затем «Применить переименование». Индексатор теперь использует самописный парсер AST (лексер и рекурсивный парсер для Java и подмножества Kotlin), поэтому межфайловые переименования методов разрешаются, а вызывающие стороны в других файлах тоже изменяются; кнопка извлечения блока кода в новую функцию теперь есть на этом экране. Этот парсер пока минимальный: очень сложные generics, параметризованные аннотации и анонимные классы сканируются как есть, а вызовы через рефлексию и через интерфейсы не разрешаются.

Пошаговый отладчик и инспектор памяти
Чтобы проверять содержимое переменных в середине потока программы, не гадая по журналам: откройте «Пошаговый отладчик и инспектор памяти» в главном меню, выберите проект, запишите трассировку выполнения (один шаг на строку, в виде: номер строки, код, затем переменные и значения, разделённые |, например 10|int total = harga * jumlah;|harga=5000, jumlah=3, total=15000), введите номер строки точки останова и нажмите «Запустить трассировку отладки». IDE дойдёт до первой точки останова и прочитает вслух активную строку с её значениями переменных через Jieshuo. Нажмите «Шаг на одну строку», чтобы продвинуться на одну строку, «Войти в функцию», чтобы войти в вызванную функцию (со стеком вызовов), или «Продолжить программу», чтобы дойти до следующей точки останова. Этот трассировочный отладчик по-прежнему следует записанной или написанной вручную трассировке; рядом с ним есть чистый Java-клиент проводного протокола JDWP, который может выполнить рукопожатие, установить точки останова, шагать внутрь, поверх и наружу, а также приостанавливать и возобновлять VM по TCP или в режиме прослушивания. Приостановить настоящий процесс из обычного приложения по-прежнему невозможно полностью, потому что сокет JDWP процесса доступен только через adbd — проверенный путь требует беспроводной отладки и запуска цели через оболочку, что выходит за возможности самого приложения.

Менеджер зависимостей офлайн
Чтобы использовать сторонние библиотеки без интернета и избежать конфликтов версий перед сборкой: откройте «Менеджер зависимостей офлайн» в главном меню, выберите проект и нажмите «Проверить зависимости». IDE читает все файлы .gradle проекта, проверяет общее межпроектное хранилище в папке Download/brankas-bersama и разрешает конфликты — если две библиотеки просят разные версии одного артефакта, используется самая высокая версия, а о конфликте сообщается. Чтобы скачать библиотеку, введите её координаты (в виде группа:артефакт:версия, например com.google.code.gson:gson:2.10.1) и нажмите «Проверить зависимости»: при подключении файлы AAR, JAR или WHL действительно скачиваются из Maven, Google или PyPI вместе с их графом транзитивных зависимостей (рекурсивно, циклы разрываются, глубина до 25 уровней), и только успешно скачанные файлы записываются как доступные. В офлайне можно использовать только библиотеки, уже имеющиеся в общем хранилище. Диапазоны версий Maven не разрешаются, а скачанные файлы проверяются только по их SHA-1, без проверки PGP.

Инспектор базы данных и хранилища
Чтобы проверять и тестировать содержимое базы данных проекта, не написав код, печатающий содержимое таблиц: откройте «Инспектор базы данных и хранилища» в главном меню, выберите проект и файл базы данных (.db, .sqlite или .sqlite3), затем нажмите «Открыть базу данных». IDE читает схему всех её таблиц с помощью полного парсера страниц SQLite (B-дерево с overflow-страницами) и показывает первые 20 строк в виде текстовой таблицы, которую Jieshuo читает вслух. Напишите SELECT-запрос и нажмите «Выполнить запрос» (например, SELECT nama FROM pengguna WHERE kota = 'Makassar') — запросы теперь поддерживают JOIN, GROUP BY, ORDER BY и LIKE, а на телефоне выполняются через настоящий движок SQLite Android. Чтобы изменить значение, введите номер строки (1 = первая строка), имя столбца и новое значение, затем нажмите «Изменить значение ячейки» — это значение записывается обратно в файл .db. Нажмите «Сохранить резервную копию», чтобы сохранить текущее состояние таблицы как файл <имя-бд>.cadangan.txt в проекте. SharedPreferences и DataStore тоже можно читать. Что по-прежнему нельзя прочитать: зашифрованные базы данных, неподтверждённые изменения WAL и типизированные значения в специальном DataStore Proto (показываются только как общий вид полей).

Фабрика модульных тестов и фаззинг
Чтобы находить логические пробелы до того, как приложение будет опубликовано: откройте «Фабрика модульных тестов и фаззинг» в главном меню, выберите проект и файл кода, затем нажмите «Создать и запустить тесты». IDE читает сигнатуры функций в файле, создаёт обычные и граничные тестовые случаи (пустой текст, null, максимальные числа, странные символы), а затем действительно запускает эти тесты: код проекта компилируется, и каждый метод @Test выполняется с лимитом 5 секунд, так что результат — настоящие прохождения и падения с их реальными значениями. Фаззинг тоже действительно выполняется над функциями проекта (через рефлексию, 2 секунды на вызов, не более 20 методов), а процент покрытия строк действительно вычисляется с помощью инструментирования, сохраняющего исходные номера строк. Результат сообщает, сколько тестов прошло и упало, сколько строк кода и функций найдено, и какие тестовые случаи созданы. Сгенерированные тесты используют ровно тот же API, что и JUnit, но определения аннотаций и утверждений записаны внутри самого сгенерированного тестового файла, потому что настоящая библиотека JUnit не включена в приложение.

Симулятор экстремальных условий устройства и аудитор утечек памяти
Чтобы проверить стойкость приложения, когда система завершает его процесс, сеть падает, экран поворачивается или включается экономия заряда: откройте «Симулятор экстремальных условий устройства и аудитор утечек памяти» в главном меню, выберите проект и нажмите «Запустить моделирование». IDE выполняет три сценария нагрузки с моделированием поворота экрана и отслеживает объекты, удерживаемые в памяти после закрытия их экрана, а затем сообщает о потерянных данных и протекающих цепочках объектов. Состояние сохранения и восстановления теперь читается из исходников собственного проекта пользователя, а не из фиксированного примера; локальный loopback-сервер действительно останавливается в середине теста, чтобы измерить обрыв сети; берётся и разбирается настоящий heap dump, чтобы сравнить два дампа и проследить цепочку удержания от корней GC; а собственный процесс приложения действительно завершается после сохранения его состояния, затем проверяется, какие данные возвращаются при повторном открытии. Что по-прежнему невозможно из обычного приложения: выключать радио или Wi-Fi телефона и принудительно останавливать другие приложения — для обоих нужно системное разрешение; вместо этого фоновые приложения завершаются через killBackgroundProcesses, разрешение которого уже есть в манифесте, с честной пометкой на экране.

Архитектор чертежей проекта
Чтобы превратить большую идею приложения в пошаговый план работы: откройте «Архитектор чертежей проекта» в главном меню, выберите проект, запишите идею приложения (например, кассовое приложение для небольшого продуктового магазина с рассрочкой), затем нажмите «Создать чертёж». IDE строит модули, список файлов и небольшие этапы, а затем сохраняет их как cetak-biru.txt в папке проекта. Нажимайте «Отметить следующий этап выполненным» каждый раз, когда этап завершён, или «Загрузить сохранённый чертёж», чтобы снова открыть сохранённый чертёж. Если в «Настройки ИИ» выбран активный ИИ-провайдер и его ключ доступен, чертёж строит этот провайдер; если ключа нет или провайдер недоступен, IDE возвращается к офлайн-шаблонам ключевых слов и честно сообщает об этом ограничении. Ответ провайдера проверяется только на формат (модули и этапы присутствуют), а не на правдивость содержания — всегда проверяйте чертёж перед сборкой.

Рассказчик логического потока кода
Чтобы понимать длинный код, не слушая синтаксис строка за строкой: откройте «Рассказчик логического потока кода» в главном меню, выберите проект и файл кода, затем нажмите «Описание кода». IDE превращает каждую строку в индонезийское предложение (например, если итог больше 100000, то выполнить следующий блок), показывает карту вызовов между методами и анализ потока данных между методами (передаваемые, используемые или игнорируемые значения), а также отмечает тонкие возможные ошибки с их номерами строк — String, сравниваемый с ==, поток, открытый без закрытия, и переменная, записанная в двух разных методах. Если в «Настройки ИИ» выбран активный ИИ-провайдер, доступна также сводка потока от этого провайдера; если недоступно, экран использует офлайн-описание и сообщает об этом ограничении. Описание, карта вызовов и поток данных используют офлайн-анализ текстовых шаблонов, а не полный парсер AST — методы, чья открывающая скобка стоит на отдельной строке, поля класса и вызовы через рефлексию не отслеживаются — а предупреждения о гонках данных могут появляться для переменной, которая на самом деле используется только по очереди.

Фабрика пакетов приложений и готовность к Play Store
Чтобы подготовить приложение к Google Play Store прямо с телефона: откройте «Фабрика пакетов приложений и готовность к Play Store» в главном меню, выберите проект и нажмите «Собрать пакет AAB». IDE собирает файл .aab из манифеста, ресурсов и ассетов проекта вместе с настоящим BundleConfig.pb, проверяет структуру пакета, а затем разделяет пакет на настоящие вариантные APK (базовый, по архитектуре, по языку и универсальный) с размерами, измеренными по итогам этого разделения, а не оценёнными. Пакет подписывается JAR v1 тем же ключом проекта, что и подпись APK, а его цепочка подписи проверяется криптографически. Этот экран также проверяет готовность к Play — целевой SDK ниже 35 помечается как «Высокий», потому что Play Store требует 35 или выше, а отсутствующая 64-битная библиотека тоже помечается как «Высокий». Настоящий bundletool не может работать на устройстве, потому что bundletool требует JVM, а у Android нет JVM; описанный выше путь — ближайший реальный на устройстве.

Движок обновлений OTA и поэтапные выпуски
Чтобы отправить небольшое исправление, не заставляя пользователей заново скачивать весь APK: откройте «Движок обновлений OTA и поэтапные выпуски» в главном меню, выберите проект, запишите содержимое старой и новой версий, затем нажмите «Создать пакет исправления». IDE вычисляет разницу и создаёт пакет исправления (patch-ota.zip) с отпечатком SHA-256 нового содержимого, а затем проверяет, входит ли это устройство в первый этап выпуска на 10 процентов. Исправления теперь поддерживают бинарные дельты для любого файла (включая DEX и APK), упаковываются с подписью RSA-2048 и проверяются доверенным открытым ключом перед применением, а также могут скачиваться с сервера разработчика вместе с его списком выпусков; если применение не удалось, старый файл остаётся нетронутым. Применение исправления к работающему приложению выполняется через переподпись ключом проекта и PackageInstaller, потому что заменить код работающего процесса изнутри самого себя невозможно — APK заблокирован, а DEX уже загружен.

Студия командной проверки кода
Чтобы проверять изменения коллеги и разрешать конфликты слияния, не читая стрелки Git: откройте «Студия командной проверки кода» в главном меню, выберите проект, введите три текстовые версии (базовую, локальную, коллеги) и нажмите «Открыть проверку команды». IDE объединяет все три на основе синтаксических единиц Java — два изменения в одной строке, но в разных операторах, больше не считаются конфликтом — и показывает каждый конфликт как вариант голосования: «Использовать локальную версию», «Использовать версию коллеги» или «Объединить обе» — результирующая строка вставляется на исходную позицию конфликта, чтобы порядок остался правильным — а затем записывает результат в gabung-hasil.txt в проекте. Ниже находится доска задач проекта: введите заголовок задачи и нажмите «Добавить задачу»; задачи сохраняются как текст в папке .tugas внутри проекта и синхронизируются через коммиты во встроенном Git, так что доску можно прочитать из любой истории коммитов. Этот синтаксический разделитель — не полный парсер AST, а встроенный Git хранит полный снимок на коммит; специального сервера синхронизации нет.

Диктовка структуры кода
Чтобы писать код голосом внутри редактора: откройте проект в редакторе, а затем нажмите кнопку «Диктовка структуры кода». Произносите команды на индонезийском языке, например buat fungsi tambah dengan parameter a angka dan b angka, buat kelas Mobil или buat variabel teks nama sama dengan Budi — IDE превращает речь в синтаксически правильный блок кода Java, Kotlin, Python или Compose и вставляет его в позицию курсора, а затем зачитывает краткое резюме через Jieshuo. Диктовка использует встроенную системную службу голосового ввода, без дополнительного разрешения на микрофон, и распознаёт только уже зарегистрированные шаблоны команд; речь вне этих шаблонов в код не превращается. Числа, произнесённые словами (например, 'lima'), пока не превращаются в цифры.

Локальное пространство совместной работы (без интернета)
Чтобы работать вместе в одной комнате без интернета: откройте «Совместная работа» в главном меню, а затем откройте раздел «Локальное пространство совместной работы». Один телефон открывает сеанс (IDE показывает локальный IP-адрес и 6-значный PIN), другой телефон присоединяется по этому адресу и PIN. Изменения текста отправляются как построчные различия, собранный APK можно отправить на телефон тестировщика, а отчёты о сбоях с телефона тестировщика приходят обратно. Один сеанс — только для одного друга; если два человека изменят ровно одну и ту же строку одновременно, используется последнее изменение. PIN отправляется открытым текстом по локальной сети. Эта комната ещё не тестировалась на реальном телефоне.

Настройки ИИ
Чтобы настроить ИИ-провайдера и ключи API для создания приложений: в главном меню в группе «Настройки» нажмите «Настройки ИИ» (рядом с кнопкой «Коннектор»). Выберите провайдера из доступного списка и включите «Переключать модель при ошибке провайдера», чтобы при сбое одной модели IDE автоматически пробовала следующую модель того же провайдера. Нажмите «Управление ключами API», чтобы добавить резервные ключи (введите имя и ключ, затем нажмите «Сохранить»; ключи показываются замаскированными, видны только последние 4 символа). Ключи хранятся на телефоне и никогда никуда не отправляются, кроме выбранного провайдера при создании приложения. Выбранный провайдер теперь действительно используется «Архитектором чертежей проекта» и «Рассказчиком логического потока кода»; создание приложений на экране «Создатель приложений с ИИ» по-прежнему использует локальный ИИ на телефоне (без интернета).

Коннектор
Чтобы проанализировать APK, а затем отправить его: в главном меню, в группе «Настройки», нажмите «Коннектор» (рядом с кнопкой «Настройки ИИ»). Выберите файл APK из телефона, IDE прочитает его содержимое (имя пакета, версия, список активностей), а затем нажмите «Отправить APK», чтобы отправить его через системное меню обмена (например, WhatsApp или Drive).

Язык и голос
Чтобы изменить язык приложения: откройте «Настройки», затем «Язык приложения», а затем выберите язык или «Как в системе». Главный экран и большинство экранов сразу переключатся на выбранный язык без закрытия или перезапуска приложения; некоторые экраны (например, «Терминал», «Совместная работа», «Настройки ИИ» и «Управление ключами») будут использовать старый язык до повторного открытия. Если выбрать «Как в системе», язык будет следовать языку системы телефона.

Встроенная подпись для каждого проекта и Anti Tamper
Начиная с версии 5.7, проект, не использующий личную подпись, подписывается СОБСТВЕННЫМ встроенным ключом этого проекта (созданным один раз в папке tanda-tangan-bawaan внутри проекта, затем используемым далее), поэтому встроенная подпись отличается от проекта к проекту — больше не один общий ключ для всех приложений. Не удаляйте папку tanda-tangan-bawaan: без этого ключа новый APK не сможет перезаписать старый APK того же проекта. Настройки каждого проекта (отдельная архитектура, личная подпись, защита от подделки, выбранный keystore, SDK) теперь хранятся в файле settings.gradle внутри проекта и читаются снова при каждой сборке проекта. В Настройках, в категории Подпись, есть флажок Защита от подделки собранного приложения: если он активен, собранное приложение на устройстве проверяет свою подпись и содержимое dex при каждом открытии; если оно было переподписано или изменено кем-то другим, приложение отказывается работать. Инструменты отладки и внедрения, такие как Frida/Xposed, также обнаруживаются, а окно приложения блокируется от записи экрана.

Создатель демо-видео
Чтобы сделать демо-видео собранного приложения: откройте Создатель демо-видео в главном меню, выберите проект, заполните название видео, затем нажмите Создать скрипт демо-видео — IDE записывает video-demo.txt с 5 стандартными сценами (открытие, главный вид, функция 1, функция 2, закрытие) вместе с текстом narration и длительностью каждой сцены. Нажмите Создать HTML-слайдшоу, чтобы сделать video-demo.html из изображений проекта (значок + скриншоты, если есть), которые меняются автоматически каждые 5 секунд. Это НЕ видео .mp4 — для настоящего видео откройте video-demo.html в браузере телефона, а затем запишите экран, или прочитайте narration в video-demo.txt, записывая работающее приложение.

Новый вид в стиле Android Studio
Внешний вид IDE теперь приведён в порядок, чтобы напоминать Android Studio (только внешний вид — все кнопки, меню и потоки остаются точно как прежде): светло-серый фон, жирные чёрные заголовки экранов, синие кнопки с белым текстом и белые поля ввода с тонкой рамкой. Главное меню визуально сгруппировано (Функции создания, Облако, тема и прочее, Голос, код и новые функции, Инструменты) без изменения порядка кнопок. Терминал по-прежнему использует тёмную панель, как окно Терминала в Android Studio, а редактор кода по-прежнему имеет белый фон с чёрным текстом. Весь текст по-прежнему чётко читается программой Jieshuo.

Настройки
Чтобы настроить приложение: откройте меню Опции на главном экране, затем нажмите Настройки. Внутри есть 12 категорий: Настройки GitHub (безопасность, личная подпись, история сборки и токен GitHub), Настройки сборки APK на устройстве (сохранение пароля keystore и истории сборки на устройстве), Тема (цвета приложения), Подпись (создание keystore для личной подписи и флажок защиты от подделки собранного приложения), Папка проектов (расположение папки проектов), Язык и голос (язык интерфейса и скорость голоса Голосового режима), Размер текста и внешний вид (размер шрифта редактора), Сборка (целевой SDK по умолчанию и разделение архитектуры по умолчанию для экрана Создать проект), Уведомления (звук при завершении сборки), Автоматическое резервное копирование (расписание резервного копирования проектов), Профиль разработчика (имя, номер WhatsApp и счёт, показываемые на экране Пожертвования) и Конфиденциальность и данные (сброс настроек и удаление данных приложения). У каждой категории есть кнопка Назад, чтобы вернуться в меню категорий. Настройки, которые только что были сохранены (ещё не применены), имеют своё объяснение, честно написанное на экране.

Пожертвовать разработчику
Чтобы пожертвовать или поздороваться с разработчиком: нажмите кнопку Пожертвовать разработчику на главном экране, рядом с кнопкой О программе. На экране пожертвования есть кнопка Копировать счёт BRI — нажмите её, чтобы скопировать номер счёта разработчика, затем вставьте его в банковское приложение. Есть также раздел Поздороваться с разработчиком в WhatsApp: заполните своё имя и родной город, затем нажмите Отправить в WhatsApp — WhatsApp открывается с уже заполненным приветственным сообщением, просто нажмите Отправить в WhatsApp, а затем вернитесь в приложение. WhatsApp не позволяет другим приложениям отправлять сообщения автоматически, поэтому отправка всё равно выполняется вами самостоятельно в WhatsApp.

Избранные команды терминала
Чтобы сохранить команды, часто используемые в Терминале: откройте Терминал, затем нажмите Избранное. Коснитесь Добавить новое избранное, заполните имя (например, Посмотреть файл) и его команду (например, ls -la), затем нажмите Сохранить — избранное сохраняется на телефоне навсегда. Коснитесь имени избранного, чтобы выполнить его напрямую в терминале; коснитесь Удалить избранное, затем выберите одно, чтобы удалить его (с подтверждением). Уже есть 3 встроенных избранных: Посмотреть файл (ls -la), Проверить место (df -h) и Очистить экран (clear) — все они могут быть удалены. Пустая команда не может быть сохранена или выполнена; Терминал сообщает вам об этом сообщением и голосом, если это происходит.

Аналитика и качество
Чтобы увидеть сводку использования приложения и отчёты о сбоях: нажмите кнопку Аналитика и качество на главном экране, рядом с кнопкой Пожертвовать разработчику. Этот экран показывает, сколько раз приложение было открыто, какие экраны открываются чаще всего, количество сбоев и список последних сбоев с кратким предложением по исправлению. Эти данные хранятся только на вашем телефоне и никуда не отправляются. Есть кнопка Удалить данные аналитики с диалогом подтверждения для удаления всех этих данных. Последний экран записывается только для главного экрана и этого экрана.
