Välkommen till Create Aplikasi by Al Kautsar
Create Aplikasi är en app för att skapa Android-appar som körs direkt på telefonen, utan att behöva en bärbar dator. Appen låter vem som helst skapa sin egen Android-app, inklusive användare som precis har börjat lära sig att skapa appar och användare av skärmläsare. Den fullständiga guiden för att använda den här appen finns på den här Tentang Alat-skärmen.

Vad den här appen är och vem den är till för
Create Aplikasi är ett verktyg för att skapa Android-appar som körs på telefonen. Appen riktar sig till alla som vill skapa sin egen Android-app, inklusive nybörjare och användare av skärmläsare. Appen tillhandahåller en kodredigerare, en Jalankan-knapp för att testa projekt, en Bangun-knapp för att skapa en APK, samt menyer för att signera och installera APK:n.

Syftet med den här appen
Den här appen skapades så att vem som helst enkelt kan skapa sin egen Android-app, direkt från telefonen. Dess utseende gjordes så enkelt som möjligt så att även nya användare kan prova direkt.

Så skapar du ett nytt projekt, steg för steg
1. Tryck på Buat Project i huvudmenyn.
2. Välj projekttyp: HTML, Situs Web, Java, Kotlin, Compose eller Python.
3. Fyll i appens namn, exempel: Garuda Decode.
4. Fyll i paketnamnet (package name), exempel: com.android.garudadecode. Paketnamnet måste använda små bokstäver och bestå av minst två delar åtskilda av punkter.
5. Fyll i appens version, exempel: 1.0, och versionskoden i form av ett tal, exempel: 1. Om det lämnas tomt fylls versionen automatiskt i med 1.0 och versionskoden med 1.
6. Fyll i lägsta SDK och mål-SDK om det behövs. Om det lämnas tomt används standardvärdena. Lägsta SDK är den lägsta Android-version som stöds, exempel: 21 betyder Android 5.0. Högsta mål-SDK är 36 (Android 16).
7. Tryck på knappen Pilih Izin för att välja appens behörigheter, exempel: INTERNET. Behörigheten INTERNET är redan markerad som standard. Markera bara de behörigheter som appen verkligen behöver.
8. Om du vill, markera "Gunakan arsitektur terpisah 64 bit dan 32 bit" så att APK:ns storlek blir mindre, och markera "Gunakan tanda tangan pribadi" om du vill använda en egen skapad keystore.
9. Tryck på Buat Proyek. Det nya projektet sparas i mappen Download/project och syns direkt i Kelola Project.

Tillgängliga projekttyper
• HTML: utseende från index.html, style.css och script.js, körs via WebView. Byggs direkt på telefonen.
• Situs Web: webbplats med meny (Beranda, Tentang, Kontak) från index.html, tentang.html, kontak.html, style.css och script.js, körs via WebView. Byggs direkt på telefonen.
• Java: byggs på telefonen. MainActivity finns i app/src/main/java/<nama-paket>/MainActivity.java. Utseendet kommer från app/src/main/res/layout/activity_main.xml, texten från app/src/main/res/values/strings.xml och temat från app/src/main/res/values/styles.xml.
• Kotlin: kan byggas på enheten (offline) med den Kotlin-kompilator som ingår i appen, eller via GitHub Actions. MainActivity finns i app/src/main/java/<nama-paket>/MainActivity.kt, och res-filerna är desamma som i ett Java-projekt. Den första Kotlin-byggnationen är långsammare på grund av kompilatorns stora storlek, och .java-filer som refererar till Kotlin-klasser kan ännu inte byggas (.java-filer kompileras först, före .kt-filer).
• Compose: en modern Android-app vars gränssnitt skapas med Jetpack Compose (inte XML-layout). MainActivity finns i app/src/main/java/<nama-paket>/MainActivity.kt. Compose-projekt byggs via GitHub Actions (menyn Bangun proyek, sedan Bangun online) eller i Termux med Gradle, eftersom Compose kräver Jetpack Compose-bibliotek som inte finns tillgängliga på enheten.
• Python: appens logik skrivs på språket Python (Chaquopy) i app/src/main/python/main.py och körs av värden MainActivity.java i app/src/main/java/<nama-paket>/MainActivity.java. Python-projekt kan byggas direkt på telefonen (Chaquopy-runtime ingår i appen) eller via GitHub Actions. Lägsta SDK för Python-projekt är 24 (Android 7.0).

Filstruktur för projekt i Java, HTML, Situs Web, Kotlin, Compose och Python
Projekt i Java, HTML, Situs Web, Kotlin, Compose och Python är uppbyggda som Android-projekt i allmänhet. Inuti mappen app finns mappen src, och inuti den finns mappen main. Inuti mappen main finns AndroidManifest.xml bredvid mappen java, mappen res som innehåller layout/activity_main.xml och values/strings.xml samt values/styles.xml, och för HTML och Situs Web finns mappen assets som innehåller index.html (Situs Web har även tentang.html och kontak.html). HTML- och Situs Web-projekt har också en egen MainActivity i app/src/main/java/<nama-paket>/MainActivity.java, som laddar index.html i WebView och är startprogram i AndroidManifest. Python-projekt har Python-kod i app/src/main/python/main.py och värden MainActivity.java i app/src/main/java/<nama-paket>/MainActivity.java. AndroidManifest.xml, layout, strings och styles kan öppnas och ändras i redigeraren, precis som MainActivity. Gamla projekt vars manifest fortfarande ligger bredvid mappen app kan fortfarande byggas, eftersom appen vid byggnation först kontrollerar AndroidManifest.xml i app/src/main/, sedan den bredvid mappen app, och sist projektdatafilen.

Behörighetsregler (viktigt)
Behörigheter som markeras när ett projekt skapas registreras bara på ett ställe, beroende på projekttypen. För projekt i Java, HTML, Situs Web, Kotlin, Compose och Python registreras de markerade behörigheterna ENDAST i AndroidManifest.xml som finns i app/src/main/, bredvid mappen java, inuti projektmappen. Projektdatafilen för projekt i Java, HTML, Situs Web, Kotlin, Compose och Python innehåller ingen lista över behörigheter. Om du väljer Java och sedan markerar INTERNET och CAMERA registreras bara INTERNET och CAMERA i AndroidManifest.xml, utan att någon annan behörighet följer med. Vid byggnation läser appen behörigheterna från samma ställe: från AndroidManifest.xml i app/src/main/ för projekt i Java, HTML, Situs Web, Kotlin, Compose och Python (om det inte finns, från AndroidManifest.xml bredvid mappen app för gamla projekt), och från projektdatafilen för gamla projekt.

Så använder du redigeraren
Öppna Kelola Project, tryck på projektets namn för att öppna redigeraren. I redigeraren kan filer öppnas, kod skrivas och ändringar sparas. För projekt i Java, HTML, Situs Web, Kotlin, Compose och Python är filerna ordnade inuti mappen app/src/main. För att dela ett projekt, använd Ekspor ZIP (se avsnittet nedan).

Så kör du ett projekt
I redigeraren trycker du på Jalankan för att testa projektet. För HTML- och Situs Web-projekt är det index.html som körs via WebView. Om ett fel uppstår, läs felmeddelandet, rätta koden och kör igen.

Så bygger du en APK
I redigeraren trycker du på Bangun. Det finns två sätt att bygga. Det första, Bangun di perangkat: bygga direkt på telefonen utan internet, för projekt i HTML, Situs Web, Java, Kotlin och Python. Det andra, Bangun online via GitHub Actions: bygga via internet på GitHub, och kan användas för alla projekttyper. Compose-projekt kan bara byggas på det andra sättet (Bangun online) eller i Termux med Gradle, eftersom Compose kräver Jetpack Compose-bibliotek som inte finns tillgängliga på enheten. Resultatet av den första byggnationen är ännu inte signerat. Därefter signerar appen det: automatiskt med standardnyckeln, eller med en personlig signatur om rutan "Gunakan tanda tangan pribadi" markerades när projektet skapades.

Så installerar du en APK
När APK:n är klar trycker du på Pasang för att installera den. På Android 8 och högre kommer telefonen först att be om "Izinkan dari sumber ini", eftersom den här appen installerar APK:er från utanför Play Store. Aktivera den behörigheten en gång i Pengaturan och gå sedan tillbaka till appen: installationen fortsätter automatiskt utan att du behöver trycka på Pasang igen. Om Pasang-knappen inte visas, se till att byggnationen är klar och att APK:n har skapats.

Så signerar du en app
Varje APK måste signeras för att kunna installeras. Det finns två alternativ. Det första, standardnyckeln: appen signerar själv automatiskt, utan att du behöver göra någonting. Det andra, personlig signatur: skapa först en keystore via menyn Buat Keystore i huvudmenyn, förvara dess lösenord väl, och markera sedan "Gunakan tanda tangan pribadi" när du skapar projektet. Keystore sparas i Download/project/signing.

Exportera ett projekt som ZIP
Ekspor ZIP tillhandahålls så att projekt kan delas med vänner. Gör så här: i Kelola Project, tryck länge på projektets namn och välj sedan Ekspor ZIP. Resultatet sparas i Download/project/<NamaProyek>.zip. Mappen bin tas inte med, så storleken är liten, bara några tiotal KB. Den ZIP-filen kan skickas till en vän eller laddas upp till GitHub.

JAWS-tillägget
JAWS-tillägget använder tilläggsmotorn från Jieshuo (CSR), inte dess skärmläsare. På så sätt kan designen fortfarande köras även om användaren använder TalkBack. Gör så här: öppna Ekstensi JAWS i huvudmenyn. Eftersom det automatiska klicket körs av sig självt måste tjänsten först aktiveras i Pengaturan Aksesibilitas. Därefter kan en ny design skapas: skriv designens namn, tryck på OK och fyll sedan i dess rutor.

Daftar Klik är åtskild för ordningens skull
Inuti designen finns två rutor: skriptrutan och Daftar Klik-rutan. Listan över knappar sparas separat i filen daftar_klik.txt, ett namn per rad. Exempel på dess innehåll: tombolSimpan, tombolHapus, tombolBuka. För att öppna en app, skriv bara >WhatsApp i den listan. Gamla designer som ännu inte har någon daftar_klik.txt-fil kommer att visa det standardexemplet.

Enkla funktioner som tillhandahålls
• klikTombol("tombolSimpan") — klickar på en knapp utifrån dess text.
• klikDaftarTombol(daftar) — klickar på listan i daftar_klik.txt, en knapp per rad, i ordning, och berättar sedan hur många som lyckades och hur många som inte hittades.
• bukaAplikasi("WhatsApp") — öppnar en app utifrån dess namn, eller skriv ">WhatsApp" i listan.
• klik(540, 1200) — klickar på skärmkoordinater.
Alla funktioner gjordes enkla först. När du har vant dig kan ytterligare funktioner läggas till senare.

Om skärmläsare
Den här appen är utformad för att vara vänlig mot skärmläsare. Varje inmatningsfält har en etikett och ett ifyllningsexempel, och alla knappar kan nås utan komplicerade gester. JAWS-tillägget är gjort för att fortfarande köras även om användaren använder TalkBack, eftersom det som används är dess tilläggsmotor, inte dess skärmläsare.

Integritet och säkerhet
Projekt och keystore sparas på din telefon. GitHub-token används bara för onlinebyggnationer och sparas inuti den här appen. Dela inte din token eller ditt keystore-lösenord med någon. Om du använder en personlig signatur, förvara keystore och dess lösenord på ett säkert ställe, eftersom det gamla APK:t inte kan uppdateras med samma signatur om de går förlorade.

Krav
Android 5.0 eller nyare. Lagringsbehörighet: på Android 11 och högre används behörighet för åtkomst till alla filer, på Android 10 och lägre används vanlig lagringsbehörighet (läsa/skriva lagring) eftersom Android 10 inte har behörighet för åtkomst till alla filer. Att bygga på enheten kräver en telefon med ARM-processor (32 eller 64 bitar). Att bygga online via GitHub Actions kräver internet och en GitHub-token. Kotlin-projekt kan byggas på enheten, men dess första byggnation är långsammare och använder mer minne på grund av Kotlin-kompilatorns stora storlek. Compose-projekt byggs via GitHub Actions eller i Termux med Gradle. Python-projekt kräver Android 7.0 eller nyare (lägsta SDK 24) och den resulterande APK:n är större eftersom den innehåller Python-runtime (Chaquopy) tillsammans med dess standardbibliotek.

Terminal
Menyn Terminal på huvudskärmen öppnar en terminal inuti den här appen. Kommandon som ls kan användas för att se innehållet i projektmappen, cd för att byta mapp och git för att hantera kod. Kommandonas utdata visas som text som kan läsas av skärmläsaren, och det finns en Bacakan hasil-knapp för att lyssna på det senaste resultatet. Den här terminalen använder telefonens systemskal, så interaktiva program som nano och vim kan ännu inte användas här.

Licens (betalversion)
För att sälja appar, markera "Aktifkan Lisensi" när du skapar projektet och fyll sedan i ditt WhatsApp-nummer. Appen som blir resultatet av byggnationen kommer att be om en licenskod när den öppnas första gången: användaren ser sin enhets-ID, trycker på knappen Kirim ID Perangkat för att skicka det ID:t till din WhatsApp, och sedan svarar du med licenskoden. Licenskoden beräknas från enhetens ID och projektets lösenord (lisensi_seed i projektdatafilen) — förvara det lösenordet väl och dela det inte. När rätt kod har matats in öppnas appen och ber inte om koden igen.

Pembuat Ikon Otomatis
Nya projektikoner är fortfarande genomskinliga, så Pembuat Ikon finns tillgänglig i huvudmenyn. Gör så här: tryck på Pembuat Ikon, skriv en eller två bokstäver (till exempel initialerna i appens namn), välj bakgrundsfärg och textfärg, titta på dess förhandsvisning och tryck sedan på Simpan ke Proyek för att använda den ikonen i det valda projektet, eller Simpan ke Download för att använda dess PNG-fil någon annanstans. När ett projekt har skapats erbjuder appen också att skapa en ikon. Gamla projektikoner kan bytas när som helst från projektmenyn i Kelola Project (tryck länge på projektets namn och välj sedan Ganti Ikon).

Färdiga projektmallar
Om du inte vill börja från ett tomt projekt, välj en mall när du skapar projektet: Kalkulator (Java), Catatan (Java), Daftar Tugas (Kotlin), Kalkulator Web (HTML), Situs Profil (Situs Web) eller Penghitung (Compose). Att välja en mall ändrar automatiskt projekttypen så att den följer den mallen, och projektet skapas med färdig startkod — det återstår bara att köra eller ändra det. Om projekttypen ändras manuellt igen efter att en mall har valts avbryts mallen och projektet blir tomt igen. För mallar i HTML och Situs Web ersätter mallen innehållet i index.html, inklusive det HTML-skript som skrivs i formuläret.

Säkerhetskopiering och återställning av projekt
För att projekt inte ska gå förlorade finns en säkerhetskopieringsfunktion. Gör så här: i Kelola Project, tryck länge på projektets namn och välj sedan Cadangkan. Säkerhetskopian sparas som ZIP i mappen Download/backup med projektets namn och datum, exempel: GarudaDecode-2026-11-14-123045.zip. Dess innehåll är detsamma som Ekspor ZIP (hela projektets innehåll, utan mappen bin). För att återställa: öppna menyn i Kelola Project, välj Pulihkan cadangan och välj sedan dess säkerhetskopiefil. Om projektets namn redan finns kommer appen att fråga: Timpa proyek lama, eller spara med Nama baru.

Dela och importera projekt
För att dela ett projekt med en vän: i Kelola Project, tryck länge på projektets namn och välj sedan Bagikan. Projektet skickas som ZIP via delningsappar (WhatsApp, Telegram med flera). För att ta emot ett projekt från en vän: öppna menyn i Kelola Project, välj Impor proyek och välj sedan dess ZIP-fil. Den ZIP-filen måste innehålla en projektdatafil — om det inte finns avvisas filen med ett tydligt meddelande, eftersom den filen inte är ett Create Aplikasi-projekt. Om projektets namn redan finns kommer appen att fråga: Timpa proyek lama, eller spara med Nama baru.

Projektsökning och filter
Om projekten har blivit många finns det i Kelola Project en sökruta och ett typfilter. Skriv projektets namn i sökrutan så filtreras listan direkt (stora och små bokstäver skiljs inte åt). Typfiltret begränsar listan till bara en typ: Semua, HTML, Situs Web, Java, Kotlin, Compose eller Python. Varje projekts meny kan fortfarande öppnas som vanligt från den filtrerade listan.

Bygg appar med röst
Om du inte vill skriva, använd rösten: tryck på Bygg med röst i huvudmenyn och säg sedan ett kommando. Kommandon du kan säga: "Buat proyek kalkulator", "Bangun proyek Kalkulator", "Buka proyek Kalkulator", "Jalankan proyek Kalkulator", "Daftar proyek", "Buka ikon", "Kembali" och "Bantuan". Appen svarar med röst och text, så den kan fortfarande användas utan att titta på skärmen. Röstigenkänning använder telefonens inbyggda röstigenkänningsapp (gratis; den kan fungera offline om det indonesiska språkpaketet är installerat). Om telefonen saknar röstigenkänning kan kommandona skrivas i textrutan på samma skärm.

Tillgänglighetsgranskning
För att kontrollera om ett projekts layout är skärmläsarvänlig (TalkBack/Jieshuo) före publicering: öppna Tillgänglighetsgranskning i huvudmenyn, välj ett projekt och tryck sedan på Ladda layoutlista och välj en layoutfil. IDE:n läser den XML-filen och rapporterar knappar utan etikett med deras radnummer, etiketter som används upprepade gånger och element som överlappar varandra, och bygger sedan ett transkript av fokusordningen så som Jieshuo läser den högt. Om en knapp saknar etikett, fyll i dess etikett och tryck sedan på Infoga etikett automatiskt — etiketten skrivs in i layoutfilen som contentDescription. Denna kontroll läser bara layout-XML; Compose-vyer och färdiga APK:er skannas ännu inte.

Kraschobduktion
För att ta reda på varför en app stänger sig själv utifrån en kraschlogg med unikt ID: öppna Kraschobduktion i huvudmenyn, välj ett krasch-ID från logglistan och tryck sedan på Kontrollera. IDE:n matchar klassen och radnumret i loggen mot projektets källkod och förklarar orsaken på indonesiska (till exempel en tom referens, en behörighet som ännu inte begärts eller ett JSON-fel), tillsammans med ett föreslaget kodpatch. Tryck bara på Tillämpa patch om källraden fortfarande är exakt densamma som när kraschen inträffade; om den har ändrats avvisas patchen och IDE:n ber dig kontrollera själv. Det som läses är IDE:ns egen kraschlogg, inte loggen från en byggd app.

Transpilator mellan paradigm
För att omvandla enkel Java-kod till Kotlin, eller en enkel XML-layout till Compose-kod: öppna Transpilator mellan paradigm i huvudmenyn, välj ett projekt och en fil och tryck sedan på Förhandsgranska. IDE:n visar omvandlingsresultatet som text — kontrollera det först, för rader som den inte känner igen lämnas som de är och ordet static i Java tas bort i Kotlin (kontrollera dess betydelse innan du använder det). Omvandling från XML till Compose ändrar bara text, ledtrådar och orientering — storlek, färg och andra attribut ingår ännu inte. Om resultatet är rätt, tryck på Tillämpa på fil för att skriva målfilen; källfilen ändras inte. Endast säkra, vanliga mönster omvandlas.

Lokal mikroserver
För att testa en app som behöver en server utan internet: öppna Lokal mikroserver i huvudmenyn, skriv en ruttdefinition (till exempel GET /halo följt av dess JSON-svar) och tryck sedan på Starta server. IDE:n kör en liten HTTP-server på samma telefon (endast HTTP, utan TLS, för samma Wi-Fi-nätverk) och registrerar varje begäran och svar på skärmen. Rutter kan använda parametrar som {nama} och en enkel API-nyckel. Den här servern är bara till för testning på telefonen; en byggd APK kan ännu inte bli en server, och servern stannar när dess skärm stängs.

Säkerhetsgranskare
För att kontrollera säkerhetshål i projektkod före publicering: öppna Säkerhetsgranskare i huvudmenyn, välj ett projekt och tryck sedan på Starta skanning. IDE:n skannar koden, manifestet och projektkonfigurationen och rapporterar fynd från hög till låg risk — API-nycklar som blottläggs i koden, komponenter som blottläggs utan behörighet, en WebView som aktiverar JavaScript tillsammans med ett JavaScript-gränssnitt, svag krypto (MD5, SHA1, DES), http-adresser utan TLS och lösenord som skrivs direkt i koden — med fil och radnummer för varje fynd. För fynd med en säker åtgärd (till exempel byta MD5 mot SHA-256 eller http mot https) trycker du på Tillämpa åtgärd; för API-nycklar och lösenord visar IDE:n bara den föreslagna åtgärden eftersom ersättningen måste beslutas av utvecklaren själv. Den här skanningen läser textmönster i koden, inte bytecode, så vissa fynd kan i själva verket vara säkra, och ett hål utan mönster kan slinka igenom skanningen — kontrollera innan du tillämpar.

Gränssnittstestrobot
För att automatiskt testa en apps utseende med textscenarier: öppna Gränssnittstestrobot i huvudmenyn, välj ett projekt och tryck sedan på Skapa scenario automatiskt. IDE:n läser projektets manifest och layouter och skriver ett scenario av textsteg (tryck på en knapp, fyll i ett fält, vänta, gå tillbaka). Tryck på Kör torrkörning för att se scenariots körningslogg med dess tidsstämplar. I det här steget kör roboten bara en simulering (torrkörning) — riktiga knapptryckningar på telefonen och att fånga riktiga krascher är nästa steg, så kraschrapporten här är fortfarande ett exempelformat.

Tidsresa i kod
För att återställa ett projekt till ett tidigare kodtillstånd utan att skriva Git-kommandon: öppna Tidsresa i kod i huvudmenyn, välj ett projekt, fyll i en etikett för tidpunkten (den kan lämnas tom) och tryck sedan på Spela in tidpunkt. IDE:n sparar en kopia av projektets källfiler tillsammans med deras hashvärden i mappen .riwayat inne i projektet. Listan över tidpunkter visar dem alla; välj två punkter och tryck sedan på Jämför för att se filer och funktioner som lagts till, ändrats eller tagits bort. Tryck på Återställ för att hämta tillbaka ett gammalt tillstånd — innan återställning gör IDE:n alltid först en säkerhetskopia av det aktuella tillståndet, så ingenting går förlorat. Tryck på Skapa experimentkopia för att kopiera projektet till en ny mapp och pröva ändringar utan att störa det ursprungliga projektet. Endast källfiler spelas in.

Modulfabrik
För att paketera en del av ett projekt som en modul som ett annat projekt kan använda: öppna Modulfabrik i huvudmenyn, välj ett källprojekt, bocka för de skärm-, klass-, sträng- och behörighetsfiler som ska paketeras och tryck sedan på Paketera som modul. IDE:n skriver ett ZIP-arkiv tillsammans med JSON-metadata (modulnamn, version, använda strängar och behörigheter). För att installera en modul i ett annat projekt, öppna Modulfabrik, välj målprojektet och tryck sedan på Installera modul och välj modulens .zip-fil — sammanslagningen lägger till strängar och behörigheter utan att skriva över befintlig kod, och slår inte samman en fil om dess namn redan används i målprojektet. En modul bär varken med sig bibliotek eller bygginställningar.

Polymorf sköld och tillgångsvalv
För att slumpa identifiernamn och kryptera projekttillgångar före utgivning: öppna Polymorf sköld och tillgångsvalv i huvudmenyn, välj ett projekt och tryck sedan på Slumpa namn och kryptera tillgångar. IDE:n skannar klass- och metodnamn i källkoden, bygger en karta med slumpmässiga namn, krypterar projektets tillgångsfiler med AES-GCM till mappen brankas-aset i projektet och sparar en krypterad återställningskarta (perisai-peta.brankas) så att ursprungliga namn kan återställas när kraschloggar läses. Krypteringsnyckeln härleds från projektnamnet, så vem som helst som känner till projektnamnet kan öppna valvet — detta är skydd mot tillfällig läsning, inte ett valv låst med lösenord. Det som skapas här är en namnkarta och ett tillgångsvalv; omskrivning av namn i den kompilerade DEX-filen är nästa steg, så namnen i den färdiga APK:n har ännu inte slumpats.

Förtroendekedja och miljövakt
För att kontrollera signeringsnyckelkedjan och telefonens miljö före utgivning: öppna Förtroendekedja och miljövakt i huvudmenyn, välj ett projekt och tryck sedan på Kontrollera kedja och miljö. IDE:n bygger en nyckelkedja med 5 generationer från projektets paketnamn och kontrollerar dess integritet, skannar sedan minneskartan för den egna processen och enhetens egenskaper efter spår av Frida, Xposed eller emulator. Resultatet är en risknivå Säker, Försiktig eller Farlig, tillsammans med textbevis. Denna kontroll läser textmönster i minneskartan och systemegenskaperna, inte integriteten hos råminnet på den inbyggda bibliotekets nivå, och binder inte nycklarna till hårdvarans säkerhetschip — ett injektionsverktyg som döljer sina textspår kan undkomma denna skanning.

Textträdlayoutarkitekt
För att utforma en skärm utan att se skärmen: öppna Textträdlayoutarkitekt i huvudmenyn, välj ett projekt och en layoutfil och tryck sedan på Kontrollera layout. IDE:n läser XML-layouten som ett textträd och läser högt en positionsberättelse för varje element (till exempel nere till höger, 45 procent av skärmbredden), och rapporterar sedan matematiskt överlappningar mellan element och element som hamnar utanför skärmen vid 360 dp bredd. Det som beräknas är LinearLayout och enkla dp-mått; ConstraintLayout och Compose-skärmar rapporteras som att de har osäker position, inte gissade.

Designsystemstudio
För att göra avstånd, typsnitt och hörn likadana på alla skärmar och projekt: öppna Designsystemstudio i huvudmenyn, välj ett projekt, skriv designtoken (till exempel jarak=8, huruf=16, sudut=12), välj en komponent och tryck sedan på Generera komponenter. IDE:n validerar token — basavstånd 4 till 16 dp, bastypsnitt 12 till 20 sp, hörn 0 till 32 dp och minsta beröringsyta 48 dp — och skriver sedan färdiga XML-komponenter (komponen-studio.xml) tillsammans med ett XML-tema (tema-studio.xml) och ett Compose-tema (tema-studio.kt) i projektmappen. Komponenter genereras som text som klistras in i en layout och kontrolleras sedan med Layoutarkitekten; tvåkolumnsanpassningen på surfplattor använder kvalificerare för skärmbredd, inte enhetsidentifiering vid körning.

Semantisk refaktorering och AST-navigering
För att hitta definitioner och byta namn på symboler utan att förstöra annan kod som råkar ha samma namn: öppna Semantisk refaktorering och AST-navigering i huvudmenyn, välj ett projekt och tryck sedan på Skanna projektsymboler för att se alla klasser och metoder med deras filer och radnummer. Skriv in ett symbolnamn och tryck sedan på Skanna projektsymboler igen för att se dess definition och alla filer som anropar den. För att byta namn skriver du det nya namnet, trycker på Förhandsgranska omnamngivning för att se antalet förekomster i varje fil och trycker sedan på Tillämpa omnamngivning. Detta index använder textmönster, inte en fullständig AST-parser: omnamngivning av en klass gäller alla filer, medan omnamngivning av en metod bara gäller dess ägarfil — anropare i andra filer ändras inte, så kontrollera förhandsgranskningen och anroparskanningens resultat innan du tillämpar. Att extrahera ett kodblock till en ny funktion finns redan i logikmotorn, men det finns ännu ingen knapp för det på den här skärmen.

Steg-för-steg-felsökare och minnesinspektör
För att kontrollera variabelinnehåll mitt i ett programs flöde utan att gissa via loggar: öppna Steg-för-steg-felsökare och minnesinspektör i huvudmenyn, välj ett projekt, skriv exekveringsspåret (ett steg per rad, i formen radnummer, kod, sedan variabler och värden åtskilda med |, till exempel 10|int total = harga * jumlah;|harga=5000, jumlah=3, total=15000), skriv in radnumret för brytpunkten och tryck sedan på Kör felsökningsspår. IDE:n körs till den första brytpunkten och läser högt den aktiva raden tillsammans med dess variabelvärden via Jieshuo. Tryck på Stega en rad för att gå en rad framåt, eller Fortsätt programmet för att köra till nästa brytpunkt. Detta är en spårfelsökare: den följer ett inspelat eller handskrivet exekveringsspår och pausar inte en körande Android-app — att pausa en verklig process kräver en felsökningsbrygga som ännu inte finns i det här steget.

Offline-beroendehanterare
För att använda tredjepartsbibliotek utan internet och undvika versionskonflikter före bygget: öppna Offline-beroendehanterare i huvudmenyn, välj ett projekt och tryck sedan på Kontrollera beroenden. IDE:n läser alla .gradle-filer i projektet, kontrollerar offlinevalvet (brankas-maven.txt i projektet) och löser konflikter — om två bibliotek begär olika versioner av samma artefakt används den högsta versionen och konflikten rapporteras. För att registrera ett bibliotek i valvet skriver du in dess koordinater (formen grupp:artefakt:version, till exempel com.google.code.gson:gson:2.10.1) och trycker sedan på Kontrollera beroenden. Nedladdning från Maven, Google eller PyPI kräver internet: offline kan bara bibliotek som redan finns i valvet användas, och att lägga till koordinater registrerar dem bara i indexet — själva AAR-, JAR- eller WHL-filerna laddas inte ned automatiskt. Valvet sparas fortfarande per projekt.

Databas- och lagringsinspektör
För att kontrollera och testa innehållet i en projektdatabas utan att skriva kod som skriver ut tabellinnehåll: öppna Databas- och lagringsinspektör i huvudmenyn, välj ett projekt och en databasfil (.db, .sqlite eller .sqlite3) och tryck sedan på Öppna databas. IDE:n läser tabellschemat och visar de första 20 raderna som en texttabell som Jieshuo läser högt. Skriv en enkel SELECT-fråga och tryck sedan på Kör fråga (till exempel SELECT nama FROM pengguna WHERE kota = 'Makassar'). För att ändra ett värde skriver du in radnumret (1 = första raden), kolumnnamnet och det nya värdet och trycker sedan på Ändra cellvärde — värdet skrivs tillbaka till .db-filen. Tryck på Spara säkerhetskopia för att spara tabellens aktuella tillstånd som filen <db-namn>.cadangan.txt i projektet. Endast den första tabellen läses; frågor som stöds är bara enkla SELECT utan JOIN eller GROUP BY; SharedPreferences och DataStore läses ännu inte.

Enhetstestfabrik och fuzzing
För att hitta logiska luckor innan en app delas: öppna Enhetstestfabrik och fuzzing i huvudmenyn, välj ett projekt och en kodfil och tryck sedan på Skapa och kör tester. IDE:n läser funktionssignaturer i filen, genererar normala och gränsfall (tom text, null, maximala tal, konstiga tecken), kör fuzzing på exempelfunktioner och skriver ett JUnit-teststomme (Uji<Klassnamn>.java) i projektet. Resultatet rapporterar hur många tester som godkändes och underkändes, hur många kodrader och funktioner som hittades och hur många testfall som skapades. De genererade testerna är fortfarande stommar — de förväntade värdena måste skrivas av utvecklaren — och verklig fuzzing körs bara på exempelfunktionerna, inte på projektfunktionerna; täckningsprocenten för rader beräknas ännu inte.

Simulator för extrema enhetsförhållanden och minnesläckegranskare
För att testa appens motståndskraft när systemet dödar dess process, nätverket bryts, skärmen roteras eller batterisparläge är aktivt: öppna Simulator för extrema enhetsförhållanden och minnesläckegranskare i huvudmenyn, välj ett projekt och tryck sedan på Kör simulering. IDE:n kör tre stresscenarier tillsammans med en skärmrotationssimulering och spårar objekt som hålls kvar i minnet efter att deras skärm stängts, och rapporterar sedan förlorade data och kedjor av läckande objekt. Detta är en simulering över en tillståndsmodell, inte att verkligen döda en process, inte att verkligen bryta telefonens nätverk och inte en verklig heapdump; tillståndsmodellen på den här skärmen är fortfarande ett fast exempel, inte tillståndet för användarens projektskärmar.

Projektplanarkitekt
För att förvandla en stor appidé till en stegvis arbetsplan: öppna Projektplanarkitekt i huvudmenyn, välj ett projekt, skriv appidén (till exempel en kassaapp för en livsmedelsbutik med avbetalningar) och tryck sedan på Skapa plan. IDE:n ordnar moduler, en fillista och små arbetsmilstolpar och sparar dem sedan som cetak-biru.txt i projektmappen. Tryck på Markera nästa milstolpe som klar varje gång en milstolpe är färdig, eller tryck på Läs in sparad ritning för att öppna en sparad plan igen. Planer byggs från nyckelordsmönster på enheten, inte från en online-AI-modell — oigenkända idéer använder en allmän stomme (datamodell, lagring, skärmar, logik) — och att bygga via den aktiva AI-leverantören finns ännu inte i det här steget.

Berättare av kodens logiska flöde
För att förstå lång kod utan att lyssna på syntax rad för rad: öppna Berättare av kodens logiska flöde i huvudmenyn, välj ett projekt och en kodfil och tryck sedan på Kodberättelse. IDE:n förvandlar varje rad till en indonesisk mening (till exempel om summan är större än 100000, kör följande block), visar en anropskarta mellan metoder och markerar möjliga subtila buggar med deras radnummer — String jämförd med ==, en ström öppnad utan att stängas och en variabel skriven i två olika metoder. Berättelse och kontroll använder offlinetextmönster, inte en online-AI-modell och inte en fullständig dataflödesanalys; okända mönster berättas som de är, som en kodrad, och varningar om datarace kan dyka upp för variabler som i verkligheten bara används omväxlande.

App-paketfabrik och Play Store-beredskap
För att förbereda en app för Google Play Store direkt från telefonen: öppna App-paketfabrik och Play Store-beredskap i huvudmenyn, välj ett projekt och tryck sedan på Bygg AAB-paket. IDE:n sätter samman .aab-filen från manifest, resurser och projekttillgångar, simulerar nedladdningsdelstorlekar per arkitektur (arm64-v8a, armeabi-v7a, x86_64) och språk och granskar sedan Play-beredskapen — ett mål-SDK under 35 markeras som Hög eftersom Play Store kräver 35 eller mer, och ett saknat 64-bitarsbibliotek markeras också som Hög. Det resulterande paketet är ett AAB-arkiv med standardstruktur; delstorlekarna är uppskattningar från filstorlekar, inte verkliga bundletool-delresultat, och signeringen av paketet för Play Console använder fortfarande samma byggväg som APK:n.

OTA-uppdateringsmotor och stegvisa lanseringar
För att skicka små korrigeringar utan att tvinga användare att ladda ned hela APK:n igen: öppna OTA-uppdateringsmotor och stegvisa lanseringar i huvudmenyn, välj ett projekt, skriv innehållet i den gamla och nya versionen och tryck sedan på Skapa patchpaket. IDE:n beräknar radskillnaderna och skapar ett patchpaket (patch-ota.zip) med SHA-256-fingeravtrycket av det nya innehållet och kontrollerar sedan om den här enheten ingår i den tidiga utrullningsfasen på 10 procent. Patch här fungerar bara på textfiler (skript, tillgångar, konfiguration) — binära DEX- eller APK-patch stöds ännu inte, och en patch tillämpas när appen öppnas igen. Fingeravtrycket i manifestet bevisar bara innehållets integritet, inte avsändarens äkthet, eftersom det ännu inte använder en signatur med privat nyckel.

Teamkodgranskningsstudio
För att granska en kollegas ändringar och lösa sammanslagningskonflikter utan att läsa Gits pilmarkeringar: öppna Teamkodgranskningsstudio i huvudmenyn, välj ett projekt, fyll i tre textversioner (bas, lokal, kollega) och tryck sedan på Öppna teamgranskning. IDE:n slår samman alla tre och visar varje konflikt som ett röstval: Använd lokal version, Använd kollegans version eller Slå ihop båda — resultatraderna sätts in på konfliktens ursprungliga plats så att radordningen förblir korrekt — och skriver sedan resultatet till gabung-hasil.txt i projektet. Under den finns projektets uppgiftstavla: skriv in en uppgiftstitel och tryck sedan på Lägg till uppgift; uppgifter sparas som text i mappen .tugas i projektet. Sammanslagning använder radmatchning, inte syntax, så två ändringar på samma rad behandlas alltid som en konflikt även om deras betydelser inte kolliderar; uppgiftstavlan synkroniseras genom att kopiera sin textfil tillsammans med Git-historiken, utan en särskild synkroniseringsserver.

Diktat av kodstruktur
För att skriva kod med rösten inne i editorn: öppna ett projekt i Editorn och tryck sedan på knappen Diktat av kodstruktur. Tala kommandon på indonesiska, till exempel buat fungsi tambah dengan parameter a angka dan b angka, buat kelas Mobil eller buat variabel teks nama sama dengan Budi — IDE:n förvandlar talet till ett syntaktiskt giltigt Java-, Kotlin-, Python- eller Compose-kodblock och infogar det vid markörpositionen, och läser sedan upp en kort sammanfattning via Jieshuo. Diktat använder systemets inbyggda röstinmatningstjänst, utan extra mikrofonbehörighet, och känner bara igen redan registrerade kommandomönster; tal utanför dessa mönster förvandlas inte till kod. Tal som uttalas som ord (till exempel 'lima') förvandlas ännu inte till siffror.

Lokalt samarbetsrum (utan internet)
För att arbeta tillsammans i ett rum utan internet: öppna Samarbete i huvudmenyn och öppna sedan avsnittet Lokalt samarbetsrum. En telefon öppnar en session (IDE:n visar en lokal IP-adress och en 6-siffrig PIN), en annan telefon ansluter med den adressen och PIN-koden. Textändringar skickas som radskillnader, en byggd APK kan skickas till testarens telefon och kraschrapporter från testarens telefon tas emot tillbaka. En session är bara för en vän; om två personer ändrar exakt samma rad samtidigt används den sista ändringen. PIN-koden skickas som klartext på det lokala nätverket. Det här rummet har ännu inte testats på en riktig telefon.

AI-inställningar
För att ställa in AI-leverantör och API-nycklar för att skapa appar: tryck i huvudmenyn, i gruppen Inställningar, på AI-inställningar (bredvid knappen Konnektor). Välj leverantören som ska användas i den tillgängliga listan och bocka för Byt modell vid leverantörsfel så att IDE:n automatiskt prövar nästa modell från samma leverantör om en modell misslyckas. Tryck på Hantera API-nycklar för att lägga till reservnycklar (fyll i namn och nyckel och tryck sedan på Spara; nycklarna visas maskerade, bara de sista 4 tecknen syns). Nycklarna sparas på telefonen och skickas aldrig någon annanstans än till den valda leverantören när en app skapas. Observera: just nu registreras valet av leverantör och nyckel bara och visas på skärmen AI Pembuat Aplikasi — att skapa appar använder fortfarande den lokala AI:n på telefonen (utan internet); användning av onlineleverantörer kommer senare.

Konnektor
För att analysera en APK och sedan skicka den: tryck i huvudmenyn, i gruppen Inställningar, på Konnektor (bredvid knappen AI-inställningar). Välj en APK-fil från telefonen, IDE:n läser dess innehåll (paketnamn, version, lista över aktiviteter) och tryck sedan på Skicka APK för att skicka den via systemets delningsmeny (till exempel WhatsApp eller Drive).

Språk och röst
För att ändra appens språk: öppna Inställningar, sedan Appspråk och välj sedan ett språk eller Följ systemet. Huvudskärmen och de flesta skärmar byter omedelbart till det valda språket utan att stänga eller starta om appen; vissa skärmar (till exempel Terminal, Samarbete, AI-inställningar och Hantera nycklar) använder fortfarande det gamla språket tills de öppnas igen. Om du väljer Följ systemet följer språket telefonens systemspråk.
