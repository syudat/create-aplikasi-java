Välkommen till Create Aplikasi by Al Kautsar
Create Aplikasi är en app för att skapa Android-appar som körs direkt på telefonen, utan att behöva en bärbar dator. Appen låter vem som helst skapa sin egen Android-app, inklusive användare som precis har börjat lära sig att skapa appar och användare av skärmläsare. Den fullständiga guiden för att använda den här appen finns på den här Tentang Alat-skärmen.

Vad den här appen är och vem den är till för
Create Aplikasi är ett verktyg för att skapa Android-appar som körs på telefonen. Appen riktar sig till alla som vill skapa sin egen Android-app, inklusive nybörjare och användare av skärmläsare. Appen tillhandahåller en kodredigerare, en Jalankan-knapp för att testa projekt, en Bangun-knapp för att skapa en APK, samt menyer för att signera och installera APK:n.

Syftet med den här appen
Den här appen skapades så att vem som helst enkelt kan skapa sin egen Android-app, direkt från telefonen. Dess utseende gjordes så enkelt som möjligt så att även nya användare kan prova direkt.

Så skapar du ett nytt projekt, steg för steg
1. Tryck på Buat Project i huvudmenyn.
2. Välj projekttyp: HTML, Situs Web, Java, Kotlin, Compose eller Python.
3. Fyll i appens namn, exempel: Garuda Decode.
4. Fyll i paketnamnet (package name), exempel: com.android.garudadecode. Paketnamnet måste använda små bokstäver och bestå av minst två delar åtskilda av punkter.
5. Fyll i appens version, exempel: 1.0, och versionskoden i form av ett tal, exempel: 1. Om det lämnas tomt fylls versionen automatiskt i med 1.0 och versionskoden med 1.
6. Fyll i lägsta SDK och mål-SDK om det behövs. Om det lämnas tomt används standardvärdena. Lägsta SDK är den lägsta Android-version som stöds, exempel: 21 betyder Android 5.0. Högsta mål-SDK är 36 (Android 16).
7. Tryck på knappen Pilih Izin för att välja appens behörigheter, exempel: INTERNET. Behörigheten INTERNET är redan markerad som standard. Markera bara de behörigheter som appen verkligen behöver.
8. Om du vill, markera "Gunakan arsitektur terpisah 64 bit dan 32 bit" så att APK:ns storlek blir mindre, och markera "Gunakan tanda tangan pribadi" om du vill använda en egen skapad keystore.
9. Tryck på Buat Proyek. Det nya projektet sparas i mappen Download/project och syns direkt i Kelola Project.

Tillgängliga projekttyper
• HTML: utseende från index.html, style.css och script.js, körs via WebView. Byggs direkt på telefonen.
• Situs Web: webbplats med meny (Beranda, Tentang, Kontak) från index.html, tentang.html, kontak.html, style.css och script.js, körs via WebView. Byggs direkt på telefonen.
• Java: byggs på telefonen. MainActivity finns i app/src/main/java/<nama-paket>/MainActivity.java. Utseendet kommer från app/src/main/res/layout/activity_main.xml, texten från app/src/main/res/values/strings.xml och temat från app/src/main/res/values/styles.xml.
• Kotlin: kan byggas på enheten (offline) med den Kotlin-kompilator som ingår i appen, eller via GitHub Actions. MainActivity finns i app/src/main/java/<nama-paket>/MainActivity.kt, och res-filerna är desamma som i ett Java-projekt. Den första Kotlin-byggnationen är långsammare på grund av kompilatorns stora storlek, och .java-filer som refererar till Kotlin-klasser kan ännu inte byggas (.java-filer kompileras först, före .kt-filer).
• Compose: en modern Android-app vars gränssnitt skapas med Jetpack Compose (inte XML-layout). MainActivity finns i app/src/main/java/<nama-paket>/MainActivity.kt. Compose-projekt byggs via GitHub Actions (menyn Bangun proyek, sedan Bangun online) eller i Termux med Gradle, eftersom Compose kräver Jetpack Compose-bibliotek som inte finns tillgängliga på enheten.
• Python: appens logik skrivs på språket Python (Chaquopy) i app/src/main/python/main.py och körs av värden MainActivity.java i app/src/main/java/<nama-paket>/MainActivity.java. Python-projekt kan byggas direkt på telefonen (Chaquopy-runtime ingår i appen) eller via GitHub Actions. Lägsta SDK för Python-projekt är 24 (Android 7.0).

Ändra projektarkitektur
För att ändra arkitekturvalen för ett befintligt projekt utan att skapa ett nytt projekt: tryck på «Ändra projektarkitektur» i huvudmenyn, välj sedan projektet och ändra kryssrutan «Bygg 64-bitars APK (arm64-v8a)» eller «Bygg 32-bitars APK (armeabi-v7a)»; eller tryck länge på projektnamnet i «Hantera projekt» och välj «Ändra arkitektur» för att öppna samma skärm direkt för det projektet. Regeln är: om båda kryssrutorna är markerade skapar bygget två separata APK-filer, en 64-bitars och en 32-bitars; om bara en kryssruta är markerad skapar bygget en enda universell APK som fortsätter att köras på både 64- och 32-bitars enheter. En separat APK för endast en variant stöds ännu inte, eftersom byggvägen endast känner till det delade eller universella valet, men varje variants val förblir sparat i projektet så att det inte går förlorat när skärmen öppnas igen.

Filstruktur för projekt i Java, HTML, Situs Web, Kotlin, Compose och Python
Projekt i Java, HTML, Situs Web, Kotlin, Compose och Python är uppbyggda som Android-projekt i allmänhet. Inuti mappen app finns mappen src, och inuti den finns mappen main. Inuti mappen main finns AndroidManifest.xml bredvid mappen java, mappen res som innehåller layout/activity_main.xml och values/strings.xml samt values/styles.xml, och för HTML och Situs Web finns mappen assets som innehåller index.html (Situs Web har även tentang.html och kontak.html). HTML- och Situs Web-projekt har också en egen MainActivity i app/src/main/java/<nama-paket>/MainActivity.java, som laddar index.html i WebView och är startprogram i AndroidManifest. Python-projekt har Python-kod i app/src/main/python/main.py och värden MainActivity.java i app/src/main/java/<nama-paket>/MainActivity.java. AndroidManifest.xml, layout, strings och styles kan öppnas och ändras i redigeraren, precis som MainActivity. Gamla projekt vars manifest fortfarande ligger bredvid mappen app kan fortfarande byggas, eftersom appen vid byggnation först kontrollerar AndroidManifest.xml i app/src/main/, sedan den bredvid mappen app, och sist projektdatafilen.

Behörighetsregler (viktigt)
Behörigheter som markeras när ett projekt skapas registreras bara på ett ställe, beroende på projekttypen. För projekt i Java, HTML, Situs Web, Kotlin, Compose och Python registreras de markerade behörigheterna ENDAST i AndroidManifest.xml som finns i app/src/main/, bredvid mappen java, inuti projektmappen. Projektdatafilen för projekt i Java, HTML, Situs Web, Kotlin, Compose och Python innehåller ingen lista över behörigheter. Om du väljer Java och sedan markerar INTERNET och CAMERA registreras bara INTERNET och CAMERA i AndroidManifest.xml, utan att någon annan behörighet följer med. Vid byggnation läser appen behörigheterna från samma ställe: från AndroidManifest.xml i app/src/main/ för projekt i Java, HTML, Situs Web, Kotlin, Compose och Python (om det inte finns, från AndroidManifest.xml bredvid mappen app för gamla projekt), och från projektdatafilen för gamla projekt.

Så använder du redigeraren
Öppna Kelola Project, tryck på projektets namn för att öppna redigeraren. I redigeraren kan filer öppnas, kod skrivas och ändringar sparas. För projekt i Java, HTML, Situs Web, Kotlin, Compose och Python är filerna ordnade inuti mappen app/src/main. För att dela ett projekt, använd Ekspor ZIP (se avsnittet nedan).

Så kör du ett projekt
I redigeraren trycker du på Jalankan för att testa projektet. För HTML- och Situs Web-projekt är det index.html som körs via WebView. Om ett fel uppstår, läs felmeddelandet, rätta koden och kör igen.

Så bygger du en APK
I redigeraren trycker du på Bangun. Det finns två sätt att bygga. Det första, Bangun di perangkat: bygga direkt på telefonen utan internet, för projekt i HTML, Situs Web, Java, Kotlin och Python. Det andra, Bangun online via GitHub Actions: bygga via internet på GitHub, och kan användas för alla projekttyper. Compose-projekt kan bara byggas på det andra sättet (Bangun online) eller i Termux med Gradle, eftersom Compose kräver Jetpack Compose-bibliotek som inte finns tillgängliga på enheten. Resultatet av den första byggnationen är ännu inte signerat. Därefter signerar appen det: automatiskt med standardnyckeln, eller med en personlig signatur om rutan "Gunakan tanda tangan pribadi" markerades när projektet skapades.

Så installerar du en APK
När APK:n är klar trycker du på Pasang för att installera den. På Android 8 och högre kommer telefonen först att be om "Izinkan dari sumber ini", eftersom den här appen installerar APK:er från utanför Play Store. Aktivera den behörigheten en gång i Pengaturan och gå sedan tillbaka till appen: installationen fortsätter automatiskt utan att du behöver trycka på Pasang igen. Om Pasang-knappen inte visas, se till att byggnationen är klar och att APK:n har skapats.

Så signerar du en app
Varje APK måste signeras för att kunna installeras. Det finns två alternativ. Det första, standardnyckeln: appen signerar själv automatiskt, utan att du behöver göra någonting. Det andra, personlig signatur: skapa först en keystore via menyn Buat Keystore i huvudmenyn, förvara dess lösenord väl, och markera sedan "Gunakan tanda tangan pribadi" när du skapar projektet. Keystore sparas i Download/project/signing.

Exportera ett projekt som ZIP
Ekspor ZIP tillhandahålls så att projekt kan delas med vänner. Gör så här: i Kelola Project, tryck länge på projektets namn och välj sedan Ekspor ZIP. Resultatet sparas i Download/project/<NamaProyek>.zip. Mappen bin tas inte med, så storleken är liten, bara några tiotal KB. Den ZIP-filen kan skickas till en vän eller laddas upp till GitHub.

JAWS-tillägget
JAWS-tillägget använder tilläggsmotorn från Jieshuo (CSR), inte dess skärmläsare. På så sätt kan designen fortfarande köras även om användaren använder TalkBack. Gör så här: öppna Ekstensi JAWS i huvudmenyn. Eftersom det automatiska klicket körs av sig självt måste tjänsten först aktiveras i Pengaturan Aksesibilitas. Därefter kan en ny design skapas: skriv designens namn, tryck på OK och fyll sedan i dess rutor.

Daftar Klik är åtskild för ordningens skull
Inuti designen finns två rutor: skriptrutan och Daftar Klik-rutan. Listan över knappar sparas separat i filen daftar_klik.txt, ett namn per rad. Exempel på dess innehåll: tombolSimpan, tombolHapus, tombolBuka. För att öppna en app, skriv bara >WhatsApp i den listan. Gamla designer som ännu inte har någon daftar_klik.txt-fil kommer att visa det standardexemplet.

Enkla funktioner som tillhandahålls
• klikTombol("tombolSimpan") — klickar på en knapp utifrån dess text.
• klikDaftarTombol(daftar) — klickar på listan i daftar_klik.txt, en knapp per rad, i ordning, och berättar sedan hur många som lyckades och hur många som inte hittades.
• bukaAplikasi("WhatsApp") — öppnar en app utifrån dess namn, eller skriv ">WhatsApp" i listan.
• klik(540, 1200) — klickar på skärmkoordinater.
Alla funktioner gjordes enkla först. När du har vant dig kan ytterligare funktioner läggas till senare.

Om skärmläsare
Den här appen är utformad för att vara vänlig mot skärmläsare. Varje inmatningsfält har en etikett och ett ifyllningsexempel, och alla knappar kan nås utan komplicerade gester. JAWS-tillägget är gjort för att fortfarande köras även om användaren använder TalkBack, eftersom det som används är dess tilläggsmotor, inte dess skärmläsare.

Integritet och säkerhet
Projekt och keystore sparas på din telefon. GitHub-token används bara för onlinebyggnationer och sparas inuti den här appen. Dela inte din token eller ditt keystore-lösenord med någon. Om du använder en personlig signatur, förvara keystore och dess lösenord på ett säkert ställe, eftersom det gamla APK:t inte kan uppdateras med samma signatur om de går förlorade.

Krav
Android 5.0 eller nyare. Lagringsbehörighet: på Android 11 och högre används behörighet för åtkomst till alla filer, på Android 10 och lägre används vanlig lagringsbehörighet (läsa/skriva lagring) eftersom Android 10 inte har behörighet för åtkomst till alla filer. Att bygga på enheten kräver en telefon med ARM-processor (32 eller 64 bitar). Att bygga online via GitHub Actions kräver internet och en GitHub-token. Kotlin-projekt kan byggas på enheten, men dess första byggnation är långsammare och använder mer minne på grund av Kotlin-kompilatorns stora storlek. Compose-projekt byggs via GitHub Actions eller i Termux med Gradle. Python-projekt kräver Android 7.0 eller nyare (lägsta SDK 24) och den resulterande APK:n är större eftersom den innehåller Python-runtime (Chaquopy) tillsammans med dess standardbibliotek.

Terminal
Menyn Terminal på huvudskärmen öppnar en terminal inuti den här appen. Kommandon som ls kan användas för att se innehållet i projektmappen, cd för att byta mapp och git för att hantera kod. Kommandonas utdata visas som text som kan läsas av skärmläsaren, och det finns en Bacakan hasil-knapp för att lyssna på det senaste resultatet. Den här terminalen använder telefonens systemskal, så interaktiva program som nano och vim kan ännu inte användas här.

Licens (betalversion)
För att sälja appar, markera "Aktifkan Lisensi" när du skapar projektet och fyll sedan i ditt WhatsApp-nummer. Appen som blir resultatet av byggnationen kommer att be om en licenskod när den öppnas första gången: användaren ser sin enhets-ID, trycker på knappen Kirim ID Perangkat för att skicka det ID:t till din WhatsApp, och sedan svarar du med licenskoden. Licenskoden beräknas från enhetens ID och projektets lösenord (lisensi_seed i projektdatafilen) — förvara det lösenordet väl och dela det inte. När rätt kod har matats in öppnas appen och ber inte om koden igen.

Pembuat Ikon Otomatis
Nya projektikoner är fortfarande genomskinliga, så Pembuat Ikon finns tillgänglig i huvudmenyn. Gör så här: tryck på Pembuat Ikon, skriv en eller två bokstäver (till exempel initialerna i appens namn), välj bakgrundsfärg och textfärg, titta på dess förhandsvisning och tryck sedan på Simpan ke Proyek för att använda den ikonen i det valda projektet, eller Simpan ke Download för att använda dess PNG-fil någon annanstans. När ett projekt har skapats erbjuder appen också att skapa en ikon. Gamla projektikoner kan bytas när som helst från projektmenyn i Kelola Project (tryck länge på projektets namn och välj sedan Ganti Ikon).

Färdiga projektmallar
Om du inte vill börja från ett tomt projekt, välj en mall när du skapar projektet: Kalkulator (Java), Catatan (Java), Daftar Tugas (Kotlin), Kalkulator Web (HTML), Situs Profil (Situs Web) eller Penghitung (Compose). Att välja en mall ändrar automatiskt projekttypen så att den följer den mallen, och projektet skapas med färdig startkod — det återstår bara att köra eller ändra det. Om projekttypen ändras manuellt igen efter att en mall har valts avbryts mallen och projektet blir tomt igen. För mallar i HTML och Situs Web ersätter mallen innehållet i index.html, inklusive det HTML-skript som skrivs i formuläret.

Säkerhetskopiering och återställning av projekt
För att projekt inte ska gå förlorade finns en säkerhetskopieringsfunktion. Gör så här: i Kelola Project, tryck länge på projektets namn och välj sedan Cadangkan. Säkerhetskopian sparas som ZIP i mappen Download/backup med projektets namn och datum, exempel: GarudaDecode-2026-11-14-123045.zip. Dess innehåll är detsamma som Ekspor ZIP (hela projektets innehåll, utan mappen bin). För att återställa: öppna menyn i Kelola Project, välj Pulihkan cadangan och välj sedan dess säkerhetskopiefil. Om projektets namn redan finns kommer appen att fråga: Timpa proyek lama, eller spara med Nama baru.

Dela och importera projekt
För att dela ett projekt med en vän: i Kelola Project, tryck länge på projektets namn och välj sedan Bagikan. Projektet skickas som ZIP via delningsappar (WhatsApp, Telegram med flera). För att ta emot ett projekt från en vän: öppna menyn i Kelola Project, välj Impor proyek och välj sedan dess ZIP-fil. Den ZIP-filen måste innehålla en projektdatafil — om det inte finns avvisas filen med ett tydligt meddelande, eftersom den filen inte är ett Create Aplikasi-projekt. Om projektets namn redan finns kommer appen att fråga: Timpa proyek lama, eller spara med Nama baru.

Projektsökning och filter
Om projekten har blivit många finns det i Kelola Project en sökruta och ett typfilter. Skriv projektets namn i sökrutan så filtreras listan direkt (stora och små bokstäver skiljs inte åt). Typfiltret begränsar listan till bara en typ: Semua, HTML, Situs Web, Java, Kotlin, Compose eller Python. Varje projekts meny kan fortfarande öppnas som vanligt från den filtrerade listan.

Bygg appar med röst
Om du inte vill skriva, använd rösten: tryck på Bygg med röst i huvudmenyn och säg sedan ett kommando. Kommandon du kan säga: "Buat proyek kalkulator", "Bangun proyek Kalkulator", "Buka proyek Kalkulator", "Jalankan proyek Kalkulator", "Daftar proyek", "Buka ikon", "Kembali" och "Bantuan". Appen svarar med röst och text, så den kan fortfarande användas utan att titta på skärmen. Röstigenkänning använder telefonens inbyggda röstigenkänningsapp (gratis; den kan fungera offline om det indonesiska språkpaketet är installerat). Om telefonen saknar röstigenkänning kan kommandona skrivas i textrutan på samma skärm.

AI-appskapare
Skriv eller diktera den app du vill ha på skärmen AI-appskapare, till exempel: «en anteckningsapp med en sparknapp». Appen analyserar nyckelorden inne i telefonen (utan internet, utan kostnad) och skapar sedan ett riktigt projekt från den bäst matchande mallen: kalkylator, anteckningar, uppgiftslista, webbkalkylator, profilsajt eller räknare. Om din beskrivning ännu inte har någon matchande mall skapar appen ett tomt projekt och säger det ärligt — den låtsas inte förstå. Ett projekt som gjorts av AI kan öppnas direkt i Hantera projekt.

Direktförhandsvisning på en väns mobil
För att visa ett projekt för en vän innan det byggs: i Hantera projekt, tryck länge på projektnamnet och välj sedan Förhandsvisning på en väns mobil. Appen skapar ett litet förhandsvisningspaket som innehåller projektets huvudfiler (index.html, MainActivity eller main.py) plus BACA-SAYA.txt med instruktioner och info.txt. Paketet skickas som en ZIP via WhatsApp eller Telegram. Vännen som tar emot det kan öppna förhandsvisningen direkt: HTML-sidor öppnas i webbläsaren, Java/Kotlin/Python-kod läses som text.

Projektmarknad
Projektmarknad innehåller inbyggda exempelprojekt som kan installeras i projektmappen med ett tryck: Kalkylator, Anteckningar, Uppgiftslista, Webbkalkylator, Profilsajt, Räknare, Digital klocka och Webbquiz. Onlinemarknaden (ladda ner exempel från internet) finns ännu inte, så den här marknaden innehåller exempel som redan finns i appen. Ett installerat projekt kan öppnas och ändras i Hantera projekt som ett projekt du gjort själv.

Direkt samarbete
För att arbeta på ett projekt tillsammans med en vän: öppna Samarbete i huvudmenyn, välj projektet, skriv en ändringsanteckning (vad som ändrades) och tryck sedan på Dela för samarbete. Projektet skickas som en ZIP tillsammans med en CATATAN.txt-fil inuti. Din vän arbetar med det och skickar tillbaka ZIP-filen; du trycker på Ta emot svar, läser först ändringsanteckningen och väljer sedan Verkställ för att skriva över det gamla projektet eller Avbryt om du ångrar dig. En ZIP utan CATATAN.txt är inte ett samarbetspaket — för en vanlig projekt-ZIP, använd Importera projekt i Hantera projekt.

Automatisk appöversättare
För att översätta texten i en app till ett annat språk: öppna Appöversättare i huvudmenyn, välj projektet och målspråket (engelska, arabiska eller javanesiska) och tryck sedan på Översätt. Ordboken finns redan inne i telefonen (utan internet, utan kostnad) och innehåller vanliga vardagsord; text från strings.xml, layout och kod läses och översätts sedan. Resultatet skrivs till mappen values-språk/strings.xml (om projektet har en strings.xml) och en översättning-språk.txt-rapport i projektmappen. Ord som ännu inte finns i ordboken lämnas som de är och rapporteras — så att du vet vilka ord du fortfarande måste översätta själv.

Spelskapare utan kod
För att göra ett spel utan att skriva kod: öppna Spelskapare utan kod i huvudmenyn, välj speltyp (Gissa talet, Frågesport eller Fånga stjärnan), fyll i spelnamn, mängd (nivåer/frågor/stjärnor) och vinstmeddelande och tryck sedan på Skapa spel. Spelet görs som ett riktigt projekt som kan köras direkt i Hantera projekt och byggas till en APK som alla andra projekt.

Automatisk apptestning
För att kontrollera ett projekt innan det byggs: i Hantera projekt, tryck länge på projektnamnet och välj sedan Automatiskt test. IDE kontrollerar 10 saker utan att bygga en APK — obligatoriska filer finns (projektdatafil, manifest, huvudfil, layout, strängar), paketnamn och version, använda behörigheter, ikon och balans i kodparenteser. Resultatet visas per post (GODKÄND/UNDERKÄND med ett meddelande) och läses upp av Jieshuo. Åtgärda först allt som UNDERKÄNDES och tryck sedan på Bygg projekt.

AI-kodgranskare
För att kontrollera projektkod för mönster som ofta orsakar problem: öppna Kontrollera kod i huvudmenyn, välj projektet och tryck sedan på Kontrollera kod. Granskaren körs inne i telefonen (utan internet) och letar efter oanvända variabler, tomma funktioner, uppenbart oändliga loopar, text som skrivits direkt i koden (bättre i strings.xml), farliga behörigheter och API:er, TODO/FIXME-markörer och dynamisk exekvering. Varje fynd innehåller filnamn, radnummer och åtgärdsförslag. Den här granskaren är mönsterbaserad, inte en riktig AI — problem som inte följer ett mönster kan fortfarande slinka igenom.

Interaktivt inlärningsläge
För att lära dig att göra appar steg för steg: öppna Inlärningsläge i huvudmenyn. Det finns 5 lektioner: Gör ditt första projekt, Lägg till en knapp, Ändra färg, Lägg till ljud och Bygg en APK. Tryck på en lektion för att läsa dess förklaring och övningsuppgift, gör uppgiften och tryck sedan på Kontrollera uppgiften — IDE kontrollerar verkligen om uppgiften har gjorts (genom att skanna projektet och APK:en på din telefon). Lektioner som godkänns markeras som klara och sparas.

Molnsynkronisering
För att säkerhetskopiera ett projekt till molnet: öppna Molnsynkronisering i huvudmenyn. En lokal säkerhetskopia sparar projekt-ZIP:en till mappen Download/cloud med en tidsstämpel och kan återställas när som helst från säkerhetskopielistan. En GitHub-säkerhetskopia laddar upp projekt-ZIP:en till din privata repo (med token från GitHub-inställningar) och kan laddas ner igen. Detta är manuell säkerhetskopiering och återställning — fullständig automatisk tvåvägssynkronisering behöver en server, så den finns ännu inte.

För att installera en modul i ett annat projekt, öppna Modulfabrik, välj målprojektet och tryck sedan på Installera modul och välj modulens .zip-fil — sammanslagningen lägger till strängar och behörigheter utan att skriva över befintlig kod, och slår inte samman en fil om dess namn redan används i målprojektet. En modul bär varken med sig bibliotek eller bygginställningar.

Polymorf sköld och tillgångsvalv
För att slumpa identifierarnamn och kryptera projekttillgångar före publicering: öppna «Polymorf sköld och tillgångsvalv» i huvudmenyn, välj projektet och tryck sedan på «Slumpa namn och kryptera tillgångar». IDE:n skannar klass- och metodnamn i källkoden, skapar en slumpmässig namnkarta, skriver om dessa namn inuti de kompilerade DEX-filerna (ersättningsnamnen görs lika långa som originalen så att alla offsetar förblir giltiga, sedan beräknas DEX-huvudets kontrollsumma och SHA-1-signatur om), krypterar projekttillgångsfilerna med AES-GCM i mappen brankas-aset inuti projektet och sparar en krypterad återställningskarta (perisai-peta.brankas) så att de ursprungliga namnen kan återställas när kraschloggar läses. Krypteringsnyckeln härleds nu från utvecklarens lösenord med PBKDF2, 20 000 iterationer, inte från projektnamnet. Namn som också används som ren text, anteckningsnamn och felsökningsnamn skrivs medvetet inte om, och infogningspunkterna för DEX-omskrivning i byggvägen väntar ännu på testning på en riktig telefon.

Förtroendekedja och miljövakt
För att kontrollera signaturnyckelkedjan och telefonens miljö före publicering: öppna «Förtroendekedja och miljövakt» i huvudmenyn, välj projektet och tryck sedan på «Kontrollera kedja och miljö». IDE:n bygger en nyckelkedja på 5 generationer från projektets paketnamn och kontrollerar dess integritet, kontrollerar verklig minnesintegritet genom att jämföra innehållet i kodsegmenten i minnet med filerna på disken och rapporterar namnlösa körbara (RWX) mappningar, främmande bibliotek och memfd-mappningar, och skannar sedan sin egen processminneskarta och enhetsegenskaper efter spår av Frida, Xposed eller emulator. Valvnyckeln lindas med en AES-nyckel i AndroidKeyStore som använder hårdvarans säkerhetschip när det finns, och nyckelrotation är nu verklig med schema v3-signaturcertifikatslinje: den gamla nyckeln signerar beviset på rotation till den nya nyckeln och APK:n signeras om med den linjen. Resultatet är en risknivå «säker», «försiktig» eller «farlig» med textbevis. Om systemet vägrar minnesläsning rapporteras kontrollen som «kan inte verifieras», inte säker; och huruvida en nyckel verkligen använder hårdvarans säkerhetschip kan bara bekräftas på en riktig enhet.

Textträdlayoutarkitekt
För att utforma en skärm utan att se den: öppna «Textträdlayoutarkitekt» i huvudmenyn, välj projektet och layoutfilen och tryck sedan på «Kontrollera layout». IDE:n läser XML-layouten som ett textträd och läser varje elements positionsbeskrivning högt (till exempel nere till höger, 45 procent av skärmbredden) och rapporterar sedan matematiskt överlappningar mellan element och element som går utanför skärmen vid 360 dp bredd. Det som nu räknas in är LinearLayout och enkla dp-storlekar, fullständig ConstraintLayout (alla begränsningar, bias, kedjor, riktlinjer, hinder, procentbredder, 0dp match_constraint och dimensionsförhållanden) och Compose-skärmar (Column, Row och Box med deras storleksmodifierare). Endast MotionLayout och ConstraintSet som ändras under körning rapporteras fortfarande som okänd position, eftersom deras värden bara finns medan appen körs.

Designsystemstudio
För att göra avstånd, typsnitt och hörn enhetliga på alla skärmar och projekt: öppna «Designsystemstudio» i huvudmenyn, välj projektet, skriv designtoken (till exempel jarak=8, huruf=16, sudut=12), välj en komponent och tryck sedan på «Generera komponenter». IDE:n validerar token — basavstånd 4 till 16 dp, bastypsnitt 12 till 20 sp, hörn 0 till 32 dp och minsta tryckyta 48 dp — och skriver sedan färdiga XML-komponenter (komponen-studio.xml) med ett XML-tema (tema-studio.xml) och ett Compose-tema (tema-studio.kt) i projektmappen. Token kan också sparas som en namngiven uppsättning i det delade tokenbiblioteket mellan projekt, och ett enda synkroniseringskommando tillämpar bibliotekets senaste token på alla projekt som använder den uppsättningen. Komponenter skapas som text som klistras in i layouten och sedan kontrolleras med «Textträdlayoutarkitekt»; justeringen till två kolumner på surfplatta använder skärmbreddskvalificering istället för enhetsidentifiering medan den körs.

Semantisk refaktorering och AST-navigering
För att hitta definitioner och byta namn på symboler utan att bryta annan kod som råkar ha samma namn: öppna «Semantisk refaktorering och AST-navigering» i huvudmenyn, välj projektet och tryck sedan på «Skanna projektsymboler» för att se alla klasser och metoder med deras filer och radnummer. Skriv symbolnamnet och tryck sedan på «Skanna projektsymboler» igen för att se dess definition och alla filer som anropar den. För att byta namn, skriv det nya namnet, tryck på «Förhandsgranska omnamngivning» för att se antalet förekomster i varje fil och tryck sedan på «Tillämpa omnamngivning». Indexet använder nu en handbyggd AST-parser (lexer och rekursiv parser för en Java- och Kotlin-deluppsättning), så metodbyten av namn mellan filer löses och anropare i andra filer ändras också; knappen för att ta ut ett kodblock till en ny funktion finns nu på den här skärmen. Denna parser är ännu minimal: mycket komplexa generics, parametriserade anteckningar och anonyma klasser skannas som de är, medan anrop via reflektion och gränssnitt inte löses.

Steg-för-steg-felsökare och minnesinspektör
För att granska variabelinnehåll mitt i programflödet utan att gissa från loggar: öppna «Steg-för-steg-felsökare och minnesinspektör» i huvudmenyn, välj projektet, skriv ett körningsspår (en steg per rad, format radnummer, kod, sedan variabler och värden åtskilda med |, till exempel 10|int total = harga * jumlah;|harga=5000, jumlah=3, total=15000), skriv brytpunktsradnumret och tryck sedan på «Kör felsökningsspår». IDE:n kör till det första brytpunkten och läser den aktiva raden högt via Jieshuo med dess variabelvärden. Tryck på «Stega en rad» för att gå en rad framåt, tryck på «Gå in i funktion» för att gå in i en anropad funktion (med anropsstack) eller tryck på «Fortsätt programmet» för att gå till nästa brytpunkt. Den här spårfelsökaren följer fortfarande ett inspelat eller handskrivet spår; bredvid den finns en ren Java-klient för JDWP-trådprotokollet som kan handskakas, sätta brytpunkter, stega in, över och ut och pausa och återuppta VM:n via TCP eller i lyssningsläge. Att pausa en verklig process inifrån en vanlig app är ännu inte helt möjligt, eftersom en process JDWP-sockel endast exponeras via adbd — den bevisade vägen kräver trådlös felsökning och att starta målet via skalet, vilket ligger bortom vad appen själv kan göra.

Offline-beroendehanterare
För att använda tredjepartsbibliotek utan internet och undvika versionskonflikter före bygget: öppna «Offline-beroendehanterare» i huvudmenyn, välj projektet och tryck sedan på «Kontrollera beroenden». IDE:n läser alla .gradle-filer i projektet, kontrollerar det delade valvet mellan projekt i mappen Download/brankas-bersama och löser konflikter — om två bibliotek ber om olika versioner av samma artefakt används den högsta versionen och konflikten rapporteras. För att ladda ned ett bibliotek, skriv dess koordinater (format grupp:artefakt:version, till exempel com.google.code.gson:gson:2.10.1) och tryck sedan på «Kontrollera beroenden»: när man är online laddas AAR-, JAR- eller WHL-filer verkligen ned från Maven, Google eller PyPI med deras transitiva beroendegraf (rekursiv, cykler bryts, djup upp till 25 nivåer), och endast filer som laddats ned framgångsrikt registreras som tillgängliga. När man är offline kan endast bibliotek som redan finns i det delade valvet användas. Maven-versionsintervall löses inte, och nedladdade filer kontrolleras endast med deras SHA-1, utan PGP-verifiering.

Databas- och lagringsinspektör
För att granska och testa innehållet i projektets databas utan att skriva kod som skriver ut tabellinnehåll: öppna «Databas- och lagringsinspektör» i huvudmenyn, välj projektet och databasfilen (.db, .sqlite eller .sqlite3) och tryck sedan på «Öppna databas». IDE:n läser schemat för alla dess tabeller med en fullständig SQLite-sidparser (B-träd med överflödssidor) och visar de första 20 raderna som en texttabell som Jieshuo läser högt. Skriv en SELECT-fråga och tryck på «Kör fråga» (till exempel SELECT nama FROM pengguna WHERE kota = 'Makassar') — frågor stöder nu JOIN, GROUP BY, ORDER BY och LIKE och körs av den verkliga Android SQLite-motorn på telefonen. För att ändra ett värde, skriv radnumret (1 = första raden), kolumnnamnet och det nya värdet och tryck sedan på «Ändra cellvärde» — värdet skrivs tillbaka till .db-filen. Tryck på «Spara säkerhetskopia» för att spara tabellens aktuella tillstånd som en fil <databas-namn>.cadangan.txt i projektet. SharedPreferences och DataStore kan också läsas. Det som ännu inte kan läsas: krypterade databaser, obekräftade WAL-ändringar och typade värden i specialiserade DataStore Proto (visas endast som en allmän fältvy).

Enhetstestfabrik och fuzzing
För att hitta logiska luckor innan appen delas: öppna «Enhetstestfabrik och fuzzing» i huvudmenyn, välj projektet och kodfilen och tryck sedan på «Skapa och kör tester». IDE:n läser funktionssignaturerna i filen, skapar vanliga och gränsfallstestfall (tom text, null, maximala tal, konstiga tecken) och kör sedan verkligen dessa tester: projektkoden kompileras och varje @Test-metod exekveras med en gräns på 5 sekunder, så resultatet är verkliga godkännanden och underkännanden med deras faktiska värden. Fuzzing körs också verkligen på projektfunktioner (via reflektion, 2 sekunder per anrop, högst 20 metoder), och radtäckningsprocenten beräknas verkligen genom instrumentering som bevarar de ursprungliga radnumren. Resultatet rapporterar hur många tester som godkändes och underkändes, hur många kodrader och funktioner som hittades och vilka testfall som skapades. De skapade testerna använder exakt samma API som JUnit, men antecknings- och påståendedefinitionerna skrivs inuti den skapade testfilen, eftersom det verkliga JUnit-biblioteket inte ingår i appen.

Simulator för extrema enhetsförhållanden och minnesläckegranskare
För att testa appens uthållighet när systemet dödar dess process, nätverket bryts, skärmen roteras eller batterisparläge slås på: öppna «Simulator för extrema enhetsförhållanden och minnesläckegranskare» i huvudmenyn, välj projektet och tryck sedan på «Kör simulering». IDE:n kör tre stresscenarier med simulerad skärmrotation och spårar objekt som hålls i minnet även efter att deras skärm stängts, och rapporterar sedan förlorad data och läckande objektkedjor. Spara- och återställningstillståndet läses nu från användarens eget projektkälla, inte från ett fast exempel; den lokala loopback-servern stoppas verkligen mitt i testet för att mäta nätverksavbrottet; en verklig heap-dump tas och analyseras, varvid två dumpar jämförs och hållkedjan spåras från GC-rötterna; och appens egen process dödas verkligen efter att dess tillstånd sparats, varpå det kontrolleras vilken data som kommer tillbaka när den öppnas igen. Det som ännu är omöjligt från en vanlig app: att stänga av telefonens radio eller Wi-Fi och att tvångsstoppa andra appar — båda kräver systembehörighet; istället dödas bakgrundsappar via killBackgroundProcesses, vars behörighet redan finns i manifestet, med en ärlig etikett på skärmen.

Projektplanarkitekt
För att förvandla en stor appidé till en steg-för-steg-arbetsplan: öppna «Projektplanarkitekt» i huvudmenyn, välj projektet, skriv appidén (till exempel en liten livsmedelsbutikskassa-app med avbetalningar) och tryck sedan på «Skapa plan». IDE:n bygger moduler, en fillista och små milstolpar och sparar dem sedan som cetak-biru.txt i projektmappen. Varje gång en milstolpe är klar, tryck på «Markera nästa milstolpe som klar», eller tryck på «Läs in sparad ritning» för att öppna den sparade planen igen. Om en aktiv AI-leverantör är vald i «AI-inställningar» och dess nyckel är tillgänglig byggs planen av den leverantören; om nyckeln saknas eller leverantören inte kan nås faller IDE:n tillbaka till offline-nyckelordsmönster och berättar ärligt om den begränsningen. Leverantörens svar kontrolleras endast för format (moduler och milstolpar finns), inte för innehållssanning — granska alltid planen innan du bygger.

Berättare av kodens logiska flöde
För att förstå lång kod utan att lyssna på syntax rad för rad: öppna «Berättare av kodens logiska flöde» i huvudmenyn, välj projektet och kodfilen och tryck sedan på «Kodberättelse». IDE:n förvandlar varje rad till en indonesisk mening (till exempel om totalen är över 100000, kör nästa block), visar en anropskarta mellan metoder och en dataflödesanalys mellan metoder (värden som skickas vidare, används eller ignoreras) och markerar subtila potentiella buggar med deras radnummer — String jämförd med ==, en ström som öppnas utan att stängas och en variabel som skrivs i två olika metoder. Om en aktiv AI-leverantör är vald i «AI-inställningar» finns också en flödessammanfattning från den leverantören; om den inte finns använder skärmen offlineberättelsen och berättar om den begränsningen. Berättelsen, anropskartan och dataflödet använder offline-textmönsteranalys, inte en fullständig AST-parser — metoder vars öppnande klammer är på sin egen rad, klassfält och anrop via reflektion spåras inte — och varningar om datatävling kan visas för en variabel som faktiskt bara används växelvis.

App-paketfabrik och Play Store-beredskap
För att förbereda en app för Google Play Store direkt från telefonen: öppna «App-paketfabrik och Play Store-beredskap» i huvudmenyn, välj projektet och tryck sedan på «Bygg AAB-paket». IDE:n bygger .aab-filen från projektmanifestet, resurserna och tillgångarna med en verklig BundleConfig.pb, validerar paketstrukturen och delar sedan upp paketet i verkliga variant-APK:er (bas, per arkitektur, per språk och universell) med storlekar uppmätta från den uppdelningen, inte uppskattningar. Paketet signeras med JAR v1 med samma projektnyckel som används för APK-signering, och dess signaturkedja verifieras kryptografiskt. Den här skärmen granskar också Play-beredskap — mål-SDK under 35 markeras «hög», eftersom Play Store kräver 35 eller mer, och ett saknat 64-bitars bibliotek markeras också «hög». Verklig bundletool kan inte köras på enheten, eftersom bundletool kräver en JVM medan Android inte har någon JVM; vägen ovan är den närmaste verkliga vägen på enheten.

OTA-uppdateringsmotor och stegvisa lanseringar
För att skicka en liten rättelse utan att tvinga användare att ladda ned hela APK:n igen: öppna «OTA-uppdateringsmotor och stegvisa lanseringar» i huvudmenyn, välj projektet, skriv det gamla och nya versionsinnehållet och tryck sedan på «Skapa patchpaket». IDE:n beräknar skillnaden och skapar ett patchpaket (patch-ota.zip) med den nya innehållets SHA-256-fingeravtryck och kontrollerar sedan om den här enheten befinner sig i det första 10-procentiga lanseringssteget. Patchar stöder nu binär delta på vilken fil som helst (inklusive DEX och APK), packas med en RSA-2048-signatur och verifieras med en betrodd publik nyckel innan de tillämpas, och kan laddas ned från utvecklarens server med dess lanseringslista; om tillämpningen misslyckas förblir den gamla filen intakt. Att tillämpa en patch på en körande app görs genom omsignering med projektnyckeln och PackageInstaller, eftersom det är omöjligt att ersätta koden för en körande process inifrån sig själv — APK:n är låst och DEX:en är redan laddad.

Teamkodgranskningsstudio
För att granska en kollegas ändringar och lösa sammanslagningskonflikter utan att läsa Git-pilar: öppna «Teamkodgranskningsstudio» i huvudmenyn, välj projektet, skriv tre textversioner (bas, lokal, kollega) och tryck sedan på «Öppna teamgranskning». Diktat av kodstruktur

Standardsignatur per projekt och Anti Tamper
Sedan version 5.7 signeras ett projekt som inte använder en personlig signatur med projektets egen inbyggda nyckel (skapad en gång i mappen tanda-tangan-bawaan inne i projektet och sedan använd vidare), så den inbyggda signaturen skiljer sig från projekt till projekt — inte längre en gemensam nyckel för alla appar. Ta inte bort mappen tanda-tangan-bawaan: utan den nyckeln kan en ny APK inte skriva över den gamla APK:en för samma projekt. Varje projekts inställningar (separat arkitektur, personlig signatur, Anti Tamper, valt keystore, SDK) sparas nu i filen settings.gradle inne i projektet och läses igen varje gång projektet byggs. I Inställningar, kategorin Signatur, finns kryssrutan Anti Tamper för byggd app: om den är aktiv kontrollerar den byggda appen på enheten sin signatur och sitt dex-innehåll varje gång den öppnas; om den har signerats om eller ändrats av någon annan vägrar appen att köras. Felsökare och injektionsverktyg som Frida/Xposed upptäcks också, och appfönstret är låst från skärminspelning.

Nytt utseende i Android Studio-stil
IDE:s utseende har nu gjorts prydligt som Android Studio (bara utseendet — alla knappar, menyer och flöden förblir exakt som tidigare): ljusgrå bakgrund, feta svarta skärmtitlar, blå knappar med vit text och vita inmatningsrutor med tunn ram. Huvudmenyn är visuellt grupperad (Skaparens funktioner, Moln, Tema & annat, Röst, Kod & nya funktioner, Verktyg) utan att ändra knapparnas ordning. Terminalen använder fortfarande en mörk panel som Terminal-fönstret i Android Studio, och kodredigeraren har fortfarande vit bakgrund och svart text. All text läses fortfarande tydligt av Jieshuo.

Inställningar
För att ställa in appen: öppna alternativmenyn på huvudskärmen och tryck sedan på Inställningar. Inuti finns 12 kategorier: GitHub-inställningar (säkerhet, personlig signatur, bygghistorik och GitHub-token), Inställningar för APK-bygge på enheten (spara keystore-lösenord och bygghistorik på enheten), Tema (appfärg), Signatur (skapa keystore för personlig signatur och kryssrutan Anti Tamper för byggd app), Projektmapp (projektmappens plats), Språk och röst (gränssnittsspråk och röstlägets talhastighet), Textstorlek och utseende (redigerarens teckenstorlek), Bygg (standardmål-SDK och standardarkitekturuppdelning för skärmen Skapa projekt), Aviseringar (ljud när bygget är klart), Automatisk säkerhetskopia (schema för projektsäkerhetskopiering), Utvecklarprofil (namn, WhatsApp-nummer och konto som visas på donationsskärmen) och Integritet och data (återställ inställningar och ta bort appdata). Varje kategori har en knapp för Tillbaka till föregående för att återvända till kategorimenyn. Inställningar som just har sparats (ännu inte tillämpats) förklaras ärligt på skärmen.

Donera till utvecklaren
För att donera eller hälsa på utvecklaren: tryck på knappen Donera till utvecklaren på huvudskärmen, bredvid knappen Om verktyget. På donationsskärmen finns knappen Kopiera BRI-konto — tryck på den för att kopiera utvecklarens kontonummer och klistra sedan in det i din bankapp. Det finns också avsnittet Hälsa på utvecklaren på WhatsApp: fyll i ditt namn och din hemstad och tryck sedan på Skicka på WhatsApp — WhatsApp öppnas med hälsningsmeddelandet redan ifyllt, tryck bara på Skicka i WhatsApp och återvänd sedan till appen. WhatsApp tillåter inte andra appar att skicka meddelanden automatiskt, så sändningen görs fortfarande av dig själv i WhatsApp.

Terminalens favoritkommandon
För att spara kommandon som används ofta i Terminal: öppna Terminal och tryck sedan på Favorit. Tryck på Lägg till ny favorit, fyll i namn (till exempel Visa fil) och dess kommando (till exempel ls -la) och tryck sedan på Spara — favoriten sparas permanent på telefonen. Tryck på favoritnamnet för att köra det direkt i terminalen; tryck på Ta bort favorit och välj sedan en att ta bort (med bekräftelse). Det finns redan 3 inbyggda favoriter: Visa fil (ls -la), Kontrollera utrymme (df -h) och Rensa skärmen (clear) — alla kan tas bort. Ett tomt kommando kan varken sparas eller köras; Terminal meddelar dig med meddelande och röst om det händer.

Analys och kvalitet
För att se en sammanfattning av appanvändning och kraschrapporter: tryck på knappen Analys och kvalitet på huvudskärmen, bredvid knappen Donera till utvecklaren. Den här skärmen visar hur många gånger appen har öppnats, vilka skärmar som öppnas oftast, antalet krascher och en lista över de senaste krascherna med korta åtgärdsförslag. Dessa data lagras bara på din telefon och skickas ingenstans. Det finns en knapp för Ta bort analysdata med en bekräftelsedialog för att ta bort alla dessa data. Den senaste skärmen registreras bara för huvudskärmen och den här skärmen.
