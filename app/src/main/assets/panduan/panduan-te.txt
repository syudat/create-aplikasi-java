Create Aplikasi by Al Kautsar కు స్వాగతం
Create Aplikasi అనేది ల్యాప్‌టాప్ అవసరం లేకుండా నేరుగా ఫోన్‌లో నడిచే Android యాప్‌లను తయారు చేసే యాప్. ఈ యాప్ ఎవరైనా తమ సొంత Android యాప్‌ను తయారు చేసుకోవడానికి అనుమతిస్తుంది, ఇందులో యాప్‌లు తయారు చేయడం నేర్చుకోవడం ప్రారంభించిన వినియోగదారులు మరియు స్క్రీన్ రీడర్ వినియోగదారులు కూడా ఉన్నారు. ఈ యాప్‌ను ఉపయోగించడానికి పూర్తి మార్గదర్శి ఈ Tentang Alat స్క్రీన్‌లో అందుబాటులో ఉంది.

ఈ యాప్ ఏమిటి మరియు ఇది ఎవరి కోసం
Create Aplikasi అనేది ఫోన్‌లో నడిచే Android యాప్‌లను తయారు చేసే సాధనం. ఈ యాప్ తమ సొంత Android యాప్‌ను తయారు చేసుకోవాలనుకునే ఎవరి కోసమైనా, ఇందులో ప్రారంభకులు మరియు స్క్రీన్ రీడర్ వినియోగదారులు కూడా ఉన్నారు. ఈ యాప్ ఒక కోడ్ ఎడిటర్‌ను, ప్రాజెక్ట్‌ను పరీక్షించడానికి Jalankan బటన్‌ను, APK ను తయారు చేయడానికి Bangun బటన్‌ను, మరియు APK ను సంతకం చేయడానికి మరియు ఇన్‌స్టాల్ చేయడానికి మెనూలను అందిస్తుంది.

ఈ యాప్ యొక్క ఉద్దేశ్యం
ఎవరైనా సులభంగా, నేరుగా తమ ఫోన్ నుండి తమ సొంత Android యాప్‌ను తయారు చేసుకోగలిగేలా ఈ యాప్ తయారు చేయబడింది. కొత్త వినియోగదారులు కూడా వెంటనే ప్రయత్నించగలిగేలా దీని రూపాన్ని వీలైనంత సరళంగా తయారు చేశారు.

దశలవారీగా కొత్త ప్రాజెక్ట్‌ను ఎలా తయారు చేయాలి
1. ప్రధాన మెనూలో Buat Project నొక్కండి.
2. ప్రాజెక్ట్ రకాన్ని ఎంచుకోండి: HTML, Situs Web, Java, Kotlin, Compose, లేదా Python.
3. యాప్ పేరును నింపండి, ఉదాహరణ: Garuda Decode.
4. ప్యాకేజీ పేరును (package name) నింపండి, ఉదాహరణ: com.android.garudadecode. ప్యాకేజీ పేరు చిన్న అక్షరాలను ఉపయోగించాలి మరియు చుక్కతో వేరు చేయబడిన కనీసం రెండు భాగాలను కలిగి ఉండాలి.
5. యాప్ వెర్షన్‌ను నింపండి, ఉదాహరణ: 1.0, మరియు సంఖ్య రూపంలో వెర్షన్ కోడ్‌ను నింపండి, ఉదాహరణ: 1. ఖాళీగా వదిలితే, వెర్షన్ స్వయంచాలకంగా 1.0 గా మరియు వెర్షన్ కోడ్ 1 గా నింపబడుతుంది.
6. అవసరమైతే కనీస SDK మరియు లక్ష్య SDK ని నింపండి. ఖాళీగా వదిలితే, డిఫాల్ట్ విలువలు ఉపయోగించబడతాయి. కనీస SDK అనేది మద్దతు ఉన్న అత్యల్ప Android వెర్షన్, ఉదాహరణ: 21 అంటే Android 5.0. గరిష్ఠ లక్ష్య SDK 36 (Android 16).
7. యాప్ అనుమతులను ఎంచుకోవడానికి Pilih Izin బటన్‌ను నొక్కండి, ఉదాహరణ: INTERNET. INTERNET అనుమతి డిఫాల్ట్‌గా ఇప్పటికే గుర్తించబడి ఉంటుంది. యాప్‌కు నిజంగా అవసరమైన అనుమతులను మాత్రమే గుర్తించండి.
8. కావాలంటే, APK పరిమాణం చిన్నదిగా ఉండేందుకు "Gunakan arsitektur terpisah 64 bit dan 32 bit" ను గుర్తించండి, మరియు మీ సొంతంగా తయారు చేసిన keystore ను ఉపయోగించాలనుకుంటే "Gunakan tanda tangan pribadi" ను గుర్తించండి.
9. Buat Proyek నొక్కండి. కొత్త ప్రాజెక్ట్ Download/project ఫోల్డర్‌లో సేవ్ చేయబడుతుంది మరియు వెంటనే Kelola Project లో కనిపిస్తుంది.

అందుబాటులో ఉన్న ప్రాజెక్ట్ రకాలు
• HTML: index.html, style.css, మరియు script.js నుండి రూపం, WebView ద్వారా నడుస్తుంది. నేరుగా ఫోన్‌లో తయారు చేయబడుతుంది.
• Situs Web: index.html, tentang.html, kontak.html, style.css, మరియు script.js నుండి మెనూతో (Beranda, Tentang, Kontak) వెబ్‌సైట్, WebView ద్వారా నడుస్తుంది. నేరుగా ఫోన్‌లో తయారు చేయబడుతుంది.
• Java: ఫోన్‌లో తయారు చేయబడుతుంది. MainActivity app/src/main/java/<nama-paket>/MainActivity.java లో ఉంటుంది. రూపం app/src/main/res/layout/activity_main.xml నుండి, వచనం app/src/main/res/values/strings.xml నుండి, మరియు థీమ్ app/src/main/res/values/styles.xml నుండి వస్తుంది.
• Kotlin: యాప్‌లో చేర్చబడిన Kotlin కంపైలర్‌ను ఉపయోగించి పరికరంలో (ఆఫ్‌లైన్‌లో) తయారు చేయవచ్చు, లేదా GitHub Actions ద్వారా తయారు చేయవచ్చు. MainActivity app/src/main/java/<nama-paket>/MainActivity.kt లో ఉంటుంది, మరియు res ఫైళ్లు Java ప్రాజెక్ట్‌లో ఉన్నట్లే ఉంటాయి. కంపైలర్ పెద్ద పరిమాణం కారణంగా మొదటి Kotlin బిల్డ్ నెమ్మదిగా ఉంటుంది, మరియు Kotlin తరగతులను సూచించే .java ఫైళ్లను ఇంకా తయారు చేయలేము (.java ఫైళ్లు .kt ఫైళ్ల కంటే ముందు కంపైల్ చేయబడతాయి).
• Compose: ఇంటర్‌ఫేస్ Jetpack Compose తో తయారు చేయబడిన ఆధునిక Android యాప్ (XML లేఅవుట్ కాదు). MainActivity app/src/main/java/<nama-paket>/MainActivity.kt లో ఉంటుంది. Compose కు పరికరంలో అందుబాటులో లేని Jetpack Compose లైబ్రరీలు అవసరం కాబట్టి, Compose ప్రాజెక్ట్‌లు GitHub Actions ద్వారా (Bangun proyek మెనూ, తరువాత Bangun online) లేదా Termux లో Gradle తో తయారు చేయబడతాయి.
• Python: యాప్ తర్కం Python భాషలో (Chaquopy) app/src/main/python/main.py లో వ్రాయబడుతుంది, మరియు app/src/main/java/<nama-paket>/MainActivity.java లోని హోస్ట్ MainActivity.java ద్వారా నడపబడుతుంది. Python ప్రాజెక్ట్‌లను నేరుగా ఫోన్‌లో తయారు చేయవచ్చు (Chaquopy రన్‌టైమ్ యాప్‌లో చేర్చబడింది) లేదా GitHub Actions ద్వారా కూడా తయారు చేయవచ్చు. Python ప్రాజెక్ట్‌లకు కనీస SDK 24 (Android 7.0).

Java, HTML, Situs Web, Kotlin, Compose, మరియు Python ప్రాజెక్ట్‌ల ఫైల్ అమరిక
Java, HTML, Situs Web, Kotlin, Compose, మరియు Python ప్రాజెక్ట్‌లు సాధారణంగా Android ప్రాజెక్ట్‌ల లాగే అమర్చబడి ఉంటాయి. app ఫోల్డర్ లోపల src ఫోల్డర్ ఉంటుంది, దాని లోపల main ఫోల్డర్ ఉంటుంది. main ఫోల్డర్ లోపల java ఫోల్డర్ పక్కన AndroidManifest.xml ఉంటుంది, layout/activity_main.xml మరియు values/strings.xml మరియు values/styles.xml లను కలిగి ఉన్న res ఫోల్డర్ ఉంటుంది, మరియు HTML మరియు Situs Web కోసం index.html ను కలిగి ఉన్న assets ఫోల్డర్ ఉంటుంది (Situs Web లో tentang.html మరియు kontak.html కూడా ఉంటాయి). HTML మరియు Situs Web ప్రాజెక్ట్‌లకు కూడా app/src/main/java/<nama-paket>/MainActivity.java లో తమ సొంత MainActivity ఉంటుంది, ఇది WebView లో index.html ను లోడ్ చేస్తుంది మరియు AndroidManifest లో లాంచర్‌గా ఉంటుంది. Python ప్రాజెక్ట్‌లలో Python కోడ్ app/src/main/python/main.py లో మరియు హోస్ట్ MainActivity.java app/src/main/java/<nama-paket>/MainActivity.java లో ఉంటుంది. AndroidManifest.xml, లేఅవుట్, strings, మరియు styles లను MainActivity లాగే ఎడిటర్‌లో తెరిచి మార్చవచ్చు. మానిఫెస్ట్ ఇంకా app ఫోల్డర్ పక్కన ఉన్న పాత ప్రాజెక్ట్‌లను కూడా తయారు చేయవచ్చు, ఎందుకంటే తయారు చేసేటప్పుడు, యాప్ ముందుగా app/src/main/ లో AndroidManifest.xml ను తనిఖీ చేస్తుంది, తరువాత app ఫోల్డర్ పక్కన ఉన్నదాన్ని, చివరగా ప్రాజెక్ట్ డేటా ఫైల్‌ను తనిఖీ చేస్తుంది.

అనుమతి నియమాలు (ముఖ్యం)
ప్రాజెక్ట్‌ను తయారు చేసేటప్పుడు గుర్తించిన అనుమతులు, ప్రాజెక్ట్ రకాన్ని బట్టి, ఒకే ఒక్క చోట మాత్రమే నమోదు చేయబడతాయి. Java, HTML, Situs Web, Kotlin, Compose, మరియు Python ప్రాజెక్ట్‌ల కోసం, గుర్తించిన అనుమతులు ప్రాజెక్ట్ ఫోల్డర్ లోపల, java ఫోల్డర్ పక్కన, app/src/main/ లో ఉన్న AndroidManifest.xml లో మాత్రమే నమోదు చేయబడతాయి. Java, HTML, Situs Web, Kotlin, Compose, మరియు Python ప్రాజెక్ట్‌ల కోసం ప్రాజెక్ట్ డేటా ఫైల్‌లో అనుమతుల జాబితా ఉండదు. మీరు Java ను ఎంచుకుని INTERNET మరియు CAMERA లను గుర్తిస్తే, AndroidManifest.xml లో నమోదయ్యేది INTERNET మరియు CAMERA మాత్రమే, వేరే అనుమతి ఏదీ చేరదు. తయారు చేసేటప్పుడు, యాప్ అదే చోట నుండి అనుమతులను చదువుతుంది: Java, HTML, Situs Web, Kotlin, Compose, మరియు Python ప్రాజెక్ట్‌ల కోసం app/src/main/ లోని AndroidManifest.xml నుండి (లేకపోతే, పాత ప్రాజెక్ట్‌ల కోసం app ఫోల్డర్ పక్కన ఉన్న AndroidManifest.xml నుండి), మరియు పాత ప్రాజెక్ట్‌ల కోసం ప్రాజెక్ట్ డేటా ఫైల్ నుండి.

ఎడిటర్‌ను ఎలా ఉపయోగించాలి
Kelola Project ను తెరిచి, ఎడిటర్‌ను తెరవడానికి ప్రాజెక్ట్ పేరును నొక్కండి. ఎడిటర్‌లో, ఫైళ్లను తెరవవచ్చు, కోడ్ వ్రాయవచ్చు, మరియు మార్పులను సేవ్ చేయవచ్చు. Java, HTML, Situs Web, Kotlin, Compose, మరియు Python ప్రాజెక్ట్‌ల కోసం, ఫైళ్లు app/src/main ఫోల్డర్ లోపల అమర్చబడి ఉంటాయి. ప్రాజెక్ట్‌ను పంచుకోవడానికి, Ekspor ZIP ను ఉపయోగించండి (క్రింది విభాగాన్ని చూడండి).

ప్రాజెక్ట్‌ను ఎలా నడపాలి
ఎడిటర్‌లో, ప్రాజెక్ట్‌ను పరీక్షించడానికి Jalankan నొక్కండి. HTML మరియు Situs Web ప్రాజెక్ట్‌ల కోసం, నడపబడేది WebView ద్వారా index.html. లోపం సంభవిస్తే, లోప సందేశాన్ని చదివి, కోడ్‌ను సరిచేసి, మళ్లీ నడపండి.

APK ను ఎలా తయారు చేయాలి
ఎడిటర్‌లో, Bangun నొక్కండి. తయారు చేయడానికి రెండు మార్గాలు ఉన్నాయి. మొదటిది, Bangun di perangkat: ఇంటర్నెట్ లేకుండా నేరుగా ఫోన్‌లో తయారు చేయడం, HTML, Situs Web, Java, Kotlin, మరియు Python ప్రాజెక్ట్‌ల కోసం. రెండవది, GitHub Actions ద్వారా Bangun online: ఇంటర్నెట్ ద్వారా GitHub లో తయారు చేయడం, మరియు అన్ని రకాల ప్రాజెక్ట్‌ల కోసం ఉపయోగించవచ్చు. Compose కు పరికరంలో అందుబాటులో లేని Jetpack Compose లైబ్రరీలు అవసరం కాబట్టి, Compose ప్రాజెక్ట్‌లను రెండవ మార్గంలో (Bangun online) లేదా Termux లో Gradle తో మాత్రమే తయారు చేయవచ్చు. మొదటి బిల్డ్ ఫలితం ఇంకా సంతకం చేయబడలేదు. ఆ తరువాత యాప్ దానిని సంతకం చేస్తుంది: డిఫాల్ట్ కీతో స్వయంచాలకంగా, లేదా ప్రాజెక్ట్‌ను తయారు చేసేటప్పుడు "Gunakan tanda tangan pribadi" పెట్టె గుర్తించబడి ఉంటే వ్యక్తిగత సంతకంతో.

APK ను ఎలా ఇన్‌స్టాల్ చేయాలి
APK సిద్ధమైన తరువాత, దానిని ఇన్‌స్టాల్ చేయడానికి Pasang నొక్కండి. Android 8 మరియు అంతకంటే ఎక్కువ వాటిలో, ఈ యాప్ Play Store వెలుపల నుండి APK లను ఇన్‌స్టాల్ చేస్తుంది కాబట్టి, ఫోన్ ముందుగా "Izinkan dari sumber ini" అని అడుగుతుంది. Pengaturan లో ఆ అనుమతిని ఒకసారి ప్రారంభించి, యాప్‌కు తిరిగి రండి: Pasang ను మళ్లీ నొక్కాల్సిన అవసరం లేకుండా ఇన్‌స్టాలేషన్ స్వయంచాలకంగా కొనసాగుతుంది. Pasang బటన్ కనిపించకపోతే, బిల్డ్ పూర్తయిందని మరియు APK తయారు చేయబడిందని నిర్ధారించుకోండి.

యాప్‌లో ఎలా సంతకం చేయాలి
ప్రతి APK ఇన్‌స్టాల్ చేయబడటానికి సంతకం చేయబడాలి. రెండు ఎంపికలు ఉన్నాయి. మొదటిది, డిఫాల్ట్ కీ: మీరు ఏమీ చేయాల్సిన అవసరం లేకుండా, యాప్ స్వయంచాలకంగా సంతకం చేస్తుంది. రెండవది, వ్యక్తిగత సంతకం: ముందుగా ప్రధాన మెనూలోని Buat Keystore మెనూ ద్వారా keystore ను తయారు చేయండి, దాని పాస్‌వర్డ్‌ను భద్రంగా ఉంచండి, తరువాత ప్రాజెక్ట్‌ను తయారు చేసేటప్పుడు "Gunakan tanda tangan pribadi" ను గుర్తించండి. Keystore Download/project/signing లో సేవ్ చేయబడుతుంది.

ప్రాజెక్ట్‌ను ZIP గా ఎగుమతి చేయడం
ప్రాజెక్ట్‌లను స్నేహితులతో పంచుకోగలిగేలా Ekspor ZIP అందించబడింది. విధానం: Kelola Project లో, ప్రాజెక్ట్ పేరును ఎక్కువ సేపు నొక్కి పట్టుకుని, తరువాత Ekspor ZIP ను ఎంచుకోండి. ఫలితం Download/project/<NamaProyek>.zip లో సేవ్ చేయబడుతుంది. bin ఫోల్డర్ చేర్చబడదు కాబట్టి, పరిమాణం చిన్నది, కేవలం కొన్ని పదుల KB మాత్రమే. ఆ ZIP ఫైల్‌ను స్నేహితునికి పంపవచ్చు లేదా GitHub కు అప్‌లోడ్ చేయవచ్చు.

JAWS పొడిగింపు
JAWS పొడిగింపు Jieshuo (CSR) యొక్క పొడిగింపు ఇంజిన్‌ను ఉపయోగిస్తుంది, దాని స్క్రీన్ రీడర్‌ను కాదు. దీని వల్ల, వినియోగదారు TalkBack ను ఉపయోగిస్తున్నప్పటికీ రూపకల్పన నడవగలదు. విధానం: ప్రధాన మెనూలో Ekstensi JAWS ను తెరవండి. స్వయంచాలక క్లిక్ స్వయంగా నడుస్తుంది కాబట్టి, సేవను ముందుగా Pengaturan Aksesibilitas లో ప్రారంభించాలి. ఆ తరువాత, కొత్త రూపకల్పనను తయారు చేయవచ్చు: రూపకల్పన పేరును టైప్ చేసి, OK నొక్కి, తరువాత దాని పెట్టెలను నింపండి.

చక్కగా ఉండేందుకు Daftar Klik వేరు చేయబడింది
రూపకల్పన లోపల రెండు పెట్టెలు ఉన్నాయి: స్క్రిప్ట్ పెట్టె మరియు Daftar Klik పెట్టె. బటన్‌ల జాబితా daftar_klik.txt ఫైల్‌లో విడిగా సేవ్ చేయబడుతుంది, ఒక పంక్తికి ఒక పేరు. దాని విషయాల ఉదాహరణ: tombolSimpan, tombolHapus, tombolBuka. యాప్‌ను తెరవడానికి, ఆ జాబితాలో కేవలం >WhatsApp అని వ్రాయండి. ఇంకా daftar_klik.txt ఫైల్ లేని పాత రూపకల్పనలు ఆ డిఫాల్ట్ ఉదాహరణను చూపిస్తాయి.

అందించబడిన సరళమైన ఫంక్షన్‌లు
• klikTombol("tombolSimpan") — దాని వచనం ఆధారంగా ఒక బటన్‌ను క్లిక్ చేస్తుంది.
• klikDaftarTombol(daftar) — daftar_klik.txt లోని జాబితాను క్లిక్ చేస్తుంది, ఒక పంక్తికి ఒక బటన్, క్రమంలో, తరువాత ఎన్ని విజయవంతమయ్యాయో మరియు ఎన్ని కనుగొనబడలేదో తెలియజేస్తుంది.
• bukaAplikasi("WhatsApp") — దాని పేరు ద్వారా యాప్‌ను తెరుస్తుంది, లేదా జాబితాలో ">WhatsApp" అని వ్రాయండి.
• klik(540, 1200) — స్క్రీన్ కోఆర్డినేట్‌ల వద్ద క్లిక్ చేస్తుంది.
అన్ని ఫంక్షన్‌లు ముందుగా సరళంగా తయారు చేయబడ్డాయి. అలవాటు పడిన తరువాత, అదనపు ఫంక్షన్‌లను తరువాత జోడించవచ్చు.

స్క్రీన్ రీడర్ గురించి
ఈ యాప్ స్క్రీన్ రీడర్‌కు అనుకూలంగా ఉండేలా రూపొందించబడింది. ప్రతి ఇన్‌పుట్ ఫీల్డ్‌కు ఒక లేబుల్ మరియు నింపే ఉదాహరణ ఉంటుంది, మరియు అన్ని బటన్‌లను సంక్లిష్ట సంజ్ఞలు లేకుండా చేరుకోవచ్చు. JAWS పొడిగింపు వినియోగదారు TalkBack ను ఉపయోగిస్తున్నప్పటికీ నడిచేలా తయారు చేయబడింది, ఎందుకంటే ఉపయోగించేది దాని పొడిగింపు ఇంజిన్, దాని స్క్రీన్ రీడర్ కాదు.

గోప్యత మరియు భద్రత
ప్రాజెక్ట్‌లు మరియు keystore మీ ఫోన్‌లో సేవ్ చేయబడతాయి. GitHub టోకెన్ ఆన్‌లైన్ బిల్డ్‌ల కోసం మాత్రమే ఉపయోగించబడుతుంది మరియు ఈ యాప్ లోపల సేవ్ చేయబడుతుంది. మీ టోకెన్ లేదా keystore పాస్‌వర్డ్‌ను ఎవరితోనూ పంచుకోవద్దు. వ్యక్తిగత సంతకాన్ని ఉపయోగిస్తే, keystore ను మరియు దాని పాస్‌వర్డ్‌ను సురక్షితమైన చోట ఉంచండి, ఎందుకంటే అవి పోతే, పాత APK ను అదే సంతకంతో నవీకరించలేము.

అవసరాలు
Android 5.0 లేదా అంతకంటే కొత్తది. నిల్వ అనుమతి: Android 11 మరియు అంతకంటే ఎక్కువ వాటిలో అన్ని ఫైళ్ల యాక్సెస్ అనుమతిని ఉపయోగిస్తుంది, Android 10 మరియు అంతకంటే తక్కువ వాటిలో సాధారణ నిల్వ అనుమతిని (నిల్వను చదవడం/వ్రాయడం) ఉపయోగిస్తుంది ఎందుకంటే Android 10 లో అన్ని ఫైళ్ల యాక్సెస్ అనుమతి లేదు. పరికరంలో తయారు చేయడానికి ARM ప్రాసెసర్ (32 లేదా 64 బిట్) ఉన్న ఫోన్ అవసరం. GitHub Actions ద్వారా ఆన్‌లైన్‌లో తయారు చేయడానికి ఇంటర్నెట్ మరియు GitHub టోకెన్ అవసరం. Kotlin ప్రాజెక్ట్‌లను పరికరంలో తయారు చేయవచ్చు, కానీ Kotlin కంపైలర్ పెద్ద పరిమాణం కారణంగా దాని మొదటి బిల్డ్ నెమ్మదిగా ఉంటుంది మరియు ఎక్కువ మెమరీని ఉపయోగిస్తుంది. Compose ప్రాజెక్ట్‌లు GitHub Actions ద్వారా లేదా Termux లో Gradle తో తయారు చేయబడతాయి. Python ప్రాజెక్ట్‌లకు Android 7.0 లేదా అంతకంటే కొత్తది (కనీస SDK 24) అవసరం మరియు ఫలిత APK పెద్దదిగా ఉంటుంది ఎందుకంటే దానిలో Python రన్‌టైమ్ (Chaquopy) మరియు దాని ప్రామాణిక లైబ్రరీ ఉంటాయి.

Terminal
ప్రధాన స్క్రీన్‌లోని Terminal మెనూ ఈ యాప్ లోపల టెర్మినల్‌ను తెరుస్తుంది. ప్రాజెక్ట్ ఫోల్డర్ విషయాలను చూడటానికి ls, ఫోల్డర్‌లను మార్చడానికి cd, మరియు కోడ్‌ను నిర్వహించడానికి git వంటి ఆదేశాలను ఉపయోగించవచ్చు. ఆదేశాల అవుట్‌పుట్ స్క్రీన్ రీడర్ చదవగలిగే వచనంగా కనిపిస్తుంది, మరియు చివరి ఫలితాన్ని వినడానికి Bacakan hasil బటన్ ఉంటుంది. ఈ టెర్మినల్ ఫోన్ యొక్క సిస్టమ్ షెల్‌ను ఉపయోగిస్తుంది, కాబట్టి nano మరియు vim వంటి ఇంటరాక్టివ్ ప్రోగ్రామ్‌లను ఇక్కడ ఇంకా ఉపయోగించలేము.

క్రాష్ శవపరీక్ష
ప్రత్యేక ID ఉన్న క్రాష్ లాగ్ నుండి యాప్ ఎందుకు తనంతట తాను మూసుకుంటుందో తెలుసుకోవడానికి: ప్రధాన మెనూలో క్రాష్ శవపరీక్ష తెరిచి, లాగ్ జాబితా నుండి క్రాష్ ID ఎంచుకుని, ఆపై తనిఖీ చేయండి నొక్కండి. IDE లాగ్‌లోని క్లాస్ మరియు లైన్ నంబర్‌ను ప్రాజెక్ట్ మూలంతో సరిపోల్చి, కారణాన్ని ఇండోనేషియా భాషలో వివరిస్తుంది (ఉదాహరణకు ఖాళీ రిఫరెన్స్, ఇంకా అడగని అనుమతి, లేదా JSON లోపం), కోడ్ ప్యాచ్ సూచనతో పాటు. మూల లైన్ క్రాష్ జరిగినప్పుడు ఉన్నట్లుగానే ఇంకా ఉంటే మాత్రమే ప్యాచ్‌ను వర్తింపజేయి నొక్కండి; మారితే, ప్యాచ్ తిరస్కరించబడుతుంది మరియు IDE మిమ్మల్ని మీరే తనిఖీ చేయమని అడుగుతుంది. చదవబడేది IDE యొక్క స్వంత క్రాష్ లాగ్, నిర్మించిన యాప్ లాగ్ కాదు.

క్రాస్-పారడైమ్ ట్రాన్స్‌పైలర్
సాధారణ Java కోడ్‌ను Kotlin గా, లేదా సాధారణ XML లేఅవుట్‌ను Compose కోడ్‌గా మార్చడానికి: ప్రధాన మెనూలో క్రాస్-పారడైమ్ ట్రాన్స్‌పైలర్ తెరిచి, ప్రాజెక్ట్ మరియు ఫైల్ ఎంచుకుని, ఆపై ప్రివ్యూ నొక్కండి. IDE మార్పిడి ఫలితాన్ని టెక్స్ట్‌గా చూపుతుంది — ముందుగా తనిఖీ చేయండి, ఎందుకంటే అది గుర్తించని లైన్లు అలాగే ఉంచబడతాయి మరియు Java లోని static అనే పదం Kotlin లో తొలగించబడుతుంది (ఉపయోగించే ముందు దాని అర్థం తనిఖీ చేయండి). XML నుండి Compose కు మార్పిడి టెక్స్ట్, హింట్ మరియు ఓరియంటేషన్‌ను మాత్రమే మారుస్తుంది — పరిమాణం, రంగు మరియు ఇతర లక్షణాలు ఇంకా చేర్చబడలేదు. ఫలితం సరైనదైతే, లక్ష్య ఫైల్ రాయడానికి ఫైల్‌కు వర్తింపజేయి నొక్కండి; మూల ఫైల్ మార్చబడదు. సురక్షితమైన, సాధారణ నమూనాలు మాత్రమే మార్చబడతాయి.

స్థానిక మైక్రో సర్వర్
ఇంటర్నెట్ లేకుండా సర్వర్ అవసరమయ్యే యాప్‌ను పరీక్షించడానికి: ప్రధాన మెనూలో స్థానిక మైక్రో సర్వర్ తెరిచి, రూట్ నిర్వచనం రాయండి (ఉదాహరణకు GET /halo ఆపై దాని JSON సమాధానం), ఆపై సర్వర్ ప్రారంభించు నొక్కండి. IDE అదే ఫోన్‌లో చిన్న HTTP సర్వర్‌ను నడుపుతుంది (HTTP మాత్రమే, TLS లేకుండా, అదే Wi-Fi నెట్‌వర్క్ కోసం) మరియు ప్రతి అభ్యర్థన మరియు సమాధానాన్ని స్క్రీన్‌పై నమోదు చేస్తుంది. రూట్లు {nama} వంటి పారామీటర్లు మరియు సాధారణ API కీని ఉపయోగించవచ్చు. ఈ సర్వర్ ఫోన్‌లో పరీక్షించడానికి మాత్రమే; నిర్మించిన APK ఇంకా సర్వర్ కాలేదు, మరియు దాని స్క్రీన్ మూసివేస్తే సర్వర్ ఆగిపోతుంది.

భద్రతా ఆడిటర్
విడుదలకు ముందు ప్రాజెక్ట్ కోడ్‌లో భద్రతా లోపాలను తనిఖీ చేయడానికి: ప్రధాన మెనూలో భద్రతా ఆడిటర్ తెరిచి, ప్రాజెక్ట్ ఎంచుకుని, ఆపై స్కాన్ ప్రారంభించు నొక్కండి. IDE కోడ్, మానిఫెస్ట్ మరియు ప్రాజెక్ట్ కాన్ఫిగరేషన్‌ను స్కాన్ చేసి, ఎక్కువ ప్రమాదం నుండి తక్కువ ప్రమాదం వరకు ఫలితాలను నివేదిస్తుంది — కోడ్‌లో బహిర్గతమైన API కీలు, అనుమతి లేకుండా బహిర్గతమైన భాగాలు, JavaScript ఇంటర్‌ఫేస్‌తో పాటు JavaScript ను ప్రారంభించే WebView, బలహీనమైన క్రిప్టో (MD5, SHA1, DES), TLS లేని http చిరునామాలు, మరియు కోడ్‌లో నేరుగా రాసిన పాస్‌వర్డ్‌లు — ప్రతి దాని ఫైల్ మరియు లైన్ నంబర్‌తో పాటు. సురక్షిత పరిష్కారం ఉన్న ఫలితాలకు (ఉదాహరణకు MD5 ను SHA-256 గా లేదా http ను https గా మార్చడం) పరిష్కారాన్ని వర్తింపజేయి నొక్కండి; API కీలు మరియు పాస్‌వర్డ్‌ల కోసం IDE సూచించిన పరిష్కారాన్ని మాత్రమే చూపుతుంది, ఎందుకంటే ప్రత్యామ్నాయాన్ని డెవలపర్ స్వయంగా నిర్ణయించాలి. ఈ స్కాన్ కోడ్‌లోని టెక్స్ట్ నమూనాలను చదువుతుంది, బైట్‌కోడ్‌ను కాదు, కాబట్టి కొన్ని ఫలితాలు వాస్తవానికి సురక్షితంగా ఉండవచ్చు, మరియు నమూనా లేని లోపం స్కాన్ నుండి తప్పించుకోవచ్చు — వర్తింపజేసే ముందు తనిఖీ చేయండి.

ఇంటర్‌ఫేస్ పరీక్ష రోబోట్
టెక్స్ట్ సన్నివేశాలతో యాప్ రూపాన్ని ఆటోమేటిక్‌గా పరీక్షించడానికి: ప్రధాన మెనూలో ఇంటర్‌ఫేస్ పరీక్ష రోబోట్ తెరిచి, ప్రాజెక్ట్ ఎంచుకుని, ఆపై ఆటోమేటిక్ సన్నివేశాన్ని సృష్టించు నొక్కండి. IDE ప్రాజెక్ట్ మానిఫెస్ట్ మరియు లేఅవుట్‌లను చదివి, టెక్స్ట్ దశల సన్నివేశాన్ని రాస్తుంది (బటన్ నొక్కండి, ఫీల్డ్ నింపండి, వేచి ఉండండి, వెనక్కి వెళ్లండి). సన్నివేశ అమలు లాగ్‌ను టైమ్‌స్టాంప్‌లతో చూడటానికి డ్రై రన్ అమలు చేయి నొక్కండి. ఈ దశలో రోబోట్ అనుకరణను మాత్రమే అమలు చేస్తుంది (డ్రై రన్) — ఫోన్‌లో బటన్‌లను నిజంగా నొక్కడం మరియు నిజమైన క్రాష్‌లను పట్టుకోవడం తదుపరి దశ, కాబట్టి ఇక్కడ క్రాష్ నివేదిక ఇంకా నమూనా ఆకృతిలోనే ఉంది.

కోడ్ సమయ ప్రయాణం
Git ఆదేశాలను టైప్ చేయకుండా ప్రాజెక్ట్‌ను మునుపటి కోడ్ స్థితికి తిరిగి తీసుకురావడానికి: ప్రధాన మెనూలో కోడ్ సమయ ప్రయాణం తెరిచి, ప్రాజెక్ట్ ఎంచుకుని, సమయ బిందువు లేబుల్ నింపి (ఖాళీగా ఉండవచ్చు), ఆపై సమయ బిందువును రికార్డ్ చేయి నొక్కండి. IDE ప్రాజెక్ట్ మూల ఫైళ్ల కాపీని వాటి hash లతో పాటు ప్రాజెక్ట్‌లోని .riwayat ఫోల్డర్‌లో భద్రపరుస్తుంది. సమయ బిందువుల జాబితా అన్నింటినీ చూపుతుంది; రెండు బిందువులు ఎంచుకుని, ఆపై జోడించిన, మార్చిన లేదా తొలగించిన ఫైళ్లు మరియు ఫంక్షన్‌లను చూడటానికి పోల్చండి నొక్కండి. పాత స్థితిని తిరిగి పొందడానికి పునరుద్ధరించండి నొక్కండి — పునరుద్ధరించే ముందు IDE ఎల్లప్పుడూ ముందుగా ప్రస్తుత స్థితి బ్యాకప్ తీసుకుంటుంది, కాబట్టి ఏమీ కోల్పోరు. అసలు ప్రాజెక్ట్‌ను ఇబ్బంది పెట్టకుండా మార్పులను ప్రయత్నించడానికి ప్రాజెక్ట్‌ను కొత్త ఫోల్డర్‌కు కాపీ చేయడానికి ప్రయోగ నకలును సృష్టించు నొక్కండి. మూల ఫైళ్లు మాత్రమే రికార్డ్ చేయబడతాయి.

మాడ్యూల్ ఫ్యాక్టరీ
ప్రాజెక్ట్‌లోని ఒక భాగాన్ని మరొక ప్రాజెక్ట్ ఉపయోగించగల మాడ్యూల్‌గా ప్యాక్ చేయడానికి: ప్రధాన మెనూలో మాడ్యూల్ ఫ్యాక్టరీ తెరిచి, మూల ప్రాజెక్ట్ ఎంచుకుని, ప్యాక్ చేయాల్సిన స్క్రీన్, క్లాస్, స్ట్రింగ్ మరియు అనుమతి ఫైళ్లను టిక్ చేసి, ఆపై మాడ్యూల్‌గా ప్యాక్ చేయి నొక్కండి. IDE JSON మెటాడేటా (మాడ్యూల్ పేరు, వెర్షన్, ఉపయోగించిన స్ట్రింగ్‌లు మరియు అనుమతులు) తో పాటు ZIP ఆర్కైవ్‌ను రాస్తుంది. మాడ్యూల్‌ను మరొక ప్రాజెక్ట్‌లో ఇన్‌స్టాల్ చేయడానికి మాడ్యూల్ ఫ్యాక్టరీ తెరిచి, లక్ష్య ప్రాజెక్ట్ ఎంచుకుని, ఆపై మాడ్యూల్‌ను ఇన్‌స్టాల్ చేయి నొక్కి మాడ్యూల్ .zip ఫైల్ ఎంచుకోండి — విలీనం ఇప్పటికే ఉన్న కోడ్‌ను ఓవర్‌రైట్ చేయకుండా స్ట్రింగ్‌లు మరియు అనుమతులను జోడిస్తుంది, మరియు ఫైల్ పేరు లక్ష్య ప్రాజెక్ట్‌లో ఇప్పటికే ఉపయోగించబడితే ఆ ఫైల్‌ను విలీనం చేయదు. మాడ్యూల్ లైబ్రరీలు లేదా బిల్డ్ సెట్టింగ్‌లను తీసుకురాదు.

బహురూప కవచం మరియు ఆస్తి ఖజానా
విడుదలకు ముందు గుర్తింపు పేర్లను యాదృచ్ఛికం చేసి ప్రాజెక్ట్ ఆస్తులను గుప్తీకరించడానికి: ప్రధాన మెనూలో బహురూప కవచం మరియు ఆస్తి ఖజానా తెరిచి, ప్రాజెక్ట్‌ను ఎంచుకుని, పేర్లను యాదృచ్ఛికం చేసి ఆస్తులను గుప్తీకరించు నొక్కండి. IDE మూల కోడ్‌లోని తరగతి మరియు పద్ధతి పేర్లను స్కాన్ చేసి, యాదృచ్ఛిక పేర్ల పటాన్ని తయారు చేసి, ప్రాజెక్ట్ ఆస్తి ఫైళ్లను AES-GCM తో ప్రాజెక్ట్‌లోని brankas-aset ఫోల్డర్‌లో గుప్తీకరించి, గుప్తీకరించిన పునరుద్ధరణ పటాన్ని (perisai-peta.brankas) భద్రపరుస్తుంది, తద్వారా క్రాష్ లాగ్‌లను చదివేటప్పుడు అసలు పేర్లను పునరుద్ధరించవచ్చు. గుప్తీకరణ కీ ప్రాజెక్ట్ పేరు నుండి తయారవుతుంది, కాబట్టి ప్రాజెక్ట్ పేరు తెలిసిన ఎవరైనా ఖజానాను తెరవవచ్చు — ఇది తేలికపాటి చదవడం నుండి రక్షణ, పాస్‌వర్డ్‌తో తాళం వేసిన ఖజానా కాదు. ఇక్కడ తయారయ్యేది పేర్ల పటం మరియు ఆస్తి ఖజానా; కంపైల్ చేసిన DEX ఫైల్‌లోపల పేర్లను తిరిగి రాయడం తర్వాతి దశ, కాబట్టి సిద్ధమైన APK లోపలి పేర్లు ఇంకా యాదృచ్ఛికం కాలేదు.

విశ్వాస గొలుసు మరియు వాతావరణ సంరక్షకుడు
విడుదలకు ముందు సంతకం కీ గొలుసు మరియు ఫోన్ వాతావరణాన్ని తనిఖీ చేయడానికి: ప్రధాన మెనూలో విశ్వాస గొలుసు మరియు వాతావరణ సంరక్షకుడు తెరిచి, ప్రాజెక్ట్‌ను ఎంచుకుని, గొలుసు మరియు వాతావరణాన్ని తనిఖీ చేయండి నొక్కండి. IDE ప్రాజెక్ట్ ప్యాకేజీ పేరు నుండి 5 తరాల కీ గొలుసును నిర్మించి దాని సమగ్రతను తనిఖీ చేసి, తర్వాత తన స్వంత ప్రక్రియ మెమరీ పటాన్ని మరియు పరికర లక్షణాలను Frida, Xposed లేదా ఎమ్యులేటర్ జాడల కోసం స్కాన్ చేస్తుంది. ఫలితం సురక్షితం, జాగ్రత్త, లేదా ప్రమాదకరం అనే ప్రమాద స్థాయి, వచన సాక్ష్యంతో. ఈ తనిఖీ మెమరీ పటంలో మరియు వ్యవస్థ లక్షణాలలో వచన నమూనాలను చదువుతుంది, స్థానిక లైబ్రరీ స్థాయిలో ముడి మెమరీ సమగ్రతను కాదు, మరియు కీలను హార్డ్‌వేర్ భద్రతా చిప్‌కు బంధించదు — తన వచన జాడలను దాచే ఇంజెక్షన్ సాధనం ఈ స్కాన్ నుండి తప్పించుకోవచ్చు.

టెక్స్ట్ ట్రీ లేఅవుట్ వాస్తుశిల్పి
స్క్రీన్‌ను చూడకుండా స్క్రీన్‌ను రూపొందించడానికి: ప్రధాన మెనూలో టెక్స్ట్ ట్రీ లేఅవుట్ వాస్తుశిల్పి తెరిచి, ప్రాజెక్ట్ మరియు లేఅవుట్ ఫైల్‌ను ఎంచుకుని, లేఅవుట్‌ను తనిఖీ చేయండి నొక్కండి. IDE XML లేఅవుట్‌ను వచన వృక్షంగా చదివి, ప్రతి మూలకం స్థాన వివరణను గట్టిగా చదువుతుంది (ఉదాహరణకు కుడి దిగువన, స్క్రీన్ వెడల్పులో 45 శాతం), తర్వాత 360 dp వెడల్పు వద్ద మూలకాల మధ్య ఘర్షణలను మరియు స్క్రీన్ వెలుపలికి వెళ్లే మూలకాలను గణితంగా నివేదిస్తుంది. లెక్కించబడేది LinearLayout మరియు సాధారణ dp కొలతలు; ConstraintLayout మరియు Compose స్క్రీన్‌ల స్థానం అనిశ్చితంగా నివేదించబడుతుంది, ఊహించబడదు.

డిజైన్ సిస్టమ్ స్టూడియో
అన్ని స్క్రీన్‌లు మరియు ప్రాజెక్ట్‌లలో దూరం, అక్షరం మరియు మూలలను ఒకేలా చేయడానికి: ప్రధాన మెనూలో డిజైన్ సిస్టమ్ స్టూడియో తెరిచి, ప్రాజెక్ట్‌ను ఎంచుకుని, డిజైన్ టోకెన్‌లను రాయండి (ఉదాహరణకు jarak=8, huruf=16, sudut=12), భాగాన్ని ఎంచుకుని, భాగాలను సృష్టించు నొక్కండి. IDE టోకెన్‌లను ధృవీకరిస్తుంది — ప్రాథమిక దూరం 4 నుండి 16 dp, ప్రాథమిక అక్షరం 12 నుండి 20 sp, మూలలు 0 నుండి 32 dp, మరియు కనీస స్పర్శ ప్రాంతం 48 dp — తర్వాత ఉపయోగానికి సిద్ధమైన XML భాగాలను (komponen-studio.xml) XML థీమ్ (tema-studio.xml) మరియు Compose థీమ్ (tema-studio.kt) తో ప్రాజెక్ట్ ఫోల్డర్‌లో రాస్తుంది. భాగాలు వచనంగా తయారై, లేఅవుట్‌లో అతికించబడి, తర్వాత లేఅవుట్ వాస్తుశిల్పితో తనిఖీ చేయబడతాయి; టాబ్లెట్‌లో రెండు నిలువు వరుసల సర్దుబాటు స్క్రీన్ వెడల్పు అర్హతలను ఉపయోగిస్తుంది, నడుస్తున్నప్పుడు పరికర గుర్తింపును కాదు.

అర్థ పునర్నిర్మాణం మరియు AST నావిగేషన్
నిర్వచనాలను కనుగొని చిహ్నాల పేర్లను మార్చడానికి, అనుకోకుండా అదే పేరున్న ఇతర కోడ్‌ను విరగ్గొట్టకుండా: ప్రధాన మెనూలో అర్థ పునర్నిర్మాణం మరియు AST నావిగేషన్ తెరిచి, ప్రాజెక్ట్‌ను ఎంచుకుని, అన్ని తరగతులు మరియు పద్ధతులను వాటి ఫైళ్లు మరియు పంక్తి సంఖ్యలతో చూడటానికి ప్రాజెక్ట్ చిహ్నాలను స్కాన్ చేయండి నొక్కండి. చిహ్నం పేరును నమోదు చేసి, దాని నిర్వచనం మరియు దానిని పిలిచే అన్ని ఫైళ్లను చూడటానికి మళ్లీ ప్రాజెక్ట్ చిహ్నాలను స్కాన్ చేయండి నొక్కండి. పేరు మార్చడానికి, కొత్త పేరును నమోదు చేసి, ప్రతి ఫైల్‌లో ఎన్నిసార్లు ఉందో చూడటానికి పేరు మార్పు ముందస్తు చూపు నొక్కి, తర్వాత పేరు మార్పును వర్తింపజేయండి నొక్కండి. ఈ సూచిక వచన నమూనాలను ఉపయోగిస్తుంది, పూర్తి AST పార్సర్‌ను కాదు: తరగతి పేరు మార్పు అన్ని ఫైళ్లకు వర్తిస్తుంది, పద్ధతి పేరు మార్పు దాని యజమాని ఫైల్‌కు మాత్రమే — ఇతర ఫైళ్లలో పిలిచేవారు మారరు, కాబట్టి వర్తింపజేయడానికి ముందు ముందస్తు చూపు మరియు పిలిచేవారి స్కాన్ ఫలితాలను తనిఖీ చేయండి. కోడ్ బ్లాక్‌ను కొత్త ఫంక్షన్‌గా తీయడం తర్క ఇంజిన్‌లో ఉంది, కానీ ఈ స్క్రీన్‌లో దానికి ఇంకా బటన్ లేదు.

దశలవారీ డీబగ్గర్ మరియు మెమరీ ఇన్‌స్పెక్టర్
లాగ్‌ల నుండి ఊహించకుండా కార్యక్రమ ప్రవాహం మధ్యలో వేరియబుల్ విషయాలను తనిఖీ చేయడానికి: ప్రధాన మెనూలో దశలవారీ డీబగ్గర్ మరియు మెమరీ ఇన్‌స్పెక్టర్ తెరిచి, ప్రాజెక్ట్‌ను ఎంచుకుని, అమలు జాడను రాయండి (ప్రతి పంక్తికి ఒక అడుగు, రూపం పంక్తి సంఖ్య, కోడ్, తర్వాత వేరియబుల్స్ మరియు విలువలు | తో వేరు చేయబడ్డవి, ఉదాహరణకు 10|int total = harga * jumlah;|harga=5000, jumlah=3, total=15000), ఆపు బిందువు పంక్తి సంఖ్యను నమోదు చేసి, డీబగ్ జాడను అమలు చేయు నొక్కండి. IDE మొదటి ఆపు బిందువు వరకు నడుస్తుంది మరియు Jieshuo ద్వారా క్రియాశీల పంక్తిని దాని వేరియబుల్ విలువలతో గట్టిగా చదువుతుంది. ఒక పంక్తి ముందుకు వెళ్లడానికి ఒక పంక్తి ముందుకు వెళ్ళు నొక్కండి, లేదా తర్వాతి ఆపు బిందువు వరకు నడపడానికి కార్యక్రమాన్ని కొనసాగించండి నొక్కండి. ఇది జాడ డీబగ్గర్: ఇది రికార్డ్ చేసిన లేదా చేతితో రాసిన అమలు జాడను అనుసరిస్తుంది, నడుస్తున్న Android యాప్‌ను ఆపదు — నిజమైన ప్రక్రియను ఆపడానికి డీబగ్ వంతెన అవసరం, అది ఈ దశలో లేదు.

ఆఫ్‌లైన్ డిపెండెన్సీ నిర్వాహకుడు
ఇంటర్నెట్ లేకుండా మూడవ పక్ష లైబ్రరీలను ఉపయోగించడానికి మరియు నిర్మాణానికి ముందు సంస్కరణ ఘర్షణలను నివారించడానికి: ప్రధాన మెనూలో ఆఫ్‌లైన్ డిపెండెన్సీ నిర్వాహకుడు తెరిచి, ప్రాజెక్ట్‌ను ఎంచుకుని, డిపెండెన్సీలను తనిఖీ చేయండి నొక్కండి. IDE ప్రాజెక్ట్‌లోని అన్ని .gradle ఫైళ్లను చదివి, ఆఫ్‌లైన్ ఖజానాను (ప్రాజెక్ట్‌లో brankas-maven.txt) తనిఖీ చేసి, ఘర్షణలను పరిష్కరిస్తుంది — రెండు లైబ్రరీలు ఒకే ఆర్టిఫాక్ట్ వేర్వేరు సంస్కరణలను అడిగితే, అత్యధిక సంస్కరణ ఉపయోగించబడి ఘర్షణ నివేదించబడుతుంది. లైబ్రరీని ఖజానాలో నమోదు చేయడానికి, దాని నిర్దేశాంకాలను నమోదు చేయండి (రూపం సమూహం:ఆర్టిఫాక్ట్:సంస్కరణ, ఉదాహరణకు com.google.code.gson:gson:2.10.1) తర్వాత డిపెండెన్సీలను తనిఖీ చేయండి నొక్కండి. Maven, Google లేదా PyPI నుండి డౌన్‌లోడ్‌కు ఇంటర్నెట్ అవసరం: ఆఫ్‌లైన్‌లో ఖజానాలో ఇప్పటికే ఉన్న లైబ్రరీలు మాత్రమే ఉపయోగించబడతాయి, మరియు నిర్దేశాంకాలను జోడించడం వాటిని సూచికలో మాత్రమే నమోదు చేస్తుంది — AAR, JAR లేదా WHL ఫైళ్లు స్వయంగా డౌన్‌లోడ్ కావు. ఖజానా ఇంకా ప్రతి ప్రాజెక్ట్‌కు భద్రపరచబడుతుంది.

డేటాబేస్ మరియు నిల్వ ఇన్‌స్పెక్టర్
పట్టిక విషయాలను ముద్రించే కోడ్ రాయకుండా ప్రాజెక్ట్ డేటాబేస్ విషయాలను తనిఖీ చేసి పరీక్షించడానికి: ప్రధాన మెనూలో డేటాబేస్ మరియు నిల్వ ఇన్‌స్పెక్టర్ తెరిచి, ప్రాజెక్ట్ మరియు డేటాబేస్ ఫైల్‌ను (.db, .sqlite లేదా .sqlite3) ఎంచుకుని, డేటాబేస్‌ను తెరువు నొక్కండి. IDE పట్టిక పథకాన్ని చదివి మొదటి 20 వరుసలను వచన పట్టికగా చూపుతుంది, దానిని Jieshuo గట్టిగా చదువుతుంది. సాధారణ SELECT ప్రశ్న రాసి ప్రశ్నను అమలు చేయు నొక్కండి (ఉదాహరణకు SELECT nama FROM pengguna WHERE kota = 'Makassar'). విలువను మార్చడానికి, వరుస సంఖ్య (1 = మొదటి వరుస), నిలువు వరుస పేరు మరియు కొత్త విలువను నమోదు చేసి, సెల్ విలువను మార్చండి నొక్కండి — విలువ .db ఫైల్‌లోకి తిరిగి రాయబడుతుంది. పట్టిక ప్రస్తుత స్థితిని ప్రాజెక్ట్‌లో <డేటాబేస్-పేరు>.cadangan.txt ఫైల్‌గా భద్రపరచడానికి బ్యాకప్ భద్రపరచండి నొక్కండి. మొదటి పట్టిక మాత్రమే చదవబడుతుంది; మద్దతు ఉన్న ప్రశ్నలు JOIN లేదా GROUP BY లేని సాధారణ SELECT మాత్రమే; SharedPreferences మరియు DataStore ఇంకా చదవబడలేదు.

యూనిట్ పరీక్ష ఫ్యాక్టరీ మరియు ఫజ్జింగ్
యాప్‌ను పంచుకునే ముందు తర్క ఖాళీలను కనుగొనడానికి: ప్రధాన మెనూలో యూనిట్ పరీక్ష ఫ్యాక్టరీ మరియు ఫజ్జింగ్ తెరిచి, ప్రాజెక్ట్ మరియు కోడ్ ఫైల్‌ను ఎంచుకుని, పరీక్షలను సృష్టించి అమలు చేయు నొక్కండి. IDE ఫైల్‌లోని ఫంక్షన్ సంతకాలను చదివి, సాధారణ మరియు సరిహద్దు పరీక్ష సందర్భాలను తయారు చేస్తుంది (ఖాళీ వచనం, null, గరిష్ఠ సంఖ్యలు, వింత అక్షరాలు), నమూనా ఫంక్షన్‌లపై ఫజ్జింగ్ నడుపుతుంది, మరియు JUnit పరీక్ష అస్థిపంజరాన్ని (Uji<తరగతి పేరు>.java) ప్రాజెక్ట్‌లో రాస్తుంది. ఫలితం ఎన్ని పరీక్షలు ఉత్తీర్ణమయ్యాయి మరియు విఫలమయ్యాయి, ఎన్ని కోడ్ పంక్తులు మరియు ఫంక్షన్‌లు కనుగొనబడ్డాయి, మరియు ఎన్ని పరీక్ష సందర్భాలు తయారయ్యాయో నివేదిస్తుంది. తయారైన పరీక్షలు ఇంకా అస్థిపంజరాలు — ఆశించిన విలువలను డెవలపర్ రాయాలి — మరియు నిజమైన ఫజ్జింగ్ నమూనా ఫంక్షన్‌లపై మాత్రమే నడుస్తుంది, ప్రాజెక్ట్ ఫంక్షన్‌లపై కాదు; పంక్తి కవరేజ్ శాతం ఇంకా లెక్కించబడలేదు.

తీవ్ర పరికర పరిస్థితి అనుకరణకర్త మరియు మెమరీ లీక్ ఆడిటర్
వ్యవస్థ దాని ప్రక్రియను చంపినప్పుడు, నెట్‌వర్క్ తెగిపోయినప్పుడు, స్క్రీన్ తిరిగినప్పుడు, లేదా బ్యాటరీ ఆదా చురుకుగా ఉన్నప్పుడు యాప్ సహనాన్ని పరీక్షించడానికి: ప్రధాన మెనూలో తీవ్ర పరికర పరిస్థితి అనుకరణకర్త మరియు మెమరీ లీక్ ఆడిటర్ తెరిచి, ప్రాజెక్ట్‌ను ఎంచుకుని, అనుకరణను అమలు చేయు నొక్కండి. IDE స్క్రీన్ భ్రమణ అనుకరణతో మూడు ఒత్తిడి దృశ్యాలను నడుపుతుంది మరియు వాటి స్క్రీన్ మూసివేయబడిన తర్వాత మెమరీలో నిలిచిన వస్తువులను అనుసరిస్తుంది, తర్వాత కోల్పోయిన డేటా మరియు లీక్ అయ్యే వస్తువుల గొలుసులను నివేదిస్తుంది. ఇది స్థితి నమూనాపై అనుకరణ, నిజంగా ప్రక్రియను చంపడం కాదు, నిజంగా ఫోన్ నెట్‌వర్క్‌ను కత్తిరించడం కాదు, మరియు నిజమైన heap dump కాదు; ఈ స్క్రీన్‌లోని స్థితి నమూనా ఇంకా స్థిర ఉదాహరణ, వినియోగదారు ప్రాజెక్ట్ స్క్రీన్‌ల స్థితి కాదు.

ప్రాజెక్ట్ బ్లూప్రింట్ వాస్తుశిల్పి
పెద్ద యాప్ ఆలోచనను దశలవారీ పని ప్రణాళికగా మార్చడానికి: ప్రధాన మెనూలో ప్రాజెక్ట్ బ్లూప్రింట్ వాస్తుశిల్పి తెరిచి, ప్రాజెక్ట్‌ను ఎంచుకుని, యాప్ ఆలోచనను రాయండి (ఉదాహరణకు వాయిదాలతో కిరాణా దుకాణ క్యాషియర్ యాప్), తర్వాత బ్లూప్రింట్‌ను సృష్టించు నొక్కండి. IDE మాడ్యూళ్లు, ఫైల్ జాబితా మరియు చిన్న పని మైలురాళ్లను అమర్చి, వాటిని ప్రాజెక్ట్ ఫోల్డర్‌లో cetak-biru.txt గా భద్రపరుస్తుంది. ప్రతి మైలురాయి పూర్తయినప్పుడు తదుపరి మైలురాయిని పూర్తయినట్లు గుర్తించండి నొక్కండి, లేదా భద్రపరచిన బ్లూప్రింట్‌ను మళ్లీ తెరవడానికి భద్రపరచిన బ్లూప్రింట్‌ను లోడ్ చేయండి నొక్కండి. బ్లూప్రింట్‌లు పరికరంలోని కీలక పద నమూనాల నుండి నిర్మించబడతాయి, ఆన్‌లైన్ AI నమూనా నుండి కాదు — గుర్తించబడని ఆలోచనలు సాధారణ అస్థిపంజరాన్ని ఉపయోగిస్తాయి (డేటా నమూనా, నిల్వ, స్క్రీన్‌లు, తర్కం) — మరియు చురుకైన AI ప్రదాత ద్వారా నిర్మించడం ఈ దశలో లేదు.

కోడ్ తర్క ప్రవాహ కథకుడు
పంక్తి వారీగా వాక్యనిర్మాణం వినకుండా పొడవైన కోడ్‌ను అర్థం చేసుకోవడానికి: ప్రధాన మెనూలో కోడ్ తర్క ప్రవాహ కథకుడు తెరిచి, ప్రాజెక్ట్ మరియు కోడ్ ఫైల్‌ను ఎంచుకుని, కోడ్ వివరణ నొక్కండి. IDE ప్రతి పంక్తిని ఇండోనేషియా వాక్యంగా మారుస్తుంది (ఉదాహరణకు మొత్తం 100000 కంటే ఎక్కువైతే, తర్వాతి బ్లాక్‌ను అమలు చేయండి), పద్ధతుల మధ్య పిలుపు పటాన్ని చూపుతుంది, మరియు సూక్ష్మ దోషాల సంభావ్యతను వాటి పంక్తి సంఖ్యలతో గుర్తిస్తుంది — == తో పోల్చిన String, మూయకుండా తెరిచిన stream, మరియు రెండు వేర్వేరు పద్ధతులలో రాసిన వేరియబుల్. వివరణ మరియు తనిఖీ ఆఫ్‌లైన్ వచన నమూనాలను ఉపయోగిస్తాయి, ఆన్‌లైన్ AI నమూనాను కాదు మరియు పూర్తి డేటా ప్రవాహ విశ్లేషణను కాదు; గుర్తించబడని నమూనాలు ఉన్నట్లుగానే కోడ్ పంక్తిగా వివరించబడతాయి, మరియు డేటా పోటీ హెచ్చరికలు నిజంగా మార్చి మార్చి మాత్రమే ఉపయోగించబడే వేరియబుల్స్ కోసం కూడా కనిపించవచ్చు.

యాప్ బండిల్ ఫ్యాక్టరీ మరియు Play Store సన్నద్ధత
నేరుగా ఫోన్ నుండి Google Play Store కోసం యాప్‌ను సిద్ధం చేయడానికి: ప్రధాన మెనూలో యాప్ బండిల్ ఫ్యాక్టరీ మరియు Play Store సన్నద్ధత తెరిచి, ప్రాజెక్ట్‌ను ఎంచుకుని, AAB బండిల్‌ను నిర్మించు నొక్కండి. IDE మానిఫెస్ట్, వనరులు మరియు ప్రాజెక్ట్ ఆస్తుల నుండి .aab ఫైల్‌ను కూర్చి, నిర్మాణం (arm64-v8a, armeabi-v7a, x86_64) మరియు భాష వారీగా డౌన్‌లోడ్ విభాగ పరిమాణాలను అనుకరించి, తర్వాత Play సన్నద్ధతను ఆడిట్ చేస్తుంది — లక్ష్య SDK 35 కంటే తక్కువగా ఉంటే ఎక్కువగా గుర్తించబడుతుంది, ఎందుకంటే Play Store 35 లేదా అంతకంటే ఎక్కువ కోరుతుంది, మరియు తప్పిపోయిన 64-బిట్ లైబ్రరీ కూడా ఎక్కువగా గుర్తించబడుతుంది. ఫలిత బండిల్ ప్రామాణిక నిర్మాణం గల AAB ఆర్కైవ్; విభాగ పరిమాణాలు ఫైల్ పరిమాణాల నుండి అంచనాలు, bundletool విభజన నిజ ఫలితాలు కావు, మరియు Play Console కోసం బండిల్ సంతకం ఇంకా APK యొక్క అదే నిర్మాణ మార్గాన్ని ఉపయోగిస్తుంది.

OTA నవీకరణ ఇంజిన్ మరియు దశలవారీ విడుదలలు
వినియోగదారులను పూర్తి APK ని మళ్లీ డౌన్‌లోడ్ చేయమని బలవంతం చేయకుండా చిన్న సవరణలు పంపడానికి: ప్రధాన మెనూలో OTA నవీకరణ ఇంజిన్ మరియు దశలవారీ విడుదలలు తెరిచి, ప్రాజెక్ట్‌ను ఎంచుకుని, పాత మరియు కొత్త సంస్కరణ విషయాన్ని రాసి, ప్యాచ్ ప్యాకేజీని సృష్టించు నొక్కండి. IDE పంక్తి తేడాలను లెక్కించి, కొత్త విషయం యొక్క SHA-256 వేలిముద్రతో ప్యాచ్ ప్యాకేజీని (patch-ota.zip) తయారు చేసి, తర్వాత ఈ పరికరం ప్రారంభ 10 శాతం విడుదల దశలో ఉందో లేదో తనిఖీ చేస్తుంది. ఇక్కడి ప్యాచ్‌లు వచన ఫైళ్లపై మాత్రమే పనిచేస్తాయి (స్క్రిప్ట్‌లు, ఆస్తులు, ఆకృతీకరణ) — బైనరీ DEX లేదా APK ప్యాచ్‌లు ఇంకా మద్దతు లేదు, మరియు యాప్ మళ్లీ తెరిచినప్పుడు ప్యాచ్ వర్తించబడుతుంది. మానిఫెస్ట్‌లోని వేలిముద్ర విషయ సమగ్రతను మాత్రమే నిరూపిస్తుంది, పంపినవారి ప్రామాణికతను కాదు, ఎందుకంటే ఇంకా ప్రైవేట్ కీ సంతకం ఉపయోగించబడలేదు.

బృంద కోడ్ సమీక్ష స్టూడియో
Git బాణం గుర్తులను చదవకుండా సహోద్యోగి మార్పులను సమీక్షించి విలీన ఘర్షణలను పరిష్కరించడానికి: ప్రధాన మెనూలో బృంద కోడ్ సమీక్ష స్టూడియో తెరిచి, ప్రాజెక్ట్‌ను ఎంచుకుని, మూడు వచన సంస్కరణలను నింపండి (ప్రాతిపదిక, స్థానిక, సహోద్యోగి), తర్వాత బృంద సమీక్షను తెరువు నొక్కండి. IDE మూడింటినీ విలీనం చేసి, ప్రతి ఘర్షణను స్వర ఎంపికగా చూపుతుంది: స్థానిక సంస్కరణను ఉపయోగించండి, సహోద్యోగి సంస్కరణను ఉపయోగించండి, లేదా రెండింటినీ విలీనం చేయండి — ఫలిత పంక్తులు పంక్తి క్రమం సరిగ్గా ఉండేలా ఘర్షణ అసలు స్థానంలో చొప్పించబడతాయి — తర్వాత ఫలితాన్ని ప్రాజెక్ట్‌లో gabung-hasil.txt లో రాస్తుంది. దాని కింద ప్రాజెక్ట్ పని బోర్డు ఉంది: పని శీర్షికను నమోదు చేసి పనిని జోడించు నొక్కండి; పనులు ప్రాజెక్ట్‌లోని .tugas ఫోల్డర్‌లో వచనంగా భద్రపరచబడతాయి. విలీనం వాక్యనిర్మాణం కాకుండా పంక్తి సరిపోలికను ఉపయోగిస్తుంది, కాబట్టి ఒకే పంక్తిపై రెండు మార్పులు వాటి అర్థాలు ఘర్షించకపోయినా ఎల్లప్పుడూ ఘర్షణగా పరిగణించబడతాయి; పని బోర్డు దాని వచన ఫైల్‌ను Git చరిత్రతో కాపీ చేయడం ద్వారా సమకాలీకరిస్తుంది, ప్రత్యేక సమకాలీకరణ సర్వర్ లేకుండా.

కోడ్ నిర్మాణ డిక్టేషన్
ఎడిటర్‌లో వాయిస్‌తో కోడ్ రాయడానికి: ఎడిటర్‌లో ప్రాజెక్ట్ తెరిచి, ఆపై కోడ్ నిర్మాణ డిక్టేషన్ బటన్ నొక్కండి. ఇండోనేషియా భాషలో ఆదేశాలు చెప్పండి, ఉదాహరణకు buat fungsi tambah dengan parameter a angka dan b angka, buat kelas Mobil, లేదా buat variabel teks nama sama dengan Budi — IDE మాటను వ్యాకరణపరంగా సరైన Java, Kotlin, Python లేదా Compose కోడ్ బ్లాక్‌గా మార్చి కర్సర్ స్థానంలో చొప్పిస్తుంది, ఆపై Jieshuo ద్వారా చిన్న సారాంశాన్ని బిగ్గరగా చదువుతుంది. డిక్టేషన్ సిస్టమ్ అంతర్నిర్మిత వాయిస్ ఇన్‌పుట్ సేవను ఉపయోగిస్తుంది, అదనపు మైక్రోఫోన్ అనుమతి అవసరం లేదు, మరియు ఇప్పటికే నమోదైన ఆదేశ నమూనాలను మాత్రమే గుర్తిస్తుంది; ఆ నమూనాల వెలుపలి మాట కోడ్‌గా మార్చబడదు. పదాలతో చెప్పిన సంఖ్యలు (ఉదాహరణకు 'lima') ఇంకా అంకెలుగా మార్చబడవు.

స్థానిక సహకార గది (ఇంటర్నెట్ లేకుండా)
ఇంటర్నెట్ లేకుండా ఒకే గదిలో కలిసి పనిచేయడానికి: ప్రధాన మెనూలో సహకారం తెరిచి, ఆపై స్థానిక సహకార గది విభాగాన్ని తెరవండి. ఒక ఫోన్ సెషన్ తెరుస్తుంది (IDE స్థానిక IP చిరునామా మరియు 6 అంకెల PIN చూపుతుంది), మరొక ఫోన్ ఆ చిరునామా మరియు PIN తో చేరుతుంది. టెక్స్ట్ మార్పులు లైన్ తేడాలుగా పంపబడతాయి, నిర్మించిన APK పరీక్షకుని ఫోన్‌కు పంపవచ్చు, మరియు పరీక్షకుని ఫోన్ నుండి క్రాష్ నివేదికలు తిరిగి అందుతాయి. ఒక సెషన్ ఒక స్నేహితునికి మాత్రమే; ఇద్దరు వ్యక్తులు ఒకే సమయంలో ఖచ్చితంగా అదే లైన్‌ను మార్చినట్లయితే, చివరి మార్పు ఉపయోగించబడుతుంది. PIN స్థానిక నెట్‌వర్క్‌లో సాదా టెక్స్ట్‌గా పంపబడుతుంది. ఈ గది ఇంకా నిజమైన ఫోన్‌లో పరీక్షించబడలేదు.

AI సెట్టింగ్‌లు
యాప్‌లను సృష్టించడానికి AI ప్రొవైడర్ మరియు API కీలను సెట్ చేయడానికి: ప్రధాన మెనూలో, సెట్టింగ్‌లు సమూహంలో, AI సెట్టింగ్‌లు నొక్కండి (కనెక్టర్ బటన్ పక్కన). అందుబాటులో ఉన్న జాబితా నుండి ఉపయోగించాల్సిన ప్రొవైడర్‌ను ఎంచుకుని, ప్రొవైడర్ లోపం వస్తే మోడల్ మార్చండి అని టిక్ చేయండి, తద్వారా ఒక మోడల్ విఫలమైతే IDE అదే ప్రొవైడర్ యొక్క తదుపరి మోడల్‌ను స్వయంచాలకంగా ప్రయత్నిస్తుంది. బ్యాకప్ కీలను జోడించడానికి API కీలను నిర్వహించండి నొక్కండి (పేరు మరియు కీ నింపి, ఆపై సేవ్ చేయండి నొక్కండి; కీలు మాస్క్ చేసి చూపబడతాయి, చివరి 4 అక్షరాలు మాత్రమే కనిపిస్తాయి). కీలు ఫోన్‌లో భద్రపరచబడతాయి మరియు యాప్ సృష్టించేటప్పుడు ఎంచుకున్న ప్రొవైడర్‌కు తప్ప మరెక్కడికీ పంపబడవు. గమనిక: ప్రస్తుతం ప్రొవైడర్ మరియు కీ ఎంపిక మాత్రమే నమోదు చేయబడి AI Pembuat Aplikasi స్క్రీన్‌లో చూపబడుతుంది — యాప్ సృష్టి ఇంకా ఫోన్‌లోని స్థానిక AI ని (ఇంటర్నెట్ లేకుండా) ఉపయోగిస్తుంది; ఆన్‌లైన్ ప్రొవైడర్ల వినియోగం తర్వాత వస్తుంది.

కనెక్టర్
APK ని విశ్లేషించి, ఆపై పంపడానికి: ప్రధాన మెనూలో, సెట్టింగ్‌లు సమూహంలో, కనెక్టర్ నొక్కండి (AI సెట్టింగ్‌లు బటన్ పక్కన). ఫోన్ నుండి APK ఫైల్ ఎంచుకోండి, IDE దాని కంటెంట్‌ను చదువుతుంది (ప్యాకేజీ పేరు, వెర్షన్, కార్యకలాపాల జాబితా), ఆపై సిస్టమ్ షేర్ మెనూ (ఉదాహరణకు WhatsApp లేదా Drive) ద్వారా పంపడానికి APK పంపండి నొక్కండి.

భాష మరియు వాయిస్
యాప్ భాషను మార్చడానికి: సెట్టింగ్‌లు తెరిచి, ఆపై యాప్ భాష తెరిచి, ఆపై భాష లేదా సిస్టమ్‌ను అనుసరించండి ఎంచుకోండి. ప్రధాన స్క్రీన్ మరియు చాలా స్క్రీన్‌లు యాప్‌ను మూసివేయకుండా లేదా పునఃప్రారంభించకుండా వెంటనే ఎంచుకున్న భాషకు మారుతాయి; కొన్ని స్క్రీన్‌లు (ఉదాహరణకు Terminal, సహకారం, AI సెట్టింగ్‌లు మరియు కీ నిర్వహణ) మళ్లీ తెరిచే వరకు పాత భాషనే ఉపయోగిస్తాయి. సిస్టమ్‌ను అనుసరించండి ఎంచుకుంటే, భాష ఫోన్ సిస్టమ్ భాషను అనుసరిస్తుంది.
