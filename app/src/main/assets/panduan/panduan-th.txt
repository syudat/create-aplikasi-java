ยินดีต้อนรับสู่ Create Aplikasi by Al Kautsar
Create Aplikasi คือแอปพลิเคชันสร้างแอป Android ที่ทำงานบนโทรศัพท์โดยตรง โดยไม่ต้องใช้แล็ปท็อป แอปพลิเคชันนี้ช่วยให้ทุกคนสร้างแอป Android ของตัวเองได้ รวมถึงผู้ใช้ที่เพิ่งเรียนรู้การสร้างแอปและผู้ใช้โปรแกรมอ่านหน้าจอ คู่มือการใช้งานแอปพลิเคชันนี้ฉบับสมบูรณ์มีอยู่ในหน้าจอ Tentang Alat (เกี่ยวกับเครื่องมือ) นี้

แอปพลิเคชันนี้คืออะไรและเหมาะกับใคร
Create Aplikasi คือเครื่องมือสร้างแอป Android ที่ทำงานบนโทรศัพท์ แอปพลิเคชันนี้เหมาะสำหรับทุกคนที่ต้องการสร้างแอป Android ของตัวเอง รวมถึงผู้เริ่มต้นและผู้ใช้โปรแกรมอ่านหน้าจอ แอปพลิเคชันนี้มีตัวแก้ไขโค้ด ปุ่ม Jalankan (เรียกใช้) สำหรับทดสอบโครงการ ปุ่ม Bangun (สร้าง) สำหรับสร้าง APK ตลอดจนเมนูสำหรับลงนามและติดตั้ง APK

วัตถุประสงค์ของแอปพลิเคชันนี้
แอปพลิเคชันนี้สร้างขึ้นเพื่อให้ทุกคนสามารถสร้างแอป Android ของตัวเองได้อย่างง่ายดายจากโทรศัพท์โดยตรง รูปลักษณ์ของมันถูกทำให้เรียบง่ายที่สุดเท่าที่จะเป็นไปได้ เพื่อให้ผู้ใช้ใหม่สามารถลองใช้ได้ทันที

วิธีสร้างโครงการใหม่ ทีละขั้นตอน
1. กด Buat Project (สร้างโครงการ) ในเมนูหลัก
2. เลือกประเภทโครงการ: HTML, Situs Web (เว็บไซต์), Java, Kotlin, Compose หรือ Python
3. กรอกชื่อแอปพลิเคชัน ตัวอย่าง: Garuda Decode
4. กรอกชื่อแพ็กเกจ (package name) ตัวอย่าง: com.android.garudadecode ชื่อแพ็กเกจต้องใช้ตัวอักษรพิมพ์เล็กและประกอบด้วยอย่างน้อยสองส่วนที่คั่นด้วยจุด
5. กรอกเวอร์ชันของแอปพลิเคชัน ตัวอย่าง: 1.0 และรหัสเวอร์ชันในรูปตัวเลข ตัวอย่าง: 1 หากเว้นว่างไว้ เวอร์ชันจะถูกกรอกโดยอัตโนมัติเป็น 1.0 และรหัสเวอร์ชันเป็น 1
6. กรอก SDK ขั้นต่ำและ SDK เป้าหมายหากจำเป็น หากเว้นว่างไว้ จะใช้ค่าเริ่มต้น SDK ขั้นต่ำคือเวอร์ชัน Android ต่ำสุดที่รองรับ ตัวอย่าง: 21 หมายถึง Android 5.0 SDK เป้าหมายสูงสุดคือ 36 (Android 16)
7. กดปุ่ม Pilih Izin (เลือกสิทธิ์) เพื่อเลือกสิทธิ์ของแอปพลิเคชัน ตัวอย่าง: INTERNET สิทธิ์ INTERNET ถูกทำเครื่องหมายไว้แล้วตามค่าเริ่มต้น ทำเครื่องหมายเฉพาะสิทธิ์ที่แอปพลิเคชันต้องการจริง ๆ เท่านั้น
8. หากต้องการ ให้ทำเครื่องหมาย "Gunakan arsitektur terpisah 64 bit dan 32 bit" (ใช้สถาปัตยกรรมแยก 64 บิตและ 32 บิต) เพื่อให้ขนาด APK เล็กลง และทำเครื่องหมาย "Gunakan tanda tangan pribadi" (ใช้ลายเซ็นส่วนตัว) หากต้องการใช้ keystore ที่สร้างเอง
9. กด Buat Proyek (สร้างโครงการ) โครงการใหม่จะถูกบันทึกในโฟลเดอร์ Download/project และปรากฏใน Kelola Project (จัดการโครงการ) ทันที

ประเภทโครงการที่มีให้ใช้
• HTML: รูปลักษณ์จาก index.html, style.css และ script.js ทำงานผ่าน WebView สร้างบนโทรศัพท์โดยตรง
• Situs Web: เว็บไซต์ที่มีเมนู (Beranda (หน้าแรก), Tentang (เกี่ยวกับ), Kontak (ติดต่อ)) จาก index.html, tentang.html, kontak.html, style.css และ script.js ทำงานผ่าน WebView สร้างบนโทรศัพท์โดยตรง
• Java: สร้างบนโทรศัพท์ MainActivity อยู่ที่ app/src/main/java/<nama-paket>/MainActivity.java รูปลักษณ์มาจาก app/src/main/res/layout/activity_main.xml ข้อความมาจาก app/src/main/res/values/strings.xml และธีมมาจาก app/src/main/res/values/styles.xml
• Kotlin: สามารถสร้างบนอุปกรณ์ (ออฟไลน์) โดยใช้คอมไพเลอร์ Kotlin ที่มาพร้อมกับแอปพลิเคชัน หรือผ่าน GitHub Actions MainActivity อยู่ที่ app/src/main/java/<nama-paket>/MainActivity.kt และไฟล์ res เหมือนกับโครงการ Java การสร้าง Kotlin ครั้งแรกจะช้ากว่าเนื่องจากขนาดคอมไพเลอร์ที่ใหญ่ และไฟล์ .java ที่อ้างอิงคลาส Kotlin ยังไม่สามารถสร้างได้ (ไฟล์ .java จะถูกคอมไพล์ก่อนไฟล์ .kt)
• Compose: แอป Android สมัยใหม่ที่อินเทอร์เฟซสร้างด้วย Jetpack Compose (ไม่ใช่เลย์เอาต์ XML) MainActivity อยู่ที่ app/src/main/java/<nama-paket>/MainActivity.kt โครงการ Compose จะถูกสร้างผ่าน GitHub Actions (เมนู Bangun ของโครงการ จากนั้น Bangun online (สร้างออนไลน์)) หรือใน Termux ด้วย Gradle เนื่องจาก Compose ต้องการไลบรารี Jetpack Compose ที่ไม่มีในอุปกรณ์
• Python: ตรรกะของแอปพลิเคชันเขียนด้วยภาษา Python (Chaquopy) ใน app/src/main/python/main.py และถูกเรียกใช้โดยโฮสต์ MainActivity.java ใน app/src/main/java/<nama-paket>/MainActivity.java โครงการ Python สามารถสร้างบนโทรศัพท์โดยตรงได้ (รันไทม์ Chaquopy มาพร้อมกับแอปพลิเคชัน) และผ่าน GitHub Actions ด้วย SDK ขั้นต่ำของโครงการ Python คือ 24 (Android 7.0)

เปลี่ยนสถาปัตยกรรมโปรเจกต์
หากต้องการเปลี่ยนตัวเลือกสถาปัตยกรรมของโปรเจกต์ที่มีอยู่โดยไม่ต้องสร้างโปรเจกต์ใหม่: ในเมนูหลัก แตะ «เปลี่ยนสถาปัตยกรรมโปรเจกต์» แล้วเลือกโปรเจกต์และเปลี่ยนช่องทำเครื่องหมาย «สร้าง APK 64 บิต (arm64-v8a)» หรือ «สร้าง APK 32 บิต (armeabi-v7a)»; หรือใน «จัดการโปรเจกต์» ให้แตะชื่อโปรเจกต์ค้างไว้แล้วเลือก «เปลี่ยนสถาปัตยกรรม» เพื่อเปิดหน้าจอเดียวกันนั้นโดยตรงสำหรับโปรเจกต์นั้น กฎคือ: หากทำเครื่องหมายทั้งสองช่อง การสร้างจะสร้าง APK แยกกันสองไฟล์ ไฟล์หนึ่ง 64 บิตและอีกไฟล์หนึ่ง 32 บิต; หากทำเครื่องหมายเพียงช่องเดียว การสร้างจะสร้าง APK สากลไฟล์เดียวที่ยังคงทำงานได้ทั้งบนอุปกรณ์ 64 บิตและ 32 บิต APK แยกสำหรับตัวแปรเดียวเท่านั้นยังไม่รองรับ เพราะเส้นทางการสร้างรู้จักเพียงตัวเลือกแบบแยกหรือแบบสากล แต่ตัวเลือกของแต่ละตัวแปรยังคงบันทึกไว้ภายในโปรเจกต์เพื่อไม่ให้หายเมื่อเปิดหน้าจออีกครั้ง

โครงสร้างไฟล์ของโครงการ Java, HTML, Situs Web, Kotlin, Compose และ Python
โครงการ Java, HTML, Situs Web, Kotlin, Compose และ Python ถูกจัดเรียงเหมือนโครงการ Android ทั่วไป ภายในโฟลเดอร์ app มีโฟลเดอร์ src และภายในนั้นมีโฟลเดอร์ main ภายในโฟลเดอร์ main มี AndroidManifest.xml อยู่ข้างโฟลเดอร์ java โฟลเดอร์ res ที่มี layout/activity_main.xml และ values/strings.xml ตลอดจน values/styles.xml และสำหรับ HTML และ Situs Web มีโฟลเดอร์ assets ที่มี index.html (Situs Web มี tentang.html และ kontak.html ด้วย) โครงการ HTML และ Situs Web ก็มี MainActivity ของตัวเองใน app/src/main/java/<nama-paket>/MainActivity.java ซึ่งโหลด index.html ใน WebView และเป็นตัวเรียกใช้งานใน AndroidManifest โครงการ Python มีโค้ด Python ใน app/src/main/python/main.py และโฮสต์ MainActivity.java ใน app/src/main/java/<nama-paket>/MainActivity.java AndroidManifest.xml, layout, strings และ styles สามารถเปิดและแก้ไขในตัวแก้ไขได้เช่นเดียวกับ MainActivity โครงการเก่าที่ยังมี manifest อยู่ข้างโฟลเดอร์ app ก็ยังสามารถสร้างได้ เพราะเมื่อสร้าง แอปพลิเคชันจะตรวจสอบ AndroidManifest.xml ใน app/src/main/ ก่อน จากนั้นที่อยู่ข้างโฟลเดอร์ app และสุดท้ายคือไฟล์ข้อมูลโครงการ

กฎเรื่องสิทธิ์ (สำคัญ)
สิทธิ์ที่ทำเครื่องหมายเมื่อสร้างโครงการจะถูกบันทึกไว้เพียงที่เดียวตามประเภทโครงการ สำหรับโครงการ Java, HTML, Situs Web, Kotlin, Compose และ Python สิทธิ์ที่ทำเครื่องหมายจะถูกบันทึกไว้เฉพาะใน AndroidManifest.xml ที่อยู่ใน app/src/main/ ข้างโฟลเดอร์ java ภายในโฟลเดอร์โครงการเท่านั้น ไฟล์ข้อมูลโครงการสำหรับโครงการ Java, HTML, Situs Web, Kotlin, Compose และ Python ไม่มีรายการสิทธิ์ หากเลือก Java แล้วทำเครื่องหมาย INTERNET และ CAMERA สิ่งที่บันทึกใน AndroidManifest.xml จะมีเพียง INTERNET และ CAMERA เท่านั้น โดยไม่มีสิทธิ์อื่นร่วมด้วย เมื่อสร้าง แอปพลิเคชันจะอ่านสิทธิ์จากที่เดียวกัน: จาก AndroidManifest.xml ใน app/src/main/ สำหรับโครงการ Java, HTML, Situs Web, Kotlin, Compose และ Python (หากไม่มี จาก AndroidManifest.xml ที่อยู่ข้างโฟลเดอร์ app สำหรับโครงการเก่า) และจากไฟล์ข้อมูลโครงการสำหรับโครงการเก่า

วิธีใช้ตัวแก้ไข
เปิด Kelola Project แตะชื่อโครงการเพื่อเปิดตัวแก้ไข ในตัวแก้ไข สามารถเปิดไฟล์ เขียนโค้ด และบันทึกการเปลี่ยนแปลงได้ สำหรับโครงการ Java, HTML, Situs Web, Kotlin, Compose และ Python ไฟล์จะถูกจัดเรียงอยู่ภายในโฟลเดอร์ app/src/main หากต้องการแชร์โครงการ ให้ใช้ Ekspor ZIP (ส่งออก ZIP) (ดูส่วนด้านล่าง)

วิธีเรียกใช้โครงการ
ในตัวแก้ไข กด Jalankan เพื่อทดสอบโครงการ สำหรับโครงการ HTML และ Situs Web สิ่งที่เรียกใช้คือ index.html ผ่าน WebView หากเกิดข้อผิดพลาด ให้อ่านข้อความแสดงข้อผิดพลาด แก้ไขโค้ด แล้วเรียกใช้อีกครั้ง

วิธีสร้าง APK
ในตัวแก้ไข กด Bangun มีวิธีสร้างสองวิธี วิธีแรก Bangun di perangkat (สร้างบนอุปกรณ์): สร้างบนโทรศัพท์โดยตรงโดยไม่ใช้อินเทอร์เน็ต สำหรับโครงการ HTML, Situs Web, Java, Kotlin และ Python วิธีที่สอง Bangun online ผ่าน GitHub Actions: สร้างผ่านอินเทอร์เน็ตบน GitHub และสามารถใช้ได้กับโครงการทุกประเภท โครงการ Compose สามารถสร้างได้เฉพาะด้วยวิธีที่สอง (Bangun online) หรือใน Termux ด้วย Gradle เนื่องจาก Compose ต้องการไลบรารี Jetpack Compose ที่ไม่มีในอุปกรณ์ ผลการสร้างครั้งแรกยังไม่ได้ลงนาม หลังจากนั้นแอปพลิเคชันจะลงนามให้: โดยอัตโนมัติด้วยคีย์เริ่มต้น หรือด้วยลายเซ็นส่วนตัวหากช่อง "Gunakan tanda tangan pribadi" ถูกทำเครื่องหมายไว้เมื่อสร้างโครงการ

วิธีติดตั้ง APK
เมื่อ APK พร้อมแล้ว กด Pasang (ติดตั้ง) เพื่อติดตั้ง บน Android 8 ขึ้นไป โทรศัพท์จะขอ "Izinkan dari sumber ini" (อนุญาตจากแหล่งนี้) ก่อน เนื่องจากแอปพลิเคชันนี้ติดตั้ง APK จากภายนอก Play Store เปิดใช้งานสิทธิ์นั้นหนึ่งครั้งใน Pengaturan (การตั้งค่า) แล้วกลับมาที่แอปพลิเคชัน: การติดตั้งจะดำเนินต่อไปโดยอัตโนมัติโดยไม่ต้องกด Pasang อีก หากปุ่ม Pasang ไม่ปรากฏ ให้แน่ใจว่าการสร้างเสร็จสิ้นและ APK ถูกสร้างแล้ว

วิธีลงนามแอปพลิเคชัน
APK ทุกตัวต้องถูกลงนามจึงจะติดตั้งได้ มีสองตัวเลือก ตัวเลือกแรก คีย์เริ่มต้น: แอปพลิเคชันลงนามเองโดยอัตโนมัติ โดยที่คุณไม่ต้องทำอะไรเลย ตัวเลือกที่สอง ลายเซ็นส่วนตัว: สร้าง keystore ก่อนผ่านเมนู Buat Keystore (สร้าง keystore) ในเมนูหลัก เก็บรหัสผ่านของมันไว้ให้ดี จากนั้นทำเครื่องหมาย "Gunakan tanda tangan pribadi" เมื่อสร้างโครงการ Keystore จะถูกเก็บไว้ใน Download/project/signing

การส่งออกโครงการเป็น ZIP
Ekspor ZIP มีไว้เพื่อให้สามารถแชร์โครงการกับเพื่อนได้ วิธีทำ: ใน Kelola Project กดชื่อโครงการค้างไว้ จากนั้นเลือก Ekspor ZIP ผลลัพธ์จะถูกบันทึกใน Download/project/<NamaProyek>.zip โฟลเดอร์ bin จะไม่ถูกรวมอยู่ด้วย ดังนั้นขนาดจึงเล็ก เพียงไม่กี่สิบ KB ไฟล์ ZIP นั้นสามารถส่งให้เพื่อนหรืออัปโหลดไปยัง GitHub ได้

Ekstensi JAWS ใช้เครื่องยนต์ส่วนขยายของ Jieshuo (CSR) ไม่ใช่โปรแกรมอ่านหน้าจอของมัน ด้วยเหตุนี้ การออกแบบจึงยังสามารถทำงานได้แม้ว่าผู้ใช้จะใช้ TalkBack วิธีทำ: เปิด Ekstensi JAWS ในเมนูหลัก เนื่องจากการคลิกอัตโนมัติทำงานด้วยตัวเอง บริการจึงต้องเปิดใช้งานก่อนใน Pengaturan Aksesibilitas (การตั้งค่าการเข้าถึง) หลังจากนั้นจึงสามารถสร้างการออกแบบใหม่ได้: พิมพ์ชื่อการออกแบบ กด OK แล้วกรอกช่องของมัน

Daftar Klik แยกไว้เพื่อให้เรียบร้อย
ภายในหนึ่งการออกแบบมีสองช่อง: ช่องสคริปต์และช่อง Daftar Klik (รายการคลิก) รายการปุ่มจะถูกบันทึกแยกไว้ในไฟล์ daftar_klik.txt หนึ่งชื่อต่อหนึ่งบรรทัด ตัวอย่างเนื้อหา: tombolSimpan, tombolHapus, tombolBuka หากต้องการเปิดแอปพลิเคชัน ให้เขียนเพียง >WhatsApp ในรายการนั้น การออกแบบเก่าที่ยังไม่มีไฟล์ daftar_klik.txt จะแสดงตัวอย่างเริ่มต้นนั้น

ฟังก์ชันง่าย ๆ ที่จัดเตรียมไว้
• klikTombol("tombolSimpan") — คลิกปุ่มหนึ่งปุ่มตามข้อความของมัน
• klikDaftarTombol(daftar) — คลิกรายการใน daftar_klik.txt หนึ่งปุ่มต่อหนึ่งบรรทัด ตามลำดับ จากนั้นบอกว่าสำเร็จกี่รายการและหาไม่พบกี่รายการ
• bukaAplikasi("WhatsApp") — เปิดแอปพลิเคชันตามชื่อของมัน หรือเขียน ">WhatsApp" ในรายการ
• klik(540, 1200) — คลิกที่พิกัดหน้าจอ
ฟังก์ชันทั้งหมดถูกทำให้เรียบง่ายก่อน เมื่อคุ้นเคยแล้ว สามารถเพิ่มฟังก์ชันเพิ่มเติมได้ในภายหลัง

เกี่ยวกับโปรแกรมอ่านหน้าจอ
แอปพลิเคชันนี้ออกแบบมาให้เป็นมิตรกับโปรแกรมอ่านหน้าจอ ช่องกรอกทุกช่องมีป้ายกำกับและตัวอย่างการกรอก และปุ่มทุกปุ่มสามารถเข้าถึงได้โดยไม่ต้องใช้ท่าทางที่ซับซ้อน Ekstensi JAWS ถูกสร้างให้ยังคงทำงานได้แม้ว่าผู้ใช้จะใช้ TalkBack เนื่องจากสิ่งที่ใช้คือเครื่องยนต์ส่วนขยายของมัน ไม่ใช่โปรแกรมอ่านหน้าจอของมัน

ความเป็นส่วนตัวและความปลอดภัย
โครงการและ keystore จะถูกเก็บบนโทรศัพท์ของคุณ โทเค็น GitHub ใช้สำหรับการสร้างออนไลน์เท่านั้นและถูกเก็บไว้ภายในแอปพลิเคชันนี้ อย่าแชร์โทเค็นหรือรหัสผ่าน keystore ของคุณกับใคร หากใช้ลายเซ็นส่วนตัว ให้เก็บ keystore และรหัสผ่านของมันไว้ในที่ปลอดภัย เพราะหากสูญหาย APK เก่าจะไม่สามารถอัปเดตด้วยลายเซ็นเดียวกันได้

ข้อกำหนด
Android 5.0 หรือใหม่กว่า สิทธิ์พื้นที่จัดเก็บ: บน Android 11 ขึ้นไปใช้สิทธิ์เข้าถึงไฟล์ทั้งหมด บน Android 10 ลงไปใช้สิทธิ์พื้นที่จัดเก็บปกติ (อ่าน/เขียนพื้นที่จัดเก็บ) เนื่องจาก Android 10 ไม่มีสิทธิ์เข้าถึงไฟล์ทั้งหมด การสร้างบนอุปกรณ์ต้องใช้โทรศัพท์ที่มีโปรเซสเซอร์ ARM (32 หรือ 64 บิต) การสร้างออนไลน์ผ่าน GitHub Actions ต้องใช้อินเทอร์เน็ตและโทเค็น GitHub โครงการ Kotlin สามารถสร้างบนอุปกรณ์ได้ แต่การสร้างครั้งแรกจะช้ากว่าและใช้หน่วยความจำมากกว่าเนื่องจากขนาดคอมไพเลอร์ Kotlin ที่ใหญ่ โครงการ Compose จะถูกสร้างผ่าน GitHub Actions หรือใน Termux ด้วย Gradle โครงการ Python ต้องใช้ Android 7.0 หรือใหม่กว่า (SDK ขั้นต่ำ 24) และ APK ที่ได้จะมีขนาดใหญ่กว่าเนื่องจากรวมรันไทม์ Python (Chaquopy) พร้อมไลบรารีมาตรฐานของมัน

Terminal
เมนู Terminal บนหน้าจอหลักเปิดเทอร์มินัลภายในแอปพลิเคชันนี้ คำสั่งเช่น ls สามารถใช้ดูเนื้อหาของโฟลเดอร์โครงการ cd สำหรับย้ายโฟลเดอร์ และ git สำหรับจัดการโค้ด ผลลัพธ์ของคำสั่งจะแสดงเป็นข้อความที่โปรแกรมอ่านหน้าจออ่านได้ และมีปุ่ม Bacakan hasil (อ่านผลลัพธ์) สำหรับฟังผลลัพธ์ล่าสุด เทอร์มินัลนี้ใช้เชลล์ระบบของโทรศัพท์ ดังนั้นโปรแกรมแบบโต้ตอบเช่น nano และ vim ยังไม่สามารถใช้ที่นี่ได้

Lisensi (เวอร์ชันที่ต้องชำระเงิน)
หากต้องการขายแอปพลิเคชัน ให้ทำเครื่องหมาย "Aktifkan Lisensi" (เปิดใช้ใบอนุญาต) เมื่อสร้างโครงการ จากนั้นกรอกหมายเลข WhatsApp ของคุณ แอปพลิเคชันที่สร้างได้จะขอรหัสใบอนุญาตเมื่อเปิดครั้งแรก: ผู้ใช้เห็น ID อุปกรณ์ของตน กดปุ่ม Kirim ID Perangkat (ส่ง ID อุปกรณ์) เพื่อส่ง ID นั้นไปยัง WhatsApp ของคุณ จากนั้นคุณตอบกลับด้วยรหัสใบอนุญาต รหัสใบอนุญาตคำนวณจาก ID อุปกรณ์และรหัสผ่านโครงการ (lisensi_seed ในไฟล์ข้อมูลโครงการ) — เก็บรหัสผ่านนั้นไว้ให้ดีและอย่าแชร์ หลังจากกรอกรหัสที่ถูกต้อง แอปพลิเคชันจะเปิดและไม่ขอรหัสอีก

Pembuat Ikon Otomatis
ไอคอนของโครงการใหม่ยังโปร่งใสอยู่ ดังนั้นจึงมี Pembuat Ikon (ตัวสร้างไอคอน) ในเมนูหลัก วิธีทำ: กด Pembuat Ikon เขียนตัวอักษรหนึ่งหรือสองตัว (เช่น อักษรย่อของชื่อแอปพลิเคชัน) เลือกสีพื้นหลังและสีตัวอักษร ดูตัวอย่างของมัน จากนั้นกด Simpan ke Proyek (บันทึกไปยังโครงการ) เพื่อใช้ไอคอนนั้นในโครงการที่เลือก หรือ Simpan ke Download (บันทึกไปยัง Download) เพื่อใช้ไฟล์ PNG ของมันที่อื่น หลังจากโครงการถูกสร้างแล้ว แอปพลิเคชันยังเสนอให้สร้างไอคอนด้วย ไอคอนเก่าของโครงการสามารถเปลี่ยนได้ทุกเมื่อจากเมนูโครงการใน Kelola Project (กดชื่อโครงการค้างไว้ จากนั้นเลือก Ganti Ikon (เปลี่ยนไอคอน))

Template Proyek Siap Pakai
หากไม่ต้องการเริ่มจากโครงการเปล่า ให้เลือกเทมเพลตเมื่อสร้างโครงการ: Kalkulator (Java), Catatan (Java), Daftar Tugas (Kotlin), Kalkulator Web (HTML), Situs Profil (Situs Web) หรือ Penghitung (Compose) การเลือกเทมเพลตจะเปลี่ยนประเภทโครงการให้ตามเทมเพลตนั้นโดยอัตโนมัติ และโครงการจะถูกสร้างด้วยโค้ดเริ่มต้นที่พร้อมอยู่แล้ว — เพียงเรียกใช้หรือแก้ไข หากประเภทโครงการถูกเปลี่ยนด้วยตนเองอีกครั้งหลังจากเลือกเทมเพลต เทมเพลตจะถูกยกเลิกและโครงการจะกลับไปว่างเปล่า สำหรับเทมเพลต HTML และ Situs Web เทมเพลตจะแทนที่เนื้อหาของ index.html รวมถึงสคริปต์ HTML ที่พิมพ์ในแบบฟอร์ม

Cadangan dan Pulihkan Proyek
เพื่อให้โครงการไม่สูญหาย จึงมีคุณสมบัติการสำรองข้อมูล วิธีทำ: ใน Kelola Project กดชื่อโครงการค้างไว้ จากนั้นเลือก Cadangkan (สำรองข้อมูล) ข้อมูลสำรองจะถูกบันทึกเป็น ZIP ในโฟลเดอร์ Download/backup พร้อมชื่อโครงการและวันที่ ตัวอย่าง: GarudaDecode-2026-11-14-123045.zip เนื้อหาของมันเหมือนกับ Ekspor ZIP (เนื้อหาโครงการทั้งหมด โดยไม่มีโฟลเดอร์ bin) หากต้องการกู้คืน: เปิดเมนูใน Kelola Project เลือก Pulihkan cadangan (กู้คืนข้อมูลสำรอง) จากนั้นเลือกไฟล์สำรองของมัน หากชื่อโครงการมีอยู่แล้ว แอปพลิเคชันจะถามว่า: Timpa proyek lama (เขียนทับโครงการเก่า) หรือบันทึกด้วย Nama baru (ชื่อใหม่)

Bagikan dan Impor Proyek
หากต้องการแชร์โครงการกับเพื่อน: ใน Kelola Project กดชื่อโครงการค้างไว้ จากนั้นเลือก Bagikan (แชร์) โครงการจะถูกส่งเป็น ZIP ผ่านแอปแชร์ (WhatsApp, Telegram และอื่น ๆ) หากต้องการรับโครงการจากเพื่อน: เปิดเมนูใน Kelola Project เลือก Impor proyek (นำเข้าโครงการ) จากนั้นเลือกไฟล์ ZIP ของมัน ไฟล์ ZIP นั้นต้องมีไฟล์ข้อมูลโครงการ — หากไม่มี ไฟล์จะถูกปฏิเสธพร้อมข้อความที่ชัดเจน เนื่องจากไฟล์นั้นไม่ใช่โครงการ Create Aplikasi หากชื่อโครงการมีอยู่แล้ว แอปพลิเคชันจะถามว่า: Timpa proyek lama หรือบันทึกด้วย Nama baru

Pencarian dan Filter Proyek
หากโครงการมีจำนวนมาก ใน Kelola Project จะมีช่องค้นหาและตัวกรองประเภท พิมพ์ชื่อโครงการในช่องค้นหา รายการจะถูกกรองทันที (ตัวพิมพ์ใหญ่และตัวพิมพ์เล็กไม่ถูกแยกแยะ) ตัวกรองประเภทจำกัดรายการให้เหลือเพียงประเภทเดียว: Semua (ทั้งหมด), HTML, Situs Web, Java, Kotlin, Compose หรือ Python เมนูของแต่ละโครงการยังสามารถเปิดได้ตามปกติจากรายการที่กรองแล้ว

สร้างแอปด้วยเสียง
หากไม่ต้องการพิมพ์ ให้ใช้เสียง: แตะสร้างด้วยเสียงในเมนูหลัก แล้วพูดคำสั่ง คำสั่งที่พูดได้ ได้แก่ "Buat proyek kalkulator", "Bangun proyek Kalkulator", "Buka proyek Kalkulator", "Jalankan proyek Kalkulator", "Daftar proyek", "Buka ikon", "Kembali" และ "Bantuan" แอปตอบด้วยเสียงและข้อความ จึงยังใช้งานได้โดยไม่ต้องมองหน้าจอ การรู้จำเสียงใช้แอปรู้จำเสียงในตัวของโทรศัพท์ (ฟรี สามารถทำงานออฟไลน์ได้หากติดตั้งชุดภาษาอินโดนีเซีย) หากโทรศัพท์ไม่มีตัวรู้จำเสียง สามารถพิมพ์คำสั่งในกล่องข้อความบนหน้าจอเดียวกันได้

AI สร้างแอป
พิมพ์หรือบอกแอปที่ต้องการบนหน้าจอ AI สร้างแอป เช่น «แอปโน้ตที่มีปุ่มบันทึก» แอปจะวิเคราะห์คำสำคัญภายในโทรศัพท์เอง (ไม่ต้องใช้อินเทอร์เน็ต ไม่เสียค่าใช้จ่าย) แล้วสร้างโปรเจกต์จริงจากเทมเพลตที่เหมาะสมที่สุด ได้แก่ เครื่องคิดเลข โน้ต รายการงาน เครื่องคิดเลขเว็บ ไซต์โปรไฟล์ หรือตัวนับ หากคำอธิบายของคุณยังไม่มีเทมเพลตที่เหมาะสม แอปจะสร้างโปรเจกต์ว่างและบอกตามตรง — ไม่แสร้งว่าทำเข้าใจ โปรเจกต์ที่ AI สร้างสามารถเปิดได้โดยตรงในจัดการโปรเจกต์

ตัวอย่างสดไปยังโทรศัพท์ของเพื่อน
หากต้องการแสดงโปรเจกต์ให้เพื่อนดูก่อนสร้าง ในจัดการโปรเจกต์ ให้กดชื่อโปรเจกต์ค้างไว้ แล้วเลือกตัวอย่างไปยังโทรศัพท์ของเพื่อน แอปจะสร้างแพ็กเกจตัวอย่างขนาดเล็กที่มีไฟล์หลักของโปรเจกต์ (index.html, MainActivity หรือ main.py) พร้อม BACA-SAYA.txt ที่มีคำแนะนำและ info.txt แพ็กเกจจะถูกส่งเป็น ZIP ผ่าน WhatsApp หรือ Telegram เพื่อนที่ได้รับสามารถเปิดตัวอย่างได้ทันที หน้า HTML เปิดในเบราว์เซอร์ โค้ด Java/Kotlin/Python อ่านเป็นข้อความได้

ตลาดโปรเจกต์
ตลาดโปรเจกต์มีโปรเจกต์ตัวอย่างในตัวที่ติดตั้งลงในโฟลเดอร์โปรเจกต์ได้ด้วยการแตะเพียงครั้งเดียว ได้แก่ เครื่องคิดเลข โน้ต รายการงาน เครื่องคิดเลขเว็บ ไซต์โปรไฟล์ ตัวนับ นาฬิกาดิจิทัล และแบบทดสอบเว็บ ตลาดออนไลน์ (ดาวน์โหลดตัวอย่างจากอินเทอร์เน็ต) ยังไม่มี ดังนั้นตลาดนี้จึงมีตัวอย่างที่มีอยู่แล้วในแอป โปรเจกต์ที่ติดตั้งแล้วสามารถเปิดและแก้ไขได้ในจัดการโปรเจกต์เหมือนโปรเจกต์ที่สร้างเอง

การทำงานร่วมกันโดยตรง
หากต้องการทำงานในโปรเจกต์ร่วมกับเพื่อน ให้เปิดการทำงานร่วมกันในเมนูหลัก เลือกโปรเจกต์ เขียนบันทึกการเปลี่ยนแปลง (ว่าเปลี่ยนอะไรไป) แล้วกดแชร์เพื่อการทำงานร่วมกัน โปรเจกต์จะถูกส่งเป็น ZIP พร้อมไฟล์ CATATAN.txt ข้างใน เพื่อนของคุณทำงานแล้วส่ง ZIP กลับมา คุณกดรับคำตอบกลับ อ่านบันทึกการเปลี่ยนแปลงก่อน แล้วเลือกนำไปใช้เพื่อเขียนทับโปรเจกต์เก่า หรือยกเลิกหากเปลี่ยนใจ ZIP ที่ไม่มี CATATAN.txt ไม่ใช่แพ็กเกจการทำงานร่วมกัน — สำหรับ ZIP โปรเจกต์ทั่วไป ให้ใช้นำเข้าโปรเจกต์ในจัดการโปรเจกต์

ตัวแปลแอปอัตโนมัติ
หากต้องการแปลข้อความในแอปเป็นภาษาอื่น ให้เปิดตัวแปลแอปในเมนูหลัก เลือกโปรเจกต์และภาษาเป้าหมาย (อังกฤษ อาหรับ หรือชวา) แล้วกดแปล พจนานุกรมมีอยู่แล้วในโทรศัพท์ (ไม่ต้องใช้อินเทอร์เน็ต ไม่เสียค่าใช้จ่าย) และมีคำทั่วไปในชีวิตประจำวัน ข้อความจาก strings.xml เลย์เอาต์ และโค้ดจะถูกอ่านแล้วแปล ผลลัพธ์จะถูกเขียนไปยังโฟลเดอร์ values-ภาษา/strings.xml (หากโปรเจกต์มี strings.xml) และรายงานแปล-ภาษา.txt ในโฟลเดอร์โปรเจกต์ คำที่ยังไม่มีในพจนานุกรมจะถูกปล่อยไว้ตามเดิมและรายงานไว้ — เพื่อให้คุณรู้ว่าคำใดยังต้องแปลเอง

ตัวสร้างเกมโดยไม่ต้องเขียนโค้ด
หากต้องการสร้างเกมโดยไม่ต้องเขียนโค้ด ให้เปิดตัวสร้างเกมโดยไม่ต้องเขียนโค้ดในเมนูหลัก เลือกประเภทเกม (ทายตัวเลข แบบทดสอบ หรือจับดาว) กรอกชื่อเกม จำนวน (เลเวล/ข้อ/ดาว) และข้อความเมื่อชนะ แล้วกดสร้างเกม เกมจะถูกสร้างเป็นโปรเจกต์จริงที่สามารถรันได้โดยตรงในจัดการโปรเจกต์และสร้างเป็น APK ได้เหมือนโปรเจกต์อื่น ๆ

ทดสอบแอปอัตโนมัติ
หากต้องการตรวจสอบโปรเจกต์ก่อนสร้าง ในจัดการโปรเจกต์ ให้กดชื่อโปรเจกต์ค้างไว้แล้วเลือกทดสอบอัตโนมัติ IDE จะตรวจสอบ 10 อย่างโดยไม่ต้องสร้าง APK ได้แก่ ไฟล์บังคับมีอยู่ (ไฟล์ข้อมูลโปรเจกต์ manifest ไฟล์หลัก เลย์เอาต์ strings) ชื่อแพ็กเกจและเวอร์ชัน สิทธิ์ที่ใช้ ไอคอน และความสมดุลของวงเล็บโค้ด ผลลัพธ์จะแสดงเป็นรายรายการ (ผ่าน/ไม่ผ่านพร้อมข้อความ) และ Jieshuo จะอ่านออกเสียง แก้ไขสิ่งที่ตกก่อน แล้วจึงกดสร้างโปรเจกต์

AI ตรวจโค้ด
หากต้องการตรวจสอบโค้ดโปรเจกต์หารูปแบบที่มักก่อปัญหา ให้เปิดตรวจสอบโค้ดในเมนูหลัก เลือกโปรเจกต์ แล้วกดตรวจสอบโค้ด ตัวตรวจสอบทำงานในโทรศัพท์ (ไม่ต้องใช้อินเทอร์เน็ต) และค้นหาตัวแปรที่ไม่ได้ใช้ ฟังก์ชันว่าง ลูปที่ไม่มีที่สิ้นสุดอย่างชัดเจน ข้อความที่เขียนตรงในโค้ด (ควรอยู่ใน strings.xml จะดีกว่า) สิทธิ์และ API ที่อันตราย เครื่องหมาย TODO/FIXME และการรันแบบไดนามิก ผลการค้นหาแต่ละรายการมีชื่อไฟล์ หมายเลขบรรทัด และคำแนะนำในการแก้ไข ตัวตรวจสอบนี้ใช้รูปแบบเป็นฐาน ไม่ใช่ AI จริง — ปัญหาที่ไม่เป็นไปตามรูปแบบก็ยังอาจหลุดรอดได้

โหมดการเรียนรู้แบบโต้ตอบ
หากต้องการเรียนรู้การสร้างแอปทีละขั้นตอน ให้เปิดเรียนรู้ในเมนูหลัก มี 5 บทเรียน ได้แก่ การสร้างโปรเจกต์แรก การเพิ่มปุ่ม การเปลี่ยนสี การเพิ่มเสียง และการสร้าง APK แตะบทเรียนเพื่ออ่านคำอธิบายและงานฝึกหัด ทำงานนั้น แล้วกดตรวจสอบงาน — IDE จะตรวจสอบจริงว่างานเสร็จแล้วหรือไม่ (โดยสแกนโปรเจกต์และ APK ในโทรศัพท์ของคุณ) บทเรียนที่ผ่านจะถูกทำเครื่องหมายว่าเสร็จแล้วและบันทึกไว้

ซิงค์คลาวด์
หากต้องการสำรองโปรเจกต์ไปยังคลาวด์ ให้เปิดซิงค์คลาวด์ในเมนูหลัก การสำรองในเครื่องจะบันทึก ZIP โปรเจกต์ไปยังโฟลเดอร์ Download/cloud พร้อมประทับเวลา และสามารถกู้คืนได้ทุกเมื่อจากรายการสำรอง การสำรอง GitHub จะอัปโหลด ZIP โปรเจกต์ไปยัง repo ส่วนตัวของคุณ (ใช้โทเค็นจากการตั้งค่า GitHub) และดาวน์โหลดกลับมาได้อีก นี่คือการสำรองและกู้คืนด้วยตนเอง — การซิงค์สองทางอัตโนมัติเต็มรูปแบบต้องใช้เซิร์ฟเวอร์ จึงยังไม่มี

เครื่องมือสร้างแบ็กเอนด์อัตโนมัติ
หากต้องการสร้างแบ็กเอนด์โดยไม่ต้องเขียนโค้ดเซิร์ฟเวอร์ ให้เปิดเครื่องมือสร้างแบ็กเอนด์ในเมนูหลัก เลือกประเภทแบ็กเอนด์ (โน้ต รายการงาน หรือกระดานข้อความ) กรอกชื่อโปรเจกต์ แล้วกดสร้าง Backend IDE จะสร้างโปรเจกต์ HTML จริงที่มีหน้าฟอร์มและรายการข้อมูลที่เก็บไว้ในที่เก็บข้อมูลภายในโทรศัพท์ (localStorage) — ข้อมูลจะถูกบันทึกและอ่านกลับได้เมื่อรันแอป แบ็กเอนด์นี้ทำงานบนโทรศัพท์เครื่องเดียว โทรศัพท์สองเครื่องยังแชร์ข้อมูลเดียวกันไม่ได้เพราะไม่มีเซิร์ฟเวอร์อินเทอร์เน็ต

ตัวออกแบบธีมอัตโนมัติ
หากต้องการให้ธีมสีแก่โปรเจกต์ ให้เปิดนักออกแบบธีมในเมนูหลัก เลือกโปรเจกต์และธีม (สว่าง มืด น้ำเงิน เขียว แดง หรือม่วง) ตัวอย่างจะแสดงหกสีของธีม (หลัก หลักเข้ม เน้น พื้นหลัง ข้อความ ข้อความรอง) และ Jieshuo จะอ่านออกเสียง กดใช้ธีม — IDE จะเขียน colors.xml และ styles.xml (สไตล์ app_theme) ลงในโปรเจกต์ ใช้โดยตรงเมื่อรันหรือสร้างโปรเจกต์

เครื่องมือสร้างแอนิเมชัน
หากต้องการให้แอนิเมชันแก่โปรเจกต์ ให้เปิดเครื่องมือสร้างแอนิเมชันในเมนูหลัก เลือกโปรเจกต์ ประเภทแอนิเมชัน (เฟด เลื่อน หมุน เด้ง หรือเต้นเป็นจังหวะ) ระยะเวลา (100 ถึง 10000 มิลลิวินาที) และเป้าหมาย (ปุ่ม ข้อความ หรือรูปภาพ) แล้วกดสร้างแอนิเมชัน IDE จะเขียนไฟล์แอนิเมชันจริง (res/anim/anim_<ประเภท>.xml สำหรับโปรเจกต์ Java/Kotlin/Compose หรือ animasi.css สำหรับโปรเจกต์ HTML/เว็บไซต์) พร้อมโค้ดตัวอย่างวิธีใช้ที่แสดงบนหน้าจอ

เครื่องบันทึกการกระทำ
หากต้องการทำงานซ้ำโดยอัตโนมัติ IDE จะบันทึกการกระทำที่ทำไป (เปิดโปรเจกต์ รัน สร้าง ส่งออก สำรอง สร้างโปรเจกต์ บันทึกไฟล์) เปิดเครื่องบันทึกการกระทำในเมนูหลักเพื่อดูรายการการกระทำที่บันทึกไว้พร้อมแผนของมัน แล้วกดเล่นซ้ำ — IDE จะรันการกระทำที่สามารถทำให้เป็นอัตโนมัติได้อีกครั้ง (สำรองและสร้างโปรเจกต์รันทันที รัน สร้าง และส่งออกเปิดหน้าจอหลักของมัน เปิดและบันทึกเปิดตัวแก้ไข) การกระทำที่ไม่สามารถทำให้เป็นอัตโนมัติได้จะถูกข้ามและรายงานในตอนท้าย

ความปลอดภัยอัตโนมัติ
หากต้องการตรวจสอบความปลอดภัยของโปรเจกต์ ให้เปิดความปลอดภัยอัตโนมัติในเมนูหลัก เลือกโปรเจกต์ แล้วกดตรวจสอบความปลอดภัย IDE จะตรวจสอบ 8 อย่างในเครื่อง (ไม่ต้องใช้อินเทอร์เน็ต) ได้แก่ สิทธิ์อันตราย (ตำแหน่ง SMS โทรศัพท์ กล้อง ไมโครโฟน รายชื่อ) การส่งข้อมูลผ่าน HTTP การส่ง SMS โทรศัพท์ออก รหัสผ่านหรือคีย์ที่เขียนตรงในโค้ด WebView ที่ไม่มีการป้องกัน ส่วนประกอบที่ส่งออกโดยไม่มีสิทธิ์ และที่อยู่ http ที่ไม่มีการเข้ารหัส ผลการค้นหาแต่ละรายการจะได้รับระดับปลอดภัย คำเตือน หรืออันตราย พร้อมคำแนะนำในการแก้ไข และสรุปจะถูกอ่านออกเสียงโดย Jieshuo

AI ออฟไลน์
หากต้องการใช้เครื่องมือช่วยข้อความและโค้ดโดยไม่ต้องใช้อินเทอร์เน็ต ให้เปิด AI ออฟไลน์ในเมนูหลัก มี 4 เครื่องมือ ได้แก่ แก้ไขข้อความ (ตัวพิมพ์ใหญ่ เครื่องหมายวรรคตอน และช่องว่างซ้ำ) สรุปข้อความ (หยิบ 3 ประโยคที่สำคัญที่สุด) สร้างชื่อแอป (จากคำอธิบายที่เขียน) และแนะนำชื่อตัวแปร (ค้นหาชื่อตัวแปร 1-2 ตัวอักษรในโปรเจกต์) นี่คือกฎง่าย ๆ ในโทรศัพท์ ไม่ใช่โมเดล AI จริง ผลการแก้ไขข้อความสามารถนำไปใช้กับ strings.xml ของโปรเจกต์ได้ด้วยปุ่มนำไปใช้

ตัวสร้างวิดเจ็ตและวอลเปเปอร์
หากต้องการสร้างวิดเจ็ตหน้าจอหลัก ให้เปิดวิดเจ็ตและวอลเปเปอร์ในเมนูหลัก เลือกโปรเจกต์ กรอกข้อความวิดเจ็ต แล้วกดสร้าง Widget IDE จะเขียน WidgetSaya.java เลย์เอาต์วิดเจ็ต ข้อมูลวิดเจ็ต และเพิ่ม receiver ลงใน AndroidManifest.xml ของโปรเจกต์ — สร้างโปรเจกต์ แล้วติดตั้งวิดเจ็ตจากหน้าจอหลักของโทรศัพท์ สำหรับวอลเปเปอร์ ให้กรอกข้อความและสีพื้นหลังกับสีข้อความ สร้างตัวอย่าง แล้วบันทึกเป็น PNG ไปยังโฟลเดอร์ Download หรือตั้งเป็นวอลเปเปอร์โทรศัพท์โดยตรง

การผสานรวมโซเชียลมีเดีย
หากต้องการเพิ่มปุ่มแชร์ลงในแอป ให้เปิดการผสานรวมโซเชียลมีเดียในเมนูหลัก เลือกโปรเจกต์ แล้วเพิ่มการแชร์ไปยัง WhatsApp, Facebook หรือ Telegram (หรือทั้งสามพร้อมกัน) IDE จะเขียนโค้ดแชร์จริงลงในไฟล์หลักของโปรเจกต์ (MainActivity หรือ index.html) ปุ่มทดสอบการแชร์จะเปิดตัวเลือกการแชร์จาก IDE พร้อมข้อความตัวอย่าง เพื่อให้สัมผัสขั้นตอนก่อนสร้างแอป

แอปจากรูปภาพ
หากต้องการสร้างแอปแกลเลอรีจากรูปภาพ ให้เปิดแอปจากรูปภาพในเมนูหลัก เลือกรูปภาพจากแกลเลอรี IDE จะวิเคราะห์ขนาดและสีเด่นของรูปภาพ แล้วสร้างโปรเจกต์แอปแกลเลอรีจริง รูปภาพจะถูกคัดลอกไปยัง assets ของโปรเจกต์ สีธีมนำมาจากสีเด่นของรูปภาพ และชื่อแอปนำมาจากชื่อไฟล์รูปภาพ เปิดจัดการโปรเจกต์เพื่อรันหรือสร้างแอปแกลเลอรีนั้น

Terminal แบบโต้ตอบ (ตัวแยกวิเคราะห์ VT)
หากต้องการใช้โปรแกรมแบบโต้ตอบใน Terminal ให้เปิด Terminal ในเมนูหลัก แล้วรัน nano, vim, top หรือ htop Terminal ตอนนี้ใช้ตัวแยกวิเคราะห์ VT (หน้าจอกริด 24 แถว x 80 คอลัมน์) เพื่อให้โปรแกรมเหล่านั้นแสดงผลถูกต้อง — เคอร์เซอร์เคลื่อนที่ บรรทัดถูกลบ และหน้าจอเปลี่ยนเหมือนในเทอร์มินัลจริง มีปุ่มพิเศษ Tab, ลูกศรขึ้น, ลูกศรลง และ Esc เพื่อควบคุมโปรแกรมแบบโต้ตอบ ผลลัพธ์ยังคงเป็นข้อความที่ Jieshuo อ่านได้ กดอ่านหน้าจอออกเสียงเพื่อฟังบรรทัดสุดท้าย

Terminal Exec (ไบนารีของแอป)
หากต้องการรันไบนารีในโฟลเดอร์แอป (เช่น aapt2, ECJ, D8) จาก Terminal ให้พิมพ์คำสั่งตามปกติ IDE ใช้ libkautsarexec.so เพื่อให้ไบนารีในโฟลเดอร์แอปสามารถรันได้บน Android 10 ขึ้นไป กดทดสอบ Exec ใน Terminal เพื่อตรวจสอบว่าเส้นทาง exec ของไบนารีทำงานบนโทรศัพท์นี้หรือไม่ — ผลลัพธ์จะแสดงตามที่เป็น หาก exec ถูกระบบบล็อก คำสั่งระบบและสคริปต์เชลล์ยังคงทำงาน ให้รันไบนารีผ่านเมนูสร้างโปรเจกต์แทน

Terminal คงอยู่ตลอด (KeepAlive)
หากต้องการให้ shell ทำงานต่อไปขณะย้ายไปหน้าจออื่น ให้เปิด Terminal รันคำสั่ง แล้วกดกลับหรือย้ายไปหน้าจออื่น — shell จะไม่ตาย และการแจ้งเตือน Terminal ยังคงแสดงอยู่เพื่อให้คุณกลับมาได้ด้วยการแตะเพียงครั้งเดียว คำสั่งที่รันไปแล้วจะถูกเก็บในประวัติ (ปุ่มประวัติ หรือลูกศรขึ้น/ลงในช่องคำสั่ง) และคำสั่งที่ใช้บ่อยสามารถบันทึกเป็นรายการโปรดได้ (ปุ่มรายการโปรด) กดปิด shell เมื่อเสร็จแล้ว เพื่อให้ shell สิ้นสุดจริง นอกจากนี้ยังมีปุ่มสร้างใน Terminal ในเมนูโปรเจกต์และในเมนูตัวแก้ไข Terminal จะเปิดในโฟลเดอร์โปรเจกต์พร้อมคำสั่งสร้างที่กรอกไว้แล้ว

ติดตั้งเครื่องมือ Terminal (ทดลอง)
คุณสมบัติที่ยังอยู่ระหว่างการทดลอง ใน Terminal มีปุ่มติดตั้งเครื่องมือ Terminal เพื่อติดตั้งสภาพแวดล้อม Termux จากมิเรอร์ใน repo alat-termux ของนักพัฒนา (github.com/syudat/alat-termux) เป็นอีกเส้นทางหนึ่งนอกเหนือจากปุ่มติดตั้ง Termux ที่นำมาจากรีลีสอย่างเป็นทางการของ Termux เนื้อหาของมิเรอร์เหมือนกับรีลีสอย่างเป็นทางการทุกประการและได้รับการตรวจสอบด้วย SHA-256 ระหว่างการติดตั้ง หลังจากติดตั้งสภาพแวดล้อมแล้ว สามารถใช้คำสั่ง pkg update และ pkg install ได้ และเครื่องมือเพิ่มเติมจาก repo ก็จะถูกติดตั้งลงในเทอร์มินัลด้วย ได้แก่ info-terminal เพื่อดูข้อมูลสภาพแวดล้อม bersih-terminal เพื่อล้างแคช และ cadangkan-proyek เพื่อเก็บโฟลเดอร์โปรเจกต์เป็นไฟล์ tar.gz ไฟล์เดียวที่มีวันที่ หลังจากนั้นแอปจะติดตั้งแพ็กเกจ Linux พื้นฐาน (git, python, curl, wget, nano, openssh, zip, unzip) และเครื่องมือสร้าง APK พร้อมลายเซ็น (openjdk-21, kotlin, gradle, ecj, aapt2, d8, apksigner, clang, cmake, ninja, make) จาก repo อย่างเป็นทางการของ Termux โดยอัตโนมัติ เพื่อให้เทอร์มินัลพร้อมสร้างแอปได้ทันที การดาวน์โหลดแพ็กเกจขนาดใหญ่ (หลายร้อย MB) อาจใช้เวลานาน ขณะติดตั้ง ความคืบหน้าและผลลัพธ์ของคำสั่งจะแสดงบนหน้าจอหลักของ Terminal และผลลัพธ์สุดท้ายจะถูกอ่านออกเสียงโดยโปรแกรมอ่านหน้าจอ หากการติดตั้งแพ็กเกจยังไม่เสร็จ ให้กดติดตั้งเครื่องมือ Terminal อีกครั้งเพื่อดำเนินการต่อ

โหมดเสียงเต็มรูปแบบ
หากต้องการควบคุม IDE ทั้งหมดด้วยเสียง ให้เปิดโหมดเสียงเต็มรูปแบบในเมนูหลัก แล้วกดเริ่มฟัง IDE จะฟังอย่างต่อเนื่อง — ไม่ต้องกดปุ่มสำหรับแต่ละคำสั่ง — รันคำสั่งและตอบด้วยเสียง มี 26 คำสั่ง ได้แก่ สร้าง สร้าง รัน เปิด แสดงรายการ ค้นหา ลบ ทดสอบ ตรวจสอบ ส่งออก สำรอง แชร์ สร้างไอคอน แปล สร้างในเทอร์มินัล อ่านหน้าจอ เปิดหน้าจอทั้งหมด (รวมถึงความปลอดภัย AI ออฟไลน์ วิดเจ็ต โซเชียลมีเดีย เกม เรียนรู้ คลาวด์ แบ็กเอนด์ ธีม แอนิเมชัน ตัวบันทึก) กลับ ปิด และช่วยเหลือ หากปล่อยโหมดไว้ การฟังจะดำเนินต่อโดยอัตโนมัติเมื่อเปิดหน้าจอนี้อีกครั้ง กดหยุดฟังเพื่อปิดโหมดนี้ หากโทรศัพท์ไม่มีบริการรู้จำเสียง คำสั่งยังคงพิมพ์ในกล่องข้อความได้

ตัวแปลโค้ด
หากต้องการแปลโค้ดระหว่างภาษาโดยไม่ต้องใช้อินเทอร์เน็ต ให้เปิดตัวแปลโค้ดในเมนูหลัก เลือกโปรเจกต์ เลือกไฟล์ต้นฉบับ (.java/.kt) แล้วเลือกทิศทาง Java เป็น Kotlin กดแปล — ผลลัพธ์จะแสดงพร้อมรายงานบรรทัดที่ไม่สามารถแปลได้ (บรรทัดเหล่านั้นจะถูกเก็บไว้ตามเดิมและทำเครื่องหมายไว้) กดบันทึกผลลัพธ์เพื่อเขียนไฟล์ใหม่ (ชื่อ-แปล.java/.kt) ในโฟลเดอร์เดียวกัน ไฟล์ต้นฉบับจะไม่ถูกเขียนทับเลย นี่คือตัวแปลตามกฎรูปแบบ ไม่ใช่คอมไพเลอร์ — ตรวจสอบผลลัพธ์เสมอก่อนใช้

Git ในแอป
หากต้องการใช้ Git ใน IDE โดยไม่ต้องใช้ Termux ให้เปิด Git ในแอปในเมนูหลัก เลือกโปรเจกต์ แล้วกดสร้าง Repo Git เพื่อสร้าง repo ในเครื่อง (.git) ในโปรเจกต์นั้น กดตรวจสอบสถานะเพื่อดูไฟล์ใหม่ เปลี่ยนไป หรือถูกลบเมื่อเทียบกับ commit ล่าสุด กรอกข้อความ commit แล้วกด Commit เพื่อบันทึก snapshot ของโปรเจกต์ กดดู Log Commit เพื่อดูประวัติ commit Push ไปยัง GitHub และ Pull จาก GitHub ใช้ snapshot ผ่านโทเค็น GitHub (repo pembuat-aplikasi-build) — ไม่ใช่โปรโตคอล git Clone, Push (git ระบบ) และ Pull (git ระบบ) จะทำงานก็ต่อเมื่อไบนารี git ติดตั้งอยู่บนโทรศัพท์ (ปกติไม่มี) นี่ไม่ใช่ git แบบเต็ม ไม่มี merge, branch หรือ diff — แต่ละ commit จะบันทึก snapshot ZIP ทั้งโปรเจกต์

เครื่องมือสร้างโฆษณา
หากต้องการเพิ่มโฆษณาลงในแอปที่สร้างแล้ว ให้เปิดเครื่องมือสร้างโฆษณาในเมนูหลัก เลือกโปรเจกต์ ผู้ให้บริการ (AdMob, Unity Ads หรือ AppLovin) และประเภทโฆษณา (แบนเนอร์ คั่นระหว่างหน้า หรือแบบมีรางวัล) กรอก ID หน่วยโฆษณาหากมีแล้ว — ว่างหมายถึงใช้ ID ทดสอบ (AdMob ใช้ ID ทดสอบอย่างเป็นทางการของ Google; Unity ใช้ Game ID ตัวอย่าง; AppLovin ใช้ช่องว่าง) กดสร้างโค้ดโฆษณาเพื่อดูโค้ด Java, Kotlin และคำแนะนำ กดบันทึกไปยังโปรเจกต์เพื่อเขียนทุกอย่างลงในไฟล์โฆษณา-<ผู้ให้บริการ>-<ประเภท>.txt ในโปรเจกต์ นี่คือเทมเพลตโค้ด + คำแนะนำ ไม่ใช่ SDK โฆษณา — SDK ไม่ได้รวมอยู่ใน IDE โฆษณาจริงจะแสดงก็ต่อเมื่อคุณสร้างบัญชีผู้ให้บริการ สร้างหน่วยโฆษณา วาง ID หน่วยของตัวเอง และเพิ่ม dependency SDK ลงใน build.gradle ของโปรเจกต์

โหมดเด็ก
หากต้องการใช้ IDE ร่วมกับเด็ก ให้เปิดโหมดเด็กในเมนูหลัก หน้าจอถูกทำให้ง่ายขึ้นด้วยปุ่มขนาดใหญ่และมีเพียง 4 การกระทำที่ปลอดภัย ได้แก่ สร้างโปรเจกต์ (จากเทมเพลตที่ปลอดภัย เครื่องคิดเลข ทายตัวเลข แบบทดสอบ จับดาว) เปิดโปรเจกต์ รัน และเรียนรู้ ไม่มีปุ่มลบ ส่งออก สำรอง หรือตั้งค่าโทเค็นบนหน้าจอนี้ เมื่อเข้าครั้งแรก ให้สร้าง PIN 4 หลัก — PIN นั้นผู้ปกครองใช้เพื่อออกจากโหมดเด็ก (ปุ่มออกจากโหมดเด็กหรือปุ่มกลับ) PIN นี้เป็นการป้องกันเบา ๆ สำหรับเด็กเล็ก ไม่ใช่ความปลอดภัยจริง

ตัวสร้างแอป Wear OS และ TV
หากต้องการสร้างแอปนาฬิกา (Wear OS) หรือแอป TV (Android TV) ให้เปิด Wear OS และ TV ในเมนูหลัก เลือกเป้าหมาย (Wear OS, Android TV หรือทั้งสอง) กรอกชื่อโปรเจกต์แล้วกดสร้างโปรเจกต์ใหม่ Wear/TV — IDE จะสร้างโปรเจกต์ Java แล้วปรับแต่ง — หรือเลือกโปรเจกต์ที่มีอยู่แล้วแล้วกดใช้กับโปรเจกต์นี้ การปรับแต่ง ได้แก่ uses-feature ใน manifest หมวด LEANBACK_LAUNCHER + banner สำหรับ TV และเลย์เอาต์ activity_main.xml ที่ปรับแล้ว (Wear: หน้าจอเล็ก; TV: หน้าจอใหญ่เหมาะกับ D-pad) คำอธิบายทั้งหมดเขียนลงใน wear-tv.txt ในโปรเจกต์ นี่คือเทมเพลตโปรเจกต์ — การสร้าง + ทดสอบยังต้องใช้อุปกรณ์/โปรแกรมจำลอง Wear OS หรือ Android TV แบนเนอร์ TV (banner.png 320x180) ไม่ได้สร้างอัตโนมัติ ต้องเพิ่มเอง (เช่น ผ่านเครื่องมือสร้างไอคอน)

แผนที่โปรเจกต์
หากต้องการดูโครงสร้างของโปรเจกต์ ให้เปิดแผนที่โปรเจกต์ในเมนูหลัก เลือกโปรเจกต์ แล้วกดแสดงแผนที่ — IDE จะแสดงรายการโฟลเดอร์และไฟล์พร้อมขนาด ขนาดรวม ขนาดตามประเภทไฟล์ และไฟล์สำคัญ (ไฟล์หลัก manifest เลย์เอาต์ strings ไอคอน หน้าเว็บ) กดบันทึก peta-proyek.txt เพื่อเขียนแผนที่เดียวกันไปยังรากของโปรเจกต์ โฟลเดอร์ bin/ (ผลการสร้าง) และ .git/ (repo ในเครื่อง) ไม่รวมอยู่ในแผนที่เพราะเนื้อหาสามารถสร้างใหม่ได้

เครื่องคำนวณขนาด APK
หากต้องการประมาณขนาด APK ที่สร้างก่อนสร้าง ให้เปิดเครื่องคำนวณขนาด APK ในเมนูหลัก เลือกโปรเจกต์ แล้วกดคำนวณค่าประมาณ IDE จะแสดงรายละเอียดตามหมวดหมู่ (โค้ด/DEX ทรัพยากร แอสเซ็ต ไลบรารีดั้งเดิม manifest + resources.arsc ค่าใช้จ่ายเพิ่มเติม) ยอดประมาณทั้งหมด ไฟล์ที่ใหญ่ที่สุด 5 ไฟล์ และคำแนะนำในการย่อขนาด (เช่น รูปภาพขนาดใหญ่ลดความละเอียด เสียงขนาดใหญ่ตัดระยะเวลา) นี่คือค่าประมาณ ไม่ใช่ขนาดที่แน่นอน — ขนาดจริงอาจต่างกันเนื่องจากการบีบอัด aapt2 การลบโค้ดที่ไม่ได้ใช้ (R8) และทรัพยากรผลการสร้าง

ตัววิเคราะห์ APK
หากต้องการอ่านเนื้อหาของ APK ที่เสร็จแล้ว (เช่น APK Analyzer ใน Android Studio) ให้เปิดตัววิเคราะห์ APK ในเมนูหลัก เลือกโปรเจกต์ แล้วกดการวิเคราะห์ APK ผลการสร้าง IDE จะอ่าน APK ล่าสุดในโฟลเดอร์ bin ของโปรเจกต์นั้นและรายงานชื่อแพ็กเกจ เวอร์ชัน SDK ขั้นต่ำและเป้าหมาย รายการสิทธิ์ที่ใช้ จำนวนไฟล์ dex รายละเอียดขนาดตามส่วน (โค้ดโปรแกรม ทรัพยากร แอสเซ็ต ไลบรารีดั้งเดิม ลายเซ็น) และ 10 รายการที่ใหญ่ที่สุด มีประโยชน์เพื่อรู้ว่าส่วนใดทำให้ APK ใหญ่และแอปที่สร้างใช้สิทธิ์ใดบ้าง

ตัวอย่างขนาดหน้าจอ
หากต้องการตรวจสอบรูปลักษณ์ของโปรเจกต์บนหลายขนาดหน้าจอพร้อมกัน (เช่นใน Android Studio) ให้เปิดตัวอย่างขนาดหน้าจอในเมนูหลัก เลือกโปรเจกต์ แล้วกดตรวจสอบขนาดหน้าจอ IDE จะอ่านเลย์เอาต์ทั้งหมดของโปรเจกต์และรายงานองค์ประกอบที่มีความกว้างเขียนแบบคงที่ (เช่น 400dp) และเกินความกว้างหน้าจอ 320, 360, 411 หรือ 480 dp เพราะบนโทรศัพท์จอเล็ก องค์ประกอบเช่นนั้นอาจถูกบังหรือล้นออกไป องค์ประกอบที่มีความกว้าง match_parent หรือ wrap_content จะปรับตามหน้าจอโดยอัตโนมัติและไม่ต้องตรวจสอบ

ตัวจัดการทรัพยากร
หากต้องการดูและจัดการทรัพยากรทั้งหมดของโปรเจกต์ในที่เดียว (เช่น Resource Manager ใน Android Studio) ให้เปิดตัวจัดการทรัพยากรในเมนูหลัก เลือกโปรเจกต์ แล้วกดดูทรัพยากร IDE จะรายงานจำนวนและขนาดไฟล์ตามหมวดหมู่ (drawable, layout, values, mipmap และอื่น ๆ) เนื้อหาของ strings.xml, colors.xml และ styles.xml จากหน้าจอเดียวกัน สามารถเพิ่มสตริงใหม่ลงใน strings.xml และสีใหม่ลงใน colors.xml ได้โดยกรอกชื่อและค่า — ชื่อจะถูกตรวจสอบและรายการซ้ำจะถูกปฏิเสธ เพื่อไม่ให้ไฟล์ XML เสียหาย

ตัวตรวจสอบประสิทธิภาพแบบเบา
หากต้องการตรวจสอบการใช้ RAM และโปรเซสเซอร์ของแอปที่กำลังทำงาน (เช่น Profiler ใน Android Studio รุ่นเบา) ให้เปิดตัวตรวจสอบประสิทธิภาพแบบเบาในเมนูหลัก ก่อนอื่นให้รันแอปที่ต้องการตรวจสอบ (เช่น แอปที่สร้างแล้วที่กำลังลอง) กรอกชื่อแพ็กเกจของมัน — หรือเลือกโปรเจกต์แล้วกดกรอกชื่อแพ็กเกจจากโปรเจกต์ — แล้วกดเริ่มตรวจสอบ IDE จะบันทึก RAM (PSS) และ CPU ของแอปนั้นพร้อม RAM ว่างของโทรศัพท์ทุก 2 วินาที กดหยุดเพื่อดูสรุปค่าเฉลี่ยและค่าสูงสุด ไม่ต้องมีสิทธิ์เพิ่มเติม ใน Android รุ่นใหม่ การเข้าถึงอ่านโปรเซสเซอร์ของแอปอื่นถูกระบบจำกัด ดังนั้นหากอ่าน CPU ไม่ได้ รายงานจะบอกตามนั้นและยังตรวจสอบ RAM ต่อไป

การตรวจสอบการเข้าถึง
เพื่อตรวจสอบว่าเลย์เอาต์ของโปรเจกต์เป็นมิตรกับโปรแกรมอ่านหน้าจอ (TalkBack/Jieshuo) หรือไม่ก่อนเผยแพร่: เปิดการตรวจสอบการเข้าถึงในเมนูหลัก เลือกโปรเจกต์ แล้วแตะโหลดรายการเลย์เอาต์และเลือกไฟล์เลย์เอาต์ IDE จะอ่านไฟล์ XML นั้นและรายงานปุ่มที่ไม่มีป้ายกำกับพร้อมหมายเลขบรรทัด ป้ายกำกับที่ใช้ซ้ำ และองค์ประกอบที่ทับซ้อนกัน จากนั้นจัดทำบันทึกย่อลำดับโฟกัสเหมือนที่ Jieshuo อ่านออกเสียง หากปุ่มใดไม่มีป้ายกำกับ ให้กรอกป้ายกำกับแล้วแตะแทรกป้ายกำกับอัตโนมัติ — ป้ายกำกับจะถูกเขียนลงในไฟล์เลย์เอาต์เป็น contentDescription การตรวจสอบนี้อ่านเฉพาะ XML เลย์เอาต์เท่านั้น มุมมอง Compose และ APK ที่เสร็จแล้ว ยังไม่ถูกสแกน

การชันสูตรข้อขัดข้อง
หากต้องการทราบว่าแอปปิดตัวเองทำไม จากบันทึกข้อขัดข้องที่มี ID เฉพาะ: เปิด «การชันสูตรข้อขัดข้อง» ในเมนูหลัก เลือก ID ข้อขัดข้องจากรายการบันทึก แล้วแตะ «ตรวจสอบ» IDE จะจับคู่คลาสและหมายเลขบรรทัดในบันทึกกับซอร์สของโปรเจกต์และอธิบายสาเหตุเป็นภาษาอินโดนีเซีย (เช่น การอ้างอิงว่าง สิทธิ์ที่ยังไม่ได้ขอ หรือข้อผิดพลาด JSON) พร้อมข้อเสนอแนะแพตช์โค้ด แตะ «ใช้แพตช์» เฉพาะเมื่อบรรทัดซอร์สยังคงเหมือนเดิมทุกประการกับตอนที่ข้อขัดข้องเกิดขึ้น; หากเปลี่ยนไป แพตช์จะถูกปฏิเสธและ IDE จะขอให้คุณตรวจสอบด้วยตนเอง สำหรับข้อขัดข้องของแอปที่สร้างแล้ว แตะ «แทรกตัวดักแครชลงในโปรเจกต์» แล้วสร้าง APK ตามปกติ: แอปที่สร้างแล้วนั้นจะดักข้อขัดข้องของตัวเองและเขียนบันทึกลงบนโทรศัพท์ และบันทึกนั้นสามารถพบได้ด้วยปุ่ม «ค้นหาบันทึกแครชแอปที่สร้างแล้ว» ขีดจำกัดที่ซื่อสัตย์: การคัดลอกบันทึกไปยังโฟลเดอร์ Download สาธารณะใน Android 11 ขึ้นไปอาจล้มเหลวหากไม่มีสิทธิ์เข้าถึงไฟล์ทั้งหมด

ตัวแปลงข้ามกระบวนทัศน์
เพื่อแปลงโค้ด Java แบบง่ายเป็น Kotlin หรือเลย์เอาต์ XML แบบง่ายเป็นโค้ด Compose: เปิดตัวแปลงข้ามกระบวนทัศน์ในเมนูหลัก เลือกโปรเจกต์และไฟล์ แล้วแตะดูตัวอย่าง IDE จะแสดงผลการแปลงเป็นข้อความ — ตรวจสอบก่อน เพราะบรรทัดที่ไม่รู้จักจะถูกปล่อยไว้ตามเดิม และคำว่า static ใน Java จะถูกตัดออกใน Kotlin (ตรวจสอบความหมายก่อนใช้) การแปลง XML เป็น Compose จะเปลี่ยนเฉพาะข้อความ คำแนะนำ และทิศทางเท่านั้น — ขนาด สี และแอตทริบิวต์อื่นยังไม่รวม หากผลลัพธ์ถูกต้อง แตะใช้กับไฟล์เพื่อเขียนไฟล์ปลายทาง ไฟล์ต้นฉบับจะไม่ถูกเปลี่ยน จะแปลงเฉพาะรูปแบบทั่วไปที่ปลอดภัยเท่านั้น

เซิร์ฟเวอร์ขนาดเล็กในเครื่อง
หากต้องการทดสอบแอปที่ต้องการเซิร์ฟเวอร์โดยไม่มีอินเทอร์เน็ต: เปิด «เซิร์ฟเวอร์ขนาดเล็กในเครื่อง» ในเมนูหลัก เขียนนิยามเส้นทาง (เช่น GET /halo แล้วตามด้วยคำตอบ JSON ของมัน) แล้วแตะ «เริ่มเซิร์ฟเวอร์» IDE จะรันเซิร์ฟเวอร์ HTTP ขนาดเล็กบนโทรศัพท์เครื่องเดียวกัน (HTTP เท่านั้น ไม่มี TLS สำหรับเครือข่าย Wi-Fi เดียวกัน) และบันทึกทุกคำขอและคำตอบบนหน้าจอ เส้นทางสามารถใช้พารามิเตอร์เช่น {nama} และคีย์ API อย่างง่าย เซิร์ฟเวอร์ยังสามารถแพ็กลงใน APK ที่สร้างแล้วได้: แตะ «แพ็กเซิร์ฟเวอร์ลงในโปรเจกต์» และซอร์สเซิร์ฟเวอร์ แอสเซ็ต และมานิเฟสต์จะถูกแทรกเข้าไปในโปรเจกต์ ดังนั้นแอปที่สร้างแล้วจะกลายเป็นเซิร์ฟเวอร์เมื่อทำงาน เซิร์ฟเวอร์ใน IDE จะหยุดเมื่อหน้าจอของมันถูกปิด

ผู้ตรวจสอบความปลอดภัย
หากต้องการตรวจสอบโค้ดโปรเจกต์หาช่องโหว่ด้านความปลอดภัยก่อนเผยแพร่: เปิด «ผู้ตรวจสอบความปลอดภัย» ในเมนูหลัก เลือกโปรเจกต์ แล้วแตะ «เริ่มการสแกน» IDE จะสแกนโค้ดโปรเจกต์ มานิเฟสต์ และการกำหนดค่า และรายงานผลการค้นหาจากความเสี่ยงสูงไปต่ำ — คีย์ API ที่ถูกทิ้งไว้เปิดในโค้ด คอมโพเนนต์ที่ถูกเปิดเผยโดยไม่มีสิทธิ์ WebView ที่เปิด JavaScript พร้อมอินเทอร์เฟซ JavaScript ของมัน การเข้ารหัสที่อ่อนแอ (MD5, SHA1, DES) ที่อยู่ http ที่ไม่มี TLS และรหัสผ่านที่เขียนลงในโค้ดโดยตรง — พร้อมไฟล์และหมายเลขบรรทัดของพวกมัน สำหรับผลการค้นหาที่การแก้ไขปลอดภัย (เช่น เปลี่ยน MD5 เป็น SHA-256 หรือ http เป็น https) แตะ «ใช้การแก้ไข»; สำหรับคีย์ API และรหัสผ่าน IDE จะแสดงเฉพาะข้อเสนอแนะการแก้ไข เพราะสิ่งทดแทนต้องเป็นผู้พัฒนาตัดสินใจเอง การสแกนตอนนี้ยังวิเคราะห์ไบต์โค้ด DEX จริงภายใน APK ที่สร้างแล้ว (ไม่ใช่แค่รูปแบบข้อความในโค้ด) ดังนั้น API ที่อันตรายที่ถูกเรียกและข้อมูลลับที่ฝังอยู่ใน DEX จึงถูกจับได้ด้วย; ช่องโหว่ที่ไม่เป็นไปตามรูปแบบอาจยังคงหลุดรอดจากการสแกน — ตรวจสอบก่อนนำไปใช้

หุ่นยนต์ทดสอบส่วนติดต่อผู้ใช้
หากต้องการทดสอบหน้าจอแอปโดยอัตโนมัติผ่านสถานการณ์ที่เป็นข้อความ: เปิด «หุ่นยนต์ทดสอบส่วนติดต่อผู้ใช้» ในเมนูหลัก เลือกโปรเจกต์ แล้วแตะ «สร้างสถานการณ์อัตโนมัติ» IDE จะอ่านมานิเฟสต์และเลย์เอาต์ของโปรเจกต์และเขียนสถานการณ์เป็นขั้นตอนข้อความ (แตะปุ่ม กรอกฟิลด์ รอ กลับ) แตะ «รันแบบแห้ง» เพื่อดูบันทึกการรันสถานการณ์พร้อมประทับเวลาของมัน — การรันแบบแห้งนี้ยังคงเป็นเพียงการจำลองลำดับ หากต้องการทดสอบจริง แตะ «แทรกตัวแทนทดสอบลงในโปรเจกต์»: IDE จะแทรกตัวแทนทดสอบพร้อมแอสเซ็ตสถานการณ์ลงในโปรเจกต์; สร้าง APK ตามปกติ ติดตั้ง แล้วเปิดไอคอน «ทดสอบ» — ตัวแทนนั้นทำงานภายในแอปที่สร้างแล้วและแตะปุ่มจริง กรอกฟิลด์จริง และเลื่อน จากนั้นแสดงรายงานบนหน้าจอพร้อมข้อขัดข้องจริงที่มันจับได้ แตะ «ลบตัวแทนทดสอบออกจากโปรเจกต์» เพื่อลบตัวแทนนั้นอีกครั้ง ตัวแทนทำงานภายในกระบวนการของแอปเอง ดังนั้นจึงไม่ต้องการบริการการเข้าถึงหรือระบบอัตโนมัติของระบบ

การเดินทางข้ามเวลาของโค้ด
เพื่อคืนโปรเจกต์สู่สถานะโค้ดก่อนหน้าโดยไม่ต้องพิมพ์คำสั่ง Git: เปิดการเดินทางข้ามเวลาของโค้ดในเมนูหลัก เลือกโปรเจกต์ กรอกป้ายกำกับจุดเวลา (เว้นว่างได้) แล้วแตะบันทึกจุดเวลา IDE จะบันทึกสำเนาไฟล์ซอร์สของโปรเจกต์พร้อมแฮชไว้ในโฟลเดอร์ .riwayat ภายในโปรเจกต์ รายการจุดเวลาจะแสดงทั้งหมด เลือกสองจุดแล้วแตะเปรียบเทียบเพื่อดูไฟล์และฟังก์ชันที่เพิ่ม เปลี่ยน หรือลบ แตะกู้คืนเพื่อกลับสู่สถานะเก่า — ก่อนกู้คืน IDE จะสำรองสถานะปัจจุบันก่อนเสมอ จึงไม่มีอะไรหาย แตะสร้างสำเนาทดลองเพื่อคัดลอกโปรเจกต์ไปยังโฟลเดอร์ใหม่และลองเปลี่ยนแปลงโดยไม่รบกวนโปรเจกต์เดิม จะบันทึกเฉพาะไฟล์ซอร์สเท่านั้น

โรงงานโมดูล
เพื่อแพ็กส่วนหนึ่งของโปรเจกต์เป็นโมดูลให้โปรเจกต์อื่นใช้: เปิดโรงงานโมดูลในเมนูหลัก เลือกโปรเจกต์ต้นทาง ติ๊กไฟล์หน้าจอ คลาส ข้อความ และสิทธิ์ที่จะแพ็ก แล้วแตะแพ็กเป็นโมดูล IDE จะเขียนไฟล์ ZIP พร้อมข้อมูล JSON (ชื่อโมดูล เวอร์ชัน ข้อความ และสิทธิ์ที่ใช้) เพื่อติดตั้งโมดูลในโปรเจกต์อื่น เปิดโรงงานโมดูล เลือกโปรเจกต์ปลายทาง แล้วแตะติดตั้งโมดูลและเลือกไฟล์ .zip ของโมดูล — การรวมจะเพิ่มข้อความและสิทธิ์โดยไม่เขียนทับโค้ดเดิม และจะไม่รวมไฟล์หากชื่อนั้นใช้แล้วในโปรเจกต์ปลายทาง โมดูลไม่นำไลบรารีหรือค่าตั้งบิลด์มาด้วย

โล่โพลีมอร์ฟิกและห้องนิรภัยแอสเซ็ต
หากต้องการสุ่มชื่อตัวระบุและเข้ารหัสแอสเซ็ตของโปรเจกต์ก่อนเผยแพร่: เปิด «โล่โพลีมอร์ฟิกและห้องนิรภัยแอสเซ็ต» ในเมนูหลัก เลือกโปรเจกต์ แล้วแตะ «สุ่มชื่อและเข้ารหัสแอสเซ็ต» IDE จะสแกนชื่อคลาสและเมธอดในซอร์สโค้ด สร้างแผนที่ชื่อสุ่ม เขียนชื่อเหล่านั้นใหม่ภายในไฟล์ DEX ที่คอมไพล์แล้ว (ชื่อแทนถูกสร้างให้ยาวเท่าชื่อเดิมเพื่อให้ออฟเซ็ตทั้งหมดยังคงใช้ได้ จากนั้นคำนวณเช็กซัมและลายเซ็น SHA-1 ของส่วนหัว DEX ใหม่) เข้ารหัสไฟล์แอสเซ็ตของโปรเจกต์ด้วย AES-GCM ในโฟลเดอร์ brankas-aset ภายในโปรเจกต์ และบันทึกแผนที่กู้คืนที่เข้ารหัสแล้ว (perisai-peta.brankas) เพื่อให้สามารถกู้คืนชื่อเดิมได้เมื่ออ่านบันทึกข้อขัดข้อง คีย์เข้ารหัสตอนนี้ได้มาจากพาสเวิร์ดของผู้พัฒนาโดยใช้ PBKDF2 จำนวน 20,000 รอบ ไม่ใช่จากชื่อโปรเจกต์อีกต่อไป ชื่อที่ถูกใช้เป็นข้อความธรรมดา ชื่อแอนโนเทชัน และชื่อดีบักด้วยจะไม่ถูกเขียนใหม่โดยเจตนา และจุดแทรกการเขียน DEX ใหม่ในเส้นทางการสร้างยังรอการทดสอบบนโทรศัพท์จริง

ห่วงโซ่ความไว้วางใจและผู้พิทักษ์สภาพแวดล้อม
หากต้องการตรวจสอบห่วงโซ่คีย์ลายเซ็นและสภาพแวดล้อมของโทรศัพท์ก่อนเผยแพร่: เปิด «ห่วงโซ่ความไว้วางใจและผู้พิทักษ์สภาพแวดล้อม» ในเมนูหลัก เลือกโปรเจกต์ แล้วแตะ «ตรวจสอบห่วงโซ่และสภาพแวดล้อม» IDE จะสร้างห่วงโซ่คีย์ 5 รุ่นจากชื่อแพ็กเกจของโปรเจกต์และตรวจสอบความสมบูรณ์ของมัน ตรวจสอบความสมบูรณ์ของหน่วยความจำจริงโดยเปรียบเทียบเนื้อหาของส่วนโค้ดในหน่วยความจำกับไฟล์บนดิสก์และรายงานการแมปที่เรียกใช้งานได้โดยไม่ระบุชื่อ (RWX) ไลบรารีแปลกปลอม และการแมป memfd จากนั้นสแกนแผนที่หน่วยความจำของกระบวนการของตนเองและคุณสมบัติของอุปกรณ์เพื่อหาร่องรอยของ Frida, Xposed หรือตัวจำลอง คีย์ห้องนิรภัยถูกห่อด้วยคีย์ AES ใน AndroidKeyStore ซึ่งใช้ชิปความปลอดภัยของฮาร์ดแวร์เมื่อมี และการหมุนเวียนคีย์ตอนนี้เป็นของจริง โดยใช้สายเลือดใบรับรองลายเซ็นของสคีมา v3: คีย์เก่าลงนามหลักฐานการหมุนเวียนไปยังคีย์ใหม่และ APK ถูกเซ็นใหม่ด้วยสายเลือดนั้น ผลลัพธ์คือระดับความเสี่ยง «ปลอดภัย» «ระมัดระวัง» หรือ «อันตราย» พร้อมหลักฐานที่เป็นข้อความ หากระบบปฏิเสธการอ่านหน่วยความจำ การตรวจสอบจะถูกรายงานว่า «ไม่สามารถตรวจสอบได้» ไม่ใช่ปลอดภัย; และคีย์หนึ่งๆ ใช้ชิปความปลอดภัยของฮาร์ดแวร์จริงหรือไม่นั้นยืนยันได้เฉพาะบนอุปกรณ์จริงเท่านั้น

สถาปนิกเลย์เอาต์ต้นไม้ข้อความ
หากต้องการออกแบบหน้าจอโดยไม่ต้องมอง: เปิด «สถาปนิกเลย์เอาต์ต้นไม้ข้อความ» ในเมนูหลัก เลือกโปรเจกต์และไฟล์เลย์เอาต์ แล้วแตะ «ตรวจสอบเลย์เอาต์» IDE จะอ่านเลย์เอาต์ XML เป็นต้นไม้ข้อความและอ่านคำบรรยายตำแหน่งของแต่ละองค์ประกอบออกเสียง (เช่น ล่างขวา ร้อยละ 45 ของความกว้างหน้าจอ) จากนั้นรายงานทางคณิตศาสตร์เกี่ยวกับองค์ประกอบที่ทับซ้อนกันและองค์ประกอบที่ออกนอกหน้าจอที่ความกว้าง 360 dp สิ่งที่คำนวณได้ตอนนี้รวมถึง LinearLayout และขนาด dp อย่างง่าย ConstraintLayout แบบเต็ม (ข้อจำกัดทั้งหมด ความเอนเอียง โซ่ เส้นบอกแนว สิ่งกีดขวาง ความกว้างเป็นเปอร์เซ็นต์ 0dp match_constraint และอัตราส่วนมิติ) และหน้าจอ Compose (Column, Row และ Box พร้อมตัวปรับขนาดของพวกมัน) เฉพาะ MotionLayout และ ConstraintSet ที่เปลี่ยนแปลงขณะทำงานเท่านั้นที่ยังคงถูกรายงานว่าตำแหน่งไม่ทราบ เพราะค่าของพวกมันมีอยู่เฉพาะเมื่อแอปกำลังทำงาน

สตูดิโอระบบออกแบบ
หากต้องการให้ระยะห่าง แบบอักษร และมุมสม่ำเสมอในทุกหน้าจอและโปรเจกต์: เปิด «สตูดิโอระบบออกแบบ» ในเมนูหลัก เลือกโปรเจกต์ เขียนโทเค็นออกแบบ (เช่น jarak=8, huruf=16, sudut=12) เลือกคอมโพเนนต์ แล้วแตะ «สร้างคอมโพเนนต์» IDE จะตรวจสอบโทเค็น — ระยะห่างพื้นฐาน 4 ถึง 16 dp แบบอักษรพื้นฐาน 12 ถึง 20 sp มุม 0 ถึง 32 dp และพื้นที่สัมผัสขั้นต่ำ 48 dp — จากนั้นเขียนคอมโพเนนต์ XML พร้อมใช้ (komponen-studio.xml) พร้อมธีม XML (tema-studio.xml) และธีม Compose (tema-studio.kt) ลงในโฟลเดอร์โปรเจกต์ โทเค็นยังสามารถบันทึกเป็นชุดที่มีชื่อในไลบรารีโทเค็นที่ใช้ร่วมกันระหว่างโปรเจกต์ และคำสั่งซิงค์เดียวจะใช้โทเค็นล่าสุดของไลบรารีกับทุกโปรเจกต์ที่ใช้ชุดนั้น คอมโพเนนต์ถูกสร้างเป็นข้อความที่วางในเลย์เอาต์แล้วตรวจสอบด้วย «สถาปนิกเลย์เอาต์ต้นไม้ข้อความ»; การปรับสองคอลัมน์บนแท็บเล็ตใช้ตัวระบุความกว้างหน้าจอ ไม่ใช่การตรวจจับอุปกรณ์ขณะทำงาน

การรีแฟกเตอร์เชิงความหมายและการนำทาง AST
หากต้องการค้นหานิยามและเปลี่ยนชื่อสัญลักษณ์โดยไม่ทำลายโค้ดอื่นที่มีชื่อเดียวกันโดยบังเอิญ: เปิด «การรีแฟกเตอร์เชิงความหมายและการนำทาง AST» ในเมนูหลัก เลือกโปรเจกต์ แล้วแตะ «สแกนสัญลักษณ์โปรเจกต์» เพื่อดูคลาสและเมธอดทั้งหมดพร้อมไฟล์และหมายเลขบรรทัดของพวกมัน พิมพ์ชื่อสัญลักษณ์ แล้วแตะ «สแกนสัญลักษณ์โปรเจกต์» อีกครั้งเพื่อดูนิยามของมันและไฟล์ทั้งหมดที่เรียกใช้มัน หากต้องการเปลี่ยนชื่อ พิมพ์ชื่อใหม่ แตะ «แสดงตัวอย่างการเปลี่ยนชื่อ» เพื่อดูจำนวนครั้งที่ปรากฏในแต่ละไฟล์ แล้วแตะ «ใช้การเปลี่ยนชื่อ» ตัวทำดัชนีตอนนี้ใช้ตัวแยกวิเคราะห์ AST ที่สร้างขึ้นเอง (ตัวแยกคำและตัวแยกวิเคราะห์แบบเรียกซ้ำสำหรับ Java และชุดย่อยของ Kotlin) ดังนั้นการเปลี่ยนชื่อเมธอดข้ามไฟล์จึงถูกแก้ไขและผู้เรียกในไฟล์อื่นก็เปลี่ยนไปด้วย; ปุ่มแยกบล็อกโค้ดออกเป็นฟังก์ชันใหม่อยู่บนหน้าจอนี้แล้ว ตัวแยกวิเคราะห์นี้ยังเป็นแบบขั้นต่ำ: เจเนอริกที่ซับซ้อนมาก แอนโนเทชันที่มีพารามิเตอร์ และคลาสนิรนามจะถูกสแกนตามที่เป็นอยู่ ขณะที่การเรียกผ่านรีเฟลกชันและผ่านอินเทอร์เฟซจะไม่ถูกแก้ไข

ดีบักเกอร์ทีละขั้นตอนและตัวตรวจสอบหน่วยความจำ
หากต้องการตรวจสอบเนื้อหาตัวแปรกลางกระแสโปรแกรมโดยไม่ต้องเดาจากบันทึก: เปิด «ดีบักเกอร์ทีละขั้นตอนและตัวตรวจสอบหน่วยความจำ» ในเมนูหลัก เลือกโปรเจกต์ เขียนร่องรอยการดำเนินการ (หนึ่งขั้นตอนต่อบรรทัด ในรูปแบบ หมายเลขบรรทัด โค้ด จากนั้นตัวแปรและค่าคั่นด้วย | เช่น 10|int total = harga * jumlah;|harga=5000, jumlah=3, total=15000) พิมพ์หมายเลขบรรทัดของจุดพัก แล้วแตะ «รันร่องรอยดีบัก» IDE จะทำงานจนถึงจุดพักแรกและอ่านบรรทัดที่ใช้งานอยู่พร้อมค่าตัวแปรออกเสียงผ่าน Jieshuo แตะ «ก้าวหนึ่งบรรทัด» เพื่อก้าวไปหนึ่งบรรทัด แตะ «เข้าสู่ฟังก์ชัน» เพื่อเข้าสู่ฟังก์ชันที่ถูกเรียก (พร้อมสแต็กการเรียก) หรือแตะ «ดำเนินการต่อ» เพื่อก้าวไปยังจุดพักถัดไป ดีบักเกอร์ร่องรอยนี้ยังคงติดตามร่องรอยที่บันทึกไว้หรือเขียนด้วยมือ; ข้างๆ มีไคลเอนต์ Java ล้วนของโพรโทคอลสาย JDWP ที่สามารถจับมือ ตั้งจุดพัก ก้าวเข้า ก้าวข้าม และก้าวออก และหยุดและดำเนินการต่อ VM ผ่าน TCP หรือในโหมดฟัง การหยุดกระบวนการจริงจากภายในแอปธรรมดายังคงเป็นไปไม่ได้อย่างสมบูรณ์ เพราะซ็อกเก็ต JDWP ของกระบวนการจะเปิดเผยผ่าน adbd เท่านั้น — เส้นทางที่พิสูจน์แล้วต้องการการดีบักแบบไร้สายและการเปิดตัวเป้าหมายผ่านเชลล์ ซึ่งอยู่นอกเหนือสิ่งที่ตัวแอปเองทำได้

ตัวจัดการการพึ่งพาออฟไลน์
หากต้องการใช้ไลบรารีของบุคคลที่สามโดยไม่ใช้อินเทอร์เน็ตและหลีกเลี่ยงความขัดแย้งของเวอร์ชันก่อนสร้าง: เปิด «ตัวจัดการการพึ่งพาออฟไลน์» ในเมนูหลัก เลือกโปรเจกต์ แล้วแตะ «ตรวจสอบการพึ่งพา» IDE จะอ่านไฟล์ .gradle ทั้งหมดของโปรเจกต์ ตรวจสอบห้องนิรภัยที่ใช้ร่วมกันระหว่างโปรเจกต์ในโฟลเดอร์ Download/brankas-bersama และแก้ไขความขัดแย้ง — หากไลบรารีสองแห่งต้องการเวอร์ชันที่แตกต่างกันของอาร์ติแฟกต์เดียวกัน เวอร์ชันสูงสุดจะถูกใช้และความขัดแย้งจะถูกรายงาน หากต้องการดาวน์โหลดไลบรารี พิมพ์พิกัดของมัน (รูปแบบ กลุ่ม:อาร์ติแฟกต์:เวอร์ชัน เช่น com.google.code.gson:gson:2.10.1) แล้วแตะ «ตรวจสอบการพึ่งพา»: เมื่อออนไลน์ ไฟล์ AAR, JAR หรือ WHL จะถูกดาวน์โหลดจริงจาก Maven, Google หรือ PyPI พร้อมกราฟการพึ่งพาแบบส่งต่อของพวกมัน (แบบเรียกซ้ำ วงจรถูกตัด ความลึกถึง 25 ระดับ) และเฉพาะไฟล์ที่ดาวน์โหลดสำเร็จเท่านั้นที่จะถูกบันทึกว่าพร้อมใช้ เมื่อออฟไลน์จะใช้ได้เฉพาะไลบรารีที่มีอยู่ในห้องนิรภัยที่ใช้ร่วมกันแล้วเท่านั้น ช่วงเวอร์ชันของ Maven จะไม่ถูกแก้ไข และไฟล์ที่ดาวน์โหลดจะถูกตรวจสอบด้วย SHA-1 ของพวกมันเท่านั้น โดยไม่มีการยืนยัน PGP

ตัวตรวจสอบฐานข้อมูลและที่เก็บข้อมูล
หากต้องการตรวจสอบและทดสอบเนื้อหาฐานข้อมูลของโปรเจกต์โดยไม่ต้องเขียนโค้ดที่พิมพ์เนื้อหาตาราง: เปิด «ตัวตรวจสอบฐานข้อมูลและที่เก็บข้อมูล» ในเมนูหลัก เลือกโปรเจกต์และไฟล์ฐานข้อมูล (.db, .sqlite หรือ .sqlite3) แล้วแตะ «เปิดฐานข้อมูล» IDE จะอ่านสคีมาของทุกตารางด้วยตัวแยกวิเคราะห์หน้า SQLite แบบเต็ม (ต้นไม้ B พร้อมหน้าล้น) และแสดง 20 แถวแรกเป็นตารางข้อความที่ Jieshuo อ่านออกเสียง เขียนคำสั่ง SELECT แล้วแตะ «รันคำสั่ง» (เช่น SELECT nama FROM pengguna WHERE kota = 'Makassar') — คำสั่งตอนนี้รองรับ JOIN, GROUP BY, ORDER BY และ LIKE และบนโทรศัพท์จะทำงานผ่านเครื่องยนต์ SQLite จริงของ Android หากต้องการเปลี่ยนค่า พิมพ์หมายเลขแถว (1 = แถวแรก) ชื่อคอลัมน์ และค่าใหม่ แล้วแตะ «เปลี่ยนค่าของเซลล์» — ค่านั้นจะถูกเขียนกลับลงในไฟล์ .db แตะ «บันทึกสำเนาสำรอง» เพื่อบันทึกสถานะปัจจุบันของตารางเป็นไฟล์ <ชื่อ-ฐานข้อมูล>.cadangan.txt ในโปรเจกต์ SharedPreferences และ DataStore ก็อ่านได้เช่นกัน สิ่งที่ยังอ่านไม่ได้: ฐานข้อมูลที่เข้ารหัส การเปลี่ยนแปลง WAL ที่ยังไม่คอมมิต และค่าที่มีชนิดใน DataStore Proto พิเศษ (แสดงเฉพาะเป็นมุมมองฟิลด์ทั่วไป)

โรงงานทดสอบยูนิตและฟัซซิง
หากต้องการค้นหาช่องว่างทางตรรกะก่อนแชร์แอป: เปิด «โรงงานทดสอบยูนิตและฟัซซิง» ในเมนูหลัก เลือกโปรเจกต์และไฟล์โค้ด แล้วแตะ «สร้างและรันการทดสอบ» IDE จะอ่านลายเซ็นฟังก์ชันในไฟล์ สร้างกรณีทดสอบปกติและกรณีขอบ (ข้อความว่าง null ตัวเลขสูงสุด อักขระแปลก) จากนั้นรันการทดสอบเหล่านั้นจริง: โค้ดโปรเจกต์ถูกคอมไพล์และแต่ละเมธอด @Test ถูกดำเนินการโดยมีขีดจำกัด 5 วินาที ดังนั้นผลลัพธ์คือการผ่านและการล้มเหลวจริงพร้อมค่าจริงของพวกมัน ฟัซซิงก็ทำงานจริงบนฟังก์ชันของโปรเจกต์ (ผ่านรีเฟลกชัน 2 วินาทีต่อการเรียก สูงสุด 20 เมธอด) และเปอร์เซ็นต์ความครอบคลุมของบรรทัดถูกคำนวณจริงผ่านเครื่องมือที่คงหมายเลขบรรทัดเดิมไว้ ผลลัพธ์รายงานว่ามีการทดสอบกี่รายการที่ผ่านและล้มเหลว พบโค้ดกี่บรรทัดและฟังก์ชันกี่รายการ และสร้างกรณีทดสอบใดบ้าง การทดสอบที่สร้างขึ้นใช้ API เดียวกันกับ JUnit ทุกประการ แต่คำนิยามแอนโนเทชันและการยืนยันถูกเขียนไว้ภายในไฟล์ทดสอบที่สร้างขึ้นเอง เพราะไลบรารี JUnit จริงไม่ได้รวมอยู่ในแอป

ตัวจำลองสภาวะอุปกรณ์สุดขั้วและผู้ตรวจสอบการรั่วไหลของหน่วยความจำ
หากต้องการทดสอบความทนทานของแอปเมื่อระบบฆ่ากระบวนการของมัน เครือข่ายขาด หน้าจอหมุน หรือโหมดประหยัดแบตเตอรี่เปิด: เปิด «ตัวจำลองสภาวะอุปกรณ์สุดขั้วและผู้ตรวจสอบการรั่วไหลของหน่วยความจำ» ในเมนูหลัก เลือกโปรเจกต์ แล้วแตะ «รันการจำลอง» IDE จะรันสถานการณ์ความกดดันสามแบบพร้อมการจำลองการหมุนหน้าจอและติดตามออบเจกต์ที่ยังคงถูกยึดไว้ในหน่วยความจำหลังจากหน้าจอของพวกมันปิด แล้วรายงานข้อมูลที่สูญหายและสายโซ่ออบเจกต์ที่รั่วไหล สถานะบันทึกและกู้คืนตอนนี้อ่านจากซอร์สของโปรเจกต์ของผู้ใช้เอง ไม่ใช่จากตัวอย่างคงที่; เซิร์ฟเวอร์ลูปแบ็กในเครื่องถูกหยุดจริงกลางการทดสอบเพื่อวัดการตัดเครือข่าย; ฮีปดัมป์จริงถูกนำมาและวิเคราะห์เพื่อเปรียบเทียบดัมป์สองชุดและติดตามสายโซ่การยึดจากรากของตัวเก็บขยะ; และกระบวนการของแอปเองถูกฆ่าจริงหลังจากบันทึกสถานะของมัน จากนั้นตรวจสอบว่าข้อมูลใดกลับมาเมื่อเปิดอีกครั้ง สิ่งที่ยังคงเป็นไปไม่ได้จากแอปธรรมดา: การปิดวิทยุหรือ Wi-Fi ของโทรศัพท์และการบังคับหยุดแอปอื่น — ทั้งสองอย่างต้องการสิทธิ์ของระบบ; แทนที่จะทำเช่นนั้น แอปพื้นหลังจะถูกฆ่าผ่าน killBackgroundProcesses ซึ่งสิทธิ์ของมันมีอยู่ในมานิเฟสต์อยู่แล้ว พร้อมป้ายกำกับที่ซื่อสัตย์บนหน้าจอ

สถาปนิกพิมพ์เขียวโปรเจกต์
หากต้องการเปลี่ยนไอเดียแอปขนาดใหญ่ให้เป็นแผนงานทีละขั้นตอน: เปิด «สถาปนิกพิมพ์เขียวโปรเจกต์» ในเมนูหลัก เลือกโปรเจกต์ เขียนไอเดียแอป (เช่น แอปแคชเชียร์ร้านขายของชำเล็กๆ ที่มีผ่อนชำระ) แล้วแตะ «สร้างพิมพ์เขียว» IDE จะสร้างโมดูล รายการไฟล์ และหลักชัยเล็กๆ จากนั้นบันทึกเป็น cetak-biru.txt ในโฟลเดอร์โปรเจกต์ ทุกครั้งที่หลักชัยเสร็จ แตะ «ทำเครื่องหมายหลักชัยถัดไปว่าเสร็จ» หรือแตะ «โหลดพิมพ์เขียวที่บันทึกไว้» เพื่อเปิดพิมพ์เขียวที่บันทึกไว้อีกครั้ง หากเลือกผู้ให้บริการ AI ที่ใช้งานอยู่ใน «การตั้งค่า AI» และมีคีย์ของมัน พิมพ์เขียวจะถูกสร้างโดยผู้ให้บริการนั้น; หากไม่มีคีย์หรือเข้าถึงผู้ให้บริการไม่ได้ IDE จะกลับไปใช้รูปแบบคำสำคัญแบบออฟไลน์และบอกขีดจำกัดนั้นอย่างซื่อสัตย์ คำตอบของผู้ให้บริการจะถูกตรวจสอบเฉพาะรูปแบบ (มีโมดูลและหลักชัย) ไม่ใช่ความถูกต้องของเนื้อหา — ตรวจสอบพิมพ์เขียวเสมอก่อนสร้าง

ผู้บรรยายกระแสตรรกะของโค้ด
หากต้องการเข้าใจโค้ดที่ยาวโดยไม่ต้องฟังไวยากรณ์ทีละบรรทัด: เปิด «ผู้บรรยายกระแสตรรกะของโค้ด» ในเมนูหลัก เลือกโปรเจกต์และไฟล์โค้ด แล้วแตะ «คำบรรยายโค้ด» IDE จะเปลี่ยนแต่ละบรรทัดเป็นประโยคภาษาอินโดนีเซีย (เช่น หากยอดรวมมากกว่า 100000 ให้รันบล็อกถัดไป) แสดงแผนที่การเรียกระหว่างเมธอดและการวิเคราะห์กระแสข้อมูลระหว่างเมธอด (ค่าที่ถูกส่งต่อ ถูกใช้ หรือถูกเพิกเฉย) และทำเครื่องหมายข้อบกพร่องละเอียดที่อาจเกิดขึ้นพร้อมหมายเลขบรรทัดของพวกมัน — String ที่เปรียบเทียบด้วย == สตรีมที่เปิดโดยไม่ปิด และตัวแปรที่ถูกเขียนในสองเมธอดที่ต่างกัน หากเลือกผู้ให้บริการ AI ที่ใช้งานอยู่ใน «การตั้งค่า AI» จะมีสรุปกระแสจากผู้ให้บริการนั้นด้วย; หากไม่มี หน้าจอจะใช้คำบรรยายแบบออฟไลน์และบอกขีดจำกัดนั้น คำบรรยาย แผนที่การเรียก และกระแสข้อมูลใช้การวิเคราะห์รูปแบบข้อความแบบออฟไลน์ ไม่ใช่ตัวแยกวิเคราะห์ AST แบบเต็ม — เมธอดที่มีวงเล็บเปิดอยู่บนบรรทัดของตัวเอง ฟิลด์คลาส และการเรียกผ่านรีเฟลกชันจะไม่ถูกติดตาม — และคำเตือนการแข่งขันของข้อมูลอาจปรากฏสำหรับตัวแปรที่ในความเป็นจริงถูกใช้สลับกันเท่านั้น

โรงงานบันเดิลแอปและความพร้อม Play Store
หากต้องการเตรียมแอปสำหรับ Google Play Store โดยตรงจากโทรศัพท์: เปิด «โรงงานบันเดิลแอปและความพร้อม Play Store» ในเมนูหลัก เลือกโปรเจกต์ แล้วแตะ «สร้างบันเดิล AAB» IDE จะสร้างไฟล์ .aab จากมานิเฟสต์ ทรัพยากร และแอสเซ็ตของโปรเจกต์พร้อม BundleConfig.pb จริง ตรวจสอบโครงสร้างบันเดิล จากนั้นแบ่งบันเดิลเป็น APK ตัวแปรจริง (พื้นฐาน ตามสถาปัตยกรรม ตามภาษา และสากล) โดยมีขนาดที่วัดได้จากการแบ่งนั้น ไม่ใช่การประมาณ บันเดิลถูกเซ็นด้วย JAR v1 โดยใช้คีย์โปรเจกต์เดียวกันกับที่ใช้เซ็น APK และห่วงโซ่ลายเซ็นของมันถูกตรวจสอบด้วยการเข้ารหัส หน้าจอนี้ยังตรวจสอบความพร้อมของ Play — SDK เป้าหมายต่ำกว่า 35 จะถูกทำเครื่องหมายว่า «สูง» เพราะ Play Store ต้องการ 35 ขึ้นไป และไลบรารี 64 บิตที่หายไปก็ถูกทำเครื่องหมายว่า «สูง» เช่นกัน bundletool จริงไม่สามารถทำงานบนอุปกรณ์ได้ เพราะ bundletool ต้องการ JVM ในขณะที่ Android ไม่มี JVM; เส้นทางข้างต้นเป็นเส้นทางจริงที่ใกล้เคียงที่สุดบนอุปกรณ์

กลไกอัปเดต OTA และการปล่อยแบบเป็นขั้น
หากต้องการส่งการแก้ไขเล็กๆ โดยไม่บังคับให้ผู้ใช้ดาวน์โหลด APK ทั้งหมดอีกครั้ง: เปิด «กลไกอัปเดต OTA และการปล่อยแบบเป็นขั้น» ในเมนูหลัก เลือกโปรเจกต์ เขียนเนื้อหาเวอร์ชันเก่าและใหม่ แล้วแตะ «สร้างแพ็กเกจแพตช์» IDE จะคำนวณความแตกต่างและสร้างแพ็กเกจแพตช์ (patch-ota.zip) พร้อมลายนิ้วมือ SHA-256 ของเนื้อหาใหม่ จากนั้นตรวจสอบว่าอุปกรณ์นี้อยู่ในขั้นแรกของการปล่อยร้อยละ 10 หรือไม่ แพตช์ตอนนี้รองรับเดลต้าไบนารีบนไฟล์ใดๆ (รวมถึง DEX และ APK) ถูกแพ็กด้วยลายเซ็น RSA-2048 และตรวจสอบด้วยคีย์สาธารณะที่เชื่อถือได้ก่อนนำไปใช้ และสามารถดาวน์โหลดได้จากเซิร์ฟเวอร์ของผู้พัฒนาพร้อมรายการการปล่อยของมัน; หากการนำไปใช้ล้มเหลว ไฟล์เก่าจะยังคงอยู่ครบถ้วน การนำแพตช์ไปใช้กับแอปที่กำลังทำงานจะทำผ่านการเซ็นใหม่ด้วยคีย์โปรเจกต์และ PackageInstaller เพราะการแทนที่โค้ดของกระบวนการที่กำลังทำงานจากภายในตัวมันเองเป็นไปไม่ได้ — APK ถูกล็อกและ DEX ถูกโหลดแล้ว

สตูดิโอทบทวนโค้ดทีม
หากต้องการทบทวนการเปลี่ยนแปลงของเพื่อนร่วมงานและแก้ไขความขัดแย้งในการรวมโดยไม่ต้องอ่านเครื่องหมายลูกศรของ Git: เปิด «สตูดิโอทบทวนโค้ดทีม» ในเมนูหลัก เลือกโปรเจกต์ พิมพ์ข้อความสามเวอร์ชัน (พื้นฐาน ท้องถิ่น เพื่อนร่วมงาน) แล้วแตะ «เปิดการทบทวนของทีม» IDE จะรวมทั้งสามตามหน่วยไวยากรณ์ของ Java — การเปลี่ยนแปลงสองรายการในบรรทัดเดียวกันแต่อยู่ในคำสั่งที่ต่างกันจะไม่ถูกนับว่าเป็นความขัดแย้งอีกต่อไป — และแสดงแต่ละความขัดแย้งเป็นตัวเลือกโหวต: ใช้เวอร์ชันท้องถิ่น ใช้เวอร์ชันเพื่อนร่วมงาน หรือรวมทั้งสอง — บรรทัดผลลัพธ์จะถูกแทรกที่ตำแหน่งความขัดแย้งเดิมเพื่อให้ลำดับยังคงถูกต้อง — จากนั้นเขียนผลลัพธ์ลงใน gabung-hasil.txt ในโปรเจกต์ ด้านล่างเป็นกระดานงานของโปรเจกต์: พิมพ์หัวข้องานแล้วแตะ «เพิ่มงาน»; งานจะถูกบันทึกเป็นข้อความในโฟลเดอร์ .tugas ภายในโปรเจกต์และซิงค์ผ่านคอมมิตใน Git ภายในแอป ดังนั้นกระดานจึงสามารถอ่านได้อีกครั้งจากประวัติคอมมิตใดๆ ตัวแบ่งไวยากรณ์นี้ไม่ใช่ตัวแยกวิเคราะห์ AST แบบเต็มและ Git ภายในแอปบันทึกสแนปช็อตเต็มสำหรับแต่ละคอมมิต; ไม่มีเซิร์ฟเวอร์ซิงค์พิเศษ

การเขียนตามคำบอกโครงสร้างโค้ด
เพื่อเขียนโค้ดด้วยเสียงในตัวแก้ไข: เปิดโปรเจกต์ในตัวแก้ไข แล้วแตะปุ่มการเขียนตามคำบอกโครงสร้างโค้ด พูดคำสั่งเป็นภาษาอินโดนีเซีย เช่น buat fungsi tambah dengan parameter a angka dan b angka, buat kelas Mobil หรือ buat variabel teks nama sama dengan Budi — IDE จะแปลงเสียงเป็นบล็อกโค้ด Java, Kotlin, Python หรือ Compose ที่ถูกต้องตามไวยากรณ์ แล้วแทรกลงที่ตำแหน่งเคอร์เซอร์ จากนั้นอ่านสรุปสั้นๆ ผ่าน Jieshuo การเขียนตามคำบอกใช้บริการป้อนเสียงในตัวของระบบ ไม่ต้องขอสิทธิ์ไมโครโฟนเพิ่ม และรู้จักเฉพาะรูปแบบคำสั่งที่ลงทะเบียนไว้แล้วเท่านั้น เสียงนอกรูปแบบจะไม่ถูกแปลงเป็นโค้ด ตัวเลขที่พูดเป็นคำ (เช่น 'lima') ยังไม่ถูกแปลงเป็นตัวเลข

พื้นที่ทำงานร่วมกันในเครื่อง (ไม่ใช้อินเทอร์เน็ต)
เพื่อทำงานร่วมกันในห้องเดียวกันโดยไม่ใช้อินเทอร์เน็ต: เปิดการทำงานร่วมกันในเมนูหลัก แล้วเปิดส่วนพื้นที่ทำงานร่วมกันในเครื่อง โทรศัพท์เครื่องหนึ่งเปิดเซสชัน (IDE จะแสดงที่อยู่ IP ในเครื่องและ PIN 6 หลัก) โทรศัพท์อีกเครื่องเข้าร่วมด้วยที่อยู่นั้นและ PIN นั้น การเปลี่ยนแปลงข้อความจะถูกส่งเป็นความต่างของบรรทัด APK ที่สร้างแล้วสามารถส่งไปยังโทรศัพท์ของผู้ทดสอบได้ และรายงานข้อขัดข้องจากโทรศัพท์ของผู้ทดสอบจะถูกส่งกลับมา หนึ่งเซสชันใช้สำหรับเพื่อนคนเดียวเท่านั้น หากสองคนเปลี่ยนบรรทัดเดียวกันเป๊ะๆ ในเวลาเดียวกัน จะใช้การเปลี่ยนแปลงล่าสุด PIN จะถูกส่งเป็นข้อความธรรมดาบนเครือข่ายในเครื่อง ห้องนี้ยังไม่เคยทดสอบบนโทรศัพท์จริง

การตั้งค่า AI
หากต้องการตั้งค่าผู้ให้บริการ AI และคีย์ API สำหรับการสร้างแอป: ในเมนูหลัก ในกลุ่มการตั้งค่า แตะ «การตั้งค่า AI» (ข้างปุ่ม «ตัวเชื่อมต่อ») เลือกผู้ให้บริการที่จะใช้จากรายการที่มีอยู่ และทำเครื่องหมาย «สลับโมเดลเมื่อผู้ให้บริการเกิดข้อผิดพลาด» เพื่อที่ว่าหากโมเดลหนึ่งล้มเหลว IDE จะลองโมเดลถัดไปของผู้ให้บริการเดียวกันโดยอัตโนมัติ แตะ «จัดการคีย์ API» เพื่อเพิ่มคีย์สำรอง (พิมพ์ชื่อและคีย์ แล้วแตะ «บันทึก»; คีย์จะแสดงแบบถูกปิดบัง เห็นเพียง 4 ตัวอักษรสุดท้าย) คีย์จะถูกบันทึกบนโทรศัพท์และไม่เคยถูกส่งไปที่ใดนอกจากผู้ให้บริการที่เลือกเมื่อสร้างแอป ผู้ให้บริการที่เลือกตอนนี้ถูกใช้จริงโดย «สถาปนิกพิมพ์เขียวโปรเจกต์» และ «ผู้บรรยายกระแสตรรกะของโค้ด»; การสร้างแอปบนหน้าจอ «ผู้สร้างแอปด้วย AI» ยังคงใช้ AI ในเครื่องบนโทรศัพท์ (โดยไม่มีอินเทอร์เน็ต)

ตัวเชื่อมต่อ
เพื่อวิเคราะห์ APK แล้วส่ง: ในเมนูหลัก ในกลุ่มการตั้งค่า แตะตัวเชื่อมต่อ (ข้างปุ่มการตั้งค่า AI) เลือกไฟล์ APK จากโทรศัพท์ IDE จะอ่านเนื้อหา (ชื่อแพ็กเกจ เวอร์ชัน รายการกิจกรรม) แล้วแตะส่ง APK เพื่อส่งผ่านเมนูแชร์ของระบบ (เช่น WhatsApp หรือ Drive)

ภาษาและเสียง
เพื่อเปลี่ยนภาษาของแอป: เปิดการตั้งค่า แล้วเปิดภาษาของแอป แล้วเลือกภาษาหรือตามระบบ หน้าจอหลักและหน้าจอส่วนใหญ่จะเปลี่ยนเป็นภาษาที่เลือกทันทีโดยไม่ต้องปิดหรือเริ่มแอปใหม่ หน้าจอบางส่วน (เช่น Terminal การทำงานร่วมกัน การตั้งค่า AI และการจัดการคีย์) ยังใช้ภาษาเดิมจนกว่าจะเปิดใหม่ หากเลือกตามระบบ ภาษาจะตามภาษาระบบของโทรศัพท์

ลายเซ็นเริ่มต้นต่อโปรเจกต์และ Anti Tamper
ตั้งแต่เวอร์ชัน 5.7 โปรเจกต์ที่ไม่ได้ใช้ลายเซ็นส่วนตัวจะถูกเซ็นด้วยคีย์ในตัวเฉพาะของโปรเจกต์นั้นเอง (สร้างครั้งเดียวในโฟลเดอร์ tanda-tangan-bawaan ภายในโปรเจกต์ แล้วใช้ต่อไป) ดังนั้นลายเซ็นในตัวจึงต่างกันไปในแต่ละโปรเจกต์ — ไม่ใช้คีย์ร่วมกันสำหรับทุกแอปอีกต่อไป อย่าลบโฟลเดอร์ tanda-tangan-bawaan หากไม่มีคีย์นั้น APK ใหม่จะไม่สามารถเขียนทับ APK เก่าของโปรเจกต์เดียวกันได้ การตั้งค่าของแต่ละโปรเจกต์ (สถาปัตยกรรมแยก ลายเซ็นส่วนตัว ป้องกันการแก้ไข keystore ที่เลือก SDK) ตอนนี้บันทึกในไฟล์ settings.gradle ภายในโปรเจกต์และอ่านอีกครั้งทุกครั้งที่สร้างโปรเจกต์ ในการตั้งค่า หมวดลายเซ็น มีช่องทำเครื่องหมายป้องกันการแก้ไขแอปที่บิลด์แล้ว หากเปิดใช้งาน แอปที่สร้างบนอุปกรณ์จะตรวจสอบลายเซ็นและเนื้อหา dex ของตัวเองทุกครั้งที่เปิด หากถูกเซ็นใหม่หรือถูกคนอื่นแก้ไข แอปจะปฏิเสธที่จะทำงาน ดีบักเกอร์และเครื่องมือฉีดเช่น Frida/Xposed ก็ถูกตรวจจับเช่นกัน และหน้าต่างแอปถูกล็อกจากการบันทึกหน้าจอ

เครื่องมือสร้างวิดีโอสาธิต
หากต้องการสร้างวิดีโอสาธิตของแอปที่สร้างแล้ว ให้เปิดเครื่องมือสร้างวิดีโอสาธิตในเมนูหลัก เลือกโปรเจกต์ กรอกชื่อวิดีโอ แล้วกดสร้างสคริปต์วิดีโอสาธิต — IDE จะเขียน video-demo.txt ที่มี 5 ฉากมาตรฐาน (เปิดเรื่อง มุมมองหลัก คุณสมบัติ 1 คุณสมบัติ 2 ปิดเรื่อง) พร้อมข้อความบรรยายและระยะเวลาของแต่ละฉาก กดสร้าง Slideshow HTML เพื่อสร้าง video-demo.html จากรูปภาพของโปรเจกต์ (ไอคอน + ภาพหน้าจอหากมี) ที่เปลี่ยนอัตโนมัติทุก 5 วินาที นี่ไม่ใช่ วิดีโอ .mp4 — สำหรับวิดีโอจริง ให้เปิด video-demo.html ในเบราว์เซอร์โทรศัพท์แล้วบันทึกหน้าจอ หรืออ่านคำบรรยายใน video-demo.txt ขณะบันทึกแอปที่กำลังทำงาน

หน้าตาใหม่สไตล์ Android Studio
รูปลักษณ์ของ IDE ตอนนี้ถูกจัดระเบียบให้คล้าย Android Studio (เฉพาะรูปลักษณ์ — ปุ่ม เมนู และขั้นตอนทั้งหมดยังคงเหมือนเดิมทุกประการ) พื้นหลังสีเทาอ่อน ชื่อหน้าจอหนาสีดำ ปุ่มสีน้ำเงินพร้อมข้อความสีขาว และกล่องกรอกสีขาวขอบบาง เมนูหลักถูกจัดกลุ่มตามภาพ (ฟีเจอร์ผู้สร้าง คลาวด์ ธีมและอื่น ๆ เสียง โค้ดและฟีเจอร์ใหม่ เครื่องมือ) โดยไม่เปลี่ยนลำดับปุ่ม Terminal ยังคงใช้แผงสีเข้มเหมือนหน้าต่าง Terminal ใน Android Studio และตัวแก้ไขโค้ดยังคงพื้นหลังสีขาวกับข้อความสีดำ ข้อความทั้งหมดยังคงอ่านได้ชัดเจนโดย Jieshuo

การตั้งค่า
หากต้องการตั้งค่าแอป ให้เปิดเมนูตัวเลือกบนหน้าจอหลักแล้วกดการตั้งค่า ข้างในมี 12 หมวด ได้แก่ การตั้งค่า GitHub (ความปลอดภัย ลายเซ็นส่วนตัว ประวัติการสร้าง และโทเค็น GitHub) การตั้งค่าบิลด์ APK บนอุปกรณ์ (บันทึกคำผ่าน keystore และประวัติการสร้างบนอุปกรณ์) ธีม (สีแอป) ลายเซ็น (สร้าง keystore สำหรับลายเซ็นส่วนตัวและช่องทำเครื่องหมายป้องกันการแก้ไขแอปที่บิลด์แล้ว) โฟลเดอร์โปรเจกต์ (ตำแหน่งโฟลเดอร์โปรเจกต์) ภาษาและเสียง (ภาษาอินเทอร์เฟซและความเร็วเสียงของโหมดเสียง) ขนาดข้อความและการแสดงผล (ขนาดฟอนต์ตัวแก้ไข) บิลด์ (SDK เป้าหมายเริ่มต้นและการแยกสถาปัตยกรรมเริ่มต้นสำหรับหน้าจอสร้างโปรเจกต์) การแจ้งเตือน (เสียงเมื่อสร้างเสร็จ) สำรองข้อมูลอัตโนมัติ (ตารางสำรองโปรเจกต์) โปรไฟล์นักพัฒนา (ชื่อ หมายเลข WhatsApp และบัญชีที่แสดงบนหน้าจอบริจาค) และความเป็นส่วนตัวและข้อมูล (รีเซ็ตการตั้งค่าและลบข้อมูลแอป) แต่ละหมวดมีปุ่มกลับไปก่อนหน้าเพื่อกลับไปยังเมนูหมวด การตั้งค่าที่เพิ่งบันทึก (ยังไม่ได้นำไปใช้) จะมีคำอธิบายเขียนไว้บนหน้าจออย่างตรงไปตรงมา

บริจาคให้นักพัฒนา
หากต้องการบริจาคหรือทักทายนักพัฒนา ให้กดปุ่มบริจาคให้นักพัฒนาบนหน้าจอหลัก ข้างปุ่มเกี่ยวกับเครื่องมือ บนหน้าจอบริจาคมีปุ่มคัดลอกบัญชี BRI — กดเพื่อคัดลอกหมายเลขบัญชีของนักพัฒนา แล้ววางในแอปธนาคารของคุณ นอกจากนี้ยังมีส่วนทักทายนักพัฒนาทาง WhatsApp กรอกชื่อและเมืองบ้านเกิด แล้วกดส่งทาง WhatsApp — WhatsApp จะเปิดพร้อมข้อความทักทายที่กรอกไว้ล่วงหน้า เพียงกดส่งใน WhatsApp แล้วกลับมาที่แอป WhatsApp ไม่อนุญาตให้แอปอื่นส่งข้อความโดยอัตโนมัติ ดังนั้นการส่งยังคงทำด้วยตัวเองใน WhatsApp

คำสั่งโปรดของ Terminal
หากต้องการบันทึกคำสั่งที่ใช้บ่อยใน Terminal ให้เปิด Terminal แล้วกดรายการโปรด แตะเพิ่มรายการโปรดใหม่ กรอกชื่อ (เช่น ดูไฟล์) และคำสั่งของมัน (เช่น ls -la) แล้วกดบันทึก — รายการโปรดจะถูกบันทึกอย่างถาวรบนโทรศัพท์ แตะชื่อรายการโปรดเพื่อรันโดยตรงในเทอร์มินัล แตะลบรายการโปรดแล้วเลือกหนึ่งรายการเพื่อลบ (พร้อมการยืนยัน) มีรายการโปรดในตัวอยู่แล้ว 3 รายการ ได้แก่ ดูไฟล์ (ls -la) ตรวจสอบพื้นที่ (df -h) และล้างหน้าจอ (clear) — ทั้งหมดลบได้ คำสั่งว่างไม่สามารถบันทึกหรือรันได้ Terminal จะแจ้งให้คุณทราบผ่านข้อความและเสียงหากเกิดเหตุการณ์เช่นนั้น

การวิเคราะห์และคุณภาพ
หากต้องการดูสรุปการใช้งานแอปและรายงานการขัดข้อง ให้กดปุ่มการวิเคราะห์และคุณภาพบนหน้าจอหลัก ข้างปุ่มบริจาคให้นักพัฒนา หน้าจอนี้แสดงว่าแอปถูกเปิดกี่ครั้ง หน้าจอใดเปิดบ่อยที่สุด จำนวนครั้งที่ขัดข้อง และรายการการขัดข้องล่าสุดพร้อมคำแนะนำในการแก้ไขสั้น ๆ ข้อมูลนี้เก็บไว้ในโทรศัพท์ของคุณเท่านั้นและไม่ถูกส่งไปที่ใด มีปุ่มลบข้อมูลการวิเคราะห์พร้อมกล่องโต้ตอบยืนยันเพื่อลบข้อมูลทั้งหมดนั้น หน้าจอล่าสุดจะถูกบันทึกเฉพาะสำหรับหน้าจอหลักและหน้าจอนี้
