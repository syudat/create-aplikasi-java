Ласкаво просимо до Create Aplikasi by Al Kautsar
Create Aplikasi — це застосунок для створення застосунків Android, який працює безпосередньо на телефоні, без потреби в ноутбуці. Цей застосунок дозволяє будь-кому створювати власні застосунки Android, зокрема користувачам, які тільки вчаться створювати застосунки, та користувачам програм читання з екрана. Повний посібник із користування цим застосунком доступний на цьому екрані Tentang Alat (Про інструмент).

Що це за застосунок і для кого він
Create Aplikasi — це інструмент для створення застосунків Android, який працює на телефоні. Цей застосунок призначений для всіх, хто хоче створювати власні застосунки Android, зокрема для початківців і користувачів програм читання з екрана. Цей застосунок надає редактор коду, кнопку Jalankan (Запустити) для тестування проєкту, кнопку Bangun (Зібрати) для створення APK, а також меню для підписування та встановлення APK.

Мета цього застосунку
Цей застосунок створено для того, щоб будь-хто міг легко створювати власні застосунки Android безпосередньо з телефона. Його вигляд зроблено якомога простішим, щоб навіть нові користувачі могли одразу спробувати.

Як створити новий проєкт, крок за кроком
1. Натисніть Buat Project (Створити проєкт) у головному меню.
2. Виберіть тип проєкту: HTML, Situs Web (Вебсайт), Java, Kotlin, Compose або Python.
3. Заповніть назву застосунку, наприклад: Garuda Decode.
4. Заповніть назву пакета (package name), наприклад: com.android.garudadecode. Назва пакета має використовувати малі літери та складатися щонайменше з двох частин, розділених крапкою.
5. Заповніть версію застосунку, наприклад: 1.0, і код версії у вигляді числа, наприклад: 1. Якщо залишити порожнім, версію буде автоматично заповнено як 1.0, а код версії — як 1.
6. За потреби заповніть мінімальний SDK і цільовий SDK. Якщо залишити порожнім, буде використано значення за замовчуванням. Мінімальний SDK — це найнижча підтримувана версія Android, наприклад: 21 означає Android 5.0. Максимальний цільовий SDK — 36 (Android 16).
7. Натисніть кнопку Pilih Izin (Вибрати дозволи), щоб вибрати дозволи застосунку, наприклад: INTERNET. Дозвіл INTERNET уже позначено за замовчуванням. Позначайте лише ті дозволи, які справді потрібні застосунку.
8. За бажання позначте "Gunakan arsitektur terpisah 64 bit dan 32 bit" (Використовувати окремі архітектури 64 біт і 32 біт), щоб розмір APK був меншим, і позначте "Gunakan tanda tangan pribadi" (Використовувати особистий підпис), якщо хочете використовувати власноруч створене keystore.
9. Натисніть Buat Proyek (Створити проєкт). Новий проєкт зберігається в папці Download/project і одразу з'являється в Kelola Project (Керування проєктами).

Доступні типи проєктів
• HTML: вигляд із index.html, style.css і script.js, працює через WebView. Збирається безпосередньо на телефоні.
• Situs Web: вебсайт із меню (Beranda (Головна), Tentang (Про нас), Kontak (Контакти)) з index.html, tentang.html, kontak.html, style.css і script.js, працює через WebView. Збирається безпосередньо на телефоні.
• Java: збирається на телефоні. MainActivity знаходиться в app/src/main/java/<nama-paket>/MainActivity.java. Вигляд походить із app/src/main/res/layout/activity_main.xml, текст — із app/src/main/res/values/strings.xml, а тема — із app/src/main/res/values/styles.xml.
• Kotlin: може збиратися на пристрої (офлайн) за допомогою компілятора Kotlin, що входить до застосунку, або через GitHub Actions. MainActivity знаходиться в app/src/main/java/<nama-paket>/MainActivity.kt, а файли res такі самі, як у проєкті Java. Перше збирання Kotlin повільніше через великий розмір компілятора, а файли .java, які посилаються на класи Kotlin, ще не можуть бути зібрані (файли .java компілюються перед файлами .kt).
• Compose: сучасний застосунок Android, інтерфейс якого створено за допомогою Jetpack Compose (а не макетів XML). MainActivity знаходиться в app/src/main/java/<nama-paket>/MainActivity.kt. Проєкти Compose збираються через GitHub Actions (меню Bangun проєкту, потім Bangun online (Зібрати онлайн)) або в Termux із Gradle, оскільки Compose потребує бібліотек Jetpack Compose, яких немає на пристрої.
• Python: логіка застосунку написана мовою Python (Chaquopy) в app/src/main/python/main.py і запускається хостом MainActivity.java в app/src/main/java/<nama-paket>/MainActivity.java. Проєкти Python можуть збиратися безпосередньо на телефоні (середовище виконання Chaquopy входить до застосунку), а також через GitHub Actions. Мінімальний SDK проєктів Python — 24 (Android 7.0).

Змінити архітектуру проєкту
Щоб змінити налаштування архітектури наявного проєкту, не створюючи новий: у головному меню натисніть «Змінити архітектуру проєкту», потім виберіть проєкт і змініть прапорець «Зібрати 64-бітний APK (arm64-v8a)» або «Зібрати 32-бітний APK (armeabi-v7a)»; або в «Керуванні проєктами» довго натисніть ім'я проєкту та виберіть «Змінити архітектуру», щоб відкрити той самий екран одразу для цього проєкту. Правило таке: якщо обидва прапорці ввімкнено, збірка дає два окремі APK — 64-бітний і 32-бітний; якщо ввімкнено лише один прапорець, збірка дає один універсальний APK, який однаково працює і на 64-бітних, і на 32-бітних пристроях. Окремий APK лише для одного варіанта поки не підтримується, бо шлях збірки знає лише вибір «окремо» або «універсально», але вибір кожного варіанта зберігається всередині проєкту, щоб не загубитися при повторному відкритті екрана.

Структура файлів проєктів Java, HTML, Situs Web, Kotlin, Compose і Python
Проєкти Java, HTML, Situs Web, Kotlin, Compose і Python влаштовані так, як загалом проєкти Android. Усередині папки app є папка src, а в ній папка main. Усередині папки main знаходиться AndroidManifest.xml поруч із папкою java, папка res, що містить layout/activity_main.xml і values/strings.xml, а також values/styles.xml, а для HTML і Situs Web — папка assets, що містить index.html (Situs Web також має tentang.html і kontak.html). Проєкти HTML і Situs Web також мають власний MainActivity у app/src/main/java/<nama-paket>/MainActivity.java, який завантажує index.html у WebView і стає лаунчером у AndroidManifest. Проєкти Python мають код Python у app/src/main/python/main.py і хост MainActivity.java у app/src/main/java/<nama-paket>/MainActivity.java. AndroidManifest.xml, layout, strings і styles можна відкривати й змінювати в редакторі, так само як MainActivity. Старі проєкти, чий маніфест досі знаходиться поруч із папкою app, також можна зібрати, оскільки під час збирання застосунок спочатку перевіряє AndroidManifest.xml у app/src/main/, потім той, що поруч із папкою app, і нарешті файл даних проєкту.

Правила дозволів (важливо)
Дозволи, позначені під час створення проєкту, записуються лише в одному місці, залежно від типу проєкту. Для проєктів Java, HTML, Situs Web, Kotlin, Compose і Python позначені дозволи записуються ТІЛЬКИ в AndroidManifest.xml, що знаходиться в app/src/main/, поруч із папкою java, усередині папки проєкту. Файл даних проєкту для проєктів Java, HTML, Situs Web, Kotlin, Compose і Python не містить списку дозволів. Якщо ви виберете Java й позначите INTERNET та CAMERA, то в AndroidManifest.xml буде записано лише INTERNET і CAMERA, без жодних інших дозволів. Під час збирання застосунок читає дозволи з того самого місця: з AndroidManifest.xml у app/src/main/ для проєктів Java, HTML, Situs Web, Kotlin, Compose і Python (якщо його немає — з AndroidManifest.xml поруч із папкою app для старих проєктів) і з файлу даних проєкту для старих проєктів.

Як користуватися редактором
Відкрийте Kelola Project, торкніться назви проєкту, щоб відкрити редактор. У редакторі можна відкривати файли, писати код і зберігати зміни. Для проєктів Java, HTML, Situs Web, Kotlin, Compose і Python файли влаштовані всередині папки app/src/main. Щоб поділитися проєктом, скористайтеся Ekspor ZIP (Експорт ZIP) (див. розділ нижче).

Як запустити проєкт
У редакторі натисніть Jalankan, щоб протестувати проєкт. Для проєктів HTML і Situs Web запускається index.html через WebView. Якщо станеться помилка, прочитайте повідомлення про помилку, виправте код, а потім запустіть знову.

Як зібрати APK
У редакторі натисніть Bangun. Є два способи збирання. Перший, Bangun di perangkat (Зібрати на пристрої): збирає безпосередньо на телефоні без інтернету, для проєктів HTML, Situs Web, Java, Kotlin і Python. Другий, Bangun online через GitHub Actions: збирає через інтернет на GitHub і може використовуватися для всіх типів проєктів. Проєкти Compose можна зібрати лише другим способом (Bangun online) або в Termux із Gradle, оскільки Compose потребує бібліотек Jetpack Compose, яких немає на пристрої. Результат першого збирання ще не підписано. Після цього застосунок його підписує: автоматично ключем за замовчуванням або особистим підписом, якщо поле "Gunakan tanda tangan pribadi" було позначено під час створення проєкту.

Як встановити APK
Коли APK готовий, натисніть Pasang (Встановити), щоб його встановити. В Android 8 і новіших версіях телефон спочатку запитає "Izinkan dari sumber ini" (Дозволити з цього джерела), оскільки цей застосунок встановлює APK ззовні Play Store. Увімкніть цей дозвіл один раз у Pengaturan (Налаштування), а потім поверніться до застосунку: встановлення продовжиться автоматично, без потреби знову натискати Pasang. Якщо кнопка Pasang не з'являється, переконайтеся, що збирання завершено й APK створено.

Як підписати застосунок
Кожен APK має бути підписаний, щоб його можна було встановити. Доступні два варіанти. Перший, ключ за замовчуванням: застосунок підписує сам автоматично, вам нічого не потрібно робити. Другий, особистий підпис: спочатку створіть keystore через меню Buat Keystore (Створити keystore) у головному меню, добре збережіть його пароль, а потім позначте "Gunakan tanda tangan pribadi" під час створення проєкту. Keystore зберігається в Download/project/signing.

Експорт проєкту в ZIP
Ekspor ZIP надається для того, щоб проєктом можна було поділитися з друзями. Ось як: у Kelola Project довго натисніть назву проєкту, а потім виберіть Ekspor ZIP. Результат зберігається в Download/project/<NamaProyek>.zip. Папка bin не входить, тому розмір невеликий, лише кілька десятків КБ. Цей файл ZIP можна надіслати другові або завантажити на GitHub.

Ekstensi JAWS
Ekstensi JAWS використовує механізм розширень Jieshuo (CSR), а не його програму читання з екрана. Завдяки цьому конструкція може продовжувати працювати, навіть якщо користувач використовує TalkBack. Ось як: відкрийте Ekstensi JAWS у головному меню. Оскільки автоматичне клацання працює саме по собі, службу потрібно спочатку ввімкнути в Pengaturan Aksesibilitas (Налаштування доступності). Після цього можна створити нову конструкцію: введіть назву конструкції, натисніть OK, а потім заповніть її поля.

Daftar Klik відокремлено для порядку
Усередині конструкції є два поля: поле скрипту і поле Daftar Klik (Список клацань). Список кнопок зберігається окремо у файлі daftar_klik.txt, по одній назві на рядок. Приклад вмісту: tombolSimpan, tombolHapus, tombolBuka. Щоб відкрити застосунок, просто напишіть >WhatsApp у цьому списку. Старі конструкції, які ще не мають файлу daftar_klik.txt, показуватимуть цей приклад за замовчуванням.

Прості функції, що надаються
• klikTombol("tombolSimpan") — клацає одну кнопку за її текстом.
• klikDaftarTombol(daftar) — клацає список у daftar_klik.txt, по одній кнопці на рядок, по порядку, а потім повідомляє, скільки вдалих і скільки не знайдених.
• bukaAplikasi("WhatsApp") — відкриває застосунок за його назвою, або напишіть ">WhatsApp" у списку.
• klik(540, 1200) — клацає за координатами екрана.
Усі функції спочатку зроблено простими. Коли звикнете, згодом можна додати додаткові функції.

Про програму читання з екрана
Цей застосунок розроблено дружнім до програм читання з екрана. Кожне поле для заповнення має підпис і приклад заповнення, а всі кнопки можна досягти без складних жестів. Ekstensi JAWS зроблено так, щоб воно продовжувало працювати, навіть якщо користувач використовує TalkBack, оскільки використовується його механізм розширень, а не його програма читання з екрана.

Конфіденційність і безпека
Проєкти та keystore зберігаються на вашому телефоні. Токен GitHub використовується лише для онлайн-збирання й зберігається всередині цього застосунку. Нікому не повідомляйте свій токен або пароль keystore. Якщо ви використовуєте особистий підпис, зберігайте keystore та його пароль у безпечному місці, оскільки в разі їх втрати старий APK не можна буде оновити тим самим підписом.

Вимоги
Android 5.0 або новіший. Дозвіл на сховище: в Android 11 і новіших використовується дозвіл доступу до всіх файлів, в Android 10 і старіших — звичайний дозвіл на сховище (читання/запис сховища), оскільки Android 10 не має дозволу доступу до всіх файлів. Для збирання на пристрої потрібен телефон із процесором ARM (32 або 64 біт). Для онлайн-збирання через GitHub Actions потрібні інтернет і токен GitHub. Проєкти Kotlin можна збирати на пристрої, але їхнє перше збирання повільніше й використовує більше пам'яті через великий розмір компілятора Kotlin. Проєкти Compose збираються через GitHub Actions або в Termux із Gradle. Проєкти Python потребують Android 7.0 або новіший (мінімальний SDK 24), а підсумковий APK більший, оскільки містить середовище виконання Python (Chaquopy) разом із його стандартною бібліотекою.

Terminal
Меню Terminal на головному екрані відкриває термінал усередині цього застосунку. Команди на кшталт ls можна використовувати для перегляду вмісту папки проєкту, cd — для переходу між папками, а git — для керування кодом. Вивід команд відображається як текст, який програма читання з екрана може прочитати, і є кнопка Bacakan hasil (Прочитати результат), щоб прослухати останній результат. Цей термінал використовує системну оболонку телефона, тому інтерактивні програми, такі як nano та vim, тут ще не можна використовувати.

Lisensi (платна версія)
Щоб продавати застосунок, позначте "Aktifkan Lisensi" (Увімкнути ліцензію) під час створення проєкту, а потім заповніть свій номер WhatsApp. Зібраний застосунок попросить код ліцензії під час першого відкриття: користувач бачить ідентифікатор свого пристрою, натискає кнопку Kirim ID Perangkat (Надіслати ідентифікатор пристрою), щоб надіслати цей ідентифікатор на ваш WhatsApp, а потім ви відповідаєте кодом ліцензії. Код ліцензії обчислюється з ідентифікатора пристрою та пароля проєкту (lisensi_seed у файлі даних проєкту) — добре зберігайте цей пароль і не повідомляйте його. Після введення правильного коду застосунок відкривається й більше не просить код.

Pembuat Ikon Otomatis
Значок нових проєктів досі прозорий, тому в головному меню доступний Pembuat Ikon (Створювач значків). Ось як: натисніть Pembuat Ikon, напишіть одну або дві літери (наприклад, ініціали назви застосунку), виберіть колір фону та колір тексту, перегляньте його попередній вигляд, а потім натисніть Simpan ke Proyek (Зберегти до проєкту), щоб використати цей значок у вибраному проєкті, або Simpan ke Download (Зберегти до Download), щоб використати його файл PNG деінде. Після створення проєкту застосунок також пропонує створити значок. Старий значок проєкту можна змінити будь-коли з меню проєкту в Kelola Project (довго натисніть назву проєкту, а потім виберіть Ganti Ikon (Змінити значок)).

Template Proyek Siap Pakai
Якщо ви не хочете починати з порожнього проєкту, виберіть шаблон під час створення проєкту: Kalkulator (Java), Catatan (Java), Daftar Tugas (Kotlin), Kalkulator Web (HTML), Situs Profil (Situs Web) або Penghitung (Compose). Вибір шаблону автоматично змінює тип проєкту відповідно до цього шаблону, і проєкт створюється з уже готовим початковим кодом — просто запустіть або змініть його. Якщо тип проєкту знову змінити вручну після вибору шаблону, шаблон скасовується, і проєкт знову стає порожнім. Для шаблонів HTML і Situs Web шаблон замінює вміст index.html, зокрема скрипт HTML, введений у формі.

Cadangan dan Pulihkan Proyek
Щоб проєкти не губилися, доступна функція резервного копіювання. Ось як: у Kelola Project довго натисніть назву проєкту, а потім виберіть Cadangkan (Створити резервну копію). Резервна копія зберігається як ZIP у папці Download/backup із назвою проєкту й датою, наприклад: GarudaDecode-2026-11-14-123045.zip. Її вміст такий самий, як у Ekspor ZIP (увесь вміст проєкту, без папки bin). Щоб відновити: відкрийте меню в Kelola Project, виберіть Pulihkan cadangan (Відновити резервну копію), а потім виберіть її файл резервної копії. Якщо назва проєкту вже існує, застосунок запитає: Timpa proyek lama (Перезаписати старий проєкт) або зберегти з Nama baru (Нова назва).

Bagikan dan Impor Proyek
Щоб поділитися проєктом із другом: у Kelola Project довго натисніть назву проєкту, а потім виберіть Bagikan (Поділитися). Проєкт надсилається як ZIP через застосунки для обміну (WhatsApp, Telegram та інші). Щоб отримати проєкт від друга: відкрийте меню в Kelola Project, виберіть Impor proyek (Імпортувати проєкт), а потім виберіть його файл ZIP. Цей файл ZIP має містити файл даних проєкту — якщо його немає, файл відхиляється з чітким повідомленням, оскільки цей файл не є проєктом Create Aplikasi. Якщо назва проєкту вже існує, застосунок запитає: Timpa proyek lama або зберегти з Nama baru.

Pencarian dan Filter Proyek
Якщо проєктів уже багато, у Kelola Project є поле пошуку та фільтр типів. Введіть назву проєкту в поле пошуку, і список одразу відфільтрується (великі та малі літери не розрізняються). Фільтр типів обмежує список лише одним типом: Semua (Усі), HTML, Situs Web, Java, Kotlin, Compose або Python. Меню кожного проєкту й надалі можна відкрити як зазвичай із відфільтрованого списку.

Створення застосунку голосом
Якщо ви не хочете друкувати, скористайтеся голосом: натисніть «Збірка голосом» у головному меню, а потім промовте команду. Команди, які можна промовити: "Buat proyek kalkulator", "Bangun proyek Kalkulator", "Buka proyek Kalkulator", "Jalankan proyek Kalkulator", "Daftar proyek", "Buka ikon", "Kembali" та "Bantuan". Застосунок відповідає голосом і текстом, тож ним можна користуватися, не дивлячись на екран. Розпізнавання голосу використовує вбудований застосунок розпізнавання мовлення телефона (безкоштовно; може працювати без інтернету, якщо встановлено індонезійський мовний пакет). Якщо в телефоні немає розпізнавання голосу, команди можна ввести в текстове поле на тому самому екрані.

AI-створювач застосунків
Введіть або продиктуйте потрібний застосунок на екрані Створювача застосунків з ШІ, наприклад: «застосунок нотаток із кнопкою зберегти». Застосунок аналізує ключові слова всередині самого телефона (без інтернету, без витрат), а потім створює справжній проєкт із найбільш відповідного шаблону: калькулятор, нотатки, список справ, веб-калькулятор, сайт профілю або лічильник. Якщо для вашого опису ще немає відповідного шаблону, застосунок створює порожній проєкт і чесно каже про це — він не вдає, що зрозумів. Проєкт, створений ШІ, можна відкрити напряму в розділі Керувати проєктами.

Живий попередній перегляд на телефон друга
Щоб показати проєкт другові до збірки: в розділі Керувати проєктами довго натисніть назву проєкту, потім виберіть Попередній перегляд на телефон друга. Застосунок створює невеликий пакет попереднього перегляду з основними файлами проєкту (index.html, MainActivity або main.py) плюс BACA-SAYA.txt з інструкціями та info.txt. Пакет надсилається як ZIP через WhatsApp або Telegram. Друг, який його отримає, може одразу відкрити попередній перегляд: HTML-сторінки відкриваються в браузері, код Java/Kotlin/Python читається як текст.

Маркет проєктів
Ринок проєктів містить вбудовані зразки проєктів, які можна встановити в папку проєкту одним дотиком: Калькулятор, Нотатки, Список справ, Веб-калькулятор, Сайт профілю, Лічильник, Цифровий годинник і Веб-вікторина. Онлайн-ринок (завантаження зразків з інтернету) поки недоступний, тому цей ринок містить зразки, які вже є в застосунку. Встановлений проєкт можна відкрити та змінити в розділі Керувати проєктами, як проєкт, зроблений самостійно.

Пряма співпраця
Щоб працювати над проєктом разом із другом: відкрийте Співпраця в головному меню, виберіть проєкт, напишіть нотатку про зміни (що було змінено), потім натисніть Поділитися для співпраці. Проєкт надсилається як ZIP разом із файлом CATATAN.txt всередині. Ваш друг працює над ним і надсилає ZIP назад; ви натискаєте Отримати відповідь, спочатку читаєте нотатку про зміни, потім вибираєте Застосувати, щоб перезаписати старий проєкт, або Скасувати, якщо передумали. ZIP без CATATAN.txt — не пакет співпраці; для звичайного ZIP проєкту використовуйте Імпортувати проєкт у розділі Керувати проєктами.

Автоматичний перекладач застосунків
Щоб перекласти текст у застосунку іншою мовою: відкрийте Перекладач застосунків у головному меню, виберіть проєкт і цільову мову (англійська, арабська або яванська), потім натисніть Перекласти. Словник уже є в телефоні (без інтернету, без витрат) і містить повсякденні поширені слова; текст із strings.xml, розмітки та коду читається, а потім перекладається. Результат записується в папку values-мова/strings.xml (якщо проєкт має strings.xml) та звіт переклад-мова.txt у папці проєкту. Слова, яких ще немає в словнику, залишаються як є та повідомляються — так ви знаєте, які слова ще потрібно перекласти самостійно.

Створення ігор без коду
Щоб зробити гру, не написавши коду: відкрийте Створювач ігор у головному меню, виберіть тип гри (Вгадай число, Вікторина або Спіймай зірку), заповніть назву гри, кількість (рівні/питання/зірки) та повідомлення про перемогу, потім натисніть Створити гру. Гра створюється як справжній проєкт, який можна запустити напряму в розділі Керувати проєктами та зібрати в APK, як будь-який інший проєкт.

Автоматичне тестування застосунків
Щоб перевірити проєкт перед збіркою: в розділі Керувати проєктами довго натисніть назву проєкту, потім виберіть Автоматичний тест. IDE перевіряє 10 речей, не збираючи APK: наявність обов'язкових файлів (файл даних проєкту, маніфест, головний файл, розмітка, рядки), назву пакета та версію, використані дозволи, значок і баланс дужок коду. Результат показується за кожним пунктом (ПРОЙДЕНО/НЕ ПРОЙДЕНО з повідомленням) і читається вголос програмою Jieshuo. Спочатку виправте все, що НЕ ПРОЙДЕНО, потім натисніть Зібрати проєкт.

AI Pembuat Aplikasi для перевірки коду
Щоб перевірити код проєкту на шаблони, які часто спричиняють проблеми: відкрийте Перевірити код у головному меню, виберіть проєкт, потім натисніть Перевірити код. Перевіряльник працює всередині телефона (без інтернету) і шукає невикористані змінні, порожні функції, явно нескінченні цикли, текст, написаний прямо в коді (краще в strings.xml), небезпечні дозволи та API, маркери TODO/FIXME та динамічне виконання. Кожна знахідка містить назву файла, номер рядка та пропозицію щодо виправлення. Цей перевіряльник базується на шаблонах, це не справжній ШІ — проблеми, що не відповідають шаблону, все одно можуть пройти.

Інтерактивний режим навчання
Щоб вчитися створювати застосунки крок за кроком: відкрийте Навчання в головному меню. Є 5 уроків: Створення першого проєкту, Додавання кнопки, Зміна кольору, Додавання звуку та Збірка APK. Торкніться уроку, щоб прочитати його пояснення та практичне завдання, виконайте завдання, потім натисніть Перевірити завдання — IDE справді перевіряє, чи виконано завдання (скануючи проєкт і APK на вашому телефоні). Пройдені уроки позначаються як завершені та зберігаються.

Синхронізація з хмарою
Щоб зробити резервну копію проєкту в хмару: відкрийте Синхронізація з хмарою в головному меню. Локальна резервна копія зберігає ZIP проєкту в папку Download/cloud із позначкою часу та може бути відновлена будь-коли зі списку резервних копій. Резервна копія GitHub завантажує ZIP проєкту до вашого приватного репозиторію (використовуючи токен із налаштувань GitHub) і може бути завантажена знову. Це ручне резервне копіювання та відновлення — повна автоматична двостороння синхронізація потребує сервера, тому поки недоступна.

Автоматичний створювач бекенду
Щоб зробити бекенд, не написавши коду сервера: відкрийте Створювач бекенду в головному меню, виберіть тип бекенду (Нотатки, Список справ або Дошка повідомлень), заповніть назву проєкту, потім натисніть Створити Backend. IDE створює справжній HTML-проєкт зі сторінкою форми та списком даних, збережених у локальному сховищі телефона (localStorage), — дані зберігаються та можуть бути прочитані знову під час запуску застосунку. Цей бекенд працює на одному телефоні; два телефони поки не можуть ділитися одними даними, оскільки немає інтернет-сервера.

Автоматичний дизайнер тем

Попередній перегляд показує шість кольорів теми (основний, темний основний, акцент, фон, текст, вторинний текст) і читається вголос програмою Jieshuo. Натисніть Застосувати тему — IDE записує colors.xml і styles.xml (стиль app_theme) у проєкт, вони використовуються напряму під час запуску або збірки проєкту.

Створювач анімацій
Щоб надати проєкту анімацію: відкрийте Створювач анімацій у головному меню, виберіть проєкт, тип анімації (Згасання, Зсув, Обертання, Відскок або Пульсація), тривалість (від 100 до 10000 мілісекунд) і ціль (кнопка, текст або зображення), потім натисніть Створити анімацію. IDE записує справжній файл анімації (res/anim/anim_<тип>.xml для проєктів Java/Kotlin/Compose або animasi.css для проєктів HTML/Веб-сайт) разом із прикладом коду використання, показаним на екрані.

Записувач дій
Щоб повторювати роботу автоматично: IDE записує виконані дії (відкрити проєкт, запустити, зібрати, експортувати, зробити резервну копію, створити проєкт, зберегти файл). Відкрийте Записувач дій у головному меню, щоб побачити список записаних дій із їхнім планом, потім натисніть Відтворити знову — IDE знову виконує дії, які можна автоматизувати (резервне копіювання та створення проєкту виконуються на місці; запуск, збірка та експорт відкривають свій головний екран; відкриття та збереження відкривають редактор). Дії, які не можна автоматизувати, пропускаються та повідомляються наприкінці.

Автоматична безпека
Щоб перевірити безпеку проєкту: відкрийте Автоматична безпека в головному меню, виберіть проєкт, потім натисніть Перевірити безпеку. IDE перевіряє 8 речей локально (без інтернету): небезпечні дозволи (місцезнаходження, SMS, дзвінки, камера, мікрофон, контакти), надсилання даних через HTTP, надсилання SMS, вихідні дзвінки, пароль або ключ, написаний прямо в коді, WebView без захисту, компонент, експортований без дозволу, та http-адресу без шифрування. Кожній знахідці присвоюється рівень БЕЗПЕЧНО, ПОПЕРЕДЖЕННЯ або НЕБЕЗПЕЧНО з пропозицією щодо виправлення, а підсумок читається вголос програмою Jieshuo.

AI офлайн
Щоб використовувати допоміжні інструменти для тексту та коду без інтернету: відкрийте AI офлайн у головному меню. Є 4 інструменти: Виправити текст (великі літери, пунктуація та подвійні пробіли), Скоротити текст (бере 3 найважливіші речення), Створити назву застосунку (з написаного опису) та Запропонувати назву змінної (шукає назви змінних із 1-2 літер у проєкті). Це прості правила всередині телефона, а не справжня модель ШІ. Результат виправлення тексту можна застосувати до strings.xml проєкту кнопкою Застосувати.

Конструктор віджетів і шпалер

Застосунок із зображення

Інтерактивний термінал (VT-парсер)
Щоб використовувати інтерактивні програми в Терміналі: відкрийте Термінал у головному меню, потім запустіть nano, vim, top або htop. Terminal Exec (бінарний файл застосунку)
Щоб запустити бінарний файл у папці застосунку (наприклад, aapt2, ECJ, D8) з Термінала: введіть команду як зазвичай. IDE використовує libkautsarexec.so, щоб бінарні файли в папці застосунку могли виконуватися на Android 10 і вище. Натисніть Тест Exec у Терміналі, щоб перевірити, чи працює шлях exec бінарних файлів на цьому телефоні, — результат показується як є. Якщо exec заблоковано системою, системні команди та shell-скрипти все одно працюють; запустіть бінарний файл через меню Зібрати проєкт.

Термінал залишається активним (KeepAlive)
Щоб shell продовжував працювати під час переходу на інший екран: відкрийте Термінал, виконайте команду, потім натисніть Назад або перейдіть на інший екран — shell НЕ вмирає, а сповіщення Термінала залишається видимим, щоб ви могли повернутися одним дотиком. Уже виконані команди зберігаються в історії (кнопка Історія або стрілки вгору/вниз у полі команди), а часто використовувані команди можна зберегти як вибрані (кнопка Обране). Натисніть Закрити shell, коли завершите, щоб shell справді завершився. Є також кнопка Зібрати в Терміналі в меню проєкту та в меню редактора: Термінал відкривається в папці проєкту з уже заповненою командою збірки.

Встановити інструменти термінала (пробна версія)
Функція, яка все ще перебуває в пробній експлуатації: в Терміналі є кнопка Встановити інструменти термінала, щоб встановити середовище Termux із дзеркала в репозиторії alat-termux розробника (github.com/syudat/alat-termux), як ще один шлях окрім кнопки Встановити Termux, яка бере офіційну версію Termux. Вміст дзеркала точно такий самий, як офіційна версія, і перевіряється за допомогою SHA-256 під час встановлення. Після встановлення середовища можна використовувати команди pkg update і pkg install, а додаткові інструменти з репозиторію також встановлюються в термінал: info-terminal — для перегляду інформації про середовище, bersih-terminal — для очищення кешу, і cadangkan-proyek — для архівування папки проєкту в один датований файл tar.gz. Після цього застосунок автоматично встановлює базові пакети Linux (git, python, curl, wget, nano, openssh, zip, unzip) та інструменти збірки APK із підписом (openjdk-21, kotlin, gradle, ecj, aapt2, d8, apksigner, clang, cmake, ninja, make) з офіційного репозиторію Termux, тому термінал одразу готовий створювати застосунки. Завантаження великих пакетів (сотні МБ) може зайняти багато часу. Під час встановлення прогрес і виведення команд відображаються на головному екрані Термінала, а кінцевий результат читається вголос програмою читання з екрана. Якщо встановлення пакетів ще не завершено, натисніть Встановити інструменти термінала ще раз, щоб продовжити його.

Повний голосовий режим
Щоб повністю керувати IDE голосом: відкрийте Голосовий режим у головному меню, потім натисніть Почати слухати. IDE слухає безперервно — не потрібно натискати кнопку для кожної команди, — виконує команду та відповідає голосом. Є 26 команд: створити, зібрати, відкрити, запустити, перелічити, знайти, видалити, перевірити, проконтролювати, експортувати, зробити резервну копію, поділитися, створити значок, перекласти, зібрати в терміналі, прочитати екран, відкрити всі екрани (включно з безпекою, офлайн ШІ, віджетом, соціальними мережами, грою, навчанням, хмарою, бекендом, темою, анімацією, записом), назад, закрити та допомога. Якщо режим залишити активним, прослуховування продовжується автоматично під час повторного відкриття цього екрана. Натисніть Перестати слухати, щоб вимкнути цей режим. Якщо на телефоні немає служби розпізнавання голосу, команди все одно можна писати в текстове поле.

Перекладач коду
Щоб перекладати код між мовами без інтернету: відкрийте Перекладач коду в головному меню, виберіть проєкт, виберіть вихідний файл (.java/.kt), потім виберіть напрямок: Java в Kotlin. Натисніть Перекласти — результат показується разом зі звітом про рядки, які не можна перекласти (ці рядки зберігаються як є та позначаються). Натисніть Зберегти результат, щоб записати НОВИЙ файл (назва-переклад.java/.kt) у тій самій папці; вихідний файл ніколи не перезаписується. Це перекладач за правилами шаблонів, а не компілятор — завжди перевіряйте результат перед використанням.

Git у застосунку
Щоб використовувати Git всередині IDE без Termux: відкрийте Git у застосунку в головному меню, виберіть проєкт, потім натисніть Створити репозиторій Git, щоб створити локальний репозиторій (.git) у цьому проєкті. Натисніть Перевірити статус, щоб побачити нові, змінені або видалені файли порівняно з останнім комітом; заповніть повідомлення коміту, потім натисніть Коміт, щоб зберегти знімок проєкту; натисніть Переглянути журнал комітів, щоб побачити історію комітів. Надсилання до GitHub і Отримання з GitHub використовують знімки через токен GitHub (репозиторій pembuat-aplikasi-build) — не протокол git. Клонування, Надсилання (системний git) і Отримання (системний git) працюють лише якщо бінарний файл git встановлено на телефоні (зазвичай ні). Це не повний git: немає злиття, гілок або diff — кожен коміт зберігає повний ZIP-знімок проєкту.

Створювач реклами
Щоб додати рекламу до зібраного застосунку: відкрийте Створювач реклами в головному меню, виберіть проєкт, постачальника (AdMob, Unity Ads або AppLovin) і тип реклами (Банер, Міжсторінкова або З винагородою). Заповніть ID рекламного блока, якщо він у вас уже є, — порожнє поле означає використання тестового ID (AdMob використовує офіційний тестовий ID Google; Unity використовує приклад ID гри; AppLovin використовує порожнє розміщення). Натисніть Створити рекламний код, щоб побачити код Java та Kotlin і посібник; натисніть Зберегти в проєкт, щоб записати все у файл реклама-<постачальник>-<тип>.txt у проєкті. Це шаблон коду + посібник, а не рекламний SDK — SDK не включено до IDE; справжня реклама з'явиться лише після того, як ви створите обліковий запис постачальника, створите рекламний блок, вставите власний ID блока та додасте залежність SDK у build.gradle проєкту.

Дитячий режим
Щоб використовувати IDE разом із дитиною: відкрийте Дитячий режим у головному меню. Екран спрощено, з великими кнопками та лише 4 безпечними діями: Створити проєкт (із безпечних шаблонів: Калькулятор, Вгадай число, Вікторина, Спіймай зірку), Відкрити проєкт, Запустити та Навчання. На цьому екрані немає кнопки видалення, експорту, резервного копіювання або налаштувань токена. Під час першого входу створіть 4-значний PIN — цей PIN використовується батьком для виходу з Дитячого режиму (кнопка Вийти з дитячого режиму або кнопка Назад). Цей PIN — легкий захист для маленьких дітей, а не справжня безпека.

Створення застосунків для Wear OS і TV
Щоб створити застосунок для годинника (Wear OS) або телевізора (Android TV): відкрийте Wear OS & TV у головному меню, виберіть ціль (Wear OS, Android TV або обидва). Заповніть назву проєкту, потім натисніть Створити новий проєкт Wear/TV — IDE створює Java-проєкт, а потім налаштовує його, — або виберіть уже наявний проєкт, потім натисніть Застосувати до цього проєкту. Налаштування: uses-feature у маніфесті, категорія LEANBACK_LAUNCHER + банер для ТБ та налаштована розмітка activity_main.xml (Wear: малий екран; ТБ: великий екран, зручний для D-pad). Повне пояснення записується у wear-tv.txt у проєкті. Це шаблон проєкту — збірка + тестування й надалі потребують пристрою/емулятора Wear OS або Android TV; ТВ-банер (banner.png 320x180) не створюється автоматично, його потрібно додати самостійно (наприклад, через Створювач значків).

Карта проєкту
Щоб побачити структуру проєкту: відкрийте Карта проєкту в головному меню, виберіть проєкт, потім натисніть Показати карту — IDE показує список папок і файлів із їхніми розмірами, загальний розмір, розмір за типом файлів і важливі файли (головний файл, маніфест, розмітка, рядки, значок, веб-сторінка). Натисніть Зберегти карта-проєкт.txt, щоб записати ту саму карту в корінь проєкту. Папка bin/ (результати збірки) і папка .git/ (локальний репозиторій) не картуються, оскільки їхній вміст можна створити знову.

Калькулятор розміру APK
Щоб оцінити розмір зібраного APK перед збіркою: відкрийте Калькулятор розміру APK у головному меню, виберіть проєкт, потім натисніть Обчислити оцінку. IDE показує розбивку за категоріями (код/DEX, ресурси, асети, нативні бібліотеки, маніфест + resources.arsc, накладні витрати), загальну оцінку, 5 найбільших файлів і пропозиції щодо зменшення (наприклад, великі зображення зменшуються в роздільній здатності, великі звуки скорочуються за тривалістю). Це ОЦІНКА, а не точний розмір — реальний розмір може відрізнятися через стиснення aapt2, видалення невикористаного коду (R8) і зібрані ресурси.

Аналізатор APK
Щоб прочитати вміст готового APK (як Аналізатор APK в Android Studio): відкрийте Аналізатор APK у головному меню, виберіть проєкт, потім натисніть Аналіз APK результату збірки. IDE читає найновіший APK у папці bin цього проєкту та повідомляє назву пакета, версію, мінімальний і цільовий SDK, список використаних дозволів, кількість dex-файлів, розбивку розміру за частинами (код програми, ресурси, асети, нативні бібліотеки, підпис) і 10 найбільших записів. Корисно, щоб дізнатися, яка частина робить APK великим і які дозволи використовує зібраний застосунок.

Попередній перегляд розміру екрана
Щоб перевірити вигляд проєкту на багатьох розмірах екрана одразу (як в Android Studio): відкрийте Попередній перегляд розміру екрана в головному меню, виберіть проєкт, потім натисніть Перевірити розмір екрана. IDE читає всі розмітки проєкту та повідомляє про елементи, ширина яких написана фіксованою (наприклад, 400dp) і перевищує ширину екрана 320, 360, 411 або 480 dp, оскільки на телефоні з малим екраном такий елемент може бути закритий або вийти за межі. Елементи з шириною match_parent або wrap_content автоматично підлаштовуються під екран і не потребують перевірки.

Менеджер ресурсів
Щоб побачити та керувати всіма ресурсами проєкту в одному місці (як Менеджер ресурсів в Android Studio): відкрийте Менеджер ресурсів у головному меню, виберіть проєкт, потім натисніть Переглянути ресурси. IDE повідомляє кількість і розмір файлів за категоріями (drawable, layout, values, mipmap та інші), вміст strings.xml, colors.xml і styles.xml. З того самого екрана новий рядок можна додати до strings.xml, а новий колір — до colors.xml, заповнивши їхню назву та значення — назва перевіряється, а дублікати відхиляються, тому XML-файл не пошкоджується.

Легкий монітор продуктивності
Щоб відстежувати використання RAM і процесора працюючого застосунку (як Профайлер в Android Studio, легка версія): відкрийте Легкий монітор продуктивності в головному меню, спочатку запустіть застосунок, що перевіряється (наприклад, зібраний застосунок, який тестується), заповніть назву його пакета — або виберіть проєкт, потім натисніть Заповнити назву пакета з проєкту, — потім натисніть Почати відстеження. Кожні 2 секунди IDE записує RAM (PSS) і CPU цього застосунку разом із вільною RAM телефона; натисніть Зупинити, щоб побачити підсумок середнього та пікового значень. Без додаткових дозволів. У нових версіях Android доступ на читання процесора іншого застосунку обмежено системою, тому якщо CPU не читається, звіт каже про це як є, а RAM продовжує відстежуватися.

Аудит доступності
Щоб перед випуском перевірити, чи зручний макет проєкту для програм читання з екрана (TalkBack/Jieshuo): відкрийте «Аудит доступності» в головному меню, виберіть проєкт, а потім натисніть «Завантажити список макетів» і виберіть файл макета. IDE читає цей XML-файл і повідомляє про кнопки без підписів із номерами їхніх рядків, про підписи, що використовуються повторно, та елементи, які перекривають одне одного, а потім складає розшифровку порядку фокуса, як її читає вголос Jieshuo. Якщо кнопка не має підпису, заповніть її, а потім натисніть «Вставити підписи автоматично» — підпис буде записано у файл макета як contentDescription. Ця перевірка читає лише XML макетів; подання Compose та готові APK поки не скануються.

Розтин збою
Щоб дізнатися, чому застосунок сам закривається, з журналу збою з унікальним ID: відкрийте «Розтин збою» в головному меню, виберіть ID збою зі списку журналів і натисніть «Перевірити». IDE зіставляє клас і номер рядка в журналі з вихідником проєкту та пояснює причину індонезійською (наприклад, порожнє посилання, ще не запитаний дозвіл або помилка JSON) із запропонованим виправленням коду. Натискайте «Застосувати виправлення» лише якщо рядок вихідника досі точно такий самий, як у момент збою; якщо він змінився, виправлення відхиляється, і IDE просить вас перевірити самостійно. Для збоїв ЗІБРАНОГО застосунку натисніть «Впровадити перехоплювач збоїв у проєкт», потім зберіть APK як завжди: цей зібраний застосунок перехоплює власні збої та записує свій журнал на телефон, а цей журнал можна знайти кнопкою «Знайти журнал збоїв зібраного застосунку». Чесне обмеження: копіювання журналу до публічної папки Download на Android 11 і вище може не вдатися без дозволу на доступ до всіх файлів.

Транспілятор між парадигмами
Щоб перетворити простий код Java на Kotlin або простий XML-макет на код Compose: відкрийте «Транспілятор між парадигмами» в головному меню, виберіть проєкт і файл, а потім натисніть «Попередній перегляд». IDE показує результат перетворення у вигляді тексту — спочатку перевірте його, бо нерозпізнані рядки залишаються як є, а слово static з Java в Kotlin опускається (перевірте його значення перед використанням). Перетворення XML на Compose змінює лише текст, підказки та орієнтацію — розмір, колір та інші атрибути поки не враховуються. Якщо результат правильний, натисніть «Застосувати до файлу», щоб записати цільовий файл; вихідний файл не змінюється. Перетворюються лише безпечні поширені шаблони.

Локальний мікросервер
Щоб тестувати застосунок, якому потрібен сервер, без інтернету: відкрийте «Локальний мікросервер» у головному меню, запишіть визначення маршрутів (наприклад, GET /halo, потім його JSON-відповідь) і натисніть «Запустити сервер». IDE запускає невеликий HTTP-сервер на тому самому телефоні (лише HTTP, без TLS, для тієї самої мережі Wi-Fi) і записує кожен запит і відповідь на екрані. Маршрути можуть використовувати параметри на кшталт {nama} і простий ключ API. Сервер також можна упакувати в зібраний APK: натисніть «Упакувати сервер у проєкт», і вихідник сервера, ресурси та маніфест впроваджуються в проєкт, тож сам зібраний застосунок стає сервером при запуску. Сервер в IDE зупиняється, коли його екран закривається.

Аудитор безпеки
Щоб перевірити код проєкту на прогалини безпеки перед випуском: відкрийте «Аудитор безпеки» в головному меню, виберіть проєкт і натисніть «Почати сканування». IDE сканує код проєкту, маніфест і конфігурацію та повідомляє про знахідки від високого ризику до низького — ключ API, залишений відкритим у коді, компонент, відкритий без дозволу, WebView, що вмикає JavaScript з його JavaScript-інтерфейсом, слабка криптографія (MD5, SHA1, DES), http-адреса без TLS і пароль, написаний прямо в коді — з їхніми файлами та номерами рядків. Для знахідок, виправлення яких безпечне (наприклад, замінити MD5 на SHA-256 або http на https), натисніть «Застосувати виправлення»; для ключів API та паролів IDE лише показує пропозицію виправлення, бо заміну має вирішити сам розробник. Сканування тепер також розбирає справжній DEX-байткод всередині зібраного APK (а не лише текстові шаблони в коді), тому небезпечні викликані API та секрети, вбудовані в DEX, теж виявляються; прогалини, що не відповідають шаблону, досі можуть вислизнути від сканування — перевірте перед застосуванням.

Робот-тестувальник інтерфейсу
Щоб автоматично тестувати екран застосунку за допомогою текстових сценаріїв: відкрийте «Робот-тестувальник інтерфейсу» в головному меню, виберіть проєкт і натисніть «Створити сценарій автоматично». IDE читає маніфест і розмітку проєкту та записує сценарій як текстові кроки (натиснути кнопку, заповнити поле, зачекати, повернутися). Натисніть «Запустити пробний запуск», щоб побачити журнал виконання сценарію з позначками часу — цей пробний запуск досі лише моделювання послідовності. Для справжнього тестування натисніть «Впровадити тестового агента в проєкт»: IDE впроваджує тестового агента з ресурсами сценарію в проєкт; зберіть APK як завжди, встановіть його, потім відкрийте значок «Тест» — цей агент працює всередині зібраного застосунку та справді натискає кнопки, заповнює справжні поля та прокручує, а потім показує свій звіт на екрані зі справжніми впійманими збоями. Натисніть «Видалити тестового агента з проєкту», щоб знову видалити цього агента. Агент працює всередині самого процесу застосунку, тому йому не потрібні ні служба доступності, ні системна автоматизація.

Подорож у часі коду
Щоб повернути проєкт до ранішого стану коду, не вводячи команди Git: відкрийте «Подорож у часі коду» в головному меню, виберіть проєкт, заповніть мітку моменту часу (можна лишити порожньою), а потім натисніть «Записати момент часу». IDE зберігає копію вихідних файлів проєкту разом з їхніми хешами в папці .riwayat усередині проєкту. Список моментів часу показує їх усі; виберіть два моменти, а потім натисніть «Порівняти», щоб побачити додані, змінені або видалені файли та функції. Натисніть «Відновити», щоб повернути старий стан — перед відновленням IDE завжди спочатку робить резервну копію поточного стану, тож нічого не губиться. Натисніть «Створити експериментальну копію», щоб скопіювати проєкт до нової папки та пробувати зміни, не чіпаючи вихідний проєкт. Записуються лише вихідні файли.

Фабрика модулів
Щоб упакувати частину проєкту як модуль, який зможе використати інший проєкт: відкрийте «Фабрика модулів» у головному меню, виберіть вихідний проєкт, позначте файли екранів, класів, рядків і дозволів для пакування, а потім натисніть «Упакувати як модуль». IDE записує ZIP-архів разом із метаданими JSON (ім'я модуля, версія, використані рядки та дозволи). Щоб установити модуль в інший проєкт, відкрийте «Фабрика модулів», виберіть цільовий проєкт, а потім натисніть «Установити модуль» і виберіть .zip-файл модуля — злиття додає рядки та дозволи, не перезаписуючи наявний код, і не зливає файл, якщо його ім'я вже використовується в цільовому проєкті. Модуль не несе бібліотек або налаштувань збірки.

Поліморфний щит і сховище ресурсів
Щоб перемішати імена ідентифікаторів і зашифрувати ресурси проєкту перед випуском: відкрийте «Поліморфний щит і сховище ресурсів» у головному меню, виберіть проєкт і натисніть «Перемішати імена та зашифрувати ресурси». IDE сканує імена класів і методів у вихідному коді, будує карту випадкових імен, переписує ці імена ВСЕРЕДИНІ скомпільованих файлів DEX (імена-заміни робляться тієї самої довжини, що й вихідні, щоб усі зміщення лишалися правильними, потім перераховуються контрольна сума та підпис SHA-1 заголовка DEX), шифрує файли ресурсів проєкту за допомогою AES-GCM у папку brankas-aset всередині проєкту та зберігає зашифровану карту відновлення (perisai-peta.brankas), щоб вихідні імена можна було відновити під час читання журналів збоїв. Ключ шифрування тепер виводиться з пароля розробника за допомогою PBKDF2, 20 000 ітерацій, а не з імені проєкту. Імена, які також використовуються як звичайний текст, імена анотацій та налагоджувальні імена, навмисно не переписуються, а точки вставлення переписування DEX у шляху збірки ще чекають перевірки на справжньому телефоні.

Ланцюжок довіри та страж середовища
Щоб перевірити ланцюжок ключів підпису та середовище телефона перед випуском: відкрийте «Ланцюжок довіри та страж середовища» в головному меню, виберіть проєкт і натисніть «Перевірити ланцюжок і середовище». IDE будує ланцюжок ключів із 5 поколінь з імені пакета проєкту та перевіряє його цілісність, перевіряє справжню цілісність пам'яті, порівнюючи вміст сегментів коду в пам'яті з файлами на диску, і повідомляє про анонімні виконувані (RWX) відображення, чужі бібліотеки та відображення memfd, а потім сканує карту пам'яті власного процесу та властивості пристрою в пошуках слідів Frida, Xposed або емулятора. Ключ сховища обгортається ключем AES в AndroidKeyStore, який використовує апаратний чип безпеки, коли він доступний, а ротація ключів тепер справжня, з використанням lineage сертифікатів підпису схеми v3: старий ключ підписує доказ ротації до нового ключа, і APK перепідписується з цим lineage. Результат — рівень ризику «Безпечно», «Обережно» або «Небезпечно» з текстовими доказами. Якщо система відмовляє в читанні пам'яті, перевірка повідомляється як «неможливо перевірити», а не як безпечна; а чи використовує ключ насправді апаратний чип безпеки, можна підтвердити лише на справжньому пристрої.

Архітектор розмітки на основі текстового дерева
Щоб спроєктувати екран, не бачачи його: відкрийте «Архітектор розмітки на основі текстового дерева» в головному меню, виберіть проєкт і файл розмітки, потім натисніть «Перевірити розмітку». IDE читає XML-розмітку як текстове дерево й уголос описує положення кожного елемента (наприклад, унизу праворуч, 45 відсотків ширини екрана), а потім математично повідомляє про накладання елементів і про елементи, що виходять за екран за ширини 360 dp. Те, що тепер обчислюється, включає LinearLayout і прості розміри dp, повний ConstraintLayout (усі обмеження, зміщення, ланцюжки, напрямні, бар'єри, відсоткові ширини, 0dp match_constraint і співвідношення сторін), а також екрани Compose (Column, Row і Box з їхніми модифікаторами розміру). Лише MotionLayout і ConstraintSet, що змінюються під час виконання, досі повідомляються як «положення невідоме», бо їхні значення існують лише поки застосунок працює.

Студія системи дизайну
Щоб зробити відступи, шрифти та кути однаковими на всіх екранах і проєктах: відкрийте «Студія системи дизайну» в головному меню, виберіть проєкт, запишіть токени дизайну (наприклад, jarak=8, huruf=16, sudut=12), виберіть компонент і натисніть «Створити компоненти». IDE перевіряє токени — базовий відступ від 4 до 16 dp, базовий шрифт від 12 до 20 sp, кути від 0 до 32 dp і мінімальна область дотику 48 dp — а потім записує готові XML-компоненти (komponen-studio.xml) з XML-темою (tema-studio.xml) і темою Compose (tema-studio.kt) у папку проєкту. Токени також можна зберегти як іменований набір у спільній міжпроєктній бібліотеці токенів, а одна команда синхронізації застосовує найновіші токени бібліотеки до всіх проєктів, що використовують цей набір. Компоненти створюються як текст, який вставляється в розмітку, а потім перевіряється «Архітектором розмітки на основі текстового дерева»; двоколонкове налаштування на планшеті використовує кваліфікатор ширини екрана, а не визначення пристрою під час виконання.

Семантичний рефакторинг і навігація AST
Щоб знаходити визначення та перейменовувати символи, не ламаючи інший код, який випадково носить те саме ім'я: відкрийте «Семантичний рефакторинг і навігація AST» у головному меню, виберіть проєкт і натисніть «Сканувати символи проєкту», щоб побачити всі класи та методи з їхніми файлами й номерами рядків. Введіть ім'я символу та знову натисніть «Сканувати символи проєкту», щоб побачити його визначення та всі файли, які його викликають. Щоб перейменувати, введіть нове ім'я, натисніть «Попередній перегляд перейменування», щоб побачити кількість входжень у кожному файлі, а потім «Застосувати перейменування». Індексатор тепер використовує самописний парсер AST (лексер і рекурсивний парсер для Java та підмножини Kotlin), тому міжфайлові перейменування методів розв'язуються, а викликачі в інших файлах теж змінюються; кнопка вилучення блоку коду в нову функцію тепер є на цьому екрані. Цей парсер поки мінімальний: дуже складні generics, параметризовані анотації та анонімні класи скануються як є, а виклики через рефлексію та через інтерфейси не розв'язуються.

Покроковий налагоджувач та інспектор пам'яті
Щоб перевіряти вміст змінних у середині потоку програми, не гадаючи за журналами: відкрийте «Покроковий налагоджувач та інспектор пам'яті» в головному меню, виберіть проєкт, запишіть трасування виконання (один крок на рядок, у вигляді: номер рядка, код, потім змінні та значення, розділені |, наприклад 10|int total = harga * jumlah;|harga=5000, jumlah=3, total=15000), введіть номер рядка точки зупинки та натисніть «Запустити трасування налагодження». IDE дійде до першої точки зупинки та прочитає вголос активний рядок з його значеннями змінних через Jieshuo. Натисніть «Крок на один рядок», щоб просунутися на один рядок, «Увійти у функцію», щоб увійти у викликану функцію (зі стеком викликів), або «Продовжити програму», щоб дійти до наступної точки зупинки. Цей трасувальний налагоджувач досі слідує записаному або написаному вручну трасуванню; поруч із ним є чистий Java-клієнт дротового протоколу JDWP, який може виконати рукостискання, встановити точки зупинки, крокувати всередину, поверх і назовні, а також призупиняти та відновлювати VM через TCP або в режимі прослуховування. Призупинити справжній процес зі звичайного застосунку досі неможливо повністю, бо сокет JDWP процесу доступний лише через adbd — перевірений шлях вимагає бездротового налагодження та запуску цілі через оболонку, що виходить за можливості самого застосунку.

Менеджер залежностей офлайн
Щоб використовувати сторонні бібліотеки без інтернету та уникати конфліктів версій перед збіркою: відкрийте «Менеджер залежностей офлайн» у головному меню, виберіть проєкт і натисніть «Перевірити залежності». IDE читає всі файли .gradle проєкту, перевіряє спільне міжпроєктне сховище в папці Download/brankas-bersama та розв'язує конфлікти — якщо дві бібліотеки просять різні версії того самого артефакту, використовується найвища версія, а про конфлікт повідомляється. Щоб завантажити бібліотеку, введіть її координати (у вигляді група:артефакт:версія, наприклад com.google.code.gson:gson:2.10.1) і натисніть «Перевірити залежності»: при підключенні файли AAR, JAR або WHL справді завантажуються з Maven, Google або PyPI разом з їхнім графом транзитивних залежностей (рекурсивно, цикли розриваються, глибина до 25 рівнів), і лише успішно завантажені файли записуються як доступні. В офлайні можна використовувати лише бібліотеки, що вже є у спільному сховищі. Діапазони версій Maven не розв'язуються, а завантажені файли перевіряються лише за їхнім SHA-1, без перевірки PGP.

Інспектор бази даних і сховища
Щоб перевіряти та тестувати вміст бази даних проєкту, не написавши код, що друкує вміст таблиць: відкрийте «Інспектор бази даних і сховища» в головному меню, виберіть проєкт і файл бази даних (.db, .sqlite або .sqlite3), потім натисніть «Відкрити базу даних». IDE читає схему всіх її таблиць за допомогою повного парсера сторінок SQLite (B-дерево зі сторінками переповнення) і показує перші 20 рядків у вигляді текстової таблиці, яку Jieshuo читає вголос. Напишіть SELECT-запит і натисніть «Виконати запит» (наприклад, SELECT nama FROM pengguna WHERE kota = 'Makassar') — запити тепер підтримують JOIN, GROUP BY, ORDER BY і LIKE, а на телефоні виконуються через справжній рушій SQLite Android. Щоб змінити значення, введіть номер рядка (1 = перший рядок), ім'я стовпця та нове значення, потім натисніть «Змінити значення клітинки» — це значення записується назад у файл .db. Натисніть «Зберегти резервну копію», щоб зберегти поточний стан таблиці як файл <ім'я-бд>.cadangan.txt у проєкті. SharedPreferences і DataStore теж можна читати. Що досі не можна прочитати: зашифровані бази даних, непідтверджені зміни WAL і типізовані значення у спеціальному DataStore Proto (показуються лише як загальний вид полів).

Фабрика модульних тестів і фаззинг
Щоб знаходити логічні прогалини до того, як застосунок буде опубліковано: відкрийте «Фабрика модульних тестів і фаззинг» у головному меню, виберіть проєкт і файл коду, потім натисніть «Створити та запустити тести». IDE читає сигнатури функцій у файлі, створює звичайні та граничні тестові випадки (порожній текст, null, максимальні числа, дивні символи), а потім справді запускає ці тести: код проєкту компілюється, і кожен метод @Test виконується з лімітом 5 секунд, тож результат — справжні проходження та падіння з їхніми реальними значеннями. Фазинг теж справді виконується над функціями проєкту (через рефлексію, 2 секунди на виклик, не більше 20 методів), а відсоток покриття рядків справді обчислюється за допомогою інструментування, що зберігає вихідні номери рядків. Результат повідомляє, скільки тестів пройшло та впало, скільки рядків коду та функцій знайдено, і які тестові випадки створено. Згенеровані тести використовують рівно той самий API, що й JUnit, але визначення анотацій і тверджень записано всередині самого згенерованого тестового файлу, бо справжня бібліотека JUnit не включена в застосунок.

Симулятор екстремальних умов пристрою та аудитор витоків пам'яті
Щоб перевірити стійкість застосунку, коли система завершує його процес, мережа падає, екран повертається або вмикається економія заряду: відкрийте «Симулятор екстремальних умов пристрою та аудитор витоків пам'яті» в головному меню, виберіть проєкт і натисніть «Запустити моделювання». IDE виконує три сценарії навантаження з моделюванням повороту екрана та відстежує об'єкти, утримувані в пам'яті після закриття їхнього екрана, а потім повідомляє про втрачені дані та протікаючі ланцюжки об'єктів. Стан збереження та відновлення тепер читається з вихідників власного проєкту користувача, а не з фіксованого прикладу; локальний loopback-сервер справді зупиняється в середині тесту, щоб виміряти обрив мережі; береться та розбирається справжній heap dump, щоб порівняти два дампи та простежити ланцюжок утримання від коренів GC; а власний процес застосунку справді завершується після збереження його стану, потім перевіряється, які дані повертаються при повторному відкритті. Що досі неможливо зі звичайного застосунку: вимикати радіо або Wi-Fi телефона та примусово зупиняти інші застосунки — для обох потрібен системний дозвіл; натомість фонові застосунки завершуються через killBackgroundProcesses, дозвіл якого вже є в маніфесті, з чесною позначкою на екрані.

Архітектор креслень проєкту
Щоб перетворити велику ідею застосунку на покроковий план роботи: відкрийте «Архітектор креслень проєкту» в головному меню, виберіть проєкт, запишіть ідею застосунку (наприклад, касовий застосунок для невеликого продуктового магазину з розстрочкою), потім натисніть «Створити креслення». IDE будує модулі, список файлів і невеликі етапи, а потім зберігає їх як cetak-biru.txt у папці проєкту. Натискайте «Позначити наступний етап виконаним» щоразу, коли етап завершено, або «Завантажити збережене креслення», щоб знову відкрити збережене креслення. Якщо в «Налаштування ШІ» вибрано активного ШІ-провайдера та його ключ доступний, креслення будує цей провайдер; якщо ключа немає або провайдер недоступний, IDE повертається до офлайн-шаблонів ключових слів і чесно повідомляє про це обмеження. Відповідь провайдера перевіряється лише на формат (модулі та етапи присутні), а не на правдивість вмісту — завжди перевіряйте креслення перед збіркою.

Оповідач логічного потоку коду
Щоб розуміти довгий код, не слухаючи синтаксис рядок за рядком: відкрийте «Оповідач логічного потоку коду» в головному меню, виберіть проєкт і файл коду, потім натисніть «Опис коду». IDE перетворює кожен рядок на індонезійське речення (наприклад, якщо підсумок більший за 100000, то виконати наступний блок), показує карту викликів між методами та аналіз потоку даних між методами (передані, використані або проігноровані значення), а також позначає тонкі можливі помилки з їхніми номерами рядків — String, порівнюваний з ==, потік, відкритий без закриття, і змінна, записана у двох різних методах. Якщо в «Налаштування ШІ» вибрано активного ШІ-провайдера, доступна також зведення потоку від цього провайдера; якщо недоступно, екран використовує офлайн-опис і повідомляє про це обмеження. Опис, карта викликів і потік даних використовують офлайн-аналіз текстових шаблонів, а не повний парсер AST — методи, чия відкривальна дужка стоїть на окремому рядку, поля класу та виклики через рефлексію не відстежуються — а попередження про гонки даних можуть з'являтися для змінної, яка насправді використовується лише по черзі.

Фабрика пакетів застосунків і готовність до Play Store
Щоб підготувати застосунок до Google Play Store прямо з телефона: відкрийте «Фабрика пакетів застосунків і готовність до Play Store» в головному меню, виберіть проєкт і натисніть «Зібрати пакет AAB». IDE збирає файл .aab з маніфесту, ресурсів і активів проєкту разом зі справжнім BundleConfig.pb, перевіряє структуру пакета, а потім розділяє пакет на справжні варіантні APK (базовий, за архітектурою, за мовою та універсальний) з розмірами, виміряними за підсумками цього розділення, а не оціненими. Пакет підписується JAR v1 тим самим ключем проєкту, що й підпис APK, а його ланцюжок підпису перевіряється криптографічно. Цей екран також перевіряє готовність до Play — цільовий SDK нижче 35 позначається як «Високий», бо Play Store вимагає 35 або вище, а відсутня 64-бітна бібліотека теж позначається як «Високий». Справжній bundletool не може працювати на пристрої, бо bundletool вимагає JVM, а в Android немає JVM; описаний вище шлях — найближчий реальний на пристрої.

Рушій оновлень OTA та поетапні випуски
Щоб надіслати невелике виправлення, не змушуючи користувачів заново завантажувати весь APK: відкрийте «Рушій оновлень OTA та поетапні випуски» в головному меню, виберіть проєкт, запишіть вміст старої та нової версій, потім натисніть «Створити пакет виправлення». IDE обчислює різницю та створює пакет виправлення (patch-ota.zip) з відбитком SHA-256 нового вмісту, а потім перевіряє, чи входить цей пристрій до першого етапу випуску на 10 відсотків. Виправлення тепер підтримують бінарні дельти для будь-якого файлу (включно з DEX і APK), упаковуються з підписом RSA-2048 і перевіряються довіреним відкритим ключем перед застосуванням, а також можуть завантажуватися з сервера розробника разом з його списком випусків; якщо застосування не вдалося, старий файл лишається неушкодженим. Застосування виправлення до працюючого застосунку виконується через перепідпис ключем проєкту та PackageInstaller, бо замінити код працюючого процесу зсередини самого себе неможливо — APK заблоковано, а DEX уже завантажено.

Студія командної перевірки коду
Щоб перевіряти зміни колеги та розв'язувати конфлікти злиття, не читаючи стрілки Git: відкрийте «Студія командної перевірки коду» в головному меню, виберіть проєкт, введіть три текстові версії (базову, локальну, колеги) і натисніть «Відкрити перевірку команди». IDE об'єднує всі три на основі синтаксичних одиниць Java — два зміни в одному рядку, але в різних операторах, більше не вважаються конфліктом — і показує кожен конфлікт як варіант голосування: «Використати локальну версію», «Використати версію колеги» або «Об'єднати обидві» — результуючий рядок вставляється на вихідну позицію конфлікту, щоб порядок лишився правильним — а потім записує результат у gabung-hasil.txt у проєкті. Нижче знаходиться дошка завдань проєкту: введіть заголовок завдання та натисніть «Додати завдання»; завдання зберігаються як текст у папці .tugas всередині проєкту та синхронізуються через коміти у вбудованому Git, тож дошку можна прочитати з будь-якої історії комітів. Цей синтаксичний розділювач — не повний парсер AST, а вбудований Git зберігає повний знімок на коміт; спеціального сервера синхронізації немає.

Диктування структури коду
Щоб писати код голосом усередині редактора: відкрийте проєкт у редакторі, а потім натисніть кнопку «Диктування структури коду». Промовляйте команди індонезійською мовою, наприклад buat fungsi tambah dengan parameter a angka dan b angka, buat kelas Mobil або buat variabel teks nama sama dengan Budi — IDE перетворює мовлення на синтаксично правильний блок коду Java, Kotlin, Python або Compose та вставляє його в позицію курсора, а потім зачитує короткий підсумок через Jieshuo. Диктування використовує вбудовану системну службу голосового введення, без додаткового дозволу на мікрофон, і розпізнає лише вже зареєстровані шаблони команд; мовлення поза цими шаблонами в код не перетворюється. Числа, промовлені словами (наприклад, 'lima'), поки не перетворюються на цифри.

Локальний простір співпраці (без інтернету)
Щоб працювати разом в одній кімнаті без інтернету: відкрийте «Співпраця» в головному меню, а потім відкрийте розділ «Локальний простір співпраці». Один телефон відкриває сеанс (IDE показує локальну IP-адресу та 6-значний PIN), інший телефон приєднується за цією адресою та PIN. Зміни тексту надсилаються як построчні відмінності, зібраний APK можна надіслати на телефон тестувальника, а звіти про збої з телефона тестувальника повертаються назад. Один сеанс — лише для одного друга; якщо двоє людей змінять рівно той самий рядок одночасно, використовується остання зміна. PIN надсилається відкритим текстом у локальній мережі. Ця кімната ще не тестувалася на справжньому телефоні.

Налаштування ШІ
Щоб налаштувати ШІ-провайдера та ключі API для створення застосунків: у головному меню в групі «Налаштування» натисніть «Налаштування ШІ» (поруч із кнопкою «Конектор»). Виберіть провайдера зі списку доступних і ввімкніть «Перемикати модель у разі помилки провайдера», щоб при збої однієї моделі IDE автоматично спробувала наступну модель того самого провайдера. Натисніть «Керування ключами API», щоб додати резервні ключі (введіть ім'я та ключ, потім натисніть «Зберегти»; ключі показуються замаскованими, видно лише останні 4 символи). Ключі зберігаються на телефоні та ніколи нікуди не надсилаються, крім вибраного провайдера під час створення застосунку. Вибраний провайдер тепер справді використовується «Архітектором креслень проєкту» та «Оповідачем логічного потоку коду»; створення застосунків на екрані «Творець застосунків з ШІ» досі використовує локальний ШІ на телефоні (без інтернету).

Конектор
Щоб проаналізувати APK, а потім надіслати його: у головному меню, в групі «Налаштування», натисніть «Конектор» (поруч із кнопкою «Налаштування ШІ»). Виберіть файл APK із телефона, IDE прочитає його вміст (ім'я пакета, версія, список активностей), а потім натисніть «Надіслати APK», щоб надіслати його через системне меню обміну (наприклад, WhatsApp або Drive).

Мова та голос
Щоб змінити мову застосунку: відкрийте «Налаштування», потім «Мова застосунку», а потім виберіть мову або «Як у системі». Головний екран і більшість екранів одразу перемкнуться на обрану мову без закриття чи перезапуску застосунку; деякі екрани (наприклад, «Термінал», «Співпраця», «Налаштування ШІ» та «Керування ключами») досі використовуватимуть стару мову, доки їх не буде відкрито знову. Якщо вибрати «Як у системі», мова слідуватиме мові системи телефона.

Підпис за замовчуванням для кожного проєкту та Anti Tamper
Починаючи з версії 5.7, проєкт, який не використовує особистий підпис, підписується ВЛАСНИМ вбудованим ключем цього проєкту (створеним один раз у папці tanda-tangan-bawaan всередині проєкту, потім використовуваним далі), тому вбудований підпис відрізняється від проєкту до проєкту — більше не один спільний ключ для всіх застосунків. Не видаляйте папку tanda-tangan-bawaan: без цього ключа новий APK не зможе перезаписати старий APK того самого проєкту. Налаштування кожного проєкту (окрема архітектура, особистий підпис, захист від підробки, вибраний keystore, SDK) тепер зберігаються у файлі settings.gradle всередині проєкту та читаються знову під час кожної збірки проєкту. У Налаштуваннях, у категорії Підпис, є прапорець Захист від підробки зібраного застосунку: якщо він активний, зібраний застосунок на пристрої перевіряє свій підпис і вміст dex під час кожного відкриття; якщо його було перепідписано або змінено кимось іншим, застосунок відмовляється працювати. Інструменти налагодження та впровадження, такі як Frida/Xposed, також виявляються, а вікно застосунку блокується від запису екрана.

Створювач демо-відео
Щоб зробити демо-відео зібраного застосунку: відкрийте Створювач демо-відео в головному меню, виберіть проєкт, заповніть назву відео, потім натисніть Створити скрипт демо-відео — IDE записує video-demo.txt із 5 стандартними сценами (відкриття, головний вигляд, функція 1, функція 2, закриття) разом із текстом розповіді та тривалістю кожної сцени. Натисніть Створити слайд-шоу HTML, щоб зробити video-demo.html із зображень проєкту (значок + скриншоти, якщо є), які змінюються автоматично кожні 5 секунд. Це НЕ відео .mp4 — для справжнього відео відкрийте video-demo.html у браузері телефона, а потім запишіть екран, або прочитайте розповідь у video-demo.txt, записуючи працюючий застосунок.

Новий вигляд у стилі Android Studio
Зовнішній вигляд IDE тепер упорядковано, щоб нагадувати Android Studio (лише зовнішній вигляд — усі кнопки, меню та потоки залишаються точно як раніше): світло-сірий фон, жирні чорні заголовки екранів, сині кнопки з білим текстом і білі поля введення з тонкою рамкою. Головне меню візуально згруповано (Функції створення, Хмара, тема та інше, Голос, код і нові функції, Інструменти) без зміни порядку кнопок. Термінал і надалі використовує темну панель, як вікно Термінала в Android Studio, а редактор коду й надалі має білий фон із чорним текстом. Увесь текст і надалі чітко читається програмою Jieshuo.

Налаштування
Щоб налаштувати застосунок: відкрийте меню Опції на головному екрані, потім натисніть Налаштування. Всередині є 12 категорій: Налаштування GitHub (безпека, особистий підпис, історія збірки та токен GitHub), Налаштування збірки APK на пристрої (збереження пароля keystore та історії збірки на пристрої), Тема (кольори застосунку), Підпис (створення keystore для особистого підпису та прапорець захисту від підробки зібраного застосунку), Папка проєктів (розташування папки проєктів), Мова та голос (мова інтерфейсу та швидкість голосу Голосового режиму), Розмір тексту та вигляд (розмір шрифту редактора), Збірка (цільовий SDK за замовчуванням і розділення архітектури за замовчуванням для екрана Створити проєкт), Сповіщення (звук після завершення збірки), Автоматичне резервне копіювання (розклад резервного копіювання проєктів), Профіль розробника (ім'я, номер WhatsApp і рахунок, що показуються на екрані Пожертвування) та Конфіденційність і дані (скидання налаштувань і видалення даних застосунку). Кожна категорія має кнопку Повернутися назад, щоб повернутися до меню категорій. Налаштування, які щойно було збережено (ще не застосовано), мають своє пояснення, чесно написане на екрані.

Пожертвувати розробнику
Щоб пожертвувати або привітати розробника: натисніть кнопку Пожертвувати розробнику на головному екрані, поруч із кнопкою Про інструмент. На екрані пожертвування є кнопка Копіювати рахунок BRI — натисніть її, щоб скопіювати номер рахунку розробника, потім вставте його у банківський застосунок. Є також розділ Привітати розробника в WhatsApp: заповніть своє ім'я та рідне місто, потім натисніть Надіслати в WhatsApp — WhatsApp відкривається з уже заповненим вітальним повідомленням, просто натисніть Надіслати у WhatsApp, а потім поверніться до застосунку. WhatsApp не дозволяє іншим застосункам надсилати повідомлення автоматично, тому надсилання все одно виконується вами самостійно у WhatsApp.

Вибрані команди термінала
Щоб зберегти команди, які часто використовуються в Терміналі: відкрийте Термінал, потім натисніть Обране. Торкніться Додати нове улюблене, заповніть назву (наприклад, Переглянути файл) та його команду (наприклад, ls -la), потім натисніть Зберегти — улюблене зберігається на телефоні назавжди. Торкніться назви улюбленого, щоб виконати його напряму в терміналі; торкніться Видалити улюблене, потім виберіть одне, щоб видалити його (з підтвердженням). Уже є 3 вбудовані вибрані: Переглянути файл (ls -la), Перевірити місце (df -h) та Очистити екран (clear) — усі вони можуть бути видалені. Порожня команда не може бути збережена або виконана; Термінал повідомляє вам про це повідомленням і голосом, якщо це трапляється.

Аналітика та якість
Щоб побачити підсумок використання застосунку та звіти про збої: натисніть кнопку Аналітика та якість на головному екрані, поруч із кнопкою Пожертвувати розробнику. Цей екран показує, скільки разів застосунок було відкрито, які екрани відкриваються найчастіше, кількість збоїв і список останніх збоїв із короткою пропозицією щодо виправлення. Ці дані зберігаються лише на вашому телефоні та нікуди не надсилаються. Є кнопка Видалити дані аналітики з діалогом підтвердження для видалення всіх цих даних. Останній екран записується лише для головного екрана та цього екрана.
