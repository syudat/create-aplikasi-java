Create Aplikasi by Al Kautsar میں خوش آمدید
Create Aplikasi ایک اینڈرائیڈ ایپ بنانے والی ایپلیکیشن ہے جو براہ راست فون پر چلتی ہے، لیپ ٹاپ کی ضرورت کے بغیر۔ یہ ایپلیکیشن کسی کو بھی اپنی اینڈرائیڈ ایپ بنانے کی اجازت دیتی ہے، بشمول ان صارفین کے جو ایپ بنانا سیکھ رہے ہیں اور اسکرین ریڈر کے صارفین کے۔ اس ایپلیکیشن کے استعمال کی مکمل رہنمائی اسی Tentang Alat (ٹول کے بارے میں) اسکرین میں دستیاب ہے۔

یہ ایپلیکیشن کیا ہے اور کس کے لیے ہے
Create Aplikasi اینڈرائیڈ ایپ بنانے کا ایک ٹول ہے جو فون پر چلتا ہے۔ یہ ایپلیکیشن ہر اس شخص کے لیے ہے جو اپنی اینڈرائیڈ ایپ بنانا چاہتا ہے، بشمول ابتدائی صارفین اور اسکرین ریڈر کے صارفین کے۔ یہ ایپلیکیشن ایک کوڈ ایڈیٹر، پروجیکٹ کو آزمانے کے لیے Jalankan (چلائیں) بٹن، APK بنانے کے لیے Bangun (بنائیں) بٹن، اور APK پر دستخط کرنے اور انسٹال کرنے کے مینو فراہم کرتی ہے۔

اس ایپلیکیشن کا مقصد
یہ ایپلیکیشن اس لیے بنائی گئی ہے تاکہ ہر کوئی براہ راست فون سے آسانی سے اپنی اینڈرائیڈ ایپ بنا سکے۔ اس کی صورت کو جتنا ممکن ہو سادہ بنایا گیا ہے تاکہ نئے صارفین بھی اسے فوراً آزما سکیں۔

نیا پروجیکٹ بنانے کا طریقہ، قدم بہ قدم
1. مرکزی مینو میں Buat Project (پروجیکٹ بنائیں) دبائیں۔
2. پروجیکٹ کی قسم منتخب کریں: HTML، Situs Web (ویب سائٹ)، Java، Kotlin، Compose یا Python۔
3. ایپلیکیشن کا نام بھریں، مثال: Garuda Decode۔
4. پیکیج کا نام (package name) بھریں، مثال: com.android.garudadecode۔ پیکیج کے نام میں چھوٹے حروف استعمال ہونے چاہئیں اور اس میں نقطے سے الگ کیے گئے کم از کم دو حصے ہونے چاہئیں۔
5. ایپلیکیشن کا ورژن بھریں، مثال: 1.0، اور ورژن کوڈ عدد کی صورت میں بھریں، مثال: 1۔ اگر خالی چھوڑا جائے تو ورژن خودکار طور پر 1.0 اور ورژن کوڈ 1 سے بھر دیا جائے گا۔
6. اگر ضرورت ہو تو کم از کم SDK اور ہدف SDK بھریں۔ اگر خالی چھوڑا جائے تو طے شدہ قیمت استعمال ہوگی۔ کم از کم SDK سب سے کم تعاون یافتہ اینڈرائیڈ ورژن ہے، مثال: 21 کا مطلب ہے Android 5.0۔ زیادہ سے زیادہ ہدف SDK 36 (Android 16) ہے۔
7. ایپلیکیشن کی اجازتیں منتخب کرنے کے لیے Pilih Izin (اجازتیں منتخب کریں) بٹن دبائیں، مثال: INTERNET۔ INTERNET اجازت پہلے سے طے شدہ طور پر نشان زدہ ہے۔ صرف وہی اجازتیں نشان زد کریں جن کی ایپلیکیشن کو واقعی ضرورت ہو۔
8. اگر چاہیں تو "Gunakan arsitektur terpisah 64 bit dan 32 bit" (الگ 64 بٹ اور 32 بٹ معماریاں استعمال کریں) پر نشان لگائیں تاکہ APK کا سائز چھوٹا ہو جائے، اور اگر آپ خود کی بنائی ہوئی keystore استعمال کرنا چاہتے ہیں تو "Gunakan tanda tangan pribadi" (ذاتی دستخط استعمال کریں) پر نشان لگائیں۔
9. Buat Proyek (پروجیکٹ بنائیں) دبائیں۔ نیا پروجیکٹ Download/project فولڈر میں محفوظ ہو جاتا ہے اور Kelola Project (پروجیکٹ سنبھالیں) میں فوراً نظر آتا ہے۔

دستیاب پروجیکٹ کی اقسام
• HTML: index.html، style.css اور script.js سے صورت، WebView کے ذریعے چلتی ہے۔ براہ راست فون پر بنائی جاتی ہے۔
• Situs Web: index.html، tentang.html، kontak.html، style.css اور script.js سے مینو (Beranda (ہوم)، Tentang (بارے میں)، Kontak (رابطہ)) والی ویب سائٹ، WebView کے ذریعے چلتی ہے۔ براہ راست فون پر بنائی جاتی ہے۔
• Java: فون پر بنائی جاتی ہے۔ MainActivity یہاں ہے app/src/main/java/<nama-paket>/MainActivity.java۔ صورت app/src/main/res/layout/activity_main.xml سے، متن app/src/main/res/values/strings.xml سے اور تھیم app/src/main/res/values/styles.xml سے آتی ہے۔
• Kotlin: ایپلیکیشن میں شامل Kotlin کمپائلر استعمال کرکے ڈیوائس پر (آف لائن) بنائی جا سکتی ہے، یا GitHub Actions کے ذریعے۔ MainActivity یہاں ہے app/src/main/java/<nama-paket>/MainActivity.kt اور res فائلیں Java پروجیکٹ جیسی ہی ہیں۔ پہلی Kotlin تعمیر کمپائلر کے بڑے سائز کی وجہ سے سست ہوتی ہے، اور وہ .java فائلیں جو Kotlin کلاسوں کا حوالہ دیتی ہیں ابھی نہیں بنائی جا سکتیں (.java فائلیں .kt فائلوں سے پہلے کمپائل ہوتی ہیں)۔
• Compose: ایک جدید اینڈرائیڈ ایپلیکیشن جس کا انٹرفیس Jetpack Compose سے بنایا جاتا ہے (XML لے آؤٹ سے نہیں)۔ MainActivity یہاں ہے app/src/main/java/<nama-paket>/MainActivity.kt۔ Compose پروجیکٹ GitHub Actions کے ذریعے (پروجیکٹ کا Bangun مینو، پھر Bangun online (آن لائن بنائیں)) یا Gradle کے ساتھ Termux میں بنائے جاتے ہیں، کیونکہ Compose کو Jetpack Compose لائبریریوں کی ضرورت ہوتی ہے جو ڈیوائس پر دستیاب نہیں ہیں۔
• Python: ایپلیکیشن کی منطق app/src/main/python/main.py میں Python (Chaquopy) زبان میں لکھی جاتی ہے اور app/src/main/java/<nama-paket>/MainActivity.java میں موجود میزبان MainActivity.java کے ذریعے چلائی جاتی ہے۔ Python پروجیکٹ براہ راست فون پر بنائے جا سکتے ہیں (Chaquopy رن ٹائم ایپلیکیشن میں شامل ہے) اور GitHub Actions کے ذریعے بھی۔ Python پروجیکٹوں کا کم از کم SDK 24 (Android 7.0) ہے۔

منصوبے کا فن تعمیر تبدیل کریں
موجودہ منصوبے کی فن تعمیر کی ترتیبات کو نیا منصوبہ بنائے بغیر تبدیل کرنے کے لیے: مرکزی مینیو میں «منصوبے کا فن تعمیر تبدیل کریں» دبائیں، پھر منصوبہ منتخب کریں اور «64 بٹ APK بنائیں (arm64-v8a)» یا «32 بٹ APK بنائیں (armeabi-v7a)» چیک باکس تبدیل کریں؛ یا «منصوبوں کا انتظام» میں منصوبے کے نام کو دیر تک دبائیں اور «فن تعمیر تبدیل کریں» منتخب کریں تاکہ اسی منصوبے کے لیے وہی اسکرین براہ راست کھل جائے۔ قاعدہ یہ ہے: اگر دونوں چیک باکس آن ہوں تو بلڈ دو الگ APK بناتا ہے، ایک 64 بٹ اور ایک 32 بٹ؛ اگر صرف ایک چیک باکس آن ہو تو بلڈ ایک واحد عالمگیر APK بناتا ہے جو 64 بٹ اور 32 بٹ دونوں آلات پر چلتا رہتا ہے۔ صرف ایک قسم کے لیے الگ APK ابھی تعاون یافتہ نہیں ہے، کیونکہ بلڈ کا راستہ صرف تقسیم یا عالمگیر انتخاب جانتا ہے، لیکن ہر قسم کا انتخاب منصوبے کے اندر محفوظ رہتا ہے تاکہ اسکرین دوبارہ کھولنے پر ضائع نہ ہو۔

Java، HTML، Situs Web، Kotlin، Compose اور Python پروجیکٹوں کی فائل ترتیب
Java، HTML، Situs Web، Kotlin، Compose اور Python پروجیکٹ عام طور پر اینڈرائیڈ پروجیکٹوں کی طرح ترتیب دیے جاتے ہیں۔ app فولڈر کے اندر src فولڈر ہے، اور اس کے اندر main فولڈر ہے۔ main فولڈر کے اندر java فولڈر کے پاس AndroidManifest.xml ہے، res فولڈر جس میں layout/activity_main.xml اور values/strings.xml اور values/styles.xml ہیں، اور HTML اور Situs Web کے لیے assets فولڈر جس میں index.html ہے (Situs Web میں tentang.html اور kontak.html بھی ہیں)۔ HTML اور Situs Web پروجیکٹوں کی اپنی MainActivity بھی app/src/main/java/<nama-paket>/MainActivity.java میں ہے، جو index.html کو WebView میں لوڈ کرتی ہے اور AndroidManifest میں لانچر بنتی ہے۔ Python پروجیکٹوں میں Python کوڈ app/src/main/python/main.py میں اور میزبان MainActivity.java یہاں app/src/main/java/<nama-paket>/MainActivity.java میں ہے۔ AndroidManifest.xml، layout، strings اور styles کو ایڈیٹر میں کھولا اور بدلا جا سکتا ہے، بالکل MainActivity کی طرح۔ پرانے پروجیکٹ جن کا مینی فیسٹ ابھی بھی app فولڈر کے پاس ہے وہ بھی بنائے جا سکتے ہیں، کیونکہ بناتے وقت ایپلیکیشن پہلے app/src/main/ میں AndroidManifest.xml کو جانچتی ہے، پھر app فولڈر کے پاس والے کو، اور آخر میں پروجیکٹ ڈیٹا فائل کو۔

اجازتوں کے قوانین (اہم)
پروجیکٹ بناتے وقت نشان زد کی گئی اجازتیں صرف ایک جگہ درج ہوتی ہیں، پروجیکٹ کی قسم کے مطابق۔ Java، HTML، Situs Web، Kotlin، Compose اور Python پروجیکٹوں کے لیے نشان زد کی گئی اجازتیں صرف AndroidManifest.xml میں درج ہوتی ہیں جو app/src/main/ میں، java فولڈر کے پاس، پروجیکٹ فولڈر کے اندر ہے۔ Java، HTML، Situs Web، Kotlin، Compose اور Python پروجیکٹوں کی پروجیکٹ ڈیٹا فائل میں اجازتوں کی فہرست نہیں ہوتی۔ اگر آپ Java منتخب کریں اور INTERNET اور CAMERA پر نشان لگائیں، تو AndroidManifest.xml میں صرف INTERNET اور CAMERA درج ہوں گے، کوئی اور اجازت ساتھ نہیں آئے گی۔ بناتے وقت ایپلیکیشن اجازتیں اسی جگہ سے پڑھتی ہے: Java، HTML، Situs Web، Kotlin، Compose اور Python پروجیکٹوں کے لیے app/src/main/ میں AndroidManifest.xml سے (اگر نہ ہو تو پرانے پروجیکٹوں کے لیے app فولڈر کے پاس والے AndroidManifest.xml سے)، اور پرانے پروجیکٹوں کے لیے پروجیکٹ ڈیٹا فائل سے۔

ایڈیٹر استعمال کرنے کا طریقہ
Kelola Project کھولیں، ایڈیٹر کھولنے کے لیے پروجیکٹ کے نام پر چھوئیں۔ ایڈیٹر میں فائلیں کھولی جا سکتی ہیں، کوڈ لکھا جا سکتا ہے اور تبدیلیاں محفوظ کی جا سکتی ہیں۔ Java، HTML، Situs Web، Kotlin، Compose اور Python پروجیکٹوں کے لیے فائلیں app/src/main فولڈر کے اندر ترتیب دی جاتی ہیں۔ پروجیکٹ شریک کرنے کے لیے Ekspor ZIP (ZIP برآمد کریں) استعمال کریں (نیچے والا حصہ دیکھیں)۔

پروجیکٹ چلانے کا طریقہ
ایڈیٹر میں پروجیکٹ کو آزمانے کے لیے Jalankan دبائیں۔ HTML اور Situs Web پروجیکٹوں کے لیے جو چلایا جاتا ہے وہ WebView کے ذریعے index.html ہے۔ اگر کوئی خرابی پیش آئے تو خرابی کا پیغام پڑھیں، کوڈ درست کریں، پھر دوبارہ چلائیں۔

APK بنانے کا طریقہ
ایڈیٹر میں Bangun دبائیں۔ بنانے کے دو طریقے ہیں۔ پہلا، Bangun di perangkat (ڈیوائس پر بنائیں): انٹرنیٹ کے بغیر براہ راست فون پر بناتا ہے، HTML، Situs Web، Java، Kotlin اور Python پروجیکٹوں کے لیے۔ دوسرا، GitHub Actions کے ذریعے Bangun online: GitHub پر انٹرنیٹ کے ذریعے بناتا ہے، اور ہر قسم کے پروجیکٹ کے لیے استعمال کیا جا سکتا ہے۔ Compose پروجیکٹ صرف دوسرے طریقے (Bangun online) سے یا Gradle کے ساتھ Termux میں بنائے جا سکتے ہیں، کیونکہ Compose کو Jetpack Compose لائبریریوں کی ضرورت ہوتی ہے جو ڈیوائس پر دستیاب نہیں ہیں۔ پہلی تعمیر کا نتیجہ ابھی دستخط شدہ نہیں ہوتا۔ اس کے بعد ایپلیکیشن اس پر دستخط کرتی ہے: خودکار طور پر طے شدہ کنجی سے، یا ذاتی دستخط سے اگر پروجیکٹ بناتے وقت "Gunakan tanda tangan pribadi" والا خانہ نشان زد کیا گیا ہو۔

APK انسٹال کرنے کا طریقہ
جب APK تیار ہو جائے تو اسے انسٹال کرنے کے لیے Pasang (انسٹال کریں) دبائیں۔ Android 8 اور اس سے اوپر پر فون پہلے "Izinkan dari sumber ini" (اس ذریعے سے اجازت دیں) مانگے گا، کیونکہ یہ ایپلیکیشن Play Store کے باہر سے APK انسٹال کرتی ہے۔ Pengaturan (ترتیبات) میں اس اجازت کو ایک بار فعال کریں، پھر ایپلیکیشن میں واپس آئیں: انسٹال خودکار طور پر جاری رہے گا، Pasang دوبارہ دبانے کی ضرورت کے بغیر۔ اگر Pasang بٹن نظر نہ آئے تو یقینی بنائیں کہ تعمیر مکمل ہو چکی ہے اور APK بن چکا ہے۔

ایپلیکیشن پر دستخط کرنے کا طریقہ
ہر APK پر دستخط ہونا ضروری ہے تاکہ اسے انسٹال کیا جا سکے۔ دو انتخاب دستیاب ہیں۔ پہلا، طے شدہ کنجی: ایپلیکیشن خود بخود دستخط کر دیتی ہے، آپ کو کچھ کرنے کی ضرورت نہیں۔ دوسرا، ذاتی دستخط: پہلے مرکزی مینو میں Buat Keystore (keystore بنائیں) مینو کے ذریعے ایک keystore بنائیں، اس کا پاس ورڈ اچھی طرح سنبھالیں، پھر پروجیکٹ بناتے وقت "Gunakan tanda tangan pribadi" پر نشان لگائیں۔ Keystore یہاں محفوظ ہوتی ہے Download/project/signing۔

پروجیکٹ کو ZIP میں برآمد کرنا
Ekspor ZIP اس لیے فراہم کیا گیا ہے تاکہ پروجیکٹ دوستوں کے ساتھ شریک کیا جا سکے۔ طریقہ یہ ہے: Kelola Project میں پروجیکٹ کے نام کو دیر تک دبائیں، پھر Ekspor ZIP منتخب کریں۔ نتیجہ Download/project/<NamaProyek>.zip میں محفوظ ہوتا ہے۔ bin فولڈر اس میں شامل نہیں ہوتا، اس لیے اس کا سائز چھوٹا ہوتا ہے، صرف چند درجن KB۔ وہ ZIP فائل کسی دوست کو بھیجی جا سکتی ہے یا GitHub پر اپ لوڈ کی جا سکتی ہے۔

Ekstensi JAWS، Jieshuo (CSR) کے توسیعی انجن کو استعمال کرتی ہے، اس کے اسکرین ریڈر کو نہیں۔ اس طرح یہ خاکہ چلتا رہ سکتا ہے چاہے صارف TalkBack استعمال کرے۔ طریقہ یہ ہے: مرکزی مینو میں Ekstensi JAWS کھولیں۔ چونکہ خودکار کلک خود بخود چلتا ہے، اس لیے خدمت کو پہلے Pengaturan Aksesibilitas (رسائی کی ترتیبات) میں فعال کرنا ضروری ہے۔ اس کے بعد نیا خاکہ بنایا جا سکتا ہے: خاکے کا نام لکھیں، OK دبائیں، پھر اس کے خانے بھریں۔

Daftar Klik صفائی کے لیے الگ رکھا گیا ہے
ایک خاکے کے اندر دو خانے ہوتے ہیں: اسکرپٹ والا خانہ اور Daftar Klik (کلک کی فہرست) والا خانہ۔ بٹنوں کی فہرست daftar_klik.txt فائل میں الگ محفوظ ہوتی ہے، ہر سطر میں ایک نام۔ مواد کی مثال: tombolSimpan، tombolHapus، tombolBuka۔ کسی ایپلیکیشن کو کھولنے کے لیے اس فہرست میں صرف >WhatsApp لکھیں۔ پرانے خاکے جن میں ابھی daftar_klik.txt فائل نہیں ہے وہ یہی طے شدہ مثال دکھائیں گے۔

فراہم کیے گئے سادہ افعال
• klikTombol("tombolSimpan") — اس کے متن کی بنیاد پر ایک بٹن پر کلک کرتا ہے۔
• klikDaftarTombol(daftar) — daftar_klik.txt میں موجود فہرست پر کلک کرتا ہے، ہر سطر میں ایک بٹن، ترتیب سے، پھر بتاتا ہے کہ کتنے کامیاب ہوئے اور کتنے نہیں ملے۔
• bukaAplikasi("WhatsApp") — اس کے نام کی بنیاد پر ایپلیکیشن کھولتا ہے، یا فہرست میں ">WhatsApp" لکھیں۔
• klik(540, 1200) — اسکرین کے نقاط پر کلک کرتا ہے۔
تمام افعال پہلے سادہ بنائے گئے ہیں۔ جب عادت ہو جائے تو بعد میں مزید افعال شامل کیے جا سکتے ہیں۔

اسکرین ریڈر کے بارے میں
یہ ایپلیکیشن اسکرین ریڈر کے لیے دوستانہ بنائی گئی ہے۔ ہر بھرنے والے خانے پر ایک لیبل اور بھرنے کی مثال موجود ہے، اور تمام بٹن پیچیدہ اشاروں کے بغیر پہنچے جا سکتے ہیں۔ Ekstensi JAWS اس طرح بنائی گئی ہے کہ یہ چلتی رہے چاہے صارف TalkBack استعمال کرے، کیونکہ جو استعمال ہوتا ہے وہ اس کا توسیعی انجن ہے، اس کا اسکرین ریڈر نہیں۔

رازداری اور سلامتی
پروجیکٹ اور keystore آپ کے فون میں محفوظ ہوتے ہیں۔ GitHub ٹوکن صرف آن لائن تعمیر کے لیے استعمال ہوتا ہے اور اسی ایپلیکیشن کے اندر محفوظ ہوتا ہے۔ اپنا ٹوکن یا keystore کا پاس ورڈ کسی کے ساتھ شریک نہ کریں۔ اگر آپ ذاتی دستخط استعمال کرتے ہیں تو keystore اور اس کا پاس ورڈ محفوظ جگہ پر رکھیں، کیونکہ اگر وہ گم ہو جائیں تو پرانے APK کو اسی دستخط سے تازہ نہیں کیا جا سکتا۔

ضروریات
Android 5.0 یا اس سے نیا۔ ذخیرے کی اجازت: Android 11 اور اس سے اوپر پر تمام فائلوں تک رسائی کی اجازت استعمال ہوتی ہے، Android 10 اور اس سے نیچے پر عام ذخیرے کی اجازت (ذخیرہ پڑھنا/لکھنا) استعمال ہوتی ہے کیونکہ Android 10 میں تمام فائلوں تک رسائی کی اجازت نہیں ہے۔ ڈیوائس پر بنانے کے لیے ARM پروسیسر (32 یا 64 بٹ) والے فون کی ضرورت ہے۔ GitHub Actions کے ذریعے آن لائن بنانے کے لیے انٹرنیٹ اور GitHub ٹوکن کی ضرورت ہے۔ Kotlin پروجیکٹ ڈیوائس پر بنائے جا سکتے ہیں، لیکن ان کی پہلی تعمیر سست ہوتی ہے اور زیادہ میموری استعمال کرتی ہے کیونکہ Kotlin کمپائلر کا سائز بڑا ہے۔ Compose پروجیکٹ GitHub Actions کے ذریعے یا Gradle کے ساتھ Termux میں بنائے جاتے ہیں۔ Python پروجیکٹوں کو Android 7.0 یا اس سے نئے کی ضرورت ہے (کم از کم SDK 24) اور نتیجے میں بننے والا APK بڑا ہوتا ہے کیونکہ اس میں Python رن ٹائم (Chaquopy) اس کی معیاری لائبریری سمیت شامل ہوتا ہے۔

Terminal
مرکزی اسکرین پر Terminal مینو اس ایپلیکیشن کے اندر ایک ٹرمینل کھولتا ہے۔ ls جیسی کمانڈیں پروجیکٹ فولڈر کے مواد دیکھنے کے لیے، cd فولڈر بدلنے کے لیے اور git کوڈ سنبھالنے کے لیے استعمال کی جا سکتی ہیں۔ کمانڈوں کا نتیجہ ایسے متن کے طور پر ظاہر ہوتا ہے جسے اسکرین ریڈر پڑھ سکتا ہے، اور آخری نتیجہ سننے کے لیے Bacakan hasil (نتیجہ سنائیں) بٹن موجود ہے۔ یہ ٹرمینل فون کے نظام کے شیل کو استعمال کرتا ہے، اس لیے nano اور vim جیسے باہمی پروگرام یہاں ابھی استعمال نہیں کیے جا سکتے۔

Lisensi (ادا شدہ ورژن)
ایپلیکیشن بیچنے کے لیے پروجیکٹ بناتے وقت "Aktifkan Lisensi" (لائسنس فعال کریں) پر نشان لگائیں، پھر اپنا WhatsApp نمبر بھریں۔ بنی ہوئی ایپلیکیشن پہلی بار کھلنے پر لائسنس کوڈ مانگے گی: صارف اپنے ڈیوائس کی ID دیکھتا ہے، Kirim ID Perangkat (ڈیوائس ID بھیجیں) بٹن دبا کر وہ ID آپ کے WhatsApp پر بھیجتا ہے، پھر آپ لائسنس کوڈ کے ساتھ جواب دیتے ہیں۔ لائسنس کوڈ ڈیوائس ID اور پروجیکٹ پاس ورڈ (پروجیکٹ ڈیٹا فائل میں lisensi_seed) سے شمار کیا جاتا ہے — اس پاس ورڈ کو اچھی طرح سنبھالیں اور شریک نہ کریں۔ درست کوڈ داخل ہونے کے بعد ایپلیکیشن کھل جاتی ہے اور دوبارہ کوڈ نہیں مانگتی۔

Pembuat Ikon Otomatis
نئے پروجیکٹوں کا آئیکن ابھی شفاف ہے، اس لیے مرکزی مینو میں Pembuat Ikon (آئیکن بنانے والا) دستیاب ہے۔ طریقہ یہ ہے: Pembuat Ikon دبائیں، ایک یا دو حروف لکھیں (مثال ایپلیکیشن کے نام کے ابتدائی حروف)، پس منظر کا رنگ اور لکھائی کا رنگ منتخب کریں، اس کا پیش منظر دیکھیں، پھر Simpan ke Proyek (پروجیکٹ میں محفوظ کریں) دبائیں تاکہ وہ آئیکن منتخب پروجیکٹ میں استعمال ہو، یا Simpan ke Download (Download میں محفوظ کریں) دبائیں تاکہ اس کی PNG فائل کہیں اور استعمال ہو۔ پروجیکٹ بن جانے کے بعد ایپلیکیشن آئیکن بنانے کی پیشکش بھی کرتی ہے۔ پروجیکٹ کا پرانا آئیکن Kelola Project میں پروجیکٹ مینو سے کسی بھی وقت بدلا جا سکتا ہے (پروجیکٹ کے نام کو دیر تک دبائیں، پھر Ganti Ikon (آئیکن بدلیں) منتخب کریں)۔

Template Proyek Siap Pakai
اگر آپ خالی پروجیکٹ سے آغاز نہیں کرنا چاہتے تو پروجیکٹ بناتے وقت ایک سانچہ منتخب کریں: Kalkulator (Java)، Catatan (Java)، Daftar Tugas (Kotlin)، Kalkulator Web (HTML)، Situs Profil (Situs Web) یا Penghitung (Compose)۔ سانچہ منتخب کرنے سے پروجیکٹ کی قسم خودکار طور پر اس سانچے کے مطابق بدل جاتی ہے، اور پروجیکٹ پہلے سے تیار آغاز کوڈ کے ساتھ بنایا جاتا ہے — بس اسے چلائیں یا بدلیں۔ اگر سانچہ منتخب کرنے کے بعد پروجیکٹ کی قسم دوبارہ ہاتھ سے بدلی جائے تو سانچہ منسوخ ہو جاتا ہے اور پروجیکٹ دوبارہ خالی ہو جاتا ہے۔ HTML اور Situs Web سانچوں کے لیے سانچہ index.html کے مواد کو بدل دیتا ہے، بشمول فارم میں لکھے گئے HTML اسکرپٹ کے۔

Cadangan dan Pulihkan Proyek
تاکہ پروجیکٹ گم نہ ہوں، ایک بیک اپ سہولت دستیاب ہے۔ طریقہ یہ ہے: Kelola Project میں پروجیکٹ کے نام کو دیر تک دبائیں، پھر Cadangkan (بیک اپ کریں) منتخب کریں۔ بیک اپ Download/backup فولڈر میں پروجیکٹ کے نام اور تاریخ کے ساتھ ZIP کے طور پر محفوظ ہوتا ہے، مثال: GarudaDecode-2026-11-14-123045.zip۔ اس کا مواد Ekspor ZIP جیسا ہی ہے (پروجیکٹ کا پورا مواد، bin فولڈر کے بغیر)۔ بحال کرنے کے لیے: Kelola Project میں مینو کھولیں، Pulihkan cadangan (بیک اپ بحال کریں) منتخب کریں، پھر اس کی بیک اپ فائل منتخب کریں۔ اگر پروجیکٹ کا نام پہلے سے موجود ہو تو ایپلیکیشن پوچھے گی: Timpa proyek lama (پرانے پروجیکٹ پر اوپر لکھیں)، یا Nama baru (نئے نام) کے ساتھ محفوظ کریں۔

Bagikan dan Impor Proyek
پروجیکٹ دوست کے ساتھ شریک کرنے کے لیے: Kelola Project میں پروجیکٹ کے نام کو دیر تک دبائیں، پھر Bagikan (شریک کریں) منتخب کریں۔ پروجیکٹ شریک کرنے والی ایپوں (WhatsApp، Telegram اور دیگر) کے ذریعے ZIP کے طور پر بھیجا جاتا ہے۔ دوست سے پروجیکٹ وصول کرنے کے لیے: Kelola Project میں مینو کھولیں، Impor proyek (پروجیکٹ درآمد کریں) منتخب کریں، پھر اس کی ZIP فائل منتخب کریں۔ اس ZIP فائل میں پروجیکٹ ڈیٹا فائل ہونا ضروری ہے — اگر نہ ہو تو فائل واضح پیغام کے ساتھ رد کر دی جاتی ہے، کیونکہ وہ فائل Create Aplikasi پروجیکٹ نہیں ہے۔ اگر پروجیکٹ کا نام پہلے سے موجود ہو تو ایپلیکیشن پوچھے گی: Timpa proyek lama، یا Nama baru کے ساتھ محفوظ کریں۔

Pencarian dan Filter Proyek
اگر پروجیکٹ بہت ہو گئے ہوں تو Kelola Project میں ایک تلاش کا خانہ اور قسم کا چھانٹنے والا موجود ہے۔ تلاش کے خانے میں پروجیکٹ کا نام لکھیں، فہرست فوراً چھن جاتی ہے (بڑے اور چھوٹے حروف میں فرق نہیں کیا جاتا)۔ قسم کا چھانٹنے والا فہرست کو صرف ایک قسم تک محدود کرتا ہے: Semua (تمام)، HTML، Situs Web، Java، Kotlin، Compose یا Python۔ ہر پروجیکٹ کا مینو چھنی ہوئی فہرست سے بھی معمول کے مطابق کھولا جا سکتا ہے۔

آواز سے ایپ بنائیں
اگر آپ ٹائپ نہیں کرنا چاہتے تو آواز استعمال کریں: مرکزی مینیو میں آواز کے ساتھ بنائیں پر ٹیپ کریں، پھر کوئی حکم بولیں۔ بولے جا سکنے والے حکم: "Buat proyek kalkulator"، "Bangun proyek Kalkulator"، "Buka proyek Kalkulator"، "Jalankan proyek Kalkulator"، "Daftar proyek"، "Buka ikon"، "Kembali" اور "Bantuan"۔ ایپ آواز اور متن سے جواب دیتی ہے، اس لیے اسکرین دیکھے بغیر بھی استعمال ہو سکتی ہے۔ آواز کی شناخت فون کی اندرونی تقریر شناخت ایپ استعمال کرتی ہے (مفت؛ اگر انڈونیشیائی زبان پیک نصب ہو تو آف لائن بھی چل سکتی ہے)۔ اگر فون میں آواز کی شناخت نہیں ہے تو حکم اسی اسکرین کے متن خانے میں لکھے جا سکتے ہیں۔

AI ایپ بلڈر
AI ایپ بلڈر اسکرین پر مطلوبہ ایپ لکھیں یا بول کر بتائیں، مثال کے طور پر: «محفوظ کریں بٹن والی نوٹس ایپ»۔ ایپ فون کے اندر ہی کلیدی الفاظ کا تجزیہ کرتی ہے (انٹرنیٹ کے بغیر، بغیر قیمت کے)، پھر سب سے موزوں ٹیمپلیٹ سے حقیقی پروجیکٹ بناتی ہے: کیلکولیٹر، نوٹس، کاموں کی فہرست، ویب کیلکولیٹر، پروفائل سائٹ یا کاؤنٹر۔ اگر آپ کی تفصیل کا ابھی کوئی موزوں ٹیمپلیٹ نہیں ہے، تو ایپ خالی پروجیکٹ بناتی ہے اور ایمانداری سے بتاتی ہے — سمجھنے کا ڈھونگ نہیں رچاتی۔ AI سے بنایا گیا پروجیکٹ پروجیکٹس کا انتظام کریں میں براہ راست کھولا جا سکتا ہے۔

دوست کے فون پر لائیو پیش نظارہ
پروجیکٹ بنانے سے پہلے دوست کو دکھانے کے لیے: پروجیکٹس کا انتظام کریں میں پروجیکٹ کا نام دیر تک دبائیں، پھر دوست کے فون پر پیش نظارہ منتخب کریں۔ ایپ پروجیکٹ کی اہم فائلوں (index.html یا MainActivity یا main.py) کے ساتھ BACA-SAYA.txt ہدایات اور info.txt پر مشتمل چھوٹا پیش نظارہ پیکج بناتی ہے۔ پیکج ZIP کے طور پر WhatsApp یا Telegram کے ذریعے بھیجا جاتا ہے۔ جو دوست اسے وصول کرتا ہے وہ پیش نظارہ فوراً کھول سکتا ہے: HTML صفحات براؤزر میں کھلتے ہیں، Java/Kotlin/Python کوڈ متن کے طور پر پڑھا جاتا ہے۔

پروجیکٹ مارکیٹ میں بلٹ ان نمونہ پروجیکٹس ہیں جنہیں ایک ٹیپ سے پروجیکٹ فولڈر میں انسٹال کیا جا سکتا ہے: کیلکولیٹر، نوٹس، کاموں کی فہرست، ویب کیلکولیٹر، پروفائل سائٹ، کاؤنٹر، ڈیجیٹل گھڑی اور ویب کوئز۔ آن لائن مارکیٹ (انٹرنیٹ سے نمونے ڈاؤن لوڈ کرنا) ابھی دستیاب نہیں ہے، اس لیے اس مارکیٹ میں وہ نمونے ہیں جو پہلے سے ایپ کے اندر موجود ہیں۔ انسٹال شدہ پروجیکٹ کو پروجیکٹس کا انتظام کریں میں کھولا اور بدلا جا سکتا ہے جیسے خود بنایا ہوا پروجیکٹ۔

براہ راست تعاون
دوست کے ساتھ مل کر پروجیکٹ پر کام کرنے کے لیے: مین مینیو میں تعاون کھولیں، پروجیکٹ منتخب کریں، تبدیلی کا نوٹ لکھیں (کیا بدلا گیا)، پھر تعاون کے لیے شیئر کریں دبائیں۔ پروجیکٹ ZIP کے طور پر اس کے اندر CATATAN.txt فائل کے ساتھ بھیجا جاتا ہے۔ آپ کا دوست اس پر کام کرتا ہے اور ZIP واپس بھیجتا ہے؛ آپ جواب وصول کریں دبائیں، پہلے تبدیلی کا نوٹ پڑھیں، پھر لاگو کریں منتخب کریں تاکہ پرانا پروجیکٹ اوور رائٹ ہو جائے، یا منسوخ کریں اگر آپ کا ارادہ بدل جائے۔ CATATAN.txt کے بغیر ZIP تعاون کا پیکج نہیں ہے — عام پروجیکٹ ZIP کے لیے پروجیکٹس کا انتظام کریں میں پروجیکٹ امپورٹ کریں استعمال کریں۔

خودکار ایپ مترجم
ایپ میں متن کو دوسری زبان میں ترجمہ کرنے کے لیے: مین مینیو میں ایپ مترجم کھولیں، پروجیکٹ اور ہدف زبان (انگریزی، عربی یا جاوانی) منتخب کریں، پھر ترجمہ کریں دبائیں۔ لغت پہلے سے فون کے اندر موجود ہے (انٹرنیٹ کے بغیر، بغیر قیمت کے) اور اس میں روزمرہ کے عام الفاظ ہیں؛ strings.xml، لے آؤٹ اور کوڈ سے متن پڑھا جاتا ہے پھر ترجمہ کیا جاتا ہے۔ نتیجہ values-زبان/strings.xml فولڈر میں لکھا جاتا ہے (اگر پروجیکٹ میں strings.xml ہے) اور ترجمہ-زبان.txt رپورٹ پروجیکٹ فولڈر میں۔ جو الفاظ ابھی لغت میں نہیں ہیں وہ جوں کے توں چھوڑ دیے جاتے ہیں اور رپورٹ کیے جاتے ہیں — تاکہ آپ جان سکیں کہ کون سے الفاظ آپ کو خود ترجمہ کرنے ہیں۔

بغیر کوڈ کے گیم بنانے والا
کوڈ لکھے بغیر گیم بنانے کے لیے: مین مینیو میں گیم میکر کھولیں، گیم کی قسم منتخب کریں (نمبر اندازہ لگائیں، کوئز یا ستارہ پکڑیں)، گیم کا نام، مقدار (لیول/سوالات/ستارے) اور جیت کا پیغام بھریں، پھر گیم بنائیں دبائیں۔ گیم حقیقی پروجیکٹ کے طور پر بنائی جاتی ہے جسے پروجیکٹس کا انتظام کریں میں براہ راست چلایا جا سکتا ہے اور کسی بھی دوسرے پروجیکٹ کی طرح APK میں بنایا جا سکتا ہے۔

خودکار ایپ ٹیسٹ
پروجیکٹ بنانے سے پہلے جانچنے کے لیے: پروجیکٹس کا انتظام کریں میں پروجیکٹ کا نام دیر تک دبائیں پھر خودکار ٹیسٹ منتخب کریں۔ IDE بغیر APK بنائے 10 چیزیں جانچتا ہے — لازمی فائلیں موجود ہیں (پروجیکٹ ڈیٹا فائل، مینی فیسٹ، اہم فائل، لے آؤٹ، اسٹرنگز)، پیکیج کا نام اور ورژن، استعمال شدہ اجازتیں، آئیکن اور کوڈ بریکٹس کا توازن۔ نتیجہ ہر آئٹم کے لیے دکھایا جاتا ہے (پاس/فیل پیغام کے ساتھ) اور Jieshuo اسے بلند آواز سے پڑھتا ہے۔ پہلے وہ سب کچھ ٹھیک کریں جو فیل ہوا، پھر پروجیکٹ بنائیں دبائیں۔

AI Pemeriksa Kode
پروجیکٹ کوڈ کو ان پیٹرنز کے لیے جانچنے کے لیے جو اکثر مسائل پیدا کرتے ہیں: مین مینیو میں کوڈ چیک کریں کھولیں، پروجیکٹ منتخب کریں، پھر کوڈ چیک کریں دبائیں۔ چیکر فون کے اندر چلتا ہے (انٹرنیٹ کے بغیر) اور غیر استعمال شدہ متغیرات، خالی فنکشنز، واضح طور پر نہ ختم ہونے والے لوپس، کوڈ میں براہ راست لکھا ہوا متن (strings.xml میں بہتر ہے)، خطرناک اجازتیں اور APIs، TODO/FIXME مارکرز اور متحرک عمل درآمد تلاش کرتا ہے۔ ہر دریافت میں فائل کا نام، لائن نمبر اور اصلاح کی تجویز ہوتی ہے۔ یہ چیکر پیٹرن پر مبنی ہے، حقیقی AI نہیں ہے — جو مسائل پیٹرن پر عمل نہیں کرتے وہ پھر بھی بچ سکتے ہیں۔

انٹرایکٹو لرننگ موڈ
قدم بہ قدم ایپس بنانا سیکھنے کے لیے: مین مینیو میں سیکھیں کھولیں۔ 5 اسباق ہیں: اپنا پہلا پروجیکٹ بنانا، بٹن شامل کرنا، رنگ بدلنا، آواز شامل کرنا اور APK بنانا۔ کسی سبق کو ٹیپ کریں تاکہ اس کی وضاحت اور عملی کام پڑھ سکیں، کام کریں، پھر کام جانچیں دبائیں — IDE واقعی جانچتا ہے کہ آیا کام ہو گیا ہے (آپ کے فون پر پروجیکٹ اور APK اسکین کر کے)۔ پاس ہونے والے اسباق مکمل کے طور پر نشان زد اور محفوظ کیے جاتے ہیں۔

کلاؤڈ مطابقت پذیری

خودکار بیک اینڈ بلڈر

خودکار تھیم ڈیزائنر

اینیمیشن میکر

ایکشن ریکارڈر
کام خود بخود دہرانے کے لیے: IDE کی گئی کارروائیاں ریکارڈ کرتا ہے (پروجیکٹ کھولنا، چلانا، بنانا، برآمد کرنا، بیک اپ بنانا، پروجیکٹ بنانا، فائل محفوظ کرنا)۔ مین مینیو میں ایکشن ریکارڈر کھولیں تاکہ ریکارڈ شدہ کارروائیوں کی فہرست ان کے منصوبے کے ساتھ دیکھ سکیں، پھر دوبارہ چلائیں دبائیں — IDE ان کارروائیوں کو دوبارہ چلاتا ہے جنہیں خودکار بنایا جا سکتا ہے (بیک اپ بنانا اور پروجیکٹ بنانا موقع پر چلتے ہیں؛ چلانا، بنانا اور برآمد کرنا اپنی اہم اسکرین کھولتے ہیں؛ کھولنا اور محفوظ کرنا ایڈیٹر کھولتے ہیں)۔ جن کارروائیوں کو خودکار نہیں بنایا جا سکتا انہیں چھوڑ دیا جاتا ہے اور آخر میں رپورٹ کیا جاتا ہے۔

تصویر سے گیلری ایپ بنانے کے لیے: مین مینیو میں تصویر سے ایپ کھولیں، گیلری سے تصویر منتخب کریں۔ IDE تصویر کا سائز اور غالب رنگ تجزیہ کرتا ہے، پھر حقیقی گیلری ایپ پروجیکٹ بناتا ہے: تصویر پروجیکٹ کے assets میں کاپی کی جاتی ہے، تھیم رنگ تصویر کے غالب رنگ سے لیا جاتا ہے، اور ایپ کا نام تصویر فائل کے نام سے لیا جاتا ہے۔ پروجیکٹس کا انتظام کریں کھولیں تاکہ اس گیلری ایپ کو چلا سکیں یا بنا سکیں۔

ٹرمینل میں انٹرایکٹو پروگرام استعمال کرنے کے لیے: مین مینیو میں ٹرمینل کھولیں، پھر nano یا vim یا top یا htop چلائیں۔ ٹرمینل اب VT پارسر استعمال کرتا ہے (24 قطار x 80 کالم گرڈ اسکرین) تاکہ وہ پروگرام درست دکھائی دیں — کرسر حرکت کرتا ہے، لائنیں مٹ جاتی ہیں، اور اسکرین حقیقی ٹرمینل کی طرح بدلتی ہے۔ انٹرایکٹو پروگرام کنٹرول کرنے کے لیے خصوصی Tab، اوپر تیر، نیچے تیر اور Esc بٹن ہیں۔ آؤٹ پٹ اب بھی متن ہے جسے Jieshuo پڑھ سکتا ہے؛ آخری لائن سننے کے لیے اسکرین پڑھ کر سنائیں دبائیں۔

Terminal Exec (ایپ بائنری)
ٹرمینل سے ایپ فولڈر میں بائنری چلانے کے لیے (مثال کے طور پر aapt2 یا ECJ یا D8): کمانڈ معمول کی طرح ٹائپ کریں۔ IDE libkautsarexec.so استعمال کرتا ہے تاکہ ایپ فولڈر میں بائنریز Android 10 اور اس سے اوپر چل سکیں۔ Exec ٹیسٹ دبائیں تاکہ جانچ سکیں کہ آیا بائنری exec راستہ اس فون پر کام کرتا ہے — نتیجہ جوں کا توں دکھایا جاتا ہے۔ اگر exec سسٹم سے بلاک ہو جائے تو سسٹم کمانڈز اور شیل اسکرپٹس پھر بھی چلتے ہیں؛ بائنری کو پروجیکٹ بنائیں مینیو سے چلائیں۔

Terminal Tetap Hidup (KeepAlive)
دوسری اسکرین پر جاتے ہوئے shell کو چلتا رکھنے کے لیے: ٹرمینل کھولیں، کمانڈ چلائیں، پھر واپس دبائیں یا دوسری اسکرین پر جائیں — shell مرتا نہیں ہے، اور ٹرمینل نوٹیفکیشن دکھائی دیتی رہتی ہے تاکہ آپ ایک ٹیپ سے واپس آ سکیں۔ چلائی گئی کمانڈز تاریخ میں محفوظ ہوتی ہیں (تاریخ بٹن، یا کمانڈ فیلڈ میں اوپر/نیچے تیر) اور اکثر استعمال ہونے والی کمانڈز کو پسندیدہ کے طور پر محفوظ کیا جا سکتا ہے (پسندیدہ بٹن)۔ کام ختم ہونے پر shell بند کریں دبائیں، تاکہ shell واقعی ختم ہو جائے۔ پروجیکٹ مینیو اور ایڈیٹر مینیو میں ٹرمینل میں بنائیں بٹن بھی ہے: ٹرمینل پروجیکٹ فولڈر میں پہلے سے بھری ہوئی بلڈ کمانڈ کے ساتھ کھلتا ہے۔

Pasang Alat Terminal (آزمائش)
ایک خصوصیت جو ابھی آزمائش میں ہے: ٹرمینل میں Pasang Alat Terminal بٹن ہے تاکہ ڈویلپر کے alat-termux ریپوزٹری (github.com/syudat/alat-termux) میں آئینے سے Termux ماحول انسٹال کیا جا سکے، Termux انسٹال کریں بٹن کے علاوہ ایک اور راستے کے طور پر جو Termux کی سرکاری ریلیز سے لیتا ہے۔ آئینے کا مواد سرکاری ریلیز جیسا ہی ہے اور انسٹالیشن کے دوران SHA-256 سے جانچا جاتا ہے۔ ماحول انسٹال ہونے کے بعد pkg update اور pkg install کمانڈز استعمال کی جا سکتی ہیں، اور ریپوزٹری سے اضافی اوزار بھی ٹرمینل میں انسٹال ہوتے ہیں: ماحول کی معلومات دیکھنے کے لیے info-terminal، کیش صاف کرنے کے لیے bersih-terminal، اور پروجیکٹ فولڈر کو ایک تاریخ والی tar.gz فائل میں آرکائیو کرنے کے لیے cadangkan-proyek۔ اس کے بعد ایپ خود بخود بنیادی Linux پیکجز (git، python، curl، wget، nano، openssh، zip، unzip) اور دستخط کے ساتھ APK بلڈ اوزار (openjdk-21، kotlin، gradle، ecj، aapt2، d8، apksigner، clang، cmake، ninja، make) Termux کی سرکاری ریپوزٹری سے انسٹال کرتی ہے، تاکہ ٹرمینل فوراً ایپس بنانے کے لیے تیار ہو۔ بڑے پیکجز ڈاؤن لوڈ کرنے (سینکڑوں MB) میں کافی وقت لگ سکتا ہے۔ انسٹالیشن چلتے ہوئے پیشرفت اور کمانڈ آؤٹ پٹ ٹرمینل کی اہم اسکرین پر ظاہر ہوتے ہیں، اور حتمی نتیجہ اسکرین ریڈر بلند آواز سے پڑھتا ہے۔ اگر پیکج انسٹالیشن ابھی مکمل نہیں ہوئی ہے، تو جاری رکھنے کے لیے Pasang Alat Terminal دوبارہ دبائیں۔

مکمل آواز موڈ
IDE کو مکمل طور پر آواز سے کنٹرول کرنے کے لیے: مین مینیو میں وائس موڈ کھولیں، پھر سننا شروع کریں دبائیں۔ IDE مسلسل سنتا ہے — ہر کمانڈ کے لیے بٹن دبانے کی ضرورت نہیں ہے — کمانڈ چلاتا ہے اور آواز سے جواب دیتا ہے۔ 26 کمانڈز ہیں: بنائیں، تعمیر کریں، کھولیں، چلائیں، فہرست بنائیں، تلاش کریں، حذف کریں، ٹیسٹ کریں، جانچیں، برآمد کریں، بیک اپ بنائیں، شیئر کریں، آئیکن بنائیں، ترجمہ کریں، ٹرمینل میں بنائیں، اسکرین پڑھیں، تمام اسکرینیں کھولیں (بشمول سیکیورٹی، آف لائن AI، ویجیٹ، سوشل میڈیا، گیم، سیکھنا، کلاؤڈ، بیک اینڈ، تھیم، اینیمیشن، ریکارڈر)، واپس، بند کریں اور مدد۔ اگر موڈ فعال چھوڑ دیا جائے تو اس اسکرین کو دوبارہ کھولنے پر سننا خود بخود جاری رہتا ہے۔ اس موڈ کو بند کرنے کے لیے سننا بند کریں دبائیں۔ اگر فون میں آواز پہچاننے کی خدمت نہیں ہے تو کمانڈز پھر بھی ٹیکسٹ باکس میں لکھی جا سکتی ہیں۔

کوڈ مترجم
انٹرنیٹ کے بغیر زبانوں کے درمیان کوڈ ترجمہ کرنے کے لیے: مین مینیو میں کوڈ مترجم کھولیں، پروجیکٹ منتخب کریں، سورس فائل (.java/.kt) منتخب کریں، پھر سمت منتخب کریں: Java سے Kotlin۔ ترجمہ کریں دبائیں — نتیجہ ان لائنوں کی رپورٹ کے ساتھ دکھایا جاتا ہے جن کا ترجمہ نہیں ہو سکتا (وہ لائنیں جوں کی توں رکھی جاتی ہیں اور نشان زد کی جاتی ہیں)۔ نتیجہ محفوظ کریں دبائیں تاکہ اسی فولڈر میں نئی فائل (نام-ترجمہ.java/.kt) لکھی جائے؛ اصل فائل کبھی اوور رائٹ نہیں ہوتی۔ یہ پیٹرن اصول مترجم ہے، کمپائلر نہیں ہے — استعمال سے پہلے ہمیشہ نتیجہ جانچیں۔

ایپ میں Git
Termux کے بغیر IDE میں Git استعمال کرنے کے لیے: مین مینیو میں ایپ میں Git کھولیں، پروجیکٹ منتخب کریں، پھر Git Repo بنائیں دبائیں تاکہ اس پروجیکٹ میں مقامی ریپو (.git) بنایا جا سکے۔ حالت جانچیں دبائیں تاکہ آخری commit کے مقابلے میں نئی، بدلی ہوئی یا حذف شدہ فائلیں دیکھ سکیں؛ commit پیغام بھریں پھر Commit دبائیں تاکہ پروجیکٹ کا اسنیپ شاٹ محفوظ ہو؛ Commit Log دیکھیں دبائیں تاکہ commit تاریخ دیکھ سکیں۔ GitHub پر Push اور GitHub سے Pull GitHub ٹوکن کے ذریعے اسنیپ شاٹس استعمال کرتے ہیں (pembuat-aplikasi-build ریپو) — git پروٹوکول نہیں۔ Clone، Push (سسٹم git) اور Pull (سسٹم git) صرف اس وقت چلتے ہیں جب git بائنری فون پر انسٹال ہو (عام طور پر نہیں ہوتا)۔ یہ مکمل git نہیں ہے: کوئی merge، branch یا diff نہیں ہے — ہر commit پروجیکٹ کا مکمل ZIP اسنیپ شاٹ محفوظ کرتا ہے۔

اشتہار ساز
بنی ہوئی ایپ میں اشتہارات شامل کرنے کے لیے: مین مینیو میں اشتہار ساز کھولیں، پروجیکٹ، فراہم کنندہ (AdMob یا Unity Ads یا AppLovin) اور اشتہار کی قسم (بینر، انٹرسٹیشل یا انعامی) منتخب کریں۔ اشتہار یونٹ ID بھریں اگر آپ کے پاس پہلے سے ہے — خالی کا مطلب ہے ٹیسٹ ID استعمال کرنا (AdMob Google کی سرکاری ٹیسٹ ID استعمال کرتا ہے؛ Unity نمونہ Game ID استعمال کرتا ہے؛ AppLovin خالی جگہ استعمال کرتا ہے)۔ اشتہار کوڈ بنائیں دبائیں تاکہ Java اور Kotlin کوڈ اور رہنما دیکھ سکیں؛ پروجیکٹ میں محفوظ کریں دبائیں تاکہ سب کچھ پروجیکٹ میں اشتہارات-<فراہم کنندہ>-<قسم>.txt فائل میں لکھا جائے۔ یہ کوڈ ٹیمپلیٹ + رہنما ہے، اشتہار SDK نہیں ہے — SDK IDE میں شامل نہیں ہے؛ حقیقی اشتہارات صرف اس وقت ظاہر ہوتے ہیں جب آپ فراہم کنندہ اکاؤنٹ بنائیں، اشتہار یونٹ بنائیں، اپنا یونٹ ID چسپاں کریں اور پروجیکٹ کی build.gradle میں SDK انحصار شامل کریں۔

بچوں کا موڈ
بچے کے ساتھ IDE استعمال کرنے کے لیے: مین مینیو میں بچوں کا موڈ کھولیں۔ اسکرین بڑے بٹنوں کے ساتھ آسان بنائی گئی ہے اور صرف 4 محفوظ کارروائیاں ہیں: پروجیکٹ بنائیں (محفوظ ٹیمپلیٹس سے: کیلکولیٹر، نمبر اندازہ لگائیں، کوئز، ستارہ پکڑیں)، پروجیکٹ کھولیں، چلائیں اور سیکھیں۔ اس اسکرین پر حذف، برآمد، بیک اپ یا ٹوکن ترتیبات کا کوئی بٹن نہیں ہے۔ پہلی بار داخل ہوتے وقت 4 ہندسوں والا PIN بنائیں — وہ PIN والد بچوں کا موڈ چھوڑنے کے لیے استعمال کرتا ہے (بچوں کا موڈ چھوڑیں بٹن یا واپس بٹن)۔ یہ PIN چھوٹے بچوں کے لیے ہلکی حفاظت ہے، حقیقی سیکیورٹی نہیں ہے۔

Wear OS & TV ایپ بنانے والا
گھڑی ایپ (Wear OS) یا TV ایپ (Android TV) بنانے کے لیے: مین مینیو میں Wear OS & TV کھولیں، ہدف منتخب کریں (Wear OS یا Android TV یا دونوں)۔ پروجیکٹ کا نام بھریں پھر نیا Wear/TV پروجیکٹ بنائیں دبائیں — IDE Java پروجیکٹ بناتا ہے پھر اسے ایڈجسٹ کرتا ہے — یا پہلے سے موجود پروجیکٹ منتخب کریں پھر اس پروجیکٹ پر لاگو کریں دبائیں۔ ایڈجسٹمنٹس: مینی فیسٹ میں uses-feature، TV کے لیے LEANBACK_LAUNCHER زمرہ + بینر، اور ایڈجسٹ شدہ activity_main.xml لے آؤٹ (Wear: چھوٹی اسکرین؛ TV: D-pad کے لیے موزوں بڑی اسکرین)۔ مکمل وضاحت پروجیکٹ میں wear-tv.txt میں لکھی جاتی ہے۔ یہ پروجیکٹ ٹیمپلیٹ ہے — بلڈ + ٹیسٹ کے لیے اب بھی Wear OS یا Android TV ڈیوائس/ایمولیٹر کی ضرورت ہے؛ TV بینر (banner.png 320x180) خود بخود نہیں بنایا جاتا، اسے خود شامل کرنا ہوگا (مثال کے طور پر آئیکن میکر کے ذریعے)۔

پروجیکٹ کا نقشہ
پروجیکٹ کی ساخت دیکھنے کے لیے: مین مینیو میں پروجیکٹ کا نقشہ کھولیں، پروجیکٹ منتخب کریں، پھر نقشہ دکھائیں دبائیں — IDE فولڈرز اور فائلوں کی فہرست ان کے سائز، کل سائز، فائل کی قسم کے مطابق سائز اور اہم فائلیں (اہم فائل، مینی فیسٹ، لے آؤٹ، اسٹرنگز، آئیکن، ویب صفحہ) دکھاتا ہے۔ نقشہ-پروجیکٹ.txt محفوظ کریں دبائیں تاکہ وہی نقشہ پروجیکٹ کی جڑ میں لکھا جائے۔ bin/ فولڈر (بلڈ نتائج) اور .git/ فولڈر (مقامی ریپو) نقشے میں شامل نہیں ہیں کیونکہ ان کا مواد دوبارہ بنایا جا سکتا ہے۔

APK سائز کیلکولیٹر
بنانے سے پہلے بنی ہوئی APK کے سائز کا اندازہ لگانے کے لیے: مین مینیو میں APK سائز کیلکولیٹر کھولیں، پروجیکٹ منتخب کریں، پھر تخمینہ لگائیں دبائیں۔ IDE زمرے کے مطابق تفصیل دکھاتا ہے (کوڈ/DEX، وسائل، اثاثے، مقامی لائبریریاں، مینی فیسٹ + resources.arsc، اوور ہیڈ)، کل تخمینہ، 5 سب سے بڑی فائلیں اور چھوٹا کرنے کی تجاویز (مثال کے طور پر بڑی تصاویر ریزولوشن میں چھوٹی کی جاتی ہیں، بڑی آوازیں مدت میں کاٹی جاتی ہیں)۔ یہ تخمینہ ہے، درست سائز نہیں ہے — حقیقی سائز aapt2 کمپریشن، غیر استعمال شدہ کوڈ ہٹانے (R8) اور بنی ہوئی وسائل کی وجہ سے مختلف ہو سکتا ہے۔

APK تجزیہ کار
تیار APK کا مواد پڑھنے کے لیے (جیسے Android Studio میں APK تجزیہ کار): مین مینیو میں APK تجزیہ کار کھولیں، پروجیکٹ منتخب کریں، پھر تعمیر کے نتیجے کی APK کا تجزیہ دبائیں۔ IDE اس پروجیکٹ کے bin فولڈر میں جدید ترین APK پڑھتا ہے اور پیکیج کا نام، ورژن، کم سے کم اور ہدف SDK، استعمال شدہ اجازتوں کی فہرست، dex فائلوں کی تعداد، حصے کے مطابق سائز کی تفصیل (پروگرام کوڈ، وسائل، اثاثے، مقامی لائبریریاں، دستخط) اور 10 سب سے بڑی اندراجات رپورٹ کرتا ہے۔ یہ جاننے کے لیے مفید ہے کہ کون سا حصہ APK کو بڑا بناتا ہے اور بنی ہوئی ایپ کون سی اجازتیں استعمال کرتی ہے۔

اسکرین سائز کا پیش منظر
ایک ساتھ کئی اسکرین سائز پر پروجیکٹ کی شکل جانچنے کے لیے (جیسے Android Studio میں): مین مینیو میں اسکرین سائز کا پیش منظر کھولیں، پروجیکٹ منتخب کریں، پھر اسکرین سائز جانچیں دبائیں۔ IDE پروجیکٹ کے تمام لے آؤٹس پڑھتا ہے اور ان عناصر کی رپورٹ کرتا ہے جن کی چوڑائی مقررہ لکھی گئی ہے (مثال کے طور پر 400dp) اور 320 یا 360 یا 411 یا 480 dp اسکرین چوڑائی سے زیادہ ہے، کیونکہ چھوٹی اسکرین والے فون پر ایسا عنصر ڈھک سکتا ہے یا باہر نکل سکتا ہے۔ match_parent یا wrap_content چوڑائی والے عناصر اسکرین کے مطابق خود بخود ایڈجسٹ ہو جاتے ہیں اور انہیں جانچنے کی ضرورت نہیں ہے۔

وسائل مینیجر
ایک جگہ پروجیکٹ کے تمام وسائل دیکھنے اور ان کا انتظام کرنے کے لیے (جیسے Android Studio میں وسائل مینیجر): مین مینیو میں وسائل مینیجر کھولیں، پروجیکٹ منتخب کریں، پھر وسائل دیکھیں دبائیں۔ IDE زمرے کے مطابق فائلوں کی تعداد اور سائز (drawable، layout، values، mipmap اور دیگر)، strings.xml، colors.xml اور styles.xml کا مواد رپورٹ کرتا ہے۔ اسی اسکرین سے نام اور قدر بھر کر strings.xml میں نئی اسٹرنگ اور colors.xml میں نیا رنگ شامل کیا جا سکتا ہے — نام جانچا جاتا ہے اور نقل مسترد کیے جاتے ہیں، تاکہ XML فائل خراب نہ ہو۔

ہلکا پرفارمنس مانیٹر
چل رہی ایپ کے RAM اور پروسیسر استعمال کی نگرانی کے لیے (جیسے Android Studio میں Profiler، ہلکا ورژن): مین مینیو میں ہلکا پرفارمنس مانیٹر کھولیں، پہلے وہ ایپ چلائیں جسے جانچنا ہے (مثال کے طور پر بنی ہوئی ایپ جو آزمائی جا رہی ہے)، اس کا پیکیج نام بھریں — یا پروجیکٹ منتخب کریں پھر پروجیکٹ سے پیکیج نام درج کریں دبائیں — پھر نگرانی شروع کریں دبائیں۔ ہر 2 سیکنڈ میں IDE اس ایپ کی RAM (PSS) اور CPU فون کی خالی RAM کے ساتھ ریکارڈ کرتا ہے؛ اوسط اور عروج کا خلاصہ دیکھنے کے لیے رکیں دبائیں۔ کوئی اضافی اجازت نہیں۔ Android کے نئے ورژن میں دوسری ایپ کے پروسیسر تک پڑھنے کی رسائی سسٹم سے محدود ہے، اس لیے اگر CPU پڑھا نہیں جا سکتا تو رپورٹ جوں کا توں بتاتی ہے اور RAM کی نگرانی جاری رہتی ہے۔

رسائی آڈٹ
ریلیز سے پہلے یہ جانچنے کے لیے کہ آیا کسی پروجیکٹ کی ترتیب اسکرین ریڈر (TalkBack/Jieshuo) کے موافق ہے: مرکزی مینیو میں رسائی آڈٹ کھولیں، پروجیکٹ چنیں، پھر لے آؤٹ فہرست لوڈ کریں پر ٹیپ کریں اور لے آؤٹ فائل چنیں۔ IDE اس XML فائل کو پڑھتا ہے اور بغیر لیبل والے بٹنوں کی ان کی سطر تعداد سمیت، بار بار استعمال ہونے والے لیبلوں کی، اور ایک دوسرے کو ڈھانپنے والے عناصر کی رپورٹ دیتا ہے، پھر فوکس ترتیب کی نقل بناتا ہے جیسے Jieshuo بلند آواز سے پڑھتا ہے۔ اگر کسی بٹن کا لیبل نہیں ہے تو اس کا لیبل بھریں پھر لیبل خودکار داخل کریں پر ٹیپ کریں — لیبل contentDescription کے طور پر لے آؤٹ فائل میں لکھا جاتا ہے۔ یہ جانچ صرف لے آؤٹ XML پڑھتی ہے؛ Compose مناظر اور تیار APK ابھی اسکین نہیں کیے جاتے۔

کریش پوسٹ مارٹم
یہ جاننے کے لیے کہ ایپ خود کیوں بند ہوتی ہے، منفرد ID والے کریش لاگ سے: مرکزی مینیو میں «کریش پوسٹ مارٹم» کھولیں، لاگ فہرست سے کریش ID منتخب کریں، پھر «جانچیں» دبائیں۔ IDE لاگ میں کلاس اور سطر نمبر کو منصوبے کے ماخذ سے ملاتا ہے اور وجہ انڈونیشیائی میں سمجھاتا ہے (مثال کے طور پر خالی حوالہ، اجازت ابھی نہیں مانگی گئی، یا JSON غلطی)، کوڈ پیچ تجویز کے ساتھ۔ «پیچ لگائیں» صرف تب دبائیں جب ماخذ سطر ابھی بالکل وہی ہو جیسی کریش کے وقت تھی؛ اگر تبدیل ہو گئی ہے تو پیچ مسترد کیا جاتا ہے اور IDE آپ سے خود جانچنے کو کہتا ہے۔ بنی ہوئی ایپ کے کریشوں کے لیے «منصوبے میں کریش کیچر داخل کریں» دبائیں، پھر APK ہمیشہ کی طرح بنائیں: وہ بنی ہوئی ایپ اپنے کریش خود پکڑتی ہے اور اپنا لاگ فون پر لکھتی ہے، اور وہ لاگ «بنی ہوئی ایپ کریش لاگ تلاش کریں» بٹن سے مل سکتا ہے۔ ایماندار حد: لاگ کو Android 11 اور اوپر پر عوامی Download فولڈر میں نقل کرنا تمام فائلوں تک رسائی اجازت کے بغیر ناکام ہو سکتا ہے۔

بین النظریاتی ٹرانسپائلر
سادہ Java کوڈ کو Kotlin میں، یا سادہ XML ترتیب کو Compose کوڈ میں بدلنے کے لیے: مرکزی مینیو میں بین النظریاتی ٹرانسپائلر کھولیں، پروجیکٹ اور فائل چنیں، پھر پیش نظارہ پر ٹیپ کریں۔ IDE تبدیلی کا نتیجہ متن کے طور پر دکھاتا ہے — پہلے اسے جانچ لیں، کیونکہ جن سطروں کو وہ نہیں پہچانتا وہ جیسی ہیں ویسی ہی رہتی ہیں اور Java کا static لفظ Kotlin میں ہٹا دیا جاتا ہے (استعمال سے پہلے اس کا مطلب جانچ لیں)۔ XML سے Compose تبدیلی صرف متن، اشارے اور سمت بدلتی ہے — جسامت، رنگ اور دیگر صفات ابھی شامل نہیں ہیں۔ اگر نتیجہ درست ہے تو ہدف فائل لکھنے کے لیے فائل پر لگائیں پر ٹیپ کریں؛ ماخذ فائل نہیں بدلی جاتی۔ صرف محفوظ، عام نمونے بدلے جاتے ہیں۔

مقامی مائیکرو سرور
انٹرنیٹ کے بغیر سرور کی ضرورت والی ایپ جانچنے کے لیے: مرکزی مینیو میں «مقامی مائیکرو سرور» کھولیں، راستہ تعریفیں لکھیں (مثال کے طور پر GET /halo پھر اس کا JSON جواب)، پھر «سرور شروع کریں» دبائیں۔ IDE اسی فون پر چھوٹا HTTP سرور چلاتا ہے (صرف HTTP، TLS کے بغیر، اسی Wi-Fi نیٹ ورک کے لیے) اور ہر درخواست اور جواب اسکرین پر ریکارڈ کرتا ہے۔ راستے {nama} جیسے پیرامیٹر اور سادہ API کلید استعمال کر سکتے ہیں۔ سرور کو بنی ہوئی APK میں بھی پیک کیا جا سکتا ہے: «سرور منصوبے میں پیک کریں» دبائیں، اور سرور ماخذ، اثاثے اور مینیفیسٹ منصوبے میں داخل کیے جاتے ہیں، اس لیے بنی ہوئی ایپ خود چلتے وقت سرور بن جاتی ہے۔ IDE میں سرور اس کی اسکرین بند ہونے پر رک جاتا ہے۔

سیکیورٹی آڈیٹر
اشاعت سے پہلے منصوبے کے کوڈ میں سیکیورٹی خلا جانچنے کے لیے: مرکزی مینیو میں «سیکیورٹی آڈیٹر» کھولیں، منصوبہ منتخب کریں، پھر «اسکین شروع کریں» دبائیں۔ IDE منصوبے کا کوڈ، مینیفیسٹ اور ترتیب اسکین کرتا ہے اور نتائج بلند سے کم خطرہ رپورٹ کرتا ہے — API کلید جو کوڈ میں کھلی چھوڑی گئی، جزو جو اجازت کے بغیر ظاہر کیا گیا، WebView جو JavaScript کو اس کے JavaScript انٹرفیس کے ساتھ فعال کرتا ہے، کمزور خفیہ کاری (MD5، SHA1، DES)، http پتہ بغیر TLS، اور پاس ورڈ جو براہ راست کوڈ میں لکھا گیا — ان کی فائلوں اور سطر نمبروں کے ساتھ۔ نتائج کے لیے جن کی اصلاح محفوظ ہے (مثال کے طور پر MD5 کو SHA-256 یا http کو https میں تبدیل کریں)، «اصلاح لگائیں» دبائیں؛ API کلیدوں اور پاس ورڈوں کے لیے IDE صرف اصلاح تجویز دکھاتا ہے کیونکہ متبادل خود ڈویلپر کو طے کرنا ہے۔ اسکین اب بنی ہوئی APK کے اندر حقیقی DEX بائٹ کوڈ بھی تجزیہ کرتا ہے (صرف کوڈ میں متنی نمونے نہیں)، اس لیے خطرناک بلائی گئی APIs اور DEX میں سرایت شدہ راز بھی پکڑے جاتے ہیں؛ خلا جو کسی نمونے کی پیروی نہیں کرتے ابھی اسکین سے بچ سکتے ہیں — لاگو کرنے سے پہلے جانچیں۔

انٹرفیس ٹیسٹ روبوٹ
متن منظرناموں کے ذریعے ایپ اسکرین خودکار جانچنے کے لیے: مرکزی مینیو میں «انٹرفیس ٹیسٹ روبوٹ» کھولیں، منصوبہ منتخب کریں، پھر «خودکار سیناریو بنائیں» دبائیں۔ IDE منصوبے کا مینیفیسٹ اور ترتیب پڑھتا ہے اور منظرنامہ متنی مراحل کے طور پر لکھتا ہے (بٹن دبائیں، فیلڈ بھریں، انتظار کریں، واپس جائیں)۔ «ڈرائی رن چلائیں» دبائیں تاکہ منظرنامہ چلنے کا لاگ اس کے وقت نشانوں کے ساتھ دیکھیں — یہ ڈرائی رن ابھی صرف ترتیب نقالی ہے۔ حقیقی جانچ کے لیے «منصوبے میں جانچ ایجنٹ داخل کریں» دبائیں: IDE جانچ ایجنٹ منظرنامہ اثاثوں کے ساتھ منصوبے میں داخل کرتا ہے؛ APK ہمیشہ کی طرح بنائیں، انسٹال کریں، پھر «جانچ» آئیکن کھولیں — وہ ایجنٹ بنی ہوئی ایپ کے اندر چلتا ہے اور واقعی بٹن دباتا ہے، حقیقی فیلڈ بھرتا ہے، اور اسکرول کرتا ہے، پھر اپنی رپورٹ اسکرین پر دکھاتا ہے ان حقیقی کریشوں کے ساتھ جو اس نے پکڑے۔ «منصوبے سے جانچ ایجنٹ ہٹائیں» دبائیں تاکہ اس ایجنٹ کو دوبارہ ہٹائیں۔ ایجنٹ ایپ کے اپنے عمل کے اندر چلتا ہے، اس لیے اسے رسائی خدمت یا نظام خودکاری کی ضرورت نہیں ہے۔

کوڈ وقت سفر
Git حکم ٹائپ کیے بغیر پروجیکٹ کو پہلی کوڈ حالت میں لوٹانے کے لیے: مرکزی مینیو میں کوڈ وقت سفر کھولیں، پروجیکٹ چنیں، وقتی نقطہ لیبل بھریں (خالی بھی ہو سکتا ہے)، پھر وقتی نقطہ ریکارڈ کریں پر ٹیپ کریں۔ IDE پروجیکٹ ماخذ فائلوں کی نقل ان کے hash سمیت پروجیکٹ کے اندر .riwayat پوشے میں محفوظ کرتا ہے۔ وقتی نقطہ فہرست ان سب کو دکھاتی ہے؛ دو نقطے چنیں پھر جوڑی، بدلی یا ہٹائی گئی فائلوں اور افعال کو دیکھنے کے لیے موازنہ کریں پر ٹیپ کریں۔ پرانی حالت واپس لانے کے لیے بحال کریں پر ٹیپ کریں — بحال کرنے سے پہلے IDE ہمیشہ پہلے موجودہ حالت کا بیک اپ بناتا ہے، اس لیے کچھ ضائع نہیں ہوتا۔ اصل پروجیکٹ کو پریشان کیے بغیر تبدیلیاں آزمانے کے لیے پروجیکٹ کو نئے پوشے میں نقل کرنے کے لیے تجرباتی نقل بنائیں پر ٹیپ کریں۔ صرف ماخذ فائلیں ریکارڈ کی جاتی ہیں۔

ماڈیول فیکٹری
پروجیکٹ کے کسی حصے کو ایسے ماڈیول کے طور پر پیک کرنے کے لیے جسے دوسرا پروجیکٹ استعمال کر سکے: مرکزی مینیو میں ماڈیول فیکٹری کھولیں، ماخذ پروجیکٹ چنیں، پیک کی جانے والی اسکرین، کلاس، سٹرنگ اور اجازت فائلوں پر نشان لگائیں، پھر ماڈیول کے طور پر پیک کریں پر ٹیپ کریں۔ IDE JSON میٹا ڈیٹا (ماڈیول نام، نسخہ، استعمال شدہ سٹرنگیں اور اجازتیں) کے ساتھ ZIP محفوظ نامہ لکھتا ہے۔ کسی ماڈیول کو دوسرے پروجیکٹ میں نصب کرنے کے لیے ماڈیول فیکٹری کھولیں، ہدف پروجیکٹ چنیں، پھر ماڈیول نصب کریں پر ٹیپ کریں اور ماڈیول کی .zip فائل چنیں — ملاپ موجودہ کوڈ پر لکھے بغیر سٹرنگیں اور اجازتیں جوڑتا ہے، اور اگر فائل کا نام ہدف پروجیکٹ میں پہلے سے استعمال ہو رہا ہے تو اسے ملاتا نہیں۔ ماڈیول لائبریریاں یا تعمیر ترتیبات ساتھ نہیں لاتا۔

اشاعت سے پہلے شناخت کنندہ نام بے ترتیب کرنے اور منصوبے کے اثاثے خفیہ کرنے کے لیے: مرکزی مینیو میں «کثیر شکل ڈھال اور اثاثہ تجوری» کھولیں، منصوبہ منتخب کریں، پھر «نام بے ترتیب کریں اور اثاثے خفیہ کریں» دبائیں۔ IDE ماخذ کوڈ میں کلاس اور طریقہ نام اسکین کرتا ہے، بے ترتیب نام نقشہ بناتا ہے، ان ناموں کو مرتب شدہ DEX فائلوں کے اندر دوبارہ لکھتا ہے (متبادل نام اصل ناموں جتنے لمبے بنائے جاتے ہیں تاکہ تمام آفسیٹ درست رہیں، پھر DEX ہیڈر چیک سم اور SHA-1 دستخط دوبارہ گنے جاتے ہیں)، منصوبے کے اثاثہ فائلوں کو AES-GCM سے منصوبے کے اندر brankas-aset فولڈر میں خفیہ کرتا ہے، اور خفیہ شدہ بحالی نقشہ (perisai-peta.brankas) محفوظ کرتا ہے تاکہ کریش لاگ پڑھتے وقت اصل نام بحال کیے جا سکیں۔ خفیہ کاری کلید اب ڈویلپر پاس ورڈ سے PBKDF2، 20,000 تکرار کے ساتھ اخذ کی جاتی ہے، اب منصوبے کے نام سے نہیں۔ نام جو سادہ متن، تشریح نام اور ڈی بگ نام کے طور پر بھی استعمال ہوتے ہیں جان بوجھ کر دوبارہ نہیں لکھے جاتے، اور بلڈ راستے میں DEX دوبارہ لکھنے کے داخلے کے مقامات ابھی حقیقی فون پر جانچ کے منتظر ہیں۔

اعتماد زنجیر اور ماحول محافظ
اشاعت سے پہلے دستخط کلید زنجیر اور فون ماحول جانچنے کے لیے: مرکزی مینیو میں «اعتماد زنجیر اور ماحول محافظ» کھولیں، منصوبہ منتخب کریں، پھر «زنجیر اور ماحول جانچیں» دبائیں۔ IDE منصوبے کے پیکج نام سے 5 نسلوں کی کلید زنجیر بناتا ہے اور اس کی سالمیت جانچتا ہے، میموری میں کوڈ حصوں کے مواد کا ڈسک پر فائلوں سے موازنہ کر کے حقیقی میموری سالمیت جانچتا ہے اور گمنام قابل عمل (RWX) نقشہ جات، اجنبی لائبریریاں اور memfd نقشہ جات رپورٹ کرتا ہے، پھر اپنے عمل کی میموری نقشہ اور آلہ خصوصیات کو Frida یا Xposed یا ایمولیٹر کے نشانات کے لیے اسکین کرتا ہے۔ تجوری کلید AndroidKeyStore میں AES کلید سے لپیٹی جاتی ہے جو دستیاب ہونے پر ہارڈ ویئر سیکیورٹی چپ استعمال کرتی ہے، اور کلید گردش اب حقیقی ہے، اسکیم v3 دستخط سرٹیفکیٹ نسب کا استعمال کرتے ہوئے: پرانی کلید نئی کلید کی گردش کا ثبوت دستخط کرتی ہے اور APK اسی نسب سے دوبارہ دستخط کیا جاتا ہے۔ نتیجہ خطرہ سطح محفوظ، احتیاط یا خطرناک ہے، متنی ثبوت کے ساتھ۔ اگر نظام میموری پڑھنے سے انکار کرے تو جانچ «تصدیق نہیں ہو سکتی» رپورٹ کی جاتی ہے، محفوظ نہیں؛ اور آیا کلید واقعی ہارڈ ویئر سیکیورٹی چپ استعمال کرتی ہے صرف حقیقی آلے پر تصدیق ہو سکتی ہے۔

متنی درخت ترتیب معمار
اسکرین دیکھے بغیر ڈیزائن کرنے کے لیے: مرکزی مینیو میں «متنی درخت ترتیب معمار» کھولیں، منصوبہ اور ترتیب فائل منتخب کریں، پھر «ترتیب جانچیں» دبائیں۔ IDE XML ترتیب کو متنی درخت کے طور پر پڑھتا ہے اور ہر عنصر کی پوزیشن روایت بلند آواز میں پڑھتا ہے (مثال کے طور پر نیچے دائیں، اسکرین چوڑائی کا 45 فیصد)، پھر عناصر کے درمیان تصادم اور عناصر جو 360 dp چوڑائی پر اسکرین سے باہر جاتے ہیں ریاضیاتی طور پر رپورٹ کرتا ہے۔ جو اب گنا جاتا ہے اس میں LinearLayout اور سادہ dp سائز، مکمل ConstraintLayout (تمام رکاوٹیں، جھکاؤ، زنجیریں، رہنما، رکاوٹیں، فیصد چوڑائیاں، 0dp match_constraint اور تناسب ابعاد) اور Compose اسکرینیں (Column اور Row اور Box ان کے سائز Modifier کے ساتھ) شامل ہیں۔ صرف MotionLayout اور ConstraintSet جو چلتے وقت تبدیل ہوتے ہیں ابھی پوزیشن نامعلوم رپورٹ کیے جاتے ہیں، کیونکہ ان کی قدریں صرف ایپ چلتے وقت موجود ہوتی ہیں۔

ڈیزائن سسٹم اسٹوڈیو
تمام اسکرینوں اور منصوبوں میں فاصلہ، حرف اور کونے یکساں کرنے کے لیے: مرکزی مینیو میں «ڈیزائن سسٹم اسٹوڈیو» کھولیں، منصوبہ منتخب کریں، ڈیزائن ٹوکن لکھیں (مثال کے طور پر jarak=8, huruf=16, sudut=12)، جزو منتخب کریں، پھر «اجزا بنائیں» دبائیں۔ IDE ٹوکن کی توثیق کرتا ہے — بنیادی فاصلہ 4 سے 16 dp، بنیادی حرف 12 سے 20 sp، کونے 0 سے 32 dp، اور کم سے کم لمس رقبہ 48 dp — پھر تیار XML اجزا (komponen-studio.xml) XML تھیم (tema-studio.xml) اور Compose تھیم (tema-studio.kt) کے ساتھ منصوبے کے فولڈر میں لکھتا ہے۔ ٹوکن کو منصوبوں کے درمیان مشترکہ ٹوکن لائبریری میں نام یافتہ سیٹ کے طور پر بھی محفوظ کیا جا سکتا ہے، اور ایک ہم آہنگی حکم لائبریری کے تازہ ترین ٹوکن تمام منصوبوں پر لاگو کرتا ہے جو اس سیٹ کو استعمال کرتے ہیں۔ اجزا متن کے طور پر بنائے جاتے ہیں جو ترتیب میں چسپاں کیے جاتے ہیں پھر «متنی درخت ترتیب معمار» سے جانچے جاتے ہیں؛ ٹیبلٹ پر دو کالم ایڈجسٹمنٹ اسکرین چوڑائی کوالیفائر استعمال کرتی ہے، چلتے وقت آلہ شناخت نہیں۔

معنوی ری فیکٹرنگ اور AST نیویگیشن
تعریفیں تلاش کرنے اور علامتیں نام تبدیل کرنے کے لیے بغیر دوسرے کوڈ کو توڑے جو اتفاقاً وہی نام رکھتا ہے: مرکزی مینیو میں «معنوی ری فیکٹرنگ اور AST نیویگیشن» کھولیں، منصوبہ منتخب کریں، پھر «پروجیکٹ علامتیں اسکین کریں» دبائیں تاکہ تمام کلاسیں اور طریقے ان کی فائلوں اور سطر نمبروں کے ساتھ دیکھیں۔ علامت کا نام لکھیں، پھر دوبارہ «پروجیکٹ علامتیں اسکین کریں» دبائیں تاکہ اس کی تعریف اور تمام فائلیں جو اسے بلاتی ہیں دیکھیں۔ نام تبدیل کرنے کے لیے نیا نام لکھیں، «نام تبدیل کا پیش نظارہ» دبائیں تاکہ ہر فائل میں وقوعات کی تعداد دیکھیں، پھر «نام تبدیل لاگو کریں» دبائیں۔ انڈیکسر اب ہاتھ سے بنایا گیا AST پارسر استعمال کرتا ہے (Java اور Kotlin سب سیٹ کے لیے لیکسر اور بازگشتی پارسر)، اس لیے فائلوں کے درمیان طریقہ نام تبدیلیاں حل ہو جاتی ہیں اور دوسری فائلوں میں بلانے والے بھی تبدیل ہو جاتے ہیں؛ کوڈ بلاک کو نئے فنکشن میں نکالنے کا بٹن اب اس اسکرین پر ہے۔ یہ پارسر ابھی کم سے کم ہے: بہت پیچیدہ جنرکس، پیرامیٹر والی تشریحات اور گمنام کلاسیں جیسی ہیں ویسی اسکین کی جاتی ہیں، جبکہ عکاسی اور انٹرفیس کے ذریعے بلانے حل نہیں ہوتے۔

مرحلہ بہ مرحلہ ڈی بگر اور میموری معائنہ کار
پروگرام بہاؤ کے درمیان متغیر مواد جانچنے کے لیے لاگ سے اندازہ لگائے بغیر: مرکزی مینیو میں «مرحلہ بہ مرحلہ ڈی بگر اور میموری معائنہ کار» کھولیں، منصوبہ منتخب کریں، عمل نشان لکھیں (ہر سطر پر ایک قدم، شکل سطر نمبر، کوڈ، پھر متغیر اور قدریں | سے جدا، مثال کے طور پر 10|int total = harga * jumlah;|harga=5000, jumlah=3, total=15000)، رکنے کے نقطہ کا سطر نمبر لکھیں، پھر «ڈی بگ نشان چلائیں» دبائیں۔ IDE پہلے رکنے کے نقطہ تک چلتا ہے اور Jieshuo کے ذریعے فعال سطر اس کے متغیر قدروں کے ساتھ بلند آواز میں پڑھتا ہے۔ «ایک سطر آگے بڑھیں» دبائیں تاکہ ایک سطر آگے بڑھیں، «فنکشن میں داخل ہوں» دبائیں تاکہ بلائی گئی فنکشن میں داخل ہوں (کال اسٹیک کے ساتھ)، یا «پروگرام جاری رکھیں» دبائیں تاکہ اگلے رکنے کے نقطہ تک چلیں۔ یہ نشان ڈی بگر ابھی ریکارڈ شدہ یا ہاتھ سے لکھا نشان پیروی کرتا ہے؛ اس کے ساتھ خالص Java JDWP تار پروٹوکول کلائنٹ ہے جو ہینڈ شیک کر سکتا ہے، رکنے کے نقطے لگا سکتا ہے، اندر اور اوپر اور باہر قدم رکھ سکتا ہے، اور VM کو TCP یا سننے کے موڈ سے روک اور جاری رکھ سکتا ہے۔ عام ایپ کے اندر سے حقیقی عمل روکنا ابھی مکمل طور پر ممکن نہیں ہے، کیونکہ عمل کا JDWP ساکٹ صرف adbd کے ذریعے ظاہر ہوتا ہے — ثابت شدہ راستے کو وائرلیس ڈی بگنگ اور ہدف کو شیل سے چلانے کی ضرورت ہوتی ہے، خود ایپ کی صلاحیت سے باہر۔

آف لائن انحصار منتظم
انٹرنیٹ کے بغیر تیسرے فریق لائبریریاں استعمال کرنے اور بلڈ سے پہلے ورژن تصادم سے بچنے کے لیے: مرکزی مینیو میں «آف لائن انحصار منتظم» کھولیں، منصوبہ منتخب کریں، پھر «انحصار جانچیں» دبائیں۔ IDE منصوبے کی تمام .gradle فائلیں پڑھتا ہے، Download/brankas-bersama فولڈر میں منصوبوں کے درمیان مشترکہ تجوری جانچتا ہے، اور تصادم حل کرتا ہے — اگر دو لائبریریاں ایک ہی آرٹیفیکٹ کے مختلف ورژن مانگیں تو سب سے بڑا ورژن استعمال ہوتا ہے اور تصادم رپورٹ کیا جاتا ہے۔ لائبریری ڈاؤن لوڈ کرنے کے لیے اس کے کوآرڈینیٹ لکھیں (شکل گروپ:آرٹیفیکٹ:ورژن، مثال کے طور پر com.google.code.gson:gson:2.10.1) پھر «انحصار جانچیں» دبائیں: آن لائن ہونے پر AAR یا JAR یا WHL فائلیں واقعی Maven یا Google یا PyPI سے ڈاؤن لوڈ ہوتی ہیں ان کے عبوری انحصار گراف کے ساتھ (بازگشتی، چکر ٹوٹے، گہرائی 25 سطح تک)، اور صرف کامیابی سے ڈاؤن لوڈ شدہ فائلیں دستیاب کے طور پر درج کی جاتی ہیں۔ آف لائن ہونے پر صرف لائبریریاں استعمال ہو سکتی ہیں جو پہلے سے مشترکہ تجوری میں ہیں۔ Maven ورژن حدود حل نہیں ہوتیں، اور ڈاؤن لوڈ شدہ فائلیں صرف ان کے SHA-1 سے جانچی جاتی ہیں، PGP تصدیق کے بغیر۔

ڈیٹا بیس اور ذخیرہ معائنہ کار
منصوبے کے ڈیٹا بیس مواد جانچنے اور آزمانے کے لیے بغیر کوڈ لکھے جو جدول مواد چھاپے: مرکزی مینیو میں «ڈیٹا بیس اور ذخیرہ معائنہ کار» کھولیں، منصوبہ اور ڈیٹا بیس فائل (.db یا .sqlite یا .sqlite3) منتخب کریں، پھر «ڈیٹا بیس کھولیں» دبائیں۔ IDE اس کے تمام جدولوں کا اسکیما مکمل SQLite صفحہ پارسر (B-درخت اوور فلو صفحات کے ساتھ) سے پڑھتا ہے اور پہلی 20 قطاریں متنی جدول کے طور پر دکھاتا ہے جو Jieshuo بلند آواز میں پڑھتا ہے۔ SELECT سوال لکھیں پھر «سوال چلائیں» دبائیں (مثال کے طور پر SELECT nama FROM pengguna WHERE kota = 'Makassar') — سوالات اب JOIN اور GROUP BY اور ORDER BY اور LIKE کی حمایت کرتے ہیں، اور فون پر اصلی Android SQLite انجن سے چلتے ہیں۔ قدر تبدیل کرنے کے لیے قطار نمبر (1 = پہلی قطار) اور کالم نام اور نئی قدر لکھیں، پھر «سیل کی قدر تبدیل کریں» دبائیں — وہ قدر .db فائل میں واپس لکھی جاتی ہے۔ «بیک اپ محفوظ کریں» دبائیں تاکہ جدول کی موجودہ حالت <ڈیٹا بیس نام>.cadangan.txt فائل کے طور پر منصوبے میں محفوظ ہو۔ SharedPreferences اور DataStore بھی پڑھے جا سکتے ہیں۔ جو ابھی نہیں پڑھا جا سکتا: خفیہ شدہ ڈیٹا بیس، غیر کمٹ شدہ WAL تبدیلیاں، اور خاص DataStore Proto میں ٹائپ شدہ قدریں (صرف عام فیلڈ منظر کے طور پر دکھائی جاتی ہیں)۔

ایڈیٹر کے اندر آواز سے کوڈ لکھنے کے لیے: ایڈیٹر میں پروجیکٹ کھولیں، پھر کوڈ ساخت ڈکٹیشن بٹن پر ٹیپ کریں۔ انڈونیشیائی میں حکم بولیں، مثلاً buat fungsi tambah dengan parameter a angka dan b angka، buat kelas Mobil، یا buat variabel teks nama sama dengan Budi — IDE بول کو نحوی طور پر درست Java، Kotlin، Python یا Compose کوڈ بلاک میں بدلتا ہے اور اسے کرسر جگہ پر ڈالتا ہے، پھر Jieshuo کے ذریعے مختصر خلاصہ بلند آواز سے پڑھتا ہے۔ ڈکٹیشن نظام کی اندرونی آواز داخلہ خدمت استعمال کرتی ہے، بغیر اضافی مائیکروفون اجازت کے، اور صرف پہلے سے درج حکم نمونے پہچانتی ہے؛ ان نمونوں سے باہر کی بول کوڈ میں نہیں بدلی جاتی۔ لفظوں میں بولے گئے عدد (مثلاً 'lima') ابھی ہندسوں میں نہیں بدلے جاتے۔

انٹرنیٹ کے بغیر ایک ہی کمرے میں ساتھ کام کرنے کے لیے: مرکزی مینیو میں تعاون کھولیں، پھر مقامی تعاون جگہ حصہ کھولیں۔ ایک فون سیشن کھولتا ہے (IDE مقامی IP پتہ اور 6 ہندسوں والا PIN دکھاتا ہے)، دوسرا فون اس پتے اور PIN سے شامل ہوتا ہے۔ متن تبدیلیاں سطر فرق کے طور پر بھیجی جاتی ہیں، بنایا گیا APK جانچ کنندہ کے فون پر بھیجا جا سکتا ہے، اور جانچ کنندہ کے فون سے کریش رپورٹیں واپس ملتی ہیں۔ ایک سیشن صرف ایک دوست کے لیے ہے؛ اگر دو لوگ بالکل وہی سطر ایک ہی وقت میں بدلیں تو آخری تبدیلی استعمال ہوتی ہے۔ PIN مقامی نیٹ ورک پر سادہ متن کے طور پر بھیجا جاتا ہے۔ یہ جگہ ابھی حقیقی فون پر جانچی نہیں گئی۔

AI کی ترتیبات
ایپ بنانے کے لیے AI فراہم کنندہ اور API کلیدیں ترتیب دینے کے لیے: مرکزی مینیو میں ترتیبات گروپ میں «AI کی ترتیبات» دبائیں («کنیکٹر» بٹن کے ساتھ)۔ دستیاب فہرست سے استعمال کرنے والا فراہم کنندہ منتخب کریں، اور «فراہم کنندہ کی خرابی پر ماڈل بدلیں» چیک کریں تاکہ اگر ایک ماڈل ناکام ہو تو IDE خودکار طور پر اسی فراہم کنندہ کا اگلا ماڈل آزمائے۔ «API کلیدوں کا انتظام» دبائیں تاکہ بیک اپ کلیدیں شامل کریں (نام اور کلید لکھیں، پھر «محفوظ کریں» دبائیں؛ کلیدیں چھپی دکھائی جاتی ہیں، صرف آخری 4 حروف نظر آتے ہیں)۔ کلیدیں فون پر محفوظ ہوتی ہیں اور ایپ بناتے وقت منتخب فراہم کنندہ کے سوا کہیں نہیں بھیجی جاتیں۔ منتخب فراہم کنندہ اب واقعی «پروجیکٹ بلیو پرنٹ معمار» اور «کوڈ منطق بہاؤ راوی» استعمال کرتے ہیں؛ «AI سے ایپ بنانے والا» اسکرین پر ایپ بنانا ابھی فون پر مقامی AI استعمال کرتا ہے (انٹرنیٹ کے بغیر)۔

کنیکٹر
APK کا تجزیہ کرنے اور پھر اسے بھیجنے کے لیے: مرکزی مینیو میں، ترتیبات گروہ میں، کنیکٹر پر ٹیپ کریں (AI کی ترتیبات بٹن کے پاس)۔ فون سے APK فائل چنیں، IDE اس کا مواد پڑھتا ہے (پیکیج نام، نسخہ، سرگرمیوں کی فہرست)، پھر نظام اشتراک مینیو (مثلاً WhatsApp یا Drive) سے بھیجنے کے لیے APK بھیجیں پر ٹیپ کریں۔

زبان اور آواز
ایپ کی زبان بدلنے کے لیے: ترتیبات کھولیں، پھر ایپ کی زبان، پھر کوئی زبان یا سسٹم کی پیروی کریں چنیں۔ مرکزی اسکرین اور زیادہ تر اسکرینیں ایپ بند یا دوبارہ شروع کیے بغیر فوراً چنی گئی زبان میں بدل جاتی ہیں؛ کچھ اسکرینیں (مثلاً ٹرمینل، تعاون، AI کی ترتیبات اور کلید انتظام) دوبارہ کھلنے تک پرانی زبان ہی استعمال کرتی ہیں۔ اگر آپ سسٹم کی پیروی کریں چنیں تو زبان فون کی نظام زبان کی پیروی کرتی ہے۔

فی پروجیکٹ ڈیفالٹ دستخط اور Anti Tamper
ورژن 5.7 سے، وہ پروجیکٹ جو ذاتی دستخط استعمال نہیں کرتا اس کی اپنی بلٹ ان کلید سے دستخط کیا جاتا ہے (پروجیکٹ کے اندر tanda-tangan-bawaan فولڈر میں ایک بار بنائی گئی، پھر آگے استعمال کی گئی)، اس لیے بلٹ ان دستخط پروجیکٹ سے پروجیکٹ تک مختلف ہوتا ہے — اب تمام ایپس کے لیے ایک مشترکہ کلید نہیں ہے۔ tanda-tangan-bawaan فولڈر حذف نہ کریں: اس کلید کے بغیر نیا APK اسی پروجیکٹ کے پرانے APK کو اوور رائٹ نہیں کر سکتا۔ ہر پروجیکٹ کی ترتیبات (الگ آرکیٹیکچر، ذاتی دستخط، اینٹی ٹیمپر، منتخب keystore، SDK) اب پروجیکٹ کے اندر settings.gradle فائل میں محفوظ ہوتی ہیں اور ہر بار پروجیکٹ بننے پر دوبارہ پڑھی جاتی ہیں۔ ترتیبات میں، دستخط زمرے میں، بنی ہوئی ایپ اینٹی ٹیمپر چیک باکس ہے: اگر فعال ہو تو ڈیوائس پر بنی ہوئی ایپ ہر بار کھلنے پر اپنے دستخط اور dex مواد جانچتی ہے؛ اگر اسے دوبارہ دستخط کیا گیا یا کسی اور نے بدلا تو ایپ چلنے سے انکار کر دیتی ہے۔ Frida/Xposed جیسے ڈیبگر اور انجیکشن اوزار بھی پکڑے جاتے ہیں، اور ایپ ونڈو اسکرین ریکارڈنگ سے لاک ہے۔

ڈیمو ویڈیو میکر
بنی ہوئی ایپ کی ڈیمو ویڈیو بنانے کے لیے: مین مینیو میں ڈیمو ویڈیو میکر کھولیں، پروجیکٹ منتخب کریں، ویڈیو عنوان بھریں، پھر ڈیمو ویڈیو اسکرپٹ بنائیں دبائیں — IDE 5 معیاری مناظر (افتتاح، اہم منظر، خصوصیت 1، خصوصیت 2، اختتام) کے ساتھ video-demo.txt لکھتا ہے جس میں بیانیہ متن اور ہر منظر کی مدت ہوتی ہے۔ HTML سلائیڈ شو بنائیں دبائیں تاکہ پروجیکٹ کی تصاویر (آئیکن + اسکرین شاٹس اگر ہیں) سے video-demo.html بنایا جائے جو ہر 5 سیکنڈ میں خود بخود بدلتی ہیں۔ یہ .mp4 ویڈیو نہیں ہے — حقیقی ویڈیو کے لیے فون براؤزر میں video-demo.html کھولیں پھر اسکرین ریکارڈ کریں، یا چل رہی ایپ ریکارڈ کرتے ہوئے video-demo.txt میں بیانیہ پڑھیں۔

Android Studio جیسا نیا ڈیزائن
IDE کی شکل اب Android Studio جیسی صاف ستھری کر دی گئی ہے (صرف شکل — تمام بٹن، مینیوز اور بہاؤ بالکل پہلے جیسے ہی رہتے ہیں): ہلکی سرمئی پس منظر، موٹے سیاہ اسکرین عنوانات، سفید متن والے نیلے بٹن اور پتلی سرحد والے سفید ان پٹ باکسز۔ مین مینیو بصری طور پر گروپ کیا گیا ہے (بنانے کی خصوصیات، کلاؤڈ، تھیم اور دیگر، آواز، کوڈ اور نئی خصوصیات، اوزار) بٹنوں کی ترتیب بدلے بغیر۔ ٹرمینل اب بھی Android Studio میں ٹرمینل ونڈو جیسا تاریک پینل استعمال کرتا ہے، اور کوڈ ایڈیٹر اب بھی سفید پس منظر اور سیاہ متن رکھتا ہے۔ تمام متن Jieshuo کے ذریعے اب بھی واضح طور پر پڑھا جاتا ہے۔

ترتیبات
ایپ سیٹ کرنے کے لیے: اہم اسکرین پر آپشنز مینیو کھولیں پھر ترتیبات دبائیں۔ اس کے اندر 12 زمرے ہیں: GitHub ترتیبات (سیکیورٹی، ذاتی دستخط، بلڈ تاریخ اور GitHub ٹوکن)، ڈیوائس پر APK بلڈ ترتیبات (keystore پاس ورڈ اور بلڈ تاریخ ڈیوائس پر محفوظ کریں)، تھیم (ایپ رنگ)، دستخط (ذاتی دستخط کے لیے keystore بنائیں اور بنی ہوئی ایپ اینٹی ٹیمپر چیک باکس)، پروجیکٹ فولڈر (پروجیکٹ فولڈر کا مقام)، زبان اور آواز (انٹرفیس زبان اور وائس موڈ بولنے کی رفتار)، متن سائز اور شکل (ایڈیٹر فونٹ سائز)، بلڈ (پروجیکٹ بنائیں اسکرین کے لیے ڈیفالٹ ہدف SDK اور ڈیفالٹ آرکیٹیکچر تقسیم)، نوٹیفکیشنز (بلڈ ختم ہونے پر آواز)، خودکار بیک اپ (پروجیکٹ بیک اپ شیڈول)، ڈویلپر پروفائل (نام، WhatsApp نمبر اور اکاؤنٹ جو عطیہ اسکرین پر دکھائے جاتے ہیں) اور پرائیویسی اور ڈیٹا (ترتیبات ری سیٹ کریں اور ایپ ڈیٹا حذف کریں)۔ ہر زمرے میں پچھلی اسکرین پر واپس جائیں بٹن ہے تاکہ زمرہ مینیو پر واپس جا سکیں۔ جو ترتیبات ابھی محفوظ کی گئی ہیں (ابھی لاگو نہیں ہوئیں) ان کی وضاحت ایمانداری سے اسکرین پر لکھی جاتی ہے۔

ڈویلپر کو عطیہ کریں
عطیہ کرنے یا ڈویلپر کو سلام کرنے کے لیے: اہم اسکرین پر ڈویلپر کو عطیہ کریں بٹن دبائیں، آلے کے بارے میں بٹن کے پاس۔ عطیہ اسکرین پر BRI اکاؤنٹ کاپی کریں بٹن ہے — اسے دبائیں تاکہ ڈویلپر کا اکاؤنٹ نمبر کاپی ہو جائے، پھر اسے اپنی بینک ایپ میں چسپاں کریں۔ WhatsApp پر ڈویلپر کو سلام کریں سیکشن بھی ہے: اپنا نام اور آبائی شہر بھریں، پھر WhatsApp پر بھیجیں دبائیں — WhatsApp سلامی پیغام پہلے سے بھرے ہوئے کے ساتھ کھلتا ہے، بس WhatsApp میں بھیجیں دبائیں پھر ایپ پر واپس آئیں۔ WhatsApp دوسری ایپس کو خود بخود پیغامات بھیجنے کی اجازت نہیں دیتا، اس لیے بھیجنا پھر بھی آپ خود WhatsApp میں کرتے ہیں۔

ٹرمینل کی پسندیدہ کمانڈز
ٹرمینل میں اکثر استعمال ہونے والی کمانڈز محفوظ کرنے کے لیے: ٹرمینل کھولیں پھر پسندیدہ دبائیں۔ نیا پسندیدہ شامل کریں ٹیپ کریں، نام (مثال کے طور پر فائل دیکھیں) اور اس کی کمانڈ (مثال کے طور پر ls -la) بھریں، پھر محفوظ کریں دبائیں — پسندیدہ فون پر مستقل محفوظ ہو جاتا ہے۔ پسندیدہ نام ٹیپ کریں تاکہ اسے براہ راست ٹرمینل میں چلایا جا سکے؛ پسندیدہ حذف کریں ٹیپ کریں پھر حذف کرنے کے لیے ایک منتخب کریں (تصدیق کے ساتھ)۔ پہلے سے 3 بلٹ ان پسندیدہ ہیں: فائل دیکھیں (ls -la)، جگہ چیک کریں (df -h) اور اسکرین صاف کریں (clear) — سب حذف کیے جا سکتے ہیں۔ خالی کمانڈ محفوظ یا چلائی نہیں جا سکتی؛ ٹرمینل آپ کو پیغام اور آواز سے بتاتا ہے اگر ایسا ہو۔

تجزیات اور معیار
ایپ استعمال کا خلاصہ اور کریش رپورٹس دیکھنے کے لیے: اہم اسکرین پر تجزیات اور معیار بٹن دبائیں، ڈویلپر کو عطیہ کریں بٹن کے پاس۔ یہ اسکرین دکھاتی ہے کہ ایپ کتنی بار کھولی گئی، کون سی اسکرینیں سب سے زیادہ کھولی گئیں، کریشز کی تعداد اور تازہ ترین کریشز کی فہرست مختصر اصلاح تجویز کے ساتھ۔ یہ ڈیٹا صرف آپ کے فون پر محفوظ ہوتا ہے اور کہیں نہیں بھیجا جاتا۔ تجزیاتی ڈیٹا حذف کریں بٹن ہے جس میں تصدیقی ڈائیلاگ ہے تاکہ وہ تمام ڈیٹا حذف کیا جا سکے۔ آخری اسکرین صرف اہم اسکرین اور اس اسکرین کے لیے ریکارڈ کی جاتی ہے۔

اختتام
Create Aplikasi استعمال کرنے کا شکریہ۔ امید ہے کہ یہ آلہ آپ کی اور ہر اس شخص کی مدد کرے گا جو فون سے Android ایپس بنانا سیکھنا چاہتا ہے۔ اگر کوئی مسئلہ ہو تو اس رہنما سے قدم بہ قدم ٹھیک کریں، اور دوبارہ کوشش کرنے میں ہچکچاہٹ نہ کریں۔
