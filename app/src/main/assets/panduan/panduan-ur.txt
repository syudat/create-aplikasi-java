Create Aplikasi by Al Kautsar میں خوش آمدید
Create Aplikasi ایک اینڈرائیڈ ایپ بنانے والی ایپلیکیشن ہے جو براہ راست فون پر چلتی ہے، لیپ ٹاپ کی ضرورت کے بغیر۔ یہ ایپلیکیشن کسی کو بھی اپنی اینڈرائیڈ ایپ بنانے کی اجازت دیتی ہے، بشمول ان صارفین کے جو ایپ بنانا سیکھ رہے ہیں اور اسکرین ریڈر کے صارفین کے۔ اس ایپلیکیشن کے استعمال کی مکمل رہنمائی اسی Tentang Alat (ٹول کے بارے میں) اسکرین میں دستیاب ہے۔

یہ ایپلیکیشن کیا ہے اور کس کے لیے ہے
Create Aplikasi اینڈرائیڈ ایپ بنانے کا ایک ٹول ہے جو فون پر چلتا ہے۔ یہ ایپلیکیشن ہر اس شخص کے لیے ہے جو اپنی اینڈرائیڈ ایپ بنانا چاہتا ہے، بشمول ابتدائی صارفین اور اسکرین ریڈر کے صارفین کے۔ یہ ایپلیکیشن ایک کوڈ ایڈیٹر، پروجیکٹ کو آزمانے کے لیے Jalankan (چلائیں) بٹن، APK بنانے کے لیے Bangun (بنائیں) بٹن، اور APK پر دستخط کرنے اور انسٹال کرنے کے مینو فراہم کرتی ہے۔

اس ایپلیکیشن کا مقصد
یہ ایپلیکیشن اس لیے بنائی گئی ہے تاکہ ہر کوئی براہ راست فون سے آسانی سے اپنی اینڈرائیڈ ایپ بنا سکے۔ اس کی صورت کو جتنا ممکن ہو سادہ بنایا گیا ہے تاکہ نئے صارفین بھی اسے فوراً آزما سکیں۔

نیا پروجیکٹ بنانے کا طریقہ، قدم بہ قدم
1. مرکزی مینو میں Buat Project (پروجیکٹ بنائیں) دبائیں۔
2. پروجیکٹ کی قسم منتخب کریں: HTML، Situs Web (ویب سائٹ)، Java، Kotlin، Compose یا Python۔
3. ایپلیکیشن کا نام بھریں، مثال: Garuda Decode۔
4. پیکیج کا نام (package name) بھریں، مثال: com.android.garudadecode۔ پیکیج کے نام میں چھوٹے حروف استعمال ہونے چاہئیں اور اس میں نقطے سے الگ کیے گئے کم از کم دو حصے ہونے چاہئیں۔
5. ایپلیکیشن کا ورژن بھریں، مثال: 1.0، اور ورژن کوڈ عدد کی صورت میں بھریں، مثال: 1۔ اگر خالی چھوڑا جائے تو ورژن خودکار طور پر 1.0 اور ورژن کوڈ 1 سے بھر دیا جائے گا۔
6. اگر ضرورت ہو تو کم از کم SDK اور ہدف SDK بھریں۔ اگر خالی چھوڑا جائے تو طے شدہ قیمت استعمال ہوگی۔ کم از کم SDK سب سے کم تعاون یافتہ اینڈرائیڈ ورژن ہے، مثال: 21 کا مطلب ہے Android 5.0۔ زیادہ سے زیادہ ہدف SDK 36 (Android 16) ہے۔
7. ایپلیکیشن کی اجازتیں منتخب کرنے کے لیے Pilih Izin (اجازتیں منتخب کریں) بٹن دبائیں، مثال: INTERNET۔ INTERNET اجازت پہلے سے طے شدہ طور پر نشان زدہ ہے۔ صرف وہی اجازتیں نشان زد کریں جن کی ایپلیکیشن کو واقعی ضرورت ہو۔
8. اگر چاہیں تو "Gunakan arsitektur terpisah 64 bit dan 32 bit" (الگ 64 بٹ اور 32 بٹ معماریاں استعمال کریں) پر نشان لگائیں تاکہ APK کا سائز چھوٹا ہو جائے، اور اگر آپ خود کی بنائی ہوئی keystore استعمال کرنا چاہتے ہیں تو "Gunakan tanda tangan pribadi" (ذاتی دستخط استعمال کریں) پر نشان لگائیں۔
9. Buat Proyek (پروجیکٹ بنائیں) دبائیں۔ نیا پروجیکٹ Download/project فولڈر میں محفوظ ہو جاتا ہے اور Kelola Project (پروجیکٹ سنبھالیں) میں فوراً نظر آتا ہے۔

دستیاب پروجیکٹ کی اقسام
• HTML: index.html، style.css اور script.js سے صورت، WebView کے ذریعے چلتی ہے۔ براہ راست فون پر بنائی جاتی ہے۔
• Situs Web: index.html، tentang.html، kontak.html، style.css اور script.js سے مینو (Beranda (ہوم)، Tentang (بارے میں)، Kontak (رابطہ)) والی ویب سائٹ، WebView کے ذریعے چلتی ہے۔ براہ راست فون پر بنائی جاتی ہے۔
• Java: فون پر بنائی جاتی ہے۔ MainActivity یہاں ہے app/src/main/java/<nama-paket>/MainActivity.java۔ صورت app/src/main/res/layout/activity_main.xml سے، متن app/src/main/res/values/strings.xml سے اور تھیم app/src/main/res/values/styles.xml سے آتی ہے۔
• Kotlin: ایپلیکیشن میں شامل Kotlin کمپائلر استعمال کرکے ڈیوائس پر (آف لائن) بنائی جا سکتی ہے، یا GitHub Actions کے ذریعے۔ MainActivity یہاں ہے app/src/main/java/<nama-paket>/MainActivity.kt اور res فائلیں Java پروجیکٹ جیسی ہی ہیں۔ پہلی Kotlin تعمیر کمپائلر کے بڑے سائز کی وجہ سے سست ہوتی ہے، اور وہ .java فائلیں جو Kotlin کلاسوں کا حوالہ دیتی ہیں ابھی نہیں بنائی جا سکتیں (.java فائلیں .kt فائلوں سے پہلے کمپائل ہوتی ہیں)۔
• Compose: ایک جدید اینڈرائیڈ ایپلیکیشن جس کا انٹرفیس Jetpack Compose سے بنایا جاتا ہے (XML لے آؤٹ سے نہیں)۔ MainActivity یہاں ہے app/src/main/java/<nama-paket>/MainActivity.kt۔ Compose پروجیکٹ GitHub Actions کے ذریعے (پروجیکٹ کا Bangun مینو، پھر Bangun online (آن لائن بنائیں)) یا Gradle کے ساتھ Termux میں بنائے جاتے ہیں، کیونکہ Compose کو Jetpack Compose لائبریریوں کی ضرورت ہوتی ہے جو ڈیوائس پر دستیاب نہیں ہیں۔
• Python: ایپلیکیشن کی منطق app/src/main/python/main.py میں Python (Chaquopy) زبان میں لکھی جاتی ہے اور app/src/main/java/<nama-paket>/MainActivity.java میں موجود میزبان MainActivity.java کے ذریعے چلائی جاتی ہے۔ Python پروجیکٹ براہ راست فون پر بنائے جا سکتے ہیں (Chaquopy رن ٹائم ایپلیکیشن میں شامل ہے) اور GitHub Actions کے ذریعے بھی۔ Python پروجیکٹوں کا کم از کم SDK 24 (Android 7.0) ہے۔

Java، HTML، Situs Web، Kotlin، Compose اور Python پروجیکٹوں کی فائل ترتیب
Java، HTML، Situs Web، Kotlin، Compose اور Python پروجیکٹ عام طور پر اینڈرائیڈ پروجیکٹوں کی طرح ترتیب دیے جاتے ہیں۔ app فولڈر کے اندر src فولڈر ہے، اور اس کے اندر main فولڈر ہے۔ main فولڈر کے اندر java فولڈر کے پاس AndroidManifest.xml ہے، res فولڈر جس میں layout/activity_main.xml اور values/strings.xml اور values/styles.xml ہیں، اور HTML اور Situs Web کے لیے assets فولڈر جس میں index.html ہے (Situs Web میں tentang.html اور kontak.html بھی ہیں)۔ HTML اور Situs Web پروجیکٹوں کی اپنی MainActivity بھی app/src/main/java/<nama-paket>/MainActivity.java میں ہے، جو index.html کو WebView میں لوڈ کرتی ہے اور AndroidManifest میں لانچر بنتی ہے۔ Python پروجیکٹوں میں Python کوڈ app/src/main/python/main.py میں اور میزبان MainActivity.java یہاں app/src/main/java/<nama-paket>/MainActivity.java میں ہے۔ AndroidManifest.xml، layout، strings اور styles کو ایڈیٹر میں کھولا اور بدلا جا سکتا ہے، بالکل MainActivity کی طرح۔ پرانے پروجیکٹ جن کا مینی فیسٹ ابھی بھی app فولڈر کے پاس ہے وہ بھی بنائے جا سکتے ہیں، کیونکہ بناتے وقت ایپلیکیشن پہلے app/src/main/ میں AndroidManifest.xml کو جانچتی ہے، پھر app فولڈر کے پاس والے کو، اور آخر میں پروجیکٹ ڈیٹا فائل کو۔

اجازتوں کے قوانین (اہم)
پروجیکٹ بناتے وقت نشان زد کی گئی اجازتیں صرف ایک جگہ درج ہوتی ہیں، پروجیکٹ کی قسم کے مطابق۔ Java، HTML، Situs Web، Kotlin، Compose اور Python پروجیکٹوں کے لیے نشان زد کی گئی اجازتیں صرف AndroidManifest.xml میں درج ہوتی ہیں جو app/src/main/ میں، java فولڈر کے پاس، پروجیکٹ فولڈر کے اندر ہے۔ Java، HTML، Situs Web، Kotlin، Compose اور Python پروجیکٹوں کی پروجیکٹ ڈیٹا فائل میں اجازتوں کی فہرست نہیں ہوتی۔ اگر آپ Java منتخب کریں اور INTERNET اور CAMERA پر نشان لگائیں، تو AndroidManifest.xml میں صرف INTERNET اور CAMERA درج ہوں گے، کوئی اور اجازت ساتھ نہیں آئے گی۔ بناتے وقت ایپلیکیشن اجازتیں اسی جگہ سے پڑھتی ہے: Java، HTML، Situs Web، Kotlin، Compose اور Python پروجیکٹوں کے لیے app/src/main/ میں AndroidManifest.xml سے (اگر نہ ہو تو پرانے پروجیکٹوں کے لیے app فولڈر کے پاس والے AndroidManifest.xml سے)، اور پرانے پروجیکٹوں کے لیے پروجیکٹ ڈیٹا فائل سے۔

ایڈیٹر استعمال کرنے کا طریقہ
Kelola Project کھولیں، ایڈیٹر کھولنے کے لیے پروجیکٹ کے نام پر چھوئیں۔ ایڈیٹر میں فائلیں کھولی جا سکتی ہیں، کوڈ لکھا جا سکتا ہے اور تبدیلیاں محفوظ کی جا سکتی ہیں۔ Java، HTML، Situs Web، Kotlin، Compose اور Python پروجیکٹوں کے لیے فائلیں app/src/main فولڈر کے اندر ترتیب دی جاتی ہیں۔ پروجیکٹ شریک کرنے کے لیے Ekspor ZIP (ZIP برآمد کریں) استعمال کریں (نیچے والا حصہ دیکھیں)۔

پروجیکٹ چلانے کا طریقہ
ایڈیٹر میں پروجیکٹ کو آزمانے کے لیے Jalankan دبائیں۔ HTML اور Situs Web پروجیکٹوں کے لیے جو چلایا جاتا ہے وہ WebView کے ذریعے index.html ہے۔ اگر کوئی خرابی پیش آئے تو خرابی کا پیغام پڑھیں، کوڈ درست کریں، پھر دوبارہ چلائیں۔

APK بنانے کا طریقہ
ایڈیٹر میں Bangun دبائیں۔ بنانے کے دو طریقے ہیں۔ پہلا، Bangun di perangkat (ڈیوائس پر بنائیں): انٹرنیٹ کے بغیر براہ راست فون پر بناتا ہے، HTML، Situs Web، Java، Kotlin اور Python پروجیکٹوں کے لیے۔ دوسرا، GitHub Actions کے ذریعے Bangun online: GitHub پر انٹرنیٹ کے ذریعے بناتا ہے، اور ہر قسم کے پروجیکٹ کے لیے استعمال کیا جا سکتا ہے۔ Compose پروجیکٹ صرف دوسرے طریقے (Bangun online) سے یا Gradle کے ساتھ Termux میں بنائے جا سکتے ہیں، کیونکہ Compose کو Jetpack Compose لائبریریوں کی ضرورت ہوتی ہے جو ڈیوائس پر دستیاب نہیں ہیں۔ پہلی تعمیر کا نتیجہ ابھی دستخط شدہ نہیں ہوتا۔ اس کے بعد ایپلیکیشن اس پر دستخط کرتی ہے: خودکار طور پر طے شدہ کنجی سے، یا ذاتی دستخط سے اگر پروجیکٹ بناتے وقت "Gunakan tanda tangan pribadi" والا خانہ نشان زد کیا گیا ہو۔

APK انسٹال کرنے کا طریقہ
جب APK تیار ہو جائے تو اسے انسٹال کرنے کے لیے Pasang (انسٹال کریں) دبائیں۔ Android 8 اور اس سے اوپر پر فون پہلے "Izinkan dari sumber ini" (اس ذریعے سے اجازت دیں) مانگے گا، کیونکہ یہ ایپلیکیشن Play Store کے باہر سے APK انسٹال کرتی ہے۔ Pengaturan (ترتیبات) میں اس اجازت کو ایک بار فعال کریں، پھر ایپلیکیشن میں واپس آئیں: انسٹال خودکار طور پر جاری رہے گا، Pasang دوبارہ دبانے کی ضرورت کے بغیر۔ اگر Pasang بٹن نظر نہ آئے تو یقینی بنائیں کہ تعمیر مکمل ہو چکی ہے اور APK بن چکا ہے۔

ایپلیکیشن پر دستخط کرنے کا طریقہ
ہر APK پر دستخط ہونا ضروری ہے تاکہ اسے انسٹال کیا جا سکے۔ دو انتخاب دستیاب ہیں۔ پہلا، طے شدہ کنجی: ایپلیکیشن خود بخود دستخط کر دیتی ہے، آپ کو کچھ کرنے کی ضرورت نہیں۔ دوسرا، ذاتی دستخط: پہلے مرکزی مینو میں Buat Keystore (keystore بنائیں) مینو کے ذریعے ایک keystore بنائیں، اس کا پاس ورڈ اچھی طرح سنبھالیں، پھر پروجیکٹ بناتے وقت "Gunakan tanda tangan pribadi" پر نشان لگائیں۔ Keystore یہاں محفوظ ہوتی ہے Download/project/signing۔

پروجیکٹ کو ZIP میں برآمد کرنا
Ekspor ZIP اس لیے فراہم کیا گیا ہے تاکہ پروجیکٹ دوستوں کے ساتھ شریک کیا جا سکے۔ طریقہ یہ ہے: Kelola Project میں پروجیکٹ کے نام کو دیر تک دبائیں، پھر Ekspor ZIP منتخب کریں۔ نتیجہ Download/project/<NamaProyek>.zip میں محفوظ ہوتا ہے۔ bin فولڈر اس میں شامل نہیں ہوتا، اس لیے اس کا سائز چھوٹا ہوتا ہے، صرف چند درجن KB۔ وہ ZIP فائل کسی دوست کو بھیجی جا سکتی ہے یا GitHub پر اپ لوڈ کی جا سکتی ہے۔

Ekstensi JAWS
Ekstensi JAWS، Jieshuo (CSR) کے توسیعی انجن کو استعمال کرتی ہے، اس کے اسکرین ریڈر کو نہیں۔ اس طرح یہ خاکہ چلتا رہ سکتا ہے چاہے صارف TalkBack استعمال کرے۔ طریقہ یہ ہے: مرکزی مینو میں Ekstensi JAWS کھولیں۔ چونکہ خودکار کلک خود بخود چلتا ہے، اس لیے خدمت کو پہلے Pengaturan Aksesibilitas (رسائی کی ترتیبات) میں فعال کرنا ضروری ہے۔ اس کے بعد نیا خاکہ بنایا جا سکتا ہے: خاکے کا نام لکھیں، OK دبائیں، پھر اس کے خانے بھریں۔

Daftar Klik صفائی کے لیے الگ رکھا گیا ہے
ایک خاکے کے اندر دو خانے ہوتے ہیں: اسکرپٹ والا خانہ اور Daftar Klik (کلک کی فہرست) والا خانہ۔ بٹنوں کی فہرست daftar_klik.txt فائل میں الگ محفوظ ہوتی ہے، ہر سطر میں ایک نام۔ مواد کی مثال: tombolSimpan، tombolHapus، tombolBuka۔ کسی ایپلیکیشن کو کھولنے کے لیے اس فہرست میں صرف >WhatsApp لکھیں۔ پرانے خاکے جن میں ابھی daftar_klik.txt فائل نہیں ہے وہ یہی طے شدہ مثال دکھائیں گے۔

فراہم کیے گئے سادہ افعال
• klikTombol("tombolSimpan") — اس کے متن کی بنیاد پر ایک بٹن پر کلک کرتا ہے۔
• klikDaftarTombol(daftar) — daftar_klik.txt میں موجود فہرست پر کلک کرتا ہے، ہر سطر میں ایک بٹن، ترتیب سے، پھر بتاتا ہے کہ کتنے کامیاب ہوئے اور کتنے نہیں ملے۔
• bukaAplikasi("WhatsApp") — اس کے نام کی بنیاد پر ایپلیکیشن کھولتا ہے، یا فہرست میں ">WhatsApp" لکھیں۔

اسکرین ریڈر کے بارے میں
یہ ایپلیکیشن اسکرین ریڈر کے لیے دوستانہ بنائی گئی ہے۔ ہر بھرنے والے خانے پر ایک لیبل اور بھرنے کی مثال موجود ہے، اور تمام بٹن پیچیدہ اشاروں کے بغیر پہنچے جا سکتے ہیں۔ Ekstensi JAWS اس طرح بنائی گئی ہے کہ یہ چلتی رہے چاہے صارف TalkBack استعمال کرے، کیونکہ جو استعمال ہوتا ہے وہ اس کا توسیعی انجن ہے، اس کا اسکرین ریڈر نہیں۔

رازداری اور سلامتی
پروجیکٹ اور keystore آپ کے فون میں محفوظ ہوتے ہیں۔ GitHub ٹوکن صرف آن لائن تعمیر کے لیے استعمال ہوتا ہے اور اسی ایپلیکیشن کے اندر محفوظ ہوتا ہے۔ اپنا ٹوکن یا keystore کا پاس ورڈ کسی کے ساتھ شریک نہ کریں۔ اگر آپ ذاتی دستخط استعمال کرتے ہیں تو keystore اور اس کا پاس ورڈ محفوظ جگہ پر رکھیں، کیونکہ اگر وہ گم ہو جائیں تو پرانے APK کو اسی دستخط سے تازہ نہیں کیا جا سکتا۔

ضروریات
Android 5.0 یا اس سے نیا۔ ذخیرے کی اجازت: Android 11 اور اس سے اوپر پر تمام فائلوں تک رسائی کی اجازت استعمال ہوتی ہے، Android 10 اور اس سے نیچے پر عام ذخیرے کی اجازت (ذخیرہ پڑھنا/لکھنا) استعمال ہوتی ہے کیونکہ Android 10 میں تمام فائلوں تک رسائی کی اجازت نہیں ہے۔ ڈیوائس پر بنانے کے لیے ARM پروسیسر (32 یا 64 بٹ) والے فون کی ضرورت ہے۔ GitHub Actions کے ذریعے آن لائن بنانے کے لیے انٹرنیٹ اور GitHub ٹوکن کی ضرورت ہے۔ Kotlin پروجیکٹ ڈیوائس پر بنائے جا سکتے ہیں، لیکن ان کی پہلی تعمیر سست ہوتی ہے اور زیادہ میموری استعمال کرتی ہے کیونکہ Kotlin کمپائلر کا سائز بڑا ہے۔ Compose پروجیکٹ GitHub Actions کے ذریعے یا Gradle کے ساتھ Termux میں بنائے جاتے ہیں۔ Python پروجیکٹوں کو Android 7.0 یا اس سے نئے کی ضرورت ہے (کم از کم SDK 24) اور نتیجے میں بننے والا APK بڑا ہوتا ہے کیونکہ اس میں Python رن ٹائم (Chaquopy) اس کی معیاری لائبریری سمیت شامل ہوتا ہے۔

Terminal
مرکزی اسکرین پر Terminal مینو اس ایپلیکیشن کے اندر ایک ٹرمینل کھولتا ہے۔ ls جیسی کمانڈیں پروجیکٹ فولڈر کے مواد دیکھنے کے لیے، cd فولڈر بدلنے کے لیے اور git کوڈ سنبھالنے کے لیے استعمال کی جا سکتی ہیں۔ کمانڈوں کا نتیجہ ایسے متن کے طور پر ظاہر ہوتا ہے جسے اسکرین ریڈر پڑھ سکتا ہے، اور آخری نتیجہ سننے کے لیے Bacakan hasil (نتیجہ سنائیں) بٹن موجود ہے۔ یہ ٹرمینل فون کے نظام کے شیل کو استعمال کرتا ہے، اس لیے nano اور vim جیسے باہمی پروگرام یہاں ابھی استعمال نہیں کیے جا سکتے۔

Lisensi (ادا شدہ ورژن)
ایپلیکیشن بیچنے کے لیے پروجیکٹ بناتے وقت "Aktifkan Lisensi" (لائسنس فعال کریں) پر نشان لگائیں، پھر اپنا WhatsApp نمبر بھریں۔ بنی ہوئی ایپلیکیشن پہلی بار کھلنے پر لائسنس کوڈ مانگے گی: صارف اپنے ڈیوائس کی ID دیکھتا ہے، Kirim ID Perangkat (ڈیوائس ID بھیجیں) بٹن دبا کر وہ ID آپ کے WhatsApp پر بھیجتا ہے، پھر آپ لائسنس کوڈ کے ساتھ جواب دیتے ہیں۔ لائسنس کوڈ ڈیوائس ID اور پروجیکٹ پاس ورڈ (پروجیکٹ ڈیٹا فائل میں lisensi_seed) سے شمار کیا جاتا ہے — اس پاس ورڈ کو اچھی طرح سنبھالیں اور شریک نہ کریں۔ درست کوڈ داخل ہونے کے بعد ایپلیکیشن کھل جاتی ہے اور دوبارہ کوڈ نہیں مانگتی۔

Pembuat Ikon Otomatis
نئے پروجیکٹوں کا آئیکن ابھی شفاف ہے، اس لیے مرکزی مینو میں Pembuat Ikon (آئیکن بنانے والا) دستیاب ہے۔ طریقہ یہ ہے: Pembuat Ikon دبائیں، ایک یا دو حروف لکھیں (مثال ایپلیکیشن کے نام کے ابتدائی حروف)، پس منظر کا رنگ اور لکھائی کا رنگ منتخب کریں، اس کا پیش منظر دیکھیں، پھر Simpan ke Proyek (پروجیکٹ میں محفوظ کریں) دبائیں تاکہ وہ آئیکن منتخب پروجیکٹ میں استعمال ہو، یا Simpan ke Download (Download میں محفوظ کریں) دبائیں تاکہ اس کی PNG فائل کہیں اور استعمال ہو۔ پروجیکٹ بن جانے کے بعد ایپلیکیشن آئیکن بنانے کی پیشکش بھی کرتی ہے۔ پروجیکٹ کا پرانا آئیکن Kelola Project میں پروجیکٹ مینو سے کسی بھی وقت بدلا جا سکتا ہے (پروجیکٹ کے نام کو دیر تک دبائیں، پھر Ganti Ikon (آئیکن بدلیں) منتخب کریں)۔

Template Proyek Siap Pakai
اگر آپ خالی پروجیکٹ سے آغاز نہیں کرنا چاہتے تو پروجیکٹ بناتے وقت ایک سانچہ منتخب کریں: Kalkulator (Java)، Catatan (Java)، Daftar Tugas (Kotlin)، Kalkulator Web (HTML)، Situs Profil (Situs Web) یا Penghitung (Compose)۔ سانچہ منتخب کرنے سے پروجیکٹ کی قسم خودکار طور پر اس سانچے کے مطابق بدل جاتی ہے، اور پروجیکٹ پہلے سے تیار آغاز کوڈ کے ساتھ بنایا جاتا ہے — بس اسے چلائیں یا بدلیں۔ اگر سانچہ منتخب کرنے کے بعد پروجیکٹ کی قسم دوبارہ ہاتھ سے بدلی جائے تو سانچہ منسوخ ہو جاتا ہے اور پروجیکٹ دوبارہ خالی ہو جاتا ہے۔ HTML اور Situs Web سانچوں کے لیے سانچہ index.html کے مواد کو بدل دیتا ہے، بشمول فارم میں لکھے گئے HTML اسکرپٹ کے۔

Cadangan dan Pulihkan Proyek
تاکہ پروجیکٹ گم نہ ہوں، ایک بیک اپ سہولت دستیاب ہے۔ طریقہ یہ ہے: Kelola Project میں پروجیکٹ کے نام کو دیر تک دبائیں، پھر Cadangkan (بیک اپ کریں) منتخب کریں۔ بیک اپ Download/backup فولڈر میں پروجیکٹ کے نام اور تاریخ کے ساتھ ZIP کے طور پر محفوظ ہوتا ہے، مثال: GarudaDecode-2026-11-14-123045.zip۔ اس کا مواد Ekspor ZIP جیسا ہی ہے (پروجیکٹ کا پورا مواد، bin فولڈر کے بغیر)۔ بحال کرنے کے لیے: Kelola Project میں مینو کھولیں، Pulihkan cadangan (بیک اپ بحال کریں) منتخب کریں، پھر اس کی بیک اپ فائل منتخب کریں۔ اگر پروجیکٹ کا نام پہلے سے موجود ہو تو ایپلیکیشن پوچھے گی: Timpa proyek lama (پرانے پروجیکٹ پر اوپر لکھیں)، یا Nama baru (نئے نام) کے ساتھ محفوظ کریں۔

Bagikan dan Impor Proyek
پروجیکٹ دوست کے ساتھ شریک کرنے کے لیے: Kelola Project میں پروجیکٹ کے نام کو دیر تک دبائیں، پھر Bagikan (شریک کریں) منتخب کریں۔ پروجیکٹ شریک کرنے والی ایپوں (WhatsApp، Telegram اور دیگر) کے ذریعے ZIP کے طور پر بھیجا جاتا ہے۔ دوست سے پروجیکٹ وصول کرنے کے لیے: Kelola Project میں مینو کھولیں، Impor proyek (پروجیکٹ درآمد کریں) منتخب کریں، پھر اس کی ZIP فائل منتخب کریں۔ اس ZIP فائل میں پروجیکٹ ڈیٹا فائل ہونا ضروری ہے — اگر نہ ہو تو فائل واضح پیغام کے ساتھ رد کر دی جاتی ہے، کیونکہ وہ فائل Create Aplikasi پروجیکٹ نہیں ہے۔ اگر پروجیکٹ کا نام پہلے سے موجود ہو تو ایپلیکیشن پوچھے گی: Timpa proyek lama، یا Nama baru کے ساتھ محفوظ کریں۔

Pencarian dan Filter Proyek
اگر پروجیکٹ بہت ہو گئے ہوں تو Kelola Project میں ایک تلاش کا خانہ اور قسم کا چھانٹنے والا موجود ہے۔ تلاش کے خانے میں پروجیکٹ کا نام لکھیں، فہرست فوراً چھن جاتی ہے (بڑے اور چھوٹے حروف میں فرق نہیں کیا جاتا)۔ قسم کا چھانٹنے والا فہرست کو صرف ایک قسم تک محدود کرتا ہے: Semua (تمام)، HTML، Situs Web، Java، Kotlin، Compose یا Python۔ ہر پروجیکٹ کا مینو چھنی ہوئی فہرست سے بھی معمول کے مطابق کھولا جا سکتا ہے۔
