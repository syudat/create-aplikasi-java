欢迎使用 Create Aplikasi by Al Kautsar
Create Aplikasi 是一款可直接在手机上运行的 Android 应用创建应用，无需笔记本电脑。本应用让任何人都能创建自己的 Android 应用，包括刚开始学习创建应用的用户和屏幕阅读器用户。本应用的完整使用指南可在关于本工具界面中查看。

本应用是什么，适合谁使用
Create Aplikasi 是一款在手机上运行的 Android 应用创建工具。本应用面向任何想创建自己的 Android 应用的人，包括初学者和屏幕阅读器用户。本应用提供代码编辑器、用于测试项目的“运行”按钮、用于生成 APK 的“构建”按钮，以及用于签名和安装 APK 的菜单。

本应用的目的
制作本应用是为了让任何人都能直接通过手机轻松创建自己的 Android 应用。其界面尽可能做得简单，以便新用户也能立即尝试。

如何逐步创建新项目
1. 点击主菜单中的“创建项目”。
2. 选择项目类型：HTML、网站、Java、Kotlin、Compose 或 Python。
3. 输入应用名称，例如：Garuda Decode。
4. 输入包名（package name），例如：com.android.garudadecode。包名必须使用小写字母，并至少由两个以点分隔的部分组成。
5. 输入应用版本，例如：1.0，以及数字形式的版本号，例如：1。如果留空，版本将自动填为 1.0，版本号填为 1。
6. 如有需要，输入最低 SDK 和目标 SDK。如果留空，将使用默认值。最低 SDK 是所支持的最低 Android 版本，例如：21 表示 Android 5.0。目标 SDK 最高为 36（Android 16）。
7. 点击“选择权限”按钮以选择应用权限，例如：INTERNET。INTERNET 权限默认已勾选。只勾选应用确实需要的权限。
8. 如有需要，勾选“使用独立的 64 位和 32 位架构”以减小 APK 大小；如果想使用自己制作的密钥库，请勾选“使用个人签名”。
9. 点击“创建项目”。新项目会保存在 Download/project 文件夹中，并立即显示在“管理项目”中。

可用的项目类型
• HTML：由 index.html、style.css 和 script.js 构成的界面，通过 WebView 运行。直接在手机上构建。
• 网站：带有菜单（首页、关于、联系）的网站，由 index.html、tentang.html、kontak.html、style.css 和 script.js 构成，通过 WebView 运行。直接在手机上构建。
• Java：在手机上构建。MainActivity 位于 app/src/main/java/<package-name>/MainActivity.java。界面来自 app/src/main/res/layout/activity_main.xml，文本来自 app/src/main/res/values/strings.xml，主题来自 app/src/main/res/values/styles.xml。
• Kotlin：可以使用应用内附带的 Kotlin 编译器在设备上构建（离线），或通过 GitHub Actions 构建。MainActivity 位于 app/src/main/java/<package-name>/MainActivity.kt，res 文件与 Java 项目相同。首次构建 Kotlin 较慢，因为编译器体积较大；引用 Kotlin 类的 .java 文件目前还无法构建（.java 文件会先于 .kt 文件编译）。
• Compose：界面使用 Jetpack Compose 创建的现代 Android 应用（不是 XML 布局）。MainActivity 位于 app/src/main/java/<package-name>/MainActivity.kt。Compose 项目通过 GitHub Actions（构建项目菜单，然后选择在线构建）构建，或在 Termux 中用 Gradle 构建，因为 Compose 需要设备上没有的 Jetpack Compose 库。
• Python：应用逻辑用 Python 语言（Chaquopy）编写在 app/src/main/python/main.py 中，并由位于 app/src/main/java/<package-name>/MainActivity.java 的宿主 MainActivity.java 运行。Python 项目可以直接在手机上构建（Chaquopy 运行时已包含在应用中），也可以通过 GitHub Actions 构建。Python 项目的最低 SDK 为 24（Android 7.0）。

Java、HTML、网站、Kotlin、Compose 和 Python 项目的文件结构
Java、HTML、网站、Kotlin、Compose 和 Python 项目的结构与一般 Android 项目相同。在 app 文件夹内有 src 文件夹，src 内有 main 文件夹。在 main 文件夹内，AndroidManifest.xml 位于 java 文件夹旁边，res 文件夹包含 layout/activity_main.xml 和 values/strings.xml 以及 values/styles.xml；对于 HTML 和网站，还有 assets 文件夹，其中包含 index.html（网站还有 tentang.html 和 kontak.html）。HTML 和网站项目在 app/src/main/java/<package-name>/MainActivity.java 也有自己的 MainActivity，它在 WebView 中加载 index.html 并成为 AndroidManifest 中的启动器。Python 项目的 Python 代码位于 app/src/main/python/main.py，宿主 MainActivity.java 位于 app/src/main/java/<package-name>/MainActivity.java。AndroidManifest.xml、布局、字符串和样式都可以在编辑器中打开和修改，就像 MainActivity 一样。清单文件仍位于 app 文件夹旁边的旧项目仍然可以构建，因为在构建时，应用会先检查 app/src/main/ 中的 AndroidManifest.xml，然后是 app 文件夹旁边的那个，最后是项目数据文件。

权限规则（重要）
创建项目时勾选的权限只会记录在一个地方，具体取决于项目类型。对于 Java、HTML、网站、Kotlin、Compose 和 Python 项目，勾选的权限仅记录在位于项目文件夹内 app/src/main/ 中、java 文件夹旁边的 AndroidManifest.xml 中。Java、HTML、网站、Kotlin、Compose 和 Python 项目的项目数据文件不包含权限列表。如果选择 Java 然后勾选 INTERNET 和 CAMERA，那么记录在 AndroidManifest.xml 中的只有 INTERNET 和 CAMERA，不会包含其他权限。构建时，应用从相同位置读取权限：对于 Java、HTML、网站、Kotlin、Compose 和 Python 项目，从 app/src/main/ 中的 AndroidManifest.xml 读取（如果没有，则对于旧项目从 app 文件夹旁边的 AndroidManifest.xml 读取），对于旧项目则从项目数据文件读取。

如何使用编辑器
打开“管理项目”，点击项目名称以打开编辑器。在编辑器中，可以打开文件、编写代码并保存更改。对于 Java、HTML、网站、Kotlin、Compose 和 Python 项目，文件排列在 app/src/main 文件夹内。要共享项目，请使用导出 ZIP（见下文部分）。

如何运行项目
在编辑器中，点击“运行”以测试项目。对于 HTML 和网站项目，运行的是通过 WebView 打开的 index.html。如果发生错误，请阅读错误消息，修复代码，然后再次运行。

如何构建 APK
在编辑器中，点击“构建”。有两种构建方式。第一种，在设备上构建：直接在手机上构建，无需互联网，适用于 HTML、网站、Java、Kotlin 和 Python 项目。第二种，通过 GitHub Actions 在线构建：通过互联网在 GitHub 上构建，可用于所有项目类型。Compose 项目只能用第二种方式（在线构建）构建，或在 Termux 中用 Gradle 构建，因为 Compose 需要设备上没有的 Jetpack Compose 库。第一次构建的结果尚未签名。之后应用会对其签名：使用内置密钥自动签名；或者如果在创建项目时勾选了“使用个人签名”复选框，则使用个人签名。

如何安装 APK
APK 准备好后，点击“安装”进行安装。在 Android 8 及更高版本上，手机会先要求“允许来自此来源”，因为本应用安装的是 Play 商店之外的 APK。在“设置”中启用该权限一次，然后返回应用：安装将自动继续，无需再次点击“安装”。如果“安装”按钮未出现，请确保构建已完成且 APK 已生成。

如何签名应用
每个 APK 都必须签名才能安装。有两个选项。第一，内置密钥：应用自动自行签名，您无需做任何事情。第二，个人签名：先通过主菜单中的“创建密钥库”菜单创建密钥库，妥善保存其密码，然后在创建项目时勾选“使用个人签名”。密钥库保存在 Download/project/signing 中。

将项目导出为 ZIP
提供导出 ZIP 是为了让项目可以与朋友共享。操作方法：在“管理项目”中，长按项目名称，然后选择“导出 ZIP”。结果保存在 Download/project/<ProjectName>.zip 中。bin 文件夹不包含在内，因此体积较小，只有几十 KB。该 ZIP 文件可以发送给朋友或上传到 GitHub。

JAWS 扩展
JAWS 扩展使用 Jieshuo (CSR) 的扩展引擎，而不是其屏幕阅读器。这样，即使使用者使用 TalkBack，设计仍然可以运行。操作方法：在主菜单中打开 JAWS 扩展。由于自动点击会自行运行，必须先在无障碍设置中启用该服务。之后，就可以创建新设计：输入设计名称，点击“确定”，然后填写其框格。

点击列表单独存放以保持整洁
在一个设计中有两个框格：脚本框和点击列表框。按钮列表单独保存在文件 daftar_klik.txt 中，每行一个名称。其内容示例：tombolSimpan、tombolHapus、tombolBuka。要打开某个应用，只需在该列表中写入 >WhatsApp。尚未拥有 daftar_klik.txt 文件的旧设计将显示该默认示例。

提供的简单函数
• klikTombol("tombolSimpan") — 根据按钮的文本点击一个按钮。
• klikDaftarTombol(daftar) — 点击 daftar_klik.txt 中的列表，每行一个按钮，按顺序执行，然后告知有多少个成功、多少个未找到。
• bukaAplikasi("WhatsApp") — 根据名称打开一个应用，或者在列表中写入 ">WhatsApp"。
• klik(540, 1200) — 在屏幕坐标处点击。
所有函数都先做得简单。等您熟悉之后，以后可以添加其他函数。

关于屏幕阅读器
本应用的设计对屏幕阅读器友好。每个输入字段都有标签和填写示例，所有按钮无需复杂手势即可触及。JAWS 扩展的设计使其即使在使用者使用 TalkBack 时也能继续运行，因为使用的是其扩展引擎，而不是其屏幕阅读器。

隐私与安全
项目和密钥库保存在您的手机上。GitHub 令牌仅用于在线构建，并保存在本应用内。不要与任何人共享您的令牌或密钥库密码。如果使用个人签名，请将密钥库及其密码保存在安全的地方，因为如果丢失，旧的 APK 将无法用同一签名更新。

要求
Android 5.0 或更高版本。存储权限：在 Android 11 及更高版本上使用所有文件访问权限，在 Android 10 及更低版本上使用普通存储权限（读/写存储），因为 Android 10 没有所有文件访问权限。在设备上构建需要配备 ARM 处理器（32 位或 64 位）的手机。通过 GitHub Actions 在线构建需要互联网和 GitHub 令牌。Kotlin 项目可以在设备上构建，但首次构建较慢且占用更多内存，因为 Kotlin 编译器体积较大。Compose 项目通过 GitHub Actions 构建，或在 Termux 中用 Gradle 构建。Python 项目需要 Android 7.0 或更高版本（最低 SDK 24），且生成的 APK 更大，因为它包含 Python 运行时 (Chaquopy) 及其标准库。

终端
主屏幕上的“终端”菜单会在本应用内打开一个终端。可以使用 ls 等命令查看项目文件夹的内容，用 cd 在文件夹之间移动，用 git 管理代码。命令输出以屏幕阅读器可读的文本形式显示，并且有一个“朗读结果”按钮可收听最后一次结果。此终端使用手机的系统 shell，因此 nano 和 vim 等交互式程序目前还无法在此使用。

许可证（付费版）
要出售应用，请在创建项目时勾选“启用许可证”，然后输入您的 WhatsApp 号码。构建出的应用在首次打开时会要求输入许可证代码：使用者看到其设备 ID，点击“发送设备 ID”按钮将该 ID 发送到您的 WhatsApp，然后您回复许可证代码。许可证代码由设备 ID 和项目密码（项目数据文件中的 lisensi_seed）计算得出——请妥善保存该密码，不要共享。输入正确的代码后，应用将打开，并且不再要求输入代码。

自动图标制作器
新项目的图标仍然是透明的，因此主菜单中提供了图标制作器。操作方法：点击“图标制作器”，写下一到两个字母（例如应用名称的首字母），选择背景颜色和文字颜色，查看预览，然后点击“保存到项目”将该图标用于所选项目，或点击“保存到下载”在其他地方使用其 PNG 文件。创建项目后，应用还会提供创建图标的选项。项目的旧图标可以随时从“管理项目”中的项目菜单更换（长按项目名称，然后选择“更换图标”）。

现成的项目模板
如果您不想从空白项目开始，请在创建项目时选择模板：计算器 (Java)、笔记 (Java)、待办事项列表 (Kotlin)、网页计算器 (HTML)、个人主页网站（网站）或计数器 (Compose)。选择模板会自动将项目类型更改为与该模板一致，并且项目会使用现成的初始代码创建——只需运行或修改即可。如果在选择模板后再次手动更改项目类型，模板将被取消，项目恢复为空白。对于 HTML 和网站模板，模板会替换 index.html 的内容，包括在表单中输入的 HTML 脚本。

备份和恢复项目
为了不丢失项目，提供了备份功能。操作方法：在“管理项目”中，长按项目名称，然后选择“备份”。备份以 ZIP 形式保存在 Download/backup 文件夹中，名称为项目名和日期，例如：GarudaDecode-2026-11-14-123045.zip。其内容与导出 ZIP 相同（项目的全部内容，不含 bin 文件夹）。要恢复：打开“管理项目”中的菜单，选择“恢复备份”，然后选择备份文件。如果项目名称已存在，应用会询问：覆盖旧项目，还是以新名称保存。

共享和导入项目
要与朋友共享项目：在“管理项目”中，长按项目名称，然后选择“共享”。项目会以 ZIP 形式通过共享应用（WhatsApp、Telegram 等）发送。要接收朋友的项目：打开“管理项目”中的菜单，选择“导入项目”，然后选择 ZIP 文件。该 ZIP 文件必须包含项目数据文件——如果没有，该文件会被拒绝并给出明确的消息，因为该文件不是 Create Aplikasi 项目。如果项目名称已存在，应用会询问：覆盖旧项目，还是以新名称保存。

项目搜索和筛选
如果项目已经很多，“管理项目”中有搜索框和类型筛选器。在搜索框中输入项目名称，列表会立即筛选（不区分大小写字母）。类型筛选器将列表限制为一种类型：全部、HTML、网站、Java、Kotlin、Compose 或 Python。每个项目的菜单仍可像往常一样从已筛选的列表中打开。

用语音构建应用
如果不想打字，可以使用语音：在主菜单中点按语音构建，然后说出命令。可以说的命令有："Buat proyek kalkulator"、"Bangun proyek Kalkulator"、"Buka proyek Kalkulator"、"Jalankan proyek Kalkulator"、"Daftar proyek"、"Buka ikon"、"Kembali"和"Bantuan"。应用会用语音和文字回答，因此不看屏幕也能使用。语音识别使用手机内置的语音识别应用（免费；如果安装了印尼语语言包，可以离线运行）。如果手机没有语音识别器，可以在同一屏幕的文本框中输入命令。

无障碍审核
要在发布前检查项目布局是否对屏幕阅读器（TalkBack/Jieshuo）友好：打开主菜单中的无障碍审核，选择一个项目，然后点按加载布局列表并选择一个布局文件。IDE 会读取该 XML 文件，报告没有标签的按钮及其行号、重复使用的标签和相互重叠的元素，然后生成一份焦点顺序记录，如同 Jieshuo 朗读的那样。如果某个按钮没有标签，请填写标签，然后点按自动插入标签——标签会作为 contentDescription 写入布局文件。此检查仅读取布局 XML；Compose 界面和已完成的 APK 暂不扫描。

崩溃剖析
要通过带唯一 ID 的崩溃日志查明应用自行关闭的原因：打开主菜单中的崩溃剖析，从日志列表中选择一个崩溃 ID，然后点按检查。IDE 会将日志中的类和行号与项目源代码对照，并用印尼语解释原因（例如空引用、尚未请求的权限或 JSON 错误），同时给出代码补丁建议。只有当源代码行与崩溃发生时完全相同时，才点按应用补丁；如果已经改变，补丁会被拒绝，IDE 会请你自行检查。读取的是 IDE 自身的崩溃日志，而不是已构建应用的日志。

跨范式转译器
要把简单的 Java 代码转换为 Kotlin，或把简单的 XML 布局转换为 Compose 代码：打开主菜单中的跨范式转译器，选择项目和文件，然后点按预览。IDE 会以文本形式显示转换结果——请先检查，因为无法识别的行会保持原样，而 Java 中的 static 一词在 Kotlin 中会被去掉（使用前请确认其含义）。XML 到 Compose 的转换仅更改文本、提示和方向——大小、颜色和其他属性暂不包括在内。如果结果正确，点按应用到文件以写入目标文件；源文件不会被更改。仅转换安全、常见的模式。

本地微型服务器
要在没有网络的情况下测试需要服务器的应用：打开主菜单中的本地微型服务器，编写路由定义（例如 GET /halo 及其 JSON 答案），然后点按启动服务器。IDE 会在同一部手机上运行一个小型 HTTP 服务器（仅 HTTP，无 TLS，用于同一 Wi-Fi 网络），并在屏幕上记录每个请求和回答。路由可以使用 {nama} 这样的参数和简单的 API 密钥。此服务器仅用于在本机上测试；已构建的 APK 尚不能成为服务器，关闭其屏幕时服务器会停止。

安全审核器
要在发布前检查项目代码中的安全漏洞：打开主菜单中的安全审核器，选择一个项目，然后点按开始扫描。IDE 会扫描代码、清单和项目配置，并按风险从高到低报告发现的问题——代码中暴露的 API 密钥、未经许可暴露的组件、启用 JavaScript 并带有 JavaScript 接口的 WebView、弱加密（MD5、SHA1、DES）、没有 TLS 的 http 地址，以及直接写在代码中的密码——并附上每个问题的文件和行号。对于有安全修复办法的问题（例如把 MD5 换成 SHA-256 或把 http 换成 https），点按应用修复；对于 API 密钥和密码，IDE 仅显示建议的修复办法，因为替代方案必须由开发者自行决定。此扫描读取的是代码中的文本模式，而不是字节码，因此可能有些发现实际上是安全的，而没有固定模式的漏洞可能漏过扫描——应用之前请先检查。

界面测试机器人
要通过文本场景自动测试应用的外观：打开主菜单中的界面测试机器人，选择一个项目，然后点按自动创建场景。IDE 会读取项目清单和布局，编写由文本步骤组成的场景（点按按钮、填写字段、等待、返回）。点按运行试运行可查看带时间戳的场景运行日志。在此阶段，机器人仅运行模拟（试运行）——在手机上真正点按按钮和捕获真实崩溃是下一阶段，因此这里的崩溃报告仍是示例格式。

代码时间旅行
要在不输入 Git 命令的情况下把项目恢复到早期的代码状态：打开主菜单中的代码时间旅行，选择一个项目，填写时间点标签（可以为空），然后点按记录时间点。IDE 会把项目源文件的副本连同它们的哈希值保存在项目内的 .riwayat 文件夹中。时间点列表会显示全部时间点；选择两个时间点，然后点按比较，即可查看添加、更改或删除的文件和函数。点按恢复可回到旧状态——恢复之前，IDE 总是先备份当前状态，因此不会丢失任何内容。点按创建实验副本可把项目复制到新文件夹，在不打扰原始项目的情况下尝试更改。仅记录源文件。

模块工厂
要把项目的一部分打包成可供其他项目使用的模块：打开主菜单中的模块工厂，选择源项目，勾选要打包的界面、类、字符串和权限文件，然后点按打包为模块。IDE 会写入一个 ZIP 归档以及 JSON 元数据（模块名称、版本、使用的字符串和权限）。要把模块安装到另一个项目中，打开模块工厂，选择目标项目，然后点按安装模块并选择模块的 .zip 文件——合并过程会添加字符串和权限而不覆盖已有代码；如果文件名已在目标项目中使用，则不合并该文件。模块不携带库或构建设置。

多态护盾与资源保险库
要在发布前随机化标识符名称并加密项目资源：请在主菜单中打开多态护盾与资源保险库，选择项目，然后点按随机命名与资源加密。IDE 会扫描源代码中的类名和方法名，生成随机名称映射，用 AES-GCM 将项目资源文件加密到项目内的 brankas-aset 文件夹，并保存加密的恢复映射（perisai-peta.brankas），以便在读取崩溃日志时恢复原始名称。加密密钥由项目名称派生，因此任何知道项目名称的人都可以打开保险库——这是防止随意读取的保护，而不是带密码锁的保险库。这里构建的是名称映射和资源保险库；重写已编译 DEX 文件中的名称是后续阶段，因此成品 APK 中的名称尚未随机化。

信任链与环境守护者
要在发布前检查签名密钥链和手机环境：请在主菜单中打开信任链与环境守护者，选择项目，然后点按检查链与环境。IDE 会根据项目包名构建 5 代密钥链并检查其完整性，然后扫描自身进程的内存映射和设备属性，查找 Frida、Xposed 或模拟器的痕迹。结果是安全、注意或危险的风险等级，并附带文本证据。此检查读取内存映射和系统属性中的文本模式，而不是原生库级别的原始内存完整性，也不将密钥绑定到硬件安全芯片——隐藏文本痕迹的注入工具可能躲过此次扫描。

文本树布局架构师
要在不看屏幕的情况下设计界面：请在主菜单中打开文本树布局架构师，选择项目和布局文件，然后点按检查布局。IDE 会将 XML 布局作为文本树读取，并朗读每个元素的位置叙述（例如右下方，占屏幕宽度的 45%），然后以数学方式报告元素之间的重叠和在 360 dp 宽度下超出屏幕的元素。计算的是 LinearLayout 和简单的 dp 尺寸；ConstraintLayout 和 Compose 界面的位置被报告为不确定，而不是猜测。

设计系统工作室
要让所有界面和项目中的间距、字体和圆角保持一致：请在主菜单中打开设计系统工作室，选择项目，编写设计令牌（例如 jarak=8, huruf=16, sudut=12），选择组件，然后点按生成组件。IDE 会验证令牌——基础间距 4 至 16 dp、基础字体 12 至 20 sp、圆角 0 至 32 dp、最小触摸区域 48 dp——然后在项目文件夹中写入可直接使用的 XML 组件（komponen-studio.xml）以及 XML 主题（tema-studio.xml）和 Compose 主题（tema-studio.kt）。组件以文本形式生成，粘贴到布局中后再用布局架构师检查；平板上的双列调整使用屏幕宽度限定符，而不是运行时设备检测。

语义重构与 AST 导航
要查找定义并重命名符号，而不破坏恰好同名的其他代码：请在主菜单中打开语义重构与 AST 导航，选择项目，然后点按扫描项目符号，查看所有类和方法及其文件和行号。输入符号名称，再次点按扫描项目符号，即可查看其定义和调用它的所有文件。要重命名，输入新名称，点按重命名预览查看每个文件中的出现次数，然后点按应用重命名。此索引器使用文本模式，而不是完整的 AST 解析器：重命名类适用于所有文件，而重命名方法仅适用于其所属文件——其他文件中的调用者不会被更改，因此在应用之前请检查预览和调用者扫描结果。将代码块提取为新函数的功能已存在于逻辑引擎中，但此界面上还没有按钮。

单步调试器与内存检查器
要在程序流程中间检查变量内容，而不必通过日志猜测：请在主菜单中打开单步调试器与内存检查器，选择项目，编写执行跟踪（每行一步，格式为行号、代码，然后是用 | 分隔的变量和值，例如 10|int total = harga * jumlah;|harga=5000, jumlah=3, total=15000），输入断点行号，然后点按运行调试跟踪。IDE 会运行到第一个断点，并通过 Jieshuo 朗读活动行及其变量值。点按单步执行一行前进一行，或点按继续运行程序运行到下一个断点。这是一个跟踪调试器：它遍历已记录或手写的执行跟踪，不会暂停正在运行的 Android 应用——暂停真实进程需要调试桥，此阶段尚未实现。

离线依赖管理器
要在没有网络的情况下使用第三方库并在构建前避免版本冲突：请在主菜单中打开离线依赖管理器，选择项目，然后点按检查依赖。IDE 会读取项目的所有 .gradle 文件，检查离线保险库（项目内的 brankas-maven.txt），并解决冲突——如果两个库要求同一工件的不同版本，则使用最高版本并报告冲突。要将库记录到保险库中，输入其坐标（group:artifact:version 形式，例如 com.google.code.gson:gson:2.10.1），然后点按检查依赖。从 Maven、Google 或 PyPI 下载需要网络：离线时只能使用保险库中已有的库，添加坐标只会将其记录到索引中——AAR、JAR 或 WHL 文件本身不会自动下载。保险库仍按项目存储。

数据库与存储检查器
要在不编写打印表格内容的代码的情况下检查和测试项目数据库内容：请在主菜单中打开数据库与存储检查器，选择项目和数据库文件（.db、.sqlite 或 .sqlite3），然后点按打开数据库。IDE 会读取表结构，并将前 20 行显示为由 Jieshuo 朗读的文本表格。编写简单的 SELECT 查询，然后点按运行查询（例如 SELECT nama FROM pengguna WHERE kota = 'Makassar'）。要更改值，输入行号（1 = 第一行）、列名和新值，然后点按更改单元格值——该值会写回 .db 文件。点按保存备份可将当前表状态保存为项目中的 <数据库名>.cadangan.txt 文件。仅读取第一个表；支持的查询仅为简单的 SELECT，不含 JOIN 或 GROUP BY；SharedPreferences 和 DataStore 尚未读取。

单元测试工厂与模糊测试
要在分享应用之前发现逻辑漏洞：请在主菜单中打开单元测试工厂与模糊测试，选择项目和代码文件，然后点按创建并运行测试。IDE 会读取文件中的函数签名，生成正常和边界测试用例（空文本、null、最大数字、奇怪字符），对示例函数运行模糊测试，并在项目中写入 JUnit 测试骨架（Uji<类名>.java）。结果会报告通过和失败的测试数量、找到的代码行数和函数数量，以及创建的测试用例数量。生成的测试仍是骨架——期望值必须由开发者编写——真正的模糊测试仅在示例函数上运行，而不是在项目函数上；行覆盖率百分比尚未计算。

极端设备条件模拟器与内存泄漏审计器
要在系统终止进程、网络中断、屏幕旋转或省电模式开启时测试应用的韧性：请在主菜单中打开极端设备条件模拟器与内存泄漏审计器，选择项目，然后点按运行模拟。IDE 会运行三个压力场景以及屏幕旋转模拟，并跟踪界面关闭后仍保留在内存中的对象，然后报告丢失的数据和泄漏的对象链。这是对状态模型的模拟，不是真正终止进程、不是真正切断手机网络，也不是真实的堆转储；此界面上的状态模型仍是固定示例，而不是用户项目界面的状态。

项目蓝图架构师
要将大型应用创意转变为分步工作计划：请在主菜单中打开项目蓝图架构师，选择项目，编写应用创意（例如带分期付款的杂货店收银应用），然后点按创建蓝图。IDE 会整理模块、文件列表和小的工作里程碑，并将其保存为项目文件夹中的 cetak-biru.txt。每完成一个里程碑，点按将下一个里程碑标记为完成，或点按加载已保存的蓝图重新打开已保存的蓝图。蓝图是根据设备上的关键词模式构建的，而不是来自在线 AI 模型——无法识别的创意使用通用骨架（数据模型、存储、界面、逻辑）——通过活动的 AI 提供商构建的功能在此阶段尚未实现。

代码逻辑流程讲述者
要在不逐行聆听语法的情况下理解长代码：请在主菜单中打开代码逻辑流程讲述者，选择项目和代码文件，然后点按代码叙述。IDE 会将每一行转换为印尼语句子（例如如果总数大于 100000，则运行以下代码块），显示方法之间的调用图，并标记潜在的细微错误及其行号——用 == 比较 String、打开后未关闭的流，以及在两个不同方法中写入的变量。叙述和检查使用离线文本模式，而不是在线 AI 模型，也不是完整的数据流分析；无法识别的模式会按原样叙述为一行代码，数据竞争警告可能出现在实际仅轮流使用的变量上。

应用包工厂与 Play 商店就绪检查
要直接在手机上为 Google Play 商店准备应用：请在主菜单中打开应用包工厂与 Play 商店就绪检查，选择项目，然后点按构建 AAB 包。IDE 会根据项目清单、资源和资产组装 .aab 文件，模拟每种架构（arm64-v8a、armeabi-v7a、x86_64）和语言的下载拆分大小，然后审核 Play 就绪情况——目标 SDK 低于 35 会被标记为高，因为 Play 商店要求 35 或更高，缺失 64 位库也会被标记为高。生成的包是标准结构的 AAB 归档；拆分大小是根据文件大小估算的，不是真实的 bundletool 拆分结果，为 Play Console 签署包仍使用与 APK 相同的构建路径。

OTA 更新引擎与分阶段发布
要在不强迫用户重新下载整个 APK 的情况下发送小修复：请在主菜单中打开 OTA 更新引擎与分阶段发布，选择项目，编写旧版本和新版本的内容，然后点按创建补丁包。IDE 会计算行差异并创建带有新内容 SHA-256 指纹的补丁包（patch-ota.zip），然后检查此设备是否处于早期 10% 发布阶段。此处的补丁仅适用于文本文件（脚本、资源、配置）——二进制 DEX 或 APK 补丁尚不受支持，补丁在应用重新打开时应用。清单中的指纹仅证明内容完整性，而不是发送者真实性，因为尚未使用私钥签名。

团队代码评审工作室
要在不阅读 Git 箭头标记的情况下评审同事的更改并解决合并冲突：请在主菜单中打开团队代码评审工作室，选择项目，填写三个文本版本（基础、本地、同事），然后点按打开团队评审。IDE 会合并这三者，并将每个冲突显示为语音选项：使用本地版本、使用同事版本或合并两者——结果行会插入到原始冲突位置，以保持行顺序正确——然后将结果写入项目中的 gabung-hasil.txt。在其下方是项目任务板：输入任务标题，然后点按添加任务；任务以文本形式保存在项目内的 .tugas 文件夹中。合并使用行匹配，而不是语法，因此同一行的两处更改即使含义不冲突，也始终被视为冲突；任务板通过将文本文件与 Git 历史一起复制来同步，没有专用的同步服务器。

代码结构听写
要在编辑器内用语音编写代码：先在编辑器中打开一个项目，然后点按代码结构听写按钮。用印尼语说出命令，例如 buat fungsi tambah dengan parameter a angka dan b angka、buat kelas Mobil 或 buat variabel teks nama sama dengan Budi——IDE 会把语音转换为语法正确的 Java、Kotlin、Python 或 Compose 代码块，并插入到光标位置，然后通过 Jieshuo 朗读简短摘要。听写使用系统内置的语音输入服务，无需额外的麦克风权限，并且仅识别已注册的命令模式；模式之外的语音不会转换为代码。用文字说出的数字（例如 'lima'）暂不会转换为数字。

本地协作室（无需联网）
要在没有网络的情况下在同一个房间里一起工作：打开主菜单中的协作，然后打开本地协作室部分。一部手机开启会话（IDE 会显示本地 IP 地址和 6 位 PIN），另一部手机使用该地址和 PIN 加入。文本更改以行差异的形式发送，已构建的 APK 可以发送到测试者的手机，测试者手机上的崩溃报告也会被接收回来。一次会话仅限一位朋友；如果两个人同时更改完全相同的行，则采用最后一次更改。PIN 以纯文本形式在本地网络中发送。此房间尚未在真机上测试过。

AI 设置
要设置用于创建应用的 AI 提供商和 API 密钥：在主菜单的设置分组中，点按 AI 设置（连接器按钮旁边）。从可用列表中选择要使用的提供商，并勾选提供商出错时切换模型，这样如果一个模型失败，IDE 会自动尝试同一提供商的下一个模型。点按管理 API 密钥可添加备用密钥（填写名称和密钥，然后点按保存；密钥以掩码显示，仅可见最后 4 个字符）。密钥保存在手机上，除创建应用时发送给所选提供商外，绝不会发送到其他任何地方。注意：目前提供商和密钥的选择仅会被记录并显示在 AI Pembuat Aplikasi 屏幕上——创建应用时仍使用手机上的本地 AI（无需联网）；在线提供商的使用即将推出。

连接器
要分析 APK 然后发送它：在主菜单的设置分组中，点按连接器（AI 设置按钮旁边）。从手机中选择一个 APK 文件，IDE 会读取其内容（包名、版本、活动列表），然后点按发送 APK，通过系统分享菜单发送（例如 WhatsApp 或 Drive）。

语言和语音
要更改应用语言：打开设置，然后打开应用语言，再选择一种语言或跟随系统。主屏幕和大多数屏幕会立即切换到所选语言，无需关闭或重启应用；某些屏幕（例如终端、协作、AI 设置和管理密钥）在重新打开之前仍使用旧语言。如果选择跟随系统，语言将跟随手机系统语言。
