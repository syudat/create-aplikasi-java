欢迎使用 Create Aplikasi by Al Kautsar
Create Aplikasi 是一款可直接在手机上运行的 Android 应用创建应用，无需笔记本电脑。本应用让任何人都能创建自己的 Android 应用，包括刚开始学习创建应用的用户和屏幕阅读器用户。本应用的完整使用指南可在关于本工具界面中查看。

本应用是什么，适合谁使用
Create Aplikasi 是一款在手机上运行的 Android 应用创建工具。本应用面向任何想创建自己的 Android 应用的人，包括初学者和屏幕阅读器用户。本应用提供代码编辑器、用于测试项目的“运行”按钮、用于生成 APK 的“构建”按钮，以及用于签名和安装 APK 的菜单。

本应用的目的
制作本应用是为了让任何人都能直接通过手机轻松创建自己的 Android 应用。其界面尽可能做得简单，以便新用户也能立即尝试。

如何逐步创建新项目
1. 点击主菜单中的“创建项目”。
2. 选择项目类型：HTML、网站、Java、Kotlin、Compose 或 Python。
3. 输入应用名称，例如：Garuda Decode。
4. 输入包名（package name），例如：com.android.garudadecode。包名必须使用小写字母，并至少由两个以点分隔的部分组成。
5. 输入应用版本，例如：1.0，以及数字形式的版本号，例如：1。如果留空，版本将自动填为 1.0，版本号填为 1。
6. 如有需要，输入最低 SDK 和目标 SDK。如果留空，将使用默认值。最低 SDK 是所支持的最低 Android 版本，例如：21 表示 Android 5.0。目标 SDK 最高为 36（Android 16）。
7. 点击“选择权限”按钮以选择应用权限，例如：INTERNET。INTERNET 权限默认已勾选。只勾选应用确实需要的权限。
8. 如有需要，勾选“使用独立的 64 位和 32 位架构”以减小 APK 大小；如果想使用自己制作的密钥库，请勾选“使用个人签名”。
9. 点击“创建项目”。新项目会保存在 Download/project 文件夹中，并立即显示在“管理项目”中。

可用的项目类型
• HTML：由 index.html、style.css 和 script.js 构成的界面，通过 WebView 运行。直接在手机上构建。
• 网站：带有菜单（首页、关于、联系）的网站，由 index.html、tentang.html、kontak.html、style.css 和 script.js 构成，通过 WebView 运行。直接在手机上构建。
• Java：在手机上构建。MainActivity 位于 app/src/main/java/<package-name>/MainActivity.java。界面来自 app/src/main/res/layout/activity_main.xml，文本来自 app/src/main/res/values/strings.xml，主题来自 app/src/main/res/values/styles.xml。
• Kotlin：可以使用应用内附带的 Kotlin 编译器在设备上构建（离线），或通过 GitHub Actions 构建。MainActivity 位于 app/src/main/java/<package-name>/MainActivity.kt，res 文件与 Java 项目相同。首次构建 Kotlin 较慢，因为编译器体积较大；引用 Kotlin 类的 .java 文件目前还无法构建（.java 文件会先于 .kt 文件编译）。
• Compose：界面使用 Jetpack Compose 创建的现代 Android 应用（不是 XML 布局）。MainActivity 位于 app/src/main/java/<package-name>/MainActivity.kt。Compose 项目通过 GitHub Actions（构建项目菜单，然后选择在线构建）构建，或在 Termux 中用 Gradle 构建，因为 Compose 需要设备上没有的 Jetpack Compose 库。
• Python：应用逻辑用 Python 语言（Chaquopy）编写在 app/src/main/python/main.py 中，并由位于 app/src/main/java/<package-name>/MainActivity.java 的宿主 MainActivity.java 运行。Python 项目可以直接在手机上构建（Chaquopy 运行时已包含在应用中），也可以通过 GitHub Actions 构建。Python 项目的最低 SDK 为 24（Android 7.0）。

更改项目架构
要在不创建新项目的情况下更改现有项目的架构选项，请在主菜单中点按「更改项目架构」，然后选择项目并更改「构建 64 位 APK（arm64-v8a）」或「构建 32 位 APK（armeabi-v7a）」复选框；或者在「管理项目」中长按项目名称并选择「更改架构」，以直接为该项目打开同一屏幕。规则是：如果两个复选框都启用，构建会生成两个单独的 APK，一个 64 位和一个 32 位；如果只启用一个复选框，构建会生成一个在 64 位和 32 位设备上都能继续运行的通用 APK。仅针对一个变体的单独 APK 尚不受支持，因为构建路径只知道拆分或通用选择，但每个变体的选择仍保存在项目内，重新打开屏幕时不会丢失。

Java、HTML、网站、Kotlin、Compose 和 Python 项目的文件结构
Java、HTML、网站、Kotlin、Compose 和 Python 项目的结构与一般 Android 项目相同。在 app 文件夹内有 src 文件夹，src 内有 main 文件夹。在 main 文件夹内，AndroidManifest.xml 位于 java 文件夹旁边，res 文件夹包含 layout/activity_main.xml 和 values/strings.xml 以及 values/styles.xml；对于 HTML 和网站，还有 assets 文件夹，其中包含 index.html（网站还有 tentang.html 和 kontak.html）。HTML 和网站项目在 app/src/main/java/<package-name>/MainActivity.java 也有自己的 MainActivity，它在 WebView 中加载 index.html 并成为 AndroidManifest 中的启动器。Python 项目的 Python 代码位于 app/src/main/python/main.py，宿主 MainActivity.java 位于 app/src/main/java/<package-name>/MainActivity.java。AndroidManifest.xml、布局、字符串和样式都可以在编辑器中打开和修改，就像 MainActivity 一样。清单文件仍位于 app 文件夹旁边的旧项目仍然可以构建，因为在构建时，应用会先检查 app/src/main/ 中的 AndroidManifest.xml，然后是 app 文件夹旁边的那个，最后是项目数据文件。

权限规则（重要）
创建项目时勾选的权限只会记录在一个地方，具体取决于项目类型。对于 Java、HTML、网站、Kotlin、Compose 和 Python 项目，勾选的权限仅记录在位于项目文件夹内 app/src/main/ 中、java 文件夹旁边的 AndroidManifest.xml 中。Java、HTML、网站、Kotlin、Compose 和 Python 项目的项目数据文件不包含权限列表。如果选择 Java 然后勾选 INTERNET 和 CAMERA，那么记录在 AndroidManifest.xml 中的只有 INTERNET 和 CAMERA，不会包含其他权限。构建时，应用从相同位置读取权限：对于 Java、HTML、网站、Kotlin、Compose 和 Python 项目，从 app/src/main/ 中的 AndroidManifest.xml 读取（如果没有，则对于旧项目从 app 文件夹旁边的 AndroidManifest.xml 读取），对于旧项目则从项目数据文件读取。

如何使用编辑器
打开“管理项目”，点击项目名称以打开编辑器。在编辑器中，可以打开文件、编写代码并保存更改。对于 Java、HTML、网站、Kotlin、Compose 和 Python 项目，文件排列在 app/src/main 文件夹内。要共享项目，请使用导出 ZIP（见下文部分）。

如何运行项目
在编辑器中，点击“运行”以测试项目。对于 HTML 和网站项目，运行的是通过 WebView 打开的 index.html。如果发生错误，请阅读错误消息，修复代码，然后再次运行。

如何构建 APK
在编辑器中，点击“构建”。有两种构建方式。第一种，在设备上构建：直接在手机上构建，无需互联网，适用于 HTML、网站、Java、Kotlin 和 Python 项目。第二种，通过 GitHub Actions 在线构建：通过互联网在 GitHub 上构建，可用于所有项目类型。Compose 项目只能用第二种方式（在线构建）构建，或在 Termux 中用 Gradle 构建，因为 Compose 需要设备上没有的 Jetpack Compose 库。第一次构建的结果尚未签名。之后应用会对其签名：使用内置密钥自动签名；或者如果在创建项目时勾选了“使用个人签名”复选框，则使用个人签名。

如何安装 APK
APK 准备好后，点击“安装”进行安装。在 Android 8 及更高版本上，手机会先要求“允许来自此来源”，因为本应用安装的是 Play 商店之外的 APK。在“设置”中启用该权限一次，然后返回应用：安装将自动继续，无需再次点击“安装”。如果“安装”按钮未出现，请确保构建已完成且 APK 已生成。

如何签名应用
每个 APK 都必须签名才能安装。有两个选项。第一，内置密钥：应用自动自行签名，您无需做任何事情。第二，个人签名：先通过主菜单中的“创建密钥库”菜单创建密钥库，妥善保存其密码，然后在创建项目时勾选“使用个人签名”。密钥库保存在 Download/project/signing 中。

将项目导出为 ZIP
提供导出 ZIP 是为了让项目可以与朋友共享。操作方法：在“管理项目”中，长按项目名称，然后选择“导出 ZIP”。结果保存在 Download/project/<ProjectName>.zip 中。bin 文件夹不包含在内，因此体积较小，只有几十 KB。该 ZIP 文件可以发送给朋友或上传到 GitHub。

JAWS 扩展
JAWS 扩展使用 Jieshuo (CSR) 的扩展引擎，而不是其屏幕阅读器。这样，即使使用者使用 TalkBack，设计仍然可以运行。操作方法：在主菜单中打开 JAWS 扩展。由于自动点击会自行运行，必须先在无障碍设置中启用该服务。之后，就可以创建新设计：输入设计名称，点击“确定”，然后填写其框格。

点击列表单独存放以保持整洁
在一个设计中有两个框格：脚本框和点击列表框。按钮列表单独保存在文件 daftar_klik.txt 中，每行一个名称。其内容示例：tombolSimpan、tombolHapus、tombolBuka。要打开某个应用，只需在该列表中写入 >WhatsApp。尚未拥有 daftar_klik.txt 文件的旧设计将显示该默认示例。

提供的简单函数
• klikTombol("tombolSimpan") — 根据按钮的文本点击一个按钮。
• klikDaftarTombol(daftar) — 点击 daftar_klik.txt 中的列表，每行一个按钮，按顺序执行，然后告知有多少个成功、多少个未找到。
• bukaAplikasi("WhatsApp") — 根据名称打开一个应用，或者在列表中写入 ">WhatsApp"。
• klik(540, 1200) — 在屏幕坐标处点击。
所有函数都先做得简单。等您熟悉之后，以后可以添加其他函数。

关于屏幕阅读器
本应用的设计对屏幕阅读器友好。每个输入字段都有标签和填写示例，所有按钮无需复杂手势即可触及。JAWS 扩展的设计使其即使在使用者使用 TalkBack 时也能继续运行，因为使用的是其扩展引擎，而不是其屏幕阅读器。

隐私与安全
项目和密钥库保存在您的手机上。GitHub 令牌仅用于在线构建，并保存在本应用内。不要与任何人共享您的令牌或密钥库密码。如果使用个人签名，请将密钥库及其密码保存在安全的地方，因为如果丢失，旧的 APK 将无法用同一签名更新。

要求
Android 5.0 或更高版本。存储权限：在 Android 11 及更高版本上使用所有文件访问权限，在 Android 10 及更低版本上使用普通存储权限（读/写存储），因为 Android 10 没有所有文件访问权限。在设备上构建需要配备 ARM 处理器（32 位或 64 位）的手机。通过 GitHub Actions 在线构建需要互联网和 GitHub 令牌。Kotlin 项目可以在设备上构建，但首次构建较慢且占用更多内存，因为 Kotlin 编译器体积较大。Compose 项目通过 GitHub Actions 构建，或在 Termux 中用 Gradle 构建。Python 项目需要 Android 7.0 或更高版本（最低 SDK 24），且生成的 APK 更大，因为它包含 Python 运行时 (Chaquopy) 及其标准库。

终端
主屏幕上的“终端”菜单会在本应用内打开一个终端。可以使用 ls 等命令查看项目文件夹的内容，用 cd 在文件夹之间移动，用 git 管理代码。命令输出以屏幕阅读器可读的文本形式显示，并且有一个“朗读结果”按钮可收听最后一次结果。此终端使用手机的系统 shell，因此 nano 和 vim 等交互式程序目前还无法在此使用。

许可证（付费版）
要出售应用，请在创建项目时勾选“启用许可证”，然后输入您的 WhatsApp 号码。构建出的应用在首次打开时会要求输入许可证代码：使用者看到其设备 ID，点击“发送设备 ID”按钮将该 ID 发送到您的 WhatsApp，然后您回复许可证代码。许可证代码由设备 ID 和项目密码（项目数据文件中的 lisensi_seed）计算得出——请妥善保存该密码，不要共享。输入正确的代码后，应用将打开，并且不再要求输入代码。

自动图标制作器
新项目的图标仍然是透明的，因此主菜单中提供了图标制作器。操作方法：点击“图标制作器”，写下一到两个字母（例如应用名称的首字母），选择背景颜色和文字颜色，查看预览，然后点击“保存到项目”将该图标用于所选项目，或点击“保存到下载”在其他地方使用其 PNG 文件。创建项目后，应用还会提供创建图标的选项。项目的旧图标可以随时从“管理项目”中的项目菜单更换（长按项目名称，然后选择“更换图标”）。

现成的项目模板
如果您不想从空白项目开始，请在创建项目时选择模板：计算器 (Java)、笔记 (Java)、待办事项列表 (Kotlin)、网页计算器 (HTML)、个人主页网站（网站）或计数器 (Compose)。选择模板会自动将项目类型更改为与该模板一致，并且项目会使用现成的初始代码创建——只需运行或修改即可。如果在选择模板后再次手动更改项目类型，模板将被取消，项目恢复为空白。对于 HTML 和网站模板，模板会替换 index.html 的内容，包括在表单中输入的 HTML 脚本。

备份和恢复项目
为了不丢失项目，提供了备份功能。操作方法：在“管理项目”中，长按项目名称，然后选择“备份”。备份以 ZIP 形式保存在 Download/backup 文件夹中，名称为项目名和日期，例如：GarudaDecode-2026-11-14-123045.zip。其内容与导出 ZIP 相同（项目的全部内容，不含 bin 文件夹）。要恢复：打开“管理项目”中的菜单，选择“恢复备份”，然后选择备份文件。如果项目名称已存在，应用会询问：覆盖旧项目，还是以新名称保存。

共享和导入项目
要与朋友共享项目：在“管理项目”中，长按项目名称，然后选择“共享”。项目会以 ZIP 形式通过共享应用（WhatsApp、Telegram 等）发送。要接收朋友的项目：打开“管理项目”中的菜单，选择“导入项目”，然后选择 ZIP 文件。该 ZIP 文件必须包含项目数据文件——如果没有，该文件会被拒绝并给出明确的消息，因为该文件不是 Create Aplikasi 项目。如果项目名称已存在，应用会询问：覆盖旧项目，还是以新名称保存。

项目搜索和筛选
如果项目已经很多，“管理项目”中有搜索框和类型筛选器。在搜索框中输入项目名称，列表会立即筛选（不区分大小写字母）。类型筛选器将列表限制为一种类型：全部、HTML、网站、Java、Kotlin、Compose 或 Python。每个项目的菜单仍可像往常一样从已筛选的列表中打开。

用语音构建应用
如果不想打字，可以使用语音：在主菜单中点按语音构建，然后说出命令。可以说的命令有："Buat proyek kalkulator"、"Bangun proyek Kalkulator"、"Buka proyek Kalkulator"、"Jalankan proyek Kalkulator"、"Daftar proyek"、"Buka ikon"、"Kembali"和"Bantuan"。应用会用语音和文字回答，因此不看屏幕也能使用。语音识别使用手机内置的语音识别应用（免费；如果安装了印尼语语言包，可以离线运行）。如果手机没有语音识别器，可以在同一屏幕的文本框中输入命令。

AI 应用构建器
在 AI 应用构建器屏幕上输入或口述你想要的应用，例如：「带保存按钮的记事应用」。应用会在手机内部分析关键词（无需联网、免费），然后从最匹配的模板创建真实项目：计算器、记事、任务列表、网页计算器、个人资料网站或计数器。如果你的描述还没有匹配的模板，应用会创建一个空项目并如实说明——不会假装理解。AI 创建的项目可以直接在管理项目中打开。

实时预览到朋友的手机
要在构建前向朋友展示项目：在管理项目中长按项目名称，然后选择预览到朋友的手机。应用会创建一个小型预览包，其中包含项目的主要文件（index.html、MainActivity 或 main.py），以及带有说明的 BACA-SAYA.txt 和 info.txt。预览包以 ZIP 形式通过 WhatsApp 或 Telegram 发送。收到它的朋友可以立即打开预览：HTML 页面在浏览器中打开，Java/Kotlin/Python 代码以文本形式阅读。

项目市场
项目市场包含内置示例项目，只需点按一次即可安装到项目文件夹：计算器、记事、任务列表、网页计算器、个人资料网站、计数器、数字时钟和网页测验。在线市场（从互联网下载示例）尚不可用，因此这个市场包含的示例都已在应用内部。已安装的项目可以像自己创建的项目一样在管理项目中打开和修改。

直接协作
要与朋友一起开发项目：在主菜单中打开协作，选择项目，写下更改说明（改了什么），然后按分享以协作。项目以 ZIP 形式连同其中的 CATATAN.txt 文件一起发送。你的朋友进行修改后把 ZIP 发回；你按接收回复，先阅读更改说明，然后选择应用以覆盖旧项目，或在改变主意时选择取消。没有 CATATAN.txt 的 ZIP 不是协作包——对于普通项目 ZIP，请在管理项目中使用导入项目。

自动应用翻译器
要把应用中的文本翻译成其他语言：在主菜单中打开应用翻译器，选择项目和目标语言（英语、阿拉伯语或爪哇语），然后按翻译。词典已在手机内部（无需联网、免费），包含日常常用词；来自 strings.xml、布局和代码的文本会被读取然后翻译。结果写入 values-语言/strings.xml 文件夹（如果项目有 strings.xml），翻译-语言.txt 报告写入项目文件夹。词典中还没有的词会保持原样并被报告——这样你就知道哪些词还需要自己翻译。

无代码游戏制作器
要不写代码制作游戏：在主菜单中打开无代码游戏制作器，选择游戏类型（猜数字、测验或抓星星），填写游戏名称、数量（关卡/题目/星星）和获胜消息，然后按创建游戏。游戏会作为真实项目创建，可以直接在管理项目中运行，并像其他项目一样构建为 APK。

自动应用测试
要在构建前检查项目：在管理项目中长按项目名称，然后选择自动测试。IDE 无需构建 APK 即可检查 10 项内容——必需文件是否存在（项目数据文件、清单、主文件、布局、字符串）、包名和版本、使用的权限、图标以及代码括号的平衡。结果按每项显示（通过/失败并附消息），由 Jieshuo 朗读。先修复所有失败的项，然后再按构建项目。

AI 代码检查器
要检查项目代码中常出问题的地方：在主菜单中打开代码检查，选择项目，然后按代码检查。检查器在手机内部运行（无需联网），查找未使用的变量、空函数、明显死循环、直接写在代码中的文本（放在 strings.xml 中更好）、危险权限和 API、TODO/FIXME 标记以及动态执行。每项发现都包含文件名、行号和修复建议。此检查器基于模式，不是真正的 AI——不遵循模式的问题仍可能漏网。

互动学习模式
要一步步学习制作应用：在主菜单中打开学习。共有 5 课：创建第一个项目、添加按钮、更改颜色、添加声音和构建 APK。点按一课阅读其说明和练习任务，完成任务，然后按检查任务——IDE 会真正检查任务是否已完成（通过扫描手机上的项目和 APK）。通过的课程会被标记为完成并保存。

云同步
要把项目备份到云端：在主菜单中打开云同步。本地备份将项目 ZIP 带时间戳保存到 Download/cloud 文件夹，并可随时从备份列表恢复。GitHub 备份将项目 ZIP 上传到你的私有仓库（使用 GitHub 设置中的令牌），并可重新下载。这是手动备份和恢复——完整的自动双向同步需要服务器，因此尚不可用。

自动后端构建器
要不写服务器代码创建后端：在主菜单中打开后端构建器，选择后端类型（记事、任务列表或留言板），填写项目名称，然后按创建后端。IDE 会创建一个真实的 HTML 项目，包含表单页面和保存在手机本地存储（localStorage）中的数据列表——数据会被保存，运行应用时可以再次读取。此后端在一台手机上运行；由于没有互联网服务器，两台手机尚不能共享相同数据。

自动主题设计器
要给项目设置颜色主题：在主菜单中打开主题设计器，选择项目和主题（浅色、深色、蓝色、绿色、红色或紫色）。预览显示主题的六种颜色（主色、深主色、强调色、背景、文本、次要文本），由 Jieshuo 朗读。按应用主题——IDE 将 colors.xml 和 styles.xml（app_theme 样式）写入项目，运行或构建项目时直接使用。

动画制作器
要给项目添加动画：在主菜单中打开动画制作器，选择项目、动画类型（淡入、滑动、旋转、弹跳或脉动）、时长（100 到 10000 毫秒）和目标（按钮、文本或图片），然后按创建动画。IDE 会写入真实的动画文件（Java/Kotlin/Compose 项目为 res/anim/anim_<类型>.xml，HTML/网站项目为 animasi.css），并附屏幕上显示的示例用法代码。

操作录制器
要自动重复工作：IDE 会记录已执行的操作（打开项目、运行、构建、导出、备份、创建项目、保存文件）。在主菜单中打开操作录制器查看已记录操作及其计划的列表，然后按重播——IDE 会重新执行可自动化的操作（备份和创建项目就地执行；运行、构建和导出打开各自的主屏幕；打开和保存打开编辑器）。无法自动化的操作会被跳过并在最后报告。

自动安全
要检查项目的安全性：在主菜单中打开自动安全，选择项目，然后按检查安全。IDE 在本地检查 8 项内容（无需联网）：危险权限（位置、短信、通话、相机、麦克风、联系人）、通过 HTTP 发送数据、发送短信、拨打电话、直接写在代码中的密码或密钥、未受保护的 WebView、未经许可导出的组件以及未加密的 http 地址。每项发现都会根据修复建议被评为安全、警告或危险级别，摘要由 Jieshuo 朗读。

离线 AI
要离线使用文本和代码辅助工具：在主菜单中打开离线 AI。共有 4 个工具：修复文本（大写、标点和双空格）、文本摘要（提取最重要的 3 句话）、创建应用名称（根据所写的描述）和建议变量名（在项目中查找 1-2 个字母的变量名）。这些是手机内部的简单规则，不是真正的 AI 模型。文本修复结果可以通过应用按钮应用到项目的 strings.xml。

小部件和壁纸制作器
要创建主屏幕小部件：在主菜单中打开小部件与壁纸，选择项目，填写小部件文本，然后按创建小部件。IDE 会写入 WidgetSaya.java、小部件布局、小部件信息，并向项目的 AndroidManifest.xml 添加接收器——构建项目，然后从手机主屏幕安装小部件。对于壁纸：填写文字以及背景和文本颜色，制作预览，然后将其保存为 PNG 到 Download 文件夹，或直接设为手机壁纸。

社交媒体集成
要向应用添加分享按钮：在主菜单中打开社交媒体集成，选择项目，然后添加分享到 WhatsApp、Facebook 或 Telegram（或三者同时）。IDE 会将真实的分享代码写入项目的主文件（MainActivity 或 index.html）。分享测试按钮会从 IDE 打开带有示例文本的分享选择器，以便在构建应用前感受流程。

从图片创建应用
要从图片创建图库应用：在主菜单中打开从图片创建应用，从图库中选择图片。IDE 会分析图片尺寸和主色调，然后创建真实的图库应用项目：图片被复制到项目的 assets，主题颜色取自图片的主色调，应用名称取自图片文件名。打开管理项目运行或构建该图库应用。

交互式终端（VT 解析器）
要在终端中使用交互式程序：在主菜单中打开终端，然后运行 nano、vim、top 或 htop。终端现在使用 VT 解析器（24 行 x 80 列网格屏幕），因此这些程序能正确显示——光标移动、行被清除、屏幕像真实终端一样变化。有专用的 Tab、上箭头、下箭头和 Esc 按钮来控制交互式程序。输出仍是 Jieshuo 可以阅读的文本；按读出屏幕可听到最后一行。

Terminal Exec（应用二进制）
要从终端运行应用文件夹中的二进制文件（例如 aapt2、ECJ、D8）：像往常一样输入命令。IDE 使用 libkautsarexec.so，使应用文件夹中的二进制文件可以在 Android 10 及更高版本上执行。按终端中的 Exec 测试检查二进制 exec 路径是否在此手机上工作——结果会如实显示。如果 exec 被系统阻止，系统命令和 shell 脚本仍可运行；请通过构建项目菜单运行二进制文件。

Terminal 保持运行 (KeepAlive)
要在切换到其他屏幕时保持 shell 继续运行：打开终端，运行命令，然后按返回或切换到其他屏幕——shell 不会终止，终端通知会一直显示，以便你一键返回。已运行的命令保存在历史记录中（历史记录按钮，或命令字段中的上/下箭头），常用命令可以保存为收藏（收藏按钮）。完成后按关闭 shell，使 shell 真正结束。项目菜单和编辑器菜单中也有在 Terminal 中构建按钮：终端会在项目文件夹中打开，并已填好构建命令。

安装 Terminal 工具（试用）
一项仍在试用的功能：终端中有安装 Terminal 工具按钮，可从开发者 alat-termux 仓库（github.com/syudat/alat-termux）中的镜像安装 Termux 环境，这是除从 Termux 官方发布获取的安装 Termux 按钮之外的另一条途径。镜像内容与官方发布完全相同，安装期间用 SHA-256 校验。环境安装后，即可使用 pkg update 和 pkg install 命令，仓库中的附加工具也会安装到终端：info-terminal 查看环境信息，bersih-terminal 清理缓存，cadangkan-proyek 将项目文件夹归档为一个带日期的 tar.gz 文件。此后应用会自动从 Termux 官方仓库安装基础 Linux 软件包（git、python、curl、wget、nano、openssh、zip、unzip）和带签名的 APK 构建工具（openjdk-21、kotlin、gradle、ecj、aapt2、d8、apksigner、clang、cmake、ninja、make），使终端立即准备好构建应用。下载大型软件包（数百 MB）可能需要很长时间。安装进行时，进度和命令输出显示在终端主屏幕上，最终结果由屏幕阅读器朗读。如果软件包安装尚未完成，请再次按安装 Terminal 工具继续。

全语音模式
要完全用语音控制 IDE：在主菜单中打开全语音模式，然后按开始聆听。IDE 会持续聆听——无需为每个命令按键——执行命令并用语音回答。共有 26 条命令：创建、构建、打开、运行、列出、搜索、删除、测试、检查、导出、备份、分享、制作图标、翻译、在终端中构建、读出屏幕、打开所有屏幕（包括安全、离线 AI、小部件、社交媒体、游戏、学习、云端、后端、主题、动画、录制器）、返回、关闭和帮助。如果保持模式开启，再次打开此屏幕时聆听会自动继续。按停止聆听关闭此模式。如果手机没有语音识别服务，命令仍可在文本框中输入。

代码翻译器
要离线在语言之间翻译代码：在主菜单中打开代码翻译器，选择项目，选择源文件（.java/.kt），然后选择方向：Java 转 Kotlin。按翻译——结果会连同无法翻译的行的报告一起显示（这些行保持原样并被标记）。按保存结果将新文件（名称-翻译.java/.kt）写入同一文件夹；原始文件永远不会被覆盖。这是模式规则翻译器，不是编译器——使用前务必检查结果。

应用内 Git
要在 IDE 内不使用 Termux 而使用 Git：在主菜单中打开应用内 Git，选择项目，然后按创建 Git 仓库在该项目中创建本地仓库（.git）。按检查状态查看与上次提交相比新增、更改或删除的文件；填写提交消息后按 Commit 保存项目快照；按查看提交日志查看提交历史。推送到 GitHub 和从 GitHub 拉取使用通过 GitHub 令牌的快照（pembuat-aplikasi-build 仓库）——不是 git 协议。克隆、推送（系统 git）和拉取（系统 git）仅在手机上安装了 git 二进制文件时运行（通常没有）。这不是完整的 git：没有合并、分支或差异——每次提交保存项目的完整 ZIP 快照。

广告制作器
要向已构建的应用添加广告：在主菜单中打开广告制作器，选择项目、提供商（AdMob、Unity Ads 或 AppLovin）和广告类型（横幅、插页式或奖励式）。如果已有广告单元 ID 请填写——留空表示使用测试 ID（AdMob 使用 Google 官方测试 ID；Unity 使用示例 Game ID；AppLovin 使用空白）。按创建广告代码查看 Java 和 Kotlin 代码及指南；按保存到项目将所有内容写入项目中的广告-<提供商>-<类型>.txt 文件。这是代码模板 + 指南，不是广告 SDK——SDK 不包含在 IDE 中；只有在创建提供商帐户、创建广告单元、粘贴自己的单元 ID 并在项目的 build.gradle 中添加 SDK 依赖后，真实广告才会显示。

儿童模式
要与孩子一起使用 IDE：在主菜单中打开儿童模式。屏幕以大按钮简化，只有 4 个安全操作：创建项目（来自安全模板：计算器、猜数字、测验、抓星星）、打开项目、运行和学习。此屏幕上没有删除、导出、备份或令牌设置按钮。首次进入时，创建 4 位 PIN——家长用该 PIN 退出儿童模式（退出儿童模式按钮或返回按钮）。此 PIN 是针对小孩子的轻度保护，不是真正的安全措施。

Wear OS 和 TV 应用制作器
要创建手表应用（Wear OS）或电视应用（Android TV）：在主菜单中打开 Wear OS 和 TV，选择目标（Wear OS、Android TV 或两者）。填写项目名称后按创建 Wear/TV 新项目——IDE 创建 Java 项目然后进行调整——或选择已有项目后按应用到此项目。调整内容：清单中的 uses-feature、电视的 LEANBACK_LAUNCHER 类别 + 横幅，以及调整后的 activity_main.xml 布局（Wear：小屏幕；TV：适合 D-pad 的大屏幕）。完整说明写入项目中的 wear-tv.txt。这是项目模板——构建 + 测试仍需要 Wear OS 或 Android TV 设备/模拟器；电视横幅（banner.png 320x180）不会自动创建，必须自己添加（例如通过图标制作器）。

项目地图
要查看项目的结构：在主菜单中打开项目地图，选择项目，然后按显示地图——IDE 显示文件夹和文件列表及其大小、总大小、按文件类型的大小以及重要文件（主文件、清单、布局、字符串、图标、网页）。按保存 peta-proyek.txt 将同一地图写入项目根目录。bin/ 文件夹（构建结果）和 .git/ 文件夹（本地仓库）不包含在地图中，因为其内容可以重新生成。

APK 大小计算器
要在构建前估算已构建 APK 的大小：在主菜单中打开 APK 大小计算器，选择项目，然后按计算估算。IDE 按类别显示明细（代码/DEX、资源、资产、原生库、清单 + resources.arsc、开销）、总估算、最大的 5 个文件和缩小建议（例如大图片降低分辨率，大音频剪短时长）。这是估算，不是确切大小——实际大小可能因 aapt2 压缩、删除未使用代码（R8）和构建结果资源而有所不同。

APK 分析器
要读取已完成 APK 的内容（如 Android Studio 中的 APK 分析器）：在主菜单中打开 APK 分析器，选择项目，然后按构建结果 APK 分析。IDE 读取该项目 bin 文件夹中最新的 APK，并报告包名、版本、最低和目标 SDK、使用的权限列表、dex 文件数量、按部分划分的大小明细（程序代码、资源、资产、原生库、签名）和最大的 10 个条目。这有助于了解哪部分使 APK 变大，以及已构建应用使用哪些权限。

屏幕尺寸预览
要同时在多种屏幕尺寸上检查项目外观（如 Android Studio 中）：在主菜单中打开屏幕尺寸预览，选择项目，然后按检查屏幕尺寸。IDE 读取项目的所有布局，并报告宽度写为固定值（例如 400dp）且超过 320、360、411 或 480 dp 屏幕宽度的元素，因为在小屏幕手机上此类元素可能被遮挡或溢出。宽度为 match_parent 或 wrap_content 的元素会自动适应屏幕，无需检查。

资源管理器
要在一处查看和管理项目的所有资源（如 Android Studio 中的资源管理器）：在主菜单中打开资源管理器，选择项目，然后按查看资源。IDE 报告按类别划分的文件数量和大小（drawable、layout、values、mipmap 等）、strings.xml、colors.xml 和 styles.xml 的内容。在同一屏幕上，通过填写名称和值，可以向 strings.xml 添加新字符串、向 colors.xml 添加新颜色——名称会被检查，重复会被拒绝，因此 XML 文件不会损坏。

轻量性能监视器
要监视正在运行的应用的 RAM 和处理器使用情况（如 Android Studio 中的 Profiler，轻量版）：在主菜单中打开轻量性能监视器，先运行要检查的应用（例如正在试用的已构建应用），填写其包名——或选择项目后按从项目填写包名——然后按开始监视。IDE 每 2 秒记录一次该应用的 RAM（PSS）和 CPU 以及手机的空闲 RAM；按停止查看平均值和峰值摘要。无需额外权限。在较新 Android 版本中，读取其他应用处理器的访问受系统限制，因此如果 CPU 无法读取，报告会如实说明，RAM 监视继续进行。

无障碍审核
要在发布前检查项目布局是否对屏幕阅读器（TalkBack/Jieshuo）友好：打开主菜单中的无障碍审核，选择一个项目，然后点按加载布局列表并选择一个布局文件。IDE 会读取该 XML 文件，报告没有标签的按钮及其行号、重复使用的标签和相互重叠的元素，然后生成一份焦点顺序记录，如同 Jieshuo 朗读的那样。如果某个按钮没有标签，请填写标签，然后点按自动插入标签——标签会作为 contentDescription 写入布局文件。此检查仅读取布局 XML；Compose 界面和已完成的 APK 暂不扫描。

崩溃剖析
要从具有唯一 ID 的崩溃日志了解应用为何自行关闭，请在主菜单中打开「崩溃剖析」，从日志列表中选择崩溃 ID，然后点按「检查」。IDE 会将日志中的类和行号与项目源匹配，并用印尼语解释原因（例如空引用、尚未请求的权限，或 JSON 错误），并附带代码补丁建议。仅当源行与崩溃发生时完全相同时才点按「应用补丁」；如果已更改，补丁将被拒绝，IDE 会要求您自行检查。对于构建好的应用的崩溃，点按「向项目注入崩溃捕获器」，然后像往常一样构建 APK：该构建好的应用会自行捕获其崩溃并将日志写入手机，该日志可通过「查找构建好的应用崩溃日志」按钮找到。诚实的限制：在 Android 11 及更高版本上将日志复制到公共 Download 文件夹可能因缺少所有文件访问权限而失败。

跨范式转译器
要把简单的 Java 代码转换为 Kotlin，或把简单的 XML 布局转换为 Compose 代码：打开主菜单中的跨范式转译器，选择项目和文件，然后点按预览。IDE 会以文本形式显示转换结果——请先检查，因为无法识别的行会保持原样，而 Java 中的 static 一词在 Kotlin 中会被去掉（使用前请确认其含义）。XML 到 Compose 的转换仅更改文本、提示和方向——大小、颜色和其他属性暂不包括在内。如果结果正确，点按应用到文件以写入目标文件；源文件不会被更改。仅转换安全、常见的模式。

本地微型服务器
要在无互联网的情况下测试需要服务器的应用，请在主菜单中打开「本地微型服务器」，编写路由定义（例如 GET /halo，然后是其 JSON 响应），然后点按「启动服务器」。IDE 会在同一手机上运行小型 HTTP 服务器（仅 HTTP，无 TLS，用于同一 Wi-Fi 网络），并在屏幕上记录每个请求和响应。路由可以使用 {nama} 之类的参数和简单的 API 密钥。服务器也可以打包进构建好的 APK：点按「将服务器打包进项目」，服务器源、资源和清单将被注入项目，因此构建好的应用本身在运行时成为服务器。IDE 中的服务器在其屏幕关闭时停止。

安全审核器
要在发布前检查项目代码中的安全空白，请在主菜单中打开「安全审核器」，选择项目，然后点按「开始扫描」。IDE 会扫描项目代码、清单和配置，并按从高到低的风险报告结果——代码中遗留的 API 密钥、未经许可暴露的组件、启用 JavaScript 及其 JavaScript 接口的 WebView、弱加密（MD5、SHA1、DES）、无 TLS 的 http 地址，以及直接写在代码中的密码——连同其文件和行号。对于修复安全的发现（例如将 MD5 改为 SHA-256 或 http 改为 https），点按「应用修复」；对于 API 密钥和密码，IDE 仅显示修复建议，因为替代方案必须由开发者自己决定。扫描现在还分析构建好的 APK 内的真实 DEX 字节码（不仅是代码中的文本模式），因此调用的危险 API 和嵌入 DEX 中的秘密也会被捕获；不遵循模式的空白仍可能逃过扫描——应用前请检查。

界面测试机器人
要通过文本场景自动测试应用屏幕，请在主菜单中打开「界面测试机器人」，选择项目，然后点按「自动创建场景」。IDE 会读取项目清单和布局，并将场景写为文本步骤（点按按钮、填写字段、等待、返回）。点按「运行试运行」以查看场景运行日志及其时间戳——此次试运行仍只是顺序模拟。要进行真实测试，点按「向项目注入测试代理」：IDE 将测试代理连同场景资源注入项目；像往常一样构建 APK、安装，然后打开「测试」图标——该代理在构建好的应用内运行，真正点按按钮、填写真实字段并滚动，然后在屏幕上显示其报告以及捕获的真实崩溃。点按「从项目移除测试代理」可再次移除该代理。代理在应用自身进程内运行，因此不需要无障碍服务或系统自动化。

代码时间旅行
要在不输入 Git 命令的情况下把项目恢复到早期的代码状态：打开主菜单中的代码时间旅行，选择一个项目，填写时间点标签（可以为空），然后点按记录时间点。IDE 会把项目源文件的副本连同它们的哈希值保存在项目内的 .riwayat 文件夹中。时间点列表会显示全部时间点；选择两个时间点，然后点按比较，即可查看添加、更改或删除的文件和函数。点按恢复可回到旧状态——恢复之前，IDE 总是先备份当前状态，因此不会丢失任何内容。点按创建实验副本可把项目复制到新文件夹，在不打扰原始项目的情况下尝试更改。仅记录源文件。

模块工厂
要把项目的一部分打包成可供其他项目使用的模块：打开主菜单中的模块工厂，选择源项目，勾选要打包的界面、类、字符串和权限文件，然后点按打包为模块。IDE 会写入一个 ZIP 归档以及 JSON 元数据（模块名称、版本、使用的字符串和权限）。要把模块安装到另一个项目中，打开模块工厂，选择目标项目，然后点按安装模块并选择模块的 .zip 文件——合并过程会添加字符串和权限而不覆盖已有代码；如果文件名已在目标项目中使用，则不合并该文件。模块不携带库或构建设置。

多态护盾与资源保险库
要在发布前随机化标识符名称并加密项目资源，请在主菜单中打开「多态护盾与资源保险库」，选择项目，然后点按「随机命名与资源加密」。IDE 会扫描源代码中的类名和方法名，创建随机名称映射，在已编译的 DEX 文件内重写这些名称（替代名称与原名称等长以保持所有偏移有效，随后重新计算 DEX 标头的校验和与 SHA-1 签名），用 AES-GCM 加密项目内的 brankas-aset 文件夹中的项目资源文件，并保存加密的恢复映射（perisai-peta.brankas），以便在阅读崩溃日志时恢复原名称。加密密钥现在通过 PBKDF2（20,000 次迭代）从开发者密码派生，不再从项目名称派生。同时用作纯文本、注解名和调试名的名称有意不重写，构建路径中的 DEX 重写插入点仍在等待真机测试。

信任链与环境守护者
要在发布前检查签名密钥链和手机环境，请在主菜单中打开「信任链与环境守护者」，选择项目，然后点按「检查链与环境」。IDE 会根据项目包名构建 5 代密钥链并检查其完整性，通过比较内存中代码段内容与磁盘上的文件来检查真实内存完整性，并报告匿名可执行（RWX）映射、外部库和 memfd 映射，然后扫描自身进程的内存映射和设备属性以查找 Frida、Xposed 或模拟器的痕迹。保险库密钥用 AndroidKeyStore 中的 AES 密钥包装，该密钥在可用时使用硬件安全芯片，密钥轮换现在是真实的，使用架构 v3 签名证书谱系：旧密钥签署向新密钥轮换的证明，APK 用该谱系重新签名。结果是「安全」「谨慎」或「危险」的风险级别，并附有文本证据。如果系统拒绝读取内存，检查将报告为「无法验证」，而不是安全；某个密钥是否真正使用硬件安全芯片只能在真实设备上确认。

文本树布局架构师
要在不看屏幕的情况下设计屏幕，请在主菜单中打开「文本树布局架构师」，选择项目和布局文件，然后点按「检查布局」。IDE 会将 XML 布局作为文本树读取，并大声读出每个元素的位置叙述（例如右下、屏幕宽度的 45%），然后以数学方式报告元素之间的重叠以及在 360 dp 宽度下超出屏幕的元素。现在计算的内容包括 LinearLayout 和简单的 dp 尺寸、完整的 ConstraintLayout（所有约束、偏置、链、参考线、屏障、百分比宽度、0dp match_constraint 和尺寸比）以及 Compose 屏幕（带尺寸修饰符的 Column、Row 和 Box）。只有在运行时变化的 MotionLayout 和 ConstraintSet 仍报告为位置未知，因为它们的值仅在应用运行时存在。

设计系统工作室
要统一所有屏幕和项目中的间距、字体和圆角，请在主菜单中打开「设计系统工作室」，选择项目，编写设计令牌（例如 jarak=8, huruf=16, sudut=12），选择组件，然后点按「生成组件」。IDE 会验证令牌——基础间距 4 至 16 dp、基础字体 12 至 20 sp、圆角 0 至 32 dp、最小触摸区域 48 dp——然后将现成的 XML 组件（komponen-studio.xml）连同 XML 主题（tema-studio.xml）和 Compose 主题（tema-studio.kt）写入项目文件夹。令牌也可以作为命名集保存在项目间共享的令牌库中，一条同步命令会将库的最新令牌应用于使用该集的所有项目。组件以文本形式生成，粘贴到布局中，然后用「文本树布局架构师」检查；平板上的双列调整使用屏幕宽度限定符，而不是运行时设备检测。

语义重构与 AST 导航
要查找定义并重命名符号而不破坏恰好同名的其他代码，请在主菜单中打开「语义重构与 AST 导航」，选择项目，然后点按「扫描项目符号」以查看所有类和方法及其文件和行号。输入符号名称，再次点按「扫描项目符号」以查看其定义和调用它的所有文件。要重命名，输入新名称，点按「重命名预览」以查看每个文件中的出现次数，然后点按「应用重命名」。索引器现在使用手工制作的 AST 解析器（Java 和 Kotlin 子集的词法分析器和递归解析器），因此跨文件的方法重命名得以解析，其他文件中调用者也会更改；将代码块提取为新函数的按钮现在位于此屏幕上。此解析器仍是最小的：非常复杂的泛型、带参数的注解和匿名类按原样扫描，而通过反射和接口的调用不解析。

单步调试器与内存检查器
要在程序流程中间检查变量内容而不从日志中猜测，请在主菜单中打开「单步调试器与内存检查器」，选择项目，编写执行跟踪（每行一步，格式：行号、代码，然后用 | 分隔的变量和值，例如 10|int total = harga * jumlah;|harga=5000, jumlah=3, total=15000），输入断点行号，然后点按「运行调试跟踪」。IDE 会运行到第一个断点，并通过 Jieshuo 大声读出活动行及其变量值。点按「单步执行一行」可前进一步，点按「进入函数」可进入被调用的函数（带调用栈），或点按「继续运行程序」可前进到下一个断点。此跟踪调试器仍遵循已记录或手写的跟踪；其旁有一个纯 Java JDWP 线路协议客户端，可以握手、设置断点、步入、步过和步出，并通过 TCP 或监听模式暂停和继续虚拟机。从普通应用内部停止真实进程仍不完全可能，因为进程的 JDWP 套接字仅通过 adbd 暴露——已验证的路径需要无线调试和通过 shell 启动目标，超出应用自身的能力范围。

离线依赖管理器
要在无互联网的情况下使用第三方库并在构建前避免版本冲突，请在主菜单中打开「离线依赖管理器」，选择项目，然后点按「检查依赖」。IDE 会读取项目的所有 .gradle 文件，检查 Download/brankas-bersama 文件夹中项目间共享的保险库，并解决冲突——如果两个库要求同一构件的不同版本，则使用最高版本并报告冲突。要下载库，输入其坐标（格式：组:构件:版本，例如 com.google.code.gson:gson:2.10.1），然后点按「检查依赖」：在线时，AAR、JAR 或 WHL 文件会真正从 Maven、Google 或 PyPI 下载，并附带其传递依赖图（递归、切断循环、深度可达 25 层），只有成功下载的文件才记录为可用。离线时只能使用共享保险库中已有的库。Maven 版本范围不解析，下载的文件仅用其 SHA-1 检查，没有 PGP 验证。

数据库与存储检查器
要在不编写打印表内容的代码的情况下检查和测试项目数据库内容，请在主菜单中打开「数据库与存储检查器」，选择项目和数据库文件（.db、.sqlite 或 .sqlite3），然后点按「打开数据库」。IDE 会用完整的 SQLite 页面解析器（带溢出页面的 B 树）读取其所有表的架构，并将前 20 行显示为 Jieshuo 大声读出的文本表。编写 SELECT 查询，然后点按「运行查询」（例如 SELECT nama FROM pengguna WHERE kota = 'Makassar'）——查询现在支持 JOIN、GROUP BY、ORDER BY 和 LIKE，在手机上通过真正的 Android SQLite 引擎运行。要更改值，输入行号（1 = 第一行）、列名和新值，然后点按「更改单元格值」——该值将写回 .db 文件。点按「保存备份」可将表的当前状态保存为项目中的 <数据库名称>.cadangan.txt 文件。SharedPreferences 和 DataStore 也可以读取。仍无法读取的内容：加密数据库、未提交的 WAL 更改，以及特殊 DataStore Proto 中的类型化值（仅显示为通用字段视图）。

单元测试工厂与模糊测试
要在分享应用前发现逻辑空白，请在主菜单中打开「单元测试工厂与模糊测试」，选择项目和代码文件，然后点按「创建并运行测试」。IDE 会读取文件中的函数签名，创建普通和边界测试用例（空文本、null、最大数字、奇怪字符），然后真正运行这些测试：项目代码被编译，每个 @Test 方法在 5 秒限制内执行，因此结果是带有实际值的真实通过与失败。模糊测试也在项目函数上真正运行（通过反射，每次调用 2 秒，最多 20 个方法），行覆盖率百分比通过保留原始行号的插桩真正计算。结果报告有多少测试通过和失败、找到多少行代码和函数、创建了哪些测试用例。创建的测试使用与 JUnit 完全相同的 API，但注解和断言定义写在创建的测试文件本身内部，因为真正的 JUnit 库未包含在应用中。

极端设备条件模拟器与内存泄漏审计器
要在系统终止其进程、网络中断、屏幕旋转或省电开启时测试应用的耐久性，请在主菜单中打开「极端设备条件模拟器与内存泄漏审计器」，选择项目，然后点按「运行模拟」。IDE 会运行三个压力场景并附带屏幕旋转模拟，跟踪屏幕关闭后仍保留在内存中的对象，然后报告丢失的数据和泄漏的对象链。保存与恢复状态现在从用户自己的项目源读取，而不是固定示例；本地环回服务器在测试中间真正停止以测量网络中断；获取并分析真实堆转储以比较两个转储并从 GC 根跟踪保留链；应用自身进程在保存状态后真正终止，然后检查重新打开时哪些数据返回。从普通应用仍不可能的事：关闭手机无线电或 Wi-Fi 以及强制停止其他应用——两者都需要系统权限；取而代之的是，后台应用通过 killBackgroundProcesses 终止，其权限已在清单中，屏幕上有诚实的标签。

项目蓝图架构师
要将大型应用想法转变为逐步工作计划，请在主菜单中打开「项目蓝图架构师」，选择项目，编写应用想法（例如带分期付款的小杂货店收银应用），然后点按「创建蓝图」。IDE 会构建模块、文件列表和小里程碑，然后将其保存为项目文件夹中的 cetak-biru.txt。每次完成一个里程碑时，点按「将下一个里程碑标记为完成」，或点按「加载已保存的蓝图」以重新打开已保存的蓝图。如果在「AI 设置」中选择了活动的 AI 供应商且其密钥可用，蓝图由该供应商构建；如果没有密钥或无法访问供应商，IDE 会回退到离线关键词模式并诚实地说明该限制。供应商回答仅检查格式（模块和里程碑存在），不检查内容的正确性——构建前务必审阅蓝图。

代码逻辑流程讲述者
要在不逐行聆听语法的情况下理解长代码，请在主菜单中打开「代码逻辑流程讲述者」，选择项目和代码文件，然后点按「代码叙述」。IDE 会将每一行转换为印尼语句子（例如如果总和大于 100000，则运行下一个块），显示方法之间的调用图和方法之间的数据流分析（传递、使用或忽略的值），并标记微妙的潜在错误及其行号——用 == 比较的 String、打开后未关闭的流，以及在两个不同方法中写入的变量。如果在「AI 设置」中选择了活动的 AI 供应商，也可获得该供应商的流程摘要；如果不可用，屏幕使用离线叙述并说明该限制。叙述、调用图和数据流使用离线文本模式分析，而不是完整的 AST 解析器——开括号在单独行上的方法、类字段和通过反射的调用不被跟踪——数据竞争警告可能出现在实际上仅交替使用的变量上。

应用包工厂与 Play 商店就绪检查
要直接从手机为 Google Play 商店准备应用，请在主菜单中打开「应用包工厂与 Play 商店就绪检查」，选择项目，然后点按「构建 AAB 包」。IDE 会根据项目清单、资源和资产以及真实的 BundleConfig.pb 构建 .aab 文件，验证包结构，然后将包拆分为真实的变体 APK（基础、按架构、按语言和通用），其大小从该拆分中测量，而非估计。包用与签署 APK 相同的项目密钥以 JAR v1 签署，其签名链经密码学验证。此屏幕还会审计 Play 就绪情况——目标 SDK 低于 35 标记为「高」，因为 Play 商店要求 35 或更高，缺失的 64 位库也标记为「高」。真正的 bundletool 无法在设备上运行，因为 bundletool 需要 JVM，而 Android 没有 JVM；上述路径是设备上最接近的真实路径。

OTA 更新引擎与分阶段发布
要发送小修复而不强迫用户重新下载整个 APK，请在主菜单中打开「OTA 更新引擎与分阶段发布」，选择项目，编写旧版本和新版本的内容，然后点按「创建补丁包」。IDE 会计算差异并创建补丁包（patch-ota.zip）以及新内容的 SHA-256 指纹，然后检查此设备是否处于首批 10% 发布阶段。补丁现在支持任何文件上的二进制增量（包括 DEX 和 APK），用 RSA-2048 签名打包，并在应用前用受信任的公钥验证，可以从开发者服务器及其发布列表下载；如果应用失败，旧文件保持完好。在运行中的应用上应用补丁通过用项目密钥重新签名和 PackageInstaller 完成，因为从内部替换正在运行的进程的代码是不可能的——APK 已锁定，DEX 已加载。

团队代码评审工作室
要审查同事的更改并解决合并冲突而不阅读 Git 箭头标记，请在主菜单中打开「团队代码评审工作室」，选择项目，输入三个文本版本（基础、本地、同事），然后点按「打开团队评审」。IDE 根据 Java 语法单元合并三者——同一行的两处更改但在不同语句中不再视为冲突——并将每个冲突显示为投票选项：使用本地版本、使用同事版本，或合并两者——结果行插入原始冲突位置以保持顺序正确——然后将结果写入项目中的 gabung-hasil.txt。下面是项目任务板：输入任务标题，然后点按「添加任务」；任务作为文本保存在项目内的 .tugas 文件夹中，并通过应用内 Git 中的提交同步，因此可以从任何提交历史重新读取任务板。此语法分割器不是完整的 AST 解析器，应用内 Git 为每次提交保存完整快照；没有专用同步服务器。

代码结构听写
要在编辑器内用语音编写代码：先在编辑器中打开一个项目，然后点按代码结构听写按钮。用印尼语说出命令，例如 buat fungsi tambah dengan parameter a angka dan b angka、buat kelas Mobil 或 buat variabel teks nama sama dengan Budi——IDE 会把语音转换为语法正确的 Java、Kotlin、Python 或 Compose 代码块，并插入到光标位置，然后通过 Jieshuo 朗读简短摘要。听写使用系统内置的语音输入服务，无需额外的麦克风权限，并且仅识别已注册的命令模式；模式之外的语音不会转换为代码。用文字说出的数字（例如 'lima'）暂不会转换为数字。

本地协作室（无需联网）
要在没有网络的情况下在同一个房间里一起工作：打开主菜单中的协作，然后打开本地协作室部分。一部手机开启会话（IDE 会显示本地 IP 地址和 6 位 PIN），另一部手机使用该地址和 PIN 加入。文本更改以行差异的形式发送，已构建的 APK 可以发送到测试者的手机，测试者手机上的崩溃报告也会被接收回来。一次会话仅限一位朋友；如果两个人同时更改完全相同的行，则采用最后一次更改。PIN 以纯文本形式在本地网络中发送。此房间尚未在真机上测试过。

AI 设置
要设置用于创建应用的 AI 供应商和 API 密钥，请在主菜单的设置组中点按「AI 设置」（「连接器」按钮旁）。从可用列表中选择要使用的供应商，并勾选「提供商出错时切换模型」，以便一个模型失败时 IDE 自动尝试同一供应商的下一个模型。点按「管理 API 密钥」以添加备用密钥（输入名称和密钥，然后点按「保存」；密钥以掩码显示，仅最后 4 个字符可见）。密钥保存在手机上，创建应用时除所选供应商外绝不发送到任何地方。所选供应商现在真正被「项目蓝图架构师」和「代码逻辑流程讲述者」使用；在「AI 应用创建器」屏幕上创建应用仍使用手机上的本地 AI（无互联网）。

连接器
要分析 APK 然后发送它：在主菜单的设置分组中，点按连接器（AI 设置按钮旁边）。从手机中选择一个 APK 文件，IDE 会读取其内容（包名、版本、活动列表），然后点按发送 APK，通过系统分享菜单发送（例如 WhatsApp 或 Drive）。

语言和语音
要更改应用语言：打开设置，然后打开应用语言，再选择一种语言或跟随系统。主屏幕和大多数屏幕会立即切换到所选语言，无需关闭或重启应用；某些屏幕（例如终端、协作、AI 设置和管理密钥）在重新打开之前仍使用旧语言。如果选择跟随系统，语言将跟随手机系统语言。

每个项目的默认签名和防篡改
自 5.7 版本起，不使用个人签名的项目会使用该项目专属的内置密钥签名（在项目内的 tanda-tangan-bawaan 文件夹中创建一次，之后继续使用），因此内置签名因项目而异——不再是所有应用共用一个密钥。请勿删除 tanda-tangan-bawaan 文件夹：没有该密钥，新 APK 无法覆盖同一项目的旧 APK。每个项目的设置（独立架构、个人签名、防篡改、选定的 keystore、SDK）现在保存在项目内的 settings.gradle 文件中，每次构建项目时都会重新读取。在设置中，签名类别里有已构建应用防篡改复选框：如果启用，设备上的已构建应用每次打开时都会检查自己的签名和 dex 内容；如果被重新签名或被他人修改，应用会拒绝运行。Frida/Xposed 等调试器和注入工具也会被检测到，应用窗口会被锁定以防屏幕录制。

演示视频制作器
要为已构建的应用制作演示视频：在主菜单中打开演示视频制作器，选择项目，填写视频标题，然后按创建演示视频脚本——IDE 会写入包含 5 个标准场景（开场、主界面、功能 1、功能 2、结尾）以及旁白文本和每个场景时长的 video-demo.txt。按创建 HTML 幻灯片可从项目图片（图标 + 如有的截图）创建每 5 秒自动切换的 video-demo.html。这不是 .mp4 视频——要制作真实视频，请在手机浏览器中打开 video-demo.html 然后录屏，或在录制正在运行的应用时朗读 video-demo.txt 中的旁白。

Android Studio 风格的新外观
IDE 的外观现在已整理得像 Android Studio（仅外观——所有按钮、菜单和流程与以前完全相同）：浅灰色背景、粗黑屏幕标题、带白色文本的蓝色按钮和细边框的白色输入框。主菜单在视觉上分组（构建器功能、云端、主题及其他、语音、代码与新功能、工具），按钮顺序不变。终端仍使用像 Android Studio 中终端窗口一样的深色面板，代码编辑器仍保持白色背景和黑色文本。所有文本仍可由 Jieshuo 清晰朗读。

设置
要设置应用：在主屏幕上打开选项菜单，然后按设置。其中有 12 个类别：GitHub 设置（安全、个人签名、构建历史和 GitHub 令牌）、设备上构建 APK 设置（在设备上保存 keystore 密码和构建历史）、主题（应用颜色）、签名（为个人签名创建 keystore 和已构建应用防篡改复选框）、项目文件夹（项目文件夹位置）、语言和语音（界面语言和语音模式语速）、文本大小和显示（编辑器字体大小）、构建（创建项目屏幕的默认目标 SDK 和默认架构拆分）、通知（构建完成时的声音）、自动备份（项目备份计划）、开发者资料（捐赠屏幕上显示的姓名、WhatsApp 号码和帐户）以及隐私与数据（重置设置和删除应用数据）。每个类别都有返回上一页按钮，可返回类别菜单。新保存的（尚未应用的）设置会在屏幕上如实说明。

向开发者捐赠
要捐赠或向开发者打招呼：按主屏幕上关于工具按钮旁边的向开发者捐赠按钮。捐赠屏幕上有复制 BRI 帐户按钮——按它复制开发者的帐号，然后粘贴到你的银行应用中。还有在 WhatsApp 上向开发者打招呼部分：填写姓名和家乡，然后按在 WhatsApp 上发送——WhatsApp 会打开并已预填问候消息，只需在 WhatsApp 中按发送，然后返回应用。WhatsApp 不允许其他应用自动发送消息，因此发送仍由你在 WhatsApp 中亲自完成。

终端收藏命令
要在终端中保存常用命令：打开终端，然后按收藏。点按添加新收藏，填写名称（例如查看文件）和命令（例如 ls -la），然后按保存——收藏会永久保存在手机上。点按收藏名称可直接在终端中运行；点按删除收藏然后选择一个删除（需确认）。已有 3 个内置收藏：查看文件（ls -la）、检查空间（df -h）和清除屏幕（clear）——都可以删除。空命令无法保存或运行；如果发生这种情况，终端会通过消息和语音通知你。

分析与质量
要查看应用使用摘要和崩溃报告：按主屏幕上向开发者捐赠按钮旁边的分析与质量按钮。此屏幕显示应用被打开的次数、最常打开的屏幕、崩溃次数以及最近崩溃的列表并附简短修复建议。此数据仅保存在你的手机上，不会发送到任何地方。有带确认对话框的删除分析数据按钮可删除所有这些数据。最后打开的屏幕仅针对主屏幕和此屏幕记录。
